# Как писать на flang

flang — чистый функциональный язык со строгой статической типизацией, ядром
доказательств на нуле аксиом и печатью в семь целей. Пишется **русскими словами**,
и это не украшение: имена принадлежат предметной области, которая их придумала, и
не переводятся ни в одну сторону.

## Первое: чем он НЕ является

Это самая частая ошибка — перенести привычку из другого языка. Ни одна из этих
привычек здесь не работает:

| Привычка | Что на самом деле |
|---|---|
| «напишу цикл» | **циклов нет вовсе**. Есть свёртка и рекурсия |
| «изменю элемент списка» | **изменения на месте нет**. Только построение нового |
| «брошу исключение» | **исключений нет**. Отказ — это значение с кодом |
| «верну null, если не нашлось» | **есть сумма типов**, и разбор по ней обязателен |
| «положу переменную и буду менять» | `пусть` **связывает один раз** |
| «числа как числа» | числа — IEEE-754, и это ловушка, см. раздел про них |

Если решение просится «как в JavaScript» — почти наверняка оно неверно. Проверь
по этой таблице раньше, чем предлагать.

**А вот функции как значения ЕСТЬ** — не поверь обратному, это частая ошибка в
отчётах:

```flang
функция «Удвоить»              функция как значение
функция из числа в число       её тип
ф от 5                         применение
```

Перед печатью компилятор снимает их **дефункционализацией** — одним проходом
превращает в код первого порядка, поэтому граф вызовов остаётся конечным и
завершаемость доказуемой. Цена уплачена заранее и названа: проход требует
видеть всю программу целиком.

Чего действительно нет — **передачи функции туда, где она приезжает данными**
(например, отдать вычислитель параметром). Упрёшься в это — так и скажи, не
выдавай за отсутствие функций вообще.

## Форма функции — порядок частей закреплён

```flang
модуль «Отрезок»

тотальная функция «Сумма до»
  принимает н: неотрицательное
  возвращает число
  для всех н обеспечивает «сумма до неотрицательна» результат не меньше 0
  пример «до нуля — ноль»
    дано н равно 0
    ожидается 0
  если н не больше 0
    то 0
    иначе н плюс («Сумма до» от (н минус 1))
```

- **`модуль «Имя»`** — первая строка файла;
- **`тотальная`** — обещание, что функция завершается на любом входе. Компилятор
  его **проверяет** и откажет, если доказать не сможет. Не пиши наугад;
- **`принимает` / `возвращает`** — типы обязательны;
- **`требует`** — предусловие: что обязано быть верно на входе. **Доказывает
  вызывающий**, поэтому в напечатанном коде стоит ноль байт;
- **`обеспечивает`** — постусловие: что верно про результат. С именем, если на
  него будет теорема;
- **`пример`** — исполняемый пример, часть программы. Прогоняется при каждой
  проверке, а не по требованию;
- **тело** — последним, одной формой.

Имена функций и типов — **в ёлочках**: `«Сумма до»`. Вызов — `«Имя» от аргумент и аргумент`.

## Четыре формы тела, и от выбора зависит доказуемость

Это главное, что надо знать, и это измерено: **индукцию ядро цепляет только к
`разбор`у**. В библиотеке таких тел 58 из 208 — то есть 72 % кода написано
формами, к которым индукцию прицепить нечем. «Не индукция» не значит «не
доказывается»: у `если` своё правило сведения, см. ниже и раздел «Какую
конструкцию когда брать».

### `разбор` — по сумме типов. Единственная форма, к которой цепляется индукция

```flang
тип «Дерево»
  вариант Лист
  вариант Узел содержит значение: число, левое: «Дерево», правое: «Дерево»

тотальная функция «Глубина»
  принимает дерево: «Дерево»
  возвращает число
  разбор дерева
    случай Лист
      то 0
    случай вариант Узел с значение как зн и левое как л и правое как п
      1 плюс ...
```

Тотальность здесь **по структуре**: часть значения меньше значения по построению,
доказывать убывание не надо.

### `свёртка` — обход списка ровно один раз

```flang
свёртка элементы начиная с 1 как акк и эл → акк умножить на эл
```

Тотальна **по построению**: список конечен, обход один. Самая частая форма после
`если` — 49 тел в библиотеке.

### `если` — ветвление

```flang
если н не больше 0
  то 0
  иначе н плюс («Сумма до» от (н минус 1))
```

**Условие `если` ядро читает.** Гарантию над `если … то … иначе` оно сводит
правилом «разбор цели по условию»: цель разбирается по условию ветви, и в
отчёте `check --proof` стоит «доказано по объявленным типам аргументов: цель
сведена правилом «разбор цели по условию» — утверждение обо ВСЕХ входах».
Обратная замена — `разбор (условие)` со случаями `да` и `нет` — это правило
ломает: остаётся только «сетка N», то есть прогон по примерам, не
доказательство. Одна функция «Не ниже порога» с гарантией «результат не
меньше порог», снято 11 октября 2026 на flang 0.7.25 командой
`bootstrap/flang check <файл> --proof`:

| файл в `docs/examples/guide/` | тело | ответ ядра | код |
|---|---|---|---:|
| `two-outcomes.flang` | `если число не меньше порог то число иначе порог` | доказано, правило «разбор цели по условию» | 0 |
| `flag-match-unproved.flang` | `разбор (число не меньше порог)` по `да`/`нет` | сетка 2 значения, «Это не доказательство» | 0, с `--strict` 3 |
| `promise-without-examples.flang` | то же без примеров | объявлено, не доказано | 3 |

Отсюда правило: сравнение чисел и строк — через `если`; вопрос «какого вида
значение?» или «пуст ли список?» — через `разбор`. Абзац о том, что «ядро не
читает условие как факт в ветви», стоял здесь до 11 октября 2026 и был неверен
для текущего ядра — не возвращай его без нового прогона.

### `пусть` — связывание имени

```flang
пусть новое равно «Вставить в дерево» от л и число
Узел с значение равным зн и левое равным новое и правое равным п
```

Связывает **один раз**. Это не переменная.

## Какую конструкцию когда брать

Источник — страница `docs/site/which-construct.ru.md` («Какую конструкцию
когда брать»); каждый номер в столбце «Пример» — рабочий файл в
`docs/examples/guide/` с настоящим выводом компилятора. Таблица ниже обязана
совпадать со страницей строка в строку: это стережёт
`bootstrap/flang run-script skills-page:check`
(`scripts/guards/skills-follow-the-page.flang`); правишь страницу — правь и
здесь, иначе пуш краснеет.

**Главное правило: ветвление по виду значения — через `разбор`, а не через
цепочку `если … иначе если`.** Причин две. Компилятор проверяет, что разобраны
все варианты: забытый вариант — ошибка `FLANG_MATCH_NOT_EXHAUSTIVE`, а в цепочке
`если` забытый случай молча уходит в последний `иначе`. И гарантии ядро
доказывает по `разбор`у, перебирая варианты типа; по цепочке `если … иначе если`
оно гарантию либо не докажет вовсе, либо докажет только более слабую.

### Схема выбора: что нужно сделать — что писать

На странице это рисунок; здесь — те же вопросы списком. Иди сверху вниз и
остановись на первом «да».

1. Нужен файл, экран, внешняя программа или сеть? — `план`: функция
   возвращает команду, ответ рантайма идёт в `разбор`.
2. На входе список, и его надо пройти? — схема «Список» ниже.
3. Значение бывает нескольких видов? — `тип` с вариантами и `разбор`.
4. Значения может не быть, или операция может не удаться? — свой тип:
   «Есть» и «Нет», «Успех» и «Отказ» с кодом.
5. Нужно проверить несколько условий подряд? — список правил и
   `отфильтровать`.
6. Ответ выбирается по ключу: строке или числу? — таблица записей,
   `отфильтровать`, `разбор`.
7. Условие одно, исходов два? — `если … то … иначе`.
8. Промежуточному значению нужно имя? — `пусть`.
9. Ничего из этого — выражение или вызов функции.

### Схема «Список: чем его проходить»

1. Нужен новый список той же длины? — `отобразить`.
2. Нужны только подходящие элементы? — `отфильтровать`.
3. Нужен первый подходящий? — `отфильтровать`, затем `разбор`: `пусто` или
   `голова и хвост`.
4. Нужен один итог, и проход идёт до конца? — `свёртка`.
5. Иначе — `разбор` списка: `пусто`, `голова и хвост`, вызов от хвоста.

### Когда `если` уместно, а когда нет

1. Ветвей больше двух, есть «иначе если»? Нет — к шагу 2; да — к шагу 3.
2. Условие спрашивает, какого вида значение или пуст ли список? Да —
   `разбор`; нет — `если` уместно.
3. Все ветки сравнивают одно и то же значение? Нет — список правил; да — к
   шагу 4.
4. Список значений фиксирован и известен заранее? Да — `тип` с вариантами и
   `разбор`; нет — таблица записей.

Пиши `если`, когда условие одно, исходов два и условие — обычное сравнение
(`больше`, `равен`, `не меньше`). Второе законное место `если` — выход из
рекурсии по числу (пример 16). И не заменяй `если` на `разбор` по `да` и
`нет`: код работает, а гарантия перестаёт доказываться (таблица в разделе про
`если` выше).

### Конструкции, которых в разделе о формах тела нет

- `отобразить список как элемент → выражение` — map; гарантию о длине
  результата ядро доказывает само (пример 10).
- `отфильтровать список где элемент → условие` — filter; «отбор список не
  удлиняет» доказывается само (пример 11).
- `план` — действия с миром: функция возвращает команду («Прочитать файл»,
  «Запустить процесс», «Запросить»), хозяин выполняет её и зовёт функцию снова
  с ответом; логика остаётся чистой и проверяется примерами без файлов и сети
  (примеры 26–28; образец сторожа на плане — `scripts/guards/delivery-guard.flang`).
- тип `сотых` — деньги целым числом минорных единиц, без ошибок округления
  IEEE-754 (пример 20).
- `утверждение` — свойство, записанное отдельно от функции (пример 25).

## Как доказывается `тотальная` — пять способов

| Способ | Когда | Функций в дереве |
|---|---|---:|
| композицией | рекурсии нет вовсе | 4024 |
| структурой | обход части значения (`разбор`) | 292 |
| точным шагом | по `неотрицательное`, спуск ровно на 1 | 21 |
| постоянным шагом | число + проверка при работе | 2 |
| объявленной мерой | `убывает х` + проверка при работе | 64 |

**Первые три ничего не стоят при работе. Последние две ставят проверку в
напечатанный код** — и сторож объявленной меры **утраивает время функции**. Если
можно переписать под первые три — переписывай.

## Теорема — когда постусловия мало

```flang
теорема «сумма до неотрицательна»
  дано н: неотрицательное
  утверждаем результат не меньше 0
  индукция по н убывает н
    случай 0
      то по примеру «шагов не осталось»
    случай любое
      то по предположению
  следовательно доказано
```

Обоснования шага: `по предположению` (допущение индукции), `по примеру` (ссылка
на именованный пример), `по закону`, `по свойству`.

**Часто теорема не нужна вовсе.** Ядро закрывает утверждение само в 70 случаях из
110 — сначала напиши постусловие и спроси ядро, и только если оно откажет, пиши
теорему.

## Числа — здесь ловушки, и все три нас уже кусали

**Числа языка — машинные IEEE-754, и это НЕ так, как в Coq.** Не перепутай: у
Coq `nat` — построенный индуктивный тип (ноль и следующий), точный и без
верхней границы, а `Z` — точные двоичные целые. Дробные там лежат отдельной
библиотекой, и доказывать про них так же больно, как здесь.

Наш `неотрицательное` — **отрезок машинных чисел** [0, 2⁵³−1]. Размен сделан сознательно:
арифметика остаётся быстрой (одна инструкция процессора), а обе границы дают
ядру то, что нужно для индукции. Плата — всё, что ниже.

**Минус ноль.** Всплывал **трижды за сутки** в разных местах. `−0` и `0` — разные
значения при сравнении на равенство. Любая функция, сравнивающая числа на
равенство или берущая остаток, **обязана быть проверена на `−0`** до попадания в
библиотеку. Так сломались «Чётное», «Делится на» и «Уникальные».

**NaN достижим изнутри языка**: `0 делить на 0` проходит типизацию без единой
диагностики. Поэтому «очевидные» правила вроде «модуль числа неотрицателен» —
**ложь**: модуль от NaN есть NaN, а «NaN не меньше 0» ложно.

**Ассоциативность не держится.** `(0.1 + 0.1) + 0.6` даёт `0.8`, а
`0.1 + (0.1 + 0.6)` даёт `0.7999999999999999`. Ломает её **округление, а не
бесконечность** — убрать вычитание не помогает.

**Типы чисел и что они дают ядру:**

| Тип | Что это | Ядру даёт |
|---|---|---|
| `число` | IEEE-754 | ничего |
| `неотрицательное` (устаревшая краткая запись — `нат`) | отрезок [0, 2⁵³−1] | обе границы — отсюда индукция по числу и правило умножения |
| `целое` | без дна | почти ничего |
| `вес` / `стоимость` | [0, +∞] | обе границы; моноид по минимуму и максимуму |
| точные десятичные | целое число минорных единиц | ассоциативность, моноид; цена **нулевая** |

**Объявляй точное неотрицательное там, где значение неотрицательно.** Это не
педантизм: из 139 функций корпуса ядро выводило неотрицательность у 4, а при
объявлении подходящим типом — у 25.

**Пиши его `неотрицательное`, а не `нат`.** Обе поверхности означают один и тот
же тип — они стоят в одной строке перечня («Скаляр по имени»,
`flang/self/types.flang`), — но `нат` — обрубок, оставленный синонимом до 1.0
(решение владельца в коммите `1212338`; снять его — ломающее изменение, шаг 4
того же решения). Семя знает оба имени с перепечатки 3 сентября 2026
(`659d477`, v0.7.11); до неё применённое `неотрицательное` отвечало
`FLANG_UNKNOWN_NAME` на любом существующем двоичном — 24 августа 2026 так встал
весь ствол, а 26 августа нашлось ещё 180 таких применений в 78 файлах.
Проверить себя: `bootstrap/flang io scripts/guards/seed-knows-type-words-guard.fscript --plan Check --max-steps 4000000000` («чужих семени 0»).

Это частный случай общего правила, и оно же — единственное, из-за чего дерево
может перестать читаться СОБОЙ. **Ввести слово и применить его — разные
изменения:** (1) научить компилятор имени, не ставя его в позиции типа;
(2) перепечатать семя; (3) применить. Шаги 1 и 3 в одном изменении ломают дерево.

## Написал `обеспечивает` — поставь при нём `пример`

Доказанное постусловие снимается из напечатанного кода **при двух условиях
сразу**: ядро его доказало И у функции есть хотя бы один `пример`. Одного
доказательства мало. Обещание без примера уезжает проверкой при работе в каждую
напечатанную программу — и, что дороже, отнимает у функции хвостовой вызов и
покупает кадр стека всей её группе взаимной рекурсии.

Замер 28 августа 2026 на обработчике `flang/concurrency/examples/counter.flang`:

| | проверок при работе | напечатано |
|---|---:|---:|
| без обещания | 1 | 401 803 байта |
| обещание **с примером** | 1 | **401 803 байта — байт в байт** |
| то же обещание **без примера** | **2** | 402 749 байт (+946) |

**Как узнать, что вышло.** У программы БЕЗ объявления процессов — отчётом:
`flang check <файл> --proof` называет вердикт каждому утверждению. У программы
С процессами отчёт не печатается вовсе, и остаётся `flang emit`: он говорит
«проверок при работе снято N».

⚠ **Размер напечатанного признаком доказанности НЕ является.** Байты растут и
когда обещание не доказано, и когда при нём нет примера, — эти два случая по
ним не различить. Сначала поставь пример, и только потом читай размер. На этом
можно потерять день: 28 августа так были названы стеной два обработчика, у
которых с доказательством всё было в порядке.

## Как проверять свою работу

```bash
LC_ALL=C.UTF-8 bootstrap/flang check файл.flang            # типы, тотальность, примеры
LC_ALL=C.UTF-8 bootstrap/flang check файл.flang --proof --pretty   # плюс доказательства
LC_ALL=C.UTF-8 bootstrap/flang run файл.flang --function «Имя» --args '{"н": 5}'
LC_ALL=C.UTF-8 node flang/scripts/proof-ledger.mjs                  # ведомость по всему корпусу
```

`LC_ALL=C.UTF-8` обязателен — локаль в среде сломана, без него русские буквы
портятся.

**Три результата проверки гарантии, и путать их нельзя** (таблица со
страницы `docs/site/which-construct.ru.md`):

| В выводе написано | Что это значит | Код `check --proof` | Код `run` |
| --- | --- | --- | --- |
| «доказано» | верно для всех возможных входов | 0 | 0 |
| «сетка N» | проверено только на N ваших примерах, как unit-тестами; доказательства нет | 0, с `--strict` 3 | 3 |
| «объявлено, не доказано» | нет ни доказательства, ни примеров | 3 | 3 |

Строка про сетку кончается словами «Это не доказательство», и кончается так
намеренно. И четвёртый результат, самый ценный: **НАРУШЕНО** — контрпример
найден и показан.

## Чего доказательство не говорит

**Доказано ≠ правильно.** Живой случай: на функции «Чётное» ведомость печатает
«доказано обо ВСЕХ входах», а тест находит ошибку на −4 — потому что функция и её
напарница ошибаются на минус нуле **одинаково**. Ядро право, неверна спецификация.

Помни это, когда считаешь успехи. И не считай за успех **тавтологию**: утверждение
«результат равен `0 минус х`» при теле `0 минус х` принимается даром и не значит
ничего.

## Правила, по которым здесь принято работать

- **улика ДО, числом** — не «не реализовано», а «расходится на 1020 из 7888»;
- **снять правку и посмотреть, что покраснеет** — не покраснело, значит правка
  ничего не держит;
- **подделка на каждое правило** — программа, пытающаяся доказать ложь, обязана
  быть отвергнута, и код отказа обязан её назвать;
- **красный список сравнивать `diff`-ом полных списков**, не на глаз;
- **аксиом ноль** — список в `flang/self/proofterm.flang` обязан оставаться пуст, и
  это стоит отдельным тестом.

Известные чужие красные: файлы без собранного `dist`, sha256 формулы Homebrew,
часть проверок эталона ведомости. Часть тестов **подвисает под нагрузкой** —
подвисание не красный результат, прогоняй отдельно и говори об этом.

## Категорная поверхность — коротко

Семантика языка категорная, и у неё есть слова: `объект` — тип, `морфизм «имя»
из «А» в «Б» даёт «Функция»` — стрелка с функцией, которая её считает,
`морфизм «в» это «б» после «а»` — композиция, `единица «А»` — тождественная
стрелка, `категория «Имя»` со списком морфизмов и `объект «А» даёт «А равны»` —
объявленное равенство значений, `функтор`, преобразование (естественное),
`изоморфизм`, `моноид`, `монада`, форма `в монаде`. Полная форма каждого
объявления и код диагностики на каждую беду — `docs/ct/spec.md` (контракт);
то же с готовыми примерами — `docs/site/categories.ru.md`; рабочие файлы —
`flang/ct/`.

Что компилятор с этим делает сегодня, и это три разных ответа:

| Что объявлено | Что компилятор делает |
|---|---|
| категория с объявленным равенством | СЧИТАЕТ три закона (равенство — эквивалентность, композиция его уважает и ассоциативна) **на конечной сетке** значений из примеров; размер сетки называет; нарушение — отказ и отмена печати |
| преобразование | считает коммутативность квадрата на сетке; нарушение — `FLANG_TRANSFORM_NOT_NATURAL` |
| замкнутость, единицы, концы композиций, вид равенства | НЕ сверяет; говорит отдельной фразой, код 2 |
| моноид, монада, функтор, изоморфизм | НЕ судит вовсе; называет поимённо, код 2 |
| закон при стрелке | прогоняется как пример при `flang test` |

«Посчитано на сетке» — не «доказано», и слово «доказано» здесь не
употребляется намеренно. Код 2 значит «проверено НЕ ДО КОНЦА»; читать его как
«всё хорошо» нельзя, и в CI он не зелёный. Снято 11 октября 2026 на flang 0.7.25:
`bootstrap/flang check flang/ct/set-mail-routing.flang` — «сетка 10 значений на
4 объектах, троек стрелок 50, нарушений 0 — ПОСЧИТАНО НА СЕТКЕ, не доказано»,
код 2; `flang/ct/monoid-and-monad.flang` — «объявлено то, чего бинарник не судит
вовсе — monoids, monads», код 2. Судьи правил поверхности лежат в дереве на
самом flang (`flang/self/monoid.flang`, `monad.flang`, `iso.flang`,
`functor.flang` и соседи), но в сборку двоичного не входят — подробности и
довод в `docs/ct/spec.md`, раздел «Что двоичный компилятор судит, а чего не
судит».

## Как писать о языке: два адресата, и путать их нельзя

**Внутри проекта жаргон полезен** — он короче и точнее. В заданиях и в отчётах между агентами
слова «эталон», «сторож», «корпус» законны, и вычищать их оттуда НЕ надо. Придя
править внутренний текст, не трогай его словарь.

**Запрет — только на текстах для читателя со стороны:** страницы сайта, README,
`man flang`, курс и **сообщения самого компилятора** — справка, диагностика,
тексты отказов. Человек, поставивший язык, читает их первыми, а нашей кухни не
знает. Владелец — тимлид с большим опытом, но не языкостроитель, и просил об
этом дважды и резко.

### Чем заменять

| Не писать | Писать |
|---|---|
| эталон, свидетель | реализация на JavaScript / вторая реализация |
| близнец | компилятор, написанный на flang |
| корпус | программы репозитория / примеры / библиотека — **смотря о чём речь** |
| сторож | проверка |
| ведомость | отчёт о доказательствах |
| побайтовая сверка | сравнение байт в байт |
| неподвижная точка | компилятор печатает сам себя без изменений |
| изъятие | снять правку и посмотреть, что сломается |
| свод | сводка / ветка сборки — смотря о чём |
| печатник | генератор кода |
| дефункционализация | функции-значения снимаются одним проходом перед печатью |
| фронтенд | разбор языка |

Английские страницы падают на том же: `witness`, `twin`, `corpus`, `ledger`,
`byte-for-byte`, `fixed point`, `defunctionalization`.

### Правило вместо списка

Список закончится — новое слово заведётся завтра. Держись правила: **если слово
требует, чтобы читатель знал нашу внутреннюю кухню, — на публичной странице ему
не место. Либо объясни одной фразой при первом употреблении, либо убери.**

### Признак, ловящий не слово, а строй речи

**Если абзац можно начать словами «мы» или «раньше» — он про нас, а не про
предмет.** Читателю нужно, **что язык умеет и где границы**, а не как мы к
этому пришли.

| Про нас | Про предмет |
|---|---|
| «Мы измерили и увидели, что…» | «Индукция цепляется только к `разбор`у» |
| «Раньше здесь стоял другой разбор…» | «Условие `если` ядро сводит правилом «разбор цели по условию»» |
| «Нам пришлось завести отдельный проход…» | «Мера объявляется словом `убывает`» |

История правок ценная, но её место — история коммитов, а не
страница, куда пришли научиться писать на языке.

### Проверяется прогоном, а не на глаз

```bash
bootstrap/flang run-script jargon:check                # отказ с именем файла и номером строки
bootstrap/flang run-script jargon:list                  # то же, и каждое место названо поимённо
bootstrap/flang run-script jargon:debt                    # вписать новый долг после чистки
```

Это `scripts/guards/jargon-guard.fscript`, на flang. Все три режима — три плана
одного файла, и каждый сошёлся со старым прогоном на JavaScript знак в знак
(сверка пересдана 27 августа 2026 после переделки разбора: проверка 4088 знаков,
список 76 318 знаков, обе посимвольно совпали, а после `jargon:debt` файл
`docs/jargon.json` совпал с записанным старым прогоном БАЙТ В БАЙТ).

**Каждый прогон идёт минуту с четвертью** и берёт место у ворот — не то, что
запускают между делом. Против 0,32 с у старого прогона это в 239 раз дороже
(прежде было в 754), и цена эта названа, а не спрятана.

⚠ `jargon:debt` вписывает НЫНЕШНИЕ числа, а не опускает потолок: на грязном
дереве он узаконит сегодняшний жаргон. Замер 26 августа: он поднял бы долг с
977 вхождений до 1017. Звать его надо ПОСЛЕ чистки, а не вместо неё.

Слова и список поверхностей лежат в `docs/jargon.json` и правятся без правки
самого прогона. Долг числом на файл: вырасти не имеет права, а упадёт — прогон
попросит вписать новое число, чтобы потолок полз только вниз.

Слово, стоящее законно, заводится там же **исключением с цитатой**: `объяснено`
— цитата фразы, где слово объясняется при первом употреблении; `внутри` —
цитата имени вещи (имя функции на flang, ключ машинного вывода). Выдумать
цитату нельзя, прогон сверяет её с файлом.

Открытые задачи — `docs/tasks/`, решения — `docs/adr/`.
