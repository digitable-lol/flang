# flang — описание языка

Этот файл — краткое формальное описание языка flang для программиста: лексика,
типы, объявления, выражения, обещания о поведении, команды компилятора, цели
печати, модули и то, чего в языке нет. Каждое утверждение здесь сверено с
исходником компилятора (`flang/self/*.flang`) и с прогоном собранного
двоичного `bootstrap/flang`; каждый блок кода в этом файле проходит
`bootstrap/flang check`, и код возврата у блока назван, если он не ноль.
Чисел-снимков (сколько файлов, строк, функций) здесь нет намеренно: они
устаревают, а снимаются командами, названными рядом. Единственное исключение —
раздел 6.1 о доказуемости: без чисел он превратился бы в оценку, поэтому числа
там стоят, и рядом с каждым стоит команда, которой оно снимается заново.

## 1. Назначение

flang — чистый функциональный язык со строгой статической типизацией, у
которого проверка обязательна и идёт до запуска: компилятор разбирает файл,
выводит типы, доказывает завершение функций, помеченных `тотальная`, прогоняет
примеры, записанные внутри функций, и пытается доказать постусловия ядром
доказательств; программа, не прошедшая проверку, не печатается. Один исходник
печатается в десять целевых языков (`c`, `cpp`, `go`, `rust`, `java`, `js`,
`ts`, `elixir`, `python`, `csharp`). Побочных эффектов у программы нет: действие во
внешнем мире записывается значением-поручением, а исполняет его хозяин —
команда `flang io` или напечатанный вместе с программой прогонщик. Компилятор
написан на самом flang и собирается из закоммиченного семени на C одной
командой `make -C bootstrap`.

```flang
модуль «Удвоение»

тотальная функция «Удвоить»
  принимает н: число
  возвращает число
  пример «два»
    дано н равно 2
    ожидается 4
  н умножить на 2
```

```
$ flang check удвоение.flang
модуль «Удвоение»: функций 1, из них с доказанным завершением 1; типов 0
удвоение.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
$ echo $?
0
```

## 2. Лексика

**Файл.** Расширений у исходника четыре и они равноправны: `.flang`, `.fp`,
`.фп`, `.фланг` (список — функция «Расширения языка» в
`scripts/guards/file-extensions.flang`; решения ADR-0016 и ADR-0018). Команды берут
файл по пути, а не по расширению; исключение — `flang test`, который довод не
на `.flang` считает каталогом или маской.

**Отступы вместо скобок.** Блок — это строки с большим отступом. Скобки `(` `)`
служат только группировке выражений; у китайской поверхности полноширинные
`：` `，` `（` `）` значат то же, что `:` `,` `(` `)`.

**Имена.** Имя модуля, функции, типа, варианта, примера, утверждения пишется в
ёлочках `«…»`. Имя параметра, связки `пусть` и поля записи — одно слово без
кавычек либо тоже в ёлочках (`«без налога»`). Слово, занятое языком, именем
быть не может: `принимает с: число` отвергается разбором.

**Литералы.** Число — десятичная запись IEEE-754 double (`12`, `0.5`, `-3`).
Строка — `"текст"` или `'текст'`, с экранированием `\"`, `\\`, `\n`. Признак —
`да` / `нет`. Пустое значение — `ничто`. Список — `[1, 2, 3]`, пустой —
`пустой список`; то же словами: `список из 1 и 2 и 3`.

**Стрелка** `→` набирается также `->` и `=>`.

**Комментарий** — строка, начинающаяся с `//`. В дерево разбора он не попадает;
причина поведения, которую надо сохранить, пишется термом `примечание "…"`
(раздел 4).

### 2.1. Четыре поверхности записи

Каждое слово языка существует на четырёх поверхностях — русской, английской,
эсперанто, китайской — и все они сводятся лексером к одному идентификатору:
`если`, `if`, `se`, `如果` — одно слово, дерево разбора у них одно. Таблица
слов одна, в `flang/self/lexer.flang` (функция «Куски таблицы»); проверить любое
слово: `flang tokens --keyword «фраза»`. Ключевая фраза из нескольких слов
(`и притом`, `голова и хвост`, `начиная с`) склеивается лексером в один токен.
Имена функций и модулей не переводятся ни на какой поверхности. Слова
доказательств (`требует`, `обеспечивает`, `убывает`, `утверждаем`, `индукция
по`, `по свойству`, `по примеру`, `по предположению`, `для всех`, `следовательно
доказано`) открыты только на русской и английской поверхностях; у слова `это` —
только русское написание.

## 3. Типы

Значение языка — скаляр, список, запись или вариант суммы. Носитель всякого
числового типа один — IEEE-754 double; точные типы ниже — уточнения (обещание
о целости и границах), а не новые виды значения, и в напечатанном коде они
представлены тем же числом.

| Тип | Значения | Что даёт объявление |
| --- | --- | --- |
| `число` | любой double, включая `+∞`, `−∞`, «не число» | ничего; арифметика над `число` не сохраняет ни целости, ни знака |
| `неотрицательное` (`нат`, `натуральное`) | целые из [0, 2⁵³−1] | ядру доказательств — дно и потолок и целость; завершаемости — спуск на постоянную доказывается без проверки в коде |
| `целое` | целые из [−(2⁵³−1), 2⁵³−1] | целость и границы |
| `вес` (`стоимость`) | [0, +∞], где `+∞` — законное значение | дно 0; по контракту (`flang/SPEC.md` §3) вычитание, умножение, деление и остаток над `вес` — отказ `FLANG_INFINITY`; **собранный двоичный этот отказ не выносит** и на `вес минус вес` отвечает «замечаний нет» (сказано в `flang check --help`) |
| `сотых`, `тысячных` | целые из [0, 2⁵³−1], толкуемые как сотые или тысячные доли | точные деньги и доли: `10 плюс 20` равно `30`; по контракту сложение разных масштабов — `FLANG_SCALE`; **двоичный масштаб не судит** (там же) |
| `строка` | строка UTF-8; отдельного типа символа нет — символ есть строка из одной кодовой точки | образцы `пусто` и `голова и хвост` разбирают строку так же, как список |
| `признак` | `да`, `нет` | условие в `если`, `и притом`, `или`, `не` |
| `ничто` | одно значение `ничто` | — |
| `список Т` (`список из Т`) | однородный список; ковариантен | `список неотрицательное` годится там, где ждут `список числа` |
| запись `«Имя»` | набор именованных полей; поле `иногда является Т` может отсутствовать | инвариантна; читается точкой `значение.поле` |
| сумма `«Имя»` | один из объявленных вариантов, у варианта — свои поля | `разбор` обязан покрыть все варианты |
| псевдоним `тип «Имя» это Т` | то же, что `Т` | — |
| параметрический `«Имя» от Т и Т` | подстановка параметров словом `от` | аргументы при вызове выводятся из значений |
| `функция из Т и Т в Т`, `Т → Т` | значение-функция: ссылка на объявленную функцию, не замыкание | применение `ф от х` |
| `дата`, `деньги` | наследие: `дата` ведёт себя как `строка`, `деньги` — как `число` | — |
| `«Поручение»`, `«Отклик»`, `«Продолжение»`, `«Действие»` | встроенные суммы; появляются в программе, где написан `план` или `процесс` | раздел 9 и 10 |

Вложение числовых типов: `неотрицательное` ≤ `целое` ≤ `число` и
`неотрицательное` ≤ `вес` ≤ `число`. Значение втекает в объявленную позицию
(аргумент, тело против `возвращает`, элемент списка, поле, накопитель свёртки),
обратно — нет. **Точность не наследуется арифметикой**: сумма двух
`неотрицательное` имеет тип `число`, деление всегда даёт `число`. Границы
выводятся интервальным анализом: литерал знает себя точно, `если н не больше 0`
сужает тип `н` в своей ветви, `длина` и `код символа` неотрицательны по
построению. Переполнение точной сетки не отказ, а расширение типа до `число`.
Округления в языке нет ни явного, ни неявного.

## 4. Объявления

Файл начинается строкой `модуль «Имя»`; ниже, у левого края, — объявления.
Порядок объявлений свободен: функция законно зовёт объявленную ниже.

### 4.1. Функция

```
[тотальная] функция «Имя» [от «П» [и «П»]…]
  [принимает имя: Тип[, имя: Тип]…]
  возвращает Тип
  [требует «имя» Условие]…
  [убывает Выражение]
  [[для всех имя] обеспечивает «имя» Условие]…
  [пример «имя»
    [дано имя равно Значение]…
    ожидается Значение]…
  Тело
```

Части идут в этом порядке; тело — последнее выражение, одно. `тотальная` —
обещание завершаться на любом входе, компилятор его доказывает (раздел 6).
`требует` — предусловие, его снимает вызывающий. `убывает` — объявленная мера
завершаемости, обязана быть числом и стоит между `возвращает` и телом.
`обеспечивает` — постусловие о значении `результат`; без имени не разбирается.
`пример` прогоняется на каждой проверке файла.

```flang
модуль «Мера»

тотальная функция «НОД»
  принимает а: число, б: число
  возвращает число
  убывает б
  пример «двенадцать и восемнадцать»
    дано а равно 12
    дано б равно 18
    ожидается 6
  если б равен 0
    то а
    иначе «НОД» от б и (а остаток от б)
```

### 4.2. Запись, сумма, псевдоним, параметрический тип

```
объект «Имя» [от «П»]…          запись; синонимы слова: структура, запись
  имя является Тип                поле
  имя иногда является Тип         необязательное поле
  «имя»: Тип                      то же, второй формой

тип «Имя» [от «П»]…             сумма
  вариант Имя                     вариант без полей (имя словом или в ёлочках)
  вариант Имя содержит имя: Тип[, имя: Тип]…

тип «Имя» это Тип                 псевдоним
```

Запись строится формой `запись «Имя» с поле равным Значение и поле равным
Значение`; вариант — `вариант Имя с поле равным Значение`. Поля продолжает
только `и`; запятая всегда закрывает список полей.

```flang
модуль «Типы»

объект «Позиция»
  название является строкой
  цена является числом
  скидка иногда является числом

тип «Счёт» это список «Позиция»

тип «Ответ»
  вариант Успех содержит значение: число
  вариант Отказ содержит причина: строка

тотальная функция «Проверить цену»
  принимает позиция: «Позиция»
  возвращает «Ответ»
  пример «цена есть»
    дано позиция равно запись «Позиция» с название равным "болт" и цена равным 30
    ожидается вариант Успех с значение равным 30
  пример «ноль — не цена»
    дано позиция равно запись «Позиция» с название равным "гайка" и цена равным 0
    ожидается вариант Отказ с причина равным "цена не положительна"
  если позиция.цена больше 0
    то вариант Успех с значение равным позиция.цена
    иначе вариант Отказ с причина равным "цена не положительна"

тип «Возможно» от «А»
  вариант «Есть» содержит значение: «А»
  вариант «Нет»

тотальная функция «Обернуть» от «А»
  принимает значение: «А»
  возвращает «Возможно» от «А»
  вариант «Есть» с значение равным значение
```

### 4.3. Теорема

```
теорема «имя»                       имя совпадает с именем постусловия
  [дано имя: Тип]…                  переменные утверждения
  утверждаем Условие                слово в слово как в постусловии
  [индукция по имя [убывает Выражение]
    случай Образец
      то Обоснование]…
  [затем Условие по Обоснование]…
  [Обоснование]
  следовательно доказано
```

Обоснование — одно из четырёх: `по свойству «имя»` (чужое постусловие, стоящее
у вызова в заключении), `по предположению` (посылка индукции или предусловие
функции), `по примеру «имя»` (случай с одним значением, закрытый примером),
`по закону «имя»` (закон моноида, монады или изоморфизма этого модуля). Шаг без
обоснования отвергается разбором: ядро ничего не ищет.

```flang
модуль «Теорема»

тотальная функция «Сумма до»
  принимает н: неотрицательное
  возвращает число
  для всех н обеспечивает «сумма до неотрицательна» результат не меньше 0
  пример «шагов не осталось»
    дано н равно 0
    ожидается 0
  если н не больше 0
    то 0
    иначе н плюс («Сумма до» от (н минус 1))

теорема «сумма до неотрицательна»
  дано н: неотрицательное
  утверждаем результат не меньше 0
  индукция по н убывает н
    случай 0
      то по примеру «шагов не осталось»
    случай любое
      то по предположению
  следовательно доказано
```

### 4.4. Модуль, экспорт, ввоз

```
модуль «Имя»
  [экспортирует «А», «Б»]                   без строки видно всё
  [использует «Модуль» [только «А», «Б»] [из "путь"]]…
```

Модуль ищется **по имени** из первой строки файла, не по имени файла. Места
просматриваются в этом порядке (`repl_places_of` и `repl_library_places`,
`flang/src/emit/c/flang_repl.c`): каталог ввозящего файла; каждый каталог выше,
пока в нём лежит хоть один файл `.flang`; каталоги переменной
`FLANG_MODULE_DIR` (через двоеточие); библиотека, поставленная с компилятором
(`flang/stdlib`, `flang/core`, `share/flang/stdlib`, `share/flang/core` рядом с
двоичным). Форма `из "путь"` называет файл или пакет
(`из "имя.flang-package"`) прямо.

**Побеждает первое место, где имя нашлось, и молча.** Два файла с одним именем
модуля в ОДНОМ месте — отказ `FLANG_IMPORT_AMBIGUOUS` с обоими путями. Два
файла в РАЗНЫХ местах — не отказ: берётся тот, что в месте раньше, в поток
ошибок уходит строка «модуль «Имя» взят из …; тот же модуль объявляют также:
…», а код возврата остаётся 0. Проверено прогоном: файл-предок каталогом выше
корня побивает и `FLANG_MODULE_DIR`, и библиотеку языка. Отсюда и сторож
`scripts/guards/module-origin-guard.sh` — он пересчитывает правило поиска обходом
каталогов и краснеет, когда модуль приезжает из-за пределов дерева. Подъём
можно оборвать: `FLANG_MODULE_ROOT` называет каталог, выше которого поиск не
идёт, и тогда чужой файл каталогом выше не подменяет модуль, а ввоз, которому
в дереве нечем разрешиться, честно отвечает `FLANG_IMPORT_NOT_FOUND`.
Переменная не названа — поведение прежнее. `только` решает не видимость, а
состав программы: чего нет в списке — того в программе нет, и постусловие
ввезённой функции, зовущее не названного соседа, даёт `FLANG_UNKNOWN_NAME`.
Если рядом со входным файлом лежит `flang.lock`, все команды берут ввозы из
него и исходников зависимостей не читают.

```flang
модуль «Библиотека»
  экспортирует «Утроить»

тотальная функция «Утроить»
  принимает н: число
  возвращает число
  н умножить на 3

тотальная функция «Скрытая»
  возвращает число
  1
```

```flang
модуль «Ввоз»
  использует «Библиотека»

тотальная функция «Девять»
  возвращает число
  пример «три утроено»
    ожидается 9
  «Утроить» от 3
```

Обращение к «Скрытая» из модуля «Ввоз» — `FLANG_UNKNOWN_NAME`, код 1.

### 4.5. Примечание

`примечание "причина"` — терм у левого края между объявлениями. Несёт строку и
своё место; типа и значения не имеет, в напечатанный код не едет.

```flang
модуль «Примечание»

примечание "на минус нуле обе стороны сравнения ложны, поэтому ветвей две"

тотальная функция «Ноль»
  принимает н: число
  возвращает признак
  если н равен 0
    то да
    иначе нет
```

### 4.6. Объявления, которые двоичный компилятор разбирает, но не судит

Категорная поверхность (`категория`, `морфизм`, `цепочка`, `единица`,
`изоморфизм`, `функтор`, `бифунктор`, `моноид`, `монада`, `вложение`,
`пересечение`, `свойство`) и модель процессов (`процесс`, `надзор`, `прогон`)
разбираются, типизируются и печатаются, но правила самих объявлений собранный
`bootstrap/flang` не проверяет: `flang check` называет пробел словами и
отвечает **кодом 2**. У `flang emit` код зависит от того, что объявлено, и
проверено это прогоном по `flang/ct/`: объявлены `моноид` или `монада` — файлы
записаны, но код **3** («НАПЕЧАТАНО, НО ПРОВЕРЕНО НЕ ВСЁ»); объявлены только
`категория`, `морфизм` и `функтор` — код **0**, потому что их законы двоичный
считает сам (`flang/self/setoid.flang` и `flang/self/setoid-oracle.flang`).
Законы категории с объявленным равенством двоичный считает на конечной сетке
значений автора; это счёт, а не доказательство. Формы — в
[`docs/site/language.ru.md`](docs/site/language.ru.md), контракты — в
[`docs/ct/spec.md`](docs/ct/spec.md) и [`flang/conc/SPEC.md`](flang/conc/SPEC.md).

<!-- проверка: код 2 -->
```flang
модуль «Проводка заказа»

объект «Заказ»
  сумма является числом

объект «Отгрузка»
  номер является числом

тотальная функция «Отгрузить заказ»
  принимает заказ: «Заказ»
  возвращает «Отгрузка»
  запись «Отгрузка» с номер равным заказ.сумма

морфизм «отгрузить» из «Заказ» в «Отгрузка»
  даёт «Отгрузить заказ»
```

Форма связывания `в монаде «Т»` — блок из строк `пусть имя равно шаг` и
последней `возврат выражение`; компилятор разворачивает его в `разбор` по
вариантам типа, на котором объявлена монада (`монада «Т» от «А»` с строками
`возврат «Ф»` и `соединение «Ф»`). Программа с `монада` тоже получает код 2.

## 5. Выражения и операторы

Тело функции — одно выражение одной из форм:

| Форма | Запись | Условие типов | Значение | Отказ |
| --- | --- | --- | --- | --- |
| связывание | `пусть имя равно Выражение` и далее выражение | — | значение следующего выражения при связанном имени; переприсваивания нет | повтор имени — `FLANG_DUPLICATE_NAME` |
| ветвление | `если Условие то В1 иначе В2` | условие — `признак`; обе ветви обязательны | В1 либо В2; условие сужает числовые границы в своей ветви | нет `иначе` — `FLANG_PARSE` |
| разбор суммы | `разбор Выражение` / `случай Имя то В` / `случай вариант Имя с поле как имя[, поле как имя] то В` / `случай любое то В` | все варианты покрыты | значение ветви | `FLANG_MATCH_NOT_EXHAUSTIVE`, недостижимый случай — `FLANG_MATCH_UNREACHABLE` |
| разбор списка и строки | `случай пусто то В` / `случай голова и хвост то В` | — | `голова` — первый элемент (первая кодовая точка), `хвост` — остаток | те же |
| свёртка | `свёртка Список начиная с Начало как акк и эл → Тело` | элемент и накопитель типизируются по началу и списку; тип накопителя не уточняется | значение накопителя после прохода | — |
| отображение | `отобразить Список как имя → Тело` | — | новый список | — |
| отбор | `отфильтровать Список где имя → Условие` | условие — `признак` | подсписок | — |
| вызов | `«Имя» от А1 и А2` | арность и типы по подписи | значение функции | `FLANG_APPLY`, `FLANG_TYPE`, предусловие не снято — `FLANG_PRECONDITION_CALL` |
| функция как значение | `функция «Имя»`, `функция «Имя» с а равным 10` | тип `функция из … в …`; захват — только первых параметров по порядку объявления | ссылка на объявленную функцию | применение ссылки, которую программа не строит, — `FLANG_APPLY` |
| применение значения | `ф от х` | `ф` типа функции | — | как у вызова |
| конструкторы | `запись «Имя» с поле равным В и …`, `вариант Имя с поле равным В`, `[В, В]` | поля по объявлению | новое значение | недостающее или чужое поле — `FLANG_TYPE` |
| поле | `значение.поле` | запись с таким полем | — | `FLANG_TYPE` |
| арифметика | `плюс`, `минус`, `умножить на`, `делить на`, `остаток от`, `процентов от` | оба операнда — числа | IEEE-754; `делить на` всегда даёт `число` | `FLANG_TYPE` |
| сравнение | `равен`, `не равен`, `больше`, `меньше`, `не больше`, `не меньше` | — | `признак`; для «не числа» все сравнения ложны | — |
| логика | `не В`, `А и притом Б`, `А или Б` | операнды — `признак` | правый операнд не вычисляется, если левый решил | `FLANG_TYPE` |

Приоритет от слабого к сильному: `или` < `и притом` < `не` < сравнения <
`плюс` `минус` < `умножить на` `делить на` `остаток от` < `от` < `.`. Слово `и`
разделяет аргументы вызова и поля конструктора; конъюнкция — только `и притом`.
Локальное имя ищется точным совпадением, а при неудаче — по неизменяемой основе
среди уже связанных локальных имён (`«Длина» от хвоста` при параметре `хвост`);
двусмысленность — `FLANG_AMBIGUOUS_NAME`. Имена функций, типов, вариантов и
полей не склоняются.

Встроенные формы: `длина X`, `голова X`, `хвост X`, `элемент N в X`, `символ N
в X` (нумерация с единицы, номер вне границ прекращает вычисление отказом),
`добавить X к Y` (в конец), `приписать X к Y` (в начало), `подстрока X с A по
B`, `разделить X по Y`, `соединить X по Y` (список строк в строку), `соединить X
с Y` (две строки), `X содержит Y`, `X начинается с Y`, `к числу X`, `к числу или
беда X`, `к строке X`, `код символа X`, `символ по коду N`, `разложить X на
символы`, `хеш256 X`. Неверное число или тип доводов — `FLANG_BUILTIN_ARGS`.

```flang
модуль «Формы»

тотальная функция «Произведение»
  принимает элементы: список числа
  возвращает число
  пример «три множителя»
    дано элементы равно [2, 3, 4]
    ожидается 24
  свёртка элементы начиная с 1 как акк и эл → акк умножить на эл

тотальная функция «Длинные слова»
  принимает текст: строка
  возвращает список строки
  пример «короткое слово выброшено»
    дано текст равно "раз дважды трижды"
    ожидается ["дважды", "трижды"]
  отфильтровать (разделить текст по " ") где слово → (длина слово) больше 3

тотальная функция «Длины слов»
  принимает слова: список строки
  возвращает список числа
  пример «три слова»
    дано слова равно ["раз", "дважды", "трижды"]
    ожидается [3, 6, 6]
  отобразить слова как слово → длина слово

тотальная функция «Узлов»
  принимает элементы: список числа
  возвращает число
  пример «три элемента»
    дано элементы равно [1, 2, 3]
    ожидается 3
  разбор элементы
    случай пусто
      то 0
    случай голова и хвост
      то 1 плюс («Узлов» от хвост)

тотальная функция «Удвоить»
  принимает х: число
  возвращает число
  х умножить на 2

тотальная функция «Прибавить»
  принимает а: число, б: число
  возвращает число
  а плюс б

тотальная функция «Применить дважды»
  принимает ф: функция из числа в число, х: число
  возвращает число
  ф от (ф от х)

тотальная функция «Проба»
  возвращает число
  пример «пятёрка удвоена дважды»
    ожидается 20
  «Применить дважды» от функция «Удвоить» и 5

тотальная функция «Проба с захватом»
  возвращает число
  пример «десятка прибавлена дважды»
    ожидается 25
  «Применить дважды» от (функция «Прибавить» с а равным 10) и 5
```

## 6. Обещания о поведении и что с ними делает компилятор

| Слово | Кто отвечает | Что делает компилятор | Отказ при нарушении |
| --- | --- | --- | --- |
| `тотальная` | компилятор | доказывает завершение одним из пяти способов (ниже); не доказал — файл отвергнут | `FLANG_NOT_TOTAL`, код 1 |
| `убывает В` | автор называет меру | проверяет форму; на каждом витке в напечатанном коде и в вычислителе проверяются строгое убывание, неотрицательность и целость меры | `FLANG_MEASURE` при работе |
| `требует «имя» У` | вызывающий | у каждого вызова внутри программы — обязательство, которое ядро сводит из известного вызывающему; на границе программы (`--args`, примеры, прогонщик) условие вычисляется | `FLANG_PRECONDITION_CALL` при проверке; `FLANG_PRECONDITION` при работе |
| `обеспечивает «имя» У` | функция | ядро пробует доказать для всех входов; доказало — в напечатанном коде проверки нет; не доказало — условие проверяется на каждом возврате | `FLANG_PROPERTY` при работе; заведомо ложное из-за «не числа» — `FLANG_BOUND_ON_NAN` при проверке |
| `пример` | автор | вычисляет при каждой проверке файла (`check`, `test`), сравнивает с `ожидается` | `FLANG_EXAMPLE`, код 1 |
| `теорема` | автор доказательства | ядро проходит шаги; поиска нет, тактик нет | `FLANG_PROOF_*` (см. [справочник отказов](docs/site/diagnostics.ru.md)) |
| `закон` при морфизме, законы моноида и монады | автор | считаются на конечной сетке значений автора двоичным только для категории с объявленным равенством; остальное двоичный не судит | `FLANG_MONOID_*`, `FLANG_MONAD_*`, `FLANG_CATEGORY_*` — в контракте |

Завершение доказывается **композицией** (рекурсии нет), **структурой** (`разбор`
обходит часть значения), **точным шагом** (параметр `неотрицательное`, спуск на
постоянную — без проверки в коде), **постоянным шагом** (то же на `число`,
проверка в коде: на double `х минус 1` может равняться `х`) и **объявленной
мерой** (`убывает`, проверка в коде). Какой способ сработал у какой функции,
печатает `flang check --proof`.

Отчёт `flang check --proof` про каждое утверждение отвечает одним из слов, и
они не взаимозаменяемы: **доказано** (обо всех входах, из объявлений и
структуры), **доказано индукцией по «Т»**, **сетка N** (посчитано на N значениях
автора, нарушений не найдено — это не доказательство), **объявлено, не
доказано** (доказательства нет; условие проверяет рантайм на тех входах, что
придут), **на веру** (не посчитано ничем). Слова печатает функция «Слово
носителя» и соседние в `flang/self/proof.flang`.

Что означает код возврата `flang check`:

| Код | Значение |
| --- | --- |
| 0 | разбор, типы, завершаемость, ядро и примеры — замечаний нет. **Это не значит, что все постусловия доказаны**: недоказанное постусловие без теоремы код не меняет |
| 1 | программа не прошла: отказ назван кодом `FLANG_*`, строкой и столбцом |
| 2 | в программе есть объявления, которых двоичный не судит (раздел 4.6) |
| 3 | только с `--proof`: есть постусловие «объявлено, не доказано» |
| 4 | с `--быстро`: ядро, законы и примеры не запускались; с `--proof --строго`: доказанное оперлось на сетку или недоказанную посылку |

<!-- проверка: код 0 -->
```flang
модуль «Постусловие не доказано»

тотальная функция «Удвоить»
  принимает н: неотрицательное
  возвращает число
  обеспечивает «результат чётен» (результат остаток от 2) равен 0
  н умножить на 2
```

Этот файл проходит `flang check` кодом 0, а `flang check --proof` отвечает
«постусловие «результат чётен» функции «Удвоить» — объявлено, не доказано» и
кодом 3.

Ядро доказательств (`flang/self/proof-kernel.flang`) — небольшой доверенный
слой без аксиом: отдельная проверка `flang io flang/scripts/kernel-forgeries.flang
--plan 'Аксиом ноль'` читает его исходник и требует, чтобы слова «аксиома» там не
было. Что ядро умеет о числах: неотрицательность по построению (литерал,
объявленное дно, `длина`, сумма неотрицательных, произведение при известных
границах обоих сомножителей или строгой положительности одного, квадрат
конечного терма), ограниченность сверху, порядок по допущению, равенство после
подстановки допущений; вычитания в правилах нет, потому что разность натуральных
отрицательна уже на `2 минус 3`. Арифметика — машинная: «не число» лежит в
`число`, поэтому утверждение о порядке над сырой арифметикой ложно, и ядро
называет это контрпримером (`FLANG_BOUND_ON_NAN`). Независимый проверщик записи
доказательства — программа на C без строки flang, `flang/proof/чекер/сверщик.c`
(коды: 0 проверено, 3 проверено не всё, 1 не сошлось, 2 неверен вызов); запись
делает `flang check --proof --записать <файл>`.

### 6.1. Что чекер проверяет сам, а что берёт на слово

Ядро и чекер — две разные программы, и вопрос «доказано ли» распадается надвое:
что установил чекер и что он принял от ядра, не проверяя. Прибор, который это
разделяет, — `flang/proof/доля-корпуса.sh`. Снято на этом дереве 11 сентября 2026
(двоичный 0.7.17 из семени `0ce948bfd`), командой
`sh flang/proof/доля-корпуса.sh --набор корпус --проигрыванием`:

```
записей в наборе  88 (чекер поручился 85, отверг либо не позвал 3)
ЧИСЛИТЕЛЬ — Σ независимо проверенного чекером:                                625
  ├ проиграно ходами/тотальностью:                                            397
  ├ проверено по существу вычислением («по примеру»/«по свойству»):            93
  ├ структурный переигрыш узлов тотальности (дно/спуск по телу функции):       85
  └ переигранные выводы факта о типе (по шагу на правило):                     50
ЗНАМЕНАТЕЛЬ — Σ обязательств корпуса за вычетом недостижимых:                 651
доля-проигрыванием = 625 / 651 = 96.01 %
порог Г4 = 95 %; добрала ли доля порога: ДА
```

Знаменатель 651 — обязательства набора из 88 записей, лежащего в
`flang/proof/чекер/пробы/записи/корпус`, за вычетом 16 недостижимых мест (все 16 —
обязательства трёх отвергнутых записей; отвергнутая запись проигрываться и не
должна, в наборе нарочно лежат подделки). Недостающие 26 расписаны прогоном
поимённо: 16 посылок и утверждений и 4 шага чекер берёт **на слово ядра**, 6 сняты
калькулятором (тождество или разбор), а не игрой. Порог гейта Г4 — 95 %; 100 %
здесь не цель.

Вердикт целиком снимает `sh scripts/доказуемость.sh`: 11 сентября 2026 он печатает
**ДОКАЗУЕМ** и отвечает кодом 0, четырьмя проверками: калькулятор снят
(∀-целей на слове ядра 3 из 3, видов обязательства переиграно 34 из 34); доля
проигрыванием 96,01 % — не ниже 95 %; набор проб пройден (подделок 33 из 33; проб на
подлог 401, кодом 0 не принято ни одной; честных 197, отвергнуто 0); набор не ослаб
против храповика. Правил вывода 88, к 85 из них есть леммы Lean
(`docs/lean-checks-the-inference-rules.md`). Здесь стояло «517 / 665 = 77,74 %,
НЕ ДОКАЗУЕМ, `перепиской` — два вхождения» (замер 8 сентября); это снято той же
перепечаткой семени.

Что эта доля значит и чего не значит: 96 % — доля мест в собственном
доказательстве компилятора (набор записей корпуса), где независимый сверщик
переиграл ход ядра. Это не «96 % программ доказаны». Остаток до 100 % расписан в
`docs/road-to-one-hundred-measured.md`.

## 8. Цели печати

`flang emit --target` принимает десять целей: `c`, `cpp`, `go`, `rust`,
`java`, `js`, `ts`, `elixir`, `python`, `csharp`; неизвестная цель — отказ с
перечнем, код 2. Цель `cpp` пользуется рантаймом цели `c`, цель `ts` — рантаймом
цели `js` (`flang_runtime.js` и прогонщик `flang_cli.js` кладутся рядом с
модулем `.ts` дословно, а вместо `Makefile` печатается `tsconfig.json`: сборка у
неё `tsc -p .`).

**Двоичный про десятую цель молчит, хотя её печатает.** `flang emit --target ts`
отвечает кодом 0 и пишет четыре файла, но `flang emit --help` до сих пор говорит
«во все восемь целей» и перечисляет девять, а отказ на неизвестную цель отвечает
«целей здесь ДЕВЯТЬ» и называет те же девять. Оба текста вшиты в
`flang/src/emit/c/flang_repl.c` и доедут до двоичного только перепечаткой семени
(задача 8596). Число целей здесь снято не со справки, а прогоном: каждая из
десяти позвана на одной и той же программе и напечатала свои файлы.

Рантайм цели читается с диска (`--runtime`, затем `$FLANG_RUNTIME_DIR`, затем
`share/flang/<цель>` рядом с установленным `flang`; в дереве —
`flang/src/emit/<цель>`). Что печатается одинаково во все цели: значения,
пределы шагов и глубины (`FLANG_RECURSION_LIMIT` вместо переполнения стека),
проверки убывания у мер, проверки недоказанных постусловий, дверь предусловия на
границе программы, прогонщик (`--cli`).

Что цели печатают не одинаково:

| Объявление | Печатается в | Иначе |
| --- | --- | --- |
| `процесс`, `надзор`, `прогон` | `c`, `elixir`, `js`, `ts` | отказ, код 1: «у цели нет планировщика конкурентности» |
| `план` | `js` и `ts` (вместе с хозяином `flang_host_node.js`) | `FLANG_PLAN_UNSUPPORTED`, код 1, файлы не пишутся |
| `моноид`, `монада` | все десять | код 3: напечатано, но не судилось |
| `категория`, `морфизм`, `функтор` | все десять | код 0: законы посчитаны на сетке значений автора |

Функции-значения печатаются во все цели: перед печатью один проход
(`flang/self/defunc.flang`) заменяет их ссылками на объявленные функции и
диспетчером по конечному списку, поэтому замыкания целевому языку не нужны.
Параметры типов при печати стираются.

Компилятор печатает и сам себя: `sh scripts/raskrutka.sh` перепечатывает
`flang/self/*.flang` в `bootstrap/`, а `sh scripts/raskrutka.sh --check`
сравнивает перепечатку с закоммиченной. Двоичный из `bootstrap/` собирается
командой `make -C bootstrap` — нужны только `cc` и `make`.

## 9. Ввод-вывод: план, поручение, отклик, продолжение

Программа не ходит в мир сама. Она объявляет **план** — конечный автомат, где
каждый шаг возвращает **продолжение**: либо поручение хозяину и следующее
состояние, либо конец работы.

```
план «Имя»
  состояние «Тип состояния»
  начинает с «Функция без параметров, возвращающая состояние»
  обрабатывает «Функция (состояние, «Отклик») → «Продолжение»»
```

Варианты `«Продолжение»`: `«Сделать»` (поля `поручение: «Поручение»`, `потом` —
следующее состояние), `«Конец работы»` (`значение`), `«Провал»` (`код: строка`,
`сообщение: строка`), `«Не проверено»` (те же два поля). Список — функция
«Варианты продолжения» в `flang/self/parser.flang`.

Варианты `«Поручение»` (функция «Варианты поручения» там же; набор закрыт и
его длину держит постусловие): «Прочитать файл», «Записать файл», «Прочитать
октеты из файла», «Записать октеты в файл», «Удалить файл», «Завести временный
каталог», «Перечислить каталог», «Запросить» (HTTP; `https` двоичный исполняет
внешней программой `curl`), «Открыть соединение», «Принять соединение»,
«Прочитать из соединения», «Ответить в соединение», «Прочитать октеты из
соединения», «Ответить октетами в соединение», «Запустить процесс», «Запустить
процесс с вводом», «Текущее время», «Случайное число», «Показать», «Ждать
событие», «Прочитать переменную среды», «Прочитать доводы».

Варианты `«Отклик»` (функция «Варианты отклика»): «Пока ничего», «Прочитано»,
«Записано», «Ответ сети», «Отметка времени», «Выпало», «Показано», «Случилось»,
«Срок вышел», «Перечислено», «Процесс завершён», «Процесс убит», «Соединение
открыто», «Октеты», «Сбой», «Убрано», «Заведено», «Значение среды», «Переменной
среды нет», «Доводы». Отказ хозяина — не исключение, а отклик «Сбой» с полями
`код` и `сообщение` (`FLANG_IO_DENIED`, `FLANG_IO_READ`, `FLANG_IO_NOT_TEXT`,
`FLANG_IO_NO_SCREEN` и прочие из семейства `FLANG_IO_*`).

```flang
модуль «План записи»

тип «Ход»
  вариант Начало
  вариант Конец

тотальная функция «Начать»
  возвращает «Ход»
  вариант Начало

тотальная функция «Дальше»
  принимает ход: «Ход», отклик: «Отклик»
  возвращает «Продолжение»
  пример «сперва — поручение записать»
    дано ход равно вариант Начало
    дано отклик равно вариант «Пока ничего»
    ожидается вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант Конец)
  разбор ход
    случай Начало
      то вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант Конец)
    случай Конец
      то вариант «Конец работы» с значение равным 6

план «Записать привет»
  состояние «Ход»
  начинает с «Начать»
  обрабатывает «Дальше»
```

```
$ flang io план.flang --in-dir
{"plan":"Записать привет","result":6,"orders":1,"log":[{"поручение":{"variant":"Записать файл","fields":{"путь":"привет.txt","содержимое":"привет"}},"отклик":{"variant":"Записано","fields":{"сколько":6}}}]}
$ flang io план.flang --no-write
{"plan":"Записать привет","result":6,"orders":1,"log":[{"поручение":{…},"отклик":{"variant":"Сбой","fields":{"код":"FLANG_IO_DENIED","сообщение":"хозяину запрещено писать файлы"}}}]}
```

Все функции плана остаются тотальными и проверяются обычными примерами без
файлов и сети. Что хозяин этого двоичного **не исполняет**, хотя парсер эти
поручения знает: «Прочитать доводы» и «Прочитать переменную среды» отвечают
откликом «Сбой» с кодом `FLANG_IO_UNKNOWN` («хозяин не знает поручения»).
Своих доводов план не получает: `flang io план.flang --n=5` — «непонятный ключ»,
код 2; входом плану служат только файлы, сеть и процессы. Код возврата `flang io`
задаёт не программа числом, а вид продолжения: «Конец работы» — 0, «Провал» — 1,
«Не проверено» — 3. Полномочия хозяина сужаются ключами `--no-read`, `--no-write`,
`--no-net`, `--no-clock`, `--no-random`, `--no-spawn`; умолчание — разрешено
всё. Что хозяин на C не умеет и называет отказом: экран (`FLANG_IO_NO_SCREEN`)
и собственное шифрование (`https` — через `curl`, отзыв сертификата не
проверяется; «Открыть соединение» — TCP без TLS; UDP в наборе поручений нет).

## 10. Процессы и надзор

Состояние принадлежит процессу; обработчик — обычная тотальная функция
`(состояние, сообщение) → «Отклик»`, где `«Отклик»` — запись с полями
`состояние` и `действия: список «Действие»`; отправка описывается действием, а
не выполняется. `надзор` описывает решения об отказах данными; `прогон` — пример
конкурентной программы с семенем чередования. Двоичный компилятор эти
объявления сверяет не до конца и отвечает кодом 2 (раздел 4.6); печать — только
в `c`, `elixir`, `js` и `ts`.

## 12. Чего язык не делает

- **Присваивания, переменных, циклов** нет: `пусть` связывает один раз; повтор —
  рекурсия, `свёртка`, `отобразить`, `отфильтровать`.
- **Замыканий и безымянных функций** нет: значение-функция — только объявленная
  функция, захват — только первых параметров по порядку (`функция «Имя» с а
  равным 10`). Тело на месте (`эл → …`) принимают лишь встроенные формы и
  передать его никуда нельзя.
- **Исключений и `null`** нет: отказ — вариант суммы с причиной, «не нашлось» —
  вариант, и `разбор` по нему обязателен.
- **Записи в список по номеру, побитовых операций, округления** нет.
- **Раздельной компиляции** нет: снятие функций-значений и проверка идут по всей
  программе; двух версий одного модуля в программе не бывает.
- **Точные типы не наследуются арифметикой**: `неотрицательное плюс
  неотрицательное` — `число`; `делить на` всегда `число`. Литерала `+∞` нет:
  бесконечность записывается выражением `1 делить на 0`.
- **Ввода-вывода внутри функции** нет ни в каком виде: функция строит
  поручение, исполняет его хозяин. Ожидание, цикл службы, доступ к железу и
  ассемблерная вставка на flang не пишутся.
- **Тактик и поиска доказательств** нет: каждый шаг теоремы обоснован автором.
  Ядро не доказывает свойства идеальных вещественных чисел: арифметика
  IEEE-754, и «не число» — законное значение типа `число`.
- **Формально верифицированным компилятором язык не является**: доверять
  приходится ядру (`flang/self/proof-kernel.flang`), компилятору под ним и
  железу. Код возврата 0 у `flang check` говорит о типах, завершаемости
  и примерах, но не о постусловиях без доказательства — их называет `--proof`.
- **Собранный `bootstrap/flang` не судит** категорную поверхность, монады,
  процессы и надзор (код 2), а также не выносит отказы `FLANG_INFINITY`,
  `FLANG_SCALE`, `FLANG_NOT_A_NUMBER`, описанные контрактом.
- **`flang emit` не прогоняет примеры**: файл, у которого `check` падает на
  `FLANG_EXAMPLE`, печатается кодом 0. Примеры гоняет `flang test`.
- **Регулярных выражений в языке нет** — ни литерала, ни встроенной формы. В
  библиотеке есть два модуля: `flang/stdlib/automaton.flang` — образец строкой,
  разбираемый в конечный автомат без обратных ссылок и без просмотров вперёд и
  назад (`(?=…)`, `(?<=…)` отвергаются названно), — и `flang/stdlib/образцы.flang`
  — закрытый набор видов образца функциями. Классов Юникода вида `\p{L}` нет.
- **Своей криптографии у хозяина нет**: `https` исполняет внешний `curl`, отзыв
  сертификата не проверяется; TCP-соединение открывается без TLS; UDP нет. Стек
  TLS в `docs/examples/https/` — вычислительный, без источника энтропии, и
  защищённого канала не даёт.
