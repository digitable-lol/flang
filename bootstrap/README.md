# Точка раскрутки: компилятор flang, напечатанный в C

Здесь лежит компилятор языка flang, напечатанный в самодостаточный C99. Он нужен
ровно для одного: **собрать работающий компилятор, имея только `cc` и `make`.**
Ни Node, ни самого flang для этого не требуется.

```sh
make -C bootstrap -j4      # cc -std=c99 -Werror -pedantic -O2 -flto
sudo make -C bootstrap install     # или PREFIX=$HOME/.local, без sudo

flang --version
flang check путь/к/файлу.flang
flang run путь/к/файлу.flang --function «Имя» --args '{"х":21}'
flang                              # на терминале — оболочка, под конвейером — прогонщик
```

**Имя выхода — `flang`, а не `flang_cli`.** У программы одно имя на все три
дороги установки: `brew`, `asdf` и сборка из исходников кладут один и тот же файл
под одним и тем же именем. Без `install` он лежит здесь же — `bootstrap/flang`.

Проверено на `cc 13.3.0` и `cc 15.2.0`; никаких зависимостей, кроме `libm` и
`libpthread`.

**Мерьте в чистом каталоге.** Собранный бинарник лежит рядом с исходниками,
`make` видит его свежее и отвечает «nothing to be done», а замер тогда
показывает вчерашний артефакт. Прогон 18 августа на чистой выгрузке:

```sh
git archive HEAD | tar -x -C ПУСТОЙ_КАТАЛОГ
cd ПУСТОЙ_КАТАЛОГ/bootstrap
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 \
   -o flang flang_cli.c flang_repl.c flang_runtime.c compiler_flang.c -lm -lpthread
```

**85,7 с** (время плавает с загрузкой машины — этот замер снят на занятой; байты
— нет), **ни одного предупреждения**, бинарник **7 941 104 байта** (cc 15.2.0,
Linux 7.0.0). Тем же `make -j4` с теми же флагами в том же чистом каталоге —
**82,2 с** и **ровно те же 7 941 104 байта**: единиц трансляции в обоих случаях
четыре, и разница только в том, идут ли они параллельно. `-flto` здесь не стоит
ни в одном из двух прогонов — в `Makefile` он в `CFLAGS ?=`, и заданные снаружи
флаги его снимают.

**Замер 20 августа 2026, обычным `make` — то есть со штатными флагами, включая
`-flto`.** Семь файлов скопированы в каталог вне дерева, `env -i
PATH=/usr/bin:/bin` (node на этом PATH не находится), `make -j8`: **55 с**, **ни
одного предупреждения** при `-Werror -pedantic`, бинарник **12 694 664 байта**.
Он побайтово совпал с закоммиченным `bootstrap/flang`. Байты выросли против
7 941 104 выше по двум причинам сразу: `-flto` и восемь целей печати вместо
одной.

Что двоичный умеет — снято прогоном, а не переписано из справки: `check`,
`test`, `run`, `emit`, `repl`, `--help`, `--version`, и без аргументов —
прогонщик JSON. Прогнано по одной: `check` на 34 функциях, `test` — 55 примеров
из 55, `run` от 21 даёт 42, `emit` печатает 6 файлов и они собираются `make`,
`check --proof` печатает ведомость в 65 строк против 2 без ключа. У `emit` из
бинарника одна названная граница: аргументы прогонщика объявленным типам не
сверяются, и бинарник говорит об этом сам.

## Это артефакт, а не исходник

Исходники компилятора — на flang, в `flang/self/`: лексер, парсер, типы,
завершаемость, печать в C, понижение и связывающий слой
`flang/self/bootstrap/compiler.flang`. Файлы в этом каталоге **порождены** из них
и правке руками не подлежат: правка потеряется при первой перепечатке, а сторож
её и не пропустит.

Числа снимаются прогоном `sh scripts/raskrutka.sh --check`; здесь они на
20 августа 2026, после того как в двоичный въехали все восемь целей печати.

| файл | байт | что это |
|---|---|---|
| `compiler_flang.c` | 19 291 878 | сам компилятор: все слои на flang после связывания |
| `compiler_flang.h` | 3 833 997 | его объявления |
| `flang_repl.c` | 514 493 | человеческий вход: `check`, `test`, `run`, `emit`, `io`, `lsp`, `repl`, `--help`, `--version` |
| `flang_runtime.c` | 150 606 | рантайм: значения, арена, UTF-8, встроенные формы |
| `flang_runtime.h` | 60 567 | заголовок рантайма и `#define` пределов печати |
| `flang_cli.c` | 49 020 | прогонщик: JSON на входе, JSON на выходе |
| `Makefile` | 2 893 | сборка, `make install` и `make uninstall` |
| **итого** | **23 903 454** | 7 файлов, 22,80 МиБ |

Числа связанных функций и типов здесь больше нет, и это не пропуск: их печатал
загрузчик на JavaScript, которого не стало (коммит `fe8e8a37`). Новый инструмент
считает байты — то, на чём стоит побайтовое совпадение, — а не функции.

Четыре файла из семи — не порождённый код, а дословные копии
`flang/src/emit/c/*` с приписанной сверху шапкой (6 строк у `flang_runtime.c`,
10 у `flang_cli.c`, 14 у `flang_runtime.h`; `flang_repl.c` — своя шапка: имя
модуля, пределы, `#define FL_PROGRAM_CALL`). На них приходится 774 686 байт,
**3,2 %** точки; остальные 96,8 % — два файла компилятора.

## Порядок обновления

Точка раскрутки перепечатывается **в том же коммите, что и правка компилятора**:

```sh
sh scripts/raskrutka.sh           # перепечатать (8 ч 34 мин — см. docs/reprint-cost.md)
sh scripts/raskrutka.sh --check   # сверить с исходниками, код 1 при расхождении
sh scripts/raskrutka.sh --stroki  # 0,4 с: все строковые литералы рантайма C закрыты
```

Печатает САМ ДВОИЧНЫЙ, собранный из этого каталога; Node не нужен ни на одном
шаге. Полная команда, которую скрипт и выполняет, — вот она, и все её ключи
обязательны:

```sh
bootstrap/flang emit flang/self/bootstrap/compiler.flang --target c \
  --out <куда> --cli --repl --runtime flang/src/emit/c \
  --max-steps 40000000 --max-depth 20000
```

Без `--max-steps` и `--max-depth` расходится `flang_runtime.h`: эти числа уезжают
прямо в напечатанный байт (`#define FL_MAX_STEPS`), а умолчания рантайма другие
(`1000000` и `10000`). Без `--repl` не печатается `flang_repl.c` — человеческий
вход, — и файлов выходит шесть из семи; `--cli` включён по умолчанию, но назван
явно, чтобы рецепт не зависел от умолчания (с `--no-cli` пропадает и
`flang_cli.c`, остаётся пять). Без
`--runtime` печать находит исходники рантайма только тогда, когда двоичный лежит
ровно в `bootstrap/`, — на один уровень ниже корня дерева; сдвинь его, и будет
«не найдены исходники рантайма C», код 2.

Сверка краснеет на всех четырёх видах расхождения: правка исходника без
перепечатки, правка артефакта руками, пропавший файл, лишний файл от прошлой
печати.

**Чего это стоит.** Раньше сверка шла в наборе тестов
(`flang/test/self-bootstrap.test.mjs`), стоила секунды и не требовала компилятора
C: те же байты печатала реализация на JavaScript. Её удалили, и теперь сверка —
это сама печать: `cc`, `make`, **8 ч 34 мин** и около 28 ГиБ памяти. Дешёвого
второго мнения о печати в дереве больше нет.

**ЧИСЛО «ДВЕНАДЦАТЬ МИНУТ» ЗДЕСЬ СТОЯЛО ДО 2 СЕНТЯБРЯ 2026 И БЫЛО НЕВЕРНО.**
Оно не подтверждается ни одним замером в журнале прогонов: первая дошедшая до
конца печать (23 августа) шла 2 ч 59 мин, последняя (30 августа) — 8 ч 34 мин.
Лестница замеров — [`docs/reprint-cost.md`](../docs/reprint-cost.md), машинный
вид — `docs/reprint-ledger.tsv`.

Ошибка эта дорогая не сама по себе, а тем, что она внушает: читающий видит
«двенадцать минут», меряет восемь часов и заключает, что всё развалилось.
На деле печать выросла примерно втрое за неделю (2 ч 59 мин → 8 ч 34 мин), а
память за то же время упала в девять раз (259 → 27,7 ГиБ). Одного виноватого
коммита нет: росло дерево.

## Почему каталог, а не один склеенный файл

**Потому что каталог — это ровно то, что печатает бэкенд.** `emitC` выдаёт эти
семь файлов, включая Makefile. Склейка потребовала бы своего кода — порядок
заголовков, снятие `#include` — и тогда сторож сверял бы не печать, а склейку,
то есть проверял бы на одно звено меньше, чем обещает. Ценность точки раскрутки
целиком в том, что она **буквально** вывод эмиттера.

Диффы это не удорожает, потому что дешёвых диффов тут не бывает ни в одном виде.
Измерено на настоящем коммите в компилятор (`bdd05ef`, +55/−14 строк в
`flang/self/parser.flang`): напечатанный `compiler_flang.c` изменился на
**32 515 добавленных и 32 368 удалённых строк, 4 188 208 байт текста диффа** —
печать сдвигается целиком, потому что сдвигаются нумерация функций, метки и
порядок. Поэтому каталог помечен `-diff -merge linguist-generated` в
`.gitattributes`: текстовый дифф порождённого C — шум, за которым прячутся
настоящие правки. Правду про артефакт говорит сторож, а не дифф.

Зато в виде каталога 5.4 % точки — рантайм, прогонщик и оболочка — меняются
отдельно от компилятора и своей малой правкой, а `make` собирает единицы
трансляции по отдельности и параллельно.

## Чего стоит держать это в истории

Замерено настоящим git на настоящих двух версиях печати:

| | |
|---|---|
| первый коммит точки | **627 КиБ** пака (11 % от 5.55 МБ: порождённый C сжимается хорошо) |
| одно обновление | **≈303 КиБ** пака |
| пак репозитория сейчас | 33.70 МиБ на 295 коммитов |
| коммитов, правивших компилятор | 59 из 295 — то есть примерно каждый пятый |

То есть держать точку всегда честной стоит около **0.3 МиБ истории на коммит в
компилятор**, а не 4.5 МБ, как кажется по размеру файла. Это дешевле, чем
альтернатива «обновлять только при выпуске»: та экономит порядка 17 МиБ на всей
прошлой истории, но взамен делает сторожа не тем, чем он объявлен — «совпадает с
текущими исходниками» пришлось бы заменить на «совпадает с исходниками той
ревизии, которую артефакт называет», и между выпусками в дереве лежала бы точка,
собирающая **прошлый** компилятор. Выбрана честность: артефакт в дереве всегда
собирает то, что в дереве написано.

Если решение когда-нибудь пересмотрят, дешёвый вариант выглядит так: положить
рядом с печатью манифест с sha256 входных `.flang` и ревизией, сторожу требовать
совпадения печати именно с теми блобами (через `git cat-file`), а перепечатку
делать шагом выпуска. Тогда `sh scripts/raskrutka.sh --check` останется
строгим, но перестанет отвечать на вопрос «а собирает ли это сегодняшний
компилятор» — и ответ на него придётся искать где-то ещё.

## Что это НЕ убирает

Эталон на JavaScript (`flang/src/`) остаётся и остаётся нужным: у 22 316 строк там
соответствия в самоприменении нет — семь генераторов кроме C, интерпретатор,
оболочка, языковой сервер, ведомость доказательства, ограниченность. Снято Node с
пути **сборки** компилятора, а не из проекта.

Релизный архив (`scripts/build-release-c.mjs`) — это тот же каталог плюс
`packaging/flang.1`: печатает его одна и та же функция, поэтому разойтись они не
могут.
