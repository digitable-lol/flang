# flang — описание языка

flang — чистый функциональный язык со строгой статической типизацией. Программа
проверяется до запуска: компилятор разбирает файл, выводит типы, доказывает, что
функции с пометкой `тотальная` завершаются, выполняет unit-тесты, записанные
внутри функций, и пробует доказать постусловия для всех входов. Проверенная
программа вычисляется командой `flang run` или переводится в один из десяти
целевых языков командой `flang emit`.

Страница описывает компилятор версии 0.8.0. Каждый пример-модуль ниже принят
командой `flang check`; о двух из них сказано, что код возврата — 2. Вывод
команд приведён дословно; пропущенные строки, сокращённые пути и числа, которые
меняются от запуска к запуску, отмечены многоточием. Версию выводит
`flang --version`.

## Первая программа

```flang
модуль «Удвоение»

тотальная функция «Удвоить»
  принимает н: число
  возвращает число
  пример «два»
    дано н равно 2
    ожидается 4
  н умножить на 2
```

```
$ flang check удвоение.flang
модуль «Удвоение»: функций 1, из них с доказанным завершением 1; типов 0
удвоение.flang: проверено — доказано 0, проверено только на тестах 0, не доказано 0 (постусловий и утверждений 0); замечаний нет
$ flang run удвоение.flang --function «Удвоить» --args '{"н": 21}'
доказано: утверждений 0
42
```

Вторая строка ответа `flang check` считает постусловия: сколько доказано,
сколько проверено только на тестах и сколько не доказано. Постусловий в этом
файле нет, поэтому везде ноль. «Замечаний нет» значит «ошибок нет». Строка
«доказано: утверждений 0» у `flang run` говорит то же.

Файл начинается строкой `модуль «Имя»`. Ниже, у левого края, стоят объявления;
их порядок свободен, функция может вызывать объявленную ниже. `пример` внутри
функции — unit-тест: он выполняется при каждой проверке файла.

## Словарь: слова flang и привычные термины

| Во flang | Привычное название | Ближайший аналог |
| --- | --- | --- |
| `объект`, `запись` | структура с полями и её значение | struct, dataclass |
| `тип` с `вариант`ами | enum с данными, tagged union | `enum` в Rust, union в TypeScript |
| `разбор … случай` | pattern matching | `match` в Rust и Python |
| `если … то … иначе` | if как выражение | тернарный оператор |
| `пусть` | константа | `const` |
| `отобразить`, `отфильтровать`, `свёртка` | map, filter, reduce | то же в JavaScript и Python |
| `цикл` | цикл с именованными переменными состояния | `for` и `while` |
| `пример` | unit-тест внутри функции | doctest |
| `требует` | предусловие (precondition): что должно быть верно на входе | assert в начале функции |
| `обеспечивает` | постусловие (postcondition): что верно для результата | assert в конце, проверенный для всех входов |
| `тотальная функция` | функция, про которую компилятор доказал, что она завершается | — |
| `утверждение` | условие, записанное отдельно от функции | property в property-based тестах, но доказанное |
| `теорема`, `следует` | доказательство, которое пишет автор | — |
| `план` | side effects: функция возвращает команду, хост её выполняет | reducer, state machine |
| `процесс` | actor с состоянием и очередью сообщений | процесс в Erlang и Elixir |
| `использует` | import | `import` |

Слова, которые выводит компилятор:

| В выводе написано | Что это значит |
| --- | --- |
| «ядро» | ядро доказательств — часть компилятора, которая доказывает постусловия |
| «постусловие», «предусловие» | строки `обеспечивает` и `требует` |
| «утверждений N», «постусловий и утверждений N» | сколько постусловий и отдельных утверждений в программе |
| «доказано» | верно для всех возможных входов |
| «проверено только на тестах», «сетка N» | есть только N unit-тестов, доказательства нет |
| «не доказано», «объявлено, не доказано» | нет ни доказательства, ни тестов |
| «на веру» | принято без доказательства; у `flang run` — программа запущена без проверки доказательств |
| «мера» | величина, которая убывает на каждом рекурсивном вызове |
| «сторож» | проверка во время выполнения, оставленная в программе |
| «ведомость» | подробный отчёт команды `flang check --proof --explain` |
| «независимая проверка», «сверщик» | отдельная программа `checker`, которая перепроверяет доказательства |
| «хозяин», «поручение», «отклик» | хост команды `flang io`, команда ему и его ответ |
| «напечатано» | сгенерирован код на целевом языке |
| «замечание», «отказ» | ошибка |

## Синтаксис

Расширений файла четыре, они равноправны: `.flang`, `.fp`, `.фп`, `.фланг`.

Блок задаётся отступом. Круглые скобки группируют выражения, и строка с незакрытой
круглой скобкой продолжается следующими строками до закрывающей.

Имена модулей, функций, типов, вариантов, тестов и утверждений пишутся в ёлочках:
`«Сумма до»`. Имя параметра, константы и поля — одно слово без кавычек или тоже
имя в ёлочках. Ключевое слово именем быть не может:

```
$ flang check занятое.flang
FLANG_PARSE в файле занятое.flang, строка 6, столбец 3: не разобрана конструкция: неожиданное 'с' — это слово занято языком, именем оно быть не может: напишите имя в ёлочках («с») или переименуйте; а если слово попало в форму лишним — уберите его
занятое.flang: не проверено — замечаний 1
```

Ключевое ли слово, отвечает `flang tokens --keyword «слово»`.

| Литерал | Запись |
| --- | --- |
| число | `12`, `0.5`, `-3` |
| строка | `"текст"` или `'текст'`; escape-последовательности `\"`, `\\`, `\n` |
| блок текста | `"""` в конце строки, текст со следующей строки; общий отступ снимается |
| boolean | `да`, `нет` |
| пустое значение | `ничто` |
| список | `[1, 2, 3]`, `список из 1 и 2 и 3`, `пустой список` |

Стрелка `→` набирается также `->` и `=>`. Строка, начинающаяся с `//`, —
комментарий. Причину, которая должна остаться в коде, пишут термом
`примечание "текст"` у левого края между объявлениями: он не вычисляется, не
порождает обязательств и в сгенерированный код не попадает.

У каждого ключевого слова четыре написания — русское, английское, эсперанто и
китайское. Лексер сводит их к одному токену, поэтому одна программа на четырёх
языках даёт одно AST:

```
$ flang tokens --keyword если
«если» — ключевое слово, конструкция «if»
$ flang tokens --keyword 如果
«如果» — ключевое слово, конструкция «if»
```

```flang
module «Doubling»

total function «Double»
  accepts n: number
  returns number
  example «two»
    given n equals 2
    expected 4
  n times 2
```

Имена функций, типов и модулей не переводятся. Таблица всех слов —
[`glossary.md`](glossary.md), правила для четырёх языков —
[`surfaces.md`](surfaces.md).

## Типы

Значение — скаляр, список, структура или вариант enum. Числовые типы, кроме точных,
хранятся как IEEE-754 double; типы уже, чем `число`, — это ограничения на
значение, которые проверяет компилятор.

| Тип | Значения |
| --- | --- |
| `число` | любой double, включая бесконечности и NaN |
| `неотрицательное` (`нат`, `натуральное`) | целые от 0 до 2⁵³−1 |
| `целое` | целые от −(2⁵³−1) до 2⁵³−1 |
| `вес` (`стоимость`) | число не меньше нуля, включая +∞ |
| `сотых`, `тысячных` | целое число сотых или тысячных долей; для денег |
| `точное целое` | целое без потолка, неотрицательное; раздел ниже |
| `точное дробное` | дробь без потери точности, неотрицательная; раздел ниже |
| `точное целое со знаком` | целое со знаком без потолка, как `int` в Python; раздел ниже |
| `строка` | строка UTF-8; символ — строка из одного code point |
| `признак` | boolean: `да`, `нет` |
| `ничто` | одно значение `ничто` |
| `список Т` | однородный список |
| `«Имя»`, объявленное словом `объект` | структура с именованными полями |
| `«Имя»`, объявленное словом `тип` | enum с данными |
| `«Имя» от Т` | generic-тип |
| `функция из Т в Т` | ссылка на объявленную функцию |

`дата` и `деньги` — старые слова: `дата` ведёт себя как `строка`, `деньги` — как
`число`.

`неотрицательное` годится там, где ждут `целое` или `число`; обратно — нет.
`список неотрицательное` годится там, где ждут `список числа`.

Арифметика узкий тип не сохраняет: сумма двух `неотрицательное` и любое
деление имеют тип `число`.

```
$ flang check сумма.flang
…
FLANG_TYPE в файле сумма.flang, строка 6, столбец 5: функция «Сумма» объявлена как неотрицательное, а тело даёт число
сумма.flang: не проверено — замечаний 1
```

Узкий тип получают литерал, `длина`, `код символа` и `если`, у которого обе
ветки узкие:

```flang
модуль «Узкие типы»

тотальная функция «Длина слова»
  принимает слово: строка
  возвращает неотрицательное
  длина слово

тотальная функция «Ноль или пять»
  принимает н: число
  возвращает неотрицательное
  если н не больше 0
    то 0
    иначе 5
```

Аргументы `flang run` сверяются с объявленными типами до вычисления:

```
$ flang run целое.flang --function «Целое» --args '{"а": 1.5, "б": 1, "в": 2}'
доказано: утверждений 0
FLANG_TYPE: вызов функции «Целое»: аргумент «а»: 1.5 не целое, а тип целое — целый
```

Деление на ноль даёт бесконечность, `0 делить на 0` — NaN. Сравнение с NaN
ложно в обе стороны. Минус ноль и ноль не равны: `-0 равен 0` — `нет`.

### Точные целые и дроби

`число` за 2⁵³ теряет единицы: 9007199254740993 в double не записать, а
`(0.1 плюс 0.2) плюс 0.3` и `0.1 плюс (0.2 плюс 0.3)` дают 0.6000000000000001 и
0.6. Для счёта, где нужна каждая единица, есть три точных типа без потолка:

| Тип | Запись значения |
| --- | --- |
| `точное целое` | список разрядов по основанию 2²² = 4 194 304, младший первым: `[1, 0, 512]` — это 2⁵³ + 1; ноль — `[]` |
| `точное дробное` | пара точных целых, числитель над знаменателем: `[[1], [3]]` — треть; ноль — `[[], [1]]` |
| `точное целое со знаком` | формой перевода: `точное целое со знаком -7`, за 2⁵³ — строкой цифр: `точное целое со знаком "-1180591620717411303424"` |

Первые два неотрицательны. Ни один из трёх с `число` не смешивается без
перевода.

| Тип | Действия |
| --- | --- |
| `точное целое` | `плюс`, `минус`, `умножить на`, `остаток от`, сравнения |
| `точное дробное` | `плюс`, `минус`, `умножить на`, `делить на`, сравнения, `целая часть` (даёт точное целое) |
| `точное целое со знаком` | `плюс`, `минус`, `умножить на`, `делить на`, `остаток от`, сравнения |

Деление точного целого со знаком округляет вниз, как `//` и `%` в Python:
`−7 делить на 2` — `−4`, `−7 остаток от 2` — `1`. Ответ дроби всегда сокращён:

```flang
модуль «Точные дроби»

тотальная функция «Сумма»
  принимает а: точное дробное, б: точное дробное
  возвращает точное дробное
  пример «шестая плюс треть — половина»
    дано а равно [[1], [6]]
    дано б равно [[1], [3]]
    ожидается [[1], [2]]
  а плюс б

тотальная функция «Разность»
  принимает а: точное дробное, б: точное дробное
  возвращает точное дробное
  а минус б

тотальная функция «Ниже нуля»
  возвращает точное дробное
  «Разность» от [[1], [3]] и [[1], [2]]
```

Вычитание ниже нуля и деление на нулевую дробь — ошибки, а не значения:

```
$ flang run точные-дроби.flang --function '«Ниже нуля»'
доказано: утверждений 0
FLANG_PROPERTY: точное дробное ниже нуля значений не имеет: [1] над [3] минус [1] над [2]; молчаливый ноль запрещён
```

Записанный литерал проверяется: `[[2], [4]]` — ошибка «дробь не сокращена»,
`[7, 0]` — ошибка за старший ноль. Оба типа генерируются во все десять целевых
языков и дают там тот же ответ, что `flang run`.

Точное целое со знаком:

```flang
модуль «Знак»

тотальная функция «Частное»
  принимает а: точное целое со знаком, б: точное целое со знаком
  возвращает точное целое со знаком
  требует «делитель не ноль» б не равен 0
  пример «минус семь на два»
    дано а равно точное целое со знаком -7
    дано б равно точное целое со знаком 2
    ожидается точное целое со знаком -4
  а делить на б

тотальная функция «Большое»
  возвращает строка
  пример «за два в пятьдесят третьей»
    ожидается "-3541774862152233910272"
  к строке ((точное целое со знаком "-1180591620717411303424") умножить на 3)
```

```
$ flang run знак.flang --function '«Большое»'
доказано: утверждений 0
"-3541774862152233910272"
$ flang run знак.flang --function '«Частное»' --args '{"а": -7, "б": 2}'
доказано: утверждений 0
null
```

Примеры считаются верно, а `flang run` выводит результат этого типа как `null`.
Чтобы увидеть значение, переведите его формой `к строке`. Деление без
`требует` на делитель даёт предупреждение `FLANG_NOT_TOTAL`. Постусловия над
этим типом ядро не доказывает, см. «Ограничения».

### Слова фиксированной ширины

`u8`, `u16`, `u32`, `u64` и `i8` … `i64` — целые ровно в 8, 16, 32 или 64 бита,
знаковые — в дополнительном коде. С `число`, `целое` и словом другой ширины в
одном действии они не смешиваются: `FLANG_TYPE`. Литерал пишется с типом:
`u32 5`.

```flang
модуль «Слова»

тотальная функция «Младший байт»
  принимает слово: u32
  возвращает u32
  пример «от 0x1234 остаётся 0x34»
    дано слово равно u32 4660
    ожидается u32 52
  слово побитовое и 255

тотальная функция «Сложить по кругу»
  принимает а: u8, б: u8
  возвращает u8
  пример «250 и 10 дают 4»
    дано а равно u8 250
    дано б равно u8 10
    ожидается u8 4
  а плюс б с переполнением

тотальная функция «Перемешать»
  принимает а: u8
  возвращает u8
  пример «биты единицы»
    дано а равно u8 1
    ожидается u8 245
  побитовое не ((((а сдвиг влево на 3) побитовое или 1) исключающее или 3) поворот вправо на 0)

тотальная функция «Обмен половин»
  принимает а: u8
  возвращает u8
  пример «0x1F становится 0xF1»
    дано а равно u8 31
    ожидается u8 241
  ((а поворот влево на 4) сдвиг вправо на 0)

тотальная функция «Старшая половина произведения»
  принимает а: u8, б: u8
  возвращает u8
  пример «200 на 200 — это 156 в старшем байте»
    дано а равно u8 200
    дано б равно u8 200
    ожидается u8 156
  (а умножить на б с двойной разрядностью).старшая
```

| Действие | Ответ |
| --- | --- |
| `плюс`, `минус`, `умножить на`, `делить на`, `остаток от` | точный результат; не помещается в тип — `FLANG_OVERFLOW` |
| `а плюс б с переполнением` (и `минус`, `умножить на`) | результат по модулю 2^w |
| `побитовое и`, `побитовое или`, `исключающее или`, `побитовое не` | побитово |
| `сдвиг влево на`, `сдвиг вправо на` | сдвиг на `n` меньше ширины; вправо у знаковых — арифметический |
| `поворот влево на`, `поворот вправо на` | циклический сдвиг |
| `а умножить на б с двойной разрядностью` | у беззнаковых — запись с полями `старшая` и `младшая`: полное произведение |

Без слов `с переполнением` сумма `u8 250` и `u8 10` — ошибка, а не 4:

```
FLANG_OVERFLOW: 250 «add» 10 не помещается в u8
```

## Функции и завершаемость

```
[тотальная] функция «Имя» [от «П»]
  [принимает имя: Тип, имя: Тип]
  возвращает Тип
  [требует «имя» Условие]
  [убывает Выражение]
  [обеспечивает «имя» Условие]
  [пример «имя»
    дано имя равно Значение
    ожидается Значение]
  Тело
```

Части идут в этом порядке. Тело — одно выражение: `если … то … иначе …`,
`разбор`, `свёртка`, вызов, арифметика, конструктор; перед ним могут стоять
строки `пусть имя равно Выражение`. Ветка `иначе` обязательна. Присваивания
нет: повторное `пусть` с тем же именем заводит новую константу.

Вызов — `«Имя» от А и Б`. Слово `и` разделяет аргументы; логическое «и» —
`и притом`.

| Группа | Слова |
| --- | --- |
| арифметика | `плюс`, `минус`, `умножить на`, `делить на`, `остаток от`, `процентов от` |
| сравнение | `равен`, `не равен`, `больше`, `меньше`, `не больше`, `не меньше` |
| логика | `не`, `и притом`, `или` |

Слово `тотальная` требует от компилятора доказать, что функция завершается на
любом входе. Способов пять. `flang check --proof --explain` называет способ у
каждой функции:

```flang
модуль «Завершаемость»

тотальная функция «Квадрат»
  принимает х: число
  возвращает число
  х умножить на х

тотальная функция «Узлов»
  принимает места: список числа
  возвращает число
  пример «три элемента»
    дано места равно [1, 2, 3]
    ожидается 3
  разбор места
    случай пусто
      то 0
    случай голова и хвост
      то 1 плюс («Узлов» от хвост)

тотальная функция «Сумма до»
  принимает н: неотрицательное
  возвращает число
  пример «до четырёх»
    дано н равно 4
    ожидается 10
  если н не больше 0
    то 0
    иначе н плюс («Сумма до» от (н минус 1))

тотальная функция «Отсчёт»
  принимает н: число
  возвращает число
  если н не больше 0
    то 0
    иначе «Отсчёт» от (н минус 1)

тотальная функция «НОД»
  принимает а: число, б: число
  возвращает число
  убывает б
  пример «двенадцать и восемнадцать»
    дано а равно 12
    дано б равно 18
    ожидается 6
  если б равен 0
    то а
    иначе «НОД» от б и (а остаток от б)
```

| Функция | Способ, в выводе | Проверка во время выполнения |
| --- | --- | --- |
| «Квадрат» | «композицией»: рекурсии нет | нет |
| «Узлов» | «структурой»: рекурсивный вызов получает часть аргумента | нет |
| «Сумма до» | «точным шагом»: параметр `неотрицательное` убывает на 1 | нет |
| «Отсчёт» | «постоянным шагом»: параметр `число` убывает на константу | есть |
| «НОД» | «объявленной мерой»: автор написал `убывает б` | есть |

У первых трёх способов завершение доказано. У двух последних в программе
остаётся проверка во время выполнения: на каждом рекурсивном вызове величина
обязана строго убывать. Убывание меры `убывает б` над типом `число` ядро не
выводит и принимает без доказательства. Поэтому `flang check --proof` отвечает
на этом файле кодом 3:

```
$ flang check завершаемость.flang --proof
модуль «Завершаемость»: функций 5, завершение доказано у 3, без доказательства завершения: 2
…
```

`flang run` такую программу запускает только с ключом `--trust` или
`--unproven warn`. Нарушение меры останавливает вычисление:

```
$ flang run завершаемость.flang --function «НОД» --args '{"а": 12, "б": -1.5}' --trust
на веру: доказанность не считалась — запуск по ключу --trust
FLANG_MEASURE: тотальная функция «НОД»: мера на вызове «НОД» — «б» — не убыла. Завершение доказано тем, что она строго убывает; равенство цепочку не обрывает, а значит этот вызов может не кончиться никогда
```

Функцию, для которой завершаемость не доказана, компилятор с пометкой
`тотальная` не принимает:

```
$ flang check вечно.flang
…
FLANG_NOT_TOTAL в файле вечно.flang, строка 6, столбец 3: тотальная функция «Вечно»: рекурсивный вызов «Вечно» не убывает — аргумент 1 («н» add 1) увеличивает параметр «н». Передавайте часть аргумента: хвост списка из образца «голова и хвост», поле варианта из образца, поле записи или элемент коллекции
вечно.flang: не проверено — замечаний 1
```

Без слова `тотальная` та же функция проходит проверку, а при вычислении
останавливается на лимите шагов с ошибкой `FLANG_RECURSION_LIMIT`, код
возврата 1.

Функцию можно передать аргументом. Значение-функция — ссылка на объявленную
функцию, возможно с заданными первыми параметрами. Анонимных функций нет. Тело
после стрелки `→` пишется только внутри встроенных форм `отобразить`,
`отфильтровать` и `свёртка`; там оно видит параметры своей функции. Своей
функции такое тело не передать: `«Применить дважды» от (у → у плюс 1) и 5` —
ошибка `FLANG_UNKNOWN_NAME`.

```flang
модуль «Функции как значения»

тотальная функция «Удвоить»
  принимает х: число
  возвращает число
  х умножить на 2

тотальная функция «Прибавить»
  принимает а: число, б: число
  возвращает число
  а плюс б

тотальная функция «Применить дважды»
  принимает ф: функция из числа в число, х: число
  возвращает число
  ф от (ф от х)

тотальная функция «Проба»
  возвращает число
  пример «пятёрка удвоена дважды»
    ожидается 20
  «Применить дважды» от функция «Удвоить» и 5

тотальная функция «Проба с захватом»
  возвращает число
  пример «десятка прибавлена дважды»
    ожидается 25
  «Применить дважды» от (функция «Прибавить» с а равным 10) и 5
```

## Структуры и enum

```flang
модуль «Счёт»

объект «Позиция»
  название является строкой
  цена является числом
  скидка иногда является числом

тип «Счёт» это список «Позиция»

тип «Ответ»
  вариант Успех содержит значение: число
  вариант Отказ содержит причина: строка

тотальная функция «Проверить цену»
  принимает позиция: «Позиция»
  возвращает «Ответ»
  пример «цена есть»
    дано позиция равно запись «Позиция» с название равным "болт" и цена равным 30
    ожидается вариант Успех с значение равным 30
  пример «ноль — не цена»
    дано позиция равно запись «Позиция» с название равным "гайка" и цена равным 0
    ожидается вариант Отказ с причина равным "цена не положительна"
  если позиция.цена больше 0
    то вариант Успех с значение равным позиция.цена
    иначе вариант Отказ с причина равным "цена не положительна"

тотальная функция «Итог счёта»
  принимает счёт: «Счёт»
  возвращает число
  пример «две позиции»
    дано счёт равно [запись «Позиция» с название равным "болт" и цена равным 30, запись «Позиция» с название равным "гайка" и цена равным 12]
    ожидается 42
  свёртка счёт начиная с 0 как итог и позиция → итог плюс позиция.цена
```

`объект «Имя»` объявляет структуру; то же слово — `структура`. Поле
записывается `имя является Тип` или `«имя»: Тип`; поле `иногда является` —
необязательное. Значение строится формой `запись «Имя» с поле равным Значение
и поле равным Значение`, поле читается через точку или словами
`поле имя у значение`. Лишнее поле — ошибка:

```
$ flang check поле.flang
…
FLANG_TYPE в файле поле.flang, строка 8, столбец 3: запись «Точка» не имеет поля «зет»
поле.flang: не проверено — замечаний 1
```

`тип «Имя»` с вариантами объявляет enum с данными, `тип «Имя» это Тип` —
type alias. Значение enum строится формой `вариант Имя с поле равным Значение`.

Generic-тип объявляется и применяется словом `от`:

```flang
модуль «Возможное значение»

тип «Возможно» от «А»
  вариант «Есть» содержит значение: «А»
  вариант «Нет»

тотальная функция «Обернуть» от «А»
  принимает значение: «А»
  возвращает «Возможно» от «А»
  вариант «Есть» с значение равным значение

тотальная функция «Значение или ноль»
  принимает возможное: «Возможно» от число
  возвращает число
  пример «есть — значение»
    дано возможное равно вариант «Есть» с значение равным 7
    ожидается 7
  пример «нет — ноль»
    дано возможное равно вариант «Нет»
    ожидается 0
  разбор возможное
    случай вариант «Есть» с значение как найденное
      то найденное
    случай «Нет»
      то 0
```

Исключений нет, и nullable-типов нет: `число` не может быть `ничто`, ветки
`если` с типами `число` и `ничто` — ошибка `FLANG_TYPE`. Значение, которого
может не быть, описывает тип вида Optional, как «Возможно» выше; ошибку — тип
вида Result, как «Ответ».

## Pattern matching: `разбор`

`разбор` выбирает ветку по варианту enum, по форме списка или строки.

| Pattern | Что берёт |
| --- | --- |
| `случай Имя` | вариант, поля не нужны |
| `случай вариант Имя с поле как имя` | вариант, поле получает имя |
| `случай пусто` | пустой список или пустая строка |
| `случай голова и хвост` | первый элемент (первый символ) и остаток |
| `случай любое` | всё остальное |

Компилятор проверяет, что разобраны все варианты и что каждая ветка достижима:

```
$ flang check светофор.flang
…
FLANG_MATCH_NOT_EXHAUSTIVE в файле светофор.flang, строка 11, столбец 3: разбор «Свет» не покрывает «Жёлтый»
светофор.flang: не проверено — замечаний 1
$ flang check порядок.flang
…
FLANG_MATCH_UNREACHABLE: случай недостижим: предыдущий случай «любое» покрывает всё
порядок.flang: не проверено — замечаний 1
```

Рекурсивный вызов от части разобранного значения — от `хвост` или от поля
варианта — компилятор принимает как доказательство завершаемости; так устроена
функция «Узлов» выше.

## Списки: map, filter, reduce

Список обходят `отобразить` (map), `отфильтровать` (filter), `свёртка`
(reduce), рекурсия по `голова и хвост` и `цикл`. Список неизменяем: каждая
операция строит новый.

```flang
модуль «Списки»

тотальная функция «Произведение»
  принимает множители: список числа
  возвращает число
  пример «три множителя»
    дано множители равно [2, 3, 4]
    ожидается 24
  свёртка множители начиная с 1 как итог и множитель → итог умножить на множитель

тотальная функция «Квадраты»
  принимает стороны: список числа
  возвращает список числа
  пример «три квадрата»
    дано стороны равно [1, 2, 3]
    ожидается [1, 4, 9]
  отобразить стороны как сторона → сторона умножить на сторона

тотальная функция «Положительные»
  принимает остатки: список числа
  возвращает список числа
  пример «ноль и минус выброшены»
    дано остатки равно [3, 0, -1, 5]
    ожидается [3, 5]
  отфильтровать остатки где остаток → остаток больше 0

тотальная функция «Наоборот»
  принимает места: список числа
  возвращает список числа
  пример «три числа наоборот»
    дано места равно [1, 2, 3]
    ожидается [3, 2, 1]
  свёртка места начиная с пустой список как итог и место → приписать место к итог
```

| Операция | Значение |
| --- | --- |
| `длина Л` | число элементов |
| `голова Л`, `хвост Л` | первый элемент и остаток |
| `элемент N в Л` | элемент с номером N; нумерация с единицы |
| `добавить Х к Л` | новый список с Х в конце |
| `приписать Х к Л` | новый список с Х в начале |
| `Л содержит Х` | есть ли Х в списке |

Индекс вне границ останавливает вычисление. `flang check` о таком месте в
тотальной функции предупреждает и отвечает кодом 0; с ключами
`--proof --strict` предупреждение становится ошибкой:

```
$ flang check границы.flang
…
FLANG_NOT_TOTAL в файле границы.flang, строка 5, столбец 3: функция «Пятый» объявлена тотальной, а встроенная операция «элемент» может отказать при работе: номер может выйти за список; …
…
$ flang run границы.flang --function «Пятый»
доказано: утверждений 0
FLANG_BUILTIN_ARGS: «элемент»: индекс 5 вне списка длиной 3
```

### Цикл

`цикл «Имя»` — запись обхода с переменными состояния. Компилятор разворачивает
его в свёртку или в рекурсивную функцию, присваивания в языке при этом нет.

```flang
модуль «Средняя цена»

тотальная функция «Средняя»
  принимает цены: список числа
  возвращает число
  пример «три цены»
    дано цены равно [100, 250, 100]
    ожидается 150
  пример «пустой список»
    дано цены равно []
    ожидается 0
  цикл «Подсчёт»
    для каждого цена из цены
    храним сумма: число равным 0, штук: число равным 0
    в конце если штук равен 0 то 0 иначе сумма делить на штук
    дальше: сумма станет сумма плюс цена, штук станет штук плюс 1
```

```
$ flang run средняя.flang --function «Средняя» --args '{"цены": [100, 250, 100]}'
доказано: утверждений 0
150
```

| Строка | Что задаёт |
| --- | --- |
| `для каждого имя из Список` | обход списка |
| `пока Условие` с `убывает Выражение` или `шагов не больше N, иначе …` | цикл по условию; без границы — ошибка `FLANG_SUGAR_LOOP` |
| `храним имя: Тип равным Значение` | переменные состояния и их начальные значения |
| `дальше: имя станет Выражение` | значения на следующем шаге |
| `в конце Выражение` | результат цикла |

У цикла четыре ограничения. Постусловие функции, записанной циклом, ядро не
доказывает: оно остаётся проверенным только на тестах. Убывание меры у цикла
`пока` над типом `число` принимается без доказательства, как у «НОД» выше. Имя
цикла должно быть одно на модуль: два цикла «Счёт» в разных функциях — ошибка
`FLANG_TYPE` «тип «Счёт — состояние» объявлен дважды». Переменная
`храним сумма: неотрицательное` суммой не обновляется: сумма имеет тип `число`.

Функции над списками, словарями и множествами — в стандартной библиотеке:
[`site/stdlib.ru.md`](site/stdlib.ru.md).

## Строки

Строка разбирается теми же patterns, что список: `пусто` и `голова и хвост`.
Длина и индексы считаются в code points, не в байтах.

```flang
модуль «Строки»

тотальная функция «Слова»
  принимает текст: строка
  возвращает список строки
  пример «по пробелу»
    дано текст равно "раз два три"
    ожидается ["раз", "два", "три"]
  разделить текст по " "

тотальная функция «Через запятую»
  принимает слова: список строки
  возвращает строка
  пример «три слова»
    дано слова равно ["раз", "два", "три"]
    ожидается "раз, два, три"
  соединить слова по ", "

тотальная функция «Середина»
  принимает текст: строка
  возвращает строка
  пример «со второго по четвёртый символ»
    дано текст равно "привет"
    ожидается "рив"
  подстрока текст с 2 по 4

тотальная функция «Гласных»
  принимает текст: строка
  возвращает число
  пример «в слове привет две гласные»
    дано текст равно "привет"
    ожидается 2
  разбор текст
    случай пусто
      то 0
    случай голова и хвост
      то (если "аеёиоуыэюя" содержит голова то 1 иначе 0) плюс («Гласных» от хвост)
```

| Операция | Значение |
| --- | --- |
| `длина С` | число символов |
| `символ N в С` | символ с номером N; нумерация с единицы |
| `подстрока С с А по Б` | символы с А по Б включительно |
| `разделить С по Р` | split: список строк |
| `соединить Л по Р` | join: список строк в одну строку через Р |
| `соединить А с Б` | конкатенация двух строк |
| `С содержит П`, `С начинается с П` | boolean |
| `код символа С`, `символ по коду N` | code point и обратно |
| `разложить С на символы` | список символов |
| `к числу С`, `к строке Х` | преобразование |
| `хеш256 С` | SHA-256 в шестнадцатеричной записи |
| `к числу или беда С` | разбор числа без остановки: вариант «Разобрано» или «Не разобрано» |

`к числу` на строке, которая не число, останавливает вычисление.
`к числу или беда` не останавливает никогда: ошибка возвращается значением.

```flang
модуль «Разбор числа»

тотальная функция «Число или ноль»
  принимает текст: строка
  возвращает число
  пример «разобрано»
    дано текст равно "42"
    ожидается 42
  пример «не разобрано»
    дано текст равно "сорок два"
    ожидается 0
  разбор (к числу или беда текст)
    случай вариант «Разобрано» с значение как н
      то н
    случай вариант «Не разобрано» с код как код и сообщение как весть
      то 0
```

Блок текста записывает строку в несколько строк внутри отступа. Три двойные
кавычки стоят в конце строки, текст начинается со следующей, общий отступ
строк снимается; закрывающие кавычки на своей строке добавляют перевод строки в
конце значения:

```flang
модуль «Справка»

тотальная функция «Справка»
  возвращает строка
  пример «отступ снят»
    ожидается "Команды:\n  .помощь   эта справка\n"
  """
  Команды:
    .помощь   эта справка
  """
```

Escape-последовательности в блоке те же, что в `"…"`; кавычки внутри пишутся
как есть. Незакрытый блок и знак после открывающих кавычек — ошибка
`FLANG_LEX`.

Регулярных выражений среди конструкций языка нет; сопоставление со
строкой-шаблоном дают модули стандартной библиотеки.

## Доказательства

### Precondition и postcondition

`требует «имя» Условие` — предусловие: что должно быть верно на входе.
`обеспечивает «имя» Условие` — постусловие: что верно для значения
`результат`. Имя обязательно.

```flang
модуль «Гарантии»

тотальная функция «Длина слова»
  принимает слово: строка
  возвращает число
  обеспечивает «длина неотрицательна» результат не меньше 0
  длина слово

тотальная функция «Удвоить»
  принимает н: неотрицательное
  возвращает число
  обеспечивает «результат чётен» (результат остаток от 2) равен 0
  пример «три удвоено»
    дано н равно 3
    ожидается 6
  н умножить на 2
```

```
$ flang check гарантии.flang --proof
модуль «Гарантии»: функций 2, завершение доказано у 2
постусловие «длина неотрицательна» функции «Длина слова» — доказано
постусловие «результат чётен» функции «Удвоить» — проверено только на тестах (примеров 1)
итог: постусловий и утверждений 2 — доказано 1, проверено только на тестах 1, не доказано 0
гарантии.flang: доказано не всё — … независимая проверка повторила 1 из 1 — код возврата 3
подробный отчёт: flang check гарантии.flang --proof --explain
```

Первое постусловие ядро доказало для всех входов. Второе не доказано: у него
есть только unit-тест. Недоказанное постусловие остаётся в программе как
проверка во время выполнения на каждом возврате из функции; нарушение — ошибка
`FLANG_PROPERTY`. «Независимая проверка повторила 1 из 1» — программа `checker`
перепроверила одно доказанное постусловие из одного. Ключ `--explain` выводит
подробный отчёт: у каждого доказанного постусловия названо правило вывода.

Постусловие, ложное на NaN, компилятор отвергает и называет контрпример:

```
$ flang check ложное.flang
…
FLANG_BOUND_ON_NAN в файле ложное.flang, строка 6, столбец 3: постусловие «результат меньше ста» функции «Увеличить» ЛОЖНО, и контрпример назван: «н» объявлен типом «число», а «не число» живёт в этом типе и стоит ВНЕ ПОРЯДКА …
ложное.flang: не проверено — замечаний 1
```

Предусловие обязан выполнить вызывающий код. Для каждого вызова внутри
программы ядро доказывает предусловие из того, что известно в месте вызова: из
аргумента-литерала, из типа аргумента, из предусловия самой вызывающей
функции.

```flang
модуль «Предусловие»

тотальная функция «Доля»
  принимает часть: число, целое: число
  возвращает число
  требует «делитель не меньше единицы» целое не меньше 1
  часть делить на целое

тотальная функция «Половина»
  принимает часть: число
  возвращает число
  пример «половина десяти»
    дано часть равно 10
    ожидается 5
  «Доля» от часть и 2

тотальная функция «Любая доля»
  принимает часть: число, целое: число
  возвращает число
  требует «делитель не меньше единицы» целое не меньше 1
  «Доля» от часть и целое
```

Вызов, для которого предусловие доказать не из чего, — ошибка
`FLANG_PRECONDITION_CALL`, код возврата 1.

### Результаты проверки

`flang check --proof` выводит по строке на каждое постусловие и каждое
утверждение.

| В выводе написано | Что это значит |
| --- | --- |
| «доказано» | верно для всех входов; выведено из типов и тела функции |
| «доказано индукцией» | то же, индукцией по вариантам типа или по `неотрицательное` |
| «проверено только на тестах (примеров N)» | есть только N unit-тестов; доказательства нет |
| «не доказано» | нет ни доказательства, ни тестов |
| «не доказано: доказательство опирается на недоказанное» | вывод верен, но ссылается на утверждение, которое само не доказано |

Последняя строка отчёта подводит итог и называет код возврата:

| Итог в выводе | Когда | Код |
| --- | --- | --- |
| «проверено» | доказано всё | 0 |
| «доказано не всё» | есть проверенное только на тестах или не доказанное | 3 |
| «доказывать нечего» | постусловий нет, а завершение функции принято без доказательства | 3 |
| «независимая проверка повторила не всё доказанное» | с ключом `--independent`: программа `checker` перепроверила не каждое доказанное | 3 |

Ложное постусловие — ошибка проверки с кодом 1; отчёт тогда не выводится.

Подробный отчёт (`--explain`) называет те же исходы другими словами:
«сетка N» — проверено только на N тестах, «объявлено, не доказано» — не
доказано, «доказано ПРИ УСЛОВИИ» — опирается на недоказанное.

`flang check` без `--proof` отвечает кодом 0, когда программа прошла синтаксис,
типы, завершаемость и unit-тесты; недоказанное постусловие этот код не
меняет. Для CI — `flang check --proof --strict`. Ключ `--json` выводит отчёт в
машинном виде.

Ядро не перебирает варианты доказательства и не использует аксиом. Оно
применяет правила из закрытого списка
[`flang/proof/tables/inference-rules.tsv`](../flang/proof/tables/inference-rules.tsv):
строка на правило вывода и строки-запреты на то, что намеренно не выводится.
Почему среди правил нет аксиом —
[`flang/proof/axioms.md`](flang/proof/axioms.md).

### Свойство каждого элемента списка

Форма `для всех имя из Список: Условие` говорит о каждом элементе. Ядро
доказывает её по тому, как тело функции строит список.

```flang
модуль «Отбор»

тотальная функция «Только положительные»
  принимает остатки: список числа
  возвращает список числа
  обеспечивает «все положительны» для всех остаток из результат: остаток больше 0
  пример «смесь»
    дано остатки равно [3, 0, 5]
    ожидается [3, 5]
  отфильтровать остатки где остаток → остаток больше 0
```

```
$ flang check отбор.flang --proof
модуль «Отбор»: функций 1, завершение доказано у 1
постусловие «все положительны» функции «Только положительные» — доказано
…
```

После двоеточия снова стоит условие, поэтому `для всех` вкладываются. «Найдётся
значение» записывается с явным значением, которое называет автор:
`есть такой м, а именно Т, что Условие`.

```flang
модуль «Существование»

тотальная функция «Удвоить»
  принимает н: число
  возвращает число
  обеспечивает «удвоенное есть сумма» есть такой м, а именно н, что результат равен (м плюс м)
  н плюс н
```

### Свойство отдельно от функции

`утверждение «имя»` записывает условие, не привязанное к одной функции.
Строка `для всех имя: Тип` вводит переменную, `таких что Условие` —
ограничение на неё.

```flang
модуль «Свободные утверждения»

утверждение «длина пустого списка нулевая»
  утверждаем (длина пустой список) равен 0

утверждение «ноль нейтрален при сложении»
  для всех н: неотрицательное таких что н больше 0
  утверждаем (н плюс 0) равен н
```

```
$ flang check утверждения.flang --proof
модуль «Свободные утверждения»: функций 0, завершение доказано у 0
утверждение «длина пустого списка нулевая» — доказано
утверждение «ноль нейтрален при сложении» — доказано
…
```

Утверждение над параметром типа записать нельзя: строка
`утверждение «имя» от «А»` — ошибка `FLANG_PARSE`.

### Теорема

Доказательство может написать автор: `теорема` с тем же именем, что у
постусловия или утверждения.

```flang
модуль «Своё натуральное»

тип «Нат»
  вариант «Ноль»
  вариант «Следующий» содержит пред: «Нат»

тотальная функция «К числу»
  принимает н: «Нат»
  возвращает число
  разбор н
    случай вариант «Ноль»
      то 0
    случай вариант «Следующий» с пред как п
      то («К числу» от п) плюс 1

утверждение «шаг растит счёт на один»
  для всех н: «Нат»
  утверждаем («К числу» от (вариант «Следующий» с пред равным н)) равно ((«К числу» от н) плюс 1)

теорема «шаг растит счёт на один»
  дано н: «Нат»
  утверждаем («К числу» от (вариант «Следующий» с пред равным н)) равно ((«К числу» от н) плюс 1)
  индукция по н
    случай вариант «Следующий» с пред как п
      то по предположению
  следовательно доказано
```

```
$ flang check натуральное.flang --proof
модуль «Своё натуральное»: функций 1, завершение доказано у 1
утверждение «шаг растит счёт на один» — доказано индукцией
…
натуральное.flang: проверено — … независимая проверка повторила 1 из 1 — код возврата 0
```

Это утверждение ядро доказывает и без теоремы: простую индукцию оно находит
само. Разница в независимой проверке. Доказательство, записанное теоремой,
программа `checker` перепроверяет («повторила 1 из 1»), а найденное ядром на
этом файле — нет («повторила 0 из 1»).

Теорема обязана сойтись. Шаг, который ядро не свело к предположению
индукции, — ошибка `FLANG_PROOF_INDUCTION_STEP`, код возврата 1.

Каждый шаг теоремы ссылается на то, из чего он следует:

| Ссылка | На что |
| --- | --- |
| `по свойству «имя»` | доказанное постусловие или доказанное утверждение |
| `по предположению` | предположение индукции или предусловие функции |
| `по примеру «имя»` | unit-тест функции; закрывает случай с одним значением |
| `по закону «имя»` | правило из списка правил ядра |

Промежуточный шаг пишется `затем Условие по Ссылка`. Индукция идёт по вариантам
enum или по `неотрицательное` (`индукция по н убывает н`).

### Силлогизм

`следует «имя»` — вывод из уже доказанных утверждений. Это теорема, у которой
последняя строка `следовательно доказано` подразумевается.

В примере ниже посылка «все люди смертны» верна потому, что функция «Смертен»
определена как `да`: посылка задана определением, а не допущением. Примеры с
посылками-допущениями лежат в
[`flang/proof/probes/syllogism/assumptions/`](../flang/proof/probes/syllogism/assumptions).

```flang
модуль «Силлогизм»

тип «Человек»
  вариант «Человек»

тотальная функция «Смертен»
  принимает кто: «Человек»
  возвращает признак
  обеспечивает «всякий человек смертен» результат
  да

утверждение «все люди смертны»
  для всех кто: «Человек»
  утверждаем («Смертен» от кто)

утверждение «Сократ смертен»
  для всех сократ: «Человек»
  утверждаем («Смертен» от сократ)

следует «Сократ смертен»
  дано сократ: «Человек»
  утверждаем («Смертен» от сократ)
  по свойству «все люди смертны»
```

```
$ flang check силлогизм.flang --proof
модуль «Силлогизм»: функций 1, завершение доказано у 1
постусловие «всякий человек смертен» функции «Смертен» — доказано
утверждение «все люди смертны» — доказано
утверждение «Сократ смертен» — доказано
…
```

Вывод, который из названного утверждения подстановкой не получается, — ошибка
`FLANG_PROOF_STEP`. Если утверждение, на которое ссылается вывод, само не
доказано, отчёт отвечает «не доказано: доказательство опирается на
недоказанное», код возврата 3.

### История: требование словами заказчика

`история` записывает требование в форме «как … хочу … чтобы …». Компилятор
превращает её в тотальную функцию с предусловием, постусловием и примером:

```flang
модуль «Скидки»

объект «Роль»
  «менеджер зала»: признак

история «потолок скидки»
  как «менеджер зала»
  хочу «скидка» не больше 30
  чтобы "кассир не отдал товар ниже себестоимости"
  при «скидка» не меньше 0
  тогда при «скидка» 40 ответ 30
```

| Строка истории | Что из неё получается |
| --- | --- |
| `как «роль»` | предусловие: у вызывающего есть эта роль |
| `хочу «скидка» не больше 30` | постусловие `результат не больше 30` и тело, которое срезает значение по границе |
| `чтобы "…"` | ничего: строка обязательна, но в функцию не попадает |
| `при «скидка» не меньше 0` | предусловие на вход |
| `тогда при «скидка» 40 ответ 30` | пример |

`flang check --proof` отвечает: постусловие «хочу: скидка не больше 30» функции
«потолок скидки» — доказано.

### Независимый checker

`flang check --proof` сам запускает независимую проверку и пишет в итоговой
строке, сколько доказанного она повторила. Ту же проверку можно выполнить
отдельно. `flang check --proof --record <файл>` записывает доказательства в
текстовый файл. Его перепроверяет программа на C
[`flang/proof/checker/checker.c`](../flang/proof/checker/checker.c): она читает
исходник и этот файл, компилятор flang ей не нужен.

```
$ cc -std=c99 -O2 -o checker flang/proof/checker/checker.c
$ flang check натуральное.flang --proof --record натуральное.record
…
$ ./checker натуральное.flang натуральное.record
ПРОВЕРЕНО — запись сошлась с исходником, и всё доказанное проиграно заново: утверждений 1, шагов сверено с исходником 1, …
```

| Код | Ответ |
| --- | --- |
| 0 | файл доказательств соответствует исходнику, доказанное перепроверено |
| 3 | противоречий нет, но часть мест принята без перепроверки; места названы |
| 1 | файл доказательств расходится с исходником |
| 2 | неверный вызов |

Файл, в котором шаг доказательства подменён, отвергается:

```
$ ./checker натуральное.flang подмена.record
НЕ СОШЛОСЬ: теорема «шаг растит счёт на один», строка 25: запись говорит «по примеру «нет»», а в исходнике написано «по предположению»
```

Как читать отчёт и что доказано в самом компиляторе —
[`site/what-is-proved.ru.md`](site/what-is-proved.ru.md) и
[`site/how-proofs-work.ru.md`](site/how-proofs-work.ru.md).

### Запуск недоказанной программы

`flang run` и `flang io` перед запуском проверяют доказательства во всей
программе вместе с импортированными модулями. Если что-то не доказано,
программа не запускается:

```
$ flang run гарантии.flang --function «Удвоить» --args '{"н": 3}'
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск только по явному согласию: --на-веру
…
$ echo $?
3
$ flang run гарантии.flang --function «Удвоить» --args '{"н": 3}' --unproven warn
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск по ключу --unproven warn
6
```

«Сетка 1» в этих строках значит «одно постусловие проверено только на тестах».
Ключ `--trust` (`--на-веру`) запускает программу без проверки доказательств.
То же поведение задаётся ключом `unproven` в файле настроек.

## Side effects: `план` и `flang io`

Функция не читает файлы и не обращается к сети. Она возвращает команду —
«прочитай файл», «сделай запрос». Команду выполняет хост `flang io` и вызывает
функцию снова с ответом. Поэтому вся логика остаётся обычными функциями,
которые проверяются unit-тестами без диска и сети.

`план` — state machine. Первая функция возвращает начальное состояние. Вторая
получает состояние и ответ на предыдущую команду и возвращает значение типа
`«Продолжение»`: следующую команду или конец работы. В коде команда имеет тип
`«Поручение»`, ответ хоста — тип `«Отклик»`.

```flang
модуль «План записи»

тип «Ход»
  вариант Начало
  вариант Конец

тотальная функция «Начать»
  возвращает «Ход»
  вариант Начало

тотальная функция «Дальше»
  принимает ход: «Ход», отклик: «Отклик»
  возвращает «Продолжение»
  пример «сперва — команда записать файл»
    дано ход равно вариант Начало
    дано отклик равно вариант «Пока ничего»
    ожидается вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант Конец)
  разбор ход
    случай Начало
      то вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант Конец)
    случай Конец
      то вариант «Конец работы» с значение равным 6

план «Записать привет»
  состояние «Ход»
  начинает с «Начать»
  обрабатывает «Дальше»
```

```
$ flang io план.flang --in-dir
доказано: утверждений 0
{"plan":"Записать привет","result":6,"orders":1,"log":[{"поручение":{"variant":"Записать файл","fields":{"путь":"привет.txt","содержимое":"привет"}},"отклик":{"variant":"Записано","fields":{"сколько":6}}}]}
$ flang io план.flang --no-write
доказано: утверждений 0
{"plan":"Записать привет","result":6,"orders":1,"log":[{"поручение":{"variant":"Записать файл","fields":{"путь":"привет.txt","содержимое":"привет"}},"отклик":{"variant":"Сбой","fields":{"код":"FLANG_IO_DENIED","сообщение":"хозяину запрещено писать файлы"}}}]}
```

Ошибка ввода-вывода — не исключение, а ответ «Сбой» с кодом; программа
разбирает его через `разбор`.

Типы `«Продолжение»`, `«Поручение»` и `«Отклик»` встроены, набор их вариантов
закрыт.

| Вариант `«Продолжение»` | Что происходит | Код возврата `flang io` |
| --- | --- | --- |
| `«Сделать»` (поля `поручение`, `потом`) | хост выполняет команду и вызывает функцию снова | — |
| `«Конец работы»` (поле `значение`) | успешное завершение | 0 |
| `«Провал»` (поля `код`, `сообщение`) | программа сообщила об ошибке | 1 |
| `«Не проверено»` (поля `код`, `сообщение`) | программе нечем было проверить | 3 |

| Область | Команды — варианты `«Поручение»` |
| --- | --- |
| файлы | «Прочитать файл», «Записать файл», «Прочитать октеты из файла», «Записать октеты в файл», «Удалить файл», «Перечислить каталог», «Завести временный каталог» |
| сеть | «Запросить» (HTTP и HTTPS), «Открыть соединение», «Принять соединение», «Прочитать из соединения», «Ответить в соединение», «Прочитать октеты из соединения», «Ответить октетами в соединение», «Отправить датаграмму», «Принять датаграмму» |
| внешние программы | «Запустить процесс», «Запустить процесс с вводом», «Запустить процесс с пределом» |
| время и случайность | «Текущее время», «Случайное число», «Случайные октеты» |
| терминал | «Показать», «Показать страницу», «Ждать событие», «Размер экрана» |
| окружение | «Прочитать переменную среды», «Прочитать доводы» |

Ответы — варианты `«Отклик»`: «Пока ничего», «Прочитано», «Записано», «Ответ
сети», «Отметка времени», «Выпало», «Показано», «Случилось», «Срок вышел»,
«Перечислено», «Процесс завершён», «Процесс убит», «Процесс оборван»,
«Соединение открыто», «Октеты», «Сбой», «Убрано», «Заведено», «Значение среды»,
«Переменной среды нет», «Доводы», «Экран», «Датаграмма».

### Предел чужому процессу: память и срок

`«Запустить процесс»` не ограничивает программу ни в памяти, ни во времени. В
оболочке для этого служат `ulimit -v` и `kill -9` по таймеру. Команда
`«Запустить процесс с пределом»` задаёт оба предела:

```flang fragment
вариант «Запустить процесс с пределом»
  с программа равным "./stend"
  и аргументы равным пустой список
  и память равным 65536
  и срок равным 2000
```

`память` — килобайты адресного пространства, `срок` — миллисекунды от запуска;
0 в любом из полей значит «без предела».

Пределы соблюдаются по-разному, поэтому и ответы разные:

| Предел | Кто следит | Чем кончается | Ответ |
| --- | --- | --- | --- |
| `память` | ядро операционной системы: `setrlimit(RLIMIT_AS)` до `execvp`, то же, что `ulimit -v` | программе отказывает `malloc`, она выводит своё сообщение и завершается своим кодом | `«Процесс завершён»` с её кодом и её полем `ошибки` |
| `срок` | хост по своим часам | хост посылает `SIGKILL` | `«Процесс оборван»` с полями `предел` (мс), `вывод`, `ошибки` |

По памяти хост процесс не останавливал и причины его завершения не знает:
программа могла упасть и по другой причине. По сроку процесс остановил хост,
и он же называет причину.

`«Процесс оборван»` — отдельный ответ, потому что у `«Сбой»` есть только поля
`код` и `сообщение`, и вывод программы до остановки в нём пропал бы.

Срок команды и срок тишины хоста (`--timeout`, по умолчанию 30 000 мс) —
разные сроки. Первый считается от запуска, второй — от последнего выведенного
байта. Действуют оба, срабатывает тот, что раньше. По тишине хост отвечает
`«Сбой»` с кодом `FLANG_IO_TIMEOUT`, по сроку команды — `«Процесс оборван»`.
Поэтому `срок равным 0` срок тишины не отменяет.

Отдельного ключа для запрета этой команды нет: её запрещает тот же
`--no-spawn`, с тем же сообщением «хозяину запрещено запускать процессы».
Остановить процесс, который план не запускал, по номеру или по имени нельзя:
такой команды в языке нет.

Дробный или отрицательный предел — `«Сбой»` с кодом `FLANG_IO_SPAWN`.

Аргументы программы — всё, что стоит в командной строке после отдельного `--`;
их отдаёт команда «Прочитать доводы»:

```
$ flang io доводы.flang -- раз два три
доказано: утверждений 0
{"plan":"Сосчитать доводы","result":3,"orders":1,"log":[{"поручение":{"variant":"Прочитать доводы","fields":{}},"отклик":{"variant":"Доводы","fields":{"доводы":["раз","два","три"]}}}]}
```

Права хоста сужаются ключами `--no-read`, `--no-write`, `--no-net`,
`--no-clock`, `--no-random`, `--no-spawn`, `--no-env`, `--no-args`,
`--no-screen`; `--in-dir` запрещает пути вне каталога входного файла. По
умолчанию разрешено всё.

Скрипты репозитория flang — такие же программы в файлах `.fscript`; их
выполняет та же команда `flang io`.

## Процессы

`процесс` — actor: состояние, тип принимаемых сообщений и функция-обработчик.
Обработчик — обычная тотальная функция: получает состояние и сообщение,
возвращает новое состояние и список действий. Отправка сообщения другому
процессу — элемент этого списка, а не вызов. `надзор` — supervisor: что делать,
когда процесс упал. `прогон` — тест сценария с заданной последовательностью
сообщений.

```flang
модуль «Счётчик»

объект «Счёт»
  «всего»: число

объект «Отклик»
  «состояние»: «Счёт»
  «действия»: список «Действие»

тип «Команда»
  вариант «прибавить» содержит «сколько»: число

процесс «Счётчик»
  состояние «Счёт»
  начинает с «пустой счёт»
  принимает «Команда»
  обрабатывает «шаг счёта»

надзор «Учёт»
  процесс «Счётчик» стратегия «перезапустить»
  порог отказов 3 за 5000 миллисекунд иначе «передать выше»

тотальная функция «пустой счёт»
  возвращает «Счёт»
  запись «Счёт» с «всего» равным 0

тотальная функция «шаг счёта»
  принимает текущее: «Счёт», сообщение: «Команда»
  возвращает «Отклик»
  пример «прибавление меняет состояние и ничего не шлёт»
    дано текущее равно (запись «Счёт» с «всего» равным 1)
    дано сообщение равно (вариант «прибавить» с «сколько» равным 2)
    ожидается (запись «Отклик» с «состояние» равным (запись «Счёт» с «всего» равным 3) и «действия» равным [])
  разбор сообщение
    случай вариант «прибавить» с «сколько» как сколько
      пусть новое равно (запись «Счёт» с «всего» равным (текущее.«всего» плюс сколько))
      запись «Отклик» с «состояние» равным новое и «действия» равным []

прогон «два прибавления»
  семя 1
  дано «Счётчик» принимает (вариант «прибавить» с «сколько» равным 2)
  дано «Счётчик» принимает (вариант «прибавить» с «сколько» равным 3)
  ожидается «Счётчик» равен (запись «Счёт» с «всего» равным 5)
```

Варианты встроенного типа `«Действие»`: «отправить», «через», «остановить»,
«отложить», «продолжить», «породить».

| Строка | Что делает |
| --- | --- |
| `состояние «Т»`, `начинает с «Ф»` | тип состояния и функция начального состояния |
| `принимает «Т»` | тип сообщений; `принимает «Т» с ящиком 4 сообщений` ограничивает почтовый ящик |
| `обрабатывает «Ф»` | обработчик; `обрабатывает «Ф» с запасом 2000 витков` даёт предел шагов обработчику без `тотальная` |
| `процесс «П» стратегия «…»` | что делает надзор при отказе процесса: `перезапустить`, `остановить`, `передать выше` |
| `порог отказов N за M миллисекунд иначе «…»` | окно отказов и стратегия, когда окно переполнено |
| `прогон «имя»`, `семя N`, `семя от N до M` | тест сценария: сообщения на входе, ожидаемое состояние, порядок доставки |

`flang check` на программе с процессами отвечает кодом 2: типы, завершаемость
и unit-тесты обработчиков проверены, а объявления `процесс`, `надзор` и
`прогон` проверены не полностью, и вывод об этом сообщает.
`flang check --proof` на той же программе отвечает кодом 0. Код с
планировщиком процессов генерируется для целей `c`, `elixir`, `js` и `ts`.

Модель процессов, supervision и работа на нескольких узлах —
[`site/processes.ru.md`](site/processes.ru.md).

## Категорная запись

Конвейер из функций можно объявить данными: объекты, стрелки (морфизмы) между
ними и их композицию.

```flang
модуль «Проводка заказа»

объект «Заказ»
  сумма является числом

объект «Отгрузка»
  номер является числом

объект «Счёт»
  итог является числом

тотальная функция «Отгрузить заказ»
  принимает заказ: «Заказ»
  возвращает «Отгрузка»
  запись «Отгрузка» с номер равным заказ.сумма

тотальная функция «Выставить счёт»
  принимает отгрузка: «Отгрузка»
  возвращает «Счёт»
  запись «Счёт» с итог равным отгрузка.номер

морфизм «отгрузить» из «Заказ» в «Отгрузка»
  даёт «Отгрузить заказ»
  закон «номер отгрузки берётся из суммы заказа»
    пример «обычный заказ»
      дано заказ равно запись «Заказ» с сумма равным 500
      ожидается запись «Отгрузка» с номер равным 500

морфизм «выставить» из «Отгрузка» в «Счёт»
  даёт «Выставить счёт»

морфизм «провести» это «выставить» после «отгрузить»

цепочка «провести заказ»
  сначала «отгрузить»
  затем «выставить»
```

| Слово | Что объявляет |
| --- | --- |
| `морфизм «м» из «А» в «Б»`, `даёт «Ф»` | стрелку и функцию, которой она является |
| `закон «имя»` с примерами | условие на стрелку; считается на значениях примеров |
| `«в» после «а»` | композицию; правая стрелка применяется первой |
| `цепочка`, `сначала`, `затем` | ту же композицию в порядке чтения |
| `категория «К»` | набор стрелок модуля |
| `единица «Х»` | тождественную стрелку объекта |
| `изоморфизм`, `прямой морфизм`, `обратный морфизм` | пару стрелок туда и обратно |
| `функтор`, `отображается в`, `отображается в поле`, `отображается в морфизм` | связь между категориями и её строки |
| `бифунктор`, `объекты`, `морфизмы` | связь от пары категорий: пара объектов и пара стрелок |
| `моноид`, `носитель`, `операция`, `единица`, `обратный элемент` | структуру со своими законами |
| `свойство` | закон одной операции: коммутативность, монотонность и другие объявляемые |
| `вложение`, `пересечение` | часть объекта и общую часть двух объектов |

Монада объявляется над параметрическим типом, и блок `в монаде` связывает шаги,
каждый из которых может не дать ответа; компилятор разворачивает блок во
вложенные `разбор`:

```flang
модуль «Скидка»

тип «Возможно» от «А»
  вариант «Есть» содержит значение: «А»
  вариант «Нет»

монада «Возможно» от «А»
  возврат «Обернуть»
  соединение «Сплющить»

тотальная функция «Обернуть» от «А»
  принимает значение: «А»
  возвращает «Возможно» от «А»
  вариант «Есть» с значение равным значение

тотальная функция «Сплющить» от «А»
  принимает вложенное: «Возможно» от («Возможно» от «А»)
  возвращает «Возможно» от «А»
  разбор вложенное
    случай вариант «Есть» с значение как внутри
      то внутри
    случай «Нет»
      то вариант «Нет»

тотальная функция «Цена позиции»
  принимает номер: число
  возвращает «Возможно» от числа
  если номер равен 1
    то вариант «Есть» с значение равным 500
    иначе вариант «Нет»

тотальная функция «Скидка по цене»
  принимает цена: число
  возвращает «Возможно» от числа
  если цена не меньше 400
    то вариант «Есть» с значение равным (цена делить на 10)
    иначе вариант «Нет»

тотальная функция «Итог со скидкой»
  принимает номер: число
  возвращает «Возможно» от числа
  пример «по первой позиции скидка есть»
    дано номер равно 1
    ожидается вариант «Есть» с значение равным 450
  пример «второй позиции нет в каталоге»
    дано номер равно 2
    ожидается вариант «Нет»
  в монаде «Возможно»
    пусть цена равно «Цена позиции» от номер
    пусть скидка равно «Скидка по цене» от цена
    возврат цена минус скидка
```

`возврат «Ф»` называет функцию, заворачивающую значение, `соединение «Ф»` —
снимающую один слой; внутри блока `возврат выражение` стоит последней строкой.

Законы компилятор считает на конечном наборе значений и выводит его размер;
это проверка на тестах, не доказательство. На программе с монадой выше
`flang check` отвечает кодом 0 и строкой «монада «Возможно»: сетка 2 значений,
троек 32, нарушений 0». На программе со стрелками выше категории нет, законы
стрелок не считаются, и `flang check` отвечает кодом 2, а `flang emit` — кодом
3. Подробно — [`site/categories.ru.md`](site/categories.ru.md), контракт —
[`ct/spec.md`](ct/spec.md).

## Старые слова

Эти слова лексер узнаёт, но новые программы их не используют.

| Слово | Что с ним сегодня |
| --- | --- |
| `дата`, `деньги` | типы: ведут себя как `строка` и `число` |
| `утилита`, `правило`, `вложен объект`, `вложена структура`, `в данных`, `найти где`, `по морфизму` | разбираются, но программу из них не составить |
| `имеет` в строке `дано «Объект» имеет «поле» равное значение` | старая форма теоремы; рядом со словами доказательства — ошибка `FLANG_PARSE` |

## Модули и пакеты

```
модуль «Имя»
  [экспортирует «А», «Б»]
  [использует «Модуль» [из "путь"] [только «А», «Б»]]
```

`использует` — import. Без строки `экспортирует` модуль экспортирует всё. Имя,
которого в списке экспорта нет, в импортирующем модуле неизвестно — ошибка
`FLANG_UNKNOWN_NAME`.

```flang
модуль «Библиотека»
  экспортирует «Утроить»

тотальная функция «Утроить»
  принимает н: число
  возвращает число
  н умножить на 3

тотальная функция «Скрытая»
  возвращает число
  1
```

```flang
модуль «Приложение»
  использует «Библиотека»

тотальная функция «Девять»
  возвращает число
  пример «три утроено»
    ожидается 9
  «Утроить» от 3
```

Модуль ищется по имени из первой строки файла, а не по имени файла. Порядок
поиска: каталог импортирующего файла; каталоги выше него до корня проекта;
каталоги из переменной `FLANG_MODULE_DIR`; библиотека, поставленная с
компилятором. Корень проекта — ближайший каталог с `.flangrc`, `.git` или
`flang.package`. Модуль не найден — `FLANG_IMPORT_NOT_FOUND`. Два файла с одним
именем модуля — `FLANG_IMPORT_AMBIGUOUS` с обоими путями. Форма `из "путь"`
называет файл прямо; путь считается от импортирующего файла.

Модули стандартной библиотеки импортируются по имени, например
`использует «Lists»`.

`flang lock` выводит lock-файл — JSON с исходниками всех импортированных
модулей и sha256 каждого: и названных формой `из "путь"`, и найденных по имени,
и взятых из пакета `.flang-package`. Если файл `flang.lock` лежит рядом с
программой, команды берут эти модули из него, и исходники на диске не нужны.

`flang package` выводит пакет: тот же JSON с именем и версией из файла
`flang.package`. Пакет импортируется как файл:

```flang fragment
модуль «Пользователь пакета»
  использует «Discount» из "discount.flang-package"

тотальная функция «Привет»
  возвращает строка
  пример «приветствие из пакета»
    ожидается "Привет, мир!"
  «Поприветствовать» от "мир"
```

Пакет, изменённый после сборки, отвергается:

```
$ flang check пользователь.flang
FLANG_PACKAGE: адрес модуля «Discount» не сходится с его исходником: правлен или испорчен
```

`flang new <имя>` создаёт каталог пакета: модуль с unit-тестом,
`flang.package`, каталог `fspec/` и README. Подробно —
[`site/packages.ru.md`](site/packages.ru.md).

## Целевые языки

`flang emit <файл> --target <цель>` генерирует код на одном из десяти языков:
`c`, `cpp`, `go`, `rust`, `java`, `js`, `ts`, `elixir`, `python`, `csharp`.
Перед генерацией программа проходит те же проверки, что у `flang check`, кроме
unit-тестов; если есть ошибка, код не генерируется.

```
$ flang emit завершаемость.flang --target c --out out
напечатано файлов 6, байт …, в out
…
$ ls out
Makefile  flang_cli.c  flang_runtime.c  flang_runtime.h  program.c  program.h
$ make -C out
…
$ printf '%s\n' '{"fn":"НОД","args":[{"n":"12"},{"n":"18"}]}' | out/flang_cli
{"ok":true,"value":{"n":"6"}}
```

Рядом с модулем генерируются библиотека времени выполнения, файл сборки и
программа `flang_cli`, которая читает запросы JSON из stdin; с ключом
`--no-cli` она не генерируется. Файл модуля с латинским именем называется по
модулю: `module «Hello»` даёт файл «hello» с расширением `.c`. Модуль с
нелатинским именем даёт файл «program». Имена функций транслитерируются: «Удвоить» модуля «Привет» —
`privet_udvoit`.

`flang_cli` сверяет аргументы с объявленными типами так же, как `flang run`:

```
$ printf '%s\n' '{"fn":"НОД","args":[{"s":"x"},{"n":"18"}]}' | out/flang_cli
{"ok":false,"code":"FLANG_TYPE","message":"вызов функции «НОД»: аргумент «а» не соответствует типу число"}
```

В сгенерированном коде остаются лимиты шагов и глубины рекурсии, проверки
убывания у рекурсии и проверки недоказанных постусловий. Для доказанных
постусловий проверок в коде нет. Ключ `--no-postconditions` убирает из кода
все проверки постусловий.

| Объявление | Цели |
| --- | --- |
| функции, типы, теоремы | все десять |
| `процесс`, `надзор`, `прогон` | `c`, `elixir`, `js`, `ts`; у остальных — ошибка, код 1 |
| `план` | `c`, `go`, `js`, `python`, `rust`, `ts`; у `cpp`, `csharp`, `elixir`, `java` — `FLANG_PLAN_UNSUPPORTED`, код 1 |

Сгенерированные файлы по целям — [`guide/emit-walkthrough.ru.md`](guide/emit-walkthrough.ru.md),
встраивание в чужую программу — [`site/embedding.ru.md`](site/embedding.ru.md).

## Команды

| Команда | Что делает |
| --- | --- |
| `flang check <файл>` | синтаксис, типы, завершаемость, доказательства, unit-тесты |
| `flang test <файл \| каталог \| маска>` | те же проверки и счёт unit-тестов по файлам |
| `flang run <файл> --function «Имя» [--args '{…}']` | вычисляет одну функцию |
| `flang emit <файл> --target <цель>` | генерирует код на целевом языке |
| `flang io <файл> [--plan 'Имя плана']` | выполняет программу с side effects |
| `flang facts <файл> --facts <json> --claims '[…]'` | проверяет условия на заданных значениях |
| `flang ast <файл>` | AST в JSON |
| `flang tokens <файл>` | поток токенов лексера |
| `flang lint [<путь>…]` | длина строк и глубина ветвлений против пределов `.flangrc` |
| `flang lock <файл>` | выводит lock-файл |
| `flang package <файл>` | выводит пакет |
| `flang new <имя>` | создаёт каталог пакета |
| `flang run-script [<имя> [аргументы…]]` | выполняет короткую команду проекта из `.flangrc` |
| `flang repl [файл]` | REPL; то же — `flang` без аргументов в терминале |
| `flang lsp` | language server для редактора |
| `flang --mcp-mode` | MCP-сервер для ИИ-помощника |
| `flang --help`, `flang --version` | справка и версия |
| `flang --machine [<файл>]` | постоянная этой машины: сколько шагов программы она делает в секунду |

`flang <команда> --help` перечисляет ключи команды. Аргументы `flang run` —
объект JSON по именам параметров; списки, записи и варианты сверяются с
объявленными типами.

Цену функции до запуска — шаги, память и секунды многочленом от размеров
входа — выводит короткая команда репозитория flang
`flang run-script cost <файл> --function «Имя» --sizes 'н=20'`. Цену одного
запуска выводит ключ `flang run … --cost`. Подробно — [`guide/cost.ru.md`](guide/cost.ru.md).

| Код возврата | Значение |
| --- | --- |
| 0 | сделано |
| 1 | программа не прошла проверку, вычисление остановлено ошибкой, `facts` опровергла условие или программа под `io` вернула «Провал» |
| 2 | неверный вызов; у `check` — в программе есть объявления, которые компилятор проверяет не полностью |
| 3 | сделано, но проверено не всё: недоказанное под `check --proof`, отказ `run` и `io` запускать недоказанную программу, «Не проверено» под `io` |
| 4 | `check --fast`: доказательства и unit-тесты не запускались |
| 5 | остановка на лимите памяти |

Лимит памяти задаёт ключ `--memory-limit N` (`--предел-памяти`), число с
буквой K, M, G или T; у `check`, `test` и `run` по умолчанию три четверти
памяти машины, 0 снимает лимит:

```
$ flang run память.flang --function «Раздуть» --args '{"текст":"а","раз":28}' --memory-limit 32M
FLANG_MEMORY: недостаточно памяти
FLANG_MEMORY: прогон остановлен на пределе памяти 32 МиБ: занято … МиБ, просили ещё 25 165 880 байт
  считалась функция «Раздуть», шагов программы 452
…
```

Ошибка выводится строкой `КОД в файле <путь>, строка N, столбец M: текст`.
Справочник команд — [`site/cli.ru.md`](site/cli.ru.md), справочник ошибок —
[`site/diagnostics.ru.md`](site/diagnostics.ru.md).

## Файл настроек

Настройки читаются из файла `.flangrc`: строки `ключ = значение`, строка с `#`
в начале пропускается, незнакомый ключ пропускается, из двух одноимённых строк
берётся последняя. Файл ищется от рабочего каталога вверх до корня проекта,
затем в домашнем каталоге.

| Ключ | Что задаёт |
| --- | --- |
| `unproven` | что делать `flang run` и `flang io` с программой, в которой не всё доказано |
| `max-line-length` | предел длины строки в знаках для `flang lint` |
| `max-conditional-depth` | предел вложенности `если` и `разбор` в теле функции для `flang lint` |
| `lint` | `refuse` — нарушение даёт код 1, `warn` — код 0 |
| `profile`, `modules` | какие модули стандартной библиотеки программе можно импортировать |
| `profile.<имя>` | свой профиль: список модулей через запятую |
| `script.<имя>` | короткая команда проекта для `flang run-script` |
| `language` | язык ответа `flang check` (`ru` или `en`), проводника и скриптов |
| `surface`, `color`, `page` | поверхность заготовок, цвет в терминале, язык `man flang`; компилятор их не читает |
| `version`, `name`, `license`, `repository`, `issues` | сведения о пакете для скриптов и сайта |

Значения `unproven`:

| Значение | Поведение |
| --- | --- |
| `refuse` | не запускать, код возврата 3; значение по умолчанию |
| `warn` | вывести результат проверки и запустить |
| `allow` | запустить без проверки доказательств; то же, что `--trust` |

```
$ cat .flangrc
unproven = warn
$ flang run гарантии.flang --function «Удвоить» --args '{"н": 3}'
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск по настройке «unproven = warn» (…/.flangrc)
6
```

Приоритет: ключ командной строки `--unproven`, переменная окружения
`FLANG_UNPROVEN`, `.flangrc`, значение по умолчанию. Значение не из списка —
ошибка с кодом возврата 2.

`flang lint` проверяет в исходниках длину строки и глубину ветвлений и называет
место каждого нарушения:

```
$ flang lint знак.flang --max-conditional-depth 2
flang lint: файлов 1; max-line-length: без предела; max-conditional-depth 2: 1; не разобрано 0
знак.flang:11: глубина ветвлений 3 > 2 в «Знак» (max-conditional-depth)
```

Ключ команды важнее файла проекта, файл проекта важнее файла в домашнем
каталоге. Если предел нигде не задан, проверка не выполняется. Коды: 0 — нарушений нет или
`lint = warn`; 1 — нарушения есть; 2 — неверный вызов или негодное значение в
`.flangrc`; 3 — часть файлов не разобралась, и глубина в них не измерена. Других
правил стиля `flang lint` не проверяет.

Профиль — список имён модулей стандартной библиотеки. Если в `.flangrc` есть
`profile` или `modules`, программа может импортировать из библиотеки только названные
модули; на остальные — `FLANG_IMPORT_NOT_FOUND`, а первая строка ответа называет
профиль и файл настроек:

```
$ flang check проба.flang
flang: модуль «Rationals» библиотеки не входит в профиль «programmer» (…/.flangrc) — по имени не ввозится; …
…
FLANG_IMPORT_NOT_FOUND в файле проба.flang, строка 1, столбец 1: не найден модуль «Rationals»: …
```

Профили библиотеки — `programmer`, `analyst`, `mathematician`
(`flang/stdlib/profiles.flangrc`). Профиль ограничивает импорт из библиотеки, а
не файлы проекта.

Строка `script.<имя> = <команда>` — короткая команда проекта:

```
script.site:build = node docs/site/build.mjs
```

`flang run-script` без имени выводит перечень. `flang run-script site:build`
выполняет команду через `/bin/sh -c` в каталоге файла настроек; аргументы после
имени передаются команде, код возврата — её собственный. Короткие команды берутся
только из файла проекта, не из домашнего каталога.

Подробно — [`guide/settings.ru.md`](guide/settings.ru.md).

## Ограничения

Список относится к компилятору 0.8.0.

Язык:

- `число` — IEEE-754 double: целые точны до 2⁵³−1, сложение дробных не
  ассоциативно. `(0.1 плюс 0.1) плюс 0.6` даёт `0.8`, а
  `0.1 плюс (0.1 плюс 0.6)` — `0.7999999999999999`. Округления нет. Точная
  арифметика — типы `точное целое`, `точное дробное` и
  `точное целое со знаком`.
- Сумма двух `неотрицательное` имеет тип `число`. Поэтому переменная цикла
  `храним сумма: неотрицательное`, которую обновляет сумма, — ошибка типа.
- Присваивания, исключений и nullable-типов нет. `цикл` есть, но это запись
  свёртки или рекурсии: переменные состояния меняются только строкой `дальше`.
- Анонимных функций нет. Тело после `→` пишется только во встроенных формах
  `отобразить`, `отфильтровать` и `свёртка`. Значение-функция — объявленная
  функция, возможно с заданными первыми параметрами.
- Имя цикла занимает имя типа: два цикла с одним именем в одном модуле —
  ошибка `FLANG_TYPE`.
- Результат типа `точное целое со знаком` команда `flang run` выводит как
  `null`; значение видно после `к строке`.
- Программа проверяется целиком: раздельной компиляции нет, двух версий одного
  модуля в программе не бывает.
- Side effects внутри функции невозможны. Условие о состоянии во времени, о
  side effect или о параллельном исполнении записать нечем: `обеспечивает`
  говорит о значении функции.

Доказательства:

- Ядро не ищет доказательство: оно применяет правила из закрытого списка.
  Шаги, которых правила не дают, пишет автор теоремой.
- Постусловие функции, записанной циклом, ядро не доказывает. Оно остаётся
  проверенным только на тестах, и `flang check --proof` отвечает кодом 3.
- Утверждение над параметром типа записать нельзя: `утверждение «имя» от «А»`
  — ошибка `FLANG_PARSE`. Утверждение пишется для конкретного типа, например
  `список числа`.
- Убывание объявленной меры (`убывает` над типом `число`) ядро не выводит.
  Завершение такой функции принято без доказательства: `flang check --proof`
  отвечает кодом 3, `flang run` требует `--trust` или `--unproven warn`, а
  убывание проверяется во время выполнения.
- О типе `точное целое со знаком` ядро правил не имеет: постусловие
  `результат равен а` у тела `а плюс 0` осталось проверенным только на тестах.
- Условие ветки `если` ядро знает в обеих ветвях: в `то` — само условие, в
  `иначе` — его отрицание. Порядок из отрицания (`не (х меньше 0)` →
  `х не меньше 0`) выводится, только когда обе стороны сравнения не бывают NaN:
  литерал или имя типа `целое`, `неотрицательное`, `сотых`, `тысячных`. Модуль
  целого через `если х меньше 0` доказан. Тот же модуль над `число` проверен
  только на тестах: при `х` = `0 делить на 0` условие `не (х меньше 0)`
  истинно, а `х не меньше 0` ложно. Доказанное так место независимая проверка
  не повторяет.
- Строгое сравнение двух литералов в предусловии ядро вычисляет: вызов
  `«Доля» от часть и 2` при `требует … целое больше 0` принят, и независимая
  проверка его повторяет.
- Правила арифметики `вес`, `сотых` и `тысячных` компилятор проверяет.
  Выражение, которое доказуемо даёт NaN, — `а остаток от 0`,
  `(1 минус 1) делить на (2 минус 2)` — отвергается `FLANG_NOT_A_NUMBER`.
  Запись `0 делить на 0` литералами ошибкой не считается: это единственная
  запись NaN в языке, и ею пользуются библиотеки. `вес минус вес` отвергается
  `FLANG_INFINITY`, даже когда результат объявлен `число`;
  `сотых плюс тысячных` — `FLANG_SCALE`. Нижнюю границу `вес` у аргумента
  сверяют и `flang run`, и `flang_cli` сгенерированной программы: −1
  отвергается ошибкой `FLANG_TYPE`.
- Объявления процессов (`процесс`, `надзор`, `прогон`) и стрелок категории
  (`морфизм`, `категория`, `функтор`) компилятор проверяет не полностью:
  `flang check` отвечает кодом 2. `flang emit` на программе со стрелками
  отвечает кодом 3. На программе с процессами `flang check --proof` отвечает
  кодом 0, хотя `flang check` — кодом 2. Программа, где из категорных
  объявлений есть только `моноид` или `монада`, получает код 0: их законы
  посчитаны на тестовых значениях, не доказаны.
- Независимая проверка повторяет не каждое доказательство. Места, которые она
  не повторила, программа `checker` называет в отчёте и отвечает кодом 3;
  `flang check --proof` пишет «повторила N из M». В измерении 28 ноября 2026
  на версии 0.8.0 (`checker:second`, 798 записей набора проб) кодом 3 `checker`
  ответил на 173 записи. Числа мест эта команда не печатает.
- Известные случаи, когда «доказано» не значит «верно», перечислены в таблице
  [`flang/proof/tables/consistency-violations.tsv`](../flang/proof/tables/consistency-violations.tsv):
  из 15 строк открыты 3, все три — о программе `checker`. Каждый случай с
  примерами —
  [`flang/proof/known-soundness-violations.md`](flang/proof/known-soundness-violations.md).
- Сам компилятор формально не верифицирован. Без доказательства принимаются
  ядро, компилятор, библиотека времени выполнения, компилятор C и железо. Для
  safety-critical систем язык не годится.

Генерация кода:

- Доказательство относится к исходной программе. Соответствие сгенерированного
  кода исходнику в общем виде не доказано. Для цели `c` ключ `--protocol <файл>`
  выводит протокол перевода. Его сверяет программа
  [`flang/translation/matcher.c`](../flang/translation/matcher.c): каждый узел
  она повторяет по правилу из закрытого списка в 41 правило, а непокрытое
  называет. Пять правил она не повторяет: `разбор`, `случай`, `свёртка`,
  `отобразить` и хвостовой вызов (trampoline). Из 55 примеров каталогов
  `flang/proof/examples` и `docs/examples/measure` код генерируется для 48;
  на 23 из них программа отвечает кодом 0, на 25 — кодом 3 и называет
  непокрытое.
- Проверку убывания меры та же программа сличает по образцу. На функции «НОД»
  с `убывает б` ответ — код 0: «узлов в протоколе 77; переиграно правилом 70,
  принято на слово 0». Замена `<` на `<=` в этой проверке отвергается кодом 1.
  Нужна ли проверка меры у вызова, программа не проверяет. Правильно
  сгенерированный код взаимной хвостовой рекурсии она отвергает кодом 1.
- `flang emit` не выполняет unit-тесты (`пример`): их выполняют `flang check`
  и `flang test`.
- Программа `flang_cli` сгенерированного кода сверяет аргументы с объявленными
  типами и отвечает `FLANG_TYPE`. Запуском это проверено в девяти целях; в
  `elixir` не проверялось.
- `план` генерируется для `c`, `go`, `js`, `python`, `rust` и `ts`; `cpp`,
  `csharp`, `elixir` и `java` отвечают `FLANG_PLAN_UNSUPPORTED`. В `c`, `go`,
  `python` и `rust` план выполняет `flang_cli --plan <имя>`. Хост в `python`
  знает 9 видов команд из 28: файлы текстом и октетами, каталоги, переменные
  среды, аргументы. На команды сети, времени, случайных чисел и запуска
  процессов он отвечает «Сбой» с кодом `FLANG_IO_NOT_WIRED`. Процессы
  генерируются для `c`, `elixir`, `js` и `ts`.

Хост и сообщения:

- `https` у «Запросить» выполняет встроенный клиент TLS 1.3; `curl` не нужен.
  Клиент умеет один набор (`TLS_AES_128_GCM_SHA256`, x25519,
  `rsa_pss_rsae_sha256`, цепочка `sha256WithRSAEncryption`) и отзыв
  сертификата не проверяет. TLS-сокета без HTTP у плана нет: «Открыть
  соединение» — TCP без шифрования. Датаграммы — команды «Отправить
  датаграмму» и «Принять датаграмму», только IPv4.
- `flang check` отвечает на языке ключа `language` файла настроек или
  переменной `FLANG_LANG`: код `FLANG_*` тот же, текст — русский или
  английский. Английский текст есть у 13 кодов ошибок из 175; у остальных
  162 и у строк о каждом постусловии текст русский. Справка, `test`, `run`,
  `io` и `lint` отвечают по-русски.

Те же ограничения с примерами — [`guide/limits.ru.md`](guide/limits.ru.md).
