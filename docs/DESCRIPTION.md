# flang — описание языка

flang — чистый функциональный язык со строгой статической типизацией. Программа
проверяется до запуска: компилятор разбирает файл, выводит типы, доказывает, что
функции с пометкой `тотальная` завершаются, прогоняет unit-тесты, записанные
внутри функций, и пробует доказать postconditions для всех входов. Проверенная
программа вычисляется командой `flang run` или переводится в один из десяти
целевых языков командой `flang emit`.

Каждый пример ниже проходит `flang check`. Вывод команд приведён дословно;
пропущенные строки, сокращённые пути и числа, которые меняются от сборки к
сборке, отмечены многоточием. Версию двоичного печатает `flang --version`.

## Первая программа

```flang
модуль «Удвоение»

тотальная функция «Удвоить»
  принимает н: число
  возвращает число
  пример «два»
    дано н равно 2
    ожидается 4
  н умножить на 2
```

```
$ flang check удвоение.flang
модуль «Удвоение»: функций 1, из них с доказанным завершением 1; типов 0
удвоение.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
$ flang run удвоение.flang --function «Удвоить» --args '{"н": 21}'
доказано: утверждений 0
42
```

Файл начинается строкой `модуль «Имя»`. Ниже, у левого края, стоят объявления;
их порядок свободен, функция может вызывать объявленную ниже. `пример` внутри
функции — unit-тест: он выполняется при каждой проверке файла.

## Словарь: слова flang и привычные термины

| Во flang | Привычное название | Ближайший аналог |
| --- | --- | --- |
| `объект`, `запись` | структура с полями и её значение | struct, dataclass |
| `тип` с `вариант`ами | enum с данными, tagged union | `enum` в Rust, union в TypeScript |
| `разбор … случай` | pattern matching | `match` в Rust и Python |
| `если … то … иначе` | if как выражение | тернарный оператор |
| `пусть` | константа | `const` |
| `отобразить`, `отфильтровать`, `свёртка` | map, filter, reduce | то же в JavaScript и Python |
| `пример` | unit-тест внутри функции | doctest |
| `требует` | precondition: что должно быть верно на входе | assert в начале функции |
| `обеспечивает` | postcondition: что функция гарантирует на выходе | assert в конце, проверенный для всех входов |
| `тотальная функция` | функция, про которую компилятор доказал, что она завершается | — |
| `утверждение` | свойство, записанное отдельно от функции | property в property-based тестах, но доказанное |
| `теорема`, `следует` | доказательство, которое пишет автор | — |
| `план` | side effects: функция возвращает команду, рантайм её выполняет | reducer, state machine |
| `процесс` | actor с состоянием и очередью сообщений | процесс в Erlang и Elixir |
| `использует` | import | `import` |

Слова, которые печатает компилятор:

| В выводе написано | Что это значит |
| --- | --- |
| «ядро» | prover — часть компилятора, которая доказывает postconditions |
| «постусловие», «предусловие» | строки `обеспечивает` и `требует` |
| «утверждений N» | сколько postconditions и отдельных свойств в программе |
| «доказано» | верно для всех возможных входов |
| «сетка N» | есть только N unit-тестов, доказательства нет |
| «объявлено, не доказано» | нет ни доказательства, ни тестов |
| «на веру» | программа запущена без проверки доказательств |
| «мера» | величина, которая убывает на каждом рекурсивном вызове |
| «сторож» | runtime check, оставленный в программе |
| «ведомость» | отчёт команды `flang check --proof` |
| «хозяин», «поручение», «отклик» | рантайм команды `flang io`, команда ему и его ответ |
| «напечатано» | сгенерирован код на целевом языке |

## Синтаксис

Расширений файла четыре, они равноправны: `.flang`, `.fp`, `.фп`, `.фланг`.

Блок задаётся отступом. Круглые скобки только группируют выражения.

Имена модулей, функций, типов, вариантов, тестов и свойств пишутся в ёлочках:
`«Сумма до»`. Имя параметра, константы и поля — одно слово без кавычек или тоже
имя в ёлочках. Ключевое слово именем быть не может:

```
$ flang check занятое.flang
FLANG_PARSE в файле занятое.flang, строка 6, столбец 3: не разобрана конструкция: неожиданное 'с' — это слово занято языком, именем оно быть не может: напишите имя в ёлочках («с») или переименуйте; а если слово попало в форму лишним — уберите его
занятое.flang: не проверено — замечаний 1
```

Ключевое ли слово, отвечает `flang tokens --keyword «слово»`.

| Литерал | Запись |
| --- | --- |
| число | `12`, `0.5`, `-3` |
| строка | `"текст"` или `'текст'`; escape-последовательности `\"`, `\\`, `\n` |
| boolean | `да`, `нет` |
| пустое значение | `ничто` |
| список | `[1, 2, 3]`, `список из 1 и 2 и 3`, `пустой список` |

Стрелка `→` набирается также `->` и `=>`. Строка, начинающаяся с `//`, —
комментарий.

У каждого ключевого слова четыре написания — русское, английское, эсперанто и
китайское. Лексер сводит их к одному токену, поэтому одна программа на четырёх
языках даёт одно AST:

```
$ flang tokens --keyword если
«если» — ключевое слово, конструкция «if»
$ flang tokens --keyword 如果
«如果» — ключевое слово, конструкция «if»
```

```flang
module «Doubling»

total function «Double»
  accepts n: number
  returns number
  example «two»
    given n equals 2
    expected 4
  n times 2
```

Имена функций, типов и модулей не переводятся. Таблица всех слов —
[`glossary.md`](glossary.md), правила для четырёх языков —
[`surfaces.md`](surfaces.md).

## Типы

Значение — скаляр, список, структура или вариант enum. Все числовые типы
хранятся как IEEE-754 double; типы уже, чем `число`, — это ограничения на
значение, которые проверяет компилятор.

| Тип | Значения |
| --- | --- |
| `число` | любой double, включая бесконечности и NaN |
| `неотрицательное` (`нат`, `натуральное`) | целые от 0 до 2⁵³−1 |
| `целое` | целые от −(2⁵³−1) до 2⁵³−1 |
| `вес` (`стоимость`) | число не меньше нуля, включая +∞ |
| `сотых`, `тысячных` | целое число сотых или тысячных долей; для денег |
| `строка` | строка UTF-8; символ — строка из одного code point |
| `признак` | boolean: `да`, `нет` |
| `ничто` | одно значение `ничто` |
| `список Т` | однородный список |
| `«Имя»`, объявленное словом `объект` | структура с именованными полями |
| `«Имя»`, объявленное словом `тип` | enum с данными |
| `«Имя» от Т` | generic-тип |
| `функция из Т в Т` | ссылка на объявленную функцию |

`неотрицательное` годится там, где ждут `целое` или `число`; обратно — нет.
`список неотрицательное` годится там, где ждут `список числа`.

Арифметика узкий тип не сохраняет: сумма двух `неотрицательное` и любое
деление имеют тип `число`.

```
$ flang check сумма.flang
…
FLANG_TYPE в файле сумма.flang, строка 6, столбец 5: функция «Сумма» объявлена как неотрицательное, а тело даёт число
сумма.flang: не проверено — замечаний 1
```

Узкий тип получают литерал, `длина`, `код символа` и `если`, у которого обе
ветки узкие:

```flang
модуль «Узкие типы»

тотальная функция «Длина слова»
  принимает слово: строка
  возвращает неотрицательное
  длина слово

тотальная функция «Ноль или пять»
  принимает н: число
  возвращает неотрицательное
  если н не больше 0
    то 0
    иначе 5
```

Аргументы `flang run` сверяются с объявленными типами до вычисления:

```
$ flang run целое.flang --function «Целое» --args '{"а": 1.5, "б": 1, "в": 2}'
доказано: утверждений 0
FLANG_TYPE: вызов функции «Целое»: аргумент «а»: 1.5 не целое, а тип целое — целый
```

Деление на ноль даёт бесконечность, `0 делить на 0` — NaN. Сравнение с NaN
ложно в обе стороны. Минус ноль и ноль не равны: `-0 равен 0` — `нет`.

## Функции и завершаемость

```
[тотальная] функция «Имя» [от «П»]
  [принимает имя: Тип, имя: Тип]
  возвращает Тип
  [требует «имя» Условие]
  [убывает Выражение]
  [обеспечивает «имя» Условие]
  [пример «имя»
    дано имя равно Значение
    ожидается Значение]
  Тело
```

Части идут в этом порядке. Тело — одно выражение: `если … то … иначе …`,
`разбор`, `свёртка`, вызов, арифметика, конструктор; перед ним могут стоять
строки `пусть имя равно Выражение`. Ветка `иначе` обязательна. Присваивания
нет: повторное `пусть` с тем же именем заводит новую константу.

Вызов — `«Имя» от А и Б`. Слово `и` разделяет аргументы; логическое «и» —
`и притом`.

| Группа | Слова |
| --- | --- |
| арифметика | `плюс`, `минус`, `умножить на`, `делить на`, `остаток от`, `процентов от` |
| сравнение | `равен`, `не равен`, `больше`, `меньше`, `не больше`, `не меньше` |
| логика | `не`, `и притом`, `или` |

Слово `тотальная` требует от компилятора доказать, что функция завершается на
любом входе. Способов доказательства пять, и `flang check --proof` называет
способ у каждой функции:

```flang
модуль «Завершаемость»

тотальная функция «Квадрат»
  принимает х: число
  возвращает число
  х умножить на х

тотальная функция «Узлов»
  принимает места: список числа
  возвращает число
  пример «три элемента»
    дано места равно [1, 2, 3]
    ожидается 3
  разбор места
    случай пусто
      то 0
    случай голова и хвост
      то 1 плюс («Узлов» от хвост)

тотальная функция «Сумма до»
  принимает н: неотрицательное
  возвращает число
  пример «до четырёх»
    дано н равно 4
    ожидается 10
  если н не больше 0
    то 0
    иначе н плюс («Сумма до» от (н минус 1))

тотальная функция «Отсчёт»
  принимает н: число
  возвращает число
  если н не больше 0
    то 0
    иначе «Отсчёт» от (н минус 1)

тотальная функция «НОД»
  принимает а: число, б: число
  возвращает число
  убывает б
  пример «двенадцать и восемнадцать»
    дано а равно 12
    дано б равно 18
    ожидается 6
  если б равен 0
    то а
    иначе «НОД» от б и (а остаток от б)
```

| Функция | Как доказано, в выводе | Runtime check |
| --- | --- | --- |
| «Квадрат» | «композицией»: рекурсии нет | нет |
| «Узлов» | «структурой»: рекурсивный вызов получает часть аргумента | нет |
| «Сумма до» | «точным шагом»: параметр `неотрицательное` убывает на 1 | нет |
| «Отсчёт» | «постоянным шагом»: параметр `число` убывает на константу | есть |
| «НОД» | «объявленной мерой»: автор написал `убывает б` | есть |

У двух последних способов в программе остаётся runtime check: на каждом
рекурсивном вызове величина обязана строго убывать. Нарушение останавливает
вычисление:

```
$ flang run завершаемость.flang --function «НОД» --args '{"а": 12, "б": -1.5}'
доказано: утверждений 0
FLANG_MEASURE: тотальная функция «НОД»: мера на вызове «НОД» — «б» — не убыла. Завершение доказано тем, что она строго убывает; равенство цепочку не обрывает, а значит этот вызов может не кончиться никогда
```

Функцию, для которой завершаемость не доказана, компилятор с пометкой
`тотальная` не принимает:

```
$ flang check вечно.flang
…
FLANG_NOT_TOTAL в файле вечно.flang, строка 6, столбец 3: тотальная функция «Вечно»: рекурсивный вызов «Вечно» не убывает — аргумент 1 («н» add 1) увеличивает параметр «н». Передавайте часть аргумента: хвост списка из образца «голова и хвост», поле варианта из образца, поле записи или элемент коллекции
вечно.flang: не проверено — замечаний 1
```

Без слова `тотальная` та же функция проходит проверку, а при вычислении
останавливается на лимите шагов с ошибкой `FLANG_RECURSION_LIMIT`, код
возврата 1.

Функцию можно передать аргументом. Значение-функция — ссылка на объявленную
функцию, возможно с заданными первыми параметрами; лямбд нет.

```flang
модуль «Функции как значения»

тотальная функция «Удвоить»
  принимает х: число
  возвращает число
  х умножить на 2

тотальная функция «Прибавить»
  принимает а: число, б: число
  возвращает число
  а плюс б

тотальная функция «Применить дважды»
  принимает ф: функция из числа в число, х: число
  возвращает число
  ф от (ф от х)

тотальная функция «Проба»
  возвращает число
  пример «пятёрка удвоена дважды»
    ожидается 20
  «Применить дважды» от функция «Удвоить» и 5

тотальная функция «Проба с захватом»
  возвращает число
  пример «десятка прибавлена дважды»
    ожидается 25
  «Применить дважды» от (функция «Прибавить» с а равным 10) и 5
```

## Структуры и enum

```flang
модуль «Счёт»

объект «Позиция»
  название является строкой
  цена является числом
  скидка иногда является числом

тип «Счёт» это список «Позиция»

тип «Ответ»
  вариант Успех содержит значение: число
  вариант Отказ содержит причина: строка

тотальная функция «Проверить цену»
  принимает позиция: «Позиция»
  возвращает «Ответ»
  пример «цена есть»
    дано позиция равно запись «Позиция» с название равным "болт" и цена равным 30
    ожидается вариант Успех с значение равным 30
  пример «ноль — не цена»
    дано позиция равно запись «Позиция» с название равным "гайка" и цена равным 0
    ожидается вариант Отказ с причина равным "цена не положительна"
  если позиция.цена больше 0
    то вариант Успех с значение равным позиция.цена
    иначе вариант Отказ с причина равным "цена не положительна"

тотальная функция «Итог счёта»
  принимает счёт: «Счёт»
  возвращает число
  пример «две позиции»
    дано счёт равно [запись «Позиция» с название равным "болт" и цена равным 30, запись «Позиция» с название равным "гайка" и цена равным 12]
    ожидается 42
  свёртка счёт начиная с 0 как итог и позиция → итог плюс позиция.цена
```

`объект «Имя»` объявляет структуру; то же слово — `структура`. Поле
записывается `имя является Тип` или `«имя»: Тип`; поле `иногда является` —
необязательное. Значение строится формой `запись «Имя» с поле равным Значение
и поле равным Значение`, поле читается через точку. Лишнее поле — ошибка:

```
$ flang check поле.flang
…
FLANG_TYPE в файле поле.flang, строка 8, столбец 3: запись «Точка» не имеет поля «зет»
поле.flang: не проверено — замечаний 1
```

`тип «Имя»` с вариантами объявляет enum с данными, `тип «Имя» это Тип` —
type alias. Значение enum строится формой `вариант Имя с поле равным Значение`.

Generic-тип объявляется и применяется словом `от`:

```flang
модуль «Возможное значение»

тип «Возможно» от «А»
  вариант «Есть» содержит значение: «А»
  вариант «Нет»

тотальная функция «Обернуть» от «А»
  принимает значение: «А»
  возвращает «Возможно» от «А»
  вариант «Есть» с значение равным значение

тотальная функция «Значение или ноль»
  принимает возможное: «Возможно» от число
  возвращает число
  пример «есть — значение»
    дано возможное равно вариант «Есть» с значение равным 7
    ожидается 7
  пример «нет — ноль»
    дано возможное равно вариант «Нет»
    ожидается 0
  разбор возможное
    случай вариант «Есть» с значение как найденное
      то найденное
    случай «Нет»
      то 0
```

Исключений нет, и nullable-типов нет: `число` не может быть `ничто`, ветки
`если` с типами `число` и `ничто` — ошибка `FLANG_TYPE`. Значение, которого
может не быть, описывает тип вида Optional, как «Возможно» выше; ошибку — тип
вида Result, как «Ответ».

## Pattern matching: `разбор`

`разбор` выбирает ветку по варианту enum, по форме списка или строки.

| Pattern | Что берёт |
| --- | --- |
| `случай Имя` | вариант, поля не нужны |
| `случай вариант Имя с поле как имя` | вариант, поле получает имя |
| `случай пусто` | пустой список или пустая строка |
| `случай голова и хвост` | первый элемент (первый символ) и остаток |
| `случай любое` | всё остальное |

Компилятор проверяет, что разобраны все варианты и что каждая ветка достижима:

```
$ flang check светофор.flang
…
FLANG_MATCH_NOT_EXHAUSTIVE в файле светофор.flang, строка 11, столбец 3: разбор «Свет» не покрывает «Жёлтый»
светофор.flang: не проверено — замечаний 1
$ flang check порядок.flang
…
FLANG_MATCH_UNREACHABLE: случай недостижим: предыдущий случай «любое» покрывает всё
порядок.flang: не проверено — замечаний 1
```

Рекурсивный вызов от части разобранного значения — от `хвост` или от поля
варианта — компилятор принимает как доказательство завершаемости; так устроена
функция «Узлов» выше.

## Списки: map, filter, reduce

Циклов в языке нет. Список обходят `отобразить` (map), `отфильтровать`
(filter), `свёртка` (reduce) и рекурсия по `голова и хвост`. Список
неизменяем: каждая операция строит новый.

```flang
модуль «Списки»

тотальная функция «Произведение»
  принимает множители: список числа
  возвращает число
  пример «три множителя»
    дано множители равно [2, 3, 4]
    ожидается 24
  свёртка множители начиная с 1 как итог и множитель → итог умножить на множитель

тотальная функция «Квадраты»
  принимает стороны: список числа
  возвращает список числа
  пример «три квадрата»
    дано стороны равно [1, 2, 3]
    ожидается [1, 4, 9]
  отобразить стороны как сторона → сторона умножить на сторона

тотальная функция «Положительные»
  принимает остатки: список числа
  возвращает список числа
  пример «ноль и минус выброшены»
    дано остатки равно [3, 0, -1, 5]
    ожидается [3, 5]
  отфильтровать остатки где остаток → остаток больше 0

тотальная функция «Наоборот»
  принимает места: список числа
  возвращает список числа
  пример «три числа наоборот»
    дано места равно [1, 2, 3]
    ожидается [3, 2, 1]
  свёртка места начиная с пустой список как итог и место → приписать место к итог
```

| Операция | Значение |
| --- | --- |
| `длина Л` | число элементов |
| `голова Л`, `хвост Л` | первый элемент и остаток |
| `элемент N в Л` | элемент с номером N; нумерация с единицы |
| `добавить Х к Л` | новый список с Х в конце |
| `приписать Х к Л` | новый список с Х в начале |
| `Л содержит Х` | есть ли Х в списке |

Индекс вне границ проверку проходит и останавливает вычисление:

```
$ flang run границы.flang --function «Пятый»
доказано: утверждений 0
FLANG_BUILTIN_ARGS: «элемент»: индекс 5 вне списка длиной 3
```

Функции над списками, словарями и множествами — в стандартной библиотеке:
[`site/stdlib.ru.md`](site/stdlib.ru.md).

## Строки

Строка разбирается теми же patterns, что список: `пусто` и `голова и хвост`.
Длина и индексы считаются в code points, не в байтах.

```flang
модуль «Строки»

тотальная функция «Слова»
  принимает текст: строка
  возвращает список строки
  пример «по пробелу»
    дано текст равно "раз два три"
    ожидается ["раз", "два", "три"]
  разделить текст по " "

тотальная функция «Через запятую»
  принимает слова: список строки
  возвращает строка
  пример «три слова»
    дано слова равно ["раз", "два", "три"]
    ожидается "раз, два, три"
  соединить слова по ", "

тотальная функция «Середина»
  принимает текст: строка
  возвращает строка
  пример «со второго по четвёртый символ»
    дано текст равно "привет"
    ожидается "рив"
  подстрока текст с 2 по 4

тотальная функция «Гласных»
  принимает текст: строка
  возвращает число
  пример «в слове привет две гласные»
    дано текст равно "привет"
    ожидается 2
  разбор текст
    случай пусто
      то 0
    случай голова и хвост
      то (если "аеёиоуыэюя" содержит голова то 1 иначе 0) плюс («Гласных» от хвост)
```

| Операция | Значение |
| --- | --- |
| `длина С` | число символов |
| `символ N в С` | символ с номером N; нумерация с единицы |
| `подстрока С с А по Б` | символы с А по Б включительно |
| `разделить С по Р` | split: список строк |
| `соединить Л по Р` | join: список строк в одну строку через Р |
| `соединить А с Б` | конкатенация двух строк |
| `С содержит П`, `С начинается с П` | boolean |
| `код символа С`, `символ по коду N` | code point и обратно |
| `разложить С на символы` | список символов |
| `к числу С`, `к строке Х` | преобразование |
| `хеш256 С` | SHA-256 в шестнадцатеричной записи |

Регулярных выражений среди конструкций языка нет; сопоставление со
строкой-шаблоном дают модули стандартной библиотеки.

## Доказательства

### Precondition и postcondition

`требует «имя» Условие` — precondition: что должно быть верно на входе.
`обеспечивает «имя» Условие` — postcondition: что функция гарантирует о
значении `результат`. Имя обязательно.

```flang
модуль «Гарантии»

тотальная функция «Длина слова»
  принимает слово: строка
  возвращает число
  обеспечивает «длина неотрицательна» результат не меньше 0
  длина слово

тотальная функция «Удвоить»
  принимает н: неотрицательное
  возвращает число
  обеспечивает «результат чётен» (результат остаток от 2) равен 0
  пример «три удвоено»
    дано н равно 3
    ожидается 6
  н умножить на 2
```

```
$ flang check гарантии.flang --proof
гарантии.flang: ПРОВЕРЕНО С ОПОРОЙ, И ОПОРА НЕ СУДИЛАСЬ (спросить: --строго) — утверждений 2: доказано 1, условно 0, сетка 1, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
…
  постусловие «длина неотрицательна» функции «Длина слова» — доказано сведением цели с телом функции: правило «неотрицательность по построению», объявленные типы аргументов не понадобились — утверждение обо ВСЕХ входах, а не о написанных; теоремы при нём нет и не нужно
  постусловие «результат чётен» функции «Удвоить» — сетка 1 значение (примеры функции): нарушений НЕ ИСКАЛИ — прогона примеров не было, посчитано только их число. Это не доказательство — теоремы при утверждении нет
…
```

Первую postcondition prover доказал для всех входов. Вторая не доказана: у неё
есть только unit-тест. Недоказанная postcondition остаётся в программе как
runtime check на каждом возврате из функции; нарушение — ошибка
`FLANG_PROPERTY`.

Postcondition, ложную на NaN, компилятор отвергает и называет контрпример:

```
$ flang check ложное.flang
…
FLANG_BOUND_ON_NAN в файле ложное.flang, строка 6, столбец 3: постусловие «результат меньше ста» функции «Увеличить» ЛОЖНО, и контрпример назван: «н» объявлен типом «число», а «не число» живёт в этом типе и стоит ВНЕ ПОРЯДКА …
ложное.flang: не проверено — замечаний 1
```

Precondition обязан выполнить вызывающий код. Для каждого вызова внутри
программы prover доказывает precondition из того, что известно в месте вызова:
из literal-аргумента, из типа аргумента, из precondition самой вызывающей
функции.

```flang
модуль «Предусловие»

тотальная функция «Доля»
  принимает часть: число, целое: число
  возвращает число
  требует «делитель не меньше единицы» целое не меньше 1
  часть делить на целое

тотальная функция «Половина»
  принимает часть: число
  возвращает число
  пример «половина десяти»
    дано часть равно 10
    ожидается 5
  «Доля» от часть и 2

тотальная функция «Любая доля»
  принимает часть: число, целое: число
  возвращает число
  требует «делитель не меньше единицы» целое не меньше 1
  «Доля» от часть и целое
```

Вызов, для которого precondition доказать не из чего, — ошибка
`FLANG_PRECONDITION_CALL`, код возврата 1.

### Результаты проверки

`flang check --proof` печатает про каждую postcondition и каждое свойство один
результат.

| В выводе написано | Что это значит |
| --- | --- |
| «доказано» | верно для всех входов; выведено из типов и тела функции |
| «доказано индукцией по «Т»» | то же, индукцией по вариантам типа или по `неотрицательное` |
| «доказано ПРИ УСЛОВИИ» | вывод верен, но опирается на свойство, которое само не доказано |
| «сетка N» | есть только N unit-тестов; доказательства нет |
| «объявлено, не доказано» | нет ни доказательства, ни тестов |

Первая строка отчёта подводит итог и называет код возврата:

| Итог в выводе | Когда | Код |
| --- | --- | --- |
| «ПРОВЕРЕНО САМОСТОЯТЕЛЬНО» | доказано всё | 0 |
| «ПРОВЕРЕНО С ОПОРОЙ» | часть держится только на unit-тестах | 0; с ключом `--strict` — 3 |
| «НЕ ПРОВЕРЕНО» | есть «объявлено, не доказано» или «доказано ПРИ УСЛОВИИ» | 3 |

`flang check` без `--proof` отвечает кодом 0, когда программа прошла синтаксис,
типы, завершаемость и unit-тесты; недоказанная postcondition этот код не
меняет. Для CI — `flang check --proof --strict`. Ключ `--json` печатает отчёт в
машинном виде.

Prover не перебирает варианты доказательства и не использует аксиом. Он
применяет правила из закрытого списка
[`flang/proof/tables/inference-rules.tsv`](../flang/proof/tables/inference-rules.tsv) —
97 правил вывода и 15 запретов, сосчитано в этой таблице 3 октября 2026.
Правило, которым доказана postcondition, названо в отчёте.

### Свойство каждого элемента списка

Форма `для всех имя из Список: Условие` говорит о каждом элементе. Prover
доказывает её по тому, как тело функции строит список.

```flang
модуль «Отбор»

тотальная функция «Только положительные»
  принимает остатки: список числа
  возвращает список числа
  обеспечивает «все положительны» для всех остаток из результат: остаток больше 0
  пример «смесь»
    дано остатки равно [3, 0, 5]
    ожидается [3, 5]
  отфильтровать остатки где остаток → остаток больше 0
```

```
$ flang check отбор.flang --proof
…
  постусловие «все положительны» функции «Только положительные» — доказано сведением цели с телом функции: правило «все элементы по построению», объявленные типы аргументов не понадобились — утверждение обо ВСЕХ входах, а не о написанных; теоремы при нём нет и не нужно
…
```

После двоеточия снова стоит условие, поэтому `для всех` вкладываются. «Найдётся
значение» записывается с явным значением: `есть такой м, а именно Т, что
Условие`; значение называет автор.

### Свойство отдельно от функции

`утверждение «имя»` записывает свойство, не привязанное к одной функции.
Строка `для всех имя: Тип` вводит переменную, `таких что Условие` —
ограничение на неё.

```flang
модуль «Свободные утверждения»

утверждение «длина пустого списка нулевая»
  утверждаем (длина пустой список) равен 0

утверждение «ноль нейтрален при сложении»
  для всех н: неотрицательное таких что н больше 0
  утверждаем (н плюс 0) равен н
```

```
$ flang check утверждения.flang --proof
утверждения.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 2: доказано 2, условно 0, сетка 0, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
…
```

### Теорема

Когда prover не доказал postcondition или свойство сам, доказательство пишет
автор: `теорема` с тем же именем.

```flang
модуль «Своё натуральное»

тип «Нат»
  вариант «Ноль»
  вариант «Следующий» содержит пред: «Нат»

тотальная функция «К числу»
  принимает н: «Нат»
  возвращает число
  разбор н
    случай вариант «Ноль»
      то 0
    случай вариант «Следующий» с пред как п
      то («К числу» от п) плюс 1

утверждение «шаг растит счёт на один»
  для всех н: «Нат»
  утверждаем («К числу» от (вариант «Следующий» с пред равным н)) равно ((«К числу» от н) плюс 1)

теорема «шаг растит счёт на один»
  дано н: «Нат»
  утверждаем («К числу» от (вариант «Следующий» с пред равным н)) равно ((«К числу» от н) плюс 1)
  индукция по н
    случай вариант «Следующий» с пред как п
      то по предположению
  следовательно доказано
```

```
$ flang check натуральное.flang --proof
натуральное.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 1: доказано 1, условно 0, сетка 0, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
…
  утверждение «шаг растит счёт на один» — доказано индукцией по «Нат»: база 1 случай, шаг при допущении на частях (1 случай), правила сведения: тождество после переписки допущением — утверждение обо ВСЕХ входах типа «Нат», а не о написанных
…
```

Без теоремы то же свойство получает результат «объявлено, не доказано» и код
возврата 3.

Каждый шаг теоремы ссылается на то, из чего он следует:

| Ссылка | На что |
| --- | --- |
| `по свойству «имя»` | доказанная postcondition или доказанное свойство |
| `по предположению` | предположение индукции или precondition функции |
| `по примеру «имя»` | unit-тест функции; закрывает случай с одним значением |
| `по закону «имя»` | правило из списка правил prover'а |

Промежуточный шаг пишется `затем Условие по Ссылка`. Индукция идёт по вариантам
enum или по `неотрицательное` (`индукция по н убывает н`).

### Силлогизм

`следует «имя»` — вывод из уже доказанных свойств. Это теорема, у которой
последняя строка `следовательно доказано` подразумевается.

В примере ниже посылка «все люди смертны» верна потому, что функция «Смертен»
определена как `да`: посылка задана определением, а не допущением. Как записать
посылки допущениями и что prover тогда доказывает — ADR-0050 и пробы
`flang/proof/probes/syllogism/assumptions/`.

```flang
модуль «Силлогизм»

тип «Человек»
  вариант «Человек»

тотальная функция «Смертен»
  принимает кто: «Человек»
  возвращает признак
  обеспечивает «всякий человек смертен» результат
  да

утверждение «все люди смертны»
  для всех кто: «Человек»
  утверждаем («Смертен» от кто)

утверждение «Сократ смертен»
  для всех сократ: «Человек»
  утверждаем («Смертен» от сократ)

следует «Сократ смертен»
  дано сократ: «Человек»
  утверждаем («Смертен» от сократ)
  по свойству «все люди смертны»
```

```
$ flang check силлогизм.flang --proof
силлогизм.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 3: доказано 3, условно 0, сетка 0, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
…
  утверждение «Сократ смертен» — доказано: терм принят ядром, 1 шаг, правило «цель есть допущение», основания: утверждение «все люди смертны» — утверждение обо ВСЕХ входах
…
```

Вывод, который из названного свойства подстановкой не получается, — ошибка
`FLANG_PROOF_STEP`. Если свойство, на которое ссылается вывод, само не
доказано, результат — «доказано ПРИ УСЛОВИИ», код возврата 3.

### Независимый checker

`flang check --proof --record <файл>` записывает доказательства в текстовый
файл. Его перепроверяет отдельная программа на C
[`flang/proof/checker/checker.c`](../flang/proof/checker/checker.c): она читает
исходник и этот файл, компилятор flang ей не нужен.

```
$ cc -std=c99 -O2 -o checker flang/proof/checker/checker.c
$ flang check натуральное.flang --proof --record натуральное.record
…
$ ./checker натуральное.flang натуральное.record
ПРОВЕРЕНО — запись сошлась с исходником, и всё доказанное проиграно заново: утверждений 1, шагов сверено с исходником 1, …
```

| Код | Ответ |
| --- | --- |
| 0 | файл доказательств соответствует исходнику, доказанное перепроверено |
| 3 | противоречий нет, но часть мест принята без перепроверки; места названы |
| 1 | файл доказательств расходится с исходником |
| 2 | неверный вызов |

Файл, в котором шаг доказательства подменён, отвергается:

```
$ ./checker натуральное.flang подмена.record
НЕ СОШЛОСЬ: теорема «шаг растит счёт на один», строка 25: запись говорит «по примеру «нет»», а в исходнике написано «по предположению»
```

Как читать отчёт и что доказано в самом компиляторе —
[`site/what-is-proved.ru.md`](site/what-is-proved.ru.md) и
[`site/how-proofs-work.ru.md`](site/how-proofs-work.ru.md).

### Запуск недоказанной программы

`flang run` и `flang io` перед работой проверяют доказательства во всей
программе вместе с импортированными модулями. Если что-то не доказано,
программа не запускается:

```
$ flang run гарантии.flang --function «Удвоить» --args '{"н": 3}'
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск только по явному согласию: --на-веру
…
$ echo $?
3
$ flang run гарантии.flang --function «Удвоить» --args '{"н": 3}' --unproven warn
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск по ключу --unproven warn
6
```

Ключ `--trust` (`--на-веру`) запускает программу без проверки доказательств.
То же поведение задаётся ключом `unproven` в файле настроек.

## Side effects: `план` и `flang io`

Функция не читает файлы и не ходит в сеть. Она возвращает команду — «прочитай
файл», «сделай запрос», — а выполняет команду рантайм `flang io` и вызывает
функцию снова с ответом. Поэтому вся логика остаётся обычными функциями,
которые проверяются unit-тестами без диска и сети.

`план` — state machine. Первая функция возвращает начальное состояние. Вторая
получает состояние и ответ на предыдущую команду и возвращает значение типа
`«Продолжение»`: следующую команду или конец работы. В коде команда имеет тип
`«Поручение»`, ответ рантайма — тип `«Отклик»`.

```flang
модуль «План записи»

тип «Ход»
  вариант Начало
  вариант Конец

тотальная функция «Начать»
  возвращает «Ход»
  вариант Начало

тотальная функция «Дальше»
  принимает ход: «Ход», отклик: «Отклик»
  возвращает «Продолжение»
  пример «сперва — команда записать файл»
    дано ход равно вариант Начало
    дано отклик равно вариант «Пока ничего»
    ожидается вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант Конец)
  разбор ход
    случай Начало
      то вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант Конец)
    случай Конец
      то вариант «Конец работы» с значение равным 6

план «Записать привет»
  состояние «Ход»
  начинает с «Начать»
  обрабатывает «Дальше»
```

```
$ flang io план.flang --in-dir
доказано: утверждений 0
{"plan":"Записать привет","result":6,"orders":1,"log":[{"поручение":{"variant":"Записать файл","fields":{"путь":"привет.txt","содержимое":"привет"}},"отклик":{"variant":"Записано","fields":{"сколько":6}}}]}
$ flang io план.flang --no-write
доказано: утверждений 0
{"plan":"Записать привет","result":6,"orders":1,"log":[{"поручение":{"variant":"Записать файл","fields":{"путь":"привет.txt","содержимое":"привет"}},"отклик":{"variant":"Сбой","fields":{"код":"FLANG_IO_DENIED","сообщение":"хозяину запрещено писать файлы"}}}]}
```

Ошибка ввода-вывода — не исключение, а ответ «Сбой» с кодом; программа
разбирает его через `разбор`.

Типы `«Продолжение»`, `«Поручение»` и `«Отклик»` встроены, набор их вариантов
закрыт.

| Вариант `«Продолжение»` | Что происходит | Код возврата `flang io` |
| --- | --- | --- |
| `«Сделать»` (поля `поручение`, `потом`) | рантайм выполняет команду и вызывает функцию снова | — |
| `«Конец работы»` (поле `значение`) | успешное завершение | 0 |
| `«Провал»` (поля `код`, `сообщение`) | программа сообщила об ошибке | 1 |
| `«Не проверено»` (поля `код`, `сообщение`) | программе нечем было проверить | 3 |

| Область | Команды — варианты `«Поручение»` |
| --- | --- |
| файлы | «Прочитать файл», «Записать файл», «Прочитать октеты из файла», «Записать октеты в файл», «Удалить файл», «Перечислить каталог», «Завести временный каталог» |
| сеть | «Запросить» (HTTP), «Открыть соединение», «Принять соединение», «Прочитать из соединения», «Ответить в соединение», «Прочитать октеты из соединения», «Ответить октетами в соединение» |
| внешние программы | «Запустить процесс», «Запустить процесс с вводом», «Запустить процесс с пределом» |
| время и случайность | «Текущее время», «Случайное число» |
| терминал | «Показать», «Ждать событие», «Размер экрана» |
| окружение | «Прочитать переменную среды», «Прочитать доводы» |

Ответы — варианты `«Отклик»`: «Пока ничего», «Прочитано», «Записано», «Ответ
сети», «Отметка времени», «Выпало», «Показано», «Случилось», «Срок вышел»,
«Перечислено», «Процесс завершён», «Процесс убит», «Процесс оборван»,
«Соединение открыто», «Октеты», «Сбой», «Убрано», «Заведено», «Значение среды»,
«Переменной среды нет», «Доводы», «Экран».

### Предел чужому процессу: память и срок

`«Запустить процесс»` отдаёт программе всю машину: сколько она возьмёт памяти и
сколько проработает, решает она сама. В оболочке это ограничивают двумя
приборами — `ulimit -v` и `kill -9` по часам, — и ровно их называет третье
поручение:

```flang
вариант «Запустить процесс с пределом»
  с программа равным "./stend"
  и аргументы равным пустой список
  и память равным 65536      # килобайт адресного пространства; 0 — без предела
  и срок равным 2000         # миллисекунд от ЗАПУСКА; 0 — без предела
```

Пределы ДВА, и кладут их разные руки — поэтому и отклики разные:

| предел | кто держит | чем кончается | отклик |
| --- | --- | --- | --- |
| `память` | ядро на дитя, `setrlimit(RLIMIT_AS)` до `execvp` — то же, что `ulimit -v` | дитя упирается САМО: `malloc` отказывает, дитя печатает своё и кончается своим кодом | `«Процесс завершён»` с его кодом и его `ошибки` |
| `срок` | САМ хозяин по своим часам | хозяин бьёт `SIGKILL` | `«Процесс оборван»` с полями `предел` (мс), `вывод`, `ошибки` |

Разница названа нарочно: по памяти хозяин процесса НЕ УБИВАЛ и причины его
смерти не знает — дитя могло упасть и по другой причине, и объявить «это была
память» значило бы гадать. По сроку убил он сам, и он же называет.

`«Процесс оборван»` — отдельный отклик, а не `«Сбой»`, потому что `«Сбой»`
несёт только `код` и `сообщение` и ВЫБРОСИЛ БЫ напечатанное. А напечатанное до
обрыва — ровно то, ради чего предел и ставят.

Срок поручения и срок тишины хозяина (`--timeout`, умолчание 30 000 мс) —
РАЗНЫЕ сроки, и один другого не отменяет: первый считается от запуска, второй —
от последнего напечатанного байта. Ждут оба, бьёт тот, что раньше; по тишине
хозяин отвечает `«Сбой»` с кодом `FLANG_IO_TIMEOUT`, по сроку поручения —
`«Процесс оборван»`. Поэтому план, назвавший `срок равным 0`, из-под хозяйского
срока НЕ выходит.

Своего полномочия у предела нет, и это не упущение: предел не добавляет власти,
а отнимает. Запрещает поручение тот же `--no-spawn`, и тем же словом —
«хозяину запрещено запускать процессы». Отдельное полномочие понадобилось бы
для другого дела — убить процесс, которого план НЕ ЗАПУСКАЛ, по номеру или по
имени; этого в языке нет нарочно, разбор — в
[ADR-0061](adr/0061-killing-a-process-and-bounding-its-resources.md).

Дробь и отрицательное отбиваются громко, `«Сбой»` с кодом `FLANG_IO_SPAWN`:
предел в пол-килобайта — это описка, а исполнять описку молча хуже, чем
отказать.

Аргументы программы — всё, что стоит в командной строке после отдельного `--`;
их отдаёт команда «Прочитать доводы»:

```
$ flang io доводы.flang -- раз два три
доказано: утверждений 0
{"plan":"Сосчитать доводы","result":3,"orders":1,"log":[{"поручение":{"variant":"Прочитать доводы","fields":{}},"отклик":{"variant":"Доводы","fields":{"доводы":["раз","два","три"]}}}]}
```

Права рантайма сужаются ключами `--no-read`, `--no-write`, `--no-net`,
`--no-clock`, `--no-random`, `--no-spawn`, `--no-env`, `--no-args`,
`--no-screen`; `--in-dir` запрещает пути вне каталога входного файла. По
умолчанию разрешено всё.

Скрипты самого репозитория — такие же программы в файлах `.fscript`; их
выполняет та же команда `flang io`.

## Процессы

`процесс` — actor: состояние, тип принимаемых сообщений и функция-обработчик.
Обработчик — обычная тотальная функция: получает состояние и сообщение,
возвращает новое состояние и список действий. Отправка сообщения другому
процессу — элемент этого списка, а не вызов. `надзор` — supervisor: что делать,
когда процесс упал. `прогон` — тест сценария с заданной последовательностью
сообщений.

```flang
модуль «Счётчик»

объект «Счёт»
  «всего»: число

объект «Отклик»
  «состояние»: «Счёт»
  «действия»: список «Действие»

тип «Команда»
  вариант «прибавить» содержит «сколько»: число

процесс «Счётчик»
  состояние «Счёт»
  начинает с «пустой счёт»
  принимает «Команда»
  обрабатывает «шаг счёта»

надзор «Учёт»
  процесс «Счётчик» стратегия «перезапустить»
  порог отказов 3 за 5000 миллисекунд иначе «передать выше»

тотальная функция «пустой счёт»
  возвращает «Счёт»
  запись «Счёт» с «всего» равным 0

тотальная функция «шаг счёта»
  принимает текущее: «Счёт», сообщение: «Команда»
  возвращает «Отклик»
  пример «прибавление меняет состояние и ничего не шлёт»
    дано текущее равно (запись «Счёт» с «всего» равным 1)
    дано сообщение равно (вариант «прибавить» с «сколько» равным 2)
    ожидается (запись «Отклик» с «состояние» равным (запись «Счёт» с «всего» равным 3) и «действия» равным [])
  разбор сообщение
    случай вариант «прибавить» с «сколько» как сколько
      пусть новое равно (запись «Счёт» с «всего» равным (текущее.«всего» плюс сколько))
      запись «Отклик» с «состояние» равным новое и «действия» равным []

прогон «два прибавления»
  семя 1
  дано «Счётчик» принимает (вариант «прибавить» с «сколько» равным 2)
  дано «Счётчик» принимает (вариант «прибавить» с «сколько» равным 3)
  ожидается «Счётчик» равен (запись «Счёт» с «всего» равным 5)
```

Варианты встроенного типа `«Действие»`: «отправить», «через», «остановить»,
«отложить», «продолжить», «породить».

`flang check` на программе с процессами отвечает кодом 2: типы, завершаемость
и unit-тесты обработчиков проверены, а сами объявления `процесс`, `надзор` и
`прогон` проверены не полностью, и вывод это говорит. Код с планировщиком
процессов генерируется для целей `c`, `elixir`, `js` и `ts`.

Модель процессов, supervision и работа на нескольких узлах —
[`site/processes.ru.md`](site/processes.ru.md).

## Модули и пакеты

```
модуль «Имя»
  [экспортирует «А», «Б»]
  [использует «Модуль» [из "путь"] [только «А», «Б»]]
```

`использует` — import. Без строки `экспортирует` модуль экспортирует всё. Имя,
которого в списке экспорта нет, в импортирующем модуле неизвестно — ошибка
`FLANG_UNKNOWN_NAME`.

```flang
модуль «Библиотека»
  экспортирует «Утроить»

тотальная функция «Утроить»
  принимает н: число
  возвращает число
  н умножить на 3

тотальная функция «Скрытая»
  возвращает число
  1
```

```flang
модуль «Приложение»
  использует «Библиотека»

тотальная функция «Девять»
  возвращает число
  пример «три утроено»
    ожидается 9
  «Утроить» от 3
```

Модуль ищется по имени из первой строки файла, а не по имени файла. Порядок
поиска: каталог импортирующего файла; каталоги выше него до корня проекта;
каталоги из переменной `FLANG_MODULE_DIR`; библиотека, поставленная с
компилятором. Корень проекта — ближайший каталог с `.flangrc`, `.git` или
`flang.package`. Модуль не найден — `FLANG_IMPORT_NOT_FOUND`. Два файла с одним
именем модуля — `FLANG_IMPORT_AMBIGUOUS` с обоими путями. Форма `из "путь"`
называет файл прямо; путь считается от импортирующего файла.

Модули стандартной библиотеки импортируются по имени, например
`использует «Lists»`.

`flang lock` печатает lock-файл — JSON с исходниками модулей, импортированных
формой `из "путь"`, и sha256 каждого. Если файл `flang.lock` лежит рядом с
программой, команды берут эти модули из него, и исходники на диске не нужны.

`flang package` печатает пакет: тот же JSON с именем и версией из файла
`flang.package`. Пакет импортируется как файл:

```flang
модуль «Пользователь пакета»
  использует «Discount» из "discount.flang-package"

тотальная функция «Привет»
  возвращает строка
  пример «приветствие из пакета»
    ожидается "Привет, мир!"
  «Поприветствовать» от "мир"
```

Пакет, изменённый после сборки, отвергается:

```
$ flang check пользователь.flang
FLANG_PACKAGE: адрес модуля «Discount» не сходится с его исходником: правлен или испорчен
```

`flang new <имя>` создаёт каталог пакета: модуль с unit-тестом,
`flang.package`, каталог `fspec/` и README. Подробно —
[`site/packages.ru.md`](site/packages.ru.md).

## Целевые языки

`flang emit <файл> --target <цель>` генерирует код на одном из десяти языков:
`c`, `cpp`, `go`, `rust`, `java`, `js`, `ts`, `elixir`, `python`, `csharp`.
Перед генерацией программа проходит те же проверки, что у `flang check`, кроме
unit-тестов; если есть ошибка, код не генерируется.

```
$ flang emit завершаемость.flang --target c --out out
напечатано файлов 6, байт …, в out
…
$ ls out
Makefile  flang_cli.c  flang_runtime.c  flang_runtime.h  zavershaemost.c  zavershaemost.h
$ make -C out
…
$ printf '%s\n' '{"fn":"НОД","args":[{"n":"12"},{"n":"18"}]}' | out/flang_cli
{"ok":true,"value":{"n":"6"}}
```

Рядом с модулем генерируются рантайм, файл сборки и программа `flang_cli`,
которая читает запросы JSON из stdin; ключ `--no-cli` её не генерирует. Имя
файла модуля — транслитерация имени модуля, поэтому модулю, который переводится
в другой язык, дают латинское имя.

В сгенерированном коде остаются лимиты шагов и глубины рекурсии, runtime checks
убывания у рекурсии и runtime checks недоказанных postconditions. Для
доказанных postconditions проверок в коде нет. Ключ `--no-postconditions`
убирает из кода все проверки postconditions.

| Объявление | Цели |
| --- | --- |
| функции, типы, теоремы | все десять |
| `процесс`, `надзор`, `прогон` | `c`, `elixir`, `js`, `ts`; у остальных — ошибка, код 1 |
| `план` | `js`, `ts`; у остальных — `FLANG_PLAN_UNSUPPORTED`, код 1 |

Сгенерированные файлы по целям — [`guide/emit-walkthrough.ru.md`](guide/emit-walkthrough.ru.md),
встраивание в чужую программу — [`site/embedding.ru.md`](site/embedding.ru.md).

| Команда | Что делает |
| --- | --- |
| `flang check <файл>` | синтаксис, типы, завершаемость, доказательства, unit-тесты |

| `flang ast <файл>` | AST в JSON |
| `flang tokens <файл>` | поток токенов лексера |
| `flang lock <файл>` | печатает lock-файл |
| `flang package <файл>` | печатает пакет |
| `flang new <имя>` | создаёт каталог пакета |
| `flang repl [файл]` | REPL; то же — `flang` без аргументов в терминале |
| `flang lsp` | language server для редактора |
| `flang --mcp-mode` | MCP-сервер для ИИ-помощника |

`flang <команда> --help` перечисляет ключи команды. Аргументы `flang run` —
плоский объект JSON со скалярами; список или вложенный объект не принимается.

| Код возврата | Значение |
| --- | --- |
| 0 | сделано |
| 1 | программа не прошла проверку, вычисление остановлено ошибкой, `facts` опровергла условие или программа под `io` вернула «Провал» |
| 2 | неверный вызов; у `check` — в программе есть объявления, которые компилятор проверяет не полностью |
| 3 | сделано, но проверено не всё: недоказанное под `check --proof`, отказ `run` и `io` запускать недоказанную программу, «Не проверено» под `io` |
| 4 | `check --fast`: доказательства и unit-тесты не запускались |
| 5 | остановка на лимите памяти |

Лимит памяти задаёт ключ `--memory-limit N` (`--предел-памяти`), число с
буквой K, M, G или T; у `check`, `test` и `run` по умолчанию три четверти
памяти машины, 0 снимает лимит:

```
$ flang run память.flang --function «Раздуть» --args '{"текст":"а","раз":28}' --memory-limit 32M
FLANG_MEMORY: недостаточно памяти
FLANG_MEMORY: прогон остановлен на пределе памяти 32 МиБ: занято 25 МиБ, просили ещё 25 165 880 байт
  считалась функция «Раздуть», шагов программы 452
…
```

Ошибка печатается строкой `КОД в файле <путь>, строка N, столбец M: текст`.
Справочник команд — [`site/cli.ru.md`](site/cli.ru.md), справочник ошибок —
[`site/diagnostics.ru.md`](site/diagnostics.ru.md).

## Файл настроек

Настройки читаются из файла `.flangrc`: строки `ключ = значение`, строка с `#`
в начале пропускается, незнакомый ключ пропускается. Файл ищется от рабочего
каталога вверх до корня проекта, затем в домашнем каталоге.

Компилятор сам читает из файла ключ `unproven` — что делать `flang run` и
`flang io` с программой, в которой не всё доказано.

| Значение | Поведение |
| --- | --- |
| `refuse` | не запускать, код возврата 3; значение по умолчанию |
| `warn` | напечатать результат проверки и запустить |
| `allow` | запустить без проверки доказательств; то же, что `--trust` |

```
$ cat .flangrc
unproven = warn
$ flang run гарантии.flang --function «Удвоить» --args '{"н": 3}'
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск по настройке «unproven = warn» (…/.flangrc)
6
```

Приоритет: ключ командной строки `--unproven`, переменная окружения
`FLANG_UNPROVEN`, `.flangrc`, значение по умолчанию. Значение не из списка —
ошибка с кодом возврата 2.

Строки `script.<имя> = <команда>` — короткие команды проекта; их запускает
`flang run-script <имя>`. Остальные ключи (`language`, `surface`, `color`, `page`,
`version`, `name`, `license`, `repository`, `issues`) читают скрипты репозитория и
сборка сайта: [`guide/settings.ru.md`](guide/settings.ru.md).

## Ограничения

- Числа — IEEE-754 double. Целые точны до 2⁵³−1, длинной арифметики в языке
  нет. Округления нет. Сложение дробных чисел не ассоциативно:
  `(0.1 плюс 0.1) плюс 0.6` даёт `0.8`, `0.1 плюс (0.1 плюс 0.6)` —
  `0.7999999999999999`.
- Присваивания, циклов, исключений, nullable-типов, лямбд и замыканий нет.
  Значение-функция захватывает только первые параметры объявленной функции.
- Программа проверяется целиком: раздельной компиляции нет, двух версий одного
  модуля в программе не бывает.
- Side effects внутри функции невозможны. Свойство о состоянии во времени, о
  side effect или о параллельном исполнении записать нечем: `обеспечивает`
  говорит о значении функции.
- Prover не ищет доказательство: он применяет правила из закрытого списка, а
  шаги теоремы пишет автор. Условие ветки `если` он как известный факт не
  использует.
- Строгое сравнение в precondition prover на literal-аргументе не доказывает:
  вызов `«Доля» от часть и 2` при `требует … целое больше 0` — ошибка
  `FLANG_PRECONDITION_CALL`, а при `целое не меньше 1` тот же вызов принят.
- `вес`, `сотых` и `тысячных` принимаются как типы, но их правила арифметики
  не проверяются: `вес минус вес` и `сотых плюс тысячных` проходят проверку.
  Нижняя граница `вес` у аргумента `flang run` не проверяется: значение −1
  принимается.
- Объявления теории категорий (`категория`, `морфизм`, `функтор`, `моноид`,
  `монада`) и процессов (`процесс`, `надзор`, `прогон`) компилятор проверяет
  не полностью: `flang check` отвечает кодом 2, `flang emit` на программе с
  морфизмами, моноидами или монадами — кодом 3. На программе с процессами
  `flang check --proof` отвечает кодом 0, хотя `flang check` — кодом 2.
- В lock-файл `flang lock` попадают только модули, импортированные формой
  `из "путь"`; модуль, найденный по имени, в него не записывается.
- Независимый checker перепроверяет не каждое доказательство: часть мест он
  принимает со слов ядра и называет их в отчёте. На пробе
  [`step-by-restricted-postcondition.flang`](../flang/proof/checker/tests/families/citation/step-by-restricted-postcondition.flang)
  компилятор отвечает кодом 0, а checker — кодом 3.
- Доказательство относится к исходной программе. Соответствие сгенерированного
  кода исходнику в общем виде не доказано. Для цели `c` ключ `--protocol <файл>`
  печатает протокол перевода, который сверяет программа
  [`flang/translation/matcher.c`](../flang/translation/matcher.c); она покрывает
  не все конструкции, и непокрытое называет сама: на честной паре с
  `отфильтровать` — код 0 («узлов в протоколе 13; переиграно правилом 8,
  принято на слово 0»), на честной паре с `убывает` — код 3 и строка «узлов
  сторожа меры 10: их места в исходнике не сличались». Правил в закрытом
  списке 41; строгость сравнения мер и ветвь, продолжающая виток, не
  переигрываются.
- `flang emit` не запускает unit-тесты и не сверяет аргументы программы
  `flang_cli` с объявленными типами; unit-тесты запускают `flang check` и
  `flang test`.
- `план` генерируется только для `js` и `ts`, процессы — для `c`, `elixir`,
  `js` и `ts`.
- Запросы `https` рантайм `flang io` выполняет внешней программой `curl`.
  Своей реализации TLS у него нет, «Открыть соединение» — TCP без шифрования,
  UDP нет.
- Компилятор отвечает по-русски; ключ `language` файла настроек язык его
  сообщений не меняет.
- Есть два места, где «доказано» не значит «верно» (счёт — открытые строки
  `flang/proof/tables/consistency-violations.tsv`, снят 3 октября 2026).
  Шаг по правилу, которого нет ни в таблице правил вывода, ни в приёмке Lean,
  не проверяет никто. Запись, в которой доказанным не числится ничего,
  проверяющая программа принимает кодом 0 и словами «ПРОВЕРЕНО ВПУСТУЮ».
  Каждое место с пробами —
  [`flang/proof/known-soundness-violations.md`](flang/proof/known-soundness-violations.md);
  открытые пункты печатает
  `bootstrap/flang io scripts/four-coverages.fscript --plan Measure`.
- Сам компилятор формально не верифицирован. Без доказательства принимаются
  prover, компилятор, рантайм, компилятор C и железо. Для safety-critical
  систем язык не годится.

Те же ограничения с примерами — [`guide/limits.ru.md`](guide/limits.ru.md).
