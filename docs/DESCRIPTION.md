# flang — описание языка

flang — чистый функциональный язык со строгой статической типизацией. Программа
проверяется до запуска: компилятор разбирает файл, выводит типы, доказывает
завершаемость функций, помеченных `тотальная`, прогоняет примеры, записанные
внутри функций, и пробует доказать утверждения о результате. Проверенная
программа вычисляется командой `flang run` или переводится в один из десяти
целевых языков командой `flang emit`.

Описание соответствует выпуску 0.7.23. Каждый пример ниже проходит
`flang check`. Вывод команд приведён дословно; пропущенные строки и сокращённые
пути отмечены многоточием.

## Первая программа

```flang
модуль «Удвоение»

тотальная функция «Удвоить»
  принимает н: число
  возвращает число
  пример «два»
    дано н равно 2
    ожидается 4
  н умножить на 2
```

```
$ flang check удвоение.flang
модуль «Удвоение»: функций 1, из них с доказанным завершением 1; типов 0
удвоение.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
$ flang run удвоение.flang --function «Удвоить» --args '{"н": 21}'
доказано: утверждений 0
42
```

Файл начинается строкой `модуль «Имя»`. Ниже, у левого края, стоят объявления;
их порядок свободен, функция может вызывать объявленную ниже. Пример внутри
функции — часть программы: он вычисляется при каждой проверке файла.

## Запись программы

Расширений файла четыре, они равноправны: `.flang`, `.fp`, `.фп`, `.фланг`.

Блок задаётся отступом. Круглые скобки только группируют выражения.

Имена модулей, функций, типов, вариантов, примеров и утверждений пишутся в
ёлочках: `«Сумма до»`. Имя параметра, локального связывания и поля — одно слово
без кавычек или тоже имя в ёлочках. Слово, занятое языком, именем быть не
может:

```
$ flang check занятое.flang
FLANG_PARSE в файле занятое.flang, строка 6, столбец 3: не разобрана конструкция: неожиданное 'с' — это слово занято языком, именем оно быть не может: напишите имя в ёлочках («с») или переименуйте; а если слово попало в форму лишним — уберите его
занятое.flang: не проверено — замечаний 1
```

Занято ли слово, отвечает `flang tokens --keyword «слово»`.

| Литерал | Запись |
| --- | --- |
| число | `12`, `0.5`, `-3` |
| строка | `"текст"` или `'текст'`; экранирование `\"`, `\\`, `\n` |
| признак | `да`, `нет` |
| пустое значение | `ничто` |
| список | `[1, 2, 3]`, `список из 1 и 2 и 3`, `пустой список` |

Стрелка `→` набирается также `->` и `=>`. Строка, начинающаяся с `//`, —
комментарий. Пояснение, которое должно остаться в дереве разбора, пишется
объявлением `примечание "текст"` у левого края.

У каждого ключевого слова четыре написания — русское, английское, эсперанто и
китайское; лексер сводит их к одному слову, и дерево разбора у четырёх записей
одной программы одно:

```
$ flang tokens --keyword если
«если» — ключевое слово, конструкция «if»
$ flang tokens --keyword 如果
«如果» — ключевое слово, конструкция «if»
```

```flang
module «Doubling»

total function «Double»
  accepts n: number
  returns number
  example «two»
    given n equals 2
    expected 4
  n times 2
```

Имена функций, типов и модулей не переводятся. Таблица всех слов —
[`glossary.md`](glossary.md), правила смешения наборов —
[`surfaces.md`](surfaces.md).

## Типы

Значение — скаляр, список, запись или вариант суммы. Все числовые типы хранятся
как IEEE-754 double; типы уже, чем `число`, — это ограничения на значение,
которые проверяет компилятор.

| Тип | Значения |
| --- | --- |
| `число` | любой double, включая бесконечности и «не число» |
| `неотрицательное` (`нат`, `натуральное`) | целые от 0 до 2⁵³−1 |
| `целое` | целые от −(2⁵³−1) до 2⁵³−1 |
| `вес` (`стоимость`) | число не меньше нуля, включая +∞ |
| `сотых`, `тысячных` | целое число сотых или тысячных долей |
| `строка` | строка UTF-8; знак — строка из одной кодовой точки |
| `признак` | `да`, `нет` |
| `ничто` | одно значение `ничто` |
| `список Т` | однородный список |
| запись `«Имя»` | набор именованных полей |
| сумма `«Имя»` | один из объявленных вариантов |
| `«Имя» от Т` | параметрический тип |
| `функция из Т в Т` | ссылка на объявленную функцию |

`неотрицательное` годится там, где ждут `целое` или `число`; обратно — нет.
`список неотрицательное` годится там, где ждут `список числа`.

Арифметика узкий тип не сохраняет: сумма двух `неотрицательное` и любое
деление имеют тип `число`.

```
$ flang check сумма.flang
…
FLANG_TYPE в файле сумма.flang, строка 6, столбец 5: функция «Сумма» объявлена как неотрицательное, а тело даёт число
сумма.flang: не проверено — замечаний 1
```

Узкий тип получают литерал, `длина`, `код символа` и ветвь `если`, в которой
обе стороны узкие:

```flang
модуль «Узкие типы»

тотальная функция «Длина слова»
  принимает слово: строка
  возвращает неотрицательное
  длина слово

тотальная функция «Ноль или пять»
  принимает н: число
  возвращает неотрицательное
  если н не больше 0
    то 0
    иначе 5
```

Аргументы `flang run` сверяются с объявленными типами до вычисления:

```
$ flang run целое.flang --function «Целое» --args '{"а": 1.5, "б": 1, "в": 2}'
доказано: утверждений 0
FLANG_TYPE: вызов функции «Целое»: аргумент «а»: 1.5 не целое, а тип целое — целый
```

Деление на ноль даёт бесконечность, `0 делить на 0` — «не число». Сравнение с
«не числом» ложно в обе стороны. Минус ноль и ноль не равны: `-0 равен 0` — `нет`.

## Функции и завершаемость

```
[тотальная] функция «Имя» [от «П»]
  [принимает имя: Тип, имя: Тип]
  возвращает Тип
  [требует «имя» Условие]
  [убывает Выражение]
  [обеспечивает «имя» Условие]
  [пример «имя»
    дано имя равно Значение
    ожидается Значение]
  Тело
```

Части идут в этом порядке. Тело — одно выражение: `если … то … иначе …`,
`разбор`, `свёртка`, вызов, арифметика, конструктор; перед ним могут стоять
строки `пусть имя равно Выражение`. Ветвь `иначе` обязательна. Присваивания
нет: повторное `пусть` с тем же именем заводит новое связывание.

Вызов — `«Имя» от А и Б`. Слово `и` разделяет аргументы; логическое «и» —
`и притом`.

| Группа | Слова |
| --- | --- |
| арифметика | `плюс`, `минус`, `умножить на`, `делить на`, `остаток от`, `процентов от` |
| сравнение | `равен`, `не равен`, `больше`, `меньше`, `не больше`, `не меньше` |
| логика | `не`, `и притом`, `или` |

Слово `тотальная` — обещание, что функция завершается на любом входе.
Компилятор его доказывает одним из пяти способов, и `flang check --proof`
называет способ у каждой функции:

```flang
модуль «Завершаемость»

тотальная функция «Квадрат»
  принимает х: число
  возвращает число
  х умножить на х

тотальная функция «Узлов»
  принимает места: список числа
  возвращает число
  пример «три элемента»
    дано места равно [1, 2, 3]
    ожидается 3
  разбор места
    случай пусто
      то 0
    случай голова и хвост
      то 1 плюс («Узлов» от хвост)

тотальная функция «Сумма до»
  принимает н: неотрицательное
  возвращает число
  пример «до четырёх»
    дано н равно 4
    ожидается 10
  если н не больше 0
    то 0
    иначе н плюс («Сумма до» от (н минус 1))

тотальная функция «Отсчёт»
  принимает н: число
  возвращает число
  если н не больше 0
    то 0
    иначе «Отсчёт» от (н минус 1)

тотальная функция «НОД»
  принимает а: число, б: число
  возвращает число
  убывает б
  пример «двенадцать и восемнадцать»
    дано а равно 12
    дано б равно 18
    ожидается 6
  если б равен 0
    то а
    иначе «НОД» от б и (а остаток от б)
```

| Функция | Способ | Проверка при работе |
| --- | --- | --- |
| «Квадрат» | композиция: рекурсии нет | нет |
| «Узлов» | структура: аргумент на каждом шаге — часть прежнего | нет |
| «Сумма до» | точный шаг: параметр `неотрицательное` убывает на 1 | нет |
| «Отсчёт» | постоянный шаг на `число` | есть |
| «НОД» | объявленная мера `убывает б` | есть |

У двух последних способов в программе остаётся проверка: мера на каждом
рекурсивном вызове обязана строго убывать. Нарушение останавливает вычисление:

```
$ flang run завершаемость.flang --function «НОД» --args '{"а": 12, "б": -1.5}'
доказано: утверждений 0
FLANG_MEASURE: тотальная функция «НОД»: мера на вызове «НОД» — «б» — не убыла. Завершение доказано тем, что она строго убывает; равенство цепочку не обрывает, а значит этот вызов может не кончиться никогда
```

Функция, завершаемость которой доказать не удалось, с пометкой `тотальная` не
принимается:

```
$ flang check вечно.flang
…
FLANG_NOT_TOTAL в файле вечно.flang, строка 6, столбец 3: тотальная функция «Вечно»: рекурсивный вызов «Вечно» не убывает — аргумент 1 («н» add 1) увеличивает параметр «н». Передавайте часть аргумента: хвост списка из образца «голова и хвост», поле варианта из образца, поле записи или элемент коллекции
```

Без слова `тотальная` та же функция проходит проверку, а при вычислении
останавливается на пределе шагов отказом `FLANG_RECURSION_LIMIT`, код
возврата 1.

Функция может быть значением. Значение-функция — ссылка на объявленную функцию,
возможно с заданными первыми параметрами; безымянных функций нет.

```flang
модуль «Функции как значения»

тотальная функция «Удвоить»
  принимает х: число
  возвращает число
  х умножить на 2

тотальная функция «Прибавить»
  принимает а: число, б: число
  возвращает число
  а плюс б

тотальная функция «Применить дважды»
  принимает ф: функция из числа в число, х: число
  возвращает число
  ф от (ф от х)

тотальная функция «Проба»
  возвращает число
  пример «пятёрка удвоена дважды»
    ожидается 20
  «Применить дважды» от функция «Удвоить» и 5

тотальная функция «Проба с захватом»
  возвращает число
  пример «десятка прибавлена дважды»
    ожидается 25
  «Применить дважды» от (функция «Прибавить» с а равным 10) и 5
```

## Записи и суммы

```flang
модуль «Счёт»

объект «Позиция»
  название является строкой
  цена является числом
  скидка иногда является числом

тип «Счёт» это список «Позиция»

тип «Ответ»
  вариант Успех содержит значение: число
  вариант Отказ содержит причина: строка

тотальная функция «Проверить цену»
  принимает позиция: «Позиция»
  возвращает «Ответ»
  пример «цена есть»
    дано позиция равно запись «Позиция» с название равным "болт" и цена равным 30
    ожидается вариант Успех с значение равным 30
  пример «ноль — не цена»
    дано позиция равно запись «Позиция» с название равным "гайка" и цена равным 0
    ожидается вариант Отказ с причина равным "цена не положительна"
  если позиция.цена больше 0
    то вариант Успех с значение равным позиция.цена
    иначе вариант Отказ с причина равным "цена не положительна"

тотальная функция «Итог счёта»
  принимает счёт: «Счёт»
  возвращает число
  пример «две позиции»
    дано счёт равно [запись «Позиция» с название равным "болт" и цена равным 30, запись «Позиция» с название равным "гайка" и цена равным 12]
    ожидается 42
  свёртка счёт начиная с 0 как итог и позиция → итог плюс позиция.цена
```

`объект «Имя»` объявляет запись; то же слово — `структура`. Поле записывается
`имя является Тип` или `«имя»: Тип`; поле `иногда является` может
отсутствовать. Запись строится формой `запись «Имя» с поле равным Значение и
поле равным Значение`, поле читается точкой. Лишнее поле — отказ:

```
$ flang check поле.flang
…
FLANG_TYPE в файле поле.flang, строка 8, столбец 3: запись «Точка» не имеет поля «зет»
```

`тип «Имя»` с вариантами объявляет сумму, `тип «Имя» это Тип` — псевдоним.
Вариант строится формой `вариант Имя с поле равным Значение`.

Тип с параметром объявляется и применяется словом `от`:

```flang
модуль «Возможное значение»

тип «Возможно» от «А»
  вариант «Есть» содержит значение: «А»
  вариант «Нет»

тотальная функция «Обернуть» от «А»
  принимает значение: «А»
  возвращает «Возможно» от «А»
  вариант «Есть» с значение равным значение

тотальная функция «Значение или ноль»
  принимает возможное: «Возможно» от число
  возвращает число
  пример «есть — значение»
    дано возможное равно вариант «Есть» с значение равным 7
    ожидается 7
  пример «нет — ноль»
    дано возможное равно вариант «Нет»
    ожидается 0
  разбор возможное
    случай вариант «Есть» с значение как найденное
      то найденное
    случай «Нет»
      то 0
```

Исключений и `null` в языке нет: отказ и отсутствие значения — варианты суммы.

## Разбор по образцу

`разбор` выбирает ветвь по варианту суммы, по форме списка или строки.

| Образец | Что берёт |
| --- | --- |
| `случай Имя` | вариант без связывания полей |
| `случай вариант Имя с поле как имя` | вариант, поле связано с именем |
| `случай пусто` | пустой список или пустая строка |
| `случай голова и хвост` | первый элемент (первый знак) и остаток |
| `случай любое` | всё остальное |

Разбор обязан покрыть все варианты, а каждый случай — быть достижимым:

```
$ flang check светофор.flang
…
FLANG_MATCH_NOT_EXHAUSTIVE в файле светофор.flang, строка 11, столбец 3: разбор «Свет» не покрывает «Жёлтый»
…
$ flang check порядок.flang
…
FLANG_MATCH_UNREACHABLE: случай недостижим: предыдущий случай «любое» покрывает всё
```

Рекурсия по части разобранного значения — `хвост`, поле варианта — доказывает
завершаемость структурой, как у функции «Узлов» выше.

## Списки и свёртки

Циклов в языке нет. Список обходят `свёртка`, `отобразить`, `отфильтровать` и
рекурсия по `голова и хвост`. Список не изменяется: каждая форма строит новый.

```flang
модуль «Списки»

тотальная функция «Произведение»
  принимает множители: список числа
  возвращает число
  пример «три множителя»
    дано множители равно [2, 3, 4]
    ожидается 24
  свёртка множители начиная с 1 как итог и множитель → итог умножить на множитель

тотальная функция «Квадраты»
  принимает стороны: список числа
  возвращает список числа
  пример «три квадрата»
    дано стороны равно [1, 2, 3]
    ожидается [1, 4, 9]
  отобразить стороны как сторона → сторона умножить на сторона

тотальная функция «Положительные»
  принимает остатки: список числа
  возвращает список числа
  пример «ноль и минус выброшены»
    дано остатки равно [3, 0, -1, 5]
    ожидается [3, 5]
  отфильтровать остатки где остаток → остаток больше 0

тотальная функция «Наоборот»
  принимает места: список числа
  возвращает список числа
  пример «три числа наоборот»
    дано места равно [1, 2, 3]
    ожидается [3, 2, 1]
  свёртка места начиная с пустой список как итог и место → приписать место к итог
```

| Форма | Значение |
| --- | --- |
| `длина Л` | число элементов |
| `голова Л`, `хвост Л` | первый элемент и остаток |
| `элемент N в Л` | элемент с номером N; нумерация с единицы |
| `добавить Х к Л` | новый список с Х в конце |
| `приписать Х к Л` | новый список с Х в начале |
| `Л содержит Х` | признак вхождения |

Номер вне границ проверку проходит и останавливает вычисление:

```
$ flang run границы.flang --function «Пятый»
доказано: утверждений 0
FLANG_BUILTIN_ARGS: «элемент»: индекс 5 вне списка длиной 3
```

Функции над списками, словарями и множествами — в стандартной библиотеке:
[`site/stdlib.ru.md`](site/stdlib.ru.md).

## Строки

Строка разбирается теми же образцами, что список: `пусто` и `голова и хвост`.
Длина и номера считаются в кодовых точках, не в байтах.

```flang
модуль «Строки»

тотальная функция «Слова»
  принимает текст: строка
  возвращает список строки
  пример «по пробелу»
    дано текст равно "раз два три"
    ожидается ["раз", "два", "три"]
  разделить текст по " "

тотальная функция «Через запятую»
  принимает слова: список строки
  возвращает строка
  пример «три слова»
    дано слова равно ["раз", "два", "три"]
    ожидается "раз, два, три"
  соединить слова по ", "

тотальная функция «Середина»
  принимает текст: строка
  возвращает строка
  пример «со второго по четвёртый знак»
    дано текст равно "привет"
    ожидается "рив"
  подстрока текст с 2 по 4

тотальная функция «Гласных»
  принимает текст: строка
  возвращает число
  пример «в слове привет две гласные»
    дано текст равно "привет"
    ожидается 2
  разбор текст
    случай пусто
      то 0
    случай голова и хвост
      то (если "аеёиоуыэюя" содержит голова то 1 иначе 0) плюс («Гласных» от хвост)
```

| Форма | Значение |
| --- | --- |
| `длина С` | число знаков |
| `символ N в С` | знак с номером N; нумерация с единицы |
| `подстрока С с А по Б` | знаки с А по Б включительно |
| `разделить С по Р` | список строк |
| `соединить Л по Р` | список строк в одну строку через Р |
| `соединить А с Б` | две строки в одну |
| `С содержит П`, `С начинается с П` | признак |
| `код символа С`, `символ по коду N` | кодовая точка и обратно |
| `разложить С на символы` | список знаков |
| `к числу С`, `к строке Х` | преобразование |
| `хеш256 С` | SHA-256 шестнадцатеричной строкой |

Регулярных выражений среди форм языка нет; разбор по образцу-строке дают модули
стандартной библиотеки.

## Доказательства

### Предусловие и постусловие

`требует «имя» Условие` — предусловие: что обязано быть верно на входе.
`обеспечивает «имя» Условие` — постусловие: что верно о значении `результат`.
Имя обязательно.

```flang
модуль «Обещания»

тотальная функция «Длина слова»
  принимает слово: строка
  возвращает число
  обеспечивает «длина неотрицательна» результат не меньше 0
  длина слово

тотальная функция «Удвоить»
  принимает н: неотрицательное
  возвращает число
  обеспечивает «результат чётен» (результат остаток от 2) равен 0
  пример «три удвоено»
    дано н равно 3
    ожидается 6
  н умножить на 2
```

```
$ flang check обещания.flang --proof
обещания.flang: ПРОВЕРЕНО С ОПОРОЙ, И ОПОРА НЕ СУДИЛАСЬ (спросить: --строго) — утверждений 2: доказано 1, условно 0, сетка 1, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
…
  постусловие «длина неотрицательна» функции «Длина слова» — доказано сведением цели с телом функции: правило «неотрицательность по построению», объявленные типы аргументов не понадобились — утверждение обо ВСЕХ входах, а не о написанных; теоремы при нём нет и не нужно
  постусловие «результат чётен» функции «Удвоить» — сетка 1 значение (примеры функции): нарушений НЕ ИСКАЛИ — прогона примеров не было, посчитано только их число. Это не доказательство — теоремы при утверждении нет
```

Первое постусловие ядро доказало для всех входов. Второе не доказано: у него
есть только пример. Недоказанное постусловие проверяется при работе на каждом
возврате, нарушение — отказ `FLANG_PROPERTY`.

Постусловие, ложное на «не числе», отвергается при проверке, и контрпример
назван:

```
$ flang check ложное.flang
…
FLANG_BOUND_ON_NAN в файле ложное.flang, строка 6, столбец 3: постусловие «результат меньше ста» функции «Увеличить» ЛОЖНО, и контрпример назван: «н» объявлен типом «число», а «не число» живёт в этом типе и стоит ВНЕ ПОРЯДКА …
```

Предусловие обязан обеспечить вызывающий. У каждого вызова внутри программы
ядро доказывает предусловие из того, что вызывающему известно, — в первую
очередь из его собственных `требует`:

```flang
модуль «Предусловие»

тотальная функция «Доля»
  принимает часть: число, целое: число
  возвращает число
  требует «делитель положителен» целое больше 0
  часть делить на целое

тотальная функция «Любая доля»
  принимает часть: число, целое: число
  возвращает число
  требует «делитель положителен» целое больше 0
  «Доля» от часть и целое
```

Вызов, у которого предусловие вывести не из чего, — отказ
`FLANG_PRECONDITION_CALL`, код возврата 1.

### Вердикты ядра

`flang check --proof` печатает про каждое утверждение один вердикт.

| Вердикт | Что значит |
| --- | --- |
| доказано | верно для всех входов; выведено из объявлений и тела функции |
| доказано индукцией по «Т» | то же, индукцией по объявленному типу или по `неотрицательное` |
| доказано при условии | вывод верен, но опирается на посылку, которую ядро не доказало |
| сетка N | у утверждения есть N примеров; это не доказательство |
| объявлено, не доказано | нет ни доказательства, ни примеров |
| на веру | допущение автора, не проверено ничем |

Первая строка отчёта сводит их в итог и код возврата:

| Итог | Когда | Код |
| --- | --- | --- |
| ПРОВЕРЕНО САМОСТОЯТЕЛЬНО | все утверждения доказаны | 0 |
| ПРОВЕРЕНО С ОПОРОЙ | есть вердикт «сетка» | 0; с ключом `--strict` — 3 |
| НЕ ПРОВЕРЕНО | есть «объявлено, не доказано» или «доказано при условии» | 3 |

`flang check` без `--proof` отвечает кодом 0, когда программа прошла разбор,
типы, завершаемость и примеры; недоказанное постусловие этот код не меняет.
Ключ `--json` печатает тот же отчёт в машинном виде.

Ядро не ищет доказательство перебором и не имеет аксиом. Оно применяет правила
из закрытого перечня [`flang/proof/tables/inference-rules.tsv`](../flang/proof/tables/inference-rules.tsv);
правило, закрывшее утверждение, названо в отчёте.

### Кванторы

Утверждение о каждом элементе списка пишется формой `для всех имя из Список:
Условие`. Ядро доказывает его по форме списка, который строит тело.

```flang
модуль «Отбор»

тотальная функция «Только положительные»
  принимает остатки: список числа
  возвращает список числа
  обеспечивает «все положительны» для всех остаток из результат: остаток больше 0
  пример «смесь»
    дано остатки равно [3, 0, 5]
    ожидается [3, 5]
  отфильтровать остатки где остаток → остаток больше 0
```

```
$ flang check отбор.flang --proof
…
  постусловие «все положительны» функции «Только положительные» — доказано сведением цели с телом функции: правило «все элементы по построению», объявленные типы аргументов не понадобились — утверждение обо ВСЕХ входах, а не о написанных; теоремы при нём нет и не нужно
```

Тело после двоеточия — снова условие, поэтому кванторы вкладываются.
Существование записывается с явным значением: `есть такой м, а именно Т, что
Условие`; значение пишет автор.

### Утверждение

`утверждение «имя»` записывает свойство отдельно от функции. Строка `для всех
имя: Тип` вводит переменную, `таких что Условие` — посылку.

```flang
модуль «Свободные утверждения»

утверждение «длина пустого списка нулевая»
  утверждаем (длина пустой список) равен 0

утверждение «ноль нейтрален при сложении»
  для всех н: неотрицательное таких что н больше 0
  утверждаем (н плюс 0) равен н
```

```
$ flang check утверждения.flang --proof
утверждения.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 2: доказано 2, условно 0, сетка 0, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
…
```

### Теорема

Когда ядро не закрывает утверждение само, доказательство пишет автор: `теорема`
с тем же именем, что у постусловия или утверждения.

```flang
модуль «Своё натуральное»

тип «Нат»
  вариант «Ноль»
  вариант «Следующий» содержит пред: «Нат»

тотальная функция «К числу»
  принимает н: «Нат»
  возвращает число
  разбор н
    случай вариант «Ноль»
      то 0
    случай вариант «Следующий» с пред как п
      то («К числу» от п) плюс 1

утверждение «шаг растит счёт на один»
  для всех н: «Нат»
  утверждаем («К числу» от (вариант «Следующий» с пред равным н)) равно ((«К числу» от н) плюс 1)

теорема «шаг растит счёт на один»
  дано н: «Нат»
  утверждаем («К числу» от (вариант «Следующий» с пред равным н)) равно ((«К числу» от н) плюс 1)
  индукция по н
    случай вариант «Следующий» с пред как п
      то по предположению
  следовательно доказано
```

```
$ flang check натуральное.flang --proof
натуральное.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 1: доказано 1, условно 0, сетка 0, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
…
  утверждение «шаг растит счёт на один» — доказано индукцией по «Нат»: база 1 случай, шаг при допущении на частях (1 случай), правила сведения: тождество после переписки допущением — утверждение обо ВСЕХ входах типа «Нат», а не о написанных
```

Без теоремы то же утверждение получает вердикт «объявлено, не доказано» и код
возврата 3.

Каждый шаг теоремы обоснован одним из четырёх способов:

| Обоснование | На что ссылается |
| --- | --- |
| `по свойству «имя»` | доказанное постусловие или утверждение |
| `по предположению` | посылка индукции или предусловие функции |
| `по примеру «имя»` | пример функции; закрывает случай с одним значением |
| `по закону «имя»` | правило вывода из перечня |

Промежуточный шаг пишется `затем Условие по Обоснование`. Индукция идёт по
объявленной сумме или по `неотрицательное` (`индукция по н убывает н`).

### Силлогизм

`следует «имя»` — запись вывода из уже доказанных утверждений. Это теорема с
подразумеваемой последней строкой `следовательно доказано`.

```flang
модуль «Силлогизм»

тип «Человек»
  вариант «Человек»

тотальная функция «Смертен»
  принимает кто: «Человек»
  возвращает признак
  обеспечивает «всякий человек смертен» результат
  да

утверждение «все люди смертны»
  для всех кто: «Человек»
  утверждаем («Смертен» от кто)

утверждение «Сократ смертен»
  для всех сократ: «Человек»
  утверждаем («Смертен» от сократ)

следует «Сократ смертен»
  дано сократ: «Человек»
  утверждаем («Смертен» от сократ)
  по свойству «все люди смертны»
```

```
$ flang check силлогизм.flang --proof
силлогизм.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 3: доказано 3, условно 0, сетка 0, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
…
  утверждение «Сократ смертен» — доказано: терм принят ядром, 1 шаг, правило «цель есть допущение», основания: утверждение «все люди смертны» — утверждение обо ВСЕХ входах
```

Заключение, которое из названной посылки не получается подстановкой, —
отказ `FLANG_PROOF_STEP`. Посылка, которую ядро само не доказало, даёт
заключению вердикт «доказано при условии» и код возврата 3.

### Независимая проверка

`flang check --proof --record <файл>` записывает доказательства в текстовый
файл. Его перепроверяет отдельная программа на C
[`flang/proof/checker/checker.c`](../flang/proof/checker/checker.c): она читает
исходник и запись, компилятор ей не нужен.

```
$ cc -std=c99 -O2 -o checker flang/proof/checker/checker.c
$ flang check натуральное.flang --proof --record натуральное.record
…
$ ./checker натуральное.flang натуральное.record
ПРОВЕРЕНО — запись сошлась с исходником, и всё доказанное проиграно заново: утверждений 1, шагов сверено с исходником 1, …
```

| Код | Ответ |
| --- | --- |
| 0 | запись сошлась с исходником, доказанное проверено заново |
| 3 | противоречий нет, но часть мест принята со слов ядра; места названы |
| 1 | запись расходится с исходником |
| 2 | неверный вызов |

Запись, в которой обоснование шага подменено, отвергается:

```
$ ./checker натуральное.flang подмена.record
НЕ СОШЛОСЬ: теорема «шаг растит счёт на один», строка 25: запись говорит «по примеру «нет»», а в исходнике написано «по предположению»
```

Как читать отчёт и что именно доказано в самом компиляторе —
[`site/what-is-proved.ru.md`](site/what-is-proved.ru.md) и
[`site/how-proofs-work.ru.md`](site/how-proofs-work.ru.md).

### Запуск недоказанной программы

`flang run` и `flang io` перед работой считают вердикт по всей программе вместе
с ввезёнными модулями. Программу, в которой есть недоказанное утверждение, они
не запускают:

```
$ flang run обещания.flang --function «Удвоить» --args '{"н": 3}'
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск только по явному согласию: --на-веру
…
$ echo $?
3
$ flang run обещания.flang --function «Удвоить» --args '{"н": 3}' --unproven warn
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск по ключу --unproven warn
6
```

Ключ `--trust` (`--на-веру`) запускает без подсчёта вердикта. То же поведение
задаётся ключом `unproven` в файле настроек.

## Планы и ввод-вывод

Функция не выполняет ввод-вывод. Действие во внешнем мире описывается
значением, а выполняет его исполнитель — команда `flang io`; в сообщениях
компилятора он назван «хозяин».

`план` — конечный автомат. Начальная функция возвращает состояние. Функция шага
получает состояние и отклик на предыдущее действие и возвращает значение типа
`«Продолжение»`.

```flang
модуль «План записи»

тип «Ход»
  вариант Начало
  вариант Конец

тотальная функция «Начать»
  возвращает «Ход»
  вариант Начало

тотальная функция «Дальше»
  принимает ход: «Ход», отклик: «Отклик»
  возвращает «Продолжение»
  пример «сперва — поручение записать»
    дано ход равно вариант Начало
    дано отклик равно вариант «Пока ничего»
    ожидается вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант Конец)
  разбор ход
    случай Начало
      то вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант Конец)
    случай Конец
      то вариант «Конец работы» с значение равным 6

план «Записать привет»
  состояние «Ход»
  начинает с «Начать»
  обрабатывает «Дальше»
```

```
$ flang io план.flang --in-dir
доказано: утверждений 0
{"plan":"Записать привет","result":6,"orders":1,"log":[{"поручение":{"variant":"Записать файл","fields":{"путь":"привет.txt","содержимое":"привет"}},"отклик":{"variant":"Записано","fields":{"сколько":6}}}]}
$ flang io план.flang --no-write
доказано: утверждений 0
{"plan":"Записать привет","result":6,"orders":1,"log":[{"поручение":{"variant":"Записать файл","fields":{"путь":"привет.txt","содержимое":"привет"}},"отклик":{"variant":"Сбой","fields":{"код":"FLANG_IO_DENIED","сообщение":"хозяину запрещено писать файлы"}}}]}
```

Функции плана остаются тотальными и проверяются обычными примерами, без файлов
и сети. Отказ исполнителя — не исключение, а отклик «Сбой» с кодом.

Типы `«Продолжение»`, `«Поручение»` и `«Отклик»` встроены; их состав закрыт.

| `«Продолжение»` | Код возврата `flang io` |
| --- | --- |
| `«Сделать»` (поля `поручение`, `потом`) | работа продолжается |
| `«Конец работы»` (поле `значение`) | 0 |
| `«Провал»` (поля `код`, `сообщение`) | 1 |
| `«Не проверено»` (поля `код`, `сообщение`) | 3 |

| Область | Варианты `«Поручение»` |
| --- | --- |
| файлы | «Прочитать файл», «Записать файл», «Прочитать октеты из файла», «Записать октеты в файл», «Удалить файл», «Перечислить каталог», «Завести временный каталог» |
| сеть | «Запросить», «Открыть соединение», «Принять соединение», «Прочитать из соединения», «Ответить в соединение», «Прочитать октеты из соединения», «Ответить октетами в соединение» |
| процессы | «Запустить процесс», «Запустить процесс с вводом» |
| время и случай | «Текущее время», «Случайное число» |
| терминал | «Показать», «Ждать событие», «Размер экрана» |
| среда | «Прочитать переменную среды», «Прочитать доводы» |

Варианты `«Отклик»`: «Пока ничего», «Прочитано», «Записано», «Ответ сети»,
«Отметка времени», «Выпало», «Показано», «Случилось», «Срок вышел»,
«Перечислено», «Процесс завершён», «Процесс убит», «Соединение открыто»,
«Октеты», «Сбой», «Убрано», «Заведено», «Значение среды», «Переменной среды
нет», «Доводы», «Экран».

Доводы плана — всё, что стоит в командной строке после отдельного `--`:

```
$ flang io доводы.flang -- раз два три
доказано: утверждений 0
{"plan":"Сосчитать доводы","result":3,"orders":1,"log":[{"поручение":{"variant":"Прочитать доводы","fields":{}},"отклик":{"variant":"Доводы","fields":{"доводы":["раз","два","три"]}}}]}
```

Права исполнителя сужаются ключами `--no-read`, `--no-write`, `--no-net`,
`--no-clock`, `--no-random`, `--no-spawn`, `--no-env`, `--no-args`,
`--no-screen`; `--in-dir` запрещает пути вне каталога входного файла. По
умолчанию разрешено всё.

Скрипты самого репозитория — планы в файлах `.fscript`, их исполняет та же
команда `flang io`.

## Процессы

`процесс` объявляет состояние, тип принимаемых сообщений и функцию-обработчик.
Обработчик — обычная тотальная функция: получает состояние и сообщение,
возвращает новое состояние и список действий. Отправка сообщения — действие в
этом списке. `надзор` описывает, что делать при отказе процесса, `прогон` —
пример работы с заданным порядком сообщений.

```flang
модуль «Счётчик»

объект «Счёт»
  «всего»: число

объект «Отклик»
  «состояние»: «Счёт»
  «действия»: список «Действие»

тип «Команда»
  вариант «прибавить» содержит «сколько»: число

процесс «Счётчик»
  состояние «Счёт»
  начинает с «пустой счёт»
  принимает «Команда»
  обрабатывает «шаг счёта»

надзор «Учёт»
  процесс «Счётчик» стратегия «перезапустить»
  порог отказов 3 за 5000 миллисекунд иначе «передать выше»

тотальная функция «пустой счёт»
  возвращает «Счёт»
  запись «Счёт» с «всего» равным 0

тотальная функция «шаг счёта»
  принимает текущее: «Счёт», сообщение: «Команда»
  возвращает «Отклик»
  пример «прибавление меняет состояние и ничего не шлёт»
    дано текущее равно (запись «Счёт» с «всего» равным 1)
    дано сообщение равно (вариант «прибавить» с «сколько» равным 2)
    ожидается (запись «Отклик» с «состояние» равным (запись «Счёт» с «всего» равным 3) и «действия» равным [])
  разбор сообщение
    случай вариант «прибавить» с «сколько» как сколько
      пусть новое равно (запись «Счёт» с «всего» равным (текущее.«всего» плюс сколько))
      запись «Отклик» с «состояние» равным новое и «действия» равным []

прогон «два прибавления»
  семя 1
  дано «Счётчик» принимает (вариант «прибавить» с «сколько» равным 2)
  дано «Счётчик» принимает (вариант «прибавить» с «сколько» равным 3)
  ожидается «Счётчик» равен (запись «Счёт» с «всего» равным 5)
```

Варианты встроенного типа `«Действие»`: «отправить», «через», «остановить»,
«отложить», «продолжить», «породить».

`flang check` на программе с процессами отвечает кодом 2: типы, завершаемость
и примеры обработчиков проверены, правила самих объявлений `процесс`, `надзор`
и `прогон` проверены не полностью, и это сказано в выводе. Код с планировщиком
процессов генерируется для целей `c`, `elixir`, `js` и `ts`.

Модель процессов, надзор и работа на нескольких узлах —
[`site/processes.ru.md`](site/processes.ru.md).

## Модули и пакеты

```
модуль «Имя»
  [экспортирует «А», «Б»]
  [использует «Модуль» [из "путь"] [только «А», «Б»]]
```

Без строки `экспортирует` снаружи видно всё. Имя, которого в списке экспорта
нет, ввозящему модулю неизвестно — отказ `FLANG_UNKNOWN_NAME`.

```flang
модуль «Библиотека»
  экспортирует «Утроить»

тотальная функция «Утроить»
  принимает н: число
  возвращает число
  н умножить на 3

тотальная функция «Скрытая»
  возвращает число
  1
```

```flang
модуль «Ввоз»
  использует «Библиотека»

тотальная функция «Девять»
  возвращает число
  пример «три утроено»
    ожидается 9
  «Утроить» от 3
```

Модуль ищется по имени из первой строки файла, а не по имени файла. Порядок
поиска: каталог ввозящего файла; каталоги выше него до корня проекта; каталоги
из переменной `FLANG_MODULE_DIR`; библиотека, поставленная с компилятором.
Корень проекта — ближайший каталог с `.flangrc`, `.git` или `flang.package`.
Модуль не найден — `FLANG_IMPORT_NOT_FOUND`. Одно имя у двух найденных файлов —
`FLANG_IMPORT_AMBIGUOUS` с обоими путями. Форма `из "путь"` называет файл
прямо; путь считается от ввозящего файла.

Модули стандартной библиотеки ввозятся по имени, например `использует «Lists»`.

`flang lock` печатает замок — JSON с исходниками модулей, ввезённых формой
`из "путь"`, и sha256 каждого. Если файл `flang.lock` лежит рядом с программой,
команды берут эти модули из него, и исходники на диске не нужны.

`flang package` печатает пакет: замок с именем и версией из файла
`flang.package`. Пакет ввозится как файл:

```flang
модуль «Пользователь пакета»
  использует «Discount» из "discount.flang-package"

тотальная функция «Привет»
  возвращает строка
  пример «приветствие из пакета»
    ожидается "Привет, мир!"
  «Поприветствовать» от "мир"
```

Пакет, исправленный после сборки, отвергается:

```
$ flang check пользователь.flang
FLANG_PACKAGE: адрес модуля «Discount» не сходится с его исходником: правлен или испорчен
```

`flang new <имя>` создаёт каталог пакета: модуль с примером, `flang.package`,
каталог `fspec/` и README. Подробно — [`site/packages.ru.md`](site/packages.ru.md).

## Целевые языки

`flang emit <файл> --target <цель>` генерирует код на одном из десяти языков:
`c`, `cpp`, `go`, `rust`, `java`, `js`, `ts`, `elixir`, `python`, `csharp`.
Перед генерацией программа проходит те же проверки, что у `flang check`, кроме
прогона примеров; при замечании код не генерируется.

```
$ flang emit завершаемость.flang --target c --out out
напечатано файлов 6, байт 455425, в out
…
$ ls out
Makefile  flang_cli.c  flang_runtime.c  flang_runtime.h  zavershaemost.c  zavershaemost.h
$ make -C out
…
$ printf '%s\n' '{"fn":"НОД","args":[{"n":"12"},{"n":"18"}]}' | out/flang_cli
{"ok":true,"value":{"n":"6"}}
```

Рядом с модулем генерируются библиотека времени выполнения, файл сборки и
программа запуска `flang_cli`, которая читает запросы JSON со стандартного
ввода; её снимает ключ `--no-cli`. Имя файла модуля — транслитерация имени
модуля, поэтому модулю, который переводится в другой язык, дают латинское имя.

В сгенерированном коде остаются пределы шагов и глубины, проверки убывания меры
и проверки недоказанных постусловий; для доказанных постусловий проверок нет.
Ключ `--no-postconditions` убирает проверки постусловий из кода.

| Объявление | Цели |
| --- | --- |
| функции, типы, теоремы | все десять |
| `процесс`, `надзор`, `прогон` | `c`, `elixir`, `js`, `ts`; у остальных — отказ, код 1 |
| `план` | `js`, `ts`; у остальных — `FLANG_PLAN_UNSUPPORTED`, код 1 |

Разбор сгенерированных файлов по целям — [`guide/emit-walkthrough.ru.md`](guide/emit-walkthrough.ru.md),
встраивание в чужую программу — [`site/embedding.ru.md`](site/embedding.ru.md).

## Команды

| Команда | Что делает |
| --- | --- |
| `flang check <файл>` | разбор, типы, завершаемость, доказательства, примеры |
| `flang test <файл \| каталог \| маска>` | те же проверки и счёт примеров по файлам |
| `flang run <файл> --function «Имя» [--args '{…}']` | вычисляет одну функцию |
| `flang emit <файл> --target <цель>` | генерирует код на целевом языке |
| `flang io <файл> [--plan «Имя»]` | исполняет план |
| `flang facts <файл> --facts <json> --claims '[…]'` | проверяет утверждения на заданных значениях |
| `flang ast <файл>` | дерево разбора в JSON |
| `flang tokens <файл>` | поток токенов лексера |
| `flang lock <файл>` | печатает замок |
| `flang package <файл>` | печатает пакет |
| `flang new <имя>` | создаёт каталог пакета |
| `flang repl [файл]` | интерактивная оболочка; то же — `flang` без доводов в терминале |
| `flang lsp` | языковой сервер для редактора |
| `flang --mcp-mode` | служба для ИИ-помощника по стандартным потокам |

`flang <команда> --help` перечисляет ключи команды. Аргументы `flang run` —
плоский объект JSON со скалярами; список или вложенный объект не принимается.

| Код возврата | Значение |
| --- | --- |
| 0 | сделано |
| 1 | программа не прошла проверку, вычисление остановлено отказом, `facts` опровергла утверждение или план вернул «Провал» |
| 2 | неверный вызов; у `check` — в программе есть объявления, которые компилятор проверяет не полностью |
| 3 | сделано, но проверено не всё: недоказанное под `check --proof`, отказ `run` и `io` запускать недоказанную программу, «Не проверено» у плана |
| 4 | `check --fast`: доказательства и примеры не запускались |
| 5 | остановка на пределе памяти |

Предел памяти задаёт ключ `--memory-limit N` (`--предел-памяти`), число с
буквой K, M, G или T; у `check`, `test` и `run` по умолчанию три четверти
памяти машины, 0 снимает предел:

```
$ flang run память.flang --function «Раздуть» --args '{"текст":"а","раз":28}' --memory-limit 32M
FLANG_MEMORY: недостаточно памяти
FLANG_MEMORY: прогон остановлен на пределе памяти 32 МиБ: занято 25 МиБ, просили ещё 25 165 880 байт
  считалась функция «Раздуть», шагов программы 452
…
```

Отказ печатается строкой `КОД в файле <путь>, строка N, столбец M: текст`.
Справочник команд — [`site/cli.ru.md`](site/cli.ru.md), справочник отказов —
[`site/diagnostics.ru.md`](site/diagnostics.ru.md).

## Файл настроек

Настройки читаются из файла `.flangrc`: строки `ключ = значение`, строка с `#`
в начале пропускается, незнакомый ключ пропускается. Файл ищется от рабочего
каталога вверх до корня проекта, затем в домашнем каталоге.

Компилятор читает из файла один ключ — `unproven`: что делать `flang run` и
`flang io` с программой, в которой есть недоказанное утверждение.

| Значение | Поведение |
| --- | --- |
| `refuse` | не запускать, код возврата 3; умолчание |
| `warn` | напечатать вердикт и запустить |
| `allow` | запустить, вердикт не считать; то же, что `--trust` |

```
$ cat .flangrc
unproven = warn
$ flang run обещания.flang --function «Удвоить» --args '{"н": 3}'
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск по настройке «unproven = warn» (…/.flangrc)
6
```

Старшинство: ключ командной строки `--unproven`, переменная среды
`FLANG_UNPROVEN`, `.flangrc`, умолчание. Значение не из списка — отказ с кодом
возврата 2.

Остальные ключи файла (`language`, `surface`, `color`, `page`, `version`,
`name`, `license`, `repository`, `issues`) читают скрипты репозитория и сборка
сайта: [`guide/settings.ru.md`](guide/settings.ru.md).

## Ограничения

- Числа — IEEE-754 double. Целые точны до 2⁵³−1, длинной арифметики в языке
  нет. Округления нет. Сложение чисел с дробной частью не ассоциативно.
- Присваивания, циклов, исключений, `null`, безымянных функций и замыканий нет.
  Значение-функция захватывает только первые параметры объявленной функции.
- Программа проверяется целиком: раздельной компиляции нет, двух версий одного
  модуля в программе не бывает.
- Ввода-вывода внутри функции нет. Утверждение о состоянии во времени, о
  побочном эффекте или о параллельном исполнении записать нечем: `обеспечивает`
  относится к значению функции.
- Поиска доказательств нет: ядро применяет правила из закрытого перечня, шаги
  теоремы пишет автор. Условие ветви `если` ядро фактом не считает.
- Предусловие у вызова с литералом ядро не выводит: вызов `«Доля» от часть и 2`
  при предусловии `целое больше 0` отвергается как `FLANG_PRECONDITION_CALL`.
- Объявления `вес`, `сотых` и `тысячных` принимаются как типы, но их особые
  правила арифметики не проверяются: `вес минус вес` и `сотых плюс тысячных`
  проходят проверку. Нижняя граница `вес` у аргумента `flang run` не
  проверяется: значение −1 принимается.
- Объявления категорной записи (`категория`, `морфизм`, `функтор`, `моноид`,
  `монада`) и процессов (`процесс`, `надзор`, `прогон`) компилятор проверяет не
  полностью: `flang check` отвечает кодом 2, `flang emit` на программе с
  морфизмами, моноидами или монадами — кодом 3. На программе с процессами
  `flang check --proof` отвечает кодом 0, хотя `flang check` — кодом 2.
- В замок `flang lock` попадают только модули, ввезённые формой `из "путь"`;
  модуль, найденный по имени, в замок не записывается.
- Независимая программа проверки повторяет не каждое доказательство ядра. На
  силлогизме из этого описания ядро отвечает кодом 0, а она — кодом 3 и
  называет места, принятые со слов ядра.
- Доказательство относится к исходной программе. Соответствие сгенерированного
  кода исходнику в общем виде не доказано. Для цели `c` ключ `--protocol <файл>`
  печатает протокол перевода, который сверяет программа
  [`flang/translation/matcher.c`](../flang/translation/matcher.c); она покрывает
  не все конструкции и на функции с `отфильтровать` отвечает кодом 3, на
  функции с объявленной мерой — кодом 1.
- `flang emit` не прогоняет примеры и не сверяет аргументы программы запуска с
  объявленными типами; примеры прогоняют `flang check` и `flang test`.
- План генерируется только для `js` и `ts`, процессы — для `c`, `elixir`, `js`
  и `ts`.
- Запросы `https` исполнитель выполняет внешней программой `curl`. Своей
  реализации TLS у него нет, соединение «Открыть соединение» — TCP без
  шифрования, UDP нет.
- Компилятор отвечает по-русски; ключ `language` файла настроек язык его
  сообщений не меняет.
- Компилятор не является формально верифицированным. На веру принимаются ядро
  доказательств, компилятор, библиотека времени выполнения, компилятор C и
  аппаратура. Для разработки критичных к безопасности систем язык не
  предназначен.

Известные ограничения с примерами — [`guide/limits.ru.md`](guide/limits.ru.md).
