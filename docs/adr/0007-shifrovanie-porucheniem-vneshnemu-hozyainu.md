# ADR-0007. Шифрование берётся поручением внешнему хозяину, а не своим кодом

**Состояние:** предложено (ветка `u/zashchishchyonnoe-soedinenie`), прогнано на живой сети
**Дата:** 22 августа 2026
**Основание:** хозяин двоичного `flang/src/emit/c/flang_repl.c`, словарь эффектов
`flang/self/parser.flang`, пример `flang/examples/io/zapros-po-https.flang`
**Связано:** [ADR-0002](0002-ishodyashchee-soedinenie.md) — там TLS назван отсутствующим

---

## Улика

```
«Запросить» на https://rosettacode.org/w/api.php
→ FLANG_IO_NO_TLS: «притворяться, что сходил, — хуже отказа»   код возврата 1
```

Воспроизведено 22 августа двоичным из `bootstrap/` на ветке от `422f42a3`. Отказ
выдавался в `io_request`, `flang/src/emit/c/flang_repl.c`, строка 9807 — первой же
проверкой адреса, до сокета.

Отказ честный: язык не молчал и не врал. Но жить с ним нельзя — служба, которой
надо сходить в интернет, упирается сюда целиком: ни клиента к чужому API, ни
выгрузки, ни оплаты, ни обновления.

## Три пути, взвешенные числом

Считалось на этой машине, замерами, а не на вкус. Всё, что ниже, — прогоны;
журналы в `/srv/flang-rabota/u-tls-progon/`.

| | 1. OpenSSL в семя | 2. TLS на flang | 3. Поручение наружу |
|---|---|---|---|
| своего кода, без комментариев и пустых строк | 91 строка C (замер: собрано и прогнано) | тысячи строк flang | **282 строки C** (замер) — вчетверо больше только потому, что сюда входят трубы, срок, разбор кода возврата и проверка полномочий, которых у скелета на OpenSSL нет вовсе |
| ЧУЖОГО кода в замыкании | **1 551 696 строк C** (OpenSSL 4.0.1, без `test/` и `fuzz/`) | 0 | 0 |
| что прибавляется к сборке семени | `-lssl -lcrypto` и заголовки: `cc` одного больше не хватает | ничего | ничего |
| ключ соединения взять откуда | из OpenSSL | **НЕОТКУДА** (см. ниже) | из curl |
| скорость | скорость машины | 43,3 КБ/с напечатанным C, ≈52 Б/с толкователем | скорость машины |
| подделка отвергнута | 4 из 5 | нечем проверить | **4 из 5** |

### Путь 2 закрыт не ценой, а отсутствием ключа

Главный довод против «написать на flang» — не медленно и не много работы.
**Программе на flang неоткуда взять секрет.** Единственный источник случайности в
словаре — поручение `«Случайное число»`, и вот замер, три прогона подряд без
`--seed`, `flang/examples/io/...` в `/srv/tmp`:

```
прогон 1: код 0, выпало 0.8401877167634666
прогон 2: код 0, выпало 0.8401877167634666
прогон 3: код 0, выпало 0.8401877167634666
```

Одно и то же число. Хозяин зовёт `rand()` без `srand()` (`io_random`), а с
`--seed` — mulberry32, то есть повторимый счётчик. **Из такого источника закрытый
ключ X25519 не выйдет ни одним способом**: он предсказуем целиком. Значит путь 2
начинается не с криптографии, а с нового поручения хозяину за настоящей
случайностью — то есть **с пути 3**, только длиннее.

Цена, впрочем, тоже названа числом, и она своя:

* SHA-256 без единой битовой операции — 925 195 шагов толкователя на блок
  (`docs/zettel/sha256-bez-bitovyh-operaciy-stoit-925-tysyach-shagov.md`).
  Замер сегодня, на этом дереве: 1 блок — 4,43 с, 10 блоков — 15,18 с,
  100 блоков — 125,67 с, то есть **1,224 с на 64 байта**;
* напечатанным C то же самое — **43,3 КБ/с** (20 прогонов по 6391 байту за 2,88 с);
  `openssl speed sha256` на той же машине — 1 552 146 КБ/с. **Медленнее в 35 000 раз**;
* битовых операций в языке нет вовсе — ни «и», ни «или», ни сдвига. AES и GHASH
  считались бы поразрядно, то есть дороже SHA-256 на байт, а не дешевле;
* хранилище корней — полторы сотни сертификатов, которые надо где-то держать и
  обновлять. Читать системное — это снова опереться на хозяина.

### Путь 1 не даёт того, за что платит

91 строка своего C на OpenSSL написана и прогнана (`zamer-openssl.c` в рабочем
каталоге, в дерево не кладётся; 102 строки вместе с пояснениями). Они работают и
подделку отвергают. Но:

* **тот же провал на отзыве**, что и у пути 3: `revoked.badssl.com` принят кодом 0.
  То есть безопасности сверх пути 3 покупка не даёт **ни на грош**;
* 91 строка — это скелет: без разбора кусочной упаковки, без `User-Agent`
  (и потому `rosettacode.org` ответил **403 Forbidden**), без перенаправлений,
  без срока. До того, что уже умеет curl, их станет много больше;
* **платится за это тем, чего у точки раскрутки нет запасного**: сегодня семя
  собирается одним `cc` и линкует `-lm -lpthread`. После пути 1 для сборки
  компилятора нужен `libssl-dev`, а «одним make из семени» перестаёт быть правдой;
* цена не разовая: полтора миллиона строк чужого C в замыкании — это чужие
  выпуски, чужие CVE и чужой график обновлений внутри того, чему надо доверять.

### Путь 3 выбран, и он не нов

Это ровно тот приём, каким в словаре живут процессы: язык строит **описание**
действия, а делает его хозяин. Здесь описание — то же поручение `«Запросить»`,
ни одного нового варианта в словаре не прибавилось. Наружу уходит не «кусок
криптографии», а **всё поручение целиком**, и внутрь мы не заглядываем.

## Решение

**`«Запросить»` по `https` исполняет внешняя программа `curl`, запущенная
двоичным хозяином. Своей криптографии в дереве не появляется.**

Имя программы и ключи **зашиты**. Переменной среды, которой их можно подменить,
нет намеренно: «чем ходить в сеть», названное снаружи, есть тихий способ снять
проверку сертификата.

Ключи и почему каждый:

| ключ | зачем |
|---|---|
| `-q` | **не читать `~/.curlrc`.** Строка `insecure` в чужом файле настроек сняла бы проверку сертификата, и ни один прогон этого бы не показал. Главный ключ здесь — этот |
| `-sS` | без счётчика, но с текстом ошибки на stderr |
| `-i` | заголовки в поток: ответ разбирает тот же `io_http_answer`, что и незашифрованный путь |
| `-g` | не считать `[ ] { }` в адресе перечислением: адрес приходит из программы |
| `--http1.1` | разбор ждёт «HTTP/1.», а поверх TLS curl по умолчанию печатает «HTTP/2 200» |
| `-H "Content-Type:"` | снять заголовок, который curl дописывает к телу сам. Замерено: без него тело приезжало **полем формы**, а не телом |
| `--proto =https` | только https: ни `file`, ни `gopher`, ни подмены схемы |
| `--proto-redir =https` | перенаправления и так не исполняются, но вниз по схеме уйти нельзя |
| `--tlsv1.2` | нижняя граница версии |
| `--max-time` | из `--timeout` хозяина |
| `--` | конец ключей: адрес не станет ключом, начнись он с `-` |

Чего нет и не будет: `-k` / `--insecure`, `--proxy-insecure`, `--cacert` из среды —
**ни одного способа сказать «сертификат не проверять»**.

## Коды отказа: их стало два новых

| код | когда | пример слов |
|---|---|---|
| `FLANG_IO_TLS_CERT` | curl 60, 90, 91 — сертификат не принят | `curl: (60) SSL certificate OpenSSL verify result: certificate has expired (10)` |
| `FLANG_IO_TLS` | прочая беда шифрования | `curl: (35) …` |
| `FLANG_IO_NET` | curl 3, 6, 7, 28 — адрес, имя, связь, срок | как было |
| `FLANG_IO_NO_TLS` | **curl на машине нет** | «своего шифрования у двоичного хозяина нет, а внешней программы «curl» на машине не нашлось…» |
| `FLANG_IO_DENIED` | `--no-spawn` | «`https` здесь исполняет ВНЕШНЯЯ программа, а хозяину запрещено их запускать» |

Слова отказа — **curl'овы**, первая строка его stderr. Своими словами пересказывать
чужую диагностику значило бы её потерять.

## ★ Что НЕ сделано и названо, а не умолчано

**ОТЗЫВ СЕРТИФИКАТА НЕ ПРОВЕРЯЕТСЯ.** Ни OCSP, ни CRL. Пятая подделка,
`revoked.badssl.com`, принята кодом 200 — отозванный лист прошёл.

Ключ `--cert-status` (OCSP-скрепка) **замерен и не взят**: с ним отказ
«No OCSP response received» приезжает не только от `revoked.badssl.com`, но и от
`rosettacode.org`, и от `api.github.com`. Скрепку не отдаёт почти никто, то есть
ключ закрывает не дыру, а весь выход в сеть. Замер — три прогона curl, все три
кодом 91.

То же верно и для пути 1: свой клиент на OpenSSL принял `revoked.badssl.com`
точно так же. Это **не цена выбранного пути**, а общая дыра обоих.

Прочие долги:

* **сырого TLS-сокета нет.** `«Открыть соединение»` — по-прежнему голый TCP.
  Клиент к базе, требующей шифрования, этим не пишется. Закрывать это тем же
  приёмом (`openssl s_client` трубой) можно, но это отдельная работа: там нужен
  двусторонний поток октетов, а не один обмен;
* **`https` стоит запуска процесса.** На каждый запрос — `fork` + `execvp`. Для
  службы, которая ходит наружу в цикле, это дорого, и это названо, а не измерено;
* **тело не совпадает побайтово с незашифрованным путём:** curl снимает кусочную
  упаковку (`Transfer-Encoding: chunked`), наш сокет отдаёт её как есть;
* **`User-Agent` расходится:** curl шлёт свой, наш сокет не шлёт никакого.
  Поручение `«Запросить»` заголовков не возит вовсе, и выбрать программе нечем;
* **перенаправления не исполняются** ни на одном из двух путей — это прежнее
  поведение, не новое;
* **`«Случайное число»` предсказуемо.** Найдено по ходу этой работы, здесь не
  чинится: это не про TLS, но всякий, кто возьмёт его на что-то похожее на
  секрет, получит одно и то же число.

## Чего решение стоит точке раскрутки, и чем прогнано, раз семя не перепечатано

`flang/src/emit/c/flang_repl.c` уезжает в напечатанный байт **дословно** (в
`bootstrap/flang_repl.c` он же плюс девять строк заголовка с `FL_PROGRAM_CALL`).
Значит семя надо **перепечатать**, иначе `make -C bootstrap` соберёт двоичный
БЕЗ `https`.

Перепечатки здесь нет, и вот почему. `sh scripts/raskrutka.sh --bystro` **до
первой правки** этой ветки уже давал код 1 и пять расхождений:

```
• flang/self/bootstrap/compiler.flang: изменён после перепечатки
• flang/self/mcp.flang: вошёл в замыкание после перепечатки
• flang/self/proof-kernel.flang: изменён после перепечатки
• flang/self/zapis.flang: вошёл в замыкание после перепечатки
• flang/src/emit/c/flang_repl.c: изменён после перепечатки
расхождений 5.
```

После правки — те же пять, ни одного нового: `flang_repl.c` в списке уже стоял.
Перепечатка сегодня втянула бы в семя четыре ЧУЖИХ незавершённых правки вместе с
моей, и это не моё решение.

**Чем поэтому прогнано.** Двоичный собран вне дерева, из семи файлов семени, где
один заменён: `bootstrap/{Makefile,compiler_flang.c,compiler_flang.h,flang_cli.c,
flang_runtime.c,flang_runtime.h}` как есть, а `flang_repl.c` = девять строк
заголовка из `bootstrap/flang_repl.c` плюс `flang/src/emit/c/flang_repl.c`
целиком. Это ровно то, что положит в семя перепечатка. Сборка чистая:
`-std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto`, ни одного предупреждения.

```sh
SB=$(mktemp -d -p /srv/tmp)
cp bootstrap/Makefile bootstrap/compiler_flang.[ch] bootstrap/flang_cli.c    bootstrap/flang_runtime.[ch] "$SB"/
{ head -9 bootstrap/flang_repl.c; cat flang/src/emit/c/flang_repl.c; } > "$SB"/flang_repl.c
make -C "$SB" -j8
```

**Второй названный долг, тоже не заведённый этой веткой.**
`flang/проверки/ведомость-примеров.txt` отстала на целый столбец: двоичный
печатает четыре числа (`всего прошло сорвалось СВОИХ`), а в ведомости их три —
все 346 взятых строк. Мой пример при следующей перезаписи (`обход-примеров.sh
--write`) добавит строку `flang/examples/io/zapros-po-https.flang	10 10 0 10`;
переписывать ведомость целиком ради одной строки я не стал.
