## 1. Задача

Доля обязательств корпуса, проверенных независимой программой, на `gh/dev` `9a9df2e3f` и
на `e12837854` одинакова: **567 из 651 = 87,10 %** (команда: `sh flang/proof/доля-корпуса.sh
--набор корпус --проигрыванием`, набор 86 записей). Открыто 84 места. Из них **25** —
ведро Е: постусловия, которые ядро доказало разбором цели по условию, разбором случаев по
внутреннему условию или по дизъюнкции в допущении. В записи у каждого стоит только имя
правила (`правило «разбор цели по условию»` — 19 мест, `«разбор случаев по внутреннему
условию цели»` — 4, `«по дизъюнкции в допущении»` — 2) и ни одного хода; проверяющая
программа отвечает на них «место на слове ядра».

Таблица правил вывода (`flang/proof/ПРАВИЛА-ВЫВОДА.tsv`, строки Р1–Р7) описывает семь
законов семейства Р со статусом «нет-в-ADR». В проверяющей программе ни одного из них нет
(`grep '"Р1"' сверщик.c` — 0). Ядро ни один из них не печатает.

Порог 95 % — это 619 мест; не хватает 52. Ряд владельца (`m`: печать семейств отношений,
остаток узлов) даёт по замеру `otkrytye-84.md` не больше 27. Без ведра Е порог недостижим,
если не брать все мелкие ведра целиком, включая отвергнутые владельцем Д3/Д5/Ч5.

## 2. Замер: что ядро делает на этих 25 местах на самом деле

Имя правила в записи называет только ВЕРХНИЙ ход. Чтобы узнать, чем закрывается каждая
половина, охрана цели вынесена в `требует`, цель оставлена без охраны, и ядро прогнано на
16 таких половинах (`scratchpad/stack-E/halves/halves.flang`; `bootstrap/flang check --proof
--записать`; код 0, доказано 16 из 16). Имена правил — из записи ядра, не по памяти.

### 2.1. Пять форм, и ни одной новой арифметики в трёх из них

|---|---:|---|---|

| Е-2 охрана + пустота | 7 | охрана — один из четырёх фактов пустоты (`пусто Л`, `(длина Л) равен 0`, `Л равен пустой список`, `Л равен ""`); ветвь `пусто` разбора либо начало свёртки становятся телом | `тождество после переписки допущением` — все четыре вида факта, и для `разбор`, и для `свёртка` |

### 2.2. Что расходится между таблицей правил и ядром

- **Р1** в таблице сформулировано о ЦЕЛИ (`Γ, У ⊢ Ц` даёт `Γ ⊢ если У то Ц иначе да`), а
  указатель ведёт на `proof-kernel.flang` «Следствие охраны» — правило о ФАКТАХ (модус
  поненс по охранённому допущению). Форму таблицы у ядра исполняет пятый ход «Ветвлением»
  (Р2), у которого половина «условие ложно» вырождается в литерал `да`.
- **Р2** в таблице говорит «ни один факт из У не выводится, отрицания нет вовсе». Половина
  верна (отрицание не кладётся), половина нет: ядро («Обе половины») КЛАДЁТ У в допущения
  истинной половины, и на этом стоят все 19 мест «разбор цели по условию».
- **Р7** в таблице — только `не больше`/`не меньше`; ядро («Зеркальный знак») зеркалит и
  строгие знаки, и три места ведра стоят на `больше` → `меньше`.
- **Введения дизъюнкции** (6-й ход ядра «цель-выбор с истинной ветвью» и половина «условие
  ложно» пятого хода) в таблице нет вовсе; без них не печатаются два места Е-3/Е-4.
- Закон «мера ноль ⇒ пусто», о котором спрашивал бриф, **не нужен**: таблица уже вписывает
  четыре вида факта пустоты в посылку Р5/Р6, и ядро берёт все четыре (прогон половин Н5, Н5б,
  Н6, Н6б).

### 2.3. Почему сегодняшний печатник ходов их не берёт

Ядро уже печатает для «разбора цели по условию» цепочки `ход … деление / выбор / закрыть
тождеством / закрыть истиной / вычислить / закон «…»` (`zapis.flang`, «Цепочка разбора
записи» и планировщик «Решить цель записи»), и проверяющая программа их переигрывает. Ни у
одного из 25 мест такой цепочки нет, и по коду печатника видно почему: тела с
`разбор`/`свёртка`/`→` планировщик отвергает заранее (7 мест Е-2); законов у него шесть, и
ни одного о порядке, строгом порядке, О5, Н10/П6, Д5 или конечности (12 мест Е-1/Е-5);
делит он только по внешнему условию и не знает дизъюнкции в допущении (6 мест Е-3/Е-4).
Расширять планировщик значило бы завести второй, безымянный вывод рядом с таблицей правил
— против ADR-0022.

## 3. Решение

### 3.1. Семь правил Р получают статус «в ADR», таблица правится в четырёх строках

Строки Р1–Р7 таблицы правил переводятся из «нет-в-ADR» в «в ADR» ссылкой на этот
документ. Одновременно исправляется то, что замер показал расходящимся (2.2): у Р1 —
указатель на ядро («Ветвлением», половина «ложно» = литерал `да`) и оговорка, что
«Следствие охраны» — правило о фактах; у Р2 — «условие кладётся допущением истинной
половины, отрицание — нет»; у Р7 — все четыре знака; добавляются три строки того же
семейства: **Гип** (гипотеза половины — механизм, не закон: снимается Р1 или Р4 и только
ими), **Или1**, **Или2** (введение дизъюнкции слева и справа; у ядра — 6-й ход и половина
«ложно» пятого). Владелец таблицы — стек A; правки идут через него.

### 3.2. Ядро печатает ход Р блоком `вывод`

Формат — тот же, что у семейств Н/П в ветке `r/yadro-pechataet-vyvod`: под утверждением,
у которого нет ни ходов, ни посылок, строки `    вывод цель ⟨…⟩`, `    вывод N ИМЯ ⟨формула⟩
основание`, `    вывод конец`; основание — `сам`, `строка N`, `из N`, `из N M`, `из N строка M`;
формулы — в виде «Терм записи». Печатаются пять форм, и только они:

1. **охрана + пустота** — `Гип ⟨У⟩ сам` → `Р5 ⟨результат равен Т⟩ из 1 строка N` (либо `Р6`)
   → `Р1 ⟨если У то результат равен Т иначе да⟩ из 1 2`;
2. **внутреннее условие** — `Р3 ⟨цель с телом вместо результата⟩ сам` → `Разв2 ⟨цель⟩ из 1 строка N`;
   при нетривиальной половине — `Р3 … из m` с предшествующим вложенным Р3;
3. **дизъюнкция в допущении** — `Гип ⟨Л⟩ строка N`, `Гип ⟨П⟩ строка N`, вывод цели из каждой
   (сама гипотеза, П2, Или1/Или2), `Р4 ⟨Ц⟩ из m1 m2`, `Разв2`;
4. **охрана + отношение** — `Гип ⟨У⟩ сам` → `Р7` → шаг семейства С/О «из шага» → `Разв2` →
   `Р1` — печатается, когда в ядре появится печать семейств С/О (волна владельца);
5. половина «условие ложно» при `иначе да` не печатается: она есть литерал.

Печатник убеждается по форме исходника, что блок пройдёт у проверяющей программы, и иначе
**молчит**: напечатанный блок, который приём не переигрывает, роняет честную запись кодом 1
и отнимает у доли больше, чем прибавляет (урок ветки `r/yadro-pechataet-vyvod`, заметка
`the-derivation-block-prints-for-four-of-thirty-five-places`). Golden-записи — байт в
байт то, что должно быть напечатано под шестью утверждениями четырёх записей корпуса —
лежат в `ПЕРЕДАЧА/stack-E/golden/` и переезжают в пробы проверяющей программы
(`flang/proof/чекер/пробы/семьи/`) вместе с приёмом. Владелец печати — стек B.

### 3.3. Проверяющая программа переигрывает Р СЛИЧЕНИЕМ, не вычислением

В `шаг_вывода` добавляется семейство Р по контракту проектной записки. Ничего не ищется и
не считается над именами:

- **Гип** — гипотеза; **открытые гипотезы** учитываются по шагам (множество; шаг наследует
  объединение по посылкам, Гип добавляет себя, Р1 и Р4 снимают). Последний шаг блока обязан
  быть без открытых гипотез, гипотеза охраны законна только под Р1 с той же охраной знак в
  знак, гипотеза случая — только под Р4 с той же строкой `требует`. Без этого учёта
  подделка «гипотеза без снятия» доказывала бы что угодно.
- **Р1** — цель разрезается по `если … то … иначе …` верхнего уровня; охрана = формула
  гипотезы, ветвь «иначе» = литерал `да`, ветвь «то» = посылка; посылка опирается не больше
  чем на эту гипотезу.
- **Р4** — два вывода одной цели, каждый ровно на одной гипотезе, гипотезы — левая и правая
  половины дизъюнкции одной строки `требует`.
- **Р3** (и Р2) — внутреннее (первое) условие В берётся спуском по тексту тем же порядком,
  что у ядра («Условие цели» → «Атомарное условие»); В подставляется значением во всех
  признанных местах (`подставить_условие`), половина упрощается ЛИТЕРАЛАМИ (`если да/нет`,
  `не`, `или`, `и притом` над `да`/`нет`, `Т равен Т` → `да`, лишние скобки) и обязана либо
  стать `да`, либо совпасть с посылкой знак в знак. Арифметики над числами в упрощении нет.
- **Р5/Р6** — факт пустоты одного из четырёх видов о Л; строка N — первая строка тела и
  она `разбор Л` со `случай пусто` → `то Т` (либо `свёртка Л начиная с Н`); тело ветви
  или начало сличается с правой стороной заключения.
- **Р7** — стороны и знак переставлены разом, четыре пары знаков.
- **Или1/Или2** — посылка есть левая/правая половина дизъюнкции заключения.
- **С4, П2** дополнительно принимают допущение из формулы шага-основания (`из N`), а не
  только из строки `требует`.

Приём стоит в той же ветке `проиграть_вывод`, что и семейства Н/П, и место, переигранное
блоком, уходит в числитель как «переигранный вывод» — тем же учётом, что у ADR-0022.
Владелец — стек A.

### 3.4. Закон «мера ноль ⇒ пусто» не заводится

Он уже внутри Р5/Р6 четырьмя видами факта; прогон половин это подтвердил. Отдельная
строка таблицы удвоила бы правило.

### 3.5. Доверенная база: просим +350, и это выходит за храповик

Оценка (2.5): ≈ 220 строк ядро приёма + ≈ 130 Р3. Свободный остаток храповика 9353 — 232
строки — на всё оставшееся по мандату кванторов. Решение по этому документу требует ОДНОГО из
двух: (а) храповик поднимается на величину, снятую черновиком E-3 (ориентир 9353 → 9700,
точное число — в отчёте черновика), потому что семейство Р — семь правил таблицы и
единственная дорога к 95 %; либо (б) принимается только ядро приёма (без Р3): −4 места
Е-3, ожидание 567 → 576. Выбор — за владельцем; черновик E-3 подаётся двумя частями,
чтобы выбор был дешёвым.

## 4. Что НЕ решается этим документом

- **Е-5 (8 мест)** — остаток от целого и дно произведения под охраной: нужны Н10/П6 в
  приёме, закон «целость из факта `(Т остаток от 1) равен 0`» (его нет ни в таблице, ни в
  ядре как отдельного правила) и Д5, от которого владелец отказался как от счёта.
  Выносится отдельной задачей стека A с отдельным замером.
- **Ж-4** (`sources` К1): требует развёртки ЧУЖОГО вызова в блоке `вывод` — правила нет.
- **Печать семейств С/О** в ядре (для Е-1) — волна владельца 6132; здесь только зависимость.
- **Р2 в чистом виде** (обе половины нетривиальны без гипотезы) на корпусе не встречается;
  приём принимает его тем же кодом, печать не пишется.
- Числа в разделе 2.5 — оценка до кода; заменяются снятыми черновиком.

## 5. Риски

- **Текст против дерева.** Ядро ищет внутреннее условие по дереву разбора, проверяющая
  программа — по тексту (`если`, ` или `, ` и притом `, `не `). Расхождение на одной цели
  даёт ложный отказ, не ложное принятие; ловится golden-записью `corpus-hof`. Что `не Х` у
  разборщика — выбор (`если Х то нет иначе да`), проверено прогоном: `bootstrap/flang ast` на
  цели `(не результат) или (х больше 0)` даёт два узла `if` и ни одного узла отрицания —
  спуск ядра доходит до Х, как и спуск по тексту у проверяющей программы.
- **Нормальная форма после упрощения** для `Р3 … из m` (одно место, `Ограничить`): печатник
  и приём обязаны упрощать одинаково до знака. Golden на эту форму не написан; при
  расхождении место остаётся на слове (−1), не ломая остального.
- **Печать зависит от перепечатки семени** — как у всякой печати ядра; батч overagent'а.
- **Храповик** — раздел 3.5.
- **Соседство с волной владельца**: `flang/self/**` занят перепечаткой; черновик печати
  собран над `r/yadro-pechataet-vyvod` и вливается после неё.

## 6. Как проверить, что решение исполнено

1. Четыре golden-записи с блоками Р: проверяющая программа даёт **код 0** (сегодня — код 1
   «имени «Гип» в приёме нет»); сводка показывает «переигранных выводов» 1/2/1/2.
2. Тринадцать подделок из проектной записки (переставленные стороны охраны, `иначе` не
   `да`, гипотеза без снятия, обе половины в одном случае, потерянная посылка, пустота из
   чужого факта, чужое начало свёртки, только знак без сторон, …) — **код 1** с названной
   причиной у каждой; «принято кодом 0» в наборе подделок — 0.
3. `sh flang/proof/чекер/пробы/прогон.sh` — «сошлось всё».
4. После перепечатки и пересъёмки записей: `доля-корпуса.sh --проигрыванием` — **≥ 580 / 651**
   (или ≥ 576 при выборе (б) в 3.5); `scripts/доказуемость.sh` — проверки 1, 3, 4 не
   покраснели.
5. Таблица правил: Р1–Р7 «в ADR», строки Гип/Или1/Или2 есть, `scripts/сверка-ведомости.sh`
   зелёный.

## 7. Где не уверен

- Оценка строк (2.5) — до кода. Черновик E-3 её заменит.
- Форма Р3 «из m» на `Ограничить` — нормальная форма не зафиксирована golden'ом.
- Печать Е-1 (4 места) стоит на печати С/О владельцем; сроков у неё нет.
- Замер половин переносит охрану в `требует`; у ядра факты из `требует` и из половины
  проходят один и тот же сбор фактов (`proof-kernel.flang` «Свести при известном»), но это
  прочитано, а не измерено прямо на исходных 25 местах.
