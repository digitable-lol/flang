## 1. Три разных утверждения, и путать их нельзя

Про функцию можно сказать три вещи, и каждая следующая сильнее предыдущей:

1. **«На всяком входе завершится».** Это тотальность. Она у нас доказана и
   переигрывается независимой программой: доля 625 из 651, 96,01 %.
2. **«На всяком входе завершится не позже чем за P(н) шагов»**, где P —
   многочлен с числовыми коэффициентами, а н — размер входа. Это
   ограниченность. Из неё следует первое; из первого она не следует: функция
   Аккермана тотальна, и это сказано в самом дереве
   (`flang/self/bounded.flang`, шапка; `flang/conc/SPEC.md`, «Тотальность — это
   не ограниченность»).
3. **«На машине М — не позже чем за P(н) / c(М) секунд».** Это уже не теорема о
   программе, а утверждение о паре «программа + машина», и c(М) — данные, а не
   свойство языка.

Стандарты (ADR-0031 §2) спрашивают третье. У нас есть первое доказательством,
второе — анализом, который ни в запись доказательства не печатается, ни
проверяющей программой не переигрывается, и третье — прибором, который снимает
c(М), но ни с чем её не перемножает. Ниже каждое из этих трёх слов —
«доказательство», «анализ», «прибор» — подтверждено прогоном.

## 2. Что есть сегодня — четыре прибора, каждый с замером

### 2.1. Доказательство завершения: в записи есть шаг и дно, нет числа вызовов

Проба: функция «Сумма до» над `н: неотрицательное` с `убывает н`, телом «если
н не больше 0 то 0 иначе н плюс («Сумма до» от (н минус 1))» и постусловием
«результат не меньше 0». Прогон `flang check --proof --строго --записать`:

- отчёт: «доказано точным шагом: аргумент 1 («н») объявлен натуральным и
  убывает на 1; дно и потолок даёт тип, внутри потолка шаг точен»;
- в записи узел завершаемости печатается двумя строками, дословно:
  `принцип тип «неотрицательное» по «н» носитель segment база 1 шаг 1` и
  `объявление встроенный «неотрицательное» дно 0 потолок 9007199254740991`;
- проверяющая программа: код 0, «узлов вердикта «разбором по случаям» проиграно
  заново 1».

**Что в записи есть:** дно 0, потолок 2⁵³−1, шаг спуска 1. Шаг ровно единица —
условие останова, а не круглое число (`flang/self/proof-initial.flang:2120`
«Шаг вниз начальной»), и проверяющая программа сверяет его буквально: вызов в
ветви спуска обязан быть `«F» от (н минус 1)` (`сверщик.c:4915`).

**Чего в записи нет:** числа вызовов. Из дна, шага и потолка оно выводится в
одну строку — рекурсивных вызовов не больше н, — но ни ядро, ни проверяющая
программа этой строки не пишут и не проверяют. Тем более нет числа шагов
**внутри** одного вызова: тело «н плюс вызов» стоит сколько-то витков, и это
«сколько-то» узел завершаемости не спрашивает.

У второго носителя, индукции по объявленной сумме (`носитель algebra`), нет
даже этого: там убывание — «часть меньше целого», числа при нём никакого, и
глубина рекурсии ограничена размером значения молча.

Перечисление по дереву: строк `убывает` в `flang/**.flang` — 17, из них в
`flang/self/` — 1. Тотальных функций (строк `^тотальная функция`) — 13 813,
обычных (`^функция`) — 2 401. То есть почти всё дерево тотально, и почти всё
тотально по структуре, а не по числу.

### 2.2. Оценка витков: есть, считается многочленом, но живёт вне доказательства

`flang/self/bounded.flang` (1 763 строки) — модуль «Ограниченность»: оценка
сверху на витки от размера входа, многочлен с числовыми коэффициентами
(«`витков ≤ 12·н + 7` можно сверить с квантом, а «линейна» — нельзя», шапка
файла). Читается из одного AST, ничего не вычисляет.

**Кто её потребляет.** Перечисление по дереву:

| потребитель | что делает | место |
|---|---|---|
| эталон планировщика | доказанный потолок ставится пределом пробега вместо запаса в миллион | `flang/self/conc.flang:1890` «Потолки прогона», `:1904` «Предел по имени» |
| множество отказов процесса | растущая или отсутствующая оценка → отказ «предел витков планировщика» достижим → без надзора `FLANG_UNCOVERED_FAILURE` | `flang/self/failures.flang:1408` «Чем плоха оценка» |
| замыкание двоичного `flang check` | **не потребляет**: слой отказов в двоичный не ввезён | `flang/self/processes.flang:37–56`; прогон ниже |
| ядро доказательств, обязательства, печать записи, проверяющая программа | **не потребляют**: вхождений слов «Ограниченность», «витков ≤», «bounded» — 0 в `obligations.flang`, `proof-kernel.flang`, `proofterm.flang`, `proof-initial.flang`, `сверщик.c` | перечисление 11 сентября |
| команды двоичного | ни одна не печатает оценку человеку: строк с «оценк»/«потолк» среди текстов вывода `flang_repl.c` — 0 | перечисление 11 сентября |

Прогон `flang check` на `flang/conc/examples/counter.flang`, `measure.flang`,
`budget.flang` — все три отвечают одинаково: «проверено НЕ ДО КОНЦА — … НЕ
сверено одно: достижим ли отказ ВНУТРИ тотальной функции — множество отказов
считает отдельный слой, в замыкание бинарника не ввезённый». Оценка витков в
этом ответе не упомянута ни числом, ни словом.

**Где оценка отказывает — названо в самом файле.** Десять причин
(`bounded.flang:470–532`): числовая рекурсия, ветвящаяся, взаимная, вызов в
цикле, применение функции-значения, растущий аргумент, вызов через
функцию-значение, неизвестная функция, размер не выведен, вид. Рекурсивный
вызов внутри свёртки не покрыт (`:1528`).

**Первая причина — самая важная для этого документа.** «Причина числовая»
означает: функция, у которой завершение доказано *по числу* (§2.1, `убывает`,
точный шаг), оценки витков не получает вовсе. Два прибора на числах не
пересекаются: там, где узел завершаемости знает дно и шаг, оценка молчит; там,
где оценка считает, узел завершаемости говорит «часть меньше целого» без
числа.

Единственный замер оценки по многим программам, который есть в дереве, —
`docs/zettel/nine-handlers-in-ten-need-no-preemption.md`: 55 из 60 мест вызова
обработчика с постоянной оценкой, наибольшая 47 витков, пять без оценки. Он
снят стендом на JavaScript, которого в дереве больше нет, и **сегодняшним
двоичным не повторён** — команды для этого нет (таблица выше).

### 2.3. Предел шагов рантайма: обрыв, а не граница

- `FL_MAX_STEPS` = 1 000 000 (`flang/src/emit/c/flang_runtime.h:117`);
  `--max-steps N` у `check`, `run`, `emit`, `repl`.
- Считают его **два** счётчика: `fl_tick` — по единице за виток
  (`flang_runtime.c:1962`), `fl_charge` — числом за проход встроенной формы
  (`:1606`); сумма — `ctx->steps`. Встроенные формы над строками и списками
  заряжаются длиной (`разделить`, `символы`, `подстрока`, `к числу`,
  `добавить` на медленном пути — список в `:1580–1595`).
- Исчерпание — объявленный исход `FLANG_RECURSION_LIMIT` «функция «…» исчерпала
  лимит шагов» (`:1975–1983`), у толкователя — отдельный вид «Прогон исчерпал
  предел» (`flang/self/interpret.flang:212`): «ИСХОД, а не поломка».

Это не граница отклика, а её противоположность: предел говорит, *после* какого
шага программу остановят, и ничего — о том, *успеет ли* она до него. Он нужен
как защита от зависания, и в этом качестве честен.

**Расхождение единиц, которое никто не мерил.** Оценка витков считает встроенную
форму над строкой за один виток — «строка — СКАЛЯР … встроенные формы над ней
стоят один виток, а не длину» (`bounded.flang:374`). Рантайм за ту же форму
берёт длину (`fl_charge`). Значит «витки» оценки и «шаги» предела — разные
величины с одним словом, и потолок 47 витков из зеттеля не обещает, что счётчик
`ctx->steps` не перейдёт 47. Сходятся ли они на настоящих обработчиках — не
проверено ни одним прогоном; это §9.

### 2.4. Постоянная машины: витки в секунды переводятся, но никем

`flang --машина` снимает постоянную этой машины (`flang_repl.c:18231`). Прогон
здесь, 11 сентября:

```
ядер: 256
занято ядер: 31.32
витков в секунду, разбор: 159074509
витков в секунду, лексер: 214982398
разброс: 0.74
```

Три вещи, которые этот вывод говорит сам, и они важнее числа:

1. постоянная **не одна**: виток разбора и виток лексера различаются в 0,74
   раза на одной и той же машине, и печатаются обе;
2. она **зависит от загрузки**: в комментарии к команде записано, что один и тот
   же файл считался 9 минут при загрузке 30 и 7 часов 23 минуты при 110; поэтому
   загрузка печатается рядом;
3. **перемножать нечем**: `--машина <файл>` печатает снятое раньше как есть
   (справка `flang_repl.c:342–352`), а команды, которая берёт потолок функции и
   постоянную и печатает секунды для названной машины, в двоичном нет.

## 3. Разница «завершится» и «завершится за N» — прямо

- **«Завершится»** — утверждение о существовании: у всякого входа есть конец.
  Оно не говорит, где. У нас доказано, в записи, переиграно.
- **«Завершится за N»** — утверждение о числе: у всякого входа конец не дальше
  N. Оно содержит первое (нельзя не дойти, если дошёл к N-му шагу) и добавляет
  меру. У нас — анализ, который умеет часть функций, не умеет ровно те, что
  доказаны по числу, не печатается в запись, не переигрывается, и единицы
  которого не сверены с рантаймом.
- **Второе без первого не бывает; первое без второго — бывает, и это наш
  случай.** 96,01 % — доля первого. Доля второго не измерена, потому что
  измерять нечем (§2.2, последний абзац).
- И даже «за N шагов» — не «за N секунд». Витки — свойство программы, секунды —
  свойство машины (§2.4), а время ожидания ввода-вывода не входит ни в то, ни в
  другое: поручение плану стоит столько же витков, сколько любой вызов, а
  длится столько, сколько диск. Это не недоработка, а устройство: витки считают
  работу программы, а не мира.

## 4. Цена: что придётся добавить, чтобы граница печаталась в запись и переигрывалась

Оценка по частям. Где число не измерено, оно названо предположением.

| часть | что нужно | на чём стоит оценка | цена |
|---|---|---|---|
| **А. Правило для числовой рекурсии** | из дна, шага и потолка узла отрезка (§2.1) вывести «вызовов не больше (н − дно) / шаг + 1» и умножить на витки тела | вся опора уже в узле: `база`, `шаг`, `дно`, `потолок` печатаются сегодня; сама оценка витков тела — `bounded.flang` | **обозримая**: одно правило по образцу ADR-0029; но многочлен окажется от *значения* н, а не от *размера* — `bounded.flang:368` считает размер по значению, и это решение придётся принять явно |
| **Б. Печать в запись** | новый вид узла: `оценка витков <многочлен> носитель …` с посылками по ветвям | образец — узел отрезка `proof-initial.flang:2100–2126` и его посылки; «Принцип индукции» занимает 142 строки (ADR-0026 §6) | **не измерено**; предположение — того же порядка, что узел отрезка. Едет партией перепечатки ADR-0026 §11 (8–9 часов), отдельной перепечатки не бывает (ADR-0032 §2.4) |
| **В. Переигрывание** | проверяющая программа пересчитывает многочлен по телу из исходника: кадр вызова, свёртка, отображение, вызов функции с оценкой | сегодня узел отрезка проигрывается ≈ 100 строками C (`сверщик.c:4843–4940`) для тела из одного `если`; обходчик многочленов должен взять все формы, которые берёт `bounded.flang` | **не измерено**; предположение — несколько сотен строк C, и каждая — строка того, чему верят |
| **Г. Правила и второй судья** | по строке в `flang/proof/ПРАВИЛА-ВЫВОДА.tsv` на каждое правило оценки + лемма Lean | ADR-0022 §8А | по числу правил; правил у оценки — по одному на форму тела |
| **Д. Единицы** | либо оценка заряжает встроенные формы длиной (а длина строки статически не выводится — строка скаляр), либо запись называет, **какой счётчик** она ограничивает | §2.3 | **решение, а не строки**: без него узел говорил бы о величине, которой рантайм не считает |
| **Е. Секунды** | одна команда: потолок × 1 / c(М) для названной машины, с печатью обеих постоянных и загрузки | `--машина <файл>` уже читает снятое | **дёшево**: данные на данные; дорого только не соврать — печатать разброс, а не одно число |
| **Ж. Собранный код** | граница — о витках толкователя; напечатанный C считает `fl_tick` свои | ADR-0030: разрыв печатника | **тот же разрыв, что у всего остального**: закрывается ADR-0030, не здесь |

Что **не** требуется, и это стоит сказать: квантор ADR-0026. Граница шагов —
утверждение о входах *одной* функции, ровно под тем единственным квантором,
который в языке есть («для всех входов этой функции», ADR-0032 §3.1). Порог
ADR-0026 §11.3 на эту работу не ложится.

## 5. Решение

1. **Слово «граница времени отклика» в текстах не употребляем как доказанное.**
   Есть «доказанное завершение» и «оценка витков»; второе — анализ, и называется
   анализом, пока не печатается в запись и не переигрывается.
2. **Задача [1408](../../tasks/1408-granica-shagov-v-zapisi-dokazatelstva.md)** —
   граница шагов печатается в запись доказательства и переигрывается
   проверяющей программой (части А–Г таблицы §4). Условие партии перепечатки
   неизменно: проверяющая программа читает новый узел раньше, чем ядро начинает
   его печатать. Первый шаг — замер, не код: сколько функций набора получили
   бы оценку сегодняшним `bounded.flang`, и на скольких из них узел отрезка даёт
   число вызовов.
3. **Задача [1409](../../tasks/1409-otsenka-vitkov-chislovaya-rekursiya-edinicy-sekundy.md)** —
   единицы (часть Д), секунды для названной машины (часть Е) и повтор замера
   зеттеля сегодняшним двоичным. Не зависит от 1408 и от перепечатки.
4. **Ограничения оценки не прячем.** Десять причин отказа (`bounded.flang:470–532`)
   остаются десятью; функция, у которой оценки нет, так и печатается — «оценки
   нет: <причина>», а не нулём.
5. **Ни ADR-0031 §5.4, ни ADR-0017 этим документом не отменяются**: применимости к
   медицине, авиации и космосу не обещаем; временной логики не заводим.

## 6. Что мы теряем

- **Доверенная база растёт дважды.** Новый вид узла в ядре и обходчик
  многочленов в проверяющей программе — это строки, которым верят без
  доказательства (ADR-0026 §6, тот же довод). «Прочитаешь за вечер» станет менее
  правдой.
- **Даже после 1408 у нас будет «за N шагов», а не «за N секунд».** Ожидание
  ввода-вывода, загрузка машины, разброс между видами витков, память под
  ареной — всё это вне многочлена. Жёсткое реальное время (то, о чём говорит
  DO-178C §6.3.4.f, разобранный в `docs/memory-and-regions.md`) остаётся вне
  досягаемости, и §5.1 запрещает говорить иначе.
- **Функции, доказанные по числу, — ровно те, у которых оценки нет** (§2.2).
  До части А таблицы §4 «Сумма до», НОД и всё с `убывает` не получат границы, а
  это 17 мест дерева и все программы, которые захотят считать по числу.
- **Целые классы остаются без границы навсегда в этой форме:** взаимная и
  ветвящаяся рекурсия, вызов через функцию-значение, цикл по значению
  неизвестного размера. Оценка сверху в общем случае неразрешима, и файл честно
  об этом говорит; никакая работа отсюда этого не меняет.
- **Граница — о толкователе, не о собранном коде.** Пока разрыв ADR-0030 не
  закрыт, аудитору предъявить нечего и здесь.
- **Партия перепечатки становится ещё тяжелее.** Части А–Б едут той же партией,
  что ADR-0026 §11 и 1403; каждая добавка — риск, что партия не соберётся с
  первого захода.

## 7. Что отвергнуто

- **Считать предел шагов границей.** §2.3: предел — обрыв, он говорит «после N
  остановим», а не «до N успеем». Объявленный исход не есть доказательство.
- **Анализ времени исполнения напечатанного C чужим инструментом (WCET).** Это не
  наше доказательство и не переигрывается нашей программой; для стандартов он
  сам потребовал бы квалификации инструмента (ADR-0031 §9). Возможен как
  дополнение, не как замена.
- **Печатать оценку секундами без названия машины.** §2.4: постоянная не одна и
  зависит от загрузки; одно число было бы ложью.
- **Временная логика** — ADR-0017, в силе.
- **Ждать ADR-0026 для этой работы.** §4, последний абзац: квантор здесь не
  нужен.

## 8. Как проверить, что решение исполнено

1. `sh scripts/доказуемость.sh` печатает **ДОКАЗУЕМ** — этим документом ничего
   не сломано (прогон 11 сентября: ДОКАЗУЕМ, 625 из 651, 96,01 %; набор проб —
   «сошлось всё», честных 197, проб на подлог 401, принято 0).
2. После 1408: запись пробы «Сумма до» из §2.1 содержит строку с многочленом;
   проверяющая программа её переигрывает; подделка с заниженным многочленом
   отвергается кодом 1.
3. После 1409: `flang --машина <файл>` в паре с записью печатает секунды для
   названной машины **с разбросом**, а не одним числом; и есть число: на
   скольких функциях набора «витки» оценки и «шаги» рантайма сошлись.
4. Поиск по `docs/` не находит слов «граница времени отклика» вне этого
   документа, ADR-0031 и ADR-0032.

## 9. Где не уверен

- **Единицы** (§2.3): расхождение названо по двум комментариям, а не прогоном;
  возможно, на настоящих обработчиках оценка и счётчик совпадают, потому что
  строки там короткие. Это первый шаг задачи 1409.
- **Многочлен от значения, а не от размера** (часть А): в `bounded.flang`
  размер числа — само число (`:368`), и это может оказаться неверным
  соглашением для границы отклика.
- **Собранный C считает те же витки, что толкователь?** Не проверял; если нет,
  часть Ж дороже, чем сказано.
- **Числа зеттеля (55 из 60, потолок 47)** сняты стендом, которого нет;
  сегодняшний двоичный их не повторял, и повторить их сегодня нечем.
- **Оценки цены Б и В** — предположения по аналогии, не замеры. Задача 1408
  обязана начать с замера, а не с кода.
