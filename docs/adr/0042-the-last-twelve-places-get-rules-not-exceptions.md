## 1. Решение одной фразой

Сто процентов берутся правилами, а не выносом: каждое из двенадцати мест получает
либо строку ведомости с леммой Lean и приёмом сверщика, либо переписанную цель,
которую уже закрывает существующее правило. Ни одно честное место из знаменателя
не выносится — правило ADR-0023 остаётся как есть.

## 2. Решения по местам

| места | решение | почему так |
|---|---|---|
| `abilities` У3, `poddelka-svyortka-shagom`, `poddelka-strict-order` | **семейство М — мера по построению**: М1 `длина (добавить Э к Л) = (длина Л) плюс 1` (то же для «приписать»); М2 `длина (свёртка Л начиная с Н как а и э → Ш) = (длина Н) плюс (длина Л)` при `длина Ш = (длина а) плюс 1` | ядро это уже доказывает (правило 4, «мера списка»); не хватало строки ведомости и приёма. Обе — уравнения вычислителя: один виток на элемент, одна приписка на виток |
| `equality` Р1 | **Разв3** — развёртка ВЫЗВАННОГО плоского определения (сегодня Разв2 разворачивает только своё тело); **К↑** — проекция поля выписанного конструктора `(вариант «К» с п равным Т).п = Т` | ADR-0022 §3.8 «деструктор не входит» сужается: проекция поля ЗНАЧЕНИЯ, построенного в той же цели, — уравнение вычислителя, а не деструктор неизвестного значения; проекция неизвестного значения остаётся запретом |
| `types` Т1 | **Разв1 для суммы автора**: разбор выписанного конструктора в цели сводится к ветви этого конструктора с подстановкой полей | лемма Разв1 сегодня есть только для списка; для суммы — та же лемма над `«Сумма»` модели |
| `abilities` У23, `poddelka-protivorechie` | **семейство Пр — противоречие пары допущений**: из `а меньше б` и `б не больше а` в допущениях следует любая цель | правило 8 ядра («несовместимые допущения») уже есть; ведомость закрытым списком семейств его не несла. Этим документом список открывается ровно на одно семейство. Лемма: в модели с NaN обе посылки вместе ложны при любых значениях |
| `sources` К1 | **цель переписывается квантором** `для всех э из результат: э не меньше 0` — её закрывают Э2/Э3 | правило о свёртке-признаке «равен да» было бы вторым путём к тому, что квантор уже говорит; но `sources` — в `flang/self`, а квантор не печатается ни в одну цель (задача 7098), и компилятор с ним перестал бы печатать сам себя. Поэтому — **после 7098** |
| `corpus-bytes` (1 шаг), `corpus-cforms` (3 шага) | **вычислитель «по примеру» сверщика учится двум вещам**: строке с нулевым знаком (длина хранится при строке, а не ищется до нуля) и `отфильтровать` | это рост того, что сверщик вычисляет, и он ограничен: оба умения — уравнения вычислителя с леммой (`«отбор»` в `Модель.lean` уже есть); ловушка «калькулятор снят» проверяет, что вычислением не закрывается ничего, кроме замкнутого примера |

**Исполнение `sources` К1** (задача 1794, 15 сентября 2026): цель переписана
квантором, закрывает её Э1 — тело «Модули» есть пустой список, — а не Э2/Э3.
Файл лежит в `flang/proof/map/`, не в `flang/self`, и семя ствола квантор уже
читает: перепечатки правка не ждала.

## 3. Доверенная база

- Строка бюджета «покрытие без новых правил» ХРАПОВИКа: **+200 → +310** —
  подписано этим документом (просьба задачи 9616: превышено на ≈90 печатью Ч5,
  Разв1 и многострочного тела, потолок 7188 не пробит).
- Этот документ: **+180 строк кода `сверщик.c`** на М1, М2, Разв3, К↑, Разв1-суммы,
  Пр и два умения вычислителя; потолок `ХРАПОВИК.txt` поднимается на съеденное и
  ни строкой больше; примитивов 15 не прибавлять.
- **Дополнение 15 сентября 2026 (задача 3449): +74 строки кода** (`sh
  flang/proof/сверка-ведомости.sh --строки-кода`: 7401 → 7475) на третье и
  четвёртое умения вычислителя примера — разбор посчитанного списка по звену и
  вариант с полями. §2 их не называл: за отбором у `corpus-cforms` нашлась цепочка
  «Первая из меток» → вариант с полем → разбор со связыванием поля (задача 3448,
  раздел «Что осталось»). Довод: без них три шага остаются на слове ядра, а вынос
  по ADR-0023 не положен. Уравнения — те же, что Разв1 говорит о выписанном
  конструкторе: строка «Выч» ведомости расширена, леммы «Выч-звено», «Выч-вариант»,
  «Выч-первое-из-отбора», ловушки 50–52. Потолок поднят на съеденное. «Выч» вне
  приёмки Lean, как и прежде (вычислитель половин модель не повторяет): нового
  правила блока «вывод» здесь нет, долг задачи 1130 прежний. Подпись — влитие PR.
- Каждое новое правило — строка `ПРАВИЛА-ВЫВОДА.tsv`, лемма в `Правила.lean`,
  ловушка в `Ловушка.lean` и **случай в `Приёмка.lean`/`Состоятельность.lean`**
  (ADR-0041): правило, которое сверщик принимает, а теорема не покрывает, —
  долг задачи 1130, а не норма.

## 4. Перепечатка семени — одна партия

Десять мест PR #21, снятие предусловий (1261, 5332), кванторы (3123, 4058) и
правила этого документа меняют `flang/self/**` и доезжают до собранного
двоичного только перепечаткой (5–8 часов, пик ≈21 ГиБ). Решение: **одна партия**
после вливания всех этих PR, задача 5190; до неё записи корпуса остаются печатью
семени, как требует сторож `доля-корпуса.sh --вложенность`, а печать ядра живёт
пробами. Перепечатка трогает корень доверия (`bootstrap/**`) и потому идёт
отдельным PR с проверками воспроизводимости (`reprint-determinism`,
`seed-fingerprint`) и после неё — выпуск.

## 5. Что отвергнуто

- **Вынос четырёх шагов из знаменателя** как «нарочных пределов». ADR-0023
  выносит только «лжёт-запись»; честная запись, которую сверщик не умеет
  проверить, — долг сверщика, а не свойство корпуса.
- **Правило о свёртке-признаке «равен да»** для `sources`: второй путь к тому, что
  говорит квантор, — лишняя строка доверенной базы.
- **Проекция поля неизвестного значения** (общий деструктор): остаётся запретом
  ADR-0022 §3.8.

## 6. Как проверить, что решение исполнено

1. После перепечатки `sh flang/proof/доля-корпуса.sh --проигрыванием` — **650 / 650**
   (651 → 650: задача 1794 сняла функцию «Все неотрицательны»);
   `sh scripts/доказуемость.sh` — ДОКАЗУЕМ.
2. `sh flang/proof/чекер/пробы/прогон.sh` — «сошлось всё»; на каждое новое правило —
   порча записи с кодом 1; ловушка «калькулятор снят» зелена.
3. `sh flang/proof/lean/прогон.sh` — леммы приняты, ловушки отвергнуты, сверка
   вердиктов C ↔ Lean — расхождений 0, новые правила — в приёмке Lean.
4. Строк кода сверщика прибавилось не больше 180 сверх подписанного «покрытия».

## 7. Где не уверен

- М2 требует от шага свёртки меры «ровно плюс один»; если шаг зовёт функцию, мера
  берётся её доказанным обещанием (восьмой ход) — печать этого пути не проверена.
- Строка с нулевым знаком в вычислителе сверщика меняет представление строк в
  C-коде сверщика; цена по строкам — оценка.
