# ADR-0054. Профиль в `.flangrc` выбирает, какие модули библиотеки ввозятся

**Состояние:** принято. Фильтр ввоза по имени работает в двоичном без печати
компилятора (C-оболочка, `flang/src/emit/c/flang_repl.c`); то, что требует печати,
перечислено в разделе 5.
**Рядом:** [ADR-0024](0024-the-settings-file-and-the-language-of-output.md) — файл
настроек; [ADR-0045](0045-run-and-io-print-the-verdict-and-refuse-an-unproved-program.md) —
вердикт перед запуском; [ADR-0049](0049-short-commands-live-in-the-settings-file.md) —
короткие команды в том же файле.
**Проверяется:** проба в разделе 6.

---

## 1. Задача

Библиотека одна на всех: длинные целые и дроби нужны математику, сеть и шифры —
программисту, статистика и таблицы — аналитику. Владелец просит включать и выключать
наборы модулей из `.flangrc` — режимами «математик», «программист», «аналитик».

Модуль ищется по имени из строки `использует «Имя»`: каталог файла, каталоги выше
него до корня дерева, каталоги `FLANG_MODULE_DIR`, библиотека рядом с двоичным
(`flang/stdlib`, `flang/core`, `share/flang/…`). Поиск делает C-оболочка двоичного
(`repl_find_module`), а не компилятор: компилятору приезжают уже найденные файлы.

## 2. Решение

**Три ключа файла настроек.**

```
profile = mathematician
modules = Bignum, Rationals
profile.statistician = Numbers, Statistics, Lists
```

| ключ | значение |
| --- | --- |
| `profile` | имя профиля или несколько через запятую; модули складываются |
| `modules` | модули сверх профиля, по имени из строки `модуль «…»`; ёлочки можно писать, можно не писать |
| `profile.<имя>` | объявление профиля в самом проекте; одноимённое объявление библиотеки им перекрывается |

Файл тот же, что у ключа `unproven`: ближайший `.flangrc` от рабочего каталога вверх.

**Профиль — это список имён модулей, и ничего больше.** Профили, поставляемые с
языком, лежат в `flang/stdlib/profiles.flangrc` строками `profile.<имя> = …`:

| профиль | модули |
| --- | --- |
| `mathematician` | числа, длинные целые, дроби, классические задачи, дерево чисел, запись чисел, статистика, логика, функции высшего порядка, списки, необязательное, результат |
| `analyst` | числа, статистика, запись чисел, списки, строки, словари, дата и время, JSON, TOML, SQLite, Postgres, необязательное, результат, функции высшего порядка |
| `programmer` | всё общее, форматы данных, сеть, базы данных и криптография; без длинных целых, дробей и статистики |

**Что запрещает профиль.** Нет ни `profile`, ни `modules` — ввоз как без профиля.
Есть хоть один — модуль, найденный в месте библиотеки и не названный ни профилем, ни
`modules`, по имени не ввозится. Поиск отвечает «не найдено», связывание — кодом
`FLANG_IMPORT_NOT_FOUND`, а строкой выше в stderr стоит, какой профиль и какой файл
его запретили:

```
flang: модуль «Rationals» библиотеки не входит в профиль «programmer» (/work/.flangrc) — по имени не ввозится; допишите его в «modules» или выберите другой профиль
```

Неизвестное имя профиля — строка в stderr и пустой профиль, а не молчание.

**Чего профиль не запрещает.**

* Модули проекта: найденные рядом с файлом и выше по каталогам ввозятся всегда.
* Ввоз из файла самой библиотеки: модуль профиля ввозит своих соседей без
  ограничений, иначе `Rationals` не собрался бы без `Bignum`.
* `flang/core`: это часть языка, а не библиотеки.
* Ввоз путём (`использует «Имя» из "…"`): путь называет файл, а не выбирает его из
  библиотеки. Профиль — граница удобства и намерения, а не песочница.

## 3. Профиль и вердикт о доказанности

Вердикт перед запуском (ADR-0045) считается по ЗАМЫКАНИЮ — по всем файлам, которые
программа ввозит, включая зависимости модулей библиотеки. Профиль вердикта не
меняет и ослабить его не может: он только решает, может ли модуль попасть в
замыкание по ввозу из файла проекта. Отсюда следствие, которое надо знать: модуль
профиля с недоказанным утверждением в зависимости делает недоказанной каждую
программу, которая его ввозит. Так сейчас с `Rationals`: в `Bignum` два постусловия
держатся только на примерах, и `flang run` программы с дробями без `--на-веру` не
запускается.

## 4. Почему так

* **Список имён, а не каталоги.** Каталог библиотеки один, и раскладывать его по
  папкам профилей значило бы двигать файлы, которые ввозят по пути.
* **Фильтр в поиске, а не в компиляторе.** Поиск и так в C-оболочке, и там же
  читается `.flangrc`. Правка не трогает напечатанный компилятор и работает сразу.
* **Файл профилей библиотеки — в формате `.flangrc`.** Его читает тот же разбор
  «ключ = значение», и он лежит рядом с модулями, которые перечисляет.

## 5. Что требует печати компилятора

| что | почему нельзя в C-оболочке |
| --- | --- |
| отдельный код отказа для модуля вне профиля вместо `FLANG_IMPORT_NOT_FOUND` | текст и код отказа связывания печатает компилятор |
| профиль в отчёте `flang check --proof` и в записи доказательства | отчёт и запись печатает компилятор |
| профиль, меняющий язык, а не библиотеку (например, запрет типа `число` у математика) | слова типов знает `flang/self/types.flang` |

## 6. Проба

```
$ cat .flangrc
profile = programmer
$ flang check use.flang          # использует «Rationals»
flang: модуль «Rationals» библиотеки не входит в профиль «programmer» (…/.flangrc) — по имени не ввозится; …
FLANG_IMPORT_NOT_FOUND в файле use.flang, строка 1, столбец 1: не найден модуль «Rationals»: …
$ printf 'profile = mathematician\n' > .flangrc
$ flang check use.flang
use.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```
