## 1. Задача

Прибор печатает вердикт и раздел, который сам себя называет ходом доказательства:
«чем получен каждый шаг (правило и основания — строками записи доказательства)».
У большинства утверждений в этом разделе стоит одна строка — имя правила. Замер
2 октября 2026, двоичный 0.7.23, корпус 47 файлов:

| мера | число |
|---|---:|
| доказанных утверждений | 53 |
| из них с хотя бы одной строкой шага | 7 |
| из них только с именем правила | 46 |
| реальных шагов, напечатанных человеку | 20 |
| реальных шагов в записях `--record` | 42 |
| реальных шагов в `--proof --json` | 0 |
| реальных ходов в записях / из них напечатано человеку | 22 / 0 |
| строк правил в `flang/proof/tables/inference-rules.tsv` | 112 |
| различных словесных формулировок у этих правил | 16 |
| правил без словесной формулировки | 14 |
| различных кодов правил, дошедших до читателя на корпусе | 7 |

Дословно то, что сегодня получает читатель на программе из 22 строк с двумя доказанными
постусловиями:

```
чем получен каждый шаг (правило и основания — строками записи доказательства):
  утверждение «владелец не меняется» функции «Пополнить» строка 10
    правило «тождество после переписки допущением»
  утверждение «остаток при переименовании цел» функции «Переименовать» строка 20
    правило «тождество после переписки допущением»
```

Это не вывод: ни цели, ни посылок, ни места, ни того, что подставлено. И это не ошибка
печати — в самой записи у этих утверждений блок кончается, не начавшись. Независимый
сверщик отвечает `ПРОВЕРЕНО` кодом 0, потому что он не переигрывает запись, а выводит
утверждение из исходника заново (задача 2748). Пробел в записи не роняет ни один вердикт
и потому не виден ничем, кроме чтения глазами.

Там, где шаги есть, они читаются — и это показывает, что мера верная:

```
  утверждение «цена не ушла в минус» функции «Цена со скидкой» строка 7
    правило «неотрицательность по построению»
    вывод цель ⟨результат не меньше 0⟩
    вывод 1 Н3 ⟨скидка не меньше 0⟩ строка 4
    вывод 2 Пред1 ⟨скидка помещается⟩ строка 4
    вывод 3 П3 ⟨скидка не больше 9007199254740991⟩ из 2
    вывод 4 Н12 ⟨( цена минус скидка ) не меньше 0⟩ из 1 3
    вывод 5 Разв2 ⟨результат не меньше 0⟩ из 4 строка 12
```

Пять шагов, у каждого правило, посылки номерами и место. Не хватает одного: `Н3`, `Пред1`,
`П3`, `Н12`, `Разв2` — коды, а не слова, и у `Разв2` в ведомости словесной формулировки нет
вовсе.

## 2. Развилка

Три пути, и выбор обоснован замером выше.

**А. Печатать запись прозой переводчиком вне компилятора.** Отдельная программа читает
`--record` и печатает рассуждение по-русски. Дёшево, доверенной основы не трогает,
устроено как переводчик предложений из ADR-0050. **Отвергнуто:** печатать нечего. У 46 из
53 доказанных утверждений в записи нет шагов — проза из имени правила будет той же одной
строкой, только длиннее. Переводчик лечил бы форму там, где пусто содержание.

**Б. Дать прозу ведомости правил и рендерить её на месте кода.** К 112 строкам
`inference-rules.tsv` дописать словесную формулировку, печать берёт её по коду.
**Принято частью** — это задача 2146. Само по себе решения не даёт: 46 утверждений
по-прежнему остаются одной строкой, а 14 правил сегодня вообще безымянны.

**В. Терм доказательства несёт вывод у каждого доказанного утверждения, и печать
его печатает.** Ядро, сведя цель с телом функции, кладёт в терм те шаги, которые
действительно сделало: развернуть тело, переписать по закону, закрыть правилом. Формы
становится одна вместо трёх (`вывод`, `ход`, `шаг`), и у каждого шага обязательны четыре
поля: правило словами и кодом, посылки, подстановка, строка исходника. **Выбрано.**

Выбор обоснован так: мера читаемости — не длина вывода, а доля утверждений, у которых
есть что читать. Сегодня она 7/53 = 13,2 %. Путь А её не двигает вовсе, путь Б не двигает
её тоже (он двигает качество строки, а не их число), и только путь В поднимает её, потому
что добавляет шаги там, где их нет.

## 3. Решение

1. **Форма вывода одна.** Три формы (`вывод` с кодом правила, `ход` с движениями,
   `шаг` с номером строки) сводятся к одной. Сегодня из трёх человеку печатаются две,
   Lean моделирует одну (`flang/proof/lean/Record.lean` — только блок `вывод`), сверщик
   переигрывает одну. Три формы при двух читателях и одной модели — три разные правды.
2. **У каждого доказанного утверждения в записи есть вывод.** Утверждение, доказанное
   сведением по объявлению, несёт в записи не меньше одного шага: цель, развёртка тела,
   закрывающее правило. «Правило без шагов» перестаёт быть законной записью, и сторож
   записи краснеет на неё.
3. **У каждого шага четыре обязательных поля:** имя правила словами и кодом ведомости;
   посылки — номерами прежних шагов либо строкой исходника; подстановка — та формулировка,
   которая получилась после замены; место — строка исходника. Поле, которого у шага нет
   по существу, печатается прочерком, а не опускается.
4. **Ведомость правил становится источником слов.** Все 112 строк получают словесную
   формулировку, сторож `flang/proof/tables-guard.fscript` краснеет на прочерк.
5. **Машинный вид несёт то же, что текстовый.** `--proof --json` печатает массив шагов.
   Сегодня он не несёт ни одного шага, а поле `steps` считает написанные автором строки
   `затем`.
6. **Шаг можно развернуть глубже** ключом, который берёт одно утверждение и печатает
   его вывод подробнее. Без этого «читаемый ход» упирается в одну строку на шаг.
7. **Словаря и языковой модели в печати нет.** Слова берутся из ведомости правил, которую
   заполнил автор языка, — та же дисциплина, что в ADR-0050: компилятор выбирает строку из
   таблицы, а не склоняет.

## 4. Чего это решение не даёт

* **Не даёт доказательства тому, что сегодня не доказано.** Доля доказанного не меняется:
  на 14 пользовательских программах доказано 28 обязательств из 33 написанных, и решение
  это число не двигает. Оно двигает только то, можно ли прочесть, как получены те 28.
* **Не делает сверщик переигрывателем записи.** Сверщик сегодня выводит заново из
  исходника и потому зелен на записи без шагов; после правки у него появится что
  переигрывать, но решение о том, обязан ли он переигрывать, — это задача 2748, не эта.
* **Не даёт силлогистического вида по умолчанию.** Вид предложениями по ADR-0050 остаётся
  отдельным переводчиком вне доверенной основы; его вердикт — пять строк, и хода
  доказательства в нём нет: «СЛЕДУЕТ: предложение 3 выведено из посылок 1, 2» названо
  посылками, но не правилом и не шагами.
* **Не трогает кванторы и отрицание.** Границы ядра, названные в ADR-0050 §4 (цепочка
  модус поненсов, введение отрицания, квантор в посылке), остаются где были.

## 5. Цена, и почему это ADR, а не правка

Правка живёт в терме доказательства (`flang/self/proofterm.flang`), в ядре
(`flang/self/proof-kernel.flang`), в печати записи (`flang/self/zapis.flang`) и в разделе
ведомости — то есть в доверенной основе, и доезжает до двоичного только перепечаткой
самосборной части. Меняется формат записи, который читают три независимых читателя:
сверщик `flang/proof/checker/checker.c` (10 497 строк C99), модель Lean
(`flang/proof/lean/`, 12 676 строк) и человек. Смена формата при трёх читателях — решение
об устройстве, а не правка печати.

## 7. Приёмка

На корпусе из 47 файлов у каждого из 53 доказанных утверждений в разделе
`чем получен каждый шаг` стоит не меньше одной строки шага, и в каждой строке есть имя
правила словами, посылки и строка исходника. Доля утверждений с ходом — 53 из 53 вместо
7 из 53. Проба краснеет, если хотя бы у одного доказанного утверждения в разделе осталась
одна строка.
