# ADR-0081. Напечатанный код следует канону своей цели

**Состояние:** предложено. Принимает владелец.
**Основание:** `flang/self/emit-*.flang`, `flang/self/emit-layout.flang`,
`flang/src/emit/**`, `scripts/targets/target-canons.fscript`,
`scripts/targets/target-canons.tsv`, `.github/workflows/target-canons.yml`.

---

## Решение

Программа, напечатанная в любую из десяти целей, — это код, который
форматтер и линтер этой цели принимают без правки. Мерило — инструмент цели
с его умолчаниями, а не вкус печати. Где канона нет (C и C++), он назван здесь
одним словом, и дальше действует так же.

| цель | раскладка | проверки |
|---|---|---|
| c | `clang-format --style=LLVM` | сборка `-std=c99`, `clang-tidy` |
| cpp | `clang-format --style=LLVM` | сборка `-std=c++17`, `clang-tidy` |
| go | `gofmt` | `go build`, `go vet` |
| rust | `rustfmt` (edition 2021) | `cargo build`, `cargo clippy` |
| java | — | `javac -Xlint:all` |
| js | `prettier` | `node --check` |
| ts | `prettier` | `tsc --strict` |
| elixir | `mix format` | `elixirc` |
| python | `black` | `ruff check`, `mypy` |
| csharp | `dotnet format` | `dotnet build`, `dotnet format --severity info` |

Ширина строки — умолчание форматтера цели: 88 у black, 80 у prettier, 100 у
rustfmt, 98 у mix format, 80 у LLVM. Ни одна цель не получает своего файла
настроек форматтера: печать подстраивается под умолчание, а не умолчание под
печать.

У Java форматтера в поставке JDK нет; `google-java-format` в набор не входит,
пока его нельзя поставить из пакетов дистрибутива или из самого JDK.

## Имена

Имя flang русское и пишется в ёлочках; в напечатанном коде оно становится
**стабильным ASCII-идентификатором** транслитерацией, как сегодня:
`«Приписать строку в начало»` → `pripisat_stroku_v_nachalo` в Python и Rust,
`PripisatStrokuVNachalo` в Go, `pripisatStrokuVNachalo` в JavaScript. Регистр
и разделители — по канону цели.

Юникодные идентификаторы не используются, хотя восемь целей из десяти их
допускают:

- руководства стиля просят ASCII: PEP 8 для стандартной библиотеки и для
  проектов с широким кругом читателей, руководства Google для Java и C++,
  `non_ascii_idents` в Rust;
- экспорт в Go держится на заглавной первой букве, и правило «заглавная
  кириллица экспортирует» неочевидно читателю;
- имя набирают на клавиатуре и ищут `grep`-ом люди, которые flang не знают.

Транслитерация детерминирована: одно имя flang на любой печати даёт один и тот
же идентификатор, столкновения после транслитерации ловит печать и отказывает.
Исходное имя остаётся в документирующем комментарии и в таблице вызова по
имени, поэтому функция находится и по русскому имени.

Ролевые приставки (`fn_`, `rec_`, `funkciya_`, `Sozdat…`) остаются частью
устойчивого интерфейса: они разводят функцию и запись с одним именем flang.

## Раскладка

Печать собирает строку целиком, а последний проход раскладывает её по канону
цели. Проход один на все цели и лежит в `flang/self/emit-layout.flang`:

- строка длиннее ширины цели делится на последней паре скобок верхнего
  уровня; аргументы встают по одному на строку с запятой в конце там, где цель
  её ставит (Python, JavaScript, TypeScript, Rust), и без неё в Elixir;
- black сначала пробует уложить всё тело скобок одной строкой, и проход делает
  то же; сумма строк в Python делится перед `+`;
- единственный аргумент-литерал (список, словарь, `vec![…]`) обнимается
  скобками вызова там, где так делает форматтер цели;
- в Elixir аргументы `raise`, `if` и `unless` встают под вызовом, присваивание
  делится после `=`, многострочное выражение отделяется пустыми строками, а
  длинное целое пишется группами `1_000_000`;
- в JavaScript и TypeScript утверждения кончаются точкой с запятой, а ключи
  объекта, годные в идентификаторы, пишутся без кавычек;
- в Rust последний `return` функции становится её значением, а привязка,
  которую блок сразу возвращает, становится значением блока;
- строковые литералы экранируют знаки, которые цель в исходнике не принимает:
  BOM в Go, U+0085, U+2028 и U+2029 в Elixir и C#, невидимые U+00AD, U+200B и
  U+2060 в Rust.

Строчных комментариев-следов (`# пусть «имя»`, `# постусловие «…»`) печать не
ставит там, где переложена: имя уже стоит в идентификаторе, имя постусловия —
в его вызове. Остаются комментарии, которые несут смысл: шапка файла и
документирующие комментарии из контрактов.

## Интерфейс напечатанного кода

- один модуль flang — один файл цели и модуль, пакет или класс с тем же
  именем;
- каждая функция flang — публичная функция цели с документирующим
  комментарием в формате цели (docstring, `///`, JSDoc, `@doc`, XML-doc): что
  принимает, что возвращает, доказано ли завершение, какие постусловия
  проверяются;
- записи и варианты — фабрики с полями по именам;
- вызов по имени flang — через диспетчер `call`, тем же текстом отказов, что у
  интерпретатора.

## Что остаётся не по канону намеренно

- **Одно представление значения** (`rt.Value`, `fl_value`, кортежи в Elixir)
  вместо родных типов цели. Семантика flang — точные числа, минус ноль, NaN,
  полные записи — обязана совпасть с интерпретатором до бита; родные типы
  десяти целей этого не дают.
- **Контекст вычисления** первым параметром: пределы шагов и глубины — часть
  языка, а не рантайма.
- **Временные `t1`, `_t2`**: порядок вычисления — часть семантики, и печать
  держит его явным.
- **Сторожа постусловий и предусловий** в теле: недоказанное утверждение
  проверяется при работе.
- **Отказ значением** в Go и Rust и исключением в остальных — по канону
  каждой цели, но с одним кодом и текстом отказа на все десять.
- **Пакет в Go, пространство имён в C# и пакет в Java** пока общие для всех
  программ; модуль flang станет пространством имён отдельным решением.

## Как это проверяется

`bootstrap/flang io scripts/targets/target-canons.fscript --plan Measure`
печатает корпус из двенадцати программ во все десять целей, гонит
инструменты из таблицы выше и сверяет счёт с ведомостью
`scripts/targets/target-canons.tsv`. Счёт может только падать: выросший или
новый счёт краснит работу. После печати, уронившей счёт, ведомость
переписывается той же командой с доводом `-- Record`. Работа идёт по
расписанию в `.github/workflows/target-canons.yml`.
