# ADR-0083. Цена функции известна до прогона: граница шагов и памяти от размеров входа, переведённая в секунды и байты названной машины

**Состояние:** предложено. Принимает владелец.
**Основание:** [ADR-0033](0033-termination-is-not-a-bound-on-steps.md) §2.2–§2.4,
§5.3 и §9; [ADR-0031](0031-certification-is-a-process-not-a-property-of-the-language.md) §2;
[ADR-0061](0061-killing-a-process-and-bounding-its-resources.md).
**Код:** `scripts/cost/` (анализатор, калибровка, сверка, проба на подлог),
`flang/src/emit/c/flang_repl.c` (ключ `flang run --cost`),
`flang/src/emit/c/flang_cli.c` (поле `"cost"` запроса напечатанного прогонщика).
**Задачи:** [1409](../tasks/1409-step-estimate-units-match-the-runtime-and-seconds-name-the-machine.md)
(этим документом закрывается по существу, кроме места правки),
[1408](../tasks/1408-the-step-bound-is-printed-into-the-proof-record.md) (остаётся: переигровка

## Решение

До выкладки в работу для функции печатается её цена: сколько шагов она
сделает, сколько памяти возьмёт и какие действия с миром совершит — как
многочлен от размеров входа. Многочлен переводится в секунды и байты по
профилю названной машины, снятому калибровкой на этой же машине. Каждое число
помечено, откуда оно: **выведено** из устройства функции, **оценено** (в
выводе есть допущение, оно названо) или **оценки нет** (с причиной).

```
bootstrap/flang run-script cost docs/examples/web/orders-api.flang \
  --function 'Обработать запрос' --sizes '|хвостадреса|=132' \
  --profile scripts/cost/profiles/dev.profile
```

```
цена «Обработать запрос»
  размеры:
    |метод| — байтов в строке «метод»
    |путь| — байтов в строке «путь»
    |хвостадреса| — байтов в строке «хвостадреса»
  граница выведена из устройства функции; проверяющей программой не переиграна (ADR-0083)
  шагов толкователя (flang run) ≤ 116·|хвостадреса|^3 + 1659·|хвостадреса|^2 + 5086·|хвостадреса| + 7112
  шагов напечатанного C ≤ 14·|хвостадреса|^4 + 94·|хвостадреса|^3 + 258·|хвостадреса|^2 + 311·|хвостадреса| + 274 (вызовов 0 + зарядов длиной 14·|хвостадреса|^4 + 94·|хвостадреса|^3 + 258·|хвостадреса|^2 + 311·|хвостадреса| + 274)
  памяти напечатанного C ≈ 12·|хвостадреса|^4 + 150·|хвостадреса|^3 + 1167·|хвостадреса|^2 + 2794·|хвостадреса| + 2260 байт (оценка)
  вызовов функции ≤ 1
  действий с миром: нет
при размерах |хвостадреса|=132:
  flang run: шагов ≤ 296381168
  напечатанный C: шагов ≤ 4471074574
  машина «dev»: снята при загрузке 8.91 из 256 ядер
  flang run: время 741.80 с – 1567.84 с, память сверх старта программы ≈ 431050.6 МиБ
  напечатанный C: время 2.32 с – 52.31 с, память ≈ 9746.4 МиБ
```

Граница — **сверху**, не прогноз среднего. Она держится для любого входа
названного размера; насколько она грубее настоящего прогона, показывает
сверка (§6).

## 1. Три счётчика, и у каждого своя единица

ADR-0033 §2.3 нашёл, что «витки» оценки и «шаги» рантайма — разные величины с
одним словом. Здесь они разведены по именам, и каждая сверена со своим
счётчиком.

| счётчик | что считает | чем снимается в прогоне |
|---|---|---|
| шаги толкователя | поле «витки» результата `flang run` — единица за каждый узел, который вычисляет толкователь (`flang/self/interpret.flang`) | `flang run --cost`: строка «цена прогона: шагов N, пик памяти B байт, секунд T» в поток ошибок |
| вызовы напечатанного C | `fl_enter` — единица за вход в рекурсивную функцию | поле `"steps"` ответа прогонщика при `"cost":"1"` |
| заряды длиной | `fl_charge` — длина строки или списка за проход встроенной формы (`flang_runtime.c`) | входят в то же `"steps"`; граница C = вызовы + заряды |

Таблица цены узла для толкователя выписана из `interpret.flang`, а не
подобрана: литерал и имя — 1; действие над двумя — 3 + левое + правое;
встроенная форма — 1 + число аргументов + их цена; вызов — 1 + аргументы +
тело вызванной + 1 за кадр возврата (кадра нет у хвостового вызова функции без
постусловий); ветвление — 2 + условие + большая из ветвей; `пусть` — 2 +
значение + тело; `разбор` — 2 + разбираемое + самый дорогой случай; свёртка —
4 + список + начало + длина·(1 + шаг); отображение и фильтр — 3 + список +
длина·(1 + шаг). Постусловия толкователь проверяет на каждом вызове, и их цена
входит в границу; функции, связанные постусловиями в круг, развязаны так же,
как развязывает компилятор («Развязать постусловия»): у двойника постусловий
нет.

Напечатанный C проверяет не все постусловия: какие оставлены, анализатор
узнаёт из напечатанного кода (`fl_post`), а не предполагает.

## 2. Как выводится граница

Анализатор (`scripts/cost/bound.flang`) читает связанное дерево программы
(`flang ast`), строит для каждой функции сводку снизу вверх и подставляет
сводки вызванных функций в места вызова.

- **Размеры.** Число — его значение `н`; строка — её байты `|s|`; список —
  длина `|xs|` и размер элемента `|xs[]|`; запись и вариант — сумма полей.
  Размер результата выводится вместе с ценой: длина `добавить x к xs` — `|xs|
  + 1`, `соединить` — сумма частей, постусловие вида `(длина результат) не
  больше E` берётся как граница длины.
- **Рекурсия.** Число вызовов выводится из спуска: по хвосту списка, по части
  значения, по `минус c` у числа — это **выведено**. Если функция объявила
  меру (`убывает`), а спуска анализатор не нашёл, принимается, что мера
  убывает хотя бы на 1 за вызов — это **оценено**, и допущение печатается.
  Ветвящаяся рекурсия без спуска по частям и рост аргумента — **оценки нет**.
- **Накопители.** Свёртка, у которой шаг добавляет к накопителю ограниченное,
  получает линейный рост накопителя; рост, который анализатор не ограничил, —
  «оценки нет» с именем функции, а не ноль.
- **Действия с миром** (`процесс`, порядки ввода-вывода) не предсказываются:
  их время зависит от мира. Печатается их **число** по видам —
  `действий с миром: «Прочитать файл» ≤ 2·н` — и время к цене не прибавляется.

Анализатор написан на flang и для скорости печатается в C (`flang emit
--target c`); напечатанный анализатор держится в `$FLANG_TMP` по отпечатку
исходников и пересобирается, когда исходник меняется.

## 3. Выведено и оценено — разные слова

- **выведено** — граница следует из таблицы §1 и правил §2 без допущений.
  Она ещё не переиграна проверяющей программой: запись доказательства границы
  не содержит (задача 1408). Поэтому строка вывода говорит «выведена из
  устройства функции; проверяющей программой не переиграна», а не «доказана».
- **ОЦЕНЕНО** — в выводе есть допущение (мера убывает на 1), оно напечатано
  рядом.
- **оценки нет: <причина>** — числа нет; нулём оно не заменяется (ADR-0033 §5.4).

Обещание цены проверяется: `--promise 'многочлен'` отказывает кодом 1, если
обещанный многочлен не покрывает выведенный.

## 4. Перевод в секунды и байты: калибровка машины

Профиль машины — текстовый файл `scripts/cost/profiles/<машина>.profile`,
снимается планом `Calibrate` (`bootstrap/flang run-script cost:calibrate`).
План гоняет функции `scripts/cost/calibration.flang` (вызовы, строки, списки)
на нескольких размерах обоими путями — толкователем и напечатанным C — и
делит приращения времени и памяти на приращения счётчиков. Получаются:

| ключ | смысл |
|---|---|
| `interpreter.step.low/high` | секунд на шаг толкователя: нижняя и верхняя из снятых |
| `interpreter.charge.low/high` | секунд на единицу длины, которую шаги не объяснили |
| `interpreter.byte` | байт пика памяти толкователя на байт оценки памяти |
| `c.step.low/high`, `c.charge.low/high` | то же для напечатанного C |
| `c.byte` | байт арены на байт оценки памяти |
| `machine`, `cores`, `load` | имя машины, ядра, загрузка в момент снятия |

Секунды печатаются **отрезком** (по нижней и верхней постоянной) и всегда с
именем машины и загрузкой, при которой профиль снят (ADR-0033 §2.4: одно
число без машины было бы ложью). Профиль чужой машины к этой не применяется:
его снимают там, где будет работать программа.

## 5. Что исключено и почему

- **Граница времени в худшем случае с учётом кэшей, предсказателя переходов,
  прерываний и соседей по машине (WCET).** Шаги считаются точно, а секунда на
  шаг — нет: она зависит от того, что в кэше, от частоты ядра и от того, кто
  ещё занимает машину. Калибровка даёт отрезок, снятый при названной загрузке;
  за его пределы при другой загрузке время выйти может. Строгая граница
  требовала бы модели процессора и квалифицированного инструмента (ADR-0033 §7)
  и под нашей проверкой не переигрывается.
- **Шум операционной системы и сборки мусора.** Паузы планировщика, подкачка,
  старт процесса не входят в многочлен; старт толкователя (разбор и проверка
  программы) измеряется отдельно и в цену функции не входит.
- **Время действий с миром.** Сеть, диск и ожидание не предсказываются; число
  действий — да (§2).
- **Логарифмические границы.** Многочлен не выражает `log n`: двоичный поиск
  получает линейную границу, и она верна, но груба (§6).
- **Память толкователя — оценка, не граница.** Шаги ограничены сверху; память
  переводится по профилю из оценки байтов и помечена «≈».

## 6. Сверка: предсказано и измерено

План `Validate` (`bootstrap/flang run-script cost:validate`) берёт 21 функцию
`scripts/cost/validation.flang` — списки, строки, числа, множества, словари и
обработчик HTTP-запроса из `docs/examples/web/orders-api.flang` — и на
нескольких размерах сравнивает границу со счётчиком прогона, толкователем и
напечатанным C. «Раз» — граница, делённая на измеренное; держит — граница не
меньше измеренного.

  байты меток анализатор оценивает с запасом. Граница от размера самого запроса

| н | байт запроса | шагов: измерено | граница `116·B^3 + 1659·B^2 + 5086·B + 7112` | раз |
|---|---|---|---|---|
| 0 | 21 | 2 609 | 1 919 813 | 736 |
| 20 | 132 | 595 213 | 296 381 168 | 498 |
| 80 | 492 | 23 681 043 | 14 219 170 208 | 600 |

  словарь на каждой записи, и измеренный рост между н = 40 и н = 80 — в 6,8
  раза, почти куб. Запас в сотни раз — от размера: граница обязана допустить
  запрос из пар по одному байту, а в замере пара занимает шесть байт.
- **Напечатанный C.** Граница держит везде, но грубее: длина при `добавить`
  заряжается по худшему пути копирования, и у списков граница квадратна при
  линейном прогоне (`Reverse list` — в 2 112 раз).
- **Время.** Измеренное время толкователя не выше верхнего конца отрезка у 20
  функций из 21. Исключение — `Unique list`: 10,6 с при отрезке 1,1–9,9 с;
  заряды длиной у толкователя дороже, чем сняла калибровка. Где граница шагов
  груба, груб и отрезок. Секунды — прогноз по профилю, не граница.
- **Память.** Память толкователя переводится из шагов по профилю. Где каждый
  шаг держит ячейку списка до конца прогона, прогноз близок и ошибается в обе
  стороны до 7 % (`Reverse list` 387 МиБ измерено против 361 предсказанных,
  `Index in list` 489 против 506, `Reverse letters` 357 против 344); где шаги
  памяти не держат, прогноз завышен до сотен раз (`Numbers up to` 9,5 МиБ
  против 2 272). Память — прогноз, не граница, и помечена «≈».

## 7. Подлог

План `Forgery` (`bootstrap/flang run-script cost:forgery`) проверяет, что
занижение ловится с обеих сторон:

1. обещание `18·н + 9` для «Calls» (выведено `19·н + 20`) — отказ, код 1;
2. обещание `19·н + 20` — принято, код 0;
3. прогон «Calls» при н = 1000 с `--max-steps 19021` (граница) — проходит, код 0;
4. тот же прогон с `--max-steps 18009` (меньше граница) — обрыв, код 1.

Ответ плана: «подлог пойман: коды 1 0 0 1». Любой другой набор кодов — провал
`FLANG_COST_FORGERY`.

## 8. Что мы теряем

- Граница переигрывается сверкой с прогоном, а не проверяющей программой.
  Пока 1408 не сделана, аудитору предъявить можно таблицу §6, но не запись.
- Граница груба там, где размер входа описан хуже, чем работа: у обработчика
  запроса работа идёт по парам `ключ=значение`, а размер известен в байтах;
  каждая пара может быть в один байт, и граница обязана это допустить.
- Две таблицы цены (толкователь и C) нужно держать вместе с рантаймом: правка
  `interpret.flang` или `fl_charge` без правки `bound.flang` делает границу
  неверной. Сверка §6 это ловит, если её прогонять.

## 9. Как проверить, что решение исполнено

1. `bootstrap/flang run-script cost:forgery` — «подлог пойман: коды 1 0 0 1».
2. `bootstrap/flang run-script cost:validate` — в столбцах «держит» нет «нет».
3. `bootstrap/flang run-script cost <файл> --function <имя> --sizes … --profile …`
   печатает границу шагов, секунды отрезком с машиной и загрузкой, память и
   число действий с миром.

## 10. Где не уверен

- Таблица цены выписана по `interpret.flang` руками; сверка подтверждает её на
  21 функции, но не доказывает для каждого узла.
- Профиль снят на машине, где кроме нас работают другие; верхняя и нижняя
  постоянные разнятся, и отрезок секунд от этого шире.
- Команды `flang cost` в двоичном нет: цена печатается планом из
  `scripts/cost/`. Перенос в `flang/self/cli.flang` едет партией перепечатки.
