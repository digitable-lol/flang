# ADR-0090. Помощник ввезённой функции связывается в её модуле, а тёзка из другого файла — отказ связывания, не перекрытие

**Состояние:** предложено. Принимает владелец.
**Дата:** 11 октября 2026.
**Основание:** заявки 349 (P0: гарантия, доказанная в модуле, ложна в
собранной программе) и 350 (место беды связывания не называет файл) и обещание
`docs/guide/project-layout.ru.md`, раздел 4: совпадение имён — ошибка
`FLANG_DUPLICATE_NAME`, а не перекрытие.
**Замер:** ветка `a/an-imported-function-keeps-its-own-helper` от `dev`
`1149c78f7`, двоичный `bootstrap/flang` 0.7.25 из этого же дерева; правленое
связывание гонялось толкователем из исходника (`flang/self/link.flang`
ввезён в программу-гарнитуру, `bootstrap/flang run … --на-веру`), потому что
семя с правкой не перепечатано. Числа сняты 11 октября 2026.
**Рядом:** задача 1113 — два ввоза одного модуля с разными списками `только`
(та же область имён, соседняя дыра); задачи 9697 и 2761 — заведены этой же
работой.
**Новые задачи:** 9697, 2761.

---

## 1. Задача

Связывание сливает объявления всех файлов в одну плоскую таблицу имён, а
список `только` сужает, что из файла в неё попадёт. Помощник, которого ввозящий
не перечислил, в таблицу не попадает — так и задумано, об этом говорит раздел 7
руководства по раскладке: `только` перечисляет имена, а не замыкание. Вызов
такого помощника внутри ввезённой функции честно отказывался
`FLANG_UNKNOWN_NAME`.

Дыра была в другом случае. Если имя помощника приносит кто-то ещё — другой
модуль или сам ввозящий файл, — вызов внутри ввезённой функции молча связывался
с ним. Программа заявки:

```
-- step-v.flang: модуль «В», тотальная функция «Шаг» → "в"
-- step-g.flang: модуль «Г», «Шаг» → "г";
--               «Через шаг Г» обеспечивает результат равен "г", тело — «Шаг»
-- probe.flang:  использует «В» только «Шаг»; использует «Г» только «Через шаг Г»
```

`flang check step-g.flang --proof --strict` — гарантия «через шаг Г — г»
доказана, код 0. `flang check probe.flang` — «замечаний нет», код 0. А
`flang run probe.flang --function «Через Г» --на-веру` падает на
`FLANG_PROPERTY: нарушено свойство «через шаг Г — г»`: «Шаг» внутри тела
функции модуля «Г» связался с «Шагом» модуля «В». Приговор о собранной
программе лгал — P0 по `docs/zero-bug-policy.md`. То же при собственной
функции «Шаг» во входном файле; напечатанный C делал то же, что и толкователь,
потому что оба читают одну связанную программу.

Второй порок, из заявки 350: беда связывания несла строку и столбец, но не
файл. При трёх файлах «строка 3, столбец 1» без имени файла — место, по
которому человек идёт править не тот файл.

## 2. Решение

1. **Имя внутри тела ввезённой функции значит то, что значило в её модуле.**
   После второго прохода связывание смотрит на каждый файл, у которого есть
   скрытые объявления (имя объявлено в файле, но спрятано его `экспортирует`
   или чужим `только`), и на каждую связанную функцию из этого файла: если она
   зовёт скрытое имя, а в собранной программе под этим именем стоит функция
   другого файла, — отказ `FLANG_DUPLICATE_NAME` с обоими файлами и именем
   ввезённой функции, которая зовёт тёзку. Если под именем никого нет — всё как
   прежде, `FLANG_UNKNOWN_NAME`. Плоская таблица имён остаётся: лексическая
   область модуля не вводится, а охраняется отказом. В плоской таблице это одно
   и то же: либо имя разрешается в своём модуле (другого кандидата нет), либо
   программа не собирается.
2. **Место беды связывания называет файл.** Все беды связывания, привязанные к
   узлу (`«Беда узла»` в `flang/self/link.flang`), начинают сообщение словами
   `в файле <путь>:`. Запись `«Место»` не меняется — у неё 45 построений в
   одном `types.flang`, и правка её формы разошлась бы по всем печатникам и
   языковому серверу ради одного поля.
3. Отказ написан так, чтобы человек знал, что делать: вписать помощника в
   `только` либо переименовать одну из функций.

Чего решение НЕ делает: не дотягивает помощников в программу само (это
изменило бы документированный смысл `только` и перенесло бы `FLANG_DUPLICATE_NAME`
на честные программы, которые сужением как раз и разводят тёзок) и не вводит
квалифицированные имена (`docs/modularity-and-packages.md` называет цену —
парсер, связывание, восемь печатников).

## 3. Что это ломает и замер по корпусу

Меняется приговор ровно для программ, где скрытый тёзка уже перехвачен: они
собирались и теперь отказаны. Честные программы, у которых скрытое имя никто
из связанных функций того же файла не зовёт, собираются как прежде.

Замер на дереве (прибор — `scan.py` в журнале работы: замыкание ввозов по
`использует … из "…"` и по имени в каталоге файла, выше и в `flang/stdlib`;
тёзка считается перехваченным, если скрыт всеми ввозами файла и его зовёт
видимая функция того же файла):

| что | число |
|---|---|
| программ с `использует` в дереве (`.flang` и `.fscript`) | 348 |
| из них в замыкании одно имя функции объявлено в двух файлах | 48 |
| из них перехват по правилу выше | 1 |

Единственный перехват — `scripts/seed/seed-refresh.fscript`: он объявлял
свою `«Root»` и ввозил `«Openings»`/`«Positions»` из
`seed-runtime-is-source.fscript`, где их `«Root»` спрятана списком `только`.
Обе возвращали `"../.."`, поэтому ложь была без последствий; теперь `«Root»`
вписана в `только`, своя удалена, сторож отвечает тем же. Семь оставшихся
групп тёзок (`«Шаг начала»` в TLS, `«Цифры»`, `«Ограничить»`,
`«Шаг уникальных»`, …) ни одна связанная функция их файлов не зовёт — отказ на
них не встаёт.

Прогон правленого связывания толкователем на программах заявок:

| программа | до (семя 0.7.25) | после (связывание из исходника) |
|---|---|---|
| `probe.flang` (349) | бед 0 | `FLANG_DUPLICATE_NAME, строка 7, столбец 1: в файле …/step-g.flang: функция «Шаг» объявлена в двух модулях: …/step-v.flang и …/step-g.flang; из второго ввезена не она, а «Через шаг Г», которая её зовёт — …` |
| `own-step.flang` (своя «Шаг») | бед 0 | тот же отказ, второй файл — `own-step.flang` |
| `honest.flang` («Г» целиком) | бед 0 | бед 0 |
| `hidden-unused.flang` (тёзка скрыт, никем не зовётся) | бед 0 | бед 0 |
| `both.flang` (350) | `FLANG_DUPLICATE_NAME, строка 3, столбец 1: функция «Имя пары» …` | `… строка 3, столбец 1: в файле …/pairs-b.flang: функция «Имя пары» …` |

Проверка самого `flang/self/link.flang` семенем: «проверено — разбор, типы,
завершаемость, ядро и примеры; замечаний нет».

Проба `flang/proof/probes/import-helper-binding/` держит эти программы
контрактом (20 строк); на семени 0.7.25 расходятся ровно 11 строк — те, что
стоят на правке. Шаг `binary.yml` «Check imported helpers bind in their own
module» красен до перепечатки семени, и это названо в его комментарии.

Цена: лишний проход по телам функций только у файлов со скрытыми именами
(«Имена узла» уже ходит по тем же телам при отбрасывании недостижимого);
у программ без ввозов и без `только`/`экспортирует` работы не прибавляется.

## 4. Открытое

- Раннее предупреждение о тёзке при проверке самого модуля (просьба 350,
  пункт 1) — задача 9697: нужен список соседей от оболочки двоичного.
- `--на-веру` снимает и отказ связывания — задача 2761.
- Та же дыра у типов: `только` прячет и типы, а тип в сигнатуре ввезённой
  функции может прийти из другого файла. Правило этого ADR написано для
  функций; типы — следующим шагом по той же схеме («Слить тип» и
  «откуда типов» уже ведут учёт).
