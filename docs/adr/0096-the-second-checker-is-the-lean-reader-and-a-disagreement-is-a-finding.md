## 1. Задача

Запись доказательства (`flang check … --proof --record`) переигрывает одна программа —
сверщик на C `flang/proof/checker/checker.c`. Её пробы написаны вместе с ней; строку
записи, которую она читает не так, как требует описание формата, заметить некому. Задача
1313 просит вторую реализацию, которая читает тот же текст записи, выносит вердикт по всем
её блокам и не делит с первой ни языка, ни средства сборки, ни кода, — и сверку вердиктов
двух реализаций на всём корпусе записей.

В дереве было два кандидата:

- `flang/proof/checker.flang` — 1831 строка на flang: отпечатки, чтение шапки и привязки.
  Собирается и исполняется тем самым компилятором, чьи доказательства проверяет, —
  общая точка отказа с ядром. Второй реализацией по условию задачи не считается.
- `flang/proof/lean/RecordReader.lean` — до 7 октября 2026 читал только блоки «вывод» и
  сличал по ним вердикт приёмки (`flang/proof/lean/run.fscript`); остальные блоки записи
  не судил.

## 2. Решение

Путь — довести Lean-читатель до вердикта по всей записи; третьего пути не изобретается.
Решение ADR-0076 от 7 октября уже выбрало Lean, и к 8 октября в дереве лежит
`flang/proof/checker/second/` — одиннадцать модулей (`Checker`, `Totality`, `Moves`,
`Evaluator`, `Body`, `Node`, `Premises`, `Theorem`, `Sections`, `Source`, `Terms`), которые
судят привязку, полноту, блоки утверждений, тотальности, теорему исходника, снятия и план.
Собирает их `make -C flang/proof/checker second` своим набором (`lean -c`, `leanc`) без
`bootstrap/flang`. Сличает обе реализации план `flang/proof/second-checker.fscript`.

Этот документ фиксирует, что к решению ADR-0076 добавлено и что показал первый замер на
корпусе:

- **Подлог обоим.** К планам `Crosscheck` (честные записи обеим) и `Forgery` (испорченная
  копия — только второй, ждётся ровно одно названное расхождение) добавлен план
  `Forgery both` (`checker:second-both`): та же испорченная копия подаётся ОБЕИМ, и план
  зелен только когда обе ответили кодом 1 и ни одна честная запись не разошлась.
- **Расхождение — находка.** План не правится под ответ и реализации не правятся друг под
  друга: каждое расхождение печатается строкой с кодами обеих и роняет прогон.
- **Работа на каждом пуше.** Работа `second-checker` в `.github/workflows/binary.yml` рядом
  с `proof-checker`; расписание `lean-crosscheck.yml` остаётся.

## 3. Что считается независимостью

| сторона | сверщик на C | второй сверщик |
|---|---|---|
| язык | C99 | Lean 4 |
| средство сборки | один `cc` | `lean -c` + `leanc`, версия прибита `lean-toolchain` |
| откуда формат записи | чтение `checker.c` | `docs/flang/proof/record-format.md` — описание, написанное по печати `flang/self/proof-record.flang` |
| приёмка блока «вывод» | список `шаг_вывода` в `checker.c` | `flang/proof/lean/Acceptance.lean` с теоремой «состоятельность» |
| общие таблицы на входе | нет: `ПРАВИЛА[]` зашит в `checker.c` | нет: таблиц `.tsv` второй не читает (`grep -l '\.tsv' second/*.lean` — пусто) |
| автор кода | написан под задачи владельца разными линиями | написан под ADR-0076 другой линией; «другой автор» не доказуем — обе линии ведёт один владелец |

**Что остаётся общим и названо общей точкой отказа:** сам текст записи и исходник; правила
«что проверять по существу, а что брать на слово ядра» — они описаны в
`docs/flang/proof/checker/README.md` и уточнялись по поведению первой на наборе проб
(ADR-0076, раздел 5). Ошибку, общую для этих правил, вторая реализация не заметит. Общая
ошибка описания формата, если печать и описание врут одинаково, тоже не ловится — против
неё стоит только привязка записи к исходнику.

## 4. Замер на корпусе

Корпус — все `*.record` под `flang/proof/checker/tests` и `flang/proof/forgeries` на `dev`
`8897f2350`. Команда и числа (11 октября 2026, двоичные с дерева `77cdc709b`):

```
$ bootstrap/flang run-script checker:second

второй не взялся целиком 0
```

| без исходника — не сличает ни одна | 52 | строка `исходник` указывает в `/srv/tmp/dokazuemyy/…` (клоны и подделки фальсификатора Ч71, Ч365, Ч76, Ч87); файла в дереве нет |

| записей, за которые вторая не взялась целиком (код 4) | 0 | строка «не взялся целиком» |

Все семь — следствие одного дня: 11 октября 2026 `checker.c` получил десять коммитов
приёмов (`425b8a103` … `77cdc709b`: разбор цели по условию, счёт длин, вычислитель,
переписка, свидетель), а `second/*.lean` между `9f0181997` и `dev` не менялся. На корпусе
8 октября (задача 1313, 624 записи) расхождений было 0. Это и есть то, ради чего вторая
реализация заведена: отставание второго мнения измерено, а не оговорено. Отдельная
находка в самом отставании: на незнакомое правило вторая отвечает кодом 1 «НЕ СОШЛОСЬ», а
не кодом 4 «НЕ ВЗЯЛСЯ ЦЕЛИКОМ», как обещает ADR-0076, раздел 3, — незнакомое принимается
за ложное.

## 5. Встречные примеры

- **Подлог только второй** (`checker:second-forgery`): в копии честной
  `families/type-families/families.record` строка `знаков N` заменена на `знаков 1N`.
  Прогон 11 октября: строка `РАСХОЖДЕНИЕ … families.record: сверщик на C — 0, второй — 1`
  напечатана; план красен словом «РАЗОШЛОСЬ» — из-за семи расхождений честных записей, а не
  потому, что подлог не назван (до этой правки план печатал «подлог не назван» и в этом
  случае; теперь слова различены).
- **Подлог обоим** (`checker:second-both`): та же копия обеим — строка `codes.tsv`
  `1	1	…families.record`: отвергли обе, одним кодом. План красен тем же «РАЗОШЛОСЬ».
- **Подделки корпуса:** 250 записей, которые обе отвергли кодом 1, из них 181 названы
  подделкой в имени файла (`poddelka-`, `forgery-`, `forged/`).
- **Отрицательный контроль плана:** семь расхождений выше — живое доказательство, что
  сличение не зеленеет само; пробы функции «Judged» в `second-checker.fscript` держат
  случаи «подлог не назван», «подлог принят одним», «не взялся целиком».

## 6. Что не сделано

- **Расхождений не 0.** Критерий задачи 1313 «расхождений 0, код 0» на `dev` не выполнен:
  семь записей раздела 4. Закрывать их — работа второй реализации по описанию формата (новые
  строки записи: род правила переписки, свидетель ядра; узел «разбор цели по условию»), а не
  правка плана. Задача 1313 остаётся открытой с этим следующим шагом.
- **Lean на `dev` не собирается.** `flang/proof/lean/Rules.lean:3081`
  (`theorem «равен-на-не-числе» : «равен» «неЧисло» «неЧисло» = false := rfl`, коммит
  `fb7553c77`, в `main` и `dev` с 11 октября 11:21 UTC) противоречит модели: в
  `Model.lean` `«равен» x y := decide (x = y)`, и `#eval «равен» «неЧисло» «неЧисло»` даёт
  `true`. Из-за этого `make -C flang/proof/checker second`, `flang/proof/lean/run.fscript`
  и новая работа `second-checker` на `dev` красны, пока строка не исправлена линией ADR-0084.
  Поэтому двоичные замера собраны на `77cdc709b`.
- **52 записи без исходника** не сличает ни одна реализация: их исходники жили во временных
  клонах фальсификатора. Либо записи переснимаются на исходники дерева, либо уходят из
  корпуса сличения; решение не принято.
- Ключей `--набор`, `--зависимость` у второй нет (ADR-0076, раздел 5): пробы
  `probes.tsv`, которые их подают, сличаются только первой.
- Lake-проекта у `flang/proof/lean` нет (`lakefile` отсутствует), сборка — прямым `lean`;
  `lake build` к дереву неприменим.

## Что замерено и что отвергнуто

**Отвергнуто.** Сличитель на flang (`flang/proof/checker.flang`) как вторая реализация —
делит с ядром компилятор и ловушку Томпсона не ловит. Правка второй реализации «под C» в
день замера — превратила бы прибор в эхо первой; расхождения оставлены в таблице. Снятие
красного плана условием «считать 3 и 0 согласием» — отвергнуто: код 3 значит «взято на
слово», и разница 0/3 — ровно то, что ADR-0073 велит называть отдельно. Работа только по
расписанию — отвергнута замером: сборка 3 мин 20 с и три плана по минуте укладываются в
работу на каждый пуш рядом с `proof-checker`.
