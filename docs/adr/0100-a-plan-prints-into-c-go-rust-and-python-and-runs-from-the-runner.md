# ADR-0100. План печатается в C, Go, Rust и Python и исполняется прогонщиком цели

**Состояние:** предложено. Принимает владелец.
**Дата:** 12 октября 2026.
**Основание:** пункт раздела «Ограничения» в `docs/DESCRIPTION.md` — «`план`
генерируется только для `js` и `ts`, процессы — для `c`, `elixir`, `js` и `ts`»;
задача 8589 (цель «c» не печатает план).
**Замер:** ветка `a/plans-and-processes-print-into-more-targets` от `dev`
`973a31f3e`, двоичный `bootstrap/flang` 0.7.25 из этого же дерева. Правленую
печать гонял толкователь компилятора из исходника (гарнитура вне дерева, по
образцу `flang/self/bootstrap/emit-from-source.flang`), потому что семя с
правкой не перепечатано. Числа сняты 12 октября 2026.
**Рядом:** [ADR-0081](0081-printed-code-follows-the-canon-of-its-target.md) —
канон напечатанного кода цели; задача 8589.

---

## 1. Задача

Программа с объявлением `план` печаталась в две цели из десяти — `js` и `ts`.
Восемь остальных отказывали `FLANG_PLAN_UNSUPPORTED` кодом 1 и не писали ни
файла. Прогон на семени 0.7.25:

```
$ bootstrap/flang emit docs/examples/wal/append-plan.flang --target <цель> --out d
c, cpp, csharp, elixir, go, java, python, rust   код 1, FLANG_PLAN_UNSUPPORTED
js, ts                                            код 0
```

Текст отказа к тому же называл печатающей одну цель «js», хотя печатала и «ts».

Процессы (`процесс`, `надзор`, `прогон`) печатаются в `c`, `elixir`, `js`, `ts`;
`cpp`, `csharp`, `go`, `java`, `python`, `rust` отвечают «у цели «…» нет
планировщика конкурентности», код 1. Эта половина пункта здесь не решается —
см. раздел 6.

## 2. Решение

Исполнять план — работа прогонщика цели, а не модуля. Модуль программы у всех
десяти целей уже печатает вызов функции по исходному имени flang (`call` у
Python, `Call` у Go, `call` у Rust, `<префикс>_call` у C). Значит прогонщику
достаточно знать три имени на план — имя плана, функцию начального состояния и
функцию шага, — и цикл «шаг → поручение → отклик» пишется один раз на цель в её
рантайме, а печать на flang только кладёт таблицу имён.

1. **Таблица планов печатается ТОЛЬКО у программы с планом**, поэтому вывод
   программы без плана не меняется ни на байт:
   - `c` — строка `#define FL_PROGRAM_IO_PLANS {{"имя", "начало", "шаг"}, …}`
     перед `flang_cli.c` (рядом с `FL_PROGRAM_CALL`);
   - `go` — файл `flang/plans.go`, который в `init` заполняет `rt.Plans`;
   - `rust` — константа `PLANS` в модуле программы и `main.rs`, зовущий
     `cli::main_with_plans(program::PLANS)`;
   - `python` — список `PLANS` в модуле и файл `flang_io.py` рядом (исполнитель,
     лежавший в дереве с 6 сентября 2026 без печати; поле «исходник
     исполнителя» таблица целей двоичного уже подавала).
2. **Исполнитель** — порт `flang/src/emit/js/flang_io.js`: тот же предел 10 000
   поручений, те же ворота словаря (поручение не из 25 родов до хозяина не
   доходит), те же исходы и коды возврата, что у `flang io`: 0 — «Конец работы»,
   1 — «Провал» (план сдался сам), 3 — «Не проверено» и сломанный инструмент.
   Шаг зовётся в свежем контексте: пределы шагов и глубины — на одно обращение
   плана. У C все значения плана живут в одной арене на прогон: состояние
   переходит из шага в шаг.
3. **Хозяин** исполняет девять родов из 25: «Прочитать файл», «Записать файл»,
   «Прочитать октеты из файла», «Записать октеты в файл», «Перечислить каталог»,
   «Удалить файл», «Завести временный каталог», «Прочитать переменную среды»,
   «Прочитать доводы». Экранным трём — «Сбой» `FLANG_IO_NO_SCREEN`, остальным
   тринадцати (сеть, процессы, часы, кости) — «Сбой» `FLANG_IO_NOT_WIRED` с
   именем рода и советом исполнить план двоичным. Пути — от каталога запуска.
4. **Запуск** — тем же прогонщиком: `flang_cli --plan <имя> [довод…]` (у Python
   `python3 flang_cli.py <модуль> --plan <имя> [довод…]`); пустое имя —
   единственный план. Итог печатается так же, как поле итога у `flang io`:
   `{"result":…,"orders":N}`; беда — `{"error":…,"code":…}` в поток ошибок.
5. `flang/self/bootstrap/compiler.flang`: «Отказ по плану» больше не зовут цели
   `c`, `go`, `rust`, `python`; его текст называет шесть печатающих целей.

## 3. Сужения

- Хозяин целей не знает ключей `flang io` (`--in-dir`, `--no-write`, `--seed`…):
  права у него полные, пути не заперты в каталог. Это то же, что у
  `flang_host_node.js` по умолчанию.
- Сверки типов значений на входе шага нет — та же оговорка, что в
  `flang_io.py` и `flang_io.js`: проверяется форма («Продолжение»,
  «Поручение», «Отклик»), а не типы полей.
- C открывает POSIX (`_POSIX_C_SOURCE 200809L`, `opendir`, `mkdtemp`) только
  у программы с планом; обещание переносимого C99 у остальных не тронуто.

## 4. Замер

Проба `flang/proof/probes/plans-in-targets/` — три программы, каждая через
`flang io` и через прогонщики шести целей (21 строка `expected.tsv`):
`round-trip.flang` (каталог, запись, чтение, перечень, удаление файла и
каталога, повторное чтение до «Сбоя», среда, доводы — 9 поручений),
`gives-up.flang` («Провал» кодом 1), `octets.flang` (октеты туда и обратно).

| что | семя 0.7.25 | после правки |
|---|---|---|
| строк пробы | 21 | 21 |
| сошлось | 9 (io, js, ts на трёх программах) | 21 (раздел 4.1) |
| `flang emit … --target c\|go\|rust\|python` на программе с планом | код 1, `FLANG_PLAN_UNSUPPORTED` | код 0 |

Итог `round-trip.flang` у `flang io` и у прогонщиков c, go, rust, python, js,
ts один и тот же:
`{"result":"записано 17; прочитано «привет, план — ёж»; имена note.txt; повтор — FLANG_IO_READ; среды нет; доводов 2","orders":9}`.
`octets.flang` у js и ts кончается «Провалом» `FLANG_PROBE_OCTETS`: хозяин
Node октетов не заводит (`FLANG_IO_NOT_WIRED`), и строка пробы держит это
кодом 1, а не прячет.

### 4.1. Как получен вывод «после правки»

Три программы набора напечатал в c, go, rust и python компилятор из
исходника: гарнитура-план, ввозящая «Compiler flang» и зовущая «Напечатать
связанное», «…в Go», «…в Rust», «…в Python» с рантаймами из дерева, прогнана
`bootstrap/flang io … --trust` (два прогона, около полутора часов каждый,
до 50 ГиБ памяти). Её вывод подан пробе переменной `PLANS_EMITTED_DIR`:
`bootstrap/flang io run.fscript` — «проб 21, разошлось 0». Сборка: `make` с
`-std=c99 -Wall -Wextra -Werror -pedantic` для C, `go build` (и `go vet`,
`gofmt -l` — пусто) для Go, `cargo build` для Rust, `python3 -B` для Python.

Напечатанные таблицы — ровно те, что описаны в разделе 2, например у Go:
`{Name: "Октеты туда и обратно", Initial: "Начать октеты", Step: "Дальше по октетам"},`
в `flang/plans.go`, у C — `#define FL_PROGRAM_IO_PLANS {{"Октеты туда и обратно", "Начать октеты", "Дальше по октетам"}}`.

Правленые печатники проверены семенем: `bootstrap/flang check
flang/self/emit-python.flang`, `…/emit-go.flang`, `…/emit-rust.flang` —
«проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет».
Замыкание `bootstrap/flang check flang/self/bootstrap/compiler.flang
--предел-шагов 100000000000`: строк FLANG_TYPE и FLANG_DUPLICATE_NAME — 0,
упор в предел шагов («Искать признак», FLANG_RECURSION_LIMIT).

## 5. Встречные примеры и отрицательный контроль

- Испорченный хозяин: в напечатанном `flang_io.py` «Записано» считает октеты
  вместо кодовых точек — проба отвечает «проб 21, разошлось 1», строка
  `round-trip.flang [python]` с выводом «записано 31».
- Семя до правки: «проб 21, разошлось 12» — c, go, rust, python на трёх
  программах отвечают `FLANG_PLAN_UNSUPPORTED`.
- Хозяин Node октетов не заводит: строки `octets.flang [js]` и `[ts]` ждут
  «Провал» `FLANG_PROBE_OCTETS` кодом 1 — граница записана, а не спрятана.

## 6. Что не сделано

- **Процессы в `go`, `python`, `rust`** — не начаты. Нужен планировщик в
  рантайме цели (у JS это `flang_conc.js`, 678 строк; у Elixir
  `flang_conc.ex`, 1 120) и печать объявлений процессов данными. Задача
  заведена.
- **План в `cpp`, `csharp`, `java`, `elixir`** — отказ `FLANG_PLAN_UNSUPPORTED`
  остаётся. У `cpp` рантайм тот же, что у `c`, и прогонщик тот же `flang_cli.c`;
  не сделана только печать таблицы в `emit-cpp.flang`.
- Хозяину целей не хватает 16 родов из 25 (сеть, процессы, часы, кости, экран).
- **Перепечатка семени.** До неё `bootstrap/flang emit` печатает по-старому, и
  двенадцать строк пробы (c, go, rust, python на трёх программах) красны на
  семени; это и есть снимаемое ограничение. Шаг `binary.yml` «Check plans run
  in the print targets» красен до перепечатки.
- Каноны ADR-0081 для C (clang-format) и Python (black) на этой машине не
  мерены — инструментов нет. Код C стоит под `#ifdef FL_PROGRAM_IO_PLANS`, и
  программы корпуса его не включают; rustfmt-разность `flang_cli.rs` осталась
  45 строк, clippy — 28 замечаний на напечатанной программе до и после.
