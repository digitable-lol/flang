# ADR-0101. Двоичный хозяин говорит по TLS клиентом на языке, напечатанным в него, и умеет датаграммы

**Состояние:** предложено. Принимает владелец.
**Дата:** 12 октября 2026.
**Основание:** `flang/src/emit/c/flang_repl.c` (`io_https`, `io_datagram_on`,
поручения «Отправить датаграмму» и «Принять датаграмму», ключ `--trust-roots`),
`flang/stdlib/tls-client.flang` («Запрос по полёту октетами», «Ответ сервера
октетами»), `flang/self/parser.flang` (словарь: поручений 25 → 27, откликов
22 → 23), `scripts/bootstrap-reprint.sh` (вторая печать — клиент TLS),
`flang/proof/probes/network/`.
**Рядом:** [ADR-0007](0007-encryption-by-request-to-an-external-host.md) —
прежнее решение отдать `https` curl; [ADR-0078](0078-tls-1-3-is-assembled-in-the-language-and-runs-printed.md) —
клиент TLS 1.3 на языке и условие пересмотра (§7.3: «когда счёт и соединение
живут в одном процессе»); [ADR-0077](0077-the-host-hands-out-octets-from-the-system-random-source.md) —

## 1. Задача

Пункт «Ограничений» в `docs/DESCRIPTION.md`: «Запросы `https` рантайм `flang io`
выполняет внешней программой `curl`. Своей реализации TLS у него нет, «Открыть
соединение» — TCP без шифрования, UDP нет.»

Воспроизведено 12 октября 2026 двоичным из `bootstrap/` (дерево `973a31f3e`),
план из одного «Запросить» по `https://localhost:1/`:

```
$ bootstrap/flang io https-get.flang --на-веру -- https://localhost:1/
{"error":"curl: (7) Failed to connect to localhost:1 after 0 ms: Could not connect to server", … "code":"FLANG_IO_NET" …}
$ PATH=<каталог без curl> bootstrap/flang io https-get.flang --на-веру -- https://localhost:1/
{"error":"своего шифрования у двоичного хозяина нет, а внешней программы «curl» на машине не нашлось …", … "code":"FLANG_IO_NO_TLS" …}
```

План с вариантом «Отправить датаграмму» тем же двоичным: `FLANG_UNKNOWN_NAME:
неизвестный вариант «Отправить датаграмму»`, код 3. Пункт настоящий во всех трёх
частях.

ADR-0078 оставил `https` за curl по трём доводам: толкователь считает X25519
158,7 с, а узел ждёт Finished около 9 с; напечатанный двигатель живёт отдельным
процессом; хозяин держать его внутри себя не умеет. Третий довод снимается
печатью, первые два — следствия третьего.

## 2. Решение

1. **«Запросить» по `https` исполняет клиент TLS на языке, собранный в сам
   двоичный.** Перепечатка семени печатает `flang/stdlib/tls-client.flang` в C
   второй печатью и кладёт `tls_client.c` и `tls_client.h` в `bootstrap/` рядом
   с напечатанным компилятором. `flang_repl.c` включает их одной единицей
   трансляции (`#include "tls_client.c"` под `__has_include`), поэтому
   напечатанный `Makefile` и `flang/self/emit-c.flang` не меняются. Все имена
   двигателя несут приставку `tls_client_`, с именами `compiler_flang_` они не
   встречаются; сборка прошла с `-std=c99 -Wall -Wextra -Werror -pedantic`.
2. **Хозяин — только трубы.** Адрес, TCP (`io_connect_to`, тот же, что у
   «Открыть соединение»), 64 октета из `/dev/urandom` (32 на скаляр X25519, 32
   на случайное ClientHello), часы, связка корней. Счёт — четыре вызова
   двигателя: «Привет клиента шестнадцатеричным», «Финиш словом», «Запрос по
   полёту октетами», «Ответ сервера октетами». Первые два — те же, что у
   `docs/examples/https/https-get.flang`; два последних добавлены в
   `tls-client.flang`: они везут произвольные октеты запроса и отдают ответ
   целиком, а не первую строку.
3. **Запрос уходит после проверки.** Finished клиента — до цепочки (так узел не
   рвёт связь, ADR-0078 §2.2), данные приложения — только после цепочки, срока,
   имени и CertificateVerify.
4. **Корни доверия — ключ `--trust-roots <файл PEM>`**, без него — первая
   найденная системная связка (`/etc/ssl/certs/ca-certificates.crt`,
   `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/ssl/cert.pem`). Переменной среды
   нет: подмена доверия обязана стоять в самой команде. Выключить проверку
   нечем.
5. **Отказы.** Беда сертификата (`FLANG_TLS_CHAIN`, `FLANG_TLS_EXPIRED`,
   `FLANG_TLS_NAME`, `FLANG_TLS_SIGNATURE`) — `FLANG_IO_TLS_CERT`, прочая —
   `FLANG_IO_TLS`; код двигателя — первым словом сообщения. Двоичный, собранный
   без `tls_client.c` рядом (в том числе всякая программа, напечатанная
   `flang emit --repl`), отвечает `FLANG_IO_NO_TLS` и за чужой программой не
   ходит. curl из хозяина убран целиком, `--no-spawn` к `https` больше
   отношения не имеет.
6. **UDP — два поручения и один отклик.** «Отправить датаграмму» (`адрес`,
   `порт`, `откуда`, `октеты`) → «Записано»; «Принять датаграмму» (`порт`,
   `срок`) → «Датаграмма» (`октеты`, `адрес`, `порт`) или «Срок вышел». Свой
   порт привязывается один раз на прогон: «послать с P, ждать ответа на P» —
   один сокет. `откуда` = 0 — временный сокет на любом свободном порту.
7. **Правка рантайма требует перепечатки.** `flang_repl.c` уезжает в семя
   дословно, и сторож `seed-runtime-is-source` сверяет `bootstrap/flang_repl.c`
   с исходником: до перепечатки он красный по построению, как и `seed-refresh`.
   Новые слова словаря (`flang/self/parser.flang`) семя узнаёт тоже только
   перепечаткой. Применение слов в этой ветке — только в пробе
   `flang/proof/probes/network/`, которую двоичный ствола не исполняет; ни один
   файл, который читает двоичный ствола при сборке или проверке дерева, их не
   применяет (правило 2 `AGENTS.md`).

## 3. Сужения

* Один набор: TLS 1.3, `TLS_AES_128_GCM_SHA256`, группа x25519, подпись узла
  `rsa_pss_rsae_sha256`, цепочка `sha256WithRSAEncryption`. Нет ECDSA и P-384,
  HelloRetryRequest, возобновления, ALPN, HTTP/2 — ровно покрытие ADR-0078.
  Узел, который этого не умеет, получает отказ с причиной двигателя.
* Отзыв сертификата не проверяется (ни OCSP, ни CRL) — как и у curl до этого
  решения (ADR-0007).
* Конец связи без `close_notify` ответ не отменяет; длину тела судит HTTP.
  Узел, пославший `close_notify` и не рвущий связь (`openssl s_server`), узнаётся
  по тишине: двигатель спрашивается, когда узел молчит 200 мс, и в конце связи.
* Кусочная упаковка (`chunked`) не снимается — ответ доезжает тем же телом, что
  и по `http://`.
* Двигатель печатается без проверки (`--no-check`) и без сторожей постусловий
  (`--no-postconditions`), как `tls:engine`. Модуль проверяет
  `flang check flang/stdlib/tls-client.flang` (см. §4).
* Датаграммы — только IPv4. Датаграмма больше 65 507 октетов отвергается
  `FLANG_IO_OCTETS` до отправки. Хозяин вкладки отвечает `FLANG_IO_NO_SOCKETS`,
  каркас Node — `FLANG_IO_NOT_WIRED`.
* Своего TLS-сокета у плана нет: «Открыть соединение» — по-прежнему голый TCP;
  клиент к базе, требующей шифрования, планом не пишется.

## 4. Замер

Одна машина, 12 октября 2026. «Частная сборка» — `bootstrap/` ствола
(`973a31f3e`), в котором `flang_repl.c` заменён исходником этой ветки (с шапкой
печати) и рядом положены `tls_client.c` (1 817 068 байт) и `tls_client.h`
(427 181 байт) из `bootstrap/flang emit flang/stdlib/tls-client.flang --target c
--no-check --no-postconditions` (43,5 с). Сборка `make -j8`: 1 мин 34,5 с
(5 мин 24,8 с процессора); двоичный 26 546 096 → 27 524 160 байт.

`flang check flang/stdlib/tls-client.flang`: «функций 746, из них с доказанным

замечаний нет», 12 мин 54,6 с.

(строка udp), двоичный ствола — «проб 5, разошлось 5». `--plan Forgery`
(`network:forgery`, коды ожиданий перевёрнуты) на частной сборке — «подлог
отвергнут: … проб 5, разошлось 5».

Испорченная запись снята вне набора — ретранслятором на Python в
рабочем каталоге вне дерева (питон в дереве расти не должен, сторож
`no-growth`), который переворачивает один бит потока узла: бит 120-го октета
(запись рукопожатия) — `FLANG_IO_TLS`, `FLANG_TLS_RECORD запись не прошла
проверку тега`; бит 3000-го октета (запись ответа) — `FLANG_TLS_RECORD запись
ответа не прошла проверку тега`. Там же: свой корень при системной связке —
`FLANG_TLS_CHAIN … издатель CN=flang probe root`.

## 5. Встречные примеры

* **Подменённый сертификат, чужое имя, просроченный лист** — три строки набора,
  **испорченная запись** — два прогона ретранслятором (§4): каждый кончается
  отказом с причиной, запрос не уходит ни в одном.
* **Подлог ожиданий** — `--plan Forgery`: все пять строк разошлись.
* **Двигателя нет в сборке** — та же частная сборка без `tls_client.c` отвечает
  `FLANG_IO_NO_TLS`, а не идёт за curl.

## 6. Что не сделано

* **Перепечатка семени.** До неё двоичный ствола по-прежнему зовёт curl и не
  знает датаграмм; набор `network` на нём красный по всем пяти строкам.
  После неё ожидается 5 из 5 — строка udp проверена здесь только по частям
  (исполнение — обвязкой на C, разбор и типы — исходным компилятором,
  `flang/self/bootstrap/check-with-source-compiler.flang`).
* Перепечатка удлиняется второй печатью (43,5 с) и сборкой двигателя; отпечаток
  входов (`scripts/seed-fingerprint`) включает теперь 17 файлов замыкания
  `tls-client.flang`: обход замыкания в `scripts/bootstrap-reprint.sh` начинается
  с двух входов. Правка скрипта — без роста строк (4 заменены на 4).
* Живые узлы этой работой не трогались (внешнюю сеть не трогать — условие
  поручения); замер ADR-0078 §5 (`www.google.com`, `example.com`) снят прежним
  планом, а не этим путём.
* Отзыв, ECDSA, IPv6 у датаграмм, исполнение датаграмм каркасом Node.
