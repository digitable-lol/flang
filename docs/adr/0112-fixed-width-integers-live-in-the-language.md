# ADR-0112. Целые фиксированной ширины и битовые операции живут в самом языке

**Состояние:** предложено. Принимает владелец. Слова решены.

## 1. Вопрос

Напечатанный в C клиент TLS тратит на счёт одного рукопожатия 3,27 с. Время
уходит не на алгоритм, а на представление: битовая операция над 32-битным словом
— свёртка по 32 весам с остатком от деления над `double`, байт — значение в
списке, длинное число — список разрядов по 2¹⁶. Рукописный C с машинными словами
на тех же алгоритмах считает то же рукопожатие за 9,6 мс. Разницу снимают
машинные слова в языке; отдельный прототип на C языку их не даёт.

## 2. Решение

Слова фиксированной ширины — вид значения языка, который проходит все слои:
лексер, разбор, проверку типов, вычислитель, ядро доказательств и печать.
Второго исполнителя на C рядом с языком нет: рантайм C знает тег значения и
действия над ним так же, как знает числа и строки.

### 2.1. Типы

Восемь типов: `u8`, `u16`, `u32`, `u64`, `i8`, `i16`, `i32`, `i64`. Имена — те,
которыми эти типы зовут в C, Rust и Zig, и на всех поверхностях они одинаковы.
Значение — ровно `w` бит, знаковые — в дополнительном коде. С `число`,
`целое`, точными числами и словом другой ширины слово в одном действии не
смешивается: `FLANG_TYPE` с подсказкой «нужен перевод «u32 …»».

### 2.2. Литерал и перевод

`u32 5` — слово; `u64 "18446744073709551615"` — слово из десятичных цифр, когда
значение не помещается в точные числа двойной точности. Та же форма от выражения
— перевод с отказом: `u8 (к числу т)`, `u32 б` при `б: u8`. Перевод сохраняет
значение и отказывает `FLANG_OVERFLOW`, если оно не помещается в тип:
`u32 (i8 -1)` — отказ, а не 4294967295. Литерал вне типа отвергает проверка
типов: `u8 300` — `FLANG_OVERFLOW` до запуска.

Числовой литерал рядом со словом берёт тип соседа: `а плюс 1`, `а меньше 9`,
`а сдвиг вправо на 7` при `а: u32` пишутся без перевода. Литерал вне отрезка
типа — `FLANG_OVERFLOW` при проверке.

В примерах слово пишется той же формой: `дано х равно u32 1`,
`ожидается u64 "18446744073709551615"`.

### 2.3. Арифметика: переполнение — отказ, заворот назван словами

`плюс`, `минус`, `умножить на`, `делить на`, `остаток от` над словами дают
`FLANG_OVERFLOW`, если точный результат не помещается в тип; деление на ноль —
тот же код. Деление — с отбрасыванием дробной части к нулю, остаток — со знаком
делимого.

Арифметика по модулю 2^w пишется явно: `а плюс б с переполнением`,
`а минус б с переполнением`, `а умножить на б с переполнением`. Слова
`с переполнением` относятся ко всей цепочке одного яруса слева от них:
`а плюс б плюс в с переполнением` заворачивает оба сложения;
`а плюс б умножить на в с переполнением` заворачивает только умножение — оно
стоит на своём ярусе ближе. Скобки цепочку закрывают.

Почему отказ, а не заворот по умолчанию: язык держится правила «ложь в типе
хуже отказа» (`255 плюс 1` в `u8` молча давало бы ноль); переполнение размера —
главный источник переполнений буфера в C; криптографии заворот нужен, и там он
написан словами и виден читателю. Где ядро докажет, что `а + б < 2^w`, проверка
отказа не печатается вовсе (§3).

### 2.4. Битовые действия

`побитовое и`, `побитовое или`, `исключающее или`, `побитовое не` (перед
значением), `сдвиг влево на`, `сдвиг вправо на`, `поворот влево на`,
`поворот вправо на`. Двуместные стоят на ярусе сложения и читаются слева
направо: `(х поворот вправо на 2) исключающее или (х поворот вправо на 13)`.
Сдвиг вправо у беззнаковых логический, у знаковых арифметический (`i32 -9`
сдвиг вправо на 1 — `-5`). Сдвиг на `n ≥ w` — `FLANG_BUILTIN_ARGS`; литерал
сверяется при проверке типов. Поворот определён для любого `n` по модулю `w`.
Величина сдвига — слово любой ширины или целое число не меньше нуля.

### 2.5. Произведение двойной разрядности

`а умножить на б с двойной разрядностью` — полное произведение двух слов
ширины `w`: запись из двух половин «старшая» и «младшая», каждая типа `w` (у
`u64` — два `u64`). На нём строится длинная арифметика по 64 бита без
128-битного типа.

### 2.6. Перевод в число и в строку

`к числу` над словом даёт точное число; слово за 2⁵³ − 1 по модулю —
`FLANG_OVERFLOW`. `к строке` даёт десятичную запись со знаком.

### 2.7. Массив байтов

`байты` — массив октетов с длиной за постоянное время, взятием октета с
отказом за концом, срезом без копирования, словом из байтов старшим или
младшим вперёд и сравнением за время, не зависящее от места различия.

## 3. Ядро

Ядро ставит обязательства отказов: у сложения `а + б < 2^w`, у вычитания
`б ≤ а`, у умножения `а · б < 2^w`, у сдвига `n < w`, у взятия октета
`i < длина`. Закрытое обязательство снимает проверку из напечатанного кода.
Каждое правило — строка `flang/proof/tables/inference-rules.tsv`, лемма в
`flang/proof/lean/Rules.lean` (`BitVec`: `toNat_add`, `toNat_and`,
`toNat_ushiftRight`, `toNat_rotateRight`, `isLt`) и ловушка в `Trap.lean`.
Доказательства — переписыванием леммами, без `bv_decide`: та тактика тянет
аксиому доверия компилятору Lean.

Подделки, которые ядро обязано отвергнуть:

| утверждение | почему ложно |
|---|---|
| `(а плюс б с переполнением) не меньше а` у `u32` | `4294967295 + 2` даёт `1` |
| `(а побитовое или б) меньше 2^31` у `u32` | старший бит |
| `(а сдвиг вправо на 1) сдвиг влево на 1 равно а` | младший бит теряется |
| `i32 -9` сдвиг вправо на 1 равно `-4` | арифметический сдвиг округляет вниз: `-5` |
| `а плюс б` у `u8` не отказывает без посылки | `255 + 1` |

## 4. Слова живут в одной строке

Каждое слово этого решения записано ровно один раз — в таблице
`«Слова целых фиксированной ширины»` лексера, строкой
`фраза=идентификатор@поверхность`. Три таблицы лексера (фраза → понятие,
фраза → поверхность, понятие → фраза) выводят свои куски из неё. Разбор,
проверка типов, вычислитель и печать знают только идентификаторы (`opWrap`,
`bitXor`, `rotateLeft`, `opWide`). Замена слова — правка одной строки таблицы.

## 5. Представление

| слой | слово |
|---|---|
| вычислитель | вариант `Знач слово`: ширина, знак, две половины по 32 бита; действия — над половинами, точны в двойной точности |
| C | тег `FL_WORD`: `uint64_t` и ширина в тех же трёх словах значения; действия — машинные, без неопределённого поведения C |
| JSON ответа | число, пока значение точно в двойной точности, иначе строка десятичных цифр |
| напечатанный прогонщик C | `{"w":"u32","v":"…"}` |

## 6. Печать в остальные цели

| цель | слова | заворот | отказ | `байты` |
|---|---|---|---|---|
| C++ | `uint8_t`…`int64_t` | через беззнаковое | сравнение до действия | `std::span<const uint8_t>` |
| Go | `uint8`…`int64` | родной | `math/bits` | `[]byte` |
| Rust | `u8`…`i64` | `wrapping_*` | `checked_*` | `&[u8]` |
| Java | `int`/`long` | родной | `Math.addExact`, беззнаковые сравнения | `byte[]` и смещение |
| C# | `byte`…`ulong` | `unchecked` | `checked` | `ReadOnlyMemory<byte>` |
| JS, TS | до 32 бит — `number` с `>>> 0` и `Math.imul`; 64 — `BigInt` и `asUintN` | маска | сравнение | `Uint8Array` |
| Python | `int` и маска | `& (2**w - 1)` | сравнение | `bytes`, `memoryview` |
| Elixir | целое и `Bitwise` | маска | сравнение | двоичное |

## 7. Порядок работы

1. Типы, литерал, перевод, арифметика с отказом и заворотом, битовые действия,
   сдвиги и поворот — в лексере, разборе, проверке типов, вычислителе и печати C.
2. Обязательства отказов в ядре, строки ведомости, леммы и ловушки Lean, набор
   подделок.
3. Произведение двойной разрядности; печать в остальные цели.
4. `байты`.
5. Библиотека: `sha256`, `hmac`, `kdf`, `aes`, `x25519`, `rsa`, `der`, `tls`,
   `certificate-path`, `tls-client` на словах; замер рукопожатия.

Слова языка доходят до двоичного `bootstrap/flang` только печатью семени.
Библиотека переходит на них после печати: до неё двоичный этих слов не знает.

## 8. Чего решение не делает

- Постоянного времени исполнения не обещает: ветви по секрету в лестнице X25519
  и в отказах остаются.
- Команд AES-NI, PCLMULQDQ и SHA-NI переносимый C не даёт.
- Запись, у которой все поля — слова, печатается в C общей записью, а не
  структурой; это отдельная правка печати.
