# ADR-0115. Код возврата `check --proof` называет то, что доказано

**Состояние:** предложено. Принимает владелец.
**Дата:** 16 октября 2026.
**Основание:** issues 409 и 381, находка 5295 разбора открытых issues: ложная граница,
проверенная только примерами, получала код 0; запись, которую сверщик опроверг, получала
под `--строго` «ДОКАЗАНО» и код 0.
**Пересматривает:** [ADR-0073](0073-a-verdict-counts-as-proved-only-when-the-checker-replays-it.md),
пункт 2 («код возврата не меняется») — в одном месте: ответ сверщика «НЕ СОШЛОСЬ» теперь
меняет код. Пункт 5 (код 3 за непроигранное сверщиком) остаётся будущим шагом.
**Рядом:** [ADR-0010](0010-compatibility-promise-for-0-x.md) — смысл четырёх кодов;
[ADR-0045](0045-run-and-io-print-the-verdict-and-refuse-an-unproved-program.md) — вердикт
запуска.

---

## 1. Задача

У `flang check --proof` было два зелёных ответа, и один из них зелёным не был. Слово
«ПРОВЕРЕНО С ОПОРОЙ, И ОПОРА НЕ СУДИЛАСЬ» ставилось утверждению, у которого нет
доказательства, а есть только примеры функции («сетка N»), и код при этом был 0. Сборочный
сценарий, читающий код, принимал ложь `результат не больше 510` при теле
`если значение больше 100 то 511 иначе 0` (issue 409). Код 0 ADR-0010 обещает только
случаю «сделано, сказать нечего», а здесь сказать есть что: утверждение не доказано.

Второй случай — независимая проверка. Сверщик (`flang/proof/checker`) отвечает кодом 1,
когда запись доказательства противоречит исходнику. Этот ответ печатался строкой, но в код
возврата не попадал: на 391, 415 и 416 `--строго` давал «ДОКАЗАНО» и 0. Если ядро однажды
докажет ложь, а сверщик её поймает, код этого не покажет.

## 2. Решение

Приговор считается после ответа сверщика. Сверщик запускается всегда, когда есть запись,
в том числе под `--json`; его строка уходит в поток ошибок перед строкой приговора.

| что в ведомости и у сверщика | без ключа | `--строго` |
|---|---|---|
| нарушено ≥ 1 | 1, НЕ СОШЛОСЬ | 1, ОПРОВЕРГНУТО |
| сверщик «НЕ СОШЛОСЬ», ввоза у файла нет | 3, НЕ СОШЛОСЬ СО СВЕРЩИКОМ | 3, НЕ СОШЛОСЬ СО СВЕРЩИКОМ |
| объявлено, не доказано; отвергнуто; закон на веру | 3, НЕ ПРОВЕРЕНО | 3, НЕ УДАЛОСЬ ДОКАЗАТЬ — ОБЪЯВЛЕНО, НЕ ДОКАЗАНО |
| сетка, закон на сетке, доказано при условии | **3**, НЕ ДОКАЗАНО — ОПОРА НЕ СУДИЛАСЬ | 3, НЕ УДАЛОСЬ ДОКАЗАТЬ — ОПОРА НЕ СУДИЛАСЬ |
| утверждений нет | 0, ПРОВЕРЕНО САМОСТОЯТЕЛЬНО | 3, НЕ УДАЛОСЬ ДОКАЗАТЬ — ПРОВЕРЕНО ВПУСТУЮ |
| всё доказано, сверщик сошёлся или не взялся | 0, ПРОВЕРЕНО САМОСТОЯТЕЛЬНО | 0, ДОКАЗАНО |

Старшинство сверху вниз. Новых чисел нет: все исходы ложатся в четыре кода ADR-0010.

**Почему расхождение со сверщиком — код 3, а не 1.** Код 1 у `check --proof` значит
«найден контрпример». Сверщик контрпримера не находит: он говорит, что не принял запись, и
причина бывает тремя разными: запись противоречит исходнику, ядро записало ход, которого
сверщик не знает (класс «в» разбора issues: 391, 415, 416), или сверщик иначе читает
исходник (модули на английской поверхности, часть планов: «в исходнике постусловий 0, а в
записи …»). Прогон `check --proof` по 1090 файлам дерева без ввоза (кроме `flang/self`):
сверщик ответил на 835, «НЕ СОШЛОСЬ» — на 64; у 21 из них причина «в исходнике
постусловий N, а в записи …», у остальных сверщик не принял ход ядра. Ложных утверждений
среди них этот прогон не искал. Все три значат одно и то же для того, кто
читает код: независимого подтверждения нет, а возражение есть. Это код 3 — «проверено не
всё, и непроверенное названо», — со своим словом, которое старше прочих слов кода 3.
Строкой выше приговора печатается первая причина сверщика.

**Почему у файла с ввозом код не меняется.** Сверщику из оболочки подаётся одна запись,
без записей ввезённых модулей (`--зависимость`). На таком файле сверщик отвечает «НЕ СОШЛОСЬ» уже потому, что
у зовомой ввезённой функции «нет блока тотальности НИ в записи, НИ в поданном наборе», —
так он ответил и на плане `flang/proof/probes/strict/run.fscript`, где утверждений нет
вовсе. Независимая проверка здесь не состоялась, и это тот же
случай, что «сверщика нет»: строка сверщика называет его словами «НЕЗАВИСИМО НЕ ПРОВЕРЕНО»,
а код остаётся за ядром. Поднять такой файл до кода 3 значило бы покрасить каждый план и
каждый модуль с ввозом, не узнав о них ничего нового.

**Сверщика нет, он упал или файл с ввозом** — код не меняется, как и по ADR-0073:
требовать проигрыша сверщиком для нуля — пункт 5 того решения, отдельный шаг. Подделка
`checker-says-no-with-import.flang` держит эту границу: под `--строго` она остаётся 0, и
когда пункт 5 будет принят, её ожидание поменяется вместе с ним.

## 3. Что меняется в дереве

- Сетка и законы на сетке больше не дают 0 без ключа. В том же прогоне по 1090 файлам без
  ввоза слово «НЕ ДОКАЗАНО — ОПОРА НЕ СУДИЛАСЬ» и код 3 получили 113 файлов. Разница между умолчанием и
  `--строго` осталась одна: файл без утверждений.
- Пробы, которые держали старый контракт, переписаны как следствие этого решения:
  `flang/proof/probes/strict/expected.tsv` (сетка и закон на сетке без ключа — 3),
  `flang/proof/probes/ct-laws/expected.tsv` (законы на сетке — 3),
  `flang/proof/checker/tests/programs/lie-verdict.tsv` (`lie-difference-pure.flang`, ложное
  постусловие с одним примером, — 3 вместо 0: строка закрепляла ровно ту ложь, ради
  которой решение);
  `flang/proof/probes/user-programs/run.fscript` (`greeting`, `shopping-cart` — сетка, 3);
  `flang/proof/probes/quantifier-inside-a-formula/expected.tsv` (`found-witness.flang`,
  `named-witness.flang` — сверщик не принимает правило ядра «кольцо точного целого», 3).
- Подделки этого решения: `flang/proof/probes/strict/programs/checker-says-no.flang`
  и `checker-says-no-with-import.flang` — верные утверждения; сверщиком для них назначен
  `/usr/bin/false`, который на любую запись отвечает кодом 1. Файл без ввоза обязан давать 3
  и «НЕ СОШЛОСЬ СО СВЕРЩИКОМ» и без ключа, и под `--строго`; файл с ввозом — прежний код и
  строку «НЕЗАВИСИМО НЕ ПРОВЕРЕНО».
- Модули библиотеки с сеткой получают код 3. Долг доказуемости
  (`scripts/ledgers/stdlib-proof-debt.tsv`) этим решением не переписан: его переписывает
  полный прогон `stdlib-proof-guard.fscript --plan Check`, и до него проверка `Check`
  назовёт такие модули прибавившимися.

## 4. Что доезжает печатью семени

Две части того же контракта живут в `flang/self/bootstrap/compiler.flang` и до двоичного
доезжают только печатью; код возврата у них — 1, «программа не прошла», уже сегодня.

- **Утверждение, ложное на краю, опровергнуто.** Свободное `утверждение` с `для всех` по
  числу, целому, натуральному, неотрицательному или признаку (не больше трёх переменных,
  без параметров типа) считается на краях типа — 0, 1, 2 или −1, да и нет — и на числах из
  примеров функций файла. Первый вход, на котором оно ложно, даёт
  `FLANG_PROPERTY: утверждение «…» опровергнуто на входе а = 0` под `FLANG_EXAMPLE`, и
  `check` отвечает кодом 1, а не «объявлено, не доказано» (issue 381). Вход, на котором
  вычисление сорвалось, ничего не опровергает.
- **Незнакомое имя свойства — отказ.** `свойство «повторяемость»` и любое имя вне пяти
  проверяемых давало код 0 и не проверяло ничего. Теперь — `FLANG_UNKNOWN_PROPERTY` с
  перечнем пяти имён и код 1: объявление, которое молча не проверяется, читалось бы как
  проверенное.

## 5. Отвергнутые пути

- **Оставить 0 и поменять слово.** Слово читает человек, код читает сборочный сценарий;
  ложь кодом 0 пропускает именно сценарий.
- **Код 1 за расхождение со сверщиком.** Назвал бы «опровергнутыми» 64 файла дерева, в
  которых контрпримера никто не находил, в том числе примеры на английской поверхности
  языка.
- **Пятый код для сетки.** ADR-0010 обещает новое число только новому смыслу; «сделано, но
  проверено не всё, и непроверенное названо» — это ровно код 3.
- **Подавать сверщику записи ввоза из оболочки.** Нужна ведомость каждого ввезённого
  модуля на каждый вызов: цена проверки файла умножается на число ввозов. Это отдельная
  работа; до неё пробел назван словом.
