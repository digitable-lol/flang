# ADR-0124. Печать в C проверяется на каждой программе дважды: по устройству и по контракту; рантайм держится таблицей контрактов

**Состояние:** предложено. Принимает владелец.
**Основание:** требование владельца закрыть дыру «печать в C не доказана соответствующей
исходнику»; сводка всех четырёх дыр — [`docs/trust-gaps.ru.md`](../trust-gaps.ru.md).
**Замер:** дерево `gh/dev` `f32baf155`, двоичный `bootstrap/flang` 0.7.28, собранный в этом
дереве (`make -C bootstrap`). CBMC 6.6.0 и z3 4.13.3 — пакеты Ubuntu, распакованные без прав
администратора (`apt-get download`, `dpkg -x`) во временный каталог. Числа ниже сняты этими
прогонами; где прогона нет, стоит «не мерено».
**Рядом:** [ADR-0030](0030-the-printer-proves-each-run-not-itself.md) — печать проверяется на
каждом запуске протоколом перевода и сличителем; этот документ его продолжает, а не отменяет;
[ADR-0127](0127-a-reference-semantics-in-lean-is-the-yardstick-for-the-checker-and-the-print.md)
— эталонная семантика, на которую опирается этап 4.

| звено | что держит | чем проверено |
|---|---|---|
| исходник → запись доказательства | ядро и независимая проверяющая программа | `flang check --proof`, `checker.c`, двойник на Lean |

Сличитель проверяет **устройство**: каждый узел исходника стоит в протоколе, текст C собран

проверяет, что шаблон правила **значит** то же, что узел языка, и ничего не знает о рантайме.

| «НЕ СОШЛОСЬ» | 0 |

## 3. Опыт: CBMC на напечатанном C

Проверялось, можно ли по постусловиям и предусловиям исходника доказать сам текст C.

**С настоящим рантаймом — нет.** «Факториал» (`flang/proof/examples/corpus-factorial.flang`)
вместе с `flang_runtime.c`, вход ограничен `н ≤ 3`: CBMC не закончил за 900 с, занял 2,5 ГБ.
Время уходит в циклы рантайма, а не в программу: `vsnprintf` (тексты отказов),
`fl_arena_alloc`, `fl_ticks_add`, `fl_region_size`.

**С рантаймом, заменённым его контрактом, — да.** Двенадцать функций рантайма, которые зовёт
модуль «Факториала» (пятнадцать вместе с «Формулой Евклида»), заменены короткими определениями того, что они обещают (`fl_number` даёт число,
`fl_cond` отдаёт признак или отказ, `fl_enter` может отказать по глубине, области памяти
прозрачны). Это и есть контракт рантайма, записанный кодом.

| программа | что доказывалось | итог |
|---|---|---|
| `hypotenuse-square.flang` | три постусловия и неотрицательность квадрата для **всех** `нат` на входе | ДОКАЗАНО, 0,70 с, 26 МБ |
| то же, `+` в тексте C заменён на `−` | | CBMC: 3 нарушения из 70 проверок, 0,34 с; сличитель на той же правке — «НЕ СОШЛОСЬ» |
| `corpus-factorial.flang`, перебор глубины (`--unwind`) | `результат не меньше 0` | `н ≤ 5` — 2,3 с; `н ≤ 20` — 37,8 с, 676 МБ; `н ≤ 60` — не закончил за 900 с |
| `corpus-factorial.flang`, контракты функций (`__CPROVER_requires`/`__CPROVER_ensures`, `goto-instrument --enforce-contract` и `--replace-call-with-contract` по двум функциям — обёртке и телу) | `результат не меньше 0` для **всех** `н` из `[0, 2⁵³−1]` | ДОКАЗАНО, 0,50 с + 0,26 с |
| то же, ветвь «то» печатает `−1` | | НАРУШЕНО: постусловие тела |
| то же, спуск `н − 3` вместо `н − 1` | | НАРУШЕНО: предусловие рекурсивного вызова |
| `euclid-formula.flang`, «сумма квадратов катетов равна квадрату гипотенузы» для всех входов под предусловиями | равенство произведений двойной точности | не закончил за 1200 с (решатель SAT); с решателем z3 — не мерено до конца |

Выводы опыта:

1. Перебор глубины — не доказательство и дорог. Контракт функции, проверенный один раз
   против её тела при допущении контрактов вызываемых, — доказательство для всех входов, и на
   этих программах оно дешевле секунды. Завершение контракт не доказывает; его уже доказало
   ядро на исходнике.
2. Первый прогон контрактов был пустым: контракт стоял у обёртки, а рекурсия шла через тело,
   и CBMC молча не проверил ни одного постусловия. Пустоту поймала только подделка. Поэтому
   у этого пути подделка на каждую проверку обязательна с первого дня.
3. Равенства над произведениями двойной точности дороги для решателя. Их проверяет ядро на
   исходнике; на C разумно проверять форму (что вызов и проверка стоят где надо), а не
   арифметику заново.
4. Рантайм нельзя проверять вместе с программой. Он проверяется отдельно, один раз на каждую
   свою правку, против той же таблицы контрактов, которой заменяется в программе.

## 4. Решение

Путь — сочетание (в): проверка устройства и проверка контракта на каждой программе, плюс
таблица контрактов рантайма, доказанная против самого рантайма; доказательство шаблонов
правил печати — позже, против эталонной семантики.

1. **Устройство** — как сейчас: протокол перевода и сличитель (ADR-0030).
2. **Контракт.** Для каждой функции исходника печать выдаёт контракт CBMC из её `принимает`
   (тег и границы типа), `требует` и `обеспечивает`. Контракты пишутся конструкциями C
   (`__CPROVER_requires`, `__CPROVER_ensures`, `__CPROVER_assigns`), а не комментариями ACSL:
   в дереве нет рукописных комментариев, и контракт не должен им быть. Проверка — модульная:
   каждая функция против своего контракта при допущении контрактов вызываемых.
3. **Рантайм.** Таблица `flang/translation/runtime-contracts.tsv`: функция рантайма, что она
   требует, что обещает, что меняет. Из таблицы план на fscript печатает и замену рантайма
   для проверки программ, и проверку самого рантайма. Сначала 37 функций, которые зовут
   напечатанные модули `flang/proof/examples`; рост таблицы стережёт сверка со списком
   функций, которые зовёт печать.
4. **Доля перевода** печатается отдельной строкой: функций с доказанным контрактом C из
   функций с контрактом в исходнике. В долю доказательств не смешивается (ADR-0030 §4.5).
5. **Шаблоны правил.** Когда будет эталонная семантика (ADR-0127), у каждого из 41 правила
   печати появляется лемма на Lean: шаблон C на малом подмножестве C значит то же, что узел
   языка. Тогда сличитель становится единственным непроверенным звеном между исходником и C,
   а он только сравнивает формы.

## 5. Этапы

| этап | что | объём | измеримый итог |
|---|---|---|---|
| 1 | план `flang/translation/contracts.fscript` печатает контракты CBMC и замену рантайма из таблицы для функций над числами и признаками, без правки печати; прогон на `flang/proof/examples` и `docs/examples/pythagoras`; подделка на каждую доказанную функцию | 1–2 дня | строка «функций с доказанным контрактом C N из M», каждая подделка отвергнута |
| 2 | печать выдаёт контракты сама (ключ рядом с `--protocol`); правка `flang/self/emit-c.flang`, ждёт печати семени | 1–2 недели | та же доля на всём `flang/proof/examples`, без плана-посредника |
| 3 | таблица контрактов рантайма доказана против `flang_runtime.c`: скалярные функции — для всех входов, арена и области — ограниченным перебором с названной границей | 2–3 недели | «функций рантайма с доказанным контрактом N из 37» |
| 4 | списки, строки, записи в контрактах (`__CPROVER_forall`, длины) | 3–4 недели | доля по видам значений |
| 5 | леммы шаблонов правил печати против эталонной семантики | 2–3 месяца после этапа 2 ADR-0127 | «правил печати с леммой N из 41» |
| 6 | CompCert как выбираемый компилятор C (задача 3467) | неделя | сборка релиза CompCert, замер ADR-0030 §9 повторён |

Весь путь до этапа 4 — около трёх месяцев одного исполнителя; с этапом 5 — около полугода.

## 6. Что отвергнуто

- **Доказанный компилятор в духе CompCert** — формальная семантика ядра flang и подмножества
  C, доказательство печати на Lean целиком. Оценка: семантика flang 3–5 тысяч строк Lean,
  подмножество C с моделью памяти рантайма (области, арена, значения `fl_value`) 5–8 тысяч,
  доказательство 41 правила, снятия функций-значений и раскладки памяти 30–60 тысяч строк; два
  — четыре человеко-года. Отвергнуто как основной путь: результат придёт тогда, когда печать
  уже изменится не раз. Его полезная часть — леммы шаблонов (этап 5) — взята.
- **Frama-C WP с ACSL.** Модуля WP на машине нет и пакетом он не ставится; ACSL пишется
  комментариями, а в дереве их нет; модель памяти WP для объединения `fl_value` и арены
  потребовала бы той же таблицы контрактов. CBMC даёт то же модульное доказательство
  контрактами в синтаксисе C и ставится пакетом.
- **Проверять C вместе с настоящим рантаймом.** Замер §3: не заканчивается уже при `н ≤ 3`.
- **Перебор глубины вместо контрактов.** Не доказательство; время растёт быстрее входа.

## 7. Что остаётся доверенным после всех этапов

Компилятор C (до этапа 6), хозяин `flang_repl.c` и рантайм конкурентности `flang_conc.c`
(ни одна напечатанная программа о них ничего не обещает), сам CBMC и решатель, таблица
правил сличителя до этапа 5. Девять других целей печати остаются без проверки.

## 8. Где не уверен

- Сколько функций корпуса выразимы контрактом без кванторов по спискам — не мерено.
- Цена CBMC на функциях со свёрткой и разбором — не мерено; на одной программе с
  произведениями двойной точности решатель не закончил.
