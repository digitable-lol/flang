# ADR-0151. Страница — это проза и вставки из кода; сборка вставляет, проверка краснеет на расхождении

**Состояние:** предложено. Принимает владелец.
**Дата:** 17 октября 2026.
**Рядом:** [ADR-0102](0102-the-compiler-answers-in-the-language-of-the-settings.md) — каталог сообщений;
словарь `docs/glossary.md`, который печатает `scripts/site/emit-dictionary.fscript`; прибор
`docs:examples` (`scripts/site/page-examples.fscript`); числа сайта `{{ключ}}` из
`docs/site/numbers.json`.

---

## 1. Задача

Страницы документации пишутся руками и расходятся с кодом молча. При переводе первых
страниц на вставки нашлось:

- в «Справочнике отказов» восемь кодов (`FLANG_PROOF`, `FLANG_FUNCTOR_NOT_TOTAL`,
  `FLANG_TRANSFORM_SHAPE`, `FLANG_TRANSFORM_COMPONENT`, `FLANG_TRANSFORM_NOT_TOTAL`,
  `FLANG_IO_UNSUPPORTED`, `FLANG_CONC_UNSUPPORTED`, `FLANG_SELF_EVAL_UNSUPPORTED`), которых
  ни компилятор, ни его рантайм не поднимают;
- «Справочник команд» называл четырнадцать команд, а `flang --help` печатает пятнадцать;
- выводы компилятора на страницах называли файлы, которых нет в дереве (`tolko.flang`,
  `nats-ru.flang`, `circle.flang`), и переписать вывод заново было не с чего.

## 2. Решение

Страница — это проза, которую пишет человек, и **вставки**. Всё, что проза утверждает о
языке и что можно взять из кода (код, вывод двоичного, перечни, коды ошибок, команды,
ключи, числа), стоит на странице вставкой. Сборка вставляет содержимое из источника;
проверка сравнивает страницу с тем, что вставила бы сборка, и краснеет на расхождении.

### 2.1. Как вставка записана

Вставка — это строка-директива и тело под ней. Тело лежит в исходнике страницы, поэтому
сырой markdown на GitHub показывает и что вставлено, и откуда.

Код и вывод — ограда блока, директива в её первой строке после метки языка:

    ```flang insert docs/examples/reference/ru/report.flang
    ```flang insert docs/examples/reference/ru/types.flang «Позиция»
    ```flang refused insert docs/examples/diagnostics/parse.flang
    ```text insert output: check docs/examples/diagnostics/parse.flang

Таблица — область между двумя строками-примечаниями HTML, которые сайт не показывает:

    <!-- insert codes -->
    …
    <!-- end insert -->

Метка языка и пометки `refused`, `fragment` стоят до слова `insert` и значат то же, что
без вставки: прибор `docs:examples` гоняет вставленную программу так же, как набранную.

### 2.2. Виды вставок

| Директива | Что вставляется | Откуда |
| --- | --- | --- |
| `insert <файл>` | файл целиком | настоящий `.flang` в дереве |
| `insert <файл> «Имя»` | одно объявление по имени: строка объявления и всё, что под ней с отступом | тот же файл |
| `insert output: <доводы>` | строка `$ flang <доводы>`, всё, что двоичный напечатал в оба потока в их порядке, и `$ echo $?` с кодом, если код не ноль | прогон `bootstrap/flang <доводы>` из корня дерева при сборке |
| `<!-- insert codes -->` | каждый код `FLANG_…`, который поднимает строка `flang/self/**/*.flang` или `bootstrap/flang_*.c` вне примеров и постусловий: файлы, где он поднимается, и шаблоны каталога `flang/messages/catalog.tsv` на языке страницы | исходники компилятора и каталог |
| `<!-- insert keywords <раздел словаря> -->` | слова раздела на четырёх поверхностях; на русской странице — с пояснением | таблица поверхностей лексера, разделы `emit-dictionary.fscript` |
| `<!-- insert tsv <файл> [столбец=значение] -->` | строки таблицы TSV, по желанию — только с нужным значением столбца | любой TSV дерева, например `flang/proof/tables/inference-rules.tsv` |
| `<!-- insert library [<модуль>] -->` | каждый модуль `flang/stdlib/` (или один): объявления типов целиком, у функций — подпись, `требует`, `обеспечивает` и первый `пример`, без тела; под модулем — что ядро сказало о завершении и о каждой гарантии | исходники библиотеки и запись `docs/site/library-status.tsv` |
| `{{ключ}}` | число | `docs/site/numbers.json`, как и раньше |

Команды и ключи двоичного вставляются его собственной справкой: `insert output: --help` и
`insert output: <команда> --help`. Справку печатает `flang/self/cli.flang`, поэтому это и
есть вставка из него.

### 2.3. Сборка и проверка

- `bootstrap/flang run-script docs:build` — план `Build` в `scripts/site/inserts.fscript`:
  находит страницы со вставками (`git grep` по `*.md`), читает их, собирает источники всех
  вставок одним проходом, снимает выводы двоичного, переписывает изменившиеся страницы.
- `bootstrap/flang run-script docs:check` — план `Check` того же файла: то же без записи.
  Красный, если тело хоть одной вставки разошлось с источником, если вставка не
  собирается (нет файла, нет объявления, неизвестная таблица, незакрытая область) и если
  страница с таблицей кодов называет в тексте код, которого компилятор не поднимает.
  Стоит в хуке перед пушем.
- Чистая часть — `scripts/site/inserts.flang` и `scripts/site/library-api.flang`; у
  каждой функции есть пример, и проверка прогоняет их на каждом `check`.

### 2.4. Статус доказательства в API библиотеки

Ведомость `flang check --proof` по всей библиотеке стоит десятки минут, поэтому в
проверку на каждом пуше она не входит. Её снимает отдельный план
`bootstrap/flang run-script docs:library-status` (`scripts/site/library-status.fscript`):
по восемь модулей разом, предел 900 с на модуль, итог в `docs/site/library-status.tsv`
строкой на функцию и на гарантию, с отпечатком SHA-256 текста модуля, с которого снята
ведомость. Страница печатает таблицу статусов модуля, только пока отпечаток сходится с
нынешним текстом; иначе пишет, что ведомость снята с другой версии файла. Старый статус
не выдаётся за нынешний, а правка модуля не роняет пуш.

## 4. Чего это не делает

- Проза остаётся прозой: «что значит» и «что делать» в таблицах отказов пишет человек.
  Проверка следит только за тем, чтобы названный в ней код существовал.
- Формы конструкций (какие слова в каком порядке) таблицей из разборщика не печатаются:
  у двоичного нет команды, которая бы их выдала. Форму на странице показывает вставленный
  файл-пример, и он проходит `check`. Команда предложена в партию печати 9.
- Вывод `check --proof` вставками не берётся: последняя строка называет путь сверщика на
  этой машине, и страница разошлась бы с любой другой машиной.
- Вывод процесса, который читает план, ограничен 1 МиБ; поэтому библиотека читается по
  файлу на модуль, а не одним выводом.
- Вывод двоичного на английской странице — русский: двоичный говорит по-русски.

## 6. Пробы

- Правка примера меняет страницу: имя примера в `docs/examples/reference/ru/fold.flang`
  изменено — `docs:check` красный и называет вставку этого файла в `language.ru.md`,
  `docs:build` переписал страницу, после возврата примера страница вернулась.
- Подменённый руками вывод: первая строка вставки `insert output: --help` в
  `cli.ru.md` изменена — `docs:check` красный и называет эту вставку. Тот же подлог
  стоит шагом CI перед рабочим `docs:check`.
- Код, удалённый из кода: во временной рабочей копии литерал `FLANG_BOUND_ON_NAN` в
  `flang/self/obligations.flang` заменён другим — `docs:check` красный на обеих страницах
  отказов: код назван на странице, а компилятор его не поднимает.
