# ADR-0163. Напечатанный C проверяется по каждой функции против эталонной семантики: перебором всей области, где она конечна, иначе на свидетелях

**Состояние:** предложено. Принимает владелец.
**Основание:** требование владельца закрыть дыру доверия №1 — «корректность сгенерированного
C-кода не покрыта сквозным доказательством соответствия проверенному исходнику»; сводка дыр —
[`docs/trust-gaps.ru.md`](../trust-gaps.ru.md).
**Замер:** дерево `gh/dev` `28d8d588e`, двоичный `bootstrap/flang` 0.7.28, собранный в этом
дереве (`make -C bootstrap`), Lean 4.34.0 по `flang/proof/lean/lean-toolchain`, `cc` системы.
Числа ниже сняты прогоном `bootstrap/flang run-script translation:validate` (4 мин 44 с).
**Рядом:** [ADR-0030](0030-the-printer-proves-each-run-not-itself.md) — протокол перевода и
сличитель; [ADR-0124](0124-the-c-print-is-checked-per-program-by-structure-and-by-contract.md) —
контракты CBMC; [ADR-0136](0136-a-reference-semantics-in-lean-is-the-yardstick-for-the-checker-and-the-print.md)
— эталонная семантика. Этот документ ничего из них не отменяет.

## 1. Что есть сегодня

| звено | что держит | чего не держит |
|---|---|---|
| генератор C `flang/self/emit-c.flang` | ничего о самом себе | — |
| протокол перевода и сличитель `flang/translation/matcher.c` (ADR-0030) | устройство: каждый узел исходника стоит в протоколе, C собран из частей протокола, правило сличено по форме строк | смысл шаблона правила: что `fl_number(a + b)` значит то же, что `плюс`; часть правил сличается только текстом |
| контракты CBMC (ADR-0124) | решение принято, опыт снят вне дерева | в дереве их нет: `flang/translation/contracts.fscript` не заведён, таблицы контрактов рантайма нет |
| эталонная семантика `flang/proof/lean/Semantics/` (ADR-0136, этап 2) | исполнимое определение ядра языка над деревом `flang ast`: числа двойной точности, вызовы с постусловиями, разбор, свёртка, записи, варианты; `flang/proof/lean/reference.fscript` гоняет ею примеры корпуса | с напечатанным C её не сравнивало ничто |
| рантайм `flang/src/emit/c/flang_runtime.c`, прогонщик `flang_cli.c` | примеры и пробы | доказательства нет |

Значит, между проверенным исходником и тем, что исполняет машина, смысл держался только
чтением шаблонов глазами. Сличитель ловит перепутанное устройство, но не ловит шаблон, который
устроен правильно и считает не то.

## 2. Решение

**Проверка перевода (translation validation) на каждой напечатанной функции, без доказательства
генератора.** Для каждой функции независимый от генератора проверяющий — эталонная семантика на
Lean и план на fscript — исполняет напечатанный C и эталон на одних и тех же входах и сравнивает
ответы.

1. **Входы — свидетели из типов.** `Semantics/Validate.lean plan` читает дерево `flang ast` и
   для каждого параметра строит свидетелей по объявленному типу: оба значения признака, каждый
   вариант без полей, особые числа двойной точности (ноль, минус ноль, наибольшее и наименьшее
   конечные, дроби), неотрицательные целые для `нат`, строки латиницей и кириллицей, списки
   длины 0–3, сочетания полей записей и вариантов; рекурсивная сумма разворачивается дважды;
   на место параметра типа ставится `число`. Примеры функции добавляются к свидетелям.
2. **Где область конечна, свидетели — вся область.** Если все параметры конечного типа (признаки,
   варианты без полей, записи и суммы из них) и произведение областей не больше 512, план
   перебирает каждую точку. Совпадение на всех точках — это совпадение функции на C с эталоном
   на любом входе, то есть доказательство перебором при доверенной базе §4. Функция без
   параметров — область из одной точки.
3. **Иначе — на свидетелях.** До 48 наборов вразброс плюс примеры. Это проверка, а не
   доказательство, и вердикт так и пишет.
4. **Ответ — значение или отказ с кодом.** Эталон проверяет предусловия функции до тела и
   постусловия после, как напечатанный C, поэтому отказ `FLANG_PRECONDITION` и `FLANG_PROPERTY`
   сравнивается наравне со значением. Обе стороны печатает одна печать `Validate.lean canon`;
   число печатается кратчайшей десятичной записью со знаком нуля, то есть одной строкой на
   каждое значение двойной точности. Строка, где у эталона кончилось топливо или C упёрся в
   предел глубины или памяти, не сравнивается и считается отдельно.
5. **Подделки обязательны.** План портит напечатанный C честных программ по одной правке и
   требует, чтобы каждая подделка была отвергнута; подделка, которую не удалось построить, роняет
   план. Без этого пустая проверка зеленела бы.
6. **Ярлык** `.flangrc`: `translation:validate`; в CI — шаг ночной работы `lean-crosscheck`, где
   Lean уже ставится.

### Подмножество, которое валидируется первым

Чистые функции без процессов, у которых каждый параметр и результат — число (`число`, `нат` и
его синонимы, `целое`), признак, строка, список, запись или сумма из таких, в том числе
обобщённые по типу: параметр типа проверяется подстановкой `число`. Требование владельца называло
числа, записи и варианты; строки, списки и обобщённые функции взяты сразу, потому что эталон их
уже исполняет и на корпусе ни одного расхождения на них не нашлось. Подстановка одного типа — не
доказательство для всех типов: печать обобщённой функции одна на все подстановки (`fl_value`), но
это довод, а не проверка.

Вне валидации остаются функции с параметром-функцией, функции процессов и функции, у которых
каждый свидетель упёрся в предел. Причина печатается для каждой.

## 3. Замер

Корпус — `flang/proof/examples` (49 файлов) и `docs/examples/pythagoras` (2 файла).

| что | число |
|---|---:|
| функций, у которых СООТВЕТСТВИЕ ПРОВЕРЕНО | 140 |
| из них перебором всей области | 45, из них без параметров 37 |
| из них на свидетелях | 95, из них обобщённых по типу 8 |
| свидетелей сличено | 1423 |
| вне валидации | 4: параметр-функция (`corpus-hof`) |
| файлов, которым генератор отказал | 3, все три — подделки ядра (`forgery-*`), отказ задуман |
| расхождений | 0 |

Подделки, все шесть отвергнуты:

| подделка | функция | расходится на |
|---|---|---|
| знак операции `+` → `-` | `precondition` «Удвоить» | 15 из 20 свидетелей |
| литерал ветви `500` → `501` | `traffic-light` «Штраф» | 1 из 3 (вся область) |
| граница предусловия `>=` → `>` | `precondition` «Удвоить» | 2 из 20 |
| шаг рекурсии `+ 1` → `+ 2` | `precondition` «Высота от дна» | 31 из 49 |
| буква в текстовой константе | `corpus-alphabet` «Строчные» | 1 из 1 (вся область) |
| переставленные операнды вычитания | `precondition` «Сколько дополнить» | 11 из 22 |

Подделка границы предусловия ловится только двумя свидетелями из двадцати: нулём и минус нулём.
Это и показывает цену проверки на свидетелях — граница поймана потому, что ноль стоит в списке
особых чисел, а не потому, что проверка что-то доказывает.

## 4. Что остаётся доверенным

Доверенная база проверки, названная поимённо:

- **дерево `flang ast`** — его читает эталон, и тот же разбор читает генератор; ошибка разбора,
  меняющая смысл программы, здесь не видна;
- **эталонная семантика и Lean**, который её исполняет (`lean --run`); соответствие эталона языку
  держит ADR-0136;
- **рантайм C** `flang/src/emit/c/flang_runtime.c` и **прогонщик** `flang_cli.c` — они входят в
  каждый сличённый ответ C, поэтому их ошибка, одинаковая на всех свидетелях, неотличима от
  ошибки печати, а ошибка, которая на свидетелях не проявилась, не видна вовсе;
- **компилятор C** (`cc -O2`) и **libc**;
- **команды оболочки** плана — копирование, правка подделок `awk`, передача строк прогонщику.

Генератору, сличителю протокола и вычислителю `flang/self/interpret.flang` проверка не доверяет:
ни один из них в прогоне не участвует.

## 6. Что отвергнуто

- **Доказать генератор целиком.** Оценка ADR-0124 §6 — два–четыре человеко-года; результат
  пришёл бы, когда генератор уже изменится. Проверка перевода даёт ответ о каждой напечатанной
  программе сегодня.
- **Сравнивать C с вычислителем `interpret.flang`.** Он написан тем же автором на том же языке,
  что и генератор, и его ошибка может совпасть с ошибкой печати. Эталон написан отдельно и
  обязан совпадать с языком по ADR-0136.
- **Случайные входы без эталона.** Без эталона нечем решить, кто из двух прав.
- **CBMC на настоящем рантайме.** Замер ADR-0124 §3: не заканчивается уже при `н ≤ 3`.

## 7. Где не уверен

- Свидетели строки — пять фиксированных строк; ошибки печати строк с экранированием и редкими
  знаками на них могут не проявиться. Не мерено, сколько.
- Рекурсивная сумма разворачивается только дважды; ошибка, проявляющаяся на глубине три, не
  видна.
- Отказы с разными кодами у эталона и C (например, у эталона `FLANG_FIELD`, у C `FLANG_TYPE`)
  сравниваются как расхождение; на корпусе таких не нашлось, на других программах коды могут
  разойтись без ошибки печати.
