## 1. Задача

Сегодня о сверщике на C (`flang/proof/checker/checker.c`) известно: его вердикты на
наборе проб совпадают с вердиктами приёмки модели (`flang/proof/lean/run.fscript`) и с
вердиктами второго сверщика на корпусе записей (`checker:second`). Это сверка на
пробах, а не вывод: утверждение «сверщик не принимает ложного» о коде на C не доказано
и в этой постановке доказано быть не может — у кода на C нет формальной семантики в
дереве. Условие 3 просит доказательства выводом.

## 2. Решение

1. **Опорная реализация — сверщик на Lean** (`flang/proof/checker/second/`). Блок `вывод`
   он судит приёмкой модели `«принят?»` (`Theorem.lean`, `«Суд».«выводом»`;
   `Sections.lean`, `«выводСнятия»`), и о самом КОДЕ этих путей есть теоремы выводом:
   - `«выводом-по-модели»` (`Theorem.lean`): если суд блока `вывод` второго сверщика
     принял утверждение (не прибавил ни беды, ни непонятого), то читатель прочёл
     утверждение `u`, и либо `«Принят» u` (каждый шаг — конструктор `«ШагПринят»` правила
     из закрытого списка) и цель следует из окружения, либо модель отказала и принял
     запасной прогон по тексту `«прогонР»` — третьего пути нет;
   - `«выводСнятия-по-модели»` (`Sections.lean`): снятие предусловия блоком `вывод`
     принято только приёмкой модели, и цель снятия следует из окружения.

   И теоремы о приёмке записи (`flang/proof/lean/Soundness.lean`):
   - `«вывод-по-модели»`: если опорный сверщик принял блок, то блок — вывод отношения
     `«Принят»`, то есть каждый его шаг — применение конструктора `«ШагПринят»` своего
     правила из закрытого списка приёмки, и цель следует из окружения;
   - `«запись-состоятельна»`: у записи, принятой по порядку с растущим реестром
     доказанных постусловий, цель каждого утверждения следует из его окружения;
   - `«реестр-из-состоятельности»`: факт реестра о принятом утверждении следует из его
     состоятельности всюду, где окружение утверждения держится в мире вызова.
   Аксиом сверх трёх стандартных нет; `sorry` нет.
2. **Сверщик на C — быстрый исполнитель.** Он остаётся тем, что печатает вердикт в
   CI за секунды, и на каждом прогоне сверяется с опорным: `checker:second`
   (корпус записей, расхождение роняет прогон), `run.fscript` (набор проб, вердикт
   на блок). О нём самом теоремы нет и не обещается: доверие к нему — сверка.
3. **Что опорный сверщик судит ВНЕ модели — названо строкой, не теоремой.** Таблица
   `flang/proof/tables/lean-soundness-debt.tsv` держит по строке на каждый путь приёмки
   второго сверщика (`судить…`, `проиграть…`, `прогонР`, `крюкиПоТелу`,
   `кольцоТочногоЦелого`, ходы теорем по роду) с состоянием `доказано`, `нет модели`
   либо `sorry` (имя теоремы с `sorry`). Сторож `lean-soundness:check` красит:
   путь без строки, строку без пути, `sorry` без строки, строку `sorry` без `sorry`
   в файлах. Так долг не растёт молча ни новым путём приёмки, ни новым `sorry`.
4. **Реестр доказанных постусловий — в модели** (`Record.lean`, `«Постусловие»`,
   факт `«постусловие-есть»` в окружении; `Acceptance.lean`, `«мера2р»`, конструктор
   `«М2-реестр»`; лемма `«М2-реестр»` в `Rules.lean`; `«мера2р-значение»` в
   `Consistency.lean`). Шаг М2, чей шаг свёртки — вызов функции с постусловием «плюс
   одно звено», проверенным раньше по записи, судит приёмка, а не текст. Сторож
   `lean-rules:check` видит приём и лемму (подлог 7 плана `lean-rules:forgery`).

## 3. Что доказано выводом, что сверкой, что осталось

| что | как | где |
|---|---|---|
| каждый приём блока `вывод` (91 по `lean-rules:check`) состоятелен | выводом: лемма на приём, теорема «состоятельность» | `Rules.lean`, `Term.lean`, `Consistency.lean` |
| второй сверщик принял блок `вывод` ⇒ модель приняла и цель из окружения, либо принял `«прогонР»` | выводом, о коде сверщика | `checker/second/Theorem.lean`, «выводом-по-модели» |
| второй сверщик принял снятие блоком `вывод` ⇒ модель приняла и цель из окружения | выводом, о коде сверщика | `checker/second/Sections.lean`, «выводСнятия-по-модели» |
| приёмка модели приняла блок ⇒ каждый шаг — правило модели, цель из окружения | выводом | `Soundness.lean`, «вывод-по-модели» |
| запись принята по порядку с реестром ⇒ каждая цель из своего окружения | выводом | `Soundness.lean`, «запись-состоятельна» |
| М2 по реестру: мера свёртки шагом-вызовом точна под порогом округления | выводом | `Rules.lean` «М2-реестр», `Consistency.lean` «мера2р-значение» |
| нарезка записи на утверждения и строй блока `вывод` — по описанию формата | выводом | `RecordFormat.lean` |
| строка шага читается назад, формулы читаются как напечатаны | сверкой: пробы `#guard`, корпус (`lean-model:blocks`: форма, `НЕ ПРОЧЁЛ` = 0), вердикты (`run.fscript`) | `RecordFormat.lean`, `ModelBlocks.lean` |
| сверщик на C согласен с опорным | сверкой на каждом прогоне | `checker:second`, `run.fscript` |
| факт реестра держится в мире вызова (допущения сняты в точке вызова, результат равен телу) | не доказано: посылка `hcall` теоремы «реестр-из-состоятельности» | строка долга |
| ходы теорем, посылки индукции, тотальности, снятия без блока вывода, категорные теоремы, кольцо, крюки по телу, `прогонР` | не доказано: модели нет | `lean-soundness-debt.tsv`, состояние «нет модели» |

Сторож `lean-soundness:check` красит ещё строку `доказано`, чья причина не называет
теорему (`теорема «…»`) либо называет теорему, которой нет в файлах модели и сверщика,
и рост строк «нет модели» выше потолка, записанного в самом стороже: новый путь без
модели проходит только правкой потолка, с доводом в коммите.

Числа — из прогонов `bootstrap/flang run-script lean-soundness:check` и
`bootstrap/flang run-script lean-model:blocks`; в прозе они не повторяются.

## 4. Встречные примеры

- `lean-rules:forgery`, подлог 7: в копии `Rules.lean` лемма «М2-реестр» снята —
  сторож `lean-rules:check` красен («реестр доказанных постусловий: леммы «М2-реестр»
  в Rules.lean нет»).
- `Rules.lean`, «М2-реестр-за-порогом-ложна»: шаг, растущий лишь под ограничением, за
  ним звена не прибавляет — без ограничения лемма «М2-реестр» ложна в арифметике с
  округлением.
- `lean-soundness:check`: пробы функции «Troubles» держат четыре случая — путь без
  строки, строка без пути, `sorry` без строки, уплаченный долг.

## 5. Почему не «sorry на каждый ход»

Теорема с `sorry` требует формулировки, и формулировка должна быть верной. Для
запасного прогона `«прогонР»` очевидная формулировка — «принял ⇒ цель следует из
окружения» — относительно модели не обязана быть верной: прогон берёт шаг М2 по
постусловию из реестра второго сверщика, которое модель не прочла (его в окружении
нет), и шаг Р5 по телу функции, которое читатель не собрал в терм (факта «результат
равен телу» в окружении тоже нет). Цель держится на фактах, которых в окружении нет, и
`sorry` мог бы спрятать ложное утверждение — встречного мира никто не искал, но и
довода за верность нет. Поэтому `«прогонР»` — строка «нет модели», а теорема
«выводом-по-модели» называет его отдельной ветвью дизъюнкции.

Теорема с `sorry` требует формулировки. У ходов теорем, посылок индукции и тотальностей
формулировки нет: у них нет модели значений, и всякая запись вида «если второй сверщик
принял ход, то …» была бы либо пустой, либо ложной с рождения. Строка долга с
состоянием «нет модели» честнее: она называет путь и держится сторожем. Как только у
пути появляется модель, строка меняет состояние на `sorry` (теорема названа) и дальше
на `доказано`.

## 6. Что не сделано

- Модели ходов теорем нет: 15 родов ходов второго сверщика (`Moves.lean`) судятся
  текстом.
- Чтение формул (`RecordReader.lean`, `partial def`) — вне теоремы; связь с печатью —
  сверка на корпусе и на пробах.
- Модель значений округляет не по binary64 на всём пути (ADR-0041 §2.3).
