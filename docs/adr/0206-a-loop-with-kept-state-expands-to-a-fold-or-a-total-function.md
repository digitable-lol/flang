Взяты 15 задач из `docs/examples/leetcode` — по одной на каждый приём, которым корпус

- **строки** — непустые строки решения. У flang не считаются блоки `пример` (с их `дано` и

  одному токену; у Python так же;
- **строки заголовков** — `модуль`, `функция`, `принимает`, `возвращает`;
- **функции-циклы** — функции, которые зовут сами себя и стоят на месте цикла `for`/`while`
  решения на Python (рекурсия дерева в 104 и заливка в 200 не считаются: они рекурсивны и на

- **помощники вместо встроенного** — функции, которые в Python даны языком: меньшее и
  большее из двух, приписать в начало, перевернуть, разложить на символы, ряд единиц.

## 2. Решение

Сахар — новая запись, которая разворачивается в формы, которые ядро уже знает. Новых
правил ядра нет, ведомость, записи доказательства и сверщики не меняются: судят они
развёрнутый текст, а он — обычный flang.

### 2.1. `цикл` — первое и главное

```
цикл «Имя»
  для каждого <элемент>[: <тип>] из <список>
  пока <условие>
  убывает <мера>
  шагов не больше <число>, иначе <значение>
  храним <имя>: <тип> равным <начало>, …
  в конце <значение>
  <тело: строки «пусть», «если», «разбор»>
  … дальше: <имя> станет <значение>, …
```

Строки-предложения стоят первыми, по одной на строке, в любом порядке; за ними тело.
Читается так: цикл хранит значения, на каждом шаге тело либо говорит `дальше` и называет,
какие из хранимых меняются, либо отдаёт ответ — и тогда цикл кончен. Когда кончился список
или стало ложным условие, цикл отдаёт `в конце`.

| запись | во что разворачивается | чем доказано завершение | сторож при работе |
|---|---|---|---|
| `для каждого`, тело кончается одним `дальше` | `свёртка` с записью хранимых: объект `«Имя — состояние»`, поля читаются в `пусть` | свёртка тотальна по построению | нет |
| `для каждого` с ранним выходом | новая тотальная функция `«Имя»`: `разбор` остатка списка, шаг — вызов на хвосте | структурой | нет |
| `пока` + `шагов не больше N, иначе V` | новая функция с параметром `«Имя — запас»: неотрицательное`, шаг — `запас минус 1` | точным шагом | нет |
| `пока` + `убывает M` | новая функция с `убывает M` | объявленной мерой (ADR-0093) | есть, как у любой объявленной меры |

Новая функция получает параметрами те параметры объемлющей функции, которые цикл
упоминает, и хранимые значения; возвращает то же, что объемлющая. `дальше: х станет е`
разворачивается в вызов этой функции, где на месте `х` стоит `(е)`, остальные хранимые
передаются как есть.

### 2.2. Пример: 121, свёртка с двумя хранимыми

До (корпус):

```flang
объект «Сделка»
  минимум является числом
  прибыль является числом
…
    случай голова и хвост
      пусть начальное равно запись «Сделка» с минимум равным голова и прибыль равным 0
      пусть итог равно свёртка хвост начиная с начальное как акк и цена
        пусть минимум равно если цена меньше акк.минимум то цена иначе акк.минимум
        пусть сегодня равно цена минус акк.минимум
        пусть прибыль равно если сегодня больше акк.прибыль то сегодня иначе акк.прибыль
        запись «Сделка» с минимум равным минимум и прибыль равным прибыль
      итог.прибыль
```

После:

```
    случай голова и хвост
      цикл «Сделка»
        для каждого цена из хвост
        храним минимум: число равным голова, прибыль: число равным 0
        в конце прибыль
        пусть сегодня равно цена минус минимум
        пусть ниже равно если цена меньше минимум то цена иначе минимум
        пусть лучше равно если сегодня больше прибыль то сегодня иначе прибыль
        дальше: минимум станет ниже, прибыль станет лучше
```

Развёрнутое — та же свёртка с объектом `«Сделка — состояние»`, что и в корпусе.

### 2.3. Пример: 011, два указателя

До — отдельная функция `«Наибольшая площадь между»` с четырьмя параметрами, мерой и
вызовом из `«Наибольшая вода»`. После:

```
  цикл «Сужение»
    пока лево меньше право
    убывает право минус лево плюс 1
    храним лево: число равным 1, право: число равным длина элементы, лучшее: число равным 0
    в конце лучшее
    пусть слева равно элемент лево в элементы
    пусть справа равно элемент право в элементы
    пусть площадь равно («Меньшее из двух» от слева и справа) умножить на (право минус лево)
    пусть итог равно «Большее из двух» от лучшее и площадь
```

```flang
  принимает элементы: список числа, лево: число, право: число, лучшее: число
  возвращает число
  убывает право минус лево плюс 1
  если не (лево меньше право)
    то лучшее
    иначе
      …
      если слева меньше справа
        то «Сужение» от элементы и (лево плюс 1) и право и итог
        иначе «Сужение» от элементы и лево и (право минус 1) и итог
```

### 2.4. Пример: 704, двоичный поиск с ранним выходом

В корпусе топливом служит копия списка, и её приходится объявлять, передавать и
разбирать. После:

```
  цикл «Поиск»
    пока низ не больше верх
    шагов не больше длина элементы, иначе -1
    храним низ: число равным 1, верх: число равным длина элементы
    в конце -1
    пусть сумма равно низ плюс верх
    пусть середина равно (сумма минус (сумма остаток от 2)) делить на 2
    пусть значение равно элемент середина в элементы
    если значение равен цель
      то середина минус 1
      иначе если значение меньше цель
        то дальше: низ станет середина плюс 1
        иначе дальше: верх станет середина минус 1
```

Ветвь `то середина минус 1` не говорит `дальше` — это и есть ранний выход. Завершение
развёрнутой функции ядро доказывает точным шагом по `«Поиск — запас»`; в корпусе —
структурой по списку-топливу. Сторожа нет ни там, ни там.

### 2.5. Что дал прототип, числом

Счёт тот же, что в 1.1. Решение на flang с циклом против решения корпуса и Python:

| задача | строк: корпус → с циклом | Python | токенов: корпус → с циклом | Python | функций: корпус → с циклом |
|---|--:|--:|--:|--:|--:|
| 121 | 18 → 16 | 8 | 106 → 81 | 51 | 1 → 1 |
| 011 | 29 → 24 | 9 | 206 → 157 | 73 | 5 → 3 |
| 704 | 24 → 17 | 11 | 150 → 107 | 67 | 2 → 1 |

Токенов меньше на 24–29 %, строк — на 11–29 %. До Python остаётся в 1,6–2,2 раза по
токенам: заголовки функций, `пусть … равно`, `элемент i в xs` вместо `xs[i]`, помощники
вместо `min` и `max`. В 011 помощники `«Меньшее из двух»` и `«Большее из двух»` оставлены
нарочно: на их постусловиях четыре доказанных утверждения, и без них сличать вердикты было
бы не с чем.

Вердикты `check --proof` совпали построчно (план `Compare`, `bootstrap/flang run-script
sugar:check`):

```
121: совпало — код 0, ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 0: доказано 0, … — код возврата 0
011: совпало — код 0, ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 4: доказано 4, … — код возврата 0
704: совпало — код 0, ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 0: доказано 0, … — код возврата 0
```

Ведомость тотальности при этом меняется там, где меняется форма: в 704 «структурой по
топливу» становится «точным шагом по запасу», в 011 исчезает функция `«Площадь между»`,
которую цикл вписал в тело. Число сторожей при работе не выросло ни в одной задаче: 0, 2 и 0
до и после.

### 2.6. Где живёт: план разворота, без перепечатки

Разворот написан на flang — `flang/sugar/loops.flang`, — и запускается планом:

```
bootstrap/flang run-script sugar:expand -- задача.flang развёрнутое.flang
bootstrap/flang check --proof развёрнутое.flang
```

Это недоверенный переводчик в смысле ADR-0058: доверять ему не нужно, судит развёрнутый
текст. Ошибка разворота видна как отказ `check` на развёрнутом, а не как ложное «доказано».
Перепечатка семени не нужна, `flang/self` не тронут.

Слова `для каждого`, `храним`, `станет`, `в конце`, `дальше`, `пока` особые только внутри
блока `цикл «…»`; вне его разворот их не читает, поэтому ни одна программа дерева не
ломается. Перенос в разбор языка (`flang/self/lexer.flang`, `flang/self/parser.flang` и
проход разворота рядом с `flang/self/monad-expand.flang`) — следующий шаг и отдельная
перепечатка. До него нужно снять занятость слов прибором `word:occupancy`: `дальше`
встречается в дереве именем (`пусть дальше равно …`, функция `«Дальше»` в планах), и как
ключевое слово его, вероятно, придётся сделать словом только внутри цикла или заменить.

## 3. Чего цикл не делает, и почему

| чего нет | почему | как обойтись |
|---|---|---|
| тело видит имена `пусть` объемлющей функции | новая функция получает только параметры объемлющей; тип имени `пусть` разворот не знает | передать через `храним х: тип равным х` |
| вложенный цикл, конец которого продолжает внешний | продолжение внешнего нужно звать из внутренней функции, а имя хвоста внешнего списка в ней не видно | внутренний цикл в хвосте тела внешнего; предложение на будущее — `цикл «Имя» даёт <тип>` в позиции значения |
| `дальше` в середине строки после выражения | `дальше` забирает остаток строки целиком | писать `то дальше: …` / `иначе дальше: …` |
| изменение на месте | значения flang не меняются; `станет` строит новое значение для следующего шага | — |
| молчаливое «шаги кончились» | при `шагов не больше` значение на этот случай обязательно (`, иначе …`) | — |

## 4. Предложено дальше, без прототипа

Каждое — тоже разворот в существующие формы, со своим замером.

1. **Заголовок в одну строку.** `тотальная функция «Площадь» принимает элементы: список
   числа, лево: число возвращает число` → те же три строки. Снимает две строки с каждой
   функции: по таблице 1.2 до 108 строк из 465. Цена — правка разбора языка.
2. **Таблица значений.** `таблица "I" → 1, "V" → 5, … иначе 0` разворачивается в функцию с
   `разбор`-ом по строкам или в список пар и поиск по нему. Снимает лестницы 013 и 020
   (29 строк с заголовками).
3. **Помощники из библиотеки вместо копий.** Корпус LeetCode самодостаточен нарочно
   (`index.json`); 39 строк помощников в 15 задачах — цена этого правила. Решение не языка,
   а корпуса: разрешить `использует «Списки»`.

## 5. Отвергнуто

- **Цикл как новое правило ядра** (мутабельная переменная, `while` в ядре). Ядро пришлось
  бы учить новой семантике, и записи доказательства перестали бы проигрываться сверщиками.
  Разворот даёт тот же текст без единого нового правила.
- **Мера по умолчанию для `пока`.** Угаданная мера — либо ложь, либо сторож, о котором
  автор не знает. Граница цикла пишется всегда: `убывает` или `шагов не больше`.

## Приложение: решения на Python, с которыми сравнивалось

```python
def two_sum(nums, target):
    for i, x in enumerate(nums):
        for j in range(i + 1, len(nums)):
            if x + nums[j] == target:
                return [i, j]
    return []

def length_of_longest_substring(s):
    left = 0
    best = 0
    for right in range(len(s)):
        while s[right] in s[left:right]:
            left += 1
        best = max(best, right - left + 1)
    return best

def max_area(h):
    left, right, best = 0, len(h) - 1, 0
    while left < right:
        best = max(best, min(h[left], h[right]) * (right - left))
        if h[left] < h[right]:
            left += 1
        else:
            right -= 1
    return best

VALUES = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}

def roman_to_int(s):
    total, prev = 0, 0
    for ch in s:
        v = VALUES.get(ch, 0)
        if prev < v:
            total -= 2 * prev
        total += v
        prev = v
    return total

PAIRS = {")": "(", "]": "[", "}": "{"}

def is_valid(s):
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif not stack or stack.pop() != PAIRS[ch]:
            return False
    return not stack

def signature(word):
    return ",".join(str(word.count(c)) for c in "abcdefghijklmnopqrstuvwxyz")

def group_anagrams(words):
    groups = {}
    for w in words:
        groups.setdefault(signature(w), []).append(w)
    return list(groups.values())

def max_sub_array(nums):
    if not nums:
        return 0
    current = best = nums[0]
    for x in nums[1:]:
        current = max(current + x, x)
        best = max(best, current)
    return best

def unique_paths(m, n):
    if m <= 0 or n <= 0:
        return 0
    row = [1] * n
    for _ in range(m - 1):
        for j in range(1, n):
            row[j] += row[j - 1]
    return row[-1]

def climb_stairs(n):
    prev, cur = 1, 1
    for _ in range(n - 1):
        prev, cur = cur, prev + cur
    return cur

class Node:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def insert(t, v):
    if t is None:
        return Node(v)
    if v < t.val:
        t.left = insert(t.left, v)
    else:
        t.right = insert(t.right, v)
    return t

def max_depth(t):
    if t is None:
        return 0
    return 1 + max(max_depth(t.left), max_depth(t.right))

def depth_from_list(xs):
    t = None
    for x in xs:
        t = insert(t, x)
    return max_depth(t)

def max_profit(prices):
    if not prices:
        return 0
    low, best = prices[0], 0
    for p in prices[1:]:
        low = min(low, p)
        best = max(best, p - low)
    return best

def num_islands(grid):
    grid = [row[:] for row in grid]
    rows = len(grid)
    cols = len(grid[0]) if rows else 0

    def fill(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols or grid[r][c] != 1:
            return
        grid[r][c] = 0
        fill(r - 1, c)
        fill(r + 1, c)
        fill(r, c - 1)
        fill(r, c + 1)

    count = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == 1:
                fill(r, c)
                count += 1
    return count

def contains_duplicate(nums):
    for i, x in enumerate(nums):
        if x in nums[i + 1:]:
            return True
    return False

def product_except_self(nums):
    n = len(nums)
    prefix = [1] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] * nums[i]
    suffix = [1] * (n + 1)
    for i in range(n - 1, -1, -1):
        suffix[i] = suffix[i + 1] * nums[i]
    return [prefix[i] * suffix[i + 1] for i in range(n)]

def search(nums, target):
    low, high = 0, len(nums) - 1
    while low <= high:
        mid = (low + high) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1
```
