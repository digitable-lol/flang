# ADR-0208. Класс — это запись, её методы и закрытый вариант; изменяемого наследования нет

**Состояние:** предложено. Принимает владелец.
**Дата:** 6 ноября 2026.
**Основание:** слово владельца 6 ноября 2026: ООП нужно как простой и понятный сахар.
**Рядом:** [ADR-0206](0206-a-loop-with-kept-state-expands-to-a-fold-or-a-total-function.md) —
тот же способ: сахар разворачивается в формы, которые ядро уже знает, и слово `станет` оттуда;
[ADR-0047](0047-a-syllogism-gets-one-surface-word-not-four.md) — правило сахара;
спецификация, разделы «Функции первого класса», «Суммы типов», «Параметрические типы»,
«Модуль: `использует` и `экспортирует`» (`docs/flang/SPEC.md`).
**Проверяется:** пока ничем — это решение без прототипа. Развёрнутый пример §3 проверен
`bootstrap/flang check --proof` вручную; его вердикт приведён в §3.3 дословно.

---

## 1. Что в языке уже есть

ООП в привычном смысле складывается из пяти вещей. Четыре из них во flang есть под другими
именами; не хватает записи, а не возможностей.

| в ООП | во flang сегодня | чего не хватает |
|---|---|---|
| поля объекта | `объект «Счёт»` с полями | — |
| конструктор | `запись «Счёт» с … равным …` | — |
| метод | функция, первый параметр которой — запись | имени метода рядом с классом; вызова «у объекта» |
| «изменить поле» | новая запись, все поля перечислены заново | записи «то же, но вот это поле — так» |
| интерфейс с несколькими реализациями | `тип` с вариантами и `разбор`; или запись из функций-значений | разбора, собранного из методов по классам |
| инвариант класса | `требует` и `обеспечивает` у каждой функции | одного места, где инвариант пишется один раз |
| объект с идентичностью и изменяемым состоянием | `процесс`: состояние, сообщения, обработчик | — |
| сокрытие | `экспортирует` модуля | — |

## 2. Решение

### 2.1. `класс` — запись и её методы

```
класс «Счёт»
  поле владелец: строка
  поле остаток: число
  всегда остаток не меньше 0

  метод «Положить» принимает сумма: число
    требует сумма не меньше 0
    остаток станет остаток плюс сумма

  метод «Снять» принимает сумма: число
    требует сумма не больше остаток
    остаток станет остаток минус сумма

  метод «Остаток» возвращает число
    остаток
```

Разворот, форма в форму:

| поверхность | во что разворачивается |
|---|---|
| `класс «К»` + строки `поле х: Т` | `объект «К»` с полями `х: Т` |
| `метод «М» принимает а: А возвращает Р` + тело | `тотальная функция «К: М»`, `принимает этот: «К», а: А`, `возвращает Р` |
| имя поля `х` в теле метода | `этот.х` |
| метод без `возвращает`, тело — строки `х станет е` | `возвращает «К»`; тело — `запись «К» с х равным (е) и у равным этот.у …`: неназванные поля переносятся как есть |
| `всегда И` у класса | у каждого метода `требует` И об `этот`; у метода, возвращающего `«К»`, ещё `обеспечивает` И о результате |
| `требует П` у метода | `требует П` у функции |
| `создать «К» с х равным е …` | `запись «К» с х равным е …` и обязательство `всегда` на построенном значении |

Вызов пишется как обычный вызов функции: `«Счёт: Снять» от счёт и 30`. Форма `счёт.«Снять» от
30` требует знать тип `счёт` при развороте; поэтому она — второй шаг, внутри разбора языка
после вывода типов (§4), а не в плане разворота.

### 2.2. Интерфейс — закрытый вариант, и диспетчер собирается из методов

```
вид «Фигура»
  метод «Площадь» возвращает число

класс «Круг» есть «Фигура»
  поле радиус: число
  метод «Площадь» возвращает число
    3.14 умножить на (радиус умножить на радиус)

класс «Прямоугольник» есть «Фигура»
  поле ширина: число
  поле высота: число
  метод «Площадь» возвращает число
    ширина умножить на высота
```

разворачивается в `тип «Фигура»` с вариантами `«Круг»` и `«Прямоугольник»`, в функции
`«Круг: Площадь»`, `«Прямоугольник: Площадь»` и в одну функцию `«Фигура: Площадь»`, тело
которой — `разбор этот` со случаем на каждый класс. Все классы вида перечислены в одном
модуле, и вид **закрыт**: новый класс — это правка модуля, а не подкласс где-то снаружи.

Почему закрытый вариант, а не запись из функций-значений. Оба способа во flang есть, но
анализ завершаемости видит их по-разному (спецификация, «Функции первого класса»): вызов
через `разбор` — обычный вызов по имени, граф вызовов известен целиком, и завершение
доказывается как у любой функции; тег, взятый из поля записи, не прослеживается, и цикл через
такое применение отвергается `FLANG_NOT_TOTAL`. Значит запись из функций годится только для
вида без рекурсии через себя; она остаётся доступной как есть, без сахара.

### 2.3. Метод по умолчанию вместо наследования

```
вид «Фигура»
  метод «Имя» возвращает строка
    "фигура"
```

Класс, который `«Имя»` не объявил, получает тело по умолчанию: в `разбор` диспетчера
идёт `случай любое то "фигура"`. Это всё «наследование», которое входит.

## 3. Пример целиком и что ядро говорит о нём сегодня

### 3.1. До разворота — §2.1

### 3.2. После разворота

```flang
объект «Счёт»
  владелец: строка
  остаток: число

тотальная функция «Счёт: Положить»
  принимает этот: «Счёт», сумма: число
  возвращает «Счёт»
  требует «вклад: остаток не отрицателен» этот.остаток не меньше 0
  требует «вклад: сумма не отрицательна» сумма не меньше 0
  обеспечивает «вклад: остаток не отрицателен после» результат.остаток не меньше 0
  запись «Счёт» с владелец равным этот.владелец и остаток равным (этот.остаток плюс сумма)

тотальная функция «Счёт: Снять»
  принимает этот: «Счёт», сумма: число
  возвращает «Счёт»
  требует «снятие: остаток не отрицателен» этот.остаток не меньше 0
  требует «снятие: хватает денег» сумма не больше этот.остаток
  обеспечивает «снятие: остаток не отрицателен после» результат.остаток не меньше 0
  запись «Счёт» с владелец равным этот.владелец и остаток равным (этот.остаток минус сумма)
```

### 3.3. Вердикт `check --proof` на развёрнутом (с примерами у каждой функции)

```
постусловие «вклад: остаток не отрицателен после» функции «Счёт: Положить» — доказано …
  правило «неотрицательность по построению»
постусловие «снятие: остаток не отрицателен после» функции «Счёт: Снять» — сетка 1 значение
  (примеры функции): нарушений на них нет … Это не доказательство
НЕ ДОКАЗАНО — ОПОРА НЕ СУДИЛАСЬ — утверждений 2: доказано 1, … сетка 1 … — код возврата 3
```

Инвариант класса проверяется ровно тем, чем проверяется любое постусловие, — и ровно так же
честно: у `«Снять»` ядро пока не выводит `остаток минус сумма не меньше 0` из предусловия
`сумма не больше остаток` и говорит «сетка», а не «доказано». Сахар этого не меняет и не
прячет; правило вычитания под предусловием — отдельная работа ядра.

## 4. Как вводить

1. **План разворота**, как у цикла (ADR-0206): `класс`, `вид`, `поле`, `метод`, `станет`,
   `всегда`, `создать`. Вызов — обычный `«К: М» от объект и …`. Без перепечатки.
2. **Разбор языка.** Слова в лексер и разбор, проход разворота в `flang/self`, вызов
   `объект.«М» от …` с выбором `«К: М»` по выведенному типу. Перепечатка; занятость слов
   `класс` и `метод` снимается прибором `word:occupancy` до правки — оба слова встречаются в
   дереве (по `git grep -w` — 538 и 192 места, вместе со строками и примечаниями; прибор
   отделяет имена от текста, `git grep` — нет).

## 5. Что намеренно не входит

| чего нет | почему |
|---|---|
| изменяемое поле, `сеттер`, общий изменяемый объект | значения flang не меняются. Объект с идентичностью и состоянием, которое меняется во времени, — это `процесс`: сообщения вместо методов, надзор вместо исключений. Сахар не притворяется, что запись — это процесс |
| открытое наследование, переопределение метода в подклассе вне модуля | вызов `этот.«М»` из метода базового класса уходит туда, куда скажет тип во время работы: граф вызовов перестаёт быть известным при проверке, и завершение не доказать. Закрытый вид даёт то же для известного набора классов |
| `null` в поле, исключение из метода | в языке их нет: пустое значение — вариант, отказ — значение с кодом |
| перегрузка метода по типам параметров | имя функции в модуле одно (`FLANG_DUPLICATE_NAME`); `«К: М»` уже разводит методы разных классов |
| закрытые поля внутри модуля | сокрытие во flang — у модуля (`экспортирует`). Класс, которому нужно скрыть поля, живёт в своём модуле и не экспортирует `объект`, а только методы |
| отражение, классы во время работы | всё известно при проверке; на этом стоит снятие функций-значений и доказательство завершения |

## 6. Где не уверен

- Слова. `git grep -w` по `*.flang` и `*.fscript` (вместе со строками и примечаниями):
  `вид` — 6034 места, `поле` — 9308, `интерфейс` — 0, `создать` — 22. Внутри блока `класс`
  плана разворота это неважно; для лексера `вид` и `поле` почти наверняка не годятся, и
  интерфейс тогда пишется словом `интерфейс`, а поле — строкой `имя: тип`, как в `объект`.
  Решает замер прибором `word:occupancy`.
- Обязательство `всегда` на `создать`: проверять его постусловием сгенерированного
  конструктора или предусловием у места создания. Первое проще, второе ближе к тому, как
  пишут сегодня.
