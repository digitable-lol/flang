## 1. Что в языке уже есть

ООП в привычном смысле складывается из пяти вещей. Четыре из них во flang есть под другими
именами; не хватает записи, а не возможностей.

| в ООП | во flang сегодня | чего не хватает |
|---|---|---|
| поля объекта | `объект «Счёт»` с полями | — |
| конструктор | `запись «Счёт» с … равным …` | — |
| метод | функция, первый параметр которой — запись | имени метода рядом с классом; вызова «у объекта» |
| «изменить поле» | новая запись, все поля перечислены заново | записи «то же, но вот это поле — так» |
| интерфейс с несколькими реализациями | `тип` с вариантами и `разбор`; или запись из функций-значений | разбора, собранного из методов по классам |
| инвариант класса | `требует` и `обеспечивает` у каждой функции | одного места, где инвариант пишется один раз |
| объект с идентичностью и изменяемым состоянием | `процесс`: состояние, сообщения, обработчик | — |
| сокрытие | `экспортирует` модуля | — |

## 2. Решение

Класс и интерфейс — запись поверх того, что есть: `объект`, `тип` с вариантами,
тотальные функции, `требует` и `обеспечивает`. Разворот стоит перед лексером, и ядро,
типы, завершаемость и оба сверщика видят только развёрнутое. Новой семантики при работе
нет.

### 2.1. `класс` — объект и функции над ним

```
класс «Счёт»
  владелец: строка
  остаток: число
  всегда «остаток не отрицателен» остаток не меньше 0

  метод «Положить» принимает сумма: число
    требует «сумма не отрицательна» сумма не меньше 0
    остаток станет остаток плюс сумма

  метод «Пусто ли» возвращает признак
    остаток равен 0
```

Строки класса, каждая с отступом в два знака:

| строка | что значит |
|---|---|
| `имя: тип` | поле, как в `объект` |
| `всегда «имя» утверждение` | инвариант класса: утверждение о полях |
| `метод «М» [принимает …] [возвращает Т]` | метод; заголовок в одну строку, как в ADR-0206 §4 |

Строки метода — с отступом в четыре знака: `требует`, `обеспечивает`, `пример` и тело, как
у функции. Поле в методе пишется голым именем.

Разворот, форма в форму:

| поверхность | во что разворачивается |
|---|---|
| `класс «К»` и строки `имя: тип` | `объект «К»` с теми же полями |
| `метод «М» принимает а: А возвращает Т` | `тотальная функция «К: М»`, `принимает этот: «К», а: А`, `возвращает Т` |
| имя поля `х` в методе | `этот.х`; имя перед `равным` (поле записи) и после точки не трогается |
| метод без `возвращает`, тело кончается строками `х станет е` | `возвращает «К»`; тело — строки `пусть` перед ними и `(запись «К» с х равным (е) и у равным этот.у …)`: поле, которое не названо, переносится как было |
| `всегда «И» утверждение` | у каждого метода `требует «И»` об `этот`; у метода, который возвращает `«К»`, ещё `обеспечивает «И после»` о `результат` |

Вызов — обычный вызов функции: `«Счёт: Положить» от счёт и 30`. Конструктор — обычная
`запись «Счёт» с владелец равным "Аня" и остаток равным 0`.

Инвариант проверяется ровно тем, чем проверяется любое постусловие, и ровно так же честно:
у `«Счёт: Положить»` ядро выводит `результат.остаток не меньше 0` правилом «неотрицательность
по построению»; там, где правила нет, отчёт говорит «сетка» или «объявлено, не доказано», и
сахар этого не прячет.

### 2.2. `интерфейс` — набор обязательных методов с законами

```
интерфейс «Фигура»
  метод «Площадь» возвращает число
  метод «Название» возвращает строка
    обеспечивает «название не пусто» (длина результат) больше 0
    "фигура"

класс «Квадрат» есть «Фигура»
  сторона: число
  метод «Площадь» возвращает число
    сторона умножить на сторона
  метод «Название» возвращает строка
    "квадрат"

класс «Прямоугольник» есть «Фигура»
  ширина: число
  высота: число
  метод «Площадь» возвращает число
    ширина умножить на высота
```

| поверхность | во что разворачивается |
|---|---|
| `интерфейс «И»` и классы `класс «К» есть «И»` того же файла | `тип «И»` с вариантом `вариант «К» содержит значение: «К»` на каждый класс |
| `метод «М» …` интерфейса | `тотальная функция «И: М»`, `принимает этот: «И», …`; тело — `разбор этот`, и в случае каждого класса — `«К: М» от «значение» и …` |
| `обеспечивает «закон» …` у метода интерфейса | закон: `обеспечивает «закон — К» …` у метода каждого класса и `обеспечивает «закон» …` у `«И: М»` |
| тело у метода интерфейса | метод по умолчанию: класс, который метод не дал, получает это тело в своём случае `разбор` |

Интерфейс закрыт: все его классы стоят в одном файле. Новый класс — правка файла, а не
подкласс снаружи. Так граф вызовов известен целиком, и `«И: М»` — обычная функция с
`разбор`: её завершение доказывается композицией, а закон о ней — индукцией по `«И»` (в
примере выше `«название не пусто»` у `«Фигура: Название»` ядро доказывает по двум случаям).

Значение интерфейса строится вариантом: `вариант «Квадрат» с значение равным квадрат`.

Почему закрытый вариант, а не запись из функций-значений: вызов через `разбор` — вызов по
имени, граф вызовов известен, завершение доказывается как у любой функции; тег, взятый из
поля записи, не прослеживается, и цикл через такое применение отвергается
`FLANG_NOT_TOTAL` (спецификация, «Функции первого класса»). Запись из функций остаётся в
языке как есть, без сахара.

### 2.3. Отказы

Неверная форма — отказ до лексера, со строкой и столбцом исходника:

| код | когда |
|---|---|
| `FLANG_SUGAR_CLASS` | строка класса — не поле, не `всегда` и не `метод`; у класса нет полей; `всегда` без имени; метод не называет `возвращает` и не меняет полей; метод с `станет` называет `возвращает` не `«К»`; `станет` меняет поле, которого нет; после строк `станет` стоит что-то ещё; поле названо параметром, `пусть`, `как` или `дано` |
| `FLANG_SUGAR_INTERFACE` | строка интерфейса — не `метод`; метод интерфейса не называет `возвращает` или несёт `требует`/`пример`; у интерфейса нет классов; класс назвал интерфейс, которого нет в файле; класс не дал обязательный метод; метод класса принимает или возвращает не то, что в интерфейсе |

## 3. Что намеренно не входит

| чего нет | почему |
|---|---|
| изменяемое поле, `сеттер`, общий изменяемый объект | значения flang не меняются. Объект с идентичностью и состоянием, которое меняется во времени, — это `процесс`: сообщения вместо методов, надзор вместо исключений. Сахар не притворяется, что запись — это процесс |
| открытое наследование, переопределение метода в подклассе вне модуля | вызов `этот.«М»` из метода базового класса уходит туда, куда скажет тип во время работы: граф вызовов перестаёт быть известным при проверке, и завершение не доказать. Закрытый вид даёт то же для известного набора классов |
| `null` в поле, исключение из метода | в языке их нет: пустое значение — вариант, отказ — значение с кодом |
| перегрузка метода по типам параметров | имя функции в модуле одно (`FLANG_DUPLICATE_NAME`); `«К: М»` уже разводит методы разных классов |
| закрытые поля внутри модуля | сокрытие во flang — у модуля (`экспортирует`). Класс, которому нужно скрыть поля, живёт в своём модуле и не экспортирует `объект`, а только методы |
| отражение, классы во время работы | всё известно при проверке; на этом стоит снятие функций-значений и доказательство завершения |
| вызов `счёт.«Снять» от 30` | выбор `«К: М»` по типу `счёт` требует вывода типов, а разворот стоит до лексера. Вызов пишется полным именем `«Счёт: Снять» от счёт и 30` |
| слово `создать` | это второй способ написать `запись «К» с …`; обязательство инварианта на построенном значении ложится на первый же метод, который его получит, через `требует` |
| слова `вид` и `поле` | `вид` и `поле` — частые имена в дереве; интерфейс пишется словом `интерфейс`, поле — строкой `имя: тип`, как в `объект` |
