# ADR-0212. У каждой функции рантайма, которую зовёт печать, есть модель в эталоне, и она сверяется через функции, которые её зовут

**Состояние:** предложено, исполнено: модели функций рантайма влиты вместе с решением
(`flang/translation/`). Принимает владелец.
**Основание:** условие 8 в [`docs/road-to-1-0.md`](../road-to-1-0.md) и этап 7 таблицы этапов
[ADR-0163](0163-the-printed-c-is-validated-function-by-function-against-the-reference.md): рантайм
`flang/src/emit/c/flang_runtime.{c,h}` входит в каждый сличённый ответ C, а контракта нет ни у одной
его функции.
**Рядом:** [ADR-0124](0124-the-c-print-is-checked-per-program-by-structure-and-by-contract.md) —
контракты CBMC; ADR-0163 — проверка перевода.

---

## 1. Задача

Символьное сравнение принимает `fl_add`, `fl_b_dlina`, `fl_chain_head` и остальные за операции
языка на веру. Свидетели проверяют рантайм только косвенно и только на тех функциях, которые его
зовут. Нужен способ, при котором каждая функция рантайма, которую зовёт печать, названа, к ней
приставлена модель и её поведение сверено с моделью, и при котором всё это укладывается в правила
дерева: код — только flang и fscript (Lean — в `flang/proof/lean`), ничего не ставится в систему.

## 2. Решение

1. **Модель — эталон.** Смысл каждой функции рантайма уже записан в эталонной семантике:
   встроенная форма — `«форма»` в `Semantics/Eval.lean`, операция — `«двучлен»`, равенство —
   `«равны»`, образцы списка и варианта — `«подходит»`, сборка значения — конструкторы `«Зн»`,
   отображение — `«образы»`, проверки условий и отказы — `«шаг»` и `«беда»`. Функции учёта
   (`fl_enter`, `fl_leave`, `fl_check_entry`, `fl_tick`) соответствуют топливу `«выч»`, функции
   памяти (`fl_region_*`) смысла значения не имеют. Таблица «функция C — модель» лежит в плане
   проверки перевода (`«Runtime models»` в `flang/translation/validation.fscript`), 65 строк.
2. **Перепись.** План перечисляет функции рантайма, которые зовёт каждый напечатанный модуль
   корпуса (имена `fl_…(` в напечатанном C, определённые в `flang_runtime.c` или
   `flang_runtime.h`), и печатает строку «функций рантайма C, которые зовёт сличённый C, N, из них
   без модели в эталоне K». Ключ `--unmodelled-ceiling` ставит потолок K; в CI он 0, так что
   функция рантайма, которую печать начала звать без строки модели, красит прогон.
3. **Сверка через вызывающих.** Функция рантайма сверена, когда каждая функция корпуса, которая её
   зовёт, сошлась с эталоном (перебором, символьно или на свидетелях) и расхождений нет. Чтобы
   каждая модель стояла хотя бы под одной функцией с прямым вызовом, в корпус по умолчанию входит
   `flang/translation/runtime-contracts.flang`: по одной функции на форму, операцию, образец,
   сборку и обход, со свидетелями из типов.
4. **CBMC — позже и снаружи.** Доказательство для всех входов (контракт CBMC на каждую функцию
   рантайма, ADR-0124) требует собрать CBMC и его решатель из исходников вне дерева и держать
   обвязку на C; обвязка на C в дереве нарушает правило «код — только flang и fscript». Это
   отложено: решение настоящего ADR даёт закрытый список и сверку уже сейчас и не мешает потом
   доказать те же строки таблицы.

## 3. Что это даёт и чего не даёт

Даёт: закрытый список функций рантайма с моделью у каждой, потолок, который не растёт молча, и
сверку каждой функции на свидетелях своих вызывающих.

Не даёт: доказательства. Ошибка функции рантайма на входе, которого не взял ни один свидетель
вызывающих, не видна; символьное сравнение по-прежнему принимает модель за смысл функции C.

## 4. Где не уверен

- Строка модели — ссылка словами на определение в Lean; механической связи между именем C и
  определением Lean нет, её держит чтение глазами.
- Функции `…_dokazano` (голова, хвост, код символа, разделить без проверки) моделью считаются
  формы с проверкой; они совпадают с ней, только пока ядро право в том, что проверка не нужна.
