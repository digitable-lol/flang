# ADR-0218. Независимые обязательства судят процессы-работники, ответ собирается по номерам

**Состояние:** предложено. Принимает владелец.
**Дата:** 7 ноября 2026.
**Рядом:** условие 2 [дороги до 1.0](../road-to-1-0.md) — печать семени за час;
[цена перепечатки](../reprint-cost.md); [ADR-0072](0072-normal-parallelism-is-the-pool-the-pure-map-and-a-proved-monoid.md) —
пул потоков `fl_par_map` для тотальных тел (`flang/concurrency/bench/parallel-map.fscript`).

---

## 1. Задача

Печать семени (`sh scripts/bootstrap-reprint.sh`) идёт на одном ядре, и большую часть
времени занимает суд ядра доказательств над обязательствами компилятора. Обязательства
разных функций друг от друга не зависят: вердикт одного не читает вердикта другого.
Нужен суд в несколько исполнителей так, чтобы вывод — семя, записи доказательств, тексты
замечаний — оставался побайтово тем же, что у суда по порядку.

Пул потоков `fl_par_map` здесь не годится. Он раздаёт только тела, которые зовут
тотальные функции, а суд ядра зовёт нетотальные и живёт на кеше суда (`fl_memo`):
кеш — одно состояние на процесс, привязанное к одной арене, с закреплёнными адресами
значений. Делить его между потоками значило бы ставить замок на самый горячий путь
печати или переписывать кеш.

## 2. Решение

**Отображение раздачей.** В рантайме C есть `fl_spread_map` — то же отображение, что
цикл по порядку. Печатник C зовёт её вместо цикла для отображений в функциях из списка
«Spread functions» (`flang/self/emit-c.flang`); остальные отображения печатаются циклом
или пулом потоков. В списке шесть функций, и в каждой отображение считает один элемент
из общих неизменяемых доводов:

| функция | что считает элемент |
|---|---|
| «Вклады обязательств» (`flang/self/proofterm.flang`) | вердикт ядра одного обязательства со своей теоремой-термом или объявлением |
| «Примеры функций» (`flang/self/bootstrap/compiler.flang`) | примеры одной функции |
| «Опровержения функций» | поиск опровержения постусловий одной функции на краях |
| «Опровержения утверждений по одному» | поиск опровержения одного утверждения |
| «Связать исходники» (`flang/self/link.flang`) | разбор одного файла |
| «Связать разобранные файлы» | повторный разбор одного файла с именами первого прохода |

Вклад каждого элемента склеивается с остальными свёрткой «добавить в конец» по порядку
элементов, поэтому строки итога, их порядок и диагностика те же, что у цикла.

**Работники — процессы, а не потоки.** Хозяин считает первые элементы сам и, если по их
цене остаток обещает больше двух секунд работы (`FL_SPREAD_WORTH_NS`), отделяет `fork`
работников. Копия процесса получает всё — программу, кеш суда, накопленный до раздачи,
арену, стек — и считает элемент тем же однопоточным кодом, что хозяин; замков в горячем
пути нет. Номера элементов хозяин раздаёт по одному через трубу: дорогие и дешёвые
обязательства перемешаны, и куски равной длины ждали бы самого медленного. Ответ
возвращается значением, уложенным байтами, и раскладывается в арену хозяина **по номеру
элемента**, а не по приходу. Имена полей и вариантов едут текстом и получают в хозяине
один адрес на одинаковый текст. Работник выходит `_exit`, чтобы не звать `atexit`
хозяина и не сбрасывать его буферы второй раз.

**Закон — тот же ответ.**

1. Значения flang неизменяемы, тело — функция своих доводов: элемент даёт одно и то же,
   где бы его ни считали.
2. Порядок результата — порядок элементов.
3. Отказ любого элемента, смерть работника, нехватка памяти при разборе ответа или сумма
   шагов сверх предела — и раздача отбрасывается целиком; хозяин досчитывает по порядку
   с того же места, и отказ случается тем же текстом и на том же шаге.
4. Шаги каждого элемента считаются от счёта хозяина на входе в раздачу и складываются:
   если сумма укладывается в предел, по порядку предел не перешёл бы ни один префикс.
   Кеш суда отвечает записанной ценой, поэтому сумма не зависит от того, что успел
   запомнить каждый работник.

**Сколько работников.** `FLANG_JOBS` — число; без неё — число ядер, но не больше 64.
`FLANG_JOBS=1` — по порядку. Работников не больше, чем помещается по гигабайту
(`FL_SPREAD_WORKER_BYTES`) над полом в 16 ГиБ свободной памяти (`FL_SPREAD_FLOOR_BYTES`,
Linux, `MemAvailable`); когда свободной памяти меньше пола, освободившийся работник
отпускается, последний — никогда. Остаток `FLANG_MEMO_BYTES` делится между работниками,
иначе N копий кеша взяли бы N потолков.

**Когда раздачи нет.** Внутри работника (вложенная раздача идёт по порядку), при кеше
доказательств на диске (`FLANG_PROOF_CACHE`) и при поимённых приборах
(`FLANG_TICKS_OUT`, `FLANG_TIME_OUT`): их ведомость обязана быть полной, а кеш и приборы
работника умирают вместе с ним. Пульс печати (`FLANG_WATCH`) в работниках молчит, пул
потоков в них не заводится; хозяин раз в 30 секунд пишет строку «раздача: работников N,
готово k из n».

## 3. Чем не стало

- Суд снятия предусловий без теорем («Закрыть без теорем») идёт по порядку: проход
  засчитывает вердикт обязательства и тут же даёт его следующему обязательству того же
  прохода. Раздать его, не меняя ответа, можно только зная, какие доказанные ключи читал
  каждый вердикт; это другая работа.
- Кеш суда не делится: работник заполняет свою копию. Хозяин позже посчитает такой вызов
  заново — тот же ответ, та же цена.
- Печать в Go, Rust и другие цели не меняется: там эти отображения — обычные циклы.
- Печать ускоряется только у двоичного, собранного из семени с раздачей: печатник,
  собранный из прежнего семени, судит по порядку.

## 4. Как проверяется

- `bootstrap/flang run-script spread:check` (`flang/concurrency/bench/spread-map.fscript`):
  стенд — программа на flang (`spread-map.flang`), напечатанная в C двоичным; её отображение
  тотально и печатается через `fl_par_map`, и сторож меняет этот вызов на `fl_spread_map`
  с тем же видом. Один ответ, один отказ и один отказ по пределу шагов при 1, 2, 8 и 64 работниках;
  рантайм, раскладывающий ответы по приходу, даёт другой ответ (подделка краснеет);
  убитый работник не меняет ответа; восемь работников быстрее одного не меньше чем в
  четыре раза.
- Две печати одного дерева двоичным с раздачей — `FLANG_JOBS=1` и с работниками — дают
  побайтово одно семя (`scripts/seed/two-prints-identical.fscript`), и это семя совпадает
  с напечатанным прежним печатником; цена печати — строка
  [`reprint-ledger.tsv`](../reprint-ledger.tsv).
