# ADR-0222. Толкование целей строится из семантической модели: ходы теорем — блоки, которые читает модель

**Состояние:** предложено. Принимает владелец.
**Дата:** 10 ноября 2026.
**Основание:** `docs/road-to-1-0.md`, условие 3 («блоков „вне модели“ нет»);
[ADR-0202](0202-moves-of-a-theorem-are-sound-against-a-model-of-goals.md),
[ADR-0220](0220-the-remaining-moves-are-sound-against-laws-of-the-kernel.md) — все 17 родов хода
состоятельны относительно толкования `«Толкование»`, но толкование задано посылками;
[ADR-0041](0041-the-checker-is-proved-sound-against-a-mechanised-semantics.md) — семантическая модель
(`flang/proof/lean/Model.lean`, `Term.lean`), которой судятся блоки `вывод`.
**Компилятор не тронут:** работа только в `flang/proof/**`, печать семени не нужна.

---

## 1. Задача

Перепись `bootstrap/flang run-script lean-model:blocks` считает блок взятым, только когда его
читает модель. На вершине `a/lean-fields-move-model` (10 ноября 2026, корпус 100 записей):
блоков с доказательством 603, модель читает 80 (блоки `вывод`), вне модели 523:

| род | блоков | судится путём с теоремой |
|---|---|---|
| тотальность | 329 | да |
| утверждение-ходы | 75 | да |
| утверждение-на-слове | 58 | нет |
| утверждение-посылки | 45 | да |
| таблица | 14 | да |
| снятие | 2 | да |

Ходы теорем доказаны состоятельными относительно толкования — структуры с полем «формула
верна» (`«истинно» : String → Prop`) и законами-полями (около сорока в `Goals.lean`, ещё
пять структур законов ядра в `Canon.lean`). Пока толкование — произвольное, теорема говорит
«если законы языка верны, ход не принимает ложного», а сами законы — посылки. Блок ходов
станет блоком, который читает модель, когда толкование будет **построено** из модели, и
каждый закон станет теоремой о модели.

## 2. Решение

### 2.1. Что значит «верно»

Экземпляр `«ТолкованиеМодели» (М : «Мир»)`:

- `«истинно» g` := ∃ ф, `«читатьФормулу» g = some ф` ∧ `«верна» М ф`, где `«читатьФормулу»` —
  читатель формул записи (`RecordReader.lean`), а `«верна»` — значение формулы `«Форм»` в мире
  `М` (`Term.lean`, `«значение»`);
- `«здесь» a b` := оба терма читаются и их значения в `М` равны (равенство языка — как
  `Object.is`, ADR-0202 §2);
- `«тожд» a b` := оба читаются и равны во **всех** мирах, отличающихся от `М` только
  значениями имён (`«связать»` в `Term.lean`);
- мир `М` — **мир программы**: его поле `«функции»` на каждой тотальной функции исходника даёт
  значение её тела. Сейчас `«функции»` — произвольная функция; закон развёртки
  («развёртка-тождество», ADR-0220 §2.7) и законы постусловий становятся теоремами только о
  мирах программы. Построение мира программы для тотальных функций опирается на теорему
  тотальности («тотальность-фундирована», `Paths.lean`) — это часть шага 7;
- `«метка» c` — каждый факт ветви `+У` / `-У` верен либо ложен в `М`.

Утверждение о прогоне: если прогон ходов принят, то для каждого мира, в котором верны
допущения посылки, верна её начальная цель. Это уже теорема «блок-состоятелен» (ADR-0202 §7)
— она переходит к модели без правок, как только построен экземпляр.

### 2.2. Нечитаемый текст

Текст, который читатель не читает, ложен: `«истинно» g` требует, чтобы `g` читалось. Тогда:

- законы, у которых верность текста — посылка (`«т-верно»`, `«подстановка-тождества»`, все
  законы ядра), для нечитаемой посылки верны пусто;
- законы, которые выводят верность нового текста из верности старого (`«т-сохраняет»`,
  `«ужать-верно»`, `«подстановка-равенства»` в обратную сторону), требуют теоремы: читатель
  читает результат нормализации и подстановки, если читал исходник. Это главная работа шага 3:
  `«т»`, `«ужатьТ»`, `«вместо»` — операции над текстом, и нужна лемма «чтение коммутирует с
  нормализацией» (`читатьФормулу (т g) = читатьФормулу g`) и «подстановка текста — подстановка
  в терме» (`читатьФормулу (вместо g a b) = подставить (читатьФормулу g) …`) — на тех классах
  текста, которые читатель читает.
- если такую лемму доказать нельзя для какого-то хода (подстановка по тексту ловит не терм, а
  кусок), этот ход получает проверку «результат читается и равен подстановке в дереве» в самом
  сверщике: ход не берётся, когда чтение не сходится. Поведение меняется только на записях,
  которые сверщик и так не вправе принимать.

### 2.3. Читатель без `partial def`

Читатель формул — десять `partial def` (`RecordReader.lean`, строки 149–379: `«число»`,
`«список»`, `«текст»`, `«форм»`, `«тело»`, `«сумма»`, `«поля»`, `«случаи»`, `«доводы»`,
`«члены»`). О `partial def` Lean не даёт ничего доказать. Два пути:

1. **Топливо.** Каждая функция получает довод `n : Nat` и на нуле отвечает `none`; вызов
   сверху даёт топливо, равное длине текста. Тело то же, рекурсия по `n` структурная, доказывать
   можно индукцией по `n`. Цена — по одному доводу в каждой из десяти функций и лемма «запас
   топлива не меняет ответа».
2. **Мера.** Рекурсия по длине куска текста (`termination_by s.length`) с доказательством, что
   каждый вызов идёт на строго меньший кусок. Чище, но разрез по слову сверху (`«сверху»`) надо
   снабдить леммой о длине каждого куска.

Предлагается топливо: оно не трогает разбор по существу, и уже стоящая сверка читателя на
корпусе (`«форма»` в переписи: шагов 318, прочитано 318) остаётся пробой, что ответы не
изменились.

### 2.4. Модель за пределами целых

Сейчас конечное значение модели — `Int` (`Model.lean`, «Границы модели», п. 1). Цели ходов
говорят и о дробях (`число`), и о тексте, списках, записях, признаках. Шаги:

- тексты, списки, признаки, записи с полями, варианты — в `Term.lean` уже есть (`«ТермТ»`,
  `«ТермС»`, `«Форм»`, `«ТермСм»`, `«Поля»`, `«Случаи»`);
- дроби: значение `«кон» (q : Rat)` с округлением по `«Округление»` (Binary64.lean) — расширение
  ровно там, где сегодня `Int`. Законы, которые держатся только на целых (`«нейтральный-ноль»`,
  `«даёт-нет»` с `«безНеЧисла»`), уже несут в посылке тип довода; на дробях они либо остаются
  теоремами, либо их ход получает проверку типа;
- пока дробей нет, блок, чья цель говорит о дробях, остаётся «вне модели» и перепись называет
  его отдельной причиной («дробь вне модели»), а не молча.

### 2.5. Что переходит в модель и в каком порядке

Перепись получает новый вид прочтения «ходы — читает модель» (`Read by the model` в
`flang/proof/lean/model-blocks.fscript`): блок ходов читается моделью, когда (1) начальная цель
каждой посылки и каждое допущение читаются, и (2) каждый ход прогона — того рода, для чьих
законов есть теорема о `«ТолкованиеМодели»`. Счёт по родам хода — так, что каждый шаг сразу
снимает блоки:

| шаг | что | сколько блоков (оценка, снимается прогоном шага 1) |
|---|---|---|
| 1 | прибор: перепись печатает по блокам ходов, читается ли каждая цель и какие роды ходов стоят | — |
| 2 | читатель на топливе; лемма «топливо не меняет ответа» | — |
| 3 | экземпляр `«ТолкованиеМодели»`; законы подстановки и нормализации (§2.2) | — |
| 4 | роды без законов о тексте: `цель`, `дано`, `конец`, `связка`, `выбор`, `деление`, `закрыть` | блоки ходов, где других родов нет |
| 5 | `замена`, `соседи`, `вычислить` (счёт против модели), `подставить`, `нейтральный` | |
| 6 | `факт`, `переписать` (экземпляр доказанного утверждения: связь с записью целиком — набор, ADR-0193 §3) | |
| 7 | законы ядра `закон`, `переписать формой`, `поля`, `развернуть` — по закону на шаг | до 75 ходов |
| 8 | посылки индукции (45): те же ходы плюс принцип индукции по объявлению типа | до 45 |
| 9 | снятия ходами (2) | до 2 |

Тотальности (329) и таблицы (14) этой записью не берутся: у них свой предмет (ранг зовов,
оглавление), и модель для них — отдельная запись. «На слове» (58) — блоки без доказательства в
записи; их снимают печать ядра и крюки по телу, не толкование.

Итог при выполнении всех шагов: из 523 вне модели переходят до 122 (75 ходов, 45 посылок,
2 снятия), остаётся 401: 329 тотальностей, 14 таблиц, 58 «на слове». Точное число по шагам —
вывод прибора шага 1, а не эта оценка.

### 2.6. Оценка в днях

Дни работы одного исполнителя с Lean 4.34 на этой машине; сборка второго сверщика целиком —
около 40 минут, сборка одного файла — секунды, но очередь `heavy.sh` добавляет часы ожидания.

| шаг | дней |
|---|---|
| 1. прибор переписи | 1 |
| 2. читатель на топливе | 2–3 |
| 3. экземпляр и леммы чтения (`т`, `ужатьТ`, `вместо` против дерева) | 8–12 |
| 4. семь простых родов | 2 |
| 5. пять родов | 3–4 |
| 6. `факт`, `переписать` по свойству и постусловию | 3–5 |
| 7. законы ядра (около двадцати законов) | 6–10 |
| 8. посылки индукции | 3–5 |
| 9. снятия | 1 |
| дроби в модели (§2.4), если нужны блокам | 5–8 |
| **всего** | **34–51** |

Шаг 3 — главный риск: лемма «подстановка текста равна подстановке в дереве» может не
доказаться для `«вместо»` (замена по словам, а не по дереву). Тогда §2.2, последний пункт: ход
получает проверку в сверщике, и шаг дешевеет, а поведение меняется на записях, где текстовая
подстановка расходится с деревом.

## 3. Как узнаем, что взято

Перепись `lean-model:blocks` печатает вид «ходы — читает модель» и число блоков в нём; потолок
«вне модели» в шаге CI опускается с каждым шагом, как сейчас потолок 521/523. Блок не считается
прочитанным, пока его проверяет не модель, а законы-посылки: сторож `lean-soundness:check`
различает теорему о `«Толкование»` вообще и теорему о `«ТолкованиеМодели»`.

## 4. Чего эта запись не обещает

- Тотальности, таблицы и блоки «на слове» — другие записи.
- Совпадение модели с вычислителем в binary64 (ADR-0041 §2.3) — отдельно; дроби §2.4 его не
  заменяют.
- Сам сверщик на C связан с моделью по-прежнему сверкой вердиктов (`checker:second`), а не
  выводом.
