# ADR-0230. Функция зовётся из консоли без JSON: аргументы литералами, по месту и по имени, недостающие спрашиваются

**Состояние:** предложено. Принимает владелец.
**Дата:** 11 ноября 2026.
**Основание:** вопрос владельца — «есть ли удобный способ вызвать функцию с аргументами в консоли, не
вбивая JSON в кавычках; может быть, спрашивать значение каждого аргумента».
**Компилятор тронут:** `flang/self/call-words.flang` (новый), `flang/self/bootstrap/compiler.flang`,
`flang/self/parser.flang`, `flang/self/types.flang` и хозяин `flang/src/emit/c/flang_repl.c`. Решение
доезжает до двоичного с печатью семени.

---

## 1. Задача

`flang run` принимал аргументы одним способом — объектом JSON в ключе `--args`:

```bash
flang run 069-sqrtx.flang --function 'Корень в отрезке' --args '{"н":9,"низ":0,"верх":9}'
```

Значения по месту (`9 0 9`) и по имени (`--н 9`) отвергались как непонятный ключ, а вызов без
аргументов отвечал отказом типов. JSON в кавычках оболочки неудобно набирать, и он не язык: списки,
записи и варианты в нём пишутся иначе, чем в примере функции.

## 2. Решение

Новых команд и ключей нет. Меняется то, что `run` делает со словами после имени файла.

```bash
flang run 069-sqrtx.flang '«Корень в отрезке»' 9 0 9
flang run 069-sqrtx.flang '«Корень в отрезке»' верх=9 н=9 низ=0
flang run 069-sqrtx.flang '«Корень в отрезке»' 9 верх=9
flang run 069-sqrtx.flang '«Корень в отрезке»'
```

1. **Имя функции — первое слово после файла.** `--function «Имя»` остаётся и значит то же.
2. **Слово `имя=значение` — аргумент по имени.** Делит слово первый знак `=`; имя можно писать в
   ёлочках. Слово без `=` и слово, у которого до `=` стоит кавычка (строка со знаком равенства
   внутри), — значение по месту.
3. **Значения по месту идут в параметры по порядку объявления**, пропуская названные по имени.
4. **Значение — литерал языка.** Его читает разбор самого языка: слова складываются в строки
   `дано «имя» равно значение` примера, пример разбирается обычным разбором, и из него берутся
   аргументы — те же узлы, какие дают примеры функций и `--args`. Поэтому число, строка, список,
   `запись «Т» с …` и `вариант «В» с …` пишутся как в исходнике, а сверка с объявленными типами —
   прежняя «Проверить аргументы вызова» до вычисления, с теми же отказами `FLANG_TYPE`.
5. **Строковому параметру годится слово без кавычек**: `слово=дом` значит `"дом"`, `«дом у реки»` —
   `"дом у реки"`. Литерал в кавычках берётся как написан.
6. **Недостающий обязательный параметр спрашивается, когда ввод и вывод — терминал.** Приглашение
   называет имя и объявленный тип: `низ: число = `. Ответ — такой же литерал. Ответ, который не
   читается или не подходит по типу, отвергается с причиной, и вопрос задаётся снова. Строку читает
   та же дверь, что у оболочки (`repl_read_input`): стрелки и история работают. Конец ввода
   прекращает вопросы, и вызов отказывает как незаданный.
7. **Когда ввод или вывод не терминал, вопросов нет**: отказ `FLANG_TYPE` и код `1`, как и было, —
   сценарий не повисает. Сообщение называет функцию один раз.
8. **Кривой вызов — код `2`**: лишнее значение, имя, которого у функции нет, имя дважды, значение в
   несколько строк, значение, не читаемое литералом, и слова вместе с `--args`.
9. **`--args` работает как работал.** Функции без параметров не нужно ничего.
10. Слово, начинающееся с `-` и цифры, — значение (`-3`), а не ключ.

Кириллических близнецов не заводится, потому что не заводится ключей: у `--function` и `--args`
близнецов нет, и новые формы обходятся без ключа.

**Запись аргумента по имени — договор.** `имя=значение`, где имя — имя параметра из строки
`принимает` (голое или в ёлочках), а значение — литерал языка, каким он пишется в строке `дано`
примера. На эту запись опираются другие входы (поля аргументов площадки строятся по параметрам
`принимает`), поэтому она не меняется без нового решения.

Рукописный C не вырос: в файле хозяина на три строки меньше.

## 4. Две поломки, снятые заодно

**Оболочка не вычисляла выражения.** Оболочка оборачивает выражение в функцию `«⟨выражение⟩»` без
строки `возвращает`, а разбор с выпуска 0.7.32 отвергает функцию без этой строки. На 0.7.28
`1 плюс 2` даёт `3`, на 0.7.32–0.7.34 — `FLANG_PARSE`. Разбор теперь пропускает без типа результата
одну функцию — с этим именем.

**Сообщение о незаданном аргументе называло функцию дважды**: «вызов функции «Ф» функции «Ф» не
задаёт аргумент». Метка вызова уже несёт имя функции, и второй раз оно не дописывается.

## 5. Что решение не делает

- Приглашение показывает объявленный тип параметра; условия `требует` в нём не названы, они
  проверяются при вызове, как и раньше.
- Функция с именем `«⟨выражение⟩»`, написанная в файле без строки `возвращает`, разбором не
  отвергается.
- Строка повтора в снимке отладки называет файл и функцию, но не слова-аргументы.
- Краткая справка `flang --help` показывает прежнюю форму с `--function`; новые формы описаны в
  `flang run --help` и на странице командной строки.
