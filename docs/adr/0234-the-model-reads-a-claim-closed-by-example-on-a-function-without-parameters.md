# ADR-0234. Утверждение, закрытое примером у функции без доводов, читает модель; что нужно остальным блокам «на слове»

**Состояние:** предложено. Принимает владелец.
**Дата:** 11 ноября 2026.
**Основание:** `docs/road-to-1-0.md`, условие 3 («блоков „вне модели“ нет»);
[ADR-0222](0222-the-interpretation-of-goals-is-built-from-the-semantic-model.md) §2.5 —
«„на слове“ — блоки без доказательства в записи; их снимают печать ядра и крюки по телу, не
толкование»;
[ADR-0228](0228-the-model-reads-a-composition-totality-by-the-reference-evaluator.md) —
эталонный вычислитель как модель.
**Компилятор не тронут:** правок в `flang/self/**` и `bootstrap/**` нет, печать семени не
нужна.

---

## 1. Задача

Перепись `lean-model:blocks` зовёт блок «на слове», когда утверждение несёт вердикт
«доказано», а под ним нет ни блока `вывод`, ни ходов, ни посылок. Таких блоков в корпусе
58. Замер до постройки, по строкам записи и исходнику:

| чем закрыто | блоков | доводы у функции |
|---|---|---|
| теорема исходника, шаг «по примеру» | 47 | нет ни у одной |
| теорема исходника, шаг «по свойству» с правилом ядра | 4 | есть |
| теорема исходника, шаг «по предположению» с правилом ядра «неотрицательность по построению» | 2 | есть |
| теорема исходника, шаг «по предположению допущение N», правило «цель есть допущение» | 2 | у одной есть, второе — свободное утверждение без функции |
| теоремы нет, названо правило ядра | 3 | есть |

## 2. Решение о примере

### 2.1. Что значит «верно»

У функции без доводов вход один. Вызов её тела в эталонном вычислителе с проверкой
постусловий — перебор всех входов, а не проба: если он даёт значение, каждое постусловие
функции на этом значении дало «да». Так ядро Lean закрывает замкнутое утверждение
вычислением.

### 2.2. Правило

`«принятьПример» P строки f имя строка N` (`flang/proof/lean/Semantics/Examples.lean`):
функция `f` есть в дереве программы; доводов у неё нет; строка исходника с номером из шапки
блока стоит внутри `f` и начинается с `обеспечивает «имя»`; вызов тела `f` на пустой среде
при запасе `N` даёт значение.

### 2.3. Теорема

`«пример-исчерпывает»`: у принятого блока есть значение `v` такое, что при любом запасе не
меньше `N` вызов тела даёт `v`, тело вычисляется в `v`, и каждое постусловие функции на `v`
вычисляется в «да». Доказано выводом, без `sorry`, на трёх стандартных аксиомах Lean;
перепись повторяет теорему у себя (`«принятый-пример»` в `ModelBlocks.lean`) и при сборке
отказывает, если та встала на `sorry` или на аксиому сверх трёх.

### 2.4. Что перепись считает прочитанным

Блок читается, когда все его шаги — «по примеру», индукции в нём нет и у функции нет
доводов. Тогда судит `«принятьПример»` при запасе 256: `ПРИНЯЛ`; `ОТВЕРГ`, когда вызов
отказал либо строка исходника — не постусловие этой функции с этим именем. Блок, чей вызов
упирается в узел вне эталона или в запас, остаётся «на слове» с причиной. Имя примера
правило не читает: у функции без доводов любой пример — тот же единственный вызов.

### 2.5. Пробы

В том же файле стоят проверки сборки (`#guard`): принято верное постусловие; отвергнуты
ложное постусловие, функция с доводом, чужое имя утверждения, строка исходника без
постусловия и нулевой запас.

## 3. Чего правило о примере не берёт

- Пример у функции с доводами: один вход из многих — не доказательство, и правило такой
  блок не читает. В корпусе таких блоков «на слове» нет.
- Соответствие постусловия в строке исходника постусловию в дереве программы: дерево
  печатает компилятор, читает `Semantics/Json.lean`, и теорема говорит обо всех постусловиях
  функции в дереве разом.

## 4. Остальные 11 блоков: предложение

Ни один из них не закрыт голым словом автора. «По предположению» в записи значит одно из
двух: цель совпала с допущением, объявленным в теореме (правило «цель есть допущение»),
либо шаг автора закрыло правило ядра. Поэтому отдельной графы «не читается по построению»
условию 3 не нужно; каждому роду нужна своя теорема:

| род | блоков | что нужно модели |
|---|---|---|
| правило ядра без шагов в записи: «неотрицательность по построению» 2, «порядок по построению» 1, «тождество после переписки допущением» 1, «начало по построению» 1 | 5 | теорема о правиле ядра над эталонным вычислителем — та же, что нужна посылкам без ходов (задача 6627) |
| «по свойству» с правилом ядра («разбор цели по условию» 3, «неотрицательность по построению» 1) | 4 | экземпляр доказанного раньше утверждения (ADR-0222, шаг 6) и теорема о правиле |
| «цель есть допущение» | 2 | чтение цели и допущения читателем формул; теорема «допущение влечёт себя» над толкованием модели (ADR-0222, шаги 2–4) и проверка, что допущение взято из самого утверждения: обе записи корпуса (`forgery-hypothesis-outside-the-postcondition`, `forgery-hypothesis-outside-the-statement`) — подделки с допущением, которого в утверждении нет, и модель обязана их отвергнуть |

Предлагается: перепись продолжает писать эти блоки видом `утверждение-на-слове` с причиной
в последнем столбце, и они идут в потолок «вне модели», пока теоремы нет. Владелец решает,
согласен ли он с тем, что графа «на слове» остаётся частью меры условия 3.

## 5. Записи корпуса, которые сверщик не принимает

Из 100 записей корпуса сверщик на C не принимает 29: 12 отвергает («НЕ СОШЛОСЬ»), у 17
отвечает «НЕ ПРОВЕРЕНО — ВПУСТУЮ» (запись сошлась с исходником, доказанного в ней нет).
Перепись считает блоки и таких записей; строкой «из них в записях, которые второй сверщик
отвергает» она печатает, сколько блоков «вне модели» стоит в отвергнутых записях: 9 (4
утверждения ходами, 2 «на слове», 2 посылки без ходов, 1 тотальность). Потолок эта строка
не меняет.

| ответ сверщика | подделка по имени (`forgery-…`, `poddelka-…`) | имя подделкой не зовёт |
|---|---|---|
| НЕ СОШЛОСЬ, 12 | `forgery-case-split-captures-a-bound-name`, `forgery-hypothesis-outside-the-postcondition`, `forgery-hypothesis-outside-the-statement`, `forgery-unfold-inside-a-list`, `forgery-unfold-of-a-whole-comparison`, `forgery-unfold-without-arguments`, `poddelka-nositel-chislo-segment`, `poddelka-nositel-psevdonim-ne-otrezok`, `poddelka-raznost-bez-poryadka`, `poddelka-razv2-sebya`, `poddelka-razv3-raznost`, `poddelka-svyortka-nad-pustym` | — |
| НЕ ПРОВЕРЕНО — ВПУСТУЮ, 17 | `forgery-binder-hides-the-condition`, `forgery-if-without-descent`, `poddelka-element-po-nomeru`, `poddelka-istinnaya-vetv`, `poddelka-krug-pri-rabote`, `poddelka-lozhnaya-polovina`, `poddelka-mera-dliny-stroki`, `poddelka-porjadok-sosednih`, `poddelka-ravenstvo-v-tele-ne-dokazyvaet`, `poddelka-razdvoenie-diz`, `poddelka-refleksivnost`, `poddelka-sortirovka-ne-ubyvaet`, `poddelka-vhozhdenie` | `krug-tuda-i-obratno`, `negative-zero-a-minus-a`, `negative-zero-a-plus-zero`, `negative-zero-zero-times-a` |

Таблица проб `flang/proof/checker/tests/probes.tsv` называет пять из этих записей: четыре
строкой подделки с ожидаемым кодом 1 (`poddelka-nositel-chislo-segment`,
`poddelka-nositel-psevdonim-ne-otrezok`, `poddelka-razv2-sebya`, `poddelka-razv3-raznost`) и
одну честной строкой с ожидаемым кодом 3 (`krug-tuda-i-obratno`); об остальных 24 таблица
молчит, и что запись — подделка, говорит только её имя.

Владелец решает, как условие 3 считает блок отвергнутой записи: для него «модель читает»
может значить только «модель отвергает по той же причине».

## 6. Как узнаем, что взято

`bootstrap/flang run-script lean-model:blocks` печатает вид `утверждение-примером` с
вердиктами и вид `утверждение-на-слове` с числом 11; потолок «вне модели» в шаге CI опущен
до числа прогона.
