## 1. Задача

Посылка индукции `закрыта reduction шагов 0 правило «неотрицательность по построению»` несёт
только имя правила ядра; ходов под ней нет. То же правило закрывает утверждение «на слове»,
когда в записи стоит шаг автора с этим правилом. Такие блоки перепись держала вне модели:
теоремы о правиле над эталонным вычислителем не было.

## 2. Что ядро принимает

Сверщик на C (`неотрицательно_algebra` в `flang/proof/checker/checker.c`) и ядро
(`flang/self/proof-kernel.flang`, «Правило неотрицательности») берут цель
`результат не меньше 0`, когда тело функции собрано из неотрицательного:

- выписанное число не меньше нуля;
- имя довода с дном: объявлен отрезком (`неотрицательное`, `нат` и синонимы) либо строкой
  `требует … Т не меньше К` / `Т больше К` при выписанном К не меньше нуля;
- допущение индукции — вызов своей функции;
- сумма неотрицательных; выбор, у которого обе ветви неотрицательны;
- произведение неотрицательного на выписанное число из (0, 2⁵³−1];
- свёртка с неотрицательным началом и шагом счёта;
- `длина` чего угодно;
- развёртка одного вызова чужой плоской функции;
- в посылке спуска по отрезку — произведение довода на допущение, когда условие ветви
  делает довод строго положительным.

## 3. Правило модели

`«нн» P S d K e` (`flang/proof/lean/Semantics/Nonnegative.lean`) — признак, вычислимый по
дереву программы: `K` — имена, о которых известно, что они неотрицательны, `S` — функции,
чей вызов неотрицателен, `d` — сколько развёрток чужих функций ещё можно.

- число: `неБольше64 (+0) d`; имя: из `K`;
- `add` — обе части; `mul` — одна часть выписанное конечное число больше нуля, другая
  неотрицательна;
- `если` — обе ветви, условие не читается;
- `пусть x = v в b` — `b` при `x` в `K`, если `v` неотрицательно, иначе при `K` без `x`;
- вызов `g`: `g` из `S` и у `g` в дереве есть постусловие `результат не меньше 0`; иначе
  развёртка тела `g` с `d − 1`, где неотрицательны те доводы `g`, чьё выражение у вызова
  неотрицательно;
- `разбор` — каждая ветвь при `K` без имён, которые связывает образец;
- `свёртка` — начало, и шаг при `K` без имён накопителя и элемента, но с накопителем;
- форма `#отказ …` — значения не даёт вовсе;
- прочее — нет.

## 4. Теоремы

- `«нн-верно»`: если на среде `ρ` каждое имя из `K` неотрицательно, `«нн» P S d K e`
  принят и `выч P n ρ e = ok v`, то `v` — неотрицательное число. Индукция по запасу.
- `«неотрицательность-по-построению»`: принятый `«принятьНеотрицательность»` блок даёт
  функцию в дереве, её постусловие `результат не меньше 0`, доводы с дном среди её
  доводов, строку исходника внутри функции, кончающуюся
  `обеспечивает «имя» результат не меньше 0`, и для каждой среды, где доводы с дном
  неотрицательны и тело вычислилось в `v`: `v` неотрицательно, и постусловие на `v` при
  любом запасе от двух вычисляется в «да».

Обе стоят на трёх стандартных аксиомах Lean без `sorry`; перепись при сборке отказывает,
если вторая встала на большее. Пробы `#guard` в том же файле: принято тело
`н плюс («Сумма до» от …)` при `н` с дном; отвергнуты то же без дна у `н`, без
`«Сумма до»` в `S`, с вычитанием вместо сложения, с произведением на вызов, произведение
на ноль, пересвязанное отрицательным `пусть` имя, свёртка с шагом-элементом.

## 5. Что теорема говорит и чего не говорит

Вызов функции в эталоне возвращает значение только после того, как каждое её постусловие
вычислилось в «да» (`«вызватьТело»`). Допущение индукции у вызова функции из `S` взято из
этой проверки, а не из дна доводов вызова: «`Сумма до` от (н минус 1)» неотрицательна потому,
что эталон проверил её постусловие, а не потому, что `н минус 1` лежит на отрезке. Теорема —
частичная правильность над эталоном: если тело вычислилось, результат неотрицателен.

Рантайм доказанное постусловие не вычисляет (задача 6284). Если эталон перейдёт на его
правило (выбор 1 в задаче 6284), у четырёх блоков с вызовом своей функции на
`н минус 1` (`if-over-a-segment` трижды, `segment`) допущение придётся выводить из условия
ветви и отрезка, как это делает сверщик на C.

Правило `K` выписывает перепись из дерева программы: доводы с типом-отрезком и доводы со
строкой `требует` указанного вида. Что дерево верно передаёт объявление исходника, теорема
не говорит.

## 6. Что перепись считает прочитанным

Блок утверждения `вид postcondition` читается, когда под каждой посылкой без ходов стоит
правило «неотрицательность по построению» (у утверждения «на слове» — каждый шаг называет
это правило), функция входит в набор `S`, который перепись строит из всех функций с
постусловием `результат не меньше 0`, отбрасывая не принятые, пока набор не перестанет
меняться, и `«принятьНеотрицательность»` принял блок. Вид — `утверждение-по-построению`,
вердикт `ПРИНЯЛ`, причина называет доводы с дном.

Посылки с ходами в таком блоке теорема покрывает целиком: она говорит о самом утверждении.
Блок, где другую посылку закрыл шаг автора (`закрыта term … правило «»`), остаётся вне
модели: шаг автора своей теоремы не имеет.

## 7. Чего правило не берёт

- `corpus-factorial`: спуск `н умножить на («Факториал» от (н минус 1))`. Сверщик на C
  берёт его, читая условие ветви (`н` строго положителен на отрезке). Модель условия не
  читает; `0 умножить на +∞` — не число, и без условия правило отказывает. Расхождения в
  правильности нет: модель берёт меньше.
- `poddelka-nositel-chislo-segment`, `poddelka-nositel-psevdonim-ne-otrezok`: довод `число`
  и псевдоним числа без дна. Оба сверщика запись отвергают; модель блок не принимает.
- Блоки, где рядом стоит шаг автора, и правила «тождество после переписки допущением»,
  «разбор цели по условию», «порядок по построению» — следующие теоремы задачи 6627.

## 8. Ограниченность точным потолком

Правило ядра «ограниченность точным потолком по построению» закрывает цель
`(длина результат) не больше К`. Модель берёт его тем же путём
(`flang/proof/lean/Semantics/Ceiling.lean`).

- `«потолок» M T e` — верхняя граница длины строки либо списка, которые даёт `e`: строковый
  литерал — его длина; имя — граница из `M`; `если` — большая из ветвей; `разбор` по имени
  — большая из ветвей, причём если разбираемое имя из `T` (довод, объявленный строкой),
  голова образца `голова и хвост` получает границу 1; прочее — границы нет.
- `«потолок-верен»`: если имена из `M` связаны со значениями не длиннее своей границы,
  имена из `T` — со строками, и `e` вычислилось в `v`, то длина `v` не больше границы.
- `«ограниченность-по-построению»`: принятый `«принятьПотолок»` блок даёт функцию, ее
  строковые доводы среди доводов, строку исходника внутри функции с постусловием
  `обеспечивает «имя» (длина результат) не больше …`, постусловие в дереве вида
  `(длина связка) не больше d` с `изЦелого B ≤ d`, и для каждой среды, где строковые доводы —
  строки и тело вычислилось в `v`: длина `v` не больше `B`, и постусловие при любом запасе
  от трёх вычисляется в «да».

Вспомогательные: литерал `k` дерева есть `изЦелого k`; `изЦелого` монотонно на
натуральных; `неБольше64` транзитивно. Пробы `#guard`: граница 1 у головы строки; нет
границы без строкового довода и у хвоста; постусловие `не больше 0` отвергнуто.

Здесь допущения индукции нет вовсе: вызовов граница не берёт, и проверка постусловий
эталоном теореме не нужна.

Не берёт: `К4 голова не длиннее текста` (`sources`) — граница не литерал, а длина довода;
это правило «порядок по построению».

## 9. Как узнаем, что взято

`bootstrap/flang run-script lean-model:blocks` печатает вид `утверждение-по-построению` с
вердиктами; потолок «вне модели» в шаге CI опущен до числа прогона, пол судимых путём с
теоремой не меняется: блоки ушли из видов без теоремы пути.
