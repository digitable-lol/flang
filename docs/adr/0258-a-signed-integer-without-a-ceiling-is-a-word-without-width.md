# ADR-0258. Целое со знаком без потолка — слово без ширины, а деление над ним округляет вниз

**Состояние:** предложено, исполнено в исходниках компилятора; в собранный двоичный попадает только
печатью семени выпуска 0.9.0. Владелец решил завести такое целое в выпуске 0.9.0 (26 ноября 2026);
само решение о форме — этот документ — владельцем не рассмотрено.
**Дата:** 26 ноября 2026.
**Основание:** находка переводчика Python: «во flang нет целого со знаком без потолка с делением»,
поэтому `int` из Python переводится в `число`, а оно точно только до 2⁵³ − 1.
**Рядом:** [ADR-0036](0036-an-exact-integer-is-a-new-kind-of-value-not-a-new-name.md) — точное целое
без знака; [ADR-0062](0062-an-exact-fraction-is-a-pair-of-exact-integers-reduced-at-the-action.md) —
точное дробное и остаток над точным целым; [ADR-0074](0074-the-integer-part-of-an-exact-fraction-is-a-built-in-form.md) —
целая часть дроби; [ADR-0095](0095-ring-laws-are-one-rule-over-the-exact-integer-and-a-refusal-with-a-cause-over-number.md) —
законы кольца над точным целым; [ADR-0112](0112-fixed-width-integers-live-in-the-language.md) —
слова фиксированной ширины; [ADR-0058](0058-a-foreign-language-enters-through-an-untrusted-translator.md) —
переводчик Python, которому не верят.

---

## 1. Верна ли находка

Сверено по стволу `dev` `dab63b2a5` (двоичный 0.8.0) — чтением кода и документов, без догадок.

| что нужно для `int` Python | что есть в языке | годится ли |
|---|---|---|
| целое без верхней границы | `точное целое` (ADR-0036) | без знака: `[1] минус [2]` — отказ «точное целое ниже нуля значений не имеет» |
| знак | `целое`, `i64` и другие слова | у всех есть потолок: `целое` — до 2⁵³ − 1, `i64` — до 2⁶³ − 1 |
| частное с округлением вниз (`//`) | `делить на` над `точное целое` | не определено — отказ проверки типов; частное даёт только дробь, а перевести вычисленное точное целое в дробь нечем (ADR-0062 §2 п. 4) |
| остаток со знаком делителя (`%`) | `остаток от` над `точное целое` (ADR-0062 §2 п. 7) | знака нет, значит и вопроса о знаке остатка нет |
| частное и остаток слов | `делить на`, `остаток от` над `i64` | округляют к нулю, а не вниз: `i32 -7` на `i32 2` — `-3`, в Python `-4` |

Значит находка верна в полном объёме: ни один тип языка не даёт одновременно знака, отсутствия
потолка и деления с округлением вниз. Переводчик выбрал `число` потому, что из всех типов только у
него есть и знак, и `делить на`, и `остаток от` — ценой точности за 2⁵³.

## 2. Решение

1. **Новый тип `точное целое со знаком`** (en `exact signed integer`, eo `preciza entjero kun signo`,
   zh `精确有符号整数`; падежи `точного целого со знаком`, `точным целым со знаком`). Значение —
   любое целое число со знаком, без верхней и нижней границы.
2. **Внутри компилятора это слово без ширины.** Проверка типов держит его тем же видом, что `u8` …
   `i64`, — `«Вид слова»` с шириной 0 и знаком. Отсюда даром приходит всё, что слова уже умеют:
   тип ни с чем не смешивается без перевода; числовой литерал рядом с ним берёт его тип
   (`а плюс 1`, `б не равен 0`); перевод формой `точное целое со знаком x` из числа, слова или
   литерала-строки цифр; место деления помечается как обязательство «делитель не ноль».
   Ширина 0 значит «без потолка»: побитовые действия, сдвиги, повороты, `с переполнением` и
   `с двойной разрядностью` над ним отвергаются проверкой типов.
3. **Запись значения.** `точное целое со знаком -7`, `точное целое со знаком "-1180591620717411303424"`
   (строка цифр — для чисел за 2⁵³), в примерах — так же. Перевод числа точен для любого целого
   числа двойной точности; дробное число — отказ `FLANG_OVERFLOW`: «1.5 не целое и в точное целое со
   знаком не переводится».
4. **Действия.** `плюс`, `минус`, `умножить на` — точно, без переполнения. `делить на` и `остаток от`
   **округляют вниз**, как `//` и `%` в Python: остаток несёт знак делителя, `−7 делить на 2` — `−4`,
   `−7 остаток от 2` — `1`, `7 остаток от −2` — `−1`. Сравнения — по значению. `к числу` — точное
   число, если модуль не больше 2⁵³ − 1, иначе отказ `FLANG_OVERFLOW`; `к строке` — десятичная запись.
5. **Деление на ноль — обязательство, а не значение.** Проверка типов помечает каждое место
   `делить на` и `остаток от` над этим типом; доказанным оно считается при делителе-литерале не ноль,
   при сравнении имени делителя с нулём в ветви и при `требует`. Недоказанное место в тотальной
   функции — `FLANG_NOT_TOTAL` (сегодня предупреждение, с `--proof --strict` — ошибка). При работе
   деление на ноль — отказ `FLANG_PROPERTY`: «точное целое со знаком: «div» на ноль не определено».
6. **Вычислитель** держит значение знаком и модулем — разрядами по основанию 2²², как точное целое, и
   считает их теми же функциями сложения, вычитания, умножения и деления разрядов.
7. **Печать в цели.** Вызов формы печатается помощником каждой цели (`fl_b_signed`, `BSigned`,
   `bSigned`, `b_signed`, `$b_signed`); C++ берёт рантайм у C, TypeScript — у JavaScript. Значение
   живёт в виде слова своей цели: в JavaScript — `BigInt`, в Python и Elixir — родное целое, в Go,
   Java и C# — большие целые стандартной библиотеки, в C и Rust — знак и разряды самого рантайма.

## 3. Что доказывает ядро

Ничего нового этим решением. Ядро не знает имени `точное целое со знаком`, поэтому:

- утверждение о нём, которое ядро не выводит, остаётся «объявлено, не доказано» — ложного «доказано»
  быть не может;
- законы кольца (ADR-0095) правилом ядра выводятся только над `точное целое`. Над ℤ они тоже верны,
  и включить новый тип в то же правило — отдельная правка ядра, сверщика на C и леммы Lean; здесь она
  не сделана и названа долгом;
- закон деления с остатком `а = б · (а делить на б) плюс (а остаток от б)` при `б` не ноль и знак
  остатка ядром не выводятся: это новое правило, его цена — строка ведомости вывода, теорема Lean и
  переигровка в сверщике на C.

## 4. Что отвергнуто

- **Дать знак самому `точному целому`.** Отвергнуто: тип принят владельцем без знака (ADR-0036),
  дробь построена на нём как ℚ≥0 (ADR-0062), а ядро в линейной арифметике и в «неотрицательности по
  построению» полагается на то, что вычитание ниже нуля отказывает. Знак поменял бы смысл
  доказанного.
- **Переводчик Python сам собирает целое со знаком из пары «знак, точное целое».** Отвергнуто
  решением владельца: деление нужно языку, а не одному переводчику; к тому же частное точных целых
  словами языка не записать (§1).
- **Округление к нулю, как у слов.** Отвергнуто: целью решения названа точность перевода `int` Python,
  а Python округляет вниз. Слова фиксированной ширины свою семантику сохраняют.
- **Отдельное слово `делить нацело`.** Отвергнуто: у нового типа нет второго деления, с которым его
  можно спутать, а новое слово стоило бы четырёх поверхностей лексера.

## 5. Порядок ввода

По правилу «ввести слово и применить его — разные изменения» (AGENTS.md): эта правка вводит тип в
исходники компилятора и нигде в дереве его не применяет. Семенной двоичный 0.8.0 слова не знает;
проверяется оно исходниками компилятора (`flang/self/bootstrap/check-with-source-compiler.flang`),
набор проб — `flang/proof/probes/signed-integer/`. Переводчик Python переводит `int` в новый тип
отдельной правкой после печати семени 0.9.0: проверка перевода в CI идёт семенным двоичным.

У этого перевода есть цена, и её надо назвать до него. Завершение рекурсии над `int` в корпусе
переводчика ядро доказывает сегодня над `число` («постоянный шаг» у `factorial`, `fib`, `power`,
«шаг Евклида» у `gcd` — `flang/foreign/python/corpus/expected.tsv`). Имени нового типа ядро не знает
(§3), поэтому такие функции после перевода, по всей видимости, станут нетотальными, пока ядро не
научится мере над ним. Это не замерено: замер возможен только двоичным, знающим тип.
Кроме того, номер элемента, длина списка и `range` в языке — `число`: на каждом таком месте
переводчику придётся ставить перевод `к числу` или `точное целое со знаком (…)`.

## 6. Как проверить

- **Вычислитель — примерами в самом `interpret.flang`.** `bootstrap/flang check flang/self/interpret.flang`
  семенным двоичным 0.8.0 считает их: `−7 делить на 2` → `−4`, `−7 остаток от 2` → `1`,
  `7 остаток от −2` → `−1`, `−6 делить на 2` → `−3`, деление на ноль — отказ `FLANG_PROPERTY`,
  2⁶⁰ из числа — разряды `[0, 0, 65536]`, `2⁵³ + 1` в десятичной записи — `9007199254740993`,
  строка `"12а"` — отказ. Проверка файла — код 0.
- **Язык целиком — набор `flang/proof/probes/signed-integer/programs/`**: деление вниз, большие числа
  за 2⁶⁴, сравнение и запись (`floor-division.flang`); те же примеры с подделанными ожиданиями,
  которые обязаны упасть (`floor-division-forged.flang`); деление на ноль при работе и недоказанный
  делитель в тотальной функции (`zero-divisor.flang`); смесь с числом, побитовое и, сдвиг
  (`refusals.flang`). Каждая программа зовёт компилятор из исходников:
  `bootstrap/flang run --trust --max-steps 400000000000 --function "Свод" <программа>`.
  **Не замерено:** под потолком адресного пространства 48 ГиБ прогон умирает с `FLANG_MEMORY` на
  связывании исходников (пик занятой памяти 24,3 ГиБ, 591 с). Таблицы ожиданий поэтому нет: ожидание
  — замер, а не предсказание. После печати семени 0.9.0 те же тексты проверяются обычным
  `flang check` за секунды.
- **Рантаймы целей** собраны своими компиляторами с флагами дерева и прогнаны водителями, которые
  зовут помощников напрямую; водители лежат вне дерева, числа — в описании запроса слияния.
