## Сборка сайта

`node docs/site/build.mjs --check` на входе отказывал двумя бедами базы знаний,
обе унаследованы от `gh/dev`: `[[version-string-drifts-every-release]]` — заметка
без цели (сосед убран из заметки); `[[имя]]` — заголовок коммита в `CHANGELOG.md`
о TOML-таблицах, который разметка принимала за ссылку базы знаний. Починено в
`docs/site/markdown.mjs` и `build.mjs`: на странице, напечатанной из
`CHANGELOG.md`, двойные скобки остаются текстом (ключ `ссылкиБазы`); на прочих
страницах разбор не изменился.

**Ссылки по собранному сайту.** Владелец нашёл 404 на
`…/flang/examples/crypto`. Замер сканером по `docs/site/out/**/*.html` (каждый
`href` и `src`, кроме внешних, считанный от каталога страницы, как считает
браузер): **904 битых из 59 120 на 47 страницах** — 777 ссылок `.md` (666 из
них на указателе базы знаний: соседи печатались как `слаг.md`), 70 файлов дерева
(`flang/SPEC.md`, `README.md`, `fspec/*.flang`), 57 каталогов (`examples/*`,
`fspec/*`, `flang/stdlib/`); отдельно — ссылки `[[слаг]]` с английских страниц
(`en/`) без `../`. Причина: сборка проверяла, что цель ссылки есть в дереве, и
печатала href как в исходнике. Починено в `docs/site/build.mjs`: ссылка на файл,
из которого собрана страница сайта, печатается адресом страницы; на любой другой
файл или каталог дерева — адресом на GitHub (`…/tree/main/<путь>` для каталога,
`…/blob/main/<путь>` для файла; корень берётся из `package.json`); заметка со
страницы в подкаталоге — через `../`. Сторож заведён там же: после сборки каждый
`href`/`src` каждой страницы обязан вести на страницу или файл сборки, иначе
`node docs/site/build.mjs --check` (и сборка) отказывает «на собранном сайте
ссылка ведёт в никуда». После починки тот же сканер по `out/`: **0 битых из
59 120**.
