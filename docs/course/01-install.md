# Установка и первая проверка

Ставить flang можно четырьмя путями, и — **это изменилось** — все четыре дают
один и тот же компилятор.

| Путь | Что ставит | Печатает в | Вывод | Нужно на машине |
| --- | --- | --- | --- | --- |
| Homebrew | двоичный `flang` + `man flang` | все восемь целей | словами | `brew`, `cc`, `make` |
| asdf / mise | тот же двоичный | все восемь целей | словами | `asdf`, `cc`, `make` |
| Из исходников | тот же двоичный | все восемь целей | словами | `git`, `cc`, `make` |
| npm | запускатель + тот же двоичный | все восемь целей | словами | Node ≥ 20 |

**Прошлая редакция этой главы говорила иначе**, и разницу стоит назвать, потому
что она отменяет три места в курсе. Там было написано: первые три пути дают
двоичный, который печатает только в C, а npm даёт **вторую реализацию** — на
Node, с выводом в JSON и с проверками, которых в двоичном нет.

Второй реализации больше нет. Команда `flang` из пакета npm — это
`packaging/flang-launch.mjs`, двадцать строк, которые запускают **тот же
двоичный** и отдают его код возврата. В самом файле написано и почему без
молчаливого отката на Node:

> две программы под одним именем, расходящиеся в мелочах, — 54 расхождения из
> 59 вызовов

Цена этого запускателя названа там же: один запуск Node поверх двоичного — 36 мс
против 956 мс, которые двоичный тратит на `check flang/stdlib/lists.flang`, то
есть 3,8 %.

## Homebrew

```bash
brew install digitable-lol/tap/flang
```

Ставит `flang`, `libcompiler_flang.a`, заголовки и страницу `man flang`. Node не
нужен: в архиве релиза лежит готовый C99.

**И ещё одно, чего не надо узнавать самому через неделю.** Выпуск 0.5.0 на macOS
не собирался вовсе — ни у кого. В `flang_repl.c` объявлен `_POSIX_C_SOURCE
200809L`; на glibc эта строка `mkdtemp` открывает, а на Darwin закрывает, и
сборка с `-Werror` останавливается. Починено в 0.5.1. Если у вас macOS —
ставьте не ниже 0.5.1.

## Из исходников — путь, который проверен в этом курсе полностью

```bash
git clone https://github.com/digitable-lol/flang.git
cd flang
make -C bootstrap -j4
```

Вот что этот прогон дал:

```
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o flang_runtime.o flang_runtime.c
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o compiler_flang.o compiler_flang.c
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o flang_cli.o flang_cli.c
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o flang_repl.o flang_repl.c
ar rcs libcompiler_flang.a flang_runtime.o compiler_flang.o
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto -o flang flang_cli.o flang_repl.o flang_runtime.o compiler_flang.o -lm -lpthread
```

**64 секунды по стенным часам**, на выходе — `bootstrap/flang` размером
**14 068 112 байт**. Node при этом не нужен: компилятор flang уже написан на
flang и напечатан в C, а C собирается чем угодно.

*Снято 27 августа 2026 на дереве `d363b1e5`, `make -j4`. Прошлая редакция главы
называла 8 392 296 байт: двоичный вырос в 1,68 раза. Четыре строки `cc` вместо
трёх — не изменение сборки, а поправка: `flang_runtime.c` компилировался и
тогда, просто в расшифровку не попал.*

Поставить в систему — `sudo make -C bootstrap install` (или
`PREFIX=$HOME/.local make -C bootstrap install`, без `sudo`). Снять —
`make -C bootstrap uninstall`.

Дальше в курсе команда пишется просто `flang`. Если вы не ставили её в систему,
подставляйте путь к собранному файлу.

## Через npm

```bash
npm install git+https://github.com/digitable-lol/flang.git
```

В `node_modules/.bin/` появляются два файла: `flang` и `flang-lsp` (языковой
сервер для редактора) — это ровно то, что объявлено в `package.json` полем `bin`.
Своих зависимостей у пакета нет ни одной: в `package.json` нет ни
`dependencies`, ни `devDependencies`.

**И главное про этот путь: `flang` отсюда — не программа на Node.** Это
двадцать строк, которые находят двоичный и запускают его, отдавая его же код
возврата. Если двоичного при установке не собрали, здесь **отказ с названной
причиной и код 3** — «чините машину», — а не тихая подмена компилятора.

*Расшифровку `npm install` эта глава больше не показывает: прошлая редакция
приводила её как «прогон при подготовке курса», а переснять её на этой машине
нечем — установка ходит в сеть.*

Из реестра npm пока не поставить: под именем `@digitable-lol/flang` ещё ничего
не выложено. Ставится только из git.

## Проверка, что поставилось

```bash
flang --version
```

```
flang 0.6.2
```

Через npm — **ровно то же самое**, потому что отвечает тот же двоичный. Прошлая
редакция главы обещала здесь короткий ответ `0.5.0` без слова `flang`; это была
строка второй реализации, и её больше нет.

Число здесь будет ваше — оно зависит от того, какой выпуск вы взяли.

```bash
flang --help
```

```
flang 0.6.2 — язык, проверяемый до запуска: типы и доказанное завершение.

  flang                              оболочка: объявляй и считай сразу
  flang check <файл>                 разбор, типы, завершаемость, доказательства
  flang test <файл|каталог>          прогон примеров: один файл или весь корпус
  flang run <файл> --function «Имя»  вычислить одну функцию и напечатать значение
  flang emit <файл> --target «цель»  напечатать программу: c|go|rust|java|js|elixir|python|csharp
  flang ast <файл>                   разобранная программа деревом в JSON
  flang tokens <файл>                поток токенов: чем каждое слово стало у лексера
  flang facts <файл> --claims '[…]'  проверить утверждения на фактах

  flang --help                       эта справка

```

**Эта справка сверена со `flang --help` слово в слово 27 августа 2026.** Из
двенадцати строк, которые цитировала прошлая редакция главы, разошлись четыре:

```
было   flang test <файл>              прогон примеров, объявленных внутри функций
стало  flang test <файл|каталог>      прогон примеров: один файл или весь корпус

было   flang emit <файл> --target c   напечатать программу в C99
стало  flang emit <файл> --target «цель»
                                      напечатать программу: c|go|rust|java|js|elixir|python|csharp

добавилось  flang tokens <файл>       поток токенов: чем каждое слово стало у лексера
добавилось  flang --mcp-mode          служба для ИИ-помощника (MCP по стандартным потокам)
```

Обратите внимание на строку `emit`: **целей восемь, а не одна.** На этом стояла
целая глава курса, и её пришлось переписать — [глава про восемь
целей](09-eight-targets.md).

У справки есть и хвост, который прошлая редакция не показывала вовсе, а он
важнее списка команд:

```
Без доводов и без терминала на входе (конвейер, «--json») бинарник остаётся
прогонщиком: JSON на входе, JSON на выходе, по запросу на строку.

Здесь все 12 команд, и «flang lsp» среди них; отдельная команда «flang-lsp» —
тот же языковой сервер, который кладёт на «PATH» пакет npm.
Служба для ИИ-помощника отвечает НЕ «ок»: три вердикта — «доказано», «сетка N»
и «объявлено, не доказано» — уходят порознь.
```

Первый абзац — [ловушка из главы 02](02-first-program.md): голая команда с
конвейером открывает не оболочку.

## Три расхождения, которых больше нет, и одна граница, которая осталась

Прошлая редакция главы называла здесь три места, где инструментарий на Node
отвечал иначе, чем двоичный. Все три сняты — не тем, что их починили, а тем, что
второй реализации не стало. Перечислить их всё-таки стоит: по этим расхождениям
написаны целые главы курса, и читатель, нашедший их в старых заметках, должен
знать, что случилось.

| было расхождение | что с ним сегодня |
| --- | --- |
| **форма вывода**: двоичный словами, Node в JSON | нет: отвечает двоичный, словами. JSON у него тоже есть — по ключу `--json` |
| **восемь целей против одной**: `--target go` только через npm | нет: все восемь печатает двоичный, снято прогоном в [главе 09](09-eight-targets.md) |
| **слово «сетка»**: «НЕ ИСКАЛИ» против «искали прогоном» | нет: осталась одна формулировка, [глава 05](05-promise.md) |

**А граница осталась одна, и она серьёзнее всех трёх.** Проверка, которая ловит
рассогласование двух модулей (та самая, ради которой в языке заведена категорная
поверхность), в двоичном не реализована. Слово `FUNCTOR` встречается в его
исходнике ноль раз:

```bash
grep -c FUNCTOR bootstrap/compiler_flang.c
```

```
0
```

Прежде это лечилось словами «ставьте npm». Сегодня лечить нечем: судьи этих
объявлений нет ни в одной реализации. **Зато компилятор перестал молчать.** На
программе с категорными объявлениями он отвечает не «замечаний нет» и не кодом 0,
а «проверено НЕ ДО КОНЦА» и **кодом 2**, и перечисляет поимённо, чего не судил.
Разбор — в [главе про функторы](10-functor.md).

Отсюда одно правило, которое стоит унести из этой главы:

> **Читайте код возврата, а не последнюю строку.** `0` — проверено. `1` —
> нашлась беда в предмете. `2` — проверено не всё.

## Что дальше в курсе понадобится

**Хватает любого одного пути.** Прошлая редакция главы просила поставить два —
двоичный для глав 02–08 и 10–12, npm для главы 09 и полного разбора главы 10.
Больше не нужно: это один и тот же компилятор. Для главы 09 понадобятся
тулчейны тех языков, в которые будете печатать, — но не второй flang.

## Задача

Поставьте flang любым путём и выполните три команды:

```bash
flang --version
flang --help
```

**Проверка:** `flang --version` печатает строку вида `flang 0.6.x` и возвращает
код 0. Проверить код возврата:

```bash
flang --version > /dev/null; echo $?
```

```
0
```

Если код 1 — установка не дошла до конца, и до следующей главы идти незачем.
