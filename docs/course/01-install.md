# Установка и первая проверка

Ставить flang можно тремя путями, и все три дают один и тот же компилятор —
двоичный файл `flang`.

| Путь | Что ставит | Печатает в | Вывод | Нужно на машине |
| --- | --- | --- | --- | --- |
| Homebrew | двоичный `flang` + `man flang` | все десять целей | словами | `brew`, `cc`, `make` |
| asdf / mise | тот же двоичный | все десять целей | словами | `asdf`, `cc`, `make` |
| Из исходников | тот же двоичный | все десять целей | словами | `git`, `cc`, `make` |

Пути через npm нет: в дереве нет `package.json`, и
`npm install git+https://github.com/digitable-lol/flang.git` ничего не ставит.
Под именем `@digitable-lol/flang` в реестре npm ничего не выложено.

## Homebrew

```bash
brew install digitable-lol/tap/flang
```

Ставит `flang`, `libcompiler_flang.a`, заголовки и страницу `man flang`. Node не
нужен: в архиве релиза лежит готовый C99.

## Из исходников — путь, который проверен в этом курсе полностью

```bash
git clone https://github.com/digitable-lol/flang.git
cd flang
make -C bootstrap -j4
```

Вот что этот прогон дал:

```
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o flang_runtime.o flang_runtime.c
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o compiler_flang.o compiler_flang.c
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o flang_cli.o flang_cli.c
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o flang_repl.o flang_repl.c
ar rcs libcompiler_flang.a flang_runtime.o compiler_flang.o
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto -o flang flang_cli.o flang_repl.o flang_runtime.o compiler_flang.o -lm -lpthread
```

На выходе — `bootstrap/flang`, около 25 МБ. Node при этом не нужен: компилятор
flang уже написан на flang и напечатан в C, а C собирается чем угодно.

Поставить в систему — `sudo make -C bootstrap install` (или
`PREFIX=$HOME/.local make -C bootstrap install`, без `sudo`). Снять —
`make -C bootstrap uninstall`.

Дальше в курсе команда пишется просто `flang`. Если вы не ставили её в систему,
подставляйте путь к собранному файлу.

## Проверка, что поставилось

```bash
flang --version
```

```

оболочка 9f361fce: правит строку (стрелки, слова, история, Tab), цвет digitable
```

Вторая строка называет сборку оболочки, которая правит ввод.

## Граница, которая осталась

Проверка, которая ловит
рассогласование двух модулей (та самая, ради которой в языке заведена категорная
поверхность), в двоичном не реализована. Слово `FUNCTOR` встречается в его
исходнике ноль раз:

```bash
grep -c FUNCTOR bootstrap/compiler_flang.c
```

```
0
```

Судьи этих объявлений нет. **Зато компилятор не молчит.** На
программе с категорными объявлениями он отвечает не «замечаний нет» и не кодом 0,
а «проверено НЕ ДО КОНЦА» и **кодом 2**, и перечисляет поимённо, чего не судил.
Разбор — в [главе про функторы](10-functor.md).

Отсюда одно правило, которое стоит унести из этой главы:

> **Читайте код возврата, а не последнюю строку.** `0` — проверено. `1` —
> нашлась беда в предмете. `2` — проверено не всё.

## Что дальше в курсе понадобится

**Хватает любого одного пути**: это один и тот же компилятор. Для главы 09
понадобятся тулчейны тех языков, в которые будете печатать, — но не второй
flang.

## Задача

Поставьте flang любым путём и выполните три команды:

```bash
flang --version
flang --help
```

**Проверка:** `flang --version` печатает строку вида `flang 0.7.x` и возвращает
код 0. Проверить код возврата:

```bash
flang --version > /dev/null; echo $?
```

```
0
```

Если код 1 — установка не дошла до конца, и до следующей главы идти незачем.
