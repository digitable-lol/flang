# Первая программа

Наберите файл `hello.flang`:

```flang
модуль «Привет»

тотальная функция «Удвоить»
  принимает н: нат
  возвращает число
  обеспечивает «удвоенное не меньше исходного» результат не меньше н
  пример «дважды два»
    дано н равно 2
    ожидается 4
  н плюс н
```

Девять строк, и в них видно почти всё, что делает язык непохожим на другие.

## Пять частей, и каждая делает свою работу

**`модуль «Привет»`** — первая строка файла, всегда. Имя в ёлочках, потому что
имя в flang — это фраза, а не идентификатор: `«Место вставки»`, `«Есть повторы»`,
`«Отменённый заказ»`. Пробелы внутри имени законны.

**`тотальная`** — обещание, что функция завершается на любом входе. Компилятор
его **проверяет**. Не доказал — файл не собирается. Это главное решение языка, и
ему отведена [следующая глава](03-totality.md).

**`принимает` / `возвращает`** — типы. Обязательны, выводом не заменяются. `нат`
здесь выбран не для красоты: это отрезок `[0, 2⁵³−1]`, у которого есть оба конца
и целость. Поставьте на его место `число` — и файл перестанет собираться;
почему, разобрано ниже и составляет половину этой главы.

**`обеспечивает`** — обещание про результат. Имя в ёлочках обязательно: по нему
утверждение находят в отчёте о доказательствах.

**`пример`** — исполняемый пример. Он **часть программы**, а не тест сбоку, и
прогоняется при каждой проверке. Не сошёлся — `check` отвечает `FLANG_EXAMPLE` и
ненулевым кодом, и печатать такую программу компилятор откажется.

**Тело** — последней строкой, одной формой. Здесь `н плюс н`.

## Три команды

### Проверить

```bash
flang check hello.flang
```

```
модуль «Привет»: функций 1, из них с доказанным завершением 1; типов 0
hello.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Код возврата 0. За этой строкой стоит пять работ: разбор, проверка типов,
доказательство завершения, ядро доказательств и **прогон примеров**. Последнее
стоит отметить: в других языках «скомпилировалось» и «тесты прошли» — два разных
события. Здесь одно.

### Прогнать примеры отдельно

```bash
flang test hello.flang
```

```
hello.flang: примеров 1, прошло 1, не прошло 0
```

### Запустить

```bash
flang run hello.flang --function Удвоить --args '{"н": 21}'
```

```
42
```

Имя функции здесь **без ёлочек**: в объявлении они часть записи, в командной
строке — уже нет. `--args` берёт плоский объект JSON: ключ — имя параметра ровно
так, как оно написано в `принимает`.

## Теперь то, ради чего эта глава написана

Поменяйте в подписи **одно слово**: `нат` на `число`.

```flang
// ОЖИДАЕТСЯ ОТКАЗ: этот блок НЕ собирается, и в этом вся глава.
модуль «Привет»

тотальная функция «Удвоить»
  принимает н: число
  возвращает число
  обеспечивает «удвоенное не меньше исходного» результат не меньше н
  пример «дважды два»
    дано н равно 2
    ожидается 4
  н плюс н
```

```bash
flang check hello.flang
```

```
модуль «Привет»: функций 1, из них с доказанным завершением 1; типов 0
hello.flang: не проверено — замечаний 1
```

Код возврата 1, и замечание вот такое:

```
FLANG_BOUND_ON_NAN в файле hello.flang, строка 6, столбец 3: постусловие
«удвоенное не меньше исходного» функции «Удвоить» ЛОЖНО, и контрпример назван:
«н» объявлен типом «число», а «не число» живёт в этом типе и стоит ВНЕ ПОРЯДКА —
оно не больше и не меньше ничего, включая самоё себя. Тело собрано только из
арифметики над «н», а всякая арифметическая операция «не число» переносит,
значит результат есть «не число», и сравнение с ним ложно. Позовите «Удвоить»
от (0 делить на 0) — рантайм ответит FLANG_PROPERTY. Чинится тремя способами:
объявить вход отрезком («нат», «целое») — тогда «не число» не втащить вовсе;
поставить предусловие — за него платит вызывающий; либо оговорить границу, и
ядро оговорку читает: обеспечьте «не ((н минус н) равен 0) или (…)»
```

Прочитайте это ещё раз, потому что здесь три разные вещи сразу.

**Первое: обещание не «не доказано», а ЛОЖНО.** Ядро не пожало плечами — оно
**опровергло** написанное.

**Второе: контрпример назван, и он не выдуман.** `не число` (оно же `NaN`) —
законное значение типа `число`, и оно **вне порядка**: `NaN не меньше NaN` —
ложь, `NaN не больше NaN` — тоже ложь. Удвоение `не числа` даёт `не число`,
значит «результат не меньше н» на нём ложно. Отказ даже говорит, каким вызовом
это увидеть.

**Третье: названы три починки.** Не «ошибка компилятора, которую надо
погуглить» — перечень допустимых ходов, и починка всегда в нём.

### Эта глава раньше учила обратному, и это стоит сказать вслух

До выпуска `0.6.x` та же программа проверку **проходила**. Глава была построена
на этом: `flang check` отвечал «замечаний нет», а обещание в программе было
ложью, и увидеть это можно было только отчётом `--proof`. Мораль была «`валидно`
и `доказано` — разные слова».

Сегодня компилятор ловит ровно то, про что глава писала «`flang check` этого не
сказал». Пример, выбранный как показательный, перестал быть показательным — не
потому, что кто-то ошибся, а потому, что **язык догнал свой учебник**. Мораль от
этого не отменилась, а стала дешевле: её теперь говорит сам `check`, без ключей.

## Три починки, названные самим отказом

### Первая: объявить вход отрезком

Это та программа, с которой глава началась, — `нат` вместо `число`. Проверка
проходит. Но отчёт доказательства говорит не то, чего ждёшь:

```bash
flang check hello.flang --proof
```

```
постусловие «удвоенное не меньше исходного» функции «Удвоить» — сетка 1 значение
(примеры функции): нарушений НЕ ИСКАЛИ — прогона примеров не было, посчитано
только их число. Это не доказательство — теоремы при утверждении нет
```

и итог:

```
утверждений 1: доказано 0, сетка 1, объявлено, не доказано 0
```

**Доказано 0.** Утверждение стало **правдой** — на отрезке `[0, 2⁵³−1]` удвоение
и вправду не меньше исходного, — но доказанным не стало: у ядра нет правила на
цель вида «результат не меньше <выражение>». Это не оговорка и не случай — это
измеренная граница, и [глава про цену](06-cost.md) называет её числом.

Обратите внимание и на слова «нарушений **НЕ ИСКАЛИ**». «Сетка 1» здесь — это
буквально счёт примеров, а не их прогон.

### Вторая: сказать то, на что правило есть

```flang
модуль «Привет»

тотальная функция «Удвоить»
  принимает н: нат
  возвращает число
  обеспечивает «удвоенное неотрицательно» результат не меньше 0
  пример «дважды два»
    дано н равно 2
    ожидается 4
  н плюс н
```

```
постусловие «удвоенное неотрицательно» функции «Удвоить» — доказано по
объявленным типам аргументов: цель сведена правилом «неотрицательность по
построению» — утверждение обо ВСЕХ входах, а не о написанных; теоремы при нём
нет и не нужно
```

```
утверждений 1: доказано 1 (из них без теоремы 1, объявленным типом 1), сетка 0,
объявлено, не доказано 0
```

Вот теперь **доказано обо всех входах**. Ценой того, что обещание стало слабее:
«неотрицательно» говорит о функции меньше, чем «не меньше исходного».

Этот размен — «сказать слабее и получить доказательство» против «сказать сильнее
и получить сетку» — вы будете делать в flang постоянно. Он честно назван в
[замере цены](06-cost.md): из шести утверждений, которые ядро закрыло даром,
содержательными оказались два, а четыре пришлось ослабить.

### Третья: предусловие, за которое платит вызывающий

Оставить вход `число`, но потребовать от вызывающего, чтобы `не число` он не
приносил. Как это пишется и во что обходится — [глава про
обещания](05-promise.md): предусловие в напечатанном коде стоит **ноль байт**,
потому что к моменту вызова оно уже доказано.

## Отсюда первое правило работы с flang

> `flang check` без ключей отвечает на вопрос «эта программа собирается?» — и с
> `0.6.x` этот вопрос включает «а обещания в ней не ложны?». На вопрос «а чем
> именно несётся каждое обещание — доказательством или счётом на сетке?»
> отвечает `flang check --proof`, и отвечает числом.

Курс дальше почти везде показывает `--proof`. Привыкайте смотреть на строку
`утверждений N: доказано M`.

## Оболочка

Голая команда открывает оболочку — как `python`, как `iex`:

```bash
flang
```

```
flang 0.6.2 — оболочка. «.помощь» — команды, «.выход» или Ctrl-D — конец.
```

**Вторая строка заставки зависит от того, лежит ли рядом с двоичным его
библиотека** — `libcompiler_flang.a`. Она появляется там при `make -C bootstrap`
вместе с самим двоичным. Если её нет — а так бывает, когда двоичный скопировали
куда-то один, — оболочка честно говорит об этом и **не считает**:

```
Объявление заканчивается пустой строкой; выражение проверяется, но не вычисляется — почему, сказано ниже.
вычислять нечем: не найден libcompiler_flang.a ($FLANG_LIB_DIR, ../lib или каталог самого бинарника).
Разбор, типы и завершаемость проверяются по-прежнему; выражение отвечает «проверено».
```

Это ровно тот вид отказа, ради которого стоит читать этот курс: инструмент не
делает вид, что посчитал, — он называет, чего ему не хватает, и говорит, что
именно продолжает работать. Ищите библиотеку рядом с двоичным или назовите её
каталог в `FLANG_LIB_DIR`.

**Ловушка, на которой легко потерять час.** Голая команда открывает оболочку
только тогда, когда на входе терминал. Если ввод пришёл конвейером или из файла,
двоичный становится совсем другой программой — прогонщиком запросов «JSON на
входе, JSON на выходе»:

```bash
echo "2 плюс 2" | flang
```

```
{"ok":false,"code":"CLI","message":"ожидался объект запроса"}
```

Это написано в его собственной справке и это не ошибка, а решение. Для сценария
нужна команда по имени:

```bash
echo "2 плюс 2" | flang repl
```

Так же загружается файл в сессию:

```bash
echo "«Удвоить» от 21" | flang repl hello.flang
```

```
объявлено: тотальная функция «Удвоить» — завершение доказано
загружено из hello.flang
```

Здесь ёлочки нужны — это уже текст на языке, а не аргумент команды.

*Обе расшифровки сняты 27 августа 2026 двоичным от 23 августа 16:00 UTC (дерево
не установлено, не новее `883fe9a9`). Значения выражений — `4` и `42` — прошлая
редакция главы показывала здесь как ответ оболочки; на двоичном, у которого нет
рядом библиотеки, вместо значения печатается слово «проверено», поэтому курс их
не показывает, а не переписывает по памяти.*

## Задача

Допишите в `hello.flang` вторую функцию — `«Утроить»` — так, чтобы выполнялись
три условия:

1. `flang check hello.flang` возвращает 0;
2. `flang check hello.flang --proof` печатает про неё строку со словом
   **«доказано»**, а не «сетка»;
3. утверждение при этом **говорит что-нибудь о функции**, а не повторяет её тело.

Третье условие — не придирка. Постусловие `результат равен (н плюс н плюс н)`
при теле `н плюс н плюс н` ядро принимает даром, и отчёт честно напишет
«доказано обо ВСЕХ входах». Это называется тавтологией, и это способ надуть
любую метрику доказуемости до любого размера. Разбор — в [главе про
цену](06-cost.md).

**Подсказка:** правил на форму цели у ядра ровно три — «не меньше 0», «не больше
конечного литерала», «равно». Ищите обещание, которое ложится в одно из трёх и
при этом не переписывает тело. Тип входа тоже ваш инструмент: `нат` говорит ядру
то, чего не говорит `число`.

**Проверка задачи:**

```bash
flang check hello.flang --proof | grep "утверждений"
```

Должно быть `доказано 2` при `утверждений 2`. Для этого «Удвоить» надо взять в
том виде, в каком она вышла из второй починки — с обещанием «удвоенное
неотрицательно»: с обещанием «не меньше исходного» её собственное утверждение
останется сеткой, и вы получите `доказано 1` при `утверждений 2`. Это тоже
законный ответ, просто про другую программу.
