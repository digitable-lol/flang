# Отличие первое: завершение доказывает компилятор

Полнота по Тьюрингу и гарантия завершения несовместимы. Либо язык умеет всё,
либо про любую его программу можно доказать, что она остановится. Обычно язык
выбирает одно.

**flang не выбирает, а делит программы на два класса, и класс проверяет
компилятор.**

Функция, помеченная словом `тотальная`, обязана доказать завершение. Функция без
пометки может рекурсировать как угодно. Оба класса законны, оба живут в одном
файле, и вызывать друг друга им можно — с одним ограничением, о котором ниже.

## Самый короткий пример в дереве

`examples/leetcode/217-contains-duplicate.flang` — двадцать шесть строк
вместе с комментарием:

```flang
модуль «Есть повторы»

тотальная функция «Есть повторы»
  принимает элементы: список числа
  возвращает признак
  пример «Пример 1 из условия»
    дано элементы равно [1, 2, 3, 1]
    ожидается да
  пример «Пример 2 из условия»
    дано элементы равно [1, 2, 3, 4]
    ожидается нет
  пример «Пример 3 из условия»
    дано элементы равно [1, 1, 1, 3, 3, 4, 3, 2, 4, 2]
    ожидается да
  разбор элементов
    случай пусто
      то нет
    случай голова и хвост
      если хвост содержит голова то да иначе «Есть повторы» от хвоста
```

```bash
flang check examples/leetcode/217-contains-duplicate.flang
```

```
модуль «Есть повторы»: функций 1, из них с доказанным завершением 1; типов 0
examples/leetcode/217-contains-duplicate.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Почему компилятор согласился: рекурсивный вызов получает **`хвост`** — часть того
значения, которое пришло на вход. Часть значения меньше значения по построению,
поэтому доказывать убывание отдельно не надо: оно следует из формы `разбор`.

Это и есть главный приём языка. Всё остальное — его развитие.

## Пять способов, которыми несётся обещание

Компилятор принимает пометку `тотальная` пятью разными доводами. Разница между
ними не academic: **три первых ничего не стоят при работе, два последних ставят
проверку в напечатанный код.**

Сводка по всему дереву языка. Пересчитать её можно одной командой:

```bash
./ярлык числа
```

Она перемеряет все числа страниц и кладёт их в `docs/site/numbers.json`. Вот что
там сейчас записано про завершаемость:

| что | сколько |
| --- | ---: |
| файлов | 322 |
| функций | 24 063 |
| из них тотальных | 19 694 |
| обычных | 4 369 |
| **тотальных, у которых при работе не проверяется ничего** | **19 109** |

| чем несётся обещание «тотальная» | сколько |
| --- | ---: |
| композицией (рекурсии нет) | 17 538 |
| структурой (часть значения) | 2 019 |
| точным шагом (`нат`, проверки нет) | 30 |
| постоянным шагом (число + проверка при работе) | 43 |
| объявленной мерой (+ проверка при работе) | 64 |

Проверок меры, оставшихся в напечатанном коде: **145 мест у 107 функций**.

*Числа взяты из `docs/site/numbers.json` — файла, который дерево перемеряет само
и сверяет отдельной проверкой. Последний пересчёт — коммит `252606e8`,
23 августа 2026. Прежняя редакция главы называла здесь 9687 функций и 7445
тотальных, снятые 20 августа: за три дня дерево вобрало в счёт вдвое больше
кода.*

Разберём таблицу.

### 1. Композицией — 17 538 функций

Рекурсии в функции нет вовсе. Тогда её завершение складывается из завершения
тех, кого она зовёт. Это самый частый случай — почти девять десятых всех
тотальных функций дерева, — и он не стоит ничего: ни строки в напечатанном
коде, ни такта при работе.

### 2. Структурой — 2019 функций

То, что вы видели у `«Есть повторы»`: рекурсия по части значения. Хвост списка
из образца `голова и хвост`, поле варианта из `разбор`, элемент коллекции.
Тоже бесплатно.

### 3. Точным шагом — 30 функций

Рекурсия по типу `нат` со спуском ровно на единицу. `нат` — это отрезок
`[0, 2⁵³−1]`, у него есть дно, и строгий спуск из отрезка с дном завершается.
Ядро читает спуск в теле функции, а не принимает на слово. Тоже бесплатно.

### 4. Постоянным шагом — 43 функции

Рекурсия по обычному числу с постоянным шагом вниз. Здесь доказательство неполно:
в вещественных числах оно верно, но числа языка — IEEE-754, и при большом
модуле `х минус 1` равно `х`. Поэтому в напечатанный код ставится **проверка при
работе**.

### 5. Объявленной мерой — 64 функции

Автор пишет `убывает <выражение>` и обещает, что это выражение падает. Компилятор
ставит проверку в напечатанный код.

**Цена этих двух способов названа числом:** проверка объявленной меры
**утраивает время функции**. Если рекурсию можно переписать под способы 1–3 —
переписывайте.

### Что означает последняя строка сводки

```
тотальных, у которых при работе не проверяется НИЧЕГО: 19 109 из 19 694
```

Это и есть ответ на вопрос «а что мне с этого». **19 109 функций дерева работают
без единой проверки завершения при работе** — их завершение доказано до запуска,
и в напечатанном коде от доказательства не осталось ни байта.

## Второе, что стоит знать: `тотальная` — это «завершится ИЛИ честно откажет»

Есть и второй род проверок при работе — **частичная форма**. Это встроенные
операции, определённые не на всех значениях своего типа: `голова` пустого
списка, `элемент` за концом, `к числу` от строки, которая числом не является.

Функция, зовущая такую операцию, остаётся тотальной — но на негодном входе она
**откажет значением**, а не зависнет и не бросит исключение. Исключений в языке
нет вовсе.

Разница между проверкой меры (145 мест у 107 функций) и частичной формой важна:
первое стоит там, где завершение **доказано**, и следить осталось только за
представлением чисел; второе — там, где о непустоте списка не доказано ничего.

## Что тотальная функция не может

Одно ограничение, и оно жёсткое: **тотальная функция не может звать обычную.**
Иначе обещание протекало бы вниз по графу вызовов и ничего не значило.

Обратное можно: обычная зовёт тотальную сколько угодно.

Проверяется это так — и отказ называет обе стороны:

```
FLANG_NOT_TOTAL … тотальная функция «Тотальная» вызывает обычную функцию
«Обычная»: обычная функция может не завершиться, и гарантия «Тотальная»
становится пустой. Пометьте «Обычная» как тотальную или снимите «тотальная» с
«Тотальная»
```

## Как это выглядит на смешанном файле

`examples/rosetta/quicksort.flang` держит оба класса в одном файле:

```bash
flang check examples/rosetta/quicksort.flang
```

```
модуль «Быстрая сортировка»: функций 5, из них с доказанным завершением 4; типов 0
без доказанного завершения: «Быстрая сортировка»
examples/rosetta/quicksort.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Вторая строка — новая: компилятор теперь **называет по имени** ту функцию,
которая осталась без доказанного завершения, а не оставляет читателя вычитать её
из разницы «5 и 4».

Четыре из пяти доказаны, пятая — быстрая сортировка — нет, и файл всё равно
собирается. Почему именно она не доказывается и что с этим делать — [следующая
глава](04-when-it-does-not-prove.md).

## Чего доказанное завершение НЕ говорит

Три вещи, которые легко приписать этому обещанию по ошибке:

1. **Не говорит, что функция быстрая.** Доказано, что она остановится; за
   сколько — не обещано ничем.
2. **Не говорит, что она правильная.** Тотальность — про остановку, не про
   ответ. Функция, всегда возвращающая ноль, тотальна.
3. **Не говорит, что она не откажет.** См. выше про частичную форму.

Первое отличие языка — про завершение и только про завершение. Про правильность
— [отличие второе](05-promise.md).

## Задача

Возьмите любой из 82 файлов в `examples/leetcode/` и ответьте на три
вопроса **командой**, а не чтением:

1. сколько в нём функций и сколько из них тотальных;
2. чем несётся обещание у каждой;
3. сколько проверок останется в напечатанном коде.

```bash
flang check examples/leetcode/104-maximum-depth-of-binary-tree.flang --proof
```

На этом файле ответ такой:

```
  функций 4: тотальных 4, обычных 0
  обещание несёт: композиция 2, структура 2, точный шаг 0, постоянный шаг 0, объявленная мера 0
  сторожей в рантайме: 0 мест
```

**Проверка:** найдите в `examples/` файл, у которого проверок при работе
больше нуля. Их немного — большинство примеров написано так, что при работе не
проверяется ничего. Ответ (не подглядывайте сразу): `measure/euclid.flang` — одно
место, `measure/binary-search.flang` — два. Оба из каталога `measure/`, и это не
совпадение: он весь про пятый способ, объявленную меру.
