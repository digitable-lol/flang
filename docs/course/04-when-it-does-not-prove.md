# Когда доказать не удалось

В прошлой главе всё получалось. Эта — про то, что бывает чаще.

## Как выглядит отказ

Возьмём быструю сортировку из дерева — `examples/rosetta/quicksort.flang`.
Её функция объявлена **обычной**, без пометки. Попробуем пометить её тотальной:

```bash
sed 's/^функция «Быстрая сортировка»/тотальная функция «Быстрая сортировка»/' \
    examples/rosetta/quicksort.flang > quicksort-total.flang
flang check quicksort-total.flang
```

```
модуль «Быстрая сортировка»: функций 5, из них с доказанным завершением 4; типов 0
без доказанного завершения: «Быстрая сортировка»
FLANG_NOT_TOTAL в файле quicksort-total.flang, строка 110, столбец 25: тотальная функция «Быстрая сортировка»: рекурсивный вызов «Быстрая сортировка» не убывает — аргумент 1 («меньшие») не выведен ни из одного параметра. Передавайте часть аргумента: хвост списка из образца «голова и хвост», поле варианта из образца, поле записи или элемент коллекции
FLANG_NOT_TOTAL в файле quicksort-total.flang, строка 111, столбец 26: тотальная функция «Быстрая сортировка»: рекурсивный вызов «Быстрая сортировка» не убывает — аргумент 1 («большие») не выведен ни из одного параметра. Передавайте часть аргумента: хвост списка из образца «голова и хвост», поле варианта из образца, поле записи или элемент коллекции
quicksort-total.flang: не проверено — замечаний 2
```

Код возврата 1.

Прочитайте диагностику внимательно — она устроена так, чтобы её можно было
исполнить:

- назван **вызов**, а не функция: строка и столбец указывают на место;
- назван **аргумент**, который не убывает: `«меньшие»`;
- названа **причина**: «не выведен ни из одного параметра». Список `меньшие`
  получен фильтрацией, а о размере отфильтрованного списка компилятору не
  известно ровно ничего;
- назван **список того, что принимается**: хвост из образца, поле варианта,
  поле записи, элемент коллекции.

Это не «ошибка компилятора, которую надо погуглить». Это перечень допустимых
форм, и починка всегда в нём.

## Выход первый: снять пометку

Самый частый и совершенно законный. Быстрая сортировка в дереве так и написана —
обычной функцией, и в шапке файла названа причина.

**Цена:** функция перестаёт быть доступна тотальным функциям. Всё, что её
зовёт, тоже становится обычным. Обещание не протекает вниз.

**Когда так и надо:** когда алгоритм действительно может не завершиться на
некоторых входах, и вы это знаете. Честная обычная функция лучше тотальной,
доказанной приёмом, который никто потом не поймёт.

## Выход второй: переписать `разбор`ом

Компилятор признаёт убывание, когда оно видно **в форме вызова**. Форма
`разбор` даёт это даром:

```
  разбор элементов
    случай пусто
      то ...
    случай голова и хвост
      то ... «Функция» от хвоста ...
```

`хвост` — часть `элементов` по построению, доказывать нечего.

**Цена:** переписывание. И она измерена: из 208 функций стандартной библиотеки
формой `разбор` по параметру написаны 58 — то есть **72 % кода написано
формами, к которым индукция не цепляется**. Это же число объясняет, почему
доказывать поведение в flang пока трудно, и [глава про цену](06-cost.md) на нём
и стоит.

## Выход третий: объявить меру

Появилось ради алгоритма Евклида, где убывание есть, но его не видно в форме
вызова: `а остаток от б` — не часть `б`, и шаг на каждом витке свой.

`examples/measure/euclid.flang`:

```flang
тотальная функция «НОД»
  принимает а: число, б: число
  возвращает число
  убывает б
  пример «Классическая пара»
    дано а равно 1071
    дано б равно 462
    ожидается 21
  если б равен 0
    то а
    иначе «НОД» от б и (а остаток от б)
```

Строка `убывает б` — обещание автора. Компилятор проверяет **форму** обещания
(мера объявлена у каждой функции цикла, она число, в ней одни параметры), а
само обещание проверяется **при работе**: на каждом витке мера обязана
строго убыть, не уйти ниже нуля и остаться целой.

Уберите строку `убывает б` — и получите:

```bash
grep -v '^  убывает б$' examples/measure/euclid.flang > euclid-bez-mery.flang
flang check euclid-bez-mery.flang
```

```
модуль «Евклид»: функций 2, из них с доказанным завершением 0; типов 0
без доказанного завершения: «НОД» «НОК»
FLANG_NOT_TOTAL в файле euclid-bez-mery.flang, строка 57, столбец 11: тотальная функция «НОД»: рекурсивный вызов «НОД» не убывает — аргумент 1 («б») — часть параметра «б», а сравнивается с параметром «а» на своей позиции; аргумент 2 («а» mod «б») не выведен ни из одного параметра. Передавайте часть аргумента: хвост списка из образца «голова и хвост», поле варианта из образца, поле записи или элемент коллекции
euclid-bez-mery.flang: не проверено — замечаний 1
```

Заодно видно цену: без меры теряется не одна функция, а две — «НОК» зовёт «НОД»,
и обещание не протекает вниз.

**Цена — две, и обе надо знать.**

**Первая: время.** Проверка меры стоит **утроение времени функции**. Мера — не
бесплатное объявление, а код, который выполняется на каждом витке.

**Вторая: обещание становится условным.** Мера проверяется, а не доказывается,
и на входе, где она не убывает, функция **откажет**:

```bash
flang run examples/measure/euclid.flang --function НОД \
  --args '{"а": 1.6180339887, "б": 1}'
```

```
FLANG_MEASURE: тотальная функция «НОД»: мера на вызове «НОД» — «б» — перестала быть целой. Целость — это то, чем мера вообще что-то доказывает: строго убывающая цепочка целых неотрицательных чисел не длиннее своего первого члена, а дробная не обрывается вовсе (0.618, 0.382, 0.236 … больше нуля всегда). Отказ здесь честнее зацикливания
```

На дробных числах алгоритм Евклида действительно не заканчивается — остатки
пары (φ, 1) идут 0.618, 0.382, 0.236 … и не кончаются никогда. Отказ здесь —
правильный ответ, а не изъян инструмента.

## Выход четвёртый: топливо

Приём, который стоит знать, потому что вы встретите его в дереве. Рядом с
настоящими аргументами едет список, у которого на каждом шаге берётся хвост.
Топливо убывает структурно, значит цикл доказуемо конечен.

`examples/leetcode/704-binary-search.flang` написан так: двоичный поиск
сужает пару чисел, убывание по числам не признаётся, и топливом служит сам
список — шагов заведомо хватает, их нужно log₂n, а есть n.

**Цена:** лишний параметр в подписи функции, который к задаче не относится.

**Оговорка, которую стоит проверить самому.** В шапке `704-binary-search.flang`
написано «в языке не хватает убывания по мере». Это было верно, когда файл
писали, и **больше не верно**: убывание по мере в языке есть, и тот же двоичный
поиск написан через него в `examples/measure/binary-search.flang` строкой
`убывает верх минус низ плюс 1`. Два файла в одном дереве решают одну задачу
двумя приёмами — сравните их, это лучшее упражнение по этой главе.

## Сводка: что выбрать

| Выход | Цена при работе | Цена в коде | Когда |
| --- | --- | --- | --- |
| снять пометку | нет | функция закрыта для тотальных | алгоритм правда может не кончиться |
| переписать `разбор`ом | нет | переписывание | почти всегда, если получается |
| объявить меру | время ×3 | одна строка | убывание есть, но не в форме вызова |
| топливо | нет | лишний параметр | когда мера не годится |

Порядок в таблице — это и есть порядок предпочтения, с одной поправкой:
`разбор` стоит пробовать первым, а «снять пометку» — последним из первых двух.

## Задача

В `examples/rosetta/` лежат файлы, где тотальность не доказывается, и
причина названа в шапке каждого. Возьмите
`examples/rosetta/primes-by-trial-division.flang` — там пять функций и
доказана одна.

1. Найдите, какая доказана и почему (подсказка: в её имени есть слово
   «топливо»).
2. Попробуйте пометить тотальной любую из четырёх остальных и прочитайте отказ.
3. Ответьте себе: какой из четырёх выходов подошёл бы здесь, кроме топлива?

**Проверка:**

```bash
flang check examples/rosetta/primes-by-trial-division.flang --proof | grep "функций"
```
