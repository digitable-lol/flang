# Отличие второе: обещание о результате проверяется на всех входах

Вот вся разница между тестом и обещанием, в двух строчках.

**Тест:**

```
проверь, что «Фибоначчи» от 10 равно 55
```

Проверено одно значение. Про остальные не сказано ничего.

**Обещание:**

```
обеспечивает «шаг Фибоначчи неотрицателен» результат не меньше 0
```

Компилятор либо **докажет это обо всех входах**, либо честно скажет, что не смог.
Третьего ответа нет.

## Два слова: `требует` и `обеспечивает`

**`обеспечивает`** — постусловие: что верно про результат. Имя в ёлочках
обязательно, по нему утверждение находят в отчёте о доказательствах.

**`требует`** — предусловие: что обязано быть верно на входе. Доказывает его
**вызывающий**. Поэтому в напечатанном коде предусловие стоит **ноль байт**: к
моменту вызова оно уже доказано, проверять нечего.

Вот и то и другое на одной функции, `examples/rosetta/fibonacci.flang`:

```flang
тотальная функция «Фибоначчи шагом»
  принимает осталось: нат, предыдущее: число, текущее: число
  возвращает число
  требует «предыдущее неотрицательно» предыдущее не меньше 0
  требует «текущее неотрицательно» текущее не меньше 0
  обеспечивает «шаг Фибоначчи неотрицателен» результат не меньше 0
  пример «Шагов не осталось»
    дано осталось равно 0
    дано предыдущее равно 7
    дано текущее равно 9
    ожидается 7
  если осталось не больше 0
    то предыдущее
    иначе «Фибоначчи шагом» от (осталось минус 1) и текущее и (предыдущее плюс текущее)
```

## Четыре ответа ядра, и путать их нельзя

```bash
flang check examples/rosetta/fibonacci.flang --proof
```

```
постусловие «шаг Фибоначчи неотрицателен» функции «Фибоначчи шагом» — доказано
индукцией по «нат»: база 1 случай, шаг при допущении на убывшем «осталось»
(1 случай), правила сведения: цель есть допущение — утверждение обо ВСЕХ
значениях отрезка «нат» [0, 9007199254740991], а не о написанных: отрезок конечен,
спуск строг и дна не проскакивает
```

```
утверждений 1: доказано 1 (из них индукцией 1), сетка 0, объявлено, не доказано 0 (шагов в термах 2)
```

Ядро отвечает одним из четырёх слов, и разница между ними — это вся ценность
инструмента:

| Ответ | Что значит |
| --- | --- |
| **доказано** | верно про **все** входы, выведено из объявлений и структуры |
| **сетка N** | прогнали по N значениям автора, нарушений не нашли. **Это не доказательство** |
| **объявлено, не доказано** | утверждение высказано, доказательства при нём нет — проверяется при работе |
| **НАРУШЕНО** | найден контрпример, и он показан |

Строка «сетка» в выводе кончается словами «Это не доказательство» — и кончается
так намеренно.

Четвёртый ответ — самый ценный. Утверждение, отвергнутое с контрпримером, — это
найденная ошибка, а не неудача инструмента.

| посчитано на конечной сетке значений | 556 |
| отвергнуто ядром | 0 |
| принято на веру | 0 |

*Числа из `docs/site/numbers.json`, последний пересчёт — коммит `252606e8`,
23 августа 2026. Прежняя редакция главы называла 395 высказанных и 236
доказанных, снятые 20 августа.*

**Принятого на веру ноль.** Это не оборот речи: ни одно из 407 доказанных
утверждений не опирается на «примем это на веру», и отчёт `--proof` печатает
отдельной строкой `на веру: 0` на каждом файле, который вы проверите сами.

## Теорема — когда постусловия мало

Иногда ядро само не справляется, и тогда пишется теорема. Вот та, что закрывает
Фибоначчи:

```flang
модуль «Фибоначчи с теоремой»

тотальная функция «Фибоначчи шагом»
  принимает осталось: нат, предыдущее: число, текущее: число
  возвращает число
  требует «предыдущее неотрицательно» предыдущее не меньше 0
  требует «текущее неотрицательно» текущее не меньше 0
  обеспечивает «шаг Фибоначчи неотрицателен» результат не меньше 0
  пример «Шагов не осталось»
    дано осталось равно 0
    дано предыдущее равно 7
    дано текущее равно 9
    ожидается 7
  если осталось не больше 0
    то предыдущее
    иначе «Фибоначчи шагом» от (осталось минус 1) и текущее и (предыдущее плюс текущее)

теорема «шаг Фибоначчи неотрицателен»
  дано осталось: нат
  утверждаем результат не меньше 0
  индукция по осталось убывает осталось
    случай 0
      то по предположению
    случай любое
      то по предположению
  следовательно доказано
```

Шесть строк. До неё утверждение стояло в отчёте словом «сетка» — посчитано
одним примером автора, на одном входе из отрезка `[0, 2⁵³−1]`. После — доказано
обо всех.

Обоснования шага бывают четыре: `по предположению` (допущение индукции или
предусловие функции), `по примеру` (ссылка на именованный пример), `по закону`,
`по свойству`.

**Важная деталь этой теоремы.** Дно закрыто не примером, а `по предположению`, и
предположение здесь — не индукционное, а **предусловие** `требует «предыдущее
неотрицательно»`. В дне тело возвращает `предыдущее`, и цель дна — «предыдущее
не меньше 0». Уберите строку `требует` — и рухнет не только теорема, но и само
утверждение: вход `0 / −7 / 9` даёт `−7`.

## Правило порядка: сперва постусловие, потом теорема

**Часто теорема не нужна вовсе.** Отчёт `--proof` на каждом файле печатает, чем
именно закрыто утверждение, и «без теоремы» там встречается чаще, чем «индукцией»:
на `flang/stdlib/lists.flang` из 38 доказанных 33 закрыты без теоремы. Порядок
работы поэтому такой:

1. напишите `обеспечивает`;
2. спросите ядро (`--proof`);
3. только если оно откажет — пишите теорему.

Обратный порядок стоит времени и обычно не окупается: в замере цены
доказательств **написано 14 теорем, принято ядром 0**. Всё, что тогда было
доказано, доказано без теоремы. Подробности — [следующая глава](06-cost.md).

## «Сетка N» значит меньше, чем кажется, и отчёт говорит об этом прямо

Строку про сетку стоит дочитать до конца:

```
постусловие «удвоенное не меньше исходного» функции «Удвоить» — сетка 1 значение
(примеры функции): нарушений НЕ ИСКАЛИ — прогона примеров не было, посчитано
только их число. Это не доказательство — теоремы при утверждении нет
```

**«Не искали» и «искали, не нашли» — разные новости**, и здесь именно первое:
`сетка N` — это счёт примеров, а не их прогон. Прогнать их — отдельная команда,
`flang test`.

*Прежняя редакция главы называла это «расхождением двух реализаций»: мол,
двоичный пишет «НЕ ИСКАЛИ», а инструментарий на Node — «искали прогоном на всех
N». Второй реализации в дереве больше нет, и сравнивать не с чем; осталась одна
строка, и приведена она выше как есть.*

Вот как эта строка выглядит на настоящем файле библиотеки:

```bash
flang check flang/stdlib/lists.flang --proof
```

```
  функций 38: тотальных 38, обычных 0
  утверждений 66: доказано 38 (из них индукцией 5) (из них без теоремы 33), сетка 28, объявлено, не доказано 0
```

*Прошлая редакция главы называла здесь `утверждений 17: доказано 9`. Число это
живое: за одни сутки, пока курс переснимался, оно съездило с 59 на 66 — в
библиотеку дописали функции. Поэтому у каждой главы курса и объявлен замер:
число без дерева и дня ничего не значит.*

## Задача

Возьмите `flang/proof/examples/precondition.flang` — файл из дерева, в котором
намеренно собраны три разных исхода на трёх функциях:

```bash
flang check flang/proof/examples/precondition.flang --proof
```

1. Найдите функцию, где утверждение **доказано индукцией**, и уберите у неё
   строку `требует`. Прочитайте, что скажет ядро.
2. Найдите функцию, где утверждение доказано **без индукции**, за один шаг.
3. Найдите функцию, где утверждение **высказано и не доказано**, и прочитайте
   названную рядом причину.

**Проверка:** после шага 1 в выводе появится код `FLANG_PROOF_INDUCTION_STEP`, и
это правильный результат задачи, а не поломка.
