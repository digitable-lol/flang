# Цена: 2 из 20

Эта глава — не оговорка мелким шрифтом и не раздел «известные ограничения» в
конце. Она стоит в середине курса, потому что без неё всё остальное — реклама.

Вопрос был задан прямо: **дешевле ли доказать функцию, чем написать на неё
тесты?** В проекте его не мерили ни разу, потом померили трижды.

## Как мерили

На каждой из двадцати функций стандартной библиотеки сделали **две работы, обе с
нуля**:

- **тесты** — примеры при функции, прогон `flang test`;
- **доказательство** — постусловие и теорема при ней же, прогон
  `flang check --proof`.

Считали строки, время (секундомером вокруг каждой из сорока работ), число
попыток и что получено на выходе.

**Как отбирали двадцать — это важнее самих чисел**, потому что выборка под
удобный результат обесценила бы весь замер:

1. что брали — все функции `flang/stdlib/*.flang`;
2. порядок — «файл по алфавиту, внутри файла по порядку объявления». Никакой
   сортировки по вкусу;
3. годные — «нет ни постусловия, ни теоремы». Годными оказались **все 185 из
   185**: в стандартной библиотеке не было ни одного утверждения о поведении;
4. выборка — **каждая девятая** (шаг `⌊185 / 20⌋ = 9`), индексы 0, 9, 18, …, 171.

Во второй раз взяли **те же двадцать по именам**: замер — линейка, а не поиск
удобного материала.

Отчёты лежат в дереве целиком, вместе с сорока файлами работы:
[`docs/benchmark-proof-cost.md`](https://github.com/digitable-lol/flang/blob/main/docs/benchmark-proof-cost.md),
[`docs/benchmark-proof-cost-2.md`](https://github.com/digitable-lol/flang/blob/main/docs/benchmark-proof-cost-2.md).

## Числа

| мера | тесты | доказательство |
| --- | ---: | ---: |
| строк написано | **394** | **169** |
| времени | **276 с** | **589 с** |
| попыток | **20** | **41** |
| **что получено** | **20 работающих наборов, 110 примеров, 4 настоящие ошибки** | **2 доказанных содержательных утверждения** |

Цена за единицу результата — то, ради чего замер и делается:

| | тесты | доказательство | отношение |
| --- | ---: | ---: | ---: |
| строк на единицу результата | 19,7 | 84,5 | дороже в **4,3 раза** |
| секунд на единицу результата | 13,8 | 294 | дороже в **21 раз** |

**Теорем написано 14, принято ядром 0.** Всё, что было доказано, доказано без
теоремы — одним постусловием, которое ядро свело с телом функции.

## А там, где ядро берёт, доказательство в 18 раз дешевле тестов

Это второе число замера, и оно меняет вывод:

| функция | тесты | доказательство |
| --- | --- | --- |
| «Размер словаря» | 18 строк / 17 с | **1 строка** / 11 с |
| «Чётное» | 18 строк / 17 с | **1 строка** / 29 с |

Одна строка постусловия против восемнадцати строк примеров. Теорема не
понадобилась ни там, ни там.

Отсюда вывод, который не был виден при первом замере:

> **Цена доказательства в flang — больше не проблема. Проблема — охват.**
> Когда ядро берёт цель, доказательство дешевле тестов примерно в двадцать раз.
> Берёт оно 2 случая из 20.

## Почему восемнадцать не прошли

Причины названы поимённо, и они не про «ядро слабое вообще»:

| причина | сколько |
| --- | ---: |
| **тело написано не `разбор`ом** — свёрткой, вызовом, арифметикой; строить посылку индукции не из чего | **7** |
| **у типа нет принципа индукции** — `строка`, `признак` | **3** |
| **на языке не выразить** | **4** |
| у цели нет вида, к которому есть правило («или», «не больше <выражение>») | 2 |
| в базе индукции остаётся свободное имя | 1 |
| цель не сводится ни одним из трёх правил | 1 |

**Главная помеха — форма тела, и у неё есть знаменатель.** Ядро строит
заключение посылки индукции только с ветвей `разбор` по переменной индукции.
Таких тел в стандартной библиотеке было **58 из 208**. Остальные 150 написаны
свёрткой (45), условием (37), арифметикой (21), вызовом (18), встроенной формой
(9), `пусть` (8), отображением и отбором (8), построением (3), применением (1).

**72 % библиотеки написано формами, к которым индукция ядра не цепляется** — и
обычный код пишут именно так, свёрткой, а не разбором.

**Четыре случая невыразимости — это дыры языка, а не ядра:**

- поле суммы из выражения не достать: `связь.ключ` → «доступ к полю требует
  записи», а `разбор` в постусловие не помещается, оно однострочное;
- равенства на параметре типа нет: «результат равен запасному» → «сравнивать на
  равенство можно только скаляры»;
- проверки варианта выражением нет вовсе: «результат `да` ровно тогда, когда
  итог это «Успех»» сказать нечем.

содержательных**, снятая с разбором поимённо, а не 9 из 22, снятая счётчиком.

**И честная поправка про сам замер.** Перемерить его сегодня своими руками

flang. Числа этой главы поэтому названы датой, а не «сегодня».

## Тавтология закрывается даром — и это ловушка любой метрики

Постусловие `результат равен (0 минус х)` при теле `0 минус х` ядро сводит
правилом тождества за один шаг, и отчёт честно печатает «доказано обо ВСЕХ
входах».

Содержательное утверждение о той же функции — `(результат плюс х) равен 0` —
ядро **не взяло**.

То есть цифру «закрыто утверждений» можно надуть до любого размера, просто
переписав тело в постусловие. Это не обвинение ядру — оно право, — а
предупреждение о том, **как эту метрику нельзя мерить**. Если кто-то показывает
вам высокий процент доказанного, первый вопрос: сколько из этого тавтологий.

## Самое важное в этой главе: доказано ≠ правильно

Функция «Чётное» — одна из двух, где доказательство сработало. Вот она,
`flang/stdlib/numbers.flang`:

```flang
модуль «Числа»

тотальная функция «Делится на»
  принимает число: число, делитель: число
  возвращает признак
  пример «Делится»
    дано число равно 9
    дано делитель равно 3
    ожидается да
  (число остаток от делитель) равен 0

тотальная функция «Чётное»
  принимает число: число
  возвращает признак
  обеспечивает «чётность есть делимость на два» результат равен («Делится на» от число и 2)
  пример «Чётное»
    дано число равно 4
    ожидается да
  пример «Нечётное»
    дано число равно 5
    ожидается нет
  (число остаток от 2) равен 0
```

Отчёт о доказательствах:

```
постусловие «чётность есть делимость на два» функции «Чётное» — доказано
сведением цели с телом функции: правило «тождество после переписки допущением»,
объявленные типы аргументов не понадобились — утверждение обо ВСЕХ входах, а не
о написанных; теоремы при нём нет и не нужно
```

Доказано. Обо всех входах. Теперь запустите:

```bash
flang run flang/stdlib/numbers.flang --function Чётное --args '{"число": -4}'
```

```
false
```

**Минус четыре — чётное число, а функция отвечает «нет».**

Противоречия здесь нет, и в этом весь урок. Доказано утверждение «чётность есть
делимость на два» — то есть «эти две функции библиотеки отвечают одинаково». Они
и отвечают одинаково. **Обе ошибаются.**

Причина — минус ноль. `−4 остаток от 2` даёт `−0`, а `−0 равен 0` — ложь, потому
что в IEEE-754 это разные значения. Проверить можно так:

```flang
// ОЖИДАЕТСЯ ОТКАЗ: этот блок НЕ собирается, и в этом всё дело.
модуль «Минус ноль»

тотальная функция «Остаток»
  принимает х: число
  возвращает число
  пример «минус четыре»
    дано х равно -4
    ожидается 0
  х остаток от 2
```

```
FLANG_EXAMPLE: пример «минус четыре» функции «Остаток»: значение не совпало с ожидаемым: ожидалось 0, получено 0
```

**Прочитайте это ещё раз: «ожидалось 0, получено 0».** Отказ выглядит абсурдно и
абсурдным не является — это и есть минус ноль во всей красе. `flang run` на том
же входе печатает `0`: печать не различает `0` и `−0`, а сравнение различает.
(Хвост «получено …» в этой строке новый; прежняя редакция главы его не
показывала, потому что компилятор его тогда не печатал.)

**Отсюда правило, которое надо унести из курса целиком:**

> «Доказано» значит «утверждение верно про все входы». Оно **не** значит «функция
> делает то, что вы хотели». Разрыв между доказанным и правильным — это ваша
> спецификация, и доказывать её нечем.

## Чего тесты нашли, а доказательства — нет

В том же замере обычные примеры нашли **четыре настоящие ошибки** библиотеки:

1. «Чётное» от −4 отвечает «нет»;
2. «Уникальные» от `[0, −0, 1]` оставляет два нуля — тот же корень;
3. «Строчная буква» от пустой строки **отказывает**, будучи объявленной
   тотальной;
4. «Строчная буква» от `"AB"` молча портит вход, возвращая `"a"`.

Доказательства не нашли ни одной. Во втором замере — **те же четыре, ни одной
новой, ни одна не починена**.

## Что из этого следует для вашего проекта

Не «не используйте flang». Три вывода, каждый из которых практический:

1. **Пишите примеры.** Они дешевле, они ловят ошибки, и они часть программы —
   прогоняются при каждой проверке, а не по требованию. Доказательства их не
   заменяют и в обозримом будущем не заменят.
2. **Завершаемость берите — она почти бесплатна.** 7445 функций дерева несут
   доказанное завершение, и это работает массово.
3. **Обещания о поведении пишите там, где цель ложится в одно из трёх правил
   ядра**: «не меньше 0», «не больше конечного литерала», «равно». Ложится —
   получите доказательство за одну строку. Не ложится — получите «сетку», и
   тогда честнее написать примеры.

И одно условие, при котором всё изменится, — оно записано в базе знаний проекта
отдельной заметкой:

> Революция наступит ровно тогда, когда доказательство станет дешевле тестов.

Сегодня оно дороже в 21 раз по времени и в 4,3 раза по строкам. Это измерено, а
не оценено.

## Задача

Проверьте вывод этой главы своими руками:

```bash
flang run flang/stdlib/numbers.flang --function Чётное --args '{"число": -4}'
flang run flang/stdlib/numbers.flang --function Чётное --args '{"число": 4}'
flang check flang/stdlib/numbers.flang --proof | grep "чётност"
```

**Проверка:** первая команда печатает `false`, вторая `true`, третья — строку со
словом «доказано». Если вы получили это — вы видели своими глазами доказанное
ложное ожидание, и дальше в курсе вам будет легче.
