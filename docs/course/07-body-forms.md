# Формы тела

Тело функции в flang — **одна форма**, а не последовательность операторов. Форм
несколько, и выбор между ними — не вопрос стиля. От него зависит, сможет ли ядро
что-нибудь про функцию доказать.

Начнём с того, чего в языке нет.

| Привычка из другого языка | Что здесь на самом деле |
| --- | --- |
| напишу цикл | **циклов нет вовсе**. Есть свёртка и рекурсия |
| изменю элемент списка | **изменения на месте нет**. Только построение нового |
| брошу исключение | **исключений нет**. Отказ — это значение |
| верну `null`, если не нашлось | есть **сумма типов**, и разбор по ней обязателен |
| положу переменную и буду менять | `пусть` **связывает один раз** |

Функции как значения при этом **есть** — не поверьте обратному. Компилятор
снимает их одним проходом перед печатью — заменяет функцию-значение меткой, а
применение разбором по меткам, — поэтому граф
вызовов остаётся конечным. Чего действительно нет — замыканий, и почему —
[в главе про границы](11-boundaries.md).

## `разбор` — единственная форма, к которой цепляется индукция

```flang
модуль «Дерево»

тип «Дерево»
  вариант Лист
  вариант Узел содержит значение: число, левое: «Дерево», правое: «Дерево»

тотальная функция «Наибольшее»
  принимает а: число, б: число
  возвращает число
  пример «два и три»
    дано а равно 2
    дано б равно 3
    ожидается 3
  если а меньше б то б иначе а

тотальная функция «Глубина»
  принимает дерево: «Дерево»
  возвращает число
  пример «у листа глубина ноль»
    дано дерево равно вариант Лист
    ожидается 0
  разбор дерева
    случай Лист
      то 0
    случай вариант Узел с левое как л и правое как п
      то 1 плюс («Наибольшее» от («Глубина» от л) и («Глубина» от п))
```

Разбор даёт две вещи сразу:

1. **тотальность по структуре** — часть значения меньше значения по построению;
2. **точку прицепа для индукции** — ядро строит посылку по ветвям разбора.

Это и есть та форма, к которой стоит стремиться, когда вы хотите что-нибудь
доказать.

## `свёртка` — обход списка ровно один раз

```
свёртка элементы начиная с 0 как акк и эл → если эл меньше цель то акк плюс 1 иначе акк
```

Тотальна **по построению**: список конечен, обход один. Это самая частая форма
после `если` — в стандартной библиотеке 45 тел.

**И это же главная причина, по которой доказательства не идут.** Индукция к
свёртке не цепляется: у ядра нет способа построить посылку «предположим, верно
для хвоста». Заметка базы знаний называется прямо — «левая свёртка не даёт
индукции по списку».

## `если` — ветвление

```
если н не больше 0
  то 0
  иначе н плюс («Сумма до» от (н минус 1))
```

**Ловушка, которая стоила дня работы и измерена.** Ядро **не читает условие как
факт в ветви**. Попытку научить его этому сделали и померили:

```
функций в корпусе          4009
условий «если»             3454
из них читаемых             199
целей это закрывает           0
```

*Замер сделан на дереве того дня; сегодня функций вчетверо больше, но ответ
последней строки от размера не зависит — он про идиому, а не про число.*

Ноль. Причина не в слабости правила, а в идиоме кода: пишут всегда
`если <мало> то <база> иначе <работа>`, и нужный факт всегда лежит в ветви
`иначе` — а её читать нельзя, потому что на NaN ложны обе стороны сравнения.

Не беритесь за это заново без нового довода. И не рассчитывайте, что условие
`если` подскажет ядру то, что вы имели в виду.

## `пусть` — связывание имени

```
пусть новое равно «Вставить в дерево» от л и число
Узел с значение равным зн и левое равным новое и правое равным п
```

Связывает **один раз**. Это не переменная: присвоить второй раз нечем, и
конструкции для этого в языке нет.

## Что это значит на практике: измеренный знаменатель

Разложение тел стандартной библиотеки — 208 функций, снятое при замере цены
доказательств 16 августа 2026 (сегодня библиотека вдвое больше, и разложение
надо снимать заново — нечем: измеритель удалён вместе с реализацией на
JavaScript):

| форма | сколько |
| --- | ---: |
| `разбор` по параметру | **58** |
| свёртка | 45 |
| условие | 37 |
| арифметика | 21 |
| вызов | 18 |
| встроенная форма | 9 |
| `пусть` | 8 |
| отображение и отбор | 8 |
| построение | 3 |
| применение | 1 |

**58 из 208 — 28 %.** Остальные 72 % написаны формами, к которым индукция ядра
не цепляется, и это ровно то, что видно в [замере цены](06-cost.md): семь
отказов из восемнадцати названы причиной «тело написано не `разбор`ом».

Число это в дереве двигают: в более позднем замере тел вида «`разбор` по
параметру» стало 96 из 208, и отказы переехали по коду — `INDUCTION_BRANCH` с 7
на 2, `INDUCTION_STEP` с 2 на 6. То есть переписывание помогает, но упирается в
следующее узкое место.

## Правило выбора формы

1. **Хотите доказать что-нибудь про функцию — пишите `разбор`ом.** Даже если
   свёрткой короче.
2. **Не собираетесь ничего доказывать — пишите как удобно.** Свёртка тотальна по
   построению, и завершение вы получите даром в любом случае.
3. **`если` — обычное ветвление и ничего больше.** Условие в нём ядру не факт.

## Задача

Возьмите `«Место вставки»` из
`examples/leetcode/035-search-insert-position.flang` — функцию, написанную
свёрткой:

```flang
тотальная функция «Место вставки»
  принимает элементы: список числа, цель: число
  возвращает число
  свёртка элементы начиная с 0 как акк и эл → если эл меньше цель то акк плюс 1 иначе акк
```

1. Добавьте ей постусловие `обеспечивает «место не дальше конца» результат не
   больше (длина элементы)` и снимите отчёт о доказательствах.
2. Перепишите тело `разбор`ом — `случай пусто` и `случай голова и хвост` — и
   снимите отчёт снова.
3. Сравните **не вердикт, а маршрут**.

Вот что получается на самом деле, и это честнее, чем ожидаемое «свёртка не
доказывается».

Свёрткой:

```
постусловие «место не дальше конца» функции «Место вставки» — доказано сведением
цели с телом функции: правило «порядок по построению», объявленные типы
аргументов не понадобились — утверждение обо ВСЕХ входах, а не о написанных;
теоремы при нём нет и не нужно
```

```
утверждений 1: доказано 1 (из них без теоремы 1), сетка 0, объявлено, не доказано 0
```

Разбором:

```
постусловие «место не дальше конца» функции «Место вставки» — доказано индукцией
по «список»: база 1 случай, шаг при допущении на частях (1 случай), правила
сведения: ограниченность точным потолком по построению; порядок по построению —
утверждение обо ВСЕХ входах типа «список», а не о написанных
```

```
утверждений 1: доказано 1 (из них индукцией 1), сетка 0, объявлено, не доказано 0
```

**Оба доказаны.** Разница — в том, чем: свёртка закрылась одним правилом
сведения, разбор — индукцией. На простом утверждении это не видно, и утверждать
«свёрткой не доказать» было бы неправдой.

Разница бьёт там, где цель **требует** посылки индукции — когда про результат
надо сказать что-то, что верно для хвоста и переносится на целое. Тогда у
свёртки прицепа нет, и вы получаете один из семи отказов, названных в [замере
цены](06-cost.md) причиной «тело написано не `разбор`ом».

**Проверка:** оба отчёта печатают `доказано 1`. Если у вас так — задача
сделана; если у одной из версий «сетка» — вы написали утверждение другой формы,
и это тоже полезный результат: посмотрите, какой именно.
