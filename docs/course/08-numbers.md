# Числа

Здесь легче всего ошибиться, если вы читали про доказательства в Coq или Agda.
**Числа flang — машинные IEEE-754, а не построенные индуктивно.** Размен сделан
сознательно: арифметика остаётся одной инструкцией процессора. Плата — всё, что
ниже.

## Пять типов, и они не про диапазон, а про то, что знает ядро

| Тип | Что это | Что даёт ядру |
| --- | --- | --- |
| `число` | IEEE-754 double | **ничего** |
| `нат` | целое из `[0, 2⁵³−1]` | обе границы и целость — отсюда индукция по числу |
| `целое` | целое из `[−(2⁵³−1), 2⁵³−1]` | почти ничего |
| `вес` (`стоимость`) | `нат`, где `+∞` — значение, а не край | обе границы; моноид по минимуму и максимуму |
| `сотых`, `тысячных` | целое число минорных единиц | ассоциативность, моноид — и цена **нулевая** |

Вложение: `нат` ≤ `целое` ≤ `число` и `нат` ≤ `вес` ≤ `число`. Значение втекает в
объявленную позицию, обратно — нет.

**Практическое правило:** объявляйте `нат` везде, где значение неотрицательно.
Это не педантизм, это измерено, и цена типа записана в журнале языка одной
строкой: **21 функция из 139 становится доказуемо неотрицательной**
просто оттого, что тип объявлен точнее (коммит `120f1fab`).

Вы это уже видели в [главе 02](02-first-program.md): постусловие «результат
не меньше 0» доказывается **правилом «неотрицательность по построению»** ровно
потому, что аргумент объявлен `нат`.

Оговорка: `делить` выводит из точного типа — результат становится `число`.
Округления в языке нет ни явного, ни молчаливого.

## Ловушка первая: минус ноль

`−0` и `0` — **разные значения** при сравнении на равенство.

```flang
// ОЖИДАЕТСЯ ОТКАЗ: этот блок НЕ собирается, и в этом всё дело.
модуль «Минус ноль»

тотальная функция «Остаток»
  принимает х: число
  возвращает число
  пример «минус четыре»
    дано х равно -4
    ожидается 0
  х остаток от 2
```

```
FLANG_EXAMPLE: пример «минус четыре» функции «Остаток»: значение не совпало с ожидаемым: ожидалось 0, получено 0
```

При этом `flang run` на том же входе печатает `0`: печать не различает `0` и
`−0`, а сравнение различает.

**На этом уже сломались три функции стандартной библиотеки** — «Чётное»,
«Делится на» и «Уникальные», — и одна из них при этом несёт **доказанное**
постусловие. Разбор — в [главе про цену](06-cost.md).

> Любая функция, сравнивающая числа на равенство или берущая остаток, обязана
> быть проверена на `−0` до того, как вы на неё положитесь.

## Ловушка вторая: NaN достижим изнутри языка

```flang
тотальная функция «Ноль на ноль»
  принимает х: число
  возвращает число
  х делить на х
```

Проходит проверку типов без единой диагностики, завершение доказано. А результат:

```bash
flang run chisla.flang --function "Ноль на ноль" --args '{"х": 0}'
```

```
NaN
```

Следствие, которое ломает «очевидные» рассуждения: правило «модуль числа
неотрицателен» — **ложь**. Модуль от NaN есть NaN, а «NaN не меньше 0» ложно.

Это же объясняет, почему ядро не читает условие `если` как факт в ветви `иначе`:
на NaN ложны **обе** стороны сравнения. Мера, [измеренная в главе
07](07-body-forms.md), — ноль закрытых целей.

## Ловушка третья: ассоциативность не держится

```flang
тотальная функция «Слева»
  принимает х: число
  возвращает число
  (0.1 плюс 0.1) плюс х

тотальная функция «Справа»
  принимает х: число
  возвращает число
  0.1 плюс (0.1 плюс х)
```

```bash
flang run chisla.flang --function Слева  --args '{"х": 0.6}'
flang run chisla.flang --function Справа --args '{"х": 0.6}'
```

```
0.8
0.7999999999999999
```

Одно выражение, сложенное в разном порядке, — два ответа. Ломает
ассоциативность **округление**, а не бесконечность: убрать вычитание не помогает.

Отсюда прямое следствие для доказательств: **у ядра ноль аксиом о плавающей
точке**, и про сложение `число` доказывать нечего.

## Что с этим делать: точные десятичные, и они бесплатны

`examples/money/exact-decimal.flang` — деньги на типе `сотых`, целом числе
сотых долей. Рубль пятьдесят — это `150`.

```
10 плюс 20 = 30    точно
```

Это сложение целых внутри точной сетки double: соседние целые различимы, ничего
не округляется. **Ассоциативность на нём настоящая**, значит сложение копеек —
моноид, а на моноиде уже есть что доказывать.

Масштаб надевается только в подписи — `принимает сумма: сотых`. Внутри тела
копейки складываются только с копейками: смешение с безразмерным счётчиком или с
тысячными — это `FLANG_SCALE`, а не молчаливая порча.

И самое полезное: постусловия «Копеек в остатке» — оба, «не меньше 0» и «не
больше 99» — **доказаны обо всех входах**. Над `число` то же утверждение
недоказуемо, потому что `5.5 остаток от 2` равно `1.5`.

**Цена точных десятичных — ноль.** Это отдельная измеренная заметка проекта:
они не в сто раз дороже, как принято думать, а не дороже вовсе.

## Задача

Проверьте все три ловушки одним файлом:

```flang
// ОЖИДАЕТСЯ ОТКАЗ: два примера из трёх НЕ сходятся, и это задача главы.
модуль «Ловушки чисел»

тотальная функция «Ноль на ноль»
  принимает х: число
  возвращает число
  пример «ноль делить на ноль»
    дано х равно 0
    ожидается 0
  х делить на х

тотальная функция «Слева»
  принимает х: число
  возвращает число
  пример «слева»
    дано х равно 0.6
    ожидается 0.8
  (0.1 плюс 0.1) плюс х

тотальная функция «Справа»
  принимает х: число
  возвращает число
  пример «справа»
    дано х равно 0.6
    ожидается 0.8
  0.1 плюс (0.1 плюс х)
```

```bash
flang check chisla.flang
```

**Проверка:** ровно два замечания `FLANG_EXAMPLE` — на «ноль делить на ноль» и
на «справа», — и ни одного на «слева». Код возврата 1.

```
модуль «Ловушки чисел»: функций 3, из них с доказанным завершением 3; типов 0
FLANG_EXAMPLE: пример «ноль делить на ноль» функции «Ноль на ноль»: значение не совпало с ожидаемым: ожидалось 0, получено null
FLANG_EXAMPLE: пример «справа» функции «Справа»: значение не совпало с ожидаемым: ожидалось 0.8, получено 0.7999999999999999
```

```
chisla.flang: не проверено — замечаний 2
```

Хвост «получено …» показывает обе ловушки прямо: `не число` в машинном выводе
записывается как `null`, а правая сумма отличается от левой в семнадцатом знаке.

Обратите внимание: **все три функции доказано завершаются**. Тотальность и
правильность — разные обещания, и это то же наблюдение, что в главе 06.
