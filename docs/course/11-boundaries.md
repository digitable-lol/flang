# Границы

Список того, чего нет, длиннее списка того, что есть. Здесь он разложен на три
части, и разница между ними существенная:

- **чего нет и не будет** — решение принято, причина названа;
- **чего нет пока** — работа не сделана;
- **что сломано сегодня** — найдено при подготовке курса, прогонами.

## Чего не будет: решено, с причиной

**Замыканий не будет.** Захват окружения ломает анализ завершаемости и прямую
печать в C, Go и Rust.

Не перепутайте с другим: **функции как значения ЕСТЬ**. Это разные вещи, и
отвергнута только первая.

```
функция «Удвоить»              функция как значение
функция из числа в число       её тип
ф от 5                         применение
```

Компилятор снимает их одним проходом перед печатью (приём Рейнольдса, 1972):
функция-значение заменяется меткой, применение — разбором по меткам. Так написана
`flang/stdlib/higher-order.flang` — 34 функции, все тотальные.

Цена приёма названа заранее: проход требует **видеть всю программу целиком**.

Чего действительно нет — передачи функции туда, где она приезжает данными
(например, отдать вычислитель параметром снаружи программы).

**Двух версий одной библиотеки в одной программе не будет.** Ромб зависимостей
решается подъёмом версии, а не сосуществованием.

**Полной модели Unison не будет.** Хранить код в базе вместо файлов значит
завести свой редактор, свой хостинг и потерять git. Половину Unison —
адресацию по содержимому — берут; вторую не берут.

## Чего нет пока

**Менеджера пакетов нет.** Сами пакеты есть: `flang package` кладёт библиотеку
со всем её замыканием в один файл, и он подключается одной строкой. Прогон
проекта: 8 модулей и 53 функции уехали в 13 161 байт против 99 508 байт
исходников, и на другой машине из двух файлов собралась та же программа с
той же печатью в C, байт в байт.

Нет того, что стоит **над** пакетом: реестра, поиска по имени, диапазонов
версий (`^1.2`), разрешения зависимостей. Обновление — взять новый файл и
положить вместо старого. Раздача библиотеки от этого не блокируется, но
становится ручной.

**Базы данных нет.** Совсем.

**Полноценной сети нет.** Ходить в сеть язык умеет — есть поручения «Запросить»,
«Открыть соединение», «Принять соединение», — но это примитивы, а не библиотека.

**Библиотека невелика:** 42 файла, 35 581 строка
<!-- СНЯТО 2026-08-31 файлов flang/stdlib/*.flang = 42 --><!-- СНЯТО 2026-08-31 строк-в flang/stdlib/*.flang = 35581 -->
(`ls flang/stdlib/*.flang | wc -l`, `cat flang/stdlib/*.flang | wc -l`,
27 августа 2026). Есть списки, строки, числа, словари, деревья, множества, JSON,
HTTP-разбор, SHA-256, Base64, UTF-8, дата и время, функции высшего порядка.
Прошлая редакция главы называла 19 файлов и 9 410 строк — за неделю библиотека
выросла вдвое с лишним.

**Прикладного кода почти нет.** Бэкенд — один пример на 7 файлов и 563 строки.
Фронтенд — демонстрация в браузере, а не приложение.

**Из реестра npm пока не поставить.** Под именем `@digitable-lol/flang` ничего
не выложено, хотя справка двоичного эту команду печатает.

**Граница входа у напечатанной программы пуста.** Сам двоичный аргументы типам
сверяет: `Факториал` объявлен на `нат`, и на `−3` отвечает
`FLANG_TYPE: аргумент «н»: -3 вне нат`. А у программы, напечатанной через
`flang emit`, этой границы нет, и печать говорит об этом сама, прямо в своём
выводе:

```
аргументы напечатанной программы по типам не проверяются: это ограничение двоичного flang, полная проверка есть в версии для Node
```

**За вход напечатанной программы отвечает вызывающий.** Вторая половина этой
строки — «полная проверка есть в версии для Node» — сегодня уже неправда:
версии для Node не существует. Строка осталась в компиляторе, и курс показывает
её как есть.

## Что сломано сегодня: найдено прогонами

Пять находок. Все пять пересняты 27 августа 2026 двоичным от 23 августа
16:00 UTC (дерево не установлено, не новее `883fe9a9`).

**Прежняя редакция называла этот раздел «расхождения между двоичным и
инструментарием на Node».** Инструментария на Node больше нет: его удалили из
дерева, а команда `flang` из пакета npm запускает тот же самый двоичный. Значит
и расхождений между реализациями нет — есть границы одной.

### 1. Категорную поверхность не судит никто

Разобрано в [главе 10](10-functor.md). Проверки квадрата функтора в двоичном как
не было, так и нет:

```bash
grep -c FUNCTOR bootstrap/compiler_flang.c
```

```
0
```

**Но молчания больше нет.** На файле с внесённой ошибкой компилятор отвечает не
«замечаний нет» и не кодом 0, а «проверено НЕ ДО КОНЦА» и **кодом 2**, и
перечисляет поимённо, чего он не судил. Прежняя редакция главы обещала здесь
`FLANG_FUNCTOR_SQUARE` от второй реализации — второй реализации нет, и квадрат
сегодня не считает никто. Компилятор говорит это своими словами.

### 2. Слово «сетка» значит меньше, чем кажется

`сетка N` у двоичного — это **счёт** примеров, а не их прогон: «нарушений НЕ
ИСКАЛИ — прогона примеров не было, посчитано только их число». Прогнать их —
отдельная команда, `flang test`.

### 3. `--args` не берёт списки

```bash
flang run examples/leetcode/035-search-insert-position.flang \
  --function "Место вставки" --args '{"элементы": [1,3,5,6], "цель": 5}'
```

```
flang run: «--args» разобрать не удалось — ждался плоский объект скаляров, вроде '{"н":10}'
```

Код возврата **2**. Читается только плоский объект скаляров. Любой пример со
списком на входе с командной строки не запускается — а списки в языке повсюду.
Прежняя редакция обещала, что «npm-овский ответит `3`»: сегодня npm — тот же
двоичный, и ответ тот же.

### 4. Голая команда с конвейером — не оболочка

```bash
echo "2 плюс 2" | flang
```

```
{"ok":false,"code":"CLI","message":"ожидался объект запроса"}
```

Двоичный становится прогонщиком запросов JSON. Для сценария нужна команда по
имени: `flang repl`. Это сказано и в его собственной справке.

### 5. Напечатанный `Makefile` для C# не работает на .NET 10

Разобрано в [главе 09](09-eight-targets.md). `make run` падает с кодом 134,
потому что ключ `--nologo` доезжает до самой программы. Проверено заново на
.NET 10.0.110: **падает по-прежнему**, и текст отказа тот же. Сама печать при
этом верна — `make build` проходит без единого предупреждения, а собранная
сборка отвечает правильно.

## Что из этого следует

Ни одна из пяти находок не отменяет трёх отличий языка. Но общий их смысл
переменился, и это стоит сказать прямо.

**Прежде вывод был: «у языка две реализации, и они не равны — проверяйте тем,
чем будете пользоваться».** Сегодня реализация одна. Значит, и разночтений
«проверил одним, а поеду на другом» больше нет — а взамен появилась обязанность
читать **код возврата**, а не только последнюю строку:

> `0` — проверено. `1` — нашлась беда в предмете. `2` — проверено НЕ ВСЁ, и
> компилятор перечислил, чего именно не судил. Набор проверок, который считает
> удачей только `0`, честнее того, который считает удачей «не `1`».

## Про версию и обещания совместимости

Язык в версии `0.x`. Совместимыми поверхностями объявлены **только** канонический
JSON и коды диагностик; «синтаксис растёт через документированные предложения».

Практически это значит: синтаксис будет меняться, часть описанных ограничений
исчезнет, часть решений развернётся в обратную сторону. **Эта глава — живое тому
доказательство**: из пяти её находок одна за неделю развернулась целиком
(двоичный печатает все восемь целей), а вторая — наполовину (молчание сменилось
кодом 2).

Курс переснят на дереве `d363b1e5` 27 августа 2026 года и ни на чём другом.

## Задача

Проверьте одну границу самостоятельно и запишите, что получилось.

Возьмите любое утверждение из списка «чего нет пока» и попробуйте его опровергнуть
командой. Например:

```bash
flang run flang/stdlib/lists.flang --function Длина --args '{"элементы": [1,2,3]}'
```

**Проверка:** ответом будет отказ разбора `--args` и код 2 — и через `brew`, и
через npm, потому что это один и тот же двоичный. Если у вас ответило `3` —
граница №3 закрыта, и это хорошая новость: напишите об этом в репозиторий языка.
