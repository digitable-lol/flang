## 0. Итог на одной странице

1. **Перебор из трёх написан не дважды, а в трёх программах и в девяти местах**
   (§1): в ядре два пути (теорема / без теоремы) перебирают порознь, слово
   носителя ставится тремя литералами в `proof-initial.flang`; в `сверщик.c`
   закрытый список стоит на 6641, но к нему ещё три места, где слово читается, и
   **четыре разных списка имён натурального**; третий читатель — `сверщик.flang`.
2. **Что ломается — прогоном** (§2). Тип вне трёх на пути теоремы даёт отказ
   `FLANG_PROOF_INDUCTION_TYPE` с честным текстом «принцип читается из трёх
   мест». Без теоремы тот же тип даёт **молчаливое «сетка 1»** и запись
   `вердикт нет вердикта` без причины. Псевдоним `тип «Возраст» это неотрицательное`
   ядро отвергает, хотя анализ завершаемости в той же ведомости пишет «объявлен
   натуральным» — два слоя одного двоичного читают одно объявление по-разному.
   Сверщик: слово вне трёх ловит (код 1), а **`segment` над параметром `число`
   не ловит** (код 3 «не взялся», не 1); источник с именем `натуральное` ядро
   доказывает (код 0), а сверщик не проигрывает (код 3) — списки имён разошлись.
3. **Замена** (§3): одна функция ядра `«Принцип типа по объявлению»`,
   возвращающая сумму `«Начальная алгебра» | «Отрезок с дном» | «Нет принципа»
   с причиной`, читает объявление (`тип … вариант`, `объект`, `тип … это …`,
   встроенные) — три функции «по имени» и три литерала уходят. Запись получает
   строку `объявление …` — что ядро прочло. Сверщик заводит свой читатель
   объявлений на C и **сверяет строку записи с исходником, а не верит ей**;
   списки встроенных имён обеих программ ставятся под сторож
   `сверка-ведомости.sh` (как уже стоят имена правил).
4. **Корпусу это не даёт ни одного места** (§4): 99 файлов прогнано —
   `FLANG_PROOF_INDUCTION_TYPE` 0; из 58 кванторов `для всех` 56 стоят над
   суммой/списком/строкой/`неотрицательное`, псевдонимов в корпусе 0, `объект`
   под квантором 0. Доля-проигрыванием 567/651 = 87,10 % от этой задачи не
   сдвинется. **Задача про расширяемость и про проверяемость дубля, а не про
   долю** — и одна подделка (`segment` над `число`) сегодня проходит кодом 3.
5. **План** (§5): Ш0 — только сверщик (без ядра и без семени): читатель
   объявлений + подделка + сторож списков; Ш1 — ядро; Ш2 — строка записи и
   пересъёмка 26 записей; Ш3 — тексты. Перепечатка семени нужна (ядро в семени
   — проверено), и её надо делать **одним батчем с 6202** (§7).

## 1. Замер: где на самом деле живёт перебор из трёх

ADR-0026 §2.4 называет три функции ядра и одно место сверщика. Чтение показало
больше: перебор размазан по обоим путям ядра, слово носителя пишется и читается
ещё в четырёх файлах, а у сверщика помимо списка носителей четыре списка имён
одного и того же типа. Всё ниже — по `4d13d5a88`.

### 1.1. Ядро: два пути, оба перебирают

**Путь теоремы** (`flang/self/proofterm.flang`):

| функция | строки | что делает |
| --- | --- | --- |
| `«Проверить индукцию»` | 2217–2230 | берёт тип переменной из `vars` (`«Узел типа переменной индукции»` 1717–1723), зовёт `«Начало принципа»`; не сумма → `«Названо натуральным»`; не натуральное → `«Отказ без принципа»` |
| `«Начало принципа»` | 2199–2211 | имя пустое → встроенный `list`/`string`; иначе `«Сумма по имени»` (204–215, принимает **только** `kind = "sum"`; `alias` и `record` не смотрит) |
| `«Проверить индукцию по сумме»` | 2256–2265 | тело — свёртка по переменной → `«Принцип по свёртке»`, иначе `«Принцип индукции»` |
| `«Отказ без принципа»` | 1816–1819 | текст «принцип читается из трёх мест и ниоткуда больше» |

**Путь без теоремы** (те же `proofterm.flang`), порядок чтения тела —
`разбор` → `свёртка` → `если`, и каждый несработавший шаг возвращает
`«Узел ничто»` **молча**:

| функция | строки | носитель |
| --- | --- | --- |
| `«Случаями по телу»` → `«Случаями по имени»` | 2752–2761, 2887–2894 | объявленная сумма / встроенные |
| `«Свёрткой по телу»` → `«Свёрткой по имени»` | 2780–2789, 2874–2881 | свёртка (при этом тип обязан быть суммой/встроенным — 2879) |
| `«Отрезком по телу»` → `«Отрезком по имени»` | 2832–2842, 2849–2855 | `«Названо натуральным»` |

**Слово носителя** пишется тремя литералами в `flang/self/proof-initial.flang`:
`"algebra"` 1662, `"fold"` 1957, `"segment"` 2354; читается обратно в
`proofterm.flang:391` и `2160–2168` (какие поля класть в свод), в
`proof.flang` (объект `«Индукция»` 265–273, разбор слова 2427–2498) и печатается
в запись `zapis.flang:1465–1469` строкой `принцип тип «Т» по «п» носитель X …`.

**Список имён натурального** — `proof-kernel.flang:5543–5546`, шесть имён:
`неотрицательное|нат|натуральное|nat|naturo|自然数`.

**Псевдонимы.** Типизатор их разворачивает (`types.flang:3194–3225`,
`«Развернуть объявленный псевдоним»`), анализ завершаемости — тоже
(`totality.flang:2568`, `«Точные имена программы»`). Ядро доказательств — нет:
в `vars` лежит тип **как написан** (`obligations.flang:197–201`), а
`«Сумма по имени»` и `«Названо натуральным»` смотрят на имя.

**Поправка к ADR-0026 §2.4 и к п. 1 задачи.** «Поле `forall` несёт только имя» —
верно для узла парсера (`parser.flang:4214`, `«Поле текста»`) и для заключения
принципа (`proof-initial.flang:1633`). В **обязательстве** поле `forall` уже
узел с `name` и `type`: `«Квантор по имени»` (`obligations.flang:222–234`)
возвращает узел параметра целиком, и ведомость читает из него `.name`
(`compiler.flang:2319`). Тип берётся из `vars`, а не из `forall`, потому что на
пути теоремы переменную называет `индукция по …`, а не квантор. Значит п. 1
задачи — не смена представления, а два чтения свести к одному.

## 2. Что ломается — прогоном

Пробные программы и записи лежат в scratchpad прогона; команды — в приложении.
Двоичный: `bootstrap/flang 0.7.16` из `4d13d5a88`.

### 2.1. Ядро, путь теоремы: отказ назван, и в нём же назван перебор

Три программы, у каждой `для всех п обеспечивает …` и теорема с `индукция по п`:

| тип параметра | объявление | ответ ядра |
| --- | --- | --- |
| `«Точка»` | `объект «Точка»` с двумя полями `неотрицательное` | `FLANG_PROOF_INDUCTION_TYPE … у этого типа («Точка») принципа индукции нет` |
| `«Возраст»` | `тип «Возраст» это неотрицательное` | `FLANG_PROOF_INDUCTION_TYPE … у этого типа («Возраст») принципа индукции нет` |
| `число` | встроенный | `FLANG_PROOF_INDUCTION_TYPE … у этого типа (число) принципа индукции нет` |

Текст отказа один на всех (`proofterm.flang:1819`):

> Принцип читается из трёх мест и ниоткуда больше: у объявленной суммы — из её
> вариантов, у встроенного списка — из двух образцов, которыми язык исчерпывает
> его разбор, у объявленного `неотрицательное` — из двух границ отрезка.

Для `число` это правильный отказ по существу (ADR-0026 и сам текст объясняют
`+∞`). Для `«Возраст»` — нет: та же программа в разделе завершаемости той же
ведомости получает «`«Сумма лет»` доказано точным шагом: аргумент 1 («н»)
**объявлен натуральным** и убывает на 1». Один двоичный, одно объявление, два
ответа.

### 2.2. Ядро, путь без теоремы: молчаливое «не подошло»

Те же `«Возраст»` и `число` без теоремы (тело — `если … иначе н плюс (… (н минус 1))`,
ровно как в `segment.flang`): код 0, «утверждений 1: доказано 0, **сетка 1**»,
а в записи:

```
утверждение «сумма лет неотрицательна» функции «Сумма лет» строка 10
  вид postcondition
  вердикт нет вердикта
  теоремы нет
конец утверждения
```

Ни носителя, ни причины. Это и есть «молчаливое „не подошло“» из задачи: три
функции «по имени» вернули `«Узел ничто»`, и дальше о них никто не спросил.
Легенда ведомости при этом говорит (`proof.flang:3063`): «Принцип читается с
ОБЪЯВЛЕНИЯ, и носителей у него **два**» — текст отстал от кода на один носитель.

### 2.3. Сверщик: слово вне трёх ловит, ложь про отрезок — нет

Записи собраны руками поверх **честной** шапки (строк/знаков/оба отпечатка/
`отпечаток256` сняты ядром с того же исходника), подменён только блок
утверждения — по форме `if-over-a-segment.запись`.

| проба | исходник | что в записи | код | первая строка ответа |
| --- | --- | --- | --- | --- |
| П2 | `н: число` | `носитель record` | **1** | `НЕ СОШЛОСЬ: … носитель принципа «record» — сверщику известны только «algebra», «segment» и «fold»` |
| П1 | `н: число` | `принцип тип «число» … носитель segment`, посылки «дно»/«спуск», вердикт доказано | **3** | `НЕ ВЗЯЛСЯ (строк причин 4; мест на слово ядра 3): … узел вердикта не проигран — спуск «н плюс …» — ни сумма неотрицательного по построению …` |
| П1б | `н: число` | то же, но `тип «неотрицательное»` (ложь и о типе) | **3** | тот же текст |
| П3 | `н: «Возраст»` (псевдоним) | `принцип тип «Возраст» … носитель segment` | **3** | тот же текст |

П1 — подделка класса «лжёт-запись» (индукции по `число` не существует, ядро
такую запись не печатает), и она обязана давать 1. Сверщик отвечает 3: он
пытается **проиграть** спуск, не находит `н : неотрицательное` в `принимает` и
списывает место на слово ядра. Условия «носитель `segment` разрешён объявлением
параметра» у него нет — он верит слову записи.

### 2.4. Списки имён разошлись — честная запись честной программы не проигрывается

`if-over-a-segment.flang` с заменой `неотрицательное` → `натуральное` (одно из
шести имён `«Названо натуральным»`):

| кто | ответ |
| --- | --- |
| ядро | `ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 3: доказано 3`, три строки `носитель segment`, код 0 |
| сверщик | код **3**, `узел вердикта не проигран — спуск …` |
| контроль (`неотрицательное`) | сверщик: `ПРОВЕРЕНО … всё доказанное проиграно заново`, код 0 |

Это ровно «разошлись молча» из ADR-0026 §6 п. 3, только уже случившееся: ядро
знает 6 имён, сверщик — 2. В корпусе подписи пишут `неотрицательное` 39 раз,
`нат` 6, остальных четырёх имён — 0, поэтому сегодня это не потеря доли; но
первый же файл с `nat`/`натуральное` уйдёт со слова ядра.

## 3. Замена: разбор объявления как единственный источник

### 3.1. Сегодня смешаны две оси, и от этого список «из трёх»

«Носитель» в записи отвечает сразу на два вопроса: **что даёт тип** и **как
прочитано тело**. Разведём:

| объявление типа | что оно даёт принципу | какое тело читается | слово в записи |
| --- | --- | --- | --- |
| `тип «Т»` с `вариант …`; встроенные `список`, `строка` | начальная алгебра: варианты, у каждого — рекурсивные части (уже читает `«Сигнатура функтора»`, `proof-initial.flang:858`) | `разбор` по переменной | `algebra` |
| то же | то же | `свёртка` по переменной | `fold` |
| `неотрицательное` и синонимы — встроенный отрезок [0, 2⁵³−1] | конечный отрезок с дном 0 и точным шагом | `если` с дном и спуском на 1 | `segment` |
| `объект «Т»` (запись) — **новое** | начальная алгебра с одним конструктором и нулём рекурсивных частей: одна посылка, без допущений | `разбор`/чтение полей | `algebra` |
| `тип «Т» это Х` (псевдоним) — **новое** | то, что даёт `Х`, по цепочке | как у `Х` | как у `Х` |
| `число`, `целое`, `признак`, функция, параметр типа, `вес` | **нет принципа**, и у каждого своя причина (`+∞`; нет дна; не индуктивен; …) | — | отказ `FLANG_PROOF_INDUCTION_TYPE` с причиной поимённо |

Ось «что даёт тип» — двузначная (алгебра / отрезок) плюс отказ. Ось «как
прочитано тело» — трёхзначная (разбор / свёртка / если) и подчинена первой:
свёртка возможна только над алгеброй-списком, `если` — только над отрезком.
Список «из трёх» — это склейка двух осей в одно слово. Разбор объявления
заменяет первую ось; вторая остаётся чтением тела, каким она и есть.

### 3.2. Ядро: одна функция вместо шести, одно значение вместо трёх литералов

Новый тип в `proofterm.flang` (или `proof-initial.flang`, где живут читатели
объявлений):

```flang
тип «Принцип типа»
  вариант «Начальная алгебра» содержит «сумма»: «Значение», «откуда»: строка
  вариант «Отрезок с дном» содержит «имя»: строка, «дно»: число, «потолок»: число, «откуда»: строка
  вариант «Нет принципа» содержит «причина»: строка
```

`«откуда»` — что именно прочитано: `тип «Дерево» строка 25`, `объект «Точка»
строка 6`, `псевдоним «Возраст» → неотрицательное строка 6`, `встроенный
список`. Это поле уезжает в запись (§3.3).

Одна функция `«Принцип типа по объявлению»` (программа × узел типа) — читает,
не перебирает:

1. узел `list`/`string` → `«Объявление списка»`/`«Объявление строки»`
   (`proof-initial.flang:666, 747`, уже есть) → `«Начальная алгебра»`;
2. узел `named` → ищет в `program.types` **по имени, любого `kind`**:
   - `sum` → `«Начальная алгебра»` (как сегодня `«Сумма по имени»`);
   - `record` → `«Начальная алгебра»` с одним вариантом из полей записи
     (арность 0 — `«Поле рекурсивно»` 107 и так вернёт «нет» для полей не того
     имени);
   - `alias` → рекурсивно по полю `of` (с ограничением глубины — цепочка
     псевдонимов конечна, но ядру это надо доказать тотальностью: мера — число
     ещё не пройденных объявлений);
   - имени нет среди объявлений: `«Названо натуральным»` (тот же список из
     `proof-kernel.flang:5546`) → `«Отрезок с дном»` с `дно 0`, `потолок 2⁵³−1`;
     иначе `«Нет принципа»` с причиной по имени (`число` — `+∞`; `целое` — нет
     дна; `признак` — не индуктивен; неизвестное имя — «объявления нет»);
3. узел `function`/`param`/прочее → `«Нет принципа»` с причиной по виду узла.

Куда встаёт:

- `«Проверить индукцию»` (2217–2230) — один `разбор` по `«Принцип типа»`:
  алгебра → `«Проверить индукцию по сумме»`; отрезок → `«Проверить индукцию по
  отрезку»`; нет → `«Отказ без принципа»` **с причиной из значения** (текст
  «читается из трёх мест» уходит, вместо него — что прочитано и почему не
  подошло).
- `«Случаями по телу»`/`«Свёрткой по телу»`/`«Отрезком по телу»` (2752–2842)
  остаются чтением тела, но принцип типа считается **один раз до них**, и
  каждая ветка проверяет совместимость (свёртка только над алгеброй, `если`
  только над отрезком). Три функции «по имени» (2849–2894, 37 строк) уходят.
  Несовместимость и `«Нет принципа»` **не молчат**: узел вердикта получает поле
  `unread` с видом `carrier` и причиной — той же дорогой, какой сегодня
  уезжают непрочитанные мера/дно/спуск (`«Отказ непрочитанного»` 1824), — и
  ведомость печатает причину вместо голого «сетка».
- `«Принцип по числу»` (`proof-initial.flang:2596`) получает дно и потолок из
  `«Отрезок с дном»`, а не из знания, что имя натуральное; для псевдонима это
  единственный способ прочесть отрезок.
- Три литерала `"carrier"` (1662, 1957, 2354) → одна функция
  `«Код носителя»` от (`«Принцип типа»`, форма тела): алгебра+разбор →
  `algebra`, алгебра+свёртка → `fold`, отрезок+если → `segment`. Слова в записи
  **не меняются** — этого требует §3.3 и весь набор проб.
- `«Узел типа переменной индукции»` (1717) остаётся единственным чтением типа;
  `forall.type` в обязательстве уже есть (§1.1) и сверяется с ним отдельным
  отказом, если разошлись (сегодня такого сличения нет — это и есть п. 1
  задачи).

Порядок величин: −37 строк перебора, +≈60 строк читателя и типа, ±0 в
`proof-initial`. Тексты отказов и легенда ведомости (`proof.flang:3063`)
переписываются по значению.

### 3.3. Запись: ядро печатает, что прочло, — а сверщик это сверяет

К строке `принцип тип «Т» по «п» носитель X база Б шаг Ш` (без изменений)
добавляется одна строка **под ней**:

```
  объявление сумма «Дерево» строка 25 варианты «Лист» 0 «Узел» 2
  объявление запись «Точка» строка 6 варианты «Точка» 0
  объявление псевдоним «Возраст» строка 6 → отрезок «неотрицательное» дно 0 потолок 9007199254740991
  объявление встроенный «список» варианты «пусто» 0 «голова и хвост» 1
  объявление встроенный «неотрицательное» дно 0 потолок 9007199254740991
```

Число после имени варианта — арность (сколько рекурсивных частей). Строка
печатается из поля `«откуда»` и функтора — то есть из того, что ядро **уже**
вычислило; она не добавляет ядру ни одного решения.

Зачем строка, если сверщик всё равно читает объявление сам (§3.4): чтобы дубль
стал **проверяемым**. Сегодня расхождение ядра и сверщика (§2.4) не видно
никому: ядро пишет `segment`, сверщик молча уходит в код 3. Со строкой
`объявление` сверщик сличает **три вещи**: (а) свою собственную читку
объявления с этой строкой знак в знак; (б) слово `носитель` с видом объявления
(`сумма`/`запись`/`встроенный`-сумма → `algebra`|`fold`; `отрезок` → `segment`);
(в) число и имена посылок с вариантами и арностями. Любое расхождение — код 1
с названным местом.

### 3.4. Сверщик на C: читатель объявлений вместо списка слов

Одна функция вместо четырёх списков и одного перебора:

```c
typedef struct { const char *вид;   /* "сумма" | "запись" | "псевдоним" | "отрезок" | "встроенная-сумма" | "" */
                 Сп варианты; Сп арности; const char *цель; long строка; long дно, потолок; } Объявление;
static Объявление объявление_типа(Сп строки, const char *имя);
```

Читает из **исходника**: блок `тип «X»` + `вариант` (это уже `варианты_типа`,
721), блок `объект «X»` + поля (новое, тем же приёмом), строку `тип «X» это Y`
(новое; по `Y` — рекурсивно), встроенные `список`/`строка` (уже зашиты в
735) и встроенный отрезок — **по одному списку имён** (§3.5). Арность варианта
считается по полям, чей тип — то же имя (как `«Поле рекурсивно»` в ядре; список
`список «X»` не считается — граница та же, что у ядра).

Куда встаёт:

- 6641–6644: вместо `strcmp` с тремя словами — `носитель` обязан быть тем, что
  **выводится** из `объявление_типа(...).вид`; слово вне вывода — код 1 с
  текстом «носитель `segment`, а объявление параметра «н» — `число`, отрезка с
  дном у него нет». Это закрывает П1/П1б/П3 из §2.3.
- 6667–6675 (имена посылок) и 6676–6687 (покрытие) — по `вид`, покрытие теперь
  и для `запись` (ровно одна посылка) и для псевдонима-к-сумме.
- 6656–6664 (сличение строки `объявление` с собственной читкой) — новое.
- 4512–4519 (ветка проигрывания) — по `вид` + слову тела, а не по слову записи.
- 3773 `довод_с_дном`, 7490 `тип_отрезок_с_дном`, 6105, 6270 — на один
  `объявление_типа(...).вид == "отрезок"`.
- 5205 (тождество свёртки только над `список`) — остаётся названным
  ограничением; строка/сумма под свёрткой у сверщика в приём не входят и
  сегодня.

`сверщик.flang` (874–901) получает тот же читатель на flang — там уже есть
`«Варианты типа»`, добавить `объект`/`это`.

### 3.5. Встроенные имена — один список, и он под сторожем

Список имён встроенного отрезка — знание о **языке**, а не о программе; читать
его из исходника неоткуда, и в обеих программах он останется. Чтобы дубль был
проверяемым, а не молчаливым:

1. Список объявляется таблицей `flang/proof/ОТРЕЗКИ.tsv` (имя, дно, потолок,
   целость, откуда в типизаторе) — по образцу `ПРАВИЛА-ВЫВОДА.tsv` (задача
   6130, ADR-0022 §3), с отпечатком.
2. `сверка-ведомости.sh` получает пятый сторож **С-5**: имена таблицы равны
   строке `«Названо натуральным»` (`proof-kernel.flang:5546`) и равны списку в
   `сверщик.c` (`тип_отрезок_с_дном`) и в `сверщик.flang` — в обе стороны, как
   С-1 сверяет имена правил. **Сегодня С-5 был бы красным** (6 против 2, §2.4)
   — и это правильно: расхождение существует, его надо увидеть, а не заводить
   сторож зелёным.
3. То же для слов носителя: `algebra`/`segment`/`fold` — три слова, и они
   обязаны совпадать между `«Код носителя»` ядра, `zapis.flang`, `сверщик.c`
   и `сверщик.flang`; сторож С-1 уже умеет сличать закрытые списки двух
   сверщиков с ядром — добавить ещё одно поле.

### 3.6. Как это ложится в ADR-0026

ADR-0026 §5 шаг 1 требует: разбор объявления вместо перебора, отказ поимённо,
правка в ядре **и** в проверяющей программе, подделка. §6 п. 3 признаёт цену:
«два места вместо одного, дважды», и что разойтись они могут молча.

Проект не отменяет второе место — при модели доверия ADR-0014/0022 сверщик
обязан читать объявление **сам**, иначе он верит ядру. Он делает дубль
**громким** тремя способами: сверщик сверяет строку записи с исходником
(§3.3); сторож сверяет списки трёх программ (§3.5); подделки сверяют поведение
живым прогоном (§5). Доверенная база при этом растёт на ≈60 строк flang и
≈120 строк C — и это честная цена, названная в ADR §6 п. 1.

Что проект **не** делает (по границам задачи): не снимает «переменная обязана
быть параметром» (шаг 2), не заводит `∃` и высший порядок (шаг 3), не трогает
`flang/ct` — там опереться не на что (ADR §4.3 подтверждён: ссылок из ядра и
сверщика на `flang/ct` ноль, и прогоном здесь ничего нового не найдено).

Трогает `proofterm.flang` (204–215, 1717–1723, 1816–1819, 2199–2230,
2752–2894), `proof-initial.flang` (1662, 1957, 2354, 2596–2650),

Практика ствола — «батч перепечатки» (коммиты `17548d851`, `c8c172758`):
несколько правок ядра → одна печать. **Ш1 идёт в один батч с 6202** (§7).

### Ш2 — строка `объявление` в записи и её сверка

Трогает `zapis.flang:1454–1469`, `сверщик.c` (сличение, §3.3), пересъёмку 26
записей корпуса, у которых есть строки `принцип` (список — в приложении).

1. Печать строки из `«откуда»` + функтора.
2. Сверщик: строка **необязательна** для записей без неё (старые семьи проб),

   записей не краснеют до пересъёмки, а после пересъёмки — сверяются.
3. Пересъёмка: `доля-корпуса.sh` уже умеет печатать записи ядром
   (`--записать`, строки 1595/1936); переснять 26, `diff` обязан показать
   **только** добавленные строки `объявление`.
4. Подделки на строку: `объявление` с чужим числом вариантов → 1; `носитель
   segment` при `объявление сумма` → 1. Храповик — `33 → 35`.

### Ш3 — тексты

SPEC.md §3 («три источника» → «объявление»), ADR-0026 §2.4 (поправка про
`forall`, §1.1), легенда ведомости, `ЧИТАТЬ.md` сверщика (таблица наборов),

### Чего не делать

- Не менять слова `algebra`/`segment`/`fold` в записи: 237 проб и 86 записей

| | 6202 (потолок → посылка П3) | 6203 (носитель из объявления) |

Строки не пересекаются нигде: разные файлы ядра, разные функции `сверщик.c`
(6509 против 6625+), разные строки таблиц. Пересекаются **три вещи**:

1. `НАБОР.tsv` и `ХРАПОВИК.txt` — оба дописывают строки и поднимают числа.
   Разносится порядком: кто вливается вторым, **пересчитывает** числа
   храповика прогоном (`доля-корпуса.sh --проигрыванием`, строка «числитель
   набора»), а не берёт максимум из двух веток. Слияние строк `НАБОР.tsv` —
   текстовое, конфликт тривиальный.
2. Записи корпуса — пересъёмка. Записей на правиле потолка (`grep
   'ограниченность точным потолком по построению'`) пять: `boundaries`,
   `corpus-natural-ceiling`, `abilities`, `poddelka-dlina`, `sources`; из них
   **три** несут и строку `принцип` — `abilities`, `poddelka-dlina`, `sources`.
   Кто второй — переснимает **все** свои записи на слитом ядре; `diff` обязан
   быть объясним строками обеих задач.
3. Семя. Две перепечатки по 8–12 ч вместо одной — цена несогласованности.
   Порядок: **6202 первым** (правка ядра меньше и уже измерена задачей), Ш0
   этой задачи — **параллельно** (семени не трогает, `сверщик.c` — в других
   функциях), Ш1 — в **тот же батч перепечатки**, что 6202, Ш2 — после. Тогда
   печать одна.

Общий гейт после слияния: `прогон.sh` «сошлось всё», `доказуемость.sh` 1/3/4
«ДА», доля ≥ 567/651, `сверка-ведомости.sh` код 0 (с С-5 — уже зелёным).

## 8. Где не уверен

- **Псевдоним в `vars`.** Что там лежит тип как написан — следует из текста
  отказа («Возраст») и `obligations.flang:197–201`; что типизатор не подменяет
  его где-то раньше для других слоёв — не проверял. Ш1 обязан начать с этого.
- **Индукция по записи (`объект`) — нужна ли.** Принцип с одной посылкой без
  допущений почти совпадает с «доказано по объявленным типам»
  (`«Вердикт по объявлению»`, `proofterm.flang:2649`). Замера, есть ли место, где
  он даст что-то сверх, нет: `объект` под квантором в корпусе 0.
- **Проверка ядра до перепечатки** через `flang io` из исходника — названа по
  коммиту `ea8fdb596` («10 мин на factorial»), здесь не гонялась; для
  `check --proof` на корпусе цена не измерена.
- **Свёртка над строкой/суммой.** Ядро допускает (`«Свёрткой по имени»` 2879:
  любой непустой `«Начало принципа»`), сверщик — только `список` (5205). Ещё
  одно расхождение того же рода, что §2.4; в корпусе `fold` — 4 записи, все по
  списку. В задачу не входит, названо.
- **Число пересъёмок в Ш2** — 26 записей (по `grep 'принцип тип'`), если
  строка `объявление` идёт под каждый принцип; при печати только для
  объявленных в программе сумм — 13 (замер по типу в строке `принцип`).
  Выбор за исполнителем, цена та же (одна печать ядром).
- **Цена С-5 «красным с первого дня»** — сторож, заведённый красным, надо
  зеленить в том же коммите (сверщик учит 6 имён); иначе `сверка-ведомости.sh`
  в гейте краснит всех соседей.
- **`сверщик.flang` как второй гейт** — С-1 требует согласия «обоих
  сверщиков»; сколько стоит научить его читателю объявлений — не мерил
  (1 994 строки, `«Варианты типа»` уже есть).

## Приложение. Прогоны, файлы, команды

Двоичный: `make -s -C bootstrap` в worktree `w6203d` от `4d13d5a88`
(≈6 мин). Сверщик: `cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -o сверщик flang/proof/чекер/сверщик.c`.

Пробные программы (в scratchpad прогона, не в дереве):

- `тип-запись.flang` — `объект «Точка»`, `для всех т …`, теорема `индукция по т`;
- `тип-псевдоним.flang` / `тип-псевдоним-без-теоремы.flang` — `тип «Возраст» это неотрицательное`, тело как в `segment.flang`;
- `тип-число.flang` / `тип-число-без-теоремы.flang` — `н: число`;
- `имя-натуральное.flang` — `if-over-a-segment.flang` с `sed s/неотрицательное/натуральное/g`.

Команды:

```sh
LC_ALL=C.UTF-8 bootstrap/flang check <файл> --proof --записать <файл>.запись
./сверщик <исходник> <запись>; echo $?
for f in flang/proof/examples/*.flang flang/test/fixtures/*.flang flang/proof/map/*.flang; do
  LC_ALL=C.UTF-8 bootstrap/flang check "$f" --proof; done 2>&1 | grep -c FLANG_PROOF_INDUCTION_TYPE   # 0
grep -h '^ *принцип тип ' flang/proof/чекер/пробы/записи/корпус/*.запись | sed -n 's/.*носитель \([a-z]*\).*/\1/p' | sort | uniq -c
sh scripts/доказуемость.sh
```

Подделки П1/П1б/П2/П3: шапка (9 строк) — из честной записи ядра для того же
исходника, блок утверждения — по форме `if-over-a-segment.запись` с
подменёнными `тип`/`носитель`.
