правил внутри записи (ADR-0022 §3.10). *Второй судья* — ядро Lean 4, которому поданы
леммы по правилам таблицы (`flang/proof/lean/`).

## 1. Как выбраны десять

Утверждение попадало в список, только если выполнены все четыре условия.

- **Тема из ADR-0028 §6 п.1:** целые в пределах представления [0, 2⁵³−1], границы,
  инварианты свёрток, свойства списков, порядок.
- **Нужно дереву сегодня:** есть открытое место корпуса, которому этот факт нужен, или
  повторяемый довод — закон, зашитый в проверяющую программу, повторяющееся постусловие
  стандартной библиотеки.
- **Записывается формами ADR-0026 §11** — `утверждение «имя»` с `для всех л: тип`,
  несколько имён через `и`, ограничение `таких что` — без того, что в партию не входит:
  квантор в `требует` (п.5), индукция по функции (п.8), лексикографическая индукция (п.2).
- **Вывод собирается правилами таблицы** — или точно названо, какого правила не хватает.

**Запись на flang ниже — черновик синтаксиса**, по контракту формы записи кванторов (рабочая
записка стека ядра вне дерева: `ПЕРЕДАЧА/stack-B/kontrakt-kvantory.md`, разделы К3, К5) и
ADR-0026 §11 п.3, п.6. **Проверяется после партии**: ни одна строка ниже не проходила
разбор.

**Блок `вывод`** — в той форме, что ядро уже печатает для постусловий (образец —
`flang/proof/чекер/пробы/семьи/вывод/pred-zov.запись`): `вывод цель ⟨…⟩`, затем шаги
`вывод K ПРАВИЛО ⟨заключение⟩` с опорой `сам` (посылок нет), `строка N` (факт взят со
строки исходника) или `из I J` (посылки — шаги I и J), затем `вывод конец`. У постусловия
последний шаг — `Разв2` (развёртка тела функции в `результат`); у утверждения функции нет,
цель — сама формула, и этого шага нет. Заголовок блока утверждения — по контракту К3:
`утверждение «И» строка N` / `вид statement` / `для всех «л» ⟨тип⟩ строка N` /
`таких что ⟨…⟩ строка N`.

### 2.1. Как будет выглядеть блок `вывод` каждого

Шапка блока (`утверждение «И» строка N` / `вид statement` / `для всех …` / `таких что …` /
`вердикт доказано` / `теоремы нет` / `правило «…»`) — по контракту К3 и К5; ниже только
сам вывод. Номера строк — `N`: исходника нет.

**1. Длина любого списка не меньше нуля**

```
    вывод цель ⟨( длина л ) не меньше 0⟩
    вывод 1 Н4 ⟨( длина л ) не меньше 0⟩ сам
    вывод конец
```

Тот же шаг уже стоит в пробах: `вывод 1 Н4 ⟨( длина элементы ) не меньше 0⟩ сам`.

**2. Сумма двух неотрицательных**

```
    вывод цель ⟨( а плюс б ) не меньше 0⟩
    вывод 1 Н3 ⟨а не меньше 0⟩ строка N
    вывод 2 Н3 ⟨б не меньше 0⟩ строка N
    вывод 3 Н5 ⟨( а плюс б ) не меньше 0⟩ из 1 2
    вывод конец
```

`строка N` у Н3 — строка связывания `для всех а: неотрицательное …`: тип с дном назван
там, а не в параметре функции.

**3. Разность под потолком**

```
    вывод цель ⟨( а минус б ) не больше 9007199254740991⟩
    вывод 1 П2 ⟨а не больше 9007199254740991⟩ строка N
    вывод 2 Н3 ⟨б не меньше 0⟩ строка N
    вывод 3 П5 ⟨( а минус б ) не больше 9007199254740991⟩ из 1 2
    вывод конец
```

Шаг 1 берёт потолок из ограничения `таких что` (строка N — строка ограничения), правилом
П2 «граница из допущения». У постусловия тот же вывод идёт через Пред1 → П3 (проба
`pred-zov.запись`): там потолок — обязательство, которое оплачивает зовущий (ADR-0025).
У утверждения зовущего нет, поэтому потолок записан ограничением; другой путь — §5 п.3.

**4. Остаток от 7**

```
    вывод цель ⟨( н остаток от 7 ) не больше 6⟩
    вывод 1 Н3 ⟨н не меньше 0⟩ строка N
    вывод 2 П6 ⟨( н остаток от 7 ) не больше 6⟩ из 1
    вывод конец
```

Делитель — литерал: П6 берёт только положительный целый литерал. Утверждение с
делителем-переменной (`для всех н и д таких что д больше 0`) правилами таблицы не
выводится — кандидат в полосу Lean и в новую строку таблицы (§3).

**5. Счёт по условию не меньше нуля**

```
    вывод цель ⟨( свёртка л начиная с 0 как акк и эл → … ) не меньше 0⟩
    вывод 1 Н1 ⟨0 не меньше 0⟩ сам
    вывод 2 Н2 ⟨акк не меньше 0⟩ <допущение шага свёртки>
    вывод 3 Н1 ⟨1 не меньше 0⟩ сам
    вывод 4 Н5 ⟨( акк плюс 1 ) не меньше 0⟩ из 2 3
    вывод 5 Н6 ⟨( если у от эл то акк плюс 1 иначе акк ) не меньше 0⟩ из 4 2
    вывод 6 Н7 ⟨( свёртка л … ) не меньше 0⟩ из 1 5
    вывод конец
```

Вторая посылка Н7 — «тело шага неотрицательно ПРИ неотрицательном накопителе»: шаг 2
опирается на допущение, которое вводит сама свёртка, а не строка исходника. Формы такой
опоры в записи сегодня нет; её задаёт печать Н7 (задача
[6132](../../tasks/6132-yadro-pechataet-vyvod-fakta-o-tipe.md)), не эта записка.

**6. Счёт по условию не больше длины**

```
    вывод цель ⟨( свёртка л начиная с 0 как акк и эл → … ) не больше ( длина л )⟩
    вывод 1 О9 ⟨( свёртка л … ) не больше ( длина л )⟩ сам
    вывод конец
```

Две посылки О9 по таблице — «начало свёртки есть ноль» и «шаг прибавляет не больше
единицы» — это сличения формы, а не подвыводы других правил. Печатать их отдельными
шагами или оставить побочными условиями — решает печать О9.

**7. Отбор не удлиняет**

```
    вывод цель ⟨( длина ( отфильтровать л где эл → у от эл ) ) не больше ( длина л )⟩
    вывод 1 Н4 ⟨( длина л ) не меньше 0⟩ сам
    вывод 2 О2 ⟨( длина л ) не больше ( длина л )⟩ из 1
    вывод 3 О8 ⟨( длина ( отфильтровать л … ) ) не больше ( длина л )⟩ из 2
    вывод конец
```

Шаги 1–2 уже стоят в пробах знак в знак (`вывод 2 О2 ⟨( длина элементы ) не больше ( длина элементы )⟩ из 1`).
Расхождение: в таблице у О8 посылок 0, а ядро по её же колонке «побочные» переписывает
`длина (отфильтровать Л …)` в `длина Л` и зовёт разбор порядка заново — то есть посылка
есть. Либо строка О8 получает посылку ⟨1⟩, либо шаг 3 печатается `сам` и шаги 1–2
исчезают; решать при печати О8.

**8. Приписывание сохраняет неубывание**

```
    вывод цель ⟨( приписать г к ( приписать в к х ) ) не убывает⟩
    вывод 1 СС2 ⟨( приписать в к х ) не убывает⟩ строка N
    вывод 2 О1 ⟨г не больше в⟩ строка N
    вывод 3 СС3 ⟨( приписать г к ( приписать в к х ) ) не убывает⟩ из 1 2
    вывод конец
```

Оба факта — половины одного ограничения `таких что … и притом …`; распадается ли оно в
ядре на два факта, не проверено (§5 п.4).

**9. Добавленное содержится**

```
    вывод цель ⟨( добавить э к л ) содержит э⟩
    вывод 1 В2 ⟨( добавить э к л ) содержит э⟩ сам
    вывод конец
```

Шаг знак в знак как в пробах: `вывод 1 В2 ⟨( добавить что к элементы ) содержит что⟩ сам`.

**10. Прибавление общего сохраняет порядок**

```
    вывод цель ⟨( ш плюс о ) не больше ( ш плюс п )⟩
    вывод 1 О1 ⟨о не больше п⟩ строка N
    вывод 2 ??? ⟨ш — число⟩ из 3 4         ← правила нет
    вывод 3 Н3 ⟨ш не меньше 0⟩ строка N
    вывод 4 П2 ⟨ш не больше 9007199254740991⟩ строка N
    вывод 5 О5 ⟨( ш плюс о ) не больше ( ш плюс п )⟩ из 1 2
    вывод конец
```

Посылка ⟨2⟩ О5 — «общая прибавка — ЧИСЛО, ни бесконечность, ни не-число». Именно её
отсутствие Lean нашёл в прежней записи О5 (при Г = +∞ и Ш = −∞ обе суммы — не-число).
Сегодня её закрывает только целый литерал. Для переменной нужно новое правило вида
«Т не меньше 0 и Т не больше конечного литерала ⇒ Т — число»: строка таблицы, лемма в
Lean, приём в `сверщик.c` и печать в ядре. Это отдельное решение, не часть библиотеки.

### 2.2. Что не вошло в десять и почему

- **«Литерал неотрицателен»** — самый частый зашитый закон (в записях корпуса на него 15
  ссылок), но это правило Н1 без переменных: квантору нечего связывать. Заменить закон
  выводом Н1 — правка проверяющей программы, не утверждение библиотеки.
- **Дно произведения** (4 места `poddelka-dno-proizvedeniya`, «произведение не ниже
  единицы»). Правило Д5 в таблице есть, но печать ядра от него отказалась: дно
  произведения надо сосчитать. Решение по нему — у стека разбора случаев (ADR-0027,
  подведро Е-5), не здесь.
- **Целость из охраны** (4 места `poddelka-integrality-from-fact`): закона нет нигде, а
  модель Lean дробей не знает (§3), так что и второму судье его не поручить.
- **Начало строки** (2 места, «склейка начинается со звёздочки и двойки»): Ч5 требует
  сличить точный текст, то есть вычислить его; к библиотеке о программах это ближе всего,
  но кванторного утверждения тут нет — места о выписанных литералах.
- **Исключённое третье** (3 места, цель вида `(не (х больше 0)) или (х больше 0)`). По
  виду цели это, вероятно, три места `corpus-hof` «признак … влечёт …»: сравнение
  возвращает признак, у признака два значения, и разбор его на «да»/«нет» (правила Р2/Р3)
  закрывает цель без классического закона. Если так, это работа печати семейства Р
  (ADR-0027), а не библиотеки и не Lean (§5 п.9).

## 3. Полоса второго судьи (Lean)

### 3.1. Что поручается и почему мост туда короток

Мост — доказательство того, что объект Lean правда описывает наше значение. Он короток
там, где модель `flang/proof/lean/Модель.lean` описывает значение одним прямым
определением, которое читается глазами за минуту:

- **Значение** — `«Знач»`: конечное целое, плюс и минус бесконечность, не-число.
- **Порядок** — `«неБольше»` (на не-числе ложно всегда), строгий `«меньше»`, `«равен»`.
- **Арифметика** — `«плюс»`, `«минус»`, `«умножить»`, `«остаток»` через округление, о
  котором предположено РОВНО два свойства: оно не меняет целых в пределах 2⁵³ и не
  переставляет порядок.
- **Списки** — `List «Знач»`, `«свёртка»`, `«разборСписка»`, `«неубыв»`; **строки** — список
  знаков, `«начинается»`.

Отсюда полоса, в порядке, в каком она нужна библиотеке.

1. **Состоятельность каждой строки таблицы, которой пользуются десять.** Уже сделано:
   `flang/proof/lean/Правила.lean` — лемма на строку, над леммой строка таблицы дословно
   всеми колонками; нарочно испорченные правила в `Ловушка.lean` Lean отвергает.
   Правила десяти (Н1–Н7, П2, П5, П6, О1, О2, О5, О8, О9, СС2, СС3, В2) переведены там все.
2. **Новые строки таблицы, которые библиотека попросит, — до того, как строка войдёт в
   таблицу.** Сейчас их две: «Т не меньше 0 и Т не больше конечного литерала ⇒ Т —
   число» (утверждение 10) и остаток с делителем-переменной (обобщение утверждения 4). Обе
   — целая арифметика внутри потолка; в модели для первой уже есть опора
   (`«неNaNлево»`, `«подЧислом»`).
3. **Утверждения библиотеки, которые проверяющая программа переиграть пока не может**
   (4–7, пока в `сверщик.c` нет Н6, Н7, П6, О8, О9; 10 — пока нет правила). Lean может
   подтвердить само утверждение над моделью: квантор «для всех л: список числа»
   переводится в `∀ l : List «Знач»` без промежуточных понятий. Такое подтверждение
   печатается отдельной строкой и в долю не идёт (§3.3).
4. **Места «закона отношений» и «исключённого третьего», если они дойдут до Lean.**
   Чтением целей (не прогоном): из 14 мест «закона отношений» в полосу попадают порядок и
   строгий порядок под охраной, рефлексивность, монотонность сложения, начало строки, дно
   произведения; не попадают 4 места целости из охраны. Три места «исключённого третьего»
   для признака в модели — тавтология над `Bool`, но, вероятно, до Lean не дойдут вовсе
   (§2.2).

### 3.2. Что НЕ поручается — и почему

- **Рациональные.** Модель дробей не знает: конечное значение в ней целое
  (`docs/lean-checks-the-inference-rules.md` §4 п.1). Мост к рациональным не построен и не
  оценён (ADR-0028 §10).
- **Плавающая точка за пределами двух свойств округления.** Переполнение в бесконечность
  модель не воспроизводит (там же, §4 п.3), знак нуля у результата арифметики не различает
  (§4 п.4). Всё, что зависит от этого, — вне полосы; мост не оценён.
- **Целость, прочитанная из охраны** (`(н остаток от 1) равен 0` ⇒ «н целое»): в модели
  нецелого значения нет, поэтому утверждение там истинно по построению и ничего не
  проверяет.
- **Переименование связанной переменной** (правило Т2): в модели нет записи терма, Т2 не
  выразилось и при сверке правил.
- **Порядок поиска и полнота правил, соответствие `сверщик.c` строкам таблицы.** Lean
  проверяет, что правило верно, а не что его так применяет код.

### 3.3. Где печатается строка «подтверждено вторым судьёй» (только описание)

ADR-0028 §11 п.1: место, подтверждённое только Lean, печатается отдельной строкой и в
числитель не идёт. Скрипты этой запиской не трогаются; описание того, куда строка ляжет:

- **Считает** — [`flang/proof/доля-корпуса.sh`](../../flang/proof/доля-корпуса.sh) (прибор
  доли), в режиме `--проигрыванием`, в разделе «не проверенное у поручённых записей,
  поимённо» — рядом со строками «на слово ядра» и «снято калькулятором», отдельной строкой
  вида `подтверждено вторым судьёй (Lean), в числитель не идёт   N`. Эти N мест —
  подмножество «не проверено у поручённых записей»: знаменатель не меняется, числитель
  тоже.
- **Показывает** — [`scripts/доказуемость.sh`](../../scripts/доказуемость.sh) (вердикт),
  справочной строкой под «проверка 2». Долю он берёт только из строки
  `доля-проигрыванием = …` (якоря `sed` в строках 220–222), поэтому отдельная строка в
  числитель не просочится, и ни одна из четырёх проверок от неё не зависит.
- **Третий исход.** Если Lean не установлен или в том же прогоне не прошла ловушка с
  нарочно испорченными правилами (ADR-0028 §9 п.4), строка печатает «не снято», а не 0.

## 4. Порог и какое утверждение пойдёт первым

ADR-0028 §11 п.2: «ADR-0026 закрыт» — три проверяемых факта. На `c96a7f2bd` не выполнен
ни один.

| факт | как проверить | сегодня |
|---|---|---|
| 1. Партия перепечатки с кванторами влита | в `gh/dev` есть слияние партии; в записях корпуса появились строки `  для всех «…» строка N` (контракт, строка 3) | строк `  для всех «` в записях корпуса — 0 |
| 2. Строгий режим строк кванторов включён | `#define СТРОКИ_КВАНТОРОВ_ОБЯЗАТЕЛЬНЫ 1` в `сверщик.c` | `сверщик.c:7539` — значение 0 |
| 3. Хотя бы одно утверждение с квантором над произвольным типом записано и переиграно, код 0 | записи `вид statement` есть в корпусе, проверяющая программа отвечает на неё кодом 0 | записей `вид statement` во всём дереве — 0 |

**Первым пойдёт утверждение 1** — «длина любого списка не меньше нуля»:

```
утверждение «длина любого списка неотрицательна»
  для всех л: список числа
  утверждаем (длина л) не меньше 0
```

Почему оно:

- **квантор связывает не параметр функции** — ровно то, чего сегодня записать нельзя, и
  ровно то, что проверяет факт 3;
- **вывод в один шаг Н4 без посылок**, и Н4 проверяющая программа переигрывает уже
  сегодня — если утверждение не пройдёт, дело в кванторе, а не в арифметике;
- **ни теоремы, ни ограничения `таких что`, ни потолка** — не зависит от вопросов §5 п.3–п.5;
- **заменяет зашитый закон** «мера неотрицательна»: первый же вклад показывает, зачем
  библиотека.

Проверка факта 3 на нём: ядро печатает запись с блоком `утверждение … / вид statement /
для всех «л» ⟨список числа⟩ строка N` и выводом из §2.1; проверяющая программа при
строгом режиме отвечает кодом 0; прибор доли показывает обязательство вида `statement` в
знаменателе и в числителе. Вторым пойдёт утверждение 9 (тоже один шаг, `сам`), третьим — 2
(две посылки со строки связывания).

## 5. Где не уверен

1. **Сослаться на утверждение нечем — и это главное.** `по свойству «…»` ссылается на
   постусловие функции (`flang/proof/SPEC.md`, раздел про ссылку на свойство); контракт К3
   о ссылке на утверждение молчит, ADR-0026 §11 тоже. Пока ссылки нет, утверждение
   библиотеки — отдельное обязательство: доказано, в записи, в доле, но 17 мест из §2
   закрываются только печатью вывода прямо в их записях (задача 6132), для которой десять
   утверждений — первый образец вывода под квантором, не больше. Нужно решение: либо
   `по свойству` ссылается на утверждение (и проверяющая программа переигрывает
   подстановку), либо зашитые законы `сверщик.c:674–680` заменяются ссылкой на доказанные
   утверждения. Без него «библиотека закрывает места» — обещание, не факт.
2. **Тип элемента.** Все десять — о списках числа. Параметр типа «А» под квантором
   ADR-0026 допускает только переписыванием (матрица партии, рабочая записка вне дерева
   `ПЕРЕДАЧА/adr-0026-matrix.md`, строка К9); можно ли
   написать `для всех л: список «А»` в утверждении — контракт не говорит. Если нельзя,
   утверждения о списках придётся повторять для каждого типа элемента.
3. **Потолок у переменной точного типа.** В утверждениях 3, 4, 10 потолок представления
   записан ограничением `таких что`, по ADR-0025 (потолок — обязательство). Второй путь —
   считать, что квантор над точным типом пробегает только представимые значения, и
   выводить Пред1 из строки связывания; это новое решение, Пред1 сегодня определён только
   для довода функции.
4. **Составное ограничение.** В утверждениях 8 и 10 два факта берутся из одного
   `таких что … и притом …`; распадается ли конъюнкция в ядре на два известных факта —
   не проверял.
5. **Квантор над функцией** (утверждения 5–7, `у: функция из числа в признак`). ADR-0026
   п.8 разрешает о всех функциях только переписывание; Н7, О8, О9 индукции не ведут, так
   что должно пройти, — но не проверено, и контракт отдельно этого не называет.
6. **Формы шагов, которых ещё нет:** опора на допущение шага свёртки (утверждение 5), две
   посылки О9 (6), посылка О8, которой нет в таблице (7). Их решает печать задачи 6132.
7. **Что Н3 возьмёт строку связывания.** Опора Н3 — объявление имени типом с дном; у
   утверждения объявление — строка `для всех а: неотрицательное`. Проверяющая программа
   обязана принять её как объявление (работа К3 на её стороне) — не проверено.
8. **Числа Lean разошлись между документами.** `docs/lean-checks-the-inference-rules.md`
   говорит о 78 строках таблицы и 77 переведённых; шапка `flang/proof/lean/Правила.lean`
   — о 79 и 78; строк данных в таблице сегодня 79. Документ, похоже, отстал на одну
   строку (Пред1). Сам прогон Lean я не повторял.
9. **Исключённое третье, возможно, не довод за Lean.** ADR-0028 §6 п.3 называет 3 места
   «исключённого третьего» среди того, ради чего нужна полоса. Если это три места
   `corpus-hof` (моё предположение по виду цели), их закрывает разбор признака на два
   значения (Р2/Р3), который печатает стек ADR-0027. Прогоном не проверено.
10. **Полоса 14 мест оценена чтением целей**, не приёмом; ADR-0028 §10 честно говорит,
    что это не измерено, и эта записка измерения не добавляет.
