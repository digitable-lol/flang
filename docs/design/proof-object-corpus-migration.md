## 1. Опись записей корпуса

### 1.1. Где считано и почему НЕ по сырому grep

Задание называет три дерева — `flang/proof/**`, `stdlib/**`, `flang/self/**`.
Сырой `grep -rc 'обеспечивает «'` по ним даёт числа, которые ничего не
описывают: `flang/proof` — 770, `flang/stdlib` — 2885, `flang/self` — 7303
совпадений. Это не «места доказательств», а вхождения слова в ЛЮБОМ виде:
подделки (`flang/proof/чекер/пробы/программы`, `flang/proof/подделки`),
рукотворные записи-пробы, и — для `flang/self` — строковые ЛИТЕРАЛЫ внутри
самого компилятора (парсер/принтер/примеры кодогена держат тексты
flang-программ КАК ДАННЫЕ, не как свои собственные обязательства). Раздутое
число — не улика, а шум счётчика; сверять их без разбора значило бы
«не измерено», а не «измерено много».

Вместо этого — та же линейка, что уже держит гейт Г4: **золотой корпус**
`flang/proof/чекер/пробы/записи/корпус/` (86 `.запись`), который
`flang/proof/доля-корпуса.sh` меряет как «набор корпус» и на который ссылаются
все пять разведок. Это НЕ «весь код с постусловиями», а курированная выборка
реальных мест (`flang/proof/examples`, `flang/proof/map`) плюс несколько
образцов-крайностей из `flang/test/fixtures`, плюс пробы порчи на Г2. Он
целиком лежит внутри `flang/proof/**`, кроме шести файлов из
`flang/test/fixtures` (см. ниже) — и это единственная площадка, где сегодня
можно ОТДЕЛИТЬ калькулятор от переигрывателя числом, а не прозой, потому что
чекер сам считает оба числа и печатает их в вердикте.

### 1.2. Прогон — сколько мест калькулятор, сколько переигрыватель, СЕГОДНЯ

Чекер сам печатает оба числа в вердикте (`сверщик.c:5473`–`5497`): «сведений
проиграно заново N (ходов проверено N)» — это ПЕРЕИГРЫВАТЕЛЬ; «Узлов
«разбором по случаям»/«тождество после переписки допущением»/«разбор цели по
условию» проиграно заново N (снято со слова ядра мест N)» — это КАЛЬКУЛЯТОР
(Ч363/Ч365/Ч369 — `proigran`/`perepisan`/`razobran`, `сверщик.c:4918`+);
«Шагов по примеру/по свойству проверено по существу N» — отдельная, НЕ
калькуляторная проверка (Ч71/S2-привязка); «НА СЛОВО ЯДРА: посылок и
утверждений N, шагов N» — остаток, не покрытый НИЧЕМ.

Прогон по всем 55 честным записям (третий довод — sha256 не подавался,
привязка на многочленной свёртке; это не меняет счётчики калькулятора и
переигрывателя, только колонку «привязка»):

```bash
export LC_ALL=C.UTF-8
for f in flang/proof/чекер/пробы/записи/корпус/*.запись; do
  case $(basename "$f" .запись) in poddelka-*|forgery-*) continue;; esac
  src=$(/usr/bin/grep -a -m1 '^исходник ' "$f" | sed 's/^исходник //')
  flang/proof/чекер/сверщик "$src" "$f" 2>&1 | /usr/bin/grep -a 'утверждений '
done
```

## 2. Что перегенерить

### 2.1. Условие перегенерации

Записи `.запись` — НЕ семя, они получены `check --proof --записать` УЖЕ
собранным двоичным. Перепечатка 4125 меняет `zapis.flang` (печать), а не
`proof-kernel.flang` (вывод) — значит после перепечатки вывод ядра ТОТ ЖЕ, но
печать РАЗНАЯ: там, где вчера печаталось голое `правило «тождество после
переписки допущением»`, сегодня допечатается блок `ход цель … ход конец`.
Пока корпусные `.запись` не переснимут заново новым двоичным, чекер
по-прежнему сверяет СТАРУЮ запись (без ходов) — КОД 3 не сдвинется ни на
одно место, ровно как уже было зафиксировано раньше: «записи отстали от
печати на ТРИ перепечатки семени, и одна перегенерация дала 28 → 33 из 86»
(`proof-object-roadmap.md §2.3`).

**Признак записи старой формы у сверщика — КОД 3 с непустым «на слово ядра»
именно по тем правилам, что печатает 4125.** Как это увидеть: вердикт
`сверщик.c:5456` печатает `НЕ ВЗЯЛСЯ`/`НЕ ПРОВЕРЕНО` со строкой причины,
называющей «место на слове ядра» под конкретным правилом.

### 2.2. Список — 22 честные записи, КОД 3 сегодня

```bash
export LC_ALL=C.UTF-8
for f in flang/proof/чекер/пробы/записи/корпус/*.запись; do
  base=$(basename "$f" .запись)

  /usr/bin/grep -aq '^НЕ ПРОВЕРЕНО' /tmp/o && echo "$base"
```

Список файлов и код 3/22 — точный (прогон выше). Колонка «что несёт» —
иллюстративная классификация по семьям из пяти разведок и по счётчикам
калькулятора/на-слово каждой записи (не построчное перечтение каждого из 22
исходников заново); там, где это разошлось с разведкой при проверке, поправлено
(например, `boundaries` несёт ДВА места С2, не одно). Для точной раскладки
каждого файла до последнего утверждения смотреть сами `.запись` (`--по-
утверждениям`) — здесь цель дать РАБОЧУЮ, не карманную, оценку того, что даст
перегенерация.

| файл | что несёт | перегенерация даст ход сразу (4125) | перегенерация улучшит частично | перегенерация НЕ изменит код |
|---|---|---|---|---|

## 3. Точное условие снятия калькулятора `perepiskoy`

### 3.1. Поимённо — что обязано проиграться

Калькулятор (`perepiskoy`/`svesti_term`/`razborom_celi`/`iz_obyavlennogo`,
`сверщик.c` ~1506–3794 минус `ocenit_term`, ~2080–2289 строк) кроет ВСЁ
постусловное доказательство корпуса, а не одно правило. `git rm` законен
ТОЛЬКО когда каждый из следующих классов проигрывается переигрывателем (или
закрыт независимой проверкой по существу — Ч71/Ч56/Ч76/Ч87, которые
калькулятором не являются) — семь классов, ни одним меньше:

1. **146 мест «по объявлению»** (5 вычислительных правил, `proof-object.md
   §8`) — печатают след и переигрываются. Сюда входят семьи С1–С7 (род 1) и
   ещё девять правил вне таксономии этой задачи (неотрицательность, порядок,
   вхождение, начало, ограниченность, строгий порядок, соседи, счёт частей,
   вычисление) — 4125 печатает ТОЛЬКО подмножество рода 1 (С1/С2/С3/С4-Э1/
   С5-узкое); девять прочих правил без печати вовсе.
2. **«тождество» — все 7 семей С1–С7** (38 мест). Сегодня печатью 4125
   закрываются С1, С2, С3 целиком; С4 — только форма Э1 (не Э2–Э4, «счёт над
   вызовом» литерального номера); С5 — только замкнутая цель без вызова (не
   «К1», где счёт идёт ПОСЛЕ развёртки в пользовательский вызов); С6
   (проекция/разбор варианта) и С7 (индукция/fold ПОД теоремой) — печати
   НЕТ вовсе.
3. **«по примеру» — 14 «не взявшихся»** через рост `ocenit_term` (семьи
   A/B/C/D) — печать 4125 сюда НЕ относится: род не завязан на ходы вовсе,
   решается ростом счёта (не в этой волне).
4. **«разбором по случаям» — все 4 места** — печати «Ходы деления записи»
   для посылок под принципом в `zapis.flang` НЕТ (проверено: 0 упоминаний
   «деление» в дифф-файле `2eb5633e`, только два упоминания слова «выбор» в
   прозе комментария, не хода).
5. **«разбор цели по условию» — Р1–Р5 (21 место)** — та же дыра: чекер
   (`hod_deleniya`/`hod_vybora`) готов и придирки А+Б уже влиты
   (`3cb04bcb`), но `zapis.flang` не печатает ни строки хода `деление`/
   `выбор` ни для постусловий, ни тем более для посылок под принципом.
6. **«по предположению»/индукция S1 — хвост Р3/Р5** — расщепление связки
   (`и притом`/`или`) в `proigrat_blok`, отдельная правка кода, вне печати.
7. **«по свойству» — все 64 места** (S2). Приём в чекере готов
   (`e5a75366`, `d433f3b2`), но `zapis.flang` печатает ТОЛЬКО узкий
   «восьмой ход» (постусловие-обёртка без теоремы); АВТОРСКИЙ шаг `по
   свойству «имя»` внутри написанной `теорема` (седьмой ход — ровно то, чем
   являются все известные 64 места) печати не имеет вовсе.

`ocenit_term` (205 строк) остаётся доверенным примитивом P8 — над IEEE-754
`2+2=4` не разложить в под-ходы.

### 3.2. Пропущенный подкласс ИМЕННО этой перепечатки — поимённо, подтверждено чтением `2eb5633e`

Дифф коммита `2eb5633e` (648 добавленных строк `zapis.flang`, прочитан
целиком, без выполнения) сам называет свои границы прямо в комментариях —
ниже цитаты и файл:строка внутри диффа, не домысел:

- **Внешние скобки.** Для С1–С5 печать берёт тело функции РОВНО КАК НАПИСАНО
  и не разбирает скобки вокруг вызова; для S2 граница написана явно:
  «Тело в скобках (`(«Г» …)`) … сюда НЕ ложится: печать хода не выпускает».
  То же обнаружено разведкой рода 4 (`-razbor-celi.md §4.1`, Р2, 5 мест):
  `hod_vybora` не снимает один слой скобок вокруг `да`/`нет`, если автор
  написал `если (У) то …` — придирка Б (`3cb04bcb`) чинит ДРУГОЙ баг
  (двойное оборачивание `vstavit_vmesto`), а не эту форму; печати под неё в
  `2eb5633e` тоже нет.
- **Счёт над вызовом.** У С5 явно исключён случай «К1» — «счёт идёт ПОСЛЕ
  развёртки тела в вызов пользовательской функции… тем же сверщиком
  ОТВЕРГНУТ: терм не замкнут… считать нечего, потому что `ocenit_term` не
  считает сквозь вызов». У S2 исключено «тело с арифметикой над вызовом
  (`(«Г» …) плюс 1`)» — по той же причине: подстановка постусловия вызванной
  не работает, когда вызов обёрнут арифметикой снаружи.
- **Неравенства.** S2 явно требует «постусловие вызванной — РАВЕНСТВО
  (сверщик замыкает `закрыть по свойству` модус-поненсом только по
  равенству, сверщик.c 1114) … постусловие-неравенство вызванной сюда НЕ
  ложится». Любое место, где лемма — неравенство (а не равенство), печати
  не получает.
- **Шаги-в-теоремах.** Печать 4125 работает СТРОГО с постусловиями по
  маршруту `by == "declaration"` (без написанной `теорема`). Всё, что живёт
  ПОД `теорема`/`принцип` — посылки индукции с формой «если» (придирка А
  открыла ГЕЙТ чекера для них, `3cb04bcb`, но printer'а в `zapis.flang`
  по-прежнему нет — 0 упоминаний «Ходы посылки под принципом»/«деление» в
  дифф-файле), fold-носитель С7, авторский шаг `по свойству «имя»` внутри
  теоремы (все 64 места рода 6) — остаётся полностью непокрытым этой волной.

Все четыре подкласса совпадают со сказанным в постановке задачи дословно —
это не совпадение, а проверенный факт: подкласс назван по итогам ЭТОЙ же
серии разведок (`-razbor-celi.md`, `-lemma-po-svoystvu.md`) и подтверждён
чтением реального диффа перепечатки.

### 3.3. Необходимое и достаточное (без изменений от роадмапа)

Закрытие любого ОДНОГО класса из семи — необходимо, но не достаточно: пока
хоть один класс остаётся на калькуляторе, `git rm perepiskoy` роняет долю Г4
на местах, которые он же и кроет (`proof-object-migration.md §5`). Закрытие
ВСЕХ семи при остающемся `ocenit_term` — необходимо и достаточно.

## 4. Оценка доли после ЭТОЙ (частичной) перепечатки

### 4.1. Метод и оговорка

Официального прибора «доля-проигрыванием» в дереве нет (`proof-object-
roadmap.md §0.2`, п.2 — это отдельная поставка, шаг Ш5). Ниже — НЕ этот
прибор, а РУЧНАЯ, консервативная прикидка по золотому корпусу (55 честных
записей, 226 обязательств), выстроенная на подтверждённом чтением объёме
печати `2eb5633e` (§3.2) и на семейной раскладке рода 1 из
`proof-object-migration.md §1` (С1=3, С2=8, С3=8, С4=7, С5=2, С6=2, С7=8).

### 4.2. Что именно сдвинется

Печать 4125 покрывает семьи С1+С2+С3 целиком (3+8+8=19 мест) и узкие
подмножества С4 (Э1, по образцам разведки — не более 1–2 мест из 7) и С5
(замкнутая цель без вызова — не более 1 места из 2, второе — «К1», исключено
явно). Итого из 38 мест рода «тождество» переедут на печатаемый след, ПРИ
УСЛОВИИ регенерации записей, — **≈20–22 места**. Это единственный род, кто
вообще сдвигается: роды 2 (по примеру), 3 (разбором по случаям), 4 (разбор
цели), 5 (хвост по предположению) и 6 (по свойству) печатью 4125 не
затронуты вовсе (§3.2) — 0 мест.

Отдельно узкая печать S2 («восьмой ход», постусловие-обёртка без теоремы) —
это НЕ то же множество, что 64 известных места «по свойству» (все 64 —
седьмой ход, авторский шаг ВНУТРИ теоремы, `proof-object-migration-po-
svoystvu-stdlib.md §4` подтверждает: «53 из 53 — явный шаг, автоматический
восьмой ход — 0»). Сколько мест в золотом корпусе закроет именно узкий
«восьмой ход» — неизвестно и, по всей видимости, немного (единственный
названный образец во всём дереве — `flang/stdlib/hashmap.flang:613-616`,
вне золотого корпуса); для оценки доли принимается **0** мест корпуса — не
потому что их не существует, а потому что учитывать неизмеренное было бы
подделкой числа.

### 4.3. Грубая доля

Оговорка про единицы: «мест на калькуляторе»/«на переигрывателе» ниже — это
счётчики УЗЛОВ чекера (Ч363/365/369 считают узел вердикта, переигрыватель —
проверенный ход), а не утверждений один-к-одному; складывать их с 226 напрямую
нельзя (сумма всех четырёх строк сегодня — 293, а не 226/191, ровно потому что
единицы разные). Доля ниже поэтому взята ОТДЕЛЬНО, как отношение «мест,
которые ЭТА волна перекладывает с калькулятора на переигрыватель» к
знаменателю 226 (утверждений) — это единственное сравнение, которое волна
меняет; строки «по существу» и «на слово ядра» этой перепечаткой не
трогаются вовсе и здесь для контекста, а не для сложения.

| | сегодня (узлов) | после ЭТОЙ перепечатки + перегенерации 22 записей |
|---|---:|---:|
| мест на переигрывателе (индукция + пришедшие С1/С2/С3/частично-С4/С5) | 21 | ≈41–43 |
| мест на калькуляторе (Ч363+Ч365+Ч369, за вычетом переехавших) | 93 | ≈71–73 |
| мест по существу (Ч71, не калькулятор, этой волной НЕ трогается) | 79 | 79 |
| мест на слово ядра (остаток, этой волной НЕ трогается) | 100 | 100 |
| **доля переехавших мест ИМЕННО этой волной, от 226 утверждений** | — | **≈9–10 %** (≈20–22 из 226) |
| **накопленная доля на печатаемом следе, от 226 утверждений** | ≈9 % (21/226) | ≈18–19 % (41–43/226) |

Даже если считать оптимистично (обе узкие формы С4/С5 полностью, узкий S2
даёт ещё пару мест сверх золотого корпуса), доля-проигрыванием не выходит за
**четверть корпуса**. Порог Г4 (95 %) на порядок недостижим этой волной: до
`git rm perepiskoy` остаются НЕТРОНУТЫМИ пять из семи именных классов §3.1
(разбором по случаям, разбор цели, хвост по предположению, по свойству
целиком, С4-Э2-4/С5-К1/С6/С7 внутри тождества) — калькулятор несёт **≈75–90
% корпуса** и после того, как эта перепечатка встанет на прод.

### 4.4. Что это значит для порядка следующих волн

Возврат к дорожной карте (`proof-object-roadmap.md §1.1`) не меняется: после
[Ш3-волна-1] (эта перепечатка) следующей ценой по отдаче идёт печать «Ходы
деления/выбора записи» для родов 3+4 (25 мест сразу, чекер УЖЕ готов
придирками А+Б) — дешевле, чем С4-Э2-4/С5-полный вычислитель, и не требует
нового хода в чекере вовсе. Печать S2 под авторский шаг «по свойству»
(род 6, 64 места) — вторая по отдаче, чекер тоже уже готов. Обе — работа
ТОЛЬКО в `zapis.flang`, тем же составом приёмов, что уже применён в
`2eb5633e`, и обе требуют СВОЕЙ отдельной батч-перепечатки (нельзя вписать
в уже идущую).
