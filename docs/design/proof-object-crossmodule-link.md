## 1. Где сегодня сверщик упирается в межмодульное

Переигрыватель сертификата тотальности-композиции — `sverit_totalnost` (`сверщик.c:5459`). Четыре
проверки §2: (а) привязка к объявлению, (б) самовызова нет, (в) список зовомых пересобран из тела,
(г) у каждого зовомого ЕСТЬ блок тотальности в записи либо он примитив. Проверку (г) несёт цикл
**`сверщик.c:5510-5520`**:

```c
for (i = 0; i < zovyot_zapis.n; i++) {          /* 5515 */
  int est = 0;
  for (j = 0; j < vse_imena.n; j++)
    if (strcmp(zovyot_zapis.e[i], vse_imena.e[j]) == 0) { est = 1; break; }
  esli_ne(s, est,                                /* 5518 */
    fmt("тотальность «%s»: «%s» не примитив и не имеет блока тотальности в записи "
        "— тотальность зовомого не доказана", imya, zovyot_zapis.e[i]));   /* 5519 */
}
```

`vse_imena` — имена блоков тотальности РОВНО ЭТОЙ записи (собраны первым проходом,
`сверщик.c:5683-5685`). Если G живёт в другом модуле, её блока в `vse_imena` нет, `est` остаётся 0,
`esli_ne` кладёт беду → **КОД 1 «НЕ СОШЛОСЬ»**. Это первое лицо изъяна: межмодульный блок,
БУДЬ он в записи, сегодня отвергается.

Второе лицо — почему в корпусе такого блока нет вовсе. Печать (`zapis.flang:2455`, `Тотальности
записи`) раскладывает лишь те обязательства вида `totality`, что дал самоанализ; анализ одного файла
(`check <файл> --proof`) зовомую из другого файла НЕ разрешает и обязательства для F не порождает
(видно на `poddelka-sortirovka-ne-ubyvaet`: «Отсортировать» зовёт нигде не определённую «Сортировать»
→ блока тотальности в записи нет, вердикт «ПРОВЕРЕНО ВПУСТУЮ»). Тогда тотальность F садится на
маршрут «по объявлению» (`sverit_obyavlenie`) и уходит **на слово ядра**.

Итог: межмодульная тотальность сегодня либо отвергается (лицо 1), либо не проигрывается и висит на
слове (лицо 2). Механизм закрывает оба.

## 2. Замер: сколько из непроигранного — межмодульное СЕГОДНЯ

Прогон `sh flang/proof/доля-корпуса.sh --проигрыванием` по 86 записям корпуса:

```

непроиграно у поручённых: на слово ядра посылок и утверждений 103, шагов 27,

```

Хвост «по объявлению» — те самые 103 места «на слово ядра: посылок и утверждений». Разбор корпуса
(проверочные скрипты в `/tmp/.../scratchpad`, воспроизводимы grep-ом по записям):

- Функций, объявленных `тотальная функция`, но БЕЗ проигранного блока в записи: **89** (различных).
  Из них **35 самих себя рекурсивны** (несут `убывает`/`мера` или зовут себя) — это семья §7.2
  (структура/мера), НЕ композиция; ещё **8** зовут локальную рекурсивную G (композиция-на-рекурсии,
  тоже §7.2); **46** — прочее (в основном тела без пользовательских вызовов, тотальность у них с
  маршрута «по объявлению» по иной причине).
- Пользовательских вызовов «G не примитив И не определена в том же исходнике» (то есть подлинно
  межмодульных) по всему корпусу: **1**, и та — в `poddelka-sortirovka-ne-ubyvaet`, где «Сортировать»
  просто НЕ ОПРЕДЕЛЕНА (сломанная программа-подделка), а не тотальна в другом модуле.

**Честный вывод: в СЕГОДНЯШНЕМ корпусе межмодульных вызовов доказано-тотальной G — ноль.** Корпус
построен самодостаточным НАРОЧНО: функции `flang/self` и `flang/stdlib` перенесены в примеры
ПОБАЙТОВО (комментарии `corpus-*.flang`: «перенесены сюда из `flang/self/lexer.flang` ДОСЛОВНО»),
каждый пример — свой `модуль`, межмодульных вызовов в них нет. Все `зовёт «G» строка N тотальна` в
корпусе указывают на строку N В ТОМ ЖЕ исходнике (проверено: N = строка объявления G в своём файле).

Значит на текущем корпусе механизм закроет **0 мест**. Его ценность — не здесь, а впереди.

### 2.1. Проспективная ценность (ради чего механизм строится)

Настоящий `flang/self` несёт около 6800 объявлений `тотальная функция`, `flang/stdlib` — около 1467
(счёт `grep -c` по деревьям). Там модули зовут друг друга сплошь: лексер зовёт stdlib, парсер зовёт
лексер, `higher-order.flang` — 34 функции, которые тянут отовсюду. Как только в корпус войдут записи
РЕАЛЬНЫХ модулей (а не их самодостаточных копий), межмодульные вызовы станут массовыми, и без этого
механизма КАЖДЫЙ из них уйдёт на слово ядра либо в код 1. Механизм — предусловие того, чтобы корпус
перестал быть набором изолированных копий и стал деревом. Число закрываемых мест тогда — порядка
числа межмодульных рёбер в графе вызовов дерева (тысячи), но называть его точным сегодня было бы
враньём: этих записей в корпусе ещё нет.

## 3. Два пути (задание) и выбор

### Путь (1) — многозаписьное замыкание

Сверщику подаётся НАБОР пар (исходник, запись). Тотальность G берётся, только если G сама несёт
проигранный блок тотальности в КАКОЙ-ТО записи набора — проигранный против ЕЁ исходника теми же
четырьмя проверками §2. Транзитивно (G зовёт H из третьего модуля — H тоже обязана нести проигранный
блок) и с детектом цикла между записями. Доверенное ядро НЕ растёт: 15 примитивов, и только они —
дно доверия; набор добавляет ВХОД, не аксиомы.

### Путь (2) — доверенный манифест

Закрытый именованный список «доказано-тотальных» функций stdlib/self. По варианту А допустим, ЕСЛИ
манифест сам ПРОВЕРЯЕМ: каждая строка обязана быть подтверждена проигранным блоком тотальности в
корпусе. То есть манифест = КЭШ замыкания (1), а не аксиома.

### Выбор — путь (1); (2) только как ПРОИЗВОДНЫЙ кэш (гибрид)

Разбор показывает, что (2) в честном исполнении СВОДИТСЯ к (1):

- Если сверщик ОБЯЗАН перепроверять каждую строку манифеста проигрыванием (условие варианта А), то
  манифест не добавляет доверия — он лишь ИНДЕКС в набор. Вся работа — та же, что в (1). Доверенное
  ядро не растёт.
- Если сверщик НЕ перепроверяет и берёт манифест на слово — доверенное ядро растёт на ДЛИНУ
  манифеста, и каждая строка — голая аксиома. Это ровно то, что запрещает вариант А своей же
  оговоркой «манифест сам проверяем» и конституция ст. VII (ничего на слово мимо проверки).

Третьего у (2) нет: либо он (1) с индексом (роста нет), либо голое доверие (запрещено). Поэтому
рекомендуется **(1)**, а манифест допускается лишь как ВЫЧИСЛЯЕМЫЙ кэш: он ВЫВОДится из набора
прогоном и при каждом прогоне ПЕРЕВЫВОДится (сверяется). Манифест как ВХОД доверия не принимается
никогда — только как выход. Это и есть «гибрид»: путь (1) внутри, необязательный кэш снаружи.

## 4. Устройство пути (1) в сверщике

Идея: до сверки главной записи `сверщик` прогоняет ПРЕД-ПРОХОД по записям-зависимостям, собирает
имена блоков тотальности, которые прошли §2 БЕЗ единой беды против своих исходников, в реестр
`тотальные_набора`; затем проверка (г) главной записи принимает G, если G в `vse_imena` ИЛИ в
`тотальные_набора`.

### 4.1. Транзитивность и цикл — замыкание до неподвижной точки

Блок G может звать H из третьего модуля. Тогда G входит в `тотальные_набора`, только когда H УЖЕ там.
Пред-проход повторяется, пока реестр РАСТЁТ (fixpoint) — тем же приёмом, что замыкание достижимости в
`sverit_krugi_totalnosti` (`сверщик.c:5540-5547`): на каждом витке блок принимается, если ВСЕ его
`зовёт «…»` либо примитивы, либо уже в реестре. Цикл F→G→…→F до примитива не доходит НИКОГДА → ни одна
его функция в реестр не попадёт → все они останутся неподтверждёнными → зовущие получат код 1. Это и
есть детект цикла между записями: не отдельная ошибка, а недостижимость дна доверия. Дополнительно —
расширить `sverit_krugi_totalnosti` на ОБЪЕДИНЁННЫЙ граф (рёбра из блоков всех записей набора), чтобы
межзаписьный круг был назван вслух, а не только молча не-подтверждён.

### 4.2. Точные точки правок в `сверщик.c` (номера — `d6e2d568`, перемерять на стволе)

1. **`main` (`сверщик.c:5715` и цикл разбора доводов ниже).** Принять набор зависимостей: ключ
   `--набор КАТАЛОГ` (все `*.запись` каталога как пары с их полем `исходник`) либо повторяемый
   `--зависимость ИСХОДНИК ЗАПИСЬ`. Каждую пару прочитать (`prochitat_fajl`, уже есть).

2. **Новый пред-проход (рядом с `sverit`, `сверщик.c:5586`).** Для каждой зависимости отсечь секцию
   тотальности (тем же `razdelit(zapis, "\nтотальность ")`, что в `сверчике`, `сверщик.c:5594-5600`),
   для каждого блока прогнать `sverit_totalnost` против ЕГО исходника В ОТДЕЛЬНУЮ `Sverka` (беды в
   главный счёт не текут). Имя блока, прошедшего с нулём бед и все `зовёт «…»` которого уже примитивы
   или в реестре, добавить в `тотальные_набора`. Повторять до неподвижной точки. Плюс `собрать_рёбра`

3. **`Sverka` или сигнатура `sverit_totalnost` (`сверщик.c:5459`).** Передать `тотальные_набора`
   рядом с `vse_imena` (новый параметр `Sp vne_nabora`, либо поле `Sverka`).

4. **Проверка (г) (`сверщик.c:5515-5519`) — ЕДИНСТВЕННАЯ смягчаемая строка.** В условии `est`
   искать G не только в `vse_imena`, но и в `тотальные_набора`:
   ```c
   for (j = 0; !est && j < vse_imena.n; j++)   if (!strcmp(zovyot_zapis.e[i], vse_imena.e[j]))  est = 1;
   for (j = 0; !est && j < vne_nabora.n; j++)  if (!strcmp(zovyot_zapis.e[i], vne_nabora.e[j])) est = 1;
   ```
   Текст беды при `!est` — прежний, но точнее: «…не имеет блока тотальности НИ в записи, НИ в
   поданном наборе».

5. **Передача в двух-проходном блоке `sverit` (`сверщик.c:5683-5689`).** `sverit_totalnost(&s, …,
   vse_imena, тотальные_набора)`; `sverit_krugi_totalnosti` — на объединённых блоках, если набор
   подан.

6. **Сторож коллизии имён (новый, в пред-проходе).** Имена в наборе обязаны быть уникальны: если две
   записи набора несут блок тотальности с ОДНИМ именем, но РАЗНОЙ строкой/исходником объявления —
   **код 1** («в наборе два разных определения «G» — имя не различает, кому верить»). Без этого сторожа
   подделыватель отмывал бы ложную G, подложив честную одноимённую (см. пробу П4). Различитель здесь —
   имя+исходник+строка объявления, все три уже в блоке и в поле `исходник` записи.

Ядро, семя, `zapis.flang` — не трогаются (см. §6). Всё — `сверщик.c` плюс подаваемые данные.

### 4.3. Формат набора и почему НЕ нужен новый формат записи

Набор — это уже существующие записи модулей-зависимостей (каждый модуль печатается в свою запись со
своими блоками тотальности). Строка вызова `зовёт «G» строка N тотальна` (`zapis.flang:2408`) уже
несёт имя G; проверка (г) читает ТОЛЬКО имя (`v_yolochkah(l,1)`, `сверщик.c:5478`). Поэтому для
первого среза достаточно РАЗРЕШЕНИЯ ПО ИМЕНИ (при стороже коллизии §4.2.6) — новый квалификатор
модуля в строку вызова не нужен, а значит не нужна и перепечать. Квалификатор («зовёт «G» из «Модуль»
строка N») — поздняя надстройка, только если в реальном дереве появятся законные тёзки в разных
модулях; тогда это правка `zapis.flang` и перепечать. Сегодня — не нужна.

## 5. Безопасность и проба-подделка

Свойство, которое обязано выжить: **сверщик НЕ примет ложную межмодульную тотальность.** Подделка —
набор/манифест объявляет G тотальной, а её блок нигде НЕ проигран → обязан КОД 1.

Как механизм это держит: G входит в `тотальные_набора` ТОЛЬКО через `sverit_totalnost` с нулём бед
против исходника G. Цепочка доверия транзитивно упирается в 15 примитивов; иного дна нет. Ни имя в
манифесте, ни строка «тотальна» в записи сами по себе в реестр не кладут ничего.

Четыре пробы (каждая ОБЯЗАНА дать код 1 или, где сказано, код 0 — иначе сторож инертен):

- **П1 «пустое заявление / нет носителя».** Честный набор {R_F, R_G}, где R_G несёт проигранный блок
  G → F даёт код 0. Убрать R_G из набора (или подать набор без него) → G не в реестре → F даёт
  **код 1**. Носитель строится расщеплением любой честной композиции: вынести зовомую G в отдельный
  модуль/запись.
- **П2 «лживый блок».** R_G несёт `тотальность «G»`, но тело G на самом деле ЗОВЁТ САМУ СЕБЯ
  (рекурсия) либо строка объявления — не `тотальная функция «G»`. Пред-проход прогоняет §2 против
  исходника G: проверка (б)/(а) краснеет (`сверщик.c:5490,5495`) → G НЕ входит в реестр → F даёт
  **код 1**. Набор не может отмыть ложную тотальность.
- **П3 «манифест как аксиома».** Манифест называет G тотальной, но в наборе НЕТ записи с проигранным
  блоком G. Сверщик обязан G отвергнуть → **код 1**. Если реализация когда-нибудь ответит здесь
  кодом 0 — манифест стал аксиомой (голый рост доверия), это провал варианта А и нарушение
  конституции. Эта проба — единственный сторож того, что (2) не выродился в доверие.
- **П4 «отмывание тёзкой».** Набор содержит ДВА определения «G»: честно-тотальное и одноимённого
  недоказанного самозванца. F зовёт «G». Сторож коллизии (§4.2.6) → **код 1** («два разных «G»»).
  Без сторожа проверка (г) нашла бы честного тёзку и пропустила самозванца — имя не различает.

Пробы садятся в `flang/proof/чекер/пробы/` рядом с существующими подделками; мерило готовности до
слияния — П1–П4 ОБЯЗАНЫ покраснеть (П1/П2/П4) и П3 дать код 1.

### 5.1. PoC на настоящем двоичном (серийные файлы не тронуты)

Проба-подделка П1 показана прогоном РЕАЛЬНОГО `сверщик` без единой правки серийного кода. Взята
запись `corpus-tables.запись` (вердикт как есть — код 3), у которой функция «Перевод слова» зовёт
«Слово имён списка», а та несёт свой блок тотальности В ТОЙ ЖЕ записи. Изъят блок «Слово имён списка»
(строки 42-46) и уменьшено `тотальностей 5`→`4` — это МОДЕЛЬ того, что G живёт в другом модуле и её
блока в записи F нет:

```
$ sed '42,46d' corpus-tables.запись | sed 's/^тотальностей 5$/тотальностей 4/' > mutant.запись
$ сверщик corpus-tables.flang mutant.запись ; echo $?
НЕ СОШЛОСЬ: тотальность «Перевод слова»: «Слово имён списка» не примитив и не имеет блока
тотальности в записи — тотальность зовомого не доказана
1
```

Код 1 и есть тот самый порог, который механизм ОБЯЗАН сохранить: пока блок G нигде не проигран,
зовущий F не проходит. Путь (1) закрывает это не смягчением порога, а подачей блока «Слово имён
списка» ОТДЕЛЬНОЙ записью набора: пред-проход проиграет её против её исходника, положит имя в
`тотальные_набора`, и (г) у «Перевод слова» пройдёт — не на слово, а по проигранному носителю.

## 6. Нужен ли реприпт: НЕТ

- **Печать (`zapis.flang`) — не трогается.** `Тотальности записи` (`zapis.flang:2455-2462`) лишь
  раскладывает обязательства анализа; `строка K` в `зовёт «G» строка K тотальна` уже определена как
  «первое ОБЪЯВЛЕНИЕ G» (`zapis.flang:2451`), и оно может лежать в другом файле — формат готов к
  межмодульному без правки.
- **Ядро/семя — не трогаются.**
- **`сверщик.c` — трогается** (§4.2): пред-проход, реестр, одна смягчённая строка (г), сторож
  коллизии, расширение круга.
- **Данные — подаются**: существующие записи модулей-зависимостей как набор. Их перепечатывать не
  надо — блоки тотальности в них уже есть.

Единственная честная оговорка. Чтобы у РЕАЛЬНОГО межмодульного F в его записи ВООБЩЕ появился блок
тотальности, самоанализ должен разрешать зовомую из другого файла и класть обязательство `totality`
для F (сегодня анализ одного файла этого не делает — см. §1, лицо 2). Это правка АНАЛИЗА
(ядро/`carriers.flang`), НЕ печати и НЕ этого механизма. Сам механизм линковки (доверие сверщика к
набору) реприпта не требует: он принимает те строки `зовёт «G»`, что уже есть, и разрешает их по
набору. Разделение чистое: этот проект — про то, как сверщик ВЕРИТ межмодульной G; порождение блоков
для межмодульных F — соседняя задача уровня анализа.
