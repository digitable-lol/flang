## 3. Главный вопрос — ложится ЧАСТЬЮ, и вот прогоном откуда это видно

### 3.1. Ход `деление` — сам по себе достаточен. Рабочий сертификат, КОД 0

Никакого нового хода не нужно: правило раскладывается в примитив `деление` +
`выбор` + `закрыть` + `развернуть` (`proof-object.md:117`, «Ветвлением»), и ВСЕ
четыре — среди исходных 7 ходов чекера (`сверщик.c` дispatch, `hod_shaga:1043`).
Чтобы не спорить на словах, вот минимальный честный пример и сертификат от
руки, доведённый до КОД 0 настоящим `сверщик`:

`оснастка/proba-razbor.flang`:
```flang
модуль «Проба разбор по случаям»

тотальная функция «Знак»
  принимает н: число
  возвращает число
  обеспечивает «знак верен» если н больше 0 то результат равен 1 иначе результат равен 0
  если н больше 0 то 1 иначе 0
```

Ядро (`bootstrap/flang check --proof --записать`) кладёт ровно то, что и
предсказано в §2: `правило «разбор цели по условию»`, `теоремы нет`, БЕЗ единого
хода. Рукотворный сертификат — 8 ходов, все семь исходных примитивов, кроме
`развернуть`+`деление`+`выбор`(×4)+`закрыть`(×2):

```
  утверждение «знак верен» функции «Знак» строка 6
    вид postcondition
    вердикт доказано
    теоремы нет
    ход цель
    ход 1 развернуть ⟨«Знак» от ( н )⟩ строка 7 ⟨если н больше 0 то 1 иначе 0⟩
    ход 2 деление ⟨н больше 0⟩
    ход 3 выбор ⟨если да то ( если да то 1 иначе 0 ) равен 1 иначе ( если да то 1 иначе 0 ) равен 0⟩
    ход 4 выбор ⟨если да то 1 иначе 0⟩
    ход 5 закрыть тождеством
    ход 6 выбор ⟨если нет то ( если нет то 1 иначе 0 ) равен 1 иначе ( если нет то 1 иначе 0 ) равен 0⟩
    ход 7 выбор ⟨если нет то 1 иначе 0⟩
    ход 8 закрыть тождеством
    ход конец
  конец утверждения
```

Прогон:
```bash
export LC_ALL=C.UTF-8
./flang/proof/чекер/сверщик оснастка/proba-razbor.flang оснастка/proba-razbor.запись
echo $?
```
```
ПРОВЕРЕНО — запись сошлась с исходником, и всё доказанное проиграно заново:
утверждений 1 … сведений проиграно заново 1 (ходов проверено 8) …
Узлов «разбор цели по условию» проиграно заново 0 (снято со слова ядра мест 0) …
код=0
```
Важно: счётчик калькулятора Ч369 здесь **0** — цель закрыл ИМЕННО ход-объект
(`proigrat_blok`), не калькулятор. Гейт 4102 сработал (`est_hody && !est_princip`
истинно: ход есть, принципа нет).

**Подделка на этот сертификат.** Испортил тело развёртки (`⟨…иначе 9⟩` вместо
`⟨…иначе 0⟩`) — чекер отверг с именованием строки, не свернув на слово:
```
НЕ СОШЛОСЬ: … развёртка «Знак»: запись несёт тело ⟨если н больше 0 то 1 иначе 9⟩,
а в строке 7 исходника написано «если н больше 0 то 1 иначе 0»; … код=1
```
Двойная привязка держится: чекер читает строку 7 сам, а не верит записи
(«снимок-со-снимком» отсюда не проходит, `proof-object-migration.md §6`).

**Вывод §3.1.** Для АТОМАРНОГО условия («н больше 0» — сравнение без вложенных
скобок) ход `деление` работает без единой правки калькулятора. Это закрывает
БОЛЬШИНСТВО мест правила (семья А, §5) — но не те 4, ради которых задача
заведена: там условие либо не атомарно, либо путь к `proigrat_blok` вовсе не
открывается. Ниже — почему именно.

### 3.2. Гейт `est_princip` инертен для посылок без письменной теоремы — 3 места из 4

`bez_teoremy` (`сверщик.c:4882`) — точка входа для постусловий-без-теоремы.
Гейт:
```c
est_hody = *pervaya_s_nachalom(svoi, "ход цель") != 0;      // сверщик.c:4905
est_princip = *pervaya_s_nachalom(svoi, "принцип ") != 0;   // сверщик.c:4906
if (est_hody && !est_princip) {                              // сверщик.c:4907
  …  p = proigrat_blok(&o); …                                 // ходы РЕАЛЬНО проигрываются
} else {
  proigran = dokazano && proigrat_uzel(…);      // Ч363
  perepisan = !proigran && dokazano && perepiskoy(…);  // Ч365
  razobran = !proigran && !perepisan && dokazano && razborom_celi(…);  // Ч369
}
```
Комментарий над этим местом (`сверщик.c:4901-4904`) говорит прямым текстом:
«Записи С ПРИНЦИПОМ … идут той же прежней дорогой — переигрыватель их не
трогает». Для трёх из четырёх мест (binder-wall-map ×2, substantive С5 ×1)
`принцип …` стоит В ЛЮБОМ СЛУЧАЕ — его кладёт кернел-функция «Разбором по
случаям» (§1в) как часть самой формы доказательства, а не как случайность,
которую можно напечатать без него. Значит `est_princip` истинно ВСЕГДА для
этой семьи мест, и `proigrat_blok` не позовётся, СКОЛЬКО БЫ ходов ни было
дописано под посылкой.

Проверено прогоном, не домыслом. Взял настоящую запись `binder-wall-map.запись`
и вручную дописал ПОД обеими посылками («пусто», «голова и хвост») блок
`ход цель / ход 1 соседи ⟨а плюс б⟩ / ход конец` (заведомо валидный ФОРМАТ,
неважно какой ход — важно, увидит ли его чекер вообще):

```bash
./flang/proof/чекер/сверщик flang/proof/examples/binder-wall-map.flang оснастка/bwm-diag.запись
```
```
НЕ ВЗЯЛСЯ (…): утверждение «разбор: при положительном пороге ноль или один»:
посылка «пусто» сведена правилом «разбор цели по условию» и ни одного хода
не записано — место на слове ядра; … посылка «голова и хвост» … ни одного
хода не записано — место на слове ядра; …
код=3
```
**Мои ходы не увидены вовсе** — ни ошибки об их содержимом, ни попытки их
разобрать. Это и есть инертный гейт: не «риск», а наблюдаемое сегодня
поведение. Причина — в печати тоже нет опоры: `zapis.flang`, функция
«Ходы посылки» (`zapis.flang:1050`) для `by="reduction"` зовёт «Ходы сведённой
посылки записи» (`zapis.flang:1351`), а та проверяет ТОЛЬКО форму
«неотрицательность по построению» (условие на строке 1367); для формы «если …
то … иначе …» результат — пустой список **уже на уровне печати**, до всякого
гейта. Для `by="term"` (не наш случай здесь, но случай №4) — то же самое:
ветки на равенство (`Это цель равенства записи`) и на неотрицательность
(`Это цель неотрицательности записи`) есть, ветки на «если» — нет вовсе
(`zapis.flang:1066-1087`). Значит нужны ДВЕ независимые правки калькулятора —
расширить гейт `est_princip` в `сверщик.c:4907` (или завести отдельный
подмаршрут для посылок под принципом) И дописать builder в `zapis.flang` — обе
за пределами «документ + оснастка».

### 3.3. Составное условие после развёртки — новый, отдельный разрыв (1 место из 4)

Четвёртое место, `ohrana-daet-fakt.flang:43`, идёт ДРУГИМ маршрутом —
`sverit_teoremu` (автор написал `теорема` явно), а не `bez_teoremy`. Проверено
прогоном, что здесь гейт НЕ блокирует: дописал под посылкой `Узел` фиктивный
`ход 1 соседи ⟨а плюс б⟩` — чекер его **разобрал по существу** и назвал
настоящую цель в ошибке (не «не увидел», как в §3.2):
```
НЕ СОШЛОСЬ: … соседи: в цели «если ( «Хорошее» от (…) ) то ( «Левое хорошее»
от (…) ) иначе да» нет терма «а плюс б» … код=1
```
То есть `proigrat_blok` ЗДЕСЬ вызывается для посылок под теоремой уже сегодня
(и это согласуется с тем, что в `stack.запись` посылки под письменной теоремой
«Копия равна оригиналу» УЖЕ проигрываются ходами, §2 `proof-object-migration.md`).
Так что для маршрута «письменная теорема» гейта-блокировки нет — но есть ДРУГОЕ
препятствие, найденное этим же прогоном.

Тело шага — конъюнкция: `(зн не меньше 0) и притом («Хорошее» от л) и притом
(«Хорошее» от п)` (`ohrana-daet-fakt.flang:28`). Развернул вызов «Хорошее»
одним настоящим ходом `развернуть` — и вот итоговая цель, напечатанная САМИМ
чекером:
```
если ( ( зн не меньше 0 ) и притом ( «Хорошее» от л ) и притом ( «Хорошее» от п ) )
то ( «Левое хорошее» от (…) ) иначе да
```
Обратите внимание на **двойные скобки** сразу после «если» — `( (`. Это не
опечатка исходника: `hod_razvyortki` подставляет развёрнутое тело через
`vstavit_vmesto` (`сверщик.c:501`), а тот шаблон для уже-скобочного места
БЕЗУСЛОВНО оборачивает вставляемое ещё в одну пару скобок
(`fmt(" ( %s ) ", na)`, `сверщик.c:502`), независимо от того, нужна ли обёртка
телу самому по себе. Для тела-конъюнкции (само по себе НЕ единая скобочная
пара — `odna_para` на нём ложно, потому что первая скобка `(зн не меньше 0)`
закрывается на середине) это добавляет ЛИШНИЙ, ничем не устранимый уровень
скобок вокруг всего условия.

А вот это и есть разрыв: `term()` (`uzhat∘rasstavit`), которым нормализуется
ЛЮБОЙ аргумент ⟨…⟩ хода, снимает ЛЮБУЮ добавленную автором обёртку с
уже-сбалансированного, никогда не проваливающегося в минус содержимого — то
есть КАКУЮ БЫ строку я ни написал в `ход N деление ⟨…⟩`, `term()` сведёт её к
ОДНОУРОВНЕВОЙ форме условия, а в цели стоит ДВУХУРОВНЕВАЯ. Строковое сравнение
`soderzhit(cel, "если <chto> то ")` (`hod_deleniya`, `сверщик.c:932`) на этом
не сойдётся НИ ПРИ КАКОМ написании `chto`. Проверено прогоном (тем же приёмом:
подставил настоящий `развернуть`, а вторым ходом — заведомо ложный `соседи`,
чтобы получить от чекера дословный текст цели, не гадая по коду).

Это узкий, ранее не описанный разрыв: он проявляется НЕ у всех целей вида
«если», а только там, где после развёртки условие — составное (конъюнкция/
дизъюнкция из нескольких скобочных частей), а место подстановки было заранее
обёрнуто в скобки (что для целей-постусловий типично: `результат` в
`nachalnaya_cel`/`cel_pri_znachenii` всегда подставляется через `v_skobki`).
Чинится ОДНОЙ строкой в калькуляторе — не заводить безусловную обёртку в
`vstavit_vmesto`, когда `na` уже не нуждается в ней по смыслу (симметрично тому,
как это уже сделано в `v_skobki` для простого случая), — но это правка кода
`сверщик.c`, вне рамок документа.
