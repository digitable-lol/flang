# Разведка 53 мест «по свойству» в stdlib

**Состояние:** разведка под приёмку S2. Кода не трогает — читаны только `flang/stdlib/*.flang` и
`flang/self/proofterm.flang` (ядро). Числа сняты построчным чтением исходников, сентябрь 2026, ветка
`r/4121` (основание `gh/dev`).

**Область.** Задача 4114 разобрала честные места «по свойству» в коде — **11** (`docs/design/
proof-object-migration-po-svoystvu.md`, §3) — и назвала остаток тем же механизмом (седьмой ход ядра:
постусловие вызванной функции как факт, инстанцированное по месту вызова, `proofterm.flang:1039`+):
**53 в `stdlib`**. Приём, которым эту дыру закрывает независимая проверка, спроектирован в
`docs/design/proof-object-lemma-po-svoystvu.md` (S2 «постусловие вызванной»). Этот документ — разведка
именно 53 мест stdlib для приёмки S2: где они, в какой форме, что из них S2 закроет сам, и не упирается
ли что-то в предел ядра `proofterm.flang:1188`.

**Ответ сразу, числом.** 53 — подтверждено, не поправлено. Грепом `по свойству «` по
`flang/stdlib/*.flang`, минус две строки внутри блочных комментариев (`hashmap.flang:997`,
`postgres.flang:1601` — обе описывают приём словами, а не кладут шаг), выходит **60** сырых
попаданий в **18 файлах**. Построчной проверкой каждого попадания (какой это модуль/функция, что за
теорема, `случай` под индукцией или нет) 60 строк складываются РОВНО в **53 теоремы** — семь теорем
несут ссылку дважды (двухшаговая форма, см. §3). Других мест «по свойству» вне `flang/self/**` (код
4114) и вне `flang/stdlib/**` в дереве нет — весь остальной текст грепа (`лексер`, словари ключевых
слов, `zapis.flang`, `сверщик.c`/`.flang`, тестовые подделки, пробы `Ч392`) уже разобран в
`proof-object-migration-po-svoystvu.md` или является служебным (перевод/грамматика/подделка), а не
честным местом.

## 3. Форма: почему всё Ф1, и что значит «двухшаговая»

**Ф1** (`proof-object-migration-po-svoystvu.md` §3) — весь вывод теоремы есть один шаг «по свойству
«имя»» перед `следовательно доказано»`; тело доказываемой функции — голый вызов, и постусловие
вызванной сходится с целью знак в знак (или после подстановки охраны). **Ф2** (`то по свойству «имя»`
внутри `случай` индукции) в stdlib НЕ встречается ни разу — все 53 места одноуровневые, ни одна из
53 теорем не содержит `индукция по`/`случай`.

Семь мест — **двухшаговая** разновидность Ф1 (не отдельная форма, а тот же одношаговый вывод, которому
не хватает ОДНОЙ ссылки): `aes.flang` («утроенное — байт», «подстановка — байт», «обратная подстановка
— байт»), `hmac.flang`, `sha1.flang` (обе теоремы), `strings.flang`. Причина названа в комментариях
исходника дословно: `hmac.flang:331` — «Односложным «по свойству» цель не берётся: у печати длина
сказана термом (длина байты), а не числом»; `sha1.flang:445` — то же про перевод длины байтов в длину
печатной строки. Схема одна: `затем ⟨факт⟩ по свойству «А»` вводит промежуточный факт (обычно —
числовую длину, взятую из постусловия первого вызова), а второе `по свойству «Б»` замыкает цель уже
этим фактом. Для S2 это не новая форма сертификата — это ДВЕ пары `ход факт / ход закрыть` подряд
(§1.1 `proof-object-lemma-po-svoystvu.md`), не новый ход.

`hashmap.flang` и `kdf.flang`/`postgres.flang` дают Ф1 с охраной/дизъюнкцией в цели — ровно тот случай,
для которого в S2 предусмотрен `ход закрыть по свойству по охране ⟨охрана⟩` (§1.1). Правка сертификата
для них не отличается от простого равенства — разница только в том, что шаг `(г)` берёт ветвь `охрана`
вместо прямого сличения.

## 4. Явный шаг vs автоматический восьмой ход — почему разбивка тривиальна

Задание просило по каждому кластеру отметить, несёт ли место шаг «по свойству» ЯВНО или закрывается
автоматическим восьмым ходом (`proofterm.flang:2366` — постусловие вызванной БЕЗ ссылки автора).
**Ответ по всем 53: явно, без исключений — и иначе быть не может при этой методике счёта.** Восьмой ход
по определению (`proofterm.flang:2368`: «на пути «постусловие без теоремы» автора нет вовсе») не
оставляет в исходнике текста «по свойству» — ни строки, ни слова. Выборка, полученная грепом этого
текста, структурно не может содержать автоматические места: это была бы логическая ошибка счёта, а не
находка. 53 — это ровно и только седьмой ход (`proofterm.flang:1105` «По свойству»), явный по
построению.

Это не значит, что автоматического восьмого хода в stdlib нет вовсе — он есть, просто это ДРУГАЯ,
не пересекающаяся с 53 выборка, и в счёт задачи не входит. Пример, разобранный автором в самом
исходнике: `hashmap.flang:613-616`, функция «Искать» —

```
обеспечивает «где признака нет, поиск отдаёт запасное» если узел равен (вариант «Пустое место»)
  то (результат равен запасное) иначе да
```

Это постусловие ФУНКЦИИ (не отдельная теорема), и доказывается ядром автоматически по структуре
`разбор`а её тела, случай за случаем (комментарий `hashmap.flang:993-997`: «Пустое место» ядро закрыло
само, «Одиночку» — ссылкой «по свойству «в пустом месте ключей нет…»»» на СОСЕДНЮЮ функцию, «Четвёрку»
— «по предположению», «Гроздь» — не закрыто, стоит «сеткой»). Ссылка «по свойству» здесь тоже есть, но
она не в счёт 53 stdlib-мест этой задачи: это не отдельная теорема с явным шагом «по свойству» перед
`следовательно доказано», а внутренняя, ЧУЖАЯ ссылка внутри автоматического доказательства постусловия
другой функции, и та же самая теорема-цель («чего в словаре нет, за то отдаётся запасное»,
`hashmap.flang:1010-1016`) уже посчитана мной как одно из 53 — именно она СВЕРХУ ссылается на
постусловие «Искать» одним явным шагом «по свойству «где признака нет, поиск отдаёт запасное»»»
(строка 1015). То есть один и тот же файл несёт оба слоя одновременно, но задача 4121 считает верхний
(53), а не внутренний механизм проверки постусловия «Искать».

**Для S2:** пункт 7.3 `proof-object-lemma-po-svoystvu.md` предупреждает, что без печати сертификата для
автоматического восьмого хода часть мест «останется непокрытой» — но, как показывает разведка, среди
СЕГОДНЯШНИХ 53 stdlib непокрытых таким образом нет: все они уже несут явный текст и печатаются по
маршруту седьмого хода. Печать восьмого хода нужна на будущее (для мест вроде `hashmap.flang:616`,
если корпус захочет их мигрировать), но не блокирует закрытие нынешних 53.

## 5. Край предела `proofterm.flang:1188` — проверка

Предел ядра дословно (`proofterm.flang:1182-1188`): «ДОПУЩЕНИЙ ИНДУКЦИИ ЗДЕСЬ НЕТ… шаг, которому нужны
И допущение, И постусловие вызываемого, сегодня не пишется» — то есть ОДИН шаг внутри `случай`
индукции не может одновременно опираться на допущение индукции (`по предположению`) И вносить
постусловие чужой функции (`по свойству`). Если такой шаг где-то нужен — писать его сегодня НЕЧЕМ, и
это точка, где S2 не поможет: нужна правка ИСХОДНИКА (переформулировать теорему без совмещения).

Проверка на 53 местах:
1. **форма Ф2 в stdlib отсутствует полностью** (`то по свойству` — 0 попаданий, §1) — а без Ф2 нет и
   `случай`, внутри которого шаг мог бы совмещать оба обоснования;
2. ни одна из 53 теорем не содержит `индукция по` в СВОЁМ теле (проверено построчным чтением каждой
   теоремы, §2–3 и Приложение) — «по свойству» у всех 53 стоит в теореме БЕЗ индукции вовсе, совмещать
   там нечего.

Два файла (`hashmap.flang`, `postgres.flang`) несут ОБА ключевых слова, `по свойству` и «по
предположению», но в РАЗНЫХ, не пересекающихся теоремах:
- `postgres.flang` — восемь теорем «по свойству» (§2, все Ф1 без индукции) плюс ОТДЕЛЬНАЯ, девятая
  теорема «дополнение не укорачивает запрос» (`postgres.flang:1616-1624`), которая идёт `индукция по
  запас` и закрывается ТОЛЬКО «по предположению» — «по свойству» в ней нет вовсе (комментарий файла,
  `postgres.flang:1595-1598`, называет это прямо: «Девять теорем… Восемь — `по свойству`… Девятая —
  индукция»);
- `hashmap.flang` — теорема «чего в словаре нет...» (одна из 53, Ф1, без индукции) ссылается на
  постусловие «Искать», а «по предположению» встречается внутри АВТОМАТИЧЕСКОГО доказательства этого
  постусловия у самой функции «Искать» (§4) — тоже отдельно, не в одном шаге с «по свойству».

**Итог: 0 из 53 мест упирается в предел 1188. Файлов, требующих правки исходника по этой причине, нет.**
Совпадение двух слов в одном ФАЙЛЕ — не то же самое, что совмещение в одном ШАГЕ; предел бьёт только по
второму, и второго среди 53 не найдено.
