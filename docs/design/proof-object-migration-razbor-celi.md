## 2. Рукотворный сертификат — «разбор цели по условию» ложится

### 2.1. Устройство ходов (вычислено чтением, проверено прогоном)

Механизм для постусловия вида `если У то <нечто с результат> иначе да`:

1. `ход цель` строит начальную цель — постусловие, где `результат` заменён
   вызовом функции. Подстановка автоматически ОБОРАЧИВАЕТ вызов в скобки
   (`vstavit_vmesto`/`v_skobki`, `сверщик.c:496-504`), если тот содержит пробел.
2. `развернуть` (P1) подставляет тело функции НА МЕСТО вызова ДО деления —
   тогда условие `У` оказывается продублировано (снаружи, из постусловия, и
   внутри, из свежеразвёрнутого тела) В ОДНОМ терме.
3. `деление ⟨У⟩` (P5) заменяет ОБА вхождения `У` разом (`vstavit_vmesto` бьёт по
   всем вхождениям текста в цели, не по одному) на `да`/`нет` — раздел на две
   цели одним ходом, а не двумя раздельными.
4. `выбор` (P3) читает ветвь внешнего «если», затем внутреннего — ветвь за
   ветвью, как обычное чтение написанного.
5. `закрыть тождеством`/`закрыть истиной` снимает цель.

### 2.2. Сертификат, снятый руками, и прогон

Модуль `оснастка/proba-razbor.flang`:

```flang
модуль «Проба разбор цели»

тотальная функция «Порог или ноль»
  принимает порог: число, значение: число
  возвращает число
  обеспечивает «при положительном пороге само значение» если порог больше 0 то результат равен значение иначе да
  пример «порог положителен»
    дано порог равно 1
    дано значение равно 5
    ожидается 5
  если порог больше 0 то значение иначе 0
```

Ядро (`bootstrap/flang check --proof`) само подтверждает: «доказано сведением
цели с телом функции: правило «разбор цели по условию» … теоремы при нём нет и
не нужно».

Рукотворная запись `оснастка/proba-razbor.запись` (шапку посчитал
`оснастка/shapka.py`, см. §7):

```
утверждение «при положительном пороге само значение» функции «Порог или ноль» строка 6
  вид postcondition
  вердикт доказано
  теоремы нет
  ход цель
  ход 1 развернуть ⟨«Порог или ноль» от ( порог ) и значение⟩ строка 11 ⟨если порог больше 0 то значение иначе 0⟩
  ход 2 деление ⟨порог больше 0⟩
  ход 3 выбор ⟨если да то ( если да то значение иначе 0 ) равен значение иначе да⟩
  ход 4 выбор ⟨если да то значение иначе 0⟩
  ход 5 закрыть тождеством
  ход 6 выбор ⟨если нет то ( если нет то значение иначе 0 ) равен значение иначе да⟩
  ход 7 закрыть истиной
  ход конец
конец утверждения
```

Прогон (`$?` — хвостом, без трубы):

```
$ сверщик оснастка/proba-razbor.flang оснастка/proba-razbor.запись
ПРОВЕРЕНО — запись сошлась с исходником, и всё доказанное проиграно заново:
утверждений 1 … сведений проиграно заново 1 (ходов проверено 7) …
$ echo $?
0
```

**КОД 0.** «По объявлению» и «правило «…»» в записи не написаны вовсе — они и
не нужны: `sverit_obyavlenie` (`сверщик.c:2687`) молча уступает дорогу, когда
маршрут явно другой (ни `правило`, ни `по объявлению` не стоит).

### 2.3. Три подделки на этот же сертификат — «два числа»

| подделка | правка | ответ чекера | КОД |
|---|---|---|---|
| `подделка/podmena-tela.запись` | тело развёртки `⟨… иначе 0⟩` → `⟨… иначе 999⟩` | «запись несёт тело ⟨… иначе 999⟩, а в строке 11 исходника написано «… иначе 0»» | 1 |
| `подделка/lozhnoe-uslovie.запись` | `деление ⟨порог больше 0⟩` → `⟨порог больше 5⟩` | «деление: «порог больше 5» не стоит в цели условием» | 1 |
| `подделка/nevernoe-zakrytie.запись` | `закрыть истиной` → `закрыть тождеством` | «закрыть тождеством: у цели «да» стороны равенства разные» | 1 |

Честная запись — КОД 0; три подделки — КОД 1 каждая, и каждая называет СВОЮ
строку (двойная привязка работает так же, как в §9 `proof-object.md`).
Подделок отвергнуто 3, честных отвергнуто 0.

### 2.4. Ещё два подтверждения на настоящих местах корпуса

Чтобы не полагаться на один синтетический пример, тот же приём применён
руками к двум РЕАЛЬНЫМ местам корпуса (без правки `сверщик.c`/`zapis.flang`,
только дописанная копия `.запись` в `оснастка/`):

- **`order.flang`, П2 «длина пары ровно два»** (`(длина результат) равен 2`,
  цели-«если» в постусловии НЕТ вовсе — оно в теле). Сертификат: `развернуть` →
  `деление ⟨а не больше б⟩` → `выбор` → **`вычислить ⟨длина ( [а, б] )⟩ = ⟨2⟩`**
  → `закрыть тождеством`, зеркально для второй ветви. **КОД 0, 8 ходов.**
  Находка попутно: `вычислить`/`ocenit_term` СЧИТАЕТ длину списочного литерала,
  даже когда его элементы — свободные имена (`а`, `б` не связаны) — счёт длины
  не требует знать ЗНАЧЕНИЯ элементов, только их число. Это шире буквы §2.2
  `proof-object.md` («T обязан быть без свободных имён»), но не противоречит
  ей по существу: свободные имена внутри `T` не мешают, если сама операция
  (здесь — счёт элементов) их не трогает.
- **`forms.flang`, Ф12 «встроенная форма под разбором цели по условию»**
  (обе ветви — равенства с встроенной формой `символ N в текст`). Тот же приём,
  8 ходов, **КОД 0**.

Итого рукотворных сертификатов с КОД 0 — **3**, они закрывают представителей
всех трёх непринципиальных под-семей, что реально встали в §3 без сучка (см.
Р1 в таблице ниже).

## 3. Семьи мест правила «разбор цели по условию»

| семья | мест | ложится | причина |
|---|---:|---|---|
| **Р1.** Условие в постусловии БЕЗ авторских скобок (`если У то …`) | **9** | **ДА** (пруф §2) | развёртка дублирует `У`, одно `деление` бьёт по обоим вхождениям, `выбор`×N, `закрыть` |
| **Р2.** То же самое, но автор обернул ВЕСЬ `У` в скобки (`если (У) то …`) | **5** | **ЧАСТЬЮ** | `выбор` не снимает лишний слой скобок вокруг `да`/`нет` — см. §4.1 |
| **Р3.** Цель после деления — связка (`и притом`/`или`) или встроенная форма (`содержит`), а не голое равенство/`да` | **3** | **ЧАСТЬЮ** | ни один из 4 видов `закрыть` не берёт такую цель — см. §4.2 |
| **Р4.** Постусловие с принципом, теоремы НЕТ (посылки) | **3** | **НЕТ** | у `bez_teoremy` нет ни одного кода-пути к `proigrat_blok` для посылок — см. §5.1 |
| **Р5.** Теорема ЕСТЬ, шаг «по предположению», посылка правилом 16 | **1** | **ЧАСТЬЮ** | путь к `proigrat_blok` УЖЕ есть и работает (§5.2), но цель после развёртки — конъюнкция допущения, тот же дефицит, что Р3 |

Итого: 9 + 5 + 3 + 3 + 1 = **21** — сходится с §1.2 без остатка: Р1∪Р2∪Р3 = все
17 постусловий «теоремы нет, принципа нет»; Р4 = обе посылки `binder-wall-map`
плюс посылка `substantive`; Р5 = единственное место `ohrana-daet-fakt`.

**Списки семей поимённо:**

- **Р1 (9, ДА):** `binder-hides-the-condition` — «Длина при пороге без
  связывателя»/«…под пусть» (2); `binder-wall-map` — «Порог снаружи»/«…под
  пусть»/«…под пусть со свёрткой» (3, авторские `пусть` нормализация
  разворачивает раньше хода, см. комментарий `binder-hides-the-condition.flang:14-17`);
  `honest-modus-ponens-by-guard` — «Страж»/«Страж единицы» (2); `order` — «П2
  длина пары ровно два» (1, пруф §2.4); `forms` — «Ф12» (1, пруф §2.4).
- **Р2 (5, ЧАСТЬЮ):** `forms` — «Ф4 условное: охрана да», «Ф5 условное: дерево
  условий тела» (2, постусловие пишет `если (н не меньше 0) то …`/`если (н
  больше 0) то …`); `corpus-hof` — «нулевой остаток влечёт признак чётности»,
  «превышение нуля влечёт признак положительности», «положительная длина
  влечёт признак непустоты» (3, постусловие пишет `если ((… ) равен/…) то
  результат иначе да`).
- **Р3 (3, ЧАСТЬЮ):** `forms` — «Ф1 связка: конъюнкция» (цель после деления —
  `X не меньше 0 и притом X не больше 2`), «Ф8 принадлежность: результат из
  набора» (цель после деления — `["да","нет"] содержит "да"`); `body-forms` —
  «это классическая импликация» (цель после деления — `следствие равен ((не
  да) или следствие)`, нужна ещё и логическая свёртка `не да`→`нет`).
- **Р4 (3, НЕТ):** `binder-wall-map` — «разбор: при положительном пороге ноль
  или один», посылки «пусто»/«голова и хвост»; `substantive` — «С5 сохранение:
  длина выросла на один», посылка «голова и хвост» (шаг; база того же
  утверждения — правило «тождество», отдельная порода).
- **Р5 (1, ЧАСТЬЮ):** `ohrana-daet-fakt` (`flang/test/fixtures/`) — «у хорошего
  дерева левое хорошо», посылка «Узел».

## 4. Почему Р2 и Р3 — ЧАСТЬЮ, а не ДА: две находки прогоном

### 4.1. Р2 — лишний слой скобок топит `выбор`

Прогон на `forms.flang` Ф5 (постусловие `если (н больше 0) то (результат равен
2) иначе (результат равен 0)`): после `развернуть`+`деление ⟨н больше 0⟩` цель
становится

```
если ( да ) то ( ( если да то 2 иначе 0 ) равен 2 ) иначе ( ( если да то 2 иначе 0 ) равен 0 )
```

— скобки вокруг `да` СОХРАНИЛИСЬ, потому что `деление` меняет только текст
ВНУТРИ уже стоящих скобок автора (`vstavit_vmesto` бьёт по паддингу пробелами,
не по всей скобочной группе), а `выбор` берёт условие словом ПОСЛЕ «если»
(`hod_vybora`, `сверщик.c:917`: `slova_posle(po_to.levo, 1)`) — и получает
`( да )`, а не `да`, что не совпадает буквально ни с `"да"`, ни с `"нет"`:

```
$ сверщик flang/proof/map/forms.flang оснастка/находки/forms-proba-f5.запись
НЕ СОШЛОСЬ: … выбор: условие «( да )» не вычислено до литерала — ветвь брать не из чего …
```

Причина в источнике: автор написал `если (н больше 0) то …` — весь `У` в
скобках. Там, где автор пишет `если н больше 0 то …` без скобок (Р1), тот же
приём проходит НАСКВОЗЬ (§2). Это НЕ пробел в наборе примитивов — это
негладкость чтения условия в `hod_vybora`, который не снимает один слой скобок
вокруг `да`/`нет`. Чинится в теории парой строк (снять `bez_kraev`, если
результат — ровно `( да )`/`( нет )`), но это КОД, а задача — только документ;
здесь фиксируется КАК НАЙДЕННЫЙ ФАКТ, а не чинится.

`corpus-hof` бьёт по той же причине сильнее: постусловие пишет ДВОЙНУЮ скобку
`если ((х остаток от 2) равен 0) то результат иначе да` — здесь и условие ОТ
АВТОРА уже в скобках, и `условие = равенство` тоже в скобках. Проверено тем же
прогоном на «нулевой остаток влечёт признак чётности» — цель после развёртки
дословно `если ( ( х остаток от 2 ) равен 0 ) то ( ( х остаток от 2 ) равен 0 )
иначе да`, и `деление` с любым текстовым доводом, который переживёт `term()`
(нормализация САМА снимает один слой лишних скобок с ЦЕЛОГО довода — see
`uzhat`, `сверщик.c:485`), не может дать текст, буквально совпадающий с ДВОЙНОЙ
скобкой внутри цели. Тупик того же рода, что и у Ф5.

### 4.2. Р3 — нет формы закрытия для связки/вхождения

Прогон на `forms.flang` Ф1 (конъюнкция): после `развернуть`+`деление`+`выбор`
цель —

```
( ( 2 ) не меньше 0 ) и притом ( ( 2 ) не больше 2 )
```

```
$ сверщик flang/proof/map/forms.flang оснастка/находки/forms-proba-f1.запись
НЕ СОШЛОСЬ: … закрыть тождеством: у цели «...» стороны равенства разные …
```

Ни один из 4 видов `закрыть` (`дано`/`тождеством`/`истиной`/`требованием`) не
умеет расщеплять `и притом`/`или` в ЦЕЛИ (расщепление конъюнкции ЖИВЁТ, но
только внутри калькулятора — `сверщик.c:1620-1627`, `3719-3777`, вне
`proigrat_blok`). Столь же тупиково для Ф8 (`содержит` на литеральном списке):

```
$ сверщик flang/proof/map/forms.flang оснастка/находки/forms-proba-f8.запись
НЕ СОШЛОСЬ: … закрыть истиной: цель «["да", "нет"] содержит ( "да" )» не литерал «да» …
```

`body-forms` («это классическая импликация») требует ЕЩЁ и `не да → нет`
литеральной свёртки — той же породы дефицита, но третьей связкой.

**Итог по Р2/Р3.** Это НЕ «правило не ложится» в духе тождества-С6 (там были
нужны принципиально новые операции — проекция поля, редукция разбора). Здесь
механизм (`развернуть`→`деление`→`выбор`) РАБОТАЕТ буквально до последнего
хода — и либо спотыкается о скобки (Р2, вопрос устойчивости синтаксиса
`hod_vybora`), либо о недостающий вид `закрыть`/новый примитив для связок
(Р3, `и притом`/`или`/`содержит`). Обе придирки МЕЛКИЕ по объёму (не 205 строк
`ocenit_term`, а десятки), но это КОД, и задача его не трогает — здесь только
называю находку прогоном.

## 5. Гейт принципа — нужен ли сверх 4102? Прогон, а не гадание

### 5.1. Р4 — постусловие с принципом БЕЗ теоремы: инертно ПОЛНОСТЬЮ

Взял честный `binder-wall-map.flang`/`.запись` как есть (КОД 3, «НЕ ПРОВЕРЕНО»,
2 посылки «на слово ядра» под утверждением «разбор: при положительном пороге
ноль или один»). Дописал под честную посылку «пусто» ЗАВЕДОМО ЛОЖНЫЙ ход:

```
  посылка «пусто» вид base вариант «пусто» вердикт доказано закрыта reduction шагов 0 правило «разбор цели по условию»
    ход цель
    ход 1 закрыть истиной
    ход конец
```

(«закрыть истиной» на первом же ходу — цель посылки «пусто» никогда не
`да» буквально, это заведомая ложь). Прогон:

```
$ сверщик flang/proof/examples/binder-wall-map.flang оснастка/подделка/binder-wall-map-lozhniy-hod.запись
НЕ ВЗЯЛСЯ … посылка «пусто» сведена правилом «разбор цели по условию» и ни
одного хода не записано — место на слове ядра; …
КОД=3
```

**Ответ БУКВАЛЬНО ТОТ ЖЕ**, что и без дописанного хода (сверено байт в байт с
контрольным прогоном без правки): чекер даже не заметил, что ход есть, лживый
он или нет. Причина — не в тексте гейта 4102, а в АРХИТЕКТУРЕ: `proigrat_blok`
для посылок зовёт ТОЛЬКО `sverit_teoremu` (`сверщик.c:4822`), а
`sverit_teoremu` зовётся ТОЛЬКО когда `est_teorema` истинно (написана
`теорема «…»`, `сверщик.c:5006`). У постусловия с принципом, но БЕЗ написанной
теоремы, управление никогда не доходит до `sverit_teoremu` — оно всё время в
`bez_teoremy`, а там при `est_princip` истинном код идёт в `else`-ветку
(`proigran`/`perepisan`/`razobran`, `сверщик.c:4918-4933`), которая ходы вообще
не читает. Печать ходов здесь — украшение в буквальном, измеренном смысле.

**Значит гейта 4102 тут действительно НЕ хватает — но фраза «расширить условие
`!est_princip`» была бы неточной.** Условие снять недостаточно: `bez_teoremy`
нужен НОВЫЙ код-путь, вызывающий `proigrat_blok` ПО ПОСЫЛКАМ, когда принцип
есть, а теоремы нет — по образцу того, что уже делает `sverit_teoremu`. Это
не однострочная правка, а маленькая архитектурная работа (кода я не пишу, но
называю, в чём именно она состоит, раз задание просит «прямо»).

### 5.2. Р5 — «по предположению» под ЯВНОЙ теоремой: гейта не нужно, дорога уже есть

Взял `ohrana-daet-fakt.flang`/`.запись` (тест-образец, единственное честное
место, где шаг теоремы обоснован «по предположению», а посылка ШАГА несёт
правило «разбор цели по условию»). Контроль без правки — КОД 3, «НЕ
ПРОВЕРЕНО», и явным текстом: «теорема «у хорошего дерева левое хорошо»: шаг «по
предположению» сверщик по существу не проигрывает, место на слове ядра»
(Ч7104, `сверщик.c:1096-1103`) — это ЧЕСТНОЕ признание долга, а не подделка.

Дописал под посылку «Узел» тот же трюк — заведомо ложный `ход 1 закрыть
истиной`:

```
$ сверщик flang/test/fixtures/ohrana-daet-fakt.flang оснастка/подделка/ohrana-daet-fakt-lozhniy-hod.запись
НЕ СОШЛОСЬ: … закрыть истиной: цель «если ( «Хорошее» от (...) ) то ( «Левое
хорошее» от (...) ) иначе да» не литерал «да»; …
КОД=1
```

**Ложь ПОЙМАНА**, и точно назвала настоящую цель шага (двойная привязка
работает). Это ДОКАЗЫВАЕТ: `sverit_teoremu` зовёт `proigrat_blok` НА ПОСЫЛКАХ
ПИСЬМЕННОЙ теоремы БЕЗУСЛОВНО — принцип есть здесь ТОЖЕ (`принцип тип «Д» по
«дерево»`), но `est_princip` в этом маршруте вообще не проверяется
(`sverit_teoremu`, `сверщик.c:4780-4823`, ни разу не читает `принцип `). Значит
для мест «теорема есть» гейт-принципа СВЕРХ уже стоящего НЕ НУЖЕН — путь и так
открыт для любого принципа, писанного явной теоремой.

**Что мешает — не гейт, а примитив.** Настоящий (не ложный) сертификат для
«Узла» нуждается в РАСЩЕПЛЕНИИ конъюнкции допущения: развёрнутая охрана
«Хорошее» даёт `(зн не меньше 0) и притом («Хорошее» от л) и притом («Хорошее»
от п)`, и чтобы применить предположение индукции к `«Хорошее» от л`, конъюнкт
надо СНАЧАЛА достать. Это тот же дефицит, что у Р3 (§4.2) — не хватает
операции над связкой «и притом» внутри `proigrat_blok`, не гейта.

**Итог по вопросу задания.** «По предположению» — под принципом, ДА, но НЕ
поэтому «может не проходить гейт 4102»: сам гейт 4102 писан только для маршрута
БЕЗ теоремы (`bez_teoremy`); маршрут «теорема есть» (`sverit_teoremu`) 4102 не
касается вовсе и принципом не гейтится с самого начала. У «по предположению»
проблема — недостача примитива (Р3-порода), а не гейта. У «принцип без
теоремы» (Р4) проблема — ИМЕННО отсутствие какого-либо кода-пути, то есть
жёстче, чем «гейт не пропускает»: пропускать НЕЧЕМ.
