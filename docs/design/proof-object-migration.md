## 0. Коротко, числами

| вопрос | ответ |
|---|---|
| строк правила «тождество…» по 12 честным записям корпуса | **44** (`grep -c` по `пробы/записи/корпус/*.запись`) |
| из них различимых обязательств (постусловие + посылка) | **38**: 31 постусловие без теоремы + 7 посылок под принципом |
| набор 4101 назвал | **42** — расхождение в пределах перегенерации записей и того, считать ли строку-сводку `сведение` отдельным местом (см. §1) |
| семей вышло | **7** |
| семей, чья печать возможна СЕГОДНЯШНИМИ 7 ходами | **2** (рефлексив, соседи) — всего 11 мест |
| семей, требующих нового хода (риск для набора проб) | **4** (длина Д, элемент Э, вычислить, круг/разбор) — 19 мест |
| семья за теоремным треком (4102 не трогал) | **1** (индукция + свёртка-постусловие) — 8 мест |
| итоговый минус Г3 по завершении ВСЕГО корпуса | **≈ −1800 строк** (снять калькулятор ~2080, прибавить новые ходы ~50–100) |
| условие снятия калькулятора | весь корпус переигрывается — не только эти 42, а все правила (см. `proof-object.md §8`) |

**Неудобный вывод сразу.** Тривиальная база `развернуть → закрыть тождеством`
подходит НЕ «ни к одному» (как сказано в 4101), а ровно к двум лёгким семьям (11
мест из 38). Оставшиеся 27 требуют либо перестановки соседей (уже есть ход), либо
переписки встроенной формы (`длина`/`элемент`), либо замкнутого счёта, либо
проекции поля/редукции разбора — и ВОТ на них тривиальная база не ложится. Три из
этих механизмов — расширение переигрывателя, то есть риск для набора проб.
Одна семья (свёртка-постусловие, место `У3`) — скрытая индукция без принципа:
она либо получает ход свёртки, либо переписывается в исходнике под явную теорему.

## 1. Перепись 42 мест по форме

Счёт снят так:

```bash
export LC_ALL=C.UTF-8
for f in abilities binder-wall-map boundaries corpus-hof \
         element-po-nomeru-chestnaya equality forms sources stack \
         substantive svyortka-prefiks-chestnaya types; do
  /usr/bin/grep -a -c 'тождество после переписки' \
    flang/proof/чекер/пробы/записи/корпус/$f.запись
done            # сумма 44
```

44 строки правила = 31 постусловие `теоремы нет` + 7 посылок под принципом + 6
строк-сводок `сведение «тождество…»` (по одной на теорему/принцип, не отдельное
место). Обязательств, стало быть, 38. 4101 назвал 42 — разница объяснима
перегенерацией записей между задачами и тем, считать ли `сведение` местом;
существа классификации это не меняет, семьи те же.

Постусловия проверены прогоном:
`bootstrap/flang check --proof flang/proof/map/abilities.flang` → **28/28
доказано, КОД 0**; `…/equality.flang` → **6 доказано, 2 сетка** (`Р2` и `Р8` — не
из нашей породы, см. ниже).

### Семьи

**С1. Соседи** — перестановка двух операндов ОДНОГО узла (`плюс`/`умножить на`).
Мест **3**.
- пример: `Сумма наоборот` (`abilities.flang:26`) тело `а плюс б`, постусловие
  `результат равен (б плюс а)`.
- ещё: `Произведение наоборот` (`abilities.flang:37`), `Удвоить`/`Р3`
  (`equality.flang:40`, тело `н умножить на 2` стр.48, цель `2 умножить на н`).
- цепочка: `развернуть` (результат→тело) → `соседи` → `закрыть тождеством`.
- граница чётко видна в `equality.flang:8`: `Р2` (`н умножить на 2 = н плюс н`) —
  сетка, ядро НЕ берёт; соседи ≠ дистрибутивность.

**С2. Рефлексив** — после развёртки `результат`→тело стороны совпали знак в знак
(часть — тавтологии). Мест **8**.
- примеры: `Тот же список`/`Р6`,`Р7` (`equality.flang:61`), `Себя же`/`Т4`
  (`types.flang:42`), `Мера списка`/`В10` (`boundaries.flang:14`, тело
  `длина элементы`, цель `результат равен (длина элементы)`), `Всегда ноль`/`В11`
  (`boundaries.flang:51`, `0`=`0`), `Удвоить`/`Квадрат`/`Заглавная точка`
  (`corpus-hof.flang:68,77,112`).
- цепочка: `развернуть` → `закрыть тождеством`. Больше ничего.

**С3. Длина встроенной формы (законы Д1–Д5)** — цель `(длина F(…)) равен …`, где
`F` — встроенная форма без тела flang. Мест **8**.
- механизм — в калькуляторе, `сверщик.c:3229`–`3237` (коммент) и `3344`–`3359`
  (`svesti_term`): `Д1/Д2 длина(добавить/приписать Э к Л)=(длина Л)+1`; `Д3
  длина(соединить А с Б)=(длина А)+(длина Б)`; `Д4 длина(разложить Т)=длина Т`;
  `Д5 длина(отобразить Л …)=длина Л`.
- примеры: `Знаки текста`/`У4` (Д4), `Дописать в конец`/`У5` (Д1), `Дописать в
  начало`/`У6` (Д2), `Склейка строк`/`У7` (Д3) — все `abilities.flang`;
  `Приписать хвостом`/`Р4` (Д1, `equality.flang:50`); `Единицы`/`С3`
  (`substantive.flang:37`, Д5 над `отобразить … → 1`); `Отобразить`
  (`corpus-hof.flang:137`, Д5); `Порог под отображением`
  (`binder-wall-map.flang:68`, Д5).
- цепочка: `развернуть` (результат→тело) → **переписать длину по Дk** → `закрыть
  тождеством`. Хода «переписать длину» в семи НЕТ (§2).

**С4. Элемент по номеру (законы Э1–Э4)** — цель `(элемент N в F(…)) равен …`.
Мест **7** (весь `element-po-nomeru-chestnaya.flang`).
- механизм — `сверщик.c:3234`–`3237`, `3362`–`3382`: `Э1 элемент 1 в (приписать
  Г к Х)=Г`; `Э2 элемент К в (приписать Г к Х)=элемент (К−1) в Х` (К литерал ≥2);
  `Э3 элемент ((длина Х)+1) в (добавить Э к Х)=Э`; `Э4 элемент К в [Э₁…Эн]=Эк`.
- примеры: `Приписанное стоит первым` (Э1, стр.17), `Второе приписанное стоит
  вторым` (Э2, стр.31), `Дописанное стоит последним`/`…за прежними` (Э3, стр.45,
  58).
- цепочка: `развернуть` → **переписать элемент по Эk** → `закрыть тождеством`.
  Э2/Э3 несут счёт над литеральным номером — риск выше, чем у Д (§2).

**С5. Замкнутая арифметика (ход `вычислить`)** — цель замкнута (свободных имён
нет), закрывается счётом. Мест **2**.
- `Замкнутая цель`/`Ф9` (`forms.flang:45`): цель `(2 плюс 2) равно 4` — это
  дословно пример `proof-object.md §4`.
- `Модули`/`К1` (`sources.flang:23`): тело `пустой список` делает цель замкнутой,
  `(«Все неотрицательны» от пустой список) равен да` считается (`sources.flang:7`
  коммент это и говорит).
- цепочка: `вычислить ⟨T⟩=⟨V⟩` → `закрыть тождеством`. Хода `вычислить` в семи НЕТ
  (§2), но он уже расписан в `proof-object.md` (P8, обёртка над `ocenit_term`).

**С6. Круг и разбор в постусловии** — развёртки мало: нужна проекция поля или
редукция разбора известного варианта. Мест **2**.
- `Круг через коробку`/`Р1` (`equality.flang:31`): `«Достать» от («Положить» от
  н)` → две развёртки дают `(вариант «Коробка» с «внутри» равным н).«внутри»`,
  и это надо СПРОЕЦИРОВАТЬ в `н`.
- `Обернуть в успех`/`Т1` (`types.flang:18`): постусловие — `разбор результат
  случай …`; после развёртки `результат` — известный вариант, разбор надо
  РЕДУЦИРОВАТЬ к его ветви.
- развёртка (`сверщик.c:813` `hod_razvyortki`) ни того, ни другого не делает
  (только раскрывает вызов в тело). Оба приёма — новые (§2). Семья самая мелкая и
  самая дорогая по месту.

**С7. Индукция и свёртка-постусловие** — за теоремным треком, 4102 не трогал.
Мест **8**.
- algebra-индукция (тело `разбор`, пользовательские функции): `Копия`/«копия
  равна оригиналу» (`stack.flang:91`, шаг — `тождество`, ходы УЖЕ печатаются, см.
  `stack.запись`); `Вставить в упорядоченный`/`С5` (`substantive.flang:48`, база
  — `тождество`); `Голову в хвост`/`М3` (`substantive.flang:68`, база и шаг —
  `тождество`).
- fold-индукция (тело `свёртка`, носитель fold): три теоремы
  `svyortka-prefiks-chestnaya.flang` («размер есть длина», «пересобранный есть
  тот же», «в пересобранном столько же»). Ходов в их записи **нет ни строки**
  (`grep -c 'ход ' svyortka-prefiks-chestnaya.запись` = 0) — печать носителя fold
  не написана.
- свёртка-постусловие: `Копия свёрткой`/`У3` (`abilities.flang:49`): `(длина
  результат) равен (длина элементы)` над `свёртка … → добавить эл к акк`, БЕЗ
  принципа. Калькулятор закрывает спец-веткой свёртки (`сверщик.c:1911`+, кадры
  `SV_VERH`); в законах Д свёртки нет. Это скрытая индукция без теоремы (та же
  форма, что «в пересобранном столько же», но без `теорема`).

## 2. Вид печатаемого следа по каждой семье

Печать реконструирует цепочку из СТРУКТУРНЫХ данных записи (тип, конструктор,
тело текстом, номер строки), а не из следа ядра — как это уже делают построители
индукции `«Ходы тождества записи»` (`zapis.flang:1225`) и `«Ходы переписки
записи»` (`zapis.flang:1239`), собранные `«Строки ходов записи»`
(`zapis.flang:975`). Для постусловий нужны АНАЛОГИЧНЫЕ построители, привязанные к
печати постусловия (сейчас там только `правило «имя»`).

Существующие 7 ходов (`сверщик.c`): `развернуть` (813), `замена по дано` (886),
`выбор` (914), `соседи` (900), `деление` (930), `закон` (940, законов ДВА:
`сумма неотрицательных`, `литерал неотрицателен`, `primenit_zakon` 561), `закрыть`
(950: `дано`/`тождеством`/`истиной`/`требованием`). Структурные: `ход цель`,
`ход дано`, `ход конец`.

**С1 соседи — 7 ходов ХВАТАЕТ.**
```
    ход цель
    ход 1 развернуть ⟨«Сумма наоборот» от ( а ) и б⟩ строка 34 ⟨а плюс б⟩
    ход 2 соседи ⟨а плюс б⟩
    ход 3 закрыть тождеством
    ход конец
```
`hod_sosedey` (`сверщик.c:900`) переставит операнды узла `плюс`; стороны совпадут.
Печать: новый построитель «Ходы соседей записи» рядом с 1225.

**С2 рефлексив — 7 ходов ХВАТАЕТ.**
```
    ход цель
    ход 1 развернуть ⟨«Тот же список» от ( элементы )⟩ строка 69 ⟨элементы⟩
    ход 2 закрыть тождеством
    ход конец
```
Это ровно `«Ходы тождества записи»` (`zapis.flang:1225`) без варианта — база уже
написана, её надо позвать для постусловия.

**С3 длина Д — НОВЫЙ ход, риск.**
```
    ход цель
    ход 1 развернуть ⟨«Склейка строк» от ( первый ) и второй⟩ строка … ⟨соединить первый с второй⟩
    ход 2 переписать формой ⟨длина (соединить первый с второй)⟩ = ⟨(длина первый) плюс (длина второй)⟩ законом «мера склейки»
    ход 3 закрыть тождеством
    ход конец
```
Хода `переписать формой` в семи НЕТ. Это переписка равного на равное по ЗАКРЫТОМУ
списку встроенных законов Д1–Д5. Отличается от `замена по дано` тем, что источник
равенства — не допущение записи, а встроенная форма; чекер обязан ПРОВЕРИТЬ, что
левая сторона в цели правда `длина(соединить …)`, и САМ пересобрать правую по Дk,
а не взять её из записи (иначе снимок-со-снимком, §6). Расширение переигрывателя →
риск для набора проб.

**С4 элемент Э — НОВЫЙ ход, риск выше.** Тот же `переписать формой`, законы Э1–Э4:
```
    ход 2 переписать формой ⟨элемент 1 в (приписать первый к элементы)⟩ = ⟨первый⟩ законом «голова приписанного»
```
Э2/Э3 несут арифметику литерального номера (`К−1`, `(длина Х)+1`); ход обязан
считать её сам, не доверяя записи. Больше поверхности для подделки, чем у Д.

**С5 вычислить — НОВЫЙ ход (уже расписан в спеке).**
```
    ход цель
    ход 1 вычислить ⟨2 плюс 2⟩ = ⟨4⟩
    ход 2 закрыть тождеством
    ход конец
```
`P8` из `proof-object.md §2.2/§4`: обёртка над `ocenit_term` (`сверщик.c:1986`),
проверяет замкнутость `T`, считает, сверяет с `⟨V⟩`. Для `К1` перед `вычислить`
стоит `развернуть` (результат→`пустой список`).

**С6 круг/разбор — ДВА новых хода, риск наибольший.** Нужны:
- `проекция ⟨(вариант «Коробка» с «внутри» равным н).«внутри»⟩ = ⟨н⟩` — читает
  поле известного варианта;
- `разбор ⟨вариант «Успех» …⟩` — редуцирует `разбор` известного варианта к ветви,
  связывая имена образца (не путать с `деление` — то по булеву условию цели).

Оба — чтение конструктора, без вычисления, но в семи их нет. Развёртка их не
делает намеренно (`сверщик.c:813` разворачивает только вызов в тело).

**С7 индукция/свёртка.**
- algebra: печать УЖЕ есть (`«Ходы переписки записи»` 1239 даёт шаг `Копии`:
  `развернуть`×3 + `замена по дано 1` + `закрыть тождеством`, см. `stack.запись`).
  Хватает 7 ходов, потому что `Высота`/`Копия` — пользовательские функции с
  разбором, развёртка по конструктору берёт их тело.
- fold: печати носителя fold нет; её надо дописать по образцу algebra. Шаг
  свёртки «в пересобранном столько же» разворачивается в `(1 плюс (длина акк))
  равен (1 плюс (длина пройдено))` — то есть шагу НУЖЕН закон Д1
  (`длина(добавить)=+1`), значит fold-семья наследует расширение С3.
- `У3` — либо ход свёртки (fold-мера), либо переписать исходник под явную
  `теорема` (правка исходника, не только печать; назвать прямо).

## 3. Что нужно на стороне чекера сверх 4102

4102 провёл ровно постусловия-равенства БЕЗ принципа (`est_hody && !est_princip`,
`сверщик.c:4795`). По семьям:

| семья | маршрут 4102 несёт? | что нужно чекеру сверх 4102 |
|---|---|---|
| С1 соседи | да | ничего — ход `соседи` стоит |
| С2 рефлексив | да | ничего — `развернуть`+`закрыть` стоят |
| С3 длина Д | да (как только ход есть) | НОВЫЙ ход `переписать формой` (законы Д1–Д5) в `proigrat_blok` |
| С4 элемент Э | да | тот же ход + счёт литерального номера (Э2/Э3) |
| С5 вычислить | да | ход `вычислить` (P8, обёртка `ocenit_term`) |
| С6 круг/разбор | да | ходы `проекция`, `разбор`-варианта |
| С7 индукция/свёртка | **нет** | теоремный трек / гейт принципа — ниже |

Ни одной семье НЕ нужен новый МАРШРУТ, кроме С7: С1–С6 — постусловия без
принципа, их несёт готовый гейт 4102, им нужны только новые ХОДЫ внутри
`proigrat_blok`. Теоремный трек (`sverit_teoremu`, зов `proigrat_blok` на
`сверщик.c:4710`) и замкнутый счёт `ocenit_term` 4102 не трогал — там КОД 3 стоит
(один пример stack «не взялся»).

**С7 требует отдельной работы чекера:**
- `С5`/`М3` — постусловия С ПРИНЦИПОМ; гейт 4102 их НЕ берёт (`est_princip` истинно
  → уходят в `perepiskoy`/`proigrat_uzel`, `сверщик.c:4808`+). Нужно расширить
  гейт на принцип-постусловия, иначе печать инертна (§6).
- fold-носитель — печати нет и теоремный трек ходов не видит; нужно и печатать, и
  чтобы `proigrat_blok` под теоремой их проигрывал.

## 4. Порядок миграции

Критерий готовности КАЖДОЙ семьи (все четыре обязательны):
1. `zapis.flang` печатает след (`ход цель … ход конец`) на местах семьи;
2. чекер переигрывает файл семьи до **КОД 0**;
3. набор проб байт-в-байт — ни одна честная запись не покраснела, каждая
   существующая подделка по-прежнему красная;
4. НОВАЯ подделка на новый ход семьи находит свою строку и краснеет (§6).

Порядок — от крупного-однородного-дешёвого к мелкому-дорогому:

1. **С2 рефлексив (8)** — существующие ходы, самая крупная безрисковая. Первой:
   проверяет, что печать постусловия и зов гейта состыковались, не заводя новых
   ходов. Файлы: `boundaries`, `equality`, `types`, `corpus-hof`.
2. **С1 соседи (3)** — существующий ход `соседи`. Второй.
3. **С5 вычислить (2)** — ход уже расписан спекой, `ocenit_term` готов, мест мало.
   Дешёвая обкатка машины «новый ход + подделка на него». Файлы: `forms`,
   `sources`.
4. **С3 длина Д (8)** — крупнейшая содержательная семья, один механизм
   (`переписать формой`) кроет Д1–Д5. Высокая отдача. Файлы: `abilities`,
   `equality`, `substantive`, `corpus-hof`, `binder-wall-map`.
5. **С4 элемент Э (7)** — тот же ход формы плюс счёт номера. После С3, чтобы
   переиспользовать проверку хода. Файл: `element-po-nomeru-chestnaya`.
6. **С7 индукция/свёртка (8)** — теоремный трек. Сначала печать algebra (строители
   1239 уже есть) и гейт принцип-постусловий; затем fold-носитель (наследует Д1 из
   С3); `У3` — последним, с решением «ход свёртки или явная теорема».
7. **С6 круг/разбор (2)** — самая мелкая и самая дорогая по месту (два узких
   хода). Последней. Кандидат остаться за калькулятором, если проекция/разбор
   окажутся дороже своей отдачи (2 места).

## 5. Учёт Г3

**Где печать.** Только `zapis.flang` (слой печати) — новые построители рядом с
`«Ходы тождества записи»` (1225) и `«Ходы переписки записи»` (1239). «Ядро
решений» (`proof-kernel.flang`) НЕ трогать: печать реконструирует цепочку из
структурных данных записи, как индукция, а не получает след от ядра. Правку 4101
(поле «ходы» в ядре) НЕ закладывать — она инертна, ядро след и так выбрасывает, а
восстановить его на слое печати можно без него.

**Траектория доверенной базы (числа — по `proof-object.md §7`, перемерять при
снятии):**

| шаг | что с доверенной базой |
|---|---|
| С1,С2 напечатаны | 0 новых строк доверия (ходы уже стоят); калькулятор ещё нужен — доля не падает |
| С3–С6 ходы влиты | доверенная база **РАСТЁТ** на ~50–100 строк (`переписать формой` Д+Э ~40, `вычислить` ~20, `проекция`/`разбор` ~30); калькулятор ещё СТОИТ рядом — снять нельзя |
| весь корпус (эти 42 И остальные правила `proof-object.md §8`) переигран | калькулятор `сверщик.c` ~2080 (1506–3794 минус `ocenit_term` 205) **снимается** |
| итог | −2080 снято, +~50–100 прибавлено → **чистый ≈ −1800** |

**Условие снятия калькулятора — жёсткое.** `perepiskoy`/`svesti_term`/
`razborom_celi`/`iz_obyavlennogo` кроют НЕ только правило «тождество», а всё
постусловное доказательство корпуса. Снять их можно ТОЛЬКО когда переигрывается
весь корпус (все 17 правил, `proof-object.md §8`), а не когда переехали эти 42.
Эти 42 — необходимый ломоть, не достаточный. До снятия запас Г3 (потолок 1,86×)
временно СЪЕДАЕТСЯ ростом переигрывателя при стоящем калькуляторе — держать в
смете, не обнаруживать прогоном на середине.

Приборы Г3: `flang/scripts/kernel-lines-to-trust.flang` (`ядроРешенийСтрок`,
`достижимоСтрок`), `одна-линейка.py`. «Ядро решений» на `gh/dev` — 4638 строк
(число из `proof-object.md §7`, перемерять).

## 6. Риски и породы

**Инертный сторож (печать есть — чекер не зовёт).** Самый вероятный провал.
- С7: если напечатать ходы под постусловием-с-принципом (`С5`/`М3`) или под
  fold-теоремой, гейт 4102 их НЕ позовёт (`est_princip` истинно, `сверщик.c:4795`)
  — печать станет украшением. Лечится расширением гейта на принцип ДО печати.
- проверка: под каждым мигрированным местом посадить ЛОЖНЫЙ ход и убедиться, что
  КОД 1. Если печать есть, а ложный ход не краснит — сторож инертен. Ровно так
  ловится порода «7111» (ложные ходы под посылками, `сверщик.c:4790` коммент).

**Снимок-со-снимком.** Запись рождена `--записать` из того же прогона ядра, что
потом переигрывается. Если новый ход БЕРЁТ правую сторону из записи (`длина А +
длина Б`, `⟨V⟩`, поле), а не пересобирает сам — чекер сверяет запись с записью и
зеленеет всегда.
- лечится тем же приёмом, что развёртка: двойная привязка. `вычислить` — считает
  `T` через `ocenit_term`, не верит `⟨V⟩`. `переписать формой` — сам собирает
  правую по Дk/Эk из ЦЕЛИ и сверяет, а записанную — только как двойную привязку.
  `проекция`/`разбор` — читают конструктор из цели, не из записи.
- проверка: подделать записанную правую (`длина А` вместо `длина А + длина Б`;
  `⟨5⟩` вместо `⟨4⟩`) — обязан КОД 1 с называнием места.

**Зелёный на протухшем.** Ход, доверяющий записанному значению/строке, пропустит
устаревший или подделанный факт.
- проверка на каждый новый ход — подделка, которая НАХОДИТ свою строку (правка
  сверяет запись не саму с собой). Классы подделок для новых ходов:

| ход | подделка | ожидаемый отказ |
|---|---|---|
| соседи | перестановка через скобки (ассоциативность) | «не сумма/произведение ровно двух соседей» |
| переписать формой Д | `длина(соединить А Б)` → `длина А` (обронить слагаемое) | правая пересобрана чекером ≠ записанной |
| переписать формой Д | Дk на терме, который не `соединить`/`добавить`/… | форма цели не та, закон не подошёл |
| переписать формой Э | `элемент 1 в (добавить …)` по закону Э1 (Э1 про `приписать`) | форма не совпала с законом |
| переписать формой Э | подменённая арифметика номера (Э2/Э3) | номер, пересчитанный чекером, ≠ записанному |
| вычислить | `⟨V⟩` ≠ счёту `T` | «T посчитан … , а запись несёт V» |
| вычислить | `T` со свободным именем | «терм не замкнут — считать нечего» |
| проекция | поле не то у известного варианта | «у варианта «…» поля «…» нет» |
| разбор | выбрана не та ветвь известного варианта | «вариант «…» ведёт в ветвь «…»» |

**Два числа, не одно.** На каждый шаг миграции считать И «подделок отвергнуто», И
«честных отвергнуто 0». Одно без другого не значит ничего: ход, отвергающий всё
подряд, отвергнет и ложь, и правду — тогда подделка при нём ничего не меряет
(порода из `element-po-nomeru-chestnaya.flang:5` и `svyortka-prefiks-chestnaya`).
Честная половина — файлы `*-chestnaya`, они обязаны оставаться КОД 0.

**Место реально сдвинулось.** Печать без сдвига счётчика — украшение. Мерить по
счётчикам чекера: мигрированное место обязано УМЕНЬШИТЬ «на слово ядра» /
калькуляторный путь и УВЕЛИЧИТЬ «сведений проиграно заново» (`сверщик.c` влитие в
`bez_teoremy`). Не сдвинулось — сторож инертен, разбираться до печати следующей
семьи.
