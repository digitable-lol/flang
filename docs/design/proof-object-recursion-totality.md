## 1. Где сегодня рекурсия висит на слове ядра

### 1.1. Что печатает ведомость (stdout) — и чего НЕ печатает запись

Прогон `flang check <пример> --proof` печатает носитель завершения строкой ведомости:

- `corpus-numtree` «Высота»: `доказано структурой: аргумент 1 («дерево») на каждом витке
  становится частью себя; цепочка частей конечного дерева обрывается сама, сторожа нет`;
- `corpus-factorial` «Факториал»: `доказано точным шагом: аргумент 1 («н») объявлен
  натуральным и убывает на 1; дно и потолок даёт тип, внутри потолка шаг точен — сторожа нет`;
- `corpus-tree-height`: «Глубина дерева» — структурой; «Глубже» — **композицией** (рекурсии нет).

Это ведомость, идущая в stdout. В ЗАПИСЬ (`--записать`) из этого не попадает НИЧЕГО
проверяемого. Снято прогоном:

- `corpus-factorial.запись` (26 строк) несёт только `вид postcondition` + блок теоремы
  индукции; блока `тотальность «Факториал»` НЕТ, строки `тотальностей N` в шапке НЕТ.
- `corpus-numtree.запись` — то же: структурная «Высота» блока не получает.
- `corpus-tree-height.запись`: `тотальностей 1`, и это блок `тотальность «Глубже» строка 60 /
  вид composition` — **композиция**; структурная «Глубина дерева» блока не имеет.

Итог: у структурно/шагово-рекурсивной функции носителя завершения в записи нет вовсе — он
живёт лишь строкой ведомости в stdout, которую сверщик не читает. Завершение рекурсии
сегодня — целиком «на слово ядра».

### 1.2. Объявленная мера `убывает`: обязательство есть, но закрыто анализом

Когда автор пишет `убывает <мера>` (напр. `docs/examples/measure/euclid.flang:6` `убывает б`,
`docs/examples/measure/binary-search.flang:6` `убывает верх минус низ плюс 1`,
`docs/examples/leetcode/022-generate-parentheses.flang:6` `убывает (2 умножить на н) минус
открыто минус закрыто плюс 1`), `obligations.flang` строит обязательство меры
(`Обязательство меры`, `:289`): `kind="measure"`, `goal=` поле `decreases` (сама мера),
`proof=` ничто, `grid=0`, а `discharge` — `Закрытие мерой` (`:278`):

```
by:"analysis"   says:"доказано объявленной мерой: убывание доказал анализ завершаемости"
```

То есть обязательство приходит УЖЕ ЗАКРЫТЫМ, и закрыл его не автор, а анализ завершаемости
до всякого доказательства (комментарий `obligations.flang:274-277`). Ходов при нём нет
(`proof` пуст). Для сверщика это `by:analysis` — ровно случай A1 «на слово ядра»: он его
не переигрывает. Носитель `убывает`-меры (`docs/examples/measure`, `docs/examples/leetcode`) в корпус
самодостаточных копий не входит, поэтому в корпусе `объявленная мера 0` — семья проспективна,
как межмодуль (`crossmodule-link §2.1`).

### 1.3. Что уже посчитано и выброшено — а нам нужно

Анализ считает носитель полностью, а `carriers.flang` даже выносит его наружу — но в
ведомость, не в обязательства:

- `Структурное убывание` (`carriers.flang:58-63`) = `{откуда, куда, позиция, параметр}` —
  ребро рекурсии, ПОЗИЦИЯ убывающего аргумента и его ИМЯ. Имя берётся той же «Именем по
  номеру», какой его называют отказы анализа (`:150`). Это ровно свидетель структурного
  убывания, и он уже вычислен (`Структуры компонент`, `:187`).
- спуски объявленной меры анализ отдаёт полем `descents` «Итога тотальности», оттуда их берёт
  `Мест у функции` (`obligations.flang:320`) и `goal=decreases` (`:301`).

Ядро эти данные ВЫЧИСЛЯЕТ и (для структуры) ВЫБРАСЫВАЕТ из обязательств; печать их не видит.
Дыра — печать не кладёт носитель рекурсии в запись, а сверщик не умеет его переиграть.

## 2. Формат блока — расширение зарезервированного `вид`

Блок тотальности уже несёт поле `вид`, и `composition` объявлен закрытым списком, у которого
`structure`/`measure`/`step` — «сёстры, здесь их значение отвергается вслух»
(`proof-object-po-obyavleniyu-trace.md §1.1`; в коде — `сверщик.c:5483`). Рекурсия наполняет
эти сёстры. Ниже — грамматика каждого вида. Всё в блоке — данные, ПЕРЕПРОВЕРЯЕМЫЕ чтением
исходника и подстановкой, без веры записи.

### 2.1. `вид structure` — убывание части значения

```
тотальность «Высота» строка 56
  вид structure
  убывает аргумент 1 «дерево»
  дно тип «Дерево»
  виток строка 58 «Высота» от х
    часть «х» поле «хвост» варианта «Развилка»
  самовызов строка 58
  конец тотальности
```

- `убывает аргумент N «имя»` — позиция и имя убывающего аргумента (из `Структурное
  убывание`, `carriers.flang:150`).
- `дно тип «Т»` — фундированность даёт тип: цепочка частей конечного значения обрывается
  сама. Т — тип убывающего аргумента.
- `виток строка K «F» от …` — по одному на КАЖДОЕ рекурсивное ребро, номер строки тела.
- `часть «п» поле «поле» варианта «В»` — аргумент на убывающей позиции есть ПОЛЕ «поле»
  варианта «В», разобранного в объемлющем `разбор`, того же типа Т. Это дословно то, что
  сверщик уже проверяет у индукции S1: «поле того же типа: не круг» (`сверщик.c:4938`,
  `:2142` «это не индукция, а круг»).
- `самовызов строка K` — свидетельство, что рекурсия ЕСТЬ (для рекурсии обязательна, в
  отличие от `самовызова нет` у композиции).

### 2.2. `вид step` — точный/постоянный шаг по числу

```
тотальность «Факториал» строка 66
  вид step
  убывает аргумент 1 «н»
  дно тип «нат»
  виток строка 84 «Факториал» от (н минус 1)
    ход цель ⟨(н минус 1) меньше н⟩
    ход 1 вычислить … / закон «литерал неотрицателен»
    ход конец
  мера не меньше 0 тип «нат»
  самовызов строка 84
  конец тотальности
```

- `дно тип «нат»` / `мера не меньше 0 тип «нат»` — обе границы даёт тип-отрезок `нат`
  [0, 2⁵³−1] (skill: «обе границы — отсюда индукция по числу»). Дно фундировано типом,
  доказывать `≥0` не надо — это факт подписи.
- убывание `(н минус 1) < н` — цепочка стоящих ходов (§3.2).

### 2.3. `вид measure` — объявленная `убывает <мера>`

```
тотальность «Двоичный поиск» строка 5
  вид measure
  мера ⟨верх минус низ плюс 1⟩
  дно ноль
  виток строка K «Двоичный поиск» от … (низ' = серёдка плюс 1)
    ход цель ⟨(верх минус (серёдка плюс 1) плюс 1) меньше (верх минус низ плюс 1)⟩
    ход дано 1 …            (сторожа ветви: низ не больше верх, серёдка ≥ низ …)
    ход 1 …                 (стоящие ходы)
    ход конец
  мера не меньше 0
    ход цель ⟨(верх минус низ плюс 1) не меньше 0⟩
    ход 1 …
    ход конец
  самовызов строка K
  конец тотальности
```

- `мера ⟨…⟩` — сам терм меры (из `goal=decreases`, `obligations.flang:301`), синтаксисом
  языка в уголках (как уже печатаются термы развёртки, `zapis.flang:35`).
- `виток … ход цель ⟨после меньше до⟩ … ход конец` — на каждое рекурсивное ребро цепочка
  стоящих ходов, доказывающая СТРОГОЕ убывание меры под сторожами ветви, ведущей к вызову.
- `мера не меньше 0 … ход конец` — фундированность, если тип дна её не даёт (мера — общий
  терм, а не `нат`): цепочка ходов до `закон «сумма/литерал неотрицателен»`.

**Ключ печати:** цепочку убывания и `≥0` ядро уже ПРОХОДИТ анализом; печать = запомнить шаги,
как это уже сделано для индукции (`proof-object.md §1,§5`), а не считать заново.

## 3. Что делает сверщик — независимая перепроверка по видам

`сверить_тотальность` (`сверщик.c:5459`) сегодня знает один вид: строка `:5483` требует ровно
`вид composition` и отвергает прочее. Механизм: диспетчер по `вид`, где `composition` — как
есть (четыре проверки `proof-object-po-obyavleniyu-trace.md §2`), а `structure`/`step`/`measure`
получают свои проверки. Общее у всех рекурсивных видов — ИНВЕРСИЯ проверки (б): самовызов не
запрещён, а ТРЕБУЕТСЯ и служит опорой.

### 3.1. `structure` — четыре проверки чтения, БЕЗ арифметики

- **(а) привязка** к строке объявления — как у композиции (`строка_по_номеру:326`,
  `хозяин_строки:658`, `имя_функции`).
- **(б-инв) самовызов ЕСТЬ** — перечитать тело сам (`строка_самовызова`, `сверщик.c:5440`,
  сегодня зовётся в (б) на строке `:5494`): вернул строку — хорошо; вернул 0 — красное
  («блок вида structure, а рекурсии в теле нет»).
- **(в) убывающая часть** — на КАЖДОМ рекурсивном ребре аргумент на объявленной позиции есть
  поле разобранного варианта ТОГО ЖЕ типа. Это дословно проверка S1 индукции, уже стоящая
  (`сверщик.c:2142` «не того же типа — это не индукция, а круг»): переиспользуется, не пишется
  заново. Чужой тип поля → красное.
- **(г) дно** — тип убывающего аргумента объявлен вариантами (индуктивен): цепочка частей
  конечна. Не индуктивный тип → красное.

Арифметики здесь НЕТ — только чтение тела и сверка типа поля. Доверенная база не растёт.

### 3.2. `step`/`measure` — переигрывание убывания стоящими ходами

- **(а)/(б-инв)** — как у structure.
- **убывание** — на каждом ребре сверщик держит цель `⟨после меньше до⟩` и переигрывает
  цепочку `ход …` тем же `проиграть_блок` (`сверщик.c:992`, ~296 строк, уже стоит). Все ходы —
  из стоящих семи-девяти: `развернуть`, `замена по дано`, `соседи`, `закон`, `деление` (по
  сторожу ветви), `вычислить` (замкнутый счёт `оценить_терм`), `закрыть`. `после` — мера с
  подставленными аргументами рекурсивного вызова; подстановку даёт `вставить_вместо` (уже есть).
- **фундированность** — `нат`/`вес`/точные десятичные дают дно типом (проверка чтения подписи,
  как structure §3.1(г)); общий терм меры несёт свою цепочку `мера не меньше 0 … ход конец`,
  переигрываемую тем же `проиграть_блок` до `закон «сумма/литерал неотрицателен»` (2 IEEE-леммы
  A3, уже в доверии).

**Строгость + дно = нет бесконечного спуска.** Оба под-факта — обычные числовые цели,
кроются стоящими ходами и стоящими законами. `вычислить` ограничен замкнутыми термами
(`proof-object.md §4`); мера параметрична, поэтому убывание доказывается ходами
переписки/законом (как постусловие), а не одним замкнутым счётом — но тем же набором ходов.

### 3.3. Круг и композиция-на-рекурсии

`все_имена` (`сверщик.c:5683-5685`) собирает имена ВСЕХ блоков секции первым проходом,
НЕЗАВИСИМО от вида. Значит как только рекурсивная G обретает блок (любого рекурсивного вида),
её имя входит в `все_имена`, и проверка (г) композиции F, зовущей G (`:5515-5519`, «зовомый
обязан быть в `все_имена`»), проходит. **Композиция-на-рекурсии (8) закрывается АВТОМАТИЧЕСКИ,
без единой правки со стороны F** — подтверждено прогоном сбора `все_имена` и §7.2 trace-дока.

Одна тонкость — ацикличность. `сверить_круги_тотальности` (`:5531`) объявляет кругом всякую
функцию, достижимую из самой себя по рёбрам `зовёт «…»`. Для рекурсивного блока ПРЯМОЕ ребро
F→F законно и погашено свидетелем убывания — этот проход обязан снимать саморебро с блока,
несущего убывание (иначе честная рекурсия названа кругом). Взаимная рекурсия F→G→F без общей
меры дна доверия не достигает и остаётся кругом (код 1) — общая мера взаимной рекурсии честно
вне этой семьи.

## 6. Реприпт: ДА (в отличие от межмодуля)

Показано прогоном на РЕАЛЬНОМ сверщике без правки серийного кода. Взята честная
`corpus-tree-height.запись` (код 0), в блоке `тотальность «Глубже»` подменён `вид composition`
→ `вид structure` — модель того, что печать положила бы рекурсивный блок, которого сверщик
ещё не читает:

```
$ сверщик corpus-tree-height.flang mutant-structure.запись ; echo $?
НЕ СОШЛОСЬ: строка записи 33 не узнана: «вид structure» — чекер не принимает того, чего не
читает; тотальность «Глубже»: заявлен вид не composition — это другая семья, здесь
отвергается вслух
1
```

Контроль (честная запись) — код 0. То есть места под носитель рекурсии в записи сегодня нет,
и сверщик его отвергает. Значит:

- **Печать (`zapis.flang`) — трогается** (§4): новый носитель в записи.
- **Сверщик (`сверщик.c`) — трогается** (§5): диспетчер по видам.
- **Реприпт корпуса — ДА:** записи 86 модулей надо перепечатать, чтобы рекурсивные блоки в них
  появились (батч [Ш4]). Это прямая противоположность межмодулю (`crossmodule-link §6`: реприпт
  НЕ нужен, там менялся только сверщик и подавались существующие записи). Причина различия:
  межмодуль ПЕРЕИСПОЛЬЗУЕТ уже напечатанные блоки зовомых, а рекурсия печатает носитель,
  которого в записи не было НИКОГДА.
- **Ядро/семя — не трогаются** печатью; но структурный носитель ядро в узлы обязательств
  сегодня не кладёт (кладёт только меру и композицию) — источник для печати структуры берётся
  из `carriers.flang` тем же приёмом, что композиция. Если предпочесть путь через обязательство
  (единый конвейер с мерой), это правка `obligations.flang` (добавить `kind="structure"` рядом
  с `Обязательство меры`), тоже серийная и в реприпт входящая.

## 7. Рост доверенной базы: НЕТ — названо числом

Доверенное дно сверщика — **15 примитивов языка** (`сверщик.c:1450`, `PRIMITIVY[]`: плюс,
минус, умножить, делить, остаток, длина, соединить, подстрока, содержит, начинается, если,
разбор, свёртка, отобразить, отфильтровать) плюс переигрыватель ходов (~296 строк) и замкнутый
счёт `оценить_терм` (~205 строк) — всё уже стоит.

| что рекурсия просит от доверия | откуда берётся | прибавляет |
|---|---|---|
| арифметика меры (`минус`/`плюс`/`умножить`/`длина`…) | те же 15 примитивов | **0** |
| замкнутый счёт `⟨2 плюс 2⟩` в ходе `вычислить` | `оценить_терм` (P8, уже в доверии) | **0** |
| переигрывание убывания/`≥0` | `проиграть_блок` + стоящие ходы/законы | **0** |
| структурное убывание (часть значения) | проверка типа поля из S1 (уже в сверщике) | **0** |
| дно `нат`/`вес`/десятичных | чтение подписи (тип-отрезок) | **0** |

Новый КОД сверщика — диспетчер по видам и чтение рекурсивных рёбер тела (`строка_самовызова`/
`вызовы_тела` уже есть) — это оснастка, а не доверенный ПРИМИТИВ: он читает исходник и
подставляет, ничего нового на веру не беря. **Итог: доверенная база не растёт ни на один
примитив сверх 15 + `оценить_терм`.** Это тот же ответ, что у композиции (`trace §3`: «прибавляет
ноль») и межмодуля (`crossmodule-link §7`: «НЕ растёт»).

**Нужен ли новый ход:** НЕТ. Убывание меры и `мера ≥ 0` — обычные числовые цели, кроются
семью-девятью стоящими ходами. Структура вообще без хода — проверкой чтения. Ни `вычислить`,
ни `переписать формой` в новом виде не нуждаются: `вычислить` берётся как есть для замкнутых
кусков меры, `переписать формой` (развернуть/соседи/замена) — как есть для параметрических.

## 9. Проба-подделка — носитель обязан быть отвергнут

Свойство, обязанное выжить: сверщик НЕ примет ложную меру/структуру. По одному классу на вид
(мерило готовности — каждая ОБЯЗАНА дать код 1, честная — код 0):

| проба | подделка | ожидаемый отказ |
|---|---|---|
| structure | `часть` названа полем ЧУЖОГО типа (не рекурсивным) | «поле не того же типа — это круг, а не убывание» |
| structure | блок `вид structure`, а самовызова в теле нет | «вид structure, а рекурсии в теле нет» |
| step | `убывает аргумент` не `нат`, дна нет | «дно не фундировано: тип аргумента не отрезок» |
| measure | записанное `после` НЕ меньше `до` (мера растёт) | «убывание не доказано: цепочка не закрывает `после меньше до`» |
| measure | `мера ⟨…⟩` со свободным именем вне параметров | «мера ссылается на имя, не связанное подписью» |
| measure | пропущено ребро (виток на одном самовызове, а их два) | «витков в блоке 1, а самовызовов в теле 2» |
| круг | F→G→F, оба блока `вид measure` без общей меры | «круг тотальности: F достижима из себя через G» |

Уже показано прогоном (§6): подмена `composition`→`structure` в честной записи даёт код 1 —
образца строки нет, вид отвергнут вслух. Это тот порог, который печать обязана СНЯТЬ (дав
образец и переигрывание), не ослабив сторож: правка обязана НАЙТИ свою строку исходника,
иначе сверяет запись саму с собой. Считать два числа: «подделок отвергнуто» и «честных
отвергнуто 0».
