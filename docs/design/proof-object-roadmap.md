# Дорожная карта миграции на объект доказательства

**Состояние:** сводная карта под стройку. Кода/ядра/семени/чекера не трогает —
только сводит воедино пять разведок и спеку в один порядок работ. Числа не
переснимались заново: каждое взято из названного входного документа со своим
провенансом (ветка/коммит указаны в источнике) и здесь помечено ссылкой. Числа
строк `сверщик.c`/`zapis.flang` в источниках сняты на РАЗНЫХ ветках (файл растёт,
номера уезжают — предупреждение `proof-object-migration.md:18-20`); при стройке
перемерять на рабочем стволе.

**Зачем эта карта.** Пять разведок (`proof-object-migration.md` и четыре разбора
по родам) и проект S2 (`proof-object-lemma-po-svoystvu.md`) разобрали КАЖДЫЙ род
правил порознь и каждый назвал свой порядок. Но стройка идёт по ОДНОМУ дереву, с
ОДНИМ `сверщик.c`, ОДНИМ `zapis.flang` и ОДНОЙ дорогой перепечаткой семени — и
если вести роды параллельно и наивно, перепечаток выйдет шесть, а не одна, и
калькулятор снимут раньше времени, обрушив долю Г4. Эта карта склеивает роды в
единый критический путь с зависимостями, чтобы стройка шла по плану, а не кругами.

Входы (все влиты в dev): `proof-object.md` (спека), `proof-object-migration.md`
(правило «тождество», 7 семей), `-po-primeru.md`, `-po-svoystvu.md`,
`-po-sluchayam.md`, `-razbor-celi.md`, `proof-object-lemma-po-svoystvu.md` (проект
S2), `DESCRIPTION.md`, `/srv/tmp/dokazuemyy/КРИТЕРИЙ.md` (гейты Г1–Г7).

### 0.2. Прибор, который скажет «готово»: ярлык `доказуемость`

`./ярлык доказуемость` (`scripts/доказуемость.sh`) печатает ОДНО слово —

все три (и это же — три гейта, которые карта закрывает):

2. **доля корпуса, проверенного ПЕРЕИГРЫВАТЕЛЕМ, ≥ 95 %** — это Г4. Прибор честно
   признаёт: инструмента, отделяющего «проиграно» от «посчитано» и называющего

   измерить», а не «измерено 0». Появление этого прибора — отдельная поставка
   карты (шаг **[Ш5]**).
3. **набор проб цел** — ни одна подделка не принята, ни одна честная запись не
   отвергнута (`flang/proof/чекер/пробы/прогон.sh`). Это Г2.

Связка гейтов с шагами — в §4.

## 1. Порядок работ с зависимостями

### 1.1. Критический путь (серийный хребет)

Ровно как назвала разведка: **2 придирки чекера → S2 в чекер → печать следа всех
семей → ОДНА батч-перепечатка → снятие калькулятора.** Разворачиваю в шаги с тем,
что каждый трогает и почему он там, где он есть.

```
[Ш1] сверщик.c: 2 повторяющиеся придирки + мелкие ходы    ─┐
[Ш2] сверщик.c: приём S2 «постусловие вызванной» (лемма)   │ один файл — серийно
[Ш6] сверщик.c: снять калькулятор (~2080 строк)           ─┘  (Ш6 — после Ш5)
[Ш3] zapis.flang: печать следа всех семей (+ печать ядра)  ─── один файл — серийно
[Ш4] ОДНА батч-перепечатка семени + перегенерация записей  ─── дорогая, серийно
[Ш5] прибор доли-проигрыванием + замер Г4/Г2/Г7            ─── замер
```

**Почему `сверщик.c` — серийный хребет, но БЕЗ перепечатки.** Чекер собирается
`make -C flang/proof/чекер` из одного C-файла, «без единой строки от flang»
(`DESCRIPTION.md §6`). Значит **Ш1, Ш2 и Ш6 не требуют перепечатки семени вовсе** —
их проверяют локально собранным `сверщик` на золотых сертификатах (оснастка). Они
серийны только потому, что правят один файл и один список ходов (диспетчер закрыт:
«первичных ходов девять, список закрыт», `-po-svoystvu.md §2.1`).

**Почему `zapis.flang` — второй серийный файл.** Печать следа реконструируется в
слое печати (`zapis.flang`), по образцу уже стоящих построителей индукции
(`«Ходы тождества записи»` 1225, `«Ходы переписки записи»` 1239, `-migration.md
§5`). Все построители семей (соседи, деление, форма Д/Э, факт по свойству) садятся
рядом — один файл, серийно. Правки `zapis.flang` можно тестировать на локально
СОБРАННОМ flang ДО перепечатки; в семя они попадают только шагом [Ш4].

**Почему перепечатка одна.** См. §2.

### 1.2. Состав шагов

**[Ш1] `сверщик.c` — 2 повторяющиеся придирки + мелкие ходы.** Две придирки
блокируют места СРАЗУ НЕСКОЛЬКИХ правил — оттого идут первыми, отдача наибольшая:

- **Придирка А — гейт принципа инертен.** Постусловие с `принцип …`, но БЕЗ

  `bez_teoremy`, а там при `est_princip` истинном идёт `else`-ветка, которая ходы

  `bez_teoremy`, зовущим `proigrat_blok` по посылкам под принципом (по образцу
  `sverit_teoremu`). Блокирует: разбор цели по условию Р4 (3 места), разбором по

- **Придирка Б — скобки.** Два подвида: (1) `hod_vybora` не снимает один слой

- **Мелкие ходы, уже расписанные спекой** (в тот же серийный проход по файлу):

### 1.3. Что серийно, что параллельно

| работа | серийно/параллельно | почему |
|---|---|---|
| **[Ш1],[Ш2],[Ш6]** правки `сверщик.c` | **серийно** между собой | один файл, один закрытый список ходов; конфликтуют построчно |
| **[Ш3]** построители `zapis.flang` | **серийно** внутри файла | один файл; «черновики порознь ложатся, друг на друга — нет», конфликт в `zapis.flang` уже наблюдался (`КРИТЕРИЙ.md:80`) |
| **[Ш4]** батч-перепечатка | **серийно, одна** | §2 |
| разведка по родам | **параллельно (уже сделана)** | шесть независимых документов |
| **золотые сертификаты** (рукотворные `.flang`+`.запись` в оснастке, `untracked`) | **параллельно** | не трогают дерево; каждая разведка уже построила свои (`-migration.md §9`, `-po-primeru.md §4`, `-po-sluchayam.md §3.1`, `-razbor-celi.md §2`, `-lemma-po-svoystvu.md §6`) — собрать их в единый регресс-набор можно параллельно правкам чекера |
| наборы подделок на каждый ход (§9 спеки) | **параллельно** правкам, но применяются ПОСЛЕ соответствующего хода | подделка меряет ход, которого ещё нет — держать наготове |
| эта карта и доки | **параллельно** | документ, кода не трогает |

Внутри [Ш1]/[Ш3] сами СЕМЬИ идут в порядке «от крупного-дешёвого к
мелкому-дорогому», как назвали разведки: рефлексив/соседи (готовые ходы) →
вычислить (обкатка «новый ход + подделка») → длина Д → элемент Э → индукция/свёртка
→ круг/разбор (`-migration.md §4`); D-вариант → C-длина → A-квантор → B-тело
(`-po-primeru.md §6`).

### 1.4. Противоречия между входными документами — названы

Разведка местами спорит сама с собой; для стройки это надо разрешить, а не
замолчать.

1. **Кто печатает след: ядро или слой печати.** `proof-object.md §8` говорит
   «протянуть запись ходов через диспетчер из 12 правил» — то есть ЯДРО печатает
   ходы. Все ПОЗДНИЕ разведки (`-migration.md §5` и далее) говорят обратное: печать
   реконструируется в `zapis.flang` из СТРУКТУРНЫХ данных записи (тип, конструктор,
   тело, строка), ядро НЕ трогать, а поле «ходы» 4101 в ядре ИНЕРТНО — ядро след и
   так выбрасывает, восстановить его на слое печати можно без него.
   **Разрешение карты:** держимся позднего, проверенного прогоном подхода — печать
   в `zapis.flang`. Это дешевле (не трогает доверенное ядро, лучше для Г3) и уже
   доказано на индукции. ЕДИНСТВЕННОЕ исключение — теоремы «для всех элементов»
   (по примеру семьи A/D) и fold-носитель, где сертификата ядра нет ВОВСЕ: там
   реконструировать нечего, и ядро обязано напечатать (`-po-primeru.md §3`,
   `-migration.md §2 С7`). Это остаток исходной формулировки `proof-object.md §8`,
   суженный до мест, где иначе никак.

2. **Сколько прибавляет доверенная база.** `proof-object.md §7` называет **+50**
   строк (три хода) и итог **−1800**. Но +50 снято ДО открытия S2 и до ходов
   `переписать формой`/`проекция`/`разбор`. Суммой поздних разведок прибавка выше:
   S2 ~110–150 (`-lemma-po-svoystvu.md §5.1`), форма Д/Э ~40, проекция/разбор ~30,
   вычислить/счёт/противоречие ~50, придирки — десятки. **Разрешение:** заголовок
   −1800 УСТОЯТ (снимаемые ~2080 доминируют), но аддитивную часть карта считает
   честно ~+200…+350, а не +50 (§3.3). Число +50 в `proof-object.md §7` —
   заниженное, помечаю прямо.

3. **«146 переводятся автоматически».** `proof-object.md §8` («146 автоматически,
   но не даром») верно оговаривает «не даром», но слово «автоматически» всё же
   преуменьшает хвост: «по свойству» (64) — это НЕ печать, а целый новый приём S2;
   4 места «разбором по случаям» упираются в ПРАВКИ КОДА (гейт+скобки), а не в
   печать; по примеру семья B — рост `ocenit_term` в сторону полного вычислителя
   (`-po-primeru.md §5`). **Разрешение:** «печать 146» механична лишь для родов,
   чьи ходы уже стоят (С1/С2, Р1, нульарные базы по примеру); содержательный хвост
   — это код, а не печать. Карта разносит их по [Ш1]/[Ш2]/[Ш3] явно.

4. **Число мест не сходится между разведками — это перемеры, не спор.**
   «тождество» 42/38 (`-migration.md`), «разбор цели по условию» 21, не ~5
   (`-razbor-celi.md §0`), «по примеру» 93/14. Каждый счёт снят на СВОЕЙ ветке и
   назвал расхождение. При стройке перемерять на рабочем стволе (`-migration.md`
   прямо предупреждает: файл вырос, номера уехали).

## 2. Батч-перепечатка

### 2.1. Что копится до одной перепечатки

Полная перепечатка семени — «часы и десятки гигабайт памяти» (`DESCRIPTION.md §3`),
не быстрая операция. Поэтому в неё копят ВСЁ, что меняет вывод семени:

- все построители следа в `zapis.flang` из [Ш3] (шесть родов сразу);
- печать ходов из ядра для теорем «для всех элементов»/fold (единственная правка
  ядра, §1.4 п.1), если она войдёт в эту волну.

Правки `сверщик.c` ([Ш1],[Ш2],[Ш6]) в перепечатку НЕ входят — чекер собирается
отдельным `make`, семени не касается. Значит перепечатка нужна ровно из-за
`zapis.flang` (и, возможно, одной правки печати ядра) — их и батчим.

### 2.2. Что перепечатка проверяет

Перепечатка проверяет **неподвижную точку** раскрутки (`DESCRIPTION.md §3`,
`scripts/raskrutka.sh --check`):

1. семя → `make` → двоичный `flang₁`;
2. `flang₁` печатает `flang/self/*.flang` обратно в C → собирается `flang₂`;
3. C от `flang₁` и `flang₂` совпадает ПОБАЙТОВО (`cmp`, exit 0 на всех семи
   печатаемых файлах).

Красное на любом расхождении.

### 2.3. Перегенерация записей корпуса — отдельно, но той же волной

Записи `.запись` — НЕ семя; они генерируются `check --proof --записать` уже
перепечатанным двоичным. Их надо переснять после [Ш4], иначе чекер сверяет старую
запись (без новых ходов) — и доля не сдвинется. Ровно это уже стоило Г4: записи
отстали от печати на ТРИ перепечатки семени, и одна перегенерация дала 28 → 33 из
86 (`КРИТЕРИЙ.md:1117-1140`, `40d2c83e`). Обе нынешние записи «по свойству»
(`honest-modus-ponens-by-guard`, `body-forms`) — СТАРОЙ формы, дают КОД 3
(`-lemma-po-svoystvu.md §7`); их переснять обязательно.

### 2.4. Необходимое/достаточное условие Г6

Г6 = семя воспроизводимо бит в бит (`DESCRIPTION.md §7`; не взят).

- **Необходимое:** перепечатка идёт на раннере с памятью — нужно 64 ГБ, есть 499
  ГБ и 256 ядер, «258,9 ГиБ» была память ДО починки; препятствие оказалось ложным,
  нужен не купленный раннер, а НАСТРОЕННЫЙ (`КРИТЕРИЙ.md:91`).
- **Достаточное (для Г6):** произведённое семя проходит фикспойнт §2.2 (`cmp`
  exit 0 на всех семи файлах, `raskrutka.sh --check` зелён). Это и есть Г6 — его
  меряет фикспойнт, а не проза.

Иными словами: **батч-перепечатка — это точка, где Г6 меряется** (фикспойнт нового
семени) и где записи догоняют печать (питание Г4). Её нельзя раздробить: каждая
дробь платит «часы + десятки ГБ» и заново рискует фикспойнтом. Отсюда — одна.

## 3. Условие снятия калькулятора `perepiskoy` (точно)

### 3.1. Когда весь корпус проигрывается — что должно быть закрыто

Калькулятор кроет НЕ одно правило, а ВСЁ постусловное доказательство корпуса
(`perepiskoy`/`svesti_term`/`razborom_celi`/`iz_obyavlennogo`). Снять его можно
ТОЛЬКО когда переигрывается весь корпус — все роды, а не часть (`proof-object.md
§8` шаг 4, `-migration.md §5`, единый рефрен всех разведок). Поимённо должно быть
закрыто:

1. **146 мест «по объявлению»** (5 вычислительных родов) печатают след и
   переигрываются (`proof-object.md §8`).
2. **«тождество» — все 7 семей С1–С7** (`-migration.md §4`): С1/С2 готовыми
   ходами; С3/С4 через `переписать формой`; С5 через `вычислить`; С6 через
   `проекция`/`разбор`; С7 через индукцию/fold.
3. **«по примеру» — 14 «не взявшихся»** через рост покрытия `ocenit_term` +
   печать ходов из ядра для теорем «для всех» (`-po-primeru.md §3,§5`). Блока Г7
   тут 0 — ни одно место не остаётся за калькулятором В ПРИНЦИПЕ.
4. **«разбором по случаям» — все 4 места** через починку гейта принципа + скобок
   (`-po-sluchayam.md §4`).
5. **«разбор цели по условию» — Р1–Р5** (`-razbor-celi.md §3`): Р1 готово; Р2/Р3
   через 2 придирки + закрытие связок; Р4 через код-путь гейта принципа; Р5 через
   расщепление конъюнкции допущения.
6. **«по предположению»/индукция S1** — уже переигрывается (`stack.запись`); хвост
   Р5 — тем же расщеплением связки.
7. **«по свойству» — все 64 места** через приём **S2** (`-lemma-po-svoystvu.md`).
8. **`ocenit_term` (205 строк) ОСТАЁТСЯ** доверенным примитивом P8 — над IEEE-754
   `2+2=4` не разложить в под-ходы (`proof-object.md §4`).

### 3.2. Необходимое и достаточное

- Закрытие ЛЮБОГО одного рода — **необходимо, но НЕ достаточно**: пока хоть одна
  запись корпуса идёт калькулятором, снять его = обрушить долю Г4 (`-migration.md
  §5`: «эти 42 — необходимый ломоть, не достаточный»).
- Закрытие ВСЕХ родов вместе (пп. 1–7) при остающемся `ocenit_term` —
  **необходимо И достаточно**: тогда доля-проигрыванием ≥ порога, и калькулятор
  ненужен.

### 3.3. Траектория доверенной базы Г3 (числом)

Г3 меряет размер доверия по единой линейке (`kernel-lines-to-trust.flang`,
`одна-линейка.py`); «ядро решений» на dev — 4638 строк (`proof-object.md §7`,
`cfbe56d5`), потолок держится с запасом 1,86×.

| стадия | доверенная база чекера |
|---|---|
| С1/С2, рефлексив/соседи напечатаны | +0 (ходы стоят); калькулятор стоит — доля не падает |
| ходы влиты (вычислить/счёт/противоречие ~50, форма Д/Э ~40, проекция/разбор ~30, S2 ~110–150, придирки ~десятки) | **РАСТЁТ на ~+200…+350** (не +50, как в `proof-object.md §7`, §1.4 п.2); калькулятор ещё СТОИТ рядом — снять нельзя |
| весь корпус переигран → [Ш6] | калькулятор **−2080** снимается |
| **итог** | **чистый ≈ −1700…−1800** (снято ~2080, прибавлено ~200–350; заголовок `proof-object.md §7`/`-migration.md §0` «−1800» устоит) |

**Промежуточный рост — в смету, не под прогон.** В ХОДЕ миграции доверенная база
временно РАСТЁТ (переигрыватель прибавляется, пока калькулятор не снят), и запас
Г3 (1,86×) на это время СЪЕДАЕТСЯ — возвращается с прибылью в конце. Ровно так уже
случался незамеченный регресс Г3 (`КРИТЕРИЙ.md:3737`) — держать число по той же
линейке на каждом шаге, а не обнаружить на середине.

## 4. Что закрывает каждый гейт

Три числа ярлыка `доказуемость` (§0.2) — это ровно три гейта, которые карта берёт.

**Г2 — независимый чекер переигрывает объект и отвергает подделку** (СНЯТ:
«объект выдаётся, но пока не тот, что переигрывается независимо», `DESCRIPTION.md
§7`; держат остатки r6341/4820, `КРИТЕРИЙ.md:87`). Закрывают **[Ш1]+[Ш2]+[Ш3]+[Ш4]**
вместе: печать следа (Ш3) + ходы в чекере (Ш1/Ш2) + перегенерация записей (Ш4)
дают объект, который чекер ПЕРЕИГРЫВАЕТ, а набор проб (третье число ярлыка)
подтверждает: подделка отвергнута, честная — нет. **Леммовую подделку 4114**
(цель `результат равен 3` при теле, дающем `0`, свойство настоящее и привязано
верно → сегодня КОД 0, `-lemma-po-svoystvu.md §4.2, §6 C2`) ловит именно шаг **[Ш2]
S2**, перепроверкой (г) «закрыть по свойству / модус-поненс»: факт `X не меньше 0`
цель `X равен 3` не закрывает → КОД 1. Мерило Г2 — «два числа»: подделок отвергнуто
> 0 И честных отвергнуто = 0 (`-migration.md §9`).

**Г4 — доля ЗАПИСЕЙ корпуса, проверенных переигрывателем, ≥ 95 %** (не взят: 33/86
= 38,37 %, `КРИТЕРИЙ.md:1112-1128`). Закрывают **[Ш3]+[Ш4]** (печать + перегенерация
поднимают долю: одна перегенерация уже дала 28 → 33) плюс **[Ш5]** (прибор
доли-проигрыванием — иначе долю нечем измерить, §0.2 п.2). Порог 95 % = 82 из 86,
недостаёт 49. Дорога вверх — НЕ дописывание теорем: честная теорема долю ОПУСКАЕТ
(код 0 → код 3, `КРИТЕРИЙ.md:89,1128`), а у крупнейшей породы теоремы быть не
может. Дорога — печать следа для маршрута «по объявлению».

**Г7 — нет доказанного без проверки** (признан не мерящим по старым словам,
`DESCRIPTION.md §7`; но `by:"declaration"` = «цель сведена с телом» = доказательство
вычислением, `КРИТЕРИЙ.md:2862`). Закрывает **[Ш6]** — снятие `perepiskoy`: пока
калькулятор в чекере, доля держится ВЫЧИСЛЕНИЕМ, а не проигрыванием записанного —
это и есть открытая дыра Г7 (`scripts/доказуемость.sh`, проверка 1). Снят калькулятор
(`git grep -c perepiskoy` = 0) → на слово ядра не остаётся ничего вычислительного;
`ocenit_term` остаётся честно названным примитивом P8, не пере-выводом.

**Связка с ярлыком `доказуемость`:** [Ш6] закрывает число 1 (perepiskoy снят, Г7),
[Ш5]+печать закрывают число 2 (доля ≥ 95 %, Г4), набор проб закрывает число 3 (Г2).
Все три сойдутся — ярлык печатает ДОКАЗУЕМ, код возврата 0. Это и есть машинный
критерий «готово», не проза.

**Прочие гейты (контекст):** Г1 (объект выдаётся, код 0) — ВЗЯТ; Г3 (размер доверия
назван) — ВЗЯТ, карта держит его число на траектории §3.3; Г5 (разбор с границы
доверия) и Г6 (семя бит в бит) карта прямо не берёт, но [Ш4] — точка замера Г6 (§2.4).

## 6. Риски и края

**Инертный сторож — самый вероятный провал** (`-migration.md §6`, подтверждён
прогоном в `-po-sluchayam.md §3.2` и `-razbor-celi.md §5.1`). Печать следа есть, а
чекер её НЕ зовёт → печать становится украшением, вывод по-прежнему на слово ядра.
Мерило готовности КАЖДОГО мигрированного места: посадить ЛОЖНЫЙ ход и убедиться,
что стало КОД 1. Пока ложный ход не краснит — сторож инертен, разбираться ДО печати
следующей семьи. Ровно этот риск — причина, почему придирка А (гейт принципа) стоит
в [Ш1] первой: без неё печать под посылками с принципом инертна по конструкции.

**Снимок-со-снимком** (`-migration.md §6`). Запись рождена тем же прогоном ядра,
что переигрывается. Если новый ход БЕРЁТ правую сторону из записи (`⟨V⟩`, инстанцию
постусловия, поле), а не пересобирает сам — чекер сверяет запись с записью и
зеленеет всегда. Лечится двойной привязкой: `вычислить` считает `T` через
`ocenit_term`; `переписать формой` сам собирает правую по Дk/Эk из цели; S2 строит
инстанцию двумя подстановками, а не берёт готовую (`-lemma-po-svoystvu.md §1.1`).
Проба: подделать записанную правую → обязан КОД 1 с называнием места.

**Предел `proofterm.flang:1188` — край, названный заранее** (`-lemma-po-svoystvu.md
§0,§7`). Шаг, которому нужны И «по предположению» (допущение индукции), И «по
свойству» (постусловие вызванной) В ОДНОМ шаге, ядро СЕГОДНЯ НЕ ПИШЕТ. Среди
нынешних 64 мест «по свойству» таких НЕТ. Но если такое место в корпусе появится —
оно потребует правки ИСХОДНИКА `.flang` (переписать под явную теорему), а не только
чекера/печати. Назвать заранее, а не обнаружить прогоном на середине.

**Места, что могут остаться за калькулятором:**
- **С6 круг/разбор** (2 места, `-migration.md §4`): проекция поля и редукция
  разбора — самые узкие и дорогие по месту ходы; кандидат остаться за
  калькулятором, если их отдача (2 места) окажется меньше цены. НО пока хоть одно
  место за калькулятором — [Ш6] невозможен (§3.2); значит либо закрыть и С6, либо
  принять, что калькулятор не снять и язык не «доказуем» по ярлыку.
- **По примеру семья B** (6 мест, тело считает не литерал): закрытие требует роста
  `ocenit_term` в сторону полного вычислителя — доверенная база тут РАСТЁТ, а не
  падает; кандидат частично остаться на приёме Ч71 «по существу через
  `ocenit_term`», если полный вычислитель в доверии дороже отдачи (`-po-primeru.md
  §6`). Тот же тупик [Ш6], что и С6.

**Запас Г3 съедается на время миграции** (§3.3) — не край, но обязательная строка
сметы: держать число доверия по линейке на каждом шаге.

**Числа входов — ветко-относительны.** Все счёты мест и номера строк сняты на
разных ветках (`r/4004`…`r/4118`); при стройке перемерять на рабочем стволе
(`-migration.md:18-20`).
