# Объект доказательства (сертификат): спецификация

**Состояние:** спецификация под стройку. Все числа сняты прогоном и чтением на
ветке `r/4004` (основание `gh/dev`, `bootstrap/flang` собран из неё же,
6 сентября 2026). Команды и файлы названы у каждого числа.

**Задача 4004.** Сделать flang доказуемым через ОБЪЕКТ доказательства: ядро
кладёт в запись не имя правила, а цепочку переписок; чекер её ПЕРЕИГРЫВАЕТ, а не
считает заново. Порода направления: *сторожат ровно то, что умеют посчитать* —
пока чекер пере-выводит цель сам, он обязан вырасти до размера ядра. Сертификат
затем и нужен, чтобы чекер ПРОВЕРЯЛ готовый вывод, а не воспроизводил его.

Это спецификация, не код. Кода ядра и чекера она не трогает.

## 1. Что уже есть в дереве (стройка НЕ с нуля)

Это главное, что меняет смету. Три вещи из четырёх уже написаны и работают:

1. **Тип «Сведение» ядра** (`proof-kernel.flang:132`) несёт `принято`, `правило`,
   `причина`, `развёрнуто`. Ядро ВЫЧИСЛЯЕТ цепочку переписок (движок «Свести …»,
   `proof-kernel.flang:1329…8320`, 6992 строки, диспетчер `Свести правилами при
   фактах` — перебор 12 правил по виду цели, БЕЗ поиска), но в запись кладёт лишь
   `правило` (итоговое имя) и `развёрнуто` (какие тела развернул). **Самой цепочки
   в объекте нет. Вот дыра.**

2. **Печать ходов в записи** (`zapis.flang:975` «Строки ходов записи»,
   `zapis.flang:1236` и далее) уже умеет выписывать `ход цель`, `ход N развернуть
   ⟨…⟩ строка N ⟨тело⟩`, `ход N закон «…»`, `ход N замена по дано N`, `ход N
   закрыть тождеством`, `ход дано N предположение по «…»`, `ход конец`. Поле
   `«свод».«ходы»` в записи существует. Печатью занят путь ИНДУКЦИИ, не «по
   объявлению».

3. **Переигрыватель ходов в чекере** (`сверщик.c:992` `proigrat_blok` и ходы
   760–1014) держит список незакрытых целей, к первой применяет названный ход,
   требует, чтобы к `ход конец` целей не осталось. **Семь первичных ходов, список
   закрыт** (`сверщик.c:989`). Он НЕЗАВИСИМ от калькуляторного пути: пользуется
   только `vstavit_vmesto` (подстановка), `est_term` (вхождение), `term`/`uzhat`
   (нормализация скобок), `razrez_po` (разрез по операции), `primenit_zakon`. Ни
   `svesti_term`, ни `ocenit_term`, ни `razborom_celi` он не зовёт.

Чего НЕТ (задача 4004): (а) ядро не печатает ходы для маршрута «по объявлению»;
(б) нет хода замкнутого вычисления (`2+2=4` считает только калькулятор); (в) пара
правил (противоречие, счёт частей) ещё не разложены в ходы.

**Проба, снятая руками (не чтением).** `сверщик flang/proof/examples/stack.flang
пробы/записи/корпус/stack.запись`:

```
НЕ ПРОВЕРЕНО … сведений проиграно заново 4 (ходов проверено 9) … КОД=3
```

Переигрыватель прошёл 9 ходов по 4 сведениям (обе теоремы стека: «высота
неотрицательна» и «копия равна оригиналу», база и шаг). Код 3, а не 0, ровно
потому, что один шаг базы «по примеру» упирается в калькулятор (`НЕ ВЗЯЛСЯ:
значение примера (вариант «Пусто») сверщику незнакомо`) и один остаётся «на слове
ядра». Это и есть места, которые сертификат закрывает.

## 2. Примитивные правила вывода — доверенная база чекера

Ключевая мысль: **17 правил закрытого списка ядра — НЕ примитивы.** Каждое —
макрос: «нормализуй (разверни определения, перепиши длины) и сличи с образцом
замкнутой формы». Примитивы лежат ниже — это ХОДЫ, из которых цепочка сборана.
Доверять надо ходам, а не 17 макросам.

### 2.1. Как 17 правил ядра раскладываются в ходы

Список правил — `сверщик.c:1053` (`PRAVILA[]`), производители — в
`proof-kernel.flang` (`Принято правилом» от («…»)`). 16 имён + пустое:

| # | имя правила в записи | ставит (ядро) | цепочка примитивов |
|---|---|---|---|
| 1 | неотрицательность по построению | Правило неотрицательности | `развернуть`* → `закон «сумма/литерал неотрицателен»` → `закрыть` |
| 2 | тождество после переписки допущением | Правило тождества | `развернуть`* → `замена по дано` → `закрыть тождеством` |
| 3 | ограниченность точным потолком по построению | Правило ограниченности | `развернуть`* → `закон` → `закрыть` |
| 4 | порядок по построению | Правило порядка | `развернуть`* → `закон` → `закрыть` |
| 5 | строгий порядок по построению | Правило строгого порядка | как 4, знак строгий |
| 6 | вхождение по построению | Правило вхождения | `развернуть`* → `закрыть` |
| 7 | начало по построению | Правило начала | `развернуть`* → `закрыть` (сличение приставки) |
| 8 | цель есть допущение | Правило допущения | `закрыть дано N` |
| 9 | несовместимые допущения | Правило противоречия | **`закрыть противоречием`** (нового вида) |
| 10 | порядок соседних по построению | Правило соседних | `соседи` → `закон` → `закрыть` |
| 11 | равенство, решённое счётом замкнутых частей | Правило счёта частей | **`счёт ⟨T⟩ = N`** (нового вида) → `закрыть` |
| 12 | вычисление замкнутой цели | Вычислением | **`вычислить ⟨T⟩ = ⟨V⟩`** (нового вида) → `закрыть тождеством/истиной` |
| 13 | разбор случаев по дизъюнкции в допущении | Разбором случаев | `деление` → две подцели |
| 14 | цель-выбор с истинной ветвью | Истинной ветвью | `выбор` → `закрыть` |
| 15 | разбор случаев по внутреннему условию цели | Внутренним условием | `деление` → подцели |
| 16 | разбор цели по условию | Ветвлением | `деление` → подцели |
| — | «» (пустое) | — | сведений ноль, цель совпала как есть |

`развернуть`* — ноль или больше развёрток определений, пока цель не станет
замкнутой формой. Из таблицы видно ровно, чего переписывателю НЕ ХВАТАЕТ: три
хода (`вычислить`, `счёт`, `закрыть противоречием`). Остальные 13 правил кроются
семью ходами, которые в чекере уже стоят.

### 2.2. Минимальный доверенный список — примитивы

Каждый примитив: что берёт, что даёт, почему ему можно верить (что чекер
проверяет САМ, а не берёт со слова ядра).

| примитив (ход) | вход | выход | доверенное потому что |
|---|---|---|---|
| **P1 развернуть** (β / разворот определения) | терм вызова `⟨«F» от аргументы⟩`, номер строки тела в исходнике, тело термом | первая цель, где вызов заменён телом с подставленными доводами | чекер САМ читает ту строку исходника, сверяет тело знак в знак (двойная привязка), проверяет, что строка в теле функции F, начата «то», над ней стоит нужный `случай` |
| **P2 замена по дано N** (равное на равное) | номер допущения-равенства | цель, где ЛЕВАЯ сторона равенства заменена правой (или обратно) | чекер проверяет, что допущение N — равенство и что его сторона в цели есть |
| **P3 выбор** (чтение ветви) | терм `⟨если да то А иначе Б⟩` | цель, где выбор заменён взятой ветвью | условие уже литерал `да`/`нет`; ход ЧИТАЕТ ветвь, ничего не вычисляя |
| **P4 соседи** (коммутативность одного узла) | терм `⟨А плюс Б⟩` или `⟨А умножить на Б⟩` | цель, где операнды ОДНОГО узла переставлены | переставляются ровно два соседа одного узла; перестановка через скобки была бы ассоциативностью — она в IEEE-754 ложна, и её ход НЕ делает |
| **P5 деление** (разбор по булевой цели) | терм-условие `⟨U⟩`, стоящий в цели как `если U то …` | две подцели: с `U`=да и `U`=нет | берётся только выражение, СТОЯЩЕЕ в цели условием — у произвольного подтерма значений больше двух |
| **P6 закон** | имя закона | подцели закона (обычно ноль) | закрытый список из **2 законов**: «сумма неотрицательных», «литерал неотрицателен» — это утверждения об IEEE-754, приняты на веру (аксиомы A3) |
| **P7 закрыть** | вид: `дано N` / `тождеством` / `истиной` / `требованием … строка N` / **`противоречием`** | цель снята | `дано` — совпала с допущением; `тождеством` — стороны равенства совпали после `uzhat`; `истиной` — цель есть `да`; `требованием` — строка N исходника ПРАВДА несёт этот `требует` и факт=цель; `противоречием` — среди допущений есть несовместимая пара |
| **P8 вычислить** (НОВОЕ; замкнутый счёт) | замкнутый терм `⟨T⟩`, посчитанное значение `⟨V⟩` | цель, где T заменён V | чекер считает T замкнутым счётом (`ocenit_term`, ~205 строк) и сверяет с V; T обязан быть без свободных имён |
| **P9 счёт** (НОВОЕ; равенство счётом частей) | терм `⟨T⟩`, число замкнутых частей N | цель с T=N | зеркало P8 для формы «равенство длин/частей»; тот же замкнутый счёт |
| **S1 индукция** (по структуре) | тип цели; вариант на посылку | посылки: по одной на каждый вариант типа | чекер сам строит начальную цель посылки из теоремы и конструктора варианта (`nachalnaya_cel`) и сам считает предположение индукции `ход дано` — то же утверждение о РЕКУРСИВНОМ поле (проверяет, что поле того же типа: не круг) |
| **S2 постусловие вызванной** | вызов функции G в теле | доказанное постусловие G как факт | `закрыть требованием` уже держит предусловие; постусловие вызванной — ограниченный случай (см. §8, долг по свёртке) |

**Итог доверенной базы: 9 ходов + 2 структурных приёма + 2 закона.** Всё —
проверки чтения и подстановки, без единого поиска. Именно это человек читает
глазами и чему верит вместо ядра.

## 3. Формат объекта — как цепочка ложится в запись

### 3.1. Грамматика (та же, что уже печатает `zapis.flang`, плюс три хода)

Сертификат посылки/утверждения — блок строк записи, каждая начата четырьмя
пробелами (уровень записи их уже соблюдает):

```
    ход цель
    ход дано K предположение по «поле»        (0+ строк; только под индукцией)
    ход N <примитив> <доводы примитива>        (N считается с 1, подряд)
    …
    ход конец
```

- `ход цель` — чекер СТРОИТ начальную цель сам (из теоремы и варианта посылки, либо
  из постусловия для маршрута «по объявлению»). В записи цель не лежит — иначе был
  бы второй источник одного и того же.
- `ход дано K …` — предположение индукции; чекер вычисляет его сам, из записи берёт
  лишь ИМЯ рекурсивного поля.
- `ход N <примитив>` — примитивы §2.2. Развёртка несёт двойную привязку:
  `ход N развернуть ⟨терм-вызова⟩ строка M ⟨тело-термом⟩`.
- `ход конец` — незакрытых целей не осталось. Номер хода СЧИТАЕТСЯ: пропуск или
  перестановка ловятся (`сверщик.c:979`).

### 3.2. Как ложится в запись целиком

Строка вердикта посылки уже несёт `правило «имя»` (`сверщик.c` образцы, задача
9997). Сертификат — блок ходов ПОД ней. Совместимость: когда блок ходов стоит и
доведён до `ход конец`, чекер посылку ПЕРЕИГРАЛ (не «на слове»); когда стоит
только `правило «имя»` без ходов — старое поведение, «на слово ядра» (A1). Так
корпус мигрирует по одной записи, не ломаясь (§8).

### 3.3. Печать в девять целей

Сертификат — это СТРОКИ записи (списки строк с термами в ⟨уголках⟩ и именами в
ёлочках). Запись уже печатается во все девять целей генерации (c, cpp, csharp,
elixir, go, java, js, python, rust) как данные; ходы — те же данные и едут тем же
путём. Новое требование к печати: НОЛЬ. Термы в ⟨уголках⟩ пишутся синтаксисом
языка (как их читает разбор), скобки несёт дерево — это уже сделано для развёртки
(`zapis.flang:35`).

### 3.4. Три требования к формату — выполнены конструкцией

- **(а) ядро печатает из того, что уже вычисляет.** Движок «Свести …» проходит
  цепочку; печать ходов = запомнить каждый шаг перехода, а не считать заново.
  Инфраструктура памяти уже есть на пути индукции (§1).
- **(б) чекер переигрывает, не веря ядру.** `proigrat_blok` держит список целей и
  применяет ходы; каждый примитив §2.2 проверяется чтением исходника/допущений.
- **(в) печать в девять целей.** §3.3.

## 4. Сертификат `2+2=4` (этап 1) — дословно

Этап 1 — замкнутые равенства/вычисления. Пусть в модуле стоит

```flang
теорема «два и два четыре»
  утверждаем (2 плюс 2) равно 4
  следовательно доказано
```

Ядро закрывает это правилом «вычисление замкнутой цели». Сертификат (с новым
ходом `вычислить`, §2.2 P8):

```
  теорема «два и два четыре» строка N
  следовательно доказано да
    ход цель
    ход 1 вычислить ⟨2 плюс 2⟩ = ⟨4⟩
    ход 2 закрыть тождеством
    ход конец
```

Переигрывание: начальная цель `(2 плюс 2) равно 4`. Ход 1 — чекер считает
замкнутый терм `2 плюс 2` (`ocenit_term`) = `4`, сверяет с записанным `⟨4⟩`,
подставляет: цель `4 равно 4`. Ход 2 — стороны равенства совпали после `uzhat`,
цель снята. Целей не осталось — `ход конец` законен.

Что теперь проверено НЕЗАВИСИМО: чекер сам посчитал `2+2` и сам сверил стороны.
Раньше он либо брал «вычисление замкнутой цели» на слово (A1), либо пере-выводил
всю цель калькулятором. Теперь он проверяет ГОТОВЫЙ шаг.

> Замкнутый счёт `ocenit_term` (~205 строк) остаётся в доверенной базе как
> примитив — это честно: `2+2=4` над IEEE-754 нельзя разложить в под-ходы, не
> впав в абсурд (никакой Пеано под машинными числами нет). ACL2 держит ground-eval
> ровно так же. Ход `вычислить` лишь делает применение счёта ЯВНЫМ и ограничивает
> его замкнутыми термами.

## 5. Сертификат индукции (этап 2) — дословно, из живого прогона

Этап 2 — теоремы «для всех …». Формат ОБЯЗАН вмещать индукцию, разбор случаев,
предположение индукции, применение постусловия — и он их вмещает СЕГОДНЯ. Ниже —
не выдуманный, а НАСТОЯЩИЙ сертификат из `пробы/записи/корпус/stack.запись`,
который переигрыватель проходит прогоном (§1). Тип — список-стек (`Пусто` |
`Звено` содержит `голова`, `хвост`), теорема — высота стека неотрицательна.

```
  теорема «высота неотрицательна» строка 65
  случай строка 69 шагов 1
  случай строка 71 шагов 1
  следовательно доказано да
  посылка «Пусто» вид base вариант «Пусто» вердикт доказано закрыта term шагов 1 правило «»
    ход цель
    ход 1 развернуть ⟨«Высота» от (вариант «Пусто»)⟩ строка 56 ⟨0⟩
    ход 2 закон «литерал неотрицателен»
    ход конец
  посылка «Звено» вид step вариант «Звено» вердикт доказано закрыта term шагов 1 правило «неотрицательность по построению»
    ход цель
    ход дано 1 предположение по «х»
    ход 1 развернуть ⟨«Высота» от (вариант «Звено» с голова равным г и хвост равным х)⟩ строка 58 ⟨((«Высота» от х) плюс 1)⟩
    ход 2 закон «сумма неотрицательных»
    ход 3 закрыть дано 1
    ход 4 закон «литерал неотрицателен»
    ход конец
```

Переигрывание шага (посылка «Звено»):
- `ход цель` — чекер строит цель сам: `(«Высота» от (Звено с …)) не меньше 0`.
- `ход дано 1 предположение по «х»` — чекер сам кладёт в допущения `(«Высота» от х)
  не меньше 0` (то же утверждение о рекурсивном поле «х»; проверяет, что «х» — поле
  того же типа, не круг).
- `ход 1 развернуть` — разворачивает тело «Высоты» из строки 58, двойная привязка.
  Цель: `(((«Высота» от х) плюс 1)) не меньше 0`.
- `ход 2 закон «сумма неотрицательных»` — цель `A плюс B ≥ 0` делится на `A ≥ 0` и
  `B ≥ 0`.
- `ход 3 закрыть дано 1` — `(«Высота» от х) ≥ 0` закрыто предположением индукции.
- `ход 4 закон «литерал неотрицателен»` — `1 ≥ 0` закрыто.
- `ход конец` — целей нет.

Второй теоремой той же записи (`копия равна оригиналу`) переигрыватель проходит и
`ход N замена по дано 1` (замена равного равным по предположению) — то есть весь
приём этапа 2 стоит и работает. Аналог «длина приписанного = длина + 1» — ровно
той же формы: индукция по списку, база разворачивает определение и закрывается,
шаг разворачивает, применяет предположение и закон.

**Вывод по вместимости: этап 2 в формат влезает — он в нём УЖЕ живёт.** Novoe в
этапе 2 не формат, а покрытие: перевести на ходы те шаги, что сейчас идут «по
примеру»/«на слове» (в прогоне stack — 1 место `НЕ ВЗЯЛСЯ` + 1 «на слове»).

## 6. Что должен уметь переписыватель термов в чекере — и его цена

### 6.1. Проверка оценки «6952 строки ядра + редуктор»

**Число подтверждено, вывод из него — опровергнут.**

- Движок сведения/нормализации ядра (`proof-kernel.flang`, «Нормализовать» 1329 …
  «Свести счётом» 8320) — **6992 строки**. Оценка работника ~6952 верна (разница —
  где резать границу).
- Но это цена ПЕРЕ-ВЫВОДА: 6992 строки ищут, КАКОЕ правило применить, разворачивают
  до нормальной формы, перебирают 12 правил. Чекеру-переигрывателю поиск не нужен:
  цепочку уже нашло ядро, чекер её ПРИМЕНЯЕТ.
- Переигрыватель в чекере УЖЕ есть и стоит **~296 строк** (законы `сверщик.c`
  537–577 = 41; ходы + `proigrat_blok` 760–1014 = 255), независимо от калькулятора.

Значит переписыватель, которого «нет нарочно», — это НЕ 6992 строки. Это ~296 уже
написанных плюс небольшое расширение.

### 6.2. Чего переписывателю недостаёт — точно

| нужно | что это | оценка строк |
|---|---|---|
| ход `вычислить ⟨T⟩=⟨V⟩` | обёртка над готовым `ocenit_term`: проверить замкнутость T, посчитать, сверить с V | ~20 |
| ход `счёт ⟨T⟩=N` | зеркало для равенства счётом частей | ~20 |
| `закрыть противоречием` | ещё одна ветвь в `hod_zakrytiya` | ~10 |
| замкнутый счёт `ocenit_term` | ОСТАЁТСЯ в доверии как примитив (§4) | 205 (уже есть) |

Новых строк доверия: **~50** сверх уже стоящих 296+205. **Итог доверенного
переписывателя ≈ 550 строк**, а не 6992.

### 6.3. Что при этом можно СНЯТЬ с доверия

Калькуляторный путь чекера (`сверщик.c` 1506–3794, **2289 строк**:
`svesti_term`, `znach_moya`, `razborom_celi`, `polovina_zakryta`, `perepiskoy`,
`iz_obyavlennogo`, `nesovmestima_para`, `mera_neotricatelna`,
`nachalo_po_postroeniyu`, `delenie`, `ogovorka_o_konechnosti` …) — это чекер,
пере-выводящий цель за ядро. Ровно сюда задачи 9998/9999 добавляли ПРАВИЛА, чтобы
поднять Г4. Сертификат делает этот путь ненужным: цель переигрывается, а не
пере-выводится. За вычетом остающегося `ocenit_term` (205) снять можно **~2080
строк**.

## 7. Граница доверия (Г3) — числом

Г3 меряет размер доверия по одной линейке для flang и C
(`flang/scripts/одна-линейка.py`, `kernel-lines-to-trust.flang`). Сегодня доверие
переезжает с полосы **[4548…6710 строк ядра + компилятор flang + семя]** на **[N
строк чекера + libc поимённо + компилятор C]**; «ядро решений» на нынешнем dev —
**4638 строк** (сверено обоими приборами, расхождений 0).

Что делает сертификат с числом N чекера:

| часть чекера | строк | после сертификата |
|---|---:|---|
| переигрыватель ходов (P1–P7) | 296 | **остаётся** в доверии |
| замкнутый счёт `ocenit_term` (P8/P9) | 205 | **остаётся** в доверии |
| 3 новых хода | ~50 | **прибавляется** |
| калькуляторный пере-вывод (1506–3794 без `ocenit_term`) | ~2080 | **снимается** |

**Ответ на вопрос задачи «сколько строк прибавляет доверенная база»:**
доверенный ПЕРЕПИСЫВАТЕЛЬ по завершении — ~550 строк; сверх уже стоящего он
прибавляет ~50, а СНИМАЕТ ~2080. Итог по завершении миграции — доверенная база
чекера **уменьшается на ~1800 строк** (было бы ~2626 калькулятор+переигрыватель,
станет ~550). Гейт Г3 от этого не проваливается — он требует, чтобы число было
НАЗВАНО по той же линейке; названо.

**Оговорка про запас 1,86×.** Потолок сегодня держится с запасом (владельцева
цифра). В ХОДЕ миграции доверенная база временно РАСТЁТ: пока не все записи поехали
ходами, калькулятор снять нельзя, и он стоит рядом с растущим переигрывателем.
Запас Г3 съедается на время миграции и возвращается с прибылью в конце. Это надо
держать в смете, а не обнаружить прогоном на середине.

## 8. Путь миграции — 146 автоматически, но не даром

**Наличное состояние.** 86 записей корпуса; 37 несут «по объявлению». Мест
«доказано» без теоремы — 159 в 38 записях: **146 маршрутом `by:"declaration"`**
(печатают `правило «имя»`, ходов нет), 13 индукционных (ходы уже печатают, 18
строк `ход цель` в корпусе).

**Что переводится автоматически: 146.** Движок «Свести …» детерминирован и без
поиска — значит для каждого из 146 мест цепочка ходов ОДНОЗНАЧНА и
восстановима из того, что ядро уже проходит. Ручного вывода не требует ни одно:
это печать, а не доказательство заново.

**Но «просто напечатать» — не даром.** Ядро цепочку ВЫЧИСЛЯЕТ и ВЫБРАСЫВАЕТ
(тип «Сведение» несёт итог, не шаги). Чтобы печатать, надо протянуть запись ходов
через диспетчер из 12 правил — по правилу за раз, как это уже сделано для
индукции. Порядок:

1. **Замкнутый счёт (ход `вычислить`).** Закрывает правило 12. В stdlib это 4
   места, в корпусе — счёт замкнутых равенств. Самый дешёвый рычаг: `ocenit_term`
   уже есть, нужен ход-обёртка и печать из ядра.
2. **Правила, кроющиеся стоящими ходами (1–8, 10, 13–16).** Разворот + закон +
   закрытие / деление. 13 из 16 правил. Печать ходов ставится по образцу
   индукции. Это основной объём 146.
3. **Два недостающих хода** (`счёт` для правила 11, `закрыть противоречием` для
   правила 9) — ~30 строк чекера + печать.
4. **Снять калькулятор.** ТОЛЬКО когда все записи корпуса переигрываются: снять
   2080 строк, добить Г3-выигрыш. До этого — не трогать, иначе Г4 падает.

**Что требует руки (не автомат):** индукционные базы, идущие «по примеру» — в
прогоне stack одно место `НЕ ВЗЯЛСЯ` (значение примера незнакомо калькулятору).
Их надо перевести на `вычислить`/`развернуть`+`закрыть тождеством`. Таких мест по
корпусу — единицы (13 индукционных записей, по 1–2 базы), это не 146, а десятки.

**Оценка по дереву (для масштаба).** По всему дереву — 652 утверждения, 224
доказаны ядром (`docs/спецификации/язык-доказательств.md`). Доля «по объявлению»
среди доказанных — большинство; в stdlib из 62 доказанных 38 идут тождеством, 6
разбором по условию, 5 неотрицательностью, 5 порядком, 4 вычислением, 3
ограниченностью, 1 допущением — ВСЕ кроются ходами §2.1.

## 9. Чем проверять на каждом шаге — подделка обязана быть отвергнута

Формат без пробы бесполезен. На каждое правило и каждый ход — подделка, и чекер
обязан назвать её словами (порода дерева: «подделка на каждое правило»).

**Живая проба, снятая руками (не чтением).** Взял честную `stack.запись`, в базе
теоремы «высота неотрицательна» подменил тело развёртки `⟨0⟩` → `⟨5⟩`:

```
контроль (честная):     КОД 3  НЕ ПРОВЕРЕНО (9 ходов проверено)
подделка (⟨0⟩→⟨5⟩):     КОД 1  НЕ СОШЛОСЬ
  развёртка «Высота»: запись несёт тело ⟨5⟩, а в строке 56 исходника написано «0»
```

Чекер сам перечитал строку 56 исходника, нашёл «0», отверг подменённый ход, назвал
подмену. Двойная привязка работает.

**Набор проб под стройку — по одному классу на примитив:**

| проба | подделка | ожидаемый отказ |
|---|---|---|
| развёртка | тело хода ≠ строке исходника (сделано выше) | «запись несёт тело ⟨…⟩, а в строке N написано …» |
| развёртка | номер строки указывает не на ту функцию | «строка N исходника стоит в функции …» |
| замена по дано | допущение N не равенство | «допущения-равенства под этим номером нет» |
| выбор | условие не литерал `да`/`нет` | «условие не вычислено до литерала» |
| соседи | перестановка через скобки (ассоциативность) | «не сумма и не произведение ровно двух соседей» |
| деление | делят не то выражение, что стоит условием | «не стоит в цели условием» |
| закон | имя закона не из двух | ход неизвестен / закон не подошёл |
| вычислить (нов.) | записанное `⟨V⟩` ≠ счёту T | «T посчитан в …, а запись несёт V» |
| вычислить (нов.) | T со свободным именем | «терм не замкнут — считать нечего» |
| закрыть тождеством | стороны равенства разные | «стороны равенства разные» |
| закрыть дано | цель ≠ допущению | «цель не совпала с допущением» |
| закрыть требованием | строка N не несёт этот `требует` | «в строке N исходника стоит …» |
| индукция | предположение по НЕ рекурсивному полю | «поле не того же типа — это круг» |
| индукция | пропущен ход посередине | «ход K стоит K+1-м: пропущен или переставлен» |
| конец | целей не осталось, а `ход конец` не стоит | «сведение оборвано: ход конец не стоит» |
| конец | `ход конец` стоит, а цель не закрыта | «не доведено: незакрытых целей M» |

Правило проверки самой пробы: правка обязана НАЙТИ свою строку (иначе сверяет
запись саму с собой и зеленеет всегда). Считать два числа: «подделок отвергнуто»
и «честных отвергнуто 0» — одно без другого не значит ничего.

## 10. Что теперь проверяется НЕЗАВИСИМО (порода направления)

Сертификат меняет, ЧТО берётся на слово:

| место | сегодня | по сертификату |
|---|---|---|
| `2+2=4` | имя «вычисление замкнутой цели» на слово (A1) ИЛИ пере-вывод калькулятором | чекер сам считает `2+2` и сверяет стороны (ход `вычислить`) |
| «высота ≥ 0», шаг | ядро свело, чекер верит имени ИЛИ пере-выводит | чекер переигрывает 4 хода, применяет предположение индукции сам |
| 146 мест «по объявлению» | `правило «имя»` на слово ядра — «не несут ничего» (задача 9993) | цепочка ходов, переигранная чекером |
| замкнутый счёт | внутри чекера-калькулятора, неотличим от пере-вывода | явный примитив P8, ограничен замкнутыми термами |

Что ОСТАЁТСЯ на слово (честно назвать): 2 закона IEEE (A3), замкнутый счёт как
примитив (P8), предусловие держит вызывающий (P7 `требованием`). Это доверенная
база — короткая, читаемая, названная числом.
