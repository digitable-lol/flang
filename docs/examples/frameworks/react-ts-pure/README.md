# flang + React + TypeScript: компоненты без логики

Тот же счёт витрины, что в `react-invoice/`, но с одной разницей, ради которой
пример и заведён: **в компонентах React нет ни строки предметной логики**. Данные
о товарах, начальные количества, границы (не меньше нуля, не больше остатка),
суммы, скидка ступенями, запись рублей с разрядами и запятой, признаки
«кнопку можно нажать» — всё это считает ядро на flang и отдаёт готовыми к показу
строками и признаками. React объявляет компоненты и раскладывает то, что ему
отдали, по разметке.

```
core/storefront.flang              данные, действия, редьюсер «Шаг», суммы, скидка, запись рублей
printed/storefront.js              ядро, напечатанное в JS (без зависимостей)
printed/flang_cli.js               прогонщик ядра для проверки из командной строки
scripts/markup-without-logic.flang проверка: в src/*.tsx нет строк логики
src/App.tsx                        корень: useReducer(shag, nachalnayaKorzina()) и таблица
src/Stroka.tsx                     строка витрины: две кнопки и четыре ячейки
src/Itogi.tsx                      итоги: сумма, скидка, к оплате
src/main.tsx                       точка входа React
ЗАМЕР.md                           размер бандла и Web Vitals против react-invoice и vue-roman
```

## Где граница

В `react-invoice/src/App.tsx` хозяину оставлено 15 строк логики: каталог
литералом, деление на 100 и `toLocaleString`, `useState` с начальными
количествами, `.filter(… > 0)`, `?? 0`, `Math.max(0, Number(…))`. Здесь всё это
переехало в `core/storefront.flang`:

| в react-invoice было на TS | здесь — функция flang |
|---|---|
| `const tovary = [...]`, `useState({...})` | «Товары витрины», «Начальная корзина» |
| `Math.max(0, Number(e.target.value))`, `max={остаток}` | «Зажать», «Задать количество» |
| `setКол({...})` | «Шаг» — редьюсер по действиям «Больше», «Меньше», «Сбросить» |
| `(копейки / 100).toLocaleString(...)` | «Рубли» → `"2 500,00 ₽"`, «Разряды», «Две цифры» |
| `{скидка} %` | «Проценты» |
| `.filter(...).map(...)` | «Строки витрины» — список записей с готовыми строками |

Компонент получает запись `«Строка витрины»` с полями `«цена»: строка`,
`«стоимость»: строка`, `«больше нельзя»: признак` и ставит их в `<td>` и
`disabled={…}` как есть. Признаки заведены в утвердительной для разметки форме
(«больше нельзя», а не «можно больше»), чтобы в TSX не понадобилось даже
отрицания `!`.

Что при этом проверил компилятор, а в `react-invoice` не проверял никто:

- **тотальность** всех 23 функций — ядро не зациклится и не упадёт ни на каком входе;
- 16 обещаний, из них **10 доказаны обо всех входах** (два — индукцией по типу
  «Действие»: любой шаг редьюсера сохраняет число товаров и позиций), 6 — на
  сетке примеров; «Зажать» доказанно возвращает одну из трёх точек;
  «Скидка в процентах» — только 0, 5 или 10;
- 48 примеров — исполняемые, прогоняются при каждой проверке;
- в напечатанный JS **10 проверок при работе не уехали** — они доказаны.

## Что остаётся TypeScript

Импорты, объявления компонентов, `useReducer`, `dispatch(...)` в `onClick`,
`.map` по списку для рендера и типы, которые `tsc --strict` выводит сам из
напечатанного JS (`allowJs`): например, тип `dispatch` в `Stroka.tsx` записан
как `Dispatch<Parameters<typeof shag>[1]>` — это вариант «Действие» из ядра.
Файл `.d.ts` рукой не понадобился.

## Проверка, что логики в разметке нет

`scripts/markup-without-logic.flang` — план для `flang io`: перечисляет `../src`,
читает каждый `.tsx`, снимает из строки текст в кавычках и хвост после `//` и
ищет приметы логики — арифметику и сравнения, `?:`, `if`/`switch`/`for`,
`.filter`/`.reduce`/`.sort`, `Math.`, `Number(`, `toLocaleString`, `let`, `new`,
`=> {`, хуки с вычислением и `const` без вызова справа (данные литералом).
`useState`, `useReducer`, `.map`, стрелка в `onClick` разрешены.

```
npm run storozh
# {"plan":"Логики в разметке нет","result":"логики 0 строк: файлов .tsx 4, строк кода 36", …}   код 0
```

На `react-invoice/src` та же проверка отвечает кодом 1 и называет 5 строк
(`App.tsx:16, 23, 30, 53, 55`) — по одной на оператор, поэтому 5, а не 15.

Границы проверки названы: она текстовая. Не увидит оператор на строке без
`{`, `(` и `=`; примет `//` внутри строки за начало замечания; апостроф в
тексте разметки собьёт снятие кавычек. Проверка дерева разбора TypeScript была
бы точнее, но требовала бы кода на JS — здесь его не заводили нарочно.

## Запуск

```
npm install
npm run dev        # режим разработки
npm run build      # tsc --noEmit && vite build → dist/
npm run preview    # отдать dist/ для замера
npm run storozh    # проверка «логики в разметке нет» (нужен bootstrap/flang)
```

## Переиздать ядро

Из корня дерева flang:

```
bootstrap/flang check examples/frameworks/react-ts-pure/core/storefront.flang --proof
bootstrap/flang emit examples/frameworks/react-ts-pure/core/storefront.flang \
  --target js --out examples/frameworks/react-ts-pure/printed
```

Файлы в `printed/` печатает компилятор — руками их не правят, правят
`core/storefront.flang` и печатают заново. Пять строк шапки (лицензия и
команда переиздания) добавлены к напечатанному поверх, как у соседей.
