# Исполняемые утилиты FTS

FTS 0.2 позволяет описать чистую утилиту один раз и получить три связанных результата:

- непосредственно исполняемую модель;
- TypeScript-реализацию;
- тесты, построенные из предметных примеров.

## Полный пример

```fts
категория «Продажи»

  объект Покупка
    сумма является деньгами
    «постоянный клиент» является признаком

  утилита «Рассчитать скидку»
    принимает Покупка
    возвращает деньги
    начинает с 0

    правило «Большая покупка»
      если сумма не меньше 10000
      то добавить 10 процентов от поля сумма

    правило «Постоянный клиент»
      если «постоянный клиент» равен да
      то добавить 5 процентов от поля сумма

    свойство «Скидка ограничена»
      результат не больше 20 процентов от поля сумма

    пример «Обычная покупка»
      дано сумма равна 5000
      дано «постоянный клиент» равен нет
      ожидается результат равен 0

    пример «Большая покупка постоянного клиента»
      дано сумма равна 20000
      дано «постоянный клиент» равен да
      ожидается результат равен 3000
```

Рабочий файл находится в [`examples/utilities/discount.fts`](../examples/utilities/discount.fts).

## Цикл разработчика

Проверить структуру, ссылки на поля и типы:

```bash
fts check examples/utilities/discount.fts
```

Выполнить примеры прямо по спецификации:

```bash
fts test examples/utilities/discount.fts --pretty
```

Результат содержит число пройденных и упавших примеров. Несовпадение ожидаемого значения даёт ненулевой exit code, поэтому команду можно запускать в CI.

Создать реализацию и обычные тесты проекта:

```bash
fts generate examples/utilities/discount.fts --out generated
```

Команда создаёт:

```text
generated/
  fts.utilities.ts
  fts.utilities.test.ts
```

Сгенерированная функция доступна по предметному имени:

```ts
import { ftsUtilities } from "./generated/fts.utilities.js"

const discount = ftsUtilities["Рассчитать скидку"]({
  сумма: 20_000,
  "постоянный клиент": true,
})

// 3000
```

Файл тестов использует встроенный `node:test` и после обычной TypeScript-компиляции запускается вместе с остальными тестами проекта.

## Семантика

1. Результат получает значение из `начинает с`.
2. Правила рассматриваются сверху вниз.
3. Выполняются все правила, условия которых истинны.
4. `то добавить` требует числовой результат и числовое выражение.
5. После правил проверяются все свойства.
6. Затем результат сравнивается с ожиданием каждого примера.

Эта последовательность одинакова в interpreter FTS и сгенерированном TypeScript.

## Что генерируется, а что нет

Версия 0.2 предназначена для чистых детерминированных вычислений: тарифов, скидок, классификаторов, нормализаторов с конечными правилами и command guards.

FTS не генерирует сетевые вызовы, транзакции, репозитории или работу с платёжными системами. Для внешнего эффекта приложение вызывает сгенерированную утилиту, проверяет результат и затем самостоятельно выполняет интеграцию.

Без `--out` команда `fts generate` не пишет файлы и возвращает их содержимое как JSON. Этот режим предназначен для IDE, build-систем и ИИ-агентов. MCP предоставляет тот же результат через `fts_generate`.
