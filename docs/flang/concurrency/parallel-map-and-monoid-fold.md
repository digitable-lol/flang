# Параллельный `отобразить` и свёртка по доказанному моноиду

Решение — [ADR-0072](../../adr/0072-normal-parallelism-is-the-pool-the-pure-map-and-a-proved-monoid.md).
Здесь — как это устроено в напечатанном C.

## Что печатается

**`отобразить`.** Если тело зовёт только тотальные функции, генератор кода выносит
его в отдельную функцию C (`<функция>_map_<временное>`) с подписью
`fl_par_item`: элемент, массив захваченных значений, результат. Захвачены ровно те
имена тела, что связаны снаружи; каждое передаётся значением в массиве
`fl_value[]`, собранном на месте вызова. Сам цикл заменён одним вызовом
`fl_par_map` из рантайма.

**`свёртка`.** Свёртка печатается так же, через `fl_par_fold` и вынесенную функцию
с подписью `fl_par_pair`, только когда проверка перед печатью отметила её
полем `monoid`. Отметку ставит `«Отметить свёртки моноидов»`
(`flang/self/bootstrap/compiler.flang`):

1. для каждого объявленного `моноид` ядро получает три цели — сочетательность
   `F(F(a, b), c) = F(a, F(b, c))`, левую единицу `F(e, a) = a` и правую
   `F(a, e) = a` — над переменными объявленного носителя;
2. моноид годится, только если ядро свело все три (`«Свести витками»`,
   принято); сетка значений тут не участвует;
3. отмечается свёртка, тело которой — ровно вызов операции годного моноида от
   накопителя и элемента, в этом порядке.

Ядро сводит сочетательность и единицу у точного целого: правило кольца точных
складывает листья суммы как набор, а выписанный пустой список (точный ноль) из
набора снимает. У `число` сочетательность не сводится, и свёртка суммой `число`
печатается по порядку. Ложная единица не сводится, и свёртка по такому моноиду
тоже идёт по порядку. Сверщик записей (C и Lean) правило кольца не
переигрывает: доказательство моноида стоит на слове ядра.

`flang check` и `flang emit` пишут о каждом моноиде строку: сведены ли законы и
режется ли свёртка. Несведённый закон — не отказ проверки, а последовательная
печать. Моноид с объявленным обращением по-прежнему называется несудимым.

При `--protocol` генератор печатает всё по порядку: правил для вынесенных тел в
закрытом списке сличителя нет.

## Другие цели

| цель | `отобразить` | свёртка по моноиду | как |
|---|---|---|---|
| C++ | кусками | кусками | печать C, тот же рантайм |
| Go | кусками | кусками | замыкание `func(ctx *rt.Ctx, …)`, `rt.ParMap`/`rt.ParFold`, горутины |
| Java | кусками | кусками | безымянный класс `Flang.ParItem`/`Flang.ParPair`, захваченное снимается в `final` до вызова, `Flang.parMap`/`Flang.parFold` на пуле потоков |
| C# | кусками | кусками | лямбда `(ctx, …) =>`, `Flang.ParMap`/`Flang.ParFold` на `Parallel.For` |
| Elixir | кусками | кусками | `Flang.Rt.par_map`/`Flang.Rt.par_fold`, `Task.async_stream` с `ordered: true`; контекст задачи — словарь её процесса |
| Rust | по порядку | по порядку | значения стоят на `Rc` и `RefCell` и между потоками не передаются |
| JavaScript, TypeScript, Python | по порядку | по порядку | один поток |

Во всех целях правило одно и то же: тело зовёт только тотальные функции, остаток
списка отдаётся кускам после замера первых элементов, отказ куска или перебор
предела шагов возвращает счёт по порядку с того же места, а у запаса списка
(`Grow`) есть владелец — контекст, который его завёл.

## Что делает рантайм C

`fl_par_map` и `fl_par_fold` (`flang/src/emit/c/flang_runtime.c`) сначала
считают по порядку на своём потоке. Через 1, 2, 4, 8… элементов они смотрят на
часы; если на первые элементы ушло не меньше 20 мкс и оставшееся по той же цене
займёт не меньше 100 мкс, остаток списка отдаётся пулу.

Пул заводится при первом таком случае: `FLANG_THREADS` потоков (по умолчанию
число процессоров, не больше 64), один из них — вызывающий. Остаток режется на
куски, по четыре на поток; каждый кусок считается в своём контексте (`lane`) и
своей арене. Контекст куска несёт ту же глубину и тот же предел глубины, что
вызывающий, предел шагов — остаток вызывающего, запас стека — остаток стека
вызывающего.

Куски `отобразить` пишут результат по своему номеру; затем вызывающий
копирует каждый результат в свою арену в порядке элементов, складывает шаги
кусков в свой счёт и отдаёт арены кусков системе.

Кусок свёртки сворачивает свои элементы, начиная с первого. Вызывающий
применяет операцию к накопленному и к итогу каждого куска по порядку. Вызовов
операции при этом ровно столько же, сколько при счёте по порядку; число шагов
совпадает, когда цена операции не зависит от величины операндов.

Если отказал хоть один кусок, перешёл предел шагов в сумме или не удалась
копия, параллельный итог выбрасывается, счёт шагов возвращается к прежнему, и
список досчитывается по порядку с того же места. Наружу уходит ответ или
отказ счёта по порядку.

Вложенный `отобразить` внутри куска считается по порядку. Если пул занят
другим потоком (рабочий режим процессов), вызов тоже считает по порядку.

## Что не делится между потоками

Контекст куска (`lane` не ноль) не пишет общих приборов: имени работающей
функции, окна наблюдения, ведомостей витков и зарядов, пульса.

Запас списка (`fl_grow`) помнит арену, в которой заведён. «Добавить» и
«приписать» пишут в запас на месте, только если он заведён в арене текущего
контекста; иначе они копируют. Без этого два куска, добавляющие к одному
захваченному списку, писали бы в одну и ту же ячейку.

## Как проверяется

План `flang/concurrency/bench/parallel-map.fscript` печатает стенды из
`flang/concurrency/bench/parallel-map.flang`, собирает их и сверяет:

- ответ при 1, 2, 8 и 64 потоках побайтово один и тот же, и у `отобразить`, и у
  свёртки по моноиду точных целых;
- сборка с `-fsanitize=thread` при четырёх потоках даёт ноль предупреждений;
- подделка рантайма — запись имени функции из куска возвращена — даёт
  предупреждения;
- свёртка суммой `число` под объявленным `моноид` и моноид с ложной единицей
  печатаются без `fl_par_fold`;
- ускорение стенда `отобразить` на восьми потоках не ниже шести раз.
