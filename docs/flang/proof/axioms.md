# Почему в ядре доказательств нет аксиом

Ядро доказательств (`flang/self/proofterm.flang`, `flang/self/proof-kernel.flang`,
`flang/self/proof-initial.flang`) не принимает ни одного утверждения на веру. Каждое
место, где можно было бы заподозрить аксиому, объяснено доводом: почему это теорема,
чтение или факт, а не допущение. Доводы собраны здесь, по одному на место.

Список доводов закрыт и проверяется: `bootstrap/flang run-script axioms:check`
краснеет, если из этой страницы пропал хоть один заголовок вида `── … ──`, на
который опирается ядро.

### Аксиом ноль, и это не упущение — `flang/self/proof-kernel.flang`

```
// Ядро доказательства: сведение заключения посылки к допущениям — на самом
// flang.
//
// ── Что здесь есть ──────────────────────────────────────────────────────────
// Два решающих правила, одна нормализация, ни одного поиска:
//
//   ПРАВИЛО 1  «Е не меньше 0» выводится, если `Е` собрано из неотрицательного:
//              литерал не меньше нуля, терм с допущением «не меньше 0», их
//              сумма, выбор из них. Четыре случая, список закрыт.
//   ПРАВИЛО 2  «А равно Б» выводится, если после переписки допущениями (по
//              одному проходу на допущение) стороны совпадают синтаксически.
//
// Нормализация закрыта тремя переписками, и все три — чтение, а не вывод:
// `пусть` разворачивается, `разбор` известного конструктора выбирает ветвь,
// `если` с уже вычисленным условием выбирает ветвь. ВЫЗОВ ФУНКЦИИ НЕ
// РАЗВОРАЧИВАЕТСЯ НИКОГДА — у «Высота» от х при неизвестном `х` нормальной
// формы нет, и разворачивать его значило бы не заканчиваться.
//
// ── Аксиом ноль, и это не упущение ──────────────────────────────────────────
// Числа flang — IEEE-754, и в них ложно почти всё привычное: «х плюс 1 не
// меньше х» неправда при |х| от 2⁵³. Оба правила выше — ДОКАЗАННЫЕ теоремы о
// IEEE-754, а не постулаты: посылка «а не меньше 0» истинна только для не-NaN
// значений из [0, +∞], а сумма двух таких значений под округлением к ближайшему
// снова лежит в [0, +∞] — переполнение даёт +∞, а не отрицательное.
//
// Поэтому в списке НЕТ умножения («ноль умножить на бесконечность» даёт не
// число) и НЕТ вычитания («а минус б» при неотрицательных `а` и `б`
// ОТРИЦАТЕЛЕН). Дописать сюда правило можно только тем же рассуждением, каким
// открыты эти два.
//
// Умножение вошло позже и НЕ СЮДА, а в ДНО: `дно(а·б)` собирается из дон
// сомножителей, когда оба дна СТРОГО ПОЛОЖИТЕЛЬНЫ. Строгость — это и есть та
// самая посылка, которой не хватало знаку: положительное дно исключает у
// сомножителя и ноль, и не-число, а без нуля «ноль умножить на бесконечность»
// не получить ниоткуда. Вычитания нет по-прежнему и нигде.
//
// ── Два места, где flang и JavaScript расходятся, и оба пришлось написать ───
// Узлы сличаются здесь не через `равен` языка: в двух точках он отвечает
// ПРОТИВОПОЛОЖНОЕ:
//
//   МИНУС НОЛЬ  `-0 === 0` в JavaScript ИСТИННО, а `равен` языка работает
//               через `Object.is` и говорит «нет». Поэтому числа здесь
//               сличает «Числа сошлись по порядку» — через двойное «не меньше», а не
//               через `равен`.
//   НЕ ЧИСЛО    `NaN === NaN` ЛОЖНО, а `Object.is(NaN, NaN)` истинно. То же
//               двойное «не меньше» даёт «нет».
//
// Ошибиться тут стоило бы дорого молча: «ноль» цели («Е не меньше 0») сличается
// именно этим сравнением, и ядро, считающее `-0` не нулём, отказывало бы там,
// где двойное «не меньше» выводит.
//
// ── Тотальность ─────────────────────────────────────────────────────────────
// Обход AST вглубь тотальным здесь не выходит по той же причине, по которой он
// не выходит в `self/emit-c.flang` («Обход всего»): убывание идёт по чужому
// дереву, разложенному в «Значение», и анализ его не признаёт. Всё, что
// считается НЕ обходом — сличение скаляров, чтение вида узла, разбор литерала,
// сборка вердикта, — тотально и без единого сторожа.
```

### ПОЧЕМУ ТЕОРЕМА, А НЕ АКСИОМА — `flang/self/proof-kernel.flang`

```
// ПЯТОЕ РЕШАЮЩЕЕ ПРАВИЛО — «цель есть допущение» (Γ, A ⊢ A). Первое в
// наборе, которое НЕ СПРАШИВАЕТ ВИДА ЦЕЛИ: четыре прежних заведены каждое под
// свой вид («не меньше 0», «не больше конечного», «не больше терма», «равно»),
// это работает на любом.
//
// ── ПОЧЕМУ ТЕОРЕМА, А НЕ АКСИОМА ────────────────────────────────────────────
// Подозрение в РЕФЛЕКСИВНОСТИ отводится первым, потому что оно законное:
// «Е не больше Е» в IEEE-754 НЕ теорема — на `не число` сравнение ложно, и
// рефлексивность порядка держится посылкой «не NaN». Здесь другое, и разница
// точная: рефлексивность говорит нечто ОБ ОПЕРАЦИИ, применённой к двум копиям
// значения, и потому зависит от края носителя. Это правило не применяет НИ
// ОДНОЙ операции языка — оно говорит, что одно и то же выражение имеет одно и
// то же значение, и `не число` в это утверждение попасть неоткуда.
//
// Доказательство после этого в две строки. Допущение `A` значит здесь ровно
// одно: «выражение `A` при данном входе вычисляется в `да`» (признаком его
// объявил типизатор, а не автор). Цель `A` значит то же самое о том же
// выражении. Значит при истинном допущении цель истинна — и не «следует», а
// СОВПАДАЕТ: это одно утверждение, записанное дважды. Теоремой это делает то,
// что совпадение ПРОВЕРЯЕТСЯ узел в узел («Одинаковы»), а не объявляется.
//
// Держится оно двумя посылками, и обе уже несут вес в этом ядре: ОДНО
// ОКРУЖЕНИЕ (на нём же стоят правило тождества и разбор по условию; ломается
// оно захватом имени, а захват стережётся в подстановке и в развёртке) и
// ДОПУЩЕНИЕ ДЕЙСТВИТЕЛЬНО ДОПУЩЕНО (посылку индукции ядро СТРОИТ само,
// предусловие снимается на каждом месте вызова). Без второй это была бы ровно
// та аксиома, из-за которой список аксиом пуст.
```

### ПОЧЕМУ СЧЁТ НЕ АКСИОМА — `flang/self/proof-kernel.flang`

```
// ═════════════ четвёртый ход `Свести`: ПРИНИМАЮЩАЯ ЕГО ПОЛОВИНА ═════════════
//
// ВЫЧИСЛЕНИЕ ЗАМКНУТОЙ ЦЕЛИ — тот же ход, каким `по примеру` закрывает случай, и
// довод у него тот же: закрытый терм — это значение, и спорить о нём не о чем,
// надо посчитать. Новое здесь только место, откуда ход позван (`Свести`).
//
// ── ПОЧЕМУ СЧЁТ НЕ АКСИОМА ──────────────────────────────────────────────────
// Аксиома — утверждение, принятое БЕЗ доказательства; ложная аксиома отравляет
// всё, что из неё выведено, и ровно поэтому список аксиом ядра пуст и остаётся
// пуст. Здесь не принимается на веру НИЧЕГО: цель не утверждается, а
// ВЫЧИСЛЯЕТСЯ тем же интерпретатором, которым язык считает всё остальное, и
// принимается ровно значение `да`. У замкнутого терма значение ОДНО — свободных
// имён в нём не осталось ни одного, — значит один прогон говорит обо всех входах
// сразу, а не об одном из них. Это не новое доверие, а тот же ход, которым ядро
// уже закрывает случай `по примеру`: доверенных сущностей не прибавилось.
// Три границы держат это утверждение той силы, какой оно есть: замкнутость
// (проверяется «Свободными именами», теми же, какими её проверяет посылка
// индукции), предел витков и глубины (исчерпание — ОТКАЗ, а не «нет») и
// значение (принимается `да`; `нет` — ложное утверждение, не признак — цель не
// утверждение вовсе, отказ прогона — цель не имеет значения). Ослабь любую из
// трёх, и ход начал бы печатать «доказано» о неправде — а не завёл бы аксиому:
// разница важна, потому что чинится это по-разному.
//
// ── Почему довод приезжает ПРОГРАММОЙ, а не вычислителем ────────────────────
// Замыкание, захватывающее программу и имя обёртки, отдало бы ход одним
// доводом. В языке замыкания нет и не будет — на нём ломается доказательство
// завершаемости, ради которого язык существует, — поэтому довод проводится
// ЯВНО: сюда едет сама программа, а обёртку и предел ход строит на месте.
//
// ── Три условия, и ни одно не украшение ─────────────────────────────────────
//   ЗАМКНУТОСТЬ  У цели не осталось ни одного свободного имени, и считается она
//                ТОЙ ЖЕ функцией («Свободные имена»), какой её считает посылка
//                индукции для `по примеру`.
//   ПРЕДЕЛ       Вычисление ограничено витками и глубиной; исчерпание предела —
//                отказ, а не «нет».
//   ЗНАЧЕНИЕ     Принимается ровно `да`. `нет` — ЛОЖНОЕ утверждение; не признак
//                — цель не утверждение вовсе; отказ прогона — цель не имеет
//                значения, и говорить о ней нечего.
//
// ОБЫЧНАЯ, а не тотальная: «Вызвать» считает ЧУЖУЮ программу, завершаться она не
// обязана, и нетотальность заразна по вызову. Обещать здесь завершение значило бы
// выдать пустую гарантию — ровно ту неправду, которую слой обещаний и ловит.
```

### ПОЧЕМУ ЭТО НЕ АКСИОМА — `flang/self/proof-kernel.flang`

```
// ═══════════ ШЕСТАЯ ПЕРЕПИСКА: ЗАМКНУТАЯ АРИФМЕТИКА ═══════════
//
// `0 плюс 1` есть `1`, и спорить тут не о чем: у обоих слагаемых значение
// написано в тексте, значит у суммы оно тоже одно, и считает его ТА ЖЕ
// операция, какой считает вычислитель.
//
// ── ПОЧЕМУ ЭТО НЕ АКСИОМА ──
// Это не вывод и не аксиома об арифметике — это чтение написанного, ровно как
// разбор известного конструктора выше. Аксиома принимается БЕЗ проверки и
// говорит о всех значениях сразу; здесь же оба значения написаны в тексте, а
// операция взята у вычислителя, и ответ проверяется тем же прогоном, каким
// проверяется всякий пример. Список принятого на веру от этой переписки не
// пополнился ни на строку — он и остался пуст.
//
//
// ЗАЧЕМ, числом. Переписка длины даёт `длина(пусто)` РАВНЫМ нулём, а форма
// `добавить`/`приписать` — суммой `1 плюс …`. Отсюда у базы индукции обе стороны
// верны и уже посчитаны, но записаны по-разному: `1` слева и `0 плюс 1` справа.
// Тождество сличает СИНТАКСИЧЕСКИ и такую базу отвергало — то есть отвергало
// доказательство из-за формы записи числа, а не из-за содержания.
//
// СПИСОК ОПЕРАЦИЙ ЗАКРЫТ ТРЕМЯ, и закрыт не из осторожности вообще:
//   плюс, минус, умножить — на двух числовых литералах дают ровно то, что даёт
//     вычислитель, включая обе бесконечности, оба нуля и «не число»;
//   деления и остатка здесь НЕТ: `остаток` вычислитель считает не остатком
//     JavaScript, а своей `remainderOf`, и второй ответ на тот же вопрос развёл
//     бы ядро с вычислителем молча;
//   сравнений здесь НЕТ: их значение — признак, и решает о нём ЧЕТВЁРТЫЙ ХОД
//     (вычисление замкнутой цели) целиком, а не по одному узлу.
```

### ПОЧЕМУ ЭТО ТЕОРЕМА, А НЕ АКСИОМА — `flang/self/proof-kernel.flang`

```
// ═════ РАЗБОР ВЫПИСАННОГО СПИСКА: `разбор [] …` и `разбор [г, …] …` ═════
//
// ЧТО ДЕЛАЕТ ПРАВИЛО. `разбор`, чьё разбираемое к этому месту стало ВЫПИСАННЫМ
// списком, перестаёт быть разбором: ветвь выбирается по числу написанных
// элементов — `случай пусто` у пустого, `случай голова и хвост` у непустого, —
// а части связываются ТОЧНЫМИ значениями: голова есть первый написанный
// элемент, хвост есть список остальных.
//
// ── ПОЧЕМУ ЭТО ТЕОРЕМА, А НЕ АКСИОМА ───────────────────────────────────────
// Новой доверенной сущности не прибавилось ни одной, и «принято считать» здесь
// нет: выбор ветви ПРОЧИТАН У ВЫЧИСЛИТЕЛЯ. `разбор` по списку
// смотрит на длину уже посчитанного списка: ноль —
// берётся ветвь `пусто`, иначе берётся ветвь `голова и хвост`, и в неё кладутся
// первый элемент и остаток, знак в знак. Выбора, поиска и отката здесь нет ни
// одного: число написанных элементов известно на разборе, а третьего образца у
// списка не бывает — и говорит это не ядро, а типизатор («Отчёт об
// исчерпывающести» в `types.flang`: «разбор списка не покрывает «пусто» и
// «голова и хвост»»).
//
// Не прибавилось и нового ХОДА: ветвь связывается и нормализуется теми же
// «Ветвь по конструкции» и «Связи ветви», какими это делается у объявленной
// суммы, и имена конструкторов берутся теми же («Список пусто», «Список
// звено», «Список голова», «Список хвост» стоят выше и здесь не переписаны).
// Прибавилось ровно одно умение: прочитать выписанный список тем конструктором,
// которым его и так читают образцы.
//
// ── ОТКУДА БЕРЁТСЯ ЗНАНИЕ О СПИСКЕ, И ИСТОЧНИКОВ РОВНО ТРИ ─────────────────
// 1. СПИСОК ВЫПИСАН ПРЯМО В ТЕКСТЕ: `разбор пустой список …`, `разбор [а, б] …`.
//    Число элементов известно на разборе, и допущений не нужно ни одного.
// 2. РАВЕНСТВО САМОМУ СПИСКУ: допущение `Л равен пустой список` (или
//    `Л равен [а, б]`) приезжает сюда пятым ходом, а переписка равенством
//    ставит выписанный список на место имени ДО этого места — и правило видит
//    уже случай 1. Второго чтения равенства здесь поэтому НЕТ.
// 3. ДОПУЩЕНИЕ О МЕРЕ: `(длина Л) равен 0` — ровно та охрана, которой написаны
//    обещания библиотеки. Здесь оно НЕ ЧИТАЕТСЯ вовсе: этот ход смотрит на терм
//    и не знает допущений. Такой разбор закрывает отдельный ход — «Разбор при
//    известной пустоте» (ниже, при правиле переписки), и берёт он ОДНУ ЛИШЬ
//    ветвь `пусто`, потому что мера говорит о числе элементов, а не о частях и
//    не о виде разбираемого. Разделение это не двоевластие, а разные посылки:
//    здесь известно, ЧТО НАПИСАНО, там — что элементов НЕТ.
//
// ── ГРАНИЦА ПРАВИЛА, И ОНА ПРО СВЯЗАННЫЕ ИМЕНА ─────────────────────────────
// НЕПУСТОТА НЕ ЧИТАЕТСЯ НИ ИЗ ОДНОГО ДОПУЩЕНИЯ. `(длина Л) больше 0`,
// `не (пусто Л)`, `Л содержит э` ветви `голова и хвост` НЕ дают: она берётся
// ровно тогда, когда список ВЫПИСАН. Это граница, а не недоделка.
//
// Образец `голова и хвост` СВЯЗЫВАЕТ ДВА ИМЕНИ, и ветвь под ним говорит не о
// списке, а о его частях. Знать, что список непуст, — не то же, что знать его
// голову и хвост: связать `голова` и `хвост` было бы НЕЧЕМ, они остались бы в
// цели свободными именами, ничего не означающими, а цель, закрытая после такой
// подстановки, была бы закрыта НИ О ЧЁМ. Ровно поэтому ход внутрь `разбор`
// закрыт нарочно (шапка файла и «СВЯЗЫВАТЕЛЯ НАД ДИЗЪЮНКЦИЕЙ НЕТ ПО
// ПОСТРОЕНИЮ» ниже), и правило это открывает его РОВНО ТАМ, где связанным
// именам есть чем стать, — где части написаны. У ветви `пусто` связанных имён
// нет ни одного, и с неё эта граница не спрашивается вовсе: ей хватает и меры.
//
// ЧТО СЛУЧАЕТСЯ, КОГДА ВЕТВИ НЕТ. Ветвь ищется по имени конструктора; не нашлась
// — читается `случай любое` тем же «Разбором по любому», что и у суммы, и в
// него уходит НАСТОЯЩИЙ выписанный список, а не конструкция, собранная здесь.
// Порядок этот не косметика: конструкция нужна одной лишь «Связи ветви», чтобы
// достать части по ключам; попади она в терм — и `разбор` дальше читал бы уже
// не список, а вариант, которого автор не писал.
//
// Подделка на правило: `flang/test/fixtures/poddelka-razbor-spiska.flang` —
// четыре лжи на четыре способа обойти посылку (пустой список, разобранный

// ═══ ДЕВЯТЫЙ ХОД: РАВЕНСТВО, РЕШЁННОЕ СЧЁТОМ ЗАМКНУТЫХ ЧАСТЕЙ ═══
//
// ЧТО ЗА ДЫРА. Восемь ходов выше кончаются одним и тем же отказом, и он самый
// частый в библиотеке: «после переписки допущениями стороны равенства остались
// разными термами. Ядро сличает синтаксически и равенства вычислений не
// решает». Для ядра `50` и `100 делить на 2` — разные вещи, хотя значение у них
// одно и написано оно в тексте целиком.
//
// ЧТО ЗДЕСЬ ДЕЛАЕТСЯ. Прежде чем сличать стороны, ядро СЧИТАЕТ те их части, у
// которых не осталось ни одного свободного имени, и ставит на место части её
// значение. Считает — тем же вычислителем, каким язык считает всё остальное,
// и той же дорогой, какой четвёртый ход считает замкнутую ЦЕЛЬ: обёрткой без
// параметров и с названным пределом.
//
// ── ПОЧЕМУ ЭТО НЕ АКСИОМА И НЕ НОВОЕ ДОВЕРИЕ ────────────────────────────────
// Аксиома принимается БЕЗ проверки и говорит обо всех значениях сразу. Здесь
// не принимается на веру ничего: у ЗАМКНУТОЙ части значение ОДНО — свободных
// имён в ней не осталось, — значит один прогон говорит о ней целиком, а не об
// одном из её входов. Подстановка значения на место части есть замена терма
// РАВНЫМ ему термом, и это тот же ход, каким ядро уже разворачивает `пусть`,
// выбирает ветвь известного разбора и складывает `1 плюс 1` («Считанная
// арифметика»). Список принятого на веру от этого не пополнился ни на строку —
// он и остался пуст. Доверенных сущностей тоже не прибавилось: вычислитель
// ядру уже доверен четвёртым ходом.
//
// ── АЛГЕБРЫ ЗДЕСЬ НЕТ НИ ОДНОЙ, И В ЭТОМ ВСЁ ДЕЛО ──────────────────────────
// Ход НЕ переставляет скобки, НЕ переносит слагаемые и НЕ пользуется ни
// ассоциативностью, ни дистрибутивностью. В IEEE-754 они ЛОЖНЫ прямым числом:
// `(0.1 плюс 0.1) плюс 0.6` даёт `0.8`, а `0.1 плюс (0.1 плюс 0.6)` даёт
// `0.7999999999999999`. Правило, переставляющее скобки, доказало бы здесь
// неправду; это правило их не трогает — оно СЧИТАЕТ написанное и сличает
// посчитанное. Поэтому `0.1 плюс 0.2 равен 0.3` им НЕ доказывается: слева
// выходит `0.30000000000000004`, справа `0.3`, и это разные литералы.
//
// ── ТРИ ГРАНИЦЫ, И НИ ОДНА НЕ УКРАШЕНИЕ ─────────────────────────────────────
//   ЗАМКНУТОСТЬ  У части не осталось ни одного свободного имени, и считается
//                она ТОЙ ЖЕ «Свободные имена», какой её считает четвёртый ход.
//                Часть со свободным именем не считается вовсе: значений у неё
//                много, и одно из них не говорит об остальных ничего.
//   ПРЕДЕЛ       Витки, глубина и ЧИСЛО ПОСЧИТАННЫХ ЧАСТЕЙ названы числами
//                ниже. Исчерпание любого из трёх — часть остаётся собой, то
//                есть ОТКАЗ, а не «ладно». Счёт каждой стороны идёт со СВОИМ
//                запасом частей: раздели один запас на двоих — и одинаковые
//                стороны считались бы по-разному, а значит расходились бы там,
//                где сходились до этой работы.
//   ЗНАЧЕНИЕ     На место части встаёт только СКАЛЯР — число, строка или
//                признак. Список, запись и вариант обратно в написанное не
//                кладутся: собирать их узлами значило бы завести второй ответ
//                на вопрос «как это записано», а он уже есть у разбора.
//
// ── ДВА ЧИСЛА, КОТОРЫЕ ОБРАТНО НЕ КЛАДУТСЯ, И ЭТО НЕ ПРИДИРКА ──────────────
// МИНУС НОЛЬ. Числа ядро сличает «Числа сошлись по порядку» — по-JavaScript
// (`===`), — а `равен` языка есть `Object.is`. На `-0` они расходятся ПРОТИВ
// нас: сличение говорит «то же самое», язык говорит «нет». Подставь ядро
// посчитанный `-0` — и оно доказало бы `(0 умножить на (0 минус 1)) равен 0`,
// то есть ЛОЖЬ. Поэтому минус ноль на место части не встаёт: часть остаётся
// собой. Отличается он от плюс нуля ровно тем самым расхождением: «Числа
// тождественны» отвечает «да», а `равен` языка — «нет».
// НЕ ЧИСЛО. Здесь расхождение обратное и безвредное (`равен` языка говорит
// «да», сличение — «нет»), но подстановка не дала бы ничего, кроме ложного
// чувства, что цель посчитана. Не-число на место части тоже не встаёт.
// ОДНОЙ ЭТОЙ ОГОВОРКИ МАЛО, и это замерено на подделке, а не выведено: минус
// ноль приезжает и ОКОЛЬНО — посчитанный «минус один» встаёт на место части
// законно, а «Считанная арифметика» при следующей нормализации складывает
// «0 умножить на минус один» в минус ноль сама. Поэтому вторая застава стоит на
// ГОТОВЫХ сторонах («Одинаковы до порядка соседей»), а не на частях.
//
// ── ГДЕ ЭТОТ ХОД СТОИТ ──────────────────────────────────────────────────────
// Ход — ВТОРАЯ ПОЛОВИНА ПРАВИЛА ТОЖДЕСТВА, а не девятый ход свода: он
// спрашивается внутри «Свести равенство» и ровно там, где сличение сторон
// отказало. Перебора шести правил и восьми ходов он не меняет, а у ПРАВИЛА
// ТОЖДЕСТВА даёт вторую пробу. Отнять он не может ничего: принятое
// сличением принятым и остаётся.
//
// Тронуты этим ТРИ подписи свода — «Свести правилами», «Свести правилами при
// фактах» и «Свести равенство»: во все три добавлена «программа» последним
// доводом перед «отчёт». Больше в своде не тронуто ничего.
//
// ОБЫЧНАЯ, а не тотальная: «Вызвать» считает ЧУЖУЮ программу, завершаться она
// не обязана, и нетотальность заразна по вызову.
```

//                     инстанцируется ПО МЕСТУ ВЫЗОВА — параметры на аргументы
//                     этого вызова, `результат` на сам вызов, — и заключение
//                     обязано быть СВЕДЕНО из полученного факта. Ссылка не
//                     разрешение; поиска здесь нет ни одного: кандидатов ровно

### Почему это чтение, а не аксиома — `flang/self/proof-initial.flang`

```
// ОБЪЯВЛЕНИЕ ВСТРОЕННОГО СПИСКА — ПРОЧИТАННОЕ, А НЕ ПОСТУЛИРОВАННОЕ.
//
// ── Почему это чтение, а не аксиома ─────────────────────────────────────────
// Аксиома — утверждение, принятое без доказательства; его нельзя проверить, и
// ложная аксиома отравляет всё, что из неё выведено (`х плюс 1 не меньше х`
// ЛОЖНО при |x| от 2⁵³ — ровно поэтому список аксиом ядра пуст и остаётся
// пуст). Здесь же не утверждается ничего нового: три факта о списке уже
// объявлены языком, СЧИТАЮТСЯ им сегодня и держат на себе другие слои. Эта
// функция их переписывает в ту же форму, в какой автор пишет `тип … вариант …`:
//
//   1. КОНСТРУКТОРОВ РОВНО ДВА. Говорит типизатор: `разбор` списка исчерпан
//      тогда и только тогда, когда покрыты `пусто` и `голова и хвост`
//      («Отчёт об исчерпывающести» в `types.flang`). Третьего образца у списка
//      нет ни в разборщике, ни в одной из восьми целей печати. Значит посылок у
//      принципа ровно две — столько же, сколько конструкторов, как и у
//      объявленной суммы.
//   2. ПОЛЯ ЗВЕНА И ИХ ТИПЫ. Говорит тот же типизатор (случай `cons` связывания
//      образца): при разборе `список Э` голова получает тип `Э`, хвост — тип
//      `список Э`. Отсюда функтор читается буквально и без выбора:
//
//          F(X) = 1 + (Э × X)
//
//      Место `X` — хвост, потому что его тип есть САМ разбираемый тип; голова —
//      коэффициент, потому что её тип другой. Правило то же самое, что у
//      объявленной суммы, и применяется той же строкой кода.
//   3. ХВОСТ — ЧАСТЬ ЗНАЧЕНИЯ, СТРОГО МЕНЬШАЯ ЦЕЛОГО. Говорит анализ
//      завершаемости (голова и хвост помечаются «глубже»), и на этом факте
//      стоит обещание «тотальная, структурой» у функций корпуса. Допущение
//      индукции о хвосте законно ровно постольку, поскольку законно это
//      обещание, — довод один и тот же.
//
// То есть форма списка была известна разборщику, типизатору и анализу
// завершаемости; не знало её одно ядро доказательства. Здесь оно её узнаёт из
// тех же трёх мест, а не из четвёртого решения.
//
// ── СТРОКА ЧИТАЕТСЯ РЯДОМ И ТЕМ ЖЕ ПРАВИЛОМ («Объявление строки» ниже) ──────
// Довод — там же, при «Объявление строки».
```

// части — тоже «для всех прочих», и взять его при любых прочих аргументах

// ── ПОИСКА ЗДЕСЬ НОЛЬ ───────────────────────────────────────────────────────

//   СВЯЗЫВАТЕЛЕМ  войдя внутрь `пусть`, `разбор`, `свёртка`,
//               `отобразить`/`отфильтровать`: под связывателем аргументы вызова

//   ЧИСЛО       аргументов у вызова столько же, сколько параметров у функции.
//   БЕЗ ЗАХВАТА подстановка идёт тем же «Подставить начальной», что и везде, и

//   ЦЕЛЬ ДАЛА НЕ ПРИЗНАК — она не утверждение вовсе, и «да» или «нет» о ней нет.
//   СЧЁТ СОРВАЛСЯ — значения у цели нет; отказ вычисления это ОТКАЗ, а не «нет»,
//     и предел называется вслух, иначе он неотличим от зависания.
//
// Исход едет сюда СУММОЙ («Исход счёта» в `proof-kernel.flang`), а не признаком,
// и потому каждый отказ говорит своё: на признаке три последних были бы
// неразличимы — ход отвечал бы «не закрыл», и приписка выходила бы одна, про
// свободные имена.
//
// ── Аксиом не прибавилось ───────────────────────────────────────────────────
// Приписка не закрывает НИ ОДНОЙ цели: она только удлиняет ОТКАЗ. Ход, который
// умеет одно — сказать «нет» подробнее, — состоятельности не касается вовсе, и
// `АКСИОМЫ` при нём остаются пустым списком, каким были. Проверено подделкой:
// программа с ложным постусловием остаётся ОТВЕРГНУТОЙ, у неё лишь названа
// причина.
//
// ОБЫЧНАЯ, а не тотальная: «Свободные имена» обещания завершения не даёт, а
// нетотальность заразна по вызову. Обещать здесь завершение значило бы выдать
// пустую гарантию — ровно ту неправду, которую слой обещаний и ловит.
```

### Почему это факт, а не допущение — `flang/self/proofterm.flang`

//
// Седьмой ход («по свойству») читает то же самое, но ТОЛЬКО по ссылке автора; на

//
// ── Почему это факт, а не допущение ─────────────────────────────────────────
// Постусловие проверяется вычислителем ПОСЛЕ КАЖДОГО возврата,
// и нарушенное прекращает вычисление отказом `FLANG_PROPERTY`.
// Значит у вызова, У КОТОРОГО ЕСТЬ ЗНАЧЕНИЕ, постусловие вызванного истинно:
// вход, на котором оно ложно, значения не даёт вовсе. Тот же род факта, что
// `требует` у `по предположению`, только платит за него не вызывающий на каждом
// месте вызова, а вызываемый на каждом возврате. Список постулатов не
// пополнился ни строкой: «АКСИОМЫ» здесь нечему соответствовать.
//
// ── ТРИ ОПАСНОСТИ, И КАЖДАЯ ЗАКРЫТА УСТРОЙСТВОМ, А НЕ ВНИМАНИЕМ ─────────────
//
//   КРУГ. Постусловие функции, применённое к доказательству её же
//     постусловия, — это P из P. Прямой случай — рекурсивный вызов; через два
//     шага — взаимная рекурсия; через три — тройка. Закрыто НЕ проверкой, а
//     ПОСТРОЕНИЕМ: фактом вправе стать только то постусловие, которое ядро УЖЕ
//     ДОКАЗАЛО, — и доказало БЕЗ него. Ход идёт неподвижной точкой («Закрыть без
//     теорем» ниже): на каждом проходе доступны факты только из закрытых
//     РАНЬШЕ, а первый проход идёт с пустым списком, то есть ровно так, как
//     ядро работало до этого хода. Ни рекурсию, ни взаимную рекурсию отдельно
//     ловить не надо — они не могут начаться.
//     ЦЕНА НАЗВАНА: ход НЕ берёт постусловие, которое автор написал, а ядро не
//     доказало. Это сознательный размен: ненадёжное постусловие в библиотеке
//     находили дважды, и ход, берущий ненадёжное, потащил бы ложь дальше молча.
//
//   НЕОПЛАЧЕННОЕ `требует`. Постусловие вызываемого верно ТОЛЬКО при
//     выполненном предусловии. Взять его на месте, где `требует` не снято,
//     значило бы завести аксиому, которой не поймает ни один сторож пустоты
//     «АКСИОМЫ». Закрыто тем, что оплату решает не этот ход, а снятие
//     предусловий («Снять предусловия» ниже): оно отдаёт ИМЕНА вызванных, у
//     которых хоть одно место не снято, и факт с такого вызванного не берётся
//     вовсе. Второго ответа на вопрос «оплачено ли» здесь нет ни одного.
//     Снятие само читает доказанные обещания вызванных — теми же шестью
//     условиями, что ниже, — и потому идёт с этим ходом ОДНИМ кругом до
//     неподвижной точки: на каждом витке доступно только доказанное к
//     предыдущему витку у вызванной, чьи места оплачены к предыдущему витку.
//     ИМЯ ВЫЗВАННОГО, А НЕ РЕБРО, и это оценка СВЕРХУ нарочно: нормализация
//     вправе принести вызов из ЧУЖОГО тела (развёртка определения), и тогда
//     ребра «доказываемая → вызванная» в исходнике не было вовсе, а
//     неоплаченное место — было.
//
//   НЕ ПО ИМЕНИ, А ПО РЕБРУ. Постусловие берётся у той функции, которая правда
//     вызвана в этом узле («Функция терма по имени» от программы и имени вызова), и
//     инстанцируется по ЕЁ параметрам. Поиска постусловия ПО ИМЕНИ УТВЕРЖДЕНИЯ
//     здесь нет: «Найти постусловие» обходит все функции модуля и на одноимённых
//     постусловиях двух разных функций вернёт первую попавшуюся — то есть
//     доказательство про чужое тело.
//
// ── СПИСОК СЛУЧАЕВ, КОТОРЫЕ ХОД БЕРЁТ, — ЦЕЛИКОМ ────────────────────────────
// Берётся факт, и только он, когда сошлись ВСЕ шесть:
//   1. узел — вызов с именем;
//   2. имя разрешается в функцию ЭТОЙ программы;
//   3. у неё есть хоть одно `обеспечивает`;
//   4. это постусловие ядро УЖЕ ДОКАЗАЛО на одном из прошлых проходов;
//   5. у вызванной не осталось НЕОПЛАЧЕННЫХ мест `требует`;
//   6. инстанция строится: число аргументов совпало с числом параметров и
//      подстановка не захватила бы имени.
// Всё, что под эти шесть не подошло, факта не даёт, и вердикта тогда нет —
// ровно как было до этого хода.
```
