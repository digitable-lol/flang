# Семья «algebra-domains»: узел algebra с доменами «не больше» и «охрана»

Узел вердикта «разбором по случаям» на носителе `algebra` сверщик проигрывает в
пяти доменах цели (`проиграть_узел_algebra`): неотрицательность, тождество,
**порядок «не больше»**, **охрана «если У то Ц иначе да»**, булева цель. Пробы
этой семьи — цели ловушки проверки 1 (`tests/trap/kinds.tsv`) для двух выделенных
доменов.

## Что здесь лежит

| файл | класс | код | что стережёт |
|---|---|---:|---|
| `head.{flang,record}` | честная | 0 | «Голова строки» дословно из `flang/proof/map/sources.flang` (К3): `(длина результат) не больше 1` — домен порядка, по телу случая (`""` — длина 0; `г` — головной знак). Запись напечатана ядром как есть |
| `guard.{flang,record}` | честная, **запись правлена руками** (не печать ядра) | 0 | тип «Д», «Хорошее», «Левое хорошее» дословно из `flang/test/fixtures/ohrana-daet-fakt.flang`, БЕЗ теоремы: `если («Хорошее» от дерево) то результат иначе да` — домен охраны, конъюнкт `«Хорошее» от л` найден в развёрнутой по конструктору охране. Шапка — ядра; у посылки «Пусто» правило заменено на «разбор цели по условию» (ядро печатает «вычисление замкнутой цели» — см. ниже); пометка стоит и в `tests/trap/kinds.tsv` |
| `corrupt/head-lies.{flang,record}` | подделка | 3 | тело случая `то соединить г с г` (длина 2): узел не проигран, названо «случай «голова и хвост»: «2» не больше «1» — правилами ядра не выводится» |
| `corrupt/guard-lies.{flang,record}` | подделка | 3 | тело случая `то не («Хорошее» от л)`: названо «среди конъюнктов охраны … нет обещанного» |
| порчей строки записи в прогоне | подделка | 1 | посылка «пусто» убрана — покрытие суммы не сходится |

Ложь у обеих подделок — в ИСХОДНИКЕ (шапки записей пересняты ядром на лживом
исходнике, блок утверждения — честный): узел, который сверщик не смог
проиграть, — третий исход с названным случаем, а не приёмка и не отказ.

## Узел со смешанными правилами посылок

Ядро печатает у `guard.flang` посылку «Пусто» с правилом «вычисление замкнутой
цели» (цель ветви — `если да то да иначе да`), а «Узел» — «разбор цели по
условию». Такой узел со СМЕШАННЫМИ правилами приём оставляет вне (`вне приёма
сверщика 1`, код 3): домен охраны требует «разбор цели по условию» у каждой
названной посылки. В корпусе тот же узел (`ohrana-daet-fakt.record`)
проигрывается только потому, что при теореме база закрыта шагом автора
(`правило «»`). Честная запись здесь несёт у «Пусто» правило «разбор цели по
условию» — сверщик его проверяет по существу (`в_то` = `да`), и это не ложь о
программе, а расхождение имени правила у ядра. Поэтому цель этого вида в ловушке —
НЕ вывод ядра; узел со смешанными правилами посылок описан в задаче
[6204](../../../../../../tasks/6204-a-node-with-mixed-premise-rules-is-left-outside-the-checker.md).
