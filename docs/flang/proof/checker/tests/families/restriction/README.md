# Семья «ограничение»: «таких что» и допущения теоремы (ADR-0026 К5)

Ячейка К5 кластера 6202/6203 (10 сентября 2026, ветка `r/a-k5` от `gh/dev
c96a7f2bd`). Контракт — `ПЕРЕДАЧА/stack-B/kontrakt-kvantory.md` §К5:

| где в исходнике | строка записи | где в записи |
|---|---|---|
| `для всех н таких что P обеспечивает …` | `таких что ⟨P⟩ строка N` | сразу под `для всех «н» строка N` |
| теорема: `дано н: T таких что P` | `дано «н» строка N`, затем `допущение ⟨P⟩ строка N` | в теореме |
| теорема: `дано P` (гипотеза) | `допущение ⟨P⟩ строка N` (строки `дано «…»` нет) | в теореме |
| шаг `по предположению`, закрытый допущением J | суффикс ` допущение J` у строки шага | — |

Что делает сверщик: ограничение постусловия и каждое допущение сличает с
исходником как терм; номер строки и порядок допущений сличает разметка теоремы
(исходник даёт метку «допущение N»); у шага с ` допущение J` проверяет, что J
есть среди допущений записи. Сам вывод цели из допущения сверщик не
переигрывает — место на слове ядра, как у всякого «по предположению»; поэтому
честные записи здесь дают код 3, а не 0.

Строки нет при ограничении или допущении в исходнике — код 1 всегда: сегодняшнее
ядро такой программы не пропускает, и «проверено» без строки не выдаётся.
Прежде такое ограничение сверщик отбрасывал молча: запись матрицы ADR-0026 З10
(принцип без ограничения над ограниченным квантором) проходила кодом 3.

кванторов); шапки посчитаны по файлу тем же счётом, что сверяет `сверить_шапку`.

## Чего здесь нет

- Ограничение в свободном утверждении (`утверждение … для всех н: T таких что P`)
  — ячейка К3.
- Вывод цели из допущений «при фактах» сверщик не переигрывает (новых законов
  арифметики К5 не вводит; `н > 0 ⇒ н − 1 ≥ 0` — ведро Е, ADR-0027).
- Печать ядра после партии — сличить с этими записями.
