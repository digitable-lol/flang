# Семья «прогон-индукция»: чем закрывается утверждение о прогоне

Основание — [ADR-0032](../../../../../../adr/0032-one-missing-rule-and-three-other-logics.md)
§3.1. Соседняя семья [`прогон`](../run/README.md) сверяет строку
`прогон «Ф» шаг «Ш» строка N` с исходником. Здесь — то, как ядро закрывает само
утверждение о прогоне: индукцией по списку свёртки (правила ведомости Инд2 и Инд3).

## Что лежит

| файл | чем снят | что показывает |
|---|---|---|
| `letters.фп` | рукой | тот же малый прогон, что в семье «прогон»: шаг «В ящик», прогон «Все в ящик» — свёртка по списку писем, и свободное утверждение о ней |
| `letters.record` | `flang check … --proof --записать` | запись без строки «прогон»; вердикт носит правило «цель есть допущение» |

`bootstrap/flang check --proof` на `letters.фп` отвечает «утверждений 3: доказано
3», и свежая печать ядра несёт в блоке `вид statement` строку

```
  прогон «Все в ящик» шаг «В ящик» строка 16
```

сразу под связываниями. Лежащая здесь `letters.record` этой строки не несёт —
`diff` с новой печатью показывает ровно эту разницу.

## Чего здесь НЕТ и почему

**Ходов базы и шага в записи нет.** Первичных ходов у сверщика ровно тринадцать,
и список закрыт (`checker.c`, `ход_шага`); ход, которого он не знает, роняет
ЧЕСТНУЮ запись кодом 1, а не оставляет её на слове ядра. Поэтому ядро не печатает
ходов индукции по прогону, пока сверщик их не переигрывает: сначала приём в
сверщике, потом печать в ядре.
