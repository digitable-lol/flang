# Почему в пяти пробных программах остался комментарий

В дереве комментариев в `.flang` не пишут; `scripts/guards/no-comments-guard.fscript`
стоит в `.githooks/pre-push` и краснеет на любом файле, где строк с `//` стало больше,
чем записано в `scripts/ledgers/no-comments-debt.tsv`. Пробные программы сверщика
подчиняются тому же правилу, и записи (`*.record`) при них перевыпущены по исходникам без
комментариев: запись пришпилена к байтам исходника (число строк, число знаков, два
отпечатка, SHA-256), поэтому снятие комментариев перевыпускает и её.

Пять файлов держат по одному комментарию, и это не остаток, а предмет пробы:

| файл | что прячет комментарий |
|---|---|
| `programs/note-instead-of-postcondition.flang` | текст постусловия, которого в коде нет |
| `programs/intermediate-step-by-note.flang` | обоснование промежуточного шага |
| `programs/list-body-f4-link-commented-out.flang` | закомментированное звено списка |
| `records/v1-g2/type-behind-a-note.flang` | тип довода, объявленный только в примечании |
| `records/v1-g2/variant-behind-a-note.flang` | «рекурсивность» варианта, которой в объявлении нет |

Сверщик обязан читать строку исходника так, как её читает язык, то есть без хвостового
примечания и без закомментированных строк; каждая из пяти проб подсовывает ему запись, которая
сходится с исходником только если примечание прочитать как код. Убрать эти комментарии значит
убрать саму подделку. Все пять стоят в `scripts/ledgers/no-comments-debt.tsv` с этой причиной
в третьем столбце; прибавить к ним шестой сторож не даст.

Программа `programs/lie-collision.flang` совпадает с `flang/proof/examples/corpus-natural.flang`
по числу строк, числу знаков и обоим многочленным отпечаткам, но не по SHA-256 и не по телу
(`минус` вместо `плюс`). Свободные знаки, которыми подобрано совпадение, лежат в имени модуля,
а не в комментарии.
