# Доверенная база сверщика

Запись доказательства переигрывают две программы: сверщик на C
(`flang/proof/checker/checker.c`) и второй сверщик на Lean
(`flang/proof/checker/second/`). Эта страница отвечает на один вопрос: когда программа
печатает «ПРОВЕРЕНО», чему в этом ответе приходится верить, а что доказано.

Образец — CompCert: доказанная часть названа теоремой, недоказанная перечислена
поимённо. Строка таблицы стоит в одном из трёх состояний:

- **доказано** — утверждение проверено ядром Lean, без `sorry` и без своих аксиом;
- **пробы** — теоремы нет, есть прогон, который краснеет при поломке, и он назван;
- **на веру** — ни теоремы, ни прогона, который ловил бы ошибку именно здесь.

## Что доказано об ответе «ПРОВЕРЕНО»

Опорная программа — второй сверщик. Его ответ — функция `«исход» («сверить» …)`
(`flang/proof/checker/second/Checker.lean`). `«сверить»` режет запись на части
(`«нарезать»`) и склеивает суды частей по списку `«Нарезка».«суды»`; изменяемого состояния
в ней нет. Теоремы об ответе — `flang/proof/checker/second/Verified.lean`:

| теорема | что следует из кода 0 |
|---|---|
| «проверено-по-частям» | принят каждый суд записи: планы, тотальности, шапка, каждое утверждение, круги ссылок, места строк, снятия, категорные теоремы и их полнота; бед привязки нет |
| «проверено-привязка» | в шапке стоит SHA-256 байтов исходника; строк и знаков столько, сколько в исходнике; утверждений столько, сколько обещает шапка и сколько в исходнике постусловий и высказываний; ни одна теорема исходника не замолчана |
| «проверено-шапка-и-планы» | каждая строка шапки по форме печати; оглавление таблиц — ровно таблицы исходника; каждый план принят путём с теоремой «план-по-исходнику» |
| «проверено-тотальности» | каждый блок тотальности принят, у каждой функции с блоком есть ранг зовов; при двух посылках о языке зовы между функциями с блоками фундированы |
| «проверено-утверждения» | каждое утверждение с вердиктом «доказано» принято названным путём; путь блоком `вывод` даёт истинность цели в модели: цель верна в каждом мире, где держится окружение |
| «проверено-места-и-снятия» | строки записи стоят на своих местах; если блоки снятия есть, каждый принят, место не записано дважды, и их столько, сколько мест вызова под «требует» |
| «проверено-счёт» | на слово не взято ничего; либо доказано хоть одно утверждение, либо утверждений нет, а секции есть |
| «реестр-обоснован» | каждое имя реестра доказанного — блок записи, принятый судом с реестром, где этого имени ещё не было: утверждение не может опереться на себя |

Аксиомы, на которых стоят эти теоремы, печатает сборка (`#print axioms` в конце
`Verified.lean`).

Теорема «проверено-утверждения» — не «каждое утверждение записи истинно». Истинность
цели она даёт только пути блоком `вывод`, который принят приёмкой модели
(`flang/proof/lean/Acceptance.lean`, теорема «состоятельность»). Остальные пути названы
в заключении своей приёмкой: что из неё следует, говорит теорема пути в `Paths.lean`,
`Goals.lean`, `Canon.lean`, а у путей без модели — ничего. Их перечень и состояние —
`flang/proof/tables/lean-soundness-debt.tsv`, сторож `bootstrap/flang run-script
lean-soundness:check`.

| компилятор C | `cc` | на веру | — |

Две оговорки к строке «доказано».

Блоки снятия. Запись без единого блока снятия оба сверщика принимают: теорема
«проверено-места-и-снятия» говорит о снятиях только при непустом наборе, а сверщик на C
печатает число «мест вызова без блока снятия» в строке ответа. Запись ядра, снятая до
появления блоков снятия, остаётся «ПРОВЕРЕНО» с этим числом.

Вердикт. «ПРОВЕРЕНО» значит: всё, что запись числит доказанным, переиграно. Утверждение
с вердиктом «нет вердикта» ответ не роняет; сколько доказано, названо в строке ответа.

## Как связаны два сверщика

Теоремы — о втором сверщике. Сверщик на C с ними связан прогонами, а не выводом:

| прогон | что сличает |
|---|---|
| `bootstrap/flang run-script checker:second` | коды обоих на каждой записи проб и подделок, у которой есть исходник — по строке «исходник» либо рядом с записью |
| `bootstrap/flang run-script checker:second-both` | испорченную копию отвергают оба |
| `bootstrap/flang run-script checker:second-examples` | коды обоих на записях, которые ядро даёт по каждому файлу `docs/examples` и `flang/stdlib` |
| `bootstrap/flang run-script checker:check` | пробы на подлог сверщика на C |
| `make -C flang/proof/checker сверщик-san` | сборка под `-fsanitize=address,undefined` для прогона корпуса |

Расхождение кодов — находка. Пока она не починена, она названа строкой
`flang/proof/tables/second-checker-disagreements.tsv`: запись, оба кода, причина. Прогон
красит расхождение, которого в таблице нет, и строку таблицы, которой в прогоне больше нет.

Сколько записей сличено и сколько расхождений названо, печатает сам прогон.

Названные причины двух родов. Второй сверщик отстаёт: место, которое сверщик на C
проигрывает по телу функции, он оставляет на слове ядра и отвечает «НЕ ПРОВЕРЕНО».
Приёмка модели уже ядра: шаг Р8 «разбор цели по условию», где условие ветки сокращает
вложенное «если», она не принимает, и второй сверщик отвечает «НЕ СОШЛОСЬ» на честной
записи. Ни в одной строке таблицы второй сверщик не принял того, что отверг первый.

Прогон `checker:second-examples` даёт второму сверщику 15 минут на запись; запись, на
которой он не уложился или оборвался без вердикта (на длинной записи он переполняет стек),
и запись файла с ввозом считаются как «не взялся целиком» и прогон не роняют.

## Чего не хватает до «сверщик доказан»

1. Пути без модели. Пока путь стоит строкой «нет модели», его приёмка — код, а
   не теорема, и «проверено-утверждения» называет её как есть.
2. Чтение текста. Нарезка записи, чтение исходника и формул сверены на корпусе; теоремы
   «прочитанное — то, что написала печать» нет.
3. Модель значений. Истинность цели — истинность в модели `Model.lean`; что модель
   совпадает с вычислителем языка, не доказано.
4. Сверщик на C. О его коде теорем нет; он держится сверкой со вторым сверщиком.
5. Набор зависимостей. Ключей `--набор` и `--зависимость` у второго сверщика нет:
   запись файла с ввозом оба без набора отвергают, а с набором её судит только первый.
6. Названные расхождения. Каждая строка таблицы расхождений — место, где ответ сверщика
   на C не подтверждён вторым.
