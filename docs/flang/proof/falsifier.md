# Опровергатель: поиск ложных «доказано»

Опровергатель порождает много маленьких программ, спрашивает о каждой ядро
(`flang check --proof --strict`) и сам, не веря ядру, считает каждую программу
на конкретных входах. Если ядро говорит «доказано», а счёт находит вход, на
котором утверждение ложно, — это дыра в ядре. Если ядро принимает обещание
`тотальная`, а счёт упирается в предел шагов, — это тоже дыра.

Код лежит в `flang/proof/probes/falsifier/`:

| файл | что в нём |
|---|---|
| `generator.flang` | случайные выражения и условия, сетки входов, сборка программы для ядра и программы-оракула |
| `templates.flang` | шаблоны программ и их мутанты |
| `run.fscript` | план: пишет программы во временный каталог, зовёт ядро, независимую проверяющую программу и оракул, сводит находки |
| `expected-failures.tsv` | известные находки: причина, ключ в `flang/proof/tables/consistency-violations.tsv`, номер задачи |

## Команды

```sh
bootstrap/flang run-script falsifier:check     # проба: номера 0…59
bootstrap/flang run-script falsifier:forgery   # подлог: номера 40…45 без таблицы известных находок
bootstrap/flang run-script falsifier:hunt      # охота: номера 0…3999
```

Зерно одно — 20261001, поэтому прогон повторим: те же программы, те же
мутанты, тот же порядок. Проба зелёная, пока каждая найденная причина стоит в
`expected-failures.tsv`, и краснеет кодом `FLANG_PROBE_FALSIFIER` на первой
причине, которой в таблице нет. Подлог забывает таблицу и идёт по номерам, где
лежит известная находка (номер 44), поэтому обязан покраснеть; CI (`binary.yml`,
работа `falsifier`) требует этого перед пробой. Охота печатает то же, что
проба, и вдобавок текст первой программы каждой причины, включая известные.

Охоте можно дать отрезок номеров доводами плана:
`bootstrap/flang run-script falsifier:hunt -- 45 245` проверит номера с 45 по
244. Длинную охоту режут на отрезки по 200 номеров: один прогон плана на тысячи
номеров растёт в памяти и замедляется с каждой программой. Временный каталог
берётся в `$FLANG_TMP` (если переменной нет — в `/tmp`) и убирается в конце.

Итог прогона — четыре строки и по строке на каждую причину:

```
falsifier: зерно 20261001, номера 0…59, программ 60, мутантов 222
  ядро: доказало 45, приняло без замечаний 167, отказало 115
  оракул: не смог 0, сторож меры остановил 9
  причин находок 1, новых 0
  · известная <причина> — находок 2; первая: logic/base номер 44, контрпример "", сверщик 1
```

## Что порождается

Номер программы с 0 по 44 идёт по пятнадцати шаблонам, каждый трижды с разным
зерном; дальше чередуются случайное утверждение и случайная функция. Каждый
номер даёт базу и её мутанты; у программы три части: семейство, номер и
мутант — имя мутации, текст для ядра и текст оракула.

**Случайное утверждение** — `утверждение` с одной или двумя переменными
`для всех` (типы `неотрицательное`, `целое`, `число`, `список неотрицательное`,
`список числа`, `строка`), иногда с ограничением `таких что`, и условием из
сравнений, `не`, `и притом`, `или`, `содержит`, `пусто`, `начинается с`.
Числовые выражения — имена, литералы, `плюс`, `минус`, `умножить на`,
`делить на`, `остаток от`, `если`, `длина`, `свёртка`.

**Случайная функция** — `тотальная функция` со случайным телом, постусловием
`обеспечивает` о `результат` и иногда предусловием `требует`.

**Шаблоны** — вычитание под предусловием, рекурсия по числу и по списку с
теоремой индукцией, ссылка на постусловие с `таких что` через `по свойству`,
теорема с гипотезой `дано`, вызов через функцию-значение, разбор суммы типов,
запись и её поля, построение записи, объявленная мера `убывает`, взаимная
рекурсия, вызов под чужим предусловием, `свёртка`, устройство доказательства
(ссылка на чужое свойство, теорема о другом утверждении, чужое предусловие,
циклы вызовов), силлогизм над признаками.

**Мутанты.** У случайных программ: перевёрнутое сравнение, сдвинутая константа,
отрицание утверждения, снятое или перевёрнутое ограничение, снятое или
перевёрнутое предусловие. У шаблонов — свои: снять предусловие, ослабить
гипотезу, поменять местами поля, испортить шаг рекурсии, зациклить через
функцию-значение (прямо, через частичное применение, через вторую функцию,
через список), перенести посылки силлогизма только в теорему. Мутант, совпавший
с базой, отбрасывается.

## Оракул

Для каждой программы собирается вторая программа без `требует`,
`обеспечивает` и теорем. Она перебирает сетку входов вложенными свёртками и на
каждом входе, где выполнены предусловие и ограничение, сама вычисляет функцию и
проверяет постусловие (или условие утверждения). Сетка числа несёт `-0`, `-1`,
дроби, `1e308`, обе бесконечности и не-число; сетка `неотрицательное` — ноль и
верхнюю границу 2⁵³−1; списки и строки — пустые и короткие. Модуль оракула и
функции показа значений (`«Показ число»` и соседние) план приставляет к тексту
оракула, когда пишет файл.

Оракул запускается `flang run --trust --max-steps 150000` под `timeout 30`.
Исчерпанный предел шагов, предел глубины и снятие по времени читаются как
незавершение. Остановка сторожем объявленной меры (`FLANG_MEASURE`) —
не незавершение: так напечатанная программа и обязана себя вести; итог
считает такие остановки отдельно.

Сравнение `не меньше` в оракуле переписано в `не больше` с обменом сторон:
интерпретатор останавливается с `FLANG_PROPERTY` на `не меньше` двух не-чисел
(задача 1137), а `не больше` считает их честно (`нет`).

## Что считается находкой

| вид | условие |
|---|---|
| `false-proof` | ядро ответило «ДОКАЗАНО» с кодом 0, оракул нашёл вход-нарушение |
| `accepted-loop` | ядро не выдало ни одного кода `FLANG_` (или доказало), оракул не завершился |
| `checker-calls-it-a-lie` | ядро доказало, оракул нарушения не нашёл, а независимая проверяющая программа ответила кодом 1 |

О каждой программе, которую ядро доказало или приняло без замечаний,
спрашивается и независимая проверяющая программа `flang/proof/checker/сверщик`
по записи ядра: код 0 — приняла, 3 — не взялась судить, 1 — назвала запись
ложью. Её код печатается рядом с находкой. План собирает проверяющую программу,
только если её файла нет; после правки `checker.c` её пересобирают
`make -C flang/proof/checker`.

**Причина** находки — ключ, по которому находки схлопываются. У шаблона это
`семейство/мутация/вид`, у случайного утверждения и случайной функции —
`семейство/вид/правило ядра`, которым ядро закрыло цель. У
`checker-calls-it-a-lie` — первая строка отказа проверяющей программы, где
имена в ёлочках заменены на `«…»`, а отдельно стоящие числа — на `N`.

## Чего опровергатель не говорит

Сетка конечна: молчание оракула не доказывает, что утверждение верно. Оракул —
тот же интерпретатор `flang run`; ошибку, общую ядру и интерпретатору, он не
увидит. Случайные условия малы (глубина до двух), и ядро доказывает из них
меньшую часть; шаблоны покрывают только перечисленные формы языка.

## Как написан код

Исходники проходят `bootstrap/flang lint` с пределами из `.flangrc`
(ADR-0053): строка не длиннее 120 знаков, ветвления не глубже двух. Тексты
программ и ожидания примеров пишутся блоком `"""` (ADR-0052), списки
переносятся после `[`. Выбор из нескольких условий — список правил
`«Правило»` и `«Первое годное»`, а не лестница `если … иначе если`. Части,
из которых собирается функция-образец, — три небольшие записи
(`«Заголовок»`, `«Контракт»`, `«Код»`), чтобы каждая помещалась в строку
примера.
