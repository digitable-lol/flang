# Формат записи доказательства

Запись доказательства — текст, который `flang check <файл> --proof --record <запись>`
кладёт рядом с программой. Эта страница описывает формат так, как его печатает
печать записи — модуль «Запись доказательства», файл
[`flang/self/proof-record.flang`](../../../flang/self/proof-record.flang), — а не так,
как его читает сверщик `flang/proof/checker/checker.c`. Строки, которые печать не
выдаёт, здесь не описаны; где сверщик читает иначе, сказано в
[последнем разделе](#расхождения-с-checkerc).

Вход печати — функция «Запись доказательства» от списка обязательств, пути исходника,
его текста и номера ядра. Зовёт её «Ведомость по итогам»
(`flang/self/bootstrap/compiler.flang`); номер ядра — «Версия ядра»
(`flang/self/proofterm.flang`), она даёт `2`.

## Соглашения

- Запись — текст UTF-8. Строки соединены знаком `\n`; последний элемент списка —
  пустая строка, поэтому текст кончается переводом строки.
- Отступ — ровно 0, 2 или 4 пробела, как в шаблонах ниже. Табуляций печать не ставит.
- `L` — номер строки исходника. Строки исходника — куски текста, разрезанного по `\n`,
  номера с 1. Номер берётся из поля `span.line` узла («Строка узла записи»); у узла
  без `span` номер `0`.
- `N`, `K` — неотрицательные целые десятичной записью («Число строкой»).
- `«И»` — имя, одетое в ёлочки («В ёлочках записи»): текст имени как есть, без экранирования.
- `⟨Т⟩` — терм в уголках. Терм приходит в одном из трёх видов:
  - **нормальная форма** («Терм записи»): вне строковых литералов и имён в ёлочках
    знаки `(`, `)`, `:` обрастают пробелами, пробеги пробелов сжимаются в один, края
    обрезаются, внешняя пара скобок, обнимающая весь терм, снимается — не больше четырёх
    раз («Ужать записи»). Пример: `( длина элементы ) плюс 1`;
  - **печать узла** («Терм узла записи»): имя, число, `(«Ф» от а и б)`, `(а плюс б)` —
    скобки без пробелов внутри; прочие узлы печатаются пустой строкой;
  - **строка исходника** («Строка исходника записи»): строка `L` с обрезанными краями
    (пробел, `\t`, `\r`).
- `столбец` — номер знака в строке исходника, с 1, как его даёт поле `span.column`.
- Если печать не нашла места или имени, она не пропускает строку, а печатает пустое
  значение: `строка 0`, `«»`. Исключения названы при строках.

## Порядок частей

Функция «Запись доказательства» склеивает части в таком порядке:

| № | часть | печатает | когда |
|---|---|---|---|
| 1 | шапка, 9 строк | «Строки шапки» | всегда |
| 2 | оглавление таблиц | «Строки оглавления записи» | в исходнике есть таблица (§2) |
| 3 | блоки утверждений | «Строки утверждения», порядок — «Утверждения записи» | по блоку на обязательство вида `postcondition` и `statement` |
| 4 | блоки снятия | «Строки снятий записи» | по блоку на обязательство вида `precondition-at-call` |
| 5 | блоки тотальности | «Строки тотальности записи» | по блоку на обязательство вида `totality` |
| 6 | `конец записи` | «Запись доказательства» | всегда |

Обязательства иных видов в запись не попадают. Раздела `план` печать не выдаёт (§7).

## 1. Шапка

«Строки шапки». Девять строк, без отступа, в этом порядке:

| № | шаблон | значение |
|---|---|---|
| 1 | `запись доказательства 1` | версия формата, «Версия записи» |
| 2 | `исходник ПУТЬ` | путь исходника так, как его подали печати; пробелы в пути не экранируются |
| 3 | `строк N` | число кусков текста, разрезанного по `\n`; текст, кончающийся переводом строки, даёт на кусок больше |
| 4 | `знаков N` | длина текста в символах (кодовых точках), не в байтах |
| 5 | `отпечаток A B` | два многочленных отпечатка текста («Отпечаток текста») |
| 6 | `ядро N` | номер ядра, переданный печати |
| 7 | `утверждений N` | число блоков утверждений в части 3 |
| 8 | `отпечаток256 H` | SHA-256 текста, 64 строчные шестнадцатеричные цифры («Отпечаток 256 текста») |
| 9 | `тотальностей N` или пустая строка | число блоков тотальности; при нуле — пустая строка |

Многочленный отпечаток: `h₀ = 7`, затем по каждому символу текста
`h ← (h · m + код символа) остаток от p`. Константы формата:

| | множитель `m` | модуль `p` | функции |
|---|---|---|---|
| `A` | 131 | 1000000007 | «Первый множитель», «Первый модуль» |
| `B` | 137 | 998244353 | «Второй множитель», «Второй модуль» |

Код символа — номер кодовой точки Unicode. У пустого текста оба отпечатка равны `7`,
а SHA-256 — `e3b0c442…b855` (первый вектор FIPS 180-4).

## 2. Оглавление таблиц

«Строки оглавления записи», «Таблицы записи», «Строка таблицы записи».

```
таблиц N
  таблица «Ф» открыта A закрыта B звеньев K
  …
                                   ← пустая строка
```

Таблица — функция без доводов, чьё тело — списочный литерал, где `[` и `]` стоят
каждая одна на своей строке. Обход «Шаг обхода таблиц записи» идёт по строкам исходника:

- строка, начатая от края словами `функция «` или `тотальная функция «`, открывает
  функцию с именем из первых ёлочек и закрывает предыдущую («Закрыть таблицу записи»);
- строка, которая после обрезки краёв начинается с `принимает `, помечает функцию как
  функцию с доводами — такая в оглавление не идёт;
- строка, равная после обрезки `[`, ставит `A` (номер этой строки) и сбрасывает `B`;
  строка, равная `]`, ставит `B`. Учитываются последние такие строки функции.

Функция попадает в оглавление, если у неё нет доводов, `A > 0` и `B > A + 1`.
`K = B − A − 1` — число строк между скобками, а не число звеньев списка.
Строки идут в порядке функций в исходнике; `N` — их число. Нет таблиц — нет и этой части,
вместе с завершающей пустой строкой.

## 3. Блок утверждения

### 3.1. Какие блоки и в каком порядке

«Утверждения записи»: сначала берутся обязательства вида `postcondition` в порядке
списка обязательств, затем каждое обязательство вида `statement` вставляется
(«Вставить блок по строке записи») перед первым блоком, чья строка `L` больше его
строки; при равных строках оно встаёт после.

### 3.2. Строки блока по порядку

«Строки утверждения». Скобки `[ ]` — часть может отсутствовать.

| № | строки | печатает | условие |
|---|---|---|---|
| 1 | заголовок | «Заголовок утверждения записи» | всегда |
| 2 | `  вид K` | «Строки утверждения» | всегда |
| 3 | [кванторы, ограничения, свидетель, прогон] | «Строки кванторов записи» | §3.3 |
| 4 | `  вердикт V` | «Строки утверждения» | всегда |
| 5 | `  теоремы нет` или блок теоремы | «Строки теоремы» | §3.4 |
| 6 | [принцип, объявление, сведения, посылки с ходами] | «Строки принципа», «Строки правил сведения», «Строки посылок» | у обязательства есть вердикт (§3.5) |
| 7 | [`правило`, `по объявлению`] | «Строки объявленного правила» | вердикт `by = declaration` |
| 8 | [обязательства входа по подписи] | «Строки обязательства входа записи» | §3.7 |
| 9 | [цепочки ходов утверждения] | §3.8 | есть вердикт |
| 10 | [обязательства входа из вывода, блок вывода] | «Строки обязательства представимости записи», «Строки обязательства целости записи», «Вывод записи по объявлению» | §3.9 |
| 11 | `конец утверждения` | «Строки утверждения» | всегда |
| 12 | пустая строка | «Строки утверждения» | всегда |

Строки 1, 2, 4, 5, 11 и 12 стоят в каждом блоке по одной, поэтому блок не короче шести строк.

**Заголовок** («Заголовок утверждения записи»):

- `утверждение «И» функции «Ф» строка L` — вид `postcondition`; `И` — поле `name`,
  `Ф` — поле `of`, `L` — строка обязательства (строка `обеспечивает «И»`);
- `утверждение «И» строка L` — вид `statement`; `L` — строка `утверждение «И»`.

**Вид**: `  вид postcondition` или `  вид statement` — поле `kind` как есть.

**Вердикт**: `  вердикт V`. `V` — поле `verdict` записи `discharge`, перенесённое как
есть; нет записи `discharge` — `нет вердикта`. Ядро ставит в это поле слова «Доказано»,
«Доказано при условии», «Сетка терма», «Отвергнуто» (`flang/self/proofterm.flang`):
`доказано`, `доказано при условии`, `сетка`, `отвергнуто`.

### 3.3. Кванторы, ограничения, свидетель, прогон

«Строки кванторов записи» печатает четыре группы подряд, каждую — только если она есть.

**Квантор постусловия** («Строки квантора постусловия записи»), вид `postcondition`:

```
  для всех «а» «б» строка L
```

Одна строка; имена — из поля `forall` (список узлов или один узел) в порядке поля,
через пробел; `L` — строка обязательства. Поле пусто — строки нет.

**Связанные утверждения** («Строка связанной записи»), вид `statement`, по строке на
каждый элемент поля `vars`, в его порядке:

```
  для всех «x» ⟨Т⟩ строка L
```

`L` — строка узла переменной; без места — первая строка ниже заголовка, которая после
обрезки начинается с `для всех ` и связывает имя («Строка связывания записи»). `Т` —
тип, как он написан в строке `L` («Тип связанной записи»): текст после `x: ` (или
`«x»: `) до ` таких что ` / ` such that `; если там дальше следующее связывание, тип
обрывается на последнем ` и ` (` and `) перед ним.

**Ограничения** («Строки ограничений записи») — по строке на каждый элемент поля
`hypotheses`, кроме тех, чья строка совпадает со строкой одного из `proof.given`
(допущения теоремы печатает теорема, §3.4):

```
  таких что ⟨P⟩ строка L
```

`L` — у постусловия строка обязательства, у утверждения строка самого допущения.
`P` — в нормальной форме, из строки `L` («Текст ограничения записи»): текст после
`таких что ` до ` обеспечивает `; без `таких что ` — текст после `дано `. Ограничения
идут после всех строк `для всех`.

**Свидетель** («Строки свидетеля записи») — только если цель (`goal`) вида `exists`:

```
  свидетель «м» ⟨Т⟩ строка L
  после подстановки ⟨Ц⟩
```

`L` — строка цели; `м` — поле `name` цели; `Т` — нормальная форма текста строки `L`
между `а именно ` и `, что `; `Ц` — нормальная форма текста после `, что `, где имя
`м` заменено на `Т` (составной `Т` берётся в скобки, «Вставить вместо записи»).

**Прогон** («Строки прогона записи», «Строка прогона записи») — только вид `statement`,
цель не `exists`:

```
  прогон «Ф» шаг «Ш» строка L
```

Цель — текст после `утверждаем ` в первой строке ниже заголовка утверждения, которая
после обрезки так начинается («Строка под заголовком записи»; поиск обрывается на
следующей строке от края). `Ф` — первая по исходнику функция, чьё имя цель зовёт
(`«Ф» от `) и в чьём блоке есть строка, начатая словом `свёртка ` («Имя прогона записи»);
`L` — строка её заголовка; `Ш` — имя в первых ёлочках после первой ` → ` в тексте этой
свёртки («Имя шага прогона записи»). Нет `Ф`, `Ш` или `L` — строки нет.

### 3.4. Теорема

Поле `proof` пусто — одна строка `  теоремы нет`. Иначе «Строки теоремы»:

```
  теорема «И» строка L
  дано «x» строка L                                 ← по строке на элемент vars
  допущение ⟨P⟩ строка L                            ← по строке на элемент given
  цель строка L
  [шаги | индукция со случаями]
  следовательно доказано да|нет
  [блок вывода теоремы]
```

| строка | поля |
|---|---|
| `  теорема «И» строка L` | `name` и строка теоремы |
| `  дано «x» строка L` | имя и строка элемента `vars` |
| `  допущение ⟨P⟩ строка L` | строка элемента `given`; `P` — «Текст ограничения записи» этой строки («Строки допущений теоремы записи») |
| `  цель строка L` | строка узла `claim` |
| `  следовательно доказано да` | поле `qed` истинно; иначе `нет` |

Все строки `дано` идут перед всеми строками `допущение`, независимо от порядка в исходнике.

**Шаги** («Строки шагов», «Строка шага записи»), если поля `induction` нет — по строке на
элемент `steps`, номера с 1:

```
    шаг N строка L ВИД ОБОСНОВАНИЕ[ допущение H][ ПРИВЯЗКА][ правило «R»]
```

| часть | значение |
|---|---|
| `ВИД` | `закрывающий`, если у шага нет `claim`, иначе `промежуточный` («Вид шага») |
| `ОБОСНОВАНИЕ` | по полю `by.rule` («Обоснование шага»): `hypothesis` → `по предположению`; `property` → `по свойству «И»`; `example` → `по примеру «И»`; `law` → `по закону «И»` и посылки; иное `X` → `правило не названо (X)` |
| посылки закона | `by.from` непуст: ` из ` и посылки через ` и `; посылка вида `line` — `строки N`, иная — `N` («Посылки шага записи») |
| ` допущение H` | поле шага `hypothesis` — число; его ставит «Теорема с допущениями записи» из `discharge.hypothesisSteps` по совпадению строки |
| `ПРИВЯЗКА` | `example` → ` пример строка K`: строка `пример «И»` в блоке функции `of` («Номер примера записи»); `property` → ` свойство строка K`: первая по модулю строка `обеспечивает «И»` (или `для всех … обеспечивает «И»`), а если её нет — строка `утверждение «И»` («Номер свойства или утверждения записи»); не найдено — `0` |
| ` правило «R»` | поле шага `kernelRule`; его ставит «Теорема с правилами записи» из `discharge.stepRules` по совпадению строки |

**Индукция** («Строки индукции автора»), если поле `induction` есть:

```
  индукция по «p» строка L
  случай строка L шагов K
    шаг 1 строка L …
  …
```

`p` — поле `param`, `L` — строка индукции. На каждый случай — строка случая (`K` — число
его шагов) и его шаги, номера шагов в каждом случае с 1.

**Блок вывода теоремы** («Блок вывода теоремы записи») — если все шаги `по закону` и хотя
бы у одного есть посылки. Цель — нормальная форма текста строки `claim` без первого слова.
Шаг `N` блока — шаг `N` теоремы: правило — имя закона, формула — у закрывающего шага цель,
у промежуточного — нормальная форма текста строки шага до ` по закону ` без начального
`затем `. Основание («Основание вывода ведомости записи»): посылок нет — `сам`; одна —
`строка N` для посылки вида `line`, иначе `из N`; две и больше — `из N1 строка N2`, если
вторая вида `line`, иначе `из N1 N2`. Вид первой посылки при двух и больше не печатается,
посылки после второй не печатаются. Форма блока — §3.10.

### 3.5. Принцип, сведения, посылки

Печатаются, если у обязательства есть запись `discharge`.

**Принцип** («Строки принципа») — если у вердикта есть `induction`:

```
  принцип тип «T» по «p» носитель C база N шаг K
  [объявление …]
```

`T` — `type`, `p` — `param`, `C` — `carrier` словом без ёлочек, `N` и `K` — числа
`base` и `step`. Строка объявления («Строка объявления записи») — только если поле
`declared` непусто; стоит сразу под принципом:

- `  объявление D дно N потолок M` — носитель `segment`, `N` и `M` — `segment.низ` и `segment.верх`;
- `  объявление D варианты «В» K «В» K …` — носитель `algebra` и непустой `functor.variants`;
  `K` — `arity` варианта;
- `  объявление D` — прочее.

`D` — значение поля `declared` как есть, например `сумма «Дерево» строка 25` или
`встроенный «неотрицательное»`.

**Сведения** («Строки правил сведения») — если есть `induction`, по строке на элемент
`induction.rules`: `  сведение «R»`.

**Посылки** («Строки посылок», «Строки посылки») — по одной на элемент `discharge.cases`:

```
  посылка «М» вид K вариант «В» вердикт V закрыта B шагов N правило «R»
  [ход-цепочка посылки]
```

`М` — `label`, `K` — `kind` (`base` или `step`), `В` — `variant`, `V` — `verdict` как
есть, `B` — `by` (`term` или `reduction`), `N` — `steps`, `R` — `rule` (поля нет —
`«»`). Все значения переносятся без проверки.

**Ходы посылки** («Ходы посылки») — только при `verdict = доказано`. Строки цепочки — §3.8.

- `by = reduction` («Ходы сведённой посылки записи»): `kind = base`, цель `Т не меньше 0`,
  `Т` — неотрицательный литерал, тело ветви `случай вариант «В»` равно этому литералу:
  ```
      ход цель
      ход 1 развернуть ⟨«Ф» от (вариант «В»)ХВОСТ⟩ строка L ⟨Т⟩
      ход 2 закон «литерал неотрицателен»
      ход конец
  ```
- `by = term`, цель — равенство двух вызовов одной функции `«Г»` от одного довода
  («Ходы равенства записи»): тело ветви совпадает с образцом — четыре строки
  («Ходы тождества записи»):
  ```
      ход цель
      ход 1 развернуть ⟨«Ф» от (КОНСТРУКТОР)ХВОСТ⟩ строка L ⟨ТЕЛО⟩
      ход 2 закрыть тождеством
      ход конец
  ```
  или, если ветвь связывает одну часть `ч` и тело — конструктор с `«Ф» от ч` на её месте,
  восемь («Ходы переписки записи»):
  ```
      ход цель
      ход дано 1 предположение по «ч»
      ход 1 развернуть ⟨«Ф» от (КОНСТРУКТОР)ХВОСТ⟩ строка L ⟨ТЕЛО⟩
      ход 2 развернуть ⟨«Г» от (КОНСТРУКТОР)⟩ строка L2
      ход 3 развернуть ⟨«Г» от (ТЕЛО)⟩ строка L2
      ход 4 замена по дано 1
      ход 5 закрыть тождеством
      ход конец
  ```
- `by = term`, цель `Т не меньше 0` («Свод посылки», «Ходы тела», «Ходы по своду»):
  ```
      ход цель
      [ход дано 1 предположение по «ч»]
      ход 1 развернуть ⟨«Ф» от (КОНСТРУКТОР)ХВОСТ⟩ строка L ⟨ТЕЛО⟩
      ход 2 …
      ход конец
  ```
  Ходы со второго — свод левой части цели: неотрицательный литерал →
  `закон «литерал неотрицателен»`; сумма двух слагаемых, ни одно не сумма →
  `закон «сумма неотрицательных»`, затем свод левого и правого слагаемого; вызов `«Ф»`
  на одном имени `ч` с тем же хвостом доводов → `закрыть дано 1` (и строка `ход дано`).
  Если левая часть цели — имя `х`, ход один: `закрыть требованием «И» строка K`, где `K` —
  первая строка исходника `требует «И» х не меньше 0`. Две разные части, не найденное
  требование или любой другой узел — цепочки нет.

Здесь `Ф` — функция `of`; `КОНСТРУКТОР` — строка случая без первого слова, где ` как `
заменено на ` равным `; `ХВОСТ` — имена доводов со второго, каждый с приставкой ` и `
(«Прочие доводы функции»); `L` — строка тела ветви (строка, следующая за единственной
строкой случая в функции, «Строка ветви записи») либо строка левой части цели; `ТЕЛО` —
тело ветви без слова `то ` либо печать узла левой части цели.

### 3.6. Правило и «по объявлению»

«Строки объявленного правила», при `discharge.by = declaration`, две строки подряд:

```
  правило «R»
  по объявлению да|нет
```

`R` — `discharge.rule`; `да` — поле `byType` истинно.

### 3.7. Обязательство входа по подписи

«Строки обязательства входа записи»: при `by = declaration` и
`rule = ограниченность точным потолком по построению`, по строке на каждый довод подписи
функции `of`, объявленный типом точной сетки («Доводы точной сетки подписи записи»):

```
  обязательство вход «x» ⟨x не больше 9007199254740991⟩ строка L на зовущем
```

`L` — строка `принимает` функции; число — «Точная сетка записи».

### 3.8. Цепочки ходов

Цепочка — строки с отступом 4:

```
    ход цель
    [ход дано 1 предположение по «ч»]
    ход 1 …
    ход 2 …
    ход конец
```

Номера ходов идут подряд с 1; `ход дано` номера не занимает. После посылки стоит цепочка
этой посылки (§3.5). После строк §3.7 стоят цепочки самого утверждения — каждая
печатается, только если у обязательства есть `discharge` и `verdict = доказано`:

| порядок | функция | условие | ходы |
|---|---|---|---|
| 1 | «Ходы тождества утверждения записи» | вид `statement`, `by = declaration`, `rule = тождество после переписки допущением` | `соседи`, `нейтральный ноль` или `вычислить`, затем `закрыть тождеством` |
| 1 | «Ходы правила тождества постусловия записи» | вид `postcondition`, то же правило | первая непустая из «Ходы соседей постусловия записи», «Ходы длины постусловия записи», «Ходы вычисления постусловия записи», «Ходы тождества постусловия записи» |
| 2 | «Ходы по свойству постусловия записи» | вердикт ссылается на свободное утверждение в `props`, либо `by = declaration`, правило иное и ровно один вызов в `calls` | `развернуть`, `факт по свойству`, `закрыть по свойству` |
| 3 | «Ходы разбора цели постусловия записи» | 1 и 2 пусты; правило из списка «Правило разбора цели записи»; тело без `свёртка `, `разбор `, `отобразить `, `→`, тело и цель вместе не длиннее 300 знаков | `развернуть`, `подставить пусть`, затем ходы «Решить цель записи» (не глубже 16) |
| 4 | «Ходы допущением постусловия записи» | 1–3 пусты; `rule = цель есть допущение`; цель без `результат` совпадает с требованием функции | `закрыть требованием` |

Список правил разбора: `разбор цели по условию`, `разбор случаев по внутреннему условию
цели`, `неотрицательность по построению`, `ограниченность точным потолком по построению`,
`начало по построению`, `вхождение по построению`.

**Виды ходов**, которые печать выдаёт (после `ход N `):

| ход | откуда |
|---|---|
| `развернуть ⟨«Ф» от (КОНСТРУКТОР)ХВОСТ⟩ строка L ⟨ТЕЛО⟩` | «Строка развёртки записи», всегда первым ходом |
| `развернуть ⟨ВЫЗОВ⟩ строка L ⟨ТЕЛО⟩` | «Строка развёртки вызовом записи»; `ТЕЛО` — строка исходника `L` |
| `развернуть ⟨«Г» от (Т)⟩ строка L` | «Ходы переписки записи», без тела |
| `закон «И»` | `литерал неотрицателен`, `сумма неотрицательных`, `мера неотрицательна`, `квадрат под оговоркой`, `пустая приставка`, `начало склейки` |
| `закрыть тождеством` / `закрыть истиной` | конец цепочки; `истиной` — «Решить цель записи» |
| `закрыть дано 1` | «Дописать виток» |
| `закрыть требованием «И» строка L` | «Свод посылки», «Ходы допущением постусловия записи» |
| `закрыть по свойству` / `закрыть по свойству по охране ⟨У⟩` | «Ходы леммы записи», «Ходы обещания записи» |
| `факт по свойству «И» строка L вызов ⟨Т⟩` | «Ходы леммы записи», «Ходы обещания записи»; `L` — «Номер свойства записи» |
| `факт по свойству «И» строка L подстановка «x» ⟨Т⟩ …` | «Ходы леммы записи» при свойстве-утверждении («Хвост подстановки записи») |
| `замена по дано 1` | «Ходы переписки записи» |
| `соседи ⟨Т⟩` | «Ходы соседей записи», «Ходы цели утверждения записи» |
| `нейтральный ноль ⟨Т⟩` | «Ходы цели утверждения записи» |
| `вычислить ⟨Т⟩ = ⟨V⟩` | «Ходы вычисления записи», «Строка хода формы записи» |
| `переписать формой ⟨Т⟩ = ⟨Т2⟩ законом «И»` | «Строка хода формы записи», «Ходы длины записи»; законы `Мера склейки`, `Мера прибавления`, `Мера разложения`, `Мера построения`, `Развернуть элемент по номеру`, `Склейка разложения`, `Закон признака`, `Вхождение в выписанный список` |
| `выбор ⟨если У то А иначе Б⟩` | «Решить цель записи» |
| `деление ⟨У⟩` | «Решить цель записи» |
| `связка ⟨и притом⟩`, `связка ⟨или⟩ левая`, `связка ⟨или⟩ правая` | «Решить цель записи» |
| `подставить пусть строка L` | «Подставить пусть в цель записи» |

### 3.9. Вывод по объявлению

«Вывод записи по объявлению» печатается, если вид `postcondition`, есть `discharge`, нет
теоремы, `discharge.cases` пуст и ни одна цепочка §3.8 не напечатана. Он пробует по
порядку «Вывод факта о типе записи», «Вывод разбора записи», «Вывод выписанного разбора
записи», «Вывод отношений или последних мест записи» и берёт первый непустой блок.

Перед блоком стоят обязательства входа, вынутые из его же строк:

- `  обязательство вход «x» ⟨x не больше 9007199254740991⟩ строка L на зовущем` — по строке
  на шаг блока с ` Пред1 ⟨`, кроме правила `ограниченность точным потолком по построению`
  («Строки обязательства представимости записи»);
- `  обязательство вход «x» ⟨x : цел⟩ строка L на зовущем` — по строке на шаг с ` Цел2 ⟨`
  («Строки обязательства целости записи»).

`x` и `L` вырезаются из строки шага по словам: `x` — четвёртое слово без `⟨`, `L` —
седьмое (`Пред1`) или восьмое (`Цел2`) слово.

### 3.10. Блок вывода

Форма, правила и их переигрывание — [блок «вывод»](../../design/proof-object-blok-vyvoda.md)
и модель `flang/proof/lean/Record.lean`. Строки, которые выдаёт печать:

```
    вывод цель ⟨Ц⟩
    вывод N R ⟨Ф⟩ ОСНОВАНИЕ
    …
    вывод конец
```

Номера шагов подряд с 1 («Строка шага вывода записи», «Строки блока вывода записи»,
«Строки вывода снятия записи»). `R` — имя правила одним словом из ведомости
`flang/proof/tables/inference-rules.tsv`; у блока теоремы — имя закона из исходника.
`Ф` — нормальная форма. `ОСНОВАНИЕ` — одно из: `сам`, `строка L`, `из N`, `из N M`,
`из N M K`, `из N строка L`. «Строки блока вывода записи» последним шагом ставит
`Разв2 ⟨Ц⟩ из N строка L`, где `L` — строка тела функции. Блок стоит в трёх местах:
в теореме после `следовательно` (§3.4), в утверждении последним (§3.9), в снятии (§4).

## 4. Блок снятия

«Строки снятия записи», по блоку на обязательство `precondition-at-call` в порядке списка:

```
снятие «И» функции «Ф» зовёт «Г» строка L столбец C
  вид precondition-at-call
  вердикт V
  правило «R»
  [блок вывода | цепочка ходов]
конец снятия
                                   ← пустая строка
```

`И` — имя требования `требует «И»` у вызванной `Г`; `Ф` — функция, где стоит вызов;
`L` и `C` — строка и столбец вызова (`span.line`, `span.column`); `V` и `R` — поля
`verdict` и `rule` записи `discharge` как есть (записи нет — пустые).

Цель снятия («Цель снятия записи»): с позиции `C` строки `L` должен начинаться текст
`«Г» от `; доводы вызова режутся союзом `и` верхнего уровня до непарной `)`
(«Доводы вызова записи»; строковый довод даёт пустой список); их число равно числу
параметров `Г`; формула `требует «И» …` функции `Г` с доводами на месте параметров —
в нормальной форме. Иначе цель пуста и тела у блока нет.

Тело («Вывод снятия записи»): шаги вывода — одна строка `Т1 ⟨Ц⟩ строка K`, если цель
совпадает с требованием `требует` функции `Ф` на строке `K`; `Н1 ⟨Ц⟩ сам` для
`целое не меньше 0`; «Шаги вывода записи» для `имя не меньше 0`. Если последний шаг
заключает цель — блок вывода. Иначе цепочка «Ходы обещания записи»:

```
    ход цель
    ход 1 факт по свойству «П» строка K вызов ⟨ВЫЗОВ⟩
    ход 2 закрыть по свойству
    ход конец
```

— если цель содержит вызов `( «Г» от … )`, у вызванной нет `требует`, число доводов
равно числу параметров и среди её строк `обеспечивает «П» …` есть такая, что формула с
доводами на месте параметров и вызовом на месте `результат` равна цели; берётся первая.
`K` — «Номер свойства записи» имени `П`. Иначе тела нет.

## 5. Блок тотальности

«Строки блока тотальности», по блоку на обязательство `totality` в порядке списка.
Вид — поле `mode`: `structure`, `step`, всё прочее — композиция.

```
тотальность «Ф» строка L
  вид composition
  зовёт «Г» строка K тотальна            ← вызов функции
  зовёт примитив «п»                     ← вызов kind = primitive
  самовызова нет
  конец тотальности
```

```
тотальность «Ф» строка L
  вид structure
  убывает аргумент N «a»
  дно тип «T»
  виток строка K «Ф» от ТЕКСТ
    часть «ч» поле «п» варианта «В»
  самовызов строка K
  конец тотальности
```

```
тотальность «Ф» строка L
  вид step
  убывает аргумент N «a»
  дно тип «T»
  виток строка K «Ф» от ТЕКСТ
  мера не меньше 0 тип «T»
  самовызов строка K
  конец тотальности
```

| строка | поля обязательства |
|---|---|
| заголовок | `name`, строка обязательства |
| `зовёт …` | элементы `calls` по порядку: `kind = primitive` → имя; иначе имя и строка узла |
| `убывает аргумент` | `arg` (номер довода с 1), `argname` |
| `дно тип`, `мера не меньше 0 тип` | `floor` |
| `виток строка` | элемент `loops`: `line`, `argtext` — текст довода как есть |
| `часть … поле … варианта` | у `structure`: `part`, `field`, `variant` того же витка, сразу под ним |
| `самовызов строка` | `selfcall` |

После блока пустой строки нет.

## 6. Конец записи

`конец записи` и пустая строка — текст кончается `конец записи\n`.

## 7. План

Раздела

```
план «П» строка L
  разрешено «Р» строка L
  поручение «Р» функции «Ф» строка L
  конец плана
```

не печатает ни `flang/self/proof-record.flang`, ни другой файл `flang/self/`, ни
компилятор: строк `разрешено «` и `поручение «` в печатающем коде нет. Раздел есть только
в рукотворных записях семьи `flang/proof/checker/tests/families/plan/` и в сверщике
`checker.c` (`сверить`, `МЕСТА_СТРОК`), который отсекает его по строке, начатой
`план `, раньше всех прочих разделов.

## Расхождения с `checker.c`

Сверщик узнаёт строку записи по закрытому списку образцов `ОБРАЗЦЫ` (`знакомая_строка`,
`скелет`, `по_образцу`: имя в ёлочках и терм в уголках сжимаются в один знак, `#` —
число, `.` — одно непустое слово, `…` — любой хвост), место строки — по таблице
`МЕСТА_СТРОК`, целость блока — `сверить_целость_блока`, шапку — `сверить_шапку`.
Против печати:

**Печать выдаёт, сверщик не узнаёт или читает иначе**

1. `  вердикт сетка`, `  вердикт отвергнуто` — в `ОБРАЗЦЫ` только `доказано`,
   `нет вердикта`, `доказано при условии`; запись с такой строкой — «строка не узнана».
2. `посылка … вердикт V …` с `V` иным, чем `доказано`: `ОБРАЗЦЫ` знает `доказано` и
   `нет вердикта`; `доказано при условии`, `сетка`, `отвергнуто` не узнаются.
3. `  вердикт ` с пустым значением в снятии без `discharge`: печать снятия, в отличие от
   печати утверждения, не подставляет `нет вердикта`, а `ОБРАЗЦЫ` строки `вердикт` без
   слова не знают.
4. Второе и следующие `  таких что` подряд (утверждение с двумя ограниченными
   связываниями; постусловие с двумя элементами `hypotheses`): `МЕСТА_СТРОК` требует
   над `таких что ` строку `для всех `, а печать ставит все ограничения после всех
   кванторов; `сверить_высказывание` сам при этом ждёт их подряд, по одному на строку
   исходника.
5. Порядок `дано` / `допущение` в теореме: печать ставит все `дано`, затем все
   `допущение`; `сверить_разметку_теоремы` сравнивает с `разметка_теоремы`, где метки идут
   по строкам исходника (`дано L1, допущение L1, дано L2`). Теорема, где `дано … таких что`
   или `дано P` стоит выше другого `дано`, не сходится. Строка `дано а: … и б: …` даёт в
   записи два `дано` с одной строкой, а в разметке — одну метку.
6. `ядро N`: печать переносит номер ядра; `ОБРАЗЦЫ` знают только `ядро 2`.
7. Слова, которые печать переносит без проверки, а образец требует одним непустым словом
   (`.`): `носитель C` в принципе, `вид K` и `закрыта B` в посылке, имя правила в шаге
   вывода (у блока теоремы — имя закона из исходника). Пустое поле или имя с пробелом —
   «строка не узнана»; `разобрать_шаг_вывода` к тому же берёт правило третьим словом.

**Сверщик узнаёт, печать не выдаёт**

8. `цель ⟨⟩`, `цель строка # ⟨⟩`, `шаг # ⟨⟩ …`, `шаг # строка # ⟨⟩ …` — у печати
   терма рядом с номером строки нет.
9. `посылка … вердикт нет вердикта …` — у посылки печать всегда ставит слово ядра.
10. `план «» строка #`, `разрешено «» строка #`, `поручение «» функции «» строка #`,
    `конец плана` и строки `МЕСТА_СТРОК` для них — раздела не печатает никто (§7).
11. Ходы `замена по дано N обратно`, `переписать по свойству «…»`, `развернуть ⟨…⟩` без
    номера строки (`ход_развёртки`, ветвь `где < 1`), законы формы `Склейка ассоциативна`,
    `Пустая склейка слева`, `Пустая склейка справа` (`закон_формы_есть`).

**Шапка**

12. `сверить_шапку` читает строки по местам 1, 3, 4, 5, строку 2 — `привязка_путём`,
    строку 7 — `сверить`; `отпечаток256 ` и `тотальностей ` ищутся по началу в любом месте
    шапки. Строки 6, 8, 9 по местам не проверяются; пустая девятая строка проходит
    образцом `""`, который узнаёт пустую строку в любом месте записи.
