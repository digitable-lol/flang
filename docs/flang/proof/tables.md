# Таблицы доказательного слоя: `flang/proof/tables/`

Пять таблиц, у каждой первая строка — заголовок, разделитель — табуляция,
комментариев нет. Их читают программы; прозу о строках держат страницы `docs/`.

## `inference-rules.tsv` — правила вывода

| колонка | что в ней |
|---|---|
| `name` | имя правила, единственное в таблице (Н1, О✗, Разв3, …); им же названа лемма в `flang/proof/lean/Rules.lean` |
| `family` | семейство: Н Кон П Пред О Д С СС В Ч Разв Т Р Инд Тожд Э Св Пр М Кол |
| `kind` | `rule` либо `ban` — запрет, которым не выводится ничего |
| `kernel-rule` | имя, которое ядро кладёт в поле `rule` записи; несколько — через `\|`; `—` — в поле `rule` не попадает |
| `anchor` | `proof-kernel.flang:СТРОКА «Имя функции»` — место ядра, которое это и делает |
| `status` | как ядро относится к тексту решения: `code`, `code-wider`, `code-stricter`, `code-narrower`, `not-in-adr`, `not-in-code` |

Посылки, заключение, побочные условия и категорная запись каждого правила —
[правила вывода](inference-rules.md).

Читатели: `flang/proof/tables-guard.fscript` (проверки С-1, С-2, С-4), `flang/proof/lean/run.fscript`
(лемма на каждую строку), `scripts/four-coverages.fscript` (покрытие формализации),
`flang/scripts/kernel-lines-to-trust.fscript` (число строк), `scripts/report-provenance.fscript`
(версия семантики).

`inference-rules.digest` — sha256 таблицы, «версия семантики» в шапке вердикта.
Правка таблицы без пересъёма красит С-4; переснять — отдельное действие руками:

```sh
sha256sum flang/proof/tables/inference-rules.tsv | cut -d' ' -f1 > flang/proof/tables/inference-rules.digest
```

## `segments.tsv` — имена встроенного отрезка

| колонка | что в ней |
|---|---|
| `name` | как отрезок [0, 2⁵³−1] пишется в подписи `принимает х: имя` |
| `floor` | нижняя граница, литерал |
| `ceiling` | верхняя граница, литерал; равна «Точному потолку» ядра |
| `integrality` | `integer` либо `fractional` |

Проверка С-5 сличает список с «Названо натуральным» ядра и с `НАТУРАЛЬНОЕ[]`
проверяющей программы на C в обе стороны. Точные десятичные типы, `вес` и
`целое` — не этот отрезок и в таблицу не входят.

## `abilities.tsv` — умения ядра

| колонка | что в ней |
|---|---|
| `number` | номер умения (У1 … У28); под этим номером умение описано в `docs/flang/proof/SPEC.md` |
| `rule` | правило ядра, которому умение принадлежит |
| `anchor` | подстрока, обязанная стоять в `flang/self/proof-kernel.flang` |
| `evidence` | имя функции-улики в `flang/proof/map/abilities.flang` |

Читает `scripts/guards/kernel-abilities-guard.fscript`: ядро, описание и улики
обязаны сходиться на каждой строке.

## `lean-acceptance-debt.tsv` — приёмы сверщика без приёмки Lean

| колонка | что в ней |
|---|---|
| `name` | имя приёма `шаг_вывода` проверяющей программы на C |
| `task` | номер задачи, которая этот долг закрывает |
| `reason` | почему приёма нет в `flang/proof/lean/Acceptance.lean`, одной строкой |

Читает `flang/proof/lean/rules-guard.fscript` (ярлыки `lean-rules:check`,
`lean-rules:census`, `lean-rules:numbers`, `lean-rules:forgery`; ADR-0064): каждый
приём сверщика обязан стоять либо в закрытом списке `«правила»` приёмки, либо
строкой здесь; строка о приёме, который в приёмку уже вошёл или которого в сверщике
нет, красит сторож так же, как приём без строки. Список закрытый в обе стороны:
«долг уплачен» видно по красному, а не по памяти. Таблица пуста: все приёмы сверщика
в приёмке.

## `lean-soundness-debt.tsv` — долг состоятельности опорного сверщика

| колонка | что в ней |
|---|---|
| `path` | путь приёмки второго сверщика на Lean: имя судящей функции в ёлочках (`«судитьТотальности»`, `«Суд».«выводом»`, …) либо род хода теоремы (`ход развернуть`) |
| `status` | `доказано` — путь судит приёмка модели и о нём есть теорема (её имя — в `reason`); `нет модели` — модели у пути нет, теоремы сформулировать нечем; `sorry` — теорема названа (её имя в `path`), доказательства нет |
| `reason` | почему путь в этом состоянии, одной строкой |

Читает `flang/proof/lean/soundness-guard.fscript` (ярлык `lean-soundness:check`;
ADR-0193): каждый путь приёмки второго сверщика (функции `судить…`, `проиграть…`,
`прогонР`, `крюкиПоТелу`, `кольцоТочногоЦелого` в `flang/proof/checker/second/*.lean` и
роды ходов из `Moves.lean`) обязан стоять строкой; строка о пути, которого нет, —
красно; каждый `sorry` в `flang/proof/lean/*.lean` и `flang/proof/checker/second/*.lean`
обязан стоять строкой `sorry` с именем своей теоремы, и строка `sorry` без `sorry` в
файлах — уплаченный долг, тоже красно. Строка `доказано` обязана назвать в причине
теорему (`теорема «…»`), и теорема с этим именем обязана стоять в файлах модели либо
второго сверщика. Строк `нет модели` не больше потолка, записанного в самом стороже
(функция «Ceiling»): новый путь без модели проходит только правкой потолка. Так долг не
растёт молча ни новым путём, ни новым `sorry`. Проба порчи —
`bootstrap/flang run-script lean-soundness:forgery` (четыре подлога на копиях прочитанного).
