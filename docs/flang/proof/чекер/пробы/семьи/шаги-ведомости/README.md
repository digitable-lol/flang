# Семья «шаги ведомости»: ход пишет человек, ядро проверяет

Задача [3464](../../../../../../tasks/3464-theorem-steps-name-a-ledger-rule-and-its-premises.md),
шаг 4 плана владельца: **доказательство пишет человек, ядро только проверяет**.
Основание — ведомость [ПРАВИЛА-ВЫВОДА.tsv](../../../../ПРАВИЛА-ВЫВОДА.tsv);
новых правил ведомости и новых приёмов сверщика здесь ноль.

## Зачем семья

До неё шаг теоремы называл обоснование (`по свойству`, `по предположению`), а
правило выбирало ядро — перебором. Теперь шаг называет **правило ведомости и
посылки**: `затем а не больше 10 по закону «О10» из 1 и 2`. Ядро не ищет, а
проверяет применимость названного правила к названным посылкам.

## Измеренное основание

Цель «результат не больше десяти» при допущениях «а не больше б» и
«б не больше 10» ядро САМО не берёт: без шагов — «объявлено, не доказано»,
код 3; с теоремой `по предположению` — `FLANG_PROOF_STEP: цель не сведена к
2 предусловию функции`, и в отказе стоит `известно:` с ОБОИМИ предусловиями.
То есть обе посылки у ядра в руках, а сложить их в цепочку оно не умеет:
середина цепочки — это выбор имени, а не вычисление. Называет её человек.

## Что здесь лежит

| файл | что это |
|---|---|
| `шаги.flang` | три теоремы с явными шагами: **О1 → О1 → О10 → Разв2** (порядок через названную середину), **Н3 → Н3 → Н5 → Разв2** (сумма двух `нат`), **Н1 → Разв2** (литерал) |
| `шаги.запись` | честная запись: у каждого утверждения блок `вывод` теми же строками, какими его печатает ядро |

## Мерило

Честная запись — код 0, места сняты со слова ядра («Выводов факта о типе
проиграно заново»), долг ноль. Подделки собираются порчей одной строки записи
прямо в `прогон.sh` (раздел «семья „шаги ведомости“»): чужая посылка,
пропущенный шаг, правило не по форме — код 1, и у каждой своя названная
причина. Те же подделки отвергает и ЯДРО: на `О10 из 1 и 1` оно отвечает
«О10 — середина не сходится: шаг 1 кончается «б», шаг 1 начинается «а»».
