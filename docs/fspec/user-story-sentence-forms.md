# Пользовательская история: девять закреплённых образцов предложений

Аналитик пишет требование словами — «как менеджер зала, я хочу, чтобы скидка не
превышала 30, чтобы кассир не отдал товар ниже себестоимости». Чтобы такое
требование доехало до ядра доказательств, а не осталось комментарием, у него
должна быть **закреплённая форма записи**: закрытый набор образцов предложений,
где каждый образец переводится в заданную часть программы, а всё, что в образцы
не попало, получает названный отказ.

Набор образцов, переводчик и проба лежат в `flang/proof/probes/story/`. Приём тот
же, что у силлогизма ([ADR-0050](../adr/0050-a-reasoning-is-written-as-declared-words-and-fixed-sentences.md)):
**автор объявляет слова, язык не угадывает морфологию.**

## Девять образцов

Текст истории читается предложениями: предложения отделяются точкой, переводы
строк считаются пробелами. Первое слово предложения — его образец.

| образец предложения | во что превращается | отказ, если не вышло |
|---|---|---|
| `Роль: <слово>` | объявление роли в словаре | — |
| `Величина: <им. форма>, <форма после «при»>` | объявление величины в словаре | `у величины «X» объявлена одна форма: нужны две — «Величина: X, <ещё форма>»` |
| `История: <имя>` | имя функции | `у истории нет имени` |
| `Как <роль>` | вход `«кто»: «Роль»` и `требует «как <роль>» «кто».«<роль>»` | `у истории нет роли`; `роль «X» не объявлена: впишите её строкой «Роль: X»` |
| `Хочу <величина> не больше <число>` | `обеспечивает «хочу: …» результат не больше <число>` | `желание «…» не переводится в цель`; `величина «X» не объявлена` |
| `Хочу <величина> не меньше <число>` | то же с `не меньше` | то же |
| `Чтобы <зачем>` | строка отчёта о истории (в программу не едет) | `у истории нет «зачем»: впишите его строкой «Чтобы <зачем>» или прочерком «Чтобы —»` |
| `При <величина> не меньше <число>` | `требует «при: …» «<величина>» не меньше <число>` | `условие «…» не переводится: образец — «При <величина> не меньше <число>»`; `условие … о величине «Y», а желание — о «X»` |
| `Тогда при <форма величины> <число> ответ <число>` | `пример` с входом и ожиданием | `пример «…» не считается: образец — «Тогда при <форма> <число> ответ <число>»`; `форма величины «…» не та: ждали «…»` |

Форма величины после `при` объявляется второй формой в словаре именно затем,
чтобы «Тогда при скидке 40» читалось без угадывания падежа: правило морфологии
здесь не выводится, а берётся из словаря.

## Что получается на выходе

```
$ bootstrap/flang io flang/proof/probes/story/run.fscript --plan Translate -- flang/proof/probes/story/texts/discount-cap.txt
модуль «Story»

объект «Роль»
  «менеджер зала»: признак

тотальная функция «потолок скидки»
  принимает «кто»: «Роль», «скидка»: число
  возвращает число
  требует «как менеджер зала» «кто».«менеджер зала»
  требует «при: скидка не меньше 0» «скидка» не меньше 0
  обеспечивает «хочу: скидка не больше 30» результат не больше 30
  пример «тогда вход 40 ответ 30»
    дано «кто» равно запись «Роль» с «менеджер зала» равным да
    дано «скидка» равно 40
    ожидается 30
  если «скидка» не больше 30
    то «скидка»
    иначе 30
```

Приговор об этой программе выносит ядро, а не переводчик:

```
$ bootstrap/flang io flang/proof/probes/story/run.fscript --plan Judge -- flang/proof/probes/story/texts/discount-cap.txt
История: потолок скидки.
Как менеджер зала.
Хочу скидка не больше 30.
Чтобы кассир не отдал товар ниже себестоимости.
При скидка не меньше 0.
Тогда вход 40 ответ 30.
ЗАПИСАНО: цель «хочу: скидка не больше 30» доказана ядром обо всех входах
ядро: ДОКАЗАНО — утверждений 1: доказано 1, условно 0 …
```

## Ложная история краснеет

Это главное, ради чего образцы без пробы не считаются сделанными. История
`texts/the-shown-case-does-not-agree.txt` обещает «скидка не больше 30» и
показывает «Тогда при скидке 40 ответ 40»:

```
НЕ ЗАПИСАНО: «тогда» истории не сходится с её «хочу» — FLANG_EXAMPLE: пример
«тогда вход 40 ответ 40» функции «потолок скидки с примером против»: значение не
совпало с ожидаемым: ожидалось 40, получено 30
```

Отвергает её не сверка строк, а `flang check … --proof --strict` над
напечатанной программой: тот же путь, которым проверяется любая спека в `fspec/`.

## Как позвать весь набор

```sh
bootstrap/flang io flang/proof/probes/story/run.fscript --plan Binary --max-steps 40000000
```

Таблица ожиданий — `flang/proof/probes/story/expected.tsv`: строка на текст, с
кодом возврата и словом, которое обязано стоять в приговоре. Текст, лежащий в
`texts/` без строки таблицы, набор называет сам.

## Чего здесь нет

**Поверхности языка.** `bootstrap/flang check` на истории, записанной словами
языка (`история «…» / как «…» / хочу «…»`), по-прежнему падает на первом слове:
`история`, `как`, `хочу` лексеру неизвестны. Образцы живут в пробе, а не в
`flang/self/lexer.flang` и `flang/self/parser.flang`; чтобы они оказались в
двоичном, нужна перепечатка самосборной части. Это остаток задачи 8545.

**Цели, которую ядро может ОТВЕРГНУТЬ по сути, а не примером.** Образец берёт
одно `Хочу` на историю, и тело функции задаётся тем же образцом, поэтому цель
всегда доказуема. Ложь ловится примером («Тогда»), а не противоречием двух
желаний: для второго нужна форма `Ещё хочу …`, которой в наборе нет.

**«Зачем» в программе.** `Чтобы <зачем>` доезжает до отчёта, а не до ядра: связи
между историями в языке пока нет.
