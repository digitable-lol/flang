# Таблица поведения правила

Бизнес-правило — «кто может читать отчёт», «положена ли скидка» — в flang
записано функцией с постусловием и примерами. Если правило поменяли вместе с
его постусловием и примерами, все проверки остаются зелёными: спецификация
поменялась вместе с кодом. Что поменялось поведение, видно только по исходам.
Таблица поведения показывает исходы правила на его входах, а дифф таблицы —
только те строки, где исход стал другим.

Решение и его границы — [ADR-0118](../adr/0118-a-rule-is-reviewed-by-the-table-of-its-behavior-and-its-diff.md).
Все прогоны ниже запускаются из корня дерева; файлы лежат в
[`docs/examples/behavior/`](../examples/behavior).

## Таблица

```
bootstrap/flang run-script behavior docs/examples/behavior/report-access-before.flang «Можно читать отчёт»
```

```
«Можно читать отчёт» · docs/examples/behavior/report-access-before.flang
полная таблица, строк 8: перебраны все входы
  роль = Владелец, архивный = да          →  нет
  роль = Владелец, архивный = нет         →  да
  роль = Заблокированный, архивный = да   →  нет
  роль = Заблокированный, архивный = нет  →  нет
  роль = Админ, архивный = да             →  да
  роль = Админ, архивный = нет            →  да
  роль = Чужой, архивный = да             →  нет
  роль = Чужой, архивный = нет            →  нет
```

Роль — вариант из четырёх, архивный — признак, поэтому входов ровно восемь, и
таблица **полная**: в ней все входы, какие бывают.

Число, строка и список бесконечны. Для них таблица — **выборка**: граничные
значения (`-1`, `0`, `1` у числа) и значения из примеров функции:

```
bootstrap/flang run-script behavior docs/examples/behavior/discount.flang «Скидка положена»
```

```
«Скидка положена» · docs/examples/behavior/discount.flang
выборка, строк 8: варианты и признаки перебраны целиком, числа, строки и списки взяты граничными значениями и значениями из примеров
  сумма = -1, постоянный = да     →  нет
  сумма = -1, постоянный = нет    →  нет
  сумма = 0, постоянный = да      →  нет
  сумма = 0, постоянный = нет     →  нет
  сумма = 1, постоянный = да      →  нет
  сумма = 1, постоянный = нет     →  нет
  сумма = 5000, постоянный = да   →  да
  сумма = 5000, постоянный = нет  →  нет
```

Выборка — не все входы. Если на ней исходы совпали, на других числах они могут
разойтись.

Строк по умолчанию не больше 256. Больше — таблица не строится, и сообщение
называет оба числа:

```
bootstrap/flang run-script behavior docs/examples/behavior/report-access-before.flang «Можно читать отчёт» --limit 4
```

```
«Можно читать отчёт» · docs/examples/behavior/report-access-before.flang
таблица не построена: строк было бы 8 при пределе 4; поднимите предел ключом --limit
```

## Дифф: правка, при которой всё зелёное

Задача: «владелец должен читать и архивные отчёты». Правка в
[`report-access-after.flang`](../examples/behavior/report-access-after.flang)
поменяла тело правила, вспомогательную функцию «Без доступа», на которую
опирается постусловие, и примеры. `flang check` у обеих версий проходит, пример
«заблокированному нельзя» заменён примером «чужому нельзя».

```
bootstrap/flang run-script behavior docs/examples/behavior/report-access-after.flang «Можно читать отчёт» docs/examples/behavior/report-access-before.flang
```

```
поведение «Можно читать отчёт»
  было:  docs/examples/behavior/report-access-before.flang — полная таблица, строк 8: перебраны все входы
  стало: docs/examples/behavior/report-access-after.flang — полная таблица, строк 8: перебраны все входы
перевернулось строк: 3
  роль = Владелец, архивный = да          нет  →  да
  роль = Заблокированный, архивный = да   нет  →  да
  роль = Заблокированный, архивный = нет  нет  →  да
появилось строк: 0
исчезло строк: 0
совпало строк: 5
```

Первая строка — то, о чём просили. Две следующие — заблокированный пользователь
теперь читает отчёты. Этого никто не просил, и ни одна проверка этого не
заметила: постусловие поменялось вместе с кодом.

Прежнюю версию можно взять из git: `--против HEAD`, `--против gh/dev` — тогда
второй файл не нужен. Если правило переименовали — `--прежнее-имя «Имя»`.

## Дифф пуст, когда поведение то же

В [`report-access-refactored.flang`](../examples/behavior/report-access-refactored.flang)
у правила другое имя, другие имена параметров и другое тело, но те же исходы:

```
bootstrap/flang run-script behavior docs/examples/behavior/report-access-refactored.flang «Читает ли отчёт» docs/examples/behavior/report-access-before.flang --прежнее-имя «Можно читать отчёт»
```

```
поведение «Читает ли отчёт»
  было:  docs/examples/behavior/report-access-before.flang — полная таблица, строк 8: перебраны все входы
  стало: docs/examples/behavior/report-access-refactored.flang — полная таблица, строк 8: перебраны все входы
поведение не изменилось: совпали все строки, 8
```

## На ревью

Шаг `behavior-review` перед пушем находит правила, которые ветка поменяла
относительно ствола, и печатает их дифф. Правило — функция с хотя бы одним
`обеспечивает`, которая возвращает признак или вариант. Шаг красный, если
строка перевернулась или исчезла, а в сообщениях коммитов ветки нет строки

```
Behavior-change: docs/examples/behavior/report-access-before.flang
```

по одной на файл. Строка — запись автора «перемена задумана»; человек видит
её рядом с диффом.

Для описания PR тот же дифф печатается в файл:

```
bootstrap/flang run-script behavior:review gh/dev --markdown --out behavior.md
```

## Ключи

| ключ | что делает |
|---|---|
| `--json` | таблица или дифф записью JSON |
| `--limit N`, `--предел N` | предел строк, по умолчанию 256 |
| `--против <ревизия>`, `--against` | прежняя версия файла из git |
| `--прежнее-имя «Имя»`, `--old-name` | имя правила в прежней версии |
| `--out <файл>`, `--в-файл` | печать в файл вместо потока вывода |

Последней строкой вывода `flang io` печатает свою запись о прогоне — так у
всех планов.

## Чего таблица не делает

- Тип из другого модуля не раскрывается: вход заполняется значениями примеров,
  а без них таблица не строится, и сообщение называет вход.
- Обобщённое правило (`от «А»`) таблицы не получает.
- Строка, где ложно `требует`, получает исход «вне требования».
- Выборка чисел не берёт `-0` и NaN.
