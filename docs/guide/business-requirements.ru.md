# Требования и спецификации: что flang даёт бизнесу и чего не даёт

Страница для того, кто решает, брать ли язык. Каждый пример ниже лежит файлом в
дереве, каждый вывод получен запуском, и рядом с каждым числом названа команда.
Если страница обещает больше, чем показывает запуск, это ошибка страницы.

Все команды запускаются программой `bootstrap/flang` из корня дерева.

## 1. Коротко: что вы получаете и чего нет

**Вы получаете три вещи.**

1. Требование к программе записывается **рядом с кодом**, словами правила
   предметной области. Его читает компилятор, а не только человек.
2. **Недоказанное постусловие видно.** `flang check --proof` называет его
   словами «не доказано» и выходит с кодом 3. Комментарий в коде и страница в
   вики выглядят одинаково, соблюдено правило или нет.
3. Доказанное можно **перепроверить другой программой**, которая не использует
   код компилятора.

**Вы не получаете:**

- полноты. Ядро доказательств закрывает узкий список видов утверждения, и
  обычное деловое правило может в него не попасть. Граница показана в разделе 5:
  предусловие, записанное функцией-предикатом, ядро не доказывает ни на одном
  вызове;
- ничего про **состояние во времени, побочные действия и одновременность**: в
  логике языка этих понятий нет;
- доказательства о **собранной программе**: оно привязано к команде
  `flang check`. Перевод в C проверяется отдельно и только частично (раздел 7).

## 2. Требование стоит рядом с кодом

[`docs/examples/usage/order-total.flang`](../examples/usage/order-total.flang):

```flang
модуль «Order total»

тотальная функция «Итог заказа»
  принимает товары: неотрицательное, доставка: неотрицательное
  возвращает число
  обеспечивает «итог не меньше стоимости товаров» результат не меньше товары
  пример «доставка бесплатна»
    дано товары равно 1200
    дано доставка равно 0
    ожидается 1200
  пример «доставка платная»
    дано товары равно 1200
    дано доставка равно 300
    ожидается 1500
  товары плюс доставка
```

Строка `обеспечивает` — постусловие: утверждение о результате **на любом входе**.
Строки `пример` — часть объявления, а не тесты в соседнем файле.

```
$ bootstrap/flang check docs/examples/usage/order-total.flang --proof
модуль «Order total»: функций 1, завершение доказано у 1
постусловие «итог не меньше стоимости товаров» функции «Итог заказа» — доказано
итог: постусловий и утверждений 1 — доказано 1, проверено только на тестах 0, не доказано 0
docs/examples/usage/order-total.flang: проверено — доказано 1, проверено только на тестах 0, не доказано 0, ложно 0 (постусловий и утверждений 1); независимая проверка повторила 0 из 1 — код возврата 0
```

Последняя строка говорит ещё одно: независимая проверка это доказательство не
повторила («0 из 1»). С ключом `--explain` та же команда печатает подробный
отчёт и называет правило: «доказано по объявленным типам аргументов: цель
сведена правилом „порядок по построению“».

Доказательство опирается на **типы аргументов.** Оба объявлены
`неотрицательное`, поэтому «сумма не меньше слагаемого» ядро выводит само. На
копии файла с типом `вес` вместо `неотрицательное` та же команда отвечает
«проверено только на тестах (примеров 2)» и выходит с кодом 3.

## 3. Четыре ответа и их коды возврата

Измерено запусками на файлах этой страницы и их копиях.

| Что с постусловием | Строка `check --proof` | Итог под `--proof --строго` | `check` | `check --proof` | `check --proof --строго` |
|---|---|---|---:|---:|---:|
| доказано для всех входов | «— доказано» | ДОКАЗАНО | 0 | 0 | 0 |
| есть примеры, доказательства нет | «— проверено только на тестах (примеров N)» | НЕ УДАЛОСЬ ДОКАЗАТЬ — ОПОРА НЕ СУДИЛАСЬ | 0 | 3 | 3 |
| нет ни доказательства, ни примеров | «— не доказано» | НЕ УДАЛОСЬ ДОКАЗАТЬ — ОБЪЯВЛЕНО, НЕ ДОКАЗАНО | 0 | 3 | 3 |
| пример или найденный вход нарушает постусловие | `FLANG_PROPERTY: … нарушено …` | отчёт не печатается | 1 | 1 | 1 |

Третья строка измерена на
[`docs/examples/proofs/reverse.flang`](../examples/proofs/reverse.flang).
Слово «сетка» в подробном отчёте значит «проверено только на тестах». Код 4
остаётся за ключом `--быстро` и значит «часть проверок не запускалась».

**Команда `flang check` без `--proof` о доказанности не судит.** На
`reverse.flang`, где утверждение не доказано, она выходит с кодом 0 и пишет
«не доказано: 1 — подробности: flang check reverse.flang --proof». Если в вашей
сборке стоит `flang check` без `--proof`, её код возврата о доказанности ничего
не говорит.

Справка `flang check --help` пишет, что без `--строго` проверка только на тестах
выходит с кодом 0. Сегодня это не так: код 3 в обоих случаях.

## 4. Недоказанное требование видно

[`docs/examples/usage/discount.flang`](../examples/usage/discount.flang):

```flang
модуль «Discount»

тотальная функция «Цена со скидкой»
  принимает цена: неотрицательное, скидка: неотрицательное
  возвращает число
  требует «скидка не больше цены» скидка не больше цена
  обеспечивает «скидка не делает цену отрицательной» результат не меньше 0
  цена минус скидка
```

Строка `требует` — предусловие.

```
$ bootstrap/flang check docs/examples/usage/discount.flang --proof
модуль «Discount»: функций 1, завершение доказано у 1
постусловие «скидка не делает цену отрицательной» функции «Цена со скидкой» — доказано
итог: постусловий и утверждений 1 — доказано 1, проверено только на тестах 0, не доказано 0
docs/examples/usage/discount.flang: проверено — доказано 1, проверено только на тестах 0, не доказано 0, ложно 0 (постусловий и утверждений 1); независимая проверка повторила 1 из 1 — код возврата 0
```

Здесь независимая проверка доказательство повторила: «1 из 1».

Доказательство опирается на предусловие. На копии файла без строки
`требует` постусловие ложно, и компилятор сам находит вход, на котором оно
нарушено:

```
$ bootstrap/flang check discount.flang --proof
FLANG_EXAMPLE: FLANG_PROPERTY: постусловие «скидка не делает цену отрицательной» функции «Цена со скидкой» нарушено на входе цена = 0, скидка = 1 — посчитано вычислителем на этом входе
discount.flang: не проверено — ведомость не печатается у программы с замечаниями
```

Код возврата 1. Слово `ведомость` в последней строке значит «отчёт о
доказательствах».

Верное, но недоказанное утверждение выглядит иначе:

```
$ bootstrap/flang check docs/examples/proofs/reverse.flang --proof
модуль «List reversal»: функций 2, завершение доказано у 2
утверждение «двойное обращение возвращает список» — не доказано
итог: постусловий и утверждений 1 — доказано 0, проверено только на тестах 0, не доказано 1
docs/examples/proofs/reverse.flang: доказано не всё — доказано 0, проверено только на тестах 0, не доказано 1, ложно 0 (постусловий и утверждений 1); независимая проверка повторила 0 из 0 — код возврата 3
подробный отчёт: flang check docs/examples/proofs/reverse.flang --proof --explain
```

Такая программа собирается и работает. Утверждение остаётся в ней проверкой во
время выполнения. Назвать его доказанным нельзя: отчёт пишет «не доказано», а
команда выходит с кодом 3. Комментарий `// скидка не сделает цену отрицательной`
в другом языке выглядит одинаково, выполняется правило или давно нарушено.

## 5. Кто доказывает предусловие и где граница

Предусловие (`требует`) доказывается на стороне **вызывающего**.
[`docs/examples/usage/discount-on-call.flang`](../examples/usage/discount-on-call.flang)
вызывает ту же функцию с литералами:

```flang
тотальная функция «Цена товара по акции»
  возвращает число
  пример «тысяча минус триста»
    ожидается 700
  «Цена со скидкой» от 1000 и 300
```

```
$ bootstrap/flang check docs/examples/usage/discount-on-call.flang
модуль «Discount on call»: функций 2, из них с доказанным завершением 2; типов 0
docs/examples/usage/discount-on-call.flang: проверено — доказано 0, проверено только на тестах 0, не доказано 0 (постусловий и утверждений 0); замечаний нет
```

Код возврата 0. На копии с вызовом `от 100 и 300`, где скидка больше цены, та
же команда отвечает:

```
FLANG_PRECONDITION_CALL … вызов «Цена со скидкой» в функции «Цена товара по акции» не снимает предусловие «скидка не больше цены»: …
… не проверено — замечаний 1
```

Код возврата 1. «Не снимает» значит «не доказывает». Негодный вызов найден до
запуска.

В напечатанном C (`flang emit --target c`) тело функции предусловие не
проверяет. Его проверяет вход по имени функции (`discount_call`), через который
приходят значения извне; там нарушение даёт `FLANG_PRECONDITION`.

**Граница узкая.** Ядро доказывает предусловие, только если оно — сравнение
(«не меньше», «не больше», «меньше», «больше», «равно») с литералом или
выражением, «содержит», «не убывает» или «начинается с». Сообщение об ошибке
называет правило, которое ядро пробовало, и формы, которые это правило
принимает. Предусловие, записанное **вызовом своей функции-предиката** («список
неубывающий», «клиент проверен», «договор действует»), ядро не доказывает ни на
одном вызове, даже там, где оно очевидно истинно. Пример — на странице
[«flang на чужом коде»](foreign-code.ru.md), раздел 4: вызов с упорядоченным
списком `[100, 500, 900]` отвергается так же, как вызов с неупорядоченным.

Практический вывод: **компилятор доказывает требования, которые записаны
неравенствами и равенствами над числами, строками и списками.** Требование,
записанное предикатом предметной области, сегодня записывается, проверяется во
время выполнения и остаётся недоказанным.

## 6. Чего в логике нет вовсе

- **состояния во времени.** Утверждений вида «после оплаты заказ не может стать
  черновиком» язык не выражает: временно́й логики в ядре нет;
- **побочных действий.** Действие в flang — описанное значение, которое
  исполняет хост, запустивший план. Доказательств о том, что происходит с
  внешним миром, ядро не даёт;
- **одновременности.** Процессы в языке есть, утверждений о гонках и
  взаимных блокировках — нет.

Полный перечень — [«Известные ограничения»](limits.ru.md). Среди задач дерева
такие помечены строкой `карта: Чего в языке нет вовсе` в файлах
`docs/tasks/*.md`. Их число меняется; его показывает
`bootstrap/flang run-script tasks:board`.

## 7. Где кончается доказательство

Итог сценария `bootstrap/flang io scripts/provability.fscript --plan Verdict --timeout 900000`
(порог доли — 100 %) относится только к команде `flang check`.

```
$ bootstrap/flang io scripts/provability.fscript --plan Verdict --timeout 900000
…
ДОКАЗУЕМ

проверка 1 — калькулятор снят? ДА (…)
проверка 2 — доля проигрыванием не ниже 100 %? ДА (100.00 %: 650 из 650; …)
проверка 3 — набор проб пройден? ДА (набор подделок 39 из 39; проб на подлог 632, принято кодом 0 — 0; …)
проверка 4 — набор не ослаб? ДА (…)
```

Вывод записан раньше; 27 ноября 2026 команда не перезапускалась: она идёт
дольше десяти минут. Он значит: 650 из 650 утверждений набора **повторила
независимая программа**, которая не использует код компилятора, и 632 попытки
провести ложное утверждение через ту же запись отвергнуты.

Чего в этом числе нет:

| шаг | что доказано |
|---|---|
| `flang check` | постусловия и завершение; независимая программа это повторила |
| `flang run` | ничего: вычислитель внутри компилятора не доказан |
| `flang emit --target c` и сборка | не доказано. С ключом `--protocol` печать C записывает протокол перевода, и `flang/translation/matcher.c` сверяет с ним напечатанный файл |

Протокол перевода описан в [ADR-0030](../adr/0030-the-printer-proves-each-run-not-itself.md)
(принято 13 сентября 2026) и есть только у цели C. На `discount.flang` сверка
отвечает «узлов в протоколе 21; переиграно правилом 16, принято на слово 0» и
«СОШЛОСЬ»; после правки одного числа в напечатанном C — «НЕ СОШЛОСЬ» с номером
строки. Это проверка одного запуска печати, а не доказательство компилятора.
Сборку C компилятором `cc` не проверяет ничто. Тот же разрыв есть у Coq, Lean и
Idris; закрыли его CompCert и CakeML, каждый годами работы команды.

Доказательство не замечает правку, которая поменяла правило вместе с его
постусловием и примерами. Все проверки проходят, потому что спецификация
поменялась вместе с кодом. Такую правку показывает
[таблица поведения правила](behavior-table.ru.md) — строки, где исход стал
другим.

## 8. Про сертификацию

На вопрос «годится ли это для авиации, медтехники, атомной станции» ответ:
**сегодня нет, и доля доказанного тут ни при чём.**

Сертификация процесса (DO-178C, IEC 62304, IEC 61508 и родственные) спрашивает
о другом:

- **прослеживаемость** «требование → код → тест → результат прогона», сквозная и
  документированная;
- **квалификация инструмента**: компилятор и проверяющие программы сами должны
  пройти квалификацию, с описанием, что они делают и как их отказ обнаруживается;
- **границы времени отклика**, доказанные или измеренные на целевом железе;
- **поведение при отказе**: что делает программа, когда память кончилась,
  устройство не ответило, значение вышло за диапазон;
- **управление изменениями и конфигурацией** с записью, кто что принял.

Ни одного из этих пунктов у нас нет, и плана с датами тоже нет. Язык даёт часть первого пункта (требование записано рядом с кодом и
проверяется машиной) и ничего из остальных.

## 9. Если вы решаете, брать ли

Три вопроса, на которые отвечает запуск, а не эта страница:

1. Возьмите **три своих настоящих правила**, самых обычных. Запишите их как
   `обеспечивает` и запустите `flang check --proof`. Сколько из трёх ответили
   «доказано», сколько «проверено только на тестах», сколько «не доказано»? Это
   ваша доля; доля на программах самого языка о ней не говорит.
2. Посмотрите на те, что остались недоказанными. **Вас устраивает, что они
   видны, но не доказаны?** Если да, язык полезен вам уже сейчас. Если нужна
   именно доказанность, считайте по пункту 1.
3. Нужен ли вам собранный код или довольно проверки исходника? Если нужен
   собранный, смотрите раздел 7 и решайте, терпим ли разрыв.
