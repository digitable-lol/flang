# flang на чужом коде: перевести, увидеть несоответствия, вынуть спецификацию

Здесь описан один опыт: кусок чужого кода переписан на flang, и записано, **что
при этом обнаружилось, что доказано и что осталось недоказанным**. Числа
получены программой `bootstrap/flang` из корня дерева. Все файлы лежат в дереве,
и каждый запуск можно повторить.

Для подмножества C перевод делает программа, а соответствие перевода исходнику проверяют
обратная печать в C и сравнение на наборе входов — [«Код на C в flang»](c-into-flang.ru.md).
Подмножество Python тоже переводит программа, а соответствие проверяет сравнение ответов
перевода с ответами самого Python на наборе входов — [«Python во flang»](../python-to-flang.ru.md).

## 1. Сначала поправка: ошибки находит не проверка, а переписка

`flang check` проверяет **только новый код**, написанный на flang. Чужой
исходник она не читает и с переводом не сравнивает. Ошибку в вашем Python она
не найдёт.

Несоответствия находятся раньше. Когда вы записываете чужой код с явными
типами, предусловиями и постусловиями, **приходится назвать то, что в исходнике
подразумевалось.** Подразумеваемое либо не выражается, либо выражается, и тогда
видно, что его никто не проверял.

Поэтому дальше отдельно описано, что обнаружилось при переписке (раздел 3) и
что ответила проверка (раздел 5).

## 2. Что переводилось

Взята функция `bisect_left` из стандартной библиотеки CPython,
Lib/bisect.py — место вставки значения в упорядоченный список. Она короткая,
чистая (без ввода-вывода), хорошо известна и взята из чужого репозитория.

Строение исходника (сокращено до того, что переводилось; ветвь `key` разобрана
в разделе 6 отдельно):

```python
def bisect_left(a, x, lo=0, hi=None, *, key=None):
    """Return the index where to insert item x in list a, assuming a is sorted."""
    if lo < 0:
        raise ValueError('lo must be non-negative')
    if hi is None:
        hi = len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

Результат перевода —
[`docs/examples/usage/lvalue.flang`](../examples/usage/lvalue.flang).

## 3. Что всплыло при переписке — шесть мест

Пять из них мелкие, шестое — главное.

**1. Цикл записан рекурсией.** `while lo < hi` в переводе — рекурсивная
функция, и её завершение надо обосновать. Убывает здесь не список, а разность,
поэтому автор называет её сам: `убывает верх минус низ плюс 1`. Компилятор это
убывание не доказывает и проверяет его во время выполнения, в двух местах.
Сегодня в языке есть форма `цикл … пока` со строкой `убывает`; она
переписывается в такую же функцию ([«Во что переписываются циклы и
классы»](surface-sugar.ru.md)).

**2. Значений по умолчанию нет.** `lo=0`, `hi=None` — их в языке не бывает.
Вышло две функции: «Место слева в отрезке» с явными границами и «Место слева»,
которая подставляет `0` и `длина элементы`. Заодно стало видно, что `hi=None`
в исходнике означает не «граница неизвестна», а «граница — конец списка», и
что различить эти два смысла по подписи было нельзя.

**3. Исключений нет.** `raise ValueError('lo must be non-negative')` становится
**предусловием**: `требует «низ неотрицателен» низ не меньше 0`. Исключение
проверяется при каждом вызове. Предусловие доказывается на стороне вызывающего
при проверке; в напечатанном C его проверяет только вход по имени функции, через
который приходят значения извне.

**4. Нумерация с другого конца.** В Python `a[mid]` считает с нуля, в flang
`элемент N в список` — с единицы. Стало `элемент (середина плюс 1) в элементы`.
Если это пропустить, перевод разойдётся с исходником без сообщения об ошибке.

**5. Целочисленного деления нет.** `(lo + hi) // 2` не переводится одним знаком;
вышло `(сумма минус (сумма остаток от 2)) делить на 2`. Переполнения
целого, известного по двоичному поиску в стандартной библиотеке Java, здесь
нет: числа языка — не машинные целые. Граница у них своя: это числа IEEE-754,
точные до 2⁵³−1.

**6. Сортированность списка в исходнике не записана нигде, кроме строки
документации.** Это главная находка.

`bisect_left` работает правильно только на упорядоченном списке. В коде CPython
проверяется ровно одно условие — `lo < 0`. Что список упорядочен, не
проверяется и не объявляется: это слова `assuming a is sorted` в строке
документации, которую интерпретатор не проверяет. На неупорядоченном списке
функция вернёт неверное число без ошибки.

При переводе это пришлось назвать:

```flang
тотальная функция «Неубывающий»
  принимает элементы: список числа
  возвращает признак
  …

тотальная функция «Место слева»
  принимает элементы: список числа, цель: число
  возвращает число
  требует «список неубывающий» («Неубывающий» от элементы) равен да
  …
```

Предусловие записано, файл проходит проверку (код возврата 0). Что из этого
вышло на вызовах, показывает раздел 4.

## 4. Требование записалось — и не сработало ни на одном вызове

[`docs/examples/usage/lvalue-with-call.flang`](../examples/usage/lvalue-with-call.flang)
вызывает «Место слева» с упорядоченным списком литералов:

```flang
тотальная функция «Куда встанет цена»
  принимает цена: число
  возвращает число
  пример «между сотней и пятью сотнями»
    дано цена равно 300
    ожидается 1
  «Место слева» от [100, 500, 900] и цена
```

```
$ bootstrap/flang check docs/examples/usage/lvalue-with-call.flang
FLANG_PRECONDITION_CALL … строка 70, столбец 3: вызов «Место слева» в функции
«Куда встанет цена» не снимает предусловие «список неубывающий» …
docs/examples/usage/lvalue-with-call.flang: не проверено — замечаний 1
```

Код возврата 1. «Не снимает» значит «не доказывает». Та же ошибка приходит и на
неупорядоченном списке `[900, 100, 500]`. Проверка **отвергает правильный вызов
так же, как неправильный**: ядро не вычисляет `«Неубывающий» от [100, 500, 900]`.
Оно сравнивает утверждения по форме, а предусловие, записанное вызовом своей
функции, ни под одно его правило не подходит.

Вывод: **назвать подразумеваемое требование можно всегда, а доказать его на
вызовах — только если оно записано неравенством или равенством над числами,
строками и списками.** Предикат предметной области сегодня записывается и
проверяется во время выполнения, но вызовы по нему не проверяются. Отдельно об этом —
[«Требования и спецификации»](business-requirements.ru.md), раздел 5.

## 5. Что сказала проверка

Перевод без требований об отрезке индексов
([`lvalue.flang`](../examples/usage/lvalue.flang)):

```
$ bootstrap/flang check docs/examples/usage/lvalue.flang --proof
модуль «Place on the left»: функций 3, завершение доказано у 2, без доказательства завершения: 1
постусловие «место не левее низа» функции «Место слева в отрезке» — проверено только на тестах (примеров 1)
постусловие «место не правее верха» функции «Место слева в отрезке» — проверено только на тестах (примеров 1)
…
docs/examples/usage/lvalue.flang: доказано не всё — доказано 0, проверено только на тестах 2, не доказано 0, ложно 0 (постусловий и утверждений 2); независимая проверка повторила 0 из 0 — код возврата 3
…
```

С ключом `--explain` подробный отчёт называет способ для каждой функции:
«Неубывающий» — «доказано структурой», «Место слева» — «доказано композицией»,
«Место слева в отрезке» — «объявленной мерой … спуск ядром не выведен — на
веру», то есть убывание принято без доказательства и проверяется при работе.

С ключом `--strict` та же команда выходит с кодом **1**. Предупреждение
`FLANG_NOT_TOTAL` о встроенной операции `элемент` («номер может выйти за
список») под этим ключом становится ошибкой, и отчёт не печатается.
`bootstrap/flang test` на том же файле: «примеров 7, прошло 7, не прошло 0»,
код возврата 0.

Итог числами:

| | сколько |
|---|---:|
| функций переведено | 3 |
| завершение доказано | 2 из 3 (структурой 1, композицией 1); у третьей убывание объявлено и проверяется при работе |
| постусловий доказано обо всех входах | **0 из 2** |
| постусловий проверено только на примерах автора | 2 из 2 |
| проверок убывания во время выполнения | 2 места |

Оба постусловия — «результат не левее низа» и «результат не правее верха» —
записаны, проверяются во время выполнения и остаются недоказанными. Завершение
самого двоичного поиска тоже не доказано: оно проверяется при каждом
рекурсивном вызове.

### Попытка усилить сделала хуже

Если дописать три предусловия об отрезке индексов, которые исходник
подразумевает (`низ не меньше 0`, `верх не больше длины`, `низ не больше
верх`), файл перестаёт проходить проверку:

```
$ bootstrap/flang check docs/examples/usage/lvalue-with-slice.flang
FLANG_PRECONDITION_CALL … строка 46 … не снимает предусловие «низ неотрицателен»
FLANG_PRECONDITION_CALL … строка 46 … не снимает предусловие «низ не правее верха»
FLANG_PRECONDITION_CALL … строка 47 … не снимает предусловие «верх не дальше конца списка»
FLANG_PRECONDITION_CALL … строка 47 … не снимает предусловие «низ не правее верха»
… не проверено — замечаний 4
```

Код возврата 1, четыре ошибки
([`lvalue-with-slice.flang`](../examples/usage/lvalue-with-slice.flang)).
Инвариант, который двоичный поиск сохраняет на каждом шаге, ядро не выводит, и
рекурсивные вызовы не доказывают предусловие собственной функции. Сегодня
выбор такой: не записывать эти предусловия, и тогда программа говорит о них не
больше исходника, или записать, и тогда файл не проходит проверку.

## 6. Чего не всплыло, хотя ожидалось

Ветвь `key=None` в `bisect_left` принимает **функцию параметром**. Ожидалось,
что она не переведётся. Она переводится:
`ключ: функция из числа в число`, применение `ключ от (элемент … в элементы)`.
[`lvalue-by-key.flang`](../examples/usage/lvalue-by-key.flang):
«функций 4, из них с доказанным завершением 4 … замечаний нет», код возврата 0;
`flang test` — «примеров 8, прошло 8, не прошло 0», код возврата 0.

Функцию, объявленную по имени, передать параметром можно. Нельзя передать
функцию, которая приходит данными (например, разобрана из файла настроек), и
нельзя записать безымянную функцию на месте аргумента своей функции.

## 7. Спецификация, которая вынулась

Было: одна проверка во время выполнения (`lo < 0`) и фраза в строке
документации. Стало шесть названных пунктов, каждый записан в коде:

| пункт | как записан | что с ним | было ли в исходнике |
|---|---|---|---|
| список неубывающий | `требует «список неубывающий»` | на вызовах не доказывается (раздел 4) | только в строке документации |
| низ неотрицателен | `требует «низ неотрицателен»` | рекурсивные вызовы его не доказывают, код 1 (раздел 5) | `raise ValueError` при работе |
| верх не дальше конца списка | `требует «верх не дальше конца списка»` | то же, код 1 | нигде |
| низ не правее верха | `требует «низ не правее верха»` | то же, код 1 | нигде |
| результат лежит между низом и верхом | два `обеспечивает` | проверено только на тестах, проверяется при работе | нигде |
| функция завершается на любом входе | `тотальная` + `убывает` | не доказано: убывание проверяется при работе | нигде |

Из шести пунктов **не доказан ни один**. Все шесть теперь **записаны в коде**,
а не только в строке документации, и часть из них проверяется во время
выполнения.

## 8. Что из этого следует для вашего репозитория

- Переводить имеет смысл **чистые куски**: расчёты, разбор форматов, правила
  проверки данных. Код, который в основном меняет состояние и делает
  ввод-вывод, перевести можно, но проверка о нём ничего не скажет: в логике
  языка нет состояния во времени и побочных действий.
- Находки появляются **при переписке, а не при запуске**. Главная находка этого
  опыта — пункт 6 раздела 3. Она сделана, когда пришлось написать слово
  `требует`, а не по сообщению компилятора.
- Считайте на своём коде. В этом опыте из 6 пунктов спецификации не доказан
  ни один. У вас выйдет другое число, и узнать его можно только запуском.
- Часть кода не выразится совсем. Такие задачи в `docs/tasks/` помечены строкой
  `карта: Чего в языке нет вовсе`; их число показывает
  `bootstrap/flang run-script tasks:board`. Полный перечень —
  [«Известные ограничения»](limits.ru.md).
