# Где flang находит свою библиотеку и рантаймы

`flang` читает файлы двух родов, которых нет в самом двоичном: стандартную библиотеку
(`использует «Lists»` без пути) и исходники рантаймов, которые `flang emit` кладёт в
вывод. И то и другое ищется рядом с двоичным, поэтому одно правило годится для любого
способа установки.

## Каталог самого двоичного

Двоичный берёт свой путь из `argv[0]` (или из `PATH`, если запущен по имени) и раскрывает
символьные ссылки. `brew`, `asdf` и `install.sh` кладут в `bin/` ссылку или прокладку;
в счёт идёт каталог настоящего файла. Ниже `<корень>` — каталог на уровень выше него.

## Модуль, названный без пути

`использует «Lists»` ищется по имени из первой строки модуля. Места по порядку:

1. каталог файла, в котором написано `использует`;
2. каждый каталог выше, пока в нём есть хоть один `.flang` и пока он внутри дерева файла
   (другой предел задаёт `FLANG_MODULE_ROOT`);
3. каталоги из `FLANG_MODULE_DIR` (через двоеточие);
4. `<корень>/flang/stdlib`, `<корень>/flang/core`;
5. `<корень>/share/flang/stdlib`, `<корень>/share/flang/core`.

Два файла с одним именем модуля берутся оба, и связывание отвечает
`FLANG_IMPORT_AMBIGUOUS` с обоими путями. Не нашлось нигде —
`FLANG_IMPORT_NOT_FOUND … ни рядом с файлом, ни выше по каталогам, ни в библиотеке компилятора`.

## Исходники рантайма цели печати

`flang emit --target <ц>` берёт рантайм цели `<ц>` из первого подходящего:

1. `--runtime <каталог>`;
2. `$FLANG_RUNTIME_DIR`;
3. `<корень>/flang/src/emit/<ц>`;
4. `<корень>/share/flang/<ц>`.

`cpp` и `ts` смотрят уровнем выше (`<корень>/share/flang`): они читают и файлы других
целей. Копия с шапкой `Сгенерировано flang` отвергается — рантаймом считаются только
рукописные исходники.

## Что кладёт каждый способ установки

| Установка | Двоичный | Библиотека | Рантаймы |
|---|---|---|---|
| клон, `make -C bootstrap` | `bootstrap/flang` | `flang/stdlib` (место 4) | `flang/src/emit/<ц>` (место 3) |
| готовая сборка, `install.sh`, deb, rpm, AUR | `bin/flang` | `share/flang/stdlib` | `share/flang/<ц>` |
| Homebrew (`flang-package`, `flang`) | `Cellar/…/bin/flang` | `Cellar/…/share/flang/stdlib` | `Cellar/…/share/flang/<ц>` |
| asdf (готовая сборка или архив C) | `installs/flang/<в>/bin/flang` | `…/share/flang/stdlib` | `…/share/flang/<ц>` |
| `make install PREFIX=<п>` | `<п>/bin/flang` | не ставится | не ставятся |

Архив C выпуска несёт образ `share/flang` в каталоге `runtime/`: по подкаталогу на цель и
`stdlib/`. Каждая упаковка переносит этот каталог целиком, и библиотека едет той же дорогой,
что и рантаймы. В выпусках до 0.7.29 `stdlib/` нет; установка такого выпуска находит
библиотеку только через `FLANG_MODULE_DIR`.

`make install` из дерева ставит `bin`, `lib`, `include` и страницу руководства. Библиотеку
и рантаймы такой установке показывают на дерево:
`FLANG_MODULE_DIR=<клон>/flang/stdlib` и `--runtime <клон>/flang/src/emit/<ц>`.

## Как это проверяется

- `bootstrap/flang run-script install-parity:check` гоняет одни и те же вызовы на каждой
  установке из `packaging/install-parity.txt`. Три вызова работают с файлом вне дерева,
  ввозящим `«Lists»` (`check`, `run`, `emit --target c`); первая установка обязана их
  пройти, поэтому установка без `share/flang/stdlib` отвергается поимённо
  (`ОТКАЗ | <установка> | …`), даже когда все установки сломаны одинаково.
- `scripts/release/release-in-c.fscript` ставит архив C в префикс и оттуда печатает такой
  файл в C и JavaScript.
- Формулы Homebrew проверяют и печатают тот же файл в `brew test`.
