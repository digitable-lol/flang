# Известные ограничения

Что во flang 0.7.34 не работает и что делать вместо этого.

## Как читать отчёт о доказательствах

`flang check --proof` даёт каждому постусловию (`обеспечивает`) один из трёх
результатов. Это разные вещи:

| В отчёте написано | Что это значит |
| --- | --- |
| `доказано` | верно для **всех** входов. Доказал prover, и отдельная программа-сверщик может перепроверить доказательство по шагам |
| `сетка N` | проверено только на N значениях, которые вы написали, как unit-тестами. Про остальные входы не известно ничего. **Это не доказательство** |
| `объявлено, не доказано` | записано, но нет ни доказательства, ни примера |

Завершение `тотальная` функций, типы и полнота pattern matching (`разбор`)
всегда доказываются, а не тестируются.

`flang check` без ключей отвечает кодом 0 и тогда, когда постусловие посчитано только на сетке
или объявлено без доказательства. Вердикт показывают `flang check --proof` (код 3) и `flang run`
(отказ, код 3).

Независимый сверщик перепроверяет не каждое место доказательства: остальное он называет в отчёте
как взятое на слове ядра.

## Чего доказать нельзя

| Не работает | Что делать вместо |
| --- | --- |
| «существует x такой, что …» с значением, которое не читается из самой цели: prover ищет такое значение только среди подтермов цели (не больше восьми), по значениям не ищет | назвать значение: `есть такой м, а именно н, что …`; негодное названное значение `check` отказывает кодом `FLANG_PROOF_STEP` — не опровержение, а «этим значением не сведено» |
| квантор внутри формулы в независимой проверке: `есть такой м, что …` без `а именно` под `и притом`/`если`, квантор под `или` и `не` и в свободном утверждении сверщики записи оставляют на слове ядра — код 3 | назвать значение словом `а именно`: квантор под `и притом` и под `если` с названным значением, `для всех … из` над отбором, `приписать` и пустым списком оба сверщика переигрывают по исходнику |
| порядок из ветви `иначе` над `число`: из `не (х меньше 0)` не следует `х не меньше 0`, потому что на не-числе ложны обе стороны сравнения | объявить аргумент `целое`, если он целый; для `число` — теорема с шагами или проверка в рантайме |
| свойство состояния во времени, side effects или параллелизма: записать его в языке негде | тестировать `пример`ами, а процессы — сценариями `прогон` |
| свойство сгенерированного кода на C, Go, Rust и других целях: доказательство покрывает программу на flang, генератор кода не доказан | тестировать сгенерированную программу отдельно; для цели `c` сверять каждый запуск печати протоколом `--protocol` и программой `flang/translation/matcher.c` — она переигрывает узлы, включая проверку меры, и называет, чего не переиграла |
| постусловие, которое prover не принимает | см. [Что принимает prover](../site/what-the-kernel-accepts.ru.md); написать `теорема` или переформулировать постусловие |

Внешний SMT-решатель не подключён. Софт для медицины, авиации и космоса на
flang не пишите: сертификация — это процесс, а не свойство языка.

## Язык

**Записи в список по номеру нет.** Читать элемент можно — `элемент N в
список`, и это работает на всех целевых языках. Значения неизменяемы, поэтому
«список с заменённым N-м элементом» — это новый список. Алгоритмы на
изменяемой таблице — динамическое программирование вроде Coin Change или Edit
Distance, хеш-таблица с корзинами — напрямую не переносятся. Для словаря
берите готовый из библиотеки: список пар с линейным поиском
(`flang/stdlib/dictionary.flang`), дерево поиска с поиском за O(log n)
(`flang/stdlib/tree.flang`) или хеш-trie (HAMT), глубина которого ограничена
длиной хеша (`flang/stdlib/hashmap.flang`).

**Побитовых операторов нет.** Берите функции библиотеки, которые делают то же
арифметикой, например `«Исключающее или байтов»` (XOR байтов) в
`flang/stdlib/aes.flang`.

**Счёт вверх завершение не доказывает.** Рекурсивный вызов на `н плюс 1`
отвергается с `FLANG_NOT_TOTAL`: «рекурсивный вызов не убывает». Переверните
счёт вниз по параметру типа `неотрицательное` (неотрицательное целое) — тогда
завершение доказывает сам тип (`docs/examples/measure/natural.flang`).

**Когда шаг меняется от вызова к вызову, убывающую меру компилятор сам не
находит.** Он находит структурную рекурсию (по хвосту списка, по части дерева)
и числовой аргумент, убывающий на постоянный шаг. Для остального напишите меру
сами строкой `убывает <выражение>`: двоичный поиск — `убывает верх минус низ
плюс 1`, алгоритм Евклида — `убывает б` (`docs/examples/measure/`).
Сгенерированный код тогда проверяет во время работы, что мера целая,
неотрицательная и строго убывает, и останавливается с `FLANG_MEASURE`, а не
зависает. Та же проверка во время работы стоит при постоянном шаге по обычному
`число`: числа — двойной точности IEEE-754, и `x минус 1` равно `x` при
больших `x`. Для параметра `неотрицательное` проверка не нужна и не
генерируется: значение ограничено типом.

**Вариант с именем ключевого слова не сопоставляется.** Если варианты
называются `Да`, `Нет`, `Плюс` или `Больше`, `случай Да` читается как
ключевое слово, и ошибка винит образец (`FLANG_TYPE: образец-литерал имеет тип
признак …`), а не имя. Пишите `случай вариант «Да»` или переименуйте вариант.

**Side effects — только через `план`.** Функция сама файл не читает: она
возвращает команду как данные (`вариант «Прочитать файл» с путь равным …`),
`flang io` её выполняет и вызывает функцию снова с ответом. Команд 27, и

Неправильный UTF-8, прочитанный как текст, даёт `FLANG_IO_NOT_TEXT`; двоичные
файлы читайте байтами.

**`https` — встроенным клиентом TLS 1.3.** «Запросить» по `https` исполняет клиент, написанный
на flang и встроенный в двоичный; `curl` не нужен. Клиент умеет только `TLS_AES_128_GCM_SHA256`,
x25519, `rsa_pss_rsae_sha256` и цепочку `sha256WithRSAEncryption`; узел без них — отказ
`FLANG_IO_TLS`. Отзыв сертификата не проверяется, отключить проверку сертификата нельзя. Корни —
`--trust-roots <файл PEM>` или системная связка. Ответ — не больше 1 048 576 байт. Сырого
TLS-сокета у плана нет: «Открыть соединение» — голый TCP. Датаграммы — только IPv4.

**Программа с `план` генерируется в `c`, `go`, `js`, `python`, `rust` и
`ts`**. `cpp`, `csharp`, `elixir` и `java` отказывают с
`FLANG_PLAN_UNSUPPORTED`, называют план и не пишут ни одного файла. В `c`,
`go`, `python` и `rust` план запускает прогонщик: `flang_cli --plan <имя>
[довод…]`; его хозяин исполняет 9 родов поручений из 27 (файлы текстом и
октетами, каталоги, среда, доводы), на сеть, процессы, часы, кости и экран
отвечает «Сбой» с `FLANG_IO_NOT_WIRED` или `FLANG_IO_NO_SCREEN`. Такой план
запускайте через `flang io`.

**Компилятор отвечает по-английски не на всё.** `flang check` при `language = en` в `.flangrc`
(или `FLANG_LANG=en`) печатает итог и отказы по-английски, но часть текстов остаётся русской —
например, `FLANG_TYPE` об образце-литерале. Код `FLANG_*` один на всех языках. Справка, `test`,
`run`, `io` и `lint` отвечают по-русски.

**Монады ввода-вывода нет.** Шаги сцепляются так: функция возвращает команду
и следующий шаг объявленным значением, а не скрытым замыканием.

**Примеры перед `flang emit` не прогоняются.** Их прогоняют `flang check` и `flang test`; `emit`
печатает и программу с ложным примером. Прогоняйте `flang test <файл>` перед печатью.

## Категорные объявления

Законы `категория` и `изоморфизм` компилятор считает на конечной сетке значений из примеров, а
не доказывает. Законы `моноид` над `число` и `строка` ядро не доказывает: они тоже остаются на
сетке, и `flang check --proof` отвечает кодом 3. Законы `монада` и законы `отобразить` по списку
ядро доказывает. Подробно — [«Категории и функторы»](../site/categories.ru.md).

## Процессы

| Не работает | Что делать вместо |
| --- | --- |
| процессы в `cpp`, `csharp`, `go`, `java`, `python`, `rust`: `flang emit` отказывает с кодом 1, «у цели «…» нет планировщика конкурентности» | генерировать в `c`, `elixir`, `js` или `ts` |
| `породить` (spawn) в Elixir и JavaScript: планировщик отвечает ошибкой | брать цель `c`, где он работает |
| ограниченный mailbox в Elixir: `flang emit --target elixir` отказывает | брать `c`, `js` или `ts` либо неограниченный mailbox |
| отправка порождённому процессу по имени, вычисленному во время работы: компилятор проверяет только литеральные имена | дать порождённому процессу работу первым сообщением, а ответ слать процессу с объявленным именем |
| работа на нескольких машинах: файл размещения узлов двоичный компилятор не читает (`--размещение` — неизвестный ключ) | работать на одном узле |
| доказать отсутствие deadlock: сценарии `прогон` перебирают конечное число порядков сообщений при фиксированных seed — это тестирование, а не доказательство | строить протокол так, чтобы процессы не ждали друг друга по кругу |

Планировщик в сгенерированном C работает в двух режимах: один поток, который
упорядочивает сообщения по seed, так что один seed даёт один и тот же журнал
доставок, и пул рабочих потоков (поле `workers` в запросе). Пул быстрее только
на программе с параллельной работой; на программе без неё он в разы медленнее.
