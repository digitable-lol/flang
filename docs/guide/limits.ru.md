# Известные ограничения

Чего flang не делает и не гарантирует, и что писать вместо этого. Страница —
справочник: ищите свой случай по заголовкам.

## Чего flang не гарантирует

### Компилятор не доказан целиком

CompCert — компилятор C, у которого доказано: любая его выходная программа ведёт
себя как исходная. У flang такого доказательства нет. Доказательства flang
относятся к программе на flang, а генератор кода может ошибиться.

Взамен проверяется каждая сгенерированная программа на C. Команда
`translation:validate` сравнивает её с эталоном — описанием смысла языка на Lean —
и выдаёт вердикт по каждой функции:

| Вердикт | Что он значит |
| --- | --- |
| совпадает на любом входе | доказано: перебором всех значений аргументов или сравнением двух деревьев ветвлений |
| совпало на примерах | ответы одинаковы на подобранных входах; об остальных входах ничего не известно |
| вне проверки | функция использует то, чего эталон пока не описывает |

Машинные слова эталон пока не описывает. Все функции примера
`docs/examples/reference/ru/machine-words.flang` получают третий вердикт:

```text
$ flang run-script translation:validate -- --path docs/examples/reference/ru/machine-words.flang
СООТВЕТСТВИЕ ПРОВЕРЕНО для 47 функций, вне валидации 7
…
  причины вне валидации: вид типа u8 — 1; вид типа u32 — 6
…
расхождений 0
```

Первая строка: 47 функций совпадают на любом входе, 7 остались вне проверки
(«вне валидации»). Эти 47 — функции восьми служебных файлов, которые команда
всегда проверяет вместе с вашим. Семь — все функции примера. Строка о причинах
называет тип аргумента: `u8` у одной функции и `u32` у шести. Последняя строка:
расхождений между C и эталоном не найдено.

Команда запускается из клона репозитория и требует установленный Lean. Сколько
функций примеров она доказывает и как устроена — в описании
[проверки перевода в C](../translation-validation.ru.md). Для остальных девяти
целевых языков такой проверки нет.

### Что принимается без доказательства

Вердикт «совпадает на любом входе» говорит о тексте функции на C. Ниже него
остаются части, которые никто не доказывал:

| Часть | Что в ней |
| --- | --- |
| рантайм на C | память, строки, списки, планировщик процессов |
| компилятор C | `cc` вашей системы |
| libc и потоки | `malloc`, `pthread_create`, `fopen` и другие |
| эталон на Lean | он написан руками и может расходиться с документацией |

### `тотальная` не значит «без ошибок»

Ключевое слово `тотальная` обещает одно: вычисление закончится. Остановка с
ошибкой при выполнении тоже считается завершением. Файл
`docs/examples/reference/ru/word-division.flang`:

```flang insert docs/examples/reference/ru/word-division.flang
модуль «Word division»

тотальная функция «Пакетов в буфере»
  принимает буфер: u64, пакет: u64
  возвращает u64
  пример «в 4096 байтов входит два пакета по 1500»
    дано буфер равно u64 4096
    дано пакет равно u64 1500
    ожидается u64 2
  буфер делить на пакет

тотальная функция «Пакетов в буфере или ноль»
  принимает буфер: u64, пакет: u64
  возвращает u64
  пример «пакет нулевой длины — ноль пакетов»
    дано буфер равно u64 4096
    дано пакет равно u64 0
    ожидается u64 0
  если пакет равен 0
    то u64 0
    иначе буфер делить на пакет
```

```text insert output: check docs/examples/reference/ru/word-division.flang
$ flang check docs/examples/reference/ru/word-division.flang
модуль «Word division»: функций 2, из них с доказанным завершением 2; типов 0
предупреждений 1: встроенная операция в тотальной функции может отказать при работе; код возврата они не меняют, с «--proof --strict» это ошибки
FLANG_NOT_TOTAL в файле docs/examples/reference/ru/word-division.flang, строка 10, столбец 9: функция «Пакетов в буфере» объявлена тотальной, а встроенная операция «делить на» может отказать при работе: делитель может оказаться нулём; добавьте «требует» с условием на аргументы или проверку перед вызовом; пока это предупреждение, станет ошибкой в 0.9.0
docs/examples/reference/ru/word-division.flang: проверено — доказано 0, проверено только на тестах 0, не доказано 0 (постусловий и утверждений 0); замечаний нет
```

Проверка прошла, предупреждений нет. Запуск первой функции с делителем 0:

```text insert output: run docs/examples/reference/ru/word-division.flang --function "Пакетов в буфере" --args '{"буфер":4096,"пакет":0}'
$ flang run docs/examples/reference/ru/word-division.flang --function "Пакетов в буфере" --args '{"буфер":4096,"пакет":0}'
доказано: утверждений 0
FLANG_OVERFLOW: 4096 «div» 0: деление на ноль
$ echo $?
1
```

Строка с `FLANG_OVERFLOW` — ошибка деления на ноль (`div` — внутреннее имя
действия `делить на`), код возврата 1. Так же ведут себя сложение машинных слов, которое
не помещается в тип, и `подстрока` за концом строки. Закрывайте такие места
ветвью `если`, как во второй функции, или предусловием `требует`.

### `flang check` не сообщает, доказаны ли постусловия

`flang check` проверяет синтаксис, типы, завершение и примеры. На постусловие
(`обеспечивает`), которое не доказано, он не жалуется и возвращает код 0.
Доказано ли оно, показывает `flang check --proof`: он выводит отчёт о
доказательствах и возвращает код 3, если хоть одно постусловие не доказано.
`flang run` такую программу не запускает, пока не дан ключ `--trust`.

### Целая операционная система на flang не пишется

| Чего в языке нет | Что из этого следует |
| --- | --- |
| указателей и адресов | нельзя обратиться к регистру устройства или к таблице страниц |
| прерываний и ожидания | обработчик по вектору и цикл ожидания пишутся на C |
| ассемблерных вставок | переключение контекста пишется на C или ассемблере |
| записи на месте | буфер нельзя изменить, можно построить новый |

На flang пишется решающая часть: разбор заголовков, проверка прав, политика
планировщика, автомат драйвера. Это чистые функции, и их постусловия
доказываются. Как такая функция соединяется с кодом на C —
[Граница между flang и хостом](../site/host-boundary.ru.md).

### Сгенерированный C требует libc и потоки

Программа на C, сгенерированная из модуля без единого эффекта, ссылается на 62
внешних символа: `malloc`, `pthread_create`, `fopen`, `fork` и другие. Число
получено на примере `machine-words.flang`: `flang emit --target c --no-cli`,
затем `cc -O2 -c` (gcc 15) и `nm -u`. В прошивку без операционной системы такой
код сегодня не соберётся. Вариант без libc в работе.

## Как читать отчёт о доказательствах

`flang check --proof` даёт каждому постусловию один из трёх результатов. Они
видны в последней строке отчёта:

```text
$ flang check docs/examples/reference/ru/machine-words.flang --proof
…
docs/examples/reference/ru/machine-words.flang: НЕ ДОКАЗАНО — ОПОРА НЕ СУДИЛАСЬ — утверждений 2: доказано 1, условно 0, сетка 1, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 3
```

| В отчёте написано | Что это значит |
| --- | --- |
| `доказано` | верно для всех входов; доказательство может перепроверить отдельная программа `checker` |
| `сетка N` | проверено только на N примерах, как unit-тестами; об остальных входах ничего не известно |
| `объявлено, не доказано` | записано, но нет ни доказательства, ни примера |

В примере постусловий два: одно доказано, одно проверено на одном примере.
Поэтому первая часть строки — «НЕ ДОКАЗАНО», и код возврата 3.

Завершение функций с ключевым словом `тотальная`, типы и полнота `разбор`
(сопоставление с образцом, `match`) доказываются всегда.

Программа `checker` перепроверяет не каждое доказательство. Сколько
доказательств она повторила и сколько принято без перепроверки, отчёт называет
отдельной строкой.

## Чего доказать нельзя

| Не работает | Что делать вместо |
| --- | --- |
| «существует x такой, что …», если значение x не записано в самом постусловии | назвать значение: `есть такой м, а именно н, что …`; негодное значение даёт ошибку `FLANG_PROOF_STEP` |
| постусловие о результате маски, сдвига или сложения машинных слов | проверять примерами; о слове известен только диапазон его типа |
| порядок из ветви `иначе` над `число`: из `не (х меньше 0)` не следует `х не меньше 0`, потому что для NaN ложны оба сравнения | объявить аргумент `целое`, если он целый; для `число` написать `теорема` с шагами |
| свойство состояния во времени, эффектов или параллельной работы | тестировать: `пример` для функций, сценарии `прогон` для процессов |
| свойство сгенерированного кода на Go, Rust и других целях, кроме C | тестировать сгенерированную программу отдельно |
| постусловие, которое компилятор не доказал сам | написать `теорема` или переформулировать: [Что доказывается автоматически](../site/what-the-kernel-accepts.ru.md) |

Внешний SMT-решатель не подключён. Для медицины, авиации и космоса flang не
годится: сертификация — процесс, которого у языка нет.

## Язык

**Записи в список по номеру нет.** Читать элемент можно: `элемент N в список`.
Значения неизменяемы, поэтому список с заменённым элементом — новый список.
Алгоритмы на изменяемой таблице напрямую не переносятся. Для словаря берите
готовый из библиотеки: `flang/stdlib/dictionary.flang` (список пар),
`flang/stdlib/tree.flang` (дерево поиска) или `flang/stdlib/hashmap.flang`.

**Побитовые операции есть только у машинных слов.** Над `число` их нет.
Объявите значение как `u8` … `u64` и пишите `побитовое и`, `сдвиг вправо на`:
[Машинные слова](../site/language.ru.md#машинные-слова-u8-u64-i8-i64).

**Шестнадцатеричных литералов нет.** `0xFF` даёт ошибку `FLANG_PARSE`. Пишите
десятичное число: 255.

**Типа «массив байтов» и массива фиксированного размера нет.** Берите
`список u8` и постусловие о длине.

**Деления над `точное целое` нет.** Есть `плюс`, `минус`, `умножить на` и
`остаток от`. Для полей до 64 бит берите `u64`.

**Счёту вверх нужна мера.** Рекурсивный вызов на `н плюс 1` без строки
`убывает …` даёт ошибку `FLANG_NOT_TOTAL`: «рекурсивный вызов не убывает».
Напишите `убывает предел минус н` над двумя параметрами типа `неотрицательное`, и
спуск докажет ядро ([Счёт вверх до границы](totality.ru.md#счёт-вверх-до-границы)).
Над `число` мера принимается без доказательства. Счёту вниз мера не нужна
(`docs/examples/measure/natural.flang`).

**Меру с переменным шагом компилятор сам не находит.** Он находит рекурсию по
части значения (хвост списка, поддерево) и убывание на постоянный шаг. Для
остального напишите строку `убывает <выражение>`: у двоичного поиска это
`убывает верх минус низ плюс 1` (`docs/examples/measure/`). Сгенерированный код
тогда проверяет меру при выполнении и останавливается с `FLANG_MEASURE`.

**Вариант с именем ключевого слова не сопоставляется.** `случай Да` читается
как литерал `да`, и ошибка `FLANG_TYPE` указывает на образец. Пишите
`случай вариант «Да»` или переименуйте вариант.

**Монады ввода-вывода нет.** Функция возвращает эффект и следующий шаг обычным
значением.

**Примеры перед `flang emit` не выполняются.** Их выполняют `flang check` и
`flang test`. Запускайте `flang test <файл>` перед генерацией кода.

**Сообщения компилятора переведены на английский не все.** При `language = en`
в `.flangrc` итог `flang check` выводится по-английски, часть ошибок остаётся
русской. Код `FLANG_*` одинаков на всех языках.

## Эффекты

**Эффекты доступны только через `план`.** Функция файл не читает. Она
возвращает описание действия, `flang io` его выполняет и вызывает функцию снова
с ответом. Список эффектов закрыт: файлы, каталоги, сеть, процессы, экран,
время, случайные числа, переменные среды, аргументы командной строки. Полная
таблица — [Граница между flang и хостом](../site/host-boundary.ru.md).

**Текст читается только как UTF-8.** Неправильный UTF-8 даёт ошибку
`FLANG_IO_NOT_TEXT`. Двоичные файлы читайте байтами.

**`https` — только TLS 1.3 с одним набором шифров.** Клиент встроен в `flang`,
`curl` не нужен. Он знает `TLS_AES_128_GCM_SHA256`, x25519,
`rsa_pss_rsae_sha256` и цепочку `sha256WithRSAEncryption`. Сервер без них даёт
ошибку `FLANG_IO_TLS`. Отзыв сертификата не проверяется. Ответ ограничен
1 048 576 байтами. Датаграммы — только IPv4.

**Программа с `план` генерируется не во все языки.** Работают `c`, `go`, `js`,
`python`, `rust` и `ts`. Цели `cpp`, `csharp`, `elixir` и `java` дают ошибку
`FLANG_PLAN_UNSUPPORTED` и не пишут ни одного файла.

**Сгенерированная программа выполняет не все эффекты.** В `c`, `go`, `python`
и `rust` план запускается командой `flang_cli --plan <имя>`. Она выполняет
эффекты для файлов, каталогов, переменных среды и аргументов. На сеть,
процессы, время, случайные числа и экран она отвечает ошибкой
`FLANG_IO_NOT_WIRED` или `FLANG_IO_NO_SCREEN`. Такой план запускайте через
`flang io`.

## Категорные объявления

Законы `категория` и `изоморфизм` компилятор проверяет на значениях из
примеров и не доказывает. Законы `моноид` над `число` и `строка` тоже только
проверяются, и `flang check --proof` возвращает код 3. Законы `монада` и законы
`отобразить` по списку доказываются. Подробно —
[Категории и функторы](../site/categories.ru.md).

## Процессы

| Не работает | Что делать вместо |
| --- | --- |
| процессы в `cpp`, `csharp`, `go`, `java`, `python`, `rust`: `flang emit` возвращает код 1 | генерировать в `c`, `elixir`, `js` или `ts` |
| `породить` (spawn) в Elixir и JavaScript | брать цель `c` |
| ограниченный почтовый ящик в Elixir | брать `c`, `js`, `ts` или неограниченный ящик |
| отправка порождённому процессу по имени, вычисленному при выполнении | дать ему работу первым сообщением, ответ слать процессу с объявленным именем |
| работа на нескольких машинах | работать на одном узле |
| доказательство отсутствия взаимной блокировки: сценарии `прогон` перебирают конечное число порядков сообщений | строить протокол так, чтобы процессы не ждали друг друга по кругу |

Планировщик в сгенерированном C работает в двух режимах. Один поток
упорядочивает сообщения по числу `seed`: одинаковый `seed` даёт одинаковый
журнал доставок. Пул рабочих потоков (поле `workers`) быстрее только на
программе с параллельной работой.
