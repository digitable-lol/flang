# Настройки: файл `.flangrc`

`.flangrc` — файл настроек проекта: каким языком `flang check` отвечает, что делать с
недоказанной программой, какие модули библиотеки можно ввозить, пределы линтера и короткие
команды проекта.

## Как выглядит файл

```
language = ru
unproven = refuse

profile = programmer

max-line-length = 120
max-conditional-depth = 2
lint = refuse

script.test = flang test main.flang
```

- Строка — «ключ = значение»; пробелы вокруг знака равенства не важны.
- Строка, начинающаяся с «#», и пустая строка пропускаются.
- Ключ встретился дважды — побеждает последний.
- Незнакомый ключ пропускается молча.

## Ключи

| ключ | значения | умолчание | кто читает |
| --- | --- | --- | --- |
| `language` | `ru` `en` | `ru` | `flang check` |
| `unproven` | `refuse` `warn` `allow` | `refuse` | `flang run`, `flang io` |
| `profile` | имя профиля или несколько через запятую | нет — библиотека без ограничений | поиск модуля по имени |
| `modules` | имена модулей библиотеки через запятую | нет | то же |
| `profile.<имя>` | имена модулей через запятую — объявление своего профиля | три профиля библиотеки | то же |
| `max-line-length` | целое больше нуля | нет: длина не ограничена | `flang lint` |
| `max-conditional-depth` | целое больше нуля | нет: глубина не ограничена | `flang lint` |
| `lint` | `refuse` `warn` | `refuse` | `flang lint` |
| `script.<имя>` | строка команды | нет | `flang run-script` |

Ключа `registry` больше нет: с 0.7.34 реестр пакетов и команда `flang install` сняты, модуль
подключается по ссылке — [«Пакеты»](../site/packages.ru.md). Строка `registry = …` в старом
файле пропускается как незнакомый ключ.

Ключи `surface`, `color`, `page`, `version`, `name`, `license`, `repository`, `issues` читают
инструменты сборки самого репозитория flang. Команды `flang` на них не смотрят.

## Язык ответа

```
$ flang check m.flang                     # в файле: language = en
module «M»: functions 2, with termination proved 2; types 0
m.flang: verified — parsing, types, termination, proof kernel and examples; no problems found
```

Код `FLANG_*` от языка не зависит. Английский текст есть не у всех диагностик: у которых нет,
те приходят по-русски. Остальные команды отвечают по-русски всегда.

## Что делать с недоказанным

`flang run` и `flang io` считают вердикт до работы. Программу, в которой есть недоказанное
обещание, они не запускают и возвращают код `3`:

```
$ flang run m.flang --function «Сумма» --args '{"части":[1,2,3]}'
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск только по явному согласию: --на-веру
…
$ echo $?
3
```

Ключ `--trust` решает один прогон, ключ файла — все:

```
unproven = warn
```

```
$ flang run m.flang --function «Сумма» --args '{"части":[1,2,3]}'
не доказано: утверждений 2: доказано 1, сетка 1, на веру 0 — запуск по настройке «unproven = warn» (/work/.flangrc)
6
```

| значение | что делает |
| --- | --- |
| `refuse` | не запускать: вердикт сказан, код `3`. Умолчание |
| `warn` | вердикт посчитать, сказать строкой и запустить, код `0` |
| `allow` | вердикта не считать; то же, что `--trust` |

Те же слова принимает ключ командной строки `--unproven`. Негодное значение — отказ и код `2`:

```
$ flang run m.flang --function «Сумма» --args '{"части":[1,2,3]}'    # в файле: unproven = allowed
flang: «allowed» — такого значения у «unproven» нет (/work/.flangrc).
Годны три: refuse — не запускать; warn — сказать и запустить;
allow — запустить, вердикта не считая.
```

## Профиль: какие модули библиотеки ввозятся

```
profile = mathematician
modules = UUID
```

Профиль — список модулей библиотеки, которые файлы проекта ввозят по имени. Модуль вне профиля
и вне `modules` не находится:

```
$ flang check u.flang                     # в файле: profile = mathematician; u.flang ввозит «UUID»
flang: модуль «UUID» библиотеки не входит в профиль «mathematician» (/work/.flangrc) — по имени не ввозится;
допишите его в «modules» или выберите другой профиль
FLANG_IMPORT_NOT_FOUND в файле u.flang, строка 1, столбец 1: не найден модуль «UUID»: …
```

Нет ни `profile`, ни `modules` — ограничений нет. С языком приходят три профиля:

| профиль | для чего |
| --- | --- |
| `mathematician` | числа, длинные целые, дроби, классические задачи, статистика, логика |
| `analyst` | числа, статистика, списки и строки, словари, дата и время, JSON, TOML, SQLite, Postgres |
| `programmer` | общие модули, форматы данных, сеть, базы данных, криптография |

Свой профиль объявляется строкой `profile.<имя> = Модуль, Модуль`; одноимённый профиль
библиотеки он перекрывает. Модули проекта и ввоз путём (`из "…"`) профилем не ограничиваются.
Ключи профиля читаются только из `.flangrc` проекта, не из `~/.flangrc`. Вердикт о доказанности
профиль не меняет: он считается по всем ввезённым файлам.

## Пределы линтера

```
max-line-length = 40
lint = refuse
```

```
$ flang lint m.flang
flang lint: файлов 1; max-line-length 40: 3; max-conditional-depth: без предела; не разобрано 0
m.flang:5: длина строки 53 > 40 (max-line-length)
m.flang:13: длина строки 59 > 40 (max-line-length)
m.flang:17: длина строки 62 > 40 (max-line-length)
$ echo $?
1
```

С `lint = warn` находки печатаются те же, код возврата `0`. Что именно считается —
раздел `lint` [справочника команд](../site/cli.ru.md#lint).

## Короткие команды

Строка `script.<имя> = <команда>` заводит короткую команду проекта — как раздел `scripts` в
`package.json`. Имя пишется строчной латиницей, цифрами, дефисом и двоеточием.

```
script.hello = echo привет
```

```
$ flang run-script hello
привет
$ flang run-script
короткие команды проекта (/work/.flangrc):

  hello                              echo привет

звать: flang run-script <имя> [доводы…]
```

Строку получает `/bin/sh -c` в каталоге файла; код возврата — её собственный. Берётся только
файл проекта: `~/.flangrc` коротких команд не даёт.

## Где файл ищется

1. **`.flangrc` проекта** — от рабочего каталога вверх. Подъём обрывается на первом каталоге,
   где лежит `.flangrc`, `.git` или `flang.package`.
2. **`~/.flangrc`** — файл человека на этой машине.

Дальний файл не перекрывает ближний.

## Что старше чего

```
ключ командной строки → переменная среды → .flangrc проекта → .flangrc дома → умолчание
```

Переменные среды: `FLANG_LANG` для `language`, `FLANG_UNPROVEN` для `unproven`.

```
$ FLANG_UNPROVEN=allow flang run m.flang --function «Сумма» --args '{"части":[1,2,3]}'
на веру: доказанность не считалась — запуск по переменной среды FLANG_UNPROVEN=allow
6
```

## Старая запись ключа

Старая русская запись ключа `unproven` читается, и `flang` отвечает на неё строкой с заменой:

| русский ключ | английский ключ |
| --- | --- |
| `недоказанное` со словами `отказ`, `предупреждение`, `разрешение` | `unproven` со словами `refuse`, `warn`, `allow` |

```
$ flang run m.flang --function «Сумма» --args '{"части":[1,2,3]}'    # в файле: недоказанное = разрешение
flang: /work/.flangrc: запись «недоказанное = разрешение» устарела и пока читается — замените её на «unproven = allow»
на веру: доказанность не считалась — запуск по настройке «недоказанное = разрешение» (/work/.flangrc)
6
```

Стоят в файле обе записи — читается английская, а про старую сказано, что её надо удалить.

## Чего в файле нет

Ключа «писать только русскими словами» или «только английскими» нет: все поверхности записи
принимаются одновременно — [«Четыре поверхности»](surfaces.ru.md).
