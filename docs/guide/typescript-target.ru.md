# Цель печати TypeScript

`flang emit программа.flang --target ts --out каталог` печатает программу в
TypeScript. Это та же печать, что у цели `js`, — те же тела функций, тот же
прогонщик, тот же рантайм, — с одной прибавкой: у каждой напечатанной функции,
записи и суммы типов стоит объявленный тип.

## Что лежит в каталоге вывода

| файл | что это |
|---|---|
| `<имя>.ts` | программа: `export function f(n: number): number`, `export type Zapis = { "поле": number }`, `export type Summa = $FlangVariant`, таблица `$PROGRAM` для прогонщика |
| `flang_runtime.js` | рантайм — те же куски, которые цель `js` вшивает в модуль, только отдельным файлом и со строкой `export`; `.ts` ввозит отсюда то, что ему нужно |
| `flang_cli.js` | прогонщик, тот же, что у цели `js`: JSON на входе, JSON на выходе |
| `tsconfig.json` | настройки `tsc`: `strict`, `allowJs`, `noEmit`; лежит рядом, чтобы проверка не требовала ключей |
| `flang_host_node.js` | хозяин ввода-вывода — только программе с объявлением `план`, как у цели `js` |

## Проверить и запустить

```sh
cd каталог && tsc -p .                       # строгая проверка типов, код 0 — модуль сходится
printf '%s\n' '{"fn":"Факториал","args":[{"n":"10"}]}' | node flang_cli.js ./factorial.ts
```

Node 23.6 и новее читает `.ts` сам, снимая типы; на Node 22.6–23.5 нужен ключ
`--experimental-strip-types`. Печатаются только стираемые конструкции —
пометки типов, `type`, `as`, — поэтому ни `enum`, ни параметров-свойств в
выводе нет, и отдельный шаг сборки не требуется. Хочется получить `.js` —
`tsc -p . --noEmit false --outDir dist`.

## Как отображаются типы

| flang | TypeScript |
|---|---|
| `число`, `нат`, `целое` и их синонимы | `number` |
| `строка` | `string` |
| `признак` | `boolean` |
| `ничто` | `null` |
| `список X` | `Array<X>` |
| запись «Имя» | `export type Imya = { "поле": T; … }`; фабрика `(fields: Partial<Imya> = {}): Imya` — недостающее поле становится `null`, как у интерпретатора |
| сумма типов «Имя» | `export type Imya = $FlangVariant`; конструктор варианта `(fields: { "поле": T }): $FlangVariant` |
| необязательное `X` | `(X\|null)` |
| функция как значение | снимается до печати одним проходом, в подписях не встречается |
| неизвестный тип | `any` |

Границы, названные прямо:

* **Сумма типов — это `$FlangVariant`, а не объединение по вариантам.** Тела
  функций разбирают варианты помощниками рантайма и `instanceof`; строгое
  объединение `{ variant: "Лист" } | …` дало бы замечание там, где код верен.
* **Внутри тел временные значения помечены `any`.** Договор типов стоит на
  подписях функций, записей и сумм; временные (`$t1`, накопитель свёртки) —
  слоты компилятора, и `tsc` их не выводит без пометки.
* **Рантайм не переписан на TypeScript.** Его типы `tsc` выводит из JavaScript
  (`allowJs`): параметры помощников — `any`, возвращаемое — по телу. Второго
  экземпляра рантайма в дереве нет намеренно: два текста разошлись бы.

## Чем отличается от цели `js`

* модуль не самодостаточен: рядом обязан лежать `flang_runtime.js`;
* `$callDeep` (расчёт на стеке под объявленный предел глубины) в `.ts` —
  обёртка, передающая рантайму адрес модуля программы: поток обязан ввозить
  программу, а не рантайм;
* всё остальное — тексты отказов, коды, пределы шагов и глубины, порядок
  полей — совпадает байт в байт: прогонщик на одних вопросах отвечает одинаково.

## Где это в дереве

Генератор — `flang/self/emit-ts.flang` поверх `flang/self/emit-js.flang`
(признак «типизировано» в общем генераторе), рантайм цели — `flang/src/emit/ts/`
(один файл `tsconfig.json`; остальное — из `flang/src/emit/js/`), строка
таблицы целей — `flang/src/emit/c/flang_repl.c`. Семя перепечатано 11 сентября
2026 (коммит `0ce948bfd`), и двоичный из него печатает в `ts`: в тот же день
`./bootstrap/flang emit docs/examples/import-check.flang --target ts --out каталог`
дал `import_check.ts`, `flang_runtime.js`, `flang_cli.js`, `tsconfig.json`, код 0.
Справка `flang emit --help` при этом всё ещё говорит «во все восемь целей» и
перечисляет девять без `ts` — текст вшит в `flang/src/emit/c/flang_repl.c`
(задача 8596).
