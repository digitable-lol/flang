# Цель печати TypeScript

`flang emit --target ts` печатает программу в TypeScript. Тела функций, прогонщик и рантайм те
же, что у цели `js`; прибавка одна — у каждой функции, записи и суммы типов стоит объявленный
тип.

```flang
модуль «Shapes»

тип «Фигура»
  вариант «Круг» с радиус: число
  вариант «Прямоугольник» с ширина: число и высота: число

объект «Точка»
  «х»: число
  «у»: число

тотальная функция «Площадь»
  принимает ф: «Фигура»
  возвращает число
  пример «Прямоугольник два на три»
    дано ф равно вариант «Прямоугольник» с ширина равным 2 и высота равным 3
    ожидается 6
  разбор ф
    случай вариант «Круг» с радиус как р
      то 3 умножить на р умножить на р
    случай вариант «Прямоугольник» с ширина как ш и высота как вы
      то ш умножить на вы

тотальная функция «Сдвиг»
  принимает х: число
  возвращает «Точка»
  запись «Точка» с «х» равным х и «у» равным 0
```

```sh
$ flang emit shapes.flang --target ts --out out-ts
напечатано файлов 5, байт 57146, в out-ts
…
$ ls out-ts
flang_cli.js  flang_runtime.js  package.json  shapes.ts  tsconfig.json
```

Объявления из напечатанного модуля:

```ts
export type Tochka = { х: number; у: number };
export function sozdatTochka(fields: Partial<Tochka> = {}): Tochka
export type Figura = $FlangVariant;
export function Krug(fields: { радиус: number }): $FlangVariant
export function Pryamougolnik(fields: { ширина: number; высота: number }): $FlangVariant
export function ploschad(f: Figura): number
export function sdvig(h: number): Tochka
```

## Что лежит в каталоге вывода

| файл | что это |
|---|---|
| модуль `.ts` | программа: функции, типы записей и сумм, таблица `$PROGRAM` для прогонщика |
| `flang_runtime.js` | рантайм; цель `js` вшивает его в модуль, здесь он отдельным файлом |
| `flang_cli.js` | прогонщик, тот же, что у цели `js`: JSON на входе, JSON на выходе |
| `tsconfig.json` | настройки `tsc`: `strict`, `allowJs`, `noEmit` — проверка не требует ключей |
| `package.json` | одна строка `"type": "module"` |

## Проверить и запустить

```sh
$ cd out-ts
$ tsc -p .
$ printf '%s\n' '{"fn":"Сдвиг","args":[{"n":"10"}]}' | node flang_cli.js ./shapes.ts
{"ok":true,"value":{"r":[["х",{"n":"10"}],["у",{"n":"0"}]]}}
```

`tsc -p .` — строгая проверка типов; код 0 значит, что модуль сходится. Node 23.6 и новее читает
`.ts` сам, снимая типы; на Node 22.6–23.5 нужен ключ `--experimental-strip-types`. Печатаются
только стираемые конструкции — пометки типов, `type`, `as`, — поэтому шаг сборки не нужен.
Нужны файлы `.js` — `tsc -p . --noEmit false --outDir dist`.

## Как отображаются типы

| flang | TypeScript |
|---|---|
| `число`, `нат`, `целое` и их синонимы | `number` |
| `строка` | `string` |
| `признак` | `boolean` |
| `ничто` | `null` |
| `список X` | `Array<X>` |
| `объект «Имя»` | `export type Imya = { поле: T; … }` и фабрика `sozdatImya(fields: Partial<Imya> = {})`; недостающее поле становится `null` |
| `тип «Имя»` с вариантами | `export type Imya = $FlangVariant` и по конструктору на вариант: `(fields: { поле: T }): $FlangVariant` |
| неизвестный тип | `any` |

Три границы:

* **Сумма типов — `$FlangVariant`, а не объединение по вариантам.** Тела функций разбирают
  варианты помощниками рантайма и `instanceof`; строгое объединение дало бы замечание `tsc` там,
  где код верен.
* **Временные значения внутри тел помечены `any`.** Типы стоят на подписях функций, записей и
  сумм; накопитель свёртки и временные `$t1` — нет.
* **Рантайм остаётся на JavaScript.** Его типы `tsc` выводит сам (`allowJs`).

## Чем отличается от цели `js`

* Модуль не самодостаточен: рядом обязан лежать `flang_runtime.js`.
* Остальное совпадает: тексты и коды отказов, пределы шагов и глубины, порядок полей. Прогонщик
  на одни и те же вопросы отвечает одинаково.
