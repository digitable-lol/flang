# Установка и первая проверка

Ставить flang можно четырьмя путями, и они **не равнозначны**. Разница не в
удобстве: два из четырёх дают инструмент, который не умеет части того, чему учит
этот курс. Поэтому глава начинается не с команды, а с таблицы.

| Путь | Что ставит | Печатает в | Вывод | Нужно на машине |
| --- | --- | --- | --- | --- |
| Homebrew | двоичный `flang` + `man flang` | только C | словами | `brew`, `cc`, `make` |
| asdf / mise | тот же двоичный | только C | словами | `asdf`, `cc`, `make` |
| Из исходников | тот же двоичный | только C | словами | `git`, `cc`, `make` |
| npm | `flang` и `flang-lsp` на Node | все восемь целей | JSON | Node ≥ 20 |

Первые три пути дают **один и тот же двоичный файл**. Четвёртый даёт другую
реализацию — она печатает в восемь языков, отвечает JSON-ом и делает несколько
проверок, которых в двоичном нет.

## Homebrew

```bash
brew install digitable-lol/tap/flang
```

Ставит `flang`, `libcompiler_flang.a`, заголовки и страницу `man flang`. Node не
нужен: в архиве релиза лежит готовый C99.

**И ещё одно, чего не надо узнавать самому через неделю.** Выпуск 0.5.0 на macOS
не собирался вовсе — ни у кого. В `flang_repl.c` объявлен `_POSIX_C_SOURCE
200809L`; на glibc эта строка `mkdtemp` открывает, а на Darwin закрывает, и
сборка с `-Werror` останавливается. Починено в 0.5.1. Если у вас macOS —
ставьте не ниже 0.5.1.

## Из исходников — путь, который проверен в этом курсе полностью

```bash
git clone https://github.com/digitable-lol/flang.git
cd flang
make -C bootstrap -j4
```

Это прогон, сделанный при подготовке курса, и вот что он дал:

```
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o compiler_flang.o compiler_flang.c
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o flang_cli.o flang_cli.c
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto   -c -o flang_repl.o flang_repl.c
ar rcs libcompiler_flang.a flang_runtime.o compiler_flang.o
cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -flto -o flang flang_cli.o flang_repl.o flang_runtime.o compiler_flang.o -lm -lpthread
```

На выходе — файл `bootstrap/flang` размером 8 392 296 байт. Node при этом не
нужен: компилятор flang уже написан на flang и напечатан в C, а C собирается
чем угодно.

Поставить в систему — `sudo make -C bootstrap install` (или
`PREFIX=$HOME/.local make -C bootstrap install`, без `sudo`). Снять —
`make -C bootstrap uninstall`.

Дальше в курсе команда пишется просто `flang`. Если вы не ставили её в систему,
подставляйте путь к собранному файлу.

## Через npm

```bash
npm install git+https://github.com/digitable-lol/flang.git
```

Прогон при подготовке курса:

```
added 1 package, and audited 2 packages in 11s

found 0 vulnerabilities
```

В `node_modules/.bin/` появляются два файла: `flang` и `flang-lsp` (языковой
сервер для редактора). Своих зависимостей у пакета нет ни одной.

Из реестра npm пока не поставить: под именем `@digitable-lol/flang` ещё ничего
не выложено. Ставится только из git.

## Проверка, что поставилось

```bash
flang --version
```

```
flang 0.5.0
```

Через npm та же команда отвечает короче — одним номером, без слова `flang`:

```
0.5.0
```

Число здесь будет ваше — оно зависит от того, какой выпуск вы взяли. Курс
проверялся на `0.5.0`, собранном из дерева на коммите `cb3b7a18`.

```bash
flang --help
```

```
flang 0.5.0 — язык, проверяемый до запуска: типы и доказанное завершение.

  flang                              оболочка: объявляй и считай сразу
  flang check <файл>                 разбор, типы, завершаемость, доказательства
  flang test <файл>                  прогон примеров, объявленных внутри функций
  flang run <файл> --function «Имя»  вычислить одну функцию и напечатать значение
  flang emit <файл> --target c       напечатать программу в C99
  flang ast <файл>                   разобранная программа деревом в JSON
  flang facts <файл> --claims '[…]'  проверить утверждения на фактах
  flang io <файл>                    исполнить план: файлы, каталоги, процессы, сеть
  flang lock <файл>                  замок: сами зависимости, а не ссылки на них
  flang package <файл>               пакет: замок с именем, версией и ведомостью
  flang repl [файл]                  та же оболочка, названная по имени
  flang lsp [--stdio]                языковой сервер для редактора (LSP)
```

Обратите внимание на пятую строку: `--target c`. У двоичного цель одна.

## Чем двоичный отличается от npm — три места, и их надо знать заранее

Это не придирка к мелочам. Курс показывает вывод двоичного, потому что это
путь установки по умолчанию, — но три расхождения меняют смысл того, что вы
увидите.

### 1. Форма вывода

Двоичный печатает словами:

```
модуль «Привет»: функций 1, из них с доказанным завершением 1; типов 0
hello.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Инструментарий на Node печатает JSON:

```json
{"valid":true,"module":"Привет","functions":[{"name":"Удвоить","total":true}],"types":[],"diagnostics":[]}
```

Обе строки — про один и тот же файл и один и тот же вердикт. Если вы поставили
через npm и ждали слов — вы не сломали установку.

### 2. Восемь целей печати против одной

`flang emit --target go` на двоичном не сработает: он знает только C. Все восемь
целей — только через npm. Проверено прогоном, [глава про восемь
целей](09-vosem-celey.md).

### 3. Двоичный делает меньше проверок — и это самое серьёзное

Проверка, которая ловит рассогласование двух модулей (та самая, ради которой в
языке заведена категорная поверхность), **в двоичном не реализована**. Слово
`FUNCTOR` встречается в его исходнике ноль раз:

```bash
grep -c FUNCTOR bootstrap/compiler_flang.c
```

```
0
```

Последствие измерено и показано в [главе про функторы](10-funktor.md): на файле
с внесённой ошибкой двоичный отвечает «замечаний нет» и кодом возврата 0, а
инструментарий на Node — `FLANG_FUNCTOR_SQUARE` и кодом 1.

Есть и четвёртое, более тонкое расхождение — в ведомости доказательства
двоичный про сетку значений пишет «нарушений НЕ ИСКАЛИ», а Node — «нарушений не
найдено (искали прогоном)». Разбор — в [главе про обещания](05-obeshchanie.md).

## Что дальше в курсе понадобится

Для глав 02–08 и 10–12 хватает двоичного. Для главы 09 (восемь целей) и для
полного разбора главы 10 нужен npm-путь. Поставьте оба — они не конфликтуют:
двоичный лежит в системе, npm-овский в `node_modules/.bin/`.

## Задача

Поставьте flang любым путём и выполните три команды:

```bash
flang --version
flang --help
```

**Проверка:** `flang --version` печатает строку вида `flang 0.5.x` и возвращает
код 0. Проверить код возврата:

```bash
flang --version > /dev/null; echo $?
```

```
0
```

Если код 1 — установка не дошла до конца, и до следующей главы идти незачем.
