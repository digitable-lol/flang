# Первая программа

Наберите файл `hello.flang`:

```flang
модуль «Привет»

тотальная функция «Удвоить»
  принимает н: число
  возвращает число
  обеспечивает «удвоенное не меньше исходного» результат не меньше н
  пример «дважды два»
    дано н равно 2
    ожидается 4
  н плюс н
```

Девять строк, и в них видно почти всё, что делает язык непохожим на другие.

## Пять частей, и каждая делает свою работу

**`модуль «Привет»`** — первая строка файла, всегда. Имя в ёлочках, потому что
имя в flang — это фраза, а не идентификатор: `«Место вставки»`, `«Есть повторы»`,
`«Отменённый заказ»`. Пробелы внутри имени законны.

**`тотальная`** — обещание, что функция завершается на любом входе. Компилятор
его **проверяет**. Не доказал — файл не собирается. Это главное решение языка, и
ему отведена [следующая глава](03-zavershaemost.md).

**`принимает` / `возвращает`** — типы. Обязательны, выводом не заменяются.

**`обеспечивает`** — обещание про результат. Имя в ёлочках обязательно: по нему
утверждение находят в ведомости доказательства.

**`пример`** — исполняемый пример. Он **часть программы**, а не тест сбоку, и
прогоняется при каждой проверке. Не сошёлся — `check` отвечает `FLANG_EXAMPLE` и
ненулевым кодом, и печатать такую программу компилятор откажется.

**Тело** — последней строкой, одной формой. Здесь `н плюс н`.

## Три команды

### Проверить

```bash
flang check hello.flang
```

```
модуль «Привет»: функций 1, из них с доказанным завершением 1; типов 0
hello.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Код возврата 0. За этой строкой стоит пять работ: разбор, проверка типов,
доказательство завершения, ядро доказательств и **прогон примеров**. Последнее
стоит отметить: в других языках «скомпилировалось» и «тесты прошли» — два разных
события. Здесь одно.

### Прогнать примеры отдельно

```bash
flang test hello.flang
```

```
hello.flang: примеров 1, прошло 1, не прошло 0
```

### Запустить

```bash
flang run hello.flang --function Удвоить --args '{"н": 21}'
```

```
42
```

Имя функции здесь **без ёлочек**: в объявлении они часть записи, в командной
строке — уже нет. `--args` берёт плоский объект JSON: ключ — имя параметра ровно
так, как оно написано в `принимает`.

## Теперь то, ради чего эта глава написана

Программа выше проходит проверку. Вывод говорит «замечаний нет». А обещание,
записанное в ней строкой `обеспечивает`, — **ложь**.

Проверьте сами:

```bash
flang run hello.flang --function Удвоить --args '{"н": -1}'
```

```
FLANG_PROPERTY: нарушено свойство «удвоенное не меньше исходного» функции «Удвоить»
```

Код возврата 1. Минус один плюс минус один — это минус два, а минус два меньше
минус единицы. Обещание «результат не меньше н» на отрицательных числах не
держится, и `flang check` этого не сказал.

**Почему не сказал** — видно, если попросить ведомость:

```bash
flang check hello.flang --proof
```

Строка про наше обещание:

```
постусловие «удвоенное не меньше исходного» функции «Удвоить» — сетка 1 значение
(примеры функции): нарушений НЕ ИСКАЛИ — прогона примеров не было, посчитано
только их число. Это не доказательство — теоремы при утверждении нет
```

и итог:

```
утверждений 1: доказано 0, сетка 1, объявлено, не доказано 0
```

**Доказано 0.** Обещание не доказано, а «посчитано на сетке из одного значения»
— из того самого примера `дано н равно 2`. Компилятор не соврал ни разу: он
сказал «доказано 0» и сказал «это не доказательство». Соврала бы привычка читать
только последнюю строку — «замечаний нет».

## Отсюда первое правило работы с flang

> `валидно` и `доказано` — разные слова. `flang check` без ключей отвечает на
> вопрос «эта программа собирается?». На вопрос «а обещания в ней верны?»
> отвечает `flang check --proof`, и отвечает он числом.

Курс дальше почти везде показывает `--proof`. Привыкайте смотреть на строку
`утверждений N: доказано M`.

## И сразу — как это чинится

Сделаем обещание правдой. Первая попытка: сузить тип входа до неотрицательных
чисел — в языке для этого есть тип `нат`, отрезок `[0, 2⁵³−1]`.

```flang
тотальная функция «Удвоить»
  принимает н: нат
  возвращает число
  обеспечивает «удвоенное не меньше исходного» результат не меньше н
  пример «дважды два»
    дано н равно 2
    ожидается 4
  н плюс н
```

```
утверждений 1: доказано 0, сетка 1, объявлено, не доказано 0
```

**Не помогло.** Утверждение стало правдой, но доказанным не стало: у ядра нет
правила на цель вида «результат не меньше <выражение>». Это не оговорка и не
случай — это измеренная граница, и [глава про цену](06-cena.md) называет её
числом.

Вторая попытка: сказать то, на что правило есть.

```flang
тотальная функция «Удвоить»
  принимает н: нат
  возвращает число
  обеспечивает «удвоенное неотрицательно» результат не меньше 0
  пример «дважды два»
    дано н равно 2
    ожидается 4
  н плюс н
```

```
постусловие «удвоенное неотрицательно» функции «Удвоить» — доказано по
объявленным типам аргументов: цель сведена правилом «неотрицательность по
построению» — утверждение обо ВСЕХ входах, а не о написанных; теоремы при нём
нет и не нужно
```

Вот теперь **доказано обо всех входах**. Ценой того, что обещание стало слабее:
«неотрицательно» говорит о функции меньше, чем «не меньше исходного».

Этот размен — «сказать слабее и получить доказательство» против «сказать сильнее
и получить сетку» — вы будете делать в flang постоянно. Он честно назван в
[замере цены](06-cena.md): из шести утверждений, которые ядро закрыло даром,
содержательными оказались два, а четыре пришлось ослабить.

## Оболочка

Голая команда открывает оболочку — как `python`, как `iex`:

```bash
flang
```

```
flang 0.5.0 — оболочка. «.помощь» — команды, «.выход» или Ctrl-D — конец.
Объявление заканчивается пустой строкой, выражение вычисляется сразу.
» 2 плюс 2
4
```

**Ловушка, на которой легко потерять час.** Голая команда открывает оболочку
только тогда, когда на входе терминал. Если ввод пришёл конвейером или из файла,
двоичный становится совсем другой программой — прогонщиком запросов «JSON на
входе, JSON на выходе»:

```bash
echo "2 плюс 2" | flang
```

```
{"ok":false,"code":"CLI","message":"ожидался объект запроса"}
```

Это написано в его собственной справке и это не ошибка, а решение. Но страница
«Первая программа» в документации языка утверждает обратное — что при конвейере
оболочка читает ввод как сценарий. Проверено: **не читает**. Для сценария нужна
команда по имени:

```bash
echo "2 плюс 2" | flang repl
```

```
4
```

Так же загружается файл в сессию:

```bash
echo "«Удвоить» от 21" | flang repl hello.flang
```

```
объявлено: тотальная функция «Удвоить» — завершение доказано
загружено из hello.flang
42
```

Здесь ёлочки нужны — это уже текст на языке, а не аргумент команды.

## Задача

Допишите в `hello.flang` вторую функцию — `«Утроить»` — так, чтобы выполнялись
три условия:

1. `flang check hello.flang` возвращает 0;
2. `flang check hello.flang --proof` печатает про неё строку со словом
   **«доказано»**, а не «сетка»;
3. утверждение при этом **говорит что-нибудь о функции**, а не повторяет её тело.

Третье условие — не придирка. Постусловие `результат равен (н плюс н плюс н)`
при теле `н плюс н плюс н` ядро принимает даром, и ведомость честно напишет
«доказано обо ВСЕХ входах». Это называется тавтологией, и это способ надуть
любую метрику доказуемости до любого размера. Разбор — в [главе про
цену](06-cena.md).

**Подсказка:** правил на форму цели у ядра ровно три — «не меньше 0», «не больше
конечного литерала», «равно». Ищите обещание, которое ложится в одно из трёх и
при этом не переписывает тело. Тип входа тоже ваш инструмент: `нат` говорит ядру
то, чего не говорит `число`.

**Проверка задачи:**

```bash
flang check hello.flang --proof | grep "утверждений"
```

Должно быть `доказано 2` при `утверждений 2`.
