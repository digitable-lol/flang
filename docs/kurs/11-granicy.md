# Границы

Список того, чего нет, длиннее списка того, что есть. Здесь он разложен на три
части, и разница между ними существенная:

- **чего нет и не будет** — решение принято, причина названа;
- **чего нет пока** — работа не сделана;
- **что сломано сегодня** — найдено при подготовке курса, прогонами.

## Чего не будет: решено, с причиной

**Замыканий не будет.** Захват окружения ломает анализ завершаемости и прямую
печать в C, Go и Rust.

Не перепутайте с другим: **функции как значения ЕСТЬ**. Это разные вещи, и
отвергнута только первая.

```
функция «Удвоить»              функция как значение
функция из числа в число       её тип
ф от 5                         применение
```

Компилятор снимает их **дефункционализацией** (приём Рейнольдса, 1972): функция
-значение заменяется меткой, применение — разбором по меткам. Так написана
`flang/stdlib/higher-order.flang` — 34 функции, все тотальные.

Цена приёма названа заранее: проход требует **видеть всю программу целиком**.

Чего действительно нет — передачи функции туда, где она приезжает данными
(например, отдать вычислитель параметром снаружи программы).

**Двух версий одной библиотеки в одной программе не будет.** Ромб зависимостей
решается подъёмом версии, а не сосуществованием.

**Полной модели Unison не будет.** Хранить код в базе вместо файлов значит
завести свой редактор, свой хостинг и потерять git. Половину Unison —
адресацию по содержимому — берут; вторую не берут.

## Чего нет пока

**Менеджера пакетов нет.** Сами пакеты есть: `flang package` кладёт библиотеку
со всем её замыканием в один файл, и он подключается одной строкой. Прогон
проекта: 8 модулей и 53 функции уехали в 13 161 байт против 99 508 байт
исходников, и на другой машине из двух файлов собралась та же программа с
побайтово той же печатью в C.

Нет того, что стоит **над** пакетом: реестра, поиска по имени, диапазонов
версий (`^1.2`), разрешения зависимостей. Обновление — взять новый файл и
положить вместо старого. Раздача библиотеки от этого не блокируется, но
становится ручной.

**Базы данных нет.** Совсем.

**Полноценной сети нет.** Ходить в сеть язык умеет — есть поручения «Запросить»,
«Открыть соединение», «Принять соединение», — но это примитивы, а не библиотека.

**Библиотека мала:** 19 файлов, 9 410 строк, 390 функций. Есть списки, строки,
числа, словари, деревья, множества, JSON, HTTP-разбор, SHA-256, Base64, UTF-8,
дата и время, функции высшего порядка.

**Прикладного кода почти нет.** Бэкенд — один пример на 7 файлов и 563 строки.
Фронтенд — демонстрация в браузере, а не приложение.

**Из реестра npm пока не поставить.** Под именем `@digitable-lol/flang` ничего
не выложено, хотя справка двоичного эту команду печатает.

**Граница входа у напечатанной программы пуста.** Сам двоичный аргументы типам
сверяет: `Факториал` объявлен на `нат`, и на `−3` отвечает
`FLANG_TYPE: аргумент «н»: -3 вне нат`. А у программы, напечатанной через
`flang emit`, этой границы нет — таблицу объявленных типов строит слой типов,
которого в двоичном нет. **За вход напечатанной программы отвечает вызывающий.**

## Что сломано сегодня: найдено прогонами при подготовке курса

Четыре расхождения между двоичным и инструментарием на Node. Все четыре
проверены на этом дереве (коммит `cb3b7a18`).

### 1. Категорной поверхности в двоичном нет вовсе

Разобрано в [главе 10](10-funktor.md). Файл с внесённой ошибкой: двоичный —
«замечаний нет», код 0; Node — `FLANG_FUNCTOR_SQUARE`, код 1.

```bash
grep -c FUNCTOR bootstrap/compiler_flang.c
```

```
0
```

Справка двоичного перечисляет, чего в нём нет, — и категорной поверхности в
этом перечне не называет.

### 2. Слово «сетка» в ведомости значит разное

Двоичный: «нарушений **НЕ ИСКАЛИ** — прогона примеров не было, посчитано только
их число».

Node: «нарушений не найдено (**искали прогоном** на всех N)».

«Не искали» и «искали, не нашли» — разные новости.

### 3. `--args` двоичного не берёт списки

```bash
flang run 035-search-insert-position.flang --function "Место вставки" \
  --args '{"элементы": [1,3,5,6], "цель": 5}'
```

```
flang run: «--args» разобрать не удалось — ждался плоский объект скаляров,
вроде '{"н":10}'
```

Двоичный читает только плоский объект скаляров. Любой пример со списком на входе
на нём не запускается — а списки в языке повсюду.

### 4. Голая команда с конвейером — не оболочка

Страница «Первая программа» в документации языка утверждает, что при конвейере
оболочка читает ввод как сценарий. Проверено:

```bash
echo "2 плюс 2" | flang
```

```
{"ok":false,"code":"CLI","message":"ожидался объект запроса"}
```

Двоичный становится прогонщиком запросов JSON. Для сценария нужна команда по
имени: `echo "2 плюс 2" | flang repl` → `4`.

### 5. Напечатанный `Makefile` для C# не работает на .NET 10

Разобрано в [главе 09](09-vosem-celey.md). `make run` падает с кодом 134, потому
что ключ `--nologo` доезжает до самой программы. Сама печать верна, ломается
обёртка.

## Что из этого следует

Ни одна из пяти находок не отменяет трёх отличий языка. Но все пять — про одно и
то же: **у языка две реализации, и они не равны**. Курс говорит об этом в каждой
главе, где это имеет значение, и повторит здесь одной строкой:

> Проверяйте тем же инструментом, каким собираетесь пользоваться в работе. Если
> вам важна категорная поверхность или списки на входе — это npm, а не brew.

## Про версию и обещания совместимости

Язык в версии `0.x`. Совместимыми поверхностями объявлены **только** канонический
JSON и коды диагностик; «синтаксис растёт через документированные предложения».

Практически это значит: синтаксис будет меняться, часть описанных ограничений
исчезнет, часть решений развернётся в обратную сторону. Курс проверен на коммите
`cb3b7a18` от 20 августа 2026 года и ни на чём другом.

## Задача

Проверьте одну границу самостоятельно и запишите, что получилось.

Возьмите любое утверждение из списка «чего нет пока» и попробуйте его опровергнуть
командой. Например:

```bash
flang run flang/stdlib/lists.flang --function Длина --args '{"элементы": [1,2,3]}'
```

**Проверка:** двоичный откажет разбором `--args`; npm-овский ответит `3`. Если у
вас двоичный ответил `3` — граница №3 закрыта, и это хорошая новость: напишите
об этом в репозиторий языка.
