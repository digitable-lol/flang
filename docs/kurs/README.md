# Курс по flang для портала Digitable

Четырнадцать глав учебного курса, готовых к заливке на
`courses.digitable.life`. **Ничего не опубликовано** — публикация решается
владельцем.

## Что здесь лежит

| Файл | Что это |
| --- | --- |
| `00-obzor.md` … `13-kuda-dalshe.md` | 14 глав курса, с front matter в формате Hugo |
| `proverka.flang` | проверка кода курса, **написанная на flang** |

## Куда это заливать

Портал — Hugo 0.93, приватный репозиторий `github.com/digitable-lol/courses`.

**Целевой адрес:** `content/post/flang-kurs/NN-slug.md` → страницы вида
`https://courses.digitable.life/post/flang-kurs/00-obzor/`.

**Почему новый трек, а не дополнение старого.** На портале уже есть трек
`flang` — «flang — полный язык поверх FTS», 14 материалов, обновлён 07.08.2026,
входная страница `/post/flang/00-overview/`. Это **разбор языка по исходникам на
конкретный коммит**, а не учебный курс, и он устарел: его первая глава сама
говорит, что три её принципиальных утверждения развернулись в
противоположную сторону за сутки.

Слить два в один нельзя — у них разный жанр. Предложение: оставить старый трек
как срез с пометкой даты, а новый поставить основным входом. Решение за
владельцем.

## Чего в этих файлах проверить нельзя, и это надо сделать руками

Репозиторий портала при подготовке курса **был недоступен** (нет ключа для
`git@github.com:digitable-lol/courses.git`, `gh` не авторизован). Всё, что
известно об устройстве портала, снято с **живых страниц** —
`https://courses.digitable.life/courses/` и `/post/flang/00-overview/`.

Отсюда: **front matter в главах — предположение, а не факт.** Поля `title`,
`description`, `date`, `lastmod`, `tags` на страницах портала видны и совпадают
по смыслу; поля `categories` и то, чем задаётся раздел каталога
(«03 · Языки и парадигмы») и порядок глав («Глава 1 из 14»), — **не видны из
собранного HTML**. Перед заливкой сверьте шапку с любой главой существующего
трека `content/post/flang/` и приведите к ней.

Что известно точно, потому что видно на собранных страницах:

- карточка трека в каталоге показывает название, описание, число материалов,
  оценку времени и дату обновления;
- хлебные крошки: `Курсы / 03 · Языки и парадигмы / <название трека> / Глава N из M`;
- под заголовком главы — время чтения, число слов, дата и дата обновления;
- метки трека `flang` на портале: `#flang`, `#fts`, `#языки программирования`,
  `#тотальность`, `#кодогенерация`.

## Как проверяется код курса

**Проверка написана на flang.** `proverka.flang` — это план (`flang io`), который
перечисляет каталог, читает каждую страницу, вынимает из неё блоки с оградой
```` ```flang ````, кладёт каждый во временный файл и зовёт на нём `flang check`.

```bash
cd docs/kurs
flang io proverka.flang
```

Итог плана — число не прошедших блоков; отчёт пишется в `proverka-otchyot.md`.

**Блоки вынимаются из готовой страницы, а не из черновика рядом.** Читатель
видит страницу — значит проверять надо её.

**Две ограды, и разница между ними — контракт:**

- ```` ```flang ```` — **целая программа**, которую можно скопировать и
  запустить. Обязана пройти `flang check` с кодом 0;
- ```` ``` ```` без имени языка — отрывок: одна строка постусловия, скелет
  `разбор`а, вывод команды. Проверке не подлежит и в неё не попадает.

**Блок, который обязан отказать**, помечается комментарием внутри самого блока:

```
// ОЖИДАЕТСЯ ОТКАЗ: …
```

Тогда проверка требует **ненулевой** код возврата, а нулевой считает провалом.
Без этого правила главы, показывающие настоящие отказы компилятора (минус ноль,
несходящиеся примеры), нельзя было бы держать проверенными.

Последний прогон — в `proverka-otchyot.md`: **17 блоков, не прошло 0**.

Сама проверка тоже проверяется:

```bash
flang check docs/kurs/proverka.flang
```

```
модуль «Проверка курса»: функций 26, из них с доказанным завершением 26; типов 6
docs/kurs/proverka.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

## Подсветка кода на портале

**Решение: печатать подсветку заранее тем же лексером, каким язык читает свои
файлы.** Ни грамматики chroma, ни набора правил не заводится.

Довод не вкусовой. Подсветка, написанная отдельными правилами (регулярками,
списком слов в теме), — это **второе описание языка**, и оно расходится с первым
в тот день, когда в язык добавят слово. Словарь языка ведёт 149 понятий на
четырёх поверхностях записи; ни один список, переписанный руками, первого
пополнения не переживёт.

Инструмент уже есть в дереве и ничего нового писать не надо —
`docs/site/podsvetka.mjs` зовёт настоящий `tokenize` из лексера языка. Прогон по
страницам этого курса:

```
страниц 14; блоков-кандидатов 94 (помечено flang 17, без метки 77);
целых программ 18; окрашено 18; текст сверен знак в знак 18 из 18
```

Восемнадцать блоков окрашиваются, остальные 77 — вывод команд и отрывки —
остаются серыми, и это правильно: блок, который лексер прочтёт «на всякий
случай», покрасится случайно совпавшими словами.

**Роли подсветки уже совпадают с портальными.** Классы `tok-slovo`, `tok-imya`,
`tok-stroka`, `tok-chislo`, `tok-kommentariy` розданы не заново: сопоставление
взято у Digitable как есть (`--course-syn-*` из `courses-v2.css`) — ключевое
слово синий, имя циан, строка зелёный, число оранжевый, комментарий приглушённый.
Шестой роли портала («объявление», фиолетовый) соответствия нет: лексер flang
такого вида токена не выдаёт, и придумывать его подсветке нельзя.

**Урок про контраст соблюдён.** Карточка кода тёмная в обеих темах, и цвет на
карточке берётся только из палитры карточки. Замер по дереву языка:

```
Контраст подсветки: палитра Digitable, карточка кода тёмная в обеих темах;
замеров 18 (мест темы 3 × цветов текста 6), норма 4.5:1, ниже нормы 0;
худший — ключевое слово 7.94:1.
```

**Чего решить нельзя без репозитория портала:** как именно готовый HTML попадает
в страницу Hugo — сырой блок в markdown (нужен `unsafe = true` у goldmark) или
шорткод. Оба пути рабочие, выбор — за тем, кто увидит `config.toml`.

## Откуда взяты числа курса

Правило курса: **ни одного числа и ни одного вывода команды по памяти.** Всё
снято на коммите `cb3b7a18` (= `github/main` на 20 августа 2026).

| Что | Чем снято |
| --- | --- |
| 9687 функций, 7445 тотальных, носители обещания | `node flang/scripts/proof-ledger.mjs` |
| 395 утверждений, 236 доказано, 155 сеткой, 0 аксиом | тот же прогон |
| 2 из 20, причины отказов, цена в строках и секундах | `docs/benchmark-proof-cost-2.md`, перепроверено `node docs/benchmark2/tools/measure20.mjs` и `reasons.mjs` |
| 149 понятий, покрытие поверхностей | `node docs/site/surfaces-run.mjs` |
| 8 целей печати, размеры напечатанного | `flang emit … --target …`, восемь прогонов |
| ответы восьми целей | сборка и запуск восьми напечатанных программ |
| 82 задачи LeetCode | `ls flang/examples/leetcode/*.flang \| wc -l` |
| 19 файлов, 390 функций библиотеки | `docs/site/numbers.json` (эти ключи с деревом сходятся) |

**Важно при обновлении курса.** `docs/site/numbers.json` на день выпуска
**отстал от дерева** на шесть ключей — курс называет числа дерева, а не файла.
Перед правкой чисел прогоняйте `node docs/site/site-numbers.mjs --check` и
смотрите, что он скажет.

## Что делать перед заливкой

1. сверить front matter с главой существующего трека `content/post/flang/`;
2. решить, как заводится раздел каталога и порядок глав (данные трека, вес,
   или что там принято);
3. выбрать способ вставки подсветки (сырой HTML или шорткод) и прогнать
   `docs/site/podsvetka.mjs` по страницам;
4. прогнать сборку Hugo и посмотреть на битые ссылки: **внутренние ссылки в
   главах написаны как `02-pervaya-programma.md`** и при заливке обязаны стать
   портальными адресами;
5. прогнать `flang io proverka.flang` ещё раз — числа и выводы в курсе привязаны
   к коммиту, и на новом дереве часть из них поедет.
