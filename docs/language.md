# Справочник языка FTS

Основной синтаксис FTS - отступный и силлогистический. Структура задаётся переносами строк и отступами; фигурные скобки, двоеточия, точки и стрелки не нужны.

## Полный пример

```fts
категория «Исполнение заказа»

  объект Заказ
    номер является строкой
    «готов к отгрузке» является состоянием «Готов к отгрузке»

  морфизм «Готовый заказ можно отгрузить»
    если «Готов к отгрузке»
    то «Отгрузить заказ разрешено»

  теорема «Заказ ЗК-7781 можно отгрузить»
    дано Заказ имеет «готов к отгрузке» равное да
    в данных заказы найти где номер равен «ЗК-7781»
    по морфизму «Готовый заказ можно отгрузить»
    следовательно «Отгрузить заказ разрешено»
```

## Основные понятия

### Категория

Категория задаёт замкнутую предметную область: набор объектов и допустимых морфизмов между их состояниями. В прикладной архитектуре это ближе всего к DDD bounded context.

### Объект

Объект задаёт наблюдаемую форму данных:

```fts
объект «Строка счёта»
  номер является строкой
  сумма является деньгами
  «срок оплаты» является датой
  комментарий иногда является строкой
```

Встроенные формы:

| Запись | Канонический тип |
|---|---|
| `является строкой` | `Строка` |
| `является числом` | `Число` |
| `является датой` | `Дата` |
| `является деньгами` | `Деньги` |
| `является признаком` | `Признак` |
| `иногда является ...` | тип может отсутствовать |

Именованное состояние записывается явно:

```fts
«готов к отгрузке» является состоянием «Готов к отгрузке»
```

### Морфизм

Морфизм - допустимый направленный переход от одного типа свидетельства к другому:

```fts
морфизм «Готовый заказ можно отгрузить»
  если «Готов к отгрузке»
  то «Отгрузить заказ разрешено»
```

Это именно морфизм, а не функтор. Функтор в теории категорий отображает целую категорию в другую категорию и в текущем прикладном ядре не требуется.

Закон морфизма пока является явной предпосылкой сертификата. FTS проверяет правильность композиции, но не объявляет внешний бизнес-закон доказанным из ничего.

### Теорема

Теорема связывает конкретный факт из данных с одним или несколькими морфизмами:

```fts
теорема «Счёт требует контроля»
  дано «Строка счёта» имеет просрочен равное да
  в данных счета найти где номер равен «СЧ-0087»
  по морфизму «Просроченный счёт требует контроля»
  следовательно «Требуется контроль»
```

Строка `дано` определяет исходный факт. Строка `в данных` строит однозначный путь к конкретному объекту. `по морфизму` называет используемое правило, а `следовательно` проверяет ожидаемый результат: если он не совпадает с выводом, компилятор отклоняет теорему.

## Композиция

Несколько переходов записываются последовательно:

```fts
теорема «Лимит может быть установлен»
  дано «Заявка на лимит» имеет «скоринг пройден» равное да
  в данных заявки найти где номер равен «ЛМ-205»
  по морфизму «Пройденный скоринг открывает риск-проверку»
  затем по морфизму «Успешная риск-проверка разрешает лимит»
  следовательно «Лимит может быть установлен»
```

Кодомен предыдущего морфизма обязан совпасть с доменом следующего.

## Исполняемые утилиты

Утилита задаёт чистое детерминированное вычисление над одним объектом. Она явно называет вход, выход и начальный результат:

```fts
утилита «Рассчитать скидку»
  принимает Покупка
  возвращает деньги
  начинает с 0
```

Правила проверяются по порядку. Выполняются все правила, условия которых истинны:

```fts
правило «Большая покупка»
  если сумма не меньше 10000
  то добавить 10 процентов от поля сумма
```

Несколько условий соединяются словом `и`. Доступны сравнения `равен`, `не равен`, `больше`, `меньше`, `не больше`, `не меньше`. Действие либо задаёт результат через `то результат равен ...`, либо прибавляет числовое значение через `то добавить ...`.

Свойство является проверяемым постусловием и не исправляет результат автоматически:

```fts
свойство «Скидка ограничена»
  результат не больше 20 процентов от поля сумма
```

Нарушение свойства завершает выполнение ошибкой `FTS_UTILITY_PROPERTY`.

Пример является исполняемым тестом:

```fts
пример «Большая покупка»
  дано сумма равна 20000
  дано «постоянный клиент» равен нет
  ожидается результат равен 2000
```

Команда `fts test model.fts` выполняет примеры непосредственно по FTS-модели. Команда `fts generate model.fts --out generated` создаёт TypeScript-реализацию и тесты на `node:test`.

В процентном выражении имя поля указывается без изменения формы: `10 процентов от поля сумма` или `10 процентов от поля «общая сумма»`. Компилятор намеренно не угадывает грамматические падежи имён.

## Имена и кавычки

Одно слово можно писать без кавычек: `Заказ`, `номер`, `заявки`. Имя с пробелами пишется в обычных кавычках или ёлочках: `"Исполнение заказа"`, `«Исполнение заказа»`.

Обе формы равноправны. Имена нормализуются в Unicode NFC. В каноническом JSON кавычки не сохраняются.

## Значения

Поддерживаются:

- `да` и `нет`;
- числа;
- `ничто`;
- строки и имена в обычных кавычках или ёлочках.

## Вложенные объекты

Для реальной композиции данных можно написать:

```fts
объект Заказ
  вложен объект «Адрес доставки»
```

Состояние `«Готов к отгрузке»` не является вложенной структурой: это тип факта. Поэтому оно описывается через `является состоянием`, а не через вложенность.

## Комментарии

Поддерживаются `// однострочные` и `/* блочные */` комментарии.

## Каноническая модель и совместимость

Естественная поверхность компилируется в тот же `FtsDocument`, который используют CLI, Node.js, browser-entry и MCP. Старый скобочный синтаксис пока принимается для обратной совместимости, но не является рекомендуемым авторским форматом.

В канонической модели `fts/1` некоторые внутренние поля всё ещё называются `functors` и `apply`. Это наследие первой версии wire format; пользовательская и научная терминология исправлена на `morphism`. Миграция wire format будет версионированной и не потребует возвращения старого синтаксиса.

## English surface

The same indentation-based surface is available in English. It has the same
semantics and compiles to the same canonical built-in types; it is not a
separate runtime or a translation performed by an AI model.

```fts
category "Sales"

  object Purchase
    amount is money
    "loyal customer" is boolean

  utility "Calculate discount"
    accepts Purchase
    returns money
    starts with 0

    rule "Large purchase"
      if amount is at least 10000
      then add 10 percent of field amount

    example "Twenty thousand purchase"
      given amount equals 20000
      given "loyal customer" equals false
      expected result equals 2000
```

Multi-word names must use regular quotes. Russian guillemets remain accepted
because both surfaces use the same Unicode-aware name reader. See
`examples/utilities/discount.en.fts` for a runnable example.
