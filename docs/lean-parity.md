# Доказательства рядом с Lean 4: замер на сорока задачах

Цель сравнения — не формализация математики, а то, что программист доказывает про
свои программы. Мерило простое: сорок небольших утверждений, которые в Lean 4
закрываются стандартными тактиками (`induction`, `cases`, `simp`, `rw`, `omega`,
`decide`, `calc`, `constructor`, `exists`, `termination_by`). Для каждого есть пара:
файл Lean и файл flang.

## Где лежит и как прогнать

| что | где |
| --- | --- |
| перечень задач, ожидаемый итог, первая причина отказа | `flang/proof/parity/corpus.tsv` |
| Lean-версии, по файлу на задачу | `flang/proof/parity/lean/<имя>.lean` |
| flang-версии без доказательства | `flang/proof/parity/programs/<имя>.flang` |
| flang-версии с ручными шагами | `flang/proof/parity/programs/<имя>-by-hand.flang` |
| прогон | `bootstrap/flang run-script lean-parity:probe` |

Прогон для каждой задачи зовёт `flang check --proof --strict` на файл без
доказательства; код 0 — «автоматически». Иначе, если рядом есть файл с ручными
шагами, зовёт его; код 0 — «вручную». Иначе — «никак». Затем зовёт `lean` на
Lean-версию (берётся из `LEAN` или из `PATH`). Печатает строку на задачу и итог.
Итог, разошедшийся со столбцом `expected` таблицы, и отказ Lean — провал с кодом
`FLANG_PROBE_LEAN_PARITY`; таблица — храповик: волна, открывшая задачу, обязана
поправить её строку.

«Вручную» значит: автор написал теорему с индукцией, шагами `затем … по …`,
`по свойству`, `по предположению` или переписал утверждение в форму, которую ядро
берёт. Файл с ручными шагами есть у каждой задачи, которая не взялась
автоматически, — это честная попытка, и её отказ записан кодом.

## Итог

| | число |
| --- | --- |
| Lean 4 принимает | 40 из 40, без `sorry` |
| flang: автоматически | 12 |
| flang: вручную | 2 |
| flang: никак | 26 |

Из 14 доказанных независимая проверяющая программа (`flang/proof/checker`)
переигрывает 6, на слове ядра остаются 7, и на одной она с ядром расходится:
перестановку слагаемых над `неотрицательное` ядро доказывает правилом «кольцо точного
целого», а проверяющая программа это правило над `неотрицательное` не принимает.

Столбец «задач упирается» считает по первой причине отказа (`gap` в
`corpus.tsv`). Списочные задачи после починки базы упираются дальше в развёртку
на `приписать`, в законы встроенных форм на конструкторе и в переписку леммой.

## Чего у flang нет и не нужно

Зависимые типы, вселенные, свои тактики, mathlib, `native_decide` — разобрано в
[`road-to-1-0.md`](road-to-1-0.md), раздел «Доказывалка рядом с Lean». Задачи этого
набора ни одной из этих возможностей не требуют.
