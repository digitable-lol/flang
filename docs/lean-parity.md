# Доказательства рядом с Lean 4: замер на шестидесяти задачах

Цель сравнения — не формализация математики, а то, что программист доказывает про
свои программы. Мерило простое: шестьдесят небольших утверждений, которые в Lean 4
закрываются стандартными тактиками (`induction`, `cases`, `simp`, `rw`, `omega`,
`decide`, `grind`, `calc`, `constructor`, `exists`, `termination_by`, `fun_induction`).
Для каждого есть пара: файл Lean и файл flang.

Первые сорок задач заведены 16 октября 2026. Двадцать добавлены 10 ноября 2026 там, где
Lean силён: индукция по натуральным и по спискам с вложенной структурой, линейные цели с
несколькими допущениями, цепочки `simp`, `decide` на конечных типах, кольцо, сортировка и
поиск, инварианты циклов (`цикл`, `пока` с `убывает`).

## Где лежит и как прогнать

| что | где |
| --- | --- |
| перечень задач, ожидаемый итог, первая причина отказа и её класс | `flang/proof/parity/corpus.tsv` |
| Lean-версии, по файлу на задачу | `flang/proof/parity/lean/<имя>.lean` |
| flang-версии без доказательства | `flang/proof/parity/programs/<имя>.flang` |
| flang-версии с ручными шагами | `flang/proof/parity/programs/<имя>-by-hand.flang` |
| прогон задач | `bootstrap/flang run-script lean-parity:probe` |
| пробы таблицы разрыва | `flang/proof/probes/lean-parity-gaps`, `bootstrap/flang run-script lean-parity:gaps` |

Прогон для каждой задачи зовёт `flang check --proof --strict` на файл без
доказательства; код 0 — «автоматически». Иначе, если рядом есть файл с ручными
шагами, зовёт его; код 0 — «вручную». Иначе — «никак». Затем зовёт
`lean -DwarningAsError=true` на Lean-версию (`lean` берётся из `LEAN` или из `PATH`):
предупреждение, в том числе о `sorry`, — отказ. Печатает строку на задачу и итог.
Итог, разошедшийся со столбцом `expected` таблицы, и отказ Lean — провал с кодом
`FLANG_PROBE_LEAN_PARITY`; таблица — храповик: волна, открывшая задачу, обязана
поправить её строку.

«Вручную» значит: автор написал теорему с шагами, записал свойство постусловием
функции, сменил тип на тот, над которым утверждение верно и доказуемо (`точное целое`,
объявленный тип «Нат»), или сослался на доказанное в библиотеке. Утверждение остаётся
тем же по смыслу; что именно изменено, сказано в таблице причин. Файл с ручными шагами
есть у каждой задачи, которая не взялась автоматически, — это честная попытка, и её
отказ записан кодом.

## Почему не берётся

Класс причины: (а) не хватает правила ядра; (б) правило есть в исходнике и ждёт печати;
(в) не хватает факта в `flang/stdlib`; (г) задача записана над типом или в форме, где она
неверна или недоказуема по устройству языка. Класс стоит у первой причины, по которой
не берётся файл без доказательства.

## Что добавлено в библиотеку

`flang/stdlib/list-facts.flang`, модуль «List facts»: длина списка в `точное целое`
(«Звеньев») и факты, которые `check --proof --strict` доказывает ядром, код 0, —
11 обязательств из 11.

| факт | где записан |
| --- | --- |
| длина сцепки — сумма длин | постусловие «Сцепить» |
| дописанный в конец удлиняет на один | постусловие «Дописать» |
| разворот сохраняет длину | постусловие «Развернуть ряд» |
| длина сплющенного — сумма длин рядов | постусловие «Сплющить ряды» |
| накопитель выносится из суммы | постусловие «Накопить сумму» |
| вставка удлиняет на один, упорядочение вставками сохраняет длину | постусловия «Поставить» и «Упорядочить вставками» |
| встречается в сцепке, если встречается в одной из частей | утверждение |
| счёт вхождений в сцепке — сумма счётов | утверждение |
| нижняя граница переживает вставку, когда она не больше вставленного | утверждение |

Задача ссылается на библиотеку строкой `использует «List facts» из …`, и её
утверждение закрывает правило «цель есть допущение».
