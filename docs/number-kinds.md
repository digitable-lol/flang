# Виды чисел и что о них доказывает ядро

Страница отвечает на два вопроса: какие числа есть в языке и библиотеке и какие
законы арифметики ядро доказывает о каждом. Каждая ячейка таблицы законов —
ответ `bootstrap/flang check <файл> --proof` на пробе, описанной перед таблицей.

## Что есть

| вид | где | представление |
| --- | --- | --- |
| `число` | язык | IEEE-754 double |
| `неотрицательное` (`нат`) | язык | целое из [0, 2⁵³−1] |
| `целое` | язык | целое из [−(2⁵³−1), 2⁵³−1] |
| `вес` (`стоимость`) | язык | [0, +∞] |
| `сотых`, `тысячных` | язык | целое число сотых или тысячных долей, не меньше нуля |
| `точное целое` | язык | целое не меньше нуля без верхней границы; значение пишется списком разрядов, ноль — `[]` |
| `точное целое со знаком` | язык | целое со знаком без верхней и нижней границы; значение пишется `точное целое со знаком -7` |
| длинное целое | `flang/stdlib/bignum.flang`, модуль «Bignum» | список разрядов по основанию 2²², младший первым; без знака |
| дробь | `flang/stdlib/rationals.flang`, модуль «Rationals» | знак, числитель и знаменатель — длинные целые, дробь всегда сокращена |
| нумерал Чёрча | `docs/examples/numbers/church-numerals.flang` | функция, применяющая другую функцию n раз |

Сумма, произведение, частное и остаток двух значений вида `неотрицательное`,
`целое`, `сотых` или `тысячных` имеют тип `число`. Функция с телом `а плюс б` над
двумя `неотрицательное`, объявленная `возвращает неотрицательное`, не проходит
проверку типов:

```
FLANG_TYPE … функция «Ф» объявлена как неотрицательное, а тело даёт число
```

По той же причине накопитель цикла `храним сумма: неотрицательное` с шагом
`сумма плюс …` — ошибка типов. У `вес` сумма остаётся `вес`, у обоих точных
целых сумма и произведение остаются того же вида.

## Что доказывает ядро о встроенных числах

Проба — функция из одной строки, у которой закон записан постусловием. Например,
перестановка слагаемых:

```flang
модуль «Проба»

тотальная функция «Ф»
  принимает а: сотых, б: сотых
  возвращает число
  обеспечивает «закон» результат равен (б плюс а)
  а плюс б
```

Таблица измерена 27 ноября 2026 года компилятором 0.8.0. В пробах нет блоков
`пример`, поэтому на недоказанный закон ядро отвечает «не доказано», код
возврата 3. С примерами тот же закон получает ответ «проверено только на тестах»,
код тоже 3. Функции над `неотрицательное`, `целое`, `сотых` и `тысячных`
объявлены `возвращает число`, остальные возвращают свой вид.

| закон | `число` | `неотрицательное` | `целое` | `вес` | `сотых`, `тысячных` | `точное целое` | `точное целое со знаком` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `а + б = б + а` | доказано | доказано | доказано | доказано | доказано | доказано | доказано |
| `а × б = б × а` | доказано | доказано | доказано | ошибка `FLANG_INFINITY` | доказано | доказано | доказано |
| `(а + б) + в = а + (б + в)` | нет | нет | нет | нет | нет | доказано | нет |
| `(а × б) × в = а × (б × в)` | нет | нет | нет | ошибка `FLANG_INFINITY` | нет | доказано | нет |
| `а + б ≥ а` | отвергнуто: NaN | доказано | отвергнуто: `а = 0, б = -1` | нет | доказано | доказано | нет |
| `а ≥ 0` | отвергнуто: NaN | доказано | отвергнуто: `а = -1` | доказано | доказано | доказано | нет |
| `max(а, б) ≥ а` | нет | доказано | нет | нет | доказано | доказано | нет |
| `а / б ≥ 0` | отвергнуто: NaN | отвергнуто: `а = 0, б = 0` | отвергнуто: `а = 0, б = 0` | ошибка `FLANG_INFINITY` | нет | ошибка `FLANG_TYPE` | нет |
| `а mod б ≥ 0` | отвергнуто: NaN | отвергнуто: `а = 0, б = 0` | отвергнуто: `а = 0, б = 0` | ошибка `FLANG_INFINITY` | нет | нет | нет |

Как читать ячейки.

* «Отвергнуто: NaN» — ошибка `FLANG_BOUND_ON_NAN`, код возврата 1: в типе `число`
  есть «не число», оно не больше и не меньше ничего.
* «Отвергнуто: `а = …`» — ошибка `FLANG_PROPERTY`, код возврата 1: компилятор сам
  вычислил функцию на названном входе и получил нарушение постусловия.
* «Ошибка `FLANG_INFINITY`» — умножение, деление и остаток над `вес` не проходят
  проверку типов: «`mul` над вес и вес выводит из отрезка [0, +∞]».
* «Ошибка `FLANG_TYPE`» у `точное целое` — деления у этого вида нет: он знает
  `плюс`, `минус`, `умножить на` и `остаток от`.

Почему так.

* **Перестановка** — правило ядра «одинаковы до порядка соседей»: два аргумента
  одного `плюс` или `умножить на` сравниваются в любом порядке. Это верно и для
  IEEE-754.
* **Сочетательность доказывается только у `точное целое`**: её сводит правило
  кольца точных. Для `число` она ложна
  (`(0.1 + 0.1) + 0.6 = 0.8`, `0.1 + (0.1 + 0.6) = 0.7999999999999999`). Для
  `неотрицательное` ложна тоже, когда сумма выходит за 2⁵³:
  `flang run` даёт `(1 + 2) + 9007199254740991 = 9007199254740994` и
  `1 + (2 + 9007199254740991) = 9007199254740992`. С предусловием «каждое
  слагаемое от 0 до 1000» она верна для `целое`, но и тогда не доказывается:
  правила, которое переставляет скобки, у ядра для этих видов нет.
* **Порядок.** «Максимум не меньше первого» доказывается для `неотрицательное`,
  `сотых`, `тысячных` и `точное целое` правилом «разбор цели по условию». Для
  `число`, `целое`, `вес` и `точное целое со знаком` не доказывается. Запись с
  ветвлением в самом постусловии
  (`если б больше а то (результат больше а) иначе (результат не меньше а)`) для
  `число` и `целое` тоже не доказывается.
* **Деление.** `делить на` даёт `число` на любом встроенном виде, кроме точных;
  `0 / 0` и `х mod 0` — NaN, поэтому неотрицательность частного и остатка без
  предусловия неверна, и для `неотрицательное` и `целое` компилятор называет
  контрпример `а = 0, б = 0`.
* **`точное целое со знаком`.** Ядро не знает этого вида по имени. Доказывается
  только перестановка; законы порядка для него ложны (число может быть
  отрицательным), и ядро отвечает «не доказано», не называя контрпримера.
* **Моноиды.** Сочетательность и обе единицы `моноид «…»` ядро сводит над
  объявленным носителем. У `точное целое` со сложением и единицей `[]` сводятся
  все три: `flang check docs/examples/proofs/exact-sum.flang --proof` отвечает
  «доказано 3», код 0. Свёртка этой операцией считается по частям
  ([параллельный `отобразить` и свёртка по моноиду](flang/concurrency/parallel-map-and-monoid-fold.md)).
  У `число` сочетательность не сводится, и свёртка идёт по порядку. На файле с
  моноидом с обращением и объявленными свойствами
  (`docs/examples/reference/ru/monoids.flang`) `flang check --proof` отвечает
  «доказано 4» из 9, один закон проверен только на тестах, код возврата 3.

## Дроби

`flang/stdlib/rationals.flang`: сложение, вычитание, умножение, деление,
противоположная, сравнение, равенство, запись строкой и гармоническая сумма как
пример. Деление требует ненулевого делителя предусловием; «Дробь из целых»
требует знаменателя не меньше единицы.

`flang check flang/stdlib/rationals.flang --proof` считает 16 постусловий и
утверждений: 12 доказано, 4 не доказано. Доказаны, среди прочих:

* ноль не бывает отрицательным — у результата сокращения и у противоположной;
* знак дроби из целых — знак числителя.

Не доказаны четыре, у каждого ответ «доказательство опирается на недоказанное»:

* произведение отрицательно только при разных знаках;
* нулевое произведение не отрицательно;
* частное отрицательно только при разных знаках;
* гармоническая сумма без слагаемых — ноль.

Законы алгебры записаны постусловиями в `docs/examples/numbers/rational-laws.flang`.
Ни один из семи не доказан, все проверены только примерами:

| закон | ответ ядра | почему |
| --- | --- | --- |
| перестановка слагаемых и множителей | проверено только примерами | сложение дробей вызывает функции «Bignum», а правило перестановки знает только встроенные `плюс` и `умножить на` |
| перестановка скобок | проверено только примерами | правила для скобок нет даже у встроенных чисел |
| прибавить ноль, минус на минус | проверено только примерами | нужно раскрыть «Сократить» и «НОД», а фактов о делимости у ядра нет |
| дробь не меньше самой себя | проверено только примерами | то же |

Не доказывается и «сумма двух неотрицательных неотрицательна»: знак суммы выводится
из двух постусловий вызванных функций, а сцеплять два постусловия в одно ядро не
умеет. В модуле этого постусловия нет.

Дроби и длинные целые запускаются `flang run` только с `--на-веру`. В «Bignum»
из 20 постусловий доказано 17. Два («ширина не меньше каждой длины», «меньшее
минус большее — ноль») проверены только на примерах, одно («короткие множатся
столбиком» у функции «Карацуба») не доказано. Вердикт о программе целиком —
«доказано не всё».

Десятичные с фиксированной точкой уже есть — `сотых` и `тысячных`; что о них
доказано, сказано в таблице выше.

## Нумералы Чёрча

Выражаются. Функция-значение пишется `функция «Имя»`, захват аргументов —
`функция «Имя» с н равным …`; анонимных функций нет, и каждая ступень нумерала
названа:

```flang
тотальная функция «Следующее»
  принимает н: функция из (функция из числа в число) и числа в число, ф: функция из числа в число, х: число
  возвращает число
  ф от (н от ф и х)
```

`flang run docs/examples/numbers/church-numerals.flang --function "Два на три"`
печатает `6`; сложение печатает `5`. Нумералы мономорфны — носитель `число`.
Возведение в степень (`н м`) требует применить нумерал к нумералу, и проверка
типов отказывает:

```
FLANG_TYPE … аргумент 1 применения «н»: ожидался функция из числа в число,
получен функция из (функция из числа в число) и числа в число
```

Для степени нужен полиморфный тип нумерала, а параметров типа у типа функции нет.
