# Песочница: устройство страницы

Страница для тех, кто меняет песочницу сайта (`docs/site/playground.js`) или ставит на неё
ссылки с других страниц. Что песочница умеет для посетителя, написано на самой странице:
`docs/site/playground.ru.md`.

## Сетапы

Сетап — именованная рабочая раскладка. Все сетапы перечислены одной таблицей `SETUPS` в
начале `docs/site/playground.js`; новый сетап — новая строка этой таблицы.

| поле | значение |
|---|---|
| `key` | имя в адресе: `#setup=<key>` |
| `name`, `note` | название и строка под ним на плитке, по-русски и по-английски |
| `starter` | стартовая программа: ключ из таблицы `STARTERS`; либо `text` — свой текст |
| `lang` | язык редактора слева, если это не flang (сейчас только `c`) |
| `views` | вкладки справа; первая открыта сразу |
| `enter` | что делает главная кнопка и Ctrl+Enter: `run`, `check`, `test`, `emit`, `translate`, `argue` |
| `buttons` | какие кнопки видны, главная первой |
| `call` | показать поля «функция» и «аргументы» |
| `labels` | своё название вкладки в этом сетапе |

Сейчас сетапов восемь: `first`, `proof`, `tests`, `emit`, `reasoning`, `formula`, `prose`, `c`.

## Адрес

```
<сайт>/playground.html#setup=<сетап>&code=<текст>&do=<действие>&fn=<функция>&args=<аргументы>&target=<язык>
<сайт>/en/playground.html#…            (английская страница, те же поля)
```

Поля после `#` разделены `&`, порядок любой, все необязательны. После `#` браузер ничего
не отправляет серверу.

| поле | значение |
|---|---|
| `setup` | сетап: `first`, `proof`, `tests`, `emit`, `reasoning`, `formula`, `prose`, `c` |
| `code` | текст программы: UTF-8 → DEFLATE без заголовка (`deflate-raw`) → base64url без `=` |
| `text` | текст программы: UTF-8 → base64url без `=`; его пишет страница, когда в браузере нет `CompressionStream` |
| `example` | вместо текста — стартовая программа по имени: `hello`, `proof`, `monad`, `loop`, `class`, `emit-c` |
| `do` | что сделать сразу: `check`, `test`, `run`, `emit`; без поля текст только открывается. Флаг `&run` без значения = `do=check` |
| `fn` | для `do=run`: имя функции без ёлочек, percent-encoding |
| `args` | для `do=run`: объект JSON с аргументами, percent-encoding |
| `target` | для `do=emit`: `c`, `cpp`, `go`, `rust`, `java`, `js`, `ts`, `elixir`, `python`, `csharp` |

Какой сетап откроется, решает функция `planOf` в `playground.js`:

1. Назван `setup` — открывается он. Без `code`, `text` и `example` в нём стоит черновик
   посетителя, а если черновика нет — стартовая программа.
2. Есть текст и нет `do` (или `do=check`) — сетап выбирается по первой значащей строке
   текста: рассуждение → `reasoning`, формула → `formula`, программа → `first`
   (с `do=check` — `proof`).
3. Иначе сетап выбирается по `do`: `check` → `proof`, `test` → `tests`, `run` → `first`,
   `emit` → `emit`.
4. Иначе по `example`: `hello`, `loop`, `class` → `first`; `proof`, `monad` → `proof`;
   `emit-c` → `emit`.

Текст из адреса важнее черновика: ссылка с `code`, `text` или `example` показывает свой
текст, а черновик сетапа остаётся в хранилище нетронутым, пока посетитель не начнёт
править.

Ссылки, написанные до появления сетапов, открываются по правилам 2–4. Пример ссылки для
кнопки на главной: `playground.html#example=proof&do=check`. Кнопка «Поделиться» пишет
`#setup=<сетап>&code=…`, а в сетапах с запуском и генерацией кода добавляет `fn`, `args`
и `target`.

## Ссылка «запустить в песочнице» под блоком кода

Ссылку руками писать не нужно. Её ставит `docs/site/search.js` под каждым блоком
```` ```flang ````, который является целой программой, то есть содержит строку
`модуль «…»` (`module`, `категория`, `category` — тоже). От страницы нужно три вещи:

1. Блок, который читатель должен запустить, — целая программа с `модуль «…»` первой
   значащей строкой. Отрывок без `модуль` помечается ```` ```flang fragment ```` и ссылки
   не получает.
2. Программа, которая по замыслу не проходит проверку, помечается
   ```` ```flang refused ````. Ссылка на ней есть; проверка страниц ждёт от неё код 1.
3. Если страница показывает команду и её вывод, они пишутся тройкой: блок программы с
   именем файла, блок ```` ```bash ```` с одной командой `flang check|test|run|emit
   <имя>.flang …` и сразу за ним блок вывода. Проверка `playground:site` сравнит вывод с
   тем, что печатает компилятор песочницы.

Правила тройки:

- имя файла программы названо либо в ограде: ```` ```flang hello.flang ````, либо в
  обратных кавычках в последней непустой строке перед блоком;
- блок вывода — ограда без языка или ```` ```text ````;
- при сравнении пробелы и переносы строк не учитываются; строка из одного `…` значит
  «тут что угодно»; всё остальное должно встретиться в выводе в том же порядке;
- команда, чей файл не назван ни одним блоком страницы, не сравнивается.

Ссылка под блоком, у которого есть такая команда, открывает песочницу сразу с этой
командой (`do=run&fn=…&args=…`).

## Проверки

Все проверки требуют собранной песочницы в `docs/site/out/playground`
(`bootstrap/flang run-script playground:build`).

| рецепт | что проверяет |
|---|---|
| `playground:page` | чистую часть `playground.js` на настоящих ответах компилятора и проверку своего текста |
| `playground:starters` | каждую стартовую программу через три кнопки: «Проверить», «Тесты», «Запустить» |
| `playground:site` | каждый блок-программу страниц сайта и тройки «программа, команда, вывод» |
| `playground:probe` | обвязку: рассуждение, формулу, генерацию кода, перевод с C |
| `playground:version` | версия компилятора песочницы равна версии дерева |

`playground.js` состоит из двух частей. Первая — таблицы и чистые функции: `planOf`
(что открыть по адресу), `present` (ответ компилятора → заголовок, сообщения, отметки
строк, строки таблиц), `callOf`, `wordAt`, `libraryHint`. Она не трогает документ, и её
исполняет Node. Вторая часть рисует страницу из того, что вернула первая.

`playground:page` (режим `--страница` в `flang/src/emit/js/flang_host_browser.js`)
прогоняет через первую часть: шесть стартовых программ × три кнопки; программу с
несошедшимся тестом; ложное постусловие; опечатку в имени; пустой текст; программу с
`использует «Lists»`; модуль, названный по-русски; каждый сетап — по своей ссылке и через
свою главную кнопку; ссылки прежнего формата. Проверка краснеет на исключении, пустом
заголовке и заголовке, который остался словом ожидания («проверяю…»).

Свой текст (`prose`) проверяется там же: пример сетапа грамматика обязана разобрать весь,
логическая форма должна построиться у всех предложений, кроме одного, и находки должны
быть «Вывод не следует» и «Противоречие»; у предложения без формы должна быть причина;
назывное предложение и предложение длиннее 30 слов получают свои пометки.
Пустой текст, текст длиннее 6000 знаков и текст больше чем из 40 предложений получают
отказ, а не исключение.

Чего эта проверка не видит: вёрстку, клавиши редактора и хранилище браузера. Их
проверяют руками в браузере.

## Швы для следующих шагов

- **Редактор.** Остальной код знает редактор по семи именам: `root`, `input.value`,
  `set`, `mark`, `goTo`, `onEdit`, `lang`, `repaint`. Их создаёт `makeEditor`; замена
  поля ввода на другой редактор — новая `makeEditor` с теми же именами. Отметки ошибок
  приходят в `mark` списком `{ line, column, length, kind }`.
- **Вопрос компилятору.** `ask(текст, { действие: … })` отправляет сообщение потоку с
  компилятором и возвращает ответ. Действия перечислены в `завестиПоток` обвязки; новое
  действие (например, подсказки) добавляется там одной строкой.
- **Вкладки справа.** Список `VIEWS` и поле `views` сетапа. Новая вкладка — имя в
  `VIEWS`, подпись в `tabs` обеих таблиц слов и функция, которая её рисует.
- **Черновики.** Ключ хранилища — `flang-playground-draft:<сетап>`, значение — JSON
  `{ text, fn, args }`. Несколько файлов в одном сетапе потребуют нового поля в этом
  значении; старые черновики читаются функцией `readDraft`.
- **Модули библиотеки.** Сборка сайта кладёт их имена на страницу блоком
  `#flang-library`; обвязка отдаёт тот же список действием `модули`.

## Из чего собрана песочница

| что | где | чем собрано |
|---|---|---|
| компилятор с ядром | `playground/flang.wasm` | `bootstrap/*.c`, `clang --target=wasm32-wasi` |
| независимая проверка доказательств | `playground/checker.wasm` | `flang/proof/checker/checker.c`, тем же `clang` |
| переводчик рассуждений | `playground/reasoning.js` | `bootstrap/flang emit --target js` |
| переводчик формул | `playground/formula.js` | `flang/foreign/formula/browser.fscript`, `bootstrap/flang emit --target js` |
| переводчик C | `playground/c.js` | `flang/foreign/c/browser.fscript`, `bootstrap/flang emit --target js` |
| чтение своего текста | `playground/argue-page.js` | `flang/experimental/argue/page.flang`, `bootstrap/flang emit --target js` |
| пометка грамматики | `playground/argue-grammar.js` | `flang/experimental/argue/page-grammar.flang`, `bootstrap/flang emit --target js` |
| поиск слов в словаре | `playground/dictionary-words.js` | `flang/ct/russian/dictionary/words.fscript`, `bootstrap/flang emit --target js` |
| словарь OpenCorpora | `playground/dictionary/` | `scripts/russian-dictionary/build.fscript` (рецепт `playground:dictionary`) |
| библиотека | `playground/library.tar` | `flang/stdlib/*.flang` и `flang/core/*.flang` |
| обвязка WASI | `playground/flang_host_browser.js` | `flang/src/emit/js/flang_host_browser.js` |
| страница песочницы | `playground.js` | `docs/site/playground.js` |
| вёрстка формул | `vendor/katex/` | KaTeX 0.16.11 (лицензия MIT), лежит в дереве: `docs/site/vendor/katex` |

Файлы каталога `playground/` собирает шаг сборки сайта (`bootstrap/flang run-script
playground:build`); в дереве их нет. Обвязка WASI держит файловую систему в памяти
вкладки: исходник пользователя, библиотеку (её песочница скачивает, только если в
тексте есть `использует`) и временный каталог `/tmp`. Компилятор работает в отдельном
потоке (Web Worker), страница при этом не замирает.

Свой текст обвязка проверяет действием `статья` за пять шагов. План `Words` из
`flang/ct/russian/dictionary/words.fscript` исполняется как есть: он просит файлы
словаря по одному, обвязка скачивает их из `playground/dictionary/` и отдаёт ему; файла
нет — план отвечает своими словами и догадкой по окончанию. Затем `grammarForPage` из
`argue-grammar.js` ставит каждому предложению пометку грамматики по таблице признаков
плана: разобрано, назывное, не разобрано, длиннее 30 слов (по одному предложению, сбой на
одном не трогает другие). `readingForPage` из `argue-page.js` строит логические формы и
пишет черновик разметки; если смысловой разбор падает на предложении, такие предложения
ищутся по одному и помечаются «внутренняя ошибка разбора», остальные читаются вместе. `judgmentForPage` даёт задания ядру, и
каждое задание проверяет `flang.wasm` командой `check --proof --strict`. Наконец
`reportForPage` пишет отчёт. Пределы — в `ПРЕДЕЛЫ_ТЕКСТА`: 6000 знаков, 40 предложений,
200 заданий ядру и 90 секунд на все задания; что не успело, отчёт называет «ядро не
решило». Ход работы поток присылает странице сообщениями `{ номер, ход }`.

Данные словаря — производное произведение словаря OpenCorpora под лицензией
CC BY-SA 3.0. В дерево они не входят: их строит сборка сайта, и рядом с ними лежит
`LICENSE.txt` с источником и лицензией. Сборка кэширует их по хешу плана сборки.

Текст на C разбирает обвязка: она строит то же дерево, что печатает
`clang -Xclang -ast-dump`, только для подмножества, которое знает переводчик. Проба
сверяет это дерево с деревом clang на девяти файлах `flang/foreign/c/corpus` строка в
строку. Чего в подмножестве нет (указатели, `long`, `switch`, препроцессор, кроме
`#include`), обвязка называет со строкой, а не переводит наугад.

Подсветка в редакторе берёт ключевые слова из таблицы лексера
(`flang/self/lexer.flang`, функция «Куски таблицы»): сборка сайта кладёт их на страницу,
второго списка слов нет. Формулы в LaTeX рисует KaTeX из `docs/site/vendor/katex`; если он
не загрузился, формула остаётся записью обычным текстом. Рисунки — SVG, который
страница строит сама из дерева разбора (`flang ast`) и машинного ответа компилятора.

Та же обвязка работает и под Node, без браузера:

```sh
node flang/src/emit/js/flang_host_browser.js docs/site/out/playground "$(cat текст.txt)"
node flang/src/emit/js/flang_host_browser.js docs/site/out/playground --json "$(cat текст.txt)"
node flang/src/emit/js/flang_host_browser.js docs/site/out/playground --на go "$(cat программа.flang)"
node flang/src/emit/js/flang_host_browser.js docs/site/out/playground --из c "$(cat функция.c)"
node flang/src/emit/js/flang_host_browser.js docs/site/out/playground --статья --json --файл статья.txt
```

Код возврата у неё тот же, что у проверки: 0 — следует или доказано, 1 — не следует,
3 — не доказано. С `--json` она печатает весь разобранный ответ — тот, из которого
страница строит итог и рисунки.

Этим путём сборка сайта и пробует песочницу (`bootstrap/flang run-script playground:probe`,
план `scripts/site/playground-probe.fscript`): Barbara обязана «следовать», и
независимая проверка обязана сойтись с записью; утверждение следствия — «не следует» с
кодом 1; ложное утверждение — код 3 и ни одного «доказано»; формула в LaTeX — перевод на flang,
доказательство и сошедшаяся независимая проверка; печать во все десять языков — те же
файлы программы, что печатает двоичный компилятор; функция на C — перевод и проверка
ядром; разбор C песочницы — то же дерево, что у clang, на каждом файле корпуса.
