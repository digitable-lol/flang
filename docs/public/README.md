# Выход в публичное пространство: материалы

Четыре документа под одну задачу — показать язык наружу, ничего при этом не
преувеличив. Ничего не опубликовано и никуда не отправлено: это заготовки,
выкладывает их владелец языка сам.

| Документ | О чём | Кому |
|---|---|---|
| `rosetta-как-выложить.md` | порядок действий на Rosetta Code: аккаунт, лицензионная оговорка, страница языка, разметка, чего не делать | владельцу |
| `show-hn.md` | заголовок и текст поста, семь вероятных возражений с ответами | владельцу; текст поста — по-английски |
| `статьи-планы.md` | три плана статей: тема, площадка с проверенными дедлайнами, тезис, структура, какие измерения есть и каких не хватает | владельцу |
| `википедия-план.md` | почему статью сейчас удалят, что должно появиться сначала и в каком порядке | владельцу |

Решения Rosetta Code лежат отдельно, рядом с кодом: `flang/examples/rosetta/`
(README каталога, `WIKI.en.md` с готовыми английскими текстами для вики и
пятнадцать `.flang`).

## Правило, по которому это написано

То же, что и во всём репозитории: **ничего не утверждать без проверки**. Каждое
внешнее обстоятельство — существует ли журнал, как называется правило, какой у
него статус — проверено чтением живой страницы 7 августа 2026, а не по памяти.
Где проверить не удалось, написано «не проверено».

Проверка окупилась сразу. Четыре ходовых представления о правилах Википедии
оказались неверными (ВП:КЗ ведёт не туда, куда думают; ВП:КЗП — про людей;
страницы «Критерии значимости программного обеспечения» не существует; реклама
в КБУ — это О9, а не О5). Конференция TAP как отдельная больше не проводится.
JFP с 2026 года выходит не в Cambridge University Press, а на Episciences.
`Rosetta Code:Add a Language` до сих пор показывает мёртвый тег `<lang>` и
позиционный параметр шаблона, который шаблон игнорирует. Ни одного из этих фактов
нельзя было взять из головы.

## Что найдено в самом репозитории по дороге

**Расхождение, которое стоит свести.** Число файлов, на которых сошлась
неподвижная точка самоприменения, названо по-разному:

- `docs/overview.ru.md`: «результат совпадает побайтово с третьим проходом —
  все **семь** файлов»;
- `flang/self/SPEC.md`: «печатают компилятор побайтово одинаково — все **шесть**
  файлов»;
- `README.ru.md`: «**шесть** файлов».

Одно из двух неверно. Для проекта, где неподвижная точка — побайтовая, это не
опечатка: разночтение в числе файлов обесценивает утверждение целиком, и найдут
его в первый же день после публикации. Из-за этого числа файлов нет ни в тексте
для Show HN, ни в материалах Rosetta Code.

**Мелочь того же рода.** Запись 179 в `flang/examples/leetcode/index.json`
объясняет, что строки нельзя сравнивать вовсе, — а девятая запись в «чего не
хватает языку» перечисляет «сравнение строк» среди восьми недостач, оказавшихся
неправдой. Обе правы по-своему: равенство строк работает, сравнения ПОРЯДКА
отвергаются (`FLANG_TYPE: сравнения порядка допустимы только для чисел`,
проверено запуском). Но читается это как противоречие, и стоит развести словами.
