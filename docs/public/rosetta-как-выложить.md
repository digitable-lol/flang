# Rosetta Code: как выложить решения

Инструкция для владельца языка. Аккаунт заводит и правки делает владелец —
подготовлены только материалы.

Всё, что ниже, проверено чтением сайта и его API 7 августа 2026 года, а не по
памяти. Где проверить не удалось — сказано прямо.

## 0. Сначала — решение, которое стоит принять до первой правки

**Лицензия.** Контент Rosetta Code выходит под GNU Free Documentation License.
Здесь есть расхождение в самом источнике, и его надо знать: подвал сайта и
`action=query&meta=siteinfo&siprop=rightsinfo` говорят **GFDL 1.3**, а страница
политики `Rosetta Code:Copyrights` — **GFDL 1.2**. Что из этого юридически
главнее — не установлено.

Практическое следствие названо на той же странице политики дословно:

> Being licensed under the GNU Free Documentation License, the material
> published on Rosetta Code is not compatible with most software licenses,
> including OSI-approved licenses such as the GPL.

Репозиторий flang лежит под BSD-2-Clause. Выкладывая код на Rosetta Code, вы
дополнительно отдаёте его под GFDL. Авторские права при этом остаются у вас, и
та же страница разрешает объявить более свободную лицензию:

> Content, once submitted to this site, becomes available under the GFDL (v1.2),
> as well as any more permissive license the contributor chooses.

**Что сделать:** после регистрации на своей странице участника написать одну
строку вроде «All code I contribute to Rosetta Code is additionally available
under the BSD 2-Clause License». Это снимает несовместимость для тех, кто
захочет взять код обратно в репозиторий.

## 1. Аккаунт

Регистрация открыта; создание аккаунта разрешено анонимной группе. Править и
создавать страницы технически можно и без аккаунта (у группы `*` есть права
`edit`, `createpage`, `createtalk`), но:

- заливать файлы (`upload`) без аккаунта нельзя;
- стоят ConfirmEdit + hCaptcha + AbuseFilter, и капча снимается только у
  `autoconfirmed`; порог autoconfirmed — настройка хостинга (Miraheze), через
  публичный API не читается, **не проверено**;
- сам сайт рекомендует регистрироваться (`Rosetta Code:Copyrights`):
  «it is recommended that you make your contributions while logged in, and keep
  a valid and current email address in your user profile».

Заводите аккаунт. Без него правки уйдут на IP-адрес, а авторство языка вам ещё
пригодится.

## 2. Порядок действий

Порядок важен: страница языка должна существовать до того, как на страницах
задач появятся заголовки `{{header|flang}}` — иначе категория, которую этот
шаблон создаёт, будет вести в пустоту.

**Шаг 1. Страница языка.** Создать `Category:flang`. Минимальное тело по
`Rosetta Code:Add a Language`:

```
{{stub}}{{language}}
```

Осторожно: `Rosetta Code:Add a Language` показывает `{{language|Ayrch}}` с
позиционным параметром — **шаблон его игнорирует**, имя берётся из
`{{PAGENAME}}`. Правильная форма без параметра приведена на
`Help:Adding a new programming language`. Проверено чтением исходника шаблона.

Параметры `{{language}}` (из раздела Usage самого шаблона) и предлагаемые
значения для flang. **Проверьте каждое сами** — это ваши утверждения о вашем
языке, не мои:

| Параметр | Что означает | Предлагается | Основание |
|---|---|---|---|
| `exec` | `machine` / `interpreted` / `bytecode` / `both` | `both` | эталон — интерпретатор; релиз — компилятор, напечатанный в C99 |
| `site` | официальный сайт | `https://github.com/digitable-lol/flang` | или `https://courses.digitable.life/fts/`, если он для вас главнее |
| `parampass` | передача параметров | `value` | язык чистый, значений-ссылок нет |
| `safety` | типобезопасность | `safe` | |
| `strength` | сила типизации | `strong` | |
| `compat` | совместимость типов | `nominative` | записи и суммы различаются по имени |
| `express` | выражение типов | `explicit` | типы в сигнатурах обязательны; вывод есть только для аргументов параметрических типов и `пусть` |
| `checking` | проверка типов | `static` | |
| `tags` | тег для `<syntaxhighlight lang=…>` | `text` | см. шаг 3 |
| `gc` | сборка мусора | **не заполнять** | у рантайма C — арена, а не сборщик; у остальных семи целей сборщик хозяйский. Одним словом честно не отвечается |
| `hopl`, `LCT`, `bnf` | ссылки на внешние каталоги | не заполнять | языка там нет |

Дополнительно: `{{language programming paradigm|Functional}}` и
`{{language programming paradigm|Declarative}}` — список допустимых значений на
`Category:Programming paradigm`.

**Шаг 2. Перенаправление из основного пространства.** Создать страницу `flang`
с единственной строкой:

```
#REDIRECT [[:Category:flang]]
```

Двоеточие перед `Category` обязательно, иначе страница не перенаправит, а
попадёт в категорию.

**Шаг 3. Задачи.** По одной странице за правку, с внятным описанием правки
(«Added flang»). Разметка:

```
=={{header|flang}}==
<английский текст из flang/examples/rosetta/WIKI.en.md>
<syntaxhighlight lang="text">
…код…
</syntaxhighlight>
```

`{{header|…}}` сам добавляет страницу в категорию языка и выставляет
SMW-свойство *Implemented in language* — руками категорию дописывать не надо.

**Шаг 4 (потом).** `{{unimpl_Page|flang}}` — страница «задачи, не решённые на
flang»; `{{implementation|flang}}` — страница реализации. Не срочно.

## 3. Разметка кода: что проверено экспериментально

Тег `<lang …>` **мёртв**. В исходнике страницы `FizzBuzz` — 694 вхождения
`<syntaxhighlight` и ноль `<lang …>`; поиск `insource:/<lang [a-z]+>/` по всему
основному пространству даёт ноль попаданий. `Rosetta Code:Add a Language` до сих
пор показывает `<lang ayrch>` — это протухший текст, не следуйте ему.

Что происходит с разными значениями `lang` (прогнано через `action=parse`,
то есть предпросмотр без сохранения):

| Разметка | Что выходит |
|---|---|
| `lang="text"` | подсветка есть (монохромная), категорий ошибок нет |
| `lang="flang"` (лексера нет) | обычный `<pre>`, **и страница попадает в скрытую `Category:Pages with syntax highlighting errors`** |
| без `lang` | то же самое |

В этой скрытой категории сейчас 1760 страниц, то есть это не катастрофа, а
обычное дело. Но справка `Help:Syntax Highlighting` прямо разрешает и даже
советует выдумать свой тег:

> Make sure to use the standard identifier for your language even if Pygments
> doesn't know how to highlight it yet. If your language isn't in the list, make
> up an identifier … and add it to the list.

и там же предупреждает:

> A multiple month delay is expected, a several year delay is not out of the
> question.

**Рекомендация: `lang="text"`.** Причина не в аккуратности, а в существе: чужой
лексер раскрасит русские слова неверно и собьёт читателя сильнее, чем отсутствие
цвета, а свой тег даст `<pre>` плюс пометку об ошибке. Если позже в Pygments
появится лексер flang — поменяете одним поиском-заменой.

## 4. Что именно вставлять в блок кода

Файлы в `flang/examples/rosetta/` несут длинные русские шапки-комментарии. Это
внутренняя документация файла; на вики ей не место — читателю она непонятна, а
английский текст из `WIKI.en.md` говорит то же самое. Снимайте её:

```bash
grep -v '^[[:space:]]*//' flang/examples/rosetta/<файл>.flang | cat -s
```

Проверено, а не предположено: все пятнадцать файлов сняты этой командой и
прогнаны заново — 222 примера, все сходятся, ни одной ошибки разбора или типов.
Команда безопасна потому, что ни в одном файле нет комментария в конце строки с
кодом.

Английские тексты для каждой задачи — `flang/examples/rosetta/WIKI.en.md`,
готовые к вставке.

## 5. Какие задачи и в каком порядке

`Rosetta Code:Add a Language` советует начать с `User Output`, `Loop
Structures`, `Conditional Structures`; `Help:Adding a new programming language`
— с `Empty Program`, `Comments`, `User Output`.

**С `User Output` есть загвоздка, и её надо решить до правки.** Язык чистый:
функция возвращает значение, а печать — это поручение, которое исполняет хозяин
(`flang io`). Решение задачи «вывести строку» на flang либо возвращает строку
(и тогда это не вывод), либо строит план ввода-вывода (и тогда это не три
строки). Готового файла под неё в наборе нет. Либо напишите её отдельно и
объясните устройство прямо в тексте, либо начните с других задач — формального
требования начинать именно с неё нет.

Предлагаемый порядок — от того, что показывает язык лучше всего:

1. `FizzBuzz` — обе поверхности, русская и английская, в одном разделе;
2. `Levenshtein distance` — динамическое программирование без таблицы, всё
   доказано; самое сильное, что есть в наборе;
3. `Towers of Hanoi` — задача, которую обычно считают по числу, здесь
   доказуема;
4. `Roman numerals/Encode` и `Roman numerals/Decode`;
5. `Ackermann function` — честная граница; поставьте её пораньше, чтобы
   «доказано» не читалось как «мы умеем всё»;
6. `100 doors`, `Run-length encoding`,
   `Sequence of primes by trial division`;
7. остальное: `Reverse a string`, `Palindrome detection`,
   `Sorting algorithms/Merge sort`, `Sorting algorithms/Quicksort`,
   `Factorial`, `Fibonacci sequence`.

Мелочь, о которой предупреждает сама страница `100 doors`: на ней ограничение на
число тегов `<syntaxhighlight>`, и поздние языки идут без подсветки. Для
`lang="text"` разницы нет.

## 6. Требования сайта к новому языку

Единственное формальное требование, `Rosetta Code:Add a Language`, раздел
Prerequisites:

> There should be an existing implementation of that language that is either
> mature or, at the very least, under active development. Language notability is
> unimportant.

flang этому отвечает: две реализации, регулярные правки. **Значимость на Rosetta
Code не требуется — и это принципиально отличает её от Википедии** (см.
`docs/public/википедия-план.md`, где всё ровно наоборот).

Второе требование — не бросать язык пустым:

> You need to provide at least one or two token examples, to give people a taste
> of the language. Otherwise, there really isn't much of a point for the
> language to be mentioned on the wiki.

Формальной процедуры одобрения нового языка нет: ни премодерации, ни очереди.
`Help:Request a new programming language` — это перенаправление на доску
пожеланий `Rosetta Code:Village Pump/Suggest a language`, а не согласование.
Есть ли неформальная практика (откат админами, обсуждение на Village Pump) —
**не проверено**; отсутствие текста не означает отсутствия практики. Админов на
вики двое.

## 7. Состояние площадки

Проверено через API 7 августа 2026:

- MediaWiki 1.45.3 на Miraheze, SemanticMediaWiki, SyntaxHighlight 2.0;
- 22 247 страниц, 3 106 «статей», 407 627 правок, 4 201 участник, 87 активных;
- правки в основном пространстве идут ровно: 350–450+ в месяц с августа 2025 по
  август 2026, без спада. В день проверки — свежие правки за то же утро.

Площадка живая. Это не «мёртвая вики, куда можно писать что угодно».

## 8. Чего НЕ делать

- **Не выкладывать `primes-by-trial-division.flang` на страницу
  `Sieve of Eratosthenes`.** Это пробное деление, а не решето; Rosetta Code
  помечает такие решения `{{incorrect|…|Not a true Sieve of Eratosthenes but
  rather a Trial Division Sieve due to modulo/% testing}}` — проверено чтением
  исходника той страницы. Файл предназначен для
  `Sequence of primes by trial division`.
- **Не выкладывать решение `Anagrams`.** Его нет и не будет, пока в языке нет
  ассоциативного массива: задача требует прочитать `unixdict.txt` и
  сгруппировать слова по набору букв. Сверх того, буквы слова не отсортировать —
  сравнения порядка для строк отвергаются проверкой типов (`FLANG_TYPE`,
  проверено запуском). Решение «на маленьком списке слов» решением этой задачи
  не является.
- **Не подгонять описание под красоту.** Тексты в `WIKI.en.md` называют границы
  прямо, и это главная ценность набора. Читатель Rosetta Code сравнивает сорок
  языков; тот, кто один раз соврал про свои возможности, теряет доверие ко всему
  остальному.
- **Не заводить страницу «flang» в основном пространстве как статью** — только
  как перенаправление на категорию.

## 9. Что проверить перед каждой правкой

```bash
node --test flang/test/rosetta.test.mjs
```

31 тест, все зелёные на момент подготовки. Тест проверяет разбор, типы,
завершаемость, все примеры и число тотальных функций в каждом файле. Если он
красный — на вики идти нельзя: витрина, в которой что-то перестало запускаться,
хуже пустой.
