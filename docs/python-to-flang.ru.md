# Python во flang: переводчик, которому не нужно верить

Переводчик читает программу, написанную на небольшой части Python, и печатает ту же
программу на flang. Верить переводчику не нужно: напечатанный текст судит `flang check`,
а отдельный прогон сравнивает ответы перевода с ответами самого Python на наборе
входов. Это правило [ADR-0058](adr/0058-a-foreign-language-enters-through-an-untrusted-translator.md),
и ему же следует [переводчик с C](guide/c-into-flang.ru.md).

Сам переводчик написан на flang, а не на Python. В браузере он работает как JavaScript,
напечатанный из flang, поэтому странице Python не нужен. Python нужен в одном месте:
чтобы узнать, что отвечает исходная программа, когда ответы сравнивают.

## Как вызвать

```
bootstrap/flang run-script foreign-python:demo
```

переводит каждую программу из `flang/foreign/python/corpus`, проверяет каждый перевод
командой `flang check`, сравнивает ответы с Python и пробует три лживые версии
переводчика. На машине нужен `python3`. Временные файлы — в `FLANG_TMP`.

Одна программа из командной строки:

```
bootstrap/flang run flang/foreign/python/browser.fscript --function "«Translate for page»" \
  --args '{"source": "def square(x: int) -> int:\n    return x * x\n", "name": "square"}'
```

Ответ — запись: `code` и `why` пусты, если программа переведена, в `unit` лежит текст на
flang, а `verdicts` по каждой функции говорит, `тотальная` ли она (доказано ли, что она
кончается) и почему. Тот же вызов работает и в сборке компилятора под WebAssembly
(`playground/flang.wasm`): переводчик — обычный модуль flang.

Для песочницы переводчик печатается в JavaScript:

```
bootstrap/flang run-script playground:python
```

кладёт `docs/site/out/playground/python.js` рядом с `formula.js`. Страница зовёт
`translateForPage(source, name)` и отдаёт `unit` компилятору как
`flang check /playground.flang` — так же, как формулу.

## Три примера

### Квадрат

```python
def square(x: int) -> int:
    return x * x


def sum_of_squares(a: int, b: int) -> int:
    return square(a) + square(b)
```

становится

```flang
тотальная функция «square»
  принимает «x»: число
  возвращает число
  «x» умножить на «x»

тотальная функция «sum_of_squares»
  принимает «a»: число, «b»: число
  возвращает число
  («square» от «a») плюс («square» от «b»)
```

Каждое имя программы берётся в ёлочки, поэтому имя из Python никогда не совпадёт со
словом flang. И `int`, и `float` становятся `число`.

### Обратный отсчёт, который кончается не всегда

```python
def countdown(n: int) -> int:
    if n == 0:
        return 0
    return countdown(n - 1)
```

На отрицательном `n` эта рекурсия не останавливается. Переводчик видит, что вызов
уменьшает `n`, но ничто перед ним не мешает `n` уйти ниже нуля, поэтому пишет `функция`, а
не `тотальная функция`, и прямо над ней объясняет почему:

```flang
примечание "Без «тотальная»: вызов на строке 4 уменьшает «n», но проверка перед ним не ограничивает «n» снизу (нужна вида n <= 0): на части входов рекурсия не кончается, поэтому перевод пишет «функция», а не «тотальная функция»"
функция «countdown»
  принимает «n»: число
  возвращает число
  если «n» равен 0
    то 0
    иначе «countdown» от («n» минус 1)
```

С `if n <= 0:` вместо `if n == 0:` та же функция становится `тотальная`, и `flang check`
доказывает, что она кончается.

### Цикл

```python
def total(xs: list[int]) -> int:
    s = 0
    for x in xs:
        s += x
    return s
```

Цикл `for` становится свёрткой по списку. Один виток цикла — отдельная функция, и
свёртка зовёт её по разу на каждый элемент:

```flang
тотальная функция «total»
  принимает «xs»: список число
  возвращает число
  пусть «s» равно 0
  пусть «s 3» равно (свёртка «xs» начиная с «s» как «s so far» и «x» → «total loop 3» от «s so far» и «x»)
  «s 3»

тотальная функция «total loop 3»
  принимает «s»: число, «x»: число
  возвращает число
  пусть «s 4» равно «s» плюс «x»
  «s 4»
```

Каждое присваивание получает новое имя — `«s 4»` это `s`, присвоенное на строке 4, —
потому что значение во flang не меняется. Если цикл меняет несколько переменных, они
идут через свёртку вместе, одной записью.

## Что входит в подмножество

| Python | flang |
|---|---|
| `def f(a: int, b: list[int]) -> bool:` | `функция «f»` с теми же параметрами; типы обязательны |
| `int`, `float` | `число` |
| `bool`, `True`, `False` | `признак`, `да`, `нет` |
| `str` | `строка` |
| `list[T]`, `[a, b]` | `список T`, `[a, b]` |
| `return`, `if` / `elif` / `else`, `a if c else b` | значение ветви, `если … то … иначе` |
| `x = …`, `x += …`, `a, b = b, a + b`, `xs: list[int] = []` | `пусть` с новым именем |
| `for x in xs`, `for i in range(…)`, `for c in text` | свёртка и функция одного витка |
| `[f(x) for x in xs if c]` | `отобразить` и `отфильтровать` |
| рекурсия | рекурсивный вызов; судится, кончается ли он (ниже) |
| `+ - * / // % **`, сравнения, `and or not`, `in` | действия flang и небольшие вспомогательные функции |
| `len abs min max sum sorted range str float list` | `длина` и вспомогательные функции |
| `xs[i]`, `xs[-1]`, `xs[a:b]`, `text[i]` | `элемент`, `голова`, `хвост`, вспомогательные функции |

Вспомогательные функции вроде `«Python remainder»` или `«Python range»` печатаются в тот
же модуль, так что перевод самодостаточен.

## Что отвергается и почему

Всё остальное переводчик отвергает и говорит, что и где. Догадку, которая может
оказаться неверной, он не пробует.

| что | код | почему |
|---|---|---|
| `class` | `FLANG_PYTHON_CLASS` | у объекта Python меняется состояние, а значения flang не меняются |
| имена на верхнем уровне модуля, `global`, `nonlocal` | `FLANG_PYTHON_GLOBAL` | функция подмножества получает всё через параметры |
| `try`, `raise`, `assert` | `FLANG_PYTHON_EXCEPTION` | перехвата во flang нет: отказ останавливает всё вычисление |
| `print`, `input`, `open`, `with` | `FLANG_PYTHON_IO` | ввод и вывод — не чистая функция |
| `import` | `FLANG_PYTHON_IMPORT` | переводится одна программа без модулей |
| `while`, `break`, `continue`, `return` внутри цикла | `FLANG_PYTHON_LOOP` | у `while` нет меры, видной из кода; из свёртки нельзя выйти раньше |
| `xs.append(…)`, `xs[i] = …`, `del` | `FLANG_PYTHON_MUTATION` | список не меняют на месте; соберите новый: `xs = xs + [v]` |
| параметр или результат без типа, тип вне таблицы | `FLANG_PYTHON_TYPE` | перевод пишет каждый тип и не угадывает его |
| функция, которая может кончиться без `return` | `FLANG_PYTHON_RETURN` | Python вернёт `None`, а у функции подмножества значение есть всегда |
| кортежи, словари, `None`, `lambda`, методы, именованные доводы | `FLANG_PYTHON_CONSTRUCT` | вне подмножества |
| имя, не заданное в функции | `FLANG_PYTHON_NAME` | глобальные имена вне подмножества |
| текст, который не Python | `FLANG_PYTHON_SYNTAX`, `FLANG_PYTHON_INDENT`, `FLANG_PYTHON_STRING`, `FLANG_PYTHON_NUMBER` | читатель называет строку и знак |

Например

```python
def doubled(xs: list[int]) -> list[int]:
    result: list[int] = []
    for x in xs:
        result.append(2 * x)
    return result
```

отвергается так: `FLANG_PYTHON_MUTATION строка 4: метод «append» меняет список на месте, а
значения flang не меняются: вместо xs.append(v) пишите xs = xs + [v]`.

## Где Python и flang расходятся

* **Числа.** У `int` в Python нет предела; `число` во flang точно до 2⁵³. Входы больше
  этого сравнение не проверяет.
* **Деление.** `//` округляет вниз, а `%` берёт знак делителя, как в Python: перевод
  зовёт `«Python floor division»` и `«Python remainder»`, потому что остаток во flang
  берёт знак делимого. Деление на ноль останавливает вычисление отказом там, где Python
  бросает `ZeroDivisionError`.
* **Минус ноль.** Во flang `-0` не равен `0`. Произведение двух значений, у которых
  могут быть разные знаки, получает в конце `плюс 0` — это превращает `-0` в `0`, и
  равенство после него значит то же, что в Python.
* **Запись чисел.** `str(…)` переводится только для целого: Python пишет `3.0` и `True`,
  flang пишет `3` и `да`.
* **Ошибки.** Где Python бросает исключение (номер вне списка, деление на ноль), перевод
  тоже отказывает. Сравнение считает это согласием: остановились оба.

## Когда перевод пишет `тотальная`

Функции во flang двух видов: `тотальная функция` всегда кончается (или честно
отказывает), про `функция` такого не обещано. Переводчик пишет `тотальная`, только когда
может назвать причину, и `flang check` обязан с ним согласиться:

* **хвост списка** — вызов получает `xs[1:]` после проверки, что `xs` не пуст: список
  становится короче, и flang видит это сам;
* **шаг вниз от проверенной границы** — вызов получает `n - 1` (или любое положительное
  число) после проверки вида `if n <= 0: return …`;
* **шаг Евклида** — вызов получает `a % b` на месте `b`: мера — `b · b`;
* **часть покороче** — вызов получает список, отфильтрованный из хвоста, как в быстрой
  сортировке: мера — длина списка.

Иначе перевод пишет `функция` и примечание с причиной. Функция, которая зовёт такую
функцию, тоже не `тотальная`, и её примечание называет вызов-причину. Двоичный поиск по
`low` и `high`, шаги Коллатца и обратный отсчёт выше лежат в корпусе, и все получают
`функция` с примечанием.

## Как проверяется переводчик

План `foreign-python:demo` делает с каждой программой корпуса четыре вещи:

1. переводит её и запускает `flang check` на переводе — код выхода обязан быть 0;
2. сверяет вердикт каждой функции (`тотальная` или нет и слова причины) с
   `corpus/expected.tsv`;
3. выполняет каждый вызов из `corpus/inputs.tsv` дважды — в Python (`reference.py`) и в
   переводе (`flang run`) — и сравнивает ответы; отказ с обеих сторон считается согласием;
4. печатает три лживых перевода — у первого `if` выпадает первая ветвь, первое число
   растёт на единицу, у первого некоммутативного действия меняются местами операнды — и
   требует, чтобы сравнение поймало каждый.

Ещё он переводит десять программ из `corpus/refused` и требует каждый код отказа из
`corpus/expected.tsv`.

Последний прогон: 20 программ корпуса, все 20 переведены и прошли `flang check`; 131 вызов, ответы
совпали с Python на всех 131; 41 функция `тотальная`, 4 — нет (двоичный поиск и функция,
которая его зовёт, шаги Коллатца, обратный отсчёт), и каждая объясняет почему; 52 лживых
перевода, пойманы все 52; 10 отвергнутых программ, у всех 10 ожидаемый код. Прогон идёт
около пяти минут.
