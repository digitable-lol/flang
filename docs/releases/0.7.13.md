# flang 0.7.13 — черновик release notes

**Черновик.** Версию и тег бампает отдельный процесс выпуска — здесь не тронуты
ни `package.json`, ни семя. Собрано прогоном `git log v0.7.12..gh/dev` (108
коммитов) и чтением `docs/design/`. Где источника не нашлось — сказано прямо,
а не придумано.

Главная линия релиза — объект доказательства (переигрыватель следа в чекере,
задача 4004, `docs/design/proof-object.md`): чекер учится проверять ГОТОВЫЙ
вывод ядра построчно, а не пересчитывать его заново и не верить имени правила
на слово.

---

## Добавлено

- **Переигрыватель гейтит равенства-постусловия по цепочке ходов.** Раньше
  `bez_teoremy` звал переигрыватель нулём строк: ложный ход под
  постусловием-равенством проходил кодом 3, неотличимым от честного. Теперь —
  по наличию `ход цель` и простой линейной цепочке (без `принцип`) — сведение
  проигрывается заново: ложный ход даёт код 1. `flang/proof/чекер/сверщик.c`,
  задача 4102, коммит `3931ae1a`.
- **Ход «вычислить» (P8).** Замкнутый счёт (`2+2=4` и подобные) в переигрывателе
  явным примитивом поверх `ocenit_term`, а не на слово ядра. Коммит `a1f19f27`.
- **Ход «переписать формой».** Законы длины Д1–Д5 (семья С3 «Длина», коммит
  `269d3ccf`) и элемента Э1–Э4 (семья С4 «Элемент», коммит `b0ef3a31`) —
  переигрыватель проверяет и эти формы вывода сам, не пересчитывая калькулятором.
  Золотые сертификаты семей С3/С4/С5 — коммит `78d964cc`.
- **Две придирки чекера закрыты.** (1) Гейт принципа: посылка под `принцип …`
  без явно написанной `теорема` до `proigrat_blok` не доходила — ходы под ней
  были декорацией, чекер их не читал. (2) Скобки: `vstavit_vmesto` безусловно
  оборачивал вставляемое тело лишней парой скобок, и на составном условии после
  развёртки `деление` до цели не дотягивалось ни при каком написании довода.
  Коммит `3cb04bcb`.
- **Приём S2 «постусловие вызванной» — независимая проверка лемм «по свойству».**
  Раньше шаг «по свойству» проверялся только привязкой имя+строка, а сам вывод
  оставался на слове ядра. Теперь чекер сам строит инстанцию постусловия по
  вызову (арность, две подстановки: параметры→аргументы, результат→узел) и
  закрывает цель модус-поненсом. **Ловит настоящую подделку**: теорема с целью
  «результат равен 3» при теле, дающем 0, и правильно привязанным свойством
  «не меньше 0» — раньше проходила кодом 0, теперь код 1. Коммит `e5a75366`.
- **Дожатие S2.** Оплата `требует` (постусловие вызванной берётся фактом только
  если КАЖДОЕ её предусловие снято в точке вызова), защита от захвата имени при
  перестановке параметров-имён, второй уровень сторожа круга (факт берётся
  только от постусловий, проверенных ПО СУЩЕСТВУ, а не взятых на слово). Коммит
  `d433f3b2`.
- **3 примера-фреймворка** — `examples/frameworks/`: `nestjs-orders`,
  `react-invoice`, `vue-roman`. Доказанное ядро на flang печатается в JS и
  работает под настоящим фреймворком (Nest/React/Vue); граница именно там, где
  сказано в README каждого примера — решение (маршрут/коды/суммы/перевод) на
  flang, сокет и рендер — у хозяина-фреймворка. Коммит `374e9aaa`.
- **DESCRIPTION.md переписан** плотнее и честнее: прогон по дереву вместо
  пересказа README, ссылки на код и `tasks/`, актуальный статус гейтов Г1–Г7.
  Коммиты `a29b37cd`, `7c37cdde`.
- **Дорожная карта миграции корпуса на объект доказательства** —
  `docs/design/proof-object-roadmap.md`. Сводит шесть частных разведок по родам
  правил (`proof-object-migration.md`, `-po-primeru.md`, `-po-svoystvu.md`,
  `-po-sluchayam.md`, `-razbor-celi.md`, `-lemma-po-svoystvu.md`) и приём S2 в
  один порядок работ с зависимостями и числом того, что каждый шаг закрывает.
  Коммит `20c0ef2e`.
- **Ярлык `доказуемость`.** `./ярлык доказуемость` (`scripts/доказуемость.sh`)
  печатает ОДНО слово — ДОКАЗУЕМ / НЕ ДОКАЗУЕМ — по трём числам, а не по
  вписанному в прозу суждению. Коммит `7b03ee3a`.

**Не нашёл в git log.** Пункт «печать следа из ядра (в семя, через
перепечатку)» — в дереве `v0.7.12..gh/dev` нет правок ни
`flang/self/proof-kernel.flang`, ни `flang/self/zapis.flang`, ни
`flang/self/proofterm.flang`, семя (`bootstrap/`) за этот диапазон менялось
только под `хеш256` (коммиты `ee3b0121`, `262509ea`, не про след доказательства).
В `docs/design/proof-object-roadmap.md` это пункт ПЛАНА ([Ш3]/[Ш4] — печать
следа в `zapis.flang` плюс одна правка печати из ядра для теорем «для всех
элементов»), не сделанная работа. В список «добавлено» не включаю.

## ЧЕСТНО про доказуемость

Объект доказательства ЕСТЬ, и он ловит подделки: приём S2 (выше) поймал
настоящую ложную теорему, которая раньше проходила кодом 0; набор проб чекера
(`flang/proof/чекер/пробы/прогон.sh`) держит подделку на каждый ход, включая
подмену тела развёртки (`docs/design/proof-object.md §9`).

Но язык **ПОКА НЕ формально доказуем** — это не оценка, а машинный вердикт:

```
$ export LC_ALL=C.UTF-8
$ git -c core.quotepath=false grep -c perepiskoy -- flang/proof/чекер/сверщик.c
flang/proof/чекер/сверщик.c:10
$ ./ярлык доказуемость
НЕ ДОКАЗУЕМ
```

Калькулятор `perepiskoy` («переиграть формой» ВЫЧИСЛЕНИЕМ, а не переигрыванием
записанных ходов) стоит в чекере — `git grep -c perepiskoy` = 10, не 0. Это
решающая из трёх проверок ярлыка: пока она не сошлась, две другие даже не
гоняются. Доля корпуса, проверенная переигрывателем, сегодня честно принята за
**0** — не потому что ничего не проиграно, а потому что мерить пока нечем:
прибора, отличающего «проиграно» от «посчитано», в дереве нет (шаг [Ш5]
дорожной карты).

Гейты (`DESCRIPTION.md §7`, снимок на письмо): **взято 2 из 7**.

| Гейт | Статус |
|---|---|
| Г1 — ядро выдаёт объект доказательства | ВЗЯТ |
| Г2 — независимый чекер переигрывает объект и отвергает подделку | СНЯТ — часть переигрывается (индукция, теперь и S2), но не маршрут «по объявлению» |
| Г3 — размер доверенного ядра назван числом | ВЗЯТ |
| Г4 — доля корпуса, проверенная переигрывателем | НЕ ВЗЯТ (≈33 из 86 записей, ~38 % при пороге 95 %) |
| Г7 — нет доказанного без проверки | признан не мерящим числом, пока калькулятор на месте |

Итог: калькулятор `perepiskoy` на месте, часть корпуса ещё СЧИТАЕТСЯ, а не
ПРОИГРЫВАЕТСЯ. Ярлык `доказуемость` (`git grep perepiskoy` ≠ 0) — это и есть
принятый в команде критерий «готово», а не отдельное упоминание в этом
документе.

## Известные ограничения

- **Узкий подкласс мест не мигрирован.** Маршрут «по объявлению» — 146 из 159
  мест «доказано» — печатает только имя правила, без цепочки ходов;
  переигрывателю нечего переигрывать, чекер верит ядру на слово.
  `docs/design/proof-object.md §0, §8`.
- **Оплата `требует` в приёме S2 — частичная.** Предусловие вызванной считается
  снятым, только если оно СИНТАКСИЧЕСКИ совпало с одним из `требует`
  вызывающей; погашение вычислением или охраной (`если`) эта волна не читает —
  такие места пока честно отвергаются (код 1), не принимаются по ошибке. Коммит
  `d433f3b2`.
- **Два места «круг/разбор» (семья С6)** — проекция поля и редукция разбора по
  варианту — и часть семьи «по примеру» (6 мест, тело считает не литерал) —
  кандидаты остаться за калькулятором дольше остальных: закрыть их дороже
  отдачи, либо требует роста доверенного `ocenit_term` почти до полного
  вычислителя. `docs/design/proof-object-roadmap.md §6`.
- **Калькулятор `perepiskoy` нельзя снять частично.** Пока хоть одна запись
  корпуса проверяется им, снятие обрушивает долю Г4 целиком — снимать можно
  только когда переигрывается весь корпус. `docs/design/proof-object-roadmap.md
  §3.2`.
- **Прибора «доля-проигрыванием» нет.** `flang/proof/доля-корпуса.sh` меряет
  разряды помех (крипто-привязка, места «на слово ядра»), а не долю записей,
  реально проверенных переигрывателем — вторая проверка ярлыка `доказуемость`
  сегодня заведомо 0, а не измерена. `scripts/доказуемость.sh`.
