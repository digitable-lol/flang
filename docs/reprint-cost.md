# Цена перепечатки семени

Перепечатка — это прогон `sh scripts/bootstrap-reprint.sh`: компилятор из
`flang/self/` печатает сам себя в C, и результат ложится в `bootstrap/` как
новое семя. Побайтовая сверка (`sh scripts/bootstrap-reprint.sh --check`) —
та же печать, после которой вывод сравнивается с закоммиченным семенем
командой `cmp`. Обе работы долгие и идут на одном ядре, поэтому их цена
записывается, а не держится в голове.

## Где лежат числа

Каждый дошедший или оборванный заход — строка в
[`reprint-ledger.tsv`](reprint-ledger.tsv):

| столбец | что |
|---|---|
| `дата` | день захода |
| `что` | `сверка` или `печать` |
| `итог` | `дошла`, `оборвана-шаги`, `оборвана-глубина`, `снята` |
| `секунд` | стенные часы захода |
| `пик-ГиБ` | пик резидентной памяти |
| `байт-вывода` | размер напечатанного семени |
| `потолок-шагов` | `MAX_STEPS`, с которым шёл заход |
| `откуда` | журнал захода, дерево и чем снят пик |

Строку дописывает рукой тот, кто провёл заход. Ведомость читает
[`scripts/seed/reprint-freshness.fscript`](../scripts/seed/reprint-freshness.fscript):
он берёт дату последней строки «сверка … дошла» и краснеет, если входы печати
правились позже.

## Две оси: время и память

Цену нельзя описать одним числом: время и пик памяти меняются независимо и
иногда в разные стороны. Поэтому в ведомости это два столбца, и планировать
заход надо по обоим. Пик снимается двумя приборами — `/usr/bin/time` или пульсом
самой печати (`FLANG_WATCH`); в столбце `откуда` сказано, каким именно, и
сравнивать пики разных приборов можно только при большом разрыве.

Раннер GitHub даёт 16 ГБ памяти; перепечатка просит больше, поэтому на каждый
пуш она не зовётся (см. ниже).

## `MAX_STEPS` — потолок следующего семени, а не этого прогона

Ключ `--max-steps` у команды `emit` **только клеймит число в вывод**; прогон
идёт под потолком того двоичного, который печатает:

```
$ flang emit проба.flang --target c --out … --max-steps 1
напечатано файлов 6, байт …               ← прогон не оборвался на первом витке
$ grep 'define FL_MAX_STEPS' …/flang_runtime.h
#define FL_MAX_STEPS 1                    ← а в вывод уехала единица
```

Отсюда правило: **`MAX_STEPS` в `scripts/bootstrap-reprint.sh` — потолок
следующего семени, и он не меньше цены той перепечатки, которую этому семени
придётся выполнить.** Иначе следующий заход оборвётся на шагах.

В скрипте рядом стоят две настройки:

- `MEASURED_COST` — измеренная цена самого дорогого шага печати (суд ядра
  доказательств о программе), по верхнему концу того, что сообщил двоичный;
- `MAX_STEPS` — потолок, с запасом над `MEASURED_COST`.

Если `MAX_STEPS` меньше `MEASURED_COST`, скрипт отказывается работать до начала
печати с кодом 2: заход, который заведомо не дойдёт, не должен занимать машину.
Потолок вшит и в само семя (`#define FL_MAX_STEPS` в
`bootstrap/flang_runtime.h`), поэтому двоичный, собранный из закоммиченного
семени, перепечатывает дерево без ручной пересборки.

Высокий потолок ослабляет ловлю зацикливания: незавершающаяся программа
считается до обрыва часами. Это сознательная цена — потолок, при котором
перепечатка не доходит, ловит не зацикливание, а саму раскрутку.

## Где сверка идёт в CI

- **`.github/workflows/reprint.yml`** — раз в неделю по расписанию. Работа
  `sverka` идёт на раннере с большой памятью и включается переменной
  репозитория `BOLSHAYA_PAMYAT=da`; без такого раннера она не запускается и не
  выдаёт зелёную галочку за работу, которая ничего не печатала.
- **`scripts/seed/reprint-freshness.fscript`** — дёшево, в работе `svezhest` того же
  `reprint.yml`: называет дату последней сверки и краснеет, если входы печати правили позже:

  ```
  побайтовая сверка перепечатки НЕ ПРОВЕРЕНА для этого дерева:
  последняя сверка …, входы печати правились …
  ```

- **`sh scripts/bootstrap-reprint.sh --bystro`** (в `binary.yml`) сверяет
  **входы** печати (файлы замыкания компилятора, файлы рантайма, уезжающие в
  вывод дословно, и пределы печати) за секунды, но побайтового совпадения семени
  с печатью не доказывает — это умеет только `--check`.
