# Заход перепечатки пускается из чистой копии ствола

Перепечатка семени (`sh scripts/bootstrap-reprint.sh`) идёт долго и занимает
машину. Заход, пущенный не из той копии, пропадает целиком: печать дойдёт до
конца, а положить её будет некуда. Здесь описан порядок захода — откуда берётся
копия, какой командой проверяется её чистота, что делать, если семя правлено
руками, и как результат попадает в ствол.

## 1. Копия — свежий клон ствола

Готовая копия соседа не годится по одной причине: `bootstrap/**` и
`scripts/seed-fingerprint` печатаются перепечаткой, и если в копии их кто-то
правил руками, печать пойдёт от правленого входа. Копия заводится клоном
ствола (`main`), без чужих правок.

## 2. Чистота проверяется одной командой, и это не `git status`

```sh
git diff --quiet HEAD -- bootstrap scripts/seed-fingerprint
```

Код `0` — семя такое же, как в стволе; код `1` — правлено. Пример на двух
копиях:

```
$ git diff --quiet HEAD -- bootstrap scripts/seed-fingerprint; echo "чистая копия, код: $?"
чистая копия, код: 0
$ git -C ../правленая diff --quiet HEAD -- bootstrap scripts/seed-fingerprint; echo "правленая копия, код: $?"
правленая копия, код: 1
```

**`git status --short -- bootstrap/` для этого не годится:** его код возврата
`0` и на чистой, и на правленой копии — он говорит о том, что команда сумела
посмотреть, а не о находке. Разница видна только глазами по печати, а проверка,
которую нельзя провалить кодом возврата, не остановит ни одного захода.

Отслеживаемых файлов в `bootstrap/` семь (`git ls-files bootstrap/`); продукты
сборки (`bootstrap/*.o`, `*.a`, сам двоичный) закрыты `.gitignore`, поэтому
`git diff` смотрит ровно на входы печати.

## 3. Проверять ДО захода

Свежеотпечатанное семя лежит в рабочем дереве несложенным в коммит, и
`git diff` называет ровно те же файлы, что и правка руками. До печати код
должен быть `0`, после печати `1` — это и есть результат. Поэтому код возврата
снимают **до** запуска `bootstrap-reprint.sh` и записывают рядом с журналом
захода: после захода уже нечем сказать, чистым ли он начинался.

## 4. Что делать, если семя правлено

1. **Не печатать из этого дерева.** Заход даст семя, выведенное из чужой правки,
   и никто не узнает, где именно оно разошлось со стволом.
2. Правку, если она нужна по существу, перенести в `flang/src/emit/c/` — оттуда
   рантайм уезжает в напечатанное дословно. Правка в `bootstrap/flang_runtime.*`
   держится ровно до следующей перепечатки и стирается без следа.
3. Завести чистую копию по пункту 1 и внести в неё только правку в
   `flang/self/**`, ради которой заход делается.

## 5. Как проверить, что дошедший заход начинался чистым

Есть голова копии захода `H` и коммит, которым семя легло в ствол, `S`. Семя
дерева захода на минуту начала совпадает со стволом, если

```sh
git diff --quiet H S^ -- bootstrap scripts/seed-fingerprint; echo $?   # → 0
```

а напечатанное совпадает с тем, что легло в ствол, если у каждого из семи
файлов (`bootstrap/compiler_flang.c`, `compiler_flang.h`, `flang_cli.c`,
`flang_repl.c`, `flang_runtime.c`, `flang_runtime.h`, `scripts/seed-fingerprint`)
`git rev-parse S:<файл>` равен `git hash-object` того же файла в копии захода.
Чистая копия на входе, семь файлов на выходе, один коммит в стволе.

## 6. Коммит в отпечатке восстанавливается измерением, а не рукой

`scripts/seed-fingerprint` называет коммит, из которого напечатано семя. Ветка
захода попадает в ствол переносом, коммит получает другой sha, и названный в
отпечатке перестаёт существовать. **Рукой эту строку не правят:** следующий
перенос снова её убьёт. Переживает перенос не sha, а содержимое входов печати,
поэтому коммит находится измерением:

```
$ sh scripts/bootstrap-reprint.sh --perekommit
коммит в отпечатке назван заново: scripts/seed-fingerprint
  было:  b8aecf53… — предком HEAD не является
  стало: 12310e37… — предок HEAD, входы совпали файл в файл
```

Прибор обходит предков HEAD, тронувших входы печати, и берёт самый молодой
из них, чьи входы сходятся с отпечатком файл в файл. Самый молодой из
**тронувших**, а не из совпадающих: назвать HEAD значило бы объявить отставание
нулевым даром. Если ветка захода в ствол не влита, её коммиты HEAD не предки, и
`--perekommit` отказывает кодом 1: семя напечатано из дерева, которого в стволе
нет, и чинится это перепечаткой.

`sh scripts/bootstrap-reprint.sh --bystro` делает ту же замену сам и судит
дальше; строку он при этом не правит, а советует `--perekommit`. Это стоит
секунды.

## 7. Перед отправкой: перенести на ствол и спросить `--bystro`

Заход идёт часами, и ствол за это время уезжает. Поэтому вопрос «сошлось ли с
нынешним стволом» задаётся перед отправкой:

```sh
git fetch origin main && git rebase origin/main
sh scripts/bootstrap-reprint.sh --bystro    # обязан ответить кодом 0
```

Код 1 значит, что ствол обогнал заход и печатать надо ещё раз. Тот же вопрос
стоит в `.github/workflows/reprint.yml` (работа `sverka`, шаг «Check seed
against the trunk») **до** печати: он отвечает за секунды, а печать идёт часами.

## Чем эта страница НЕ является

Она не про цену перепечатки — цена в [`reprint-cost.md`](reprint-cost.md) и в
[`reprint-ledger.tsv`](reprint-ledger.tsv). Не про свежесть семени — это

на другой вопрос: «те ли входы у печати», а не «чиста ли копия, из которой
печатают».
