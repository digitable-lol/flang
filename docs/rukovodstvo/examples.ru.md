# FTS на прикладных примерах

Все модели используют основной отступный синтаксис и входят в автоматические тесты.

## Форма регистрации клиента

[`customer-onboarding.fts`](../../examples/real-world/customer-onboarding.fts):

```fts
категория «Регистрация клиента»

  объект «Анкета клиента»
    ид является строкой
    «полное имя» является строкой
    «электронная почта» является Email
    телефон иногда является Телефон
    «согласие на обработку» является состоянием «Согласие получено»

  морфизм «Полученное согласие разрешает регистрацию»
    если «Согласие получено»
    то «Регистрация разрешена»

  теорема «Клиента КЛ-1042 можно зарегистрировать»
    дано «Анкета клиента» имеет «согласие на обработку» равное да
    в данных анкеты найти где ид равен «КЛ-1042»
    по морфизму «Полученное согласие разрешает регистрацию»
    следовательно «Регистрация разрешена»
```

Генератор формы читает только раздел `объект`:

```bash
node examples/utilities/form-schema.mjs \
  examples/real-world/customer-onboarding.fts \
  "Анкета клиента"
```

```json
{
  "kind": "form",
  "id": "Регистрация клиента.Анкета клиента",
  "fields": [
    { "name": "электронная почта", "control": "email", "required": true },
    { "name": "телефон", "control": "tel", "required": false }
  ]
}
```

## Таблица счетов

[`invoices-table.fts`](../../examples/real-world/invoices-table.fts) содержит объект `«Строка счёта»`. Утилита строит колонки:

```bash
node examples/utilities/table-columns.mjs \
  examples/real-world/invoices-table.fts \
  "Строка счёта"
```

```json
{
  "kind": "table",
  "columns": [
    { "key": "номер", "format": "text" },
    { "key": "сумма", "format": "number" },
    { "key": "срок оплаты", "format": "date" },
    { "key": "просрочен", "format": "badge" }
  ]
}
```

Тот же объект может стать основой CSV-экспорта, API-документации, поискового индекса или agent tool schema.

## DDD command guard

[`order-shipment.fts`](../../examples/real-world/order-shipment.fts):

```fts
категория «Исполнение заказа»

  объект Заказ
    номер является строкой
    «готов к отгрузке» является состоянием «Готов к отгрузке»

  морфизм «Готовый заказ можно отгрузить»
    если «Готов к отгрузке»
    то «Отгрузить заказ разрешено»

  теорема «Заказ ЗК-7781 можно отгрузить»
    дано Заказ имеет «готов к отгрузке» равное да
    в данных заказы найти где номер равен «ЗК-7781»
    по морфизму «Готовый заказ можно отгрузить»
    следовательно «Отгрузить заказ разрешено»
```

Guard:

```bash
node examples/utilities/command-guard.mjs \
  examples/real-world/order-shipment.fts \
  examples/real-world/order-shipment.context.json
```

```json
{
  "allowed": true,
  "command": "Отгрузить заказ разрешено"
}
```

Если в snapshot `"готов к отгрузке": false`, guard возвращает `"allowed": false`.

## Композиция кредитной политики

[`credit-limit.fts`](../../examples/real-world/credit-limit.fts) последовательно применяет два морфизма:

```fts
теорема «Лимит ЛМ-205 может быть установлен»
  дано «Заявка на лимит» имеет «скоринг пройден» равное да
  в данных заявки найти где номер равен «ЛМ-205»
  по морфизму «Пройденный скоринг открывает риск-проверку»
  затем по морфизму «Успешная риск-проверка разрешает лимит»
  следовательно «Лимит может быть установлен»
```

Если выход первого морфизма не совпадает со входом второго, компиляция прекращается. Если строка `получаем` не совпадает с фактическим выводом, теорема также отклоняется.

## Что делает FTS, а что делает приложение

FTS отвечает за предметные имена, формы данных, допустимые переходы, конкретную теорему, проверку snapshot и сертификат.

Приложение отвечает за React-компоненты, базу данных, вычисление агрегатных инвариантов, выполнение команды и выбор доверенных законов.

Практический смысл и интеграции по ролям описаны в [Зачем нужен FTS и как его интегрировать](why-and-integration.ru.md).
