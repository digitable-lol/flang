# Службы в работе

Условие 7 выпуска 1.0 ([`road-to-1-0.md`](road-to-1-0.md)) считается взятым,
когда названы службы на flang, сроки их жизни и то, что в них ломалось. Эта
страница — тот самый отчёт. В дерево пишутся только сводки: таблица служб и
журнал происшествий. Сырые журналы (запросы, пробы здоровья, journald) живут
на машине рядом со службой.

## Службы

| служба | что делает | адрес | в работе с | двоичное |
|---|---|---|---|---|
| `flang-registry` | реестр имён пакетов: отдаёт по HTTP ведомость `registry.list`, разобранные записи, версии пакета и выбор версии, описания пакетов, страницу здоровья и журнал запросов | машина разработки `dev`, `http://127.0.0.1:8766/` (порт слушается на всех адресах машины, см. журнал) | 24 октября 2026, 20:07 UTC | `flang 0.7.30`, собран `make -C bootstrap` из дерева ветки `a/the-first-service-in-production` (коммит — в `VERSION` каталога службы) |

Исходник службы — [`flang/services/registry/`](../flang/services/registry/):
`core.flang` решает (разбор запроса, маршрут, выбор записи, текст ответа,
счётчики, журнал), `serve.flang` — план, который встречается с сетью. Проверка
`flang test flang/services/registry` гоняет 806 примеров (141 свой, остальные —
ввезённых модулей), `flang check core.flang --proof` — 32 утверждения, из них
доказанных ядром 20, на сетке 12, не доказанных 0 (у `serve.flang` ещё одно, на
сетке; у пробы здоровья 4: 2 и 2).

Что отвечает служба:

```
GET /                      что здесь есть
GET /registry.list         ведомость как она лежит на диске (формат списка — задача 3403)
GET /packages              разобранная ведомость: строка на запись
GET /packages/<имя>        версии пакета и та, которую выберет установщик без нужд
GET /packages/<имя>/<в>    описание пакета — файл по адресу из ведомости
GET /<адрес из ведомости>  файл пакета по его адресу — так его берёт установщик
                           `package:install --registry http://…/registry.list`
GET /health                служба, работает, секунд работы, запросов, отказов,
                           записей и бед в ведомости, запущена
GET /journal               последние 200 запросов
```

Имя пакета в пути — кириллицей или в процентах (`%D0%9B…`). Любой другой путь —
404, любой метод, кроме GET, — 405, испорченный запрос — 400. Отказом считается
ответ с кодом от 400.

## Как служба устроена на машине

Каталог службы — `/home/b/projects/flang-registry-service/` (постоянный: `/tmp`
на машине чистится при перезагрузке):

| что | где |
|---|---|
| двоичное | `bin/flang` — копия `bootstrap/flang` дерева, из которого ставили |
| библиотека | `share/flang/stdlib`, `share/flang/core` — ввозы по имени ищутся рядом с двоичным |
| служба и проба | `service/serve.flang`, `service/core.flang`, `service/health.fscript` |
| ведомость и пакеты | `service/registry-example/` — копия `scripts/registry-example` дерева: `registry.list` и файлы пакетов рядом с ним; относительный адрес из списка считается от каталога списка (формат — `docs/registry-list-format.md` из задачи 3403) |
| журнал запросов | `service/registry.log` — окно последних 200 запросов; хозяин умеет только переписать файл, дописать нельзя, поэтому окно, а не бесконечный журнал. Переживает перезапуск: при старте служба читает его обратно |
| пробы здоровья | `health.log` — строка в пять минут: `ok секунд=… запросов=… отказов=…` либо `FAIL curl=<код>` |
| из какого коммита | `VERSION` |
| journald | `journalctl --user -u flang-registry` — старт, остановка, причина падения, перезапуск |

Единицы `systemd --user` пользователя `b` (для них включён `loginctl
enable-linger b`, иначе пользовательский systemd умирает вместе с сеансом):

- `flang-registry.service` — `flang io service/serve.flang --trust --in-dir
  --max-orders 1000000000 -- 8766`, `Restart=on-failure`, `RestartSec=5`,
  `MemoryMax=4G`;
- `flang-registry-health.timer` → `flang-registry-health.service` — проба
  `/health` раз в пять минут планом `service/health.fscript` (тоже на flang);
  упавшая проба — упавшая единица в journald и строка `FAIL` в `health.log`.

Почему `--trust`: доказательства и примеры проверяются при установке, а не при
каждом подъёме службы (проверка — полторы минуты и два гигабайта; подъём с
`--trust` — семь секунд, из них почти всё — прогон примеров). Почему `--in-dir`:
поручения плана не выходят за каталог службы, что бы ни пришло в пути
запроса; описание пакета читается только по адресу из ведомости.

### Перезапустить, посмотреть, обновить

```sh
export XDG_RUNTIME_DIR=/run/user/$(id -u)      # если команды ниже не видят шину
systemctl --user status flang-registry          # жива ли, сколько памяти, перезапуски
systemctl --user restart flang-registry         # перезапуск руками
journalctl --user -u flang-registry -n 50       # почему падала
curl http://127.0.0.1:8766/health               # здоровье
tail /home/b/projects/flang-registry-service/health.log
tail /home/b/projects/flang-registry-service/service/registry.log
```

Обновить при выпуске — из дерева с нужным коммитом:

```sh
bootstrap/flang io scripts/services/registry-deploy.fscript --plan "Установить" --timeout 14400000
```

План (на flang: оснастке на оболочке в дереве расти нельзя) собирает двоичное (`make -C bootstrap`, через `heavy.sh`, если он есть
на машине), гоняет `flang check` плана и `flang test` каталога службы и при
любой красной проверке останавливается, не трогая работающую службу; затем
раскладывает двоичное, библиотеку, исходники и ведомость, переписывает единицы
systemd, перезапускает службу и ждёт ответа `/health`. Каталог и порт — доводы
после `--` (`-- /каталог 8766`); `FLANG_REGISTRY_NO_HEAVY=1` зовёт `make`
напрямую, минуя очередь `heavy.sh`, когда двоичное уже собрано.

## Чего эта служба не умеет, и это названо

- Одно соединение — один обмен, keep-alive нет; одновременные соединения ждут
  в очереди слушающего сокета (16), служба отвечает им по одному.
- Хозяин `flang io` держит в памяти журнал всех поручений до конца прогона; при
  четырёх–шести поручениях на запрос это килобайты в сутки на пробах здоровья,
  но память службы растёт монотонно. `MemoryMax=4G` — предохранитель: упор в
  него виден как перезапуск в journald и запись сюда.
- Счётчики `/health` — с последнего подъёма; история между подъёмами — в
  `health.log` и в journald.
- Ведомость — пример `scripts/registry-example` (ADR-0059) в формате задачи
  3403: голые имена файлов, адрес считается от каталога списка. Служба отдаёт
  файл пакета по адресу из списка и ничего другого: путь, которого в ведомости
  нет, — 404.
- Порт 8766, а не 8765: 8765 на машине занят другой службой.
