# Служба flang для ИИ-помощника

`flang --mcp-mode` — служба MCP. Через неё помощник проверяет программу на
flang и узнаёт, что о ней доказано. Служба читает JSON-RPC со стандартного
ввода, по сообщению на строку, и отвечает в стандартный вывод. Рамок
`Content-Length`, как в LSP, нет.

Запускает службу помощник, а не человек. Запущенная руками, она молча ждёт
строк.

## Как подключить

```json
{"mcpServers": {"flang": {"command": "flang", "args": ["--mcp-mode"], "env": {}}}}
```

Рабочий каталог службы задайте явно: от него зависит, найдёт ли она файлы,
которые программа подключает, — см. «Служба не видит соседних файлов».

Проверить, что служба отвечает:

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' | flang --mcp-mode
```

```json
{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{}},"serverInfo":{"name":"flang","version":"{{выпуск.версия}}"}}}
```

Поле `id` возвращается таким, каким пришло: числом или строкой.

## Два средства

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' \
              '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}' \
  | flang --mcp-mode | tail -1 | python3 -m json.tool
```

| Средство | Обязательные поля | Что возвращает |
|---|---|---|
| `flang_check` | `source` | отчёт о доказательствах по всей программе |
| `flang_prove` | `source`, `claim` | вердикт по одному названному утверждению |

`source` — текст программы целиком. `claim` — имя из строки
`обеспечивает «имя» цель`, а не сама цель.

## Ответ — один текст, без поля «ок»

У `result` один ключ, у элемента `content` — два:

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"flang_check","arguments":{"source":"модуль «П»\n"}}}' \
  | flang --mcp-mode | tail -1 \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(list(d["result"]), list(d["result"]["content"][0]))'
```

```
['content'] ['type', 'text']
```

Ни `isError`, ни признака успеха нет. Исход различается по первой строке
текста:

| Первая строка ответа | Что произошло |
|---|---|
| `Слова ведомости, и они НЕ взаимозаменяемы:` | программа прошла проверку, дальше идёт отчёт |
| `Программа НЕ ПРОШЛА проверку языка, и ведомость доказательства поэтому не печатается.` | ответ `flang_check`: программа отвергнута |
| `Программа НЕ ПРОШЛА проверку языка, доказывать нечего:` | то же в ответе `flang_prove` |
| `Обещания «…» в программе нет.` | имя в `claim` не найдено; программа при этом цела |

Под строкой «НЕ ПРОШЛА» идут замечания вида `FLANG_КОД, строка N, столбец M: …`.
Опечатку, несовпадение типов, несошедшийся пример и ненайденный файл различает
только код — см. [Коды замечаний](diagnostics.html).

## Слова отчёта

Успешный ответ начинается словарём. Он приходит в каждом ответе, помнить его
между вызовами не нужно:

```
Слова ведомости, и они НЕ взаимозаменяемы:
  «доказано» — утверждение обо ВСЕХ входах, выведенное из объявлений и структуры;
  «доказано индукцией по «Т»» — то же обо всех входах типа «Т»;
  «сетка N» — посчитано на N значениях автора. ЭТО НЕ ДОКАЗАТЕЛЬСТВО;
  «объявлено, не доказано» — утверждение высказано, доказательства при нём нет;
  «НАРУШЕНО» — ложь, уже найденная примером автора.
Ни одно из этих слов не сводится к «ок».
```

Ниже идёт сам отчёт — тот же, что печатает `flang check --proof`. В его
заголовке есть шестое слово, которого нет в словаре выше: «на веру» — «не
посчитано ничем, допущение автора».

Последние строки отчёта считают исходы. Для
`docs/examples/crypto/certificate.flang`:

```
итог:
  функций 7: тотальных 7, обычных 0
  обещание несёт: композиция 7, структура 0, точный шаг 0, постоянный шаг 0, объявленная мера 0
  сторожей в рантайме: 0 мест
  законов на сетке: 0 (значений в сетках 0); на веру: 0
  утверждений 2: доказано 1 (из них без теоремы 1), сетка 1, объявлено, не доказано 0
```

Из двух утверждений одно стоит на примере автора, а не на доказательстве.
Отчёт считает только присланный текст: функции и утверждения подключённых
модулей в него не входят.

## Вердикт по одному утверждению

`flang_prove` полезен, когда утверждение выглядит верным. Здесь автор уверен,
что срок не бывает отрицательным:

```flang refused
модуль «Срок»

тотальная функция «Дней осталось»
  принимает выдан: число, ныне: число
  возвращает число
  обеспечивает «срок никогда не отрицателен» результат не меньше 0
  пример «просрочен»
    дано выдан равно 10
    дано ныне равно 400
    ожидается -25
  (выдан плюс 365) минус ныне
```

Запрос собирается из файла программы:

```bash
python3 -c 'import json; print(json.dumps({"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}))' > request.jsonl
python3 -c 'import json; print(json.dumps({"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"flang_prove","arguments":{"source":open("term.flang").read(),"claim":"срок никогда не отрицателен"}}},ensure_ascii=False))' >> request.jsonl
flang --mcp-mode < request.jsonl | tail -1 \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["result"]["content"][0]["text"])'
```

```
Программа НЕ ПРОШЛА проверку языка, доказывать нечего:

FLANG_BOUND_ON_NAN, строка 6, столбец 3: постусловие «срок никогда не отрицателен» функции «Дней осталось» ЛОЖНО, и контрпример назван: «выдан» объявлен типом «число», а «не число» живёт в этом типе и стоит ВНЕ ПОРЯДКА — оно не больше и не меньше ничего, включая самоё себя. Тело собрано только из арифметики над «выдан», а всякая арифметическая операция «не число» переносит, значит результат есть «не число», и сравнение с ним ложно. Позовите «Дней осталось» от (0 делить на 0) — рантайм ответит FLANG_PROPERTY. Чинится тремя способами: объявить вход отрезком («неотрицательное», «целое») — тогда «не число» не втащить вовсе; поставить предусловие — за него платит вызывающий; либо оговорить границу, и ядро оговорку читает: обеспечьте «не ((выдан минус выдан) равен 0) или (…)»
```

Служба назвала контрпример и три способа починить. Контрпример не тот, что в
примере автора: автор думал о просрочке, служба нашла «не число».

Если утверждение не ложно, но и не доказано, ответ говорит, что с ним будет
при работе программы:

```flang
модуль «Удвоение»

тотальная функция «Удвоить»
  принимает х: число
  возвращает число
  обеспечивает «вдвое больше входа» результат равен (х умножить на 2)
  х плюс х
```

```
  постусловие «вдвое больше входа» функции «Удвоить» — объявлено, не доказано: ни теоремы, ни примеров. Его считает рантайм после каждого возврата — на тех входах, которые придут
```

Имя, которого в программе нет:

```
Обещания «нет такого» в программе нет. Обещание пишется строкой `обеспечивает «имя» цель` внутри функции.
```

## Что служба находит сама, а что нет

В программе ниже четыре ошибки: занятое языком слово `список` в имени
параметра, два несовпадения типов и одна смысловая — функция считает не длину
списка, а ноль.

```flang refused
модуль «Отчёт»

тотальная функция «Строк в списке»
  принимает список: список строки
  возвращает число
  разбор список
    случай пусто
      то 0
    случай голова и хвост
      «Строк в списке» от хвост

тотальная функция «Заголовок»
  принимает имя: строка
  возвращает число
  имя плюс 1

тотальная функция «Метка»
  принимает номер: число
  возвращает строка
  номер
```

Ниже ответы `flang check` на файл `report.flang` с этой программой. Служба
называет те же замечания под строкой «Программа НЕ ПРОШЛА…».

**Ошибка разбора приходит одна и заслоняет остальные:**

```
FLANG_PARSE в файле report.flang, строка 6, столбец 10: не разобрана конструкция: неожиданное 'список' — это слово занято языком, именем оно быть не может: напишите имя в ёлочках («список») или переименуйте; а если слово попало в форму лишним — уберите его
report.flang: не проверено — замечаний 1
```

**Ошибки типов приходят вместе.** После переименования параметра в `строки`:

```
модуль «Отчёт»: функций 3, из них с доказанным завершением 3; типов 0
FLANG_TYPE в файле report.flang, строка 15, столбец 3: левый операнд «add»: ожидался число, получен строка
FLANG_TYPE в файле report.flang, строка 20, столбец 3: функция «Метка» объявлена как строка, а тело даёт число
report.flang: не проверено — замечаний 2
```

**Смысловую ошибку служба не видит.** После починки типов (`(длина имя) плюс 1`
и `к строке номер`) программа проходит, хотя «Строк в списке» возвращает ноль
на любом списке:

```
модуль «Отчёт»: функций 3, из них с доказанным завершением 3; типов 0
report.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Её ловит пример или утверждение, написанные автором. Пример с тремя строками
и `ожидается 3` меняет ответ:

```
модуль «Отчёт»: функций 3, из них с доказанным завершением 3; типов 0
FLANG_EXAMPLE: пример «три строки» функции «Строк в списке»: значение не совпало с ожидаемым: ожидалось 3, получено 0
report.flang: не проверено — замечаний 1
```

## Ошибки протокола

```bash
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' \
  '{"jsonrpc":"2.0","id":2,"method":"resources/list","params":{}}' \
  'это не json' \
  '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"flang_check","arguments":{}}}' \
  '{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"flang_nonexistent","arguments":{}}}' \
  | flang --mcp-mode
```

Пять строк на входе, четыре ответа на выходе. Первый — ответ на `initialize`,
остальные три:

```json
{"jsonrpc":"2.0","id":2,"error":{"code":-32601,"message":"служба flang не знает метода «resources/list»"}}
{"jsonrpc":"2.0","id":4,"error":{"code":-32602,"message":"в запросе нет поля «source» — текста программы на flang"}}
{"jsonrpc":"2.0","id":5,"error":{"code":-32602,"message":"служба flang не знает средства «flang_nonexistent». Их два: flang_check и flang_prove"}}
```

Строка, не разобранная как JSON, ответа не получает. О ней служба пишет в
стандартный поток ошибок:

```
flang --mcp-mode: строка не разобрана как JSON, пропущена
```

Клиент, который ждёт ответа на каждую строку, здесь зависнет. Ставьте срок
ожидания и читайте поток ошибок.

## Служба не видит соседних файлов

Служба получает текст программы, а не файл. Строка подключения в тексте есть:

```flang fragment
модуль «Сертификат»
  использует «X.509» из "../../../flang/stdlib/x509.flang"
```

Относительный путь служба считает от своего рабочего каталога. Программа,
которую `flang check` с диска проверяет без замечаний, через службу из чужого
каталога отвечает так:

```
FLANG_IMPORT_NOT_FOUND, строка 1, столбец 1: не найден модуль «X.509»: …/flang/stdlib/x509.flang (ENOENT: no such file or directory, …)
FLANG_UNKNOWN_NAME, строка 47, столбец 31: неизвестная функция «Версия сертификата»
…
```

Один ненайденный файл дал 41 замечание: 1 `FLANG_IMPORT_NOT_FOUND`, 27
`FLANG_UNKNOWN_NAME` и 13 `FLANG_NOT_TOTAL`. Считаются они так (в
`request.jsonl` — `initialize` и `tools/call` со средством `flang_check`, где
`source` — текст `docs/examples/crypto/certificate.flang`):

```bash
flang --mcp-mode < request.jsonl | tail -1 | python3 -c \
 'import json,sys,re,collections; t=json.load(sys.stdin)["result"]["content"][0]["text"]; print(collections.Counter(re.findall(r"FLANG_[A-Z_]+", t)))'
```

Чинить в программе нечего: не найден один файл. Запускайте службу с рабочим
каталогом программы либо присылайте программу без подключений.

Тот же запрос из каталога программы проходит и возвращает отчёт, строки
которого приведены выше:

```bash
cd docs/examples/crypto && flang --mcp-mode < request.jsonl | tail -1
```

## Чего служба не делает

- Не отвечает «ок»: исход нужно читать по словам отчёта.
- Не находит смысловых ошибок, о которых автор не написал ни примера, ни
  утверждения.
- Не запускает программу и не исполняет планы.
- Не отвечает на вопросы «что сломается, если это поменять» и «согласуются ли
  требования между собой».
