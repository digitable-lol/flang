# Проверить рассуждение в тексте

Команда `flang run-script argue` берёт текст и файл разметки к нему. Она
отвечает, какие выводы автора следуют из его посылок, а какие нет. Команда
работает в клоне репозитория flang: она записана в его файле `.flangrc`.

flang не читает свободный текст сам. Что утверждает каждое предложение и что из
чего выводится, записывает человек или языковая модель — в файле разметки.
flang делает две вещи: сравнивает каждую цитату разметки с текстом и отдаёт каждый
шаг рассуждения ядру доказательств.

## Что находит проверка

| Находка | Как она получена |
| --- | --- |
| вывод не следует из посылок | ядро подтверждает случай, когда посылки верны, а вывод ложен |
| противоречие между двумя суждениями | ядро выводит из них ложь; суждения могут стоять в разных концах текста |
| порочный круг | вывод прямо или через цепочку шагов опирается сам на себя |
| подмена термина | одно слово текста размечено двумя разными понятиями |
| шаг, который не доказательство | шаг помечен как обобщение, корреляция или ссылка на авторитет |
| вывод без посылок | у слова «следовательно» нет суждений, из которых сделан вывод |
| пропуск в разметке | в предложении есть «значит» или «поэтому», а шага в разметке нет |

Для шага, который не следует, отчёт называет недостающую посылку, когда может
её построить, и проверяет ядром, что с ней вывод следует.

## Пример: от текста до отчёта

Текст лежит в `docs/examples/argue/service.txt`:

```
Под надёжным сервисом мы понимаем сервис, который отвечает на каждый запрос.
Все сервисы с резервной копией надёжны. Сервис «Архив» имеет резервную копию.
Следовательно, «Архив» надёжен. Пользователи называют «Архив» надёжным, так
что он отвечает на каждый запрос. После перехода на новую базу жалоб стало
меньше, значит, новая база повысила качество.
```

Разметка лежит рядом, в `docs/examples/argue/service.claims`. Её начало:

```
понятие с_копией(x): у сервиса x есть резервная копия
понятие надёжен(x): сервис x надёжен
имя Архив

[2] все x: если с_копией(x), то надёжен(x)
    цитата: Все сервисы с резервной копией надёжны
[3] с_копией(Архив)
    цитата: Сервис «Архив» имеет резервную копию
[4] надёжен(Архив)
    цитата: Следовательно, «Архив» надёжен
вывод [4] из [2], [3]
```

Строка `понятие` объявляет понятие и число его мест. Строка `[N]` — суждение:
номер и логическая форма. Строка `цитата:` — слова текста, из которых суждение
взято. Строка `вывод` говорит, что автор выводит суждение 4 из суждений 2 и 3.

Запуск из корня клона:

```bash
flang run-script argue -- docs/examples/argue/service.txt --out report.md
```

```
отчёт записан: report.md; находок: 3; шагов: 3, следует: 1, не следует: 2, ядро не решило: 0
```

Файл разметки команда ищет рядом с текстом: `service.claims` для `service.txt`.
Другое место называет ключ `--claims <файл>`. Без `--out` отчёт ляжет рядом с
текстом под именем `service.argue.md`. Проверка этого текста занимает около
десяти секунд.

Отчёт — файл Markdown. Его таблица шагов:

```
| Шаг | Род | Вердикт |
| --- | --- | --- |
| [4] из [2], [3] | дедукция | следует (доказано ядром) |
| [6] из [5] | ссылка на авторитет | не следует (пример против подтверждён ядром) |
| [8] из [7] | причинное заключение из корреляции | не следует (пример против подтверждён ядром) |
```

Первый шаг доказан. Два других помечены в разметке как не строгие, и ядро
подтверждает: из посылок они не следуют. Про шаг `[8] из [7]` отчёт пишет:

```
- **Что не так:** шаг помечен в разметке как «корреляция»: из того, что два признака
  встречаются вместе, не следует, что один вызывает другой.
- **Почему:** из посылок вывод логически не следует; пример против подтверждён ядром:
  верно: `жалоб_меньше`; неверно: `база_повысила_качество`.
- **Чего не хватает:** посылки `если жалоб_меньше, то база_повысила_качество`: с ней
  вывод следует (доказано ядром). В разметке такой посылки нет.
```

Третья находка — подмена термина. Слово «надёжным» определено в первом
предложении как «отвечает на каждый запрос», а в пятом значит «нравится
пользователям».

## Как получить разметку

Готовая инструкция для языковой модели лежит в
`docs/examples/argue/claims-prompt.md`. Отдайте модели этот файл и текст статьи,
ответ сохраните как `статья.claims`. По той же инструкции размечает человек.

Модель может ошибиться. От двух ошибок flang защищает сам:

- цитата, которой нет в тексте, останавливает проверку и называет строку
  разметки: `строка 14 разметки: цитата суждения [2] не стоит в тексте дословно`;
- необъявленное понятие, пропущенная цитата и ссылка на суждение, которого нет,
  тоже называются со строкой.

Третью ошибку flang не видит: логическая форма может передавать смысл
предложения неверно. Цитата стоит рядом с формой в каждой находке отчёта,
чтобы это мог проверить человек.

Текст из PDF получают командой `pdftotext статья.pdf статья.txt`, из Word —
`pandoc статья.docx -t plain -o статья.txt`.

## Формат разметки

| Строка | Смысл |
| --- | --- |
| `понятие кит(x): пояснение` | свойство предмета |
| `понятие старше(x, y): пояснение` | отношение двух предметов |
| `понятие дождь: пояснение` | высказывание целиком |
| `имя Сократ, Моби` | названные в тексте предметы |
| `[N] форма` | суждение с номером |
| `цитата: слова текста` | откуда суждение взято; обязательна |
| `термин: слово = смысл` | в каком смысле слово стоит в этой цитате |
| `определение: слово = смысл` | то же для предложения, где автор слово определяет |
| `вывод [N] из [M], [K]` | шаг рассуждения |
| `вывод [N] из [M]: корреляция` | шаг с пометкой рода |
| `# текст` | комментарий |

Логическая форма пишется словами: `не`, `и`, `или`, `если …, то …`, скобки,
`все x:` и `есть x:`. Примеры: `все x: если кит(x), то не рыба(x)`,
`есть x: кит(x) и белый(x)`, `если дождь, то мокро`, `старше(Анна, Борис)`.

Род шага: `обобщение`, `корреляция`, `авторитет`, `определение`. Шаг без
пометки заявлен как строгий вывод.

## Как читать отчёт

Отчёт начинается сводкой: сколько предложений в тексте, сколько из них покрыто
цитатами, сколько шагов проверило ядро и сколько находок каждого вида.

Раздел «Находки» перечисляет ошибки рассуждения. У каждой есть цитаты, строки
«Что не так», «Почему» и «Чего не хватает».

Раздел «Не доказательство» перечисляет шаги с пометкой рода. flang их не
опровергает. Он показывает, что вывод не следует из посылок логически, и
называет посылку, которую автор принял, не назвав.

Раздел «Ядро не решило» перечисляет шаги, которые оказались для ядра слишком
крупными. Такой шаг нужно разбить в разметке на два.

Раздел «Покрытие» называет предложения со словами вывода, которых разметка не
коснулась. Это место, где разметку стоит перечитать.

Слова отчёта о ядре:

| Слова | Что стоит за ними |
| --- | --- |
| следует (доказано ядром) | ядро приняло доказательство шага для всех случаев |
| не следует (пример против подтверждён ядром) | ядро вычислило посылки и вывод на найденном случае: посылки верны, вывод ложен |
| ядро не решило | шаг больше, чем ядро берётся проверить, либо ядро проверку не приняло |

## Что ядро проверяет и чего не проверяет

Проверяет:

- формы без кванторов над высказываниями и над названными предметами;
- формы с кванторами одного вида в начале: `все x, y: …` или `есть x: …`;
- понятия с одним местом, с двумя и больше;
- шаг, в котором после подстановки предметов набирается до семи простых
  высказываний. До четырёх ядро доказывает само, от пяти до семи — разбором
  случаев, который записывает flang, а проверяет ядро.

Не проверяет:

- форму, где `все` и `есть` стоят вперемешку («у каждого студента есть
  наставник»): разметка с ней отклоняется;
- шаг, где простых высказываний больше семи: доказательство ядру не отдаётся, отчёт
  пишет «ядро не решило». Пример против ищется, пока высказываний не больше десяти;
- равенство, числа и арифметику внутри формы;
- истинность посылок: проверяется только связь между посылками и выводом;
- противоречие между тремя и более суждениями, если никакие два из них не
  противоречат друг другу и они не стоят посылками одного шага.

Квантор flang раскрывает сам: подставляет вместо переменной каждый предмет,
который назван в шаге. Ядро получает формулу без кванторов. Для форм из списка
«Проверяет» такой подстановки достаточно: ответ «не следует» означает, что есть
настоящий пример против.
