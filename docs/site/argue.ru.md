# Проверить рассуждение в тексте

Команда `flang run-script argue:article` берёт статью — PDF, Word или текст — и
пишет отчёт о её рассуждении: какие выводы автора следуют из его посылок, какие
нет, на чём держится главный вывод и что автор принял без доказательства.
Команда работает в клоне репозитория flang: она записана в его файле `.flangrc`.

```bash
flang run-script argue:article -- статья.pdf
```

flang не читает свободный текст сам. Что утверждает каждое предложение и что из
чего выводится, записывает языковая модель или человек — в файле разметки.
flang делает остальное: достаёт из файла текст, вызывает вашу команду разметки,
сравнивает каждую цитату разметки с текстом, отдаёт каждый шаг рассуждения ядру
доказательств и собирает отчёт.

## Что в отчёте

| Раздел | Что в нём |
| --- | --- |
| Коротко | главный вывод статьи, сколько шагов к нему ведёт и сколько из них не следуют, главное допущение |
| Карта рассуждения | все шаги «посылки → вывод» списком и диаграммой; отмечены выводы, под которыми есть шаг, который не следует |
| Провалы рассуждения | противоречия, порочные круги, подмена термина, выводы без посылок, шаги, которые не следуют |
| Допущения автора | что нужно для вывода, но в тексте не сказано, и что сказано без вывода; у каждого — какие выводы на нём стоят. Сюда же идут шаги с пометкой «допущение» |
| Не доказательство | шаги, которые разметка назвала не строгим выводом: обобщение, корреляция, ссылка на авторитет, вывод из значимости, перенос с выборки, правдоподобный вывод |
| Ядро не решило | шаги, которые ядро не проверило, и причина для каждого |
| Все шаги | таблица шагов с вердиктом ядра |
| Словарь понятий | понятия статьи с пояснениями и слова, смысл которых сменился |
| Кем прочитано | про каждое предложение: кто записал его смысл |
| Вне текста статьи | список литературы, резюме на другом языке, заголовки и строки таблиц: в счёт предложений они не идут |
| Не досчитано | шаги, проверка которых не уложилась в предел времени или памяти |
| Выброшено из разметки | записи разметки с цитатой, которой нет в тексте |

## Пример: от текста до отчёта

Текст лежит в `docs/examples/argue/service.txt`:

```
Под надёжным сервисом мы понимаем сервис, который отвечает на каждый запрос.
Все сервисы с резервной копией надёжны. Сервис «Архив» имеет резервную копию.
Следовательно, «Архив» надёжен. Пользователи называют «Архив» надёжным, так
что он отвечает на каждый запрос. После перехода на новую базу жалоб стало
меньше, значит, новая база повысила качество.
```

Готовая разметка лежит рядом, в `docs/examples/argue/service.claims`, поэтому
команда разметки здесь не нужна. Запуск из корня клона:

```bash
flang run-script argue:article -- docs/examples/argue/service.txt --out report.md
```

```
отчёт записан: report.md; провалов рассуждения: 1; подразумеваемых посылок: 0; шагов без доказательной силы: 2; шагов: 3, следует: 1, не следует: 2, без посылок: 0, посылки противоречат друг другу: 0, ядро не решило: 0; выброшено записей разметки: 0; не досчитано: 0
время: 48 с
```

Отчёт — файл Markdown. Его начало:

```
## Коротко

- Главный вывод: [8] «новая база повысила качество».
- Шагов до него: 1; из них следуют: 0, не следуют: 1 (из них строгих шагов, которым не хватает одной посылки: 0), ядро не решило: 0.
- Главное допущение: скрытая посылка шага [8] из [7]: `если жалоб_меньше, то база_повысила_качество` (с ней шаг следует — доказано ядром) — в тексте её нет. Если это неверно, без опоры остаются выводы: [8].
- Другие итоговые выводы: [4], [6].
- Найдено: провалов рассуждения: 1; подразумеваемых посылок: 0; шагов без доказательной силы: 2.
```

Карта рассуждения идёт от выводов к посылкам:

```
- [4] «Следовательно, «Архив» надёжен» — дедукция из [2], [3]: следует (доказано ядром).
  - [2] «Все сервисы с резервной копией надёжны» — принято без вывода
  - [3] «Сервис «Архив» имеет резервную копию» — принято без вывода
- [6] «он отвечает на каждый запрос» — ссылка на авторитет из [5]: не следует (пример против подтверждён ядром).
  - [5] «Пользователи называют «Архив» надёжным» — принято без вывода
```

Под списком стоит та же карта диаграммой Mermaid. GitHub, GitLab и многие
редакторы Markdown рисуют её сами.

Раздел «Допущения автора» называет посылку, которой в тексте нет:

```
- скрытая посылка шага [8] из [7]: `если жалоб_меньше, то база_повысила_качество` (с ней шаг следует — доказано ядром) — в тексте её нет. Если это неверно, без опоры остаются выводы: [8].
```

Единственный провал в этом тексте — подмена термина. Слово «надёжным»
определено в первом предложении как «отвечает на каждый запрос», а в пятом
значит «нравится пользователям».

## PDF, Word и другие форматы

Файл с расширением `.pdf` команда переводит в текст программой `pdftotext`,
файлы `.docx`, `.odt`, `.rtf`, `.html` и `.epub` — программой `pandoc`. Любой
другой файл читается как текст.

Если нужной программы нет, команда останавливается и говорит, что поставить:

```
для PDF нужна программа pdftotext, она не найдена. Поставьте пакет poppler-utils:
в Debian и Ubuntu — sudo apt install poppler-utils, в macOS — brew install poppler.
```

Текст, который достали из файла, сохраняется рядом с отчётом: для
`статья.pdf` это `статья.argue.txt`. Цитаты разметки сравниваются именно с ним.

Таблицы сохраняются отдельно, в файл `статья.argue.tables.txt`. Из документов
Word и HTML таблицы берутся целиком и в текст для разметки не попадают. В PDF
таблиц как таковых нет: команда ищет их по расположению колонок на странице и
может пропустить таблицу или принять за неё колонки текста.

Если в PDF нет текста, а есть только картинки страниц, команда скажет об этом.
Такой файл сначала нужно распознать, например программой `ocrmypdf`.

## Разметка

Разметку команда берёт одним из двух способов.

**Готовый файл.** Если рядом со статьёй лежит `статья.claims`, берётся он.
Другое место называет ключ `--claims <файл>`.

**Команда разметки.** flang сам к языковой модели не обращается и ключей
доступа не хранит. Вы называете команду, которая это делает:

```bash
flang run-script argue:article -- статья.pdf --markup-cmd "claude -p"
```

Команда разметки получает на стандартный вход готовое задание: инструкцию из
`docs/examples/argue/claims-prompt.md` и текст статьи. Она должна вывести
разметку. Подойдёт любая программа, которая читает задание со входа и выводит
ответ модели. Ответ сохраняется в `статья.claims`, прежний файл остаётся под
именем `статья.claims.bak`.

Проверенные команды:

| Команда | Что она делает |
| --- | --- |
| `--markup-cmd "claude -p"` | отдаёт задание программе Claude Code |
| `--markup-cmd "claude -p --model haiku"` | то же с быстрой моделью |
| `--markup-cmd 'cat разметка/часть$FLANG_ARGUE_PART.claims'` | подставляет разметку, которую вы написали сами для каждой части |

Чтобы не писать ключ каждый раз, задайте переменную среды
`FLANG_ARGUE_MARKUP_CMD`. Она срабатывает, только когда готовой разметки рядом
нет. Ключ `--markup-cmd` размечает статью заново при каждом запуске.

Если нет ни файла разметки, ни команды, flang ничего не выдумывает. Он
останавливается и перечисляет оба способа.

### Длинная статья

Статья длиннее 12 000 знаков размечается по частям. Часть заканчивается на
границе абзаца, новый раздел по возможности начинает новую часть. Каждая
следующая часть получает понятия и суждения предыдущих, так что словарь у
статьи один, а шаг может ссылаться на суждение из другой части.

Размер части меняет ключ `--part-size <знаков>`. Команде разметки доступны
переменные `FLANG_ARGUE_PART` и `FLANG_ARGUE_PARTS` — номер части и их число,
а также `FLANG_ARGUE_PROMPT_FILE` и `FLANG_ARGUE_TEXT_FILE` — файлы с заданием
и с текстом части.

### Цитаты

Каждое суждение разметки несёт цитату — слова текста, из которых оно взято.
flang сравнивает цитату с текстом дословно, с точностью до пробелов и переносов
строк.

Запись с цитатой, которой в тексте нет, не останавливает проверку. Суждение и
шаги, которые на него опираются, выбрасываются, а отчёт перечисляет их в
разделе «Выброшено из разметки»:

```
- суждение [2] (строка 10 разметки): цитаты нет в тексте дословно: «Пингвин — это птица»
- шаг [3] из [1], [2] (строка 13 разметки): опирается на выброшенное суждение [2]
```

Если размечаете сами или пишете свою команду разметки, вырезайте цитаты из
текста программой, а не набирайте заново. Набранная вручную цитата расходится с
текстом в кавычке, тире или переносе слова, и суждение пропадает.

Остальные ошибки разметки останавливают проверку и называют строку:
необъявленное понятие, суждение без цитаты, ссылка на суждение, которого нет.

## Как читать отчёт

**Главный вывод** — итоговый вывод, к которому ведёт больше всего шагов. При
равенстве берётся последний в тексте. Остальные итоговые выводы названы строкой
ниже.

**Карта рассуждения.** Пометка «принято без вывода» стоит у суждения, которое
автор ни из чего не выводит. Пометка «разобрано выше» значит, что суждение уже
раскрыто в карте; так показан и порочный круг. Жирная пометка «ниже есть шаг,
который не следует» стоит у итогового вывода, под которым хотя бы один шаг не
доказан.

**Провалы и допущения.** Строгий шаг, которому не хватает одной посылки, идёт
в «Допущения автора»: чаще всего автор считает эту посылку очевидной. Отчёт
называет её и говорит, какие выводы останутся без опоры, если она неверна. В
«Провалы» попадает то, что одной посылкой не чинится: противоречие, круг,
подмена термина, вывод без посылок. Решать, очевидна ли недостающая посылка,
приходится читателю: flang этого не знает.

Шаг с пометкой «допущение» тоже идёт в «Допущения автора». Так разметка
отмечает вывод, который держится на общем правиле, не названном в тексте:
«трава мокрая, следовательно, шёл дождь». Если ядро такой шаг доказало,
неназванного правила нет, и в допущения он не попадает.

**Не доказательство.** Здесь стоят шаги, которые сама разметка назвала не
строгим выводом. Для каждого отчёт говорит, почему шаг такого рода не
доказывает вывод и каких посылок ему обычно не хватает. Например, для шага с
пометкой «выборка»:

```
- **Что не так:** шаг помечен в разметке как «выборка»: то, что верно для обследованных, верно для остальных, только если выборка на них похожа.
- **Что нужно шагу этого рода:** посылки, что выборка представляет всех: как она набрана и чем остальные на неё похожи.
```

**Кем прочитано.** Раздел отвечает, кто записал смысл каждого предложения.
Если у суждения в разметке есть строка `источник:`, пометка берётся из неё:

| Пометка | Что она значит |
| --- | --- |
| грамматикой | суждение записала грамматика flang, и его оставили как есть |
| грамматикой, вариант 2 | грамматика дала несколько прочтений, выбрано второе |
| моделью | суждение написано или переписано тем, кто правил разметку |

Раздел начинается счётом суждений по источнику:

```
Источник суждений: грамматика — 1; грамматика, другой вариант — 1; модель — 1; не назван — 18.
```

Если строки `источник:` у суждения нет, пометку даёт сравнение с грамматикой.
У предложения тогда одна из пометок:

| Пометка | Что она значит |
| --- | --- |
| только моделью | смысл предложения записан в разметке, грамматика flang его не подтвердила |
| моделью, подтверждено грамматикой | грамматика flang разобрала цитату и получила ту же форму, что в разметке |
| моделью; грамматика прочла иначе | грамматика разобрала цитату, но форма вышла другой; отчёт показывает обе |
| моделью; имена понятий не сопоставлены | формы совпадают, но понятия названы по-разному и flang не смог их сопоставить |
| никем | предложения нет в разметке |

Слово «модель» здесь значит того, кто писал разметку, будь то программа или
человек. Когда есть и строка `источник:`, и ответ сравнения, пометка несёт
оба: «моделью; грамматика подтвердила».

Сравнение с грамматикой делает отдельная часть flang. Когда она есть в вашем
клоне, раздел начинается со счёта по суждениям: сколько подтверждено, сколько
расходится, сколько грамматика не прочла и почему. Грамматика flang читает
пока немногое: на научной прозе почти все суждения остаются с пометкой «только
моделью», и отчёт называет причину для каждого — чаще всего незнакомое слово.
Когда этой части нет, раздел прямо говорит, что сравнение с грамматикой не подключено.

**Вне текста статьи.** Список литературы, резюме на другом языке, заголовки,
строки таблиц и обрывки распознавания в счёт предложений и в покрытие не
входят. Раздел показывает, сколько их и какие именно.

Слова отчёта о ядре:

| Слова | Что стоит за ними |
| --- | --- |
| следует (доказано ядром) | ядро приняло доказательство шага для всех случаев |
| не следует (пример против подтверждён ядром) | ядро вычислило посылки и вывод на найденном случае: посылки верны, вывод ложен |
| ядро не решило | шаг вышел за один из пределов проверки либо ядро проверку не приняло; причину называет раздел «Ядро не решило» |

## Отчёт для программ

Ключ `--json` пишет тот же отчёт в JSON, в файл `статья.argue.json`:

```bash
flang run-script argue:article -- docs/examples/argue/service.txt --json --out report.json
```

Поля верхнего уровня: `summary`, `theses`, `steps`, `failures`,
`implied_premise_steps`, `map`, `assumptions`, `glossary`, `readers`,
`dropped`, `skipped`, `tables`, `outside_article_text`, `uncovered_markers`,
`boundary`. Шаг выглядит так:

```json
{"conclusion": "6", "premises": ["5"], "kind": "авторитет", "verdict": "fails", "missing_premise": "если пользователи_называют_надёжным(Архив), то отвечает_на_каждый(Архив)", "in_circle": false, "rests_on_weak_steps": "[6] из [5]"}
```

Вердикты шага: `follows`, `fails`, `clash` (посылки противоречат друг другу),
`none` (посылок нет), `undecided`. У суждения в списке `theses` есть поле
`origin` — его строка `источник:`, у предложения в `readers.sentences` — поле
`origins`.

## Время и пределы

Маленький пример выше занимает меньше минуты: шаги проверяются около
пятнадцати секунд, ещё полминуты идёт сравнение с грамматикой. Настоящая статья
дольше: на двенадцати научных статьях объёмом от 7 до 25 тысяч знаков проверка
готовой разметки заняла от 35 секунд до четырёх с небольшим минут, обычно около
минуты с четвертью. Отчёт о такой статье занимает от 30 до 120 КБ.

Разметка моделью идёт сверх этого. Статья в 7 тысяч знаков размечалась
командой `claude -p` около полуминуты, статья в 25 тысяч знаков, три части, —
около пяти минут.

Время проверки шагов стоит и в самом отчёте, в разделе «Коротко», а полное
время команда выводит последней строкой.

Команда следит за каждым шагом. Если проверка одного шага или поиск
противоречий для одного суждения идёт дольше пяти минут либо упирается в
предел памяти, это место пропускается, а проверка продолжается. Отчёт
перечисляет пропущенное в разделе «Не досчитано» и не выдаёт его за
проверенное.

| Переменная среды | Что задаёт | По умолчанию |
| --- | --- | --- |
| `FLANG_ARGUE_UNIT_SECONDS` | время на один шаг или одно суждение | 300 |
| `FLANG_ARGUE_MEMORY` | память проверки | 16G |
| `FLANG_ARGUE_KERNEL_SECONDS` | время ядра на одно доказательство | 600 |

Ключ `--jobs <число>` задаёт, сколько доказательств ядро проверяет
одновременно; по умолчанию восемь.

## Формат разметки

| Строка | Смысл |
| --- | --- |
| `понятие кит(x): пояснение` | свойство предмета |
| `понятие старше(x, y): пояснение` | отношение двух предметов |
| `понятие дождь: пояснение` | высказывание целиком |
| `имя Сократ, Моби` | названные в тексте предметы |
| `величина спрос, запас: пояснение` | числа, которые сравниваются |
| `неотрицательная величина доля: пояснение` | число, которое не бывает меньше нуля |
| `[N] форма` | суждение с номером |
| `цитата: слова текста` | откуда суждение взято; обязательна |
| вторая строка `цитата:` | суждение собрано из двух мест текста; с текстом сравнивается каждая цитата |
| `сила: как правило` | суждение сказано с оговоркой; из такой посылки твёрдый вывод не следует |
| `источник: грамматика` | кто записал суждение: `грамматика`, `грамматика, вариант 2` или `модель` |
| `вариант: другая форма` | другое прочтение той же цитаты; на проверку не влияет |
| `почему: несколько слов` | почему выбрана эта форма; на проверку не влияет |
| `термин: слово = смысл` | в каком смысле слово стоит в этой цитате |
| `определение: слово = смысл` | то же для предложения, где автор слово определяет |
| `вывод [N] из [M], [K]` | шаг рассуждения |
| `вывод [N] из [M]: корреляция` | шаг с пометкой рода |
| `не суждение: слова текста` | предложение со словом вывода, которое ничего не утверждает; не судится |
| `# текст` | комментарий |

Логическая форма пишется словами: `не`, `и`, `или`, `если …, то …`, скобки,
`все x:` и `есть x:`. Примеры: `все x: если кит(x), то не рыба(x)`,
`есть x: кит(x) и белый(x)`, `если дождь, то мокро`, `старше(Анна, Борис)`.
Кванторы стоят в начале формы, и вид квантора может смениться один раз:
`все x: есть y: если студент(x), то наставник(x, y)`.

Числа и объявленные величины сравниваются знаками `<`, `<=`, `=`, `!=`, `>`,
`>=` или словами `меньше`, `не больше`, `равно`, `не равно`, `больше`,
`не меньше`: `спрос < запас`, `доля >= 50 %`,
`выручка_2021 = 1,12 * выручка_2020`. Величины можно складывать, вычитать,
умножать и делить на число.

Форма `причина: если курит, то болеет` говорит, что одно вызывает другое. Как
посылка она работает как обычное условие. Как вывод она следует только из
суждения о той же причине: из того, что два признака встречаются вместе,
причина не выводится.

Род шага пишется после двоеточия в строке `вывод`. Шаг без пометки заявлен как
строгий вывод.

| Род | Что это за шаг |
| --- | --- |
| `обобщение` | от примеров ко всем случаям |
| `корреляция` | от совпадения двух признаков к причине |
| `авторитет` | от чьего-то мнения к самому утверждению |
| `определение` | вывод по определению слова; судится как строгий |
| `значимость` | от статистической значимости к эффекту |
| `выборка` | от обследованных ко всем |
| `правдоподобие` | вывод или посылка сказаны с оговоркой: «вероятно», «как правило» |
| `допущение` | вывод держится на общем правиле, которого в тексте нет |
| `объяснение` | автор объясняет, почему что-то произошло, а не доказывает; не судится |

## Что ядро проверяет и чего не проверяет

Проверяет:

- формы без кванторов над высказываниями и над названными предметами;
- формы с кванторами в начале: одного вида (`все x, y: …`, `есть x: …`) и с
  одной сменой вида (`все x: есть y: …`, `есть y: все x: …`);
- понятия с одним местом, с двумя и больше;
- сравнения чисел и объявленных величин со сложением, вычитанием, умножением
  и делением на число;
- крупный шаг: flang делит его доказательство на части по два–три простых
  высказывания, и ядро проверяет каждую часть.

Не проверяет:

- шаг, в котором после подстановки предметов больше 40 простых высказываний;
- шаг, где подстановка предметов даёт больше 600 сочетаний;
- шаг со сравнениями, где больше трёх величин или больше четырёх разных
  сравнений;
- форму, где вид квантора меняется больше одного раза, и сравнение, где одна
  величина умножена на другую: разметка с ними отклоняется, сообщение называет
  строку;
- истинность посылок: проверяется только связь между посылками и выводом;
- противоречие между тремя и более суждениями, если никакие два из них не
  противоречат друг другу и они не стоят посылками одного шага.

Шаг сверх одного из первых трёх пределов получает ответ «ядро не решило», а
раздел «Ядро не решило» называет причину:

```
- [20] из [17], [18], [19]: предел: доказательство шага на 3 простых высказываний не делится на части, посильные ядру.
```

Ответов у шага три, и каждый чем-то подтверждён. «Следует» — ядро приняло
каждую часть доказательства. «Не следует» — найден случай, на котором ядро
вычислило посылки верными, а вывод ложным. «Ядро не решило» — нет ни того, ни
другого. Доказательство и пример против ищутся отдельно, поэтому из неудачи
одного поиска ответ «следует» или «не следует» не получается.

Квантор flang раскрывает сам: подставляет вместо переменной каждый предмет,
который назван в шаге. Ядро получает формулу без кванторов. В форме со сменой
вида квантора бывает, что названных предметов не хватает ни для
доказательства, ни для примера против; тогда ответ — «ядро не решило».

## Чего проверка не обещает

- **Правдивость посылок не проверяется.** flang проверяет связь между посылками и
  выводом. Ложная посылка, из которой вывод следует, даёт вердикт «следует».
- **Разметка может исказить смысл.** Логическую форму предложения пишет модель
  или человек. flang проверяет цитату, но не то, верно ли форма передаёт её
  смысл. Цитата стоит рядом с формой в отчёте, чтобы это мог проверить читатель.
- **Не обещано, что найдены все ошибки рассуждения.** Гарантируется другое: каждый размеченный
  шаг проверен ядром или назван непроверенным, а каждое предложение, которого
  разметка не коснулась, названо в разделе «Кем прочитано».
- **Главный вывод и главное допущение выбраны по счёту шагов**, а не по смыслу
  статьи. Автор мог считать главным другое.

## Строгая проверка готовой разметки

Команда `flang run-script argue -- текст.txt` проверяет текст с готовой
разметкой и ничего не прощает: первая же цитата, которой нет в тексте,
останавливает проверку. Она удобна, когда разметку пишут и правят руками. Её
отчёт короче: в нём нет карты, допущений и словаря.
