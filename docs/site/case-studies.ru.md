# Разбор: 82 задачи с leetcode

Каталог `flang/examples/leetcode/` — 82 файла, 7 609 строк. Это не написанный
для сайта пример, а код в дереве: его можно прогнать одной командой.

## Прогоните сами

```bash
flang test flang/examples/leetcode
```

```
корпус «flang/examples/leetcode»: файлов 82, взято 82, отказано 0, примеров 804
(своих 804), на чужих примерах 0, потеряно своих 0, прошло 804, не прошло 0,
за 11956 мс
```

Код возврата 0. Двенадцать секунд на 82 задачи.

## Что здесь считано

| | |
| --- | --- |
| функций | 300 |
| из них тотальных | 298 |
| обычных | 2 |
| исполняемых примеров | 804 |
| постусловий (`обеспечивает`) | 2 |

## Что доказано

298 функций из 300 несут доказанное завершение. Это не «примеры прошли»:
компилятор отказался бы собрать файл, если бы не показал, что рекурсия
кончается. Для задач вроде «поиск в повёрнутом отсортированном массиве» или
«сбор дождевой воды» бесконечный цикл закрыт до запуска программы.

Две обычные функции названы поимённо: `«Шаг счастья»` и `«Счастливое»` из задачи
202. Они завершаются — последовательность сумм квадратов цифр попадает в цикл, —
но структурным спуском это не показать, и файл честно пишет `функция`, а не
`тотальная функция`.

## Что не доказано

Постусловий на все 82 задачи — два, оба в задаче 13, римские цифры в число:

```flang
  обеспечивает «значение цифры неотрицательно» результат не меньше 0
  обеспечивает «значение цифры не больше тысячи» результат не больше 1000
```

Значит, для 298 функций доказано, что они **останавливаются**, и почти ни для
одной — что они считают **правильно**. Правильность здесь несут 804 примера, а
пример — утверждение об одном входе.

Разрыв между «доказано» и «правильно» — это спецификация. Её можно написать:
`обеспечивает` принимает любая функция, и ядро попробует доказать. Как это
делается — [Требования, которые доказываются](fspec.html).
