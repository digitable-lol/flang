# Справочник команд

У двоичного `flang` четырнадцать команд. Для каждой здесь сказано, когда её
запускать, как вызывать, какие у неё ключи, что она печатает и с каким кодом
возврата выходит. Всё это сверяется с `flang --help` и `flang <команда> --help`;
каждый вывод ниже снят с нынешнего двоичного.

## Шпаргалка

| Команда | Когда запускать | Типичный вызов |
| --- | --- | --- |
| `check` | после каждой правки: разбор, типы, завершаемость, prover, unit-тесты | `flang check привет.flang` |
| `test` | чтобы прогнать только unit-тесты (`пример`) | `flang test привет.flang` |
| `run` | чтобы вычислить одну функцию и напечатать значение | `flang run привет.flang --function «Удвоить» --args '{"н":21}'` |
| `emit` | чтобы сгенерировать код на одном из {{цели.изСловом}} целевых языков | `flang emit привет.flang --target js --file привет.js` |
| `ast` | чтобы увидеть разобранную программу деревом JSON | `flang ast привет.flang --pretty` |
| `tokens` | чтобы увидеть, чем лексер счёл каждое слово | `flang tokens привет.flang` |
| `lint` | чтобы строки не были слишком длинными, а ветвления — слишком глубокими, по пределам из `.flangrc` | `flang lint scripts/` |
| `facts` | чтобы проверить утверждения на данных из JSON-файла | `flang facts привет.flang --facts факты.json --claims '["…"]'` |
| `io` | чтобы запустить программу, которая читает файлы, запускает процессы или ходит в сеть | `flang io план.flang --pretty` |
| `lock` | чтобы записать lock-файл, в котором лежат сами зависимости | `flang lock привет.flang > flang.lock` |
| `package` | чтобы собрать пакет: lock плюс имя, версия и список доказанного | `flang package привет.flang > привет.flang-package` |
| `new` | чтобы начать новый пакет | `flang new проба` |
| `run-script` | чтобы запустить короткую команду проекта из `.flangrc` | `flang run-script site:build` |
| `repl` | чтобы пробовать выражения интерактивно | `flang repl привет.flang` |
| `lsp` | запускает редактор: языковой сервер | `flang lsp --stdio` |

Ещё: `flang --help`, `flang --version`, `flang <команда> --help`;
`flang --machine [<файл>]` печатает, насколько быстра эта машина (шагов
вычисления в секунду); `flang --mcp-mode` — сервер для ИИ-помощника по
стандартному вводу и выводу (`flang --mcp-mode --help` — как его подключить).

Три ключа годятся при любой команде и ограничивают сам двоичный на этот
прогон:

| Ключ | Что задаёт |
| --- | --- |
| `--depth-limit N` (`--предел-глубины`) | предел глубины вызовов |
| `--step-limit N` (`--предел-шагов`) | предел шагов; исчерпание — `FLANG_RECURSION_LIMIT` с числом |
| `--memory-limit N` (`--предел-памяти`) | предел памяти, байтами или с буквой K, M, G, T; `0` — без предела. У `check`, `test` и `run` по умолчанию три четверти памяти машины. На пределе прогон останавливается с кодом `5` и называет функцию и число шагов |

Долгие прогоны печатают в поток ошибок строку хода `шагов N из M …`.

Примеры ниже идут на этом файле, `привет.flang`:

```flang
module «Привет»

total function «Удвоить»
  accepts н: number
  returns number
  example «Двадцать один»
    given н equals 21
    expected 42
  н plus н
```

## Коды возврата

Коды значат одно и то же во всех командах.

| Код | Что значит |
| --- | --- |
| `0` | сделано, замечаний нет |
| `1` | программа не прошла проверку; у `facts` и `io` — программа сама ответила «нет» |
| `2` | кривой вызов: неизвестный ключ, неверное значение, нет такого файла |
| `3` | сделано, но проверено не всё, и вывод называет, что именно. А ещё: `run` и `io` отказываются запускать программу, гарантии которой не доказаны |
| `4` | часть проверок не запускалась вовсе (`check --fast`) |
| `5` | прогон остановлен на пределе памяти |

В скрипте сборки различайте `1` и `3`: `1` — работа не сделана, `3` — сделана,
но поручиться за неё целиком нельзя.

## Входной файл: четыре расширения

Файл программы может кончаться на `.flang`, `.fp`, `.фп` или `.фланг`; все
четыре равноправны. `.flang` — основное; `.fp` избавляет от переключения
раскладки; `.фп` и `.фланг` позволяют русскому имени файла остаться в одном
алфавите. Команды берут файл по пути, так что годится и любое другое имя.

`flang test` различает один файл и набор файлов по доводу, см. [test](#test).
Файл с любым из четырёх расширений берётся как один файл:

```bash
$ flang test привет.фп
привет.фп: примеров 1, прошло 1, не прошло 0
```

## check

Проверяет программу: разбор, связывание имён, типы, завершаемость, prover и
unit-тесты. Запускайте после каждой правки.

```bash
flang check <файл.flang> [--proof [--json] [--strict] [--record <файл>]]
                          [--fast] [--step-limit N] [--depth-limit N]
```

У каждого ключа есть и кириллическое написание, оно в скобках.

| Ключ | Что делает |
| --- | --- |
| `--proof` | печатает отчёт о доказательствах: у каждой функции — чем доказано завершение, у каждого постусловия — доказано ли оно, проверено только на примерах или не доказано. Постусловие без доказательства и без примеров даёт код `3` |
| `--json` | вместе с `--proof`: тот же отчёт в JSON |
| `--strict` (`--строго`) | вместе с `--proof`: код `0` только когда доказана каждая гарантия. Для CI. Подробно ниже |
| `--record <файл>` (`--записать`) | вместе с `--proof`: записать само доказательство в файл, чтобы его перепроверила независимая программа `flang/proof/checker/checker.c` |
| `--fast` (`--быстро`) | только имена, типы, полнота pattern matching и завершаемость. Prover и unit-тесты не запускаются, вывод говорит об этом, код возврата `4`. Вместе с `--proof` нельзя |
| `--step-limit N` (`--предел-шагов`) | поднять предел шагов на этот прогон. Нужен для `--proof --json` на очень больших файлах. Ключа `--max-steps` у `check` нет: это кривой вызов, код `2` |
| `--depth-limit N` (`--предел-глубины`) | поднять предел глубины вызовов на этот прогон. Не путать с `--max-depth` у `emit`: тот записывается в сгенерированную программу |
| `--memory-limit N` (`--предел-памяти`) | предел памяти, см. выше; на пределе код `5` |

Коды: `0` — замечаний нет; `1` — программа не прошла; `2` — в программе есть
объявления, которые двоичный не проверяет вовсе (категорные объявления,
процессы, надзор), и он их называет; `3` — с `--proof` гарантия не доказана (с
`--strict` — всё, что не «доказано всё»); `4` — с `--fast`.

```bash
$ flang check привет.flang
модуль «Привет»: функций 1, из них с доказанным завершением 1; типов 0
привет.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Первая строка считает функции и сколько из них с доказанным завершением. Вторая
говорит, что прошли все проверки: разбор, типы, завершаемость, prover («ядро»)
и unit-тесты.

Когда проверка не прошла, вывод называет код ошибки, строку и столбец. Здесь
`плохо.flang` объявляет `returns string`, а тело даёт число:

```bash
$ flang check плохо.flang
модуль «Плохо»: функций 1, из них с доказанным завершением 1; типов 0
FLANG_TYPE в файле плохо.flang, строка 6, столбец 5: функция «Удвоить» объявлена как строка, а тело даёт число
плохо.flang: не проверено — замечаний 1
$ echo $?
1
```

Каждый код `FLANG_…` и как его чинить — в [Справочнике отказов](diagnostics.html).

```bash
$ flang check привет.flang --fast
модуль «Привет»: функций 1, из них с доказанным завершением 1; типов 0
ПРОВЕРЕНО: связывание имён и повторы объявлений, типы, исчерпываемость разбора,
           завершаемость (в том числе взаимная рекурсия по компонентам), процессы.
НЕ СМОТРЕЛИ НА ЭТОМ ПРОГОНЕ: ядро доказательств — обязательств 0, теорем 0;
           законы категории на сетке; прогон примеров — примеров 1.
           И это не «нарушений нет»: про них не сказано ничего — ни хорошего, ни плохого.
           «Не смотрели» — не то же, что «объявлено, доказательства нет»: второе
           значит «смотрели и не смогли», а здесь вопроса не задавали вовсе.
           Спросить всё — та же команда без «--быстро».
привет.flang: часть проверок НЕ ЗАПУСКАЛАСЬ — код возврата 4, а не 0
```

### `--strict`: свой код возврата на каждый итог

Без `--strict` команда `check --proof` выходит с `0` и когда доказано всё, и
когда часть гарантий проверена только на ваших примерах. Слова в выводе разные,
но скрипт сборки читает код возврата. С `--strict` у каждого итога свой код:

| Итог | Код | Когда |
| --- | --- | --- |
| `ДОКАЗАНО` | `0` | гарантия есть хотя бы одна, и доказана каждая |
| `ОПРОВЕРГНУТО` | `1` | найден контрпример |
| `НЕ УДАЛОСЬ ДОКАЗАТЬ` | `3` | контрпримера нет, но доказано не всё; вывод называет, что |
| `НЕ ПОДДЕРЖИВАЕТСЯ` | `2` | программа объявляет то, что двоичный не проверяет, и вывод это называет |

У кода `3` три причины, их различают слова после него:
`ОПОРА НЕ СУДИЛАСЬ` — гарантия проверена только на примерах;
`ОБЪЯВЛЕНО, НЕ ДОКАЗАНО` — у гарантии нет ни доказательства, ни примеров;
`ПРОВЕРЕНО ВПУСТУЮ` — гарантий нет вовсе. Когда причин несколько, называется
самая серьёзная: контрпример важнее отсутствия доказательства, а отсутствие
доказательства важнее «только примеров».

Файл без гарантий по умолчанию проходит, а под `--strict` — нет, потому что
«доказывать нечего» — не доказательство:

```bash
$ flang check привет.flang --proof --strict | tail -2
привет.flang: НЕ УДАЛОСЬ ДОКАЗАТЬ — ПРОВЕРЕНО ВПУСТУЮ, ОБЯЗАТЕЛЬСТВ НЕТ ВОВСЕ — утверждений 0: доказано 0, условно 0, сетка 0, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 3
  ничего: ни одно утверждение не назвало ни правила, ни шага
```

**Прошедшие примеры — не доказательство.** Здесь постусловие ложно, а два
примера случайно проходят:

```flang
модуль «Сетка»

тотальная функция «Удвоить»
  принимает н: неотрицательное
  возвращает число
  обеспечивает «не больше ста» результат не больше 100
  пример «один»
    дано н равно 1
    ожидается 2
  пример «десять»
    дано н равно 10
    ожидается 20
  н плюс н
```

`flang check сетка.flang` и `flang check сетка.flang --proof` оба выходят с `0`;
отчёт пишет `сетка 1` — одна гарантия проверена только на примерах — и
`ПРОВЕРЕНО С ОПОРОЙ, И ОПОРА НЕ СУДИЛАСЬ`. С `--strict` код возврата `3`.
`flang run` такую программу считать отказывается (см. [run](#run)), а с
`--trust` при `н = 100` нарушает постусловие:

```bash
$ flang run сетка.flang --function «Удвоить» --args '{"н":100}' --trust
на веру: доказанность не считалась — запуск по ключу --trust
FLANG_PROPERTY: нарушено свойство «не больше ста» функции «Удвоить»
$ echo $?
1
```

`--strict` делает строгим только компилятор. Независимая программа проверки
`flang/proof/checker/checker.c` на записи доказательства, где не доказано ничего,
отвечает `НЕ ПРОВЕРЕНО — ВПУСТУЮ` с кодом `3` и без ключа.

`--strict` без `--proof` — кривой вызов, код `2`. Пробные программы на все
итоги лежат в `flang/proof/probes/strict/`; прогон —
`bootstrap/flang io flang/proof/probes/strict/run.fscript --plan Binary`.

## test

Прогоняет unit-тесты (`пример`), объявленные внутри функций. Сначала делает те
же проверки, что `check`: прошедший тест в программе с ошибкой типов ничего не
значит.

```bash
flang test <файл.flang | каталог | маска> [--no-check] [--json] [--ledger]
                                          [--max-steps N] [--max-depth N]
```

| Ключ | Что делает |
| --- | --- |
| `--no-check` | не проверять, только прогнать примеры — пока программа ещё в правке |
| `--json` | итог одной строкой JSON |
| `--ledger` | по строке на файл через табуляцию — чтобы сравнивать прогоны через `diff` |
| `--max-steps N` | предел шагов вычислителя |
| `--max-depth N` | предел глубины |
| `--memory-limit N` | предел памяти; на пределе код `5` |

Довод, который не кончается ни на одно из четырёх расширений или содержит `*`
или `?`, — это набор файлов:

```bash
flang test flang/stdlib/                весь каталог, вглубь
flang test 'docs/examples/**/*.flang'  по маске (кавычки — от оболочки)
```

Коды: `0` — взяты все файлы и прошли все примеры; `1` — пример не прошёл или
файл не взят; `2` — кривой вызов; `3` — примеры прошли, а в файле объявлены
блоки `прогон`, которых никто не исполнял.

Блок `прогон` описывает сценарий над процессами, и двоичный его не исполняет:
планировщик объявлен в `flang/self/conc.flang`, а в самом двоичном этого слоя
нет. Такой файл называется числом и отвечает кодом `3` — программа, у которой
все ожидания в блоках ложны, кодом `0` не выходит:

```bash
$ flang test flang/concurrency/examples/counter.flang
flang/concurrency/examples/counter.flang: примеров 2, прошло 2, не прошло 0
flang/concurrency/examples/counter.flang: блоков «прогон» 2, исполнено 0 — исполнить их нечем: планировщика в этом двоичном нет
```

```bash
$ flang test привет.flang
привет.flang: примеров 1, прошло 1, не прошло 0
```

Для не прошедшего примера печатаются обе стороны: ожидалось и получено.
Длинное значение обрезается на 200 знаках, и полная длина называется числом.

## run

Вычисляет одну функцию и печатает значение. Считает сам двоичный: ни
компилятор C, ни Node не нужны.

```bash
flang run <файл.flang> --function «Имя» [--args '{"н":10}'] [--max-steps N]
                       [--max-depth N] [--trust] [--unproven refuse|warn|allow]
```

| Ключ | Что делает |
| --- | --- |
| `--function «Имя»` | какую функцию вычислить. Обязателен |
| `--args '{…}'` | аргументы плоским JSON-объектом из скаляров. Списки и вложенные объекты не принимаются |
| `--max-steps N` | предел шагов вычислителя |
| `--max-depth N` | предел глубины вычисляемой программы (свой предел двоичного — `--depth-limit`) |
| `--memory-limit N` | предел памяти; на пределе код `5` |
| `--trust` (`--на-веру`) | запустить, даже если гарантии не доказаны; доказательства не проверяются вовсе, и об этом говорит отдельная строка |
| `--unproven СЛОВО` (`--недоказанное`) | что делать, когда гарантии не доказаны: `refuse` — не запускать (по умолчанию), `warn` — сказать и запустить, `allow` — то же, что `--trust`. По-русски: `отказ`, `предупреждение`, `разрешение` |

Аргументы сначала сверяются с объявленными типами: «Факториал» от −3
отвергается с `FLANG_TYPE`, а не вычисляется.

**`run` не запускает недоказанную программу.** Перед вычислением он проверяет
доказательства всего, что программа использует (а не только этого файла), и
печатает одну строку в поток ошибок: `доказано: утверждений N` (N гарантий, все
доказаны) либо `не доказано: …` — и тогда не вычисляется ничего, код `3`.

```bash
$ flang run привет.flang --function «Удвоить» --args '{"н":21}'
доказано: утверждений 0
42
```

Чтобы разрешить недоказанные программы раз и навсегда, задайте ключ `unproven`
в `.flangrc`
([Настройки](https://github.com/digitable-lol/flang/blob/main/docs/guide/settings.ru.md#что-делать-с-недоказанным)):
`unproven = warn`. Ключ командной строки старше переменной среды
`FLANG_UNPROVEN`, она старше `.flangrc`, а он — умолчания `refuse`. Строка перед
значением называет, что разрешило запуск: ключ или настройку и путь к её файлу.
Неизвестное значение — код `2` с объяснением.

## emit

Генерирует код на целевом языке. Все {{цели.словом}} целей встроены в двоичный. Каталог
из `--out` заводится сам, вместе с подкаталогами, которых требует цель.

```bash
flang emit <файл.flang> --target c|cpp|go|rust|java|js|ts|elixir|python|csharp
                        [--out каталог | --file имя] [--cli|--no-cli] [--repl]
                        [--runtime каталог] [--index-base 0|1]
                        [--max-steps N] [--max-depth N] [--no-check]
                        [--no-postconditions]
```

| Ключ | Что делает |
| --- | --- |
| `--target <цель>` | `c`, `cpp`, `go`, `rust`, `java`, `js`, `ts`, `elixir`, `python`, `csharp`. Обязателен |
| `--out каталог` | записать все файлы в каталог |
| `--file имя` | один файл на стандартный вывод |
| `--cli`, `--no-cli` | генерировать ли запускалку командной строки |
| `--repl` | сгенерировать ещё и интерактивный вход. Только цель `c` |
| `--protocol файл` (`--протокол`) | только цель `c`: записать ещё журнал перевода — во что перешла каждая конструкция и по какому правилу; его перепроверяет `flang/translation/matcher.c` |
| `--runtime каталог` | где лежат исходники рантайма цели |
| `--index-base 0\|1` | объявить базу индексов программы |
| `--max-steps N` | предел шагов, записываемый в сгенерированный код |
| `--max-depth N` | предел глубины, записываемый в сгенерированный код |
| `--no-check` | не запускать prover. Разбор, типы и завершаемость проверяются всё равно |
| `--no-postconditions` | не генерировать проверки постусловий во время работы. Доказываются они по-прежнему: ключ меняет только сгенерированный код, и его шапка об этом говорит. Предусловия, проверки завершения и пределы шагов и глубины остаются. Замеры — в `flang emit --help` |

Генерируется только проверенная программа. Перед генерацией `emit` делает те же
проверки, что `flang check`; при ошибке не пишется ни одного файла, код `1`.

### `--no-check` убирает prover и больше ничего

С `--no-check` разбор, имена, типы и завершаемость проверяются, и программа, не
прошедшая их, всё так же не генерируется. Что меняется:

- Постусловия не доказываются, поэтому ни одно нельзя убрать из
  сгенерированного кода: каждое становится проверкой во время работы. Код
  больше и медленнее, но не слабее.
- Неверные доказательства не ловятся. Прогоните `flang check`, прежде чем
  доверять результату.
- Код, сгенерированный так, нельзя класть в сборку самого компилятора: отпечаток
  сборки не сойдётся. Двоичный печатает это предупреждение после каждого
  запуска с ключом.

Сколько времени ключ экономит, зависит от файла: на одних файлах — в разы, на
других весь круг с ключом идёт дольше, потому что лишние проверки обходятся
сборке C дороже, чем prover обходится `emit`. Числа — в `flang emit --help`. На
двух самых больших модулях компилятора, `flang/self/distributed.flang` и
`flang/self/bounded.flang`, prover выбирает весь предел шагов, и сгенерировать
их можно только с этим ключом.

Коды `emit`:

| Код | Что значит |
| --- | --- |
| `0` | сгенерировано, проверено всё |
| `1` | не прошло проверку; не записано ничего |
| `2` | кривой вызов: нет такой цели, нет файла, неверное значение ключа |
| `3` | сгенерировано, но проверено не всё: двоичный не проверяет категорные объявления и процессы и называет, что пропустил |

`emit` не прогоняет unit-тесты и говорит об этом; прогоните их `flang test`.

```bash
$ flang emit привет.flang --target c --out вывод
напечатано файлов 6, байт …, в вывод
аргументы напечатанной программы по типам не проверяются: это ограничение двоичного flang, полная проверка есть в версии для Node
проверено перед печатью — разбор, типы, завершаемость и ядро доказательств.
ПРИМЕРЫ НЕ ПРОГНАНЫ: их считает вычислитель на самом языке, и на самых больших
программах он в предел шагов этого бинарника не укладывается — свяжи с ними
печать, и компилятор перестал бы печатать сам себя. Прогоните их отдельно:

$ ls вывод
Makefile  flang_cli.c  flang_runtime.c  flang_runtime.h  privet.c  privet.h
```

Вывод говорит: записано 6 файлов; сгенерированная запускалка не сверяет типы
аргументов; программа проверена перед генерацией; unit-тесты не прогнаны.
Упоминание «версии для Node» устарело — такой версии нет, и типы аргументов
сгенерированного кода не проверяет ничто. Имена файлов — имя модуля латиницей
(«Привет» → `privet.c`).

Неизвестная цель — код `2` и список целей:


## tokens

Печатает поток токенов: что прочитал лексер, до разбора. Нужна, чтобы узнать,
чем станет слово, если его написать. `grep` на это не ответит: слово в
комментарии, внутри строкового литерала или внутри имени в ёлочках ключевым
словом не становится никогда.

```bash
flang tokens <файл.flang> [--json] [--pretty]
flang tokens --keyword «фраза»
```

| Ключ | Что делает |
| --- | --- |
| `--json` | JSON с теми же ключами, что у `flang ast`: `kind`, `value`, `text`, `quoted` и `span` со строкой и столбцом |
| `--pretty` | JSON с отступами; включает `--json` сам |
| `--keyword «фраза»` | ключевое ли это слово. Фраза из нескольких слов проверяется как одна фраза. Файл с этим ключом не называют |

Отказывает там же, где лексер, — незакрытый литерал, рваный отступ — с кодом
`1`; JSON при этом печатается всё равно, с пустым `tokens` и заполненным
`diagnostics`.

```bash
$ flang tokens привет.flang | head -4
1:1	слово module
1:8	ёлочка Привет
1:16	/
3:1	слово total

$ flang tokens --keyword 'элемент или беда'
«элемент или беда» — не ключевое слово языка: одним ключевым токеном лексер это не отдаёт

$ flang tokens --keyword 'код символа'
«код символа» — ключевое слово, конструкция «charCode»
```

Каждая строка — `строка:столбец`, вид токена (`слово`, `ёлочка` — имя в
ёлочках) и его текст.

## lint

`flang lint` меряет исходники flang двумя мерами и сверяет их с пределами,
записанными в `.flangrc`:

* **длина строки** — сколько знаков в строке;
* **глубина ветвлений** — сколько `если` и `разбор` вложено друг в друга в теле
  функции.

Оба предела живут в файле настроек рядом с остальными ключами:

```
max-line-length = 120
max-conditional-depth = 2
lint = refuse
```

Ключа нет — предела нет: у проекта без этих строк находок не бывает вовсе.

### Вызов

```bash
flang lint [<путь>…] [--max-line-length N] [--max-conditional-depth N]
           [--warn | --refuse] [--tsv]
```

Путь — файл или каталог. Каталог обходится целиком, кроме имён, начинающихся с
точки; берутся файлы с пятью расширениями исходников: `.flang`, `.fscript`,
`.fp`, `.фп`, `.фланг`. Названный файл, который не исходник flang, пропускается, и
об этом сказано. Без пути обходится рабочий каталог.

Ключ командной строки старше `.flangrc` проекта, а файл проекта старше
`.flangrc` в домашнем каталоге.

```
$ flang lint docs/examples/guide/ladder-before.flang docs/examples/guide/walk-tree.flang
docs/examples/guide/ladder-before.flang:17: глубина ветвлений 3 > 2 в «Цена доставки» (max-conditional-depth)
docs/examples/guide/walk-tree.flang:15: длина строки 206 > 120 (max-line-length)
flang lint: файлов 2; max-line-length 120: 1; max-conditional-depth 2: 1; не разобрано 0
```

Находка называет файл, строку, измеренное значение, предел и ключ. Последняя
строка уходит в поток ошибок и считает файлы и находки.

| Код | Что значит |
| --- | --- |
| `0` | ничего сверх пределов, или `lint = warn` |
| `1` | находки есть, и `lint = refuse` |
| `2` | плохой вызов: незнакомый ключ, несуществующий путь, негодное значение в `.flangrc` |
| `3` | сверх пределов ничего, но часть файлов не разобралась, и глубина в них не измерена |

`--tsv` печатает по находке на строку, поля через табуляцию, без итоговой строки:

```
length	<путь>	<строка>	<длина>	<предел>
depth	<путь>	<строка>	<глубина>	<предел>	<функция>	<первая строка>	<последняя строка>
unparsed	<путь>
skipped	<путь>
```

### Что считается

**Длина** считается в знаках, а не в байтах: `«Сумма»` — семь знаков. Перевод
строки не считается, табуляция — один знак. Длинный строковый литерал — тоже
длинная строка.

**Глубина** меряется по дереву разбора тела функции, а не по отступам. Каждое
`если` и каждый `разбор` на пути от тела до узла прибавляет уровень, где бы он ни
стоял: в условии, в ветви, в доводе вызова, в значении `пусть`. Глубина функции —
самый глубокий такой путь, и находка указывает на строку самого глубокого
ветвления.

```flang
если а
  то 1
  иначе если б
    то 2
    иначе 3
```

Это глубина 2: `если` в ветви `иначе` другого `если` стоит уровнем глубже.
Лестница из пяти таких ветвей — глубина 5. Мелким код остаётся от списка правил и
одного `разбор`, а не от лестницы.

`или` и `и притом` для линтера не ветвления, хотя дерево разбора пишет их как
`если`. Примеры, `обеспечивает`, `требует` и теоремы не меряются: только тело.

### Где грамматика даёт перенести строку

Строка переносится только там, где грамматика позволяет продолжить:

* внутри списка — после `[` и после запятой;
* внутри скобок — перед `иначе`;
* на уровне утверждения — `если … то … иначе …` тремя строками.

Запись, вариант с полями и цепочка вызовов не переносятся: перевод строки внутри
них заканчивает выражение. Такую строку укорачивают, назвав её часть через
`пусть` или маленькой функцией.

## facts

Проверяет утверждения на данных. Утверждение имеет вид «слева оператор справа»;
слева — факт, поле факта или функция от фактов, справа — то же или литерал.

```bash
flang facts <файл.flang> --claims '["…"]' [--facts факты.json] [--steps N] [--pretty]
```

| Ключ | Что делает |
| --- | --- |
| `--claims '[…]'` | что проверять, JSON-массивом строк. Обязателен |
| `--facts файл` | факты JSON-объектом. Без ключа фактов нет |
| `--steps N` | предел шагов. По умолчанию 10000 |
| `--pretty` | JSON с отступами |

Коды: `0` — подтверждено; `1` — **опровергнуто** (результат всё равно уходит на
стандартный вывод, а код нужен, чтобы упал CI); `2` — кривой вызов: нет файла,
не разобран JSON, не подключились импорты.

В утверждении можно вызывать только функции с доказанным завершением; любая
другая отвергается до вычисления.

```bash
$ cat факты.json
{"н": 21}

$ flang facts привет.flang --facts факты.json --claims '["«Удвоить» от н равно 42"]' --pretty | head -7
{
  "ok": true,
  "results": [
    {
      "claim": "«Удвоить» от н равно 42",
      "holds": true,
      "why": "«Удвоить» от факта «н» = 42; требование «равно 42» выполнено",
```

## io

Запускает `план`: единственный способ, которым программа на flang работает с
файлами, процессами, сетью или терминалом. Сама программа этого не делает:
каждый шаг возвращает команду как данные («запиши этот файл»), рантайм её
выполняет и вызывает программу снова с ответом. Поэтому все функции плана
остаются чистыми и тотальными, а их unit-тестам не нужны ни файлы, ни сеть.

```bash
flang io <файл.flang> [--plan 'Имя'] [--max-orders N] [--seed N] [--in-dir]
                      [--max-steps N] [--timeout N] [--pretty] [--trust]
                      [--unproven refuse|warn|allow] [-- довод…]
```

| Ключ | Что делает |
| --- | --- |
| `--plan 'Имя'` | какой план запустить, если их в файле несколько |
| `--max-orders N` | предел команд за прогон. По умолчанию 10000 |
| `--max-steps N` | предел шагов на один шаг плана |
| `--timeout N` | сколько процесс, запущенный «Запустить процесс», может молчать, в миллисекундах, от его последнего байта в stdout или stderr. По умолчанию 30000. Дольше — рантайм его убивает и отвечает «Сбой» с `FLANG_IO_TIMEOUT`. `0` или не число — кривой вызов, код `2` |
| `--seed N` | зерно случайности: прогон становится повторимым |
| `--in-dir` | запретить пути за пределами каталога входного файла |
| `--pretty` | JSON с отступами |
| `--trust` (`--на-веру`) | запустить план с недоказанными гарантиями; доказательства не проверяются, и об этом говорит отдельная строка |
| `--unproven СЛОВО` (`--недоказанное`) | `refuse` (по умолчанию), `warn`, `allow`; раз и навсегда — ключ `unproven` в `.flangrc` |
| `--` | всё после него уходит плану, а не `flang io`. План получает эти доводы командой «Прочитать доводы» — списком строк, по порядку |

Как и `run`, `io` сначала проверяет доказательства и печатает одну строку в
поток ошибок; план с недоказанными гарантиями не запускается, код `3`.

**Имя плана пишется без ёлочек, а имя с пробелом — в кавычках оболочки.** В
исходнике имена пишутся в ёлочках, но `--plan` берёт имя ровно как набрано,
вместе с ёлочками:

```bash
$ flang io scripts/shortcut-collector.fscript --plan «Целость»
доказано: утверждений 9
{"error":"не найден план ««Целость»»","diagnostics":[{"code":"FLANG_UNKNOWN_PLAN","message":"не найден план ««Целость»»","severity":"error"}]}
$ echo $?
3
$ flang io scripts/shortcut-collector.fscript --plan Целость
доказано: утверждений 9
{"plan":"Целость","result":"коротких команд 150; …
$ echo $?
0
```

Без кавычек оболочки имя из двух слов оболочка разбивает на два довода:

```bash
$ flang io flang/scripts/kernel-forgeries.fscript --plan «Аксиом ноль»
flang io: непонятный ключ «ноль»»
$ echo $?
2
$ flang io flang/scripts/kernel-forgeries.fscript --plan 'Аксиом ноль' --trust
на веру: доказанность не считалась — запуск по ключу --trust
{"plan":"Аксиом ноль","result":"подделки отвергнуты: 36 файлов каталога … аксиом ноль, нарушений 0", …
$ echo $?
0
```

Сама справка `flang io --help` пишет `--plan «Имя»`; там ёлочки только
показывают, куда ставить имя.

Права отнимаются по одному: `--no-read`, `--no-write`, `--no-net`,
`--no-clock`, `--no-random`, `--no-spawn`, `--no-env`, `--no-args`,
`--no-screen`. По умолчанию можно всё: запуская программу через `flang io`, вы
соглашаетесь с тем, что она делает.

Ключа `--args` у `io` нет: план начинается со своей функции `начинает с`, а не
с аргументов. Данные передавайте после `--`.

```bash
$ flang io docs/examples/crypto/revocation.flang --args '{}'
flang io: непонятный ключ «--args»
$ echo $?
2
```

Коды: `0` — план дошёл до конца; `1` — программа сдалась сама («Провал»): нашла
проблему и назвала её; `2` — кривой вызов; `3` — сломался инструмент, или
программа ответила «Не проверено» (проверить то, о чём просили, ей было нечем),
или план не доказан, а ни `--trust`, ни настройка `unproven` его не разрешили.

Пример плана, `план.flang`, записывает один файл:

```flang
модуль «План»

тип «Ход»
  вариант «Пишем»
  вариант «Ждём запись»

план «Записать привет»
  состояние «Ход»
  начинает с «Начало»
  обрабатывает «Дальше»

тотальная функция «Начало»
  возвращает «Ход»
  пример «план начинается с записи»
    ожидается вариант «Пишем»
  вариант «Пишем»

тотальная функция «После записи»
  принимает отклик: «Отклик»
  возвращает «Продолжение»
  пример «записано шесть байт»
    дано отклик равно вариант «Записано» с сколько равным 6
    ожидается вариант «Конец работы» с значение равным 6
  разбор отклик
    случай вариант «Записано» с сколько как сколько
      то вариант «Конец работы» с значение равным сколько
    случай любое
      то вариант «Провал» с код равным "FLANG_IO_ORDER" и сообщение равным "ждали подтверждение записи"

тотальная функция «Дальше»
  принимает ход: «Ход», отклик: «Отклик»
  возвращает «Продолжение»
  пример «первым делом пишется файл»
    дано ход равно вариант «Пишем»
    дано отклик равно вариант «Пока ничего»
    ожидается вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант «Ждём запись»)
  разбор ход
    случай вариант «Пишем»
      то вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным "привет.txt" и содержимое равным "привет") и потом равным (вариант «Ждём запись»)
    случай вариант «Ждём запись»
      то «После записи» от отклик
```

Вывод — результат плана и журнал: каждая команда («поручение») с ответом
рантайма («отклик»):

```bash
$ flang io план.flang --pretty
доказано: утверждений 0
{
  "plan": "Записать привет",
  "result": 6,
  "orders": 1,
  "log": [
    {
      "поручение": {
        "variant": "Записать файл",
        "fields": {
          "путь": "привет.txt",
          "содержимое": "привет"
        }
      },
      "отклик": {
        "variant": "Записано",
        "fields": {
          "сколько": 6
        }
      }
    }
  ]
}
```

Отнимите право — и план получит отказ как ответ и сдастся с кодом `1`:

```bash
$ flang io план.flang --no-write
доказано: утверждений 0
{"error":"ждали подтверждение записи","diagnostics":[{"code":"FLANG_IO_ORDER","message":"ждали подтверждение записи","severity":"error","span":{"line":7,"column":1}}]}
$ echo $?
1
```

**Терминал.** Экран — управляющий терминал (`/dev/tty`), и место у него одно,
«экран»; любое другое имя — `FLANG_IO_PLACE`. «Показать» рисует кадр целиком
(очистка, потом текст) в терминале, а не в stdout — в stdout идёт результат
плана. На первом «Показать» рантайм переходит на запасной экран терминала и
прячет курсор, а по окончании прогона возвращает оба. «Ждать событие» ждёт
клавишу не дольше «срока» миллисекунд (0 или без срока — без предела): клавиша
даёт «Случилось» с «откуда» равным «клавиатура», истёкший срок — «Срок вышел».
Имена клавиш: ввод, пробел, таб, возврат, выход, вверх, вниз, влево, вправо;
прочие приходят самим знаком. Ctrl-C по-прежнему останавливает программу.
«Размер экрана» отдаёт ширину и высоту в знаках. Без терминала (вывод в трубу,
CI, nohup) эти команды отвечают `FLANG_IO_NO_SCREEN`; с `--no-screen` —
`FLANG_IO_DENIED`.

**HTTPS.** Команда «Запросить» поддерживает `https`, но через внешний `curl`:
своего TLS у двоичного нет. Без `curl` ответ — `FLANG_IO_NO_TLS`; `--no-spawn`
запрещает и `https` (`FLANG_IO_DENIED`). Сертификат проверяет `curl` (срок,
цепочка, имя узла); отзыв сертификата (OCSP, CRL) не проверяется.
«Открыть соединение» — голый TCP.

## lock

Печатает lock-файл программы: JSON, в котором лежат сами зависимости, а не
ссылки на них. Для каждого подключённого модуля записан весь его исходник, и
адрес ему — `sha256` этого исходника. Реестра нет и скачивать нечего: всё уже в
lock-файле.

```bash
flang lock <файл.flang> [--pretty]
```

| Ключ | Что делает |
| --- | --- |
| `--pretty` | отступ в два пробела |

Если рядом с входным файлом лежит `flang.lock`, все команды берут импорты из
него и исходников зависимостей не читают. Испорченный lock-файл отвергается с
`FLANG_LOCK`.

```bash
$ flang lock привет.flang
{"схема":2,"вход":"./привет.flang","модули":[],"печать":"dcf9b0c54a6a814573047949d66a78d7e4706c67ae8873e637823fa799609779"}
```

`привет.flang` ничего не подключает, поэтому список модулей («модули») пуст.

## package

Печатает пакет: то же содержимое, что у lock-файла, плюс имя, версия, источник
и список доказанного.

```bash
flang package <файл.flang> [--pretty]
```

| Ключ | Что делает |
| --- | --- |
| `--pretty` | отступ в два пробела |

Имя и версия берутся из файла `flang.package` рядом с входным файлом, а не из
ключей. Без него команда отказывает с кодом `1`:

```bash
$ flang package привет.flang
FLANG_PACKAGE: рядом с привет.flang нет объявления flang.package: пакету нужны имя и версия, и берутся они оттуда, а не из вызова
$ echo $?
1
```

С `flang.package` рядом пакет собирается:

```bash
$ cat flang.package
{"имя": "Привет", "версия": "1.0.0"}

$ flang package привет.flang | head -c 160
{"схема":2,"имя":"Привет","версия":"1.0.0","вход":"./привет.flang","модули":[{"имя":"Привет","путь":"./привет.flang","функций":1,"адрес":"2bc2186046bc075d03953d3ff11c333835b8561a724dc526bb95c91730fe0699","исходник":"module «Привет»\n\ntotal function «Удвоить»\n  accepts н: number\n  returns number\n  examp
```

Пакет собирается только из проверенной программы. Как им пользоваться —
[Как писать пакеты](packages.html).

## new

Заводит каталог с готовым пакетом: модуль с одной тотальной функцией и
unit-тестом, каталог `fspec/` с одной доказанной спекой и программой проверки
`guard.flang`, манифест `flang.package` и README.

```bash
flang new <имя> [--force]
```

| Ключ | Что делает |
| --- | --- |
| `--force` (`--силой`) | переписать каталог, если он уже есть |

```bash
$ flang new проба-cli
flang new: пакет «проба-cli» создан в …/проба-cli
  cd проба-cli && flang check проба-cli.flang
  flang io fspec/guard.flang
$ ls проба-cli
README.md  flang.package  fspec  проба-cli.flang
```

Существующий каталог без `--force` — код `1`; имя с пробелом, косой чертой,
кавычками или ёлочками либо занятое слово (имя команды, `flang`, `fspec`) — код
`2`, и не создаётся ни одного файла.

## run-script

```
flang run-script [<имя> [доводы…]]
```

Короткая команда проекта — имя для строки оболочки. Записывается в файле
настроек `.flangrc` как `script.<имя> = <команда>`, как `scripts` в
`package.json`:

```
script.site:build = node docs/site/build.mjs
```

Без имени `flang run-script` перечисляет короткие команды проекта; с именем —
запускает эту, и всё после имени уходит команде. В каталоге, где `.flangrc`
состоит из двух показанных строк:

```bash
$ cat .flangrc
script.hello = echo hello
script.fail = exit 7

$ flang run-script hello
hello
$ echo $?
0

$ flang run-script fail
$ echo $?
7

$ flang run-script missing
flang run-script: короткой команды «missing» в «…/.flangrc» нет. Вот какие есть:

  hello                              echo hello
  fail                               exit 7
$ echo $?
2
```

Файл — ближайший `.flangrc` от текущего каталога вверх; файл в домашнем
каталоге коротких команд не задаёт. Строка исполняется `/bin/sh -c` в каталоге
этого файла, и код возврата — её собственный. Если имя записано дважды,
берётся последняя строка. В строке из нескольких команд через `&&` доводы
достаются последней.

| Код возврата | Когда |
| --- | --- |
| собственный код команды | команда запустилась |
| `2` | такого имени нет, или нет `.flangrc` |
| `3` | файл не прочитался, или не запустился `/bin/sh` |

Ключи самого двоичного `--depth-limit` и `--step-limit` двоичный забирает до
имени, и команде они не достаются.

## repl

Интерактивная оболочка — то же, что голый `flang` в терминале. Объявления
накапливаются за сессию, выражения вычисляются сразу, `.помощь` показывает
команды оболочки. Файл в доводе загружается при запуске.

```bash
flang repl [<файл.flang>] [--max-steps N] [--max-depth N]
```

| Ключ | Что делает |
| --- | --- |
| `--max-steps N` | предел шагов вычислителя |
| `--max-depth N` | предел глубины |

Выражение вычисляется так: для сессии генерируется C (как у `flang emit`),
собирается системным компилятором C и запускается:

```bash
$ echo '«Удвоить» от 21' | flang repl привет.flang
объявлено: тотальная функция «Удвоить» — завершение доказано
загружено из привет.flang
42
```

Без компилятора C оболочка работает всё равно: проверяет разбор, типы и
завершаемость и вместо значения отвечает «проверено», о чём говорит при запуске:

```bash
$ echo '«Удвоить» от 21' | FLANG_CC=/nonexistent/cc flang repl привет.flang
вычислять нечем: компилятора C нет (ни $FLANG_CC, ни cc, ни gcc, ни clang в PATH).
Разбор, типы и завершаемость проверяются по-прежнему; выражение отвечает «проверено».
объявлено: тотальная функция «Удвоить» — завершение доказано
загружено из привет.flang
проверено
```

Компилятор C и его файлы ищутся через `FLANG_CC`, `FLANG_INCLUDE_DIR` и
`FLANG_LIB_DIR`.

## lsp

Языковой сервер flang по стандартному вводу и выводу (рамки `Content-Length` с
телом JSON, как требует спецификация LSP). Его запускает редактор; запущенный
вручную, он молча ждёт сообщений.

```bash
flang lsp [--stdio]
```

| Ключ | Что делает |
| --- | --- |
| `--stdio` | общаться через стандартный ввод и вывод |

Умеет: диагностику (те же проверки, что `flang check`: разбор, имена, типы,
завершаемость), дополнение, подсказку с сигнатурой при наведении и переход к
объявлению. На стандартный вывод идут только сообщения протокола, всё прочее —
в поток ошибок.

Проверить, что сервер работает, — послать ему одно сообщение:

```bash
$ printf 'Content-Length: 107\r\n\r\n{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"processId":null,"rootUri":null,"capabilities":{}}}' | flang lsp --stdio
Content-Length: 311

{"jsonrpc":"2.0","id":1,"result":{"capabilities":{"positionEncoding":"utf-16","textDocumentSync":{"openClose":true,"change":1,"save":{"includeText":false}},"completionProvider":{"triggerCharacters":["«","."]},"hoverProvider":true,"definitionProvider":true},"serverInfo":{"name":"flang-lsp","version":"0.1.0"}}}
```

Известное ограничение: в программе с `использует` (импорт) ошибка в
подключённом модуле уходит в журнал редактора, а не подчёркивается в буфере
этого модуля.

## Переменные окружения

| Переменная | Что задаёт |
| --- | --- |
| `FLANG_RUNTIME_DIR` | где `emit` ищет исходники рантайма цели, если не задан `--runtime` |
| `FLANG_CC` | какой компилятор C зовёт `repl` |
| `FLANG_INCLUDE_DIR`, `FLANG_LIB_DIR` | где `repl` ищет заголовки и библиотеку |
| `FLANG_UNPROVEN` | что `run` и `io` делают с недоказанными программами: `refuse`, `warn`, `allow` |

`FLANG_RECURSION_LIMIT` — не переменная, а код ошибки: кончился предел шагов
или глубины.
