# Для разработчиков языка

Эта страница нужна, если вы хотите править сам flang. Если вы хотите писать
на нём, вам сюда: [Установка](install.html) → [Первая программа](getting-started.html)
→ [Учебник](tutorial.html).

Здесь собрано всё внутреннее: решения, задачи, рабочие планы и устройство
сборки компилятора. Страницы для пользователей языка ссылаются на внутренние
документы только через эту страницу.

Дерево написано по-русски: имена и большая часть прозы. Сообщения коммитов
пишутся по-английски. Английская запись языка есть и разбирается в те же имена. Правка, присланная
по-английски, принимается.

## Соберите

Компилятор здесь один, написан на самом flang и собирается без Node. В дереве
лежит точка раскрутки — тот же компилятор, напечатанный в C99. Весь список
зависимостей — компилятор C и `make`:

```bash
git clone https://github.com/digitable-lol/flang && cd flang
make -C bootstrap
bootstrap/flang --version
```

```
flang {{выпуск.версия}}
```

Собранный двоичный — это то, что вы дальше запускаете:

```bash
bootstrap/flang check docs/examples/rosetta/towers-of-hanoi.flang
```

Компилятору Node не нужен: языковой сервер лежит в том же двоичном —
`flang lsp --stdio` (см. [страницу редактора](editor.html)). Node нужен только
сборке сайта и цели `js`.

## Проверьте

Две проверки идут на собранном двоичном и Node не требуют:

```bash
sh flang/test/обход.sh
sh flang/test/обход-примеров.sh
```

Первая обходит дерево компилятором, вторая прогоняет примеры всех программ
дерева.

Третья проверка сверяет напечатанный C с тем, что лежит в `bootstrap/`:

```bash
sh scripts/bootstrap-reprint.sh --bystro   # только входы печати, секунды
sh scripts/bootstrap-reprint.sh --check    # печать заново и сравнение байт в байт
```

Полная сверка `--check` идёт часы на одном ядре и занимает десятки гигабайт
памяти (числа — в [`docs/reprint-ledger.tsv`](https://github.com/digitable-lol/flang/blob/main/docs/reprint-ledger.tsv)),
поэтому `bootstrap/` перепечатывают сопровождающие, партиями. От вашей правки в
`flang/self/` этого не ждут; скажите в сообщении коммита, что она ждёт
перепечатки.

Если вы правили страницы сайта, добавьте:

```bash
node docs/site/build.mjs --check
```

Она краснеет на ссылке в никуда, на странице без английской пары и на
подстановке без значения.

Код, вывод двоичного, коды ошибок и справка команд стоят на страницах вставками
из дерева, а не набраны руками: слово `insert` в первой строке ограды блока или
в примечании HTML над таблицей называет источник. Правите пример или компилятор — пересоберите
вставки и проверьте, что страницы с кодом сходятся:

```bash
bootstrap/flang run-script docs:build
bootstrap/flang run-script docs:check
```

`docs:check` сверяет все страницы. Хук перед пушем зовёт `docs:changed`: он сверяет
только страницы, чей текст или источники ветка изменила против dev своего удалённого,
— вставленный файл, файл из вставленного прогона, двоичный из `bootstrap/`, исходники
компилятора для таблицы кодов, `flang/stdlib` для таблиц библиотеки, — а все страницы,
когда изменился сам план вставок. CI зовёт полный `docs:check`.

Устройство вставок — [ADR-0151](../adr/0151-a-page-is-prose-plus-inserts-taken-from-the-code.md).

## Пришлите правку

1. Отведите ветку от `dev`: `git switch -c моя-правка origin/dev`.
2. Правьте. Пишите примеры прямо в функции — они прогоняются той же командой
   `flang test`, что и всё остальное.
3. Прогоните проверки выше. Красная проверка — не повод для объяснительной
   записки: правка не готова.
4. Сообщение коммита — по-английски, в виде `type(scope): what is now true`;
   правила — [`docs/commit-messages.md`](https://github.com/digitable-lol/flang/blob/main/docs/commit-messages.md).
5. Откройте pull request в ветку `dev` на
   [github.com/digitable-lol/flang](https://github.com/digitable-lol/flang).

Об ошибке без правки — issue в том же репозитории. Приложите текст программы и
дословный вывод команды с кодом возврата: этого хватает, чтобы повторить.
