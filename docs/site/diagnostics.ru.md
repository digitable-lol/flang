В строке — код, файл, строка и столбец и что не так. Эта страница переводит
каждый код в то, что он значит и что с ним делать. Коды сгруппированы по
стадии, которая их сообщает: сначала разбор, потом имена, типы, завершаемость и
доказательства.

Коды возврата `flang check`: `0` — ошибок нет; `1` — найдены ошибки; `2` —
кривой вызов (неизвестный ключ, нет файла); `3` — с `--proof` гарантия не
доказана (с `--proof --strict` — всё, что не «доказано всё»); `4` — часть
проверок не запускалась (`--fast`). Полная таблица для всех команд — в
[Справочнике команд](cli.html#коды-возврата).

Слова на этой странице: **гарантия** — строка `обеспечивает` (postcondition);
**prover** — часть компилятора, которая доказывает гарантии для всех входов, в
выводе он называется «ядро»; **unit-тест** — `пример`.

## Три ловушки, которые стоят дня

Прочтите их, прежде чем искать свой код. В каждой ошибка видна не там, где
сделана.

### Гарантия, которая зовёт функцию своего модуля, ломает каждый модуль, который ввозит его списком

Сам по себе модуль проверяется чисто. Падает модуль, который его ввозит.

```flang insert docs/examples/diagnostics/core.flang
модуль «Core»

тотальная функция «Двойка»
  принимает н: число
  возвращает число
  н умножить на 2

тотальная функция «Учтено»
  принимает н: число
  возвращает число
  обеспечивает «не меньше двойки» результат не меньше («Двойка» от н)
  («Двойка» от н) плюс 1
```

```flang refused insert docs/examples/diagnostics/import.flang
модуль «Import»
использует «Core» только «Учтено»

тотальная функция «Проба»
  принимает н: число
  возвращает число
  «Учтено» от н
```

```text insert output: check docs/examples/diagnostics/core.flang
$ flang check docs/examples/diagnostics/core.flang
модуль «Core»: функций 2, из них с доказанным завершением 2; типов 0
docs/examples/diagnostics/core.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

```text insert output: check docs/examples/diagnostics/import.flang
$ flang check docs/examples/diagnostics/import.flang
модуль «Import»: функций 3, из них с доказанным завершением 3; типов 0; файлов вместе с импортами 2
docs/examples/diagnostics/import.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Ввоз `только «Учтено»` приносит одно имя. И тело, и гарантия «Учтено» зовут
«Двойка», которой у ввозящего модуля нет. Столбец 56 указывает внутрь гарантии.
Номера строк — из ввезённого файла, а файл не назван, потому что проверялись два
файла вместе.

Чинится одним из трёх способов:

| Способ | Как |
|---|---|
| ввезти и помощника | `использует «Core» только «Учтено», «Двойка»` |
| ввезти модуль целиком | `использует «Core»` |
| убрать вызов из гарантии | сказать то же арифметикой: `результат не меньше (н умножить на 2)` |

### `flang check` прошёл — не значит, что гарантии доказаны

`flang check` без ключей проверяет разбор, типы, завершаемость и unit-тесты.
Гарантия, которую он не может ни доказать, ни опровергнуть, не делает проверку
красной. Гарантия «не меньше двойки» выше не доказана: без `--proof` файл
проходит с кодом 0, с `--proof` тот же файл выходит с кодом 3.

Чтобы увидеть, что доказано, попросите отчёт о доказательствах:

```bash
flang check docs/examples/diagnostics/core.flang --proof
```

```
  постусловие «не меньше двойки» функции «Учтено» — объявлено, не доказано: ни теоремы, ни примеров. Его считает рантайм после каждого возврата — на тех входах, которые придут
…
docs/examples/diagnostics/core.flang: НЕ ПРОВЕРЕНО — утверждений 1: доказано 0, условно 0, сетка 0, объявлено, не доказано 1, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 3
```

Как читать итог каждой гарантии: «доказано» — доказано для всех входов;
«сетка N» — проверено только на ваших N примерах, это не доказательство;
«объявлено, не доказано» — объявлена, и нет ни доказательства, ни примеров. В CI
берите `flang check --proof --strict`: он выходит с `0`, только когда доказано
всё.

Вторая ловушка в том же выводе: пока стоит ошибка `FLANG_UNKNOWN_NAME`,
функция теряет и доказанное завершение, и её гарантии не доказывает никто.
Сначала чините неизвестные имена.

### FLANG_BOUND_ON_NAN: в типе `число` живёт NaN, а NaN не упорядочен

Самая частая неожиданность. Гарантия выглядит очевидно верной, а prover
отвечает контрпримером.

```flang refused insert docs/examples/diagnostics/nan.flang
модуль «Probe»

тотальная функция «Прибавить один»
  принимает н: число
  возвращает число
  обеспечивает «результат больше довода» результат больше н
  н плюс 1
```

```text insert output: check docs/examples/diagnostics/nan.flang
$ flang check docs/examples/diagnostics/nan.flang
модуль «Probe»: функций 1, из них с доказанным завершением 1; типов 0
FLANG_BOUND_ON_NAN в файле docs/examples/diagnostics/nan.flang, строка 6, столбец 3: постусловие «результат больше довода» функции «Прибавить один» ЛОЖНО, и контрпример назван: «н» объявлен типом «число», а «не число» живёт в этом типе и стоит ВНЕ ПОРЯДКА — оно не больше и не меньше ничего, включая самоё себя. Тело собрано только из арифметики над «н», а всякая арифметическая операция «не число» переносит, значит результат есть «не число», и сравнение с ним ложно. Позовите «Прибавить один» от (0 делить на 0) — рантайм ответит FLANG_PROPERTY. Чинится тремя способами: объявить вход отрезком («неотрицательное», «целое») — тогда «не число» не втащить вовсе; поставить предусловие — за него платит вызывающий; либо оговорить границу, и ядро оговорку читает: обеспечьте «не ((н минус н) равен 0) или (…)»
docs/examples/diagnostics/nan.flang: не проверено — замечаний 1
$ echo $?
1
```

Причина: тип `число` — число с плавающей точкой, и в нём есть NaN («не число»).
Любая арифметика над NaN даёт NaN, а любое сравнение с NaN ложно. Значит,
«результат больше довода» для NaN неверно.

| Способ | Что писать | Кто платит |
|---|---|---|
| сузить тип аргумента | `принимает н: неотрицательное` или `целое` | никто: NaN не попадёт |
| поставить предусловие | `требует «вход есть число» (н минус н) равен 0` | вызывающий |
| исключить NaN в самой гарантии | `обеспечивает «…» не ((н минус н) равен 0) или (результат больше н)` | никто |

`(н минус н) равен 0` ложно ровно тогда, когда `н` — NaN.

## Разбор

| Код | Что значит | Что делать |

## Имена и ввоз

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_UNKNOWN_NAME` | имя не определено: нет такой функции или переменной | объявить, ввезти модуль или исправить написание |
| `FLANG_AMBIGUOUS_NAME` | два ввоза приносят одно имя | убрать один ввоз или сузить его через `только` |
| `FLANG_BAD_NAME` | имя записано не так, как пишутся имена | переименовать: имена функций — в ёлочках, параметры — простыми словами |
| `FLANG_NAME_TAKEN` | имя занято другим объявлением | выбрать другое |
| `FLANG_DUPLICATE_NAME` | одно имя объявлено дважды: в одном месте либо в двух модулях одной программы — в том числе когда тёзку-помощника ввезённой функции прячет список `только` | убрать второе объявление, вписать помощника в `только` или переименовать |
| `FLANG_IMPORT_NOT_FOUND` | ввозимый модуль не найден | проверить имя модуля и путь в `из "…"` |
| `FLANG_IMPORT_CYCLE` | модули ввозят друг друга по кругу | вынести общее в третий модуль |
| `FLANG_IMPORT_AMBIGUOUS` | одно имя приходит из двух модулей | сузить ввоз через `только` |
| `FLANG_IMPORT_NAME` | в списке `только` есть то, чего модуль не объявляет | сверить список с объявлениями модуля |

## Типы

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_TYPE` | объявленный тип расходится с тем, что даёт тело или аргумент; ещё — функция объявлена дважды | согласовать |
| `FLANG_TYPE_ARGS` | встроенному типу даны аргументы типа; встроенные типы вроде `число` их не принимают | убрать аргументы |
| `FLANG_TYPE_PARAM` | параметр типа объявлен дважды, без имени или назван как встроенный либо объявленный тип | переименовать параметр |
| `FLANG_APPLY` | вызов не подходит: не то число аргументов или вызывают не функцию | сверить вызов с сигнатурой |
| `FLANG_BUILTIN_ARGS` | встроенной операции дали не то число аргументов | свериться с описанием операции |
| `FLANG_MATCH_NOT_EXHAUSTIVE` | pattern matching покрывает не все случаи | добавить недостающий `случай` |
| `FLANG_MATCH_UNREACHABLE` | случай покрыт более ранним и не сработает никогда | убрать его или поднять выше |
| `FLANG_EXAMPLE` | unit-тест не прошёл: значение не совпало с ожидаемым | поправить тело или ожидание |

## Завершаемость и пределы

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_NOT_TOTAL` | функция объявлена `тотальная`, а завершение не доказано | передавать в рекурсивный вызов ЧАСТЬ аргумента (хвост списка, поле варианта), а не пересчитанное число |
| `FLANG_MEASURE` | объявленная мера не убывает | поправить `убывает` или вызов |
| `FLANG_RECURSION_LIMIT` | вычисление исчерпало шаги или глубину вызовов | поднять `--max-steps` / `--max-depth` или исправить рекурсию |
| `FLANG_STEP_LIMIT` | предел шагов кончился внутри unit-теста | тот же ключ `--max-steps` |
| `FLANG_BUDGET_EXHAUSTED` | кончился бюджет шагов прогона | поднять бюджет или сузить задачу |
| `FLANG_MEMORY` | кончилась память | уменьшить данные |
| `FLANG_STOPPED` | прогон остановлен снаружи | запустить заново |

## Гарантии и доказательства

Предусловия (`требует`), гарантии (`обеспечивает`) и теоремы.

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_PROPERTY` | гарантия нарушена во время работы | неверна либо гарантия, либо тело — смотрите вход, на котором сломалось |
| `FLANG_PRECONDITION` | предусловие записано неверно | проверить форму `требует «имя» <условие>` |
| `FLANG_PRECONDITION_CALL` | вызывающий не обеспечил предусловие вызываемой | доказать условие в точке вызова или сузить тип аргумента |
| `FLANG_BOUND_ON_NAN` | гарантия о порядке ложна из-за NaN | см. третью ловушку выше |
| `FLANG_PROOF_NO_GOAL` | теорема не доказывает ничего: гарантии с таким именем нет | назвать теорему ровно как гарантию |
| `FLANG_PROOF_AMBIGUOUS` | теорема доказывала бы сразу две гарантии | дать гарантиям разные имена |
| `FLANG_PROOF_CLAIM_MISMATCH` | `утверждаем` расходится с гарантией | скопировать текст гарантии слово в слово |
| `FLANG_PROOF_DUPLICATE` | две теоремы доказывают одну гарантию | оставить одну |
| `FLANG_PROOF_STEP` | у шага нет обоснования, или шагов нет вовсе | добавить `по свойству «…»`, `по примеру «…»` или `по предположению` |
| `FLANG_PROOF_UNFINISHED` | доказательство не закончено | добавить `следовательно доказано` |
| `FLANG_PROOF_UNKNOWN_VAR` | в утверждении необъявленное имя | объявить его через `дано` |
| `FLANG_PROOF_VAR_TYPE` | тип переменной теоремы не совпадает с типом параметра | согласовать `дано` с сигнатурой функции |
| `FLANG_PROOF_INDUCTION_TYPE` | индукция по этому типу невозможна | индукция идёт по типу с вариантами или по `неотрицательное` |
| `FLANG_PROOF_INDUCTION_CASES` | покрыты не все случаи индукции | добавить недостающий `случай` |
| `FLANG_PROOF_INDUCTION_BRANCH` | случай не доходит до цели | обосновать этот случай |
| `FLANG_PROOF_INDUCTION_STEP` | шаг индукции не доходит до предположения | добавить `по предположению` и сделать стороны совпадающими в точности |
| `FLANG_PROOF_INDUCTION_DESCENT` | шаг индукции не ровно на один вниз | сделать шаг ровно на один вниз |
| `FLANG_INITIAL_FAILURE` | для типа не удалось построить правило индукции | проверить, что тип объявлен вариантами |
| `FLANG_UNCOVERED_FAILURE` | случай ошибки не обработан в pattern matching | добавить случай для ошибки |

## Планы и ввод-вывод

Ошибки `flang io`. План возвращает команду как данные, а выполняет её рантайм;
коды `FLANG_IO_*` — отказы рантайма, которые план получает в ответ.

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_PLAN` | план объявлен неверно | проверить объявление `план` |
| `FLANG_UNKNOWN_PLAN` | в файле нет плана с таким именем | назвать существующий: `--plan 'Имя'`, без ёлочек |
| `FLANG_PLAN_UNSUPPORTED` | целевой язык не умеет генерировать планы | генерировать на другую цель или запускать через `flang io` |
| `FLANG_IO_DENIED` | право отнято ключом (`--no-read`, `--no-write`, `--no-net` и другие) | убрать ключ |
| `FLANG_IO_NO_HOST` | нет рантайма, который выполнил бы команду | запускать через `flang io`, а не вычислением функции |
| `FLANG_IO_NOT_TEXT` | чтение текста нашло байты, которые не текст | читать байтами |
| `FLANG_IO_TIMEOUT` | запущенный процесс молчал дольше `--timeout` | поднять `--timeout` |
| `FLANG_LOCK` | lock-файл испорчен или не сошлась его контрольная сумма | пересобрать его `flang lock` |
| `FLANG_PACKAGE` | пакет испорчен или рядом нет `flang.package` | пересобрать его `flang package` |

Права отнимаются по одному; по умолчанию можно всё:

```bash
flang io план.flang --plan 'Разбор' --no-net --in-dir
```

## Установка пакетов

Отказы установщика пакетов (`flang run-script package:install`) печатает не
компилятор, а сам установщик — план на flang; их коды и что с ними делать
перечислены на [странице пакетов](packages.html#коды-отказов-установщика).

## Процессы

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_PROCESS` | процесс объявлен неверно | проверить объявление |
| `FLANG_PROCESS_ACCEPTS` | процессу пришло сообщение, которого он не принимает | добавить вид сообщения в `принимает` |
| `FLANG_PROCESS_LIMIT` | достигнут предел числа процессов | поднять предел или запускать меньше |
| `FLANG_MAILBOX_FULL` | почтовый ящик полон: читатель отстаёт | читать чаще или притормозить отправителя |
| `FLANG_LINK_DOWN` | связь с узлом или процессом порвалась | обработать обрыв в супервизоре |
| `FLANG_HOTSWAP_REFUSED` | горячая замена кода отвергнута | сделать новый код совместимым с прежними объявлениями |

## Командная строка и внутренние ошибки

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_CLI` | кривой вызов: неизвестный ключ или нет довода | `flang <команда> --help` |
| `FLANG_INTERNAL` | сломался сам компилятор | сообщить: это ошибка инструмента, а не вашей программы |
| `FLANG_SELF_REPL_UNSUPPORTED` | оболочка не принимает эту конструкцию, например `использует` | положить код в файл и запустить `flang check` |
| `FLANG_FACTCHECK_НЕТ_ОТВЕТА` | `flang facts` не получил значения для вызова | добавить значение в факты |
