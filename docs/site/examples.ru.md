## Как прогонять

Примеры объявлены внутри функций, а не в отдельных файлах проверок, и
прогоняются двоичным:

```bash
bootstrap/flang test docs/examples/rosetta/   # один набор
bootstrap/flang test docs/examples/           # весь каталог
```

Наборы считаются очень по-разному, и это стоит знать до запуска. На общей
машине: `leetcode` — 82 файла, 806 примеров, около 14 секунд; `crypto` —
8 файлов, 1802 примера (своих 77, остальные — из модулей библиотеки, которые
набор подключает), около 19 минут, потому что считает настоящие контрольные
векторы AES и ECDSA. Файл, который двоичный не взял, он называет вместе с
кодом отказа, а не пропускает молча.

## Как создать DSL для правил захвата

DSL — язык для одной предметной области. Здесь автор уровня задаёт время
захвата клеток в [файле из двух строк](docs/examples/dsl/example.capture):

```text
neutral after 3 ticks
hostile after 5 ticks
```

1. **Определите, что задаёт язык и в каких единицах.** В примере это время
   захвата нейтральной и вражеской клетки в тактах симуляции. Грамматика
   требует две строки в этом порядке, по одному пробелу между словами и
   одну или две цифры со значением от 1 до 99. Поддерживаются переводы
   строк LF и CRLF и один необязательный перевод строки в конце.
2. **Преобразуйте текст в значения при загрузке.**
   [Разбор на flang](docs/examples/dsl/capture.flang) проверяет запись и
   возвращает либо типизированные `«Правила захвата»`, либо номер первой
   отклонённой строки. Слова DSL задаются в функции `«Разобрать правила»`.
   Для этого не нужно менять лексер flang и его четыре поверхности записи.
3. **Пишите решения на типизированной модели.** `«Срок захвата»` выбирает
   значение из записи. Сформулируйте результат каждой ветки в именованном
   постусловии. Добавьте примеры допустимого файла, пропущенных и лишних
   строк, неправильных единиц и значений. В приложении разбирайте файл при
   загрузке правил, а в симуляцию передавайте принятую запись.

Из корня репозитория проверьте примеры и оба постусловия:

```sh
bootstrap/flang check docs/examples/dsl/capture.flang --proof
bootstrap/flang test docs/examples/dsl/capture.flang
```

Чтобы прочитать файл с примером, передайте его содержимое команде flang
как JSON-строку через Node.js:

```sh
args=$(node -e 'process.stdout.write(JSON.stringify({текст:require("node:fs").readFileSync(process.argv[1],"utf8")}))' docs/examples/dsl/example.capture)
bootstrap/flang run docs/examples/dsl/capture.flang --function 'Разобрать правила' --args "$args"
```

В поле `правила` будут значения `{"нейтральная":3,"вражеская":5}`.
Если во второй строке заменить `ticks` на `seconds`, разбор вернёт
`{"вариант":"Ошибка правила","строкаПравила":2}`. Теперь вызовите ту же
функцию выбора срока, которую могла бы вызвать симуляция:

```sh
bootstrap/flang run docs/examples/dsl/capture.flang --function 'Срок захвата' \
  --args '{"правила":{"нейтральная":3,"вражеская":5},"вражеская":true}'
```

Она вернёт `5`. Два постусловия доказывают выбор поля для всех входов этой
функции. Примеры разбора проверяют конкретные допустимые и ошибочные файлы.
При расширении DSL добавляйте пример новой записи и ошибочного ввода,
который она могла бы принять. Если меняется смысл уже написанного файла,
ведите версии грамматики и выбирайте разбор при загрузке по версии файла.

## Про `library-api`

`library-api` стоит в этом ряду особняком. Остальные наборы — программы: файл, а
в нём объявления со своими примерами (у `frameworks/` рядом с такими файлами лежит
хозяин на TypeScript, см. ниже). `library-api` — проект: семь модулей на flang, из
них один свой, со своей раскладкой каталогов. Пример показывает не HTTP, а
границу: что уезжает в язык, где у куска логики есть выполняемый пример, и что
остаётся хозяину. Хозяина в дереве нет: остаётся половина на flang, и она проверяется
командой. Правила, выведенные из этой раскладки, собраны в
[Раскладке репозитория](project-layout.html).

## Под JS-фреймворками

`docs/examples/frameworks/` — три приложения с одной границей: ядро логики написано на
flang и напечатано в JavaScript (`bootstrap/flang emit … --target js`), а хозяин —
JS-фреймворк. Хозяин держит сокет, HTTP, состояние формы и рендер, а решение зовёт
у ядра. Признак границы тот же, что у `docs/examples/host-boundary/` с хозяином на C: на
flang пишется то, что **решает**; хозяину остаётся то, что **ждёт и держит
управление между решениями**.

| Каталог | Хозяин | Ядро | Что решает ядро |
|---|---|---|---|
| `docs/examples/frameworks/nestjs-orders/` | NestJS | `core/orders-api.flang` | REST-служба заказов: разбор строки запроса, обязательные поля, маршрут по методу и пути, код ответа (201/200/400/404/405) |
| `docs/examples/frameworks/react-invoice/` | React | `core/cart.flang`, `core/catalog.flang` | счёт корзины целым числом копеек: сумма, ступени скидки, итог, строки счёта |
| `docs/examples/frameworks/vue-roman/` | Vue | `core/roman-numerals.flang` | римские цифры туда и обратно в диапазоне 1..3999 |
| `docs/examples/frameworks/react-ts-pure/` | React + TypeScript | `core/storefront.flang` | витрина, где в компонентах ноль строк логики: корзина, ступени скидки, запись рублей и редьюсер — всё на flang |

Напечатанный модуль лежит в `printed/` каждого примера и самодостаточен: без
зависимостей, идёт и в Node, и в браузере. Хозяин импортирует его напрямую
(`src/orders.controller.ts`, `src/App.tsx`, `src/App.vue`). Значения на стыке:
список → массив, запись → объект; записи строятся фабриками `sozdat…` из объектов с
русскими ключами. Имена функций — транслитерация русских: «Обработать запрос» →
`obrabotatZapros`, «Сумма корзины» → `summaKorziny`, «В римские» → `vRimskie`.

Что проверено на дереве: каждое ядро проходит `bootstrap/flang check`; у кода в
`printed/` стоит шапка с лицензией и командой переиздания;
напечатанный модуль отвечает верно под `node` прямым вызовом:

```bash
cd docs/examples/frameworks/vue-roman && node --input-type=module -e \
  'import("./printed/roman_numerals.js").then(m => console.log(m.vRimskie(2024), m.izRimskih("MCMLXXXIV")))'
# MMXXIV 1984
```

Сборка хозяина — командами фреймворка из `package.json` каждого примера:
`npm install`, `npm run typecheck`, `npm run build`. На дереве она не проверяется:
ей нужны пакеты из сети. `node_modules/` и `dist/` в примеры не входят. Переиздать
ядро — из корня дерева, например
`bootstrap/flang emit docs/examples/frameworks/vue-roman/core/roman-numerals.flang --target js --out docs/examples/frameworks/vue-roman/printed`;
файлы в `printed/` печатает компилятор, руками их не правят.
