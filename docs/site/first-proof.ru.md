# Первое доказательство

Как доказать, что функция верна на любом входе? За десять минут вы напишете
функцию, дадите компилятору найти в ней ошибку, исправите её и допишете
доказательство. Нужен установленный `flang` ([Установка](install.html)).

Если вы знаете Dafny или SPARK: `требует` и `обеспечивает` работают как
`requires` и `ensures`. Если знаете Lean или Coq: `теорема` записывает
доказательство по шагам, каждый шаг проверяет компилятор; тактик и поиска нет.

## 1. Функция и постусловие

Файл `change.flang`:

```flang refused
модуль «Касса»

тотальная функция «Сдача»
  принимает внесено: неотрицательное, цена: неотрицательное
  возвращает число
  обеспечивает «сдача не отрицательна» результат не меньше 0
  пример «сто за девяносто»
    дано внесено равно 100
    дано цена равно 90
    ожидается 10
  внесено минус цена
```

Три записи здесь новые:

| Запись | Что это | В других языках |
| --- | --- | --- |
| `обеспечивает «имя» условие` | постусловие: что верно для результата при любых аргументах | `ensures` в Dafny |
| `пример` | тест, записанный внутри функции | unit-тест |
| `неотрицательное` | тип: целое от 0 до 2⁵³−1 | `nat` в Lean |

Тест проходит: 100 − 90 = 10. Проверьте файл:

```bash
flang check change.flang
```

Ответ компилятора:

```text
модуль «Касса»: функций 1, из них с доказанным завершением 1; типов 0
FLANG_EXAMPLE: FLANG_PROPERTY: постусловие «сдача не отрицательна» функции «Сдача»
нарушено на входе внесено = 0, цена = 1 — посчитано вычислителем на этом входе
change.flang: не проверено — замечаний 1
```

Код возврата 1. Тест прошёл, но компилятор сам подобрал вход, на котором
постусловие ложно: внесли 0, цена 1, сдача −1. «Вычислитель» в сообщении —
интерпретатор внутри компилятора: он выполнил функцию на этом входе.
«Замечаний 1» читается как «ошибок 1».

## 2. Предусловие

Функция имеет смысл, только если денег хватает. Это записывает строка
`требует` после строки `принимает`. Файл `change.flang` целиком:

```flang
модуль «Касса»

тотальная функция «Сдача»
  принимает внесено: неотрицательное, цена: неотрицательное
  требует «денег хватает» цена не больше внесено
  возвращает число
  обеспечивает «сдача не отрицательна» результат не меньше 0
  пример «сто за девяносто»
    дано внесено равно 100
    дано цена равно 90
    ожидается 10
  внесено минус цена
```

`требует` — предусловие (`requires` в Dafny): условие на аргументы, которое
обязан выполнить вызывающий. Проверьте снова, с ключом `--proof`. Он добавляет
отчёт о доказательствах:

```bash
flang check change.flang --proof
```

Отчёт длинный. Сейчас нужна одна его запись:

```text
…
  постусловие «сдача не отрицательна» функции «Сдача» — доказано по объявленным
типам аргументов: … — утверждение обо ВСЕХ входах, а не о написанных; теоремы при
нём нет и не нужно
…
```

Код возврата 0. «Доказано» относится к любой паре аргументов, которая проходит
предусловие; 100 и 90 из теста — частный случай. Доказательство компилятор
нашёл сам. «Теорема» — доказательство, написанное руками; до неё дойдём в шаге 4.

Предусловие проверяется и при запуске:

```bash
flang run change.flang --function Сдача --args '{"внесено": 50, "цена": 90}'
```

```text
доказано: утверждений 1
FLANG_PRECONDITION: не выполнено требование «денег хватает» функции «Сдача»
```

Код возврата 1. Первая строка относится к файлу: единственное постусловие в нём
доказано. Вторая — к этому вызову: аргументы не проходят предусловие («требование»
в сообщении), и функция не вычислялась.

## 3. Компилятор не справился сам

Следующая функция рекурсивная. Файл `total.flang`:

```flang
модуль «Касса»

тотальная функция «Итог»
  принимает цены: список неотрицательное, доставка: число
  требует «доставка не отрицательна» доставка не меньше 0
  возвращает число
  обеспечивает «итог не отрицателен» результат не меньше 0
  пример «две покупки и доставка»
    дано цены равно [100, 50]
    дано доставка равно 30
    ожидается 180
  разбор цены
    случай пусто
      то доставка
    случай голова и хвост
      то голова плюс («Итог» от хвост и доставка)
```

`разбор` — сопоставление с образцом (`match`). Пустой список даёт доставку,
непустой — первую цену плюс итог остальных.

```bash
flang check total.flang --proof
```

Ответ компилятора:

```text
…
  постусловие «итог не отрицателен» функции «Итог» — сетка 1 значение (примеры
функции): нарушений на них нет: … Это не доказательство — теоремы при утверждении нет
…
```

Код возврата 3. Словом «сетка» компилятор называет ответ «проверено только на
тестах». Тест один, он прошёл, о других входах ничего не известно. У каждого
постусловия в отчёте один из трёх ответов:

| В отчёте | Что это значит | Что будет при запуске |
| --- | --- | --- |
| `доказано` | верно для всех входов | проверки в программе нет |
| `сетка N` | прошло на N тестах, доказательства нет | условие проверяется при каждом вызове |
| `объявлено, не доказано` | нет ни доказательства, ни тестов | условие проверяется при каждом вызове |

Пока в файле есть постусловие без доказательства, `flang run` программу не
запускает и возвращает код 3. Ключ `--trust` запускает её без доказательства.

## 4. Доказательство по индукции

Почему итог не отрицателен, человеку понятно:

- список пуст — итог равен доставке, она не отрицательна по предусловию;
- список не пуст — итог равен первой цене плюс итог остальных. Первая цена не
  отрицательна по типу. Итог остальных не отрицателен, если считать, что для
  более короткого списка утверждение уже верно.

Это индукция по списку. Допишите её в конец файла. Файл `total.flang` целиком:

```flang
модуль «Касса»

тотальная функция «Итог»
  принимает цены: список неотрицательное, доставка: число
  требует «доставка не отрицательна» доставка не меньше 0
  возвращает число
  обеспечивает «итог не отрицателен» результат не меньше 0
  пример «две покупки и доставка»
    дано цены равно [100, 50]
    дано доставка равно 30
    ожидается 180
  разбор цены
    случай пусто
      то доставка
    случай голова и хвост
      то голова плюс («Итог» от хвост и доставка)

теорема «итог не отрицателен»
  дано цены: список неотрицательное
  дано доставка: число
  утверждаем результат не меньше 0
  индукция по цены
    случай пусто
      то по предположению
    случай голова и хвост
      то по предположению
  следовательно доказано
```

Как читать теорему:

- имя теоремы совпадает с именем постусловия — так компилятор их связывает;
- `дано` повторяет параметры функции, `утверждаем` — условие из `обеспечивает`;
- `индукция по цены` разбирает те же два случая, что и `разбор` в функции;
- `по предположению` читается как «следует из уже известного». В первом случае
  известно предусловие, во втором — утверждение для хвоста.

```bash
flang check total.flang --proof
```

```text
…
  постусловие «итог не отрицателен» функции «Итог» — доказано индукцией по
«список»: база 1 случай, шаг при допущении на частях (1 случай), … — утверждение
обо ВСЕХ входах типа «список», а не о написанных
…
```

Код возврата 0. «База» — случай пустого списка. «Шаг при допущении на частях» —
случай непустого списка, где утверждение считается верным для хвоста.

Программа запускается:

```bash
flang run total.flang --function Итог --args '{"цены": [100, 50], "доставка": 30}'
```

```text
доказано: утверждений 1
180
```

## 5. Неверное доказательство не проходит

Компилятор проверяет каждый шаг теоремы. Удалите из `total.flang` строку
`требует`, теорему оставьте и повторите проверку:

```bash
flang check total.flang --proof
```

Ответ компилятора:

```text
FLANG_PROOF_INDUCTION_STEP в файле total.flang, строка 23, столбец 10: шаг 1,
база «пусто» теоремы «итог не отрицателен»: «по предположению» стоит в базе
«пусто», где предположения индукции нет: … а предусловий у функции не объявлено
ни одного. …
…
```

Код возврата 1. Без предусловия первому случаю не на что опереться: доставка
может быть отрицательной. Сообщение называет строку, шаг и причину. Отчёта о
доказательствах у файла с ошибками нет.

## Что вы теперь умеете

- записать постусловие (`обеспечивает`) и предусловие (`требует`);
- отличить в отчёте «доказано» от «проверено только на тестах»;
- дописать доказательство по индукции, когда компилятор не нашёл его сам.

## Чего доказательство не даёт

Доказательство говорит, что код соответствует постусловию. Верно ли само
постусловие описывает задачу, решаете вы. Функция, которая всегда возвращает 0,
тоже прошла бы проверку `результат не меньше 0`.

Доказательства перепроверяет вторая программа, `checker`. Она написана отдельно
от компилятора и входит в готовые сборки. Её ответ — предпоследняя строка отчёта
`--proof`. Для `change.flang` из шага 2 и `total.flang` из шага 4:

```text
change.flang: независимо, сверщиком, проиграно 1 из 1 доказанных; на слове ядра 0 — код сверщика 0
total.flang: независимо, сверщиком, проиграно 0 из 1 доказанных; на слове ядра 1 — код сверщика 3
```

«Сверщик» — программа `checker`. «Проиграно 1 из 1» — она повторила
доказательство и согласилась. «На слове ядра 1» — одно доказательство принято
без перепроверки: доказательства по индукции `checker` повторяет пока не все.
На код возврата `flang check` эта строка не влияет.
