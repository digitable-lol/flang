# flang для знающих Lean и Dafny

Страница отвечает на вопрос: чем доказательство во flang отличается от Lean 4 и
Dafny и когда какой инструмент брать.

Коротко: flang ближе к Dafny, чем к Lean. Вы пишете предусловия и постусловия у
функций, а компилятор сам ищет доказательство. Уровня Lean он не достигает:
доказывает меньше, и проверяет его меньше независимого кода.

| Задача | Что брать |
| --- | --- |
| Формализовать математику, доказать произвольную теорему | Lean 4 |
| Доказать свойства алгоритма с циклами и кучей, готовы подсказывать решателю | Dafny |
| Писать прикладной код и проверять границы, длины, деньги без ручных доказательств | flang |

## Один пример на трёх языках

Функция возвращает большее из двух неотрицательных целых. Доказываем три
факта: результат не меньше первого аргумента, не меньше второго, и порядок
аргументов не важен.

flang, файл `docs/examples/proofs/largest.flang`:

```flang insert docs/examples/proofs/largest.flang
модуль «Largest»

тотальная функция «Наибольшее»
  принимает а: точное целое, б: точное целое
  возвращает точное целое
  обеспечивает «не меньше первого» результат не меньше а
  обеспечивает «не меньше второго» результат не меньше б
  если а больше б
    то а
    иначе б

утверждение «наибольшее перестановочно»
  для всех а: точное целое и б: точное целое
  утверждаем («Наибольшее» от а и б) равен («Наибольшее» от б и а)
```

```bash
flang check largest.flang --proof --strict; echo "код $?"
```

```
постусловие «не меньше первого» функции «Наибольшее» — доказано по объявленным типам аргументов …
постусловие «не меньше второго» функции «Наибольшее» — доказано по объявленным типам аргументов …
утверждение «наибольшее перестановочно» — доказано по объявленным типам аргументов …
код 0
```

Доказательств в файле нет: все три факта ядро вывело само. `точное целое` —
неотрицательное целое без верхней границы, как `Nat` в Lean и `nat` в Dafny.

Lean 4, файл `docs/examples/proofs/largest.lean`:

```lean
def largest (a b : Nat) : Nat :=
  if a > b then a else b

theorem largest_ge_left (a b : Nat) : largest a b ≥ a := by
  unfold largest; split <;> omega

theorem largest_ge_right (a b : Nat) : largest a b ≥ b := by
  unfold largest; split <;> omega

theorem largest_comm (a b : Nat) : largest a b = largest b a := by
  unfold largest; split <;> split <;> omega
```

В Lean каждую теорему доказывает программист: раскрыть определение, разобрать
ветви `if`, закрыть арифметику тактикой `omega`. Из тактик получается объект
доказательства, и его целиком проверяет ядро Lean.

Dafny, файл `docs/examples/proofs/largest.dfy`:

```dafny
function Largest(a: nat, b: nat): nat
  ensures Largest(a, b) >= a
  ensures Largest(a, b) >= b
{
  if a > b then a else b
}

lemma LargestCommutes(a: nat, b: nat)
  ensures Largest(a, b) == Largest(b, a)
{
}
```

В Dafny запись почти та же, что во flang: `ensures` соответствует `обеспечивает`,
`lemma` с пустым телом — `утверждение`. Доказательство ищет SMT-решатель Z3.

## Lean 4 и flang по свойствам

| Свойство | Lean 4 | flang |
| --- | --- | --- |
| Доказательство как объект | да: терм, который можно сохранить и проверить заново | запись шагов есть (`--record`), но повторить по ней удаётся не каждое доказательство |
| Малое ядро | да: проверяет только типы термов | ядро — около 11 тысяч строк внутри компилятора |
| Независимая перепроверка | да: терм проверяют и сторонние реализации ядра | две отдельные программы; на наборе сравнения повторено 30 доказательств из 55 |
| Проверено ли то, что проверяет | ядро мало, его читают и переписывают независимо | у каждого из 93 видов шагов доказательства лемма на Lean; о коде ядра теорем нет |
| Аксиомы | три стандартные; `#print axioms` показывает, на что опирается теорема | объявить аксиому нельзя; допущения перечислены на странице [Чему вы доверяете](trust.html) |
| Логика | зависимые типы, по желанию классическая | закрытый список правил над пред- и постусловиями |
| Кванторы | любые, в том числе по функциям и типам | «для всех» по аргументам; внутри — только по элементам списка |
| Индукция | по любому индуктивному типу, взаимная, по убывающей мере | по списку, строке, своему типу и `неотрицательное` с шагом 1 |
| Утверждения для любого типа | да | нет: утверждение пишется для конкретного типа |
| Числа с плавающей точкой | `Float` для ядра непрозрачен: считать можно, доказывать свойства — нет | правила учитывают округление, NaN, −0 и границу 2⁵³ |

Последняя строка — сильная сторона flang. `число` в нём — binary64, и ядро не
докажет над ним то, что ломается округлением. Файл
`docs/examples/proofs/float-sum.flang` объявляет сложение чисел моноидом:

```flang insert docs/examples/proofs/float-sum.flang
модуль «Float sum»

тотальная функция «Сложить числа»
  принимает а: число, б: число
  возвращает число
  пример «два и три»
    дано а равно 2
    дано б равно 3
    ожидается 5
  а плюс б

моноид «Сумма чисел»
  носитель число
  операция «Сложить числа»
  единица 0
```

```bash
flang check float-sum.flang --proof
```

```
закон «Сумма чисел — ассоциативность» — ядром НЕ доказан и доказан не будет:
носитель — двоичное «число» …, где сложение и умножение округляют, сумма не
сочетательна выше 2⁵³, а ноль не нейтрален к минус нулю …
```

Сложение binary64 не ассоциативно, и ядро называет причину. `Носитель` в выводе
— тип значений моноида. Тот же моноид над `точное целое` лежит в
`docs/examples/proofs/exact-sum.flang`, и все три его закона доказаны.

## Dafny и flang по свойствам

| Свойство | Dafny | flang |
| --- | --- | --- |
| Кто ищет доказательство | SMT-решатель Z3 | закрытый список правил в компиляторе |
| Чему доверяете | переводу в Boogie, Boogie и Z3 | ядру доказательств и компилятору |
| Независимая перепроверка | встроенной нет | частичная, отчёт называет долю |
| Время проверки | зависит от решателя, бывает нестабильным | решателя с пределом времени нет: тот же текст даёт тот же ответ |
| Сила | больше: кванторы, инварианты циклов, куча | меньше: что не подходит под правило, остаётся недоказанным |
| Подсказки | `assert`, `lemma`, `calc`, инварианты | `требует`, `теорема` по шагам |
| Недоказанное постусловие | ошибка проверки | проверяется во время выполнения; запуск — по ключу `--trust` |

## Что flang доказывает сам

Меряем набором из 60 небольших утверждений, которые в Lean 4 закрываются
стандартными тактиками. Lean доказывает все 60. flang:

| Итог | Задач |
| --- | ---: |
| доказывает сам | 33 |
| доказывает после переделки: теорема, другой тип, свойство записано постусловием | 18 |
| не доказывает | 9 |

Сам flang берёт арифметику целых, границы, длины списков, разбор по вариантам.
Сочетательность склейки списков он выводит индукцией без подсказок. Файл
`docs/examples/proofs/append-numbers.flang`:

```flang insert docs/examples/proofs/append-numbers.flang
модуль «Append numbers»

тотальная функция «Склеить»
  принимает первый: список числа, второй: список числа
  возвращает список числа
  разбор первый
    случай пусто
      то второй
    случай голова и хвост
      то приписать голова к («Склеить» от хвост и второй)

утверждение «склейка сочетательна»
  для всех а: список числа и б: список числа и ц: список числа
  утверждаем («Склеить» от («Склеить» от а и б) и ц) равен («Склеить» от а и («Склеить» от б и ц))
```

```
утверждение «склейка сочетательна» — доказано индукцией по «список»: база 1 случай,
шаг при допущении на частях (1 случай) …
```

## Что flang не доказывает

Двойное обращение списка возвращает исходный список. Lean доказывает это
индукцией с вспомогательной леммой. flang — нет. Файл
`docs/examples/proofs/reverse.flang`:

```flang insert docs/examples/proofs/reverse.flang
модуль «List reversal»

тотальная функция «В конец»
  принимает элементы: список числа, последний: число
  возвращает список числа
  разбор элементы
    случай пусто
      то [последний]
    случай голова и хвост
      то приписать голова к («В конец» от хвост и последний)

тотальная функция «Обратить»
  принимает элементы: список числа
  возвращает список числа
  разбор элементы
    случай пусто
      то пустой список
    случай голова и хвост
      то «В конец» от («Обратить» от хвост) и голова

утверждение «двойное обращение возвращает список»
  для всех а: список числа
  утверждаем («Обратить» от («Обратить» от а)) равен а
```

```
утверждение «двойное обращение возвращает список» — объявлено, не доказано: ни теоремы, ни примеров …
```

Утверждение верное. «Не доказано» значит, что у ядра не нашлось правила.

## Что во flang нельзя записать

Утверждение для любого типа элементов. Функция с параметром типа пишется,
утверждение о ней — нет. Файл
`docs/examples/proofs/unsupported/append-any-type.flang`:

```flang refused insert docs/examples/proofs/unsupported/append-any-type.flang
модуль «Append of any type»

тотальная функция «Склеить» от «А»
  принимает первый: список «А», второй: список «А»
  возвращает список «А»
  разбор первый
    случай пусто
      то второй
    случай голова и хвост
      то приписать голова к («Склеить» от хвост и второй)

утверждение «склейка сочетательна»
  для всех а: список «А» и б: список «А» и ц: список «А»
  утверждаем («Склеить» от («Склеить» от а и б) и ц) равен («Склеить» от а и («Склеить» от б и ц))
```

```
FLANG_UNKNOWN_NAME в файле append-any-type.flang, строка 13, столбец 12: неизвестный тип «А»
…
```

Строка `для всех` не умеет вводить параметр типа. То же утверждение для списка
чисел доказано выше.

Функция Аккермана. Её завершение следует из порядка на парах аргументов, а
flang ищет один аргумент, который уменьшается при каждом вызове. Файл
`docs/examples/proofs/unsupported/ackermann.flang`:

```flang refused insert docs/examples/proofs/unsupported/ackermann.flang
модуль «Ackermann»

тотальная функция «Аккерман»
  принимает м: число, н: число
  возвращает число
  если м не больше 0
    то н плюс 1
    иначе если н не больше 0
      то «Аккерман» от (м минус 1) и 1
      иначе «Аккерман» от (м минус 1) и («Аккерман» от м и (н минус 1))
```

```
FLANG_NOT_TOTAL в файле ackermann.flang, строка 9, столбец 10: в цикле «Аккерман» нет
аргумента, который убывает на каждом обходе …
```

Без слова `тотальная` функция проходит проверку и запускается. Её завершение
остаётся недоказанным.
