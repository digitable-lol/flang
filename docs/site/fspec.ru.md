# Спеки: бизнес-правило, которое доказано

Спека здесь — не документ рядом с кодом, а строка в программе. Правило
записано при функции словом `обеспечивает`, и компилятор доказывает его для
всех входов. Разойтись с кодом такая спека не может: изменили функцию так, что
правило перестало выполняться, — проверка не пройдёт.

Пример на странице — API маркетплейса из трёх служб и шлюза,
`docs/examples/web/marketplace/`.

## Как выглядит правило

Функция из службы корзины (`cart.flang`):

```flang
тотальная функция «Скидка в процентах»
  принимает сумма: число
  возвращает число
  для всех сумма обеспечивает «скидка бывает только нулевая, пятипроцентная или десятипроцентная» ((результат равен 0) или (результат равен 5)) или (результат равен 10)
  пример «мелкая покупка без скидки»
    дано сумма равно 100000
    ожидается 0
  пример «от пяти тысяч — пять процентов»
    дано сумма равно 500000
    ожидается 5
  пример «от двадцати тысяч — десять процентов»
    дано сумма равно 2000000
    ожидается 10
  если сумма не меньше 2000000
    то 10
    иначе (если сумма не меньше 500000 то 5 иначе 0)
```

| часть | что это | чем проверяется |
|---|---|---|
| `обеспечивает «имя» цель` | правило о результате | компилятор доказывает для всех входов; не смог — говорит об этом в отчёте |
| `требует «имя» условие` | условие на вход | проверяется при вызове; нарушение — отказ `FLANG_PRECONDITION` |
| `пример … ожидается …` | образец | прогоняется при каждой проверке файла |
| `тотальная` | функция завершается на любом входе | компилятор доказывает |

Имя правила — то, по чему оно находится в отчёте и сверяется между спеками.

Правило записано перечислением значений, а не границей «скидка не больше
десяти». Границу выполняет и функция, которая всегда возвращает ноль; такое
правило об этой функции ничего не говорит.

## Как проверить

```
flang check docs/examples/web/marketplace/orders.flang --proof
```

```
что высказано и чем это несётся:
  постусловие «из конечного состояния переходов нет» функции «Переходы из» — доказано индукцией по «Состояние заказа»: база 6 случаев, шаг при допущении на частях (0 случаев) — утверждение обо ВСЕХ входах типа «Состояние заказа», а не о написанных
  постусловие «из конечного состояния не разрешён никакой переход» функции «Переход разрешён» — сетка 4 значения (примеры функции): нарушений на них нет: проверка прогнала каждый пример и посчитала постусловие на его ответе. Это не доказательство — теоремы при утверждении нет
  постусловие «у состояния есть непустое название» функции «Название состояния» — доказано индукцией по «Состояние заказа»: база 6 случаев, шаг при допущении на частях (0 случаев) — утверждение обо ВСЕХ входах типа «Состояние заказа», а не о написанных

итог:
  функций 7: тотальных 7, обычных 0
  утверждений 3: доказано 2 (из них индукцией 2), сетка 1, объявлено, не доказано 0 (шагов в термах 12)
```

Код возврата 3: одно утверждение не доказано. У каждого утверждения в отчёте
одно из четырёх слов:

| слово | что значит |
|---|---|
| **доказано** | верно для всех входов |
| **сетка N** | посчитано на N примерах автора; это не доказательство |
| **объявлено, не доказано** | доказательства нет, примеров тоже |
| **НАРУШЕНО** | найден вход, на котором утверждение ложно |

Два утверждения доказаны индукцией по типу. Состояния заказа объявлены
вариантами, и доказательство разбирает каждый:

```flang
тип «Состояние заказа»
  вариант «Создан»
  вариант «Оплачен»
  вариант «Собран»
  вариант «Отправлен»
  вариант «Получен»
  вариант «Отменён»
```

Будь состояние строкой (`"paid"`, `"shipped"`), разобрать все случаи было бы
нельзя: строк бесконечно много.

Третье утверждение осталось на сетке. Тело «Переход разрешён» сворачивает не
сам параметр, а список, вычисленный из него (`«Переходы из» от откуда`), и
индукции по параметру ядру не за что зацепиться.

`flang check` без `--proof` на том же файле отвечает «замечаний нет» и кодом 0:
вердикты утверждений он не показывает.

Шлюз принимает текст HTTP-запроса и возвращает текст ответа:

```flang fragment

  вариант «Запрос негоден»
  вариант «Нет такого»
  вариант «Метод не тот»

```
  постусловие «код ответа из объявленного набора» функции «Код исхода» — доказано индукцией по «Исход»: база 9 случаев, шаг при допущении на частях (0 случаев) — утверждение обо ВСЕХ входах типа «Исход», а не о написанных
  постусловие «пояснение кода непусто» функции «Код исхода» — доказано индукцией по «Исход»: база 9 случаев, шаг при допущении на частях (0 случаев) — утверждение обо ВСЕХ входах типа «Исход», а не о написанных

Для клиента службы это значит: кодов ответа ровно столько, сколько в наборе;
кода 500 среди них нет; у каждого кода есть пояснение. Клиенту достаточно
разобрать перечисленные коды.

## Что будет, если правило нарушить

Поменяем в таблице кодов шлюза одну строку: пусть «Товара не хватает» отвечает
не 409, а 500.

```
flang check docs/examples/web/marketplace/gateway.flang --proof
```

```
FLANG_PROOF_STEP, строка 101, столбец 10: шаг 1, база «Товара не хватает» теоремы «код ответа из объявленного набора»: пример «товара не хватает — четыреста девять» не проходит: нарушено свойство «код ответа из объявленного набора» функции «Код исхода». Утверждение на этом значении неверно, значит случай им не закрывается. к этому месту не известно ничего, кроме гипотез «дано»
FLANG_PROOF_STEP, строка 125, столбец 10: шаг 1, база «Товара не хватает» теоремы «пояснение кода непусто»: пример «товара не хватает — четыреста девять» не проходит: нарушено свойство «код ответа из объявленного набора» функции «Код исхода». Утверждение на этом значении неверно, значит случай им не закрывается. к этому месту не известно ничего, кроме гипотез «дано»
docs/examples/web/marketplace/gateway.flang: не проверено — ведомость не печатается у программы с замечаниями
```

Код возврата 1. Перед каждым замечанием компилятор добавляет строку о том, что
место названо без имени файла; здесь она опущена.

Так же ловится испорченный пример. Поменяем в каталоге ожидаемое значение:
пусть из остатка 5 при запросе 2 выдаётся 3.

```
flang check docs/examples/web/marketplace/catalog.flang --proof
```

```
FLANG_EXAMPLE: пример «остатка хватает» функции «Сколько выдать»: значение не совпало с ожидаемым: ожидалось 3, получено 2
docs/examples/web/marketplace/catalog.flang: не проверено — ведомость не печатается у программы с замечаниями
```

## Второе правило не должно отменить первое

Правила копятся. Каталог `fspec/spec/` — 43 спеки предметной области, и новая
спека подключает ту, на которую опирается, строкой `использует`. Проверка
каталога отвечает на вопрос, которого `flang check` одного файла не видит:
осталось ли прежнее правило доказанным после того, как пришло новое.

```
flang run-script specs:check
```

Сейчас команда отвечает `бед в системе спек: 78` и кодом 1. 69 замечаний из 78
одного вида: отчёт `check --proof` не содержит утверждений подключённых
модулей, поэтому проверка не находит у новой спеки утверждение прежней. Она
краснеет на каждой спеке с `использует`, а не только на настоящей отмене
правила.

Как устроен каталог, что именно он сверяет и что из этого сейчас не
работает — на странице [Каталог спек](spec-catalog.html).

## Правило на другом языке

Утверждение можно повторить на языке тех, кто его читает. Метка языка стоит в
имени:

```flang fragment
обеспечивает «zh: 折扣不超过 30» результат не больше 30
```

Это отдельное утверждение, оно доказывается наравне с остальными. Проверка
каталога сверяет, что цель у перевода та же, что у основного утверждения. Сам
перевод она не читает: неверно переведённое имя при верной цели пройдёт.
