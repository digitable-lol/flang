# Первая программа

Две дороги: собрать компилятор из C и не знать про Node вовсе — или подключить
интерпретатор к своему проекту на Node. Здесь обе, компилятор первым.

```bash
git clone https://github.com/digitable-lol/flang.git
cd flang
make -C bootstrap
```

Нужны `cc` и `make`, больше ничего: ни Node, ни npm, ни сети. Замер сборки:
**30,7 с** при `make -j4` под `-O2 -flto`; на входе 9,68 МБ напечатанного C, на
выходе `bootstrap/flang_cli` — 5,1 МиБ, связанный только с `libc` и `libm`.

## Написать программу

Положите в файл `hello.flang`:

```
модуль «Привет»

тотальная функция «Удвоить»
  принимает н: число
  возвращает число
  обеспечивает «удвоенное не меньше исходного» результат не меньше н
  пример «Дважды два»
    дано н равно 2
    ожидается 4
  н плюс н
```

Здесь пять вещей, и каждая делает свою работу:

- **`тотальная`** — обещание, что функция завершается на любом входе. Компилятор
  его **проверяет** и откажется собирать файл, если доказать не сможет.
- **`принимает` / `возвращает`** — типы. Проверяются статически.
- **`обеспечивает`** — постусловие: что верно про результат. Не для всех входов,
  которые вы придумали, а **для всех вообще**, если ядро сумеет это доказать.
  Утверждение **называется** — имя в ёлочках обязательно, по нему его потом
  находят в ведомости.
- **`пример`** — исполняемый пример. Он часть программы, а не тест сбоку, и
  прогоняется при каждой проверке.
- последняя строка — тело.

## Проверить

```bash
./bootstrap/flang_cli check hello.flang
```

```
модуль «Привет»: функций 1, из них с доказанным завершением 1; типов 0
hello.flang: проверено — разбор, типы, завершаемость; замечаний нет
```

## Запустить

```bash
./bootstrap/flang_cli run hello.flang --function Удвоить --args '{"н": 21}'
```

```
42
```

Считает сам двоичный: вычислитель втащен в него, Node не нужен. Проверено
прогоном под `env -i PATH=/nonexistent` — интерпретатора на машине не достать
физически, ответ тот же.

Имя функции здесь **без ёлочек**: в объявлении они часть записи, а в командной
строке — уже нет.

## Попробовать вживую

```bash
./bootstrap/flang_cli repl
```

Оболочка вычислитель пока не зовёт: она печатает сессию в C и собирает её тем же
`cc`, которым вы только что собрали компилятор. Если `cc` нет, она не
выключается, а проверяет разбор, типы и завершаемость и говорит об этом строкой
«вычислять нечем».

## Прогнать примеры

```bash
./bootstrap/flang_cli test hello.flang
```

```
hello.flang: примеров 1, прошло 1, не прошло 0
```

Примеры — часть программы, а не тест сбоку, и `check` считает их и без `test`.

## Ведомость доказательства

```bash
./bootstrap/flang_cli check hello.flang --proof
```

Ядро пробует **доказать** постусловие — показать, что оно верно на всех входах, а
не только на двойке из примера. Ведомость называет, чем несётся каждое обещание, и
слова в ней не взаимозаменяемы:

- **доказано** — утверждение обо всех входах, выведенное из объявлений и структуры;
- **сетка N** — посчитано на N значениях автора. **Это не доказательство**, и
  ведомость говорит это прямо;
- **объявлено, не доказано** — ядру не хватило правил. Утверждение при этом
  считается во время работы, на тех входах, которые придут.

## Напечатать в C

Каталог вывода `emit` не заводит — создайте его сами:

```bash
mkdir -p ./вывод
./bootstrap/flang_cli emit hello.flang --target c --out ./вывод \
    --runtime flang/src/emit/c
make -C ./вывод
```

Шесть файлов, и они собираются тем же `cc` без единого предупреждения. Рантайм C
двоичный читает с диска: путь задаёт `--runtime` или `$FLANG_RUNTIME_DIR`.

## Границы двоичного

`check`, `test`, `run`, `repl`, `emit --target c` и ведомость — всё это в
двоичном есть. Границы у него другие, и он называет их сам, а не молчит.

**Ведомость не ищет нарушений по примерам.** Двоичный примеры считает, но не
прогоняет ради поиска: в его ведомости стоит «нарушений НЕ ИСКАЛИ — прогона
примеров не было, посчитано только их число», тогда как эталон на том же файле
пишет «нарушений не найдено (искали прогоном на всех 1)». Разница в словах —
разница в силе утверждения.

**Законов на сетке двоичный не считает.** Моноид, монада, изоморфизм, категория,
множества, связь и пять объявленных свойств считаются вычислением на сетке, и
этого слоя в двоичном нет. Программа с таким объявлением получает отказ с
названным препятствием, а не зелёную ведомость с пустым разделом.

**Целей печати у двоичного одна.** `c` — и всё; остальные семь целей (`csharp`,
`elixir`, `go`, `java`, `js`, `python`, `rust`) остались у эталона. Двух вещей
нет и у самой печати в C: недостижимое не отбрасывается, доказанное не метится
(`markProven`). На компиляторе это 6 файлов из 7 байт в байт.

**Оболочка `repl` вычислитель не зовёт.** Она печатает сессию в C и собирает её
тем же `cc`, которым вы собрали компилятор. Нет `cc` — оболочка не выключается, а
проверяет разбор, типы и завершаемость и говорит об этом строкой «вычислять
нечем».

## Где двоичный расходится с эталоном

Не «чего-то не умеет», а **отвечает иначе**, и это опаснее: неумение видно,
расхождение — нет. Место такое сегодня одно, и двоичный сам предупреждает о нём
при печати.

**У напечатанной программы граница входа пуста.** Таблицу объявленных типов
строит слой типов эталона, которого в двоичном нет, поэтому аргументы прогонщика
объявленным типам **не сверяются**. Напечатанное соберётся и заработает, но за
вход отвечает вызывающий. Сам двоичный при этом аргументы сверяет: `Факториал`
объявлен на типе `нат`, и на −3 он отвечает
`FLANG_TYPE: вызов функции «Факториал»: аргумент «н»: -3 вне нат` с кодом 1 —
тем же кодом, каким это делает эталон.

На разрешённых входах двоичный и эталон сходятся — прогон трёх программ корпуса
без Node: `Факториал(12) = 479001600`, `Фибоначчи(20) = 6765`,
`Палиндром("шалаш") = true`. Печатают по-разному: двоичный — голое значение,
интерпретатор — JSON с именем функции и аргументами.

## Второй уклад: интерпретатор на Node

Двоичный — для тех, кто **ставит язык**. Интерпретатор — для тех, кто
**встраивает его в существующий проект**: правила лежат рядом с кодом, который их
применяет, и зовутся из него же. Ставить нечего — внешних зависимостей ноль,
`npm install` не нужен.

Он же нужен, когда нужно то, чего в двоичном нет: семь остальных целей печати,
законы на сетке, суждения и поиск нарушений по примерам.

Сегодня на нём держится и вся оснастка вокруг языка: проверки дерева, сборка
этого сайта, сторожа чисел (`npm run counts:check`) и языковой сервер.

### Напечатать в остальные семь целей

```bash
node flang/bin/flang.mjs emit hello.flang --target rust --out ./вывод-rust
```

Целей восемь: `c`, `csharp`, `elixir`, `go`, `java`, `js`, `python`, `rust`.
Напечатанный код обязан выдавать **те же значения и те же коды ошибок**, что
интерпретатор — это проверяется побайтово на всём корпусе, а не декларируется.

### Ведомость с поиском нарушений

```bash
node flang/bin/flang.mjs check hello.flang --proof --pretty
```

Та же ведомость, что у двоичного, но сетка не только считается, а **прогоняется**:
вместо «не искали» — «нарушений не найдено (искали прогоном на всех 1)».
