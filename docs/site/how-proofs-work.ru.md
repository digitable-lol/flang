# Как это доказывается
<!-- замер: версия 0.7.34 · дерево 001d8df7c · сверено 2026-11-10 -->

Компилятор проверяет три вида утверждений о функции:

| Пишете | Привычный термин | Что это значит | Где проверяется |
| --- | --- | --- | --- |
| `тотальная` | termination | функция завершается на любом входе | в самой функции |
| `требует` | precondition | что должно быть верно на входе | в каждой точке вызова и на входе в программу |
| `обеспечивает` | postcondition | что функция гарантирует на выходе | для всех входов, а не только для примеров |

Ниже каждое показано на маленьком файле с выводом `flang {{выпуск.версия}}`.
Длинные строки вывода перенесены, `…` отмечает пропуск. В выводе компилятора
«ядро» — это prover, часть компилятора, которая доказывает постусловия, а
`сторож` — проверка, которую компилятор добавляет в сгенерированный код.

## Завершаемость

Рекурсивный вызов получает часть входа — хвост списка. Часть меньше целого,
списки конечны, поэтому рекурсия кончается:

```flang
модуль «Спуск»

тотальная функция «Сумма списка»
  принимает ряд: список числа
  возвращает число
  разбор ряд
    случай пусто
      то 0
    случай голова первый и хвост остальные
      первый плюс («Сумма списка» от остальные)
```

```
$ flang check --proof spusk.flang
  «Сумма списка»  доказано структурой: аргумент 1 («ряд») на каждом витке
  становится частью себя; цепочка частей конечного дерева обрывается сама,
  сторожа нет
```

Когда рекурсия отсчитывает вниз число, исход зависит от типа:

```flang
модуль «Отсчёт»

тотальная функция «Обратный отсчёт»
  принимает н: число
  возвращает число
  если н не больше 0
    то 0
    иначе 1 плюс («Обратный отсчёт» от (н минус 1))
```

```
$ flang check --proof otschyot.flang
  «Обратный отсчёт»  доказано постоянным шагом: аргумент 1 («н») убывает на
  постоянный шаг и ограничен снизу; на IEEE-754 шаг не всегда меняет число,
  поэтому сторож, 1 место
```

`число` — это float binary64, и выше 2⁵³ вычитание единицы его не меняет.
Поэтому в сгенерированном коде остаётся одна проверка. Замените тип на
`неотрицательное` (отрезок [0, 2⁵³−1], вычитание единицы в нём точное) — и
проверка уходит:

```
  «Обратный отсчёт»  доказано точным шагом: аргумент 1 («н») объявлен
  натуральным и убывает на 1; дно и потолок даёт тип, внутри потолка шаг точен
  — сторожа нет
```

Если убывает не сам аргумент, а выражение от аргументов, назовите его строкой
`убывает`:

```flang
модуль «Мера»

тотальная функция «Шагов до края»
  принимает место: число, край: число
  возвращает число
  убывает край минус место
  если место не меньше край
    то 0
    иначе 1 плюс («Шагов до края» от (место плюс 1) и край)
```

```
  «Шагов до края»  доказано объявленной мерой: убывает «край» минус «место»;
  спуск ядром не выведен — на веру: мера объявлена автором, сторож считает её
  при работе на каждом витке — 1 место
```

Функция, у которой завершение не доказано, — ошибка, а не предупреждение:

```flang refused
модуль «Растёт»

тотальная функция «До нуля»
  принимает н: число
  возвращает число
  если н равен 0
    то 0
    иначе «До нуля» от (н плюс 1)
```

```
$ flang check rastyot.flang; echo "код $?"
модуль «Растёт»: функций 1, из них с доказанным завершением 0; типов 0
без доказанного завершения: «До нуля»
FLANG_NOT_TOTAL в файле rastyot.flang, строка 8, столбец 11: тотальная функция
«До нуля»: рекурсивный вызов «До нуля» не убывает — аргумент 1 («н» add 1)
увеличивает параметр «н». Передавайте часть аргумента: хвост списка из образца
«голова и хвост», поле варианта из образца, поле записи или элемент коллекции
rastyot.flang: не проверено — замечаний 1
код 1
```

Если функция и правда может работать вечно, уберите у неё `тотальная`.
Блок `цикл` завершаемости не обходит: компилятор разворачивает его в свёртку
или в тотальную функцию и проверяет развёрнутое.

## `требует`: предусловие

Предусловие доказывает не функция, а тот, кто её зовёт:

```flang refused
модуль «Заказ»

тотальная функция «Цена со скидкой»
  принимает цена: неотрицательное, скидка: неотрицательное
  требует «скидка не больше цены» скидка не больше цена
  возвращает число
  цена минус скидка

тотальная функция «Счёт»
  возвращает число
  «Цена со скидкой» от 100 и 150
```

```
$ flang check zakaz.flang; echo "код $?"
модуль «Заказ»: функций 2, из них с доказанным завершением 2; типов 0
FLANG_PRECONDITION_CALL в файле zakaz.flang, строка 11, столбец 3: вызов «Цена
со скидкой» в функции «Счёт» не снимает предусловие «скидка не больше цены»:
… вызывающему здесь известно: собственных «требует» — 0, объявленных типов у
параметров — 0, доказанных обещаний вызванных в доводе — 0; условие ветвления
фактом ядру не является (граница названа в шапке файла)
zakaz.flang: не проверено — замечаний 1
код 1
```

Конец сообщения перечисляет, откуда вызывающий может взять нужный факт: его
собственное `требует`, объявленный тип его параметра, доказанное постусловие
функции, которая посчитала аргумент. С собственным `требует` файл проходит:

```flang
модуль «Заказ»

тотальная функция «Цена со скидкой»
  принимает цена: неотрицательное, скидка: неотрицательное
  требует «скидка не больше цены» скидка не больше цена
  возвращает число
  цена минус скидка

тотальная функция «Счёт»
  принимает цена: неотрицательное, скидка: неотрицательное
  требует «скидка по карману» скидка не больше цена
  возвращает число
  «Цена со скидкой» от цена и скидка
```

Вызовы внутри программы проверены при компиляции, и проверки во время работы у
них нет. Она стоит в одном месте — на входе, куда данные приходят снаружи:

```
$ flang run zakaz.flang --function 'Цена со скидкой' --args '{"цена": 100, "скидка": 150}'
FLANG_PRECONDITION: не выполнено требование «скидка не больше цены» функции «Цена со скидкой»
$ echo $?
1
```

Пример, вход которого нарушает `требует`, отвергает `flang check`:

```
FLANG_EXAMPLE: пример «скидка больше цены» функции «Цена со скидкой»:
FLANG_PRECONDITION: не выполнено требование «скидка не больше цены» функции
«Цена со скидкой»
```

## `обеспечивает`: постусловие и три ответа

На каждое постусловие prover отвечает одним из трёх слов. В этом файле есть все
три:

```flang
модуль «Три ответа»

тотальная функция «Цена со скидкой»
  принимает цена: неотрицательное, скидка: неотрицательное
  требует «скидка не больше цены» скидка не больше цена
  возвращает число
  обеспечивает «в минус не уходим» результат не меньше 0
  пример «сто минус десять»
    дано цена равно 100
    дано скидка равно 10
    ожидается 90
  цена минус скидка

тотальная функция «Удвоить»
  принимает х: целое
  возвращает число
  обеспечивает «результат чётный» (результат остаток от 2) равно 0
  пример «единица»
    дано х равно 1
    ожидается 2
  х умножить на 2

тотальная функция «Утроить»
  принимает х: целое
  возвращает число
  обеспечивает «результат кратен трём» (результат остаток от 3) равно 0
  х умножить на 3
```

```
$ flang check --proof tri.flang; echo "код $?"
  постусловие «в минус не уходим» функции «Цена со скидкой» — доказано по
  объявленным типам аргументов: цель сведена правилом «неотрицательность по
  построению» — утверждение обо ВСЕХ входах, а не о написанных; теоремы при
  нём нет и не нужно
  постусловие «результат чётный» функции «Удвоить» — сетка 1 значение (примеры
  функции): нарушений на них нет: проверка прогнала каждый пример и посчитала
  постусловие на его ответе. Это не доказательство — теоремы при утверждении нет
  постусловие «результат кратен трём» функции «Утроить» — объявлено, не
  доказано: ни теоремы, ни примеров. Его считает рантайм после каждого
  возврата — на тех входах, которые придут
…
  утверждений 3: доказано 1 (из них без теоремы 1, объявленным типом 1),
  сетка 1, объявлено, не доказано 1
код 3
```

| В отчёте | Что это значит | Во время работы |
| --- | --- | --- |
| «доказано» | верно для всех входов | проверки нет |
| «сетка N» | прошло на N примерах функции, как unit-тест; о прочих входах ничего | проверка при каждом возврате |
| «объявлено, не доказано» | нет ни доказательства, ни примеров | проверка при каждом возврате |

Два последних постусловия верны, но prover их не вывел. Считается только
«доказано»; как довести до него остальные —
[Что ядро доказывает само](what-the-kernel-accepts.html) и
[Доказательство руками](manual-proofs.html).

Коды возврата: `flang check` без ключей на этом файле даёт 0 — недоказанное
постусловие не ошибка. С `--proof` код 0 значит «доказано всё», 3 — «что-то не
доказано». `--proof --strict` даёт 3 ещё и там, где постусловий нет вовсе.

### Ложное постусловие

Уберите у «Цены со скидкой» строку `требует`. Постусловие станет ложным, и
компилятор сам находит вход, на котором оно нарушено:

```
$ flang check skidka.flang; echo "код $?"
модуль «Скидка»: функций 1, из них с доказанным завершением 1; типов 0
FLANG_EXAMPLE: FLANG_PROPERTY: постусловие «в минус не уходим» функции «Цена
со скидкой» нарушено на входе цена = 0, скидка = 1 — посчитано вычислителем на
этом входе
skidka.flang: не проверено — замечаний 1
код 1
```

### Недоказанное запускается только с согласия

```
$ flang run tri.flang --function 'Удвоить' --args '{"х": 3}'; echo "код $?"
не доказано: утверждений 3: доказано 1, сетка 1, на веру 1 — запуск только по
явному согласию: --на-веру
…
код 3
$ flang run tri.flang --function 'Удвоить' --args '{"х": 3}' --на-веру
на веру: доказанность не считалась — запуск по ключу --на-веру
6
```

Латиницей ключ пишется `--trust`.

### Доказанное уходит из сгенерированного кода

```
$ flang emit tri.flang --target c --out out
проверок при работе снято 1: постусловие доказано ядром обо всех входах и
проверено примерами функции — в напечатанный код оно не едет.
…
$ grep -c 'fl_post(' out/program.c
2
```

Две проверки — два недоказанных постусловия. У «Цены со скидкой» в C осталось
одно вычитание:

```c
fl_status tri_otveta_cena_so_skidkoy(fl_ctx *ctx, fl_value cena, fl_value skidka,
                                     fl_value *result, fl_error *error) {
  if (cena.tag != FL_NUMBER || skidka.tag != FL_NUMBER)
    FL_TRY(fl_not_numbers(ctx, "sub", cena, skidka, error));
  *result = fl_number(cena.as.number - skidka.as.number);
  return FL_OK;
}
```

Проверка снимается, когда постусловие доказано и у функции есть хотя бы один
пример: без примера `fl_post` остаётся и у доказанного.

## На настоящем модуле

Модуль списков стандартной библиотеки, полминуты:

```
$ flang check --proof flang/stdlib/lists.flang
  функций 38: тотальных 38, обычных 0
  обещание несёт: композиция 28, структура 8, точный шаг 1, постоянный шаг 1,
                  объявленная мера 0
  сторожей в рантайме: 1 место
  утверждений 66: доказано 42 (из них индукцией 5) (из них без теоремы 37),
                  сетка 24, объявлено, не доказано 0
```

* Завершение доказано у всех 38 функций: у 28 рекурсии нет («композиция»), 8
  идут по части входа, одна отсчитывает `неотрицательное`, одна — `число`, и это
  единственная проверка завершаемости во время работы.
* Из 66 постусловий 42 доказаны для всех входов, 37 из них без написанной
  теоремы. 24 прошли только на примерах.

```
$ flang emit flang/stdlib/lists.flang --target c --out out
$ grep -c 'fl_post(' out/lists.c
25
```

25 проверок = 24 недоказанных постусловия + 1 проверка завершаемости.

## Команды

| Команда | Что делает |
| --- | --- |
| `flang check <файл>` | синтаксис, типы, завершаемость, предусловия в точках вызова, примеры; код 1 при ошибке |
| `flang check --proof <файл>` | отчёт: чем доказаны завершение каждой функции и каждое постусловие; код 3, если что-то не доказано |
| `flang check --proof --strict <файл>` | то же, но код 0, только если постусловие есть хотя бы одно и все доказаны; для CI |
| `flang check <файл> --proof --record <запись>` | ещё и пишет [запись доказательства](record-format.html) для независимой проверки |
| `flang emit <файл> --target c --out <каталог>` | генерирует C; видно, какие проверки остались |
| `flang test <файл>` | прогоняет примеры |
