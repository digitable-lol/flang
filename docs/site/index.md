# Язык, в котором спецификация исполняется

Правило пишется **один раз**. Оно исполняется, проверяется своими же примерами,
доказывается компилятором **на всех входах** — и печатается в восемь языков, где
обязано вести себя знак в знак так же.

```
тотальная функция «Произведение»
  принимает элементы: список числа
  возвращает число
  пример «Произведение четырёх»
    дано элементы равно [1, 2, 3, 4]
    ожидается 24
  пример «Произведение пустого — единица»
    дано элементы равно пустой список
    ожидается 1
  свёртка элементы начиная с 1 как акк и эл → акк умножить на эл
```

Слово `тотальная` — не пожелание и не подсказка читателю. Компилятор **доказал**,
что эта функция завершается на любом входе, и отказался бы собрать файл, если бы
доказать не смог.

## Два уклада, и их важно не путать

Один исходник, две дороги, и ставятся они по-разному.

```mermaid Два уклада: печать в целевой язык или исполнение изнутри чужого проекта
flowchart LR
  S[исходник<br>на flang] --> C[компилятор]
  S --> R[интерпретатор]
  C --> T([печать в восемь целей<br>C, Go, Rust, Python<br>Java, C#, Elixir, JS])
  T --> B[собирается и работает<br>там, без flang]
  R --> H[исполняется внутри<br>чужого проекта]
  class S glavnoe
  class T vyvod
```

**Уклад первый — компилятор.** Программа печатается в один из восьми целевых
языков и дальше живёт его средствами: собирается его сборщиком, кладётся рядом с
его кодом. Node на этой дороге не нужен **вовсе**, в том числе чтобы собрать сам
компилятор.

**Уклад второй — интерпретатор.** flang подключается к уже существующему проекту
и исполняется изнутри другого языка — правила рядом с кодом, который их
применяет. Вот здесь нужен Node, и только здесь.

### Уклад первый: компилятор, без Node

Собирается из **точки раскрутки** — компилятора, напечатанного в самодостаточный
C99. Нужны только `cc` и `make`:

```bash
git clone https://github.com/digitable-lol/flang.git
cd flang
make -C bootstrap
./bootstrap/flang_cli check flang/examples/rosetta/factorial.flang
```

Компилятор языка **сам себя напечатал в C**, этот C собирается обычным `cc` без
единой зависимости, и получившийся компилятор печатает себя обратно — байт в байт
тем же. Проверено прогоном: [две реализации и неподвижная точка](two-implementations.html).

Двоичный умеет `check`, `run` и `repl`: вычислитель втащен в него, и программа
считается без Node. `test`, `emit` и `--proof` он не умеет. И одно расхождение,
которое надо знать до того, как на него наступишь: **аргументы объявленным типам
он не сверяет**, а эталон сверяет — `Факториал` от −3 двоичный посчитает и
ответит `1`, эталон откажет «−3 вне нат».

Формула Homebrew в дереве (`packaging/homebrew/flang.rb`) **пока не рабочая** —
её `sha256` сверять не с чем, релизного архива нет, и собственный тест дерева на
этом красный. Готовых сборок в релизах тоже пока нет.

### Уклад второй: интерпретатор, на Node

```bash
git clone https://github.com/digitable-lol/flang.git
cd flang
node flang/bin/flang.mjs check flang/examples/rosetta/factorial.flang --proof --pretty
```

Ставить нечего: `npm install` не нужен, внешних зависимостей у компилятора ноль.

Эта команда печатает **ведомость доказательства**: чем несётся обещание
`тотальная` у каждой функции и что именно доказано про результат. Дальше —
[первая своя программа](getting-started.html).

## Как программа проходит компилятор

`emit` зовёт ровно те же проверки, что и `check`; отказ на любом шаге
останавливает всё, что правее.

```mermaid Путь программы через компилятор: разбор, типы, завершаемость, доказательство, печать
flowchart TD
  I[исходник .flang] --> L[лексер и разбор<br>текст → токены → дерево]
  L --> S[связывание модулей]
  S --> T[типы<br>вывод и исчерпывающность]
  T --> Z{завершается<br>на всех входах?}
  Z -->|нет| O[отказ]
  Z -->|да| B[обязательства<br>что осталось доказать]
  B --> K[ядро доказательств<br>аксиом ноль]
  K --> V{вердикт}
  V -->|доказано| E([печать в восемь целей])
  V -->|сетка| E
  V -->|отвергнуто| O
  class K glavnoe
  class E vyvod
  class O otkaz
```

Три вердикта — не оттенки уверенности, а разные вещи, и ведомость называет их
разными словами. **Доказано** — про все входы. **Сетка** — нарушений не нашли,
прогнав по конечному набору значений; это **не** доказательство, и ведомость
говорит это прямо. **Отвергнуто** — терм предъявлен, и ядро его не приняло.

Подробнее: [зачем доказательства и как они устроены](proofs.html).

## Три вещи, которых нет у обычных языков

**Завершаемость доказана при компиляции.** В C, Python и JavaScript функция
может зациклиться, и вы узнаёте об этом в бою. Здесь `тотальная` — обещание, за
которое отвечает компилятор.

**Обещание о результате проверяется на всех входах, а не на примерах.** Тесты
покрывают те входы, до которых вы додумались. Постусловие, принятое ядром
доказательств, — все.

**Одна программа печатается в восемь языков с побайтово сверенным поведением.**
Не «должно совпадать», а проверено, что совпадает: значения, коды ошибок,
счётчики шагов. Цели: `c`, `go`, `rust`, `python`, `java`, `csharp`, `elixir`,
`js`.

## Чем это отличается от Coq, Agda и Lean

Те языки сильнее в доказательствах — и на них **не пишут сервисы**. Из Coq
программы *извлекают* в OCaml, потому что писать на нём приложение невозможно.

flang пробует закрыть эту пропасть: один язык, на котором и доказывают, и пишут
обычный код, и который при этом читается.

**Ядро доказательств не принимает на веру ничего.** Аксиом ноль, и список пуст
проверяемо — отдельным тестом, тихо добавить нельзя. Решающих правил три, и
каждое можно прочесть целиком.

## Где мы на самом деле

Числа ниже измеряются прогоном (`npm run proof:ledger`) и сверяются с ним
сторожем чисел (`npm run counts:check`) — протухнуть молча они не могут.

| | |
|---|---:|
| В корпусе | **тотальных функций 5929 из 7708** |
| О поведении | **высказано 152 утверждения** |
| Доказано про все входы | **131 доказаны ядром** |
| Посчитано на сетке — не доказано | **20 идут сеткой** примеров |
| Высказано, но не доказано | **1 объявлено и не доказано** |
| Аксиом в ядре | **0** |
| Утверждений, отвергнутых ядром | **0** |

И честно про то, чего нет:

- **обычных функций библиотеки доказывается 7 из 20** — замер брал каждую девятую
  из всех 185, чтобы не выбирать удобные;
- **язык медленнее Python в 1,4 раза**, и это **не цена доказуемости**: она
  измерена и равна 2,5 % — платит 71 функция из 2799. Остальное — обычная
  неоптимизированность, и она чинится;
- **компилятор написан на flang не целиком**: цепочка доказательства — да, а
  восемь генераторов кода, процессы, оболочка — пока нет.

Граница между «доказано» и «проверено» проведена явно и держится прогоном:
[что доказано, а что проверено](overview.html).
