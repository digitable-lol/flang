## Словарь: слова flang и привычные термины

| Во flang | Привычное название | Ближайший аналог |
| --- | --- | --- |
| `тип` с `вариант`ами | enum с данными, tagged union | `enum` в Rust, union в TypeScript |
| `разбор … случай` | pattern matching | `match` в Rust и Python |
| `если … то … иначе` | if как выражение | тернарный оператор |
| `пусть` | константа | `const` |
| `отобразить`, `отфильтровать`, `свёртка` | map, filter, reduce | то же в JavaScript и Python |
| `объект` и `запись` | структура с полями и её значение | dataclass, interface |
| `пример` | unit-тест прямо в функции | doctest |
| `требует` | precondition: что должно быть верно на входе | assert в начале функции |
| `обеспечивает` | postcondition: что функция гарантирует на выходе | assert в конце, но проверенный для всех входов |
| `тотальная функция` | функция, про которую компилятор доказал, что она всегда завершается | — |
| `теорема` | доказательство, которое вы пишете сами | — |
| `план` | side effects: функция возвращает команду («прочитай файл»), рантайм выполняет её и вызывает функцию снова с ответом | reducer, state machine |

**Prover** — часть компилятора, которая доказывает `обеспечивает` для всех
возможных входов, а не только для ваших примеров. В выводе компилятора он
называется «ядро», а строка `обеспечивает` — «постусловие».

## Как читать примеры

Большая часть примеров ниже — целые программы, и каждая проходит команду:

```bash
flang check файл.flang
```

Где это не так, сказано в тексте. Куски без строки `модуль` показывают одну
форму, а не программу. Примеры категорий, монад и процессов завершаются **кодом
2**, а не 0: разбор, типы, завершаемость и примеры проходят, но правила самих
этих объявлений двоичный компилятор не проверяет и пишет об этом в выводе.

Блоки без подсветки — то, что компилятор **печатает**: ошибки и отчёты. Слово в
начале строки (`FLANG_TYPE`, `FLANG_PROOF_STEP`) — код ошибки; каждый код
объяснён в [Справочнике отказов](diagnostics.html).

У каждого ключевого слова есть русское и английское написание (всего написаний
четыре, они называются поверхностями). Это одно и то же слово, а не перевод: оба
дают одно дерево разбора, и в одном файле можно писать любым. Понятий —
{{словарь.понятий}}; полный список с четырьмя написаниями —
[Словарь языка](glossary.html), как устроены написания —
[Четыре поверхности записи](surfaces.html).

Имена — модулей, функций, типов, примеров, постусловий — пишутся в ёлочках
`«…»` при любом написании ключевых слов.

### Что набирается несколькими способами

Стрелка набирается `→`, `->` или `=>` — это одно и то же. Ниже везде стоит `→`;
на клавиатуре её искать не надо.

| Знак | Как ещё набирается | Где стоит |
| --- | --- | --- |
| `→` | `->`, `=>` | свёртка, `отобразить`, `отфильтровать`, тип функции |
| `"текст"` | `'текст'` | литерал строки |
| `:` `(` `,` и прочие знаки препинания | полноширинные `：` `（` `，` | китайская раскладка ставит их на тех же клавишах |

Слова языка тоже бывают с несколькими написаниями: `объект` и `структура`,
`свёртка` и `свертка`, `равен`, `равна`, `равно`, `равным`, `равной`, `равное`.
Все написания каждого слова перечислены в [Словаре](glossary.html) — по столбцу
на поверхность, все в одной клетке через запятую. Знаков в словаре нет: там
только слова.

## Модуль и импорт

| Строка | Что делает |
| --- | --- |
| `модуль «Имя»` | первая строка файла, обязательна |
| `экспортирует «А», «Б»` | что видно снаружи; без строки видно всё |
| `использует «Модуль»` | импорт всех имён модуля |
| `использует … только «А», «Б»` | импорт названных имён — с оговоркой ниже |
| `использует «Модуль» из "путь"` | то же, но файл назван прямо |

```flang
модуль «Отчёт»
  экспортирует «Итог»
  использует «Lists»

тотальная функция «Итог»
  принимает элементы: список числа
  возвращает число
  пример «повторы не считаются дважды»
    дано элементы равно [3, 1, 3, 2, 1]
    ожидается 6
  «Сумма» от («Уникальные» от элементы)
```

**Без нужды `только` не пишите.** Оно не просто прячет имена: чего нет в
списке, того **нет в программе вовсе**. А импортированные функции вызывают
другие функции своего модуля — в теле и в постусловиях. Замените третью строку
примера выше на `использует «Lists» только «Сумма», «Уникальные»` — и проверка
не проходит:

```
модуль «Отчёт»: функций 3, из них с доказанным завершением 0; типов 0; файлов вместе с импортами 2
без доказанного завершения: «Сумма» «Уникальные» «Итог»
место указано строкой и столбцом, но без файла: вместе с импортами проверено файлов 2, а диагностика компилятора имени файла не несёт
FLANG_UNKNOWN_NAME, строка 460, столбец 47: неизвестная функция «Шаг суммы»
FLANG_UNKNOWN_NAME, строка 453, столбец 74: неизвестная функция «Все не меньше»
FLANG_UNKNOWN_NAME, строка 453, столбец 130: неизвестная функция «Максимум»
FLANG_UNKNOWN_NAME, строка 564, столбец 59: неизвестная функция «Шаг уникальных»
FLANG_NOT_TOTAL, строка 460, столбец 47: тотальная функция «Сумма» вызывает неизвестную функцию «Шаг суммы»: завершение доказать нельзя
FLANG_NOT_TOTAL, строка 564, столбец 59: тотальная функция «Уникальные» вызывает неизвестную функцию «Шаг уникальных»: завершение доказать нельзя
tolko.flang: не проверено — замечаний 6
```

Номера строк указывают в `flang/stdlib/lists.flang`. Строка 453 — постусловие самой `«Сумма»` («сумма
неотрицательных не меньше наибольшего из них»), оно вызывает `«Все не меньше»`
и `«Максимум»`; строка 460 — тело `«Сумма»`, оно вызывает `«Шаг суммы»`;
строка 564 — тело `«Уникальные»`. `только` все их выбросило. Тот же файл с
обычным `использует «Lists»` проходит с кодом 0.

Пути в `использует` нет: **модуль ищется по имени**. Имя — это то, что стоит первой
строкой файла в `модуль «Lists»`; имя файла и его каталог роли не играют, и
переложенный в другой каталог модуль продолжает находиться.

Ищут в трёх местах и в таком порядке:

1. каталог самого файла, который пишет `использует`;
2. каждый каталог выше него — пока в каталоге лежит хоть один файл `.flang`;
3. библиотека, поставленная вместе с компилятором.

В подкаталоги поиск не заходит. Для модуля в другом месте перечислите его
каталог в `FLANG_MODULE_DIR` (каталоги через двоеточие) или назовите файл прямо:
`использует «Модуль» из "путь"`. Путь считается от импортирующего файла и
годится и для пакета: `из "имя.flang-package"`.

Если найдено два модуля с одним именем, проверка не проходит и называет оба
пути; молча компилятор не выбирает.

Ограничение: имена модулей не переводятся. Стандартный модуль списков называется
`«Lists»` (первая строка `flang/stdlib/lists.flang`), и файл с русскими
ключевыми словами импортирует его под этим же именем. `использует «Списки»`
даёт `FLANG_IMPORT_NOT_FOUND`.

## Функция

Части идут в закреплённом порядке. Тело — последним, одним выражением.

| Часть | Обязательна | Что значит |
| --- | --- | --- |
| `тотальная` | нет | функция всегда завершается; компилятор это доказывает |
| `функция «Имя»` | да | объявление |
| `принимает имя: тип, имя: тип` | нет | параметры; типы обязательны |
| `возвращает тип` | да | тип результата |
| `требует «имя» условие` | нет | precondition; выполнить его обязан **вызывающий** |
| `убывает выражение` | нет | мера завершения: число, которое уменьшается на каждом рекурсивном вызове |
| `для всех п обеспечивает «имя» условие` | нет | postcondition о `результат` |
| `пример «имя»` / `дано` / `ожидается` | нет | unit-тест: аргументы и ожидаемый результат |

```flang
модуль «Подпись»

тотальная функция «Доля»
  принимает часть: неотрицательное, всего: неотрицательное
  возвращает число
  требует «делитель положителен» всего больше 0
  для всех часть обеспечивает «доля неотрицательна» результат не меньше 0
  пример «половина»
    дано часть равно 1
    дано всего равно 2
    ожидается 0.5
  часть делить на всего
```

Вызов — `«Имя» от аргумент и аргумент`. Слово `и` разделяет аргументы;
логическое И пишется `и притом`, чтобы они не путались.

Ограничения:

- в сгенерированном коде `требует` проверяется только на границе программы, там,
  куда значение приходит снаружи. Внутренние вызовы за проверку не платят;
- у `обеспечивает` обязательно имя: под этим именем результат виден в отчёте
  `flang check --proof`, по нему на постусловие ссылается теорема;
- примеры прогоняются при **каждой** проверке. Упавший пример — ошибка
  `FLANG_EXAMPLE`, и код для программы не генерируется.

## Тотальность и мера

Завершение функции с `тотальная` компилятор доказывает одним из пяти способов.
Первые три ничего не стоят при работе, последние два добавляют проверку в
сгенерированный код. Какой способ сработал у какой функции — в отчёте
`flang check --proof`; счёт по всему репозиторию — на странице
[Зачем и как](proofs.html).

| Способ | Когда берётся |
| --- | --- |
| композицией | рекурсии нет вовсе |
| структурой | `разбор` вызывает рекурсию на части значения |
| точным шагом | параметр `неотрицательное`, спуск на постоянную |
| постоянным шагом | то же на `число`, с проверкой при работе |
| объявленной мерой | `убывает`, с проверкой при работе |

`убывает` стоит между `возвращает` и телом и должно быть числом. Пишите его,
когда рекурсия идёт вниз арифметикой, а не взятием части значения:

```flang
модуль «Мера»

тотальная функция «НОД»
  принимает а: число, б: число
  возвращает число
  убывает б
  пример «двенадцать и восемнадцать»
    дано а равно 12
    дано б равно 18
    ожидается 6
  если б равен 0
    то а
    иначе «НОД» от б и (а остаток от б)
```

Ограничение: мера должна быть целой и неотрицательной, это проверяется на каждом
вызове. `«НОД»` от целых работает всегда; `«НОД»` от двух дробных
останавливается с `FLANG_MEASURE`: цепочка дробных остатков может убывать вечно.

## Тело: четыре формы

`разбор`, `свёртка`, `если` и `пусть`. Циклов нет.

### `разбор` — pattern matching по типу с вариантами

```flang
модуль «Дерево»

тип «Дерево»
  вариант Лист
  вариант Узел содержит значение: число, левое: «Дерево», правое: «Дерево»

тотальная функция «Узлов»
  принимает дерево: «Дерево»
  возвращает число
  пример «в листе узлов нет»
    дано дерево равно вариант Лист
    ожидается 0
  разбор дерева
    случай Лист
      то 0
    случай вариант Узел с левое как л и правое как п
      то 1 плюс («Узлов» от л) плюс («Узлов» от п)
```

Тип с вариантами — это enum с данными (tagged union). Образцы: `случай Имя` —
вариант без полей; `случай вариант Имя с поле как имя` — вариант с полями,
привязанными к именам; `случай пусто` и `случай голова и хвост` — список или
строка; `случай любое` — всё остальное.

Что проверяет компилятор: обработан каждый вариант; пропущенный вариант — ошибка
`FLANG_MATCH_NOT_EXHAUSTIVE`. Рекурсия на части значения завершается доказанно
без меры. Индукция в теореме работает **только** по этой форме.

### `свёртка` — reduce: один проход по списку

```flang
модуль «Свёртка»

тотальная функция «Произведение»
  принимает элементы: список числа
  возвращает число
  пример «три множителя»
    дано элементы равно [2, 3, 4]
    ожидается 24
  свёртка элементы начиная с 1 как акк и эл → акк умножить на эл
```

Завершение даром: список конечен, проход один.

Ограничение: тип накопителя не уточняется. `неотрицательное` в накопителе
останется `число`.

### `если` — if как выражение

```flang
модуль «Ветвление»

тотальная функция «Сумма до»
  принимает н: неотрицательное
  возвращает число
  пример «до нуля — ноль»
    дано н равно 0
    ожидается 0
  пример «до трёх — шесть»
    дано н равно 3
    ожидается 6
  если н не больше 0
    то 0
    иначе н плюс («Сумма до» от (н минус 1))
```

Ограничения: обе ветви обязательны, условие должно быть признаком (boolean).
Условие сужает **числовые границы** в своей ветви, но prover его как факт не
использует. Это постусловие не доказывается: `check --proof` пишет «объявлено,
не доказано» и завершается кодом 3:

```flang
модуль «Если»

тотальная функция «Положительное»
  принимает н: число
  возвращает число
  для всех н обеспечивает «больше нуля» результат больше 0
  если н больше 0
    то н
    иначе 1
```

Чтобы выбрать по виду значения, берите `разбор`; почему и чем это лучше для
доказательств — на странице [Какую конструкцию когда брать](which-construct.html).

### `пусть` — константа

```flang
модуль «Связывание»

объект «Позиция»
  цена является числом
  количество является числом

тотальная функция «Стоимость позиции»
  принимает позиция: «Позиция»
  возвращает число
  пример «две штуки по триста»
    дано позиция равно запись «Позиция» с цена равным 300 и количество равным 2
    ожидается 660
  пусть чистое равно позиция.цена умножить на позиция.количество
  пусть налог равно 10 процентов от чистое
  чистое плюс налог
```

Ограничение: `пусть` связывает один раз. Это не переменная, переприсваивания нет.
Имя из одного слова или в ёлочках: `пусть без налога равно …` не разберётся —
имя из двух слов пишется `«без налога»`.

## Типы

### Скалярные

| Тип | Что это |
| --- | --- |
| `число` | IEEE-754 double |
| `неотрицательное` | целое из [0, 2⁵³−1] |
| `целое` | целое из [−(2⁵³−1), 2⁵³−1] |
| `вес` (`стоимость`) | неотрицательное, где `+∞` — значение, а не край |
| `сотых`, `тысячных` | целое число минорных единиц: точные деньги и доли |
| `строка` | строка |
| `признак` | `да` / `нет` |
| `ничто` | одно значение |

Вложение: `неотрицательное` ≤ `целое` ≤ `число` и `неотрицательное` ≤ `вес` ≤ `число`. Значение втекает
в объявленную позицию, обратно — нет.

Зачем объявлять точный тип: prover берёт из него границы и целость, проверка
завершения — нижнюю и верхнюю границу. `число` не даёт ничего.

Ограничение: `делить` выводит из точного типа — результат становится `число`.
Округления в языке нет ни явного, ни молчаливого. Устройство каждого типа
целиком — [Спецификация языка](spec.html), раздел «Типы».

### Какой числовой тип брать

| Что за число | Тип | Что вы этим получаете |
| --- | --- | --- |
| счётчик, индекс, количество, длина | `неотрицательное` | ноль и выше, целое; спуск на постоянную даёт тотальность даром |
| разность, сальдо, сдвиг, температура | `целое` | минус разрешён, дробь — нет |
| деньги: рубли с копейками | `сотых` | целое минорных единиц; `19.99` пишется как `1999` |
| ставки, доли, курсы | `тысячных` | то же самое с тремя знаками после запятой |
| вес, расстояние, стоимость пути | `вес` | неотрицательное, где `+∞` — значение, а не край |
| всё остальное и всякое деление | `число` | IEEE-754 double, гарантий нет |

```flang
модуль «Точные типы»

тотальная функция «Копейки заказа»
  принимает цена: сотых, штук: неотрицательное
  возвращает число
  пример «три по 19.99»
    дано цена равно 1999
    дано штук равно 3
    ожидается 5997
  цена умножить на штук

тотальная функция «Доля»
  принимает часть: неотрицательное, всего: неотрицательное
  возвращает число
  требует «делитель положителен» всего больше 0
  пример «половина»
    дано часть равно 1
    дано всего равно 2
    ожидается 0.5
  часть делить на всего
```

Ограничение: **арифметика не сохраняет точный тип**. Сложите два
`неотрицательное`, объявите возврат `неотрицательное` — проверка не проходит:

```
FLANG_TYPE в файле nats-ru.flang, строка 6, столбец 5: функция «Сумма неотрицательное» объявлена как неотрицательное, а тело даёт число
```

Точные типы ставьте на **параметры и поля записей**: там их используют prover и
проверка завершения. Возврат объявляйте `число`, если тело считает арифметикой.

### Список

`список Тип` — однородный. Литерал — `[1, 2, 3]`, пустой — `пустой список`.
Ковариантен: `список неотрицательное` годится там, где ждут `список числа`.

`список из` — то же самое другими словами: `список из числа` в позиции типа и
`список из 1 и 2 и 3` в позиции значения.

### Запись (структура)

```flang
объект «Позиция»
  название является строкой
  цена является числом
  скидка иногда является числом
```

Поле пишется `имя является типом` или `«имя»: тип`. `иногда является` —
поле может отсутствовать. Строится запись формой
`запись «Позиция» с название равным "болт" и цена равным 30`; читается точкой —
`позиция.цена`.

Ограничение: типы записей инвариантны. Поле не меняется: значения неизменяемы,
поэтому строится новая запись.

### Тип с вариантами (enum)

```flang
тип «Ответ»
  вариант Успех содержит значение: число
  вариант Отказ содержит причина: строка
```

Строится `вариант Успех с значение равным 30`, разбирается формой `разбор`.

Так пишут Optional и Result: «нашлось» и «не нашлось» — разные варианты, и
вызывающий обязан сделать по ним `разбор`. `ничто` (null) для этого не берут.

Всё вместе, одной программой:

```flang
модуль «Типы»

объект «Позиция»
  название является строкой
  цена является числом
  скидка иногда является числом

тип «Счёт» это список «Позиция»

тип «Ответ»
  вариант Успех содержит значение: число
  вариант Отказ содержит причина: строка

тотальная функция «Проверить цену»
  принимает позиция: «Позиция»
  возвращает «Ответ»
  пример «цена есть»
    дано позиция равно запись «Позиция» с название равным "болт" и цена равным 30
    ожидается вариант Успех с значение равным 30
  пример «ноль — не цена»
    дано позиция равно запись «Позиция» с название равным "гайка" и цена равным 0
    ожидается вариант Отказ с причина равным "цена не положительна"
  если позиция.цена больше 0
    то вариант Успех с значение равным позиция.цена
    иначе вариант Отказ с причина равным "цена не положительна"
```

Поле, объявленное `иногда является`, в примерах писать не обязательно.

### Псевдоним и generic-тип

```flang
тип «Счёт» это список «Позиция»

тип «Возможно» от «А»
  вариант «Есть» содержит значение: «А»
  вариант «Нет»
```

Параметры типа (generics) вводятся словом `от` и им же подставляются. При вызове
они выводятся из значений; записать их явно негде.

Ограничение: у слова `это` английского написания нет; в файле с английскими
ключевыми словами оно пишется русским словом.

### Тип функции

`функция из числа и строки в признак` — словесная запись; `число → число` —
стрелочная. Обе дают один тип.

Ограничение: с английскими ключевыми словами словесная запись `function from
number to number` не разбирается — `to number` занято встроенной формой «к числу».
Пишите стрелкой: `number → number`.

## Выражения

| Что | Как пишется |
| --- | --- |
| вызов функции | `«Имя» от аргумент и аргумент` |
| поле записи | `значение.поле` |
| арифметика | `плюс`, `минус`, `умножить на`, `делить на`, `остаток от`, `процентов от` |
| сравнение | `равен`, `не равен`, `больше`, `меньше`, `не больше`, `не меньше` |
| логика | `не`, `и притом`, `или` |
| литералы | `12`, `"строка"`, `да`, `нет`, `ничто`, `[1, 2]` |

Приоритет, от слабого к крепкому:

```
или  <  и притом  <  не  <  сравнения  <  плюс минус  <  умножить делить  <  от  .
```

Ограничение: `не меньше` по-английски пишется `is at least`, `не больше` —
`is at most`. Обороты по аналогии не работают; написание берите из
[словаря](glossary.html).

### Строка в несколько строк

Литерал `"…"` переживает перевод строки: значение продолжается на следующей
строке, и перевод строки входит в него как есть. Одинарные кавычки `'…'` — тот
же литерал. Эти две записи дают одну и ту же строку:

```flang
модуль «Две записи»

тотальная функция «Через перевод строки»
  возвращает строка
  пример «то же, что с \n»
    ожидается "первая\nвторая"
  "первая
вторая"

тотальная функция «Одинарными кавычками»
  возвращает строка
  пример «те же кавычки, только другие»
    ожидается "текст"
  'текст'
```

Граница: отступ строк продолжения входит в значение буква в букву. Строка
`"первая⏎    вторая"` равна `"первая\n    вторая"`, поэтому текст внутри тела
функции пришлось бы начинать с первого столбца. Для текста в несколько строк
внутри отступа есть блок текста.

### Блок текста `"""`

Три двойные кавычки открывают блок; текст начинается со следующей строки; общий
отступ снимается:

```flang
тотальная функция «Справка»
  возвращает строка
  """
  Команды:
    .помощь   эта справка
    .выход    закончить
  """
```

Значение — `"Команды:\n  .помощь   эта справка\n  .выход    закончить\n"`.
Токен тот же, что у литерала с `\n`: блок — запись, а не новый вид строки.

| Правило | Что значит |
| --- | --- |
| за открывающими `"""` на строке ничего | текст начинается со следующей строки; знак за кавычками — отказ `FLANG_LEX` на его месте |
| закрывают первые незаслонённые `"""` | остаток строки за ними разбирается как обычно |
| общий отступ | наименьший отступ непустых строк и строки с закрывающими кавычками; табуляция — один знак, как пробел |
| каждая строка теряет общий отступ | строка из одних пробелов становится пустой; пробелы в конце строки остаются |
| закрывающие кавычки на своей строке | текст кончается переводом строки; на последней строке текста — не кончается |
| заслоны те же, что в `"…"` | `\n`, `\t`, `\"`, `\\`, `\uXXXX`; кавычки `"` и `'` внутри пишутся как есть |

```flang
тотальная функция «Без перевода строки в конце»
  возвращает строка
  пример «закрывающие кавычки на последней строке текста»
    ожидается "первая\nвторая"
  """
  первая
  вторая"""

тотальная функция «С отступом внутри»
  возвращает строка
  пример «закрывающие кавычки левее текста задают общий отступ»
    ожидается "  первая\n"
  """
    первая
  """
```

Границы: незакрытый блок — отказ `FLANG_LEX` на месте открывающих кавычек;
негодный `\uXXXX` внутри блока — отказ на строке и в столбце самой обратной
черты. Подстановки значений в блоке нет. Решение и полный разбор случаев —
[ADR-0052](../adr/0052-a-text-block-literal-strips-its-common-indentation.md).

## Встроенные формы над списками и строками

| Форма | Что делает |
| --- | --- |
| `длина X` | длина списка или строки |
| `голова X`, `хвост X`, `пусто` | части списка и строки |
| `элемент N в X` | N-й элемент списка |
| `символ N в X` | N-й символ строки |
| `добавить X к Y`, `приписать X к Y` | в конец и в начало списка |
| `отобразить X как имя → тело` | map: новый список |
| `отфильтровать X где имя → условие` | filter: подходящие элементы |
| `подстрока X с A по B` | кусок строки |
| `разделить X по Y` | строка → список строк |
| `соединить X по Y` | список строк → строка |
| `соединить X с Y` | склейка двух строк |
| `содержит`, `начинается с` | проверки над строкой |
| `к числу`, `к числу или беда`, `к строке` | преобразования |
| `код символа X`, `разложить X на символы` | посимвольно |
| `символ по коду N` | кодовая точка числом → строка из одного символа; ошибка на дробном, вне [0, 1114111] и на одиночном суррогате |

```flang
модуль «Встроенные формы»

тотальная функция «Длинные слова»
  принимает текст: строка
  возвращает список строки
  пример «короткое слово выброшено»
    дано текст равно "раз дважды трижды"
    ожидается ["дважды", "трижды"]
  отфильтровать (разделить текст по " ") где слово → (длина слово) больше 3

тотальная функция «Длины слов»
  принимает слова: список строки
  возвращает список числа
  пример «три слова»
    дано слова равно ["раз", "дважды", "трижды"]
    ожидается [3, 6, 6]
  отобразить слова как слово → длина слово
```

У каждой формы свои закреплённые предлоги:

```flang
модуль «Строки»

тотальная функция «Второе слово»
  принимает текст: строка
  возвращает строка
  пример «два слова»
    дано текст равно "раз дважды"
    ожидается "дважды"
  элемент 2 в (разделить текст по " ")

тотальная функция «Первые три»
  принимает текст: строка
  возвращает строка
  пример «отрезано с головы»
    дано текст равно "абвгде"
    ожидается "абв"
  подстрока текст с 1 по 3

тотальная функция «Склеено»
  принимает части: список строки
  возвращает строка
  пример «через запятую»
    дано части равно ["а", "б"]
    ожидается "а,б"
  соединить части по ","

тотальная функция «Первая буква»
  принимает текст: строка
  возвращает строка
  пример «голова строки»
    дано текст равно "абв"
    ожидается "а"
  символ 1 в текст
```

Ограничение: номера начинаются с единицы, оба конца диапазона включаются. Номер
вне списка останавливает вычисление с ошибкой. Всё остальное — функции
библиотеки; какая задача какой функцией решается — на странице
[Операции языка](operations.html).

## Функции как значения

```flang
модуль «Функция как значение»

тотальная функция «Удвоить»
  принимает х: число
  возвращает число
  х умножить на 2

тотальная функция «Прибавить»
  принимает а: число, б: число
  возвращает число
  а плюс б

тотальная функция «Применить дважды»
  принимает ф: функция из числа в число, х: число
  возвращает число
  ф от (ф от х)

тотальная функция «Проба»
  возвращает число
  пример «пятёрка удвоена дважды»
    ожидается 20
  «Применить дважды» от функция «Удвоить» и 5

тотальная функция «Проба с захватом»
  возвращает число
  пример «десятка прибавлена дважды»
    ожидается 25
  «Применить дважды» от (функция «Прибавить» с а равным 10) и 5
```

| Форма | Что значит |
| --- | --- |
| `функция «Имя»` | значение-функция |
| `функция «Имя» с а равным 10` | она же с захваченным первым параметром |
| `ф от 5` | применение значения |
| `функция из числа в число` | тип |

**Вместо замыканий — частичное применение по имени параметра.**
`функция «Прибавить» с а равным 10` даёт функцию одного аргумента. Захваченные
параметры идут в порядке объявления. Лямбд как значений нет: значением бывает
только объявленная функция. Встроенные `отобразить`, `отфильтровать` и
`свёртка` принимают тело на месте (`эл → эл плюс 1`), но это тело — часть формы,
а не значение, и передать его никуда нельзя.

Ограничение: применить можно только функцию, которую программа где-то берёт
формой `функция «Имя»`. Функция-значение, пришедшая снаружи и нигде в программе
не взятая, отвергается с `FLANG_APPLY`. Раздельной компиляции нет: функции-значения
разрешаются по всей программе сразу.

## Контракты и доказательства

Эти слова говорят о функции больше, чем её тип. Каждое проверяется по-своему.

| Слово | Где стоит | Кто обязан его выполнить | Чем проверяется |
| --- | --- | --- | --- |
| `требует «имя» условие` | после `возвращает`, до тела | **вызывающий** | проверкой при работе на границе программы |
| `для всех п обеспечивает «имя» условие` | там же, после `требует` | сама функция | prover'ом при проверке; не доказано — проверкой при работе на каждом возврате |
| `тотальная` | перед словом `функция` | компилятор | при проверке; см. [Тотальность и мера](#тотальность-и-мера) |
| `теорема «имя»` | верхним уровнем, рядом с функцией | вы | prover'ом при проверке, шаг за шагом |
| `утверждение «имя»` | верхним уровнем, БЕЗ функции | вы | prover'ом при проверке; попадает в `--proof --json` |

### `требует` — предусловие

`требует «имя» условие` — что должно быть верно, чтобы вызов был допустим.

```flang
модуль «Предусловие»

тотальная функция «Доля»
  принимает часть: неотрицательное, всего: неотрицательное
  возвращает число
  требует «делитель положителен» всего больше 0
  пример «половина»
    дано часть равно 1
    дано всего равно 2
    ожидается 0.5
  часть делить на всего
```

Внутри функции условие — **допущение**: теорема может опереться на него через
`по предположению`, даже без индукции.

Ограничение: проверка при работе генерируется только на границе программы, там,
куда значение приходит снаружи. Внутренние вызовы за неё не платят.

### `обеспечивает` — постусловие

`для всех п обеспечивает «имя» условие` — что верно для `результат` на любом
входе. `результат` в условии — возвращённое значение.

```flang
модуль «Постусловие»

тотальная функция «Удвоить все»
  принимает элементы: список числа
  возвращает список числа
  для всех элементы обеспечивает «длина сохраняется» (длина результат) равен (длина элементы)
  пример «три элемента»
    дано элементы равно [1, 2, 3]
    ожидается [2, 4, 6]
  отобразить элементы как э → э умножить на 2
```

Prover сначала пробует условие **доказать**. Доказал — в сгенерированном коде
проверки нет. Не доказал — условие проверяется на каждом возврате, и нарушение
останавливает вычисление. Что доказано, а что нет, показывает
`flang check --proof`.

Ограничение: имя обязательно — `обеспечивает` без имени не разберётся. По имени
на постусловие ссылается теорема и `по свойству` в другом доказательстве.

### `для всех … из …:` — свойство каждого элемента списка

Чтобы сказать что-то про каждый элемент списка, квантор пишут прямо в
постусловии. Его тело отделяется двоеточием.

```flang
модуль «Все элементы после отбора»

тотальная функция «Только положительные»
  принимает элементы: список числа
  возвращает список числа
  обеспечивает «все положительны» для всех п из результат: п больше 0
  пример «Смесь»
    дано элементы равно [3, 0, 5]
    ожидается [3, 5]
  отфильтровать элементы где э → э больше 0
```

Prover доказывает такое постусловие по ФОРМЕ списка, который строит тело, а не
прогоном. Он принимает четыре формы: пустой список; `отфильтровать Л где х → У`, когда `У` и
есть доказываемое свойство; `добавить Х к Л` и `приписать Х к Л`, когда свойство
верно и про `Х`, и про `Л`; `если У то А иначе Б`, когда верно в обеих ветвях.
Выписанный поэлементно список, `отобразить` (map) и вызов другой функции не
принимаются — правила для них у prover'а нет.

Тело после двоеточия — снова условие, поэтому кванторы вкладываются:

```flang
  обеспечивает «каждый с каждым положителен» для всех х из результат: для всех м из результат: м больше 0
```

Для «существует» значение называете вы сами: `есть такой м, а именно х, что …`.
Prover его не ищет.

Ограничение: первое двоеточие верхнего уровня заканчивает квантор, всё правее —
его тело. Квантор внутри условия и переменная в `для всех н обеспечивает …` —
разные вещи, и prover их не путает.

### `теорема`

Теорему пишут, когда prover не доказал постусловие сам.

```flang
модуль «Теорема»

тотальная функция «Сумма до»
  принимает н: неотрицательное
  возвращает число
  для всех н обеспечивает «сумма до неотрицательна» результат не меньше 0
  пример «шагов не осталось»
    дано н равно 0
    ожидается 0
  если н не больше 0
    то 0
    иначе н плюс («Сумма до» от (н минус 1))

теорема «сумма до неотрицательна»
  дано н: неотрицательное
  утверждаем результат не меньше 0
  индукция по н убывает н
    случай 0
      то по примеру «шагов не осталось»
    случай любое
      то по предположению
  следовательно доказано
```

| Строка | Что делает |
| --- | --- |
| `теорема «имя»` | то же имя, что у доказываемого постусловия |
| `дано имя: тип` | переменные |
| `утверждаем условие` | что доказывается |
| `индукция по имя убывает мера` | доказательство индукцией; `убывает` нужен только там, где убывает число, а не часть значения |
| `случай …` / `то обоснование` | один шаг |
| `затем утверждение по обоснование` | промежуточный факт; следующие шаги могут на него опираться |
| `следовательно доказано` | конец |

Индукция не обязательна; короткая теорема — одно обоснование:

```flang
модуль «Свойство»

тотальная функция «Удвоить все»
  принимает элементы: список числа
  возвращает список числа
  для всех элементы обеспечивает «удвоение длины не меняет» (длина результат) равен (длина элементы)
  отобразить элементы как э → э умножить на 2

тотальная функция «Через удвоение»
  принимает элементы: список числа
  возвращает список числа
  для всех элементы обеспечивает «через удвоение длина та же» (длина результат) равен (длина элементы)
  «Удвоить все» от элементы

теорема «через удвоение длина та же»
  дано элементы: список числа
  утверждаем (длина результат) равен (длина элементы)
  по свойству «удвоение длины не меняет»
  следовательно доказано
```

Ограничение: часто теорема не нужна — сначала напишите постусловие и посмотрите,
докажет ли его prover сам. Индукция работает **только** по `разбор` по типу с
вариантами и по убывающему числу.

### `утверждение` — свойство не при функции

Свойство можно записать само по себе, без функции.

```flang
модуль «Свободные утверждения»

утверждение «длина пустого списка нулевая»
  утверждаем (длина пустой список) равен 0

утверждение «ноль нейтрален при сложении»
  для всех н: неотрицательное таких что н больше 0
  утверждаем (н плюс 0) равен н
```

Prover проверяет его так же, как постусловие, и оно попадает в
`flang check --proof --json`. Строка `для всех имя: тип таких что условие` задаёт
переменные и допущение. Допущение здесь важно: `неотрицательное` при работе
принимает минус ноль, и без `н больше 0` второе свойство ложно.

Доказать свойство можно и теоремой с тем же именем, написанной рядом.

### Индукция по своему объявленному типу

`индукция по` работает не только для встроенных типов, но и для ваших типов с
вариантами: принцип индукции берётся из объявления типа.

```flang
модуль «Своё натуральное»

тип «Нат»
  вариант «Ноль»
  вариант «Следующий» содержит пред: «Нат»

тотальная функция «К числу»
  принимает н: «Нат»
  возвращает число
  разбор н
    случай вариант «Ноль»
      то 0
    случай вариант «Следующий» с пред как п
      то («К числу» от п) плюс 1

утверждение «шаг растит счёт на один»
  для всех н: «Нат»
  утверждаем («К числу» от (вариант «Следующий» с пред равным н)) равно ((«К числу» от н) плюс 1)

теорема «шаг растит счёт на один»
  дано н: «Нат»
  утверждаем («К числу» от (вариант «Следующий» с пред равным н)) равно ((«К числу» от н) плюс 1)
  индукция по н
    случай вариант «Следующий» с пред как п
      то по предположению
  следовательно доказано
```

Отчёт пишет «доказано индукцией по «Нат»». `убывает` не нужно: уменьшается часть
значения, а не число.

### Обоснования шага

У каждого шага должно быть обоснование, иначе он не разберётся. Обоснований
четыре.

| Обоснование | Когда брать |
| --- | --- |
| `по свойству «имя»` | в шаге есть **вызов** функции, у которой есть постусловие с таким именем |
| `по предположению` | есть допущение: гипотеза индукции (`индукция по`) или предусловие функции (`требует`) |
| `по примеру «имя»` | у случая **одно** значение (образец без связанных имён), и у функции есть пример с таким именем |
| `по закону «имя»` | имя — моноид, монада или изоморфизм, объявленный в этом модуле, или одно из правил вывода, которые проверяет prover (см. [Шаг, который называет правило](#шаг-который-называет-правило)) |

### `по свойству`

Берёт постусловие **другой** функции. Prover находит в шаге вызовы этой функции
и подставляет её постусловие: параметры — аргументами вызова, `результат` —
самим вызовом.

Пример — теорема «через удвоение длина та же» выше. Ссылка на постусловие,
которое сейчас доказывается, — круг, и проверка не проходит:

```
FLANG_PROOF_STEP в файле circle.flang, строка 12, столбец 3: шаг 1, теорема «длина сохраняется»: «по свойству «длина сохраняется»» ссылается на то самое постусловие, которое сейчас доказывается — это круг. Часть значения обосновывает «по предположению», а не ссылка на саму цель. к этому месту не известно ничего, кроме гипотез «дано»
```

Ограничение: постусловие с таким именем должно быть у какой-нибудь функции
модуля; иначе проверка не проходит с сообщением, что сослаться не на что.

### `по предположению`

Берёт допущение. Их два вида: гипотеза индукции (то же свойство для меньшей
части значения) и предусловие функции (строка `требует`). Теорема «Сумма до»
выше опирается на гипотезу индукции.

Если нет ни того, ни другого, проверка не проходит и называет, чего не хватает:

```
FLANG_PROOF_INDUCTION_STEP в файле hyp.flang, строка 12, столбец 3: шаг 1, теорема «половина неотрицательна»: «по предположению» стоит вне индукции, а допущений у этой цели нет ни одного: ни посылки индукции (её даёт `индукция по`), ни предусловия функции (его даёт `требует`). Предполагать не о чем. к этому месту не известно ничего, кроме гипотез «дано»
```

Ограничение: у гипотезы нет имени. Она одна на случай, и гипотезу другого
случая взять нельзя.

### `по примеру`

Доказывает случай прогоном примера. Пример — **одно** значение, поэтому он
доказывает только случай с одним значением: `случай 0`, `случай Лист`,
`случай пусто` — образец **без связанных имён**.

`случай вариант Узел с левое как л` покрывает бесконечно много значений, и один
пример его не доказывает. Там берите `по предположению`.

Ограничение: пример ищется по имени у функции, чьё постусловие доказывается.
Примера с таким именем нет — проверка не проходит и называет оба имени.

### `по закону`

Ссылается на моноид, монаду или изоморфизм, объявленный в модуле, или на
правило вывода по имени. Любое другое имя отвергается — иначе строкой
`по закону «чего не бывает»` доказывалось бы что угодно:

```
FLANG_PROOF_STEP в файле law.flang, строка 12, столбец 3: теорема «то же»: шаг 1 (чего не бывает, без основания): правило «чего не бывает» ведомости ядро пока не проверяет; проверяет шесть: Н1, Н3, Н5, О1, О10, Разв2
```

Сообщение значит: правило «чего не бывает» prover не проверяет; он проверяет
шесть правил — Н1, Н3, Н5, О1, О10 и Разв2.

### Шаг, который называет правило

Шаг может назвать правило вывода, которое применяет, и факты, на которые
опирается. Тогда prover проверяет это применение правила, а не ищет
доказательство сам.

```flang
теорема «результат не больше десяти»
  дано а: число
  дано б: число
  утверждаем результат не больше 10
  затем а не больше б по закону «О1» из строки 5
  затем б не больше 10 по закону «О1» из строки 6
  затем а не больше 10 по закону «О10» из 1 и 2
  по закону «Разв2» из 3 и строки 9
  следовательно доказано
```

`из строки N` — строка исходника, откуда берётся факт (предусловие, тело);
`из K` и `из K L` — номера предыдущих шагов этой же теоремы. Имена правил
перечислены в `flang/proof/tables/inference-rules.tsv`.

Зачем называть правило: независимая проверка доказательств
(`flang/proof/checker/checker.c`) перепроверяет шаг с названным правилом, а шаг
без имени ей приходится принимать на слово prover'а.

Ограничение: prover проверяет шесть правил — Н1, Н3, Н5, О1, О10, Разв2; любое
другое имя — ошибка (см. вывод выше).

Сколько доказывается без теоремы и какими правилами — [Зачем и
как](proofs.html) и [Спецификация prover'а](spec-proof.html).

## Категории: конвейер, объявленный данными

Объекты, стрелки (морфизмы) между ними и их композиция — объявленные, а не
вызванные.

```flang
модуль «Проводка заказа»

объект «Заказ»
  сумма является числом

объект «Отгрузка»
  номер является числом

объект «Счёт»
  итог является числом

тотальная функция «Отгрузить заказ»
  принимает заказ: «Заказ»
  возвращает «Отгрузка»
  запись «Отгрузка» с номер равным заказ.сумма

тотальная функция «Выставить счёт»
  принимает отгрузка: «Отгрузка»
  возвращает «Счёт»
  запись «Счёт» с итог равным отгрузка.номер

морфизм «отгрузить» из «Заказ» в «Отгрузка»
  даёт «Отгрузить заказ»
  закон «номер отгрузки берётся из суммы заказа»
    пример «обычный заказ»
      дано заказ равно запись «Заказ» с сумма равным 500
      ожидается запись «Отгрузка» с номер равным 500

морфизм «выставить» из «Отгрузка» в «Счёт»
  даёт «Выставить счёт»

морфизм «провести» это «выставить» после «отгрузить»

цепочка «провести заказ»
  сначала «отгрузить»
  затем «выставить»
```

| Конструкция | Что делает |
| --- | --- |
| `объект «Х»` | вид данных; поля как у записи |
| `морфизм «м» из «А» в «Б»` | стрелка; концы объявлены |
| `даёт «Ф»` | функция, которой стрелка является |
| `закон «имя»` с примерами | что стрелка гарантирует, проверяется на значениях примеров |
| `«в» после «а»` | композиция; правая применяется первой |
| `цепочка` / `сначала` / `затем` | та же композиция в порядке чтения |
| `единица «Х»` | тождественная стрелка объекта |
| `категория «К»` со списком стрелок | интерфейс: что модуль умеет |
| `изоморфизм` / `прямой морфизм` / `обратный морфизм` | пара стрелок туда и обратно |
| `функтор` / `бифунктор` | связь между категориями |
| `моноид` / `носитель` / `операция` / `единица` / `обратный элемент` | структура со своими законами |

### Что компилятор проверяет, а что нет

**Проверяет: законы категории, на конечном наборе значений.** Если у категории
объявлено своё равенство (`объект «Х» даёт «Х равны»`), компилятор проверяет на
конечном наборе значений, что равенство — эквивалентность, что композиция его
сохраняет и что композиция ассоциативна. Отчёт называет размер набора («сетка»):

```
категория «Отгрузки»: сетка 5 значений на 3 объектах, троек стрелок 7, нарушений 0 — ПОСЧИТАНО НА СЕТКЕ, не доказано
```

То есть: 5 значений на 3 объектах, 7 троек стрелок, нарушений 0 — посчитано на
этих значениях, не доказано. Нарушение — ошибка с кодом 1 и значениями, на
которых закон ломается, и код не генерируется. Так же с естественным
преобразованием: `FLANG_TRANSFORM_NOT_NATURAL` с обоими путями и их значениями.

**Не проверяет: форму объявлений.** Замкнутость под композицией, единицы у
объектов, совпадение концов у составленных стрелок, форму функтора двоичный
компилятор не проверяет. Он пишет об этом отдельной строкой и завершается кодом
2, так что за успех это не сойдёт. В частности:

- переставленный порядок композиции (`«отгрузить» после «выставить»`) ошибки
  **не даёт**, хотя контракт языка описывает `FLANG_COMPOSE_MISMATCH`;
- стрелка, не совпадающая со своей функцией, ошибки **не даёт**, хотя
  `FLANG_MORPHISM_SHAPE` описан;
- некоммутирующий квадрат функтора ошибки **не даёт**: функторы не проверяются
  вовсе, и `FLANG_FUNCTOR_SQUARE` не срабатывает.

Итого сегодня **объявление категории документирует намерение и проверяет свои
законы на значениях примеров; форму оно не проверяет.** С полными прогонами —
[Категорная поверхность](categories.html).

Прежде чем брать:

- обычную композицию, записанную вызовом функции, и так проверяет проверка
  типов. Стрелки нужны для конвейеров, которые **объявляются**, а не вызываются;
- квадрат функтора и законы стрелок **проверяются на конечном наборе значений**
  из ваших примеров; это не доказательство. Отчёт печатает размер набора;
- категория — лишь пометка для читателя, пока вы не перечислили её стрелки;
  принадлежность объекта категории не проверяет ничто;
- отображение без реализации (`отображается в` без `даёт`) не проверяется вовсе:
  оно записывается как принятое на веру.

Полный контракт — [Категории и функторы](spec-cat.html). Где кончается
«доказано» и начинается «проверено» — [Что доказано, а что нет](what-is-proved.html).

## Монада и `в монаде`: цепочка шагов, каждый из которых может не дать ответа

```flang
модуль «Скидка»

тип «Возможно» от «А»
  вариант «Есть» содержит значение: «А»
  вариант «Нет»

монада «Возможно» от «А»
  возврат «Обернуть»
  соединение «Сплющить»

тотальная функция «Обернуть» от «А»
  принимает значение: «А»
  возвращает «Возможно» от «А»
  вариант «Есть» с значение равным значение

тотальная функция «Сплющить» от «А»
  принимает вложенное: «Возможно» от («Возможно» от «А»)
  возвращает «Возможно» от «А»
  разбор вложенное
    случай вариант «Есть» с значение как внутри
      то внутри
    случай «Нет»
      то вариант «Нет»

тотальная функция «Цена позиции»
  принимает номер: число
  возвращает «Возможно» от числа
  если номер равен 1
    то вариант «Есть» с значение равным 500
    иначе вариант «Нет»

тотальная функция «Скидка по цене»
  принимает цена: число
  возвращает «Возможно» от числа
  если цена не меньше 400
    то вариант «Есть» с значение равным (цена делить на 10)
    иначе вариант «Нет»

тотальная функция «Итог со скидкой»
  принимает номер: число
  возвращает «Возможно» от числа
  пример «по первой позиции скидка есть»
    дано номер равно 1
    ожидается вариант «Есть» с значение равным 450
  пример «второй позиции нет в каталоге»
    дано номер равно 2
    ожидается вариант «Нет»
  в монаде «Возможно»
    пусть цена равно «Цена позиции» от номер
    пусть скидка равно «Скидка по цене» от цена
    возврат цена минус скидка
```

| Строка | Что делает |
| --- | --- |
| `монада «Т» от «А»` | объявление на параметрическом типе |
| `возврат «Ф»` | функция, заворачивающая значение |
| `соединение «Ф»` | функция, снимающая один слой |
| `в монаде «Т»` | блок связывания |
| `пусть имя равно шаг` | шаг, который вправе не дать ответа |
| `возврат выражение` | последняя строка блока |

Компилятор разворачивает блок во вложенные `разбор` по вариантам типа. Цепочку
«если нет — вернуть нет» на каждом шаге писать не нужно — та же идея, что `?` в
Rust или `do` в Haskell.

Ограничения: `возврат` должен быть последней строкой блока. Отображение (fmap)
не объявляется — компилятор выводит его из типа. Законы монады проверяются на
конечном наборе значений, а не доказываются.

## Процессы и надзор

Состояние принадлежит процессу, как у актора в Erlang. Обработчик — обычная
тотальная функция: принимает состояние и сообщение, возвращает новое состояние и
список действий. Отправка сообщения — действие в этом списке, а не side effect.

```flang
модуль «Счётчик»

объект «Счёт»
  «всего»: число

объект «Отклик»
  «состояние»: «Счёт»
  «действия»: список «Действие»

тип «Команда»
  вариант «прибавить» содержит «сколько»: число

процесс «Счётчик»
  состояние «Счёт»
  начинает с «пустой счёт»
  принимает «Команда»
  обрабатывает «шаг счёта»

надзор «Учёт»
  процесс «Счётчик» стратегия «перезапустить»
  порог отказов 3 за 5000 миллисекунд иначе «передать выше»

тотальная функция «пустой счёт»
  возвращает «Счёт»
  запись «Счёт» с «всего» равным 0

тотальная функция «шаг счёта»
  принимает текущее: «Счёт», сообщение: «Команда»
  возвращает «Отклик»
  пример «прибавление меняет состояние и ничего не шлёт»
    дано текущее равно (запись «Счёт» с «всего» равным 1)
    дано сообщение равно (вариант «прибавить» с «сколько» равным 2)
    ожидается (запись «Отклик» с «состояние» равным (запись «Счёт» с «всего» равным 3) и «действия» равным [])
  разбор сообщение
    случай вариант «прибавить» с «сколько» как сколько
      пусть новое равно (запись «Счёт» с «всего» равным (текущее.«всего» плюс сколько))
      запись «Отклик» с «состояние» равным новое и «действия» равным []

прогон «два прибавления»
  семя 1
  дано «Счётчик» принимает (вариант «прибавить» с «сколько» равным 2)
  дано «Счётчик» принимает (вариант «прибавить» с «сколько» равным 3)
  ожидается «Счётчик» равен (запись «Счёт» с «всего» равным 5)
```

| Строка | Что делает |
| --- | --- |
| `процесс «П»` | объявление |
| `состояние «Т»` | тип состояния |
| `начинает с «Ф»` | функция начального состояния |
| `принимает «Т»` | тип сообщений |
| `обрабатывает «Ф»` | обработчик |
| `с запасом N` | предел шагов у обработчика без `тотальная` |
| `с ящиком N` | размер почтового ящика |
| `надзор «Н»` | супервизор: что делать при отказах, данными |
| `процесс «П» стратегия «…»` | что делать при отказе |
| `порог отказов N за M … иначе «…»` | окно и запасная стратегия |
| `прогон «имя»` / `семя` / `дано` / `ожидается` | тест конкурентной программы: сообщения на входе, ожидаемое состояние на выходе |
| `семя от N до M` | тот же тест на диапазоне порядков доставки сообщений |

Ограничение: поля ответа обработчика (`состояние`, `действия`) и тип
`«Действие»` — закреплённые имена модели процессов, а не соглашение файла. Так же
закреплены имена стратегий (`перезапустить`, `остановить`, `передать выше`) и
нормальная причина остановки `норма`; при английских ключевых словах они
пишутся так же.

Модель целиком — [Процессы и отказоустойчивость](spec-conc.html).

## Слова, которых нет в примерах выше

Выше — формы, из которых пишут программы. Остальные ключевые слова перечислены
здесь, чтобы было видно, куда они относятся.

| Слово | Куда относится | Где описано |
| --- | --- | --- |
| `вложение`, `пересечение` | категории: часть объекта и общая часть двух | [Категории и функторы](spec-cat.html) |
| `объекты`, `морфизмы` | бифунктор: пара объектов и пара стрелок | то же |
| `отображается в`, `отображается в поле`, `отображается в морфизм` | строки функтора | то же |
| `свойство` | закон одной операции: коммутативность, монотонность и ещё три | [Категории и функторы](spec-cat.html) |
| `план` | side effects (файлы, сеть, процессы): объявляется теми же тремя строками, что процесс | [Категории и функторы](spec-cat.html), раздел «Эффекты и HTTP» |
| `дата`, `деньги` | старые ключевые слова: `дата` ведёт себя как `строка`, `деньги` — как `число` | [Словарь языка](glossary.html) |
| `имеет` — строка `дано «Объект» имеет «поле» равное значение` | старая форма теоремы; рядом с шагами доказательства отвергается | ниже |
| `утилита`, `правило`, `вложен объект`, `в данных`, `найти где`, `по морфизму` | старые ключевые слова: разбираются, но программу из них не составить | [Словарь языка](glossary.html) |

Старую форму теоремы нельзя смешивать с нынешней: строка
`дано «Объект» имеет «поле»` рядом с `утверждаем` — ошибка.

```
FLANG_PARSE в файле mix.flang, строка 12, столбец 1: теорема «цена та же» смешала две формы: дано «Объект» имеет «поле» — из старой, а рядом стоят слова доказательства. Выберите одну форму
```

Так же ведут себя `в данных`, `по морфизму` и `следовательно «вывод»`.

## Чего в языке нет

| Привычка | Что вместо |
| --- | --- |
| цикл | `свёртка` и рекурсия |
| изменение элемента на месте | построение нового значения |
| исключение | Result: вариант типа, несущий причину |
| `null`, когда «не нашлось» | Optional: тип с вариантами и обязательный `разбор` |
| переменная | `пусть`, связывающее один раз |
| лямбда | объявленная функция, переданная как `функция «Имя»` |
| замыкание, захватывающее локальную переменную | частичное применение по имени параметра: `функция «Имя» с а равным 10` |
| побитовые операции: `and`, `or`, `xor`, сдвиги | арифметика: `умножить на`, `делить на`, `остаток от` |
| запись в список по номеру (`x[i] = v`) | `отобразить` строит новый список |
| зависимый тип (`список длины н`) | `обеспечивает` о длине и теорема о ней |
