# Модули и пакеты

Пакет flang — **один файл**, в котором лежит библиотека вместе со всем, что она
импортирует. Менеджера пакетов нет: файл кладут рядом с программой или
подключают ссылкой прямо в строке импорта (`использует «X» из "https://…"`), и
тогда компилятор скачивает его один раз и записывает его отпечаток (sha256) в
`flang.lock`.
Чтобы опубликовать пакет, закоммитьте файл в git. Для сборки на другой машине
нужны только ваша программа и её `flang.lock`, в сеть такая сборка не ходит.

Нужны две команды: `flang package` собирает пакет,
`flang lock` пишет lock-файл для всей программы. У обеих есть `--help`. Примеры
ниже — на `docs/examples/package/`.

## Подключите пакет

1. Положите файл пакета рядом со своей программой.
2. Импортируйте его по имени модуля:

```
модуль «Shop»
  использует «Скидка» из "discount.flang-package"
```

3. Проверяйте и тестируйте как обычно:

```bash
$ ls
discount.flang-package  shop.flang

$ flang check shop.flang
модуль «Shop»: функций 4, из них с доказанным завершением 4; типов 0; файлов вместе с импортами 2
shop.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет

$ flang test shop.flang
shop.flang: примеров 7, прошло 7, не прошло 0
```

Исходников библиотеки в каталоге нет: её функции лежат в файле пакета вместе
с тестами и типами.

Имя в импорте должно совпасть с именем модуля внутри пакета. Иначе проверка
завершается с ошибкой и называет оба имени:

```bash
$ flang check shop.flang
…
FLANG_IMPORT_NAME, строка 1, столбец 1: модуль в …/discount.flang-package называется «Скидка», а импортируется как «Скидочка»
shop.flang: не проверено — замечаний 1
```

Предусловия (`требует`) функций библиотеки приходят вместе с пакетом, и ваш
код должен выполнять их в каждом вызове. Уберите `требует` у своей функции
«Сколько скинули» — и программа перестанет проходить проверку, хотя библиотека
не менялась:

```bash
$ flang check shop.flang
…
FLANG_PRECONDITION_CALL, строка 20, столбец 3: вызов «Скидка в копейках» в функции «Сколько скинули» не снимает предусловие «доля не больше ста»: …
shop.flang: не проверено — замечаний 1
```

## Подключите модуль по ссылке

Модуль с чужого адреса подключается ссылкой прямо в строке импорта. Команды
установки нет, реестр не нужен:

```
модуль «Магазин»
  использует «Скидка» из "https://example.org/discount/v1.2.0/discount.flang"
```

```bash
$ flang check shop.flang
скачано: https://example.org/discount/v1.2.0/discount.flang — отпечаток 9261f268…
в замок /home/me/shop/flang.lock: ссылок 1
shop.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Что делает компилятор:

1. ссылка — строка, которая начинается с `https://` или `file://`; её не
   склеивают с каталогом программы, а читают по адресу;
2. тело ищется по порядку: в `flang.lock` рядом с программой, затем в кеше
   `$XDG_CACHE_HOME/flang/links/` (без переменной — `~/.cache/flang/links/`),
   затем по сети; скачивается оно один раз;
3. отпечаток тела (sha256) и само тело ложатся в `flang.lock`, тело — ещё и в
   кеш; следующие сборки берут тело оттуда и сравнивают его с отпечатком;
4. импорты скачанного модуля разбираются так же: относительный путь в нём
   считается от его адреса;
5. скачанный модуль проверяется вместе с программой, как свой файл: типы,
   завершение функций, постусловия и тесты.

Ссылка называет один файл, выбора версий нет: новая версия — новая ссылка
(`/v1.2.0/` → `/v1.3.0/`). При первом скачивании компилятор берёт то, что
ответил адрес. Если файл по адресу потом подменят, отпечаток в `flang.lock`
не совпадёт, и сборка остановится.
Без сети (`FLANG_OFFLINE=1`) сборка берёт тела из замка и кеша.

### Ошибки ссылки

Код возврата у всех — 1. В сообщении стоят код ошибки, ссылка и причина.

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_LINK_FETCH` | файл не получен: адрес ответил не 200, файла нет, схема не `https://` и не `file://` | проверить ссылку |
| `FLANG_LINK_OFFLINE` | сеть закрыта `FLANG_OFFLINE`, а ни замок, ни кеш этой ссылки не знают | собрать один раз с сетью или принести `flang.lock` |
| `FLANG_LINK_CHANGED` | файл в `flang.lock` или в кеше не совпал со своим отпечатком | вернуть `flang.lock` из git; чтобы скачать заново, убрать запись из `flang.lock` и очистить кеш |

## Сделайте свой пакет

**Шаг 1. Напишите манифест.** Положите `flang.package` рядом с входным файлом
библиотеки:

```json
{
  "имя": "Скидка",
  "версия": "1.0.0",
  "источник": "https://github.com/digitable-lol/flang"
}
```

`имя` и `версия` обязательны, `источник` (адрес исходников) — нет. `имя` обязано
совпасть с именем модуля в первой строке входного файла: по этому имени пакет
импортируют. Если имена разные, `flang package` завершается с ошибкой:

```bash
$ flang package skidka/discount.flang
FLANG_PACKAGE: в flang.package пакет назван «Не Скидка», а модуль в skidka/discount.flang называется «Скидка»
$ echo $?
1
```

Самой библиотеке ничего особого не нужно: `skidka/discount.flang` — обычный
модуль с обычной шапкой `модуль` / `экспортирует`.

В примере из репозитория именно такое расхождение: модуль в
`docs/examples/package/discount.flang` называется «Discount», а манифест рядом
называет «Скидка». Поэтому `flang package docs/examples/package/discount.flang`
завершается с ошибкой `FLANG_PACKAGE`. Пакет `shop/discount.flang-package`, с которым
работает `shop.flang`, собран из версии модуля с именем «Скидка».

**Шаг 2. Соберите пакет.**

```bash
$ flang package skidka/discount.flang > skidka/discount.flang-package

$ ls skidka/
discount.flang  discount.flang-package  flang.package
```

`flang package` собирает **только проверенный код**: сначала он выполняет те же
проверки, что `flang check`, и из программы с ошибкой пакет не собирает.

Пакет — JSON-файл. Вот он с сокращённым исходником модуля (поле `исходник` —
полный текст модуля, без сжатия и без base64):

```json
{
  "схема": 2,
  "имя": "Скидка",
  "версия": "1.0.0",
  "вход": "./discount.flang",
  "модули": [
    { "имя": "Скидка", "путь": "./discount.flang", "функций": 2,
      "исходник": "модуль «Скидка»\n  экспортирует «Скидка в копейках», «Цена за вычетом»\n…" }
  ],
  "ведомость": [
    { "функция": "Цена за вычетом",
      "утверждение": "цена за вычетом не выходит за точный потолок",
      "сила": "доказано" }
  ],
  "источник": "https://github.com/digitable-lol/flang",
  "печать": "bac0aa0fc8fe3c0b39885d79bdd628cedf8063fad686d76838b248bd4c7fda13"
}
```

Второй список в файле, после списка модулей, — отчёт о доказательствах. У каждого постусловия
библиотеки в нём стоит статус: доказано, проверено только на тестах или не
доказано. По нему удобно выбирать библиотеку. Полагаться на него не
обязательно: при импорте ваш компилятор доказывает всё заново, потому что в
пакете лежит полный исходник.

**Шаг 3. Опубликуйте.** Закоммитьте один файл:

```bash
$ git add skidka/discount.flang-package
$ git commit -m "Скидка 1.0.0"
$ git push
```

Пользователь берёт **этот файл** любым способом: прямой ссылкой, из релиза,
письмом. Команды `flang publish` нет.

## Библиотека из нескольких модулей

Если в библиотеке несколько файлов, в пакет попадают все: `flang package` идёт
по импортам от входного файла. Пользователь пакета этого не видит.

У многомодульного примера `docs/examples/library-api/lib/` манифеста нет,
поэтому `flang package docs/examples/library-api/lib/api.flang` отвечает
`FLANG_PACKAGE: рядом с … нет объявления flang.package`. Положите
`flang.package` рядом с `api.flang` — и шаги те же, что выше.

У каждого модуля в пакете есть адрес — sha256 его исходника, 64
шестнадцатеричных знака. При использовании пакета исходник сравнивается с
адресом, поэтому изменение даже одного байта обнаруживается.

Пакет может импортировать другой пакет:

```
verh.flang            использует «Скидка» из "discount.flang-package"
verh.flang-package    держит и «Верх», и «Скидка»
```

Тому, кто импортирует `verh.flang-package`, файл `discount.flang-package` на
диске не нужен: он внутри.

## Смените версию

Версия записана в `flang.package`. Чтобы выпустить новую, поправьте манифест и
соберите заново:

```bash
$ sed -i 's/"версия": "1.0.0"/"версия": "1.1.0"/' skidka/flang.package
$ flang package skidka/discount.flang --pretty | grep '"версия"'
  "версия": "1.1.0",
```

Не правьте версию внутри собранного пакета. Последнее поле файла — контрольная
сумма по имени, версии, адресу исходников и числу функций каждого модуля, а у
каждого модуля — свой адрес (см. выше). Оба пересчитываются при чтении
пакета, и изменённый пакет не принимается:

```bash
$ sed -i 's/"версия":"1.0.0"/"версия":"9.9.9"/' vitrina/discount.flang-package
$ flang check vitrina/shop.flang
FLANG_PACKAGE: печать пакета «Скидка» не сходится: пакет правлен или испорчен
$ echo $?
1
```

Диапазонов версий (`^1.2`, `~> 1.2`) нет. Программа использует тот файл, что
лежит рядом, и ничего не обновляется само.

## Соберите без сети

Пакету-файлу сеть не нужна: код уже в нём. Модуль по ссылке скачивается один
раз, дальше он берётся из `flang.lock`.

```bash
$ ls
discount.flang-package  shop.flang
$ flang check shop.flang
модуль «Shop»: функций 4, из них с доказанным завершением 4; типов 0; файлов вместе с импортами 2
shop.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Чтобы убедиться, что пакет даёт то же, что исходники библиотеки,
сгенерируйте программу обоими способами и сравните каталоги:

```bash
flang emit shop.flang --target c --out ./from-package   # где лежит пакет
flang emit shop.flang --target c --out ./from-sources   # где лежат исходники
diff -r ./from-package ./from-sources && echo одинаково
```

## Если пакет изменили после сборки

Ошибок две:

```
FLANG_PACKAGE: адрес модуля «Скидка» не сходится с его исходником: правлен или испорчен
FLANG_PACKAGE: печать пакета «Скидка» не сходится: пакет правлен или испорчен
```

Первая значит, что изменён исходник модуля, хотя бы один знак. Вторая — что
изменены версия, имя пакета, адрес исходников или число функций модуля;
слово из сообщения здесь значит «контрольная сумма».

Контрольная сумма показывает, что файл не правили после сборки. Это не
подпись: кто собрал файл, она не говорит.

Если два пакета привезли один и тот же путь модуля с разным содержимым,
компилятор останавливается и называет оба:

```
FLANG_PACKAGE: путь …/obshee.flang привезли два пакета с разным содержимым:
  «Библиотека а 1.0.0» и «Библиотека б 1.0.0». Двух версий одной библиотеки
  в одной программе не бывает: поднимите обе стороны до одной версии
```

Если содержимое одинаковое, программа компилируется: пакеты сравниваются по
содержимому, а не по имени файла.

## Lock-файл и пакет

Оба кладут код в файл, поэтому их легко спутать.

| | `flang lock` | `flang package` |
| --- | --- | --- |
| отвечает на вопрос | «из чего собрана эта программа» | «вот библиотека, берите» |
| имя и версия | нет | обязательны |
| как используется | лежит рядом с программой как `flang.lock` | импортируется через `использует … из "…"` |
| сколько на программу | один | сколько угодно |
| контрольная сумма покрывает | модули | модули, имя, версию, адрес исходников, число функций |

У программы могут быть одновременно `flang.lock` и пакеты.

## Чего нет

- **Команды установки, поиска и публикации.** Ни `flang install`, ни `flang
  search`, ни `flang publish` нет: внешний модуль подключается ссылкой в
  импорте, а публикация — это коммит файла по адресу, который можно назвать.
- **Реестра пакетов.** Списка имён и версий нет: модуль называют адресом.
- **Двух версий одной библиотеки** в одной программе: импорты сливаются в одно
  плоское пространство имён.
- **Частичного обновления.** Чтобы обновить, снова запустите `flang package`.
- **Подписи автора.** Контрольная сумма показывает только, что файл не правили.
- **Пакетов в REPL и в языковом сервере.** `flang repl` и `flang lsp` сами
  разбирают импорты и пакеты не читают. В каталоге, где `flang check shop.flang`
  отвечает «замечаний нет», `flang repl shop.flang` выводит `FLANG_PARSE,
  заголовок модуля, строка 1` и функций библиотеки не видит. Языковой сервер
  не проверялся.
