# Пакеты

Пакет flang — **один файл**, в котором лежит библиотека вместе со всем, от чего
она зависит. Реестра нет, склада нет, `~/.flang` нет. Опубликовать пакет — это
положить файл в git; подключить — написать одну строку; собрать на другой
машине — скопировать туда два файла и запустить `flang check`.

Всё ниже прогнано 18 августа 2026 на `flang 0.5.0`, поставленном
[четвёртым путём установки](install.html) (`npm install`, `node_modules/.bin/flang`).
У двоичного `flang` — того, что ставится из Homebrew и собирается из
`bootstrap/` — команд `package` и `lock` нет, и он это говорит прямо:

```bash
$ flang --version
flang 0.5.0
$ flang package skidka/discount.flang
flang: неизвестная команда «package». «flang --help» — что умеет бинарник.
```

## Подключить чужой пакет

Положите файл пакета рядом со своей программой и напишите одну строку:

```
модуль «Витрина»
  использует «Скидка» из "discount.flang-package"
```

```bash
$ ls
discount.flang-package  shop.flang

$ flang check shop.flang
{"valid":true,"module":"Витрина","functions":[{"name":"Скидка в копейках","total":true},
 {"name":"Цена за вычетом","total":true},{"name":"Цена в витрине","total":true},
 {"name":"Сколько скинули","total":true}],"types":[],"diagnostics":[]}

$ flang test shop.flang
… "total":7,"passed":7,"failed":0 …
```

**Исходников библиотеки в этом каталоге нет.** Их две функции приехали внутри
файла пакета — вместе с примерами, типами и доказанным. Каталог из двух файлов
выше — это весь проект целиком.

Имя в ёлочках обязано совпасть с именем модуля внутри пакета. Не совпало —
отказ, и он называет оба имени:

```bash
$ flang check shop.flang
{"error":"модуль в …/discount.flang-package называется «Скидка»,
 а импортируется как «Скидочка»","diagnostics":[{"code":"FLANG_IMPORT_NAME", …}]}
```

## Объявить свой модуль пакетом

Рядом со входным файлом библиотеки положите `flang.package` — три поля, из
которых обязательны два:

```json
{
  "имя": "Скидка",
  "версия": "1.0.0",
  "источник": "https://github.com/digitable-lol/flang"
}
```

`имя` обязано совпасть с именем модуля в первой строке файла: по нему пакет
подключают, и разойтись им нельзя. Разошлись — отказ до сборки:

```bash
$ flang package skidka/discount.flang
{"error":"в flang.package пакет назван «Не Скидка», а модуль в
 skidka/discount.flang называется «Скидка»", …}
```

Ни одного нового слова в языке для этого не написано: библиотека
`skidka/discount.flang` — обычный модуль с обычной шапкой `модуль` и
`экспортирует`.

## Собрать пакет

```bash
$ flang package skidka/discount.flang > skidka/discount.flang-package

$ ls -la skidka/
-rw-rw-r-- 1 b b 3644 discount.flang
-rw-rw-r-- 1 b b 1554 discount.flang-package
-rw-rw-r-- 1 b b  122 flang.package
```

**3 644 байта исходника — 1 554 байта пакета.** Пакет меньше исходника, потому
что в нём лежит разбор без комментариев и без мест, обратимо сжатый.

Пакет собирается **только из проверенного**: `flang package` сначала прогоняет
те же проверки, что и `flang check`, и на программе с ошибкой типов отказывает.
Обещать за непроверенное было бы враньём.

Вот тот же пакет без груза (поле `исходник` вырезано для чтения):

```json
{
  "схема": 2,
  "имя": "Скидка",
  "версия": "1.0.0",
  "вход": "./discount.flang",
  "модули": [
    { "имя": "Скидка", "путь": "./discount.flang", "функций": 2,
      "адрес": "ca1566c88c2a530f00e41805c7e097a057ad6ec81290ec4781b51a89e53a6022" }
  ],
  "ведомость": [
    { "функция": "Цена за вычетом",
      "утверждение": "цена за вычетом не выходит за точный потолок",
      "сила": "доказано" }
  ],
  "источник": "https://github.com/digitable-lol/flang",
  "печать": "bf6453bfc8b5545adb0ee5d3930fb2e59e7410bd3c2e7c3a9513f396e55ec565"
}
```

## Опубликовать

Коммит одного файла:

```bash
$ git add skidka/discount.flang-package
$ git commit -m "Скидка 1.0.0"
$ git push
```

Тот, кто берёт пакет, скачивает **этот файл** — по `raw`-ссылке, из релиза,
письмом, с флешки. Реестра, в который надо что-то «залить», нет, и `flang
publish` не существует.

## Многомодульная библиотека

Если библиотека сама из нескольких файлов, в пакет едут все:

```bash
$ flang package examples/library-api/lib/api.flang > api.flang-package
$ ls -la api.flang-package
-rw-rw-r-- 1 b b 105937 api.flang-package
```

Внутри — **8 модулей и 53 функции**, 105 937 байт: в нём лежит весь их код
исходником, поэтому пакет размером примерно с то, что он заменяет, а не меньше.
В репозитории он занимает 21 111 байт: git жмёт объекты сам.

До 19 августа 2026 этот же пакет весил 13 161 байт — груз жался brotli. Сжатие
из формата убрано решением владельца: эталонный кодировщик brotli не написать в
двоичном компиляторе, а без него `flang package` навсегда остался бы командой
инструментария на Node. Адрес модуля теперь sha256 его исходника — 64 знака,
и по нему груз проверяется (`docs/lockfile-without-store.md`).

Замыкание берётся по рёбрам импорта и уходит за пределы каталога библиотеки,
если так написано у автора: `catalog.flang` тянет `«Списки»` из
`"../../../flang/stdlib/lists.flang"`, и `lists.flang` едет в пакет наравне с
остальными. Тому, кто пакет подключит, знать об этом не нужно.

Пакет может стоять и над пакетом:

```
verh.flang            использует «Скидка» из "discount.flang-package"
verh.flang-package    внутри — и «Верх», и «Скидка»
```

У того, кто подключил `verh.flang-package`, файла `discount.flang-package` на
диске нет вовсе, и `flang check` его не ищет: он лежит грузом внутри верхнего.

## Зафиксировать версию

Версия живёт в `flang.package` и **заверена печатью пакета**. Поднять её —
править объявление и пересобрать:

```bash
$ sed -i 's/"версия": "1.0.0"/"версия": "1.1.0"/' skidka/flang.package
$ flang package skidka/discount.flang --pretty | grep '"версия"'
  "версия": "1.1.0",
```

Править версию в готовом файле пакета бесполезно: печать пересчитывается на
чтении и не сходится.

```bash
$ sed -i 's/"версия":"1.0.0"/"версия":"9.9.9"/' vitrina/discount.flang-package
$ flang check vitrina/shop.flang
{"error":"печать пакета «Скидка» не сходится: пакет правлен или испорчен", …}
```

Диапазонов версий (`^1.2`, `~> 1.2`) нет. В программу едет ровно тот файл,
который в неё положили, и «обновиться само» не может ничего.

## Собрать без сети

Специального ключа для этого нет — он не нужен. Сборка **не ходит в сеть
никогда**: качать неоткуда, потому что код уже в файле.

```bash
$ ls
discount.flang-package  shop.flang
$ flang check shop.flang
{"valid":true,"module":"Витрина", …}
```

Это же и ответ на «соберётся ли на другой машине»: перенесите два файла — и
соберётся. Проверено побайтово: печать программы в C из пакета совпала с
печатью из исходников знак в знак
([`flang/test/package.test.mjs`](https://github.com/digitable-lol/flang/blob/main/flang/test/package.test.mjs)).

## Что пакет везёт про доказательства, а что нет

В пакете лежит `ведомость` — что ядро сказало про функции автора: `доказано`,
`сетка N`, `объявлено, не доказано`. Это **справка**, по которой выбирают
библиотеку, а не доверенный корень: тот, кто пакет подключил, доказывает всё
заново, потому что тела чужих функций приехали целиком.

И вот граница, которую надо знать до того, как на пакет сошлётесь.
**`обеспечивает` достаётся вызывающему готовым. `требует` платит каждое место
вызова.** Снимите у себя `требует` — и программа не соберётся, хотя библиотека
не менялась:

```bash
$ flang check shop.flang
{"code":"FLANG_PRECONDITION_CALL",
 "message":"вызов «Скидка в копейках» в функции «Сколько скинули» не снимает
  предусловие «доля не больше ста»: …"}
```

Иначе предусловие было бы аксиомой под другим именем, и в языке, у которого
список аксиом — пустой `Object.freeze([])`, ей взяться неоткуда.

Почему ведомость — справка, а не кеш вердиктов, названо числом. Кеш вердиктов по
адресу содержимого в дереве есть, и перемерено на 99 файлах корпуса с
обязательствами, одним процессом, на прогретом коде:

| что | время |
| --- | ---: |
| ядро доказательства — всё, что пакет мог бы сэкономить | **111 мс** |
| адреса определений — всё, что пакет обязан потратить | **145 мс** |

Ключ, которым доказательство кешируют, сегодня дороже самого доказательства.
Пакет, который вёз бы вердикты вместо справки, был бы медленнее и при этом
обязан был бы им верить.

## Что ловится и как это выглядит

Проверено пятью подменами одного и того же файла пакета:

| Испортили | Ответ |
| --- | --- |
| один знак в грузе модуля | `FLANG_PACKAGE`: «груз модуля «Скидка» в пакете «Скидка 1.0.0» не разворачивается» |
| версию | `FLANG_PACKAGE`: «печать пакета «Скидка» не сходится» |
| имя пакета | `FLANG_PACKAGE`: «печать пакета не сходится» |
| источник | `FLANG_PACKAGE`: «печать пакета не сходится» |
| число функций в модуле | `FLANG_PACKAGE`: «печать пакета не сходится» |

Печать заверяет **всё, что пакет о себе говорит**, а не только груз: имя,
версию, источник, число функций каждого модуля. Это отличие от замка
([`flang lock`](#замок-против-пакета)), у которого сопроводительные числа не
заверены и правятся молча.

Печать — не подпись: у неё нет тайны. Она отвечает на вопрос «файл не правили»,
а не «файл от того, от кого думаете».

## Две версии одной библиотеки

Их не бывает, и пакет этого не меняет: импорт в flang сливает объявления в одно
плоское пространство имён. Отказ разобран в
[Модульности и пакетах](modules.html) и записан в [роадмапе](roadmap.html).

Что пакет меняет — только сообщение. Раньше ромб выходил жалобой на случайную
функцию:

```
FLANG_DUPLICATE_NAME: функция «Есть в множестве» объявлена в двух модулях:
  …/v1/sets.flang и …/v2/sets.flang
```

Теперь он называет пакеты, версии и то, что делать:

```
FLANG_PACKAGE: путь …/obshee.flang привезли два пакета с разным содержимым:
  «Библиотека а 1.0.0» и «Библиотека б 1.0.0». Двух версий одной библиотеки
  в одной программе не бывает: поднимите обе стороны до одной версии
```

Если обе стороны везут **одно и то же** содержимое, ромб разрешается сам собой
и молча: пакеты сличаются по грузу, а не по имени файла.

## Замок против пакета

Обе команды кладут код внутрь файла, и путают их легко.

| | `flang lock` | `flang package` |
| --- | --- | --- |
| про что | «из чего собрана ЭТА программа» | «вот библиотека, берите» |
| имя и версия | нет | обязательны |
| как подключается | лежит рядом под именем `flang.lock` | пишется строкой `использует … из "…"` |
| сколько на программу | один | сколько угодно |
| печать заверяет | груз | груз, имя, версию, источник, число функций |

Одно другому не мешает: программа вправе иметь и `flang.lock`, и пакеты.

## Чего нет — списком

- **реестра и поиска.** Найти пакет по имени негде; `flang publish`, `flang
  add`, `flang search` не существуют;
- **диапазонов версий и разрешения зависимостей.** Ни `^`, ни `~>`, ни
  `latest`. Какой файл положили, такой и собрался;
- **двух версий одной библиотеки** в одной программе — см. выше;
- **частичного обновления.** Обновление — это `flang package` заново целиком: в
  файле лежит код, а не хеш, и подменить в нём одну зависимость нечем;
- **подписи автора.** Печать — самозаверение целостности, а не подпись;
- **пакетов в оболочке и в языковом сервере.** `flang repl` и `flang-lsp`
  зовут связывание сами и про пакеты не знают. Прогон: `flang repl shop.flang`
  в том же каталоге, где `flang check` отвечает `{"valid":true,…}`, даёт
  `FLANG_PARSE, заголовок модуля, строка 1`. Та же доделка, что и у замка;
- **пакетов у двоичного `flang`.** Команд `package` и `lock` в нём нет —
  прогон выше.
