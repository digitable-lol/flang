# Пакеты

Пакет flang — **один файл**, в котором лежит библиотека вместе со всем, что она
импортирует. Кеша пакетов нет, а реестр — [список имён](registry.html), а не
склад кода: команды двоичного у него нет, он отвечает адресом. Чтобы
опубликовать пакет, закоммитьте файл в git; чтобы им пользоваться, положите файл
рядом с программой и напишите одну строку импорта. Для сборки на другой машине
нужны только ваша программа и файл пакета, в сеть сборка не ходит никогда.

Работают две команды двоичного `flang`: `flang package` собирает пакет,
`flang lock` пишет lock-файл для всей программы. У обеих есть `--help`. Примеры
ниже — на `docs/examples/package/`.

## Подключите пакет

1. Положите файл пакета рядом со своей программой.
2. Импортируйте его по имени модуля:

```
модуль «Shop»
  использует «Скидка» из "discount.flang-package"
```

3. Проверяйте и тестируйте как обычно:

```bash
$ ls
discount.flang-package  shop.flang

$ flang check shop.flang
модуль «Shop»: функций 4, из них с доказанным завершением 4; типов 0; файлов вместе с импортами 2
shop.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет

$ flang test shop.flang
shop.flang: примеров 7, прошло 7, не прошло 0
```

Исходников библиотеки в каталоге нет: её функции пришли внутри файла пакета —
вместе с unit-тестами, типами и доказательствами.

Имя в импорте обязано совпасть с именем модуля внутри пакета. Иначе проверка
падает и называет оба:

```bash
$ flang check shop.flang
FLANG_IMPORT_NAME, строка 1, столбец 1: модуль в …/discount.flang-package называется «Скидка», а импортируется как «Скидочка»
shop.flang: не проверено — замечаний 1
```

Предусловия (`требует`) функций библиотеки приходят вместе с пакетом, и ваш
код обязан выполнять их в каждом вызове. Уберите `требует` у своей функции — и
программа перестанет компилироваться, хотя библиотека не менялась:

```bash
$ flang check shop.flang
FLANG_PRECONDITION_CALL, строка 34, столбец 3: вызов «Скидка в копейках» в функции «Сколько скинули» не снимает предусловие «доля не больше ста»: …
shop.flang: не проверено — замечаний 1
```

## Поставьте пакет по имени из реестра

Пакет, который есть в [списке реестра](registry.html), ставится одной командой.
Назовите файл своей программы и имя пакета, при желании — с диапазоном версий:

```bash
$ flang install проба/proba.flang 'Множество строк: не ниже 1.1'
поставлено пакетов: 3 рядом с проба/proba.flang; замок проба/flang.lock — 65547 знаков:
  · Множество строк 1.1.0 → sets.flang-package: доказано 4 из 18 обязательств
  · Списки 1.4.2 → lists.flang-package: доказано 15 из 39 обязательств
  · Логика 1.2.0 → logic.flang-package: доказано 4 из 7 обязательств
$ echo $?
0
```

Команда `flang install` доезжает до двоичного печатью семени (партия 9c); в
исходниках она есть. В двоичном 0.7.30 той же командой служит ярлык из дерева flang —
`flang run-script package:install проба/proba.flang 'Множество строк: не ниже 1.1'`;
это и есть движок, который `flang install` зовёт внутри.

Что происходит за этой строкой:

1. нужда дописывается в файл `flang.needs` рядом с программой (по нужде на
   строку: `Логика: не ниже 1.0`); без имени в команде ставится всё, что в файле;
2. берётся список реестра — по адресу из ключа `--registry`, иначе из ключа
   `registry` в `.flangrc`, иначе с постоянного адреса на GitHub;
3. по нуждам проекта и нуждам самих пакетов выбирается наибольшая годная версия
   каждого имени; одно имя — одна версия; невыполнимые вместе нужды — отказ
   `FLANG_INSTALL_CONFLICT`, который называет каждый диапазон и кто его потребовал;
4. каждый пакет скачивается, и `sha256` тела сверяется с записью списка **до**
   записи на диск: не сошёлся — `FLANG_INSTALL_FINGERPRINT`, и ни один файл не
   записан;
5. файлы ложатся рядом с программой под именем из списка без версии
   (`sets-1.1.0.flang-package` → `sets.flang-package`), чтобы строка `использует
   «Множество строк» из "sets.flang-package"` не менялась при подъёме версии;
6. программа проверяется `flang check` и запирается `flang lock`: в `flang.lock`
   ложатся сами исходники, и дальше сборка в сеть не ходит.

Пакет, который несёт `закон` или утверждение «объявлено, не доказано»,
расширяет то, чему вы верите без доказательства. Такой пакет показывается
отдельной строкой и ставится только с ключом `--accept-unproven`. Доля
доказанного печатается у каждого пакета всегда.

### Подпись автора

У пакета в списке реестра шестым полем стоит открытый ключ автора, а рядом с
файлом пакета — файл подписи `<пакет>.minisig` в формате minisign. Установщик
проверяет подпись после сверки `sha256` и до записи на диск; подписан отпечаток
файла, ключ — Ed25519
([ADR-0200](../adr/0200-a-package-is-signed-by-its-author-and-the-key-is-pinned-on-first-use.md)).

- **Первая установка закрепляет ключ.** В `flang.lock` ложится поле `"подписи"`:
  `{"имя": "Логика", "ключ": "RWTrVUCh…"}`. Строка итога это говорит:
  `подпись: ключ 37F92EEFA14055EB, сошлась за … мс; ключ закреплён при первой установке`.
- **Ключ сменился — отказ.** Следующая установка, у которой ключ имени в списке
  не тот, что в замке, отвечает `FLANG_INSTALL_KEY_CHANGED` и ничего не пишет.
  Перезакрепить ключ — `--repin <имя>` или доверенный ключ в `.flangrc` (ниже).
- **Пакет без подписи по умолчанию не ставится** — `FLANG_INSTALL_UNSIGNED`. С
  ключом `--allow-unsigned` ставится, и замок пишет `"ключ": "нет"`.
- **Доверенные ключи** лежат в `.flangrc` рядом с программой, по строке на ключ:

  ```
  trusted-key = Логика: RWTrVUCh7y75N1WY0UnU8KRab7XMZxBpTborOVlZkHnrLydNeUm9BH2B
  ```

  Есть у имени доверенные ключи — ключ из списка обязан быть одним из них
  (`FLANG_INSTALL_KEY_UNTRUSTED`), и смена ключа на доверенный проходит без
  `--repin`. Доверенный ключ защищает и первую установку, которую закрепление
  при первом использовании не защищает.

Ключ `RWTrVUCh7y75N1WY0UnU8KRab7XMZxBpTborOVlZkHnrLydNeUm9BH2B` — пробный ключ
образца: им подписаны только пакеты `scripts/registry-example/` и пакет пробы
установщика, и ни для чего настоящего он не доверен. Автор настоящего пакета
заводит свой ключ — `flang run-script package:keygen <каталог вне дерева>`.

Проверка подписи считается на вычислителе flang и не быстрая: одна подпись проверяется 11–12 секунд, и
проверка модулей подписи добавляет к старту установки около сорока секунд.

Повторная установка в пустой каталог даёт тот же `flang.lock` знак в знак — это
проверяет `flang run-script package-install:check`, и то же делает работа CI
`package-install` на чистом образе. Диапазоны записываются словами, а не
знаками: `любая`, `ровно 1.2.3`, `не ниже 1.2.3`, `в пределах 1.x`. Коды отказов —
в таблице ниже.

Как это устроено внутри: установщик — программа на flang
(`scripts/package-install.fscript`), которую `flang install` находит рядом с
двоичным (в дереве — `scripts/`, у поставленного — `share/flang/scripts/`) и
исполняет своим исполнителем планов. Из дерева flang тот же план зовётся
ярлыком `flang run-script package:install` — так он проверяется и так он
работает до печати 9c.

### Коды отказов установщика

Число выхода у всех — 1; код стоит в ответе вместе с причиной.

| Код | Что значит | Что делать |
|---|---|---|
| `FLANG_INSTALL_USAGE` | команда позвана без файла программы или с неизвестным ключом | `flang install <программа.flang> [<имя>[: <диапазон>]]... [--registry <адрес>] [--accept-unproven] [--allow-unsigned] [--repin <имя>]...` |
| `FLANG_INSTALL_ENGINE` | рядом с двоичным нет движка `package-install.fscript` (ни в `scripts/`, ни в `share/flang/scripts/`) | поставить flang целиком — тарболлом, `install.sh`, Homebrew или asdf; из дерева звать `flang run-script package:install` |
| `FLANG_INSTALL_LEDGER` | список реестра или файл пакета не получен (адрес ответил не 200, файла нет) либо список не разобран | проверить адрес: ключ `--registry` или `registry` в `.flangrc`; формат списка — `docs/registry-list-format.md` |
| `FLANG_INSTALL_NEEDS` | нужды проекта в `flang.needs` не разобраны | писать `имя: диапазон`, по нужде на строку; диапазоны — `любая`, `ровно 1.2.3`, `не ниже 1.2.3`, `в пределах 1.x` |
| `FLANG_INSTALL_CONFLICT` | нужды вместе невыполнимы или имени в реестре нет; отказ называет каждый диапазон, кто его потребовал и какие версии реестр знает | ослабить диапазон или поднять обе стороны до одной версии |
| `FLANG_INSTALL_FINGERPRINT` | отпечаток `sha256` полученного тела не совпал с записью реестра; на диск ничего не записано | подменённый или испорченный пакет — не ставить; сообщить держателю списка |
| `FLANG_INSTALL_SIGNATURE` | у пакета с ключом нет файла подписи, он не разобран, подписан другим ключом или подпись не сошлась с отпечатком; на диск ничего не записано | не ставить; сообщить автору и держателю списка |
| `FLANG_INSTALL_UNSIGNED` | у пакета в списке нет ключа автора | поставить с `--allow-unsigned`, если верите источнику; замок запишет `"ключ": "нет"` |
| `FLANG_INSTALL_KEY_CHANGED` | ключ имени в списке не совпал с закреплённым в `flang.lock`; отказ называет оба номера ключа | узнать у автора о смене ключа; перезакрепить `--repin <имя>` или `trusted-key` в `.flangrc` |
| `FLANG_INSTALL_KEY_UNTRUSTED` | у имени есть доверенные ключи в `.flangrc`, а ключ из списка — не из них | не ставить, пока ключ не подтверждён; либо дописать его в `trusted-key` |
| `FLANG_INSTALL_UNPROVED` | пакет несёт `закон` или «объявлено, не доказано» и расширил бы доверенную базу | прочитать названные строки; если согласны — повторить с `--accept-unproven` |
| `FLANG_INSTALL_BUILD` | после установки `flang check` или `flang lock` над программой ответили не нулём | прочитать их ответ в сообщении; обычно в программе нет строки `использует «Имя» из "файл.flang-package"` |

## Сделайте свой пакет

**Шаг 1. Напишите манифест.** Положите `flang.package` рядом с входным файлом
библиотеки:

```json
{
  "имя": "Скидка",
  "версия": "1.0.0",
  "источник": "https://github.com/digitable-lol/flang"
}
```

`имя` и `версия` обязательны, `источник` (адрес исходников) — нет. `имя` обязано
совпасть с именем модуля в первой строке входного файла: по этому имени пакет
импортируют. Разошлись — `flang package` отказывает:

```bash
$ flang package skidka/discount.flang
FLANG_PACKAGE: в flang.package пакет назван «Не Скидка», а модуль в skidka/discount.flang называется «Скидка»
$ echo $?
1
```

Самой библиотеке ничего особого не нужно: `skidka/discount.flang` — обычный
модуль с обычной шапкой `модуль` / `экспортирует`.

В примере из репозитория именно такое расхождение: модуль в
`docs/examples/package/discount.flang` называется «Discount», а манифест рядом
говорит «Скидка». Поэтому `flang package docs/examples/package/discount.flang`
отказывает с `FLANG_PACKAGE`. Пакет `shop/discount.flang-package`, с которым
работает `shop.flang`, собран из версии модуля с именем «Скидка».

**Шаг 2. Соберите пакет.**

```bash
$ flang package skidka/discount.flang > skidka/discount.flang-package

$ ls -la skidka/
-rw-rw-r-- 1 b b 3644 discount.flang
-rw-rw-r-- 1 b b 4343 discount.flang-package
-rw-rw-r-- 1 b b  122 flang.package
```

`flang package` собирает **только проверенный код**: сначала он прогоняет те же
проверки, что `flang check`, и программу с ошибкой не пакует.

Пакет — JSON-файл. Вот он с сокращённым исходником модуля (поле `исходник` —
полный текст модуля, без сжатия и без base64):

```json
{
  "схема": 2,
  "имя": "Скидка",
  "версия": "1.0.0",
  "вход": "./discount.flang",
  "модули": [
    { "имя": "Скидка", "путь": "./discount.flang", "функций": 2,
      "исходник": "модуль «Скидка»\n  экспортирует «Скидка в копейках», «Цена за вычетом»\n…" }
  ],
  "ведомость": [
    { "функция": "Цена за вычетом",
      "утверждение": "цена за вычетом не выходит за точный потолок",
      "сила": "доказано" }
  ],
  "источник": "https://github.com/digitable-lol/flang",
  "печать": "bac0aa0fc8fe3c0b39885d79bdd628cedf8063fad686d76838b248bd4c7fda13"
}
```

Поле `ведомость` — отчёт о доказательствах: по каждому постусловию библиотеки
сказано, доказал ли его prover (`доказано`), проверено ли оно только на примерах
(`сетка N`) или у него нет ни доказательства, ни примеров (`объявлено, не
доказано`). По нему удобно выбирать библиотеку. Верить ему не обязательно: при
импорте ваш компилятор доказывает всё заново, потому что внутри полный
исходник.

**Шаг 3. Опубликуйте.** Закоммитьте один файл:

```bash
$ git add skidka/discount.flang-package
$ git commit -m "Скидка 1.0.0"
$ git push
```

Пользователь скачивает **этот файл** любым способом: прямой ссылкой, из
релиза, письмом — или ставит его по имени, если файл и его `sha256` записаны в
[список реестра](registry.html). `flang publish` нет.

**Шаг 4. Подпишите.** Ключ заводится один раз, вне дерева проекта:

```bash
$ flang run-script package:keygen ~/.flang-keys
key 37F92EEFA14055EB: …/flang-package.key, …/flang-package.pub; list key RWTrVUCh7y75N1WY0UnU8KRab7XMZxBpTborOVlZkHnrLydNeUm9BH2B

$ flang run-script package:sign skidka/discount.flang-package ~/.flang-keys/flang-package.key
signed by key 37F92EEFA14055EB: skidka/discount.flang-package.minisig; registry list: fingerprint …, key RWTrVUCh…

$ flang run-script package:verify skidka/discount.flang-package RWTrVUCh7y75N1WY0UnU8KRab7XMZxBpTborOVlZkHnrLydNeUm9BH2B
signature and trusted comment verified, key 37F92EEFA14055EB: flang package «Скидка» 1.0.0 sha256 …
```

Ключи — формат minisign: тайный ключ без пароля (как `minisign -G -W`), открытый —
строка `RW…`. Подписать можно и самой программой `minisign`: подписывается
отпечаток, а не файл (`printf %s <sha256> > statement && minisign -Sm statement`),
а файл подписи кладётся рядом с пакетом под именем `<пакет>.minisig`. `Keygen` не
перезаписывает существующий ключ (`FLANG_SIGN_EXISTS`); тайный ключ в дерево не
кладётся. Рядом с пакетом коммитятся файл подписи и строка списка с ключом.

## Библиотека из нескольких модулей

Если в библиотеке несколько файлов, в пакет попадают все: `flang package` идёт
по импортам от входного файла. Пользователь пакета этого не видит.

У многомодульного примера `docs/examples/library-api/lib/` манифеста нет,
поэтому `flang package docs/examples/library-api/lib/api.flang` отвечает
`FLANG_PACKAGE: рядом с … нет объявления flang.package`. Положите
`flang.package` рядом с `api.flang` — и шаги те же, что выше.

У каждого модуля в пакете есть адрес — sha256 его исходника, 64
шестнадцатеричных знака. При использовании пакета исходник сверяется с
адресом, поэтому изменение даже одного байта обнаруживается.

Пакет может импортировать другой пакет:

```
verh.flang            использует «Скидка» из "discount.flang-package"
verh.flang-package    держит и «Верх», и «Скидка»
```

Тому, кто импортирует `verh.flang-package`, файл `discount.flang-package` на
диске не нужен: он внутри.

## Смените версию

Версия живёт в `flang.package`. Чтобы выпустить новую, поправьте манифест и
соберите заново:

```bash
$ sed -i 's/"версия": "1.0.0"/"версия": "1.1.0"/' skidka/flang.package
$ flang package skidka/discount.flang --pretty | grep '"версия"'
  "версия": "1.1.0",
```

Не правьте версию внутри собранного пакета. У пакета есть контрольная сумма
(`печать`) по имени, версии, адресу исходников и числу функций каждого модуля, а
у каждого модуля — свой адрес (см. выше). Оба пересчитываются при чтении
пакета, и правленый пакет отвергается:

```bash
$ sed -i 's/"версия":"1.0.0"/"версия":"9.9.9"/' vitrina/discount.flang-package
$ flang check vitrina/shop.flang
FLANG_PACKAGE: печать пакета «Скидка» не сходится: пакет правлен или испорчен
$ echo $?
1
```

Диапазонов версий в знаках (`^1.2`, `~> 1.2`) нет. Программа использует ровно
тот файл, что лежит рядом, и ничего не обновляется само; выбор версии делает
установщик по словесным диапазонам из `flang.needs` (см. выше).

## Соберите без сети

Флага для этого нет, потому что он не нужен: **сборка в сеть не ходит
никогда**. Код уже в файле пакета.

```bash
$ ls
discount.flang-package  shop.flang
$ flang check shop.flang
модуль «Shop»: функций 4, из них с доказанным завершением 4; типов 0; файлов вместе с импортами 2
shop.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Чтобы убедиться, что пакет даёт то же, что исходники библиотеки,
сгенерируйте программу обоими способами и сравните каталоги:

```bash
flang emit shop.flang --target c --out ./from-package   # где лежит пакет
flang emit shop.flang --target c --out ./from-sources   # где лежат исходники
diff -r ./from-package ./from-sources && echo одинаково
```

## Как выглядит правленый пакет

| Что правили | Ошибка |
| --- | --- |
| один знак в исходнике модуля | `FLANG_PACKAGE`: «адрес модуля «Скидка» не сходится с его исходником: правлен или испорчен» |
| версию | `FLANG_PACKAGE`: «печать пакета «Скидка» не сходится: пакет правлен или испорчен» |
| имя пакета | то же, в кавычках — правленое имя |
| адрес исходников | `FLANG_PACKAGE`: «печать пакета «Скидка» не сходится: пакет правлен или испорчен» |
| число функций модуля | `FLANG_PACKAGE`: «печать пакета «Скидка» не сходится: пакет правлен или испорчен» |

Контрольная сумма показывает, что файл не правили после сборки; кто собрал
файл, говорит подпись автора (раздел «Подпись автора» выше).

Если два пакета привезли один и тот же путь модуля с разным содержимым,
компилятор останавливается и называет оба:

```
FLANG_PACKAGE: путь …/obshee.flang привезли два пакета с разным содержимым:
  «Библиотека а 1.0.0» и «Библиотека б 1.0.0». Двух версий одной библиотеки
  в одной программе не бывает: поднимите обе стороны до одной версии
```

Если содержимое одинаковое, программа компилируется: пакеты сравниваются по
содержимому, а не по имени файла.

## Lock-файл и пакет

Оба кладут код в файл, поэтому их легко спутать.

| | `flang lock` | `flang package` |
| --- | --- | --- |
| отвечает на вопрос | «из чего собрана эта программа» | «вот библиотека, берите» |
| имя и версия | нет | обязательны |
| как используется | лежит рядом с программой как `flang.lock` | импортируется через `использует … из "…"` |
| сколько на программу | один | сколько угодно |
| контрольная сумма покрывает | модули | модули, имя, версию, адрес исходников, число функций |

У программы могут быть одновременно `flang.lock` и пакеты.

## Чего нет

- **`flang install` в двоичном 0.7.30.** Команда доезжает печатью 9c; до неё
  установка идёт тем же планом из дерева flang (`flang run-script
  package:install`). `flang publish` и `flang search` нет — публикация это
  коммит файла и строка в списке реестра.
- **Чужих пакетов в реестре.** В списке лежат только пакеты примера.
- **Двух версий одной библиотеки** в одной программе: импорты сливаются в одно
  плоское пространство имён.
- **Частичного обновления.** Чтобы обновить, снова запустите `flang package`.
- **Отзыва ключей.** Сменивший ключ автор меняет поле ключа в списке, а у тех,
  кто уже ставил пакет, установщик отказывает, пока ключ не перезакреплён.
- **Пакетов в REPL и в языковом сервере.** `flang repl` и `flang lsp` сами
  разбирают импорты и пакеты не читают. В каталоге, где `flang check shop.flang`
  отвечает «замечаний нет», `flang repl shop.flang` печатает `FLANG_PARSE,
  заголовок модуля, строка 1` и функций библиотеки не видит. Языковой сервер
  не проверялся.
