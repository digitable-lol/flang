# Как писать пакеты

Коротко и сразу: **склада пакетов нет**. Нет реестра, нет `flang add`, нет
версий и разрешения конфликтов. Есть две вещи, которые работают, и обе прогнаны
на этой странице: **подключение путём** и **замок**, кладущий зависимости внутрь
себя.

## Модуль — это файл

```
модуль «Операции»
  использует «Списки» из "../../flang/stdlib/lists.flang"
  использует «Строки» из "../../flang/stdlib/strings.flang"
```

Правила три, и все три проверяются:

1. **Имя обязано совпасть.** Модуль в файле называет себя сам первой строкой;
   расходится с тем, как его импортируют, — отказ:
   `модуль в …/sets.flang называется «Множество строк», а импортируется как
   «Множества»`. Так ловится переезд файла, о котором забыли;
2. **Путь относительный** — от файла, который импортирует;
3. **Экспорт объявляется.** Строка `экспортирует` перечисляет имена, видные
   снаружи. Нет строки — снаружи видно всё, что объявлено.

Библиотека языка устроена ровно так же: `flang/stdlib/` — шестнадцать файлов,
никакой особой связи с компилятором у них нет. Свой пакет — это файл, лежащий
где угодно.

## Замок: зависимости внутри файла

```bash
node flang/bin/flang.mjs lock docs/examples/operations.flang > flang.lock
```

Прогон 18 августа 2026: на файл в **4 764 байта** с пятью импортами замок вышел
**14 343 байта**. Внутри — JSON с полями `схема`, `вход`, `модули`, `печать`, и
в каждом модуле лежит **сам разбор зависимости**, обратимо сжатый, а не ссылка
на неё и не хеш.

Отсюда главное свойство, и оно проверено прогоном: **исходников зависимостей на
диске может не быть вовсе**. Файл и замок скопированы в пустой каталог, где до
`flang/stdlib/` не дотянуться ни одним относительным путём:

```
$ ls
flang.lock  operations.flang
$ node …/flang.mjs check operations.flang
{"valid":true,"module":"Операции","functions":[…99 функций…],"diagnostics":[]}
```

Все 99 функций на месте, включая 93 из библиотеки. Склада нет — скачивать
неоткуда, потому что всё уже в замке.

Замок берётся автоматически: лежит `flang.lock` рядом с входным файлом — все
команды читают импорты из него.

## Что замок ловит, а что нет

Проверено тремя порчами одного и того же файла:

| Испортили | Ответ |
| --- | --- |
| один символ в теле модуля (`адрес`) | отказ `FLANG_LOCK`: «Decompression failed» |
| первый символ печати замка | отказ `FLANG_LOCK`: «печать замка не сходится: замок правлен или испорчен» |
| поле `функций` с 28 на 27 | **принят молча, проверка прошла** |

Третья строка — не придирка к мелочи, а граница честности замка: печать
заверяет **код**, а сопроводительные числа рядом с ним не заверяет. Число
`функций` — справка для человека, читающего замок глазами; программа его не
сверяет. Знать это надо до того, как на него сошлётесь в отчёте.

## Чего нет — списком

- **реестра и склада.** Опубликовать пакет некуда, `flang add` не существует;
- **версий.** В замке нет ни номера версии зависимости, ни диапазона; в
  `использует` — тоже. Обновление зависимости — это `lock` заново, целиком;
- **разрешения конфликтов.** Два модуля с одним именем в одном замке — случай,
  который не разбирался; ставить на него нельзя;
- **частичного обновления.** Замок обновляется целиком: в нём лежит код, а не
  хеш, и подменить в нём одну зависимость нечем, кроме нового `lock`;
- **подписи автора.** Печать замка — самозаверение целостности, а не подпись:
  она отвечает на вопрос «файл не правили», а не «файл от того, от кого думаете».

Что из этого когда появится — [Роадмап](roadmap.html). Ставить сегодня стоит на
две работающие вещи: путь и замок.
