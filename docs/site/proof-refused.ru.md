# Ядро отказало: чья это ошибка

Ядро — prover, часть компилятора, которая доказывает постусловия — отвергает
написанную вами теорему одним из {{отказы.всего}} кодов. Первые
{{отказы.обязательств}} говорят, что теорема не сошлась с функцией, и чинятся
правкой теоремы: `FLANG_PROOF_NO_GOAL`, `FLANG_PROOF_AMBIGUOUS`,
`FLANG_PROOF_DUPLICATE`, `FLANG_PROOF_CLAIM_MISMATCH`, `FLANG_PROOF_UNFINISHED`,
`FLANG_PROOF_UNKNOWN_VAR`, `FLANG_PROOF_VAR_TYPE`. Остальные {{отказы.вывода}}
говорят, что вывод не построен, и это либо ваша ошибка, либо граница языка:
`FLANG_PROOF_STEP`, `FLANG_PROOF_INDUCTION_STEP`, `FLANG_PROOF_INDUCTION_TYPE`,
`FLANG_PROOF_INDUCTION_BRANCH`, `FLANG_PROOF_INDUCTION_CASES`,
`FLANG_PROOF_INDUCTION_DESCENT`. Тексты сообщений ниже — вывод
`flang {{выпуск.версия}}`.

Отказ — это код возврата 1 и строка `не проверено — замечаний N`. Постусловие
без теоремы, которое ядро не вывело, отказом не считается: `flang check`
отвечает кодом 0, а что с ним на самом деле, говорит `flang check --proof` —
см. [три ответа](how-proofs-work.html#обеспечивает-постусловие-и-три-ответа).

## Как читать сообщение

```
FLANG_PROOF_NO_GOAL в файле проба.flang, строка 23, столбец 1: теорема
«штраф положителен» ничего не закрывает: постусловия «штраф положителен» нет
ни у одной функции модуля. Теорема доказывает названное утверждение, а не
утверждение вообще — назовите её так же, как постусловие, которое она
закрывает
```

Код, файл, строка, столбец, текст. Дочитывайте текст до конца: у
`FLANG_PROOF_STEP` и `FLANG_PROOF_INDUCTION_STEP` он кончается тем, что ядру
было известно в этом месте (`известно: предусловие функции «Сумма»` или
`не известно ничего`). Пусто — не хватило факта, и это ваша ошибка.
Перечислены правила, а цель ни под одно не подходит — граница ядра.

## Теорема не сошлась с функцией

Эти отказы чинятся в самой теореме.

| Код | Что случилось | Что править |
| --- | --- | --- |
| `FLANG_PROOF_NO_GOAL` | постусловия с таким именем нет ни у одной функции модуля | имя теоремы: оно обязано совпасть с именем постусловия |
| `FLANG_PROOF_AMBIGUOUS` | под имя теоремы подходят два постусловия | дайте постусловиям разные имена |
| `FLANG_PROOF_DUPLICATE` | у одного постусловия больше одной теоремы | оставьте одну |
| `FLANG_PROOF_CLAIM_MISMATCH` | `утверждаем` написано не так, как постусловие | перепишите слово в слово: ядро не решает, что две записи означают одно |
| `FLANG_PROOF_UNFINISHED` | нет строки `следовательно доказано` | допишите её |
| `FLANG_PROOF_UNKNOWN_VAR` | `дано` вводит имя, которого у функции нет | назовите параметр так, как он назван в функции |
| `FLANG_PROOF_VAR_TYPE` | у переменной теоремы и у параметра разные типы | поставьте объявленный тип параметра |

Пример: у теоремы и постусловия разошлись имена.

```flang refused
модуль «Проба»

тип «Светофор»
  вариант «Красный»
  вариант «Зелёный»

тотальная функция «Штраф»
  принимает свет: «Светофор»
  возвращает число
  для всех свет обеспечивает «штраф неотрицателен» результат не меньше 0
  пример «красный»
    дано свет равно вариант «Красный»
    ожидается 500
  пример «зелёный»
    дано свет равно вариант «Зелёный»
    ожидается 0
  разбор свет
    случай вариант «Красный»
      то 500
    случай вариант «Зелёный»
      то 0

теорема «штраф положителен»
  дано свет: «Светофор»
  утверждаем результат не меньше 0
  индукция по свет
    случай вариант «Красный»
      то по примеру «красный»
    случай вариант «Зелёный»
      то по примеру «зелёный»
  следовательно доказано
```

```
$ flang check проба.flang; echo "код $?"
модуль «Проба»: функций 1, из них с доказанным завершением 1; типов 1
FLANG_PROOF_NO_GOAL в файле проба.flang, строка 23, столбец 1: теорема
«штраф положителен» ничего не закрывает: …
проба.flang: не проверено — замечаний 1
код 1
```

Назовите теорему `«штраф неотрицателен»` — файл пройдёт с кодом 0.

## Вывод не построен

| Код | Что случилось | Чья это ошибка |
| --- | --- | --- |
| `FLANG_PROOF_INDUCTION_CASES` | случаи теоремы не сошлись с вариантами типа | ваша: лишний случай говорит о том, чего у типа не бывает |
| `FLANG_PROOF_INDUCTION_STEP` | `по предположению` стоит там, где предполагать нечего | ваша: в этом случае нет ни посылки индукции, ни `требует` |
| `FLANG_PROOF_STEP` | шаг или цель не сведены ни одним правилом | по концу сообщения: не хватило факта — ваша; не тот вид цели — граница |
| `FLANG_PROOF_INDUCTION_TYPE` | индукция идёт по типу, у которого принципа индукции нет | граница: по `число` индукции нет |
| `FLANG_PROOF_INDUCTION_BRANCH` | тело функции не той формы, из которой читается результат случая | граница: тело — `разбор` или `свёртка` по той же переменной; для `неотрицательное` — `если` |
| `FLANG_PROOF_INDUCTION_DESCENT` | спуск по `неотрицательное` не назван или идёт не на единицу | не назван — ваша; не на единицу — граница |

### `FLANG_PROOF_INDUCTION_TYPE`

Индукцию несут тип с вариантами, запись, список, строка и `неотрицательное`.
По `число` её нет:

```
FLANG_PROOF_INDUCTION_TYPE … индукция теоремы «двойная норма неотрицательна»
идёт по «норма», а у этого типа (число) принципа индукции нет: у «число» нет
дна: в носителе живёт «+∞», у которого «х минус 1» равно самому «х». …
```

Обход — объявить параметр `неотрицательное`.

### `FLANG_PROOF_INDUCTION_BRANCH`

Чем оказывается `результат` в каждом случае, ядро читает из тела функции:

```
FLANG_PROOF_INDUCTION_BRANCH … тело функции «Штраф» не разбирает «свет» на
верхнем уровне и не сворачивает «свет» свёрткой, поэтому заключение посылки
индукции построить не из чего. Ядро читает «результат» случая из ДВУХ форм
тела и ниоткуда больше: с ветви `разбор` по той же переменной … и с начала и
шага `свёртка` по той же переменной … Тело-вызов, тело-арифметика и
тело-условие заключения посылки не дают
```

Обход — переписать тело разбором по переменной, по которой идёт индукция.

### `FLANG_PROOF_INDUCTION_DESCENT`

Индукция по `неотрицательное` пишется `индукция по н убывает н`. Без слов
`убывает н` ядро просит их дописать. Со словами оно сверяет спуск в теле, и
читает только `н минус 1`:

```
FLANG_PROOF_INDUCTION_DESCENT … спуск в шаге «Сумма до» не строгий: вычитают
на 2, а не на 1. Ядро читает ровно «н минус 1» и ничего кроме: убывание на
единицу внутри [0, 2⁵³−1] точно (соседние целые там представимы), и цепочка
спуска дна не проскакивает. …
```

Шаг с вычитанием на два ядро не доказывает.

### `FLANG_PROOF_STEP`

Отказ перечисляет виды цели, для которых у ядра есть правило:

```
FLANG_PROOF_STEP … цель не сведена к 1 предусловию функции: у цели этого
случая нет вида, к которому у ядра есть правило: правил десять — «не меньше 0»,
«не больше конечного литерала», «не больше терма», «не меньше терма», «меньше
терма», «больше терма», «равно», «содержит», «не убывает» и «начинается с» …
Вида цели не спрашивает только одиннадцатое, «цель есть допущение», и оно тоже
не прошло: ни одно допущение не совпало с целью знак в знак. … известно:
предусловие функции «Сумма»
```

Здесь цель была `не (результат равен 0)`. Если цель не одного из этих видов,
переписывать надо постусловие, а не теорему. Если вид подходит, а факта в
`известно:` нет — добавьте `требует` у функции или `индукция по` в теореме.

## Отказы не о теоремах

Эти коды приходят без единой теоремы в файле:

| Код | Что случилось | Где разобрано |
| --- | --- | --- |
| `FLANG_NOT_TOTAL` | завершение `тотальная` функции не доказано | [Завершаемость](how-proofs-work.html#завершаемость) |
| `FLANG_PRECONDITION_CALL` | вызывающий не доказал `требует` вызванной | [`требует`](how-proofs-work.html#требует-предусловие) |
| `FLANG_PRECONDITION` | `требует` нарушено на входе в программу или в примере | там же |
| `FLANG_EXAMPLE: FLANG_PROPERTY` | найден вход, на котором постусловие ложно | [Ложное постусловие](how-proofs-work.html#ложное-постусловие) |
| `FLANG_BOUND_ON_NAN` | граница на `число` ложна на NaN | [Что ядро доказывает само](what-the-kernel-accepts.html) |

Все коды компилятора — в [Справочнике отказов](diagnostics.html).
