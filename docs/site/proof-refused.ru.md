# Если не доказалось

Страница отвечает на вопрос: что делать, когда компилятор не написал
«доказано». Найдите свой случай в таблице и перейдите к рецепту. В каждом
рецепте два файла: до правки и после.

| Что вы видите | Рецепт |
| --- | --- |
| `FLANG_PROPERTY … нарушено на входе` | [1. Постусловие ложно](#1-постусловие-ложно-добавьте-предусловие) |
| `FLANG_PRECONDITION_CALL` | [2. Вызов не проходит предусловие](#2-вызов-не-проходит-предусловие) |
| `сетка N` у рекурсивной функции | [3. Теорема по индукции](#3-рекурсивная-функция-теорема-по-индукции) |
| `объявлено, не доказано` над типом `число` | [4. Точный тип](#4-число-с-плавающей-точкой-возьмите-точный-тип) |
| не доказано свойство, где функция вызвана дважды | [5. Свойство как постусловие](#5-свойство-о-двух-вызовах-запишите-его-постусловием) |
| `FLANG_PROOF_…` | [6. Компилятор не принял теорему](#6-компилятор-не-принял-теорему) |
| ничего не подошло | [7. Оставьте проверку](#7-ничего-не-подошло-оставьте-проверку) |

Словом «сетка» компилятор называет ответ «проверено только на тестах».
Все файлы лежат в `docs/examples/proofs`, команды запускаются оттуда.

## Сначала проверьте, верно ли постусловие

«Не доказано» бывает по двум причинам: у ядра нет подходящего правила или
постусловие ложно. В отчёте они выглядят одинаково. Прежде чем переписывать
код, проверьте постусловие на краях: `0`, `−0`, бесконечность, NaN, 2⁵³, пустая
строка, пустой список.

## 1. Постусловие ложно: добавьте предусловие

До, `before/discount.flang`:

```flang refused insert docs/examples/proofs/before/discount.flang
модуль «Скидка без предусловия»

тотальная функция «Цена со скидкой»
  принимает цена: неотрицательное, скидка: неотрицательное
  возвращает число
  обеспечивает «в минус не уходим» результат не меньше 0
  пример «сто минус десять»
    дано цена равно 100
    дано скидка равно 10
    ожидается 90
  цена минус скидка
```

```bash
flang check before/discount.flang; echo "код $?"
```

```
FLANG_EXAMPLE: FLANG_PROPERTY: постусловие «в минус не уходим» функции «Цена
со скидкой» нарушено на входе цена = 0, скидка = 1 — посчитано вычислителем на
этом входе
код 1

Компилятор нашёл вход, на котором результат отрицателен. Функция имеет смысл,

  возвращает число
  обеспечивает «в минус не уходим» результат не меньше 0
  пример «сто минус десять»
    дано цена равно 100
    дано скидка равно 10
    ожидается 90
  цена минус скидка
```

```

```

## 2. Вызов не проходит предусловие

Предусловие доказывает вызывающая функция. До, `before/order.flang`:

```flang refused insert docs/examples/proofs/before/order.flang
модуль «Заказ без предусловия»

тотальная функция «Цена заказа»
  принимает цена: неотрицательное, скидка: неотрицательное
  требует «скидка не больше цены» скидка не больше цена
  возвращает число
  цена минус скидка

тотальная функция «Счёт»
  принимает цена: неотрицательное, скидка: неотрицательное
  возвращает число
  «Цена заказа» от цена и скидка
```

```bash
flang check before/order.flang; echo "код $?"
```

```
FLANG_PRECONDITION_CALL в файле before/order.flang, строка 12, столбец 3: вызов
«Цена заказа» в функции «Счёт» не снимает предусловие «скидка не больше цены»: …
вызывающему здесь известно: собственных «требует» — 0, объявленных типов у
параметров — 2, доказанных обещаний вызванных в доводе — 0 …
код 1
```

Читайте начало и конец сообщения. Начало называет вызов и предусловие. Конец
перечисляет, что известно функции «Счёт»: своих предусловий у неё нет. «Снять
предусловие» значит доказать его в месте вызова.

Факт для предусловия берётся из трёх мест: собственное `требует` вызывающей
функции, тип её параметра, доказанное постусловие функции, посчитавшей
аргумент. Проверка `если` перед вызовом таким фактом не считается.

После, `order.flang`:

```flang insert docs/examples/proofs/order.flang

  принимает цена: неотрицательное, скидка: неотрицательное
  требует «скидка не больше цены» скидка не больше цена
  возвращает число
  цена минус скидка

тотальная функция «Счёт»
  принимает цена: неотрицательное, скидка: неотрицательное
  требует «скидка по карману» скидка не больше цена
  возвращает число
  «Цена заказа» от цена и скидка
```

```bash
flang check order.flang; echo "код $?"
```

```

```

## 3. Рекурсивная функция: теорема по индукции

До, `before/total.flang`:

```flang insert docs/examples/proofs/before/total.flang
модуль «Итог без теоремы»

тотальная функция «Итог»
  принимает цены: список неотрицательное, доставка: число
  требует «доставка не отрицательна» доставка не меньше 0
  возвращает число
  обеспечивает «итог не отрицателен» результат не меньше 0
  пример «две покупки и доставка»
    дано цены равно [100, 50]
    дано доставка равно 30
    ожидается 180
  разбор цены
    случай пусто
      то доставка
    случай голова и хвост
      то голова плюс («Итог» от хвост и доставка)
```

```bash
flang check before/total.flang --proof; echo "код $?"
```

```
постусловие «итог не отрицателен» функции «Итог» — сетка 1 значение (примеры
функции): нарушений на них нет … Это не доказательство — теоремы при утверждении нет
код 3
```

Тест прошёл, о других входах ничего не известно. Человеку причина понятна:

- список пуст — итог равен доставке, она не отрицательна по предусловию;
- список не пуст — итог равен первой цене плюс итог остальных. Первая цена не
  отрицательна по типу, итог остальных — по тому же утверждению для хвоста.

Это индукция по списку; подробно тот же пример разобран в разделе 4 урока
[Первое доказательство](first-proof.html). Запишите её теоремой с тем же
именем, что у постусловия. После, `total.flang`:

```flang insert docs/examples/proofs/total.flang
модуль «Итог»

тотальная функция «Итог»
  принимает цены: список неотрицательное, доставка: число
  требует «доставка не отрицательна» доставка не меньше 0
  возвращает число
  обеспечивает «итог не отрицателен» результат не меньше 0
  пример «две покупки и доставка»
    дано цены равно [100, 50]
    дано доставка равно 30
    ожидается 180
  разбор цены
    случай пусто
      то доставка
    случай голова и хвост
      то голова плюс («Итог» от хвост и доставка)

теорема «итог не отрицателен»
  дано цены: список неотрицательное
  дано доставка: число
  утверждаем результат не меньше 0
  индукция по цены
    случай пусто
      то по предположению
    случай голова и хвост
      то по предположению
  следовательно доказано
```

```bash
flang check total.flang --proof; echo "код $?"
```

```
постусловие «итог не отрицателен» функции «Итог» — доказано индукцией по
«список»: база 1 случай, шаг при допущении на частях (1 случай) …
код 0
```

`по предположению` значит «следует из уже известного»: в первом случае это
предусловие, во втором — утверждение для хвоста. Остальные виды теорем —
[Теоремы по шагам](manual-proofs.html).

## 4. Число с плавающей точкой: возьмите точный тип

До, `before/remainder.flang`:

```flang insert docs/examples/proofs/before/remainder.flang
модуль «Остаток на складе, число»

тотальная функция «Остаток»
  принимает было: число, ушло: число
  требует «ушло не больше, чем было» ушло не больше было
  возвращает число
  обеспечивает «остаток не отрицателен» результат не меньше 0
  было минус ушло
```

```bash
flang check before/remainder.flang --proof; echo "код $?"
```

```
постусловие «остаток не отрицателен» функции «Остаток» — объявлено, не
доказано: ни теоремы, ни примеров …
код 3
```

`число` — binary64 со всеми его значениями. Если `было` и `ушло` равны
бесконечности, предусловие выполнено, а разность равна NaN. NaN не больше и не
меньше нуля, поэтому постусловие ложно, и ядро его не доказывает.

Количество товара — целое и не отрицательное. Скажите это типом
`неотрицательное`: целое от 0 до 2⁵³−1. После, `remainder.flang`:

```flang insert docs/examples/proofs/remainder.flang
модуль «Остаток на складе»

тотальная функция «Остаток»
  принимает было: неотрицательное, ушло: неотрицательное
  требует «ушло не больше, чем было» ушло не больше было
  возвращает число
  обеспечивает «остаток не отрицателен» результат не меньше 0
  было минус ушло
```

```bash
flang check remainder.flang --proof; echo "код $?"
```

```
постусловие «остаток не отрицателен» функции «Остаток» — доказано по
объявленным типам аргументов …
код 0
```

Точные типы: `неотрицательное`, `целое`, `точное целое` (без верхней границы),
`сотых` и `тысячных` для денег.

## 5. Свойство о двух вызовах: запишите его постусловием

Утверждение сравнивает два вызова одной функции. До, `before/monotone.flang`:

```flang insert docs/examples/proofs/before/monotone.flang
модуль «Тариф без подсказки»

тотальная функция «Один»
  возвращает точное целое
  [1]

тотальная функция «Два»
  возвращает точное целое
  [2]

тотальная функция «Тариф»
  принимает минут: точное целое
  возвращает точное целое
  ((«Два») умножить на минут) плюс («Один»)

утверждение «дольше не дешевле»
  для всех а: точное целое и б: точное целое
  утверждаем если а не больше б то ((«Тариф» от а) не больше («Тариф» от б)) иначе да
```

```bash
flang check before/monotone.flang --proof; echo "код $?"
```

```
утверждение «дольше не дешевле» — объявлено, не доказано: ни теоремы, ни примеров …
код 3
```

Ядро не подставляет тело функции в оба вызова само. Помогите ему в два шага.
Запишите, чему равен результат, постусловием функции. Затем сошлитесь на это
постусловие в теореме словами `по свойству`. После, `monotone.flang`:

```flang insert docs/examples/proofs/monotone.flang
модуль «Тариф»

тотальная функция «Один»
  возвращает точное целое
  [1]

тотальная функция «Два»
  возвращает точное целое
  [2]

тотальная функция «Тариф»
  принимает минут: точное целое
  возвращает точное целое
  обеспечивает «развёрнуто» результат равен ((минут плюс минут) плюс («Один»))
  ((«Два») умножить на минут) плюс («Один»)

утверждение «дольше не дешевле»
  для всех а: точное целое и б: точное целое
  утверждаем если а не больше б то ((«Тариф» от а) не больше («Тариф» от б)) иначе да

теорема «дольше не дешевле»
  дано а: точное целое
  дано б: точное целое
  утверждаем если а не больше б то ((«Тариф» от а) не больше («Тариф» от б)) иначе да
  по свойству «развёрнуто»
  следовательно доказано
```

```bash
flang check monotone.flang --proof; echo "код $?"
```

```
постусловие «развёрнуто» функции «Тариф» — доказано по объявленным типам
аргументов: цель сведена правилом «линейная арифметика» …
утверждение «дольше не дешевле» — доказано: терм принят ядром, 1 шаг …
основания: постусловие «развёрнуто» функции «Тариф» …
код 0
```

Константы `«Один»` и `«Два»` — функции, потому что `точное целое` не
смешивается с литералом типа `число`.

Коды, которые исправляются в самой теореме:

| Код | Что случилось | Что править |
| --- | --- | --- |
| `FLANG_PROOF_NO_GOAL` | постусловия с таким именем нет | имя теоремы |
| `FLANG_PROOF_AMBIGUOUS` | имя подходит двум постусловиям | дайте постусловиям разные имена |
| `FLANG_PROOF_DUPLICATE` | у постусловия две теоремы | оставьте одну |
| `FLANG_PROOF_CLAIM_MISMATCH` | `утверждаем` отличается от постусловия | перепишите слово в слово |
| `FLANG_PROOF_UNFINISHED` | нет строки `следовательно доказано` | допишите её |
| `FLANG_PROOF_UNKNOWN_VAR` | `дано` вводит имя, которого нет у функции | возьмите имя параметра |
| `FLANG_PROOF_VAR_TYPE` | тип в `дано` отличается от типа параметра | возьмите тип параметра |
| `FLANG_PROOF_INDUCTION_CASES` | случаи теоремы не совпали с вариантами типа | перечислите те же случаи, что в `разбор` |
| `FLANG_PROOF_INDUCTION_STEP` | `по предположению` стоит там, где опереться не на что | добавьте `требует` функции |

Коды, которые говорят о границе ядра:

| Код | Что случилось | Что делать |
| --- | --- | --- |
| `FLANG_PROOF_INDUCTION_TYPE` | индукция по `число` | объявите параметр `неотрицательное` |
| `FLANG_PROOF_INDUCTION_BRANCH` | тело функции не `разбор` и не `свёртка` по той же переменной | перепишите тело разбором |
| `FLANG_PROOF_INDUCTION_DESCENT` | рекурсия по `неотрицательное` идёт не на 1 | спускайтесь на `н минус 1` |
| `FLANG_PROOF_STEP` | шаг не подходит ни под одно правило | дочитайте сообщение до слова `известно:` |

«База» — первый случай индукции, пустой список. В нём `по предположению` может
сослаться только на предусловие, а его нет: доставка может быть отрицательной.
Верните строку `требует`.

### `FLANG_PROOF_STEP`

У `FLANG_PROOF_STEP` конец сообщения перечисляет, что было известно в этом
месте. Нужного факта там нет — добавьте `требует`. Факт есть, а шаг не прошёл —
постусловие такого вида ядро не выводит, переходите к рецепту 7.

## 7. Ничего не подошло: оставьте проверку

Недоказанное постусловие остаётся в программе проверкой при каждом возврате из
функции. Это рабочий вариант. Сделайте три вещи:

- добавьте тесты (`пример`) на края: ответ `сетка N` лучше, чем `объявлено, не
  доказано`;
- запускайте программу с ключом `--trust`: без него `flang run` не запустит файл
  с недоказанным постусловием;
- в CI решите, что вам нужно: `flang check файл` допускает недоказанное,
  `flang check файл --proof --strict` — нет.

Верное постусловие, которое ядро не вывело, остаётся верным. Примеры таких
постусловий — [Чему вы доверяете](trust.html#не-доказано-не-значит-ложно).
