# Запись доказательства и независимая проверка

Слову «доказано» в выводе компилятора можно не верить на слово. Компилятор
пишет доказательство в файл — запись, — а отдельная программа на C, у которой
нет общего кода с компилятором, читает исходник и запись и перепроверяет шаги
заново.

## Как получить запись

Программа — со страницы
[Как это доказывается](how-proofs-work.html#обеспечивает-постусловие-и-три-ответа):
три постусловия, одно доказано.

```
$ flang check tri.flang --proof --record tri.proof
```

Запись — текст, который читается глазами:

```
запись доказательства 1
исходник tri.flang
строк 28
знаков 729
отпечаток 50696052 542895809
ядро 2
утверждений 3
отпечаток256 338dc9b3cf90abc44b5e3dbfa2ef7614066bf6843cedb816c45e0924a444034c
тотальностей 3
утверждение «в минус не уходим» функции «Цена со скидкой» строка 7
  вид postcondition
  вердикт доказано
  теоремы нет
  правило «неотрицательность по построению»
  по объявлению да
  обязательство вход «скидка» ⟨скидка не больше 9007199254740991⟩ строка 4 на зовущем
    вывод цель ⟨результат не меньше 0⟩
    вывод 1 Н3 ⟨скидка не меньше 0⟩ строка 4
    вывод 2 Пред1 ⟨скидка помещается⟩ строка 4
    вывод 3 П3 ⟨скидка не больше 9007199254740991⟩ из 2
    вывод 4 Н12 ⟨( цена минус скидка ) не меньше 0⟩ из 1 3
    вывод 5 Разв2 ⟨результат не меньше 0⟩ из 4 строка 12
    вывод конец
конец утверждения

утверждение «результат чётный» функции «Удвоить» строка 17
  вид postcondition
  вердикт нет вердикта
  теоремы нет
конец утверждения
…
конец записи
```

Шапка привязывает запись к исходнику отпечатками. Дальше идёт по блоку на
каждое утверждение: вердикт, правило и вывод по шагам; у недоказанного —
`нет вердикта`. За ними — блоки завершаемости функций и строка `конец записи`.
Что стоит в каждой строке, описывает
[формат записи доказательства](https://github.com/digitable-lol/flang/blob/dev/docs/flang/proof/record-format.md).

## Как проверить запись

Проверяющая программа — один файл на C, `flang/proof/checker/checker.c`.
Собирается компилятором C, без flang:

```
$ make -C flang/proof/checker
$ flang/proof/checker/сверщик tri.flang tri.proof; echo "код $?"
ПРОВЕРЕНО — запись сошлась с исходником, и всё доказанное проиграно заново:
утверждений 3, … сведений проиграно заново 3 … Числятся доказанными 1. НА СЛОВО
ЯДРА: посылок и утверждений 0, шагов 0. … Привязка к программе: SHA-256 сошёлся. …
код 0
```

«На слово ядра: 0» значит, что ни один шаг не принят без перепроверки.

Поправьте в записи один шаг — `⟨скидка не меньше 0⟩` на `⟨скидка не меньше 5⟩`:

```
$ flang/proof/checker/сверщик tri.flang forged.proof; echo "код $?"
НЕ СОШЛОСЬ: утверждение «в минус не уходим», вывод: шаг 1: Н3 заключает
неотрицательность, а вида «Т не меньше 0» у «скидка не меньше 5» нет
код 1
```

Поправьте исходник, оставив запись прежней:

```
НЕ СОШЛОСЬ: первый отпечаток не сошёлся — запись не от этой программы; …
```

| Код | Ответ | Что значит |
| --- | --- | --- |
| 0 | `ПРОВЕРЕНО` | запись от этой программы, всё доказанное перепроверено |
| 1 | `НЕ СОШЛОСЬ` | запись не от этой программы или шаг неверен |
| 3 | `НЕ ПРОВЕРЕНО` | перепроверено не всё: часть доказанного стоит на слове ядра, либо доказанного в записи нет |

Когда программа собрана, `flang check --proof` зовёт её сам и добавляет в
отчёт строку:

```
tri.flang: независимо, сверщиком, проиграно 1 из 1 доказанных; на слове ядра 0
— код сверщика 0
```

Когда не собрана — строку `НЕЗАВИСИМО НЕ ПРОВЕРЕНО — сверщика нет`. Путь к
программе в другом месте задаёт переменная среды `FLANG_CHECKER`.

Запись читает и вторая программа, написанная порознь на Lean 4
(`flang/proof/checker/second/`). `bootstrap/flang run-script checker:second`
прогоняет обе по одним и тем же записям и печатает каждое расхождение в кодах.
Сколько собственных доказательств компилятора перепроверено так —
[Что доказано, а что нет](what-is-proved.html).

## Номер версии и что он обещает

Первая строка записи называет версию формата: `запись доказательства 1`.
Проверяющая программа отвергает запись с другим номером. Номер ядра (`ядро 2`
в шапке) — другое число: он говорит о правилах вывода, а не о форме текста, и
здесь не обещается.

Пока номер версии не сменился:

- Строки шапки стоят в том же порядке и с теми же словами в начале: `исходник`,
  `строк`, `знаков`, `отпечаток`, `ядро`, `утверждений`, `отпечаток256`,
  `тотальностей`, `законов`.
- Каждый вид строки и каждый блок читается так же, как читался. Строку не
  переименовывают, не убирают и не меняют ей смысл.
- Запись версии 1, выпущенная раньше, читается программой, собранной позже.

Номер меняют убранная или переименованная строка, другой порядок строк шапки,
иной смысл значения, иной способ считать отпечатки. Новый вид строки или блока
номера не меняет, но попадает в журнал ниже.

Обещание проверяется: `bootstrap/flang run-script record-format:check` снимает
два отпечатка формата и сверяет их с журналом.

- **Отпечаток печати** — SHA-256 набора видов строк в свежих записях пяти
  опорных программ дерева. Его сдвигает новый вид строки или блока, а не другой
  исходник.
- **Отпечаток чтения** — SHA-256 закрытого списка образцов строк, по которому
  программа на C отвергает незнакомую строку.

Отпечаток разошёлся с журналом — проверка отказывает словами «смена формата
записи без записи в журнал».
