# Что осталось до 1.0

Страница отвечает на один вопрос: чего не хватает flang до выпуска 1.0.
Сейчас вышла версия {{выпуск.версия}}. Что уже вышло, написано на странице
[Выпуски](releases.html).

Выпуск 1.0 выйдет, когда выполнятся семь условий. У каждого условия есть
команда и число, по которым видно, выполнено ли оно. Сроков нет.

## Семь условий

### 1. Компилятор собирается из своих исходников, и сборки совпадают

Компилятор flang написан на flang. Вы собираете его из исходников и получаете
тот же файл байт в байт. Тогда опубликованному компилятору можно верить так же,
как его исходникам.

- **Есть.** Автоматическая проверка дважды собирает компилятор и сравнивает
  результаты. Последние запуски подряд совпали.
- **Нет.** Одна такая проверка занимает от четырёх до шести часов. Совпадение
  должно держаться при каждом изменении компилятора.

### 2. Исправление в компиляторе быстро доходит до вас

После любой правки компилятор заново собирает сам себя. Пока это долго,
исправления выходят реже.

- **Есть.** Полная пересборка занимает от 76 минут до почти трёх часов на
  разных машинах.
- **Нет.** Цель — меньше часа.

### 3. Слову «доказано» можно верить

Когда `flang check` пишет «доказано», вы полагаетесь на проверку доказательств
внутри компилятора. Условие требует доказать, что она не принимает ложных
утверждений.

- **Есть.** У каждого правила вывода есть теорема в Lean 4. Отдельная программа
  `checker` перепроверяет записи доказательств без участия компилятора.
- **Нет.** Формальная модель покрывает 511 из 603 доказательств в записях
  самого компилятора. Теоремы о коде программы `checker` пока нет.

### 4. Нет известных ошибок проверки типов

Программа, которая прошла `flang check`, не должна нарушать объявленные типы.
Каждая найденная ошибка проверки типов записана в список. У каждой есть тест,
который заметит её возвращение.

- **Есть.** Найдено 52 такие ошибки, 46 закрыты. Генератор программ ищет
  новые каждый день.
- **Нет.** Четыре ошибки исправлены, но в списке ещё не отмечены закрытыми.
  Две открыты. Первая: функция над целыми фиксированной ширины (`u8`…`i64`)
  объявлена всегда завершающейся и проходит `flang check`, хотя её сложение
  может выйти за край типа. Вторая: операция, которая может завершиться
  ошибкой, проходит проверку, когда стоит в предусловии или постусловии.
  Доказательства, что список полон, нет.

### 5. Коды ошибок и формат записи доказательства не меняются незаметно

Ваши скрипты и CI могут разбирать коды `FLANG_*` и записи доказательств.
Условие требует, чтобы они не менялись без объявления.

- **Есть.** Каждый код стоит в таблице со статусом, и устойчивый код не может
  пропасть. У формата записи есть номер версии. Версий две, и программа
  `checker` читает обе.
- **Нет.** Текст сообщения об ошибке устойчивым не считается. Автоматическая
  проверка формата следит только за первой версией.

### 6. Чужой модуль подключается одной строкой

Модуль называют адресом в строке импорта:
`использует «Логика» из "https://…/logic.flang"`. Первая команда `flang check`
скачивает модуль и записывает его текст в `flang.lock`. Следующие сборки идут
без сети и дают тот же результат.

- **Есть.** Это работает сегодня: см. [Модули и пакеты](packages.html).
- **Нет.** Подписи автора. Файл `flang.lock` подтверждает, что модуль не
  изменился, но не говорит, кто его написал.

### 8. Сгенерированный код C делает то, что доказано об исходнике

Доказательство относится к исходнику на flang. Команда `flang emit --target c`
создаёт из него код C. Условие требует проверить каждую функцию этого кода по
формальному описанию языка на Lean.

- **Есть.** На базовом наборе из 55 файлов примеров проверено соответствие 165
  функций, для любого входа доказаны 164.
- **Нет.** На всех примерах репозитория доказаны 1332 функции из 9375. Команда
  `flang emit` сама эту проверку не запускает. Полностью доказанный генератор
  кода в 1.0 не входит.

Условия под номером 7 нет: его убрали, остальные номера оставили прежними.

## План выпусков

Это план, и он может измениться.

| Выпуск | Смысл | Что войдёт |
|---|---|---|
| 0.8.0 (вышел) | не отвечает неверно | известные неверные ответы проверки исправлены; `flang check` называет каждое недоказанное утверждение; автоматические доказательства проверяются в CI |
| 0.9.0 | можно давать людям | документация, песочница, форматтер, правила совместимости; выпуск проходит все проверки |
| 1.0.0-rc | кандидат | условия 3 и 8 выполнены до записанных порогов; архивы выпуска подписаны; синтаксис заморожен |
| 1.0.0 | выпуск | только исправления по откликам на кандидат |

## Что решено не делать

- **Замыканий не будет.** Захват окружения ломает доказательство завершения и
  прямую генерацию кода C, Go и Rust. Функции-значения в языке есть. Тело,
  записанное прямо во встроенной форме (`отобразить … как х → …`), видит
  параметры своей функции; передать его как значение нельзя.
- **Двух версий одной библиотеки в одной программе не будет.**
- **Реестра пакетов и команды установки не будет.** Модуль называют адресом.
- **Код хранится в файлах.** Из хранения в базе взята только адресация по
  содержимому.
