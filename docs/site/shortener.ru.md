# Сокращатель ссылок: служба и клиент

Пример из двух программ на flang.

- **Служба** — `docs/examples/web/shortener/`. На входе текст HTTP-запроса, на
  выходе текст ответа. Сокет держит не она: соединения принимает `flang io`,
  исполняя поручения плана.
- **Клиент** — `docs/examples/web/shortener-client/`. Форма, список ссылок и
  счётчик переходов во вкладке браузера.

## Файлы службы

| файл | строк | что в нём |
|---|---:|---|
| `store.flang` | 137 | хранилище: коды, адреса, счётчик переходов |
| `service.flang` | 675 | маршруты, разбор запроса, печать ответа, утверждения |
| `plan.flang` | 74 | план: один запрос из файла, ответ в файл |
| `plan-network.flang` | 122 | план: служба на сокете `127.0.0.1:39281` |
| `plan-durable.flang` | 273 | план: служба на сокете `127.0.0.1:39283` с журналом на диске |
| `server.flang` | 136 | та же служба тремя процессами под надзором |
| `server-network.flang` | 30 | те же процессы поверх сетевого плана |
| `handler-without-budget.flang` | 36 | нарочно неверная программа: `check` её отвергает |

Разбор HTTP — библиотека `flang/stdlib/http.flang`.

## Что служба отвечает

| метод | путь | ответ |
|---|---|---|
| GET | `/здоровье` | 200 `живой` |
| GET | `/ссылки` | 200, по строке на ссылку: код, адрес, число переходов |
| POST | `/ссылки` | 201 и код; тело `адрес=…` и необязательное `код=…` |
| GET | `/с/{код}` | 301 и `Location`; переход сосчитан |
| DELETE | `/ссылки/{код}` | 204 |

Отказы: 400 — негодный запрос, 404 — нет пути или кода, 405 — метод не тот для
известного пути, 409 — код занят, 413 — тело длиннее 2048, 422 — адрес не по
http и не по https, 431 — заголовки слишком велики.

## Как запустить

Примеры, записанные в функциях:

```
flang test docs/examples/web/shortener/server.flang
```

```
docs/examples/web/shortener/server.flang: примеров 329, прошло 329, не прошло 0
```

В счёт входят примеры подключённых модулей.

### Один запрос через файлы

План `plan.flang` читает запрос из `mail/request.txt` и пишет ответ в
`mail/response.txt`:

```
flang io docs/examples/web/shortener/plan.flang --in-dir --trust
```

```
на веру: доказанность не считалась — запуск по ключу --trust
{"plan":"Обслужить через файлы","result":86,"orders":2,"log":[…]}
```

```
HTTP/1.1 201 Created
Content-Type: text/plain; charset=utf-8
Content-Length: 3

к1
```

Ключ `--in-dir` запрещает плану пути вне каталога программы. Ключ `--trust`
нужен, потому что не все утверждения службы доказаны; без него `flang io`
отвечает кодом 3:

```
не доказано: утверждений 163: доказано 92, сетка 69, на веру 2 — запуск только по явному согласию: --trust
```

В эти 163 входят утверждения всех подключённых модулей, вместе с библиотекой
HTTP.

### Служба с журналом на сокете

`plan-durable.flang` слушает `127.0.0.1:39283` и перед ответом на каждый
меняющий запрос дописывает его в файл `служба.wal` рядом с программой. Журнал
появится в каталоге примера — чтобы не писать в дерево, скопируйте
`docs/examples/web/shortener/`, `docs/examples/wal/` и `flang/stdlib/` в
отдельный каталог с теми же относительными путями.

```
cd docs/examples/web/shortener
flang io plan-durable.flang --in-dir --trust --max-orders 100000 &
```

Запрос без тела можно послать `curl`:

```
$ curl -i http://127.0.0.1:39283/здоровье
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Content-Length: 10

живой
```

Запрос с телом — нет: служба считает `Content-Length` входящего запроса в
знаках, а `curl` и браузер — в байтах (см. «Чего служба не умеет»). Ниже
запросы посланы в сокет как есть, с длиной в знаках:

```
POST /ссылки HTTP/1.1
Host: x
Content-Length: 23

адрес=https://пример.рф
```

```
HTTP/1.1 201 Created
Content-Type: text/plain; charset=utf-8
Content-Length: 3

к1
```

Два перехода по `GET /с/к1` дают два ответа:

```
HTTP/1.1 301 Moved Permanently
Content-Type: text/plain; charset=utf-8
Location: https://пример.рф
Content-Length: 0
```

После них `GET /ссылки`:

```
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Content-Length: 32

к1	https://пример.рф	2
```

Теперь остановите службу (`kill` по её номеру процесса) и запустите той же
командой. `GET /ссылки` отвечает тем же: ссылка и счётчик 2 восстановлены из
журнала. В журнале лежат сами запросы, по записи на каждый меняющий:

```
#1:77:POST /ссылки HTTP/1.1
Host: x
Content-Length: 23

адрес=https://пример.рф;#2:31:GET /с/к1 HTTP/1.1
Host: x

;#3:31:GET /с/к1 HTTP/1.1
Host: x

;
```

Восстановление — повторное обслуживание записей журнала по порядку. Это
законно, потому что обработчик — тотальная функция без ввода-вывода: тот же
запрос на том же хранилище даёт тот же ответ. Формат журнала разобран на
странице [Журнал упреждающей записи](wal.html).

Если журнал не принял запись, план отвечает 503 и оставляет прежнее хранилище:
ответ 201, 204 или 301 строится только в ветви, где хозяин ответил «Записано».
Это видно в функции «После записи в журнал» и её примерах; прогоном с
отказывающим диском здесь не проверено.

```
flang check docs/examples/web/shortener/service.flang --proof
```

```

  функций 24: тотальных 24, обычных 0
  обещание несёт: композиция 24, структура 0, точный шаг 0, постоянный шаг 0, объявленная мера 0
  сторожей в рантайме: 0 мест
  законов на сетке: 0 (значений в сетках 0); на веру: 0
  утверждений 8: доказано 5 (из них индукцией 4) (из них без теоремы 1), сетка 3, объявлено, не доказано 0 (шагов в термах 30)
```

Код возврата 3 — из-за трёх утверждений на сетке.

Доказано на всех входах:

| утверждение | функция |
|---|---|
| «код ответа из объявленного набора» | «Код исхода» |
| «пояснение кода непусто» | «Код исхода» |
| «успех исхода и успех кода — одно и то же» | «Исход успешен» |
| «октетов от одного до четырёх» | «Октетов в знаке» |
| «печать ответа начинается версией, кодом и пояснением» | «Напечатать ответ службы» |

Первые три доказаны индукцией по типу «Исход»: у него десять вариантов, и
разобран каждый.

На сетке, то есть проверено только на примерах автора:

| утверждение | функция |
|---|---|
| «урезанное не длиннее предела» | «Урезать» |
| «тело ответа не длиннее заявленного предела» | «Тело решения» |
| «в печати ответа длина тела названа в октетах» | «Напечатать ответ службы» |

Все три — о срезе строки и о вхождении подстроки; правил для них у ядра нет.

Остальные файлы:

| файл | функций | тотальных | утверждений | доказано |
|---|---:|---:|---:|---:|
| `store.flang` | 12 | 12 | 1 | 1 |
| `server.flang` | 7 | 5 | 0 | — |
| `shortener-client/client.flang` | 32 | 32 | 43 | 43 |

Отчёт считает только утверждения самого файла, без подключённых модулей.

Чего это не доказывает:

- что служба отвечает по HTTP правильно: утверждений восемь, и они о кодах,
  длинах и начале ответа. Маршруты и разбор запроса проверены примерами;
- что служба когда-нибудь кончится: каждый шаг плана завершается, а цикл приёма
  соединений идёт, пока процесс не остановят.

### Обработчик без запаса витков

У процесса обработчик либо тотален, либо назван запас витков — строка
`с запасом N витков`. `handler-without-budget.flang` не делает ни того, ни
другого:

```
flang check docs/examples/web/shortener/handler-without-budget.flang
```

```
FLANG_HANDLER_NOT_TOTAL в файле docs/examples/web/shortener/handler-without-budget.flang, строка 13, столбец 1: обработчик «шаг разбора» процесса «Разборщик» не помечен тотальным, и запаса витков процесс не называет: строки «с запасом N витков» нет. Оборвать такой пробег планировщику нечем
```

Вторым замечанием идёт `FLANG_UNCOVERED_FAILURE`: процесс с таким обработчиком
не стоит под надзором. Код возврата 1.

## Чего служба не умеет

- **Длина входящего тела считается в знаках, а не в байтах.** Тело
  `адрес=https://пример.рф` — это 23 знака и 36 байт. `curl --data-binary`
  называет 36, служба ждёт ещё 13 знаков и не отвечает. Длину тела в ответе
  служба печатает в байтах.
- **Одно соединение — один обмен.** Keep-alive нет; второй клиент ждёт, пока
  обслужат первого.
- **Заголовков CORS нет, на `OPTIONS` ответ 405.** Страница с другого адреса
  службу из браузера не вызовет.
- **В `Location` стоит адрес как есть**, кириллица не кодируется.
- **Порт и имя журнала вписаны в программу** (`39283`, `служба.wal`).
- **Журнал не уплотняется:** каждый меняющий запрос остаётся в нём навсегда, и
  восстановление повторяет всю историю.
- **Долговечность не обещана.** План переписывает файл журнала целиком, а
  «Записано» значит только то, что система приняла запись. Контрольной суммы у
  записи нет.

Пути кириллицей служба понимает и в закодированном виде:
`GET /%D1%81%D1%81%D1%8B%D0%BB%D0%BA%D0%B8` отвечает так же, как `GET /ссылки`.

## Клиент во вкладке

`client.flang` — приложение целиком: 453 строки, 32 функции, все тотальны, 51
пример. Состояние — одна запись «Стойка» из пяти полей. Обработчик чистый: на
отклик он возвращает новое состояние и следующее поручение — «Показать»,
«Ждать событие» или «Запросить». Поэтому все примеры идут без браузера и без
сети:

```
flang test docs/examples/web/shortener-client/client.flang
```

```
docs/examples/web/shortener-client/client.flang: примеров 51, прошло 51, не прошло 0
```

`check --proof` по клиенту: утверждений 43, доказано 43, проверок при работе
нет. Независимый сверщик доказательств (`FLANG_CHECKER`) повторил 32 из 43;
остальные 11 держатся на слове ядра.

Страницу отдаёт стенд, тоже написанный на flang:

```
sh docs/examples/web/build.sh
flang io docs/examples/web/stand.flang --max-orders 100000 --trust
```

`build.sh` переводит `client.flang` в JavaScript рядом со страницей; стенд
слушает `127.0.0.1:8908`. Страница —
`http://127.0.0.1:8908/docs/examples/web/shortener-client/index.html`.

**Клиент к службе не подключён.** Он запрашивает `/ссылки` у того адреса,
откуда загружен, то есть у стенда, а стенд на этот путь отвечает 404. Служба
слушает другой порт, и вызвать её со страницы мешает перечисленное выше: нет
CORS, длина тела в знаках.

Ещё одно ограничение: поручение «Показать» пишет текст на экран, а записать в
поле ввода программа не может. После «очистить» программа считает поле пустым,
а в поле остаётся прежний текст.
