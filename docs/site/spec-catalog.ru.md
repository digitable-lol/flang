# Каталог спек: как он устроен и чем проверяется

Страница [Спеки: доказанное правило](fspec.html) показывает одну спеку. Здесь —
каталог из многих: как спеки ссылаются друг на друга, что считается принятой
спекой и какая программа это проверяет.

Каталог лежит в [`fspec/`](fspec). Это не спецификация языка (она в
[`docs/flang/SPEC.md`](../flang/SPEC.md)), а образец: 43 правила предметной
области, записанные программами, и проверка поверх них.

## Как выглядит спека

Первая спека каталога,
[`fspec/spec/01-discount-cap.flang`](fspec/spec/01-discount-cap.flang), без
комментариев:

```flang
модуль «Спека 1: потолок скидки»

тотальная функция «Потолок скидки»
  принимает сумма: число
  возвращает число
  обеспечивает «скидка не больше 30» результат не больше 30
  обеспечивает «zh: 折扣不超过 30» результат не больше 30
  обеспечивает «en: discount is at most 30» результат не больше 30
  пример «потолок»
    дано сумма равно 1000
    ожидается 30
  30
```

```
$ flang check fspec/spec/01-discount-cap.flang --proof
  утверждений 3: доказано 3 (из них без теоремы 3), сетка 0, объявлено, не доказано 0
```

Спеки сверяются по паре «функция и имя утверждения». Переименовали
утверждение — связь порвалась, и проверка это назовёт.

Спека, которая опирается на написанную раньше, подключает её:

```flang fragment
модуль «Спека 3: наценка за срочность»
  использует «Спека 2: промо» из "./02-promo.flang"
```

## Правило приёмки

Правило записано в `policy.flang`. Спека принимается, если **каждое** её
утверждение доказано и **каждое** утверждение предшественницы осталось
доказанным в отчёте наследницы.

Отвергается:

| что нашлось | почему это не годится |
|---|---|
| «объявлено, не доказано» | утверждение может оказаться ложным |
| «сетка» | посчитано на примерах автора, а не для всех входов |
| «НАРУШЕНО» | ложь, найденная примером |
| спека без единого `обеспечивает` | проверять нечего |
| утверждение предшественницы пропало или ослаблено | новое правило отменило старое |
| утверждение из слепка пропало из спек | доказанное правило снято |
| у утверждения из слепка переписана цель | имя прежнее, обещание другое |
| утверждение есть, а в слепке его нет | его можно переписать незаметно |
| каталог спек пуст | проверке не на чем разойтись |
| одно имя носит два разных понятия | читатель думает об одном, а речь о двух |
| строка `принимает` разобрана не целиком | подмену понятия под этим именем не увидеть |

Верное, но не выводимое ядром утверждение тоже отвергается: ядро неполно.
Образец — [`flang/proof/examples/precondition.flang`](flang/proof/examples/precondition.flang).
Какие записи ядро берёт, разобрано на странице
[Какие постусловия prover доказывает](what-the-kernel-accepts.html).

## Утверждение, которое ничего не говорит

Утверждение может быть доказано и при этом не говорить о функции ничего. Так
бывает, когда оно верно и для заглушки с той же подписью — тела `0`, `""`,
`нет`, пустой список. Проверяется это прогоном: оставить подпись и
`обеспечивает`, заменить тело заглушкой.

```flang
модуль «Заглушка»

тотальная функция «Потолок скидки»
  принимает сумма: число
  возвращает число
  обеспечивает «скидка не больше 30» результат не больше 30
  0
```

```
$ flang check stub.flang --proof
stub.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 1: доказано 1, условно 0, сетка 0, объявлено, не доказано 0, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 0
```

Заглушка прошла: утверждение первой спеки верно для любой функции, которая
возвращает не больше 30. Первые две спеки каталога показывают связь двух спек,
а не сильное утверждение.

Заглушку не переживают утверждения о длине
(`(длина результат) равен ((длина х) плюс 1)`), о вхождении
(`результат содержит "…"`), о полях записи и о границе, где границей стоит сам
результат (`цена не больше результат`). Переживают односторонние верхние
границы (`результат не больше 30`) и неотрицательность
(`результат не меньше 0`).

## Слепок: что было доказано раньше

Правило приёмки видит спеки такими, какие они сейчас. Если переписать цель
утверждения, не тронув имени, оно этого не заметит. Для этого есть
`snapshot.txt` — строка на каждое утверждение, с целью дословно:

```
01-discount-cap.flang :: Потолок скидки :: скидка не больше 30 :: результат не больше 30
```

Проверка сверяет слепок со спеками в обе стороны:

- каждое утверждение слепка стоит в спеке с той же целью. Пропало — правило
  снято. Цель другая — обе цели показаны рядом;
- каждое утверждение спеки записано в слепке.

Слепок переписывается отдельной командой:

```sh
flang io fspec/snapshot.flang
```

Вместе со спеками он не обновляется нарочно: правка цели — два действия, и
второе видно в разборе изменений отдельной строкой.

Цель берётся из исходника спеки, из строки `обеспечивает`. Поэтому утверждение
пишется одной строкой: `обеспечивает «имя» цель` или
`для всех н обеспечивает «имя» цель`.

Слепок не судит, слабее ли новая цель прежней. «Не больше 1000» и «не больше
30» для него просто разные.

## Утверждение на другом языке

Утверждение можно повторить на другом языке, с меткой языка в имени — как в
первой спеке выше. Каждый перевод — отдельное утверждение: ядро доказывает его
само по себе, оно стоит в отчёте и в слепке.

Переводится имя утверждения. Имена функций и параметров не переводятся.

Меток девять: `ar`, `de`, `en`, `es`, `fr`, `hi`, `ja`, `pt`, `zh`. Список
закрыт, чтобы опечатка `zn:` не стала отдельным утверждением, которое ни с чем
не сверяется. Отсюда ограничение: `": "` в имени утверждения означает метку
языка.

Проверка сверяет цели переводов, а не слова. Неверно названный перевод с
верной целью пройдёт.

## Проверка проверки

`forgery.flang` — набор нарочно испорченных каталогов. На каждом проверка
обязана найти беду, а на честном изменении — промолчать.

```sh
flang run-script specs:forgery
```

Среди случаев: ослабление правила под прежним именем; спека без
предшественницы; перевод, обещающий не то, что основное утверждение; опечатка
в метке языка; переведённое имя функции.

## Что проверка отвечает сейчас

Программа проверки сама доказана не целиком, поэтому без согласия `flang io` её
не запускает:

```
$ flang io fspec/guard.flang
не доказано: утверждений 133: доказано 80, сетка 53, на веру 0 — запуск только по явному согласию: --trust
```

Команда `specs:check` запускает её с согласием и сейчас находит 78 бед:

```
$ flang run-script specs:check
бед в системе спек: 78
03-urgency-markup.flang: утверждение «скидка с промо не больше 30» функции «Скидка с промо» доказано у 02-promo.flang, а здесь его нет или оно ослаблено
…
```

| бед | какая | причина |
|---:|---|---|
| 69 | «доказано у предшественницы, а здесь его нет или оно ослаблено» | отчёт `check --proof` содержит только утверждения самого файла, без подключённых модулей; найти в нём утверждение предшественницы нельзя |
| 4 | «переписана ЦЕЛЬ» | спеки `04-discount-tiers`, `14-tax-rates`, `31-loyalty-tiers`, `37-booking-slots`: цель со словом `иначе` читается из исходника не целиком и не совпадает со слепком |
| 4 | «не записано в слепке» | те же четыре утверждения |
| 1 | «спека не проходит проверку языка» | два утверждения `26-order-invoice` стоят на сетке, `check --proof` отвечает кодом 3 |

Первая строка таблицы значит, что проверка краснеет на каждой спеке с
`использует`, а не только на настоящей отмене правила. Сама наследница при
этом доказана:

```
$ flang check fspec/spec/03-urgency-markup.flang --proof
  утверждений 1: доказано 1 (из них без теоремы 1, объявленным типом 1), сетка 0, объявлено, не доказано 0
```

Набор испорченных каталогов тоже сейчас не проходит:

```
$ flang run-script specs:forgery
подлог спек ОТКАЗЫВАЕТ, расхождений 7 (подложенных случаев 21)
```

Код возврата 1. Из семи расхождений одно — сам каталог: набор ждёт, что на
настоящих спеках проверка молчит, а она находит 78 бед. В шести остальных
проверка беду находит, но называет её не теми словами, которых ждёт случай:
два случая с утверждением «объявлено, не доказано», случай с пропавшим
утверждением предшественницы (бед две, а не одна) и три ожидания в случае с
ложным утверждением у функции без входов.

## Что видит одна `flang check`

Программы в `experiments/` показывают, какие противоречия компилятор находит
сам. Код — ответ `flang check <файл> --proof`:

| программа | что в ней написано | код |
|---|---|---:|
| `contradiction-without-example.flang` | два несовместимых `обеспечивает` у одной функции, примера нет | 1 |
| `contradiction-one-function.flang` | то же и пример автора | 1 |
| `contradiction-in-requirements.flang` | два несовместимых `требует` и вызывающий | 1 |
| `contradiction-delivery-window.flang` | «не дольше трёх дней» и «не быстрее семи» | 1 |
| `contradiction-money-rounding.flang` | «итог кратен рублю» и «в итоге пятьдесят копеек» | 1 |
| `contradiction-return-defect.flang` | два правила возврата в одной функции | 1 |
| `contradiction-tax-theorem.flang` | «ставка не выше 20» и «не ниже 27», при каждом теорема | 1 |
| `contradiction-weight-requirements.flang` | `требует` «тяжелее десяти» и «легче пяти» и вызывающий | 1 |
| `theorem-on-false.flang` | теорема, доказывающая ложь | 1 |
| `false-claim-strict-discount.flang` | «скидка строго уменьшает цену» — ложно на нулевом заказе | 1 |
| `false-claim-not-a-number.flang` | то же, цена объявлена `число`: ложно на «не число» | 1 |
| `false-claim-negative-zero.flang` | «сторно нулевого платежа есть ноль» — ложно на минус нуле | 3 |
| `spec-legacy.flang` + `spec-new-feature.flang` | наследница обещает обратное предшественнице | 0 и 1 |
| `conflict-cap-legacy.flang` + `conflict-cap-heir.flang` | новая спека требует «не меньше 50» и зовёт прежнюю | 0 и 1 |
| `conflict-rights-legacy.flang` + `conflict-rights-heir.flang` | новая обещает, что чтения у гостя не осталось | 0 и 3 |
| `silent-drop-legacy.flang` + `silent-drop-heir.flang` | наследница подключает предшественницу с отбором (`только`) и теряет одно её правило | 0 и 0 |
| `superseded-cap-30.flang` + `replacement-cap-45.flang` | вторая редакция правила, без наследования | 0 и 0 |

**Код 1** — найдена ложь. Противоречие без примера автора компилятор находит
сам: считает утверждение на пробном входе.

```
$ flang check fspec/experiments/contradiction-without-example.flang --proof
FLANG_EXAMPLE: FLANG_PROPERTY: постусловие «скидка не меньше 50» функции «Скидка заказа» нарушено на входе сумма = 0 — посчитано вычислителем на этом входе
```

**Код 3** — утверждение не доказано и не опровергнуто. Так отвечает
`false-claim-negative-zero.flang`: утверждение ложно на минус нуле, но
компилятор этого не находит и оставляет его на сетке из одного примера.
Доказано — не значит верно, а не опровергнуто — тем более: ноль, пустое
значение, край отрезка и минус ноль стоит записать примерами.

**Код 0 у двух последних пар** — то, ради чего нужен каталог. Подключение с
отбором и новая редакция правила — законные программы. Отличить отмену правила
от его замены можно, только зная, что было раньше, то есть по слепку.

## Как добавить спеку

1. Положите файл в `fspec/spec/` с номером в начале имени. Имя файла —
   английскими словами.
2. Первая строка — `модуль «Спека N: …»`. Если спека опирается на прежнюю,
   вторая строка — `использует «Спека M: …» из "./….flang"`.
3. Напишите функцию с `обеспечивает «имя» …`. Имя попадёт в отчёт о беде.
4. Проверьте: `flang check fspec/spec/<файл> --proof`. Утверждение должно быть
   доказано; «сетка» и «объявлено, не доказано» не принимаются.
5. Подмените тело заглушкой. Утверждение пережило — перепишите его.
6. Впишите утверждение в слепок: `flang io fspec/snapshot.flang`.
7. Прогоните `flang run-script specs:check`.

## Чего в каталоге нет

| чего нет | почему это нужно |
|---|---|
| поиска противоречащего примера между спеками | «не доказано» не значит «ложно»; отличить можно только предъявив значение |
| спеки до реализации | `обеспечивает` пишется при функции с телом, и утверждение выводится из тела |
| суждения, слабее ли новая цель прежней | слепок видит только, что цель другая |
| прогона примеров самой проверки | 145 примеров <!-- СНЯТО 2026-10-04 примеров-в fspec/guard.flang = 145 --> `guard.flang` не прогоняются ни одной командой: прогон упирается в предел шагов |

Внешний решатель (Z3 и подобные) сюда не подключён: его ответ «невыполнимо»
нельзя проверить ядром.
