# Совместимость: что не изменится после 1.0

Что в flang останется прежним от выпуска к выпуску, а что вправе измениться?
Эта страница отвечает по пунктам и описывает, как объявляется устаревание.

**Черновик.** Обещание вступает в силу с выпуском 1.0.0. До него действует
раздел [«До 1.0»](#до-10).

## Что замораживается в 1.0

Программа, написанная для 1.0, работает с любым выпуском 1.x без правок.
Обещание покрывает четыре вещи.

| Что | Что обещано |
| --- | --- |
| Синтаксис | Файл, который проходит `flang check` в 1.0, проходит его в любом 1.x. Ключевые слова не меняют смысл. Новые конструкции не меняют чтение старых программ. |
| Коды ошибок `FLANG_*` | Код не исчезает и не меняет смысл. Новые коды добавляются. |
| Формат записи доказательства | Запись, которую сделал `flang check --proof` в 1.0, принимает программа `checker` любого 1.x. |
| Командная строка | Команды, ключи и коды возврата остаются. В выводе `--json` поля не исчезают и не меняют тип; новые поля добавляются. |

Сломать любую из этих четырёх вещей может только выпуск 2.0.

## Что может меняться

| Что | Как меняется |
| --- | --- |
| Тексты сообщений | Слова ошибок и предупреждений правятся в любом выпуске. Сценарии должны смотреть на код `FLANG_*`, не на текст. |
| Сила ядра доказательств | Только растёт. Постусловие, доказанное в 1.0, доказывается в любом 1.x. |
| Скорость и память | Меняются в обе стороны. Заметные изменения названы в заметке о выпуске. |
| Сгенерированный код | Текст, который печатает `flang emit`, меняется. Поведение программы остаётся тем же. |
| Экспериментальное | Команды и модули, помеченные в справке как экспериментальные, обещанием не покрыты. |

Рост силы ядра проверяется на каждом выпуске. Автоматическая проверка
сравнивает список доказанных постусловий со списком прошлого выпуска. Если
список стал короче, выпуск не выходит.

У этого роста есть одно следствие. Более сильное ядро может найти контрпример
к неверному постусловию, которое раньше было проверено только на тестах. Такая
программа перестанет проходить `flang check`. Это найденная ошибка в
программе, обещание совместимости она не нарушает.

## Как объявляется устаревание

Возможность не исчезает без предупреждения. Порядок один.

1. В минорном выпуске возможность начинает предупреждать. `flang check`
   печатает предупреждение с кодом и называет замену. Код возврата не меняется.
2. В следующем минорном выпуске то же место становится ошибкой.

Срок между шагами — не меньше одного минорного выпуска. Оба шага названы в
заметках о выпусках.

После 1.0 второй шаг для четырёх замороженных вещей откладывается до 2.0:
в 1.x они только предупреждают. Для остального порядок прежний. Это, например,
функции стандартной библиотеки и ключи файла `.flangrc`.

## Что значит номер версии

Номер пишется `x.y.z`.

| Часть | До 1.0 (`0.y.z`) | После 1.0 |
| --- | --- | --- |
| `x` | всегда 0 | меняется, когда ломается замороженное |
| `y` | выпуск может ломать совместимость, после предупреждения | новые возможности; старые программы работают |
| `z` | исправления и новые возможности | только исправления |

Хвост `-rc.N` означает кандидата в выпуск: `1.0.0-rc.1` раньше, чем `1.0.0`.

## До 1.0

Сегодня совместимыми считаются коды `FLANG_*` и формы вывода `--json`.
Синтаксис ещё меняется; каждое изменение названо в заметке о выпуске.

До 1.0 осталось четыре шага.

| Выпуск | Что в нём происходит |
| --- | --- |
| 0.8.0 | Начинает действовать порядок устаревания. Всё, что уйдёт к 1.0, начинает предупреждать. |
| 0.9.0 | Предупреждения из 0.8 становятся ошибками. Синтаксис, коды, формат записи и командная строка принимают вид, в котором войдут в 1.0. |
| 1.0.0-rc.N | Кандидаты. В них попадают только исправления. |
| 1.0.0 | Обещание этой страницы вступает в силу. |
