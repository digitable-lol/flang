# Чему вы доверяете

Страница отвечает на один вопрос: насколько можно верить слову «доказано» в
отчёте flang и чем оно слабее доказательства в Lean 4.

Коротко:

- flang автоматически проверяет предусловия и постусловия закрытым списком
  правил. Его родня — Dafny, F\*, Liquid Haskell и SPARK, только без внешнего
  SMT-решателя. Интерактивным доказателем теорем, как Lean или Coq, он не является.
- «Доказано» значит: ядро доказательств вывело постусловие для всех входов
  объявленных типов.
- Часть доказанного повторяет вторая, независимая программа. Остальное держится
  на одном ядре, и отчёт называет обе доли числами.
- В выпуске 0.7.40 есть известная ошибка с функциями, у которых написано
  `убывает`. Она описана [ниже](#известная-ошибка-функция-с-убывает).

## Что значит «доказано»

Файл `docs/examples/proofs/discount.flang`:

```flang insert docs/examples/proofs/discount.flang
модуль «Скидка»

тотальная функция «Цена со скидкой»
  принимает цена: неотрицательное, скидка: неотрицательное
  требует «скидка не больше цены» скидка не больше цена
  возвращает число
  обеспечивает «в минус не уходим» результат не меньше 0
  пример «сто минус десять»
    дано цена равно 100
    дано скидка равно 10
    ожидается 90
  цена минус скидка
```

```bash
flang check discount.flang --proof
```

```
постусловие «в минус не уходим» функции «Цена со скидкой» — доказано по
объявленным типам аргументов: цель сведена правилом «неотрицательность по
построению» …
…
discount.flang: независимо, сверщиком, проиграно 1 из 1 доказанных; на слове ядра 0 …
```

Первая строка: постусловие верно для любой цены и любой скидки не больше
цены. Ядро вывело это правилом с названием «неотрицательность по построению».
Тест `пример` в выводе не участвовал.

Вторая строка — о независимой проверке, она разобрана в разделе
[«N из M»](#строка-n-из-m-независимая-проверка).

## Кому приходится верить

Чтобы «доказано» было правдой, должны быть верны четыре программы:

| Что | Что о нём известно |
| --- | --- |
| Ядро доказательств | около 11 тысяч строк внутри компилятора; шаги доказательства бывают 93 видов, у каждого вида есть лемма на Lean 4 |
| Компилятор flang | разбор текста, проверка типов и генерация кода; проверен тестами, теорем о нём нет |
| Компилятор C | внешняя программа (`cc`), flang его не проверяет |
| Библиотека времени выполнения | написана на C вручную; проверена тестами |

Вид шага — короткое имя в строках `вывод` отчёта: `Н3`, `Разв2`. Лемма на Lean
говорит: такой шаг верен в модели языка. Модель написана людьми и
проще самого языка. Конечное число в ней целое, дробных значений она не знает.
Совпадает ли код ядра с шагом из леммы, не доказано: это проверяют тесты.

## Строка «N из M»: независимая проверка

`flang check --proof` записывает каждое доказательство по шагам. Запись читает
отдельная программа `checker`, написанная на C без общего кода с компилятором.
Она берёт исходник и запись и повторяет шаги сама.

Итог стоит в предпоследней строке отчёта. Ищите в ней слово «независимо» и
пару чисел:

```
discount.flang: независимо, сверщиком, проиграно 1 из 1 доказанных; на слове ядра 0 …
```

Второе число, M, — сколько постусловий ядро назвало доказанными. Первое, N, —
сколько из них `checker` повторил сам. `сверщиком` в этой строке названа программа
`checker`, `на слове ядра` — принято без перепроверки. Остальные M − N держатся
только на ядре.

Повторяется не всё. У файла `docs/examples/proofs/largest.flang` три
доказанных утверждения, и ни одно не повторено:

```flang insert docs/examples/proofs/largest.flang
модуль «Наибольшее»

тотальная функция «Наибольшее»
  принимает а: точное целое, б: точное целое
  возвращает точное целое
  обеспечивает «не меньше первого» результат не меньше а
  обеспечивает «не меньше второго» результат не меньше б
  если а больше б
    то а
    иначе б

утверждение «наибольшее перестановочно»
  для всех а: точное целое и б: точное целое
  утверждаем («Наибольшее» от а и б) равен («Наибольшее» от б и а)
```

```
largest.flang: независимо, сверщиком, проиграно 0 из 3 доказанных; на слове ядра 3 …
```

Это не ошибка в программе: `checker` пока умеет повторять не каждое правило
ядра. На наборе из 60 задач, которым flang сравнивают с Lean, ядро доказало 55
утверждений, а `checker` повторил 30 из них.

Что делать с этим числом:

- N равно M — доказательство подтвердили две разные программы;
- N меньше M — у части постусловий подтверждение одно. Для критичного кода
  оставьте на такие постусловия тесты.

Как запустить `checker` отдельно и увидеть ответ по каждому постусловию —
[Запись доказательства](record-format.html).

## Кто проверяет само ядро

Запись доказательства читают две программы, написанные порознь:

| Программа | Что о ней доказано | Чем ещё проверена |
| --- | --- | --- |
| `checker` на C | теорем нет | 833 нарочно испорченные записи: не принята ни одна |
| вторая, на Lean 4 | для 45 путей из 52, которыми она принимает запись, есть теорема | сравнение ответов с `checker` на тех же записях |

Среди семи путей без теоремы — линейная арифметика и арифметика точных целых.

О самом ядре теорем нет. Его держат леммы о шагах, тесты и набор испорченных
доказательств, которые оно обязано отвергнуть.

## Известная ошибка: функция с `убывает`

Строка `убывает` называет выражение, которое уменьшается при каждом
рекурсивном вызове. Иногда ядро не может вывести, что оно и правда уменьшается.
Тогда завершение функции принимается без доказательства, а в код добавляется
проверка во время выполнения.

В файле `docs/examples/proofs/termination.flang` такая функция — последняя:

```flang insert docs/examples/proofs/termination.flang
модуль «Завершение»

тотальная функция «Вдвое»
  принимает х: число
  возвращает число
  х умножить на 2

тотальная функция «Сумма списка»
  принимает ряд: список числа
  возвращает число
  разбор ряд
    случай пусто
      то 0
    случай голова первый и хвост остальные
      первый плюс («Сумма списка» от остальные)

тотальная функция «Отсчёт»
  принимает н: неотрицательное
  возвращает число
  если н не больше 0
    то 0
    иначе 1 плюс («Отсчёт» от (н минус 1))

тотальная функция «Отсчёт дробного»
  принимает н: число
  возвращает число
  если н не больше 0
    то 0
    иначе 1 плюс («Отсчёт дробного» от (н минус 1))

тотальная функция «Шагов до края»
  принимает место: число, край: число
  возвращает число
  убывает край минус место
  если место не меньше край
    то 0
    иначе 1 плюс («Шагов до края» от (место плюс 1) и край)
```

```bash
flang check termination.flang --proof
```

```
«Шагов до края»  доказано объявленной мерой: убывает «край» минус «место»;
спуск ядром не выведен — на веру: мера объявлена автором, сторож считает её при
работе на каждом витке — 1 место
```

Признак — слова `спуск ядром не выведен — на веру`. Они значат: завершение
принято без доказательства. Слово `сторож` здесь — проверка во время выполнения.

На обычных числах эта функция завершается. На NaN — нет: сравнение с NaN всегда
ложно, и проверка во время выполнения её остановит. Так и задумано.

Ошибка в другом. В выпуске 0.7.40 ядро пользуется постусловиями такой функции
как доказанными фактами. Если функция на самом деле не завершается, из её постусловий выводится
и ложное утверждение, и отчёт пишет про него «доказано».

Правило для чтения отчёта:

- увидели у функции «спуск ядром не выведен» — всё доказанное с её участием
  верно при условии, что она завершается;
- завершение такой функции проверьте сами: тестами или рассуждением;
- в наших проверках ложный вывод `checker` не повторил: он остался среди M − N.

Проверка во время выполнения остановит незавершающуюся функцию на первом же
повторе. Но отчёт к этому моменту уже выдан.

Объявить аксиому в flang нельзя: такой конструкции в языке нет. Допущений,
кроме описанного, два. Ключ `--trust` запускает программу с недоказанными
постусловиями и сообщает об этом первой строкой вывода. Отображение между
категориями, у которого нет реализации, не проверяется ничем. Отчёт перечисляет
такие объявления в разделе `принято на веру`.

## «Не доказано» не значит «ложно»

Список правил закрыт. Верное постусловие, для которого нет правила, остаётся
недоказанным. В файле `docs/examples/proofs/insertion-sort.flang` два
постусловия доказаны, третье — нет:

```flang insert docs/examples/proofs/insertion-sort.flang
модуль «Сортировка вставками»

тотальная функция «Вставить»
  принимает значение: неотрицательное, элементы: список неотрицательное
  возвращает список неотрицательное
  обеспечивает «вставка удлиняет на один» (длина результат) равен ((длина элементы) плюс 1)
  разбор элементы
    случай пусто
      то [значение]
    случай голова и хвост
      если значение не больше голова
        то приписать значение к элементы
        иначе приписать голова к («Вставить» от значение и хвост)

тотальная функция «Упорядочить»
  принимает элементы: список неотрицательное
  возвращает список неотрицательное
  обеспечивает «сортировка сохраняет длину» (длина результат) равен (длина элементы)
  разбор элементы
    случай пусто
      то пустой список
    случай голова и хвост
      то «Вставить» от голова и («Упорядочить» от хвост)

тотальная функция «Не меньше всех»
  принимает граница: неотрицательное, элементы: список неотрицательное
  возвращает признак
  разбор элементы
    случай пусто
      то да
    случай голова и хвост
      то (граница не больше голова) и притом («Не меньше всех» от граница и хвост)

тотальная функция «По порядку»
  принимает элементы: список неотрицательное
  возвращает признак
  разбор элементы
    случай пусто
      то да
    случай голова и хвост
      то («Не меньше всех» от голова и хвост) и притом («По порядку» от хвост)

утверждение «сортировка упорядочивает»
  для всех а: список неотрицательное
  утверждаем («По порядку» от («Упорядочить» от а)) равен да
```

```bash
flang check insertion-sort.flang --proof; echo "код $?"
```

```
постусловие «вставка удлиняет на один» функции «Вставить» — доказано индукцией по «список» …
постусловие «сортировка сохраняет длину» функции «Упорядочить» — доказано индукцией по «список» …
утверждение «сортировка упорядочивает» — объявлено, не доказано: ни теоремы, ни примеров …
код 3
```

Что сортировка сохраняет длину списка, ядро вывело само. Что результат
упорядочен, верно, но ядро этого не вывело. Lean доказывает оба факта.

На том же наборе из 60 задач flang доказывает сам 33. Ещё 18 доказываются
после того, как программист перепишет постусловие или добавит теорему. Девять
не доказываются никак. Lean 4 доказывает все 60. Подробное сравнение —
[flang для знающих Lean и Dafny](flang-for-lean-and-dafny-users.html).

Ложное постусловие выглядит иначе. Компилятор ищет вход, на котором оно
нарушено, и показывает его с кодом `FLANG_PROPERTY`. Как отличить одно от
другого — [Если не доказалось](proof-refused.html).

## Чего доказательство не говорит

Доказательство связывает код с постусловием. Правильно ли постусловие
описывает задачу, решаете вы. Файл `docs/examples/proofs/wrong-largest.flang`:

```flang insert docs/examples/proofs/wrong-largest.flang
модуль «Не то»

тотальная функция «Большее из двух»
  принимает а: неотрицательное, б: неотрицательное
  возвращает число
  обеспечивает «не меньше первого» результат не меньше а
  обеспечивает «не меньше второго» результат не меньше б
  пример «два и три»
    дано а равно 2
    дано б равно 3
    ожидается 5
  а плюс б
```

```bash
flang check wrong-largest.flang --proof --strict; echo "код $?"
```

```
постусловие «не меньше первого» функции «Большее из двух» — доказано …
постусловие «не меньше второго» функции «Большее из двух» — доказано …
код 0
```

Оба постусловия доказаны, а функция возвращает сумму. Постусловия не сказали
главного: результат равен одному из аргументов. Тест тоже написан под сумму.

Проверить постусловие можно так: замените тело функции заглушкой, например
`0`. Если постусловие всё ещё доказано, о функции оно ничего не говорит.

## Для разработчиков языка: откуда числа

Эти команды работают в клоне репозитория, установленному `flang` они не нужны.
Для трёх последних нужен Lean 4.

| Число на странице | Команда |
| --- | --- |
| около 11 тысяч строк ядра | `flang run-script trust:ceiling` |
| 93 вида шагов, у каждого лемма | `flang run-script lean-rules:check` |
| 833 испорченные записи, принято 0 | `flang run-script checker:check` |
| 45 путей из 52 | `flang run-script lean-soundness:check` |
| 33, 18 и 9 задач из 60 | `flang run-script lean-parity:probe` |
| 30 из 55 | `flang check --proof` по каждому файлу набора `parity/programs` из каталога доказательств |
