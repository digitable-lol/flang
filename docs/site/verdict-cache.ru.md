# Кеш доказательств

Страница отвечает на вопрос: как не доказывать одно и то же при каждом
запуске. `flang check` и `flang emit` каждый раз доказывают постусловия
заново. Кеш хранит ответы ядра на диске и отдаёт их, пока не изменилось то, от
чего ответ зависит. По умолчанию кеш выключен.

## Как включить

```bash
FLANG_PROOF_CACHE=on flang check --proof discount.flang
```

| Значение `FLANG_PROOF_CACHE` | Что будет |
| --- | --- |
| не задано, пусто, `off`, `0` | кеша нет |
| `on`, `1` | каталог `.flang-cache/proofs/` в корне проекта — ближайшем сверху каталоге с `.flangrc` или `.git` |
| любое другое | путь к каталогу кеша |

Каталог можно удалить в любой момент. В git его не кладут.

## Как увидеть, что кеш работает

`FLANG_PROOF_CACHE_STATS=1` добавляет строки счётчиков. Два запуска подряд на
файле `docs/examples/proofs/discount.flang`:

```bash
FLANG_PROOF_CACHE=on FLANG_PROOF_CACHE_STATS=1 flang check --proof discount.flang
```

```
кеш доказательств: взято записей 0, попаданий 0, новых 10, потеряно 0, отвергнуто сегментов 0
```

```bash
FLANG_PROOF_CACHE=on FLANG_PROOF_CACHE_STATS=1 flang check --proof discount.flang
```

```
кеш доказательств: взято записей 10, попаданий 4, новых 0, потеряно 0, отвергнуто сегментов 0
```

Первый запуск посчитал ответы и записал десять записей. Второй прочитал их с
диска и четыре раза взял готовый ответ. «Сегмент» в выводе — один файл кеша.

## Когда ответ считается заново

Запись кеша подходит, только если совпало всё, от чего зависит ответ:

- программа `flang`: другая версия компилятора старых записей не берёт;
- постусловие и все объявления, на которые оно ссылается: функции, типы,
  утверждения, теоремы, в том числе из импортированных модулей.

Правка функции, от которой постусловие не зависит, его запись не трогает.
После правки одной функции большого файла пересчитывается только связанное с
ней.

## Почему кеш не пропустит ложного доказательства

- Ключ записи — SHA-256 от отпечатка программы `flang` и точных байтов всего,
  что получает ядро. Запись с таким ключом появляется только из того же
  вычисления.
- Файл кеша подписан: HMAC-SHA256 ключом этой машины
  (`~/.config/flang/proof-cache.key`, создаётся сам, права 0600). Испорченный
  или чужой файл не берётся, и всё считается заново.
- С `FLANG_MEMO_AUDIT=1` каждое попадание считается заново и сравнивается с
  записью. Расхождение останавливает программу.

Кеш не добавляет доверия и не убавляет: в нём лежат ответы того же ядра. Чему
вы доверяете, когда видите «доказано», — [на отдельной странице](trust.html).

## Переменные

| Переменная | Что делает |
| --- | --- |
| `FLANG_PROOF_CACHE` | включает кеш и задаёт каталог |
| `FLANG_PROOF_CACHE_STATS=1` | строки счётчиков в stderr |
| `FLANG_PROOF_CACHE_AUDIT=1` | ответ по части программы сравнивается с ответом по всей программе |
| `FLANG_MEMO_AUDIT=1` | каждое попадание пересчитывается и сравнивается с записью |
| `FLANG_PROOF_CACHE_KEY` | файл ключа подписи вместо `~/.config/flang/proof-cache.key` |
| `FLANG_PROOF_CACHE_RECHECK=0` | не запускать независимую проверку записи после запуска с попаданиями |

## Где лежит

```
.flang-cache/proofs/<отпечаток программы flang>/<отпечаток пути файла>/<номер>.seg
```

Свой каталог на каждую версию `flang` и на каждый входной файл. Два
одновременных запуска на одном файле друг другу не мешают: файл пишется под
временным именем и переименовывается.
