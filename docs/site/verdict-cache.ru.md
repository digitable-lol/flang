# Кеш доказательств

`flang check` и `flang emit` доказывают каждое обещание программы заново при
каждом запуске. Кеш доказательств хранит ответы prover'а на диске рядом с
проектом и на следующем запуске отдаёт их без пересчёта — пока не изменилось
ничего, от чего ответ зависит. По умолчанию кеш выключен.

## Как включить

```bash
FLANG_PROOF_CACHE=on flang check --proof sum.flang
```

| Значение `FLANG_PROOF_CACHE` | Что будет |
| --- | --- |
| не задано, пусто, `off`, `0` | кеша нет |
| `on`, `1` | каталог `.flang-cache/proofs/` в корне проекта — ближайшем сверху каталоге с `.flangrc` или `.git` |
| любое другое | путь к каталогу кеша |

Каталог можно удалить в любой момент. В git его не кладут.

## Как увидеть, что кеш работает

`FLANG_PROOF_CACHE_STATS=1` добавляет строку счётчиков. Два запуска подряд на
программе с одним постусловием:

```bash
$ FLANG_PROOF_CACHE=on FLANG_PROOF_CACHE_STATS=1 flang check --proof sum.flang
кеш доказательств: взято записей 0, попаданий 0, новых 1, потеряно 0, отвергнуто сегментов 0

$ FLANG_PROOF_CACHE=on FLANG_PROOF_CACHE_STATS=1 flang check --proof sum.flang
кеш доказательств: взято записей 1, попаданий 1, новых 0, потеряно 0, отвергнуто сегментов 0
```

Первый запуск посчитал ответ и записал его, второй взял с диска.

## Когда ответ считается заново

Запись кеша подходит, только если совпало всё, от чего зависит ответ:

- сам двоичный `flang` — другая версия компилятора старых записей не берёт;
- обещание и все объявления, на которые оно ссылается, — функции, типы,
  утверждения, теоремы, в том числе из импортированных модулей.

Правка функции, от которой обещание не зависит, его запись не трогает. Поэтому
после правки одной функции большого файла пересчитывается только то, что с ней
связано.

## Почему кеш не пропустит ложного доказательства

- **Ключ покрывает все входы.** Ключ записи — sha256 от отпечатка двоичного и
  точных байтов всего, что получает prover. Запись с таким ключом могла
  появиться только из того же вычисления.
- **Файл кеша подписан.** Подпись — HMAC-SHA256 ключом этой машины
  (`~/.config/flang/proof-cache.key`, создаётся сам, права 0600). Испорченный
  или чужой файл не берётся, и всё считается заново:

  ```
  кеш доказательств: …/3888793-1a2efc3d002.seg — не сегмент кеша, не взят
  кеш доказательств: взято записей 0, попаданий 0, новых 1, потеряно 0, отвергнуто сегментов 1
  ```

- **Можно перепроверить.** С `FLANG_MEMO_AUDIT=1` каждое попадание считается
  заново и сравнивается с записью; расхождение останавливает программу.

## Переменные

| Переменная | Что делает |
| --- | --- |
| `FLANG_PROOF_CACHE` | включает кеш и задаёт каталог |
| `FLANG_PROOF_CACHE_STATS=1` | строка счётчиков в stderr |
| `FLANG_PROOF_CACHE_AUDIT=1` | ответ по части программы сверяется с ответом по всей программе |
| `FLANG_MEMO_AUDIT=1` | каждое попадание пересчитывается и сверяется |
| `FLANG_PROOF_CACHE_KEY` | файл ключа подписи вместо `~/.config/flang/proof-cache.key` |
| `FLANG_PROOF_CACHE_RECHECK=0` | не запускать независимую проверку записи после запуска с попаданиями |

## Где лежит

```
.flang-cache/proofs/<отпечаток двоичного>/<отпечаток пути файла>/<номер>.seg
```

Свой каталог на каждый двоичный и на каждый входной файл. Два одновременных
запуска на одном файле друг другу не мешают: файл пишется под временным именем
и переименовывается.
