# Журнал упреждающей записи

В `docs/examples/wal/` две программы. Первая разбирает, печатает и
восстанавливает после обрыва журнал упреждающей записи (write-ahead log).
Вторая — план, который дописывает в журнал одну запись. Сами программы на диск
не пишут: план возвращает поручения «Прочитать файл» и «Записать файл», а
исполняет их `flang io`.

## Формат записи

```
#<номер>:<длина>:<тело>;
```

* `<номер>` и `<длина>` — десятичные числа канонической записи: от одного до
  пятнадцати знаков, без ведущего нуля (единственный законный ноль — сам `0`).
  Правило записано функцией «Канон числа».
* `<длина>` — число кодовых точек тела, не байт.
* `<тело>` — ровно столько кодовых точек, любых: `#`, `:`, `;` и перевод
  строки входят в тело наравне с буквами.
* Журнал — записи подряд, без разделителей между ними.

Запись печатает функция «Напечатать запись». Журнал читает по одному знаку
функция «Шаг чтения» — автомат с состояниями «Между записями», «Читаем номер»,
«Читаем длину», «Читаем тело», «Ждём метку конца» и «Сбились». Из состояния
«Сбились» выхода нет: всё, что идёт после первой порчи рамки, отбрасывается;
записи, прочитанные до неё, остаются.

Длина стоит впереди тела, потому что тело может содержать те же знаки, что и
рамка записи: читатель по разделителям на таком теле ошибается, читатель по
длине — нет. Метка конца `;` нужна всё равно: без неё запись с заниженной
длиной прочиталась бы как целая, а хвост её тела — как начало следующей.

## Как запустить

Примеры:

```
flang test docs/examples/wal/write-ahead-log.flang
flang test docs/examples/wal/append-plan.flang
```

```
docs/examples/wal/write-ahead-log.flang: примеров 98, прошло 98, не прошло 0
docs/examples/wal/append-plan.flang: примеров 110, прошло 110, не прошло 0
```

Второй прогон считает и примеры подключённого модуля: своих у плана 12.

План исполняет `flang io`. Файл журнал.wal он ищет в каталоге программы, и файл
обязан существовать. Чтобы не писать в дерево, скопируйте программы в отдельный
каталог:

```
mkdir -p /tmp/wal && cp docs/examples/wal/*.flang /tmp/wal/ && : > /tmp/wal/журнал.wal
flang io /tmp/wal/append-plan.flang
```

```
не доказано: утверждений 17: доказано 10, сетка 7, на веру 0 — запуск только по явному согласию: --trust
```

Код возврата 3: `flang io` не исполняет план, у которого не все утверждения
доказаны. Согласие даётся ключом `--trust`:

```
flang io /tmp/wal/append-plan.flang --trust
```

```
на веру: доказанность не считалась — запуск по ключу --trust
{"plan":"Дописать в журнал","result":1,"orders":2,"log":[{"поручение":{"variant":"Прочитать файл","fields":{"путь":"журнал.wal"}},"отклик":{"variant":"Прочитано","fields":{"содержимое":""}}},{"поручение":{"variant":"Записать файл","fields":{"путь":"журнал.wal","содержимое":"#1:13:выдача товара;"}},"отклик":{"variant":"Записано","fields":{"сколько":20}}}]}
```

Каждый запуск дописывает одну запись с телом «выдача товара» и следующим
номером. После двух запусков в файле:

```
#1:13:выдача товара;#2:13:выдача товара;
```

Запись с испорченной рамкой в конце файла отбрасывается. Если дописать к этому
файлу обрывок `#3:5:обрыв` без метки конца, следующий запуск оставит:

```
#1:13:выдача товара;#2:13:выдача товара;#3:13:выдача товара;
```

Без файла журнала план не идёт дальше первого поручения, код возврата 1:

```
{"error":"файл не прочитан: No such file or directory","diagnostics":[{"code":"FLANG_IO_READ","message":"файл не прочитан: No such file or directory","severity":"error","span":{"line":92,"column":1}}]}
```

## Что доказано и что нет

```
flang check docs/examples/wal/write-ahead-log.flang --proof
```

Последние строки отчёта:

```
итог:
  функций 25: тотальных 25, обычных 0
  обещание несёт: композиция 21, структура 4, точный шаг 0, постоянный шаг 0, объявленная мера 0
  сторожей в рантайме: 0 мест
  законов на сетке: 0 (значений в сетках 0); на веру: 0
  утверждений 17: доказано 10 (из них индукцией 3) (из них без теоремы 7), сетка 7, объявлено, не доказано 0
```

Код возврата 3 — из-за семи утверждений на сетке. `flang check` без `--proof`
на том же файле отвечает «замечаний нет» и кодом 0: вердикты утверждений он не
показывает. У `append-plan.flang` своих утверждений нет, шесть его функций
тотальны.

Главное утверждение о чтении: журнал, оборванный на любом знаке, читается до
последней целой записи и не дальше. Оно записано четырьмя постусловиями:

| постусловие | функция | вердикт `--proof` |
|---|---|---|
| «съедено не больше, чем подано» | «Прочитать журнал» | сетка |
| «съеденное — это ровно печать прочитанного, знак в знак» | «Прочитать журнал» | сетка |
| «съеденное и остаток дают вход, ни знаком больше и ни знаком меньше» | «Прочитать журнал» | сетка |
| «в остатке целой записи с начала нет» | «Остаток пуст для читателя» | сетка |

«Сетка» означает: утверждение проверено на примерах функции, доказательства обо
всех входах у него нет — отчёт говорит это прямо. Ядро не берёт эти четыре
утверждения потому, что они связывают результат свёртки по всей строке входа с
самой строкой (печать равна началу входа); правила такого вида у ядра нет.
Что ядро берёт, а что нет, названо на странице [какие постусловия prover
доказывает](what-the-kernel-accepts.html).

Кроме этих четырёх на сетке стоят ещё три: «цифра не больше девяти»
(«Цифра числом»), «печать не короче шести знаков» («Напечатать запись») и
«разрез не теряет и не добавляет ни знака» («Разрез сходится»).

Что ядро доказало обо всех входах:

* завершение каждой функции обоих модулей — композицией и структурой, без
  проверок убывания при работе программы;
* индукцией по строке — «начало не длиннее целого» («Начало строки») и «хвост
  не длиннее целого» («Хвост строки»); индукцией по списку — «наибольший не
  меньше начала поиска» («Наибольший номер»);
* сведением цели с телом функции — постусловия «Идём дальше», «Сбиться»,
  «Закрыть запись», «Обратный порядок», «Сколько записей», «Следующий номер».

Утверждений «объявлено, не доказано» и принятых на веру нет.

Независимый сверщик доказательств (`FLANG_CHECKER`, собирается
`make -C flang/proof/checker`) повторил 4 доказательства из 10; остальные 6
держатся на слове ядра.

Подтверждение записи в плане: вариант «Конец работы» строится в модуле «Append
plan» в одном месте — в ветви «Записано» функции «После записи журнала». Любой
другой отклик хозяина даёт «Провал»: «Сбой» — со своим кодом, прочее — с кодом
`FLANG_IO_ORDER`. Это видно чтением модуля и его примерами.

## Чего программа не гарантирует

* **Долговечности.** Сброс на диск, кэш диска и порядок записи контроллером —
  вне программы. Отклик «Записано» означает лишь то, что хозяин сообщил о
  записи.
* **Дописывания в конец файла.** Поручения такого нет; план переписывает файл
  целиком — целые записи плюс новая.
* **Целостности тела.** Контрольной суммы у записи нет; перевёрнутый бит в
  середине тела рамку не портит. Ловятся только порча рамки и обрыв.
* **Байтовой длины.** Длина считается в кодовых точках: строка приезжает в
  программу уже раскодированной хозяином.
* **Порядка записей на диске.** Следующий номер — наибольший из прочитанных
  плюс один; что записи легли в файл по порядку номеров, не проверяется.
* **Уникальности номеров за потолком канона.** Дойдя до наибольшего
  пятнадцатизначного номера, «Следующий номер» перестаёт расти.
* **Одновременного доступа.** Двух писателей в один журнал нет.
* **Создания журнала.** Отсутствующий файл план не заводит, а отвечает
  «Провал».
