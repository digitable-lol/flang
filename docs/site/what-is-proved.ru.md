# Что доказано, а что нет

Каким результатам `flang check --proof` можно доверять, что доказано о самом
компиляторе и где всё ещё нужны тесты. У каждого числа рядом стоит команда,
которая его печатает.

## Что доказано в репозитории

Компилятор, стандартная библиотека и примеры: {{корпус.файлов}} файлов,
{{корпус.функций}} функций, {{корпус.строк|разрядами}} строк. Числа ниже дал
полный прогон компилятора по репозиторию (`bootstrap/flang run-script
numbers:build`, несколько часов), поэтому они могут отставать от кода. Для
одного файла те же числа за секунды печатает `flang check <файл> --proof --json`.

### Завершаемость: {{корпус.тотальных}} функций из {{корпус.функций}}

| Чем доказана завершаемость | Функций | Проверка во время работы |
|---|---:|---|
| Рекурсии нет вовсе | {{носители.композиция}} | нет |
| Рекурсия по части входа (хвост, поле) | {{носители.структура}} | нет |

### Доказательства компилятора перепроверены независимо

[Запись доказательства](record-format.html) перепроверяет отдельная программа
на C. Одна команда прогоняет её по собственным доказательствам компилятора:

```
$ bootstrap/flang io scripts/provability.fscript --plan Verdict --timeout 900000
ДОКАЗУЕМ
проверка 2 — доля проигрыванием не ниже 100 %? ДА (100.00 %: 661 из 661;
недостижимых мест вынесено 41)
проверка 3 — набор проб пройден? ДА (набор подделок 45 из 45; проб на подлог
825, принято кодом 0 — 0; честных 414, отвергнуто 0)
```

Программа на C перепроверила 661 место доказательств из 661. Из 825 нарочно
испорченных записей не принята ни одна, из 414 правильных ни одна не
отвергнута. Сто процентов — про собственные записи доказательств компилятора.
О ваших программах и о собранном двоичном файле это число не говорит ничего.

Остальное меряет вторая команда:

```
$ bootstrap/flang io scripts/four-coverages.fscript --plan Measure --timeout 900000
```

| Что | Сколько |
|---|---|
| Правила вывода с леммой на Lean 4 | 164 из 168 строк перечня |
| Правила вывода в приёмке Lean | 93 из 144; вне приёмки 51 |
| Известные нарушения состоятельности, открыты | 5, поимённо |
| Правила перевода flang → C, сверенные с исходником | 24 из 41 |

Сам Lean эта команда не запускает; его запускает `sh flang/proof/lean/run.sh`.
Аксиом у prover'а нет, и это тоже проверяется командой —
[Зачем и как](proofs.html#что-значит-доказано).

## Что не доказано

### Собственные исходники компилятора проверены не целиком

`flang check` останавливает прогон, превысивший предел шагов, с
`FLANG_RECURSION_LIMIT`; поднять предел на один прогон — `--step-limit N`.
На самых больших исходниках компилятора обычный `flang check` может
остановиться раньше, чем проверит все примеры и доказательства. Файлы с
объявленными категориями и процессами проверяются частично: компилятор пишет
«проверено НЕ ДО КОНЦА» и завершается с кодом 2.

Доверять приходится правилам prover'а, компилятору, который их исполняет,
программе проверки на C, компилятору C и железу.

### В проверке типов открыты две дыры

`0 делить на 0` проходит `flang check`, а результат — NaN. Обобщённая функция,
вызванная в ветви `разбор`, не сверяется с объявленным типом результата.
Остальное — [Известные ограничения](limits.html).

### Граница на `число` ложна на NaN

NaN стоит вне порядка: и `NaN не меньше 0`, и `NaN меньше 0` ложны. Поэтому
«модуль неотрицателен» — ложное постусловие, и prover прав, что его не
доказывает:

```flang
модуль «Граница»

тотальная функция «Модуль»
  принимает х: число
  возвращает число
  обеспечивает «модуль неотрицателен» результат не меньше 0
  если х не меньше 0
    то х
    иначе 0 минус х

тотальная функция «Модуль не числа»
  возвращает число
  «Модуль» от (0 делить на 0)
```

```
$ flang check граница.flang --proof; echo "код $?"
  постусловие «модуль неотрицателен» функции «Модуль» — объявлено, не доказано:
  ни теоремы, ни примеров. Его считает рантайм после каждого возврата — на тех
  входах, которые придут
код 3
$ flang run граница.flang --function 'Модуль не числа' --trust; echo "код $?"
на веру: доказанность не считалась — запуск по ключу --trust
FLANG_PROPERTY: нарушено свойство «модуль неотрицателен» функции «Модуль»
код 1
```

«Prover не смог» и «утверждение ложно» в отчёте выглядят одинаково. Прежде чем
выяснять, почему постусловие не доказано, прогоните его на `0`, `−0`, `±∞`,
NaN, `2⁵³`, пустой строке. Границу на `число` пишите с условием конечности или
объявляйте аргумент точным типом: `неотрицательное`, `сотых`, `тысячных`.

### Доказанное постусловие может ничего не говорить

Постусловие `результат равен (0 минус х)` при теле `0 минус х` доказывается за
один шаг: оно повторяет тело. «Длина результата неотрицательна» верна для
любой функции. Проверить можно механически: замените тело заглушкой (`0`,
`""`, `нет`, пустой список). Если постусловие всё ещё доказано, об этой
функции оно ничего не говорит. Для границ берите заглушку за границей: `−1`
или число больше потолка.

На двадцати функциях библиотеки (`docs/benchmarks/proof-cost/functions/`):

```
$ bootstrap/flang run-script proofs:count-20
  доказано хоть что-нибудь: 14 из 20
  из них СОДЕРЖАТЕЛЬНО:    10 из 20
  содержательных: 11  ослабленных: 6  даровых: 1  не проверено: 2
```

Из двадцати доказанных постусловий 11 отпадают при заглушке, то есть говорят
о функции. Шесть доказываются и при заглушке, одно переписывает тело, два
проверить подменой не удалось.

### Доказано — не значит правильно

Доказательство говорит, что код соответствует постусловию. Что постусловие
выражает задуманное, оно не говорит:

```flang
модуль «Не то»

тотальная функция «Наибольшее»
  принимает а: неотрицательное, б: неотрицательное
  возвращает число
  обеспечивает «не меньше первого» результат не меньше а
  обеспечивает «не меньше второго» результат не меньше б
  пример «два и три»
    дано а равно 2
    дано б равно 3
    ожидается 5
  а плюс б
```

Оба постусловия доказаны для всех входов, а функция возвращает сумму, а не
наибольшее. Постусловие и пример читает человек.

### Недоказанное постусловие стоит времени

Доказанного постусловия в сгенерированной программе нет. Недоказанное
вычисляется при каждом возврате из функции. Дороже всего оно на маленькой
функции, которую `свёртка` зовёт на каждом элементе списка. `flang check
--proof --strict` завершается с кодом 3, если что-то не доказано, — ставьте
его в CI.

## Как проверить самому

| Что | Команда |
|---|---|
| Отчёт о доказательствах одного файла | `flang check <файл> --proof` |
| То же в JSON | `flang check <файл> --proof --json` |
| Отчёт по всем программам репозитория | `bootstrap/flang run-script proofs:report` |
| Полезные постусловия среди двадцати | `bootstrap/flang run-script proofs:count-20` |
| Доказательства компилятора, перепроверенные программой на C | `bootstrap/flang io scripts/provability.fscript --plan Verdict --timeout 900000` |
| Lean, состоятельность, перевод в C | `bootstrap/flang io scripts/four-coverages.fscript --plan Measure --timeout 900000` |
