# Язык доказательств: как пишется шаг и чего в нём нет

Полное описание слоя доказательства — правила ядра, принципы индукции, слова
ведомости — лежит в [`docs/flang/proof/SPEC.md`](../flang/proof/SPEC.md). Эта
страница коротко собирает то, что относится к ЗАПИСИ доказательства: какие
шаги автор может написать, как ядро их проверяет и каких шагов в языке пока нет.

## 1. Теорема и её шаги

```flang
теорема «сортировка деревом не теряет и не добавляет чисел»
  дано элементы: список числа
  утверждаем (длина результат) равен (длина элементы)
  по свойству «в дереве ровно столько чисел, сколько в списке»
  следовательно доказано
```

(`flang/stdlib/numtree.flang`.) Теорема называет гипотезы (`дано`), цель
(`утверждаем`), шаги и закрывается словами `следовательно доказано`. Слова
поверхности перечислены в разделе 1 `docs/flang/proof/SPEC.md`.

Обоснований шага четыре:

| обоснование | на что опирается |
|---|---|
| `по примеру «…»` | пример функции |
| `по предположению` | допущение индукции, предусловия, уже добытые факты |
| `по свойству «…»` | постусловие другой функции (лемма) |
| `по закону «…»` | объявленный закон |

Индукция пишется словами `индукция по <параметр> [убывает <мера>]` и случаями
`случай …` / `то …`; принцип индукции ядро читает с объявления типа.

Цепочка шагов — `затем <утверждение> по <обоснование>`:

```flang
    случай голова и хвост
      затем (длина («Вставить по порядку» от голова и («Сортировать» от хвост)))
            равен ((длина («Сортировать» от хвост)) плюс 1)
            по свойству «вставка удлиняет список ровно на один»
      то по предположению
```

Утверждение, выписанное в `затем` и НЕ совпавшее с целью, — **промежуточный
факт**: ядро доказывает его тем же обоснованием из уже известного и кладёт в
известное для следующих шагов.

## 2. Как ядро проверяет шаг

Проверка — свёртка по конечному дереву без поиска. Каждый шаг отвечает на один
вопрос: выведено ли это из уже известного НАЗВАННЫМ обоснованием.

1. **Известное к шагу N** — гипотезы `дано`, предусловия функции, допущения
   индукции этого случая и факты шагов 1…N−1. Ничего больше.
2. **Выписанное обязано быть выведено**, а не принято на слово. У `по свойству`
   факт выводится из инстанций названного постусловия на вызовах внутри
   выписанного утверждения; у `по предположению` — из допущений, предусловий и
   добытых фактов. У `по примеру` и `по закону` выписанное утверждение не
   читается.
3. **Закрытие обязательно.** Цепочка принимается, только если хотя бы один шаг
   закрыл построенную ядром цель. Цепочка из одних промежуточных фактов
   отвергается: она доказывает верное, но не заявленное.
4. **Круг запрещён**: `по свойству` на доказываемое сейчас постусловие
   отвергается.
5. **Порядок проверки.** Первый шаг случая стоит сразу за `то` и начинается
   словом обоснования, поэтому промежуточный факт не может стоять раньше
   закрывающего шага. Ядро проверяет сперва шаги с выписанным утверждением,
   потом закрывающие.

Написанное доказательство, которое не сходится, — ошибка в файле (`flang check`
отказывает), а не «объявлено, не доказано». Подделки на эти условия лежат в
`flang/test/fixtures/poddelka-promezhutochnyy-fakt.flang`.

Если шаг `по свойству` опирается на постусловие, которое само не доказано,
ведомость пишет «доказано ПРИ УСЛОВИИ» и называет недоказанную посылку.

## 3. Чем это не является

**Тактик нет.** Тактика — метапрограмма, ворочающая цель поиском; поиск
нетотален, а всё в flang либо тотально, либо объявлено обычным. Что бы ни
предложил внешний помощник, ядро проверяет написанный текст доказательства.

**Проверяющая программа ничего не ищет.** Выписанное автором утверждение она
проверяет теми же правилами, которыми проверяет цель.

## 4. Печать

Текст доказательства в напечатанный код не попадает: программа с теоремой и без
неё печатается во все цели одинаковыми байтами. Доказанное постусловие при этом
**снимает сторожа** из напечатанного кода: недоказанное постусловие печатается
проверкой после каждого возврата, доказанное — нет.

## 5. Каких шагов в языке нет

| шаг | как мог бы писаться | состояние |
|---|---|---|
| разбор случаев | `разбор случаев <терм>` / `случай …` | слова в разборщике нет |
| переписывание по определению | `по определению «Имя»` | слова в разборщике нет; развёртку определения ядро делает само, двери из доказательства нет |
| обобщённое утверждение (инвариант накопителя свёртки) | — | высказать нечем |

Пока этих шагов нет, соответствующие цели закрываются только тем, что ядро
выводит само (см. «Граница честности» в `docs/flang/proof/SPEC.md`).
