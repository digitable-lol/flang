# Чего не хватает FTS, чтобы искать противоречия

Замысел `fspec` — спеки бизнес-требований на flang и машина, которая ищет
**противоречия** между ними: легаси закрыто спекой, бизнес просит фичу, новая
спека обязана не противоречить старым. Эта страница отвечает на один вопрос:
**что из этого уже умеет язык, а чего в нём нет вовсе.** Каждый ответ получен
прогоном, и команда записана рядом.

Образец — `docs/specifications/failure-layer.flang`. Правила слоя отказов живут в
`flang/self/failures.flang` («Коды отказа»); сверки спеки с ними нет, и спека
может разойтись с деревом молча.

## 1. Поверхность FTS читается разборщиком языка

Разборщик понимает `категория`, `объект`, `утилита`, `правило`, `свойство`,
`пример`, `морфизм` и кладёт их в узлы `ftsLegacy` (`flang/self/parser.flang`).
Файл с такой поверхностью — и `.flang`, и `.fts` — проходит обычную проверку:

```
$ flang check flang/test/fixtures/fts-naslediye/query.fts
модуль «Запрос списка»: функций 0, из них с доказанным завершением 0; типов 1
flang/test/fixtures/fts-naslediye/query.fts: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
```

Образец лежит в `.flang`, чтобы рядом со спекой стояли обычные функции языка.

## 2. Сколько поверхности FTS доезжает до проверки: одна конструкция из семи

Файл с заведомо ЛОЖНЫМ свойством и заведомо ЛОЖНЫМ примером внутри утилиты FTS:

```
$ flang check проба.flang
модуль «Проба»: функций 1, из них с доказанным завершением 1; типов 1
проба.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
$ flang test проба.flang
проба.flang: примеров 0, прошло 0, не прошло 0
$ flang run проба.flang --function "«Рассчитать скидку»"
FLANG_UNKNOWN_NAME: не найдена функция «Рассчитать скидку»
```

Ложь принята молча, кодом возврата 0.

| конструкция FTS | куда доезжает | проверяется ли |
|---|---|---|
| `объект` + поля | типы программы | **да** |
| `категория` | узел `ftsLegacy` | нет |
| `утилита` | узел `ftsLegacy` | нет |
| `правило` | узел `ftsLegacy` | нет |
| `свойство` | узел `ftsLegacy` | нет |
| `пример` | узел `ftsLegacy` | нет |
| `морфизм` | узел `ftsLegacy` | нет |

**Одна из семи.** Синтаксис при этом разбирается строго: пример с ожиданием не
по форме `ожидается результат равен …` даёт `FLANG_PARSE`. То есть FTS —
проверяемая **грамматика** и непроверяемая **семантика**.

Отсюда устройство образца: таблица правил стоит в поверхности FTS, а
утверждение, которое язык умеет проверить сам, записано обычной тотальной
функцией с постусловием и примерами.

## 3. Два противоречащих требования: не ловятся как противоречие

**(а) Два правила FTS, несовместных на одном входе, и два несовместных
свойства** — проверка и примеры отвечают кодом 0: утилита FTS не исполняется
(раздел 2).

**(б) Два постусловия настоящей функции языка**, `результат не меньше 10` и
`результат меньше 10`, над входом типа `число`. Проверка отказывает, но по
другой причине: каждое постусловие по отдельности ложно на «не числе»
(`FLANG_BOUND_ON_NAN`, контрпример `0 делить на 0`). Что вместе они
невыполнимы ни на одном входе, не сказано.

**(в) То же под квантором `для всех`** — сильнейшее, что язык умеет высказать о
всех входах:

```
$ flang check противоречие.flang --proof
…
  постусловие «требование продаж: скидка не меньше десяти» функции «Скидка» — объявлено, не доказано: ни теоремы, ни примеров. Его считает рантайм после каждого возврата — на тех входах, которые придут
  постусловие «требование финансов: скидка меньше десяти» функции «Скидка» — объявлено, не доказано: ни теоремы, ни примеров. Его считает рантайм после каждого возврата — на тех входах, которые придут
…
противоречие.flang: НЕ ПРОВЕРЕНО — утверждений 2: доказано 0, условно 0, сетка 0, объявлено, не доказано 2, отвергнуто 0, нарушено 0; законов на сетке 0, на веру 0 — код возврата 3
```

Оба утверждения — «объявлено, не доказано»; о том, что вместе они невыполнимы,
ведомость молчит.

Краснеет только пример, случайно попавший в противоречивую область: он называет
одно нарушенное свойство (`FLANG_PROPERTY`), вторая половина пары не упомянута,
и без примера сигнала нет вовсе. Это не находка противоречия, а совпадение.

## 4. Что придётся достроить в `fspec`

1. **Исполнять утилиту FTS.** Шесть конструкций из семи инертны. Переводить
   надо из узла `ftsLegacy`, который разборщик уже строит целиком (правила,
   свойства, примеры — всё внутри). Без этого шага «спека» остаётся текстом.

2. **Решатель выполнимости.** У ядра вердикты — доказано, опровергнуто
   примером, объявлено. Вопрос «существует ли вход, на котором выполнены оба
   требования» не задаётся нигде: отвергнутые и нарушенные в ведомости растут
   только от примеров и сеток. Нужен ещё один вердикт — **невыполнимо** — и
   решатель над тем фрагментом, в котором пишутся требования: сравнения
   (`не меньше`, `меньше`, `равен`) над числом, строкой и признаком, соединённые
   «и притом». Это линейная арифметика с равенствами — разрешимый фрагмент, не
   общая логика первого порядка. Пары `∀`-требований проверяются попарно; при N
   требованиях это N(N−1)/2 запросов.

3. **Противоречие МЕЖДУ спеками, а не внутри одной.** Функтор наследия
   (`flang/test/fixtures/fts-naslediye/discounts-into-subscriptions.fts`) — словарь
   между двумя спеками, который утверждает, что «Заказ» одной и «Подписка»
   другой — одно понятие. Без такого словаря сравнивать правила двух спек
   нельзя. Языку эта конструкция пока ничего не значит: перенести по ней
   требование и проверить пару нечем.

4. **Что переиспользуется как есть.** Ядро доказательств, ведомость с
   различением «доказано» и «сетка N», коды диагностик, проверка типов,
   `ftsLegacy` как машиночитаемое представление спеки.

Порядок работ обратный порядку списка: без пункта 1 нечего решать, без пункта 2
нечего сравнивать, без пункта 3 сравнение ограничено одной спекой.
