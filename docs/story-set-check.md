# Проверка набора пользовательских историй: противоречия, дыры и повторы

Одна пользовательская история пишется девятью закреплёнными образцами
предложений — см. [`fspec/user-story-sentence-forms.md`](fspec/user-story-sentence-forms.md).
План `flang/experimental/story-set-check.fscript` берёт **каталог** таких историй
(по файлу `*.txt` на историю) и отвечает на три вопроса про весь набор сразу:

1. не противоречат ли истории друг другу;
2. чего в наборе не хватает;
3. какие истории ничего не добавляют.

Решение и его границы — [ADR-0248](adr/0248-a-set-of-user-stories-is-judged-per-quantity-by-an-answer-or-a-refutation.md).

```
bootstrap/flang io flang/experimental/story-set-check.fscript --plan Check --max-steps 400000000 -- <каталог>
```

Путь берётся от корня дерева; путь, начинающийся с `/`, берётся как есть. На
образце из дерева:

```
bootstrap/flang run-script story-set:demo
```

## Что печатается

```
набор историй: flang/proof/probes/story-set/programs/clash-under-a-condition, файлов 2
[история] discount-cap.txt «потолок скидки»: как менеджер зала хочу скидка не больше 30, при скидка не меньше 0
[история] discount-floor.txt «пол большой скидки»: как кассир хочу скидка не меньше 40, при скидка не меньше 100
[противоречие] «скидка»: «потолок скидки» хочет не больше 30, «пол большой скидки» — не меньше 40, при «скидка» не меньше 100: общего ответа нет
[ядро подтвердило] ДОКАЗАНО — утверждений 1: доказано 1, …
[дыра] «скидка»: при значении меньше 0 ни одна история ничего не требует
итог: историй 2, не прочитано 0, противоречий 1, дыр 1, замечаний 0
```

| строка | что значит | кто это решил |
|---|---|---|
| `[история]` | файл прочитан: роль, желание и условие сказаны обратно | переводчик |
| `[не прочитана]` | в файле нет истории по образцам; названо, чего не хватает. Сюда же — два файла с одним именем истории | переводчик |
| `[желания совместны]` | у величины есть ответ, годный каждой истории при её условии | ядро: доказало цель каждой истории на общем ответе |
| `[противоречие]` | потолок одной истории ниже пола другой там, где действуют обе | ядро: доказало, что ни одно значение не годится обеим |
| `[ядро подтвердило]` | строка ядра о программе, которую напечатал переводчик | ядро |
| `[ядро отвергло]` | показанный случай («Тогда при … ответ …») одной истории расходится с желаниями набора | ядро: пример не сошёлся |
| `[дыра]` | в наборе чего-то не хватает, список ниже | переводчик |
| `[замечание]` | не ошибка, но стоит посмотреть, список ниже | переводчик |

### Дыры

- **значения, о которых никто не говорит**: у каждой истории о величине есть
  условие `При … не меньше N`, и ниже наименьшего `N` ни одна история ничего не
  требует;
- **роль объявлена, а историй от неё нет**;
- **величина объявлена, а ни одна история о ней ничего не хочет**;
- **величина объявлена по-разному** в разных файлах (вторая форма слова
  расходится);
- **у истории нет показанного случая** — строки `Тогда при … ответ …`;
- **не сказано зачем** — `Чтобы` стоит прочерком.

### Замечания

- **у величины есть потолок, а пола нет** ни в одной истории (и наоборот);
- **история ничего не добавляет**: её желание следует из более строгого желания
  другой истории, условие которой не уже;
- **история повторяет другую**: то же желание при том же условии.

## Чем кончается прогон

| код плана | код возврата | когда |
|---|---|---|
| — | 0 | истории прочитаны, противоречий и дыр нет; замечания прогон не роняют |
| `FLANG_STORY_SET_TEXT` | 1 | хотя бы один файл не прочитан как история |
| `FLANG_STORY_SET_CONTRADICTS` | 1 | есть противоречие или показанный случай против набора |
| `FLANG_STORY_SET_HOLES` | 1 | противоречий нет, но есть дыры |
| `FLANG_STORY_SET_CANNOT_LOOK` | 3 | каталог не назван, в нём нет `*.txt`, или ядро ответило не приговором |

## Как судит ядро

Переводчик печатает одну программу на весь набор, и её проверяет тот же вызов
`flang check … --proof --strict`, которым проверяется любая спека. Посмотреть
программу:

```
bootstrap/flang io flang/experimental/story-set-check.fscript --plan Translate --max-steps 400000000 -- <каталог>
```

**Желания совместны.** На каждую историю печатается функция с её условием
(`требует`), её желанием (`обеспечивает`) и её показанным случаем (`пример`), а
тело у всех функций одной величины общее: значение зажимается между наибольшим
полом и наименьшим потолком из тех историй, что действуют при этом входе. Ядро
доказывает цель каждой истории на этом общем ответе — это и есть доказательство
совместности.

**Желания противоречат.** Печатается функция с двумя условиями — потолком одной
истории и полом другой — и целью, которая верна, только если таких значений нет:

```flang
тотальная функция «скидка: потолок скидки против пол скидки»
  принимает «скидка»: неотрицательное
  возвращает неотрицательное
  требует «потолок скидки: скидка не больше 30» «скидка» не больше 30
  требует «пол скидки: скидка не меньше 40» «скидка» не меньше 40
  обеспечивает «ни одно значение не годится обеим историям» результат меньше 40
  «скидка»
```

Ядро закрывает её линейной арифметикой. Обратная проверка снята прогоном:
потолок 30 против пола 31 — доказано, потолок 30 против пола 30 — отвергнуто, и
ядро назвало значение 30, которое годится обеим.

## Набор проб

```
bootstrap/flang run-script story-set:probe
```

Семь каталогов в `flang/proof/probes/story-set/programs/` и десять строк в
`expected.tsv`: согласный набор, набор с одним общим значением (потолок 30 и
пол 30), противоречие без условия и под условием, показанный случай против
набора, набор с шестью дырами и набор с непрочитанным файлом.

## Чего план не делает

- Желание — только `не больше <число>` и `не меньше <число>` об одной величине,
  условие — только `не меньше <число>`; числа целые неотрицательные. Истории о
  связи двух величин («скидка не больше половины цены») не читаются.
- Величины с одним именем считаются одной величиной во всех файлах, с разными —
  разными: синонимы план не сводит.
- Полнота проверяется по объявленному: роли, величины, значения входа. Про то,
  о чём в наборе не сказано ни слова, план не знает.
- `Чтобы <зачем>` проверяется только на прочерк: связь «зачем» одной истории с
  желанием другой не читается.
- Перевод текста в программу не доверен: доказано только то, что доказало ядро о
  напечатанной программе.
- Каждый запуск плана сначала проверяет сам план — это около 9 секунд из 14.
