# Четыре поверхности записи

Одну программу flang можно записать четырьмя наборами слов: русским, английским,
эсперанто и китайским. `если`, `if`, `se` и `如果` — одно слово языка, записанное
четырьмя способами, и разбор даёт одно дерево.

Страница отвечает на вопрос, на каком из четырёх наборов можно писать.

## Писать можно на четырёх. Доказывать — на двух

| | русская | английская | эсперанто | китайская |
| --- | :---: | :---: | :---: | :---: |
| обычная программа | да | да | да | да |
| печать в чужой язык | да | да | да | да\* |
| доказательство и завершаемость | да | да | **нет** | **нет** |

\* Китайская программа печатается в `python`, `java`, `csharp` и `elixir`.
Цели `c`, `cpp`, `go`, `js`, `ts` и `rust` её пока отказываются печатать:
иероглифические имена у них схлопываются в одно слово, и печать отказывает
столкновением имён. Разбор ниже — «[Печать и имена](#печать-и-имена)».

Словаря доказательств на эсперанто и китайском нет: слов `требует`,
`обеспечивает`, `убывает` и `индукция по` у них нет. Программа на китайском
проверится и запустится; доказать о ней ничего нельзя.

Поэтому репозиторий написан на двух поверхностях из четырёх. Эсперанто и
китайский — экспериментальные: на них написаны только две демонстрационные
программы в `docs/examples/surfaces/`.

Полная таблица слов — на странице [Словарь языка](glossary.html). Она строится
из той же таблицы, по которой разбирается любой файл. Пустая клетка в ней
значит, что слова нет.

### Печать и имена

Пустая клетка словаря видна в таблице. Печать в чужой язык упирается в другое —
в то, как имя функции превращается в идентификатор цели.

Печать режет имя по «словарным символам» и всё прочее считает разделителем.
Для знаков препинания это верно: длинное тире в имени в идентификатор попасть
не должно. Цели `python`, `java`, `csharp` и `elixir` словарными считают и
буквы всех четырёх поверхностей, поэтому имена печатаются как есть:

| Имя в исходнике | Идентификатор |
| --- | --- |
| `«乘积»` | `乘积` |
| `«阶乘»` | `阶乘` |
| `«Antaŭmeti»` | `antaŭmeti` |

Цели `c`, `cpp`, `go`, `js`, `ts` и `rust` режут имя по латинице и цифрам. У
иероглифического имени словарных символов не остаётся вовсе, все имена
схлопываются в одно слово. Генерация кода отказывает из-за столкновения имён
и не выдаёт разные функции под одним именем:

```
$ flang emit docs/examples/surfaces/factorial.zh.flang --target js --out …
flang emit: печать отказала — имена «乘积» и «前置» дают один идентификатор «value» — переименуйте одно из них в модели
```

Сам язык C такие имена допускает: `fn_乘积` собирается и работает,
`cc -std=c99 -Wall -Wextra -Werror -pedantic` предупреждений не даёт.

**Отказ остаётся там, где имя действительно не выводится.** Знаки препинания —
разделители, имя из одного препинания даёт `value`, а столкновение имён — отказ:
имена без сообщения не переименовываются.

### Шесть понятий на трёх поверхностях

| Понятие | русская | Молчит | Почему |
| --- | --- | --- | --- |
| `not` | `не` | эсперанто | логическое «не» в эсперанто `ne`, но `ne` таблица уже отдала литералу лжи. Файл на эсперанто пишет отрицание функцией «Не так» из `stdlib/logic.flang` |
| `opPercent` | `процентов` | китайская | китайский процент — приставка (`百分之十`), а не слово после числа |
| `nested` | `вложен объект` | эсперанто | |
| `embedding` | `вложение` | эсперанто | |
| `supervision` | `надзор` | эсперанто | |
| `hash256` | `хеш256` | эсперанто | |

У `module` слово на эсперанто теперь есть: файл на эсперанто пишет английское
`module`. Своё `modulo` значило бы и модуль, и остаток от деления, а остаток
таблица уже отдала `resto de`.

### Четыре понятия на одной поверхности

Только русское слово есть у четырёх понятий: `alias` — `это` («список чисел»
это …) и три слова пользовательской истории: `story` — `история`, `want` —
`хочу`, `soThat` — `чтобы`.

## Одна строка, четыре записи

```
если н не больше 1     то 1  иначе н умножить на («Факториал» от (н минус 1))
if n is at most 1      then 1  else n times («Factorial» of (n minus 1))
se n ne pli granda ol 1  tiam 1  alie n fojoj («Faktorialo» de (n minus 1))
如果 n 不大于 1          那么 1  否则 n 乘以 （«阶乘» 的 （n 减 1））
```

Это четыре строки из четырёх файлов репозитория:
`docs/examples/rosetta/factorial.flang`, `docs/examples/rosetta/factorial-english.flang`,
`docs/examples/surfaces/factorial.eo.flang`, `docs/examples/surfaces/factorial.zh.flang`.
Каждый проходит проверку одной и той же командой, меняется только имя файла:

```
flang check docs/examples/rosetta/factorial.flang
flang check docs/examples/surfaces/factorial.zh.flang
```

Все четыре отвечают одинаково: «функций 5, из них с доказанным завершением 3;
типов 0» и «замечаний нет».

Имена модулей у всех четырёх латинские — «Factorial», «Factorial»,
«Faktorialo», «Factorial zh», — и это правило Р7
([имена в коде](guide/naming.ru.md)): имя модуля становится именем напечатанного
файла, а от кириллического имени выходил бы транслит, от иероглифического —
пустое слово `value`; ни то, ни другое не читается.
Поверхность выбирается ключевыми словами и именами функций, а не именем модуля:
в русском файле стоит `«Факториал» от (н минус 1)`.

## Насколько «одно дерево» — правда

В сыром виде утверждение «разбор даёт одно дерево» неверно.

**Сырые деревья не совпадают.** С русским образцом расходятся **74 слота** у
английской и **76** у эсперанто и китайской (`bootstrap/flang run-script surfaces:run`):

| Что разошлось | Слотов |
| --- | --- |
| `name` — имена функций, параметров, примеров, типов | 45 (английская) / 46 |
| ключи `args` в примерах — имена параметров | 11 |
| локальные имена (`н`/`n`, `начало`/`start`, `конец`/`finish`, `первое`/`element`, `элементы`/`items`) | 14 |
| `acc`, `item` — связки свёртки | 4 |
| `module` — имя модуля | 0 (английская) / 1 |

Все они — имена, которые выбрал автор: «Факториал», «Factorial», «Faktorialo»,
«阶乘». Ни один из этих слотов не относится к разбору: среди них нет ни `kind`,
ни `op`, ни данных задачи. `2432902008176640000` во всех четырёх файлах написано
одинаково.

Дальше два шага. **Сверка**: деревья сравниваются с точностью до взаимно
однозначного переименования, отдельным словарём на каждую область видимости.
Всякий слот вне списка переименовываемых сравнивается побуквенно. Прогон даёт: «совпали», связано имён 26 (английская) и 27
(эсперанто, китайская). **Канонизация**: имена заменяются порядковыми номерами
по обходу дерева — и только они (вычеркнуто 24). После канонизации деревья
четырёх файлов побайтово **не** совпадают: прогон отвечает «совпали побайтово:
НЕТ». Сверка с биекцией при этом проходит; что именно расходится после
канонизации, прогон не называет. Поэтому страница не утверждает, что деревья
совпадают байт в байт.

Поверхности — одна таблица слов в лексере, и разборщик не знает, каким словом
набрано ключевое понятие: совпадение деревьев следует из устройства, а не
открывается прогоном. Прогон нужен ради второй половины утверждения — что
расходятся **только** имена автора.

## Как это устроено

Таблица одна: понятие → слова на четырёх поверхностях. Она лежит в разборе языка
одной константой `SURFACE_TABLE`, и из неё печатается всё остальное — плоский
список слов, словарь диагностик, страница [Словарь языка](glossary.html) и числа
этой страницы. Второго списка нет.

Поверхность файла определяется **большинством голосов** среди ключевых слов, а не
первым словом: файл на эсперанто начинается с английского `module`, потому что
эсперантского слова у этого понятия нет, и по первому слову вся диагностика файла
говорила бы по-английски.

Пометка `// surface: xx` в начале файла сильнее большинства. С 0.9.0
файл пишется на одной поверхности: слово другой — имя, а там, где разбор ждёт
ключевое слово, — отказ `FLANG_FILE_LANGUAGE`. Слово, которого у поверхности
нет, вписывается в её столбец заимствованием (`module`, `plus`, `minus` у
эсперанто, `это` у английского), а не берётся у соседней поверхности посреди файла.

## Перепроверить

```
bootstrap/flang run-script surfaces:run    перемерить
```

Числа этой страницы сняты этой командой. Страницу с прогоном сверяет короткая
команда `surfaces:check`: она собирает каждую фразу с числом из прогона и
требует, чтобы фраза нашлась на странице дословно.
