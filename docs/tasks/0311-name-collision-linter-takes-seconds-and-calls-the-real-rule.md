# 0311. Проверка столкновений латинских имён не укладывается в минуту и на каждый пуш не запускается

## Шаги воспроизведения

1. Запустить проверку на дереве с пределом в минуту:

```
( ulimit -v 8388608; timeout 60 bootstrap/flang io scripts/guards/latin-collision-guard.fscript --на-веру --max-steps 2000000000 )
```

2. Смотреть код возврата: 124 означает, что минута кончилась раньше проверки.
3. Посмотреть, когда проверку зовёт CI:

```
grep -an -B3 'latin-collision-guard.fscript --на-веру' .github/workflows/ci.yml
```

## Что происходит

```
$ ( ulimit -v 8388608; timeout 60 bootstrap/flang io scripts/guards/latin-collision-guard.fscript --на-веру --max-steps 2000000000 )
на веру: доказанность не считалась — запуск по ключу --на-веру
шагов 7 999 581 из 4 000 000 000 000 (0 %), идёт «Шаг плана», 1,1 ГиБ
шагов 123 059 486 из 4 000 000 000 000 (0 %), идёт «Шаг плана», 2,0 ГиБ
                                                                  код 124
```

Версия: flang 0.7.23. Дата прогона: 2 октября 2026. Числа шагов и памяти —
с одного прогона: строки хода печатаются по времени, а не по счёту шагов.

Проверка — план, его исполняет интерпретатор `flang io`. Напечатать её в C и
собрать нельзя: `bootstrap/flang emit scripts/guards/latin-collision-guard.fscript
--target c --file guard.c` отвечает «FLANG_PLAN_UNSUPPORTED: цель «c» не умеет
печатать объявление «план»», код 1 (без `--file` разбор ключей просит назвать,
куда печатать, и отвечает кодом 2 раньше печати). Поэтому в
`.github/workflows/ci.yml` задание `id-collisions` стоит под условием «только
тег или запуск по кнопке», а на обычный пуш столкновения не проверяет никто.

Само правило не удвоено и зовётся рано: при `emit --target c` функция
«Столкновения имён» из `flang/self/emit-c.flang` вызывается до ядра
доказательств. Пары имён «Цель C++» / «Цель C», на которой это было видно, в
дереве больше нет: лицо цели зовётся «Лицо цели си-плюс-плюс», и печать
обычного модуля в C отвечает кодом 0 — `bootstrap/flang emit
docs/examples/usage/discount.flang --target c --file skidka.c`. Не хватает
только дешёвой проверки по всему дереву до начала печати.

## Что должно быть

Два разных имени, дающих один идентификатор латиницей, называются по всему
дереву меньше чем за минуту и на каждый пуш, до долгого прогона печати
компилятора. Правило транслитерации при этом одно — то, что в
`flang/self/emit-c.flang` («Проверить столкновения»); второго воплощения,
написанного своими словами, быть не должно.

## Обходной путь

Запускать проверку руками перед пересборкой семени (bootstrap regeneration) и
ждать несколько минут; либо дождаться отказа самой печати в C — он приходит до
ядра доказательств, но уже после связывания всего дерева.

## Когда задача сделана

```
( ulimit -v 8388608; timeout 60 bootstrap/flang io scripts/guards/latin-collision-guard.fscript --на-веру )
                                                                  код 0
```

- на дереве без столкновений — код 0 и «новых столкновений 0»;
- на дереве, куда подложены две пары сразу (например «Обойти занятое целью C++»
  рядом с «Обойти занятое целью C» и ещё одна), — код 1, названы обе пары;
- задание `id-collisions` в `.github/workflows/ci.yml` идёт на каждый пуш.

## Где живёт правка

`scripts/guards/latin-collision-guard.fscript` — ускорить обход (сегодня он
читает правило из текста `flang/self/emit-c.flang` и перебирает все имена
дерева) и `.github/workflows/ci.yml` — снять условие с задания. Это правка
скриптов, пересборка семени не нужна. Другой путь — научить цель «c» печатать
объявление «план» (`flang/self/emit-c.flang`), тогда проверка собирается `cc`;
эта правка доезжает до двоичного только пересборкой семени.
