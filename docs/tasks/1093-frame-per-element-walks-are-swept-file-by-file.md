# 1093. Обходы списка в библиотеке берут кадр вызова на каждый элемент и упираются в предел глубины

## Шаги воспроизведения

1. Программа (путь к библиотеке — от места, где лежит файл):

```flang
модуль «Проба глубины»
  использует «Lists» из "flang/stdlib/lists.flang"

тотальная функция «Набрать»
  принимает н: неотрицательное, набрано: список числа
  возвращает список числа
  если н не больше 0
    то набрано
    иначе «Набрать» от (н минус 1) и (приписать н к набрано)

функция «Длина длинного»
  принимает н: неотрицательное
  возвращает число
  «Длина» от («Набрать» от н и пустой список)

функция «Взять из длинного»
  принимает н: неотрицательное
  возвращает число
  длина («Взять первые» от («Набрать» от н и пустой список) и н)
```

2. Команда: `bootstrap/flang run <файл> --function '«Взять из длинного»' --args '{"н": 30000}' --trust`.
3. Смотреть код возврата и имя функции в отказе.

## Что происходит

```
$ bootstrap/flang run <файл> --function '«Взять из длинного»' --args '{"н": 1000}' --trust --max-depth 100
FLANG_RECURSION_LIMIT: функция «Взять первые» превысила предел глубины вызовов (100) на глубине 101
                                                                 код 1
```

Версия: flang 0.7.25, прогон 11 октября 2026.

На том же прогоне с `--max-depth 100` и `{"н": 1000}` функции «Отбросить
первые» (`длина («Отбросить первые» от список и 0)`) и «Индекс» (`«Индекс» от
список и 1`) отвечают кодом 0 — предел глубины их больше не держит. Остаётся
«Взять первые»: её вызов не хвостовой, и кадр берётся на каждый элемент.
«Длина» написана свёрткой и кадров не берёт.

## Что должно быть

Функция библиотеки, объявленная тотальной, считает список любой длины, которая
помещается в память: глубина вызовов не растёт с числом элементов.

Приём зависит от формы обхода:

- обход, всегда доходящий до конца списка, переводится на свёртку;
- обход с ранним выходом («Взять первые», «Индекс», «Найти первое», «Позиция
  где», «Взять строку») свёрткой не лечится: кадры уходят, но витков становится
  столько, сколько элементов во всём списке. Ему нужна встроенная форма среза
  или поиска;
- обход двух списков сразу свёрткой не берётся: остаток второго списка лежит в
  накопителе, и проверка завершаемости отвечает `FLANG_NOT_TOTAL`.

## Обходной путь

Поднять предел ключом: `--max-depth 40000` на том же прогоне печатает 30000,
код 0. Либо считать длинные списки встроенными формами и свёрткой.

## Когда задача сделана

Прогон из шагов воспроизведения с ключом `--max-depth 100` и `{"н": 1000}`
печатает 1000 с кодом 0 для «Взять первые» (сегодня —
`FLANG_RECURSION_LIMIT … (100) на глубине 101`), как уже печатает для
«Отбросить первые» и «Индекс». Так же
проверена каждая переведённая функция. `bootstrap/flang check` каждого
затронутого файла отвечает кодом 0, вердикт постусловий в `check --proof` не
хуже прежнего, примеры проходят. У каждой переведённой функции есть пример на
списке длиннее 100 элементов, и прогон с ключом `--max-depth 100` его проходит.

## Где живёт правка

- `flang/stdlib/lists.flang`: «Взять первые» (строка 96), «Элемент»;
- `flang/stdlib/higher-order.flang`: «Найти первое», «Позиция где», «Вставить по»;
- `flang/stdlib/sqlite.flang`: «Взять октеты», «Отбросить октеты», «Варинт из
  октетов»;
- `flang/stdlib/strlists.flang`: «Номер строки»;
- `flang/stdlib/wire.flang`: «Набрать байты», «Взять строку».

Библиотека читается двоичным с диска, пересборка семени (bootstrap
regeneration) не нужна. Обходы той же формы есть в `flang/self`, `flang/scripts`
и `scripts`; там длина списка — внутренняя величина компилятора (параметры
функции, поля записи, файлы дерева), и за них браться после библиотеки. Правка
под `flang/self` доезжает до двоичного только пересборкой семени.

Следующий шаг — `flang/stdlib/lists.flang`, функция «Взять первые»: обход с
ранним выходом свёрткой не лечится, нужна встроенная форма среза либо накопитель
с разворотом в хвостовой позиции без постусловия на вызывающей. Краснеющая
сегодня проба: `bootstrap/flang run <файл> --function '«Взять из длинного»'
--args '{"н": 1000}' --trust --max-depth 100` — `FLANG_RECURSION_LIMIT`, код 1
(прогон 11 октября 2026).
