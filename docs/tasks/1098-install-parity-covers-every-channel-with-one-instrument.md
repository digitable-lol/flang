# 1098. Прибор паритета установок знает ровно две установки и не зовётся ниоткуда; что все каналы ставят один двоичный с одним отпечатком, никто не меряет

Решение: [ADR-0067](../adr/0067-the-release-ships-binaries-for-four-triples-from-one-seed.md),
раздел 5 — как проверять решение исполненным.

## Шаги воспроизведения

1. Сколько установок читает прибор: `grep -n 'sverka-nastroyka' packaging/install-parity.flang`
   и пример настройки в функции «Поле настройки» (шесть строк: имя первой,
   приставка первой, имя второй, приставка второй, корень, рабочий каталог).
2. Кто его зовёт: `grep -rc 'install-parity' .github/workflows/*.yml .flangrc | grep -v ':0'`
3. Разные ли установки сегодня: поставить из клона в чистый префикс и напечатать
   из другого каталога (шаги задачи о таблице каналов) — `flang emit` отвечает
   кодом 2, у установки brew или asdf того же выпуска — кодом 0.

## Что происходит

```
$ grep -n 'sverka-nastroyka' packaging/install-parity.flang
397:    ожидается вариант «Сделать» с поручение равным (вариант «Прочитать файл» с путь равным "sverka-nastroyka.txt") …
405:      то вариант «Сделать» с поручение равным (вариант «Прочитать файл» с путь равным "sverka-nastroyka.txt") …
                                                                код 0
$ grep -rc 'install-parity' .github/workflows/*.yml .flangrc | grep -v ':0'
                                                                код 1
```

Прибор `packaging/install-parity.flang` (план «Сверка», корпус 60 вызовов,
сверка кода, вывода и потока ошибок) сравнивает РОВНО две установки из
настройки `sverka-nastroyka.txt` и не зовётся ни одной работой CI и ни одной
короткой командой `.flangrc`. Заведён он был для пары npm/brew
(`docs/zettel/two-installs-answered-differently-on-54-calls-of-59.md`); npm
ушёл, пара распалась, прибор остался без предмета. Между тем установка из клона
уже сегодня отвечает на десять вызовов `emit` корпуса иначе, чем brew и asdf
(рантайма нет), и этого не видит никто.

Версия: `flang 0.7.24`, `оболочка 9f361fce`. Прогон 5 октября 2026.

## Что должно быть

Прибор читает настройку с N установок (N ≥ 2; первая — эталон, остальные
сверяются с ней попарно тем же корпусом), печатает по строке на пару и общий
итог `ИТОГ | установок N | вызовов 60 | расхождений 0`; расхождение в первых
двух строках `--version` (версия и отпечаток оболочки) называется отдельно —
это «не тот двоичный», а не «другой ответ». Каждая добавленная строка
`.flang` — не длиннее 120 знаков. Короткая команда `install-parity:check` в
`.flangrc`. Работа CI на теге (в `install-path.yml` или рядом): на
`ubuntu-latest` — установки asdf (двоичный), asdf (`FROM_SOURCE=1`), готовый
архив `tar -xzf`, клон `make install`, Nix (если принят); на `macos-latest` —
brew, asdf, готовый архив, клон. Порог — `расхождений 0`; расхождения клона по
`emit` снимаются либо правкой `make install` (класть `share/flang`), либо
названным исключением в настройке с причиной — молча не глотаются.

## Обходной путь

Запускать прибор руками на двух установках: написать `sverka-nastroyka.txt` из
шести строк и `bootstrap/flang io packaging/install-parity.flang --на-веру`.
Третью установку сверять вторым прогоном.

## Когда задача сделана

1. `bootstrap/flang io packaging/install-parity.flang --на-веру` на настройке из
   четырёх установок печатает `ИТОГ | установок 4 | вызовов 60 | расхождений 0`
   и завершается кодом 0.
2. Работа CI на теге зовёт `install-parity:check` на обоих раннерах; её имя
   стоит в `docs/ci-inventory.md`, а не только в YAML.
3. Проба порчи: одна из установок подменена двоичным другого выпуска —
   прибор печатает `не тот двоичный: --version разошёлся` и уходит ненулевым
   кодом; вторая порча — у одной установки снят каталог `share/flang/js` —
   прибор называет вызов `emit … --target js` и расходится ровно на нём.
4. `flang check packaging/install-parity.flang` зелен, примеры у новых функций
   есть; длина добавленных строк не больше 120 знаков
   (`awk 'length > 120' packaging/install-parity.flang` молчит).
5. Если двоичные всех четырёх троек собраны одним семенем, строка «оболочка …»
   в `--version` совпадает на обеих платформах CI — прибор это печатает числом,
   а не словами.

## Где живёт правка

`packaging/install-parity.flang` (настройка на N установок, попарная сверка,
отдельный отказ на `--version`), `.flangrc` (команда `install-parity:check`),
`.github/workflows/install-path.yml` (работа на теге), `docs/ci-inventory.md`.
Перепечатка не нужна: прибор исполняется `flang io`, а не живёт в семени.
