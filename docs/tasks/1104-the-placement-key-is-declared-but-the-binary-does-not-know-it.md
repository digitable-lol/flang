# 1104. Ключ `--размещение` объявлен, а двоичный его не знает

Заявка: https://github.com/digitable-lol/flang/issues/104

## Шаги воспроизведения

1. Взять из дерева `flang/concurrency/examples/distributed.flang` и
   `flang/concurrency/examples/distributed.json`.
2. Прогнать `flang check` с ключом `--размещение`.
3. Посмотреть код возврата и справку `flang check --help`.

## Что происходит

```
$ flang check flang/concurrency/examples/distributed.flang \
      --размещение flang/concurrency/examples/distributed.json
flang check: непонятный ключ «--размещение»             код 2
$ flang check --help | grep -c 'размещ'
0
```

Версия: `flang 0.7.22`. Прогон 27 сентября 2026.

## Что должно быть

Двоичный выпуска понимает ключ, объявленный в исходнике того же выпуска.
`flang/self/cli.flang` объявляет ключ полями записи и описывает его действие —
свести программу с размещением процессов по узлам; страница «Процессы, надзор,
распределённость» подаёт размещение рабочим приёмом.

Причина шире одного ключа: процессов и распределённости двоичный не судит
вовсе, и `flang check --help` это говорит. Ключ опирается на слой, которого в
двоичном нет.

## Обходной путь

Нет. Свести программу с размещением двоичным нечем.

## Когда задача сделана

Одно из двух, и выбор записан решением:

1. двоичный сводит программу с размещением — прогон из шагов отвечает
   вердиктом, а не отказом разбора ключа; либо
2. ключ снят из `flang/self/cli.flang` и со страницы о процессах, пока слоя в
   двоичном нет.

Первый шаг, который делается сразу: на ключ двоичный отвечает «не
поддерживается: процессов двоичный не судит» и кодом 2 вместо «непонятный
ключ». Проба — в наборе `flang/proof/probes/run`.

## Где живёт правка

Отказ с названной причиной — `flang/src/emit/c/flang_repl.c`, доезжает быстрым
пересевом. Слой процессов в двоичном — самосборная часть и рантайм
`flang_conc.c`, это работа партии печати.
