# 1111. Оболочка возвращает необязательный токен с каждым ответом

Заявка: https://github.com/digitable-lol/flang/issues/111

## Шаги воспроизведения

1. Подать оболочке три выражения через конвейер, без терминала.
2. Подать выражение с токеном перед ним.

## Что происходит

```
$ printf '2 плюс 2\n"привет"\nдлина [1,2,3]\n.выход\n' | flang repl
4
"привет"
3
$ printf '17^ 2 плюс 2\n.выход\n' | flang repl
FLANG_LEX, строка 1, столбец 3: недопустимый символ '^'      код 1
```

Три ответа идут тремя строками без единой приметы: связать ответ с посланным
выражением нечем. Версия: `flang 0.7.22`. Прогон 27 сентября 2026.

## Что должно быть

Необязательный токен перед выражением, возвращаемый в ответе, — как в GDB/MI.
Человек его не пишет и вида не замечает.

```
» 17^ 2 плюс 2
17^ 4
» 18^ к числу "ой"
18^ FLANG_BUILTIN_ARGS: …
```

## Обходной путь

Программа дописывает за выражением строковый литерал и ждёт, когда оболочка
напечатает его обратно. Метка попадает в историю и в `.исходник`, а на
многострочном объявлении её нельзя послать, пока не закрыта пустая строка.

## Когда задача сделана

1. Строка вида `<цифры>^ <выражение>` вычисляется, и ответ начинается с того
   же `<цифры>^`.
2. Отказ несёт тот же токен.
3. Строка без токена ведёт себя знак в знак как сегодня.
4. Токен не попадает ни в историю, ни в `.исходник`.
5. У многострочного объявления токен стоит на первой строке и возвращается
   один раз, с ответом.

Проба — в наборе оболочки, по прогону на каждый пункт.

## Где живёт правка

`flang/src/emit/c/flang_repl.c`. Токен снимается со строки до лексера, поэтому
самосборную часть правка не трогает и доезжает быстрым пересевом.
