# 1113. Два импорта одного модуля с разными списками «только» молча теряют второй список

Заявка: https://github.com/digitable-lol/flang/issues/113

Список `только` того импорта, до которого обход дошёл ВТОРЫМ, отбрасывается;
побеждает список первого. Слово «молча» в заголовке точнее, чем кажется: беда
двуликая, и опаснее не та сторона, которая кричит.

* **Громкая сторона.** Отказ «неизвестная функция» об имени, которое стоит в
  списке соседнего файла, да ещё без имени файла — об этом он честно пишет сам:
  «место указано строкой и столбцом, но без файла».
* **Тихая сторона, и она хуже.** Если первым стоит импорт с ШИРОКИМ списком,
  модуль с узким списком получает имена, которые он из списка исключил. Файл,
  который сам по себе не проверяется, в такой связке проверяется — и запускается.
  Перестановка двух строк `использует` превращает «не проверено, код 1» в
  «проверено, замечаний нет, код 0».

## Шаги воспроизведения

Проба в дереве держит оба случая целиком:
`flang/proof/probes/import-list-order/programs/`. Короче всего она же словами —
пять файлов в одном каталоге:

```flang
модуль «Probe source»

тотальная функция «Первое слово»
  возвращает строка
  "раз"

тотальная функция «Второе слово»
  возвращает строка
  "два"
```

```flang
модуль «Narrow list»
  использует «Probe source» из "source.flang" только «Первое слово»

тотальная функция «Сверх списка»
  возвращает строка
  «Второе слово»
```

`wide.flang` ввозит тот же модуль со ОБОИМИ именами и зовёт «Первое слово».
Сверху два файла, различающиеся ТОЛЬКО порядком двух строк:

```flang
модуль «Wide import first»
  использует «Wide list» из "wide.flang"
  использует «Narrow list» из "narrow.flang"

тотальная функция «Проба»
  возвращает строка
  «Сверх списка»
```

`narrow-first.flang` — тот же файл с переставленными строками `использует`.

## Что происходит

```
$ bootstrap/flang check source.flang              код 0   замечаний нет
$ bootstrap/flang check wide.flang                код 0   замечаний нет
$ bootstrap/flang check narrow.flang              код 1
FLANG_UNKNOWN_NAME, строка 6, столбец 3: имя «Второе слово» не связано

$ bootstrap/flang check narrow-first.flang        код 1
FLANG_UNKNOWN_NAME, строка 6, столбец 3: имя «Второе слово» не связано

$ bootstrap/flang check wide-first.flang          код 0
wide-first.flang: проверено — разбор, типы, завершаемость, ядро и примеры;
  замечаний нет
```

`narrow.flang` сам по себе ОТКАЗАН: он зовёт имя вне своего списка `только`. В
`wide-first.flang` тот же `narrow.flang` принят — и это не формальность, вызов
действительно связывается:

```
$ bootstrap/flang run wide-first.flang --function «Проба»     код 0
доказано: утверждений 0
"два"
$ bootstrap/flang run narrow-first.flang --function «Проба»   код 3
не доказано … FLANG_UNKNOWN_NAME: имя «Второе слово» не связано
```

То есть `только` перестаёт быть ограничением: при одном порядке строк программа
не запускается вовсе, при другом — запускается и отдаёт `"два"`. Чем это опасно,
видно на этом же примере, а не из рассуждения: автор `narrow.flang` написал, что
берёт у соседа ОДНО имя, проверка на его файле это подтвердила отказом, а в
сборке сверху запрет снят и никем не назван.

Та же беда на библиотеке дерева (два модуля ввозят `flang/stdlib/strings.flang`
с разными списками) меняет ещё и числа ведомости: «функций 4, доказано 2» при
одном порядке и «функций 5, доказано 3» при другом — на тех же файлах.

Версия: flang 0.7.24 (`bootstrap/flang` из дерева).

## Что должно быть

Результат проверки не зависит от порядка строк `использует`. Либо списки
складываются и каждый модуль видит своё, либо отказ называет столкновение: какой
модуль ввезён дважды, из каких файлов и с какими списками. Чего быть не должно
ни при каком выборе — чтобы один из двух порядков СНИМАЛ отказ, который на том
же файле в одиночку стоит.

## Обходной путь

Ввозить модуль везде с одним и тем же списком `только` — объединением всех
нужных имён. Обходной путь закрывает громкую сторону и не закрывает тихую: он
требует помнить, что `только` сегодня ничего не гарантирует.

## Когда задача сделана

1. Проверка верхнего файла даёт ОДИН ответ при обеих перестановках строк
   `использует`: либо код 0 оба раза, либо отказ, называющий столкновение, оба
   раза.
2. `narrow.flang`, который в одиночку отказан, остаётся отказанным в любой
   связке: `wide-first.flang` не получает кода 0, а `run` на нём не отдаёт
   `"два"`.
3. Отказ при столкновении называет ФАЙЛ, а не только строку и столбец.
4. Проба `flang/proof/probes/import-list-order/` перемерена: её `expected.tsv`
   держит сегодняшнюю асимметрию (`wide-first` — 0, `narrow-first` — 1), и
   закрытие задачи обязано её покраснить.

   Чтобы зелёная таблица не читалась как контракт, первая строка `expected.tsv`
   несёт пометку «ЭТО ФОТОГРАФИЯ ДЕФЕКТА задачи 1113, А НЕ КОНТРАКТ» с датой
   замера. Место выбрано прогоном, а не вкусом: `../table.fscript` отбрасывает
   первую строку целиком, а отдельную строку-пометку считает данными. Набор
   пометку ПРИНУЖДАЕТ: без неё план отвечает «Не проверено» и кодом 3.

## Где живёт правка — и чего там, против ожидания, НЕ не хватает

`flang/self/link.flang` (1 202 строки). Важное: **сложение списков там уже
написано и работает** — `тотальная функция «Слить просьбы»` (строка 499) отдаёт
объединение имён, а `«Запомнить просьбу»` (490) её зовёт на каждом втором ввозе
того же файла. Объединение считается правильно и **никогда не применяется**.

Почему: область имён ввезённого файла замораживается на ПЕРВОМ заходе.
`«Пройти импорты»` (строка 583) берёт видимость как
`«Просьба к файлу» от («после».«просьбы») и «путь»` — то есть ту просьбу, что
накопилась к концу обхода этого файла, — и сливает файл в область имён. Второй
ввоз того же файла до `«Пройти импорты»` уже не доходит: `функция «Загрузить»`
(540) на пути из `«загружены»` возвращается сразу. Просьба к этому моменту
обновлена, а применять её некому.

Это проверено прямым прогоном, а не вычитано: файл, который сам ввозит
`source.flang` со списком из одного имени и РЯДОМ ввозит `wide.flang` со списком
из двух, получает код 1 на втором имени (`direct-narrow`) — объединение из двух
имён посчитано и не применено; те же две строки в обратном порядке дают код 0.

Значит правка — не «написать сложение», а «применить посчитанное»: либо
переслить область имён файла, когда его просьба выросла, либо собрать все
просьбы до обхода, одним проходом. Второй путь дешевле на вид и меняет порядок
обхода — то есть решение принимается, а не подразумевается.

Отказ о столкновении, если выбран он, называется словами из
`flang/self/failures.flang`. До двоичного правка доезжает пересборкой семени
(часы, `scripts/bootstrap-reprint.sh`).
