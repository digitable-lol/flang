# 1116. Команда test не исполняет блоки «прогон», и верное ожидание от ложного не отличить

Заявка: https://github.com/digitable-lol/flang/issues/116

Молчание о непроверенном снято 2 октября 2026: `flang test` называет блоки
числом и отвечает кодом 3, то есть программа с блоками `прогон` кодом 0 больше
не выходит. Исполнения блоков это не дало — остаётся оно.

## Шаги воспроизведения

1. Взять `flang/concurrency/examples/counter.flang`: два примера функций и два
   блока `прогон`, оба ждут у процесса «Счётчик» состояние 5.
2. В копии файла заменить в обоих блоках ожидаемое состояние на 999:

```
ожидается «Счётчик» равен (запись «Счёт» с «всего» равным 999)
```

3. Прогнать `flang test` на оригинале и на копии.

## Что происходит

```
$ flang test flang/concurrency/examples/counter.flang
…: примеров 2, прошло 2, не прошло 0
…: блоков «прогон» 2, исполнено 0 — исполнить их нечем                    код 3
$ flang test <копия с ожиданием 999>
…: примеров 2, прошло 2, не прошло 0
…: блоков «прогон» 2, исполнено 0 — исполнить их нечем                    код 3
```

Ответы одинаковы: блоки не исполняются, значит отличить верное ожидание от
ложного нечем. Планировщик объявлен в `flang/self/conc.flang`, и в замыкание
двоичного этот слой не втащен — поиск имени «Прогнать» в
`bootstrap/compiler_flang.c` даёт ноль вхождений.

Версия: flang 0.7.23. Дата прогона: 2 октября 2026.

## Что должно быть

`flang test` исполняет блоки `прогон`, сверяет `ожидается` и на ожидании 999
отвечает «не прошло» с ненулевым кодом, а на верном — «прошло» и кодом 0.
Обещано в `docs/flang/concurrency/SPEC.md`, раздел «Прогон — это пример»:
прогоны идут в тот же вывод `flang test`, что и примеры функций.

## Обходной путь

Обходного пути нет: прогоны исполняла реализация на JavaScript, которой в дереве
больше нет.

## Когда задача сделана

1. Копия с ожиданием 999 даёт «не прошло 2» и ненулевой код; оригинал — «прошло
   4» и код 0.
2. Проба `flang/proof/probes/runs-not-executed/` различает верное ожидание и
   ложное: сегодня у двух её строк один и тот же код и одно и то же слово, и это
   долг, названный числом.

Счёт и код возврата сделаны: `flang test` называет неисполненные блоки числом и
отвечает кодом 3 (ADR-0010). Проба в дереве держит три случая — верное ожидание,
ложное и, отрицательным контролем, программу без блоков, которая по-прежнему
выходит кодом 0 и молча.

## Где живёт правка

Исполнение блоков требует слоя процессов в двоичном (задача 1104): `conc.flang`
в замыкание `flang/self/bootstrap/compiler.flang` не втащен. Правка доезжает до
двоичного пересборкой семени (bootstrap regeneration).

Счёт и код возврата живут в `flang/src/emit/c/flang_repl.c` (`test_runs_of`,
`test_say_runs`) — и ждут той же перепечатки: `bootstrap/flang` собирается из
копии этого файла в семени. Поэтому проба собирает себе двоичный из дерева и
говорит о дереве, а не о семени: одна команда `cc` берёт оболочку из дерева, а
логику компилятора из семени, и два `-D` заменяют девять строк шапки, которые к
копии в семени приписывает печать:

```sh
cc -std=c99 -Wall -Wextra -Werror -pedantic -O0 \
   -DFL_PROGRAM_CALL=compiler_flang_call -DFL_PROGRAM_ENTRY=compiler_flang_entry \
   -Ibootstrap -o <каталог>/flang flang/src/emit/c/flang_repl.c bootstrap/flang_cli.c \
   bootstrap/flang_runtime.c bootstrap/compiler_flang.c -lm -lpthread
```

Замер 2 октября 2026 на машине отряда: сборка 1 мин 10 с, код 0,
предупреждений нет; весь план `Check` — 1 мин 12 с. Ключи те же, что у семени,
кроме `-flto` и `-O2`: сборка нужна рабочая, а не быстрая. Проба порчи в
`binary.yml` возвращает прежний код возврата, оставляя печатаемую строку на
месте, и даёт «разошлось 2 из 3», код 1 — то есть краснеет своим предметом, а
не сломанной сборкой.

Корпусный путь (`flang test <каталог>`, `--json`, `--ledger`) блоки не считает и
кодом 3 не отвечает: слова, машиночитаемый вид и код возврата свода решает
`flang/self/bootstrap/corpus.flang`, то есть та же перепечатка.
