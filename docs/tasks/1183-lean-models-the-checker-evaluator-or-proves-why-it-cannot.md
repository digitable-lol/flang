# 1183. Правило «Выч» проверяющей программы не входит в приёмку Lean, и довода о невозможности модели нет

## Шаги воспроизведения

1. Спросить дерево, что приёмка Lean говорит о правиле «Выч»:

```
grep -an 'Выч, Р2, Р3' flang/proof/lean/Acceptance.lean
```

2. Прогнать сверку независимой проверяющей программы (proof checker) с моделью
   Lean; нужен Lean версии из `flang/proof/lean/lean-toolchain`:

```
PATH=$HOME/.elan/bin:$PATH sh flang/proof/lean/run.sh
```

3. Смотреть строку «вне приёмки Lean»: какие правила в ней названы и сколько
   шагов за каждым.

## Что происходит

```
$ grep -an 'Выч, Р2, Р3' flang/proof/lean/Acceptance.lean
33:- Выч, Р2, Р3 — вычислитель половин (`половина_закрыта`): модель его не
                                                                 код 0
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026.

```
$ PATH=$HOME/.elan/bin:$PATH sh flang/proof/lean/run.sh
  перечень — строк 109, из них с леммой 109, без леммы 0
  ВНЕ ПРИЁМКИ Lean (первый непринятый шаг — правило, которого в Acceptance.lean нет):
    сверщик принял 58, отверг 31
    ПРАВИЛА: ВЫЧ 53, Р5 24, Р6 7, Н✗ 3, О9 1, О✗ 1
  сошлось всё                                                    код 0
```

Версия: flang не записана, Lean 4.34.0. Не перепроверено: прогон дольше минуты.

Лемма у строки «Выч» перечня правил есть, а в приёмке правила нет. «Выч»
закрывает замкнутую цель вычислителем `половина_закрыта` в
`flang/proof/checker/checker.c` — это второй вычислитель языка внутри
проверяющей программы. Модель его не повторяет, а правила Р2 и Р3 берут
посылками только шаги «Выч» и без него не судятся.

## Что должно быть

ADR-0041 обещает, что проверяющая программа доказана состоятельной против
механизированной семантики. Для «Выч» это значит одно из двух:

- вычислитель половин заведён в модели, у него есть лемма состоятельности, и
  приёмка принимает шаги «Выч», а за ними Р2 и Р3;
- либо принят ADR о том, что модель взять вычислитель не может, с числом:
  сколько строк Lean потребовалось бы и почему это не делается.

## Обходной путь

Обходного пути нет: шаги «Выч» сверяются только самой проверяющей программой.

## Когда задача сделана

Сначала замер: сколько правил и мест опираются на «Выч» и сколько строк Lean
стоит модель по образцу лемм «Выч-звено» и «Выч-вариант» из
`flang/proof/lean/Rules.lean`.

Затем один из двух исходов. Первый: `sh flang/proof/lean/run.sh` отвечает
кодом 0, в строке правил вне приёмки «Выч» нет, испорченные правила на «Выч»
из `flang/proof/lean/Trap.lean` отвергнуты. Второй: в `docs/adr` лежит принятый
ADR с числом строк и доводом, а абзац о «Выч» в файле приёмки ссылается на
него.

Проба, которая краснеет: тот же прогон — расхождение вердиктов проверяющей
программы и модели роняет его кодом 1.

## Где живёт правка

`flang/proof/lean/Model.lean` и `flang/proof/lean/Rules.lean` — модель
вычислителя и лемма; `flang/proof/lean/Acceptance.lean` — приём правила и
абзац «Чего нет и почему»; `flang/proof/lean/Trap.lean` — испорченные правила.
Либо новый файл в `docs/adr`. Двоичное не меняется, пересборка семени
(bootstrap regeneration) не нужна.
