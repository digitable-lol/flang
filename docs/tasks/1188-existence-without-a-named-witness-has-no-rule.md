# 1188. Существование без названного свидетеля правила не имеет: без «а именно» — отказ разбора, а с негодным свидетелем — «объявлено, не доказано» и код 0 у check

Квантор существования в языке есть: слова `есть такой`/`there is` и
`а именно`/`namely` стоят в словаре (`flang/self/lexer.flang`), разбор —
`«Разобрать существование»` (`flang/self/parser.flang`), набор проверяющего
— `flang/proof/checker/tests/families/existence/`.

Чего нет — это ПРАВИЛА ПРЕДЪЯВЛЕНИЯ. Свидетеля обязан назвать автор словом
`а именно`; построить его ядро не умеет. Отсюда две беды разной породы:

1. без `а именно` — отказ РАЗБОРА, то есть сказать «найдётся такой м» нельзя
   вовсе, даже когда он очевидно найдётся;
2. с НЕГОДНЫМ свидетелем (`а именно 0` там, где нужен `н`) `check` отвечает
   кодом 0 и словами «замечаний нет»; «объявлено, не доказано» видно только у
   `check --proof` и у `run`.

Версия: flang 0.7.24.

## Шаги воспроизведения

1. Со свидетелем (подлинник):
   `обеспечивает «удвоенное есть сумма» есть такой м, а именно н, что результат равен (м плюс м)`
   при теле `н плюс н`. `bootstrap/flang check <проба>; echo $?` и то же
   с `--proof`.
2. Без свидетеля: та же строка без `, а именно н`. То же.
3. С негодным свидетелем: `а именно 0` вместо `а именно н`. То же, плюс
   `bootstrap/flang run <проба> --function «Удвоить»; echo $?`
4. То же свободным утверждением:
   `утверждаем есть такой м, а именно н, что («Удвоить» от н) равен (м плюс м)`.
5. Набор проверяющего:
   `cat flang/proof/checker/tests/families/existence/f10b-existence-by-expression.flang`
   — в нём стоит ещё и запись `существует м такое что`, которой двоичный не
   знает (это файл набора, не программа дерева).

## Что происходит

| конструкция | команда | код | первая строка ответа |
| --- | --- | ---: | --- |
| `есть такой м, а именно н, что …` | `check` | 0 | `модуль …: функций 1, из них с доказанным завершением 1; типов 0` |
| то же | `check --proof` | 0 | ведомость: `постусловие «удвоенное есть сумма» … доказано сведением цели с телом функции: правило «тождество после переписки допущением»` |
| `есть такой м, что …` (без `а именно`) | `check` | **1** | `FLANG_PARSE … столбец 53: ожидалось «есть такой м, а именно <терм>, что …»` |
| то же | `check --proof` | 1 | то же |
| `а именно 0` (негодный свидетель) | `check` | **0** | `… проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет` |
| то же | `check --proof` | **3** | ведомость: `объявлено, не доказано: ни теоремы, ни примеров` |
| то же | `run --function «Удвоить»` | 3 | `не доказано: утверждений 1: доказано 0, сетка 0, на веру 1 — запуск только по явному согласию: --trust` |
| `есть такой` свободным утверждением | `check` | 0 | `… функций 1 …`; ведомость: `доказано 1` |

Третья строка — главная: **`flang check` без `--proof` на негодном свидетеле
отвечает «замечаний нет» кодом 0.** Приговор «объявлено, не доказано» живёт
только в ведомости. Тот же разрыв мы сняли и на заведомо ложном свободном
утверждении (`утверждаем («Счёт» от л) больше 0` при `Счёт` пустого списка = 0):
`check` — код 0 «замечаний нет», `check --proof` — код 3, `run` — код 3 и имя
утверждения.

В `flang/proof/checker/checker.c` (10 497 строк): `exists` — **0** вхождений,

**Порядок величин.** Разбор и запись свидетеля — 22 + 29 + 2 + 4 = **57** мест

`parser.flang`. Сколько из этих мест придётся тронуть, зависит от того, какую
логику предъявления выбрать, — и этого мы не оценили (ниже).

  ловушка стоит на ∀-целях постусловий; ∃-цель, доказываемая правилом, её не
  покрыта, и достраивать придётся вместе.

## Что должно быть

1. **Решено, какая логика предъявления заводится** — и это ОТДЕЛЬНОЕ решение,
   ADR-0026 (раздел 5, шаг 3) требовал именно его и правильно требовал. Варианты
   не равноценны: свидетель из тела функции по сведению; свидетель поиском по
   сетке (тогда это «посчитано», не «доказано»); свидетель из конструктора
   объявленного типа.
2. `есть такой м, что …` без `а именно` разбирается и либо доказывается
   выбранным правилом, либо отказывается ПО СУЩЕСТВУ («свидетеля построить
   нечем: правила такого-то вида у ядра нет»), а не отказом разбора.
3. Негодный свидетель называется негодным: `check` отвечает не «замечаний нет».
   Либо приговор ведомости поднимается в `check` для ∃-целей, либо `check`
   честно говорит, что про ∃ он не судит, — но «замечаний нет» на негодном
   свидетеле говорить нельзя.

## Обходной путь

Назвать свидетеля руками через `а именно`: так работает уже сегодня и
доказывается правилом «тождество после переписки допущением». Там, где
свидетеля не выписать, — переписать условие без ∃ (через конструктор или через
постусловие о функции, которая его возвращает).

## Когда задача сделана

1. Проба `есть такой м, что результат равен (м плюс м)` без `а именно` даёт
   либо код 0 с названным правилом в ведомости, либо отказ, который называет
   правило, которого нет. Отказ разбора — не годится.
2. Негодный свидетель (`а именно 0`): `check` отвечает кодом, отличным от 0 на
   подлиннике. Отрицательный контроль обязателен — подлинник (`а именно н`)
   обязан остаться кодом 0.
3. Набор `families/existence` переснят, и в `corrupt/` есть подделка:
   запись, где свидетель подменён.
4. Ловушка `scripts/provability.fscript` достроена ∃-целью; прогон печатает
   «проверка 1 — калькулятор снят? ДА».
5. ADR-0026, раздел 2.3, помечен отставшим — ссылкой на
   `docs/adr/0056-the-quantifier-and-law-measurements-of-two-decisions-are-stale.md`.

## Чего мы не смогли оценить

- **Цену работы в строках — не оценили и не можем.** Логика предъявления не
  выбрана; до выбора считать нечего. ADR-0026, раздел 5, шаг 3, говорил то же
  («отдельная логика, оценки нет») и остаётся прав — этим замером он НЕ
  опровергнут, в отличие от шагов 1 и 2.
- **Можно ли свидетеля построить сведением с телом.** Подлинник доказывается
  правилом «тождество после переписки допущением» — то есть тело функции в
  сведении участвует. Хватит ли этого без `а именно`, мы не проверяли: пробы с
  телом, из которого свидетель читается однозначно, не ставили.
- **Правда ли «замечаний нет» у `check` — умысел, а не беда.** Разрыв между
  `check` и `check --proof` одинаков у ∃ и у заведомо ложного свободного
  утверждения, то есть это общее правило команды, а не свойство квантора. Где
  оно решено и решено ли, мы не искали.
- **Запись `существует м такое что`** лежит в наборе проверяющего
  (`f10b-existence-by-expression.flang`), а двоичный её не знает. Чья это
  запись — проверяющего, отставшая или будущая — не выясняли.
- **Высший порядок** (квантор над функциями) не трогали вовсе. ADR-0037 назвал
  второй порядок конечной конъюнкцией по тегам функций, и
  `families/all-elements/through-second-order.flang` в наборе есть; работает ли
  это на свободном утверждении — не мерено.
