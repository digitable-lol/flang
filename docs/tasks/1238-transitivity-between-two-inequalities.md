# 1238. Граница длины, прошедшая через два вызова с неравенством, остаётся недоказанной

## Шаги воспроизведения

1. Программа:

```flang
модуль «Середина между двумя границами»

тотальная функция «кусок»
  принимает х: список число
  возвращает список число
  обеспечивает «кусок не длиннее» (длина результат) не больше (длина х)
  пример «пустой»
    дано х равно []
    ожидается []
  разбор х
    случай пусто
      []
    случай голова первая и хвост прочие
      прочие

тотальная функция «Два вызова»
  принимает х: список число
  возвращает список число
  обеспечивает «не длиннее входа» (длина результат) не больше (длина х)
  пример «пустой»
    дано х равно []
    ожидается []
  пусть срез равно «кусок» от х
  «кусок» от срез
```

2. Команда: `bootstrap/flang check <файл> --proof`.
3. Смотреть вердикт постусловия «не длиннее входа». Полная приёмка с
   честными целями и подделками — `flang/proof/forgeries/transitivity.flang`.

## Что происходит

```
$ bootstrap/flang check <файл> --proof
  постусловие «кусок не длиннее» функции «кусок» — доказано … правило «порядок по построению»
  постусловие «не длиннее входа» функции «Два вызова» — сетка 1 значение (примеры функции) … Это не доказательство
  утверждений 2: доказано 1 (из них без теоремы 1), сетка 1, объявлено, не доказано 0
                                                                 код 0
$ bootstrap/flang check flang/proof/forgeries/transitivity.flang --proof
  утверждений 10: доказано 5 (из них без теоремы 5), сетка 5, объявлено, не доказано 0
                                                                 код 0
```

Версия: flang 0.7.23. Дата прогона: 2 октября 2026.

В приёмке «Ч1 два вызова» и «Ч2 три вызова» стоят на сетке. Цепочку
«равенство, затем граница» (Ч3) ядро берёт подстановкой; не берёт оно цепочку,
где оба звена — неравенства. Правило для неё в исходнике есть и в двоичное
собрано: «Есть порядок через середину» стоит последним в «По порядку». Почему
на этих целях оно не срабатывает, не выяснено: либо до него не доходит разбор
правил, либо граница первого вызова не попадает в список порядков в том виде,
в каком её сличает «Есть известное».

## Что должно быть

Из `А не больше Б` и `Б не больше В` среди допущений ядро выводит `А не больше
В`, когда все три величины лежат в области с полным порядком (длина списка,
величина с известной целостью). На типе `число` вывод ложен из-за «не числа»,
и правило его не делает. Это обещает сама приёмка: Ч1 и Ч2 обязаны стать
доказанными, подделки Д1, Д2, Д3 — остаться недоказанными.

## Обходной путь

Написать при постусловии теорему либо свести цепочку к равенству: помощник с
постусловием «той же длины» ядро подставляет само.

## Когда задача сделана

```
$ bootstrap/flang check flang/proof/forgeries/transitivity.flang --proof
  утверждений 10: доказано 7 …, сетка 3 …                        код 0
```

Ч1 и Ч2 — «доказано»; «кусок», «точный», К1, К2, Ч3 остались «доказано»; Д1,
Д2, Д3 остались на сетке. Этот файл и есть проба: он краснеет и когда ход
пропадёт, и когда правило возьмёт подделку. Причина сегодняшнего отказа названа
в описании правки.

## Где живёт правка

`flang/self/proof-kernel.flang`: «По порядку», «Есть порядок через середину»,
«Замыкание середин», «Прибавить середину», «Величина полного порядка» и сбор
порядков из постусловий вызванных функций. Спросить ядро по исходникам, минуя
двоичное, можно пробами `flang/proof/midpoint-verdicts.flang` и
`flang/proof/midpoint-price.flang`; цена перебора середины разобрана в
`docs/zettel/the-price-of-the-midpoint-search-is-linear-in-the-order-facts.md`.
До двоичного правка доезжает только пересборкой семени (bootstrap
regeneration).
