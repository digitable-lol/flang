# 1277. Два тяжёлых сторожа не дают вердикта, и записанному о них верить нечем

`counts:check` (`node flang/scripts/count-guard.mjs`) и `numbers:check`
(`node docs/site/site-numbers.mjs --check`) не зовутся **ни одной** работой CI и
отсутствуют в `pre-push`. Оба объявлены незваными в
`scripts/ledgers/uncalled-guards.json` с причиной — и на этом всё: сторож
`guard-calls:check` сверяет только **наличие** записи и непустоту причины, а
правдивость причины не проверяет никто. Запись может сгнить молча. Это та же
порода, что в задаче 4390: текст сторожится на присутствие, а не на правду.

## Шаги воспроизведения

1. Кто их зовёт:

   ```
   grep -rn 'counts:check\|numbers:check' .github/workflows/ .githooks/
   ```

2. Что о них записано в ведомости незваных:

   ```
   python3 -c "import json;d=json.load(open('scripts/ledgers/uncalled-guards.json'));print(d['counts:check']);print(d['numbers:check'])"
   ```

3. Что проверяет сторож ведомости — читать его собственные подлоги:

   ```
   grep -n 'НОВЫЙ НЕЗВАНЫЙ\|ЗАПИСЬ СТАЛА НЕПРАВДОЙ\|причина в ведомости не названа' \
     scripts/guards/who-calls-the-guards.fscript
   ```

4. Попробовать получить вердикт самому — и посмотреть, что останется в системе
   после отмены:

   ```
   timeout 420 node flang/scripts/count-guard.mjs; echo "код $?"
   pgrep -f 'flang-5825' | wc -l
   ```

## Что происходит

**Зова нет.** В `.github/workflows` `numbers:check` стоит только в примечаниях,
`counts:check` не упомянут вовсе; в `pre-push` нет обоих. Запись в ведомости у
каждого есть, и `guard-calls:check` на это зелен — он и не мог быть другим.

**Записанное о них — от 6 сентября 2026**, и перемерить его нечем:

```
counts:check  — «КРАСЕН по делу и ОЧЕНЬ ДОРОГ: код 1 за 6884 с … Сходится.»
numbers:check — «КРАСЕН по делу и ОЧЕНЬ ДОРОГ: код 1 за 6864 с … Сходится.»
```

Ведомость в целом: записей **28**, дату называют **17**, не называют **11**;
последний перемер у **14** — 6 сентября 2026, то есть 26 дней назад. «Сходится»
обещают всего **3** записи из 28 (`emit-law:check` и эти две).

**Свой замер, 2 октября 2026, дерево `ed982e1bc`, двоичный 0.7.23.**

| прогон | что вышло |
|---|---|
| `counts:check`, предел 420 с | код 124. Это **не** опровергает запись: записанная цена 6884 с больше предела в 16 раз |
| `counts:check` в worktree без собранного двоичного | код 1, падение в `flang/scripts/binary.mjs:890 сводКорпуса` — ему нужен двоичный рядом, а ведомость этого условия не называет |
| `numbers:check` | падение с разбором исключения Node в своём же тяжёлом подпрогоне (`flang/scripts/proof-ledger.fscript … --max-orders 100000 --на-веру`) — то есть по среде, а не по дереву |
| `numbers:check`, второй заход с полным захватом вывода | 12 минут без единой строки, снят |

**И самое дорогое: отмена прогона не останавливает обход.** После этих попыток в
системе остались живыми **65** процессов моего дерева, старшему **3 ч 54 мин**,
среди них дети уже удалённого worktree. Они держали **254,5 ГиБ** общей машины
на 499 ГиБ:

```
$ for p in $(pgrep -f 'flang-5825'); do ps -o rss= -p $p; done | awk '{s+=$1} END {print s/1048576}'
254.5
```

Сняты поимённо по номеру процесса; после уборки — 0 ГиБ. Снять обёртку
недостаточно: `count-guard.mjs` и `site-numbers.mjs` зовут
`flang io proof-ledger.fscript`, тот раскладывает обход корпуса по `xargs -P`, и
дети переживают смерть родителя.

## Что должно быть

Сторож либо даёт вердикт, либо честно объявлен негодным для этой машины — но не
висит между.

## Обходной путь

Числа, которые они считают, сверяются руками. Задача 0044 прямо опирается на
«`numbers:check` отвечает кодом 0 и краснеет» — на сегодня это не проверено.

## Когда задача сделана

Для **каждого** из двух — один из двух концов, и оба проверяются прибором, а не
чтением.

Конец первый, «сторож работает»:

1. в ведомости (или в самом сторожа) названы его пределы: память, стенное время,
   нужен ли собранный двоичный рядом;
2. он зовётся откуда-то — из работы CI или из `pre-push`, — и это видно
   `grep -rn '<имя>' .github/workflows/ .githooks/`;
3. прогон **даёт вердикт**: приведены команда, её последняя строка и код
   возврата, и код не 124 и не падение;
4. отмена не оставляет хвоста: после снятия прогона `pgrep -f '<корень дерева>'`
   пуст.

Конец второй, «не для этой машины»: запись в ведомости называет причину, **дату**
и прибор, которым причина снята, и `guard-calls:check` (или новая проверка рядом)
краснеет, когда запись старше дерева, которое описывает. Проба порчи: стереть
дату у записи — проверка обязана покраснеть и назвать имя сторожа.

Сегодня краснеть нечему: 11 записей из 28 дату не называют вовсе, и ведомость на
это зелена.

## Где живёт правка

`scripts/ledgers/uncalled-guards.json` (записи обоих), `.flangrc` (строки
`script.counts:check` и `script.numbers:check`), `scripts/guards/who-calls-the-guards.fscript`
(если проверять дату и прибор), `flang/scripts/count-guard.mjs` и
`docs/site/site-numbers.mjs` (объявить пределы и убирать за собой детей при
снятии). Двоичного правка не касается, перепечатка семени не нужна.
