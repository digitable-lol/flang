# 1307. Разбор остаётся в доверенной базе: дерево, напечатанное обратно в текст, не совпадает с исходником ни у одного файла

## Шаги воспроизведения

1. Замер лежит в дереве: `flang/proof/binding/parse-cycle.fscript`. Он читает
   исходник, зовёт `flang ast <файл> --pretty`, собирает из узлов дерева текст
   обратно и сличает построчно.
2. Команда, выборка из каждого пятнадцатого файла корпуса, около 50 секунд:

```
bootstrap/flang io flang/proof/binding/parse-cycle.fscript \
  --plan 'Кругооборот разбора на выборке' --на-веру \
  --max-steps 4000000000000 --max-orders 100000
```

3. Смотреть строки «слинковано, числа нет» и «файлов ЦЕЛИКОМ знак в знак».
   Весь корпус — план «Кругооборот разбора», около 22 минут.

## Что происходит

```
$ bootstrap/flang io flang/proof/binding/parse-cycle.fscript --plan 'Кругооборот разбора на выборке' …
  файлов в корпусе        346
  взято в прогон          23
  слинковано, числа нет   7
  не разобралось          0
  измерено файлов         16
  строк кода            909, сошлось 199
  строк пустых          77, сошлось 77
  строк комментария     194, сошлось 0
  знаков                46821, сошлось 6079
  файлов ЦЕЛИКОМ знак в знак   0 из 16
  ПЕРВОЕ РАСХОЖДЕНИЕ
        docs/examples/guide/chain-of-steps.flang, строка 4
        было:    вариант «Есть» содержит значение: число
        стало:   вариант «Есть»                                  код 0
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026.

Причин три. Дерево не несёт того, что нужно для печати знак в знак: написания
слова языка (слова пишутся на четырёх языках), кавычек имени, скобок,
комментариев; часть строк не имеет ни одного узла с местом. `flang ast`
печатает программу уже связанной, и узел не помнит, из какого файла он
пришёл, поэтому файл с «использует» не меряется вовсе — а таковы все файлы
`flang/self`. И печать, и разбор живут в одном двоичном: их общую ошибку
сличение не ловит.

## Что должно быть

Текст, напечатанный из дерева разбора, совпадает с исходником знак в знак на
всём корпусе, включая файлы компилятора, а печатает его программа, написанная
отдельно от разборщика (ADR-0030). Тогда разборщик проверяется сличением и из
доверенной базы выходит; в ней остаются печатник и сличитель, которые много
меньше.

## Обходной путь

Обходного пути нет: разбору верят на слово. Лексер отдельно меряет
`flang/proof/binding/cycle.py` (сборка текста из токенов).

## Когда задача сделана

- План «Кругооборот разбора» отвечает «слинковано, числа нет 0» и «файлов
  ЦЕЛИКОМ знак в знак N из N» на всём корпусе.
- Испорченный разбор (перепутаны две операции в одном правиле) даёт ненулевой
  код и первое расхождение с файлом и строкой.
- Замер стоит ярлыком в `ярлыки.flang`, и в `docs/tasks` у задачи 9790 строка
  разбора в доверенной базе пересчитана.

## Где живёт правка

`flang/self/parser.flang` и `flang/self/lexer.flang` — узел несёт написание,
кавычки, скобки и комментарии (в записи «Токен» поле «текст» сегодня
заполняется только у чисел и ключевых слов); `flang/self/link.flang` — узел помнит файл происхождения;
`flang/proof/binding/parse-cycle.fscript` — печать и сличение. Правки под
`flang/self` доезжают до двоичного только пересборкой семени (bootstrap
regeneration); замер читается двоичным с диска.

Отдельная задача, здесь не решается: таблица причин расхождений поимённо
(скобки, кавычки имени, написание слова) вместо одного первого расхождения.
