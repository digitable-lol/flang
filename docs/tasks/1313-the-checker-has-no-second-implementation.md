# 1313. У независимой проверяющей программы нет второй реализации, написанной врозь на другом языке

## Шаги воспроизведения

1. Перечислить программы дерева, которые читают запись доказательства:

```
git ls-files flang/proof | grep -a 'checker\.[a-z]*$\|Reader'
```

2. Смотреть, сколько среди них реализаций, не разделяющих ни языка, ни
   средства сборки.

## Что происходит

```
$ git ls-files flang/proof | grep -a 'checker\.[a-z]*$\|Reader'
flang/proof/checker.flang
flang/proof/checker/checker.c
flang/proof/lean/RecordReader.lean                                код 0
```

Независимая проверяющая программа (proof checker) одна —
`flang/proof/checker/checker.c`, её собирает один вызов `cc`. Две другие
второй реализацией не считаются:

- `flang/proof/checker.flang` написан на flang и собирается тем самым
  компилятором, чьи доказательства проверяются;
- `flang/proof/lean/RecordReader.lean` читает только блоки «вывод» и сличает
  вердикт по ним; остальную запись он не проверяет, а сам читатель стоит вне
  доказанной теоремы.

Пробы в `flang/proof/checker/tests` написаны вместе с этой программой. Если
программа читает какую-то строку записи не так, как требует описание формата,
и пробы этого места не касаются, расхождение не увидит никто.

## Что должно быть

Две реализации, написанные врозь по одному описанию формата записи
(`flang/proof/lean/Record.lean`, `docs/flang/proof/SPEC.md`), согласны на всём
наборе проб. Вторая не разделяет с первой ни языка (не C и не flang), ни
средства сборки и не заимствует её код.

## Обходной путь

Обходного пути нет. Частичная замена — сличение вердиктов C и Lean по блокам
«вывод» в `flang/proof/lean/run.fscript`.

## Когда задача сделана

- вторая реализация лежит в дереве рядом с `flang/proof/checker` и собирается
  одной командой без `bootstrap/flang`;
- один скрипт прогоняет обе реализации по всем записям из
  `flang/proof/checker/tests` и `flang/proof/forgeries` и печатает число
  сличённых записей и число расхождений; расхождений 0, код 0;
- тот же скрипт отвечает кодом 1 и называет запись, если вердикты разошлись:
  это показано пробой, в которой одной из реализаций подана нарочно
  испорченная запись;
- скрипт вызывается из CI.

## Где живёт правка

Новый каталог рядом с `flang/proof/checker`, скрипт сличения рядом с
`flang/proof/check.fscript`, вызов в `.github/workflows`. Пересборка семени
(bootstrap regeneration) не нужна.

Потолок размера `flang/proof/checker/checker.c` уже стоит, но зовётся только руками:
`bootstrap/flang io flang/proof/tables-guard.fscript --max-steps 4000000000 -- --guard С-6`
отвечает кодом 0 и «checker.c: 8127 строк кода, до потолка 0 (потолок 8127); примитивов 15
(названо 15)»; сами числа лежат в `flang/proof/ratchets.txt` (`checker-code-lines`,
`checker-primitives`). Ни `.flangrc`, ни работы в `.github/workflows`, ни хуки этого сторожа не
зовут, и опись сторожей без зова его не числит. Описание формата записи вынесено в
`flang/proof/lean/Record.lean`. В этой задаче их править не нужно.

## Следующий шаг

Ревизия 11 октября 2026 (ADR-0096): вторая реализация лежит в
`flang/proof/checker/second/`, собирается `make -C flang/proof/checker second`, план
`flang/proof/second-checker.fscript` сличает обе на всём корпусе и зовётся из CI
(`lean-crosscheck.yml` по расписанию и работа `second-checker` в `binary.yml` на каждом
пуше). Критерий «расхождений 0, код 0» на `dev` не выполнен:
`bootstrap/flang run-script checker:second` (двоичные с дерева `77cdc709b`, корпус с
`8897f2350`) — записей 686, без исходника 52, сличено 634, расхождений 7. Все семь — на
записях правил, которые `checker.c` получил 11 октября (`425b8a103` … `77cdc709b`: разбор
цели по условию, переписка доказанными равенствами, свидетель ядра), а
`second/*.lean` не менялся. Испорченная копия честной записи, поданная обеим
(`checker:second-both`), отвергнута обеими кодом 1.

Что делать дальше, по описанию формата `docs/flang/proof/record-format.md`, а не по
`checker.c`:

1. Второй сверщик проигрывает узел «разбор цели по условию» и снимает место со слова ядра
   — три записи `0/3` (`case-split-facts/linked-facts`,
   `totality-postcondition-over-several-lines`, `user-program/callee-argument`).
2. Второй сверщик знает строки записи о роде правила переписки (Переп1, ADR-0084) и о
   свидетеле, найденном ядром, — четыре записи `0/1` и `3/1` в `families/rewrite` и
   `families/existence`; до того на незнакомую строку он обязан отвечать кодом 4 «НЕ ВЗЯЛСЯ
   ЦЕЛИКОМ», а не кодом 1.
3. Пока не исправлена `flang/proof/lean/Rules.lean:3081` (`«равен-на-не-числе»`, коммит
   `fb7553c77`), Lean на `dev` не собирается, и сличение гоняется только на `77cdc709b`.

Записи без исходника (52) указывают во временные клоны фальсификатора и не сличаются ни
одной реализацией. Ключей `--набор` и `--зависимость` у второй нет, поэтому пробы
`flang/proof/checker/tests/probes.tsv`, которые их подают, сличаются только первой.
