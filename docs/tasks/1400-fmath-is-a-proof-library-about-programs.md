# 1400. Библиотеки доказательств о программах «fmath» в дереве нет

## Шаги воспроизведения

1. Кода библиотеки нет, есть только решение и проектная записка:

```
git ls-files | grep -i fmath
```

2. Первое утверждение из записки, файл из пяти строк:

```flang
модуль «Длина списка»

утверждение «длина любого списка неотрицательна»
  для всех л: список числа
  утверждаем (длина л) не меньше 0
```

3. Доказать, записать доказательство и отдать запись независимой проверяющей
   программе (proof checker):

```
bootstrap/flang check <файл> --proof --record <запись>
make -C flang/proof/checker
flang/proof/checker/сверщик <файл> <запись>
```

## Что происходит

```
$ git ls-files | grep -i fmath
docs/adr/0028-fmath-is-a-proof-library-for-programs-not-a-mathlib.md
docs/design/fmath-first-ten-statements.md
docs/tasks/1400-fmath-is-a-proof-library-about-programs.md
$ bootstrap/flang check <файл> --proof --record <запись>
… ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 1: доказано 1, …         код 0
$ flang/proof/checker/сверщик <файл> <запись>
НЕ ВЗЯЛСЯ (строк причин 1; мест на слово ядра 1): утверждение «длина любого
списка неотрицательна»: значение «по объявлению нет» — сверщик не повторяет
изъятие объявленного типа, место на слове ядра
НЕ ПРОВЕРЕНО — запись не противоречит исходнику, но доказательством это не
является: утверждений 1, … ходов проверено 0 …                     код 3
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026.

Компилятор закрывает цель правилом «неотрицательность по построению» и
печатает в запись только вердикт и имя правила, без шагов вывода. Проверяющей
программе переигрывать нечего, и утверждение остаётся принятым на слово
компилятора. Пока это так, каждое утверждение библиотеки увеличивает число
мест в записях и не увеличивает число проверенных мест.

## Что должно быть

ADR-0028 (`docs/adr/0028-fmath-is-a-proof-library-for-programs-not-a-mathlib.md`):
библиотека утверждений о программах — целые в пределах представления
[0, 2⁵³−1], границы, инварианты свёрток, свойства списков. Каждое утверждение
едет в записи выводом (ADR-0022) и переигрывается проверяющей программой;
ничего не принимается на слово. Первые десять утверждений и то, что поручено
Lean, перечислены в `docs/design/fmath-first-ten-statements.md`.

ADR-0028 запрещает: импортировать mathlib (его `Nat` без верхней границы),
встраивать ядро Lean в проверяющую программу, принимать теоремы как данность.
Каталог или отдельный репозиторий — решается после первых десяти утверждений.

## Обходной путь

Нужный факт записывают утверждением или постусловием в том же файле, где он
нужен, и доказывают на месте. Сослаться на утверждение по имени можно только
внутри одного файла (ADR-0048).

## Когда задача сделана

Первое утверждение библиотеки лежит в дереве, и на нём:

```
bootstrap/flang check <файл библиотеки> --proof --record <запись>   код 0
flang/proof/checker/сверщик <файл библиотеки> <запись>              ПРОВЕРЕНО, код 0
```

Запись этого файла добавлена в набор записей проверяющей программы
(`flang/proof/checker/tests/records`), поэтому её прогон краснеет, если
утверждение снова уйдёт на слово компилятора.

## Где живёт правка

Сначала две открытые задачи, без них библиотека не засчитывается:

- задача 2748 — проверяющая программа не переигрывает утверждение, у которого
  в записи стоит только имя правила (`flang/proof/checker/checker.c`, печать
  шагов в `flang/self/zapis.flang` и `flang/self/proof-kernel.flang`);
- задача 5583 — ссылка на утверждение, доказанное в другом файле.

Затем сами утверждения — новые файлы на flang; они читаются двоичным с диска.
Правки под `flang/self/` доезжают до двоичного только пересборкой семени
(bootstrap regeneration); проверяющая программа собирается отдельно, своим
`flang/proof/checker/Makefile`.
