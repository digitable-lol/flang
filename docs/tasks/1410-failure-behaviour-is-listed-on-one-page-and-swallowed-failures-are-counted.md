# 1410. Нет страницы о поведении при отказе и нет счёта обработчиков, проглатывающих «Сбой»

## Шаги воспроизведения

1. Скопировать `docs/examples/io/temp-directory.flang` и в копии убрать из
   функции «После записи» две строки:

```flang
    случай вариант «Сбой» с код как код и сообщение как сообщение
      то вариант «Провал» с код равным код и сообщение равным сообщение
```

   Ветвь `случай любое` остаётся: сбой записи теперь превращается в
   `FLANG_IO_ORDER` «ждали записи».
2. `bootstrap/flang check <копия>` — смотреть код возврата.
3. Поискать страницу описания и сверить число видов отказа процесса:

```
grep -arli "само железо" docs --include='*.md' --exclude-dir=tasks
grep -an "Видов сейчас" docs/flang/concurrency/SPEC.md
grep -an "Девять видов" flang/self/failures.flang
grep -ac "^тотальная функция «Вид " flang/self/failures.flang
```

## Что происходит

```
$ bootstrap/flang check <копия>
модуль «Temp directory»: функций 10, из них с доказанным завершением 10; типов 4
<копия>: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
                                                                  код 0
$ grep -arli "само железо" docs --include='*.md' --exclude-dir=tasks
docs/adr/0034-hardware-failure-is-described-not-proved.md        код 0
$ grep -an "Видов сейчас" docs/flang/concurrency/SPEC.md
328:Четыре — счёт на день, когда этот абзац был написан. Видов сейчас **семь**, и
$ grep -an "Девять видов" flang/self/failures.flang
69:// Девять видов, и порядок этого списка — порядок, в котором они попадают в
$ grep -ac "^тотальная функция «Вид " flang/self/failures.flang
11
```

Версия: flang 0.7.23. Дата прогона: 2 октября 2026.

Проглоченный сбой не замечает ни проверка типов (разбор полон благодаря
`случай любое`), ни ядро; ловит его только пример, если он у функции есть.
Команды, которая считает такие обработчики по дереву, нет. Страницы с четырьмя
слоями отказа нет — слои описаны только в самом ADR-0034. Число видов отказа
процесса в трёх местах разное: `docs/flang/concurrency/SPEC.md` называет семь,
шапка `flang/self/failures.flang` — девять, функций «Вид …» там одиннадцать.

## Что должно быть

ADR-0034 §5 и §8 обещают три вещи:

1. Одна страница в `docs/` с четырьмя слоями из ADR-0034 §2 (ввод-вывод; память
   и стек; процесс и узел; само железо). У каждого пункта — место в коде и
   слово, чем он держится: «проверкой типов», «примером», «по построению» или
   «ничем» (у слоя «само железо» — обязательно «ничем»). Каждое число стоит с
   приметой, которую сверяет `scripts/guards/prose-numbers-guard.fscript`.
2. Команда, печатающая число обработчиков с параметром типа «Отклик», у которых
   нет ветви «Сбой», но есть `случай любое`, и отвечающая кодом 1, когда число
   выросло. ADR-0034 §2.1 называет 79 таких обработчиков из 215 и 94, передающих
   отклик дальше; пересчёт текстом в той же полосе (`flang/**` и
   `docs/examples/**` без `flang/self/`) даёт сегодня 14 из 96, и какое из двух
   чисел верно, без такой команды не узнать.
3. В ADR-0034 §9 — цена доказательства утверждения «всякий сбой отдаётся со
   своим кодом». Написать его сегодня можно разбором в постусловии (так сделано
   у «После каталога» в примере выше), но `check --proof` отвечает на него
   «сетка 1», а не «доказано».

Запрещать `случай любое` не нужно (ADR-0034 §7); применимости к медицине,
авиации и космосу страница не обещает (ADR-0031 §5.4).

## Обходной путь

К каждому обработчику отклика писать пример с откликом «Сбой» — тогда
проглоченную ветвь ловит `flang check`. Поведение при отказе читать в ADR-0034 §2.

## Когда задача сделана

- страница существует, и `bootstrap/flang io scripts/guards/prose-numbers-guard.fscript --plan Check` на ней зелена;
- команда счёта печатает число проглоченных сбоев и код 0; на дереве с копией
  из шагов воспроизведения число больше на единицу и код 1;
- число видов отказа процесса одно и то же в `docs/flang/concurrency/SPEC.md`,
  в шапке `flang/self/failures.flang` и на странице;
- в ADR-0034 §9 вместо «не измерена» стоит число строк правки разборщика и ядра
  или причина, почему его нельзя назвать.

## Где живёт правка

Новая страница в `docs/`, новая проверка в `scripts/guards/` с ярлыком,
`docs/adr/0034-hardware-failure-is-described-not-proved.md` (§9),
`docs/flang/concurrency/SPEC.md`. Всё это читается с диска, пересборка семени
(bootstrap regeneration) не нужна. Исключение — комментарий в шапке
`flang/self/failures.flang`: его правка меняет файл самосборной части и доезжает
вместе с ближайшей пересборкой семени.
