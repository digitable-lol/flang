# 1424. Замеры на страницах сайта и курса сняты прошлыми версиями двоичного, и проверка видит не все такие места

## Шаги воспроизведения

1. Спросить проверку отставших страниц:

```
bootstrap/flang io scripts/guards/stale-pages-guard.fscript --plan 'Замер версии' --на-веру
```

2. Посчитать упоминания чужой версии, которых проверка не читает (страницы
   журнала изменений и выпусков называют прошлые версии по праву — они
   исключены):

```
v=$(sed -n 's/^version = //p' .flangrc)
git grep -onE '0\.7\.[0-9]+' -- docs/site ':!docs/site/changelog.*' ':!docs/site/releases.*' \
  | grep -v ":$v\$" | awk -F: '{n+=1; f[$1]=1} END{print "мест", n, "в файлах", length(f)}'
```

## Что происходит

```
$ bootstrap/flang io scripts/guards/stale-pages-guard.fscript --plan 'Замер версии' --на-веру
{"error":"страницы отстали от дерева:
  · docs/course/00-overview.md:10 — объявленный замер отстал: было 0.7.22, стало 0.7.23 — переснять прогоном и переписать объявление
  · docs/course/01-install.md:120 — расшифровка прогона отстала: было 0.7.22, стало 0.7.23 — сверено 2026-09-27 на дереве 1043ff82a
  … всего 19 мест в 15 файлах                                     код 1
$ <команда из шага 2>
мест 81 в файлах 35                                               код 0
```

Версия: flang 0.7.23. Дата прогона: 3 октября 2026.

Все 19 мест, которые видит проверка, — в `docs/course`: 15 файлов, где
объявление замера и расшифровки прогонов называют 0.7.22. В `docs/site`
проверка не находит ничего: обе страницы `how-proofs-work` уже пересняты.

Мимо проверки идёт 81 упоминание чужой версии в 35 файлах `docs/site`, записанное
словами («binary 0.7.17, commit …», «двоичным 0.7.17»): 0.7.17 — 64 раза,
0.7.19 — 7, 0.7.14 — 6, 0.7.22 — 2, 0.7.11 — 2; из них 0.7.22 — это
`docs/site/language-map.md:27` и `language-map.ru.md:24`. Проверка читает только
строку `flang N.N.N` и объявление замера в комментарии HTML (версия, дерево, день
сверки); слов «binary» и «двоичным» она не читает вовсе
(`grep -ci 'binary\|двоичным' scripts/guards/stale-pages-guard.fscript` → 0),
поэтому эти места не краснеют и отстают на шесть выпусков молча.

## Что должно быть

Каждый вывод команды на странице снят двоичным той версии, что записана в
`.flangrc`, и страница это объявляет. Правило «число ценно только снятое
прогоном» стоит в `docs/zero-bug-policy.md`. Проверка краснеет на любой
записи версии замера, в каком бы виде она ни стояла.

Менять номер версии правкой текста нельзя: вывод привязан к двоичному,
которым снят. Каждое место переснимается командой, которая на нём записана;
если вывод изменился, правится и текст вокруг него.

## Обходной путь

Читатель повторяет команду со страницы сам и верит своему выводу, а не
странице.

## Когда задача сделана

- команда из шага 1 отвечает «Страницы не отстали: расхождений 0.», код 0;
- проверка читает запись версии словами, а не только строкой `flang N.N.N`: в
  `scripts/guards/stale-pages-guard.fscript` стоит отрицательный контроль —
  страница со словами «binary 0.7.17» без даты замера при текущей версии
  красна, та же страница с датой замера зелена. Сегодня контроля нет, а слов
  «binary» и «двоичным» проверка не читает;
- каждое из 81 места, которые сегодня идут мимо проверки, после работы либо
  переснято текущим двоичным и несёт объявление замера, либо названо датой
  замера — и проверка эти два случая различает. Команда из шага 2 даёт счёт,
  а проверка — вердикт; требовать от шага 2 нуля нельзя: страницы журнала
  изменений и выпусков называют прошлые версии по праву, и дата замера оставляет
  место честным навсегда;
- `node docs/site/build.mjs --check` отвечает кодом 0 (сегодня код 0),
  `bootstrap/flang check docs/course/check.flang` — кодом 0 (сегодня код 0).

Чего переснять нечем, на странице названо датой замера, а не словом
«сегодня»: числа цены доказательств (измерители удалены вместе с реализацией
на JavaScript), сборка и запуск напечатанного для цели `ts` без `tsc`.

## Где живёт правка

Страницы `docs/course` и `docs/site`; чтение записи «binary N.N.N» —
`scripts/guards/stale-pages-guard.fscript`. Пересборка семени (bootstrap
regeneration) не нужна. Работу придётся повторять после каждого выпуска, пока
пересъёмка идёт вручную.

Отдельная задача, здесь не решается: проверка не сравнивает день замера ни с
чем, не видит версию, разорванную переносом строки, и принимает за настоящее
объявление, показанное образцом внутри блока кода.
