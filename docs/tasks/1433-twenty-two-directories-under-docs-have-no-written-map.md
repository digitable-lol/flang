# 1433. Проверка карты внутрь docs/ не смотрит, и новый подкаталог docs/ заводится молча

## Шаги воспроизведения

1. Какие подкаталоги `docs/` не названы в карте `docs/README.md`:

```
for d in $(git ls-files docs | awk -F/ 'NF>2{print $2}' | sort -u); do
  grep -q "$d/" docs/README.md || echo "не назван: $d"
done
```

2. Что сверяет проверка карты:

```
sh scripts/guards/published-vs-tree.sh --карта
```

3. Подложить пустой подкаталог с файлом в `docs/` и повторить шаг 2.

## Что происходит

```
$ sh scripts/guards/published-vs-tree.sh --карта | head -1
КАРТА РАСКЛАДКИ (docs/repository-layout против корня дерева):
```

Функция `karta` в `scripts/guards/published-vs-tree.sh` сверяет состав корня
дерева с блоком между метками КАРТА-НАЧАЛО и КАРТА-КОНЕЦ в
`docs/repository-layout.md` и `docs/repository-layout.ru.md`. Внутрь `docs/` она
не смотрит: подложенный в шаге 3 каталог проверку не красит. Карта
`docs/README.md` называет подкаталоги только потому, что её держат руками.

## Что должно быть

Карта `docs/README.md` называет каждый подкаталог верхнего уровня `docs/` и
говорит, какой род документа туда попадает; проверка `--карта` сверяет её с
деревом так же, как корневую, и краснеет на неназванном каталоге. Это обещает сама
карта корня (`docs/repository-layout.md`: «Prose lives in `docs/` and only there») и
правило именования в `docs/README.md`.

## Обходной путь

Читатель открывает каталог и читает `README.md` внутри, где он есть.

## Когда задача сделана

```
команда из шага 1                                   → пусто
sh scripts/guards/published-vs-tree.sh --карта      код 0
```

Проба: подложить пустой подкаталог в `docs/` — проверка обязана покраснеть и
назвать его; `node docs/site/build.mjs --check` — битых ссылок нет.

## Где живёт правка

`docs/README.md` (карта подкаталогов) и функция `karta` в
`scripts/guards/published-vs-tree.sh` (второй проход, по `docs/`). Двоичного
правка не касается, пересборка семени (bootstrap regeneration) не нужна.
