# 1433. Двадцать два подкаталога `docs/` без записанной раскладки

## Чем измерено

21 сентября 2026, ветка `a/derevo-revizia` от `gh/main`. Раздел 1 и 5 ревизии
[docs/tree-layout-audit.md](../tree-layout-audit.md).

| | |
|---|---:|
| отслеживаемых файлов в `docs/` | **1952** (53 % дерева) |
| каталогов внутри | **135** |
| подкаталогов верхнего уровня | **22** |
| из них без `README.md` и без `README.md` | **15** |
| подкаталогов, названных в карте раскладки `README.md` | **4** |
| глубина | 8 |

Снято так:

```sh
git -c core.quotepath=false ls-files -- docs | wc -l
for d in docs/*/; do [ -f "$d/README.md" ] || [ -f "$d/README.md" ] || echo "$d"; done
```

Без `README`: `adr/`, `archive/`, `benchmark/`, `benchmark2/`, `benchmarks/`, `ct/`,
`design/`, `flang/`, `fspec/`, `guide/`, `releases/`, `site/`, `tools/`,
`zamer-teorkat/`, `спецификации/`.

**Карта раскладки сверяется и зелёная**, но она про корень:

```sh
$ sh scripts/guards/published-vs-tree.sh --карта
КАРТА РАСКЛАДКИ (README против корня дерева):
опубликованное сходится с деревом          код 0
```

Из 22 подкаталогов `docs/` карта называет четыре — `examples/`, `editors/`, `adr/`,
`tasks/` — и описывает остальное одной строкой: «the site sources, the guide, decisions
(adr/), measurement reports, the knowledge base». Про 18 каталогов не сказано ничего, и
сторож туда не смотрит: он сверяет состав **корня**.

## Что именно не так

**1. Три соседних имени, различающиеся цифрой и буквой.** `docs/benchmark/` и
`docs/benchmark2/` имеют **одинаковые списки имён файлов** — по 20, `01-link-key.flang`
… `20-trim-spaces.flang`, — а содержимое различается **во всех двадцати**:

```sh
$ diff <(ls docs/benchmark/) <(ls docs/benchmark2/) && echo IDENTICAL
IDENTICAL
$ for f in $(ls docs/benchmark/); do cmp -s "docs/benchmark/$f" "docs/benchmark2/$f" || echo "DIFFER: $f"; done | wc -l
20
```

По имени выбрать нельзя. Что `benchmark2` — второй заход замера, видно только из
`docs/benchmark-proof-cost-2.md`, который на него ссылается. Рядом третий каталог —
`docs/benchmarks/` (множественное число), и в нём совсем другое устройство:
`proof-cost/`, `speed/`, `verdict-cache/`.

**2. Имя каталога не говорит, что внутри.**

| каталог | файлов | что внутри | `README` |
|---|---:|---|---|
| `docs/ct/` | 3 | теория категорий: `sets.md`, `spec.md`, `zakony.md` | нет |
| `docs/ifl/` | 6 | статья на конференцию: `abstract.txt`, `draft-paper.md` | есть |
| `docs/zamer-teorkat/` | 2 | две программы; имя транслитное | нет |
| `docs/design/` | 21 | проектные записки, часть с номерами задач, часть без | нет |
| `docs/tools/` | 2 | два скрипта `.py` | нет |
| `docs/спецификации/` | 3 | единственный кириллический каталог среди 21 латинского | нет |

У соседнего `flang/ct/` `README.md` есть — то есть образец в дереве уже имеется.

## Что сделать

Работа начинается **с записи правила, а не с переноса каталогов**.

1. **Записать раскладку `docs/`**: какие роды документов здесь бывают (читательская
   страница сайта, решение ADR, отчёт о замере, проектная записка, заметка базы знаний,
   задача, пример, архив), какой каталог какому роду отвечает и по какому признаку файл
   попадает в каталог. Место — карта в `README.md` рядом с уже существующей, либо ADR;
   выбор записать.
2. **Расширить сверку карты внутрь `docs/`**, чтобы новый подкаталог не заводился молча:
   сегодня `published-vs-tree.sh --карта` сверяет только корень.
3. **Развести или переименовать `benchmark` / `benchmark2` / `benchmarks`** так, чтобы по
   имени было видно, что где: один замер от другого отличается заходом, и это должно быть
   в имени, а не только в тексте страницы.
4. **Завести `README.md` в подкаталогах**, где по имени не видно содержимого, — в первую
   очередь `ct/`, `design/`, `tools/`, `zamer-teorkat/`, `спецификации/`. Одного абзаца
   достаточно: что здесь лежит и кто читатель.

## Чего НЕ делать

* **Не переносить и не переименовывать каталоги до того, как правило записано.**
* Не трогать `docs/tasks/` — его раскладка (`completed/`, `rejected/`, `archive/`) уже
  осмысленная и сверяется `task-numbers-guard.sh`.
* Не трогать `docs/zettel/` по составу: 721 заметка, у неё своя схема имён и свой сторож.
* Не заводить `README.md` там, где имя каталога и так говорит всё (`adr/`, `site/`,
  `guide/`, `releases/`, `archive/`): пустой `README` хуже отсутствующего.
* `docs/спецификации/` не переименовывать в этом заходе — это правило имени, задача 1419 и
  1430, а не раскладка.

## Как проверить, что сделано

* `for d in docs/*/; do … done` — список каталогов без `README` уменьшился до
  записанного в правиле числа;
* карта раскладки называет каждый подкаталог `docs/` верхнего уровня, и
  `sh scripts/guards/published-vs-tree.sh --карта` — код 0 **и** краснеет на
  подложенном каталоге (проба);
* `diff <(ls docs/benchmark/) <(ls docs/benchmark2/)` больше не даёт совпадения имён при
  разном содержимом, либо каталоги названы различимо;
* `node docs/site/build.mjs --check` — битых ссылок нет;
* `sh .githooks/pre-push` — код 0.
