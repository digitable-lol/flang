# 1710. Плагин asdf качает только архив C и собирает его сам; готового двоичного под свою тройку он не ищет, а формула Homebrew не знает бутылок

Решение: [ADR-0067](../adr/0067-the-release-ships-binaries-for-four-triples-from-one-seed.md),
разделы 2.3 (Homebrew) и 2.4 (asdf). Делается ПОСЛЕ задачи о матрице выпуска:
качать можно только то, что выпуск уже несёт.

## Шаги воспроизведения

1. Что плагин качает: `grep -n 'tar.gz' packaging/asdf/bin/download`
2. Знает ли он свою тройку: `grep -c 'uname' packaging/asdf/bin/download`
3. Знает ли формула бутылки: `grep -c 'bottle' packaging/homebrew/flang.rb`
4. Сколько стоит сборка формулы на раннере macOS: время шага «Update formula»
   работы `homebrew` в последнем прогоне выпуска (`gh run view <прогон> --json jobs`).

## Что происходит

```
$ grep -n 'tar.gz' packaging/asdf/bin/download
13:archive="flang-${version}-c.tar.gz"                           код 0
$ grep -c 'uname' packaging/asdf/bin/download
0                                                               код 1
$ grep -c 'bottle' packaging/homebrew/flang.rb
0                                                               код 1
```

Прогон 11 октября 2026 на дереве 1149c78f7 отвечает так же; шаг 4 (время
шага «Update formula» в прогоне выпуска) без сети не повторялся.

Плагин знает одно имя архива и один путь — `make` с `-Werror`. Шаг «Update
formula» (это `brew install --build-from-source`) на `macos-latest` занимает
около 3,5 мин; плюс `brew install gnu-tar` и скачивание. Формула не несёт блока `bottle`,
то есть `brew` собирает у каждого.

## Что должно быть

**asdf (обязательная половина).** `bin/download` узнаёт тройку (`uname -s`,
`uname -m`; `arm64` → `aarch64`), качает `flang-<версия>-<ось>-<арх>.tar.gz` и
`SHA256SUMS` того же выпуска, сверяет хеш и раскладывает архив; `bin/install`
ставит из раскладки. Откат на архив C и `make` — в трёх случаях, каждый назван
в выводе: у выпуска нет вложения под тройку (выпуски до матрицы и чужие
тройки); хеш не сошёлся — это ОТКАЗ, не откат; человек попросил сам,
`ASDF_FLANG_FROM_SOURCE=1`. Пробы после установки (`--version`, «Число связанных
функций», печать во все цели) остаются теми же — они спрашивают результат, а не
дорогу. README плагина перестаёт обещать `cc` и `make` всем: они нужны откату.

**Homebrew (вторая половина — только после решения владельца).** ADR-0067,
раздел 2.3, ступенью 1 оставляет формулу на исходниках и называет бутылки
решением владельца. Если владелец принимает бутылки: `brew install
--build-bottle` + `brew bottle --root-url` в работе выпуска на двух раннерах
macOS, бутылки — вложениями выпуска КРАНА, блок `bottle do … end` в
`packaging/homebrew/flang.rb` и в сабмодуле крана, шаг «Check Homebrew tap»
сверяет и его. Без решения владельца эту половину не делать.

## Обходной путь

`asdf install flang <версия>` собирает из исходников, как сегодня: `cc`, `make`
и 2–6 минут. Готовый двоичный можно взять руками со страницы выпуска, когда
матрица его положит.

## Когда задача сделана

1. На `macos-latest` и `ubuntu-latest` `asdf install flang <X>` печатает строку
   «скачиваю flang-<X>-<ось>-<арх>.tar.gz», проходит без вызова `make` и
   укладывается в 60 с от начала до конца (против около 3,5 мин сборки формулы
   на том же раннере).
2. `ASDF_FLANG_FROM_SOURCE=1 asdf install flang <X>` собирает из архива C, и
   прибор паритета (задача об install-parity) даёт `расхождений 0` между
   двумя установками одного выпуска.
3. `asdf install flang <выпуск без двоичных>` печатает названную причину
   отката и ставит из исходников — старые выпуски не ломаются.
4. Проба порчи: строка `SHA256SUMS` с подменённым хешем — `bin/download` отвечает
   отказом, а не откатом; сторож `asdf-plugin:check` по-прежнему зелен на
   четырёх файлах.
5. Если бутылки приняты: `brew install digitable-lol/tap/flang` на
   `macos-latest` пишет `Pouring flang--<X>…bottle.tar.gz`, а не `Building`.

## Где живёт правка

`packaging/asdf/bin/download`, `packaging/asdf/bin/install`,
`packaging/asdf/README.md` и их копии в сабмодуле `packaging/asdf-plugin`
(коммит и push в `digitable-lol/asdf-flang` — руками владельца); при бутылках —
`packaging/homebrew/flang.rb`, сабмодуль `packaging/homebrew-tap`,
`.github/workflows/release.yml`. Перепечатка не нужна.

Следующий шаг — `packaging/asdf/bin/download`: узнать тройку через `uname -s` и
`uname -m` (`arm64` → `aarch64`), качать `flang-<версия>-<ось>-<арх>.tar.gz` и
`SHA256SUMS`, сверять хеш, откатываться на архив C в трёх названных случаях;
ждёт матрицы выпуска. Краснеющая сегодня проба: `grep -c 'uname'
packaging/asdf/bin/download` печатает 0.

## Чем закрыта

Ветка `a/prebuilt-binaries`, коммиты `feat(asdf): the plugin installs the prebuilt build and falls back to C`
и `build(packaging): homebrew and aur manifests for flang-package`.

1. На этой машине (Linux x86_64) `bin/download` с подменённым адресом на каталог вложений взял
   `flang-package-0.7.28-linux-x86_64.tar.gz`, хеш сошёлся, `bin/install` прошёл все пробы.
   На macOS — работа `install-parity` (asdf из готовой сборки), прогон 38667409182.
2. `ASDF_FLANG_FROM_SOURCE=1` — сборка из архива C; на macOS-раннере собрана и сверена прибором.
3. Выпуск без готовых сборок (0.7.28 на GitHub): «у выпуска 0.7.28 нет готовых сборок (они
   начинаются с 0.7.29) — беру архив C». Сборка из архива на этой машине (gcc 15) падает на
   `-Werror=format-truncation` в `flang_repl.c` — это и до правки было так.
4. Подменённый байт: «хеш … не сошёлся … ставить его нельзя», код 1, отката нет.
5. Бутылки не делались: формула `flang-package` сама ставит готовую сборку (лог brew: «built in
   2 seconds»), старое имя `flang` остаётся алиасом крана.
