# 1734. Оценка числа шагов у «элемент N в СПИСОК» берёт часть от номера, а не от списка

## Шаги воспроизведения

```
grep -an 'аргумент 0' flang/self/bounded.flang
grep -an 'аргумента 1' flang/self/totality.flang
```

## Что происходит

```
$ grep -an 'аргумент 0' flang/self/bounded.flang
653:// У `элемент` берётся аргумент 0 — а это САМ НОМЕР, а не список. Оценка витков
$ grep -an 'аргумента 1' flang/self/totality.flang
1484:// — из аргумента 1, потому что нулевым стоит номер.
```

Дата прогона: 2 октября 2026. Двоичный flang в прогоне не участвует: оценку
числа шагов он не печатает, и дефект читается по исходнику.

Два прохода читают одну форму по-разному. Анализ завершаемости
(`flang/self/totality.flang`) считает частью значения аргумент 1 — список.
Оценка числа шагов (`flang/self/bounded.flang`, «Происхождение» и «Разбирающая
форма») считает частью аргумент 0 — сам номер. Поэтому функция, у которой
спуск идёт по списку в `элемент N в СПИСОК`, для завершаемости убывает, а для
оценки — нет, и многочлена не получает.

## Что должно быть

Оба прохода считают частью один и тот же аргумент — список. Функция, которой
завершаемость доказана спуском по `элемент N в СПИСОК`, получает оценку числа
шагов.

## Обходной путь

Писать спуск через `хвост` или `разбор` списка: эти формы оба прохода читают
одинаково.

## Когда задача сделана

В `flang/self/bounded.flang` форма `элемент` берёт часть от аргумента 1, и при
функции есть пример на эту форму. Снят замер до и после: сколько функций дерева
получили оценку, которой у них не было. `bootstrap/flang check` на
`flang/self/bounded.flang` даёт прежний вердикт.

## Где живёт правка

`flang/self/bounded.flang`, разбор формы `элемент`. До двоичного правка доезжает
пересборкой семени (bootstrap regeneration).
