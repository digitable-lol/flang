# 2031. Замок не записывает ни одну форму зависимости, которую умеет доставить реестр: по имени — ноль модулей, на пакет — FLANG_PARSE

Решение: [ADR-0059](../adr/0059-the-registry-is-a-ledger-of-names-not-a-store-of-code.md),
§3 и §6 п. 4. Обещание, которое не исполняется:
[ADR-0021](../adr/0021-packages-are-installed-over-the-network-and-locked-locally.md)
п. 4 — «После установки зовётся готовый `flang lock`».

## Шаги воспроизведения

1. Собрать двоичный в дереве: `make -C bootstrap`.
2. Форма «по имени» — программа дерева с тремя импортами по имени:
   `bootstrap/flang lock docs/examples/web/orders-api.flang`.
3. Форма «пакет по пути» — единственный способ употребить пакет, названный в
   `docs/DESCRIPTION.md`:
   `bootstrap/flang lock docs/examples/package/shop/shop.flang`.
4. Контроль — форма `из "путь"` на обычном `.flang`:
   `bootstrap/flang lock flang/stdlib/hmac.flang`.
5. Смотреть: длину вывода, длину списка `модули`, код возврата.

## Что происходит

```
$ bootstrap/flang lock docs/examples/web/orders-api.flang | wc -c
149                                                                   код 0
    модули: []            — а flang check над тем же файлом говорит
                            «функций 80 … файлов вместе с импортами 4»

$ bootstrap/flang lock docs/examples/package/shop/shop.flang
FLANG_PARSE в файле …/docs/examples/package/shop/discount.flang-package,
строка 1: документ должен начинаться со слова 'категория'               код 1

$ bootstrap/flang lock flang/stdlib/hmac.flang | wc -c
87465                                                                 код 0
    модули: 1 запись, SHA-256, исходник 52 532 Б
```

Вторая строка — отказ на той форме, которую `docs/DESCRIPTION.md` называет
способом употребить пакет: `использует «Имя» из "имя.flang-package"`. Замок
пробует разобрать пакет как исходник на flang.

## Что должно быть

`docs/DESCRIPTION.md` обещает про замок: «Если файл `flang.lock` лежит рядом с
программой, команды берут эти модули из него, и исходники на диске не нужны». Для
зависимости, поставленной из реестра, это обещание сегодня пусто: по имени
модуль в замок не пишется (это в `DESCRIPTION.md` названо ограничением), а
пакет по пути замок разобрать не может вовсе (это нигде не названо).

Ожидается: обе формы попадают в замок, и `flang lock` над `shop.flang`
отвечает кодом 0.

## Обходной путь

Переписать импорт на `из "путь"` к обычному `.flang` — то есть отказаться и от
имён, и от пакетов. Для зависимости, приехавшей из реестра, обхода нет: её код
лежит в `.flang-package`, а эту форму замок отвергает.

## Что сделано

**Две правки, обе в `flang/src/emit/c/flang_repl.c`.**

1. `lock_scan`: у ввоза БЕЗ ключа `"from"` (`использует «Списки»`) стояло
   `continue` — имя просто выбрасывалось. Теперь оно разрешается тем же
   `repl_find_module`, которым пользуется загрузчик: свой список мест означал бы,
   что замок пишет не тот файл, который соберётся.
2. `lock_collect`: встреченный `.flang-package` раскрывается целиком через
   `pkg_take_nested` — то же тело, что у пакета над пакетом, — а не отдаётся
   разбору flang. Два объявления (`pkg_is_package`, `pkg_take_nested`) вынесены
   вперёд: замок встречает пакет раньше, чем они определены.

**Прогон 4 октября 2026 после правки, двоичный 0.7.24:**

```
$ bootstrap/flang lock docs/examples/web/orders-api.flang | wc -c
109766                                                                код 0
    модули: 3 записи — Dictionary, String sets, Strings
    flang check над тем же файлом: «файлов вместе с импортами 4» — сходится

$ bootstrap/flang lock docs/examples/package/shop/shop.flang
                                                                      код 0
    модули: 1 запись, «Скидка», ./discount.flang-package

$ bootstrap/flang lock flang/stdlib/hmac.flang | wc -c
168237                                                                код 0
    модули: 3 записи — Numbers, SHA-256, UTF-8 (было 1)
```

Третья строка — контроль, и он тоже сдвинулся: у `hmac.flang` замыкание шло
через `sha256.flang`, который ввозит `Numbers` и `UTF-8` ПО ИМЕНИ, и эти два
модуля терялись молча. То есть «модулей 1» в прежнем замере было не границей
формы `из "путь"`, а тем же дефектом внутри неё.

**Сквозной опыт в пустом каталоге прогнан целиком:**

```
$ bootstrap/flang lock docs/examples/package/shop/shop.flang > /вне-дерева/flang.lock
                                                                      код 0
$ ls /вне-дерева                         # flang.lock и shop.flang
$ cd /вне-дерева && flang check shop.flang
                                      код 0, «файлов вместе с импортами 2»
$ rm flang.lock && flang check shop.flang
          FLANG_PACKAGE: пакет …/discount.flang-package не прочитан, код 1
```

**Прибор.** `scripts/guards/lock-closes-every-form.fscript`
(`lock-forms:check`) над всеми тремя формами сверяет длину списка `модули` с
числом «файлов вместе с импортами» минус входной файл. Прогон: «форм 3; по имени
— модулей 3 при файлах 4; пакет — модулей 1 при файлах 2; из пути — модулей 3
при файлах 4», код 0. Цена — 9 с: `flang check --fast` даёт то же число файлов,
что полная проверка, но 3,5 с против 149 с на `hmac.flang`.
Подлог (план `Forgery`) подменяет измеренную длину нулём — прежним поведением
замка на форме по имени: код 1, краснеют все три формы, каждая названа вместе с
обоими числами. Сторожа зовут работа CI `registry-resolution` и
`.githooks/pre-push.fscript` (проверок стало 24).

## Когда задача сделана

Сквозной прогон с контрольным опытом, оба обязательны:

```
$ bootstrap/flang lock docs/examples/package/shop/shop.flang > /вне-дерева/flang.lock
                                                                      код 0
$ cp docs/examples/package/shop/shop.flang /вне-дерева/
$ ls /вне-дерева                    # только shop.flang и flang.lock
$ cd /вне-дерева && flang check shop.flang
                                      код 0, «файлов вместе с импортами 2»
$ rm flang.lock && flang check shop.flang
                                      ОТКАЗ — без замка собраться не должно
```

То же для формы по имени: `flang lock` над `orders-api.flang` обязан записать
модули, которые `flang check` насчитал импортами, и число записанных модулей
обязано сойтись с «файлов вместе с импортами» минус сам входной файл.

Проба, которая краснеет, если дефект вернётся: сторож, который над каждой из
трёх форм сверяет длину списка `модули` в замке с числом файлов, названным
`flang check`. Подделка, на которой сторож обязан покраснеть: вернуть замку
прежнее поведение на одной из форм — сторож назовёт форму и оба числа.

## Где живёт правка

Решение «класть модуль в замок» принимается при построении замка: вход
`flang lock` — `flang/self/cli.flang`, исполнитель —
`flang/src/emit/c/flang_repl.c`, `lock_print`. Разбор `.flang-package` как
источника модуля живёт рядом со связыванием (`flang/self/link.flang`).

**Доставка правки. ВЫЯСНЕНО 4 октября 2026: БЫСТРЫЙ ПЕРЕСЕВ.** Правка легла
ТОЛЬКО в `flang/src/emit/c/flang_repl.c` — `flang/self/**` не тронут ни строкой.
`flang/self/cli.flang:400`, названный выше, оказался не тем местом: там стоит
разбор ТЕМЫ СПРАВКИ (`если «команда» равен "lock" то «Справка замка»`), а
решение «класть модуль в замок» принимается в C — `lock_scan` и `lock_collect`.
Пересев: `bootstrap/flang run-script seed:refresh` — «шапка 9 строк + источник
21 460 строк», заслоны `--telo` и `seed-runtime-is-source` зелены, двоичный
собран, версия `flang 0.7.24`. Полная перепечатка (по карте ADR-0021 «4 ч 41 мин
и 36,3 ГиБ») НЕ ПОНАДОБИЛАСЬ.
