# 2159. Сверщик измерен прежде, чем его сокращать

Сверщик — независимая программа на C, которая переигрывает записи доказательств.
Ему приходится верить целиком: если он ошибётся, ошибётся и вердикт. Поэтому его
размер — не вопрос вкуса, а размер доверенной базы.

## Замер 18 сентября 2026 (main `d36c0b7d7`)

Приборы: `sh flang/proof/tables-guard.sh --строки-кода` и разбор файла.

| что | сколько |
|---|---:|
| строк в файле `flang/proof/checker/checker.c` | 11 631 |
| строк кода (комментарии и пустые сняты) | **7531** |
| строк комментария | 3727 (32 % файла) |
| пустых строк | 459 |
| функций (`static`) | **431** |
| медиана длины функции | **9 строк** |
| окон по 8 строк, встречающихся дважды | **2** |

Из этих чисел следуют три вывода, и два из них против расхожей догадки.

**Дублирования нет.** Повторяющихся восьмистрочных кусков во всём файле два, и
один из них — цикл замыкания по достижимости. Сокращать «копипасту» нечего.

**Функции мелкие.** Медиана 9 строк, 431 штука. Это не монолит.

**Но одна функция — 1272 строки.** `«шаг вывода»` (разбор шага записи по видам
правил) — 17 % всего кода сверщика. Следом идут 272, 113, 96, 89. То есть вся
тяжесть сидит в одном разборе, и он растёт с каждым новым правилом вывода:
правил сейчас 109.

**Комментарии — не шум.** 202 блока по шесть строк и длиннее, в них 2496 строк;
это доводы с номерами задач и ADR (`9616: ВЕРДИКТ ПО ОБЪЯВЛЕНИЮ…`,
`ПРИЁМ «ВЫВОД»… ADR-0022 §3.10`). В `.c` доводы живут рядом с кодом сознательно:
в `.flang` комментариев не пишут, и объяснять там нечем.

## Что делать

1. **Разобрать `«шаг вывода»` на разбор и правила.** Не «отрефакторить красиво», а
   свести к таблице: имя правила → посылки → проверка. Правила уже есть данными —
   `flang/proof/tables/inference-rules.tsv` (109 строк) и леммы в `Rules.lean` (109 из
   109). Цель: код, который читает ту же таблицу, вместо ветвления на 1272 строки.
   Мера успеха — не «стало красивее», а: строк кода меньше, набор проб «сошлось
   всё», доля 650/650 не двинулась.
2. **Назвать, что нельзя снять.** Разбор записи, арифметика, свёртки, хеш — это
   не правила, это обвязка. Сколько её — сказать числом после шага 1.
3. **Проверить машиной то, что останется.** Память и переполнения — CBMC или
   Frama-C по функциям обвязки; это не доказательство соундности, а снятие
   целого класса ошибок. Оценка цены — отдельным замером, не на глаз.

## Чего НЕ делать

- **Не переписывать сверщик на flang.** Тогда он перестанет быть независимым:
  доказательство компилятора проверялось бы компилятором. Это круг, и он хуже
  большого файла.
- **Не сокращать комментарии.** Они — доводы, а не украшение; их снятие ничего не
  даёт доверенной базе (в счёт TCB идут строки кода, а не файла).
