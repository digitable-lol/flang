# 2196. Входа в flang нет ни одного

Из flang печатается десять целей. Обратно — ничего: ни одного разборщика чужого языка
ни во flang-исходник, ни в спеку.

## Шаги воспроизведения

1. `ls flang/self/emit-*.flang | wc -l`
2. `ls flang/self/ | grep -cE '^(parse|import|read|lift|from)-'`
3. `bootstrap/flang --help` — смотреть, есть ли среди команд входная.

## Что происходит

```
$ ls flang/self/emit-*.flang | wc -l
10
$ ls flang/self/ | grep -cE '^(parse|import|read|lift|from)-'
0
```

Справка называет цели печати: `c|cpp|go|rust|java|js|ts|elixir|python|csharp` — десять.
Команд у двоичного 15, входной среди них нет. Разборщики, которые в дереве есть
(`flang/self/lexer.flang`, `flang/self/parser.flang`), читают только flang — четыре
поверхности записи одного и того же дерева. Библиотека разбирает форматы данных
(`json`, `toml`, `protobuf`, `der`, `x509`), а не языки.

Самое близкое к входу — `docs/guide/foreign-code.ru.md`, и там же сказано, чего он не
делает: «`flang check` смотрит только на новый код… До чужого исходника ей дела нет: она
его не читала». Перевод там ручной: взята `bisect_left` из CPython, переведено 3 функции,
постусловий доказано обо всех входах 0 из 2.

Версия: flang 0.7.23. Дата прогона: 2 октября 2026.

## Что должно быть

Один вход, пусть узкий, и названный замером: берётся подмножество одного чужого языка,
печатается заготовка на flang, и число говорит, какая доля файлов корпуса прошла.
Решение об устройстве входа —
[ADR-0058](../adr/0058-a-foreign-language-enters-through-an-untrusted-translator.md):
разборщик чужого языка стоит вне доверенной основы, его вывод судит ядро.

## Обходной путь

Переписывать руками по `docs/guide/foreign-code.ru.md`.

## Когда задача сделана

Прогон на названном корпусе чужих файлов печатает заготовку на flang и число: сколько
файлов разобрано, сколько заготовок прошло `flang check --fast`. Проба краснеет, если
доля упала.

## Где живёт правка

Новый каталог вне `flang/self` — вход не входит в доверенную основу (ADR-0058).
