# 2663. Экспортированная функция, которая зовёт неэкспортированную, ломает проверку подключающего модуля

## Шаги воспроизведения

1. Два файла рядом.

   lib.flang:

   ```flang
   модуль «Цены»
     экспортирует «Цена со скидкой»

   тотальная функция «Скидка»
     принимает цена: число
     возвращает число
     цена делить на 10

   тотальная функция «Цена со скидкой»
     принимает цена: число
     возвращает число
     цена минус («Скидка» от цена)
   ```

   app.flang:

   ```flang
   модуль «Касса»
     использует «Цены» из "lib.flang"

   тотальная функция «Итог»
     возвращает число
     пример «сто»
       ожидается 90
     «Цена со скидкой» от 100
   ```

2. `flang check lib.flang`, затем `flang check app.flang`.

## Что происходит

```
$ flang check lib.flang
lib.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
$ flang check app.flang
…
FLANG_UNKNOWN_NAME, строка 12, столбец 15: неизвестная функция «Скидка»
FLANG_NOT_TOTAL, строка 12, столбец 15: тотальная функция «Цена со скидкой» вызывает неизвестную функцию «Скидка»: завершение доказать нельзя
app.flang: не проверено — замечаний 2        код 1
```

Версия: flang 0.7.25. Без строки `экспортирует` оба файла проходят.

## Что должно быть

`экспортирует` ограничивает имена, видные подключающему модулю, но не тела самого
модуля: «Цена со скидкой» зовёт «Скидка» внутри «Цены», и это законно (DESCRIPTION.md,
раздел «Модули и пакеты»). app.flang проходит, а прямой вызов `«Скидка»` из
app.flang по-прежнему отвергается `FLANG_UNKNOWN_NAME`.

## Обходной путь

Не писать `экспортирует` либо внести вспомогательную функцию в список.

## Когда задача сделана

`flang check app.flang` — код 0; программа, зовущая `«Скидка»` из app.flang, —
`FLANG_UNKNOWN_NAME`. Обе пары стоят в наборе проб модулей.

## Где живёт правка

Связывание ввоза в `flang/self/` (отбор имён по списку экспорта); требует перепечатки
семени.
