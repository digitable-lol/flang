# 2748. Проверяющая программа не переигрывает утверждение, у которого в записи стоит только имя правила

## Шаги воспроизведения

1. Программа из дерева — силлогизм о Сократе с собственным типом «Человек»:
   `flang/proof/checker/tests/families/statement/syllogism-socrates.flang`.
2. Доказать компилятором, записать доказательство, собрать независимую
   проверяющую программу (proof checker) и отдать ей запись:

```
bootstrap/flang check flang/proof/checker/tests/families/statement/syllogism-socrates.flang --proof --record <запись>
make -C flang/proof/checker
flang/proof/checker/сверщик flang/proof/checker/tests/families/statement/syllogism-socrates.flang <запись>
```

3. Смотреть первую строку ответа и код возврата.

## Что происходит

```
$ bootstrap/flang check …/syllogism-socrates.flang --proof --record <запись>
… ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 3: доказано 3, условно 0, …   код 0
$ flang/proof/checker/сверщик …/syllogism-socrates.flang <запись>
НЕ ВЗЯЛСЯ (строк причин 3; мест на слово ядра 3): утверждение «все люди
смертны»: значение «по объявлению нет» — сверщик не повторяет изъятие
объявленного типа, место на слове ядра; теорема «Сократ смертен»: шаг «по
свойству «все люди смертны»» — утверждение, но оно не проверено по существу
раньше этой теоремы; …
НЕ ПРОВЕРЕНО — запись не противоречит исходнику, но доказательством это не
является: утверждений 3, …                                           код 3
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026.

У утверждения «все люди смертны» запись несёт две строки — правило «цель есть
допущение» и «по объявлению нет» — и ни одного шага вывода. Проверяющей
программе переигрывать нечего, и она оставляет место на слове компилятора; за
ним на слове остаются оба шага теоремы, которые на это утверждение ссылаются.
Объявленный тип здесь ни при чём: компилятор сам пишет, что обошёлся без него.
Отказ зависит от формы цели: так уходят равенство по полю результата, цель со
связкой «и притом» или «или», признак от свободного параметра, сравнение при
теле-разборе без индукции. Равенство с вариантом-литералом компилятор печатает
шагами, и оно переигрывается.

## Что должно быть

Каждое место, которое компилятор назвал доказанным, в записи несёт вывод,
который проверяющая программа переигрывает сама (ADR-0022). Для программы
пользователя с собственным типом ответ проверяющей программы — «ПРОВЕРЕНО»,
мест на слове компилятора нет.

## Обходной путь

Обходного пути нет. На наборе записей самого компилятора дефект не виден: там
такие места закрывает другой приём проверяющей программы, разбор цели.

## Когда задача сделана

Команды из шагов воспроизведения дают от проверяющей программы «ПРОВЕРЕНО»,
код 0, и «НА СЛОВО ЯДРА: посылок и утверждений 0, шагов 0». В набор подделок
добавлена запись, в которой строка «по объявлению» или имя правила подменены:
на ней проверяющая программа отвечает кодом 1. Запись силлогизма лежит в
наборе проб, и прогон проб краснеет, если место снова уйдёт на слово
компилятора.

## Где живёт правка

Выбрать один путь и записать выбор решением (ADR):

- компилятор печатает шаги у цели, закрытой правилом без посылок, —
  `flang/self/zapis.flang` и `flang/self/proof-kernel.flang`; до двоичного
  доезжает только пересборкой семени (bootstrap regeneration);
- правило оформляется в `flang/proof/tables/inference-rules.tsv` обычной
  строкой с посылками, а приём для него добавляется в
  `flang/proof/checker/checker.c` (место отказа — `сверить_объявление`);
  пересборка семени не нужна, но растёт размер проверяющей программы, у
  которого есть потолок в `flang/proof/checker/ratchet.txt`.

Вычислитель в проверяющую программу не добавлять: она нарочно без него.
