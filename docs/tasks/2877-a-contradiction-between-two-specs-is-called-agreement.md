# 2877. Набор требований не судится на противоречивость между файлами

Заявка: —

## Шаги воспроизведения

1. Каталог спек из двух файлов. Правило зовётся одинаково, подпись одна и та
   же, а обещания несовместимы: ниже тридцати и выше пятидесяти одновременно
   не бывает.

   `spec/01-cap.flang`:

   ```flang
   модуль «Спека 1: потолок скидки»

   тотальная функция «Потолок скидки»
     принимает сумма: число
     возвращает число
     обеспечивает «скидка не больше 30» результат не больше 30
     30
   ```

   `spec/02-floor.flang`:

   ```flang
   модуль «Спека 2: пол скидки»

   тотальная функция «Потолок скидки»
     принимает сумма: число
     возвращает число
     обеспечивает «скидка не меньше 50» результат не меньше 50
     50
   ```

   Рядом — `guard.flang`, `policy.flang`, `settings.txt` (путь к двоичному и
   слово `spec`) и `snapshot.txt` с обеими строками обещаний.

2. Команда: `bootstrap/flang io <каталог>/guard.flang --на-веру` — та же, что
   стоит за ярлыком `specs:check` в `.flangrc`.
3. Что смотреть: слово `result` и код возврата.

## Что происходит

```
$ bootstrap/flang io <каталог-из-двух-файлов>/guard.flang --на-веру
"result":"спеки согласны: спек 2, утверждений 2, и каждое доказано из нуля
аксиом; обещаний в слепке 2, и у каждого цель та же; видов перевода 0, и
каждый обещает то же, что основной; понятий 4, и ни одно не носит двух
значений; обещаний с замкнутой целью 0, и ни одно не ложно"            код 0
```

«Спеки согласны» — о паре требований, которые согласны быть не могут.

Те же два обещания при ОДНОЙ функции в ОДНОМ файле проверка ловит — и не
противоречием, а недоказанностью второго обещания:

```
$ bootstrap/flang io <каталог-с-одной-функцией>/guard.flang --на-веру
"error":"бед в системе спек: 1\n01-cap.flang: спека не проходит проверку языка
… «скидка не меньше 50» … \"verdict\":\"declared\" …"                  код 1
```

Версия: `flang --version` -> 0.7.23 (сборка `make -C bootstrap flang` на dev
bd12d88dd). Дата прогона: 2 октября 2026.

Почему так, по тексту `fspec/guard.flang`: цели двух обещаний сверяются между
файлами в одном месте — «Беды перед предком», и только по рёбрам, объявленным
словом `использует`. Корпусная сверка есть («Беды понятий»), но она сравнивает
ТИПЫ под одним именем, а не цели: подпись у обеих спек одна, значит имя носит
одно понятие, и беды нет. Слепок сверяет каждое обещание само с собой.

Числа каталога `fspec/spec`: файлов 43, рёбер `использует` 33, пар файлов
`43*42/2` = 903. Сверяются на согласие обещаний 33 пары из 903. Из 19 случаев
подлога в `fspec/forgery.flang` ни один не кладёт противоречие в два файла без
`использует`: ближайший («ловит противоречие ЧЕРЕЗ ФАЙЛ») ставит в наследнице
`использует` и зовёт функцию предшественницы.

## Что должно быть

Набор требований судится как набор, а не пофайлово: две спеки, обещания
которых несовместимы, дают отказ с кодом 1, и отказ называет ОБЕ стороны
поимённо — файл, функцию, имя обещания и цель каждой. Связность и
противоречивость — свойства набора, и проверять их должно без того, чтобы
автор заранее объявил рёбра `использует`: аналитик, который противоречит сам
себе, ребра не объявит.

Три вопроса о наборе, на которые сегодня ответа нет вовсе, и они просятся
отдельными бедами:

| вопрос о наборе | что отвечает проверка сегодня |
|---|---|
| обещание несовместимо с обещанием другой спеки | «спеки согласны», код 0 |
| требование ни на что не влияет: его не зовёт ни одна функция набора | «спеки согласны», код 0 |
| случай не покрыт ни одним требованием | «спеки согласны», код 0 |

Третья строка снята прогоном: каталог из одного файла, где обещание
`обеспечивает «в столице сутки» если (зона равен "столица") то (результат
равен 1) иначе да` о двух зонах из трёх не говорит ничего, даёт
`спеки согласны: спек 1, утверждений 1` и код 0. Слов `покрыт`, `не
используется` и `ни на что` в `fspec/guard.flang` и `fspec/policy.flang` нет
ни одного.

## Обходной путь

Писать `использует` между спеками руками и звать функцию предшественницы —
тогда противоречие вылезет неудачей доказательства у наследницы. Пару спек,
не связанную `использует`, сегодня не проверяет ничто.

## Когда задача сделана

Прогон из шагов воспроизведения даёт код 1 и отказ, который называет
`01-cap.flang` с «скидка не больше 30» и `02-floor.flang` с
«скидка не меньше 50». Случай ложится в `fspec/forgery.flang` отдельной
записью `запись «Случай»`, и `bootstrap/flang io fspec/forgery.flang`
краснеет, если проверка перестанет его ловить. Отрицательный контроль — пара
спек без `использует`, обещания которых совместимы: на ней новая беда молчит.

Каталог `fspec/spec` в приёмку не входит: на двоичном из семени он сегодня
краснеет своим счётом — `бед в системе спек: 89`, из них 79 одного рода
(«доказано у <предшественницы>, а здесь его нет»), потому что
`flang check <наследница> --proof --json` утверждений предшественницы в отчёт
не кладёт. Это записано в `docs/ci-inventory.md` строкой 102 и к этой задаче
не относится.

## Где живёт правка

`fspec/guard.flang` (новая беда и её сверка), `fspec/policy.flang`
(что считать несовместимостью двух целей), `fspec/forgery.flang` (случай
подлога). Решает ли несовместимость ядро или guard своими средствами — вопрос
к решению. У ядра есть правило 8 «несовместимые допущения» — о паре
противоречивых ДОПУЩЕНИЙ (ADR-0042, семейство Пр); о паре постусловий разных
функций правила нет ни у ядра, ни у guard. Правка может свестись к тому, чтобы
guard складывал два обещания допущениями одной программы и спрашивал ядро.
