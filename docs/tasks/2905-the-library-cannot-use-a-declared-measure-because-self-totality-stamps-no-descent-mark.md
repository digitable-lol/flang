# 2905. «Поиск в диапазоне» в библиотеке списков несёт параметр-счётчик вместо объявленной меры

## Шаги воспроизведения

1. Посмотреть подпись функции и счёт слова «убывает» в файле:

```
grep -n -A1 'функция «Поиск в диапазоне»' flang/stdlib/lists.flang
grep -c 'убывает' flang/stdlib/lists.flang
```

2. Спросить, чем держится завершение:

```
bootstrap/flang check flang/stdlib/lists.flang --proof | grep '«Поиск в диапазоне»  '
```

## Что происходит

```
$ grep -n -A1 'функция «Поиск в диапазоне»' flang/stdlib/lists.flang
262:тотальная функция «Поиск в диапазоне»
263-  принимает элементы: список числа, цель: число, низ: число, верх: число, витков: неотрицательное
$ grep -c 'убывает' flang/stdlib/lists.flang
0                                                                 код 1
$ bootstrap/flang check flang/stdlib/lists.flang --proof
  «Поиск в диапазоне»     доказано точным шагом: аргумент 5 («витков») объявлен
  натуральным и убывает на 1; …                                   код 0
```

Версия: flang 0.7.23. Дата прогона: 3 октября 2026.

Параметр «витков» не нужен самому поиску: он убывает на единицу на каждом
вызове, и только по нему анализ завершаемости принимает функцию. Раньше
объявленную меру в библиотеке писать было нельзя; сегодня можно —
`flang/stdlib/bignum.flang`, `flang/stdlib/json.flang`,
`flang/stdlib/hmac.flang` и `flang/stdlib/postgres.flang` её уже несут.

Та же функция без пятого параметра, со строкой меры, проверку проходит:

```
  принимает элементы: список числа, цель: число, низ: число, верх: число
  возвращает число
  убывает (верх минус низ) плюс 1
```

```
$ bootstrap/flang check <файл> --proof
  «Поиск в диапазоне»  доказано объявленной мерой: убывает «верх» минус «низ»
  плюс 1; мера объявлена автором, сторож считает её на каждом витке — 2 места
                                                                  код 0
```

## Что должно быть

«Поиск в диапазоне» принимает четыре параметра и объявляет меру; «Двоичный
поиск» зовёт её без счётчика. Образец в дереве —
`docs/examples/measure/binary-search.flang`.

Учесть при правке: сегодня завершение доказано статически, без проверок в
рантайме; с объявленной мерой её считает проверка в рантайме в двух местах
вызова.

## Обходной путь

Оставить как есть: функция верна, параметр-счётчик подаёт «Двоичный поиск».

## Когда задача сделана

```
grep -c 'витков' flang/stdlib/lists.flang                          0
bootstrap/flang check flang/stdlib/lists.flang                      код 0
```

Отчёт `check --proof` называет у функции «доказано объявленной мерой».
Постусловие «без витков ответа нет» и пример «Витки кончились» уходят вместе с
параметром, поэтому утверждений в файле становится 65 вместо сегодняшних 66, а
доказанных — не меньше 40: столько даёт прямое снятие параметра (сегодня 42 из
66). Второе потерянное доказательство надо назвать вслух: постусловие «в пустом
списке цель не находится» у «Двоичного поиска» держится сегодня обещанием «без
витков ответа нет» и падает в «сетка 4 значения»; переписать его границу как
«(длина элементы) меньше 1» не помогает — проверено, вердикт тот же. Поэтому
задача сделана при одном из двух, и прибор их различает: доказанных 41 из 65,
то есть у «Двоичного поиска» снова «доказано», либо доказанных 40 из 65 и в
задаче сказано, что обещание о пустом списке — цена снятия счётчика. Остальные
примеры функции проходят.

## Где живёт правка

`flang/stdlib/lists.flang`: «Поиск в диапазоне» и вызов в «Двоичный поиск».
Библиотека читается двоичным с диска, пересборка семени (bootstrap
regeneration) не нужна.
