# 3127. Проверка происхождения модулей повторяет прежнее правило поиска и краснеет на подменах, которых компилятор уже не делает

## Шаги воспроизведения

1. Игрушечное дерево с приметой корня, со своим модулем в библиотеке и с чужим
   файлом того же имени над корнем; всё — из корня дерева:

```
R=$(mktemp -d)/над
mkdir -p $R/дерево/flang/stdlib $R/дерево/scripts $R/дерево/bootstrap
printf 'модуль «JSON»\n'   > $R/дерево/flang/stdlib/json.flang
printf 'модуль «Корень»\n' > $R/дерево/root.flang
printf 'модуль «Проба»\nиспользует «JSON»\n' > $R/дерево/scripts/probe.flang
: > $R/дерево/.flangrc
cp bootstrap/flang $R/дерево/bootstrap/flang
printf 'модуль «JSON»\n'   > $R/чужой-черновик.flang
```

2. Спросить проверку и спросить сам компилятор об одном и том же файле:

```
sh scripts/guards/module-origin-guard.sh --корень $R/дерево
$R/дерево/bootstrap/flang ast $R/дерево/scripts/probe.flang 2>&1 >/dev/null | grep -c 'взят из'
```

3. Смотреть код возврата первой команды и число во второй.

## Что происходит

```
$ sh scripts/guards/module-origin-guard.sh --корень $R/дерево
МОДУЛЬ ИЗ-ЗА ПРЕДЕЛОВ ДЕРЕВА  scripts/probe.flang:2: «JSON» приедет из $R/чужой-черновик.flang
      этим перекрыто в дереве: flang/stdlib/json.flang
СБОРКА НЕ ИЗОЛИРОВАНА: мест 1.                                   код 1
$ $R/дерево/bootstrap/flang ast $R/дерево/scripts/probe.flang 2>&1 >/dev/null | grep -c 'взят из'
0                                       сам разбор отвечает кодом 0
```

Компилятор не поднимается выше корня дерева: `repl_tree_root` в
`flang/src/emit/c/flang_repl.c` находит ближайший каталог-предок с `.flangrc`,
`.git` или `flang.package`, и поиск модуля по имени на нём останавливается;
переменная `FLANG_MODULE_ROOT` называет другой предел. Убрать из того же дерева
примету корня — и разбор отвечает кодом 1 с отказом `FLANG_IMPORT_AMBIGUOUS`,
назвав оба пути. Проверка же пересчитывает правило поиска сама и по другому
правилу — поднимается, пока в предке есть файлы языка. Её проба `--подлог`
строит игрушечное дерево без приметы корня и потому тоже проверяет не то
правило, которым ищет компилятор. Записи о ней в `scripts/ledgers/uncalled-guards.json` и
`scripts/ledgers/guards-without-forgery-probe.json` описывают дефект, которого
в двоичном нет.

## Что должно быть

Проверка судит по тому же правилу, что и компилятор: на дереве с приметой корня
она отвечает кодом 0, а краснеет только тогда, когда чужой файл лежит в пределах
поиска — внутри корня дерева или под названным `FLANG_MODULE_ROOT`.

## Обходной путь

Верить пробе двоичного `flang/proof/probes/module-root/run.fscript` (она стоит
шагом в `.github/workflows/binary.yml`), а ответ `module-origin:check` не
учитывать.

## Когда задача сделана

- на дереве из шагов воспроизведения `sh scripts/guards/module-origin-guard.sh`
  отвечает кодом 0, а на втором объявлении того же имени внутри корня — кодом 1;
- `sh scripts/guards/module-origin-guard.sh --подлог` строит дерево с приметой
  корня и проходит обе стороны с кодом 0;
- проверка позвана из `.githooks/pre-push`, и записей о ней в двух названных
  файлах `scripts/ledgers` нет; строки `module-origin:check` и
  `module-origin:forgery` в `.flangrc` говорят о нынешнем правиле.

Либо проверка снята вместе с короткими командами и записями, если решено, что
пробы двоичного достаточно.

## Где живёт правка

`scripts/guards/module-origin-guard.sh` (обход каталогов и проба `--подлог`),
`.flangrc`, `scripts/ledgers/uncalled-guards.json`,
`scripts/ledgers/guards-without-forgery-probe.json`, `.githooks/pre-push`.
Двоичный не меняется, пересборка семени (bootstrap regeneration) не нужна.

Отдельная задача, здесь не решается: каталог без приметы корня ищет модули
так — поднимается до первого предка без файлов языка и молча берёт
оттуда модуль, которого нет рядом.
