# 3127. Проверка происхождения модулей повторяет прежнее правило поиска и краснеет на подменах, которых компилятор уже не делает

## Шаги воспроизведения

1. Условие: в каталоге выше корня дерева лежит файл языка, первая строка
   которого — `модуль «JSON»` (имя модуля из `flang/stdlib/json.flang`).
2. Спросить проверку и спросить сам компилятор:

```
sh scripts/guards/module-origin-guard.sh
bootstrap/flang ast scripts/site/releases.flang 2>&1 >/dev/null | grep -c 'взят из'
```

3. Смотреть код возврата первой команды и число во второй.

## Что происходит

```
$ sh scripts/guards/module-origin-guard.sh
МОДУЛЬ ИЗ-ЗА ПРЕДЕЛОВ ДЕРЕВА  scripts/site/releases.flang:2: «JSON» приедет из <каталог выше дерева>/json.baseline.flang
      этим перекрыто в дереве: flang/stdlib/json.flang
… ещё пять таких мест …
СБОРКА НЕ ИЗОЛИРОВАНА: мест 6.                                   код 1
$ bootstrap/flang ast scripts/site/releases.flang 2>&1 >/dev/null | grep -c 'взят из'
0
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026.

Компилятор больше не поднимается выше корня дерева: `repl_tree_root` в
`flang/src/emit/c/flang_repl.c` находит ближайший каталог-предок с `.flangrc`,
`.git` или `flang.package`, и поиск модуля по имени на нём останавливается;
переменная `FLANG_MODULE_ROOT` называет другой предел. Два объявления одного
имени в пределах поиска дают отказ `FLANG_IMPORT_AMBIGUOUS`. Проверка же
пересчитывает правило поиска сама и делает это по-старому — поднимается, пока
в предке есть файлы языка. Её проба `--подлог` строит игрушечное дерево без
приметы корня и потому тоже проверяет прежнее правило. Записи о ней в
`scripts/ledgers/uncalled-guards.json` и
`scripts/ledgers/guards-without-forgery-probe.json` и текст ярлыка
`изоляция:проверка` описывают дефект, которого в двоичном нет.

## Что должно быть

Проверка судит по тому же правилу, что и компилятор: на описанной машине она
отвечает кодом 0, а краснеет только тогда, когда чужой файл лежит в пределах
поиска — внутри корня дерева или под названным `FLANG_MODULE_ROOT`.

## Обходной путь

Верить пробе двоичного `flang/proof/probes/module-root/run.fscript` (она стоит
шагом в `.github/workflows/binary.yml`), а ответ `изоляция:проверка` не
учитывать.

## Когда задача сделана

- `sh scripts/guards/module-origin-guard.sh` отвечает кодом 0 при чужом файле
  выше корня дерева и кодом 1 при втором объявлении того же имени внутри
  корня.
- `sh scripts/guards/module-origin-guard.sh --подлог` строит дерево с приметой
  корня и проходит обе стороны с кодом 0.
- Проверка позвана из `.githooks/pre-push`, и записей о ней в двух названных
  файлах `scripts/ledgers` нет; текст ярлыков `изоляция:проверка` и
  `изоляция:подлог` в `ярлыки.flang` говорит о нынешнем правиле.

Либо проверка снята вместе с ярлыками и записями, если решено, что пробы
двоичного достаточно.

## Где живёт правка

`scripts/guards/module-origin-guard.sh` (обход каталогов и проба `--подлог`),
`ярлыки.flang`, `scripts/ledgers/uncalled-guards.json`,
`scripts/ledgers/guards-without-forgery-probe.json`, `.githooks/pre-push`.
Двоичный не меняется, пересборка семени (bootstrap regeneration) не нужна.

Отдельная задача, здесь не решается: каталог без приметы корня ищет модули
по-прежнему — поднимается до первого предка без файлов языка и молча берёт
оттуда модуль, которого нет рядом.
