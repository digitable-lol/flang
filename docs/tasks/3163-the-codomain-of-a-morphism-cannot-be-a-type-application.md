# 3163. Концом морфизма не может быть применение параметрического типа — стрелка Клейсли «из «Номер» в «Исход» от «Заказ»» не разбирается

## Шаги воспроизведения

1. Программа:

   ```flang
   модуль «Стрелка Клейсли»

   объект «Заказ»
     номер является числом

   тип «Исход» от «Значение»
     вариант «Удалось» содержит итог: «Значение»
     вариант «Сорвалось» содержит причина: строка

   тотальная функция «Найти заказ»
     принимает номер: число
     возвращает «Исход» от «Заказ»
     вариант «Удалось» с итог равным (запись «Заказ» с номер равным номер)

   морфизм «найти» из «Заказ» в «Исход» от «Заказ»
     даёт «Найти заказ»
   ```

2. `bootstrap/flang check <файл>`.
3. Смотреть: диагностику разбора и код возврата.

## Что происходит

```
$ bootstrap/flang check стрелка.flang
FLANG_PARSE … строка 15, столбец 42: не разобрана конструкция: неожиданное 'от' —
  этим словом объявление не начинается …                              код 1
```

Версия: `flang 0.7.25`.

## Что должно быть

Концы стрелки — объекты, а объект в flang — тип (`docs/ct/spec.md`, «Что уже есть и
как ложится»); `«Исход» от «Заказ»` — тип, которым функция возвращает значение, и
`FLANG_MORPHISM_SHAPE` сверяет с ним кодомен. Стрелка категории Клейсли
`A → T B` — ровно такая стрелка, и `docs/ct/monoidal.md` описывает её псевдонимом
только потому, что иначе не пишется.

## Обходной путь

Псевдоним на каждый конец: `тип «Исход заказа» это «Исход» от «Заказ»` и
`морфизм «найти» из «Номер» в «Исход заказа»` — так в
`flang/ct/kleisli-outcome.flang`.

## Когда задача сделана

Программа из шага 1 проходит `bootstrap/flang check` с тем же ответом, что и её
запись через псевдоним; категория, перечисляющая такую стрелку, считает свою
сетку.

## Где живёт правка

Разбор концов `из … в …` у стрелки, функтора и изоморфизма (`flang/self/parser.flang`),
сверка кодомена в `flang/self/types.flang`; перепечатка семени.
