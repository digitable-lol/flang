# 3164. В проверяющей программе недостижима ветка разбора литерала с нулевым знаком и весь код «вида 6» за ней

## Шаги воспроизведения

1. Найти все места, где в `flang/proof/checker/checker.c` встречается
   переменная `есть_нуль` функции `разобрать_литерал_полно`:

```
grep -ao 'есть_нуль[^;]*;' flang/proof/checker/checker.c
grep -ac 'есть_нуль *= *1' flang/proof/checker/checker.c
grep -ac 'как_длина_без_строки\|ПР_НУЛЕВОЙ_ЗНАК' flang/proof/checker/checker.c
```

2. Смотреть: переменная заводится нулём, читается один раз и нигде не
   получает другого значения.

## Что происходит

```
$ grep -ao 'есть_нуль[^;]*;' flang/proof/checker/checker.c
есть_нуль = 0;
есть_нуль) { *знаков = зн;
$ grep -ac 'есть_нуль *= *1' flang/proof/checker/checker.c
0
$ grep -ac 'как_длина_без_строки\|ПР_НУЛЕВОЙ_ЗНАК' flang/proof/checker/checker.c
6                                                                 код 0
```

Двоичный flang в прогоне не участвует.

`разобрать_литерал_полно` возвращает 2 только при `есть_нуль`, а он всегда
ноль. Поэтому никогда не исполняются: функция `как_длина_без_строки`, ветка
`вид == 6` в `мера_а_не_значение`, причина отказа `ПР_НУЛЕВОЙ_ЗНАК` и три
места, которые её зовут. Пробы
`flang/proof/checker/tests/programs/measure-not-value-zero-character-honest.flang`
и `flang/proof/checker/tests/programs/measure-not-value-zero-character-lie.flang`
зелены, но каким путём они проходят, не установлено.

Рядом в том же файле:

- отказ в конце `шаг_вывода` перечисляет «семейства Н, П, Д, О, С, СС, В, Ч,
  Т», хотя семейства Э, Пред и Р там же разбираются;
- функции `знаков` и `длина_знаков` имеют одинаковые тела.

## Что должно быть

В независимой проверяющей программе (proof checker) нет кода, который не
исполняется ни на одном входе: её читают целиком и ей верят, а размер ограничен
храповиком `checker-code-lines` в `flang/proof/ratchets.txt`. Запаса там нет:
замер и потолок совпали на 8127 строках кода, и всякая новая строка требует
сначала снять мёртвую. Сообщение об отказе называет все семейства правил,
которые программа разбирает.

## Обходной путь

Не требуется: на вердикты мёртвый код не влияет.

## Когда задача сделана

Сделано одно из двух, кодом, а не комментарием:

1. третий исход разбора снят целиком — первая команда из шагов печатает
   0 строк, третья печатает 0 (вторая печатает 0 и до правки, ею не проверить);
2. `есть_нуль` получает единицу там, где встречен нулевой знак, и есть проба,
   которая проходит через `как_длина_без_строки` (показано тем, что при
   снятой ветке проба краснеет).

В обоих случаях `make -C flang/proof/checker пробы` отвечает кодом 0, ответы
программы на всех записях из `flang/proof/checker/tests/records` совпадают
байт в байт с ответами до правки, сообщение `шаг_вывода` называет Э, Пред и Р,
`знаков` и `длина_знаков` слиты либо у раздельности записана причина. Потолок
`checker-code-lines` в `flang/proof/ratchets.txt` опущен до нового числа строк, а
сторож С-6 отвечает кодом 0:

```
bootstrap/flang io flang/proof/tables-guard.fscript --max-steps 4000000000 --timeout 900000 -- С-6
```

## Где живёт правка

`flang/proof/checker/checker.c`: `разобрать_литерал_полно`,
`как_длина_без_строки`, `мера_а_не_значение`, `шаг_вывода`, `знаков`,
`длина_знаков`; пробы в `flang/proof/checker/tests`. Программа собирается
отдельно одним вызовом `cc`, пересборка семени (bootstrap regeneration) не
нужна.
