# 3172. Ключ типа у списка не несёт типа элемента — «список числа» и «список строки» получают один порядок

## Шаги воспроизведения

1. Прочитать тело функции «Ключ вида» в `flang/self/svoystva.flang`:

```
grep -a -A4 'если «вид» равен "named"' flang/self/svoystva.flang
```

2. Смотреть ветку `"list"`: ключ не зависит от типа элемента.
3. Проверить, доходит ли этот код до пользователя сегодня:

```
bootstrap/flang check flang/ct/crdt-merge.flang
```

## Что происходит

```
$ grep -a -A4 'если «вид» равен "named"' flang/self/svoystva.flang
  если «вид» равен "named"
    то соединить ["named:", («Строка поля» от «тип» и "name")] по ""
    иначе если «вид» равен "list"
      то "list:null"
      иначе «вид»
$ bootstrap/flang check flang/ct/crdt-merge.flang
проверено НЕ ВСЁ: в программе объявлено то, чего бинарник не судит вовсе — properties. …
flang/ct/crdt-merge.flang: проверено НЕ ДО КОНЦА — разбор, типы, завершаемость, ядро и примеры прошли
                                                                  код 2
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026.

«Ключ типа» зовут `flang/self/monotone.flang` («Найти концы») и
`flang/self/partialorder.flang` («Ключ первого входа»): по ключу ищется порядок,
объявленный на входе и на результате функции. Раз ключ у всякого списка один,
порядок, объявленный для `список числа`, находится и для `список строки`.
У «Ключ типа» и «Ключ вида» это поведение закреплено примером и
постусловием «список даёт list:null».

Двоичный объявленных свойств (порядок, монотонность) пока не проверяет вовсе и
отвечает кодом 2, поэтому на вердикты сегодня это не влияет. Влиять начнёт,
когда слой свойств попадёт в двоичный. На скольких программах дерева ключ с
типом элемента изменил бы вердикт, не измерено.

## Что должно быть

Ключ списка включает ключ типа элемента: `список числа` и `список строки`
дают разные ключи, и порядок одного не берётся для другого.

## Обходной путь

Обходного пути нет. Пока двоичный не проверяет объявленные свойства, дефект
себя не проявляет.

## Когда задача сделана

- «Ключ типа» от `список числа` и от `список строки` возвращает разные
  строки; на это стоят два примера, прежний пример «Список даёт list:null»
  и постусловие «список даёт list:null» заменены;
- завершаемость «Ключ вида» по-прежнему доказана (спуск идёт по типу
  элемента);
- снято числом, на скольких объявлениях порядка и монотонности в программах
  дерева меняется найденный порядок; если ни на одном — это число записано
  в описании изменения;
- есть проба: программа с порядком на `список числа` и монотонной функцией
  от `список строки` получает ответ «на входе порядка нет», а не проверку по
  чужому порядку.

## Где живёт правка

`flang/self/svoystva.flang`: «Ключ вида», «Ключ типа» и их примеры;
вызывающие — `flang/self/monotone.flang` и `flang/self/partialorder.flang`.
До двоичного правка доезжает только пересборкой семени (bootstrap
regeneration), а видна станет, когда слой объявленных свойств войдёт в
двоичный.
