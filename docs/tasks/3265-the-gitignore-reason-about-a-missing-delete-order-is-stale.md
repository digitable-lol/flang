# 3265. Два довода в `.gitignore` говорят «поручения «Удалить файл» в словаре нет», а оно в словаре есть

## Шаги воспроизведения

1. Спросить, где написан довод:

```
git grep -n 'в словаре ввода-вывода нет'
```

2. Спросить, есть ли поручение в словаре:

```
git grep -n 'вариант «Удалить файл»' -- docs/ct/spec.md
```

3. Прогнать наименьший план, который это поручение выдаёт. План и его времянка
   лежат вне дерева исходников:

```
mkdir -p /srv/tmp/delete-order-probe
cd /srv/tmp/delete-order-probe
printf 'есть\n' > проба-уборки.txt
cat > probe.fscript <<'EOF'
модуль «Delete order probe»

тип «Ход»
  вариант «Ждём уборку»

тотальная функция «Начать»
  возвращает «Ход»
  вариант «Ждём уборку»

тотальная функция «Дальше»
  принимает ход: «Ход», отклик: «Отклик»
  возвращает «Продолжение»
  разбор отклик
    случай вариант «Пока ничего»
      то вариант «Сделать» с поручение равным (вариант «Удалить файл» с путь равным "проба-уборки.txt") и потом равным (вариант «Ждём уборку»)
    случай вариант «Убрано»
      то вариант «Конец работы» с значение равным "поручение «Удалить файл» известно хозяину: ответ «Убрано»"
    случай вариант «Сбой» с код как код и сообщение как сообщение
      то вариант «Провал» с код равным код и сообщение равным сообщение
    случай любое
      то вариант «Провал» с код равным "FLANG_IO_ORDER" и сообщение равным "ждали ответ на уборку"

план «Проба»
  состояние «Ход»
  начинает с «Начать»
  обрабатывает «Дальше»
EOF
<путь к дереву>/bootstrap/flang io probe.fscript --plan Проба; echo $?
ls проба-уборки.txt
```

## Что происходит

```
$ git grep -n 'в словаре ввода-вывода нет' -- .gitignore
.gitignore:109:# «Удалить файл» в словаре ввода-вывода нет. Имена с точки и без «.flang»
$ git grep -n 'вариант «Удалить файл»' -- docs/ct/spec.md
docs/ct/spec.md:1024:  вариант «Удалить файл» содержит путь: строка
$ bootstrap/flang io probe.fscript --plan Проба; echo $?
{"plan":"Проба","result":"поручение «Удалить файл» известно хозяину: ответ «Убрано»","orders":1,
 "log":[{"поручение":{"variant":"Удалить файл","fields":{"путь":"проба-уборки.txt"}},
 "отклик":{"variant":"Убрано"}}]}                                       код 0
$ ls проба-уборки.txt
ls: cannot access 'проба-уборки.txt': No such file or directory         код 2
```

Первый `git grep` находит одну строку, но доводов в `.gitignore` два: во втором
слова «Удалить файл» и «в словаре» разнесены по строкам.

| место | что держится на доводе |
|---|---|
| `.gitignore`, блок `docs/benchmarks/proof-cost/.probe-bare`, `.probe-stub` | «убрать их за собой план не может — поручения «Удалить файл» в словаре ввода-вывода нет» |
| `.gitignore`, блок `docs/examples/io/.kopiya-dvoichnogo` | «Продукт прогона, а не исходник: убрать её за собой план не может — поручения «Удалить файл» в словаре ввода-вывода нет» |

Поручение в словаре есть и работает:

- объявлено в словаре: `docs/ct/spec.md`,
  `вариант «Удалить файл» содержит путь: строка`;
- показано примером документации: `docs/examples/io/temp-directory.flang`
  убирает за собой и файл, и каталог;
- выдаётся на каждом пуше: прогон `sh .githooks/pre-push` убирает этим
  поручением файлы вывода сторожей и сам временный каталог.

Удаление каталога тем же поручением тоже работает, и поручение «Завести
временный каталог» в словаре тоже есть.

## Что должно быть

Прощение в `.gitignore` держится на причине, которую можно проверить прогоном.
Либо замер убирает за собой сам и строки прощения уходят, либо довод переписан
на истинный: оба файла счёта двадцати — продукт прогона, а не исходник, и в
истории им не место независимо от того, умеет ли план их удалять.

Почему «умеет» не значит «обязан»: `.probe-bare` и `.probe-stub` переписываются
поверх при каждом прогоне, и прогон, снятый на полпути, оставит их всё равно.
Прощение в `.gitignore` нужно в любом случае — меняется только довод при нём.

## Обходной путь

Не повторять этот довод в новых местах: поручение «Удалить файл» в словаре есть.

## Когда задача сделана

Одно из двух, и в обоих случаях — прогоном.

1. **Замер убирает за собой.** После кода 0 у плана, который пишет эти файлы
   (`docs/benchmarks/proof-cost/count-20.flang`), каталог чист, а правила прощения
   убраны:

```
$ ls docs/benchmarks/proof-cost/.probe-bare docs/benchmarks/proof-cost/.probe-stub
ls: cannot access ...: No such file or directory                       код 2
$ git check-ignore -q docs/benchmarks/proof-cost/.probe-bare; echo $?
1
```

   То же для `docs/examples/io/.kopiya-dvoichnogo`.

2. **Либо довод переписан на истинный в обоих местах.** Тогда в дереве не
   остаётся ни одной строки с этим утверждением вне `docs/tasks`:

```
$ git grep -c 'в словаре ввода-вывода нет' -- ':!docs/tasks'; echo $?
1
$ git grep -c 'Удалить файл» в' -- ':!docs/tasks'; echo $?
1
```

**Проба, которая краснеет, если неправда вернётся.** Эти же два `git grep`
становятся проверкой: ноль вхождений и код 1. Чтобы она не была проверкой
пустоты, при ней обязан стоять отрицательный контроль — та же команда по образцу,
который в дереве есть (`вариант «Удалить файл»`), и он обязан находиться. Звать —
оттуда, откуда увидят: шаг CI рядом со сторожем забытых времянок (задача 1315)
либо отдельный сторож в `scripts/guards` с парной командой `:forgery`.

## Где живёт правка

`.gitignore` (два блока доводов) и — если выбран путь «убирать за собой» —
`docs/benchmarks/proof-cost/count-20.flang` с
`docs/examples/io/binary-file-round-trip.flang`. Всё читается двоичным с диска: ни
быстрый пересев, ни перепечатка самосборной части не нужны.

Словарь ввода-вывода и граница слоёв описаны в
`docs/adr/0008-layer-boundary.md`, поручения над файлами —
в `docs/adr/0006-octets-for-files.md`.
