# 3265. Четыре места в дереве говорят «поручения «Удалить файл» в словаре нет», а оно там с 23 августа 2026

## Шаги воспроизведения

1. Спросить, где написан довод:

```
git grep -n 'в словаре ввода-вывода нет'
```

2. Спросить, есть ли поручение в словаре:

```
git grep -n 'вариант «Удалить файл»' -- docs/ct/spec.md
```

3. Прогнать наименьший план, который это поручение выдаёт. План и его времянка
   лежат ВНЕ дерева исходников — класть времянку проверки в дерево и есть беда
   соседней задачи 1315 (запрос на слияние 230):

```
mkdir -p /srv/tmp/delete-order-probe
cd /srv/tmp/delete-order-probe
printf 'есть\n' > проба-уборки.txt
cat > probe.fscript <<'EOF'
модуль «Delete order probe»

тип «Ход»
  вариант «Ждём уборку»

тотальная функция «Начать»
  возвращает «Ход»
  вариант «Ждём уборку»

тотальная функция «Дальше»
  принимает ход: «Ход», отклик: «Отклик»
  возвращает «Продолжение»
  разбор отклик
    случай вариант «Пока ничего»
      то вариант «Сделать» с поручение равным (вариант «Удалить файл» с путь равным "проба-уборки.txt") и потом равным (вариант «Ждём уборку»)
    случай вариант «Убрано»
      то вариант «Конец работы» с значение равным "поручение «Удалить файл» известно хозяину: ответ «Убрано»"
    случай вариант «Сбой» с код как код и сообщение как сообщение
      то вариант «Провал» с код равным код и сообщение равным сообщение
    случай любое
      то вариант «Провал» с код равным "FLANG_IO_ORDER" и сообщение равным "ждали ответ на уборку"

план «Проба»
  состояние «Ход»
  начинает с «Начать»
  обрабатывает «Дальше»
EOF
<путь к дереву>/bootstrap/flang io probe.fscript --plan Проба; echo $?
ls проба-уборки.txt
```

Поручение не просто объявлено — оно ходит в дереве каждый день:

- объявлено в словаре: `docs/ct/spec.md:1023`,
  `вариант «Удалить файл» содержит путь: строка`;
- показано примером документации: `docs/examples/io/temp-directory.flang`
  (строки 92, 95, 108, 116) убирает за собой И файл, И каталог;
- выдаётся на каждом пуше: прогон `sh .githooks/pre-push` 2 октября 2026 (код 0
  за 52 с) выдал **22 поручения «Удалить файл» из 27 поручений прогона**, и на все
  22 хозяин ответил **«Убрано»** — 21 файл вывода сторожей и, двадцать вторым, сам
  временный каталог.

**Когда довод был верен и когда перестал.** Заметка сама называет, чем
подтверждена: «Ветка `u/schyot`, 20 августа 2026… хозяин на C —
`bootstrap/flang_repl.c`, `io_perform`: тринадцать ветвей, удаления среди них
нет». Через ТРИ ДНЯ, 23 августа 2026, коммит `ea25b467f` «Словарь ввода-вывода:
«Удалить файл» и «Завести временный каталог» — 18 поручений стало 20» завёл оба
поручения; его собственное сообщение говорит ровно о том, что заметка объявила
невозможным: «убрать за собой план не мог вовсе… Оба конца сведены». То есть
заметка была правдой, когда её мерили, и стала неправдой на третий день. Файл
заметки правили позже — `8e3faf920`, 17 сентября 2026 — но правка была
переименованием слов, а не перемером, и довод уехал дальше в `.gitignore`.

Заодно неверна и вторая половина утверждения заметки: удаление КАТАЛОГА тем же
поручением работает (это и есть двадцать второе поручение прогона хука), а
«Завести временный каталог» заведён тем же коммитом `ea25b467f`.

## Что должно быть

Прощение в `.gitignore` и заметка в `docs/zettel` держатся на причине, которую
можно проверить прогоном. Либо замер убирает за собой сам и строки прощения
уходят, либо довод переписан на истинный: оба файла счёта двадцати — продукт
прогона, а не исходник, и в истории им не место независимо от того, умеет ли план
их удалять. Заметка в `docs/zettel` — не журнал, а утверждение о языке; устаревшее
утверждение там обязано быть либо перемерено, либо помечено датой, после которой
оно неверно.

Почему «умеет» не значит «обязан»: `.probe-bare` и `.probe-stub` переписываются
поверх при каждом прогоне, и прогон, снятый на полпути, оставит их всё равно.
Прощение в `.gitignore` нужно в любом случае — меняется только довод при нём.

## Обходной путь

Читать довод как исторический и не повторять его в новых местах. Один раз он уже
был повторён: сторож забытых времянок из задачи 1315 выписал этот довод себе в
причину прощения двух файлов и был исправлен в той же ветке (`49a3e18c7`) после
того, как журнал прогона хука показал обратное.

## Когда задача сделана

Одно из двух, и в обоих случаях — прогоном.

1. **Замер убирает за собой.** После кода 0 у плана, который пишет эти файлы
   (`docs/benchmarks/proof-cost/count-20.flang`), каталог чист, а правила прощения
   убраны:

```
$ ls docs/benchmarks/proof-cost/.probe-bare docs/benchmarks/proof-cost/.probe-stub
ls: cannot access ...: No such file or directory                       код 2
$ git check-ignore -q docs/benchmarks/proof-cost/.probe-bare; echo $?
1
```

   То же для `docs/examples/io/.kopiya-dvoichnogo`.

2. **Либо довод переписан на истинный во всех четырёх местах.** Тогда в дереве не
   остаётся ни одной строки с этим утверждением:

```
$ git grep -c 'в словаре ввода-вывода нет'; echo $?
1
$ git grep -c 'Удалить файл» в'; echo $?
1
```

   Сегодня первая команда печатает три строки в трёх файлах и код 0, вторая —
   четыре строки в трёх файлах (`.gitignore:2`) и код 0.

**Проба, которая краснеет, если неправда вернётся.** Эти же два `git grep`
становятся проверкой: ноль вхождений и код 1. Чтобы она не была проверкой
пустоты, при ней обязан стоять отрицательный контроль — та же команда по образцу,
который в дереве ЕСТЬ (`вариант «Удалить файл»`), и он обязан находиться. Звать —
оттуда, откуда увидят: шаг CI рядом со сторожем забытых времянок (задача 1315)
либо отдельный сторож в `scripts/guards` с парной командой `:forgery`.

## Где живёт правка

`.gitignore` (два блока доводов), `docs/zettel/there-is-no-delete-file-order-in-the-io-dictionary.md`,
`docs/zettel/README.md`, и — если выбран путь «убирать за собой» —
`docs/benchmarks/proof-cost/count-20.flang` с
`docs/examples/io/binary-file-round-trip.flang`. Всё читается двоичным с диска: ни
быстрый пересев, ни перепечатка самосборной части не нужны.

**Цена, которую стоит знать заранее.** Переименование или снятие заметки сдвигает
число цеттелей: примета `СНЯТО … файлов docs/zettel/*.md = 726` стоит в
`docs/course/13-where-next.md:50`, `docs/course/README.md:175` и
`docs/course/00-overview.md:182`, и при каждой из них — число в прозе рядом.
Сторож `scripts/guards/prose-numbers-guard.fscript` краснеет словами «ПРИМЕТА
ОТОРВАЛАСЬ ОТ ПРОЗЫ», если правят одно без другого. Правка ТЕКСТА заметки без
смены имени файла этого числа не двигает — это самый дешёвый путь.

Словарь ввода-вывода и граница слоёв описаны в
`docs/adr/0008-layer-boundary.md`, поручения над файлами —
в `docs/adr/0006-octets-for-files.md`.
