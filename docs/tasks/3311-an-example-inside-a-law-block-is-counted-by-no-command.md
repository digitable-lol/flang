# 3311. Примера внутри блока «закон» для flang test не существует: «примеров 0» и на подлиннике, и на ложном ожидании

Задача 6752 говорит, что ложное ожидание в блоке `закон` проходит кодом 2, как
подлинник. Это так, и это полбеды. Вторая половина хуже: `flang test` на такой
программе отвечает **«примеров 0»**. Пример внутри блока `закон` не считает НИ
ОДНА команда — ни `check`, ни `test`.

И третья: ложное ожидание попадает в СЕТКУ. Сетка от него растёт, нарушений
остаётся ноль, и отчёт выглядит так, будто проверено БОЛЬШЕ, чем на
подлиннике.

## Шаги воспроизведения

1. Подлинник: `cp flang/ct/order-shipment.flang <подлинник>`
2. Проба: `sed '47s/500/777/' flang/ct/order-shipment.flang > <проба>` — строка
   47 это `ожидается запись «Отгрузка» с номер равным 500` в первом примере
   закона «номер отгрузки берётся из суммы заказа».
3. `bootstrap/flang check <подлинник>; echo $?` и то же на пробе.
4. `bootstrap/flang test <подлинник>; echo $?` и то же на пробе.
5. `bootstrap/flang check <проба> --proof; echo $?`,
   `bootstrap/flang run <проба> --function «Отгрузить заказ»; echo $?`,
   `for t in c cpp go rust java js ts elixir python csharp; do
      bootstrap/flang emit <проба> --target $t --out <кат>; echo "$? $t"; done`

## Что происходит

```
$ bootstrap/flang check <подлинник>
категория «Отгрузки»: сетка 5 значений на 3 объектах, троек стрелок 7,
                      нарушений 0 — ПОСЧИТАНО НА СЕТКЕ, не доказано     код 2

$ bootstrap/flang check <проба, 777>
категория «Отгрузки»: сетка 6 значений на 3 объектах, троек стрелок 8,
                      нарушений 0 — ПОСЧИТАНО НА СЕТКЕ, не доказано     код 2

$ bootstrap/flang test <подлинник>
<подлинник>: примеров 0, прошло 0, не прошло 0                          код 0

$ bootstrap/flang test <проба, 777>
<проба>: примеров 0, прошло 0, не прошло 0                              код 0
```

| команда | подлинник | проба 777 |
| --- | ---: | ---: |
| `check` | 2 | 2 |
| `check --proof` | 2 | 2 |
| `test` | 0 («примеров 0») | 0 («примеров 0») |
| `run --function` | 3 | 3 |
| `emit` × 10 целей (c, cpp, go, rust, java, js, ts, elixir, python, csharp) | 3 на каждой | 3 на каждой |

Ни одна из тринадцати команд не отличает ложное ожидание от истинного.

**Сетка выросла с 5 значений и 7 троек до 6 и 8.** Значение 777 в сетку взято —
значит разборщик пример видит и значения из него берёт. Не делает он одного:
не проверяет, что функция на этом входе даёт то, что обещано. Отчёт при этом
называет число больше, и читается это как «проверено шире».

## Что должно быть

1. Пример внутри блока `закон` — это пример: `flang test` его считает и
   печатает «примеров N», где N включает примеры законов.
2. Ложное ожидание даёт код 1 и называет имя закона, имя примера, ожидаемое и
   полученное.
3. Сетка законов НЕ берёт значения из примера, который сама же не проверила:
   либо пример сперва проверен, либо его значения в сетку не идут. Сегодня
   второе без первого — рост сетки от ложного ожидания.

## Обходной путь

Вынести ожидание из блока `закон` в обычный `пример` при функции, которую
закон называет: такие примеры `flang test` считает и ложное ожидание ловит
кодом 1. Блок `закон` при этом оставить без примеров — тогда он хотя бы не
растит сетку необоснованно.

## Когда задача сделана

1. `bootstrap/flang test flang/ct/order-shipment.flang` печатает «примеров 4»:
   в файле три блока `закон` (строки 44, 54, 61) и четыре примера — строки 45,
   48, 55, 62, и ВСЕ четыре лежат внутри блоков `закон`
   (`grep -n 'пример «' flang/ct/order-shipment.flang`). Сегодня эта команда
   печатает «примеров 0».
2. Проба с 777 отвечает кодом 1 и называет закон «номер отгрузки берётся из
   суммы заказа», пример «обычный заказ», ожидаемое 500, полученное 777 — или
   наоборот, смотря с какой стороны считать; важно, что оба значения названы.
3. Подлинник отвечает кодом 0 на `test` — отрицательный контроль: проверка
   отличает ложь от правды, а не краснеет на всём.
4. Сетка подлинника и сетка пробы совпадают по размеру, либо отчёт говорит,
   почему они разошлись. Сегодня они 5/7 и 6/8 без объяснения.
5. По дереву: 30 блоков `закон` в 7 файлах пересчитаны, и у каждого примеры
   считаются. Число 30 снято `git grep -c 'закон «' -- '*.flang'`.
6. Записи проверяющего переиграны — примеров в них прибавилось, и
   `scripts/guards/record-follows-its-source.fscript` зелен после пересъёмки
   654 файлов `.record`.

## Чего мы не смогли оценить

- **Сколько примеров в блоках `закон` по дереву.** Считали блоки (30 в 7
  файлах), не примеры внутри них: примеров у блока бывает несколько, и
  перечисления по вложенности мы не делали.
- **Цену правки в строках.** Где именно примеры блока `закон` теряются —
  в разборе, в сборе обязательств или в прогонщике примеров — не искали.
- **Сколько файлов дерева сменят код на `test`.** Сегодня «примеров 0» — ответ
  не только про законы; сколько из 1 125 файлов описи он касается, не мерено.
- **Правда ли сетка берёт значения ИЗ примера.** Снято косвенно: 777 в
  исходнике — сетка выросла на одно значение. Прямого прогона, который показал
  бы 777 среди значений сетки, нет: отчёт значений не печатает.

## Где живёт правка

`flang/self/parser.flang` или `flang/self/obligations.flang` (откуда примеры
блока `закон` не доходят до прогонщика), `flang/self/setoid.flang` и
`flang/self/law-oracle.flang` (сетка и её значения), `flang/self/proof.flang`
(печать), `flang/proof/checker/checker.c` (переигровка),
`scripts/ledgers/record-source-digests.tsv`.

**Требует перепечатки семени** (цена перепечатки — в `docs/reprint-ledger.tsv`).
В один день с правкой не сдаётся.
