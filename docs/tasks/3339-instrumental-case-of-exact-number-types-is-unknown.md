# 3339. Поле «является неотрицательным» и «является целым» даёт FLANG_UNKNOWN_NAME: творительный падеж понят только у числа, строки и признака

Заявка: https://github.com/digitable-lol/flang/issues/404

`поле является числом`, `строкой`, `признаком` проходят; `является целым` и `является неотрицательным` — «неизвестный тип», хотя `является неотрицательное` (именительный) проходит.

## Шаги воспроизведения

1. Программа `field.flang`:

```flang
модуль «P»

объект «А»
  поле является неотрицательным
```

2. `bootstrap/flang check field.flang`.

## Что происходит

```
$ bootstrap/flang check field.flang
field.flang: не проверено — замечаний 1
FLANG_UNKNOWN_NAME в файле field.flang, строка 3, столбец 1: неизвестный тип «неотрицательным»
код 1
```

Версия: flang 0.7.28 (`bootstrap/flang` из дерева).

## Что должно быть

Творительный падеж понимается у всех встроенных типов: `целым`, `неотрицательным`, `сотых`/`тысячных` и прочих точных.

## Обходной путь

`поле: неотрицательное`.

## Когда задача сделана

`bootstrap/flang check field.flang` — код 0; то же для `целым`.

## Где живёт правка

`flang/core/parser.flang` — таблица «Перевод» падежей типов, и её двойник в разборе `flang/self`. Ждёт печати семени.

## Правка

Причина: имя типа поля читалось как написано, и `неотрицательным` искалось
среди объявленных типов. «Тип именем» в `flang/self/parser.flang` переводит
творительный падеж точных числовых имён в именительный («Именительный падеж
числового типа», правила `разбор`): `целым`, `неотрицательным`, `натуральным`,
`весом`, `стоимостью`. `сотых` и `тысячных` пишутся одинаково в любом падеже
поля и правила не требуют. Поправка стоит в разборщике `flang/self`; таблица
«Перевод» в `flang/core/parser.flang` относится к старой поверхности FTS, её
разбор этой программы не касается.

Проба `flang/proof/probes/parse-and-import`, строки
`field-type-nonnegative-instrumental.flang` и `field-type-integer-instrumental.flang`:
двоичный 0.7.28 — `FLANG_UNKNOWN_NAME`, код 1. Исходный компилятор (`bootstrap/flang run flang/self/bootstrap/check-with-source-compiler.flang` по исходникам ветки (свой вход на несколько файлов, `--trust`), 16 октября 2026):
«ГОДНО» на обеих.
