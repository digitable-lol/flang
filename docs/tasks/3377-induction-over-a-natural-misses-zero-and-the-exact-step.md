# 3377. Индукция по «неотрицательное» не подставляет 0 на дне и не сводит (н минус 1) плюс 1 к н на спуске

Заявка: https://github.com/digitable-lol/flang/issues/410

На дне `сколько не больше 0` у `неотрицательное` значит `сколько = 0`, но ядро свободное `сколько` не заменяет. На спуске после переписки допущением остаётся `1 + (сколько − 1)` против `сколько` — точное равенство на отрезке [0, 2^53−1] при `сколько ≥ 1`.

## Шаги воспроизведения

1. Программа zeros.flang:

```flang
модуль «LengthProbe»

тотальная функция «Нули»
  принимает сколько: неотрицательное
  возвращает список число
  обеспечивает «ровно столько» (длина результат) равно сколько
  пример «ноль нулей»
    дано сколько равно 0
    ожидается []
  пример «три нуля»
    дано сколько равно 3
    ожидается [0, 0, 0]
  если сколько не больше 0
    то []
    иначе добавить 0 к («Нули» от (сколько минус 1))

теорема «ровно столько»
  дано сколько: неотрицательное
  утверждаем (длина результат) равно сколько
  индукция по сколько убывает сколько
    случай 0
      то по примеру «ноль нулей»
    случай любое
      то по предположению
  следовательно доказано
```

2. `bootstrap/flang check zeros.flang --proof`.

Версия: flang 0.7.28 (`bootstrap/flang` из дерева).

## Что должно быть

На дне индукции по `неотрицательное` подставляется 0; на спуске известно `(н минус 1) плюс 1 = н` при `н ≥ 1`.

## Обходной путь

Нет.

## Когда задача сделана

`bootstrap/flang check zeros.flang --proof` — «ровно столько» доказано, код 0. Подделка `(длина результат) равно (сколько плюс 1)` — не доказано.

## Где живёт правка

`flang/self/proof-initial.flang` (принцип по отрезку), `flang/self/proof-kernel.flang`. Ждёт печати семени.

## Чем закрыта

Ветка `a/kernel-proof-chains-0731`, коммиты `feat(kernel): one down and one up is the same
natural` и `feat(checker): both checkers replay one down and one up in a descent`, ADR-0188.
На спуске `(н минус 1) плюс 1` и `1 плюс (н минус 1)` ядро сводит к `н` у имени,
объявленного `неотрицательное`, при известном `н больше 0` (правило Тожд5); оба сверщика
переигрывают его в посылке «спуск» индукции формой (семья `one-down-one-up`: честная — 0,
ложный сосед `равен (а плюс 1)` — 1 в обоих). Проба исходным компилятором
(`check-with-source-compiler.flang`, 21 октября 2026): `count.flang` семьи — «доказано
индукцией по «неотрицательное»». 0 на дне не подставляется: `неотрицательное` при работе
принимает −0 (`0 умножить на -1`), `равен` его отличает от 0, и `(длина («Нули» от −0))
равно −0` — нет; `zeros.flang` заявки на дне по-прежнему отказ, теперь с этим объяснением.
Подделка `равно (сколько плюс 1)` — тот же отказ. Ждёт печати семени.
