# 3401. Сборку пакета командой flang package не проверяет ни одна проба, и пакеты примера реестра не пересобраны

## Шаги воспроизведения

1. Найти проверку, которая зовёт сборку пакета:

```
grep -c 'flang package' ярлыки.flang
git ls-files | grep -i package | grep -i -E 'probe|guard|test'
```

2. Собрать пакет руками в пустом каталоге и ввезти его чужой программой:

```
flang new proba
cd proba && flang package proba.flang > ../proba.flang-package
```

```flang
модуль «Гость»
  использует «Proba» из "proba.flang-package"

тотальная функция «Привет»
  возвращает строка
  «Поприветствовать» от "Мир"
```

```
flang check <файл программы «Гость»>
```

## Что происходит

```
$ grep -c 'flang package' ярлыки.flang
0                                                                 код 1
$ git ls-files | grep -i package | grep -i -E 'probe|guard|test'
scripts/guards/no-package-json-guard.fscript
$ flang new proba
flang new: пакет «proba» создан в …                               код 0
$ flang package proba.flang
{"схема":2,"имя":"Proba","версия":"0.1.0","вход":"./proba.flang",…  код 0
$ flang check <файл программы «Гость»>
модуль «Гость»: функций 2, …; файлов вместе с импортами 2
… проверено — …; замечаний нет                                    код 0
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026.

Сама команда работает: пакет собирается и ввозится. Раньше она отвечала
отказом `FLANG_TYPE` на любом входе, потому что `pkg_ledger` в
`flang/src/emit/c/flang_repl.c` звала функцию компилятора «Прогоны для ядра»
одним аргументом вместо двух, и этого никто не видел: сборку пакета не зовёт
ни одна проверка дерева. Единственный найденный файл проверяет другое —
отсутствие package.json. Так остаётся и сегодня.

Семь пакетов в `scripts/registry-example` собраны до починки. Их отчёты о
доказанном с ответом сегодняшней команды не сверены. Не перепроверено:
исходники этих пакетов лежат только внутри самих файлов пакетов.

## Что должно быть

`docs/zero-bug-policy.md`: у починенного дефекта остаётся проба, которая
краснеет, если он вернётся. Справка `flang package --help` обещает, что пакет
собирается из проверенной программы и подключается одной строкой
`использует … из`.

## Обходной путь

Прогонять шаги воспроизведения руками перед выпуском.

## Когда задача сделана

В дереве есть проверка с ярлыком в `ярлыки.flang`, которая во временном
каталоге делает `flang new`, `flang package` и ввоз получившегося пакета
чужой программой и отвечает кодом 0. Она краснеет, если в `pkg_ledger`
вернуть вызов с одним аргументом; проба порчи записана в
`scripts/ledgers/guards-without-forgery-probe.json`.

Семь пакетов `scripts/registry-example` пересобраны сегодняшней командой, и
раздел «ведомость» каждого либо совпал с записанным, либо расхождение названо
поимённо.

## Где живёт правка

Новая проверка — файл в `scripts/guards` и запись в `ярлыки.flang`; ей нужен
собранный двоичный и каталог `fspec` рядом с ним, иначе `flang new` не находит
образец. Пересборка семени (bootstrap regeneration) не нужна.

Отдельная задача, здесь не решается: на `docs/examples/package/discount.flang`
команда отвечает `FLANG_PACKAGE`, потому что имя в объявлении пакета и имя
модуля разошлись, — задача 3402.
