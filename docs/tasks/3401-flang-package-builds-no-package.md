# 3401. Сборку пакета командой flang package не проверяет ни одна проба, и пакеты примера реестра не пересобраны

## Шаги воспроизведения

1. Найти проверку, которая зовёт сборку пакета:

```
grep -c 'flang package' .flangrc
git ls-files | grep -i package | grep -i -E 'probe|guard|test'
```

2. Собрать пакет руками в пустом каталоге и ввезти его чужой программой:

```
bootstrap/flang new proba
cd proba && <двоичный> package proba.flang > ../proba.flang-package
```

```flang
модуль «Гость»
  использует «Proba» из "proba.flang-package"

тотальная функция «Привет»
  возвращает строка
  «Поприветствовать» от "Мир"
```

```
<двоичный> check <файл программы «Гость»>
```

3. Поискать в дереве исходники пакетов примера реестра:

```
grep -rl '^модуль «Логика»' --include='*.flang' .
```

## Что происходит

```
$ grep -c 'flang package' .flangrc
0                                                                 код 1
$ git ls-files | grep -i package | grep -i -E 'probe|guard|test'
scripts/guards/no-package-json-guard.fscript                      код 0
$ bootstrap/flang new proba
flang new: пакет «proba» создан в …                               код 0
$ flang package proba.flang
{"схема":2,"имя":"Proba","версия":"0.1.0","вход":"./proba.flang",…  код 0
$ flang check <файл программы «Гость»>
модуль «Гость»: функций 2, …; файлов вместе с импортами 2
… проверено — …; замечаний нет                                    код 0
$ grep -rl '^модуль «Логика»' --include='*.flang' .
                                                                  код 1
```

Команда работает на каждом шаге, и ни один шаг не зовёт проверка дерева. Ни одна
строка `script.*` в `.flangrc` не несёт слов `flang package`.
Единственный файл, который находит поиск, проверяет другое — отсутствие
`package.json`.

Пакетов в `scripts/registry-example` семь, схема у всех 2 — та же, что печатает
сегодняшняя команда. С ответом команды не сверен ни один: раздел «ведомость» у
них от 7 до 39 строк. Исходников этих пакетов в дереве нет — ни одного файла
`*.flang` с модулями «Логика», «Списки», «Множество строк», «Опциональное
значение», — поэтому пересобрать пакет можно только исходником из самого файла
пакета.

## Что должно быть

`docs/zero-bug-policy.md`: у починенного дефекта остаётся проба, которая
краснеет, если он вернётся. Справка `flang package --help` обещает, что пакет
собирается из проверенной программы и подключается одной строкой
`использует … из`.

## Обходной путь

Прогонять шаги воспроизведения руками перед выпуском.

## Когда задача сделана

В дереве есть проверка со строкой `script.<имя>:check` в `.flangrc`, которая во
временном каталоге делает `flang new`, `flang package` и ввоз получившегося
пакета чужой программой и отвечает кодом 0. Она краснеет, если в `pkg_ledger`
(`flang/src/emit/c/flang_repl.c`) вернуть вызов с одним аргументом; проба порчи
записана в `scripts/ledgers/guards-without-forgery-probe.json`.

Семь пакетов `scripts/registry-example` пересобраны сегодняшней командой, и
раздел «ведомость» каждого либо совпал с записанным, либо расхождение названо
поимённо.

## Где живёт правка

Новая проверка — файл в `scripts/guards` и строка `script.<имя>:check` в
`.flangrc`; ей нужен собранный двоичный и каталог `fspec`: `flang new` ищет
образец в `$FLANG_FSPEC_TEMPLATE_DIR` и в `<каталог двоичного>/../fspec`, а не
найдя — отвечает `FLANG_NEW` кодом 1. Пересборка семени (bootstrap
regeneration) не нужна.

Отдельная задача, здесь не решается: на `docs/examples/package/discount.flang`
команда отвечает `FLANG_PACKAGE`, потому что имя в объявлении пакета и имя
модуля разошлись, — задача 3402.
