# 3403. Установщика пакетов нет: нужды проекта негде записать, и пакет из сети не ставится одной командой

## Шаги воспроизведения

1. Спросить у двоичного команду установки:

```
bootstrap/flang install
```

2. Посмотреть, какие части уже лежат в дереве и что над ними есть:

```
ls flang/stdlib/registry.flang scripts/registry-tool.fscript scripts/registry-example
grep -c '^план «' scripts/registry-tool.fscript
grep -c 'install' .flangrc
```

## Что происходит

```
$ bootstrap/flang install
flang: неизвестная команда «install». «flang --help» — что умеет бинарник.   код 2
$ grep -c '^план «' scripts/registry-tool.fscript
4                                                                            код 0
$ grep -c 'install' .flangrc
1                                                                            код 0
```

Части есть по отдельности: разбор версий и диапазонов с транзитивным
разрешением (`flang/stdlib/registry.flang`), четыре плана над реестром
(`scripts/registry-tool.fscript`: «Найти», «Разрешить», «Сверить отпечатки»,
«Собрать реестр»), пример реестра с семью пакетами (`scripts/registry-example/`),
поручение «Запросить» для https (`docs/examples/io/https-request.flang`),
встроенная форма `хеш256`, команды `flang lock` и `flang package`.

Снято 2026-10-11 на flang 0.7.25: команды `install` по-прежнему нет (код 2),
планов в `registry-tool.fscript` 4, строка со словом `install` в `.flangrc` одна.
С тех пор написано предложение [ADR-0059](../adr/0059-the-registry-is-a-ledger-of-names-not-a-store-of-code.md)
(«реестр — ведомость имён, а не склад кода»; владельцем не рассмотрено): оно
кладёт код на задачи 2031 (замок записывает зависимость от реестра), 6990 (поле
«нужды» в `flang.package`) и 4909 (сторож разрешения версий). Установщика как
одной команды ни одна из них не даёт — эта задача остаётся над ними.

Формат перечня нужд разбирается и показан: `scripts/registry-example/request.needs`
— одна строка «Множество строк: не ниже 1.1», и план «Разрешить» её читает.
Чего нет — файла нужд рядом с программой проекта и плана, который прошёл бы от
такого файла до записанного замка. Единственная строка `script.*` в
`.flangrc` со словом `install` — `script.install-path:check`, она про путь
установки двоичного, а не про пакеты.

## Что должно быть

ADR-0021 (`docs/adr/0021-packages-are-installed-over-the-network-and-locked-locally.md`):
установщик — программа на flang в `scripts/`, язык не меняется. Одна команда:

1. читает файл нужд проекта рядом со входным файлом программы, в том формате,
   который уже разбирает `flang/stdlib/registry.flang`
   («Логика: не ниже 1.0.0; Списки: в пределах 1.x»), и адреса источников;
2. разрешает версии;
3. скачивает каждый пакет поручением «Запросить»;
4. считает отпечаток тела встроенной формой `хеш256` и сверяет с ожидаемым
   (сегодня `scripts/registry-tool.fscript` зовёт внешний `sha256sum` поручением
   «Запустить процесс», и под `--no-spawn` сверка невозможна);
5. кладёт файл в каталог внутри проекта, работает под `--in-dir`;
6. запускает `flang check` над программой с этим пакетом;
7. только после этого дописывает замок командой `flang lock`.

Служба реестра в сети и подпись автора в задачу не входят; в описании
установщика прямо сказано, что подписи нет, сертификат узла проверяет внешний
`curl`, а отзыв сертификата не проверяется.

## Обходной путь

Принести файл пакета руками, положить рядом с программой и выполнить
`bootstrap/flang lock <файл>`.

## Когда задача сделана

Сквозной прогон на файловом реестре, каждая строка — команда с кодом возврата:

- пакет A зависит от B; A ставится одной командой, код 0; повторная установка
  даёт тот же отпечаток;
- после установки сборка проходит с `--no-net`;
- подменённое тело ответа даёт отказ с ненулевым кодом, и файла на диске не
  остаётся;
- при установке печатается доля доказанного каждого пакета из его отчёта о
  доказательствах;
- пакет с `закон` или с «объявлено, не доказано» показан отдельной строкой и
  ставится только при явном согласии.

Подменённое тело и пакет с законом лежат в дереве как пробы и краснеют, если
проверка отпечатка или согласие пропадут.

## Где живёт правка

Новый сценарий в `scripts/` по образцу `scripts/registry-tool.fscript`;
`flang/stdlib/registry.flang` — адрес источника; строка `script.<имя>` в
`.flangrc`; страница в `docs/site/`. Компилятор не меняется, пересборка семени
(bootstrap regeneration) не нужна.

## Чем закрыта

Ветка `a/install-a-package-by-name-from-the-registry`, 24 октября 2026, двоичный
дерева 0.7.30. Решение — [ADR-0168](../adr/0168-a-package-is-installed-by-name-by-a-plan-and-not-by-the-binary.md).

- Установщик — `scripts/package-install.fscript`, план «Поставить», ярлык
  `script.package:install` в `.flangrc`. Нужды проекта — файл `flang.needs`
  рядом с программой; имена из команды дописываются в него после установки.
- Пять строк приёмки, прогон сторожа `scripts/guards/package-install-guard.fscript`
  (`package-install:check`, 64 шага, код 0 по файлу дерева и по
  `http://127.0.0.1:18765/registry.list`):
  - «Множество строк: не ниже 1.1» тянет «Списки» и «Логику»: одна команда, код 0;
    вторая установка в пустой каталог — тот же `flang.lock` знак в знак (111 100 байт);
  - после установки файлы пакетов удалены, `flang check` собирает программу из
    одного замка — код 0, в сеть не ходит;
  - подменённое тело (`packaging/registry/cases/install/substituted.list`) —
    `FLANG_INSTALL_FINGERPRINT`, код 1, файла на диске нет;
  - доля доказанного печатается у каждого пакета («доказано 4 из 18 обязательств»);
  - пакет с законом (`law.list`) без ключа — `FLANG_INSTALL_UNPROVED`, с
    `--accept-unproven` — код 0.
- Подлог в дереве: план `Forgery` того же сторожа читает `substituted-forged.list`
  с подогнанным отпечатком и краснеет кодом `FLANG_INSTALL_PROBE`; работа CI
  `package-install` сперва требует этого красного, потом зелёного прогона.
- Четыре пакета образца пересобраны (их не читал двоичный дерева: «адрес модуля
  не сходится»), адреса списка стали относительными каталогу списка
  (`docs/registry-ledger-format.md`).

Не сделано и названо: `--in-dir` установщик не держит (проект лежит вне каталога
плана); команды двоичного `flang install` нет — задача 3404; изоляция поиска
модулей (ADR-0021 п. 5) не тронута.

## Прежний следующий шаг

Дождаться решения владельца по ADR-0059 (оно меняет, что именно скачивается: файл
пакета или имя из ведомости), затем завести `scripts/package-install.fscript` с
планом «Поставить» над файловым реестром `scripts/registry-example/` — шаги 1, 2, 4,
5 и 7 из раздела выше работают без сети. Проба, которая краснеет сегодня: пакета A,
зависящего от B, в примере реестра нет, и ни одна команда дерева не доходит от
`request.needs` до записанного замка.
