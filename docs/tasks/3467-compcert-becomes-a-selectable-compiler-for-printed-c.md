# 3467. CompCert как выбираемый компилятор напечатанного C

Замер задачи 1402 (14 сентября 2026, CompCert 3.18, ствол `bdce1f75`): напечатанный C
собирается CompCert, и собранное отвечает байт в байт как собранное `cc` (253 программы
дерева из 255 напечатанных; 11 475 примеров и 56 987 граничных вызовов на 248 из них; сам
компилятор — ведомости, AST всех 302 файлов и печать в четыре цели). Мешает не печатник, а
рантайм, уезжающий в вывод дословно.

## Что мешает поимённо

1. **Кириллица в идентификаторах C** — расширение GCC/Clang, в C99 не входит (там только
   `\uXXXX`), а CompCert не читает и `\uXXXX`: препроцессор GCC превращает такое имя
   в `\U0000043a…`, и лексер CompCert падает с `invalid symbol '\'`. Мест четыре:
   - `flang/src/emit/c/flang_runtime.c:646–648` — `измерено` (3 употребления);
   - `flang/src/emit/c/flang_runtime.c:4590–4593` — `конец` (3), `ведущий` (2);
   - `flang/src/emit/c/flang_repl.c:11907–11950` — `поток` (12, одна функция `ast_pretty_to`).

   Переименовать в латиницу **только имена**. Те же слова стоят в текстах, и их
   трогать нельзя, иначе поменяется вывод: `конец` — в двух сообщениях
   `«подстрока»` (`flang_runtime.c:4349, 4363`) и в справке оболочки
   (`flang_repl.c:278, 287, 996`), `поток` — в трёх строках справки
   (`flang_repl.c:373, 699, 12092`). Замена по всему файлу это и сделала в первом
   заходе замера 1402. Точная замена меняет 7 строк рантайма и 12 строк оболочки,
   ответы от этого не меняются (проверено копией вне дерева, скрипт `latin.py`
   в каталоге замера).
2. **Ключи ccomp**, без которых не собирается ни один файл:
   `-fstruct-passing` (значения `fl_value` ходят по значению — так печатает печатник, это
   не правится дёшево), `-flongdouble` (`long double` только в `union fl_align` для
   выравнивания и внутри макросов `isnan/isinf/isfinite/signbit` из glibc — семантика не
   меняется), `-Wno-c11-extensions` (анонимное объединение в `<sys/resource.h>` glibc),
   `-Wno-unknown-pragmas` (`stdint.h` GCC 15, только `flang_conc.c`),
   `-Wno-literal-range` (`HUGE_VAL` = `1e10000` в glibc под не-GCC компилятором, только
   `flang_conc.c`). Ключи Makefile `-Wextra -pedantic -flto` ccomp не знает:
   первый пропускает с предупреждением, два других — ошибка. То же с ключами CI
   (`FLANG_CFLAGS` в `.github/workflows/binary.yml`): там `-flto=auto`, и это тоже ошибка
   `Unknown option`.

## Что сделать

1. Четыре имени — латиницей (правка `flang/src/emit/c/**`, печатник не трогается;
   `flang_repl.c` и `flang_runtime.c` уезжают в семя дословно — понадобится перепечатка
   или пересев, см. `docs/tasks/completed/4088-runtime-c-seed-equals-source-plus-nine-header-lines.md`).
2. В шапку напечатанного `Makefile` (её печатает `flang/self/emit-c.flang`) — строку с
   набором ключей для ccomp, чтобы `make CC=ccomp CFLAGS='…'` не приходилось подбирать.
   Сам Makefile менять не надо: `make CC=ccomp CFLAGS='-std=c99 -Wall -Werror -O2
   -fstruct-passing -flongdouble -Wno-c11-extensions -Wno-unknown-pragmas -Wno-literal-range'`
   собирает напечатанную программу как есть (проверено на `quicksort`).
3. Работа CI, собирающая семя `ccomp` и гоняющая `flang test --ledger` по
   `docs/examples` со сверкой ведомости с cc-сборкой. Цена: `compiler_flang.c` под ccomp —
   280–286 с и пик 3,0 ГиБ на AMD EPYC (два замера 14 сентября), установка CompCert
   через opam — 8 мин 48 с.

## Чего это не даёт

Ключ `-fstruct-passing` включает проход `cparser/StructPassing.ml` — он в
непроверенной части CompCert (разбор и преобразование до проверенного ядра). Теорема
CompCert покрывает C → машинный код после этого прохода; передача `fl_value` по
значению остаётся на доверии к OCaml-коду. Считать «второе место доверия закрыто
теоремой целиком» нельзя, пока печатник печатает структуры по значению; снятие этого
в печатнике — отдельная работа, цена не измерена.

## Как поймём, что сделано

```
sh -c 'cd bootstrap && make CC=ccomp CFLAGS="…набор из п.2…"'   # код 0, без копий вне дерева
./bootstrap/flang test docs/examples/rosetta --ledger | cmp - <ведомость cc-сборки>   # код 0
```
