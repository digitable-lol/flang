# 3593. Доля доказанного падает на коде, который трогает мир

Ведомость `scripts/ledgers/proved-share-ledger.txt` считает долю доказанного по дереву
одним числом и по файлам. По разделам прикладного кода её не считает никто, и потому
не видно, что разброс внутри `docs/examples` больше, чем между библиотекой и примерами.

## Шаги воспроизведения

1. Пересчитать ведомость по подкаталогам `docs/examples`:

```sh
awk -F'|' 'NF>=7 && $7 ~ /^docs\/examples\// {p=$7; sub(/^ +/,"",p); split(p,a,"/");
  k=a[3]; w[k]+=$2; d[k]+=$3} END{for(k in w) printf "%-14s %4d %4d %5.1f%%\n",
  k,w[k],d[k],100*d[k]/w[k]}' scripts/ledgers/proved-share-ledger.txt | sort -k4 -rn
```

2. Поискать эти доли в документации: `grep -rn 'leetcode' docs/*.md`.

## Что происходит

Разряды ведомости — «написано | доказано | сетка | объявлено | без приговора».
Доли доказанного по `awk` из шага 1, снято 2026-10-11 (выборка разделов; всего их 26):

| где | написано | доказано | доля |
|---|---:|---:|---:|
| `docs/examples/leetcode` | 255 | 252 | 98,8 % |
| `docs/examples/guide` | 27 | 25 | 92,6 % |
| `docs/examples/rosetta` | 81 | 72 | 88,9 % |
| `docs/examples/https` | 125 | 110 | 88,0 % |
| `docs/examples/driver` | 318 | 282 | 88,7 % |
| `docs/examples/web` | 148 | 94 | 63,5 % |
| `docs/examples/io` | 66 | 42 | 63,6 % |
| `docs/examples/crypto` | 153 | 93 | 60,8 % |
| `docs/examples/wal` | 51 | 21 | 41,2 % |
| `docs/examples/db` | 243 | 36 | 14,8 % |
| `docs/examples/usage` | 10 | 1 | 10 % |
| `docs/examples/paths` | 21 | 0 | 0 % |
| `docs/examples/money` | 12 | 0 | 0 % |

Ведомость целиком тем же днём (`proved-share-tree:check`, код 0, 13 с): файлов с
обязательствами 972, строк в описи 1140. Сравнение с `flang/self` и `flang/stdlib`
при заведении задачи давало 65,4 % и 54,3 % против 69,8 % по `docs/examples`;
сегодня не переснято — считать той же `awk` по приставке пути.
Разброс лежит не между автором-человеком и автором языка, а между алгоритмом (98,8 %) и
работой с миром — хранилищем, путями, деньгами, вызовами наружу (0…15 %).

Набор из 14 программ `user-programs` (84,8 %) этого разброса не показывает: в нём нет ни
одного файла, который трогает мир. Переносить его долю на прикладной корпус нельзя.

`grep -rn 'leetcode' docs/*.md` — ни одна страница про доказуемость этих разделов не
говорит; разбор по разделам существует только как пересчёт ведомости руками.

## Что должно быть

Ведомость (или отдельный план при ней) печатает долю доказанного по разделам прикладного
кода, и страница в `docs/` называет, чем именно упирается доказатель на работе с миром:
какое обязательство в `docs/examples/db` не доказывается и какого правила для него нет.
Пока разбора нет, вопрос «доказывается ли код кодера» получает ответ по набору из 14
программ, в котором мира нет вовсе.

## Обходной путь

Пересчитывать ведомость `awk`-ом, как в шагах воспроизведения.

## Когда задача сделана

План при ведомости печатает таблицу долей по разделам, и прогон на `docs/examples/db`
называет числом, сколько из 243 написанных обязательств не доказано и по какой причине
каждое. Проба краснеет, если доля раздела упала.

## Где живёт правка

`scripts/ledgers/proved-share-ledger.txt` и план, который его считает
(`scripts/guards/proved-share-vs-tree.fscript`), новая страница в `docs/`.

## Следующий шаг

`scripts/guards/proved-share-vs-tree.fscript`: завести план «Разделы», который группирует
строки описи по третьему звену пути под `docs/examples/` и печатает таблицу выше; затем
прогнать `bootstrap/flang check` по 18 файлам `docs/examples/db` с `--proof` и выписать
причину каждого из 207 недоказанных обязательств. Проба, которая краснеет сегодня:
в `.flangrc` нет ярлыка, печатающего доли по разделам, — таблицу даёт только `awk`.
