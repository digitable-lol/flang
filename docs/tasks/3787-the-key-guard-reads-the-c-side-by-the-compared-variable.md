# 3787. Сторож ключей читает сторону C по переменной сравнения

## Шаги воспроизведения

1. Спросить двоичный и эталон про `--step-limit`:

```
bootstrap/flang --help | grep -- '--step-limit'
bootstrap/flang check --step-limit docs/examples/guide/walk-tree.flang
grep -n 'Числовые ключи' -A 6 flang/self/cli.flang
```

2. Спросить сторожа ключей:

```
bootstrap/flang io flang/scripts/cli-keys-guard.fscript --max-steps 200000000 --timeout 600000
```

## Что происходит

Обе стороны согласны, что ключ берёт число: справка двоичного печатает
`--step-limit N`, без числа двоичный отвечает «не названо число шагов», а эталон
`flang/self/cli.flang` держит ключ в «Числовые ключи» и говорит
`--step-limit требует число`. Сторож при этом объявляет расхождение:

```
✘ разряд-3-значение: ключ есть у обоих, но «берёт значение» расходится
  НОВОЕ РАСХОЖДЕНИЕ: --step-limit
  НОВОЕ РАСХОЖДЕНИЕ: --предел-шагов
```

Причина — в чтении стороны C. Сторож (`«Берёт значение»`) ищет счётчик **рядом с
переменной сравнения**: `<счётчик> + 1 < argc` или `<счётчик> +=`. А три ветви в
`flang/src/emit/c/flang_cli.c` сравнивают не `argv[i]`, а местную копию:

```c
const char *word = argv[read];
if (strcmp(word, "--предел-шагов") == 0 || strcmp(word, "--step-limit") == 0) {
  …
  read += 2;
```

Счётчик здесь `read`, а переменная сравнения — `word`, и рядом с `word` ничего
нет. Таких ветвей в файле **ровно три**, и это ровно те ключи, на которых сторож
спотыкается: `--предел-глубины`/`--depth-limit`, `--предел-шагов`/`--step-limit`,
`--предел-памяти`/`--memory-limit`. Остальные 64 ключа написаны иначе, и их
сторож читает верно.

## Что должно быть

Сторона C читается так, что ветвь с местной копией довода видна: счётчик берётся
из ветви, а не из имени сравниваемой переменной. После этого `--step-limit` и
`--предел-шагов` уходят из ведомости долга — у них расхождения нет.

## Обходной путь

Записать в ведомость `flang/scripts/cli-keys-debt.json` разделом
`разряд-3-значение` с доводом, что расходятся не реализации, а чтение сторожа.
Так ведомость и устроена сейчас.

## Когда задача сделана

Сторож отвечает кодом 0 **без** записей `--предел-шагов` и `--step-limit` в
`разряд-3-значение`, а подложенная пара «ключ берёт значение / не берёт»
по-прежнему краснеет. Разряд проверяется пробой с двух концов.

## Где живёт правка

`flang/scripts/cli-keys-guard.fscript`, функция `«Берёт значение»` и её окно
ветви. `flang/src/emit/c/flang_cli.c` править не нужно: три ветви с местной
копией — законный C, и переписывать их ради удобства сторожа было бы той же
породой, что подгонять дерево под прибор.
