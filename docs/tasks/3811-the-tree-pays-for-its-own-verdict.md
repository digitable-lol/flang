# 3811. Своё дерево судится своим же вердиктом

## Чем измерено

18 сентября 2026, ветка `a/partiya-2-semeni`, двоичный из семени партии №2 с правкой
хозяина (задача 6427). Первое, что сказал двоичный после правки:

```
$ ./ярлык
ярлыки этого дерева (список — в ярлыки.flang):

не доказано: утверждений 17: доказано 14, сетка 3, на веру 0 — запуск только по явному
согласию: --на-веру
```

То есть **точка входа этого репозитория не проходит вердикта, который сама же и
принесла**. Ровно три постусловия в `ярлыки.flang` стоят на сетке — их ядро не выводит,
а примеры автора доказательством не считаются (`flang check ярлыки.flang --proof`,
строки 59, 64, 65 вывода):

| функция | постусловие |
|---|---|
| «Судит о доказательствах» | «названный судьёй ярлык существует» |
| «Слово о файле» | «файл узнан только по трём окончаниям» |
| «Слово о файле» | «всякое из трёх окончаний узнано» |

Два последних, если написать их без слов, — это `результат → Д` и `Д → результат` при
теле функции, равном ровно `Д`. После подстановки тела это `¬Д ∨ Д` — тавтология, и
ядро её сегодня не узнаёт. Заметка на будущее: одно правило «после подстановки тела цель
стала тавтологией» сняло бы оба места и, судя по замеру ниже, ещё сколько-то в дереве.
Правило это живёт в ядре, а ядро едет в двоичный только перепечаткой (11 часов), — в
этот выпуск оно не попадёт.

## Что делаем

1. У каждого вызова инструмента, который вердикта не проходит, в командной строке стоит
   `--на-веру` — поимённо, видимо, в том же месте, где стоит сам вызов.
2. Список таких инструментов лежит ведомостью `flang/scripts/run-verdict-debt.tsv`:
   файл, слово вердикта, сколько секунд стоит вердикт, чем и когда снято.
3. Сторож `scripts/guards/run-verdict-debt-guard.sh` сверяет ведомость с деревом в обе
   стороны: у записанного файла каждый вызов обязан называть ключ, у незаписанного — не
   обязан называть его нигде. Надгробие (долг закрыт, запись осталась) — тоже красное.
4. Ведомость — храповик: число записей растёт только решением overagent'а с доводом.

### Долг уменьшен на один: `scripts/guards/child-timeout.fscript`

Из 51 записи это была самая дешёвая: `утверждений 4: доказано 3, сетка 1`. Единственное
утверждение на сетке названо прогоном `flang check … --proof`:

```
постусловие «беда начинается с того, зачем ставился опыт» функции «Про беду»
  — сетка 1 значение (примеры функции): нарушений НЕ ИСКАЛИ
```

Причина, по которой ядро его не выводило, стоит в ведомости правил
`flang/proof/tables/inference-rules.tsv` ОТДЕЛЬНЫМ ЗАПРЕТОМ:

```
Ч✗  Ч  запрет  начало по построению  —  Γ ⊢ (соединить Ч по Р) ▷ П НЕ выводится
Ч3  Ч  правило начало по построению  1) Л ▷ П  Γ ⊢ (соединить Л с Р) ▷ П
```

То есть «начало» выводится у ДВУЧЛЕННОЙ склейки `соединить Л с Р` и не выводится у
склейки списка по разделителю `соединить […] по ""` — а тело функции было написано
вторым способом. Тело переписано цепочкой `соединить X с (соединить Y с …)`, склейка
знак в знак та же (пример функции не менялся и сходится). После правки:

```
bootstrap/flang check scripts/guards/child-timeout.fscript --proof
  постусловие «беда начинается с того, зачем ставился опыт» функции «Про беду»
    — доказано сведением цели с телом функции: правило «начало по построению»

bootstrap/flang io scripts/guards/child-timeout.fscript --plan НетТакогоПлана1234
  → доказано: утверждений 4          (было «не доказано: … сетка 1»)
```

### Что объясняли комментарии ведомостей

`flang/scripts/run-verdict-debt.tsv` — инструменты дерева, которые вердикта о
доказанности не проходят; вызов каждого обязан называть `--на-веру` в самой
командной строке. Поля: файл, слово вердикта, секунд на вердикт, чем снято.
Замер 18 сентября 2026 снят командой `flang io <файл> --plan НетТакогоПлана1234`:
план не найден, работа не идёт, платим только за вердикт. Секунды меньше одной
пишутся с запятой (0,2): округление до 1 завысило бы цену.

`flang/scripts/run-verdict-targets-not-named.tsv` — места, где цель запуска
названа переменной. По имени такую цель узнать нельзя, поэтому место обязано быть
записано с доводом; поле «ключ» говорит, обязан ли `--на-веру` стоять в строке.

`flang/scripts/run-verdict-debt-ceiling.tsv` — решения о потолке. Записей больше
потолка — красно; меньше — тоже красно, потолок опускает тот же коммит, что
закрыл долг.

### Как план читает дерево

Два поручения оболочке только собирают: `git ls-files` отдаёт перечень программ,
`grep` — строки, где `run` или `io` стоит между пробелами (297 строк из 198
файлов). Судит план: делит строку на слова, ищет тройку «двоичный, run|io, цель»,
ключ считает согласием только правее цели. `ярлыки.flang` читается целиком, куски
`соединить … по ""` склеиваются, номер строки — номер первого куска. Голое имя
после `cd каталог &&` называется путём от корня, если такой файл есть.

Жалоба «СОГЛАСИЕ ЛИШНЕЕ» больше не говорит «вердикт ПРОХОДИТ»: вердиктов сторож
не считает, и теперь сообщение говорит ровно то, что он знает, — «в ведомости
долга цели нет». Место названо файлом и номером строки.

Область поиска та же, что у прежнего сторожа, и `.githooks` в неё не входит:
вызов `shortcut-collector.fscript … --на-веру` из `.githooks/pre-push.fscript`
сторож не видит. Это дыра, она была и раньше, здесь не закрыта.

Постусловие «из одной строки отбора выходит не больше одной строчки» у функции
«Строчка отбора» ядро не вывело (стояло на сетке), и оно снято: то же
утверждение доказано у функции «Строчка из частей», которую она зовёт. Вердикт
сторожа — `доказано: утверждений 18`, ключ ему не нужен.
