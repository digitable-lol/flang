# 3870. Анализ завершаемости не видит вызова через функцию-значение и принимает бесконечную цепочку как тотальную

## Шаги воспроизведения

1. Программа: «Петля» зовёт сама себя через функцию-значение.

```flang
модуль «Петля через тег»

тотальная функция «Применить»
  принимает ф: функция из числа в число, х: число
  возвращает число
  ф от х

тотальная функция «Петля»
  принимает х: число
  возвращает число
  «Применить» от функция «Петля» и х
```

2. Проверить и запустить:

```
bootstrap/flang check <файл> --proof
bootstrap/flang run <файл> --function '«Петля»' --args '{"х": 1}' --max-steps 100000
```

3. Смотреть строку отчёта о функции «Петля» и коды возврата.

## Что происходит

```
$ bootstrap/flang check <файл> --proof
  «Применить»  доказано композицией: рекурсии нет, обещание сложено из обещаний тех, кого зовёт
  «Петля»      доказано композицией: рекурсии нет, обещание сложено из обещаний тех, кого зовёт
… ПРОВЕРЕНО САМОСТОЯТЕЛЬНО …                                       код 0
$ bootstrap/flang run <файл> --function '«Петля»' --args '{"х": 1}' --max-steps 100000
FLANG_RECURSION_LIMIT: функция «Петля» исчерпала лимит шагов (100000) на глубине вызовов 1
                                                                  код 1
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026. Без ключа `--max-steps`
тот же запуск за минуту не остановился.

Та же петля прямым вызовом («Петля» от х в теле «Петля») отвергается кодом
`FLANG_NOT_TOTAL`. Через функцию-значение ребра в графе вызовов нет: в
`flang/self/totality.flang` узлы разбора `apply` (применение) и `fnref`
(функция-значение) не упоминаются ни разу, и применение для анализа не
является вызовом.

## Что должно быть

`docs/flang/SPEC.md`, раздел «Функции первого класса»: после снятия
функций-значений граф вызовов конечен и известен целиком; применение
разворачивается в рёбра ко всем функциям-значениям подходящей арности, кроме
случая, когда значение применено на месте. Бесконечная цепочка обязана
отвергаться.

Следующий шаг по тому же разделу — прослеживать, какие функции-значения
попадают в каждый параметр (на месте вызова, пересылкой параметра, возвратом
из функции), и строить рёбра только к ним. Без этого после починки будет
отвергаться конечная программа: две применяющие функции, «Обёртка» зовёт
вторую с «Удвоить», а «Проба» зовёт первую с «Обёртка». Всё, что проследить
нельзя (значение из списка или из поля записи), получает рёбра ко всем
функциям-значениям подходящей арности.

## Обходной путь

Обходного пути нет: компилятор принимает программу сам, отказа автор не видит.

## Когда задача сделана

```
bootstrap/flang check <петля через функцию-значение>        FLANG_NOT_TOTAL, код 1
bootstrap/flang check <конечная цепочка с двумя применяющими>   код 0
```

Обе программы лежат в дереве пробами: первая краснеет, если петлю снова
примут, вторая — если анализ начнёт отвергать конечную цепочку.
`flang/stdlib/higher-order.flang` и `docs/examples/guide/function-value.flang`
по-прежнему проходят проверку с кодом 0. Раздел «Функции первого класса» в
`docs/flang/SPEC.md` описывает то, что анализ делает на самом деле.

## Где живёт правка

`flang/self/totality.flang`: построение рёбер графа вызовов — рёбра от узла
`apply` и множество функций-значений на каждый параметр (неподвижная точка по
графу вызовов). До двоичного правка доезжает только пересборкой семени
(bootstrap regeneration). Расчёт шагов — `docs/archive/hof.md`, раздел «Что НЕ
вошло и в каком порядке делать дальше».
