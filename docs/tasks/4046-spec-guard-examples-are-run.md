# 4046. Примеры проверки спек не прогоняет ни один ярлык, хотя их прогон доходит до конца за 532 с

## Шаги воспроизведения

1. Сосчитать примеры в проверке спек и ярлыки, которые её зовут:

```
grep -ac '^ *пример ' fspec/guard.flang
grep -o '^script\.specs:[^ ]*' .flangrc | sort -u
```

2. Прогнать примеры — минуту и десять минут:

```
timeout 60 bootstrap/flang test fspec/guard.flang
timeout 600 bootstrap/flang test fspec/guard.flang
```

## Что происходит

```
$ grep -ac '^ *пример ' fspec/guard.flang
138
$ grep -o '^script\.specs:[^ ]*' .flangrc | sort -u
script.specs:check
script.specs:forgery
$ timeout 60 bootstrap/flang test fspec/guard.flang
шагов 3 359 889 196 из 4 000 000 000 000 (0 %), идёт «Прогон примеров исходников», 346 МиБ
                                                                        код 124
$ timeout 600 bootstrap/flang test fspec/guard.flang
fspec/guard.flang: примеров 246, прошло 246, не прошло 0
                                                       код 0 за 531,85 с
$ sed -i '124s/ожидается да/ожидается нет/' fspec/guard.flang   # подлог
$ timeout 800 bootstrap/flang test fspec/guard.flang
fspec/guard.flang: примеров 246, прошло 245, не прошло 1
                                                       код 1 за 530,96 с
```

Версия: flang 0.7.23.

Прогон доходит до конца: 531,85 с, код 0. Последний печатный отсчёт перед
концом — 23 438 135 672 шага, то есть 0 % от потолка в 4 трлн, пик 435 МиБ.
Предел шагов тут ни при чём, хватает умолчания; цена прогона — время, и минуты
ему мало. Примеров он считает 246, а не 138: 138 объявлены в самом
`fspec/guard.flang`, 37 — во ввезённом `fspec/policy.flang`, 71 — во ввезённом
`flang/stdlib/json.flang` (`grep -ac '^ *пример '` по трём файлам, сумма через
`awk '{s+=$1} END {print s}'`).

Ярлык `specs:check` зовёт `bootstrap/flang io fspec/guard.flang --на-веру`: это
исполнение плана, примеры при нём не считаются. Ярлык `specs:forgery` зовёт
`fspec/forgery.flang`. Примеры самого `fspec/guard.flang` не запускает ничто:
ярлыка с `flang test fspec/` в `.flangrc` нет, а `grep -rn fspec .github/` даёт
одну строку, и та — комментарий.

Зелёный ответ подтверждён подлогом: испорченный один пример (строка 124,
`ожидается да` → `ожидается нет`) даёт код 1 и «не прошло 1». Имя не прошедшего
примера при этом НЕ названо — печатается только счёт; на одиночном файле без
ввозов имя называется («пример … функции … не прошёл: ожидалось …, получено …»).
Это отдельная беда прогона примеров, здесь она только замечена.

## Что должно быть

Примеры проверки спек прогоняются до конца ярлыком с кодом 0: проверка, о
которой неизвестно, работает ли она сама, ничего не удостоверяет. Справка
`bootstrap/flang test --help` называет ключи `--max-steps N` и `--max-depth N` —
ими предел задаётся, если умолчания не хватит; здесь умолчания хватает.

## Обходной путь

Звать руками: `bootstrap/flang test fspec/guard.flang` — девять минут и код 0.

## Когда задача сделана

В `.flangrc` есть ярлык `specs:examples`, он зовёт
`bootstrap/flang test fspec/guard.flang`, доходит до конца с кодом 0 и печатает
число прошедших примеров — 246 или столько, сколько их в тот день. В объявлении
ярлыка названы время и память прогона. Нарочно испорченный пример делает ярлык
красным. Девять минут для набора быстрых проверок дорого, поэтому место ярлыка —
отдельная работа CI, а не хук; если прогон надо укоротить, примеры разложены по
нескольким файлам.

## Где живёт правка

`.flangrc` — новый ярлык; при необходимости `fspec/guard.flang` — деление
примеров по файлам. Оба файла двоичный читает с диска, пересборка семени
(bootstrap regeneration) не нужна.
