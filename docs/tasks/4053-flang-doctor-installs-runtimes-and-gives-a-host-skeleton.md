# 4053. Команды flang doctor нет — установку некому проверить, рантайм некому положить, образец хозяина некому дать

## Шаги воспроизведения

1. Спросить команду: `bootstrap/flang doctor`.
2. Скопировать двоичное в пустой каталог и напечатать любую программу в
   JavaScript. Каталог поиска рантайма берётся от РОДИТЕЛЯ каталога с
   двоичным, поэтому пустым должен быть и родитель: ни `flang/src/emit`, ни
   `share/flang` рядом с ним лежать не должно, иначе печать находит рантайм и
   отвечает кодом 0:

```
mkdir -p <пусто>/bin && cp bootstrap/flang <пусто>/bin/flang
cd <пусто> && ./bin/flang emit <файл> --target js --out <каталог вывода>
```

3. Смотреть ответ и код возврата.

## Что происходит

```
$ bootstrap/flang doctor
flang: неизвестная команда «doctor». «flang --help» — что умеет бинарник.
                                                                 код 2
$ <каталог>/flang emit <файл> --target js --out <каталог вывода>
flang emit: не найдены исходники рантайма JavaScript — они уезжают в вывод ДОСЛОВНО, и
без них печать соврала бы. Узнаются они по flang_cli.js без шапки «Сгенерировано flang».
Искали в «--runtime», в $FLANG_RUNTIME_DIR и рядом с установленным flang (share/flang/js).
Что делать: назвать каталог с ними ключом «--runtime каталог» или переменной
FLANG_RUNTIME_DIR; в дереве исходников это flang/src/emit/js.
                                                                 код 2
```

Версия: flang 0.7.23. Дата прогона: 3 октября 2026.

Отказ печати называет три места поиска и путь в дереве исходников, но не
говорит, откуда взять дерево, и не предлагает положить рантайм рядом с
командой. Второе: программа на flang сама действий не совершает, их исполняет
хозяин. Образец хозяина в дереве есть (`docs/examples/host-boundary/host.c`,
словарь поручений — `flang/self/io.flang`), но команда его не выдаёт.

## Что должно быть

`flang doctor` без ключей ничего не меняет на машине и печатает:

1. версию и цели печати, как их называет `flang emit --help`;
2. по каждой цели — где лежит рантайм и какое из трёх мест поиска сработало
   (`--runtime`, `FLANG_RUNTIME_DIR`, каталог share/flang/<цель> рядом с командой);
   у цели `cpp` ключ `--runtime` ждёт корень `flang/src/emit`, а не каталог цели;
3. по каждой цели — есть ли чем собрать напечатанное (`cc`, `g++`, `go`,
   `cargo`, `javac`, `dotnet`, `elixir`, `node`, `python3`); если нет — имя
   и команду установки для этой системы. Если напечатанное найденным
   инструментом ни разу не собиралось, так и сказано.

По явному ключу `--install` (кириллицей `--поставить`) команда сначала
печатает, что собирается сделать, затем кладёт рантаймы в share/flang/<цель>
рядом с командой либо в названный каталог и печатает каркас хозяина хотя бы
для одной цели: приём поручений, чтение файла, запись файла, время, ответ.
Молча команда не ставит ничего.

## Обходной путь

Назвать рантайм самому: `--runtime <каталог>` или `FLANG_RUNTIME_DIR` с путём
к каталогу цели под `flang/src/emit` из дерева исходников. Хозяина писать по образцу
`docs/examples/host-boundary`.

## Когда задача сделана

```
$ bootstrap/flang doctor                                         код 0
$ cd <пусто> && ./bin/flang doctor                               код 1
```

Первый прогон печатает версию, цели, пути рантаймов и инструменты сборки;
второй, на установке без рантаймов (каталог из шага 2), называет, чего нет. После
`./bin/flang doctor --install` печать из шага 2 проходит с кодом 0.
Проба — эти три прогона: она краснеет, если команда начнёт молчать о
сломанной установке. `packaging/flang.1`, `docs/site/cli.md` и
`docs/site/cli.ru.md` описывают команду; `bootstrap/flang run-script cli-keys:check`
знает команду и её ключи, записи о расхождении в
`flang/scripts/cli-keys-debt.json` нет.

## Где живёт правка

`flang/src/emit/c/flang_repl.c` — разбор команды и её работа; `flang/self/cli.flang`
— модель командной строки, с которой сверяется проверка ключей. Обе правки
попадают в двоичное пересборкой семени (bootstrap regeneration). Страницы и
`packaging/flang.1` семени не касаются.
