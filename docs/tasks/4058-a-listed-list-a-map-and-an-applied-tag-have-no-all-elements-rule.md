# 4058. Три случая, которых нет у семейства Э

Решение: [ADR-0037](../adr/0037-second-order-is-a-finite-conjunction-over-function-tags.md) §4.3.

## Чем измерено

Прогон 13 сентября 2026, двоичный `bootstrap/flang` 0.7.19 из дерева `main`
`87fbd112`, `flang check <проба> --proof`:

| проба | исход |
|---|---|
| `обеспечивает для всех р из результат: р не меньше 0` при теле `отобразить функции как ф → ф от 1` | «сетка 1 значение», доказано 0 |
| `пусть ф равно функция «Удвоить»` и тело `ф от 1`, цель `результат не меньше 0` | доказано — через `пусть` ядро ярлык видит |
| место вызова `«Применить все к единице» от [функция «Удвоить», функция «Квадрат»]` с квантором в `требует` (после задачи 3123) | снять нечем: у выписанного списка правила нет |

«Отказ всех элементов» в ядре называет пропуск дословно: «Выписанный список с
элементами, отображение и вызов чужой функции не выводятся: у них нет правила».

## Где дыра

`flang/self/proof-kernel.flang`, «Все элементы по построению» (около строк
9085–9105): случаи — пустой `list`, `filter`, `if`, встроенное прибавление.
Комментарий над правилом (около 9052–9073) объясняет, почему трёх случаев нет:
выписанный список — «у сверщика в шаге не больше двух посылок»; отображение —
«свойство образа требует ∀ над прообразом с ДРУГИМ предикатом — своё правило и
своя лемма»; вызов чужой функции — восьмой ход, не построение. Первые два довода
— про цену, не про законность. Ведомость `flang/proof/ПРАВИЛА-ВЫВОДА.tsv` несёт
Э1–Э4 (строки 166–169); Lean — «Э1»…«Э4» в `Правила.lean`; `Модель.lean`
отображения не знает (по словам `отображ` и `map` — ноль вхождений).

Применение выписанного ярлыка: после подстановки Э3/Э5 в цели встаёт терм
`(функция «Удвоить») от 1`. Вычислитель читает его тем же диспетчером, что и
`«Удвоить» от 1` (`interpret.flang`, случай `fnref`; `docs/flang/SPEC.md`,
«Функции первого класса»), а ядро — нет: проверить толкованием первым делом, и
если восьмой ход уже читает такой узел, третий случай не заводить.

## Что сделать

Ведомость и Lean — ПЕРВЫМИ, сверщик — раньше печати ядра (условие партии
ADR-0026 §11 неизменно).

1. **Э5 — выписанный список с головой.** Посылки: 1) Γ ⊢ П[э:=Х₁]; 2) Γ ⊢
   ∀э∈[Х₂…Хн]. П. Заключение: Γ ⊢ ∀э∈[Х₁…Хн]. П. Две посылки — форма сверщика
   соблюдена; хвост-литерал снова Э5, пустой — Э1. Захват — как у Э3.
2. **Э6 — отображение.** Посылка: Γ ⊢ ∀х∈Л'. П[э:=Ф]. Заключение: Γ ⊢
   ∀э∈(отобразить Л' как х → Ф). П. Заперто, если П связывает `х` или имя,
   свободное в Ф. В `Модель.lean` завести отображение и лемму
   «всеЭ p (отобр f l) = всеЭ (p ∘ f) l»; ловушка — подстановка без замены имени.
3. **Яр1 — применение выписанного ярлыка** (если нужен по замеру выше):
   `(функция «Ф») от а …` есть `«Ф» от а …` — переписка по вычислителю, строка
   ведомости с «—» в правиле ядра, как у развёртки; в сверщике — отдельный шаг с
   одной посылкой, а не молчаливая нормализация внутри `терм()`.
4. Ядро: новые случаи в «Все элементы по построению»; печать —
   «Шаги всех элементов записи» в `flang/self/zapis.flang` (около 5642) печатает
   Э5/Э6/Яр1 с основаниями; сверщик — приёмы по образцу Э3 (около строки 8506),
   не больше 45 строк кода в бюджете ADR-0037 §4.5.
5. Пробы — семья `все-элементы`. Честные: выписанный список литералов;
   `отобразить` с предикатом, совпадающим после подстановки; сквозная программа
   ADR-0037 §2 п.7 (после задач 1261 и 3123): три обещания доказаны, место
   вызова снято. Подделки: Э5 с пропущенным элементом; Э6 с предикатом не о Ф;
   Яр1 с чужим именем функции; `отобразить`, где П связывает `х`.
6. Слово: семейство Э в `docs/flang/proof/SPEC.md` (сегодня о нём там ни
   строки — по словам `Э1`, `семейство Э`, `все элементы по построению` ноль
   вхождений), README семьи, текст «Отказ всех элементов».

## Чего не делать

- Не заводить квантор над ТИПОМ функции (`для всех ф: функция из …`): ADR-0026
  §11 п.8 и ADR-0037 §5 — у него нет носителя.
- Не вести индукции по функции.
- Не расширять Э6 на предикат, зависящий от номера элемента.
- Не печатать `forallIn` в цели печати — задача 7098.
- Не трогать `bootstrap/**`.
