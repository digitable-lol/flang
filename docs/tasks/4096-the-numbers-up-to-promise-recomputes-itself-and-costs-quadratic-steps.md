# 4096. «Числа до» из lists.flang под run и test стоит квадратичное число шагов

Заявка: https://github.com/digitable-lol/flang/issues/160

## Шаги воспроизведения

1. Программа, `<дерево>` — корень репозитория:

```flang
модуль «Проба»
  использует «Lists» из "<дерево>/flang/stdlib/lists.flang" только «Числа до»

тотальная функция «Синтетика числами до»
  принимает сколько: число
  возвращает число
  длина («Числа до» от сколько)
```

2. Команда для N = 100 и N = 500:

```
/usr/bin/time -f '%e s %M KB' bootstrap/flang run <файл> --trust \
  --function '«Синтетика числами до»' --args '{"сколько": N}'
```

3. Смотреть время и пик памяти.

## Что происходит

```
N=100    1,40 с      70 840 КБ                                   код 0
N=500   18,72 с   1 349 748 КБ                                   код 0
```

Версия: flang 0.7.23. Дата прогона: 30 сентября 2026.

Вход вырос в 5 раз, время — в 13 раз, память — в 19. Вычислитель проверяет
`обеспечивает` при каждом вызове, а два обещания «Числа до» сами зовут «Числа
до» от `предел минус 1` (через копию без проверок). Каждый уровень рекурсии
пересчитывает весь промежуток заново.

## Что должно быть

Вызов «Числа до» от n стоит линейное число шагов: список из n чисел строится за
n вызовов.

## Обходной путь

Своя функция промежутка без обещаний, которые зовут её же:
`добавить предел к («Номера до» от (предел минус 1))` при `предел: нат`.

## Когда задача сделана

Тот же прогон от 1000 идёт секунды, а от 500 — не более чем впятеро дольше, чем
от 100. Обещания «Числа до» либо доказаны и при работе не проверяются, либо
переписаны без вызова самой функции.

## Где живёт правка

`flang/stdlib/lists.flang`, обещания функции «Числа до» — пересборка семени не
нужна. Другой путь — вычислитель в `flang/self/interpret.flang` перестаёт
проверять доказанные обещания; он доезжает до двоичного только пересборкой
семени (bootstrap regeneration).
