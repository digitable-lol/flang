# 4318. Приёмка нового двоичного не считает, сколько функций семени потеряли батут или цикл

## Шаги воспроизведения

1. Посчитать в напечатанном семени вызовы батута (trampoline), плоские циклы и
   проверки постусловий при работе:

```
grep -ac "fl_trampoline" bootstrap/compiler_flang.c
grep -ac "for (;;)" bootstrap/compiler_flang.c
grep -ac "fl_post" bootstrap/compiler_flang.c
```

2. Проверить, смотрит ли на эти числа приёмка нового двоичного:

```
grep -ac "fl_trampoline\|for (;;)" scripts/seed/new-binary-acceptance.fscript
```

## Что происходит

```
$ grep -ac "fl_trampoline" bootstrap/compiler_flang.c
125
$ grep -ac "for (;;)" bootstrap/compiler_flang.c
228
$ grep -ac "fl_post" bootstrap/compiler_flang.c
3312
$ grep -ac "fl_trampoline\|for (;;)" scripts/seed/new-binary-acceptance.fscript
0
```

Версия: flang 0.7.23.

Хвостовой вызов печатается в C батутом или циклом и стека не занимает. Стоит
функции получить постусловие, которое считается при работе, — она печатается
обычным вызовом с `fl_post`, и вся её группа взаимной рекурсии начинает
расходовать стек. После пересборки семени (bootstrap regeneration) это видно в
`bootstrap/compiler_flang.c` обычным `grep`, но план «Accept» в
`scripts/seed/new-binary-acceptance.fscript` принимает двоичный по шести
приметам (функция «All signs»: Names, Condition, Progress, Rules, Types, Live), и
этих чисел среди них нет.

## Что должно быть

Приёмка сравнивает только что напечатанное семя с тем, что лежит в дереве, и
печатает:

- число батутов, циклов и вызовов `fl_post` — было и стало;
- поимённый список функций, потерявших батут или цикл (имя функции есть в обоих
  файлах, а батута или цикла в новом нет);
- код 1, если батутов или циклов стало меньше, код 0 — если столько же или больше.

Считать текстом по `bootstrap/compiler_flang.c`, компилятор для этого не нужен.
Красный ответ пересборку не отменяет — убыль бывает оправданной, — но обязан
назвать её числом.

## Обходной путь

После каждой пересборки семени руками выполнять три `grep` из шагов
воспроизведения на старом и новом файле и сравнивать числа.

## Когда задача сделана

```
bootstrap/flang run-script binary:acceptance
```

- на семени, совпадающем с лежащим в дереве, — код 0 и строка с числами «было»
  и «стало»;
- на копии семени, где у одной функции вызов `fl_trampoline` заменён обычным
  вызовом, — код 1, в выводе число батутов на единицу меньше и имя этой функции;
- на копии, где батутов стало больше, — код 0.

Оба прогона — с порчей и без неё — показаны в описании правки.

## Где живёт правка

`scripts/seed/new-binary-acceptance.fscript` (седьмая примета в «All signs» плана
«Accept»), его пробы в `scripts/seed/new-binary-acceptance-probe.flang` и строка
функции «Объявление короткой команды binary:acceptance» в том же файле («по шести
приметам» станет «по семи»); сама короткая команда объявлена строкой
`script.binary:acceptance` в `.flangrc`.
Это скрипты: двоичный читает их с диска, пересборка семени не нужна.
