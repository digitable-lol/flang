# 4390. Числа в описи JavaScript не сторожатся ни одной приметой

Беда не в том, что числа устарели, а в том, что их **никто не сверяет**. У обеих
таблиц `docs/javascript-inventory.md` — групповой («Куча 4. ДОЛГ») и поимённой
(«Поимённо, по убыванию») — нет ни одной приметы `СНЯТО`, поэтому сторож чисел в
прозе их не читает и остаётся зелёным, пока таблицы врут. Это тот же класс, что
описан в `docs/zettel/renaming-a-file-silently-disables-the-guard.md`: проверка,
переставшая сравнивать, продолжает зеленеть.

## Шаги воспроизведения

1. Сверить групповую строку с деревом:

   ```
   git ls-files -- 'docs/site/*.mjs' 'docs/site/*.js' | wc -l
   git ls-files -- 'docs/site/*.mjs' 'docs/site/*.js' | xargs cat | wc -l
   grep -n 'узел сайта |' docs/javascript-inventory.md
   ```

2. Сверить поимённую строку с деревом:

   ```
   wc -l docs/site/build.mjs docs/site/sitemap.mjs
   grep -n '`docs/site/build.mjs` |\|`docs/site/sitemap.mjs` |' docs/javascript-inventory.md
   ```

3. Спросить сторожа чисел в прозе — краснеет ли он на этом:

   ```
   bootstrap/flang io scripts/guards/prose-numbers-guard.fscript --plan Check
   ```

⚠ Мерить **только `git ls-files`**, а не `find`: каталог вывода сборки
сайта (docs/site/out, он в `.gitignore`) даёт `find` два лишних файла и
завышает счёт `docs/site` до 15 файлов и 6 016 строк. Так ошибся замер,
с которого эта задача заведена; прибор сторожа чисел мерит `git ls-files`.

## Что происходит

Групповая таблица — разошлись **все пять** строк:

| группа | в описи | в дереве | разрыв |
|---|---|---|---|
| `flang/scripts` | 11 файлов, 6 654 строк | 6 файлов, 3 873 строк | −5 файлов, −2 781 строка |
| `docs/site` | 9 файлов, 3 572 строк | 13 файлов, 5 660 строк | +4 файла, **+2 088 строк** |
| `scripts` | 3 файла, 2 186 строк | 2 файла, 1 764 строк | −1 файл, −422 строки |
| `flang/concurrency` | 3 файла, 657 строк | 4 файла, 1 392 строк | +1 файл, +735 строк |
| `docs/benchmarks` | 2 файла, 398 строк | 2 файла, 339 строк | −59 строк |
| заголовок кучи | 28 файлов, 13 467 строк | 27 файлов, 13 028 строк | −1 файл, −439 строк |

Поимённая таблица — 26 строк: **7** сошлись с деревом, **13** разошлись, **6**
называют путь, которого в дереве больше нет (`flang/scripts/proof-ledger.mjs`,
`word-guard.mjs`, `discriminating-search.mjs`, `claim-guard.mjs`,
`target-words.mjs`, `scripts/jargon-guard.mjs`). Крупнейшие расхождения:

| строка описи | в описи | в дереве | разрыв |
|---|---|---|---|
| `docs/site/diagram.mjs` | 410 | 930 | +520 |
| `flang/scripts/link-collision-guard.mjs` | 828 | 1101 | +273 |
| `docs/site/build.mjs` | 958 | 1139 | +181 |
| `docs/site/site-numbers.mjs` | 482 | 559 | +77 |
| `docs/site/sitemap.mjs` | 495 | 569 | +74 |

А сторож на всё это молчит:

```
$ bootstrap/flang io scripts/guards/prose-numbers-guard.fscript --plan Check
сторож чисел: все 213 примет сошлись с деревом                          код 0
```

Приметы у этих таблиц нет ни одной, вот он и сошёлся: сверять ему тут нечего.

Разрыв накоплен не одной правкой. Задача 0037 добавила в `docs/site/build.mjs` и
`docs/site/sitemap.mjs` 48 строк (1100 → 1139 и 560 → 569, снято с двух сторон
`git show`), а описи эти строки были неверны и до неё — на 142 и 65
соответственно.

Версия: flang 0.7.23. Дата прогона: 2 октября 2026, дерево `fbdf73067`.

## Что должно быть

У каждой строки обеих таблиц стоит примета `СНЯТО <дата> строк-в <путь> = <N>`
(и `файлов` там, где в строке есть счёт файлов), и сторож чисел в прозе краснеет,
как только таблица разойдётся с деревом. Инструмент для этого уже есть и мерит
**`git ls-files`**: `строк-в` принимает список образцов через запятую, значит
годится и для точного пути, и для группы.

**Таблицу правят целиком или не правят вовсе.** Поимённая отсортирована по
убыванию: по своим числам порядок ещё держится, по дереву — уже нет (проверено
прогоном). Починить две строки значит сделать таблицу свежей на вид и лживой
по-прежнему, да ещё сломать её порядок. Поэтому правка снимает всю таблицу
прибором и расставляет приметы всем строкам разом.

## Обходной путь

Числа описи приходится пересчитывать руками перед каждым использованием. Обхода
для сторожа нет: сверять он начнёт только с появлением примет.

## Когда задача сделана

```
bootstrap/flang io scripts/guards/prose-numbers-guard.fscript --plan Check   код 0
```

при том, что число примет выросло на число строк обеих таблиц, и у каждой строки
примета с датой. Проба порчи: изменить число в ЛЮБОЙ строке таблицы на единицу —
сторож обязан покраснеть и назвать путь и строку.

Форма отказа проверена на живом приборе: примета на точный путь годится, и если
число в ней сдвинуть на единицу, ответ такой:

```
примет 214: сошлось 213, разошлось 1, негодных 0
docs/javascript-inventory.md:254: РАЗОШЛОСЬ С ДЕРЕВОМ — строк-в docs/site/build.mjs:
  в примете 1138, снято сегодня 1139 (примета от 2026-10-02)              код 1
```

Вернуть число — снова код 0. Без этой пробы проверка неотличима от выключенной,
а выключенной она и была.

## Где живёт правка

`docs/javascript-inventory.md` — обе таблицы и заголовок «Куча 4», плюс фраза
«отпирает узел сайта, 9 файлов» в том же файле. Строки, называющие исчезнувшие
пути, либо получают нынешний путь, либо уходят из таблицы живых в раздел о
снятом. Двоичного правка не касается, перепечатка семени не нужна.
