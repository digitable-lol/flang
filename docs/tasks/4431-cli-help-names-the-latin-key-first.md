# 4431. Сообщения двоичного советуют ключи кириллицей, хотя справка называет первым латинское написание

## Шаги воспроизведения

1. Программа:

```flang
модуль «Проба»

функция «Один»
  возвращает число
  1
```

2. Исчерпать предел шагов и предел глубины самого двоичного, попросить
   протокол у цели, которая его не печатает, и совместить два несовместимых
   ключа:

```
bootstrap/flang check <файл> --step-limit 10
bootstrap/flang check <файл> --depth-limit 3
bootstrap/flang emit <файл> --target go --protocol <файл протокола> --out <каталог>
bootstrap/flang check <файл> --proof --fast
```

3. Смотреть, каким написанием сообщение называет ключ.

## Что происходит

```
$ bootstrap/flang check <файл> --step-limit 10
… а поднять его на один прогон: flang check <файл> --предел-шагов N.
                                                                 код 1
$ bootstrap/flang check <файл> --depth-limit 3
… поднять на один прогон: flang <команда> <файл> --предел-глубины N.
                                                                 код 1
$ bootstrap/flang emit <файл> --target go --protocol <файл протокола> --out <каталог>
flang emit: «--протокол» есть только у цели «c»: протокол перевода печатает …
                                                                 код 2
$ bootstrap/flang check <файл> --proof --fast
flang check --быстро и --proof вместе не имеют смысла: …
                                                                 код 2
```

Версия: flang 0.7.23.

Справка всех команд называет первым `--step-limit`, `--depth-limit`,
`--protocol`, `--fast`, а кириллическое написание даёт синонимом со словом
«Кириллицей». Сообщения об отказе ведут кириллицей, в том числе когда человек
набрал ключ латиницей.

Рядом лежит неверная запись: в `flang/scripts/cli-keys-debt.json` про
`--machine` сказано, что справка его не называет. Справка называет:
`bootstrap/flang --machine --help` начинается строкой
«flang --machine [<файл>]        (кириллицей: --машина)».

## Что должно быть

ADR-0010 обещает пару написаний у каждого ключа, и справка ведёт латинским.
Сообщение называет ключ тем же написанием, что справка; кириллическое может
стоять рядом синонимом. Цитаты вывода самой программы (строка вердикта с
«--на-веру», значения «отказ | предупреждение | разрешение») остаются дословными.

## Обходной путь

Оба написания принимаются разбором, совет из сообщения работает как написан.

## Когда задача сделана

Четыре прогона из шагов воспроизведения называют `--step-limit N`,
`--depth-limit N`, `--protocol`, `--fast`. Проба — подсчёт по исходнику
сообщений, он даёт 6, должен давать 0:

```
grep -c -- '--предел-шагов N\|--предел-глубины N\|«--протокол»\|"flang check --быстро\|без «--быстро»' flang/src/emit/c/flang_repl.c
```

Запись о `--machine` в `flang/scripts/cli-keys-debt.json` говорит то, что
есть, а `bootstrap/flang run-script cli-keys:check` отвечает кодом 0 и
«НАБОРЫ СОШЛИСЬ: ни одного расхождения сверх записанного долга».

## Где живёт правка

`flang/src/emit/c/flang_repl.c`: совет после предупреждения о запасе шагов, совет
после отказа по глубине, два отказа `flang emit` о протоколе, отказ
`flang check` о несовместимых ключах и строка «Спросить всё — та же команда
без …». В двоичное правка попадает пересборкой семени (bootstrap
regeneration): она переносит файл в `bootstrap/flang_repl.c`.
`flang/scripts/cli-keys-debt.json` — одна запись, семени не касается.
