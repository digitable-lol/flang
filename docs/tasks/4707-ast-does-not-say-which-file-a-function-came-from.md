# 4707. «flang ast» не говорит, из какого файла пришла функция

## Шаги воспроизведения

1. Программа (путь к библиотеке — от места, где лежит файл):

```flang
модуль «Свой модуль»
  использует «Optional» из "flang/stdlib/optional.flang"

тотальная функция «Своя»
  принимает н: число
  возвращает число
  н плюс 1
```

2. Команда:

```
bootstrap/flang ast <файл> > ast.json
```

3. Смотреть: сколько функций в списке `functions`, какие у узла функции ключи и
   есть ли среди них файл.

## Что происходит

```
$ bootstrap/flang ast <файл> > ast.json                           код 0
ключи верхнего уровня:  flang, functions, legacy, module, types
функций в списке:       12  (одна своя, одиннадцать из flang/stdlib/optional.flang)
ключи функции:          body, examples, name, params, postconditions, returns,
                        span, total, typeParams
функций с ключом file:  0
```

Версия: flang 0.7.23.

Своя функция и ввезённые лежат в одном списке. Поле `span` несёт только строку и
столбец (у «Своя» — строка 4, у первой функции библиотеки — строка 7), без файла,
поэтому по нему своё от чужого не отличить.

Сведение при этом есть внутри связывания: объект «Связывание» в
`flang/self/link.flang` держит список «файлы функций», идущий строго параллельно
списку «функции» («С функцией» и «С повтором функции» пополняют оба). Теряется
оно в «Собрать итог»: тот передаёт список файлов в сборку теорем, а в «Собрать
программу» — нет.

## Что должно быть

У каждого узла списка `functions` в выводе `flang ast` есть поле `file` с путём
файла, где функция объявлена. Имя поля — рядом со `span`, которое уже отвечает
на вопрос «где». Читатели берут поля по ключу, и новое поле их не ломает.

## Обходной путь

Отсеивать ввезённые функции по имени: `отсеятьЧужое` в
`flang/scripts/binary.mjs` для каждого ввоза заново разбирает соседний файл
целиком и вычёркивает совпавшие имена. Это лишний полный `flang ast` на каждый
ввоз, и файл, объявивший функцию с тем же именем, что у соседа, теряет свою.

## Когда задача сделана

На программе из шагов воспроизведения:

- у всех 12 функций есть поле `file`;
- у «Своя» оно равно пути самого файла, у остальных одиннадцати —
  `flang/stdlib/optional.flang`;
- проба: в свой файл добавлена функция с именем, которое есть в библиотеке
  (например «Обернуть»), — при разборе, где такое допустимо, её поле `file`
  указывает на свой файл, а не на библиотеку;
- `отсеятьЧужое` в `flang/scripts/binary.mjs` отбирает по полю `file`, а не
  разбором соседей.

## Где живёт правка

`flang/self/link.flang`, около пятнадцати строк:

- новая функция, которая идёт по списку функций со счётчиком и каждому узлу
  добавляет поле `file` из «Файл по номеру» — так же, как «Постусловия своей»
  берёт файл по номеру для теорем;
- «Собрать программу» принимает ещё список файлов и кладёт в `functions` узлы
  с полем;
- «Собрать итог» передаёт ей «файлы функций».

В C править нечего: JSON печатает общая «Печать значения», новое поле выйдет
само. Файл входит в самосборную часть, поэтому до двоичного правка доезжает
только пересборкой семени (bootstrap regeneration); заказывать пересборку ради
одной этой правки не стоит — приложить к ближайшей.
