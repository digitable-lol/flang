# 4791. Приёмы Р5 и Р6 читают тело функции по строкам, и приёмка Lean их не судит; Р2 и Р3 судятся только через Выч

## Шаги воспроизведения

1. Спросить дерево, какие приёмы `шаг_вывода` проверяющей программы стоят вне
   приёмки Lean:

```
bootstrap/flang run-script lean-rules:census
```

2. Смотреть строки с пометкой «долг» в третьей колонке и строку «вне приёмки».

## Что происходит

```
$ bootstrap/flang run-script lean-rules:numbers
приёмов 83, с леммой 83, в приёмке 78, вне приёмки 5, в долге 5         код 0
```

<!-- СНЯТО 2026-10-05 lean-rules:numbers приёмов = 83, в приёмке = 78, вне приёмки = 5 -->

Версия: flang 0.7.24, Lean 4.34.1. Дата прогона: 5 октября 2026, ветка
`a/checker-rules-are-sound-in-lean`.

Вне приёмки — Выч, Р2, Р3, Р5, Р6. Выч ведёт задача 1183 (вычислитель половин
внутри проверяющей программы). Остальные четыре — здесь:

- **Р5, Р6** (пустота списка отдаёт ветвь «случай пусто» либо начало свёртки):
  проверяющая программа читает тело функции ПО СТРОКАМ — `блок_функции`,
  `строка_разбора`, `найти_случай`, `тело_случая`, `тело_функции_текст`
  (`flang/proof/checker/checker.c`, `семейство_р`). Читатель записи
  `flang/proof/lean/RecordReader.lean` собирает тело только одной строкой
  (`«Функция».«тело»`), многострочный `разбор` с ветвями в терм не собирает.
  Цена по графу вызовов (15 сентября 2026): 41 функция и 350 строк C, из них
  29 функций общие с вычислителем половин.
- **Р2, Р3** (условие В, подставленное в Ф литералами «да» и «нет», даёт две
  половины): посылками проверяющая программа берёт ТОЛЬКО шаги Выч, и пока Выч
  вне приёмки, блок с Р2/Р3 всё равно упирается в Выч. Сама же лемма приёма —
  «обе половины истинны, значит истинна Ф» — требует в модели поиска куска В по
  первому расхождению и подстановки без захвата; у проверяющей программы
  подстановка текстовая (`вставить_вместо`) и о связывателях над В она не
  спрашивает.

## Что должно быть

Каждый приём `шаг_вывода` — с теоремой состоятельности в Lean (ADR-0041 §2.1,
ADR-0064). Для четырёх приёмов это значит:

- Р5, Р6 — читатель записи собирает многострочное тело (`разбор Л` с ветвями
  «случай пусто» / «случай голова и хвост», `свёртка Л начиная с Н как …` первой
  строкой), в модели есть разбор списка списочного сорта, и приёмка принимает
  шаг «результат равен Т» при факте пустоты того же списка;
- Р2, Р3 — приёмка восстанавливает В из первого расхождения разобранных деревьев
  Ф и о1, проверяет, что В не стоит под связывателем, связывающим его свободное
  имя, и что замены В на «да» и «нет» дают о1 и о2; лемма — разбор случаев по
  значению В в мире. Приёмка здесь строже проверяющей программы (она захвата не
  спрашивает), и это надо назвать в шапке `Acceptance.lean`.

Либо, если цена названа и решено не платить, — строка долга остаётся, а в ADR
стоит довод с числом строк Lean.

## Обходной путь

Обхода нет: шаги Р2, Р3, Р5, Р6 сверяются только самой проверяющей программой.

## Когда задача сделана

`bootstrap/flang run-script lean-rules:check` зелен при пустых строках долга на
Р5 и Р6 (а при закрытии 1183 — и на Р2, Р3); строки из
`flang/proof/tables/lean-acceptance-debt.tsv` сняты, иначе сторож краснеет
словами «долг уплачен — строку долга снять». В
`bootstrap/flang io flang/proof/lean/run.fscript` число «вне приёмки» падает на
блоки этих приёмов (на 2 октября 2026 — Р5 24, Р6 7), расхождений 0, ловушки на
новые приёмы отвергнуты.

## Где живёт правка

`flang/proof/lean/RecordReader.lean` — сборка многострочного тела;
`flang/proof/lean/Term.lean`, `Model.lean` — разбор списка в модели;
`flang/proof/lean/Acceptance.lean`, `Consistency.lean` — приёмы и случаи теоремы;
`flang/proof/lean/Trap.lean` — ловушки; `flang/proof/tables/lean-acceptance-debt.tsv`
— снять строки. Двоичное не меняется, перепечатка семени не нужна.
