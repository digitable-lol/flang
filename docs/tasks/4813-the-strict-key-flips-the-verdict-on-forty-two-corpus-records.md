# 4813. Ключ `--строго` меняет приговор сверщика на C на 27 записях корпуса из 94, а у двойника на flang этого ключа нет — который приговор верен, не сказано

## Шаги воспроизведения

1. Собрать сверщик на C (`make -C flang/proof/checker` кладёт его рядом под именем
   `сверщик`; ниже он назван `<каталог>/checker-c`):

```
cc -std=c99 -O1 -o <каталог>/checker-c flang/proof/checker/checker.c
```

2. Прогнать честную запись без ключа и с ключом:

```
<каталог>/checker-c flang/proof/examples/precondition.flang flang/proof/checker/tests/records/corpus/precondition.record
<каталог>/checker-c --строго flang/proof/examples/precondition.flang flang/proof/checker/tests/records/corpus/precondition.record
```

3. Пройти весь корпус и сосчитать, у скольких записей приговор меняется
   (исходник каждой записи назван второй строкой самой записи):

```
for r in flang/proof/checker/tests/records/corpus/*.record; do
  s=$(sed -n 2p "$r" | sed 's/^исходник //')
  <каталог>/checker-c "$s" "$r" >/dev/null 2>&1; a=$?
  <каталог>/checker-c --строго "$s" "$r" >/dev/null 2>&1; b=$?
  [ "$a" = "$b" ] || echo "$a→$b $r"
done | wc -l
```

4. Сосчитать ключ у двойника на flang:

```
grep -ac 'строго' flang/proof/checker/checker.c
grep -ac 'строго' flang/proof/checker.flang
```

## Что происходит

```
$ <каталог>/checker-c … precondition.flang … precondition.record
ПРОВЕРЕНО — запись сошлась с исходником … Числятся доказанными 2.         код 0
$ <каталог>/checker-c --строго … precondition.flang … precondition.record
НЕ УДАЛОСЬ ДОКАЗАТЬ — ДОКАЗАННЫМИ ЧИСЛЯТСЯ НЕ ВСЕ (ключ --строго, числа
ниже): утверждений 3 … Числятся доказанными 2.                            код 3
$ for r in … done | wc -l
27
$ grep -ac 'строго' flang/proof/checker/checker.c
40
$ grep -ac 'строго' flang/proof/checker.flang
0
```

Версия: flang 0.7.25, прогон 11 октября 2026.

Записей с исходником в корпусе 94; приговор не меняется у 67, меняется у 27, и
все 27 переходов одинаковы — `0 → 3`. То есть на 27 записях «ПРОВЕРЕНО» без ключа
и «ДОКАЗАННЫМИ ЧИСЛЯТСЯ НЕ ВСЕ» с ключом, а какой из двух ответов идёт в долю
доказанного, не сказано ни в описании формата (`docs/flang/proof/SPEC.md`), ни в
справке сверщика: она называет пять ключей и ничего о том, какой режим — приёмка.
У двойника на flang ключа нет вовсе (0 упоминаний против 40), поэтому строгий
вопрос ему не задать; это ожидаемо и отдельной бедой не считается, пока не назван
верный приговор.

## Что должно быть

Долю выпуска снимают **нестрогим** режимом, чтобы число оставалось сравнимым
между выпусками; режим называется в заметках выпуска (`CHANGELOG.md`,
`docs/release-notes.json`). Решения о режиме приёмки при этом нет.

Названо и записано решением, какой режим сверщика — приёмка корпуса: приговор
без ключа или с `--строго`. Прибор доли доказанного
(`scripts/four-coverages.fscript`) считает корпус тем же режимом, и в описании
формата сказано, что значит «числятся доказанными не все» для честной записи.

## Обходной путь

Звать сверщик обоими способами и смотреть оба числа; в споре — читать
`Числятся доказанными N` из вывода, а не код возврата.

## Когда задача сделана

- режим приёмки назван в решении (ADR) и в справке сверщика;
- прогон корпуса в этом режиме даёт одно число и один код, и оно совпадает с
  числом прибора доли доказанного;
- проба краснеет, если запись корпуса меняет приговор между режимами приёмки.

## Где живёт правка

`flang/proof/checker/checker.c` (справка и условия ключа), прибор доли
доказанного `scripts/four-coverages.fscript`, описание формата
`docs/flang/proof/SPEC.md`, решение в `docs/adr/`. Пересборка семени (bootstrap
regeneration) не нужна: сверщик собирается своим `cc`. Что программа на flang
отвергает честную запись в трёх местах — задача 1311, здесь не решается.

**Следующий шаг.** Решение в `docs/adr/` о режиме приёмки корпуса, затем справка в
`flang/proof/checker/checker.c` и режим прибора `scripts/four-coverages.fscript`.
Проба, которая краснеет сегодня, — цикл из шага 3: 27 записей из 94 отвечают 0 без
ключа и 3 с `--строго`, и ни одна страница не говорит, который ответ идёт в долю.
