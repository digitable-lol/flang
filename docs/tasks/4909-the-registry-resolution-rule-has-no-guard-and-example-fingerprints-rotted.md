# 4909. Реестр не зовёт ни одна работа CI: отпечатки примера разошлись 4 из 7, а правило разрешения версий не стережёт никто

Решение: [ADR-0059](../adr/0059-the-registry-is-a-ledger-of-names-not-a-store-of-code.md),
§4 и §7. Обязанность, которая не принуждается:
[ADR-0021](../adr/0021-packages-are-installed-over-the-network-and-locked-locally.md)
п. 3 — «Доверие держит отпечаток, а не сервер».

## Шаги воспроизведения

1. `make -C bootstrap`.
2. Сверка отпечатков ведомости с файлами:
   `cd scripts && ../bootstrap/flang io registry-tool.fscript --plan 'Сверить отпечатки'`.
3. Независимо от двоичного:
   `cd scripts/registry-example && sha256sum *.flang-package` и сличить с полем
   `отпечаток` в `registry.list`.
4. Кто зовёт реестр в CI:
   `grep -rn registry .github/workflows/ .githooks/`.

## Что происходит

Прогон 4 октября 2026, двоичный 0.7.24, `origin/dev` `5bf477f1e`.

```
$ ../bootstrap/flang io registry-tool.fscript --plan 'Сверить отпечатки'
доказано: утверждений 40
FLANG_REESTR_OTPECHATOK: отпечатков не сошлось: 4, сошлось 3
  · Логика 1.0.0 … в реестре 2ea2d0b7…, пересчитано 1dc6da94…
  · Логика 1.2.0 … в реестре 6707a8be…, пересчитано b2bda195…
  · Логика 2.0.0 … в реестре 6fcb5fee…, пересчитано 5374735f…
  · Списки 1.4.2 … в реестре cb87ffcd…, пересчитано 802d716b…
                                                                      код 0
$ grep -rn registry .github/workflows/ .githooks/
release.yml:103:      # замка этот ключ падает с «unable to cache dependencies», а `registry-url`
```

`sha256sum` по тем же четырём файлам даёт ровно «пересчитано»: ведомость
отстала, файлы правы. Записей в ведомости 7, сошлось 3.

Второе: **код возврата у отказа — 0.** Даже если работу CI завести, она
зеленела бы на этом отказе.

Версия: `flang 0.7.24`. Дата прогона: 4 октября 2026.

## Что должно быть

ADR-0021 п. 3 держит на отпечатке всё доверие к чужому пакету; ADR-0059 §7
называет четыре свойства, каждое из которых обязано сдаваться прогоном с
подделкой. Сегодня из четырёх прибора нет ни у одного, а у того, у кого есть
план, нет ни работы CI, ни кода возврата.

## Обходной путь

Запускать `--plan 'Сверить отпечатки'` руками и читать текст — код возврата
верить нельзя. Остальные три свойства проверяются только руками и нигде не
записаны.

## Когда задача сделана

Сторож (`scripts/guards/`) и корпус случаев (`packaging/registry/cases/`),
который сторож проигрывает. Четыре свойства и четыре подделки — ADR-0059 §7:

1. **Отпечатки согласны с файлами.** Сторож пересчитывает `sha256` каждого
   адреса. Подделка: подкрутить один знак отпечатка — сторож называет запись и
   оба отпечатка. Сегодня проверка краснеет по делу (3 из 7), и первая правка —
   пересобрать пакеты примера и ведомость (это же делает задача 3401).
2. **Ответ не зависит от порядка строк ведомости.** Разрешение гоняется на
   перестановках ведомости, ответы сверяются побайтово. Подделка ОБЯЗАТЕЛЬНА и
   другого рода: убрать из ведомости версию, которая выбиралась, — ответ обязан
   измениться (измерено: `Логика 1.2.0` → `Логика 1.0.0`). Без неё сверка
   зеленеет и на приборе, который ведомость не читает.
3. **Отказ назван, а не проглочен.** Четыре запроса из таблицы ADR-0059 §5
   обязаны дать `FLANG_REESTR_KONFLIKT`, `FLANG_REESTR_KONFLIKT`,
   `FLANG_REESTR_ZAPROS`, `FLANG_REESTR_STROKA` — сторож сверяет И код, И текст
   причины. Подделка: снять из текста перечень диапазонов.
4. **Код возврата у отказа не ноль.** Сегодня 0; обязан быть ненулевым, иначе
   работа CI зеленеет на красном.

Плюс работа CI, которая всё это зовёт, и запись в
`scripts/guards/who-calls-the-guards.fscript`, чтобы новый сторож не оказался
сторожем, которого никто не звал.

## Где живёт правка

- `scripts/guards/` — новый сторож (план `.fscript`).
- `packaging/registry/cases/` — корпус случаев: вход (ведомость и нужды) и
  ожидаемый ответ построчно.
- `scripts/registry-example/registry.list` и `*.flang-package` — пересобрать,
  чтобы отпечатки сошлись.
- `scripts/registry-tool.fscript` — код возврата у отказа.
- `.github/workflows/` — работа, которая сторожа зовёт.

Перепечатки семени не требует ничего из перечисленного: `scripts/**` и
`packaging/**` в перепечатку не входят.

**Грабля, на которую наступил замер.** `flang io` считает пути поручений от
каталога ПЛАНА, а не от текущего каталога: прогон плана из каталога вне дерева
читал и ПИСАЛ файлы дерева (`--plan 'Собрать реестр'` перезаписал
`scripts/registry-example/registry.list`). Корпус случаев поэтому обязан лежать
рядом со сторожем, а не подставляться через текущий каталог.
