# 5147. Знак вне BMP: цель C считает его трёхбайтовым

## Как пришло

Issue #103 от 22 сентября 2026: «код символа вне BMP: оболочка отдаёт ведущий
октет UTF-8 вместо кодовой точки». Сообщение верное, диагноз в заголовке —
нет: оболочка ни при чём.

## Замер

Двоичный 0.7.21, ствол `e470e93d2`.

| выражение | `flang run` | `flang repl` |
|---|---:|---:|
| `код символа "﷽"` (U+FDFD, конец BMP) | 65021 | 65021 |
| `код символа "𝒜"` (U+1D49C) | 119964 | **240** |
| `код символа "👍"` (U+1F44D) | 128077 | **240** |

240 = 0xF0 — ведущий октет четырёхоктетной последовательности.

**Оболочка вычисляет ПЕЧАТЬЮ В C и запуском напечатанного** — она и просит
`flang_runtime.h` с `libcompiler_flang.a`, без них отвечает «проверено» и
ничего не считает. Значит спрашивать надо печать, а не оболочку:

```
$ flang emit proba.flang --target c --out out --runtime flang/src/emit/c
$ grep FL_STRING out/proba.c
static const fl_value proba_text_1 = { FL_STRING, { .string = { "𝒜", 3, 1 } } };
                                                                    ↑
                                              байтов объявлено 3, а их 4
```

Беда шире одного `код символа`. Длина объявляется короче на каждый знак вне
BMP, и усечение видно на любой строке:

```
"𝒜тест" → { "𝒜тест", 11, 5 }      байтов 12, объявлено 11, точек 5 — верно
```

Последний октет уезжает за объявленный конец: напечатанная программа выдаст
обрезанную строку, а рантайм при разборе — ведущий октет вместо кодовой точки.
Вычислитель при этом прав: `flang run` отвечает 119964 и `"𝒜тест"` целиком.

## Причина — устаревший довод, записанный в самом коде

`flang/self/emit-c.flang`, до правки строка 2063:

```
// Всё остальное считается трёхбайтовым. Для символов вне BMP это неверно
// (они четырёхбайтовые), и это записано в долг: получить их код нечем.
```

Ширина знака бралась из ПЕРЕЧИСЛЕНИЯ диапазонов: «Однобайтовые» — весь ASCII
строкой из 128 знаков, «Двухбайтовые» — тридцать кусков с перечнем кодовых
точек U+0080..U+07FF, всё остальное — три байта.

Довод перечисления («кодовой точки как числа язык не выдаёт») **устарел и
опровергается пятьюдесятью строками ниже в том же файле**: функция «Октеты
знака» уже зовёт `код символа «знак»`. Форма встроена, перечисление держалось
по инерции, а четвёртая ветвь так и не появилась.

## Что сделано

`flang/self/emit-c.flang`: ширина считается по коду, а не по таблице.

```
  пусть «код» равно (код символа «знак»)
  если «код» меньше 128 то 1
  иначе если «код» меньше 2048 то 2
  иначе если «код» меньше 65536 то 3
  иначе 4
```

Перечисления «Однобайтовые», «Двухбайтовые», «Двухбайтовый» снесены — вне этой
функции их никто не звал (`grep` по `flang/self/*.flang`: 0 вхождений в других
файлах). У «Октеты знака» добавлена четвёртая ветвь и пример
`"𝒜" → [240, 157, 146, 156]`. Файл стал короче на 39 строк.

## Приём

Правка лежит в ПЕЧАТАЕМОЙ части семени, поэтому до перепечатки её в двоичном
нет. Приём снимается ПОСЛЕ `sh scripts/raskrutka.sh`:

```
flang check flang/self/emit-c.flang                    код 0
flang test  flang/self/emit-c.flang                    все примеры, включая четыре новых
flang emit proba.flang --target c | grep FL_STRING     { "𝒜", 4, 1 }
printf 'код символа "𝒜"\n.выход\n' | flang repl        119964
printf 'код символа "👍"\n.выход\n' | flang repl       128077
собрать напечатанное и запустить                        строка печатается целиком
```

Плюс общий приём партии: `sh flang/proof/checker/tests/run.sh` — «сошлось
всё», `sh scripts/доказуемость.sh` — ДОКАЗУЕМ 4 из 4.

## Чего эта задача НЕ закрывает

Остальные девять целей печати (`cpp`, `go`, `rust`, `java`, `js`, `ts`,
`elixir`, `python`, `csharp`) здесь не проверялись: длина в байтах нужна только
цели C, у остальных строка — родной тип языка. **Проверить это прогоном, а не
рассуждением** — отдельным шагом, той же пробой на знаке вне BMP по каждой
цели.
