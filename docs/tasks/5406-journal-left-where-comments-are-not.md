# 5406. В исходниках компилятора остались упоминания снятой реализации на JavaScript вне строк комментариев

Снятая реализация на JavaScript в текстах названа «свидетелем». Упоминания
остались в печатаемых литералах и в именах примеров.

## Шаги воспроизведения

1. `grep -n 'значений свидетеля' flang/self/emit-*.flang`
2. `grep -n 'пример «[^»]*свидетел' flang/self/declared-properties.flang flang/self/types.flang`

## Что происходит

```
$ grep -n 'пример «[^»]*свидетел' flang/self/declared-properties.flang flang/self/types.flang
flang/self/declared-properties.flang:14:  пример «Пять имён и порядок свидетеля»
flang/self/declared-properties.flang:38:  пример «Список даёт list:null — ошибка свидетеля перенесена»
flang/self/declared-properties.flang:176:  пример «Начало сообщения свидетеля знак в знак»
flang/self/types.flang:3178:  пример «Узел без kind назван undefined, как у свидетеля»
```

Первая команда находит строковые литералы, которые печатаются в рантайм цели,
и целей этих семь, а не четыре: `emit-elixir.flang:4082`,
`emit-rust.flang:2776`, `emit-java.flang:3812`, `emit-python.flang:4866` и те же
слова в длинных строках `emit-go.flang:2192`, `emit-csharp.flang:4736`,
`emit-c.flang:4933`. У цели C слова стоят ДВАЖДЫ: в печати (строка 4933) и в
`ожидается` примера рядом (строка 4932), — правка одной строки краснит пример.

Версия: flang 0.7.25, прогон 11 октября 2026. Строки сдвинулись после снятия
комментариев из исходников компилятора; слов «свидетел» в `flang/self/*.flang` —
117 строк, сюда входят и упоминания в именах примеров, и в печатаемых литералах.

## Что должно быть

Исходники не ссылаются на файлы и поведение реализации, которой в дереве нет:
ни в печатаемых литералах, ни в именах примеров.

## Обходной путь

Не нужен: на поведение компилятора это не влияет.

## Когда задача сделана

- две команды из шагов воспроизведения ничего не находят;
- правка литералов меняет байты напечатанного кода всех семи целей — C, Go,
  Rust, Java, C#, Python, Elixir: вывод `flang emit` на одном примере снят до и
  после по каждой цели, и разница состоит только из этих строк;
- у цели C правлены обе строки, 4932 и 4933:
  `grep -c 'значений свидетеля' flang/self/emit-c.flang` отвечает 0, а не 2
  (у остальных шести файлов — 0, а не 1), иначе `ожидается` примера расходится с
  печатью. Весь `flang test` на `emit-c.flang` для этого не годится: он не
  укладывается ни в 300 с, ни в 6 млрд шагов;
- правка имён примеров не меняет числа примеров: `flang test` на
  `flang/self/declared-properties.flang` называет «примеров 185, прошло 185», на
  `flang/self/types.flang` — «примеров 355, прошло 355».

## Где живёт правка

`flang/self/types.flang`,
`flang/self/declared-properties.flang`, `flang/self/emit-c.flang`,
`flang/self/emit-go.flang`, `flang/self/emit-rust.flang`,
`flang/self/emit-java.flang`, `flang/self/emit-csharp.flang`,
`flang/self/emit-python.flang`, `flang/self/emit-elixir.flang`. Всё в
самосборной части: требует перепечатки.

**Следующий шаг.** Семь литералов `значений свидетеля` в `flang/self/emit-*.flang`
(у C — обе строки 4932–4933) и четыре имени примеров в
`flang/self/declared-properties.flang` (строки 14, 38, 176) и `flang/self/types.flang`
(строка 3178). Проба, которая краснеет сегодня, — две команды из шагов
воспроизведения: первая находит восемь строк в семи файлах, вторая — четыре.
