# 5439. Примеры и постусловия самих сторожей не проверяет никто

## Шаги воспроизведения

```
grep -rn 'flang check' .github/workflows/*.yml .githooks/pre-push.fscript | grep -c 'scripts/guards'
ls scripts/guards/*.fscript | wc -l
```

## Что происходит

```
0
51
```

Версия: flang 0.7.23.

Ни одна работа CI и ни один хук не зовут `flang check` по `scripts/guards/`:
сторожей 51, зовов проверки — ноль. Ложный пример в стороже поэтому никого не
красит: так пример «Номер после двоеточия» в
`scripts/guards/traceability-guard.fscript` после замены `abilities.flang:34` на
`abilities.flang:11` ждал `34` при входе `:11`, и `bootstrap/flang check` на
этом файле отвечал кодом 1, не замеченным никем.

Беда не в одном примере: примеры сторожей — единственное, что стоит между
сторожем и молчаливой поломкой, и их не прогоняет никто. Сколько сторожей
красны своим же `flang check` — не измерено; прогон на
`traceability-guard.fscript` стоит около 40 с.

## Что должно быть

1. Перепись: `flang check` по всем сторожам, с кодом и ценой у каждого.
   Красные — поимённо, с причиной.
2. Прогон по сторожам стоит в CI либо в хуке перед пушем — там, где цена
   позволяет, и с храповиком на тех, кто красен по делу.

## Обходной путь

Звать `bootstrap/flang check scripts/guards/<имя>.fscript` руками перед
правкой сторожа. Это и есть то, чего в дереве нет.

## Когда задача сделана

1. Есть прогон, который проверяет примеры сторожей, и он позван — его видит
   `bootstrap/flang run-script guard-calls:check`.
2. У прогона есть проба порчи: ложный пример в сторожа — прогон краснеет.
3. Перепись красных сторожей записана ведомостью, и расти ей нельзя.

## Где живёт правка

- `.github/workflows/` либо `.githooks/pre-push.fscript` — место зова;
- `scripts/ledgers/` — ведомость красных, если долг остаётся.
