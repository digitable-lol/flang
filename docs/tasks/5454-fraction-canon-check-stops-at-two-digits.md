# 5454. Сокращённость литерала точного дробного сверяется только у числителя и знаменателя не длиннее двух разрядов

## Шаги воспроизведения

1. Программа:

```flang
модуль «Длинная несокращённая дробь»

тотальная функция «Две шестых длинными разрядами»
  возвращает точное дробное
  [[2, 0, 0], [6, 0, 0]]
```

   (разряды `[2, 0, 0]` здесь в каноне не стоят — старшие нули; суть
   воспроизведения — числитель и знаменатель из трёх разрядов с общим
   делителем, например `[[0, 0, 2], [0, 0, 6]]`.)

2. Команда: `bootstrap/flang check <файл>`.
3. Смотреть замечание: ждётся отказ «дробь не сокращена», как у `[[2], [4]]`.

## Что происходит

`flang/self/types.flang` строка 484: «дробь длиннее двух разрядов в записи не
сверяется на сокращённость — получите её вычислением»; пример «Длиннее двух
разрядов в записи не сверяется» (строка 529). `docs/flang/SPEC.md` «Точное
дробное» документирует предел. Версия: `flang 0.7.26`.

## Что должно быть

ADR-0062 §7: «Предел «два разряда» для сверки сокращённости может оказаться
тесен раньше, чем ждётся; тогда переносится деление разрядов в типизатор».
Канон дроби должен проверяться у литерала любой длины — тем же делением
разрядов, каким вычислитель сокращает дробь при действии.

## Обходной путь

Получать длинную дробь вычислением (`делить на`), а не литералом: при действии
канон восстанавливается.

## Когда задача сделана

Литерал `[[0, 0, 2], [0, 0, 6]]` отвергается `FLANG_TYPE` со словом «не
сокращена», строка в `flang/proof/probes/exact-fraction/expected.tsv` держит
это; пример «Длиннее двух разрядов в записи не сверяется» в `types.flang`
снят.

## Где живёт правка

`flang/self/types.flang` (сверка литерала дроби), `flang/self/interpret.flang`
(общий код сокращения), `docs/flang/SPEC.md`. Доезжает до двоичного только
перепечаткой семени.
