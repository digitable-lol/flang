# 5555. Планы ввода-вывода написаны рукописной машиной продолжений, хотя форма «в монаде» в языке есть

План ввода-вывода — это сумма «Продолжение» и шаг, разбирающий её: монада,
развёрнутая руками. Так было сделано, пока форма `в монаде` не умела типов, у
которых параметр стоит внутри поля-функции. Частичное применение с тех пор
появилось (`docs/archive/hof.md`), а планы остались прежними.

## Шаги воспроизведения

1. `grep -c 'в монаде' docs/examples/io/*.flang | grep -v ':0'`
2. `grep -l 'в монаде' docs/examples/monad/*.flang flang/self/monad*.flang`

## Что происходит

```
$ grep -c 'в монаде' docs/examples/io/*.flang | grep -v ':0'
                                                              код 1, пусто
$ grep -l 'в монаде' docs/examples/monad/*.flang flang/self/monad*.flang
docs/examples/monad/order-total.flang
flang/self/monad.flang
flang/self/monad-expand.flang
```

Ни один план из `docs/examples/io/` формой `в монаде` не написан. Разворачивает
ли форма тип плана, у которого продолжение стоит полем-функцией, не
перепроверено.

Версия: flang 0.7.23, 30 сентября 2026.

## Что должно быть

Хотя бы один настоящий план написан формой `в монаде` и ведёт себя так же, как
прежняя запись. Либо названо числом и примером, чего форме для этого не
хватает.

## Обходной путь

Писать план рукописной машиной продолжений, как сейчас.

## Когда задача сделана

1. Проба показывает, разворачивает ли `в монаде` тип, у которого параметр стоит
   внутри поля-функции. Если нет — недостающее названо, и задача на этом
   переформулируется.
2. На типе плана объявлена монада, и один план из `docs/examples/io/` переписан
   формой `в монаде`.
3. `bootstrap/flang io` и `bootstrap/flang check` на переписанном плане дают тот
   же исход, что до переписи; печать в цели сходится с вычислителем.
4. Записано решение, остаётся ли рукописная запись второй законной формой.

## Где живёт правка

Один файл из `docs/examples/io/`; если форме чего-то не хватает —
`flang/self/monad-expand.flang` (требует перепечатки).
