## Что случилось

Сослаться на доказанное утверждение по имени в flang можно — так же, как в Lean
ссылаются на лемму. Пишется это словом, которое в языке уже есть:

```flang
теорема «запас неотрицателен»
  дано элементы: список числа
  утверждаем результат не меньше 0
  по свойству «счёт любого списка неотрицателен»
  следовательно доказано
```

Внутри одного файла это работает у обоих судей: ядро отвечает `ДОКАЗАНО`, код 0, и
независимая проверяющая программа переигрывает шаг — на записи дерева
`flang/proof/checker/tests/families/statement/k3c-applying-the-statement.record` она даёт
`ПРОВЕРЕНО`, код 0, и пишет `Шагов по свойству проверено по существу 1`.

**Между файлами ломается запись.** Ядро находит лемму в соседнем файле (утверждения
переносит `flang/self/link.flang:1204`) и отвечает `ДОКАЗАНО`, код 0. А печатает вот это:

```
    шаг 1 строка 14 закрывающий по свойству «счёт любого списка неотрицателен» свойство строка 0
    ход 2 факт по свойству «счёт любого списка неотрицателен» строка 8 подстановка «л» ⟨элементы⟩
```

`строка 0` — заголовок леммы искали в строках входного файла и не нашли
(`flang/self/zapis.flang:887`). `строка 8` — строка **чужого** файла, а про этот файл в
записи не сказано ничего: у записи одно поле `исходник` и один `отпечаток256`.

Независимая проверяющая программа на такой честной записи отвечает **кодом 1,
`НЕ СОШЛОСЬ`** — то есть зовёт её ложью, а не «не взялся». Тот же ответ она даёт, если
файл леммы вовсе убрать с диска (она его не читает), и тот же — если подать лемму ключом
`--зависимость ИСХОДНИК ЗАПИСЬ`: ключ в проверяющей программе есть, но подключён только к
разделу тотальности (`flang/proof/checker/checker.c:9720`).

## Почему это важно именно сейчас

Библиотека доказательств [задачи 1400](1400-fmath-biblioteka-dokazatelstv-o-programmah.md)
— это по определению леммы в отдельных файлах, на которые ссылаются из чужих программ.
Пока запись не переживает границу файла, каждая такая ссылка будет давать место, которое
ядро числит доказанным, а второй судья — ложным. Доля проверенного от этого не вырастет,
а упадёт.

Сегодня это ещё никого не жгло: файлов `.flang`, соединённых словом `использует`, в дереве
**2** из **958**, и записей с блоком `вид statement` в корпусе доли **0**.

## Что сделать

Пункты 1–4 §6 решения, в этом порядке.

1. **Ядро перестаёт печатать `строка 0`.** Ссылка, ушедшая за границу файла, либо
   выписывается целиком, либо место отказывается, либо вердикт печатается так, что
   проверяющая программа читает его «на слове ядра» (код 3). Молча ставить ноль нельзя:
   место выглядит доказанным и проверенным, а на сверке даёт код 1.
2. **Шапка записи называет привлечённые файлы:** строка `привлечён «<путь>» отпечаток256 <…>`
   на каждый файл, откуда взята хоть одна лемма.
3. **Привязка шага и хода называет файл:** `свойство файл «<путь>» строка N` и
   `факт по свойству «И» файл «<путь>» строка N подстановка …`. Файл обязан стоять среди
   `привлечён`, отпечаток обязан сойтись.
4. **Блок леммы едет в записи потребителя** — ядро её в том же прогоне и так доказывает,
   так что реестр «доказано РАНЬШЕ этой цели» наполняется из самой записи, и сторож круга
   работает между файлами теми же строками, что внутри файла.
5. **Проверяющая программа читает названные файлы:** сверяет отпечатки, берёт цель и
   ограничения леммы из названного исходника, переигрывает ход К3c. Подключить к разделу
   доказательств уже имеющиеся `--зависимость` и `--набор`.
6. **Подделки** на каждый новый сторож в
   `flang/proof/checker/tests/families/statement/corrupt/`: чужой отпечаток; файл не назван
   в шапке; `строка 0`; ссылка на лемму из файла, который не привлечён.

  работает; второе означало бы два словаря на одну вещь.

  затем, чтобы не сверять снимок со снимком.
- **Научить проверяющую программу молчать про `строка 0`.** Это превратит код 1 в код 0 без
  единой новой проверки.

## Как поймём, что сделано

Честная проба: лемма в одном файле, ссылка на неё из другого. Ядро — код 0; независимая
проверяющая программа на записи потребителя — код 0, и в её отчёте `Шагов по свойству
проверено по существу` выросло на этот шаг. Правка файла леммы после печати записи роняет
сверку. Каждая подделка §6 п.6 отвергается, и копия проверяющей программы без нового
сторожа её принимает.
