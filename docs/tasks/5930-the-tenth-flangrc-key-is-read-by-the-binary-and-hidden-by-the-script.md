# 5930. Десятый ключ `.flangrc` читается двоичным и не виден оснастке

## Гипотеза до замера

Записана прежде прогонов, чтобы было с чем сверить результат:

1. в `.flangrc` девять ключей, `недоказанное` среди них нет;
2. читают файл `scripts/flangrc.sh` и работы CI;
3. у двоичного есть ключ `--unproven` с тремя исходами;
4. **`.flangrc` двоичный не читает вовсе** — чтение придётся писать
   в `flang/src/emit/c/flang_repl.c`.

**Пункт 4 замером опровергнут**: чтение уже написано, уже в семени и уже
работает. Работы в двоичном не осталось ни строки — осталась только оснастка.

## Замер 23 сентября 2026, ствол `ccfcbae43`, двоичный 0.7.21

### Что в файле и кто его читает

```
$ wc -l .flangrc
11 .flangrc
$ grep -c 'недоказанн' .flangrc
0
```

Девять ключей: `язык поверхность цвет страница версия имя лицензия склад беды`.
Ключа `недоказанное` в файле проекта нет.

### Что понимает двоичный

`flang run --help` и `flang io --help` называют один и тот же ключ и те же три
исхода:

```
--unproven СЛОВО   что делать с недоказанной, все три исхода сразу:
                   refuse — не запускать (умолчание), warn — сказать и
                   запустить, allow — запустить, вердикта не считая (то же,
                   что «--trust»). Кириллицей — «--недоказанное отказ |
                   предупреждение | разрешение»
```

Написаний у значения **шесть на три исхода**, и письмо ответа повторяет письмо
вопроса. Прогон на `flang/proof/probes/unproven/programs/unproven.flang`
(недоказанная «Удвоить», одно утверждение):

| что задано | код | хвост строки |
| --- | ---: | --- |
| ничего | 3 | `— запуск только по явному согласию: --на-веру` |
| `.flangrc`: `недоказанное = отказ` | 3 | `— запуск только по явному согласию: --на-веру` |
| `.flangrc`: `недоказанное = refuse` | 3 | `— запуск только по явному согласию: --trust` |
| `.flangrc`: `недоказанное = предупреждение` | 0 | `— запуск по настройке «недоказанное = предупреждение» (путь)` |
| `.flangrc`: `недоказанное = warn` | 0 | `— запуск по настройке «недоказанное = warn» (путь)` |
| `.flangrc`: `недоказанное = разрешение` | 0 | `на веру: доказанность не считалась — запуск по настройке …` |
| `.flangrc`: `недоказанное = allow` | 0 | то же |
| `.flangrc`: `недоказанное = разрешено` | 2 | `«разрешено» — такого значения у «недоказанное» нет (путь)` |
| `.flangrc`: `чепуха = что угодно` | 3 | умолчание, незнакомый ключ пропущен молча |
| среда `FLANG_UNPROVEN=allow` | 0 | `запуск по переменной среды FLANG_UNPROVEN=allow` |
| среда `FLANG_UNPROVEN=да` | 2 | `«да» — такого значения … (переменная среды FLANG_UNPROVEN)` |
| файл `разрешение` + ключ `--unproven refuse` | 3 | ключ перебил файл, ответ письмом ключа: `--trust` |
| файл `разрешение` + ключ `--недоказанное отказ` | 3 | то же, ответ кириллицей: `--на-веру` |
| файл `разрешение` + среда `refuse` | 3 | среда перебила файл |

**Старшинство держится целиком**: ключ команды → `FLANG_UNPROVEN` → `.flangrc`
проекта → `.flangrc` дома → умолчание `отказ`.

Код чтения — `flangrc_project` и `flangrc_key` в
`flang/src/emit/c/flang_repl.c`; в семени он уже есть
(`grep -c 'UNPROVEN_KEY\|FLANG_UNPROVEN' bootstrap/flang_repl.c` → 8).
Пробы — `flang/proof/probes/unproven/` (22 строки `expected.tsv`).

### Чего оснастка не умеет

```
$ sh scripts/flangrc.sh недоказанное
                                        ← пустая строка
$ echo $?
0
```

Это худший из возможных ответов: не «такого ключа нет», а тишина, неотличимая
от «ключ есть, значение пустое». Причина — `scripts/settings-file.flang`:

```
$ bootstrap/flang run scripts/settings-file.flang --function «Годное» \
    --args '{"ключ":"недоказанное","значение":"предупреждение"}'
""
```

Списки ключей в решателе закрыты: `«Ключи настроек»` — девять имён,
`«Годное»` сверяет значение с `«Коды языков»`, `«Значение по умолчанию»`
незнакомому ключу отдаёт пустоту. Новый ключ до печати не доходит.

## Решение, записанное прежде кода

**Имя ключа — `недоказанное`.** Выбирать не из чего: имя уже назначено
двоичным (`#define UNPROVEN_KEY "недоказанное"`), и второго имени у одного
ключа быть не может.

**Значений три, написаний шесть**: `отказ`/`refuse`, `предупреждение`/`warn`,
`разрешение`/`allow`. Список закрыт двоичным, оснастка его повторяет.

**Довод командной строки старше файла.** Довод набран рукой в эту минуту, файл
написан когда-то; кроме того, ключ, который нельзя отменить на один прогон,
терял бы единственное своё назначение. Это не выбор задачи, а уже принятое
правило: так же устроены остальные девять ключей
(`docs/guide/settings.ru.md`, «Что старше чего»), и так уже ведёт себя
двоичный — замерено выше тремя строками таблицы.

**Локаль за `недоказанное` не голосует**: она говорит о языке машины, а
ворота недоказанного — не про язык.

**Ключа нет вовсе — `отказ`, и это не ломающее изменение.** Проверено
прогоном: вывод без файла и вывод с `недоказанное = отказ` совпадают знак в
знак — код 3 и хвост `— запуск только по явному согласию: --на-веру`.
Отличается только `недоказанное = refuse`: хвост становится `--trust`, потому
что письмо ответа повторяет письмо вопроса. Поэтому в `.flangrc` этого проекта
ключ записан **кириллицей**.

## Что сделано этой веткой

1. `.flangrc` — десятый ключ `недоказанное = отказ` (поведение то же, знак в знак);
2. `scripts/settings-file.flang` — ключ в списке, шесть годных слов, умолчание `отказ`;
3. `scripts/flangrc.sh` — ключ в списке печати и переменная среды `FLANG_UNPROVEN`;
4. `docs/guide/settings.ru.md` — файл проекта и вывод оснастки переписаны на десять ключей.

## Что осталось сделать в двоичном и сколько это стоит

**В двоичном не осталось ничего.** Ключ `недоказанное` он читает сам, своим
разбором, и это уже в семени — прогоны выше сняты собранным двоичным 0.7.21
(`bootstrap/flang_repl.c`, 8 упоминаний `UNPROVEN_KEY`/`FLANG_UNPROVEN`).

Если правка в этом месте всё же понадобится, её цена названа точно:
`flang/src/emit/c/flang_repl.c` — **копируемая** часть семени
(`scripts/seed/seed-runtime-is-source.sh`: семя рантайма = шапка + источник),
поэтому доставка — **быстрый пересев, минуты**, а не 21 час печати. Печать
21 час стоит только `bootstrap/compiler_flang.c`, печатаемый из `flang/self`,
и к ключам `.flangrc` он отношения не имеет.

Осталась одна честная дыра, и она чужая — **задача 5413**: остальные девять
ключей двоичный по-прежнему не читает. Её шапка при этом устарела и врёт:
в ней записано «`bootstrap/*.c`: flangrc 0», а сегодня
`grep -c flangrc bootstrap/flang_repl.c` даёт не ноль. Верное утверждение
теперь узкое: двоичный читает **один** ключ из десяти.
