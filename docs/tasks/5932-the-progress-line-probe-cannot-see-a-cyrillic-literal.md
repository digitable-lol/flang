# 5932. Примета «строка хода» снята прибором, который не назван и кириллицу видит не всегда

Приёмка нового двоичного (`bootstrap/flang run-script binary:acceptance`) снимает
примету 3 поиском приметной подстроки в двоичном. Беда делится на три:

1. `strings` кириллицу не печатает вовсе, и счёт был нулём на любом двоичном.
2. Прибор в примете не назван: читатель видит число и вердикт, но не видит, чем
   снято, и повторить замер руками не может.
3. Прибора может не оказаться (`grep` не на `PATH`, двоичный не читается) — счёт
   тоже ноль, и примета говорит «строки хода НЕТ», сваливая отказ прибора на двоичный.

## Шаги воспроизведения

1. `strings` и кириллица — на файле с одной кириллической строкой:

```sh
printf 'шагов 5 из 10 (0 %%), идёт «Шаг плана»\nplain ascii line here\n' > f
strings f                 # кириллической строки в выводе нет
strings -e S f            # с однобайтовой кодировкой — есть
grep -c 'шагов' f         # 1
```

2. Тот же прибор на собранном двоичном и `grep` по тому же файлу:

```sh
strings bootstrap/flang | grep -c 'шагов'        # 0
grep -ao 'шагов' bootstrap/flang | wc -l         # 112
```

3. Отказ прибора неотличим от отсутствия строки — приёмка на целом двоичном, но
   без `grep` на `PATH`:

```sh
env PATH=<каталог без grep> bootstrap/flang io scripts/seed/new-binary-acceptance.fscript \
  --plan Accept --timeout 3600000 -- <дерево со строкой хода>
```

4. Увидеть строку хода своими глазами: позвать долгий прогон, например
   `bootstrap/flang check flang/self/proof-record.flang`, — он печатает
   `шагов 9 151 654 516 из 4 000 000 000 000 (0 %), идёт «Проверить доказательства с кешем», 1,9 ГиБ`.

## Что происходит

```
$ strings f
 10 (0 %),
plain ascii line here
$ strings bootstrap/flang | grep -c 'шагов'
0
$ grep -ao 'шагов' bootstrap/flang | wc -l
112
```

Цельного литерала со всем шаблоном в файле нет и для `grep`:
`grep -ac 'шагов .* из .*, идёт' bootstrap/flang` отвечает 0 — строка хода
складывается из кусков, и приметой годится только кусок.

Без `grep` на `PATH` примета 3 отвечала:

```
=== ПРИМЕТА 3 — строка хода
    вхождений строки хода: 0   (нужно больше 0)
  ✗ строки хода НЕТ: приметная подстрока в двоичном не встретилась
```

— то есть называла целый двоичный слепым, когда слеп был прибор.

## Что должно быть

Примета 3 судит по прибору, который кириллицу видит, и краснеет только тогда,
когда строки хода в двоичном действительно нет. Прибор назван в самой примете
дословно — так, чтобы замер повторялся руками копированием строки. Поиск идёт
байтами: локаль прибита, приметная подстрока — строка, а не выражение. Отказ
прибора говорит «примета НЕ СНЯТА», а не «строки хода нет». У приметы есть
отрицательный контроль на каждый из трёх исходов.

## Обходной путь

Снимать примету 3 руками: `LC_ALL=C grep -c -a -F -- ', идёт «' <двоичный>`
больше нуля, либо позвать долгий прогон и увидеть строку хода в выводе.

## Когда задача сделана

Три исхода сняты прогонами на разных двоичных, а не рассуждением:

```sh
bootstrap/flang io scripts/seed/new-binary-acceptance.fscript --plan Accept \
  --timeout 3600000 -- <дерево со строкой хода>   → примета 3 зелена, «строк с приметой: 1»
bootstrap/flang io scripts/seed/new-binary-acceptance.fscript --plan Accept \
  --timeout 3600000 -- <дерево без строки хода>   → примета 3 красна, «строки хода НЕТ»
env PATH=<без grep> bootstrap/flang io scripts/seed/new-binary-acceptance.fscript \
  --plan Accept --timeout 3600000 -- <дерево со строкой хода>
                                                  → примета 3 красна словами «примета НЕ СНЯТА»
```

Строка прибора стоит в выводе приметы. У функций «Progress judged» и «Tree note»
есть пример на каждый исход, и порча ветки краснит именно его.

## Чем закрыта

Коммит `ee93cace0` в ветке `a/5908-proof-record-steps`. Прибор назван в выводе
приметы, поиск идёт байтами, отказ прибора говорит «примета НЕ СНЯТА». Три
исхода сняты прогонами приёмки (двоичный 0.7.24, 4 октября 2026):

| цель прогона | примета 3 | примет красно |
|---|---|---:|
| двоичный со строкой хода | зелена, «строк с приметой: 1» | 3 |
| тот же двоичный, литерал выбит побайтно | красна, «строки хода НЕТ» | 4 |
| двоичный со строкой хода, `grep` не на `PATH` | красна, «примета НЕ СНЯТА» | 6 |

Третий исход до правки был «строки хода НЕТ» — отказ прибора списывался на
двоичный. Замечаний линтера 16 до и 16 после, тот же набор.
