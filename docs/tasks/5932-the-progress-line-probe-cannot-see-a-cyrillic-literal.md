# 5932. Примета «строка хода» в приёмке ищет кириллицу через `strings`, а он её не печатает

Приёмка нового двоичного (`bootstrap/flang run-script binary:acceptance`) снимает
примету 3 так:

```
strings "$0" 2>/dev/null | grep -c "шагов .* из .*, идёт"
```

`strings` по умолчанию собирает строки из печатных знаков одного байта, а
кириллица в UTF-8 — два байта со старшим битом. Ни одна кириллическая строка в
вывод `strings` не попадает, поэтому счёт равен нулю всегда — и на двоичном, где
строка хода есть, и на двоичном, где её нет.

## Шаги воспроизведения

1. Проверить `strings` на файле с одной кириллической строкой:

```sh
printf 'шагов 5 из 10 (0 %%), идёт «Шаг плана»\nplain ascii line here\n' > f
strings f
grep -c 'шагов' f
```

2. Спросить тем же прибором собранный двоичный и сравнить с `grep`:

```sh
strings bootstrap/flang | grep -c 'шагов'
strings bootstrap/flang | grep -c 'конкурентност'
grep -ao 'шагов' bootstrap/flang | wc -l
```

3. Увидеть строку хода своими глазами: позвать долгий прогон, например
   `bootstrap/flang run-script links:check`, — он печатает
   `шагов 9 134 337 из 4 000 000 000 000 (0 %), идёт «Шаг плана», 591 МиБ`.

## Что происходит

```
$ strings f
 10 (0 %), 
plain ascii line here
$ grep -c 'шагов' f
1
$ strings bootstrap/flang | grep -c 'шагов'
0
$ strings bootstrap/flang | grep -c 'конкурентност'
0
$ grep -ao 'шагов' bootstrap/flang | wc -l
125
```

Версия: flang 0.7.23, GNU strings 2.46. Дата прогона: 2 октября 2026.

`strings` не видит в двоичном ни одного кириллического слова: ни «шагов», ни
«конкурентност». `grep` по тому же файлу находит «шагов» 125 раз. Значит, примета
3 даёт «строки хода НЕТ» независимо от двоичного, и её единица попадает в счётчик
приёмки (задача 5963), а итог — `Двоичный НЕ ПРИНЯТ`, код 1.

Цельного литерала с таким шаблоном в файле нет и для `grep`:
`grep -ac 'шагов .* из .*, идёт' bootstrap/flang` отвечает 0 — строка хода
складывается из кусков, и обходной путь ищет только слово «шагов».

## Что должно быть

Примета 3 судит по прибору, который кириллицу видит, и краснеет только тогда,
когда строки хода в двоичном действительно нет. Прибор назван в самой примете, и
у приметы есть отрицательный контроль: на двоичном без строки хода она краснеет, на
двоичном со строкой — зеленеет.

## Обходной путь

Снимать примету 3 руками: `grep -ao 'шагов' <двоичный> | wc -l` больше нуля, либо
позвать долгий прогон и увидеть строку хода в выводе.

## Когда задача сделана

```sh
bootstrap/flang io scripts/seed/new-binary-acceptance.fscript --plan Accept \
  --timeout 3600000 -- <дерево со строкой хода>     → примета 3 зелена
bootstrap/flang io scripts/seed/new-binary-acceptance.fscript --plan Accept \
  --timeout 3600000 -- <дерево без строки хода>     → примета 3 красна
```

Оба исхода сняты прогоном на разных двоичных, а не рассуждением. У функции
«Progress sign» есть пример на каждый из двух исходов.

## Где живёт правка

`scripts/seed/new-binary-acceptance.fscript`: «Signs», поручение
`"progress line"`. Перепечатка не нужна.
