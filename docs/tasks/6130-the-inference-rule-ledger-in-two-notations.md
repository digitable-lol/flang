# 6130. Ведомость правил вывода есть, но спецификация из неё не порождается, и образцов на правила нет

Основание — `docs/adr/0022-a-type-fact-travels-as-a-derivation.md`, разделы 3
и 5: у правил вывода один источник (`flang/proof/tables/inference-rules.tsv`) и
две нотации, логическая и категорная. Ведомость заведена, проверка
`flang/proof/tables-guard.fscript` есть. Остальное не сделано.

## Шаги воспроизведения

1. `grep -vc '^#' flang/proof/tables/inference-rules.tsv`
2. `grep -c 'Правила вывода как стрелки' docs/ct/spec.md`
3. `git ls-files flang/ct | wc -l`
4. `bootstrap/flang io flang/proof/tables-guard.fscript --max-steps 4000000000 --timeout 900000`
   — смотреть строку раздела С-2.

## Что происходит

```
$ grep -vc '^#' flang/proof/tables/inference-rules.tsv
119
$ grep -c 'Правила вывода как стрелки' docs/ct/spec.md
0                                                           код 1
$ git ls-files flang/ct | wc -l
17
$ bootstrap/flang io flang/proof/tables-guard.fscript …
── С-2: непротиворечивость записи ведомости ──
   правил 102 (из них по ADR §3 — 90), запретов 16 (из них по ADR §3 — 5)
…
сошлось всё: 118 строк ведомости, пять сторожей зелены          код 0
```

В ведомости больше ста правил, в `docs/ct/spec.md` таблицы правил нет, пар
«честная программа и подделка» на каждое правило в `flang/ct/` нет: семнадцать
файлов каталога — примеры категорных конструкций, а не пары по правилам.
Строка «правил восемь» из `docs/flang/proof/SPEC.md` ушла: сегодня спецификация
числа правил не называет вовсе и отсылает к ведомости (строки 237, 384–385).

Строк в ведомости 119, из них одна — заголовок колонок, правил 102 и запретов 16.
Отпечаток `flang/proof/tables/inference-rules.digest` сходится с ведомостью (раздел
С-4 того же сторожа), и привязки правил к `flang/self/proof-kernel.flang` свежие.
Сверка имён с ядром и обоими сверщиками есть: `flang/proof/rules-match.fscript`
зовётся соседом из раздела С-1 («сосед rules-match.fscript --list-only согласен»).
Числа сняты 11 октября 2026.

Версия: flang 0.7.25, дерево 1149c78f7.

## Что должно быть

Имя, посылки, заключение и побочные условия правила берутся из ведомости всеми,
кто о правилах говорит: спецификацией, обоими проверяющими записей и текстами
отказов ядра.

## Обходной путь

Читать ведомость, а не спецификацию.

## Когда задача сделана

1. `docs/ct/spec.md` несёт раздел «Правила вывода как стрелки», порождённый из
   ведомости; проверка сверяет его с ведомостью знак в знак и краснеет на
   подлоге.
2. `docs/flang/proof/SPEC.md` либо называет число правил, равное числу строк
   ведомости, либо, как сегодня, числа не называет и отсылает к ведомости.
3. На каждое правило в `flang/ct/` есть пара: честная программа (код 0 или 2)
   и подделка, где нарушено ровно одно побочное условие (код 1 с названной
   причиной); на каждый запрет ведомости — подделка.
4. `bootstrap/flang io flang/proof/rules-match.fscript` сверяет имена
   ведомости с ядром и с обоими проверяющими записей (план есть и зовётся из
   С-1); лишнее имя в ведомости даёт код 1 и названо — это показано подлогом.
5. `flang/proof/tables-guard.fscript` краснеет на двух подлогах: «Точный
   потолок» в ядре изменён на единицу; у правила убрана одна посылка из
   логической колонки.

Печать ядра здесь не меняется (задача 6132). Аксиом не заводить: каждое правило
ведомости выводимо ядром.

## Где живёт правка

`flang/proof/tables/inference-rules.tsv`, `flang/proof/tables-guard.fscript`,
`flang/proof/rules-match.flang`, `docs/ct/spec.md`,
`docs/flang/proof/SPEC.md`, `flang/ct/`. Перепечатка не нужна. Расхождение
текста отказа и кода у правила вхождения — задача 6133.

## Следующий шаг

Дописать в `flang/proof/tables-guard.fscript` раздел, который порождает из колонки
категорной записи ведомости текст раздела «Правила вывода как стрелки» и сверяет его с
`docs/ct/spec.md` знак в знак, и положить в `docs/ct/spec.md` первый порождённый текст.
Проба, которая краснеет сегодня: шаг 2 отвечает 0. Пары программ в `flang/ct/` — вторым
заходом, по одной семье правил.
