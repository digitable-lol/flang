# 6206. ADR-0026 §11 п.14: квантор по элементам списка

## Что известно из замера

Слово владельца (11 сентября 2026): «Про „для всех элементов этого списка“ — так реализуй».

В ADR-0026 §11 такого пункта нет: пункты 1–13 говорят о кванторе над ВХОДАМИ функции
(«для всех л» при `л: список числа` ведёт индукцию по списку, п.1–2), о свободном
утверждении (п.3), об ограничении «таких что» (п.6) и о существовании (п.7). Ближайшее —
§5 шаг 1 (квантор над списком как носителем индукции) — говорит о самом списке, а не о его
элементах. Пункт заведён этой задачей как **п.14** (ADR-0026 §11).

Сегодня «все элементы результата положительны» пишется только свёрткой
(`docs/zettel/substantive-claims-are-provable-when-you-pick-the-shape.md`: «на пустом
списке истинно пусто, и заглушка его переживает»), а ядро такую цель сличает синтаксически
(`docs/proof-goal-map.md` §6: «квантор по элементам и упорядоченность не берутся никогда»).
Семья A разведки `docs/design/proof-object-migration-po-primeru.md` (6 мест корпуса —
свёртка-цель над литеральным списком) — та же нехватка с другой стороны.

Что есть в дереве и на что опирается работа (снято по `r/partiya-2` `6b7c43f86`):

| слой | где | что |
| --- | --- | --- |
| разбор | `parser.flang` «Разобрать цель» | цель целиком: `есть такой …` (п.7) либо выражение |
| типы | `types.flang` «Тип узла» | закрытый разбор видов узла; `exists` — с 6205 |
| вычислитель | `interpret.flang` | `exists` — кадр «пусть» над свидетелем (6205) |
| ядро | `proof-kernel.flang` «Свести правилами при фактах» | семь правил по виду цели; «вхождение по построению» (В1–В4) — образец «по построению» над списком |
| печать | `zapis.flang` «Шаги отношений записи» | блок `вывод` восстанавливается ТЕКСТОМ из цели и тела |

| ведомость | `ПРАВИЛА-ВЫВОДА.tsv` (88 строк) + `Правила.lean` (85 лемм) + `Ловушка.lean` (10 искажений) | |

## Что сделать

Форма (русская и английская, новых слов нет — `для всех`/`for all` и `из`/`from` уже в
словаре, `lexer.flang` «Куски таблицы»):

```
обеспечивает «все положительны» для всех п из результат: п больше 0
ensures "all positive" for all p from result: p greater than 0
```

Квантор стоит В ЦЕЛИ (как `есть такой`, п.7), а не перед `обеспечивает`: строка
`для всех л обеспечивает …` по-прежнему называет переменную индукции (п.1–2). Разделитель
тела — `:` (тот же, что у `отфильтровать Л где х: …`). Узел `forallIn` {over, item, body}
— той же формы, что `filter`, чтобы все связыватель-осведомлённые обходы (подстановка,
захват, свободные имена, сличение с переименованием) знали его одной добавкой к списку.

- **Ш0 — разбор, типы, вычислитель.** «Разобрать квантор по элементам»; «Тип всех
  элементов» (Л обязан быть списком, имя связывается типом элемента, тело — признак);
  вычислитель считает квантор свёрткой `начиная с да … если акк то У иначе нет` (на пустом
  списке — `да`).
- **Ш1 — ядро.** Новое семейство правил **Э** «все элементы по построению»
  (`«Свести всеми элементами»`): Э1 пустой список; Э2 `отфильтровать Л где х: У` при
  У[х:=п] ≡ П знак в знак (с точностью до имени связанной); Э3 `добавить Х к Л'`/`приписать`
  при посылках П[п:=Х] и ∀п∈Л'.П; Э4 `если У то А иначе Б` при обеих ветвях. Гипотеза
  индукции и допущения — прежним правилом Т1 («цель есть допущение»); ветвление по условию
  тела — прежним пятым ходом (Р). Всё, что не подошло, — названный отказ.
- **Ш2 — печать и сверщик.** `zapis.flang` восстанавливает блок `вывод` для Э1–Э4
  (посылка П[п:=Х] — Выч на замкнутой формуле либо Т1 по строке `требует`); `сверщик.c`
  переигрывает семейство Э (`все_элементы_вывода`, `шаг_всех`), знает имя правила и не
  путает квантор цели с квантором индукции (`имена_квантора`). Разделитель `:` в термах
  разводится пробелами в обоих читателях (`терм`, «Терм записи»).
- **Ш3 — ведомость, Lean, пробы.** Четыре строки Э1–Э4 в `ПРАВИЛА-ВЫВОДА.tsv`
  (семейство Э — четырнадцатое), леммы в `Правила.lean` (модель: `«всеЭ»`, `«отбор»`),
  искажение 11 в `Ловушка.lean` (Э2 с чужим предикатом); семья проб
  `пробы/семьи/все-элементы/` — честные записи и порчи (чужой предикат, пропущенная база,
  подменённый хвост, одна ветвь); зонд толкованием на честных программах.

## Чего эта задача НЕ делает

Не выводит квантор по элементам из свёртки-цели корпуса (семья A разведки «по примеру») —
это перепись целей корпуса, а не форма языка. Не заводит квантор по элементам в `требует`
(п.5 ADR-0026 — задача-наследник). Не берёт выписанный список с элементами (`[а, б]`): у
сверщика посылок в шаге не больше двух, а список из одного пишется `приписать а к пустой
список`. Не берёт `отобразить` (∀ над образом требует ∀ над прообразом с другим предикатом
— своё правило и своя лемма). Печатники целей (`emit-*`) узла не знают — как и у `exists`
(6205). Ходы посылок индукции ядро не печатает — посылки индукционного пути остаются на
слове ядра, как у всех индукций сегодня.

## Как понять, что сделано

- зонд над правленым `flang/self`: честная программа с `для всех п из результат: …` —
  «доказано», правило «все элементы по построению», запись с блоком `вывод` Э-шагов;
- сверщик: честная запись — код 0, «проиграно выводом»; порчи — код 1 с названной причиной;
- `sh flang/proof/чекер/пробы/прогон.sh` — «сошлось всё»; `sh scripts/доказуемость.sh` —
  ДОКАЗУЕМ, доля не ниже 625/651, «снято калькулятором» не выше 6;
- `LEAN=… sh flang/proof/lean/прогон.sh` — «сошлось всё», лемм 85 → 89, искажений 10 → 11;
- `sh flang/proof/сверка-ведомости.sh` — шесть сторожей зелены, С-6 в потолке.
