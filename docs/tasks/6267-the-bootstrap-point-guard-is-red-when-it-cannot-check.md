# 6267. Сторож точки раскрутки зелен, когда проверить нечем

## Шаги воспроизведения

1. Чистая копия ствола без собранного двоичного:
   `git worktree add --detach <копия> gh/dev` — в `<копия>/bootstrap/` нет `flang`.
2. Сторож запускается двоичным, собранным в другой копии (своего в дереве нет):

   ```sh
   cd <копия>
   <другая копия>/bootstrap/flang io scripts/seed/bootstrap-point-by-binary.fscript --timeout 2400000 --на-веру
   echo "код $?"
   ```

3. Смотреть: слово `result` в выводе и код возврата.

## Что происходит

До правки (ствол `7e4634dec`, `flang 0.7.22`, 27 сентября 2026), вывод
сокращён до поля `result`, журнал поручений опущен:

```
на веру: доказанность не считалась — запуск по ключу --на-веру
{"plan":"Точка раскрутки совпадает с печатью двоичного","result":"точка двоичным: НЕ ПРОВЕРЕНО — двоичного нет — соберите его: make -C bootstrap","orders":3,"log":[…]}
код 0
```

Функция `«Не проверено»` строила `вариант «Конец работы»`, то есть успех. В
неё уходили пять ветвей: в `/proc/meminfo` нет строки `MemTotal`; памяти меньше
32 ГиБ; `/proc/meminfo` не прочитан; в каталоге точки нет двоичного; каталога
точки нет. На любой машине меньше 32 ГиБ и на любом дереве без двоичного
сторож был зелен.

## Что должно быть

Код 0 — проверено и сошлось, 1 — проверено и разошлось, 3 — проверить нечем.
Так уже отвечает `flang io` на `вариант «Не проверено»`
(`flang/src/emit/c/flang_repl.c`, «ЧЕТВЁРТЫЙ ИСХОД»), так же отвечают вердикт
доказанности и планы семени (`scripts/seed/print-is-repeatable.sh`,
`scripts/seed/two-prints-identical.sh`).

## Обходной путь

Читать вывод глазами и искать «НЕ ПРОВЕРЕНО». Машина, смотрящая на код, обхода
не имела.

## Когда задача сделана

`/tmp/claude-1000/…/scratchpad/bp` двоичным ветки. Печать двоичным в настоящем
рецепте идёт 35 ч 45 мин (`scripts/bootstrap-c.sh`, замер 25 сентября), поэтому
в прогонах «с двоичным» и «подделан байт» печать подменена ключом рецепта
`FLANG=<печать>`: подставной печатник кладёт в каталог печати файлы
`bootstrap/` ствола `gh/dev` (без `README.md`). Сверка набора и байтов,


Поручения обоих прогонов (4: `/proc/meminfo`, рецепт, каталог `bootstrap`,
`sh -c "… bootstrap-c.sh --check"`) и ответ сверки сравнены `diff` — совпали.

```

```

Ветви памяти подделать прогоном нельзя: сторож читает `/proc/meminfo` по
абсолютному пути, а `unshare` в песочнице запрещён. Они закреплены примерами,
которые `flang check` прогоняет при каждой проверке: нет `MemTotal`, 7 ГБ из 32,
`/proc/meminfo` не прочитан — каждый даёт `вариант «Не проверено»`. Порча
ожидаемого «7 ГБ» на «8 ГБ» и правила `kilobytes равен 0` на `равен 1` —
`flang check` краснеет `FLANG_EXAMPLE`.

Проба на возврат дефекта: вернуть в `«Cannot check»` `вариант «Конец работы»`
— снято: краснеют все шесть примеров, ждущих `вариант «Не проверено»`
(`FLANG_EXAMPLE` шесть раз).

## Где живёт правка

- `scripts/seed/bootstrap-point-by-binary.fscript` — был планом, остался им.
  `«Не проверено»` заменена на `«Cannot check»` → `вариант «Не проверено»`
  с кодом `FLANG_BOOTSTRAP_POINT_NOT_CHECKED`. Лестницы `если … иначе если` в
  разборе памяти и ответа сверки заменены списками правил (`«Memory rules»`,
  `«Comparison rules»`) и `разбор` по первому сработавшему. Память машины
  несёт состояние плана до конца и называется в зелёном ответе. Комментарии
  (45 строк) сняты, строка из `scripts/ledgers/no-comments-debt.tsv` убрана.
  Постусловие «ход вида Ждём рецепт уходит своей ветвью» снято: вариант теперь
  несёт память, и сравнение с голым вариантом больше не пишется; добавлены два
  постусловия о длине списков правил. Итог вердикта: было 7 (доказано 6, сетка 1),
  стало 8 (доказано 7, сетка 1).
- `flang/scripts/run-verdict-debt.tsv`, `scripts/ledgers/proved-share-ledger.txt` —
  строки файла сведены.
- Двоичного правка не касается: код 3 на `вариант «Не проверено»` в `flang io`
  уже есть. Перепечатки не требует.

## Чего прогоны не показали

Настоящий прогон `./ярлык точка:проверка` с печатью двоичным не снят: 35 ч 45 мин

подставным печатником проверяет всё, кроме самой печати.
