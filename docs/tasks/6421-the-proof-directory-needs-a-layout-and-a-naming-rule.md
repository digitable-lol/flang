# 6421. Каталог доказательств: раскладка и правило имени

## Замер, а не впечатление

21 сентября 2026, ствол. Считано `git ls-files`.

| | |
|---|---:|
| файлов в `flang/proof` | **931** |
| каталогов | **115** |
| имён с кириллицей | **863** из 931 |
| файлов в `flang/proof/checker` | **792** |
| файлов `.tsv` | **10** |

Про `.tsv` поправка к впечатлению: их **десять**, а не «тонна». Четыре лежат на
верхнем уровне (`tables/inference-rules.tsv`, `tables/abilities.tsv`, `tables/segments.tsv`,
`tables/consistency-violations.tsv`), три — одноимённые `expected.tsv` в трёх
наборах проб, остальные три — внутри проверяющего. Беда не в числе, а в том,
что имя `expected.tsv` встречается трижды и по имени неразличимо.

## Что именно не так

**1. Две схемы именования в одной папке.** `flang/proof/lean` — одиннадцать
файлов:

```
RecordReader.lean   VerdictCheck.lean          ← английские
Record.lean  Trap.lean  Model.lean  Rules.lean
Acceptance.lean  Consistency.lean  Term.lean  ← кириллица
lean-toolchain  run.sh
```

Ни один известный проект на Lean или Coq так файлы не называет, и уж точно не
мешает две схемы в одной папке. Читатель, пришедший посмотреть на формализацию,
видит сначала это.

**2. Кириллица в 863 именах из 931.** По дереву правило есть и его держат два
сторожа: имя файла — английскими словами из закрытого списка
(`scripts/ledgers/file-name-words.txt`, задачи 1428 и 1419).

**Поправка к первой редакции этой задачи — моя ошибка.** Я написал, что
исключение для `flang/proof` нигде не обосновано. Это неверно, и проверяется
одной строкой: `scripts/guards/cyrillic-file-names-guard.sh:15` — «flang/proof/**
не судится: там имя файла — ключ артефактов доказательств (задача 1420)». Довод
записан и в самой задаче 1420, вместе с ценой ошибки. Претензия «почему — нигде
не сказано» снимается; остаётся вопрос, верен ли сам довод сегодня.

Настоящая дыра рядом, и она не здесь: у сторожа транслита область задана
строкой `OBLAST="scripts flang/test flang/scripts docs/site docs/zettel .github"`
— 1252 файла из 3680, то есть 34 % дерева. Область названа, а **почему именно
эти шесть путей — не сказано нигде**. Разбор: задача 1430.

**3. Верхний уровень смешивает роды.** Рядом лежат спецификация, ядро на flang,
четыре таблицы, четыре скрипта оболочки и два файла-примера про «midpoint» —
без признака, что из этого прибор, что справочник, а что образец.

**4. 792 файла в `checker/`** — это набор проб проверяющего, и его раскладка
сложилась сама. Внутри — `tests/records/Ч19/реестр.tsv`, `tests/trap/kinds.tsv`,
каталоги с номерами ячеек в именах.

## Что сделать

Работа начинается **со спецификации раскладки, а не с переименований**.

1. **Написать ADR** о раскладке `flang/proof`: какие роды файлов здесь бывают
   (спецификация, прибор, таблица-справочник, набор проб, образец), какой каталог
   какому роду отвечает и по какому признаку файл попадает в каталог. Без этого
   переименование просто перемешает беспорядок.
2. **Решить вопрос имён и записать решение.** Три возможности, и у каждой цена:
   * подчинить `flang/proof` общему правилу дерева (английские имена) — 863
     переименования, все ссылки в документах, скриптах и работах CI поедут;
   * оставить кириллицу, но **снять исключение у сторожей** и завести правило
     явно, с доводом, почему здесь иначе;
   * привести к одной схеме хотя бы `lean/` — самый дешёвый шаг и самый заметный
     снаружи: девять файлов.
   Что бы ни выбрали — довод записывается, а не подразумевается.
3. **Развести верхний уровень по родам** согласно ADR.
4. **Три `expected.tsv` назвать различимо** — по имени файла должно быть видно,
   к какому набору проб он относится.

## Приём работы

Переименование в этом дереве стоит дорого и ломается тихо. Поэтому:

* после каждой порции — `sh .githooks/pre-push` код 0 и `node docs/site/build.mjs --check`
  (битые ссылки на переименованные файлы ловятся именно там);
* `sh scripts/доказуемость.sh` — ДОКАЗУЕМ, четыре проверки из четырёх;
* `sh flang/proof/checker/tests/run.sh` — «сошлось всё»;
* ссылки из работ CI (`.github/workflows/*.yml`) и из `ярлыки.flang` проверяются
  отдельно: они не markdown, и сторож ссылок их не читает.

## Чего НЕ делать

Не переименовывать «заодно, пока рука в файле». Либо есть ADR и переименование
идёт по нему целиком, либо не идёт вовсе: половина каталога по одному правилу и
половина по другому хуже, чем весь каталог по старому.

### Четыре собственные ошибки по дороге — названы, чтобы не повторить

1. Пары «старый путь → новый» выводились обрезанием общего хвоста. На

   наполовину: `flang/proof/checker/tests/families/own-type/`. Добавил префиксы.
3. Односегментное имя правилось после любого слэша. В `run.sh` `/вывод` — не

4. Правка комментария в `*.flang` под `flang/proof` отвергает привязанную к нему
