# 6445. Печать указателя базы знаний пишет прямо в файл указателя и при обрыве оставляет его недописанным

## Шаги воспроизведения

1. `grep -n 'Записать файл' docs/zettel/zettel-index.flang`
2. `grep -c 'вариант «Провал»' docs/zettel/zettel-index.flang`

## Что происходит

```
$ grep -n 'Записать файл' docs/zettel/zettel-index.flang | cut -c1-90
346:      вариант «Сделать» с поручение равным (вариант «Записать файл» с путь равным («Фай
$ grep -c 'вариант «Провал»' docs/zettel/zettel-index.flang
9
```

Запись одна, последняя, и идёт сразу в файл указателя. Две ветви отказа
(`FLANG_UKAZATEL_NE_ZAPISALSYA` и `FLANG_IO_ORDER` после записи) срабатывают уже
после попытки записи и прежнего содержимого не возвращают. Обрыв во время
записи оставляет недописанный файл.

Версия: flang 0.7.23, 30 сентября 2026.

## Что должно быть

Обрыв или отказ в любой точке оставляет прежний указатель нетронутым.

## Обходной путь

После неудачного прогона `git checkout -- docs/zettel/` и повторить печать.

## Когда задача сделана

- `bootstrap/flang run-script zettel-index:build`, оборванный сигналом на середине, оставляет
  `git status --porcelain -- docs/zettel/` пустым;
- при нечитаемой заметке ярлык отвечает кодом 1, и указатель не изменён;
- первая строка пояснения ярлыка `указатель:печать` говорит, что он пишет в
  дерево.

## Где живёт правка

`docs/zettel/zettel-index.flang`, шаг с поручением «Записать файл» (строка 346)
и две ветви отказа после него: писать во временный файл рядом и переносить
поверх, либо восстанавливать прежнее содержимое. Поручения переименования в
словаре нет, перенос делается поручением «Запустить процесс». `ярлыки.flang`,
поле «зачем» ярлыка. Перепечатка не нужна.
