# 6702. Файл кеша приговоров держит записи всех двоичных сразу и ничего не вытесняет

## Шаги воспроизведения

1. Собрать двоичный из напечатанного семени:

   ```sh
   make -C bootstrap -j4 CFLAGS='-std=c99 -O2' flang
   ```

2. Сделать два двоичных с иным отпечатком и тем же поведением — дописать к копии один и два нулевых байта
   (ELF от этого не ломается, sha256 становится другим):

   ```sh
   cp bootstrap/flang f1; cp f1 f2; printf '\0' >> f2; cp f1 f3; printf '\0\0' >> f3
   ```

3. Три прогона по одному и тому же исходнику с ОДНИМ файлом кеша, после каждого — размер файла:

   ```sh
   for b in f1 f2 f3; do
     FLANG_KESH_PRIGOVOROV=кеш.json ./$b emit flang/core/json.flang --target c --runtime flang/src/emit/c --out out-$b
     wc -c < кеш.json
   done
   ```

4. Четвёртый прогон первым двоичным: смотреть, вырос ли файл и отвечает ли кеш попаданиями.

## Что происходит

```
$ for b in f1 f2 f3; do ... ; wc -c < кеш.json; done
f1: код 0, кеш  58980 байт, записей 31
f2: код 0, кеш 117950 байт, записей 62
f3: код 0, кеш 176889 байт, записей 93     код 0

$ FLANG_KESH_PRIGOVOROV=кеш.json ./f1 emit flang/core/json.flang --target c ...
f1 снова: код 0, кеш 176889 байт           код 0
```

Записи трёх двоичных лежат в файле разом: 93 = 3 × 31, вытеснения нет ни одного. Первый двоичный после записи
второго и третьего по-прежнему получает свои приговоры — файл вырос втрое и ни одной записи не потерял.

Версия: `flang 0.7.23`. Прогон 2 октября 2026.

## Что должно быть

Либо предел на файл кеша (по размеру или по числу отпечатков) с вытеснением старых отпечатков, либо прямая
запись в документации: файл растёт без предела, за его уборку отвечает человек.
Сегодня [`docs/site/verdict-cache.ru.md`](../site/verdict-cache.ru.md) не говорит ни того, ни другого: раздел
«Как звать» показывает один путь к файлу, а про его срок жизни и размер не сказано ничего.

## Обходной путь

Задавать свой файл кеша на каждый двоичный и убирать его руками. Обход работает, но его никто не обещал:
человек, повторивший строку из документации, получает файл, который растёт на каждом новом двоичном.

## Когда задача сделана

Прогон шагов 1—4 с тремя двоичными даёт файл, размер которого не растёт линейно по числу отпечатков: либо
записи первого двоичного вытеснены (и это видно числом), либо документация называет рост и уборку словами, а
проба краснеет, если это обещание из документации уйдёт.

## Где живёт правка

Предел и вытеснение — `flang/self/proofterm.flang` (ключ и корзины считает ядро) и
`flang/src/emit/c/flang_repl.c` (файл хранит рантайм); такая правка требует перепечатки семени.
Запись словами — `docs/site/verdict-cache.ru.md` и `docs/site/verdict-cache.md`, перепечатки не требует.
