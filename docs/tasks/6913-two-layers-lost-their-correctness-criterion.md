# 6913. У печати в C# и у языкового сервера не названо, чем проверяется верность их вывода

Остальные слои печати держатся на примерах, постусловиях и сверке с рантаймом
цели; у печати в C# и у языкового сервера критерий верности вывода не назван.

## Шаги воспроизведения

1. `grep -c 'критери\|верност' flang/self/emit-csharp.flang flang/self/lsp.flang`
2. `grep -c 'пример «' flang/self/emit-csharp.flang flang/self/lsp.flang`
3. `bootstrap/flang io scripts/editors/lsp-check.fscript; echo $?` и то же с
   ключом `--trust`.
4. `bash scripts/guards/bad-octet-guard.sh --цель csharp; echo $?`
5. `bootstrap/flang check flang/self/lsp.flang --proof` — ведомость утверждений
   слоя; `grep -n 'lsp\|csharp' .flangrc` — есть ли у этих проверок короткая
   команда.

## Что происходит

```
$ grep -c 'критери\|верност' flang/self/emit-csharp.flang flang/self/lsp.flang
flang/self/emit-csharp.flang:0
flang/self/lsp.flang:0
$ grep -c 'пример «' flang/self/emit-csharp.flang flang/self/lsp.flang
flang/self/emit-csharp.flang:258
flang/self/lsp.flang:152
```

```
$ bootstrap/flang io scripts/editors/lsp-check.fscript --trust; echo $?
{"plan":…,"result":"…клиент прицепился: да … диагностик пришло: 1 … ИТОГ: сошлось…"}
0
$ bash scripts/guards/bad-octet-guard.sh --цель csharp; echo $?
csharp   | код 134, ответов 0 | код 134, текст не тот | КРАСНО: здоровый вход не прошёл
1
```

Примеры у обоих файлов есть. Проверки, которые ТРОГАЮТ вывод этих двух слоёв, в
дереве тоже есть, но ни одна не названа критерием верности, и одна из двух
сегодня красная (прогон 11 октября 2026):

- печать C# собирается и запускается — `bad-octet:check` в `.flangrc`
  (`scripts/guards/bad-octet-guard.sh`, строки 175 и 204). `dotnet build`
  проходит, `flang.dll` получается, но прогон отвечает кодом 134 и на негодном
  октете, и на ЗДОРОВОМ входе: `System.TypeLoadException: Could not resolve
  type 'Evklid'`. Судит эта проверка одно свойство — отказ на негодном октете,
  а не верность напечатанного.
- сервер: `scripts/editors/lsp-check.fscript` без `--trust` отвечает кодом 3
  (утверждений 21: доказано 17, на веру 4), с `--trust` — кодом 0: `nvim`
  прицепился, диагностика `FLANG_TYPE` до редактора доехала, «ИТОГ: сошлось».
  Проверка живая, но критерием верности не названа. Короткой команды у этих
  двух проверок нет: ни одна строка `script.` в `.flangrc` не называет ни
  `lsp`, ни `csharp`.
- второй путь к напечатанному C# — `tests:remote`
  (`scripts/test-remote.fscript`, девять тулчейнов, среди них `dotnet:csharp`) —
  зовёт на хозяине прогонщик ярлыков, которого в дереве нет (задача 1416 закрыта,
  прогонщика в дереве по-прежнему нет), и значит путь не работает ни на каком
  хосте.

Версия: flang 0.7.25, дерево 1149c78f7.

## Что должно быть

Для каждого из двух слоёв в дереве названа проверка, которая зелена на верном
выводе и краснеет на неверном, либо прямо записано, что верность вывода сегодня
не несётся ничем.

## Обходной путь

Нет.

## Когда задача сделана

Для `flang/self/emit-csharp.flang` и `flang/self/lsp.flang` в документации
слоя записано:

- чем несётся верность вывода: короткая команда `.flangrc` и файл проверки;
- числа: сколько постусловий у файла, сколько доказано, сколько примеров — с
  командой, которая их снимает. Для сервера команда уже отвечает:
  `bootstrap/flang check flang/self/lsp.flang --proof` — код 3, утверждений 224:
  доказано 128, сетка 13, объявлено не доказано 83; 192,07 с, пик 2 146 952 КиБ
  (2,05 ГиБ) 11 октября 2026. Для печати C# — тоже отвечает, но дорого:
  `bootstrap/flang check flang/self/emit-csharp.flang --proof` — код 3,
  утверждений 659: доказано 525, сетка 57, объявлено не доказано 77; 1361,19 с
  (22,7 минуты), пик 5 440 068 КиБ (5,19 ГиБ) на 0.7.23;
- покрывает ли слой сверка неподвижной точки при перепечатке;
- подделка — и ДО неё отрицательный контроль, без которого критерий ничего не
  различает: названная проверка сначала зелена на нетронутом дереве, и только
  потом краснеет от испорченной строки печати C# и от испорченного ответа
  сервера. Проверка печати C# красная без всякой порчи (шаг 4), и порчу на ней
  не видно; проверка сервера зелена, но порчей ответа не испытана.

## Где живёт правка

Проверка печати C# — `scripts/guards/bad-octet-guard.sh` и `scripts/targets/`,
сервера — `scripts/editors/`; короткие команды — строками `script.<имя>` в
`.flangrc`; запись о критерии — в `docs/flang/SPEC.md` или рядом со слоем.
Перепечатка не нужна, пока не правятся сами `flang/self/emit-csharp.flang` и
`flang/self/lsp.flang`.

## Следующий шаг

Для сервера — строка `script.lsp:check = bootstrap/flang io scripts/editors/lsp-check.fscript --trust`
в `.flangrc` и порча ответа сервера как подлог; для печати C# — разобрать
`System.TypeLoadException: Could not resolve type 'Evklid'` в `scripts/guards/bad-octet-guard.sh`
(строки 175 и 204): здоровый вход обязан проходить прежде, чем проверка станет
критерием. Проба, которая краснеет сегодня: шаг 4 — код 134 на здоровом входе.
