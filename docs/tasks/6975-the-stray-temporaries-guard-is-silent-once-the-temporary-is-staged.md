# 6975. Сторож забытых времянок молчит, как только времянку взяли в индекс, — а зовут его только после коммита

## Шаги воспроизведения

Нужен сторож `scripts/guards/stray-temporaries-guard.fscript` из задачи 1315
(ветка `a/1315-check-temporaries-leave-the-source-tree`, `49a3e18c7`,
запрос на слияние 230). Пока она не влита, прогоны ставятся на этой ветке.

1. Положить в дерево времянку того вида, ради которого сторож заведён, и
   спросить его:

```
mkdir -p .flang-storozh-tracked
printf 'модуль «Проба»\n' > .flang-storozh-tracked/проба.flang
bootstrap/flang io scripts/guards/stray-temporaries-guard.fscript --plan Проверка; echo $?
```

2. Взять ту же времянку в индекс — то есть сделать то, чем она и уезжает в
   коммит, — и спросить сторожа ещё раз:

```
git add -f .flang-storozh-tracked/проба.flang
git status --short | grep storozh
bootstrap/flang io scripts/guards/stray-temporaries-guard.fscript --plan Проверка; echo $?
```

3. Убрать за собой:

```
git rm -q --cached .flang-storozh-tracked/проба.flang
rm -rf .flang-storozh-tracked
```

## Что происходит

```
$ bootstrap/flang io ... --plan Проверка; echo $?                      (времянка неотслеживаемая)
ЗАБЫТАЯ ВРЕМЯНКА ПРОВЕРКИ В ДЕРЕВЕ — 1
  · .flang-storozh-tracked/
прогон сняли до уборки: уберите остатки руками и не берите дерево целиком
через `git add -A` (задача 1315)
                                                                        код 1
$ git add -f .flang-storozh-tracked/проба.flang
$ git status --short | grep storozh
A  ".flang-storozh-tracked/\320\277\321\200\320\276\320\261\320\260.flang"
$ bootstrap/flang io ... --plan Проверка; echo $?                      (та же времянка, но в индексе)
забытых времянок проверок нет: путей просмотрено 1
                                                                        код 0
```

Версия: flang 0.7.23. Дата прогона: 2 октября 2026, ветка
`a/1315-check-temporaries-leave-the-source-tree` `49a3e18c7`.

Один и тот же файл на одном и том же месте: пока он неотслеживаемый — **код 1** и
путь; стоит взять его в индекс — **код 0** и «забытых нет». Это не ошибка сторожа,
а область его зрения: он спрашивает `git ls-files --others` (видимое) и
`git ls-files --others --ignored` (прощённое), а индекс в «others» по определению
не входит.

Беда в том, ГДЕ его зовут. Сегодня его два зова стоят в `ci.yml` (работа
`stray-temporaries`), то есть ПОСЛЕ коммита и пуша. Хук перед пушем — тоже после
коммита: `.githooks/pre-push.fscript:19` держит ровно 21 проверку
(«there are exactly twenty-one checks»), и все они видят уже сложенную историю.
Получается сторож, который находит времянку только в том единственном случае,
когда она ещё никому не мешает, и молчит ровно тогда, когда она уже уехала в
коммит, — а уезжает она именно так: 29 августа 2026 `git add -A` затянул
`.flang-storozh-ypvg0t/проба.flang` в коммит `03f0359a` и оттуда в ствол.

Рукой это тоже не ловится: `git status` прощённой времянки не показывает вовсе.
Замер на той же ветке `49a3e18c7` (там, где задача 1315 уже закрыла `.gitignore`
и для пробы замера занятости) с двумя времянками в дереве:

```
$ git status --short | grep -cE 'storozh|probe'
0
```

## Что должно быть

Нужны ДВЕ половины, и ни одна не заменяет другую.

**Первая — зов из `.githooks/pre-commit`,** то есть ПЕРЕД тем, как времянка может
попасть в коммит. Там сейчас два плана (`no-growth` и `lint-growth`, оба с планом
`Staged`), файл в две строки, прогон стоит 1,76 с; сам сторож стоит 1,15 с при пике
105 МиБ. Зовы в `ci.yml` при этом остаются: они держат пробу порчи, без которой
сторож неотличим от выключенного.

**Вторая — зрение индекса**: третий перечень рядом с двумя нынешними, например
`git diff --cached --name-only --diff-filter=A`.

Почему обеих мало по одной — замер на том же дереве `8a7d81452`:

```
$ mkdir -p .flang-storozh-x && printf 'модуль «Проба»\n' > .flang-storozh-x/проба.flang
$ : > occupancy-probe.flang
$ git add -A
$ git status --short | grep -ciE 'storozh'
0
$ git status --short | grep -c 'occupancy-probe'
1
```

`git add -A` ПРОЩЁННОЕ НЕ БЕРЁТ. Значит в коммит уезжает времянка нового вида, та,
которой `.gitignore` ещё не знает, — ровно так случился `03f0359a`. В момент
`pre-commit` такая времянка УЖЕ в индексе, и сторож, смотрящий только `--others`,
её не увидит: зов из `pre-commit` без зрения индекса не поймает ничего. А зрение
индекса без зова из `pre-commit` зовётся слишком поздно — коммит к тому часу уже
сложен.

## Обходной путь

Звать сторожа рукой перед `git add`:
`bootstrap/flang run-script stray-temporaries:check`. И не брать дерево целиком —
`git add -A` и есть тот самый способ, которым времянки уезжают в ствол.

## Когда задача сделана

Прогон, который покажет, что дефекта нет:

```
$ mkdir -p .flang-storozh-tracked && printf 'модуль «Проба»\n' > .flang-storozh-tracked/проба.flang
$ git add -f .flang-storozh-tracked/проба.flang
$ git -c user.name='X' -c user.email='x@x' commit -m 'test(probe): a stray must not pass'; echo $?
ЗАБЫТАЯ ВРЕМЯНКА ПРОВЕРКИ В ДЕРЕВЕ — 1
  · .flang-storozh-tracked/проба.flang
                                                                        код 1
```

То есть коммит НЕ состоялся, и сторож назвал путь — а назвать он его может только
тогда, когда обе половины на месте: зов стоит в `pre-commit`, и перечень индекса
сторож спрашивает. После `git rm --cached` и `rm -rf` тот же коммит проходит
кодом 0. Это и есть отрицательный контроль: без него проверка была бы проверкой
пустоты.

**Проба, которая краснеет, если дефект вернётся**: эти же два шага — с времянкой
и без неё — ставятся парой в `ci.yml` рядом с нынешними зовами, по образцу шага
`Probe stray temporaries on disk`: ставим времянку в индекс, требуем от
`.githooks/pre-commit` кода 1, убираем, требуем кода 0.

## Где живёт правка

`.githooks/pre-commit` (одна строка зова) и/или
`scripts/guards/stray-temporaries-guard.fscript` (перечень индекса третьим
поручением), плюс шаг пробы в `.github/workflows/ci.yml`. Всё читается двоичным с
диска: ни быстрый пересев, ни перепечатка самосборной части не нужны.

**Цена, перемеренная прогоном, — её стоит знать до начала.** Одна добавленная
строка в `.githooks/pre-commit` (2 строки → 3) двигает ДВА прибора, и оба красные,
пока числа не поправлены:

двадцати одной проверке — это другой хук.
