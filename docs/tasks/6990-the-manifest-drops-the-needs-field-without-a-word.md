# 6990. Нужды проекта записать негде: поле «нужды» в flang.package двоичный теряет молча, без отказа

Решение: [ADR-0059](../adr/0059-the-registry-is-a-ledger-of-names-not-a-store-of-code.md),
§2 и §6 п. 3. Обещание:
[ADR-0021](../adr/0021-packages-are-installed-over-the-network-and-locked-locally.md)
п. 1 — «Манифест проекта — файл рядом со входным файлом программы: имя, версия,
список нужд в уже читаемом виде (`Логика: не ниже 1.0.0`, `Списки: в пределах
1.x`) и адрес источника у каждой».

## Шаги воспроизведения

1. `make -C bootstrap`.
2. Вне дерева: `flang new proba && cd proba`.
3. Дописать в `flang.package` поле нужд:
   `{"имя": "Proba", "версия": "0.1.0", "нужды": "Логика: не ниже 1.0.0"}`.
4. `flang package proba.flang` — смотреть список полей в выводе и код возврата.

## Что происходит

```
$ flang package proba.flang
поля вывода: схема, имя, версия, вход, модули, ведомость, печать        код 0
```

Полей семь, `нужды` среди них нет. Отказа тоже нет: поле принято и потеряно.
Поле `источник` при этом двоичный ЗНАЕТ — тот же прогон с
`"источник": "file://x"` даёт восемь полей, восьмое `источник`. Значит разбор
манифеста разбирает именно названные поля, а неназванные молча отбрасывает.

Манифестов в дереве один — `docs/examples/package/flang.package`, и полей в нём
три: `имя`, `версия`, `источник`.

Версия: `flang 0.7.24`.

## Что должно быть

Разбор нужд УЖЕ написан и прогнан: `«Разобрать нужды»` и четыре вида диапазона
(`любая`, `ровно`, `не ниже`, `в пределах`) в `flang/stdlib/registry.flang`;
`flang check` над модулем — код 0, «из них с доказанным завершением 44». Подать
этому разбору нужды проекта нечем: единственное место, где их естественно
записать, их теряет.

Ожидается одно из двух, и выбор надо назвать вслух:

- либо `нужды` попадают в пакет наравне с `источник` — тогда реестр и
  постановщик читают их оттуда;
- либо `нужды` в пакете не место, и поле обязано дать НАЗВАННЫЙ отказ, а нужды
  живут в отдельном файле проекта.

Чего быть не должно в любом случае — тихой потери поля.

## Обходной путь

Писать нужды в отдельный файл и подавать их постановщику руками — так сделан
`scripts/registry-example/request.needs`. Для настоящего проекта это значит, что
манифест и нужды разъезжаются, и сверять их нечем.

## Когда задача сделана

```
$ flang package proba.flang        # манифест с полем «нужды»
                            поля вывода включают «нужды»            код 0
$ flang package proba.flang        # манифест с полем «нетакого»
                            НАЗВАННЫЙ отказ: поле не из набора      код != 0
```

Второй прогон обязателен: он и есть подделка. Пока неизвестное поле
отбрасывается молча, первый прогон ничего не доказывает — он зеленеет и на
разборе, который просто пропустил всё, чего не узнал.

Проба, которая краснеет, если дефект вернётся: сторож, который сверяет набор
полей манифеста, принимаемых двоичным, с набором, названным в
`docs/DESCRIPTION.md`, и ставит на длину набора примету.

## Где живёт правка

Разбор манифеста `flang.package` и печать пакета — `flang/self/cli.flang`
(справка пакета, `:330`–`:342`) и исполнитель в
`flang/src/emit/c/flang_repl.c`. Проверка самих диапазонов не нужна — она
написана в `flang/stdlib/registry.flang`, править там нечего.

**Доставка правки.** Если правка ложится только в `flang/src/emit/c/**` —
быстрый пересев семени. Если в `flang/self/**` — полная перепечатка (по карте
ADR-0021 «4 ч 41 мин и 36,3 ГиБ»; число не перемерено).
