# 7182. Напечатанный Makefile не знает заголовков: после смены заголовка объектные файлы не пересобираются

`bootstrap/Makefile` печатается компилятором. Зависимостей от заголовков в нём
нет, действует неявное правило «объектный файл из одноимённого исходника».
Заголовки меняются при перепечатке, в них макросы и раскладки записей. Объектный файл рантайма, собранный со старым заголовком,
линкуется с новым компилятором, и двоичный отвечает `FLANG_TYPE` на поле
записи либо проходит проверки по случайности.

## Шаги воспроизведения

1. `make -C bootstrap` — собрать.
2. `make -n -W compiler_flang.h -C bootstrap` — спросить, что пересоберётся,
   если заголовок изменился.

## Что происходит

```
$ make -n -W compiler_flang.h -C bootstrap
make: Entering directory 'bootstrap'
make: Nothing to be done for 'all'.
make: Leaving directory 'bootstrap'                                    код 0
```

Версия: flang 0.7.23, 3 октября 2026.

Что видно в самом дереве, и это задаёт форму правки:

```
$ grep -n '^#include "' bootstrap/*.c bootstrap/*.h
bootstrap/flang_cli.c:93:#include "flang_runtime.h"
bootstrap/flang_cli.c:156:#include "flang_conc.h"
bootstrap/flang_runtime.c:58:#include "flang_runtime.h"
bootstrap/flang_repl.c:146:#include "flang_runtime.h"
bootstrap/compiler_flang.h:10:#include "flang_runtime.h"
bootstrap/compiler_flang.c:7:#include "compiler_flang.h"
$ ls bootstrap/*.h
bootstrap/compiler_flang.h
bootstrap/flang_runtime.h
```

Два следствия для правки:

1. `compiler_flang.c` зовёт `flang_runtime.h` НЕ сам, а через
   `compiler_flang.h`. Зависимости, выписанные только по строкам `#include`
   самого исходника, смену `flang_runtime.h` до `compiler_flang.o` не донесут —
   нужен транзитивный обход заголовков.
2. `flang_cli.c:156` зовёт `flang_conc.h` под `#ifdef FL_WITH_CONC`, и в
   `bootstrap/` этого заголовка НЕТ. Зависимость на него make оборвёт
   («No rule to make target»), поэтому выписывать можно только те заголовки,
   которые печать кладёт рядом с исходником.

## Что должно быть

Смена заголовка пересобирает каждый объектный файл, который его включает.

## Обходной путь

Собирать с ключом `-B`: `make -C bootstrap -B`.

## Что уже сделано, и чем снято

Правка стоит в `flang/self/emit-c.flang`. Пока семя не перепечатано, двоичный
печатает старый Makefile, поэтому проба снята на КОПИИ семени: исходники
`bootstrap/*.c` и `bootstrap/*.h` скопированы в каталог вне дерева, а Makefile
в одну копию взят из ствола, в другую — напечатан правленым печатником
(`bootstrap/flang run flang/self/emit-c.flang --function 'Печать Makefile'
--на-веру --args '{"файл":"compiler_flang","прогонщик":true,"оболочка":true,"конкурентно":false}'`).
Все числа ниже сняты 4 октября 2026 на этой машине (256 ядер, средняя загрузка
на начало 16,74), двоичным `flang 0.7.23` из `bootstrap/` коммита
`188e5a6ed`; от семени выпуска 0.7.24 оно отличается только строкой версии
(коммит `c7226d395` правит `bootstrap/flang_repl.c` и ни одной строки кода).

Напечатанный тем же вызовом Makefile до правки совпадает с закоммиченным
`bootstrap/Makefile` побайтно (`diff` молчит) — то есть проба идёт по тому же
тексту, который лежит в семени, а не по его пересказу.

| прогон | ствол | с правкой |
|---|---|---|
| `make -n -W compiler_flang.h` | `Nothing to be done for 'all'` | `cc … -c -o compiler_flang.o`, затем `ar` и линковка |
| `make -n -W flang_runtime.h` | `Nothing to be done for 'all'` | 4 строки `cc … -c -o`: `flang_runtime.o`, `compiler_flang.o`, `flang_cli.o`, `flang_repl.o` |
| правка `flang_runtime.h`, затем `make -j8` | `Nothing to be done`, штампы всех четырёх объектных файлов не сдвинулись | пересобраны все четыре, `ar` и линковка прошли |

Отрицательных контролей два, и оба прогнаны на той же копии:

1. **Заголовок, которого печать рядом не кладёт, зависимостью НЕ назван.**
   `make -n -W flang_conc.h` в непроцессной сборке отвечает
   `Nothing to be done for 'all'` — и это именно то, что нужно: не
   «No rule to make target `flang_conc.h`», то есть правило печатается
   условно, по тому же признаку, по которому печатается сам файл.
2. **Зависимости точны, а не «всё от всего».** Правка `compiler_flang.h`
   пересобрала `compiler_flang.o` (штамп 14:09:23) и НЕ тронула
   `flang_runtime.o`, `flang_cli.o`, `flang_repl.o` (все три остались на
   14:06:39).

Процессная ветвь печати прогнана отдельно и целиком, на напечатанной
программе с процессами (`flang/test/fixtures/processes/12-spawn-of-undeclared-kind-fixed.flang`,
модуль `ceh`, рядом с ней печать кладёт `flang_conc.h`): Makefile от правленого
печатника собирается кодом 0; правка `flang_conc.h` пересобирает `flang_conc.o`,
`ceh.o` и `flang_cli.o` и НЕ трогает `flang_runtime.o` (штамп 14:23:35 остался);
правка `ceh.h` пересобирает только `ceh.o`.

Цена правки измерена, а не принята на веру: `bootstrap/flang check
flang/self/emit-c.flang` прогнан на том же двоичном дважды — на стволе и с
правкой.

| | ствол | с правкой |
|---|---:|---:|
| ответ | «проверено …; замечаний нет», код 0 | то же, код 0 |
| секунд | 632,14 | 630,88 |
| пик памяти | 1,74 ГиБ | 1,79 ГиБ |
| функций в модуле | 622 | 625 |
| из них с доказанным завершением | 484 | 487 |

Часы не выросли (−0,2 %, внутри разброса прогонов), память выросла на 2,9 %, а
все три новые функции вошли в число с доказанным завершением. Долг заслона
роста не вырос: строк длиннее 120 знаков в файле было 898 и осталось 898
(`bootstrap/flang lint flang/self/emit-c.flang`).

## Когда задача сделана

- `make -n -W compiler_flang.h -C bootstrap` называет пересборку
  `compiler_flang.o`; `make -n -W flang_runtime.h -C bootstrap` — всех четырёх
  объектных файлов. **Снято на копии семени (таблица выше); в самом
  `bootstrap/` будет верно после перепечатки, потому что Makefile там —
  напечатанный файл, и руками его не правят.**
- у печати Makefile есть пример с этими зависимостями. **Сделано:** пример
  стоит на `«Зависимости заголовков Makefile»` и на двух её помощниках
  (`«Строка зависимости Makefile»`, `«Заголовки рядом с модулем»`), а сама
  `«Печать Makefile»` несёт постусловия, называющие строки зависимостей
  дословно. Примера на всю `«Печать Makefile»` нет намеренно: ожидаемым
  значением был бы весь Makefile — около двух килобайт одной строкой, которую
  ломает любая правка пояснения к флагам, и заслон роста такую строку не
  пропускает.
- проверка происхождения двоичного (`scripts/seed/binary-origin.fscript`) либо
  отдельная проба краснеет, когда объектный файл старше своего заголовка.
  **НЕ сделано:** живёт в `scripts/seed/`, за печатником не числится.

## Где живёт правка

`flang/self/emit-c.flang`: `«Зависимости заголовков Makefile»` печатает
транзитивное замыкание заголовков каждого исходника, считая только те, что
печать кладёт рядом, а `«Печать Makefile»` ставит её вывод перед целью `clean`.
Для семени компилятора печатается ровно это:

```
flang_runtime.o: flang_runtime.c flang_runtime.h
compiler_flang.o: compiler_flang.c compiler_flang.h flang_runtime.h
flang_cli.o: flang_cli.c flang_runtime.h
flang_repl.o: flang_repl.c flang_runtime.h
```

В процессной сборке к этому добавляется строка `flang_conc.o` и
`flang_conc.h` входит в замыкание модуля и прогонщика; без процессов имени
`flang_conc` в Makefile нет вовсе — это и стережёт постусловие
`«без процессов движка нет»`.

Правка доезжает до `bootstrap/Makefile` перепечаткой самосборной части.
