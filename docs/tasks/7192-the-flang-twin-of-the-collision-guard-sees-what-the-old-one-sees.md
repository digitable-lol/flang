# 7192. Проверка столкновений имён на flang не сходится с проверкой на JavaScript по числу объявлений и не доходит до конца прогона

Столкновения имён считают две проверки: `flang/scripts/link-collision-guard.mjs`
с ключом `--дерево` (короткая команда `link-collisions:check`) и
`scripts/guards/name-collision-guard.fscript` (короткая команда
`name-collisions:recount`). Вторая должна заменить первую.

## Шаги воспроизведения

1. `node flang/scripts/link-collision-guard.mjs --дерево | head -5`
2. `timeout 3600 bootstrap/flang io scripts/guards/name-collision-guard.fscript --на-веру`

## Что происходит

```
$ node flang/scripts/link-collision-guard.mjs --дерево | head -5
── сторож столкновений имён ──
вход: всё дерево: 380 программ с ввозами + вся библиотека одной программой (56 модулей)
замыкание: 1970 файлов, видимых объявлений 137239

── РАЗРЯД 1: в замыканиях настоящих программ — 0 ──   код 0, 5,8 с, пик 311 МиБ
$ timeout 3600 bootstrap/flang io scripts/guards/name-collision-guard.fscript --на-веру
                                    код 124, пик 4,87 ГиБ, ни одной строки вывода
```

Сверить числа нечем: за час проверка на flang не печатает ни числа файлов, ни
числа объявлений, ни приговора. Что вход у неё другой, видно и без прогона:
собственное описание короткой команды (функция «Объявление короткой команды
name-collisions:recount» в том же файле, оттуда его берёт и `.flangrc`)
называет «всё дерево, 160 входов и 784 файла» (строка 1370) — против 380 программ и
1970 файлов у проверки на JavaScript. Больше половины файлов в замыкание не
попадает, а с ними не попадают и их объявления.

Версия: flang 0.7.25, дерево 1149c78f7; оба прогона 11 октября 2026, второй —
час на машине с 256 ядрами и 499 ГиБ, пик 5 102 984 КиБ.

## Что должно быть

На одном дереве обе проверки называют одинаковое число видимых объявлений и
одни и те же столкновения, и проверка на flang доходит до конца за время,
которое годится для короткой команды.

## Обходной путь

Гонять проверку на JavaScript; её нельзя удалять, пока числа не сошлись.

## Когда задача сделана

- найдено и названо место, где проверка на flang теряет объявления;
- два прогона подряд на одном дереве дают одинаковое число файлов,
  объявлений и столкновений обоих разрядов;
- подделка — одно имя объявлено в двух модулях одной программы — даёт код 1 у
  обеих;
- код возврата, время и пик памяти прогона на flang записаны рядом с
  короткой командой; строка описи — задача 8356.

Предела памяти у `flang io` нет, поэтому прогон ограничивать снаружи:
`systemd-run --user --scope -p MemoryMax=… -p MemorySwapMax=0 -p OOMPolicy=continue`
либо сторож по одному PID (`/proc/<pid>/status`, строка `VmRSS`, убивать по
номеру), а запас перед пуском считает
`bootstrap/flang io scripts/memory-headroom.fscript --plan Count -- --limit … --reserve …`.

## Где живёт правка

`scripts/guards/name-collision-guard.fscript` (обход замыкания и счёт видимых
объявлений), `.flangrc`. Перепечатка не нужна.

## Следующий шаг

В `scripts/guards/name-collision-guard.fscript` найти функцию, которая собирает входы
(описание зовёт их «160 входов»), и сверить её отбор с отбором `.mjs` («программы с
ввозами» плюс библиотека одной программой): недостающие 220 программ и есть потерянные
объявления; печатать число файлов и объявлений до разбора столкновений, чтобы прогон
отвечал раньше часа. Проба, которая краснеет сегодня: шаг 2 — код 124 без единой
строки вывода.
