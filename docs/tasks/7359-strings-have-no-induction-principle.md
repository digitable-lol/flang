# 7359. Спуск по строке — через список знаков, а не через тип знака

Решение: [ADR-0040](../adr/0040-a-simplifier-rewrites-by-proved-equalities-and-prints-every-step.md) §2.5;
основание — `docs/flang/proof/SPEC.md`, «Что дальше» п.7.

## Чем измерено

По спецификации ядра: 19 функций `flang/stdlib/strings.flang`, индукции доступна
одна, и та за работу над списком. Причина названа там же: у строки голова — тоже
строка, и правило «поле того же типа» назвало бы местом спуска оба поля.
Переснять на 0.7.19 первым делом: сколько функций `strings.flang` несут
обещания, сколько из них «доказано», сколько упирается в спуск по строке.

## Что сделать

1. Ш0 — переснять числа выше прогоном; выписать формы спуска по строке в корпусе
   (`разложить на символы`, `первый знак`/`остаток`, `начинается с`).
2. Решение по ADR-0040 §2.5: носитель индукции — список знаков: строка читается
   `разложить … на символы`, принцип берётся у списка (Инд по списку уже есть),
   обратный переход — склейкой; строка ведомости и лемма Lean о том, что
   `разложить` и склейка взаимно обратны (в модели тексты — списки знаков,
   `Модель.lean` «Текст»).
3. Ядро: распознать спуск по строке в теле (форма из Ш0) и подать принцип списка;
   печать блока и приём сверщика — по образцу принципа списка.
4. Пробы: `strings.flang` — число «доказано» до/после; подделка: спуск, который не
   укорачивает строку, — отказ.

## Чего не делать

Тип знака не заводить; поверхность языка не менять; `bootstrap/**` не трогать.

## Как поймём, что сделано

Число доказанных обещаний `strings.flang` выросло и названо; «склейка
ассоциативна» доказывается индукцией (вместе с 4722); подделка отвергнута;
Lean принял лемму; ДОКАЗУЕМ.
