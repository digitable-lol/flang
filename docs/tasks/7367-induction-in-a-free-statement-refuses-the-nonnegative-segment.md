# 7367. Индукция в свободном утверждении не идёт по отрезку «неотрицательное» — закона о всех натуральных автор доказать не может

Носителей принципа индукции у языка два: объявленная сумма и отрезок
`неотрицательное`. Второй читается ИЗ ТЕЛА ФУНКЦИИ — ядро само смотрит, что
аргумент спускается на единицу. У свободного утверждения тела нет, и потому
индукция по `неотрицательное` ему отказана поимённо: `FLANG_PROOF_INDUCTION_TYPE`.

Следствие: всё, что о натуральных числах не выводится закрытым списком правил,
автор доказать не может ВООБЩЕ — ни ядром, ни своей теоремой. Это и отличает нас
от Lean сильнее всего: там `Nat.rec` доступен автору всегда, здесь — только
через функцию, у которой такой спуск уже написан в теле.

Версия: flang 0.7.24, дерево `5604556ef`. Дата прогона: 4 октября 2026.

## Шаги воспроизведения

1. Программа (`проба.flang`):

```flang
модуль «Проба»

утверждение «сочетательность с литералами»
  для всех а: неотрицательное
  утверждаем ((а плюс 1) плюс 2) равен (а плюс (1 плюс 2))

теорема «сочетательность с литералами»
  дано а: неотрицательное
  утверждаем ((а плюс 1) плюс 2) равен (а плюс (1 плюс 2))
  индукция по а убывает а
    случай любое
      то по предположению
  следовательно доказано
```

2. `bootstrap/flang check проба.flang --proof; echo $?`
3. Отрицательный контроль: та же индукция у ПОСТУСЛОВИЯ функции, у которой в
   теле есть спуск на единицу, — проходит:

```flang
тотальная функция «Факториал»
  принимает н: неотрицательное
  возвращает число
  для всех н обеспечивает «факториал неотрицателен» результат не меньше 0
  если н не больше 1
    то 1
    иначе н умножить на («Факториал» от (н минус 1))

теорема «факториал неотрицателен»
  дано н: неотрицательное
  утверждаем результат не меньше 0
  индукция по н убывает н
    случай любое
      то по предположению
  следовательно доказано
```

## Что происходит

```
$ bootstrap/flang check проба.flang --proof
FLANG_PROOF_INDUCTION_TYPE … строка 10, столбец 3: утверждение «сочетательность
с литералами»: индукция по «а» идёт по отрезку «неотрицательное», а принцип по
отрезку читает дно и спуск с тела функции; у свободного утверждения тела нет.
Индукция в утверждении ведётся по объявленной сумме или по списку
проба.flang: не проверено — ведомость не печатается у программы с замечаниями
                                                                       код 1
```

Отрицательный контроль — код 0, «доказано индукцией по «неотрицательное»: база
1 случай, шаг при допущении на убывшем «н» (1 случай)».

Отказ верен по букве: спуск ядро читает в теле и не принимает на слово (так же
написано в шапке ведомости). Беда в том, что у свободного утверждения тела нет
НИКОГДА, и значит у отказа нет обходного пути — он не «пока», а «вовсе».

## Что должно быть

1. У свободного утверждения `для всех а: неотрицательное` индукция по `а`
   законна: база — `а равно 0` (либо названное автором дно), шаг — при
   допущении об `а минус 1`. Спуск здесь не читается из тела, а ЗАДАН формой
   принципа, и это надо сказать вслух в ведомости: не «прочитан», а «взят с
   отрезка».
2. Отказ остаётся там, где он по делу: `для всех а: число` — у `число` дна нет
   и принципа нет, и отказ называет именно это.
3. Ведомость называет носитель («индукцией по отрезку «неотрицательное»») и
   различает его от сегодняшнего случая, где спуск прочитан из тела, —
   два разных основания не должны печататься одной строкой.
4. Запись доказательства несёт новый ход, независимая проверяющая программа его
   переигрывает, подделка (шаг без базы, база без шага) отвергается.

## Обходной путь

Завести функцию с нужным спуском в теле и повесить свойство постусловием — тогда
индукция доступна. Цена: функция заводится РАДИ доказательства и в программе
больше ни для чего не нужна; плюс о свойстве нельзя говорить вне неё.

   дна у `число`.

## Чего мы не смогли оценить

- **Сколько законов это открывает.** Задача 1412 говорит, что сочетательность и
  распределительность на сегодняшнем носителе ЛОЖНЫ (округление), и правилами
  они станут только на точном целом. Значит индукция в утверждении открывает не
  их, а законы о списках, строках и пользовательских функциях — сколько именно,
  мы не считали. Не мерили: счёт требует прогона свода ведомости.
- **Надо ли позволять автору НАЗВАТЬ дно** (не 0, а любое). Решение не принято.
