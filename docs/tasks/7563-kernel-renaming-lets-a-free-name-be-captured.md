# 7563. Ядро переименовывает связанное имя в имя, уже свободное в свойстве

## Чем измерено

15 сентября 2026, двоичный `bootstrap/flang` 0.7.19 (`make -C bootstrap` на main `0e57d1b4b`),
`flang check <проба> --proof`:

```
тотальная функция «Больше м»
  принимает элементы: список числа, м: число
  возвращает список числа
  обеспечивает «на выходе» для всех м из результат: м больше м
  отфильтровать элементы где э → э больше м
```

Исход: «постусловие «на выходе» функции «Больше м» — доказано сведением цели с телом функции:
правило «все элементы по построению», объявленные типы аргументов не понадобились — утверждение
обо ВСЕХ входах»; «утверждений 1: доказано 1»; код 0.

Цель ложна: при элементы = [3, 5], м = 1 результат — [3, 5], и «3 больше 3» ложно. С
примером `дано элементы равно [3, 5]`, `дано м равно 1` та же программа останавливается
на вычислителе: `FLANG_PROPERTY: нарушено свойство «на выходе»` — ядро до вердикта не
доходит, и дыра пробой с примером не видна.

Т2-форму (квантор в `требует`) двоичный 0.7.19 не разбирает: `FLANG_PARSE … «для всех»
связывает элементы списка только для цели целиком` — квантор в предусловии доедет
перепечаткой (задача 3123). По исходникам ядра её проверил зонд
`flang/self/bootstrap/zond-k7.flang` (двоичный 0.7.19 толкует `flang/self/**` main
`8c1fee225`; 10 мин 17 с, 11,8 ГиБ):

```
тотальная функция «Те же»
  принимает элементы: список числа, м: число
  возвращает список числа
  требует «все больше м» для всех э из элементы: э больше м
  обеспечивает «на выходе» для всех м из результат: м больше м
  элементы
```

Исход: «постусловие «на выходе» функции «Те же» — доказано сведением цели с телом
функции: правило «цель есть допущение»»; «утверждений 1: доказано 1»; запись
печатается:

```
    вывод цель ⟨для всех м из результат : м больше м⟩
    вывод 1 Т2 ⟨для всех м из элементы : м больше м⟩ строка 6
    вывод 2 Разв2 ⟨для всех м из результат : м больше м⟩ из 1 строка 8
```

То есть ядро выводит ложную цель и печатает ровно тот шаг Т2, который сверщик после
починки (PR #47) отвергает: «имя цели «м» стоит свободным в свойстве допущения».
С примером (`дано элементы равно [3, 5]`, `дано м равно 1`) зонд останавливается на
вычислителе — `FLANG_PROPERTY: нарушено свойство «на выходе»`, — до вердикта ядра не
доходит.

## Где дыра

Правило «все элементы по построению», случай отбора (Э2): свойство цели сличается с
условием отбора после подстановки имени цели вместо имени элемента отбора, и не
спрашивается, что имя цели (`м`) не стоит в условии свободным. Та же форма у Т2
(«Есть допущением с переименованием»). Модель Lean спрашивает это условие у обоих
правил («Э2-терм», «Т2-терм», встречный пример «Т2-без-свежести-ложно», ловушка 33 в
`flang/proof/lean/`); сверщик — с PR «fix(сверщик): Т2 и Э2 …».

## Аудит правил, связывающих имя

Снят 15 сентября 2026 на main `8c1fee225`: чтение кода ядра (`flang/self/proof-kernel.flang` —
ниже «ядро:N», `proof-initial.flang`, `proofterm.flang`) и сверщика (`flang/proof/checker/checker.c`)
плюс пробы. «Прогон» — проба запущена, исход приведён; «по чтению» — пробы нет.

### Две общие причины в ядре

1. **Сличение с переименованием идёт в одну сторону.** «Одинаковы с переименованием» (ядро:804)
   сличает имена через «Имена соответствуют» (ядро:792):
   `(«Соответствие имени» от «пары» и «слева») равен «справа»`. Свободное слева имя
   соответствует само себе (ядро:768), и никто не спрашивает, не стало ли оно целью
   переименования; два связывателя слева могут получить одно имя справа. Этим путём идут
   Т2 (ядро:7657; зовётся на каждой цели — ядро:8191 — и перед каждой подцелью Э — ядро:9101),
   Э2 (ядро:9108) и сличение тождеством через «Одинаковы до порядка соседей» (ядро:654; зовут
   ядро:4625, 4734, 6150, 6159, 8956, 9007).
2. **Списки связывателей не знают «есть такой».** «Связыватель этого имени» (ядро:4338), «Это
   связыватель» (ядро:6948), «Захват в записи» (proof-initial.flang:510), «Свободные из записи»
   (ядро:8411) перечисляют `пусть`, свёртку, отображение, отбор, квантор по элементам и разбор —
   существования нет. Поэтому «Связывает где-то» (ядро:9173), «Подставить начальной»
   (proof-initial.flang:573) и «Подставить условие» (ядро:7109) вложенного «есть такой» не видят.
   Существование язык пишет только целью целиком (`FLANG_PARSE` и двоичным, и зондом по
   исходникам), поэтому причина срабатывает лишь там, где язык существование под другим
   связывателем пропускает, — проба под квантором по элементам в работе.

Печать записи сторожа тоже нет: `zapis.flang:4344–4350` печатает Т2 заменой текста и говорит
прямо «Захват имени здесь не стережётся» — стережёт один сверщик.

## Что сделать

1. В ядре — обе общие причины, а не правила по одному: сличение с переименованием —
   в обе стороны и со свежестью (новое имя не свободно в свойстве, два связывателя не
   сходятся в одно имя) — тем же условием, что сверщик после PR #47 и модель Lean
   («Т2-терм», «Э2-терм»); «есть такой» — в список связывателей каждого из четырёх мест.
   Затем — по строкам аудита, где «по чтению» стоит без пробы.
2. Пробы: по одной ложной программе на каждое правило из аудита — сегодня ядро
   говорит «доказано», после починки — «объявлено, не доказано» (или отказ с названной
   причиной). Честные записи корпуса — без изменений.
3. Печать записи (`zapis.flang`) у починенных правил не меняется: запись печатается
   только для доказанного.

## Чего не делать
