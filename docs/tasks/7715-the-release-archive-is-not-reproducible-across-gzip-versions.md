# 7715. Релизный архив не повторим между машинами: версия gzip не закреплена, и тот же вход даёт другой sha256

## Шаги воспроизведения

1. `grep -c 'gzip' .github/actions/release-archive/action.yml`
2. Сжать один и тот же вход двумя разными сборками deflate на уровне 9 и сравнить
   sha256 — сжатие единственное место, где байты архива могут разойтись:

```
gzip -9nc <файл> | sha256sum
python3 -c "import zlib,hashlib,sys; d=open(sys.argv[1],'rb').read();
c=zlib.compressobj(9,zlib.DEFLATED,16+15,9,0);
print(hashlib.sha256(c.compress(d)+c.flush()).hexdigest())" <файл>
```

3. Собрать архив той же командой на раннере GitHub и на машине разработки из
   одного дерева, сравнить sha256.

## Что происходит

```
$ grep -c 'gzip' .github/actions/release-archive/action.yml
4                                                                   код 0
```

Версия gzip печатается (`gzip --version`, строка 134), но не закрепляется.
Строка сборки — 121, `gzip -9n`.

Шаг 2 на этой машине (GNU gzip 1.14 против zlib питона, уровень 9) расходится от
размера входа:

```
вход 200 000 байт:      a080dd64…ce7b0   оба одинаково
вход 36 398 751 байт:   gzip 372222fa…eb74, zlib 0421d435…ff6a — разошлись
```

То есть байты архива зависят от сборки deflate, и на размере релизного архива
зависят наверняка.

Шаг 3 не перемерен: на машине одна версия gzip. Записанный прогон на выпуске
0.7.21, одно дерево и один список файлов:

```
раннер GitHub:                        sha256 a52de64106510fe0d91dd2d7d569ac33caf427f6290c98fd973c82630c019eb2
машина разработки, tar 1.35, gzip 1.14: sha256 4085bd7fe418adf8de404937c5628df3a3923a3489e9f61f970fdb5aba05c83d
```

На одной машине два прогона подряд дают один хеш, несжатый поток tar тоже
совпадает сам с собой.

Версия: `grep` и шаг 2 сняты на flang 0.7.23, 2 октября 2026; шаг 3 — не
перемерен.

## Что должно быть

Архив, собранный из одного дерева в двух средах, совпадает побайтово. Тогда
`scripts/guards/homebrew-formula-guard.fscript` может подтвердить sha256 формулы
архивом, собранным на месте.

## Обходной путь

Брать sha256 из вывода работы выпуска на раннере: `.github/workflows/release.yml`
ходит на тег `v*` и по ручному запуску. Проверку формулы не ослаблять: число,
которое нечем подтвердить, она отвергает правильно.

## Когда задача сделана

1. Сличён несжатый поток tar у себя и на раннере: совпал — виновато только
   сжатие.
2. Выбран и записан способ: закрепить версию gzip в работе выпуска, сжимать
   своим кодом, либо выпускать архив без сжатия (тогда замерить рост размера).
3. Есть проба: два архива из двух сред совпадают побайтово, и проба краснеет
   на подложенном расхождении.

## Где живёт правка

`.github/actions/release-archive/action.yml`, шаг сборки архива (строка 121 с
`gzip -9n`); новая проба рядом с проверками выпуска в `scripts/release/`.
Перепечатка не нужна.
