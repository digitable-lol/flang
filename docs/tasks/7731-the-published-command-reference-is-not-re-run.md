# 7731. Справочник команд сверяют рукой, и он разошёлся

`docs/site/cli.md` и `docs/site/cli.ru.md` — единственное место, где команды
двоичного описаны целиком: вызов, ключи, вывод, код возврата. Страница сама
обещает в шапке, что каждый показанный вывод прогнан на двоичном. Сверку эту
делают рукой, и последняя была 11 сентября 2026 на версии 0.7.17.

## Что снято 24 сентября 2026

Двоичный в дереве — 0.7.21, собран из `90249e71f`. Примеров вида `$ flang …` на
странице 21. Из них **5 называют настоящие файлы дерева** и поддаются прогону;
остальные 16 написаны на выдуманном привет.flang, которого в дереве нет.

Прогнаны все пять. Разошлись три:

| пример | что обещано страницей | что вышло на 0.7.21 |
|---|---|---|
| `io ярлыки.flang --plan «Целость»` | `{"error":"не найден план …"}` | отказ «не доказано: утверждений 17: доказано 14, сетка 3», код 3 |
| `io ярлыки.flang --plan Целость` | `ярлыков 102`, код 0 | тот же отказ, код 3; с `--trust` — `ярлыков 147` |
| `io kernel-forgeries.fscript --plan 'Аксиом ноль'` | результат, код 0 | тот же отказ, «утверждений 73: доказано 69, сетка 4», код 3 |

Сошлись два: `--plan «Аксиом ноль»` (та же ошибка разбора ключа, код 2) и
`io … --args '{}'` (ключа нет, код 2).

Причина первых трёх одна и названа в самой странице абзацем ниже: недоказанный
план по умолчанию не исполняется (ADR-0045). Политику ввели после 11 сентября,
а примеры остались от неё.

Кроме примеров, разошлось описание самой команды `io`:

* строка вызова на странице содержит `[--timeout N]` и не содержит
  `[-- довод…]`; двоичный печатает наоборот;
* список полномочий на странице кончается на `--no-spawn`; двоичный называет
  ещё `--no-env`, `--no-args`, `--no-screen`;
* «шестнадцать ярлыков передают `--timeout`» — в `ярлыки.flang` их 23.

Всё перечисленное поправлено вместе с заведением этой задачи. Не поправлено
главное: сверять по-прежнему некому.

## Что делать

**1. Дать странице настоящий входной файл.** Шестнадцать примеров стоят на
привет.flang, которого нет. Положить его (и плохо.flang, план.flang,
факты.json) в `docs/site/examples/` — тогда прогоняемыми станут все 21.

**2. Снимать примеры прогоном, а не рукой.** Проверка читает из страницы блоки
` ```bash `, берёт строки `$ flang …`, зовёт двоичный, сверяет вывод и код с
показанными. Строки, где вывод сокращён многоточием `…`, сверяются по началу.
Цена — секунды на пример; дороже всех `--plan Целость`, он обходит дерево.

**3. Поставить это в CI туда же, где собран двоичный** — в работу `build`
файла `.github/workflows/binary.yml`, рядом с проверкой `ярлыки.flang`. Отдельной
работой нельзя: двоичный пришлось бы собирать второй раз (5–6 минут).

**4. Сверять обе страницы одной проверкой.** Русская и английская версии
показывают одни и те же прогоны; расхождение между ними — тоже брак.

## Приём

Проверка красна на дереве, где в `docs/site/cli.md` подменён любой один
показанный вывод или код возврата, и зелена на нетронутом. Красна она и на
расхождении русской страницы с английской. Шапка страницы больше не обещает
сверки рукой, а называет проверку, которая её делает.

## Чего в этой задаче НЕТ

Не трогаются `docs/site/numbers.json` и прочие числа сайта — их сверяет
`scripts/guards/published-vs-tree.sh`. Речь только о показанных прогонах команд.
