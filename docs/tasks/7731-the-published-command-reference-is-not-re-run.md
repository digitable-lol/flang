# 7731. Справочник команд сверяют с двоичным рукой, и показанные в нём выводы расходятся с настоящими

`docs/site/cli.md` и `docs/site/cli.ru.md` описывают все команды двоичного:
вызов, ключи, вывод, код возврата. Шапка обещает: «каждый вывод ниже снят с
нынешнего двоичного».

## Шаги воспроизведения

1. `grep -c '^\$ flang' docs/site/cli.md docs/site/cli.ru.md`
2. `grep -n '"коротких команд' docs/site/cli.ru.md`, затем
   `bootstrap/flang io scripts/shortcut-collector.fscript --plan Целость`
3. Для каждого примера `$ flang …` проверить, лежат ли в дереве входные файлы,
   которые он называет.

## Что происходит

```
$ grep -c '^\$ flang' docs/site/cli.md docs/site/cli.ru.md
docs/site/cli.md:31
docs/site/cli.ru.md:31
$ grep -n '"коротких команд' docs/site/cli.ru.md
658:{"plan":"Целость","result":"коротких команд 150; …
$ bootstrap/flang io scripts/shortcut-collector.fscript --plan Целость
{"plan":"Целость","result":"коротких команд 153; посмотрено 152: …      код 0
```

Из 31 примера каждой страницы прогнать можно 14: у 17 входные файлы в дереве
не лежат — привет.flang, план.flang, плохо.flang, сетка.flang, факты.json.

Сверять страницу нечем. Единственная проверка, которая смотрит на напечатанные
команды, — `sh scripts/guards/published-vs-tree.sh --команды` из работы
`published-check` файла `.github/workflows/binary.yml`; она ищет одну беду
(имя плана в ёлочках) и обе страницы справочника из поиска исключает явным
`':!docs/site/cli.md' ':!docs/site/cli.ru.md'`. Больше их не читает никто.

Счёт команд на странице тоже держится рукой и разошёлся втрое: проза
обещает «четырнадцать команд», своя же шпаргалка страницы перечисляет 15, а
`flang --help` называет 16 (`--mcp-mode` на странице нет).

Девять битых путей из задачи 6480 стоят на этих же двух страницах.

Версия: flang 0.7.23.

## Что должно быть

Каждый пример `$ flang …` на обеих страницах снимается прогоном: проверка
читает блоки `bash`, зовёт двоичный и сверяет вывод и код возврата с
показанными. Вывод, сокращённый многоточием, сверяется по началу.

## Обходной путь

Сверять рукой при каждом выпуске.

## Когда задача сделана

1. Входные файлы примеров лежат в дереве (например, в `docs/site/examples/`),
   и прогоняемы все примеры страницы.
2. Проверка красна, если в `docs/site/cli.md` подменён один показанный вывод
   или код возврата, и зелена на нетронутом дереве.
3. Она красна на расхождении русской страницы с английской и на расхождении
   счёта команд с `flang --help`.
4. Проверка стоит короткой командой в `.flangrc` и в работе `build` файла
   `.github/workflows/binary.yml`, где двоичный уже собран.
5. Шапка страницы называет эту проверку вместо сверки рукой.

Числа сайта (`docs/site/numbers.json`) задача не трогает: их сверяет
`scripts/guards/published-vs-tree.sh --числа`.

## Где живёт правка

Новая проверка в `scripts/guards/`, строка в `.flangrc`, шаг в
`.github/workflows/binary.yml`, обе страницы `docs/site/cli.md` и
`docs/site/cli.ru.md`. Перепечатка не нужна.
