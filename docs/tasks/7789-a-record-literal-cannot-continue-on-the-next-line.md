# 7789. Литерал записи не переносится на следующую строку: пример с двумя вложенными записями не укладывается в 120 знаков, и сторож роста не пускает его в дерево

Решение рядом: `docs/adr/0086-an-adjunction-is-a-declared-unit-and-counit-with-the-triangle-identities-as-laws.md`,
раздел 8 — вторым примером сопряжения взято «Возможно ⊣ забывающий», а не
«диагональ ⊣ произведение», потому что у второго каждый пример коединицы —
литерал глубины три.

## Шаги воспроизведения

1. Программа:

   ```flang
   модуль «Пара пар»

   объект «Товар»
     код является числом

   объект «Пара товаров»
     первый является «Товар»
     второй является «Товар»

   тотальная функция «Поменять»
     принимает пара: «Пара товаров»
     возвращает «Пара товаров»
     пример «семь и три»
       дано пара равно запись «Пара товаров» с первый равным (запись «Товар» с код равным 7) и второй равным (запись «Товар» с код равным 3)
       ожидается запись «Пара товаров» с первый равным (запись «Товар» с код равным 3) и второй равным (запись «Товар» с код равным 7)
     запись «Пара товаров» с первый равным пара.второй и второй равным пара.первый
   ```

2. `git add` и `git commit` в дереве с включёнными хуками.
3. Смотреть ответ `.githooks/lint-growth.fscript`.

## Что происходит

```
$ git commit
FLANG_LINT_GROWTH: flang/ct/<файл>.flang:14: an added line is 137 characters long, the limit is 120
                                                                        код 1
```

Переносы в flang разрешены только после `[` и после запятой в списке; у литерала
записи (`запись … с … равным … и … равным …`) места переноса нет, а `дано` и
`ожидается` принимают только литерал, так что `пусть` не поможет. Запись с двумя
вложенными записями — 137 знаков при коротких именах; пара пар — больше 300.

Версия: `flang 0.7.25`, хук `.githooks/lint-growth.fscript` на `dev` `1149c78f7`.

## Что должно быть

Либо литерал записи переносится после `и` перед следующим полем (как список —
после запятой), либо сторож роста считает строку примера с литералом записи по
другой мерке. Первое предпочтительнее: правило «не перед `и`» писалось для
выражений, а не для перечня полей.

## Обходной путь

Выбирать примеры глубины не больше двух и имена не длиннее нужного; для
категорной поверхности — брать конструкции, у которых вложенность идёт через
`список` или `вариант`, а не через запись в записи.

## Когда задача сделана

Программа выше с переносом `дано` на две строки проходит `bootstrap/flang check`
кодом 0 и `git commit` без `FLANG_LINT_GROWTH`; подлог — та же программа одной
строкой — по-прежнему отвергается хуком.

## Где живёт правка

`flang/self/parser.flang` (перенос внутри литерала записи),
`.githooks/lint-growth.fscript`. Правка разборщика требует перепечатки семени.
