# 8192. Независимые сверщики не читают блок «история», и check --proof на истории отвечает кодом 3

## Шаги воспроизведения

1. Программа `flang/proof/probes/parse-and-import/programs/story-discount-cap.flang`:

   ```flang
   модуль «Story discount cap»

   объект «Роль»
     «менеджер зала»: признак

   история «потолок скидки»
     как «менеджер зала»
     хочу «скидка» не больше 30
     чтобы "кассир не отдал товар ниже себестоимости"
     при «скидка» не меньше 0
     тогда при «скидка» 40 ответ 30
   ```

2. `make -C flang/proof/checker`, затем
   `bootstrap/flang check story-discount-cap.flang --proof`.

## Что происходит

Ядро цель доказывает, а сверщик на C запись не принимает:

```
$ bootstrap/flang check story-discount-cap.flang --proof
  постусловие «хочу: скидка не больше 30» функции «потолок скидки» — доказано сведением цели с телом функции …
story-discount-cap.flang: НЕ СОШЛОСЬ СО СВЕРЩИКОМ — сверщик не принял запись доказательства файла без ввоза: НЕ СОШЛОСЬ: в исходнике постусловий 0, а в записи утверждений 1 … тотальность «потолок скидки»: строка 6 исходника — не «тотальная функция «потолок скидки»» (стоит «история «потолок скидки»»)
                                                  код 3
```

Без собранного сверщика тот же файл даёт код 0. Сверщик сличает запись со
строками исходника и ищет `тотальная функция` и `обеспечивает`; у истории это
`история` и `хочу`, а тело функции в исходнике не записано вовсе.

Версия: flang 0.7.30.

## Что должно быть

Сверщики знают, во что разбор превращает историю (таблица в `docs/flang/SPEC.md`,
раздел о блоке `история`): заголовок — тотальная функция, `хочу` — постусловие
с телом `если «в» не больше N то «в» иначе N`, `как` и `при` — предусловия,
`тогда` — пример.

## Обходной путь

Писать то же требование тотальной функцией с `обеспечивает`; её запись сверщик
переигрывает.

## Когда задача сделана

1. `checker.c` и сверщик на Lean 4 читают блок `история`; на
   `story-discount-cap.flang` `check --proof` со сверщиком отвечает кодом 0.
2. Отрицательный контроль: история с ложным `хочу` (например, тело даёт 40 при
   `хочу «скидка» не больше 30`) даёт `НЕ СОШЛОСЬ`.
3. Строка `story-discount-cap.flang` в
   `flang/proof/probes/parse-and-import/expected.tsv` снова ждёт код 0 и слово
   «— доказано»; сейчас она ждёт код 3 и «НЕ СОШЛОСЬ СО СВЕРЩИКОМ».

## Где живёт правка

`flang/proof/checker/checker.c`, сверщик на Lean 4 в `flang/proof/lean/`,
строка пробы. Семя не трогается: правка вне `flang/self/**`.

## Чем закрыта

`истории_функциями` в `checker.c` и `«историиФункциями»` в
`flang/proof/lean/RecordReader.lean` (её зовут второй сверщик в
`checker/second/Surfaces.lean` и сверка вердиктов `VerdictCheck.lean`) переводят строки
истории одну в одну: заголовок — `тотальная функция`, `как` и `при` — `требует`,
`хочу` — `обеспечивает`, на строке `чтобы` — тело, которое сверщик строит из `хочу` сам,
`тогда` — пустая строка. Номера строк записи ядра остаются номерами строк истории.

Ложное `хочу` историей не записать: тело строится из того же `хочу`. Поэтому
отрицательный контроль двойной. Семья `flang/proof/checker/tests/families/story/`:
честная пара даёт 0; три подделки дают 1 — история хочет «не больше 20», а запись
говорит «не больше 30»; утверждение приписано строке `чтобы`; заголовок `история`
заменён на `тотальная функция`. И отдельно: сверщик, у которого тело истории даёт
`иначе 40`, на той же паре отвечает «НЕ ПРОВЕРЕНО» и называет «хочу: скидка не больше 30»
местом на слове ядра — значит, цель он проигрывает по телу, а не верит записи.

Второй сверщик на Lean историю читает и цель проигрывает сам: его разбор цели по
условию не узнавал условие, которое начинается с имени в ёлочках
(`«скидка» не больше 30`), и та же функция, написанная руками с `«скидка»`, давала у него
код 3 при коде 0 у сверщика на C. Теперь `подставитьУсловие` в `second/Body.lean` ищет
такое условие до того, как ёлочка уводит чтение внутрь имени. Сверка двух сверщиков на
всех 713 записях проб и подделок — расхождений 0.
