# 8281. Значение типа «число» нечем сузить до «неотрицательное», и спецификация не говорит, что перехода нет

Заявка: https://github.com/digitable-lol/flang/issues/418

Отрицательный литерал в поле записи типа `неотрицательное` отвергается
(`FLANG_TYPE`, код 1; проба `flang/proof/probes/non-negative-field/run.fscript`).
Задача — о сужении значения типа `число`.

## Шаги воспроизведения

1. Проба suzh.flang:

   ```
   тотальная функция «Сузить»
     принимает «н»: число
     возвращает неотрицательное
     если «н» не меньше 0
       то «н»
       иначе 0
   ```

2. Проба trebuet.flang: то же с `требует «неотрицательно» «н» не меньше 0` и
   телом `«н»`.
3. Проба celost.flang: первая проба, у которой условие ещё и проверяет целость:
   `если («н» не меньше 0) и притом ((«н» остаток от 1) равен 0)`.
4. Проба celoe.flang: первая проба с `принимает «н»: целое`.
5. `bootstrap/flang check` на каждой.

## Что происходит

```
$ bootstrap/flang check suzh.flang
FLANG_TYPE в файле suzh.flang, строка 4, столбец 3: функция «Сузить» объявлена как неотрицательное, а тело даёт число     код 1
$ bootstrap/flang check trebuet.flang
FLANG_TYPE в файле trebuet.flang, строка 5, столбец 3: функция «Сузить» объявлена как неотрицательное, а тело даёт число  код 1
$ bootstrap/flang check celost.flang
FLANG_TYPE в файле celost.flang, строка 4, столбец 3: функция «Сузить» объявлена как неотрицательное, а тело даёт число   код 1
$ bootstrap/flang check celoe.flang
celoe.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет                                       код 0
```

Из `целое` сужение сравнением с литералом работает. Из `число` не работает ни
условие, ни предусловие — и проверка целости рядом со сравнением дела не меняет.

Версия: flang 0.7.25 (четыре пробы повторены 11 октября 2026, ответы те же).

## Что должно быть

Одно из двух, и выбранное записано в `docs/flang/SPEC.md`, раздел «Точное
натуральное»:

- есть форма, которая сужает `число` до `неотрицательное` (условие либо
  предусловие `не меньше 0` вместе с проверкой целости);
- либо сказано прямо, что из `число` перехода нет и сужается только `целое`.

## Обходной путь

Принимать значение как `целое` и сужать сравнением с литералом в `если`.

## Когда задача сделана

Одно из двух, и прибор их различает:

- `bootstrap/flang check suzh.flang` отвечает кодом 0 (сейчас 1);
- либо в `docs/flang/SPEC.md`, в перечне «Чего `неотрицательное` НЕ делает»
  раздела «Точное натуральное» (строка 162), стоит строка про отсутствие перехода из
  `число`, а `check suzh.flang` по-прежнему отвечает кодом 1.

В обоих случаях проба `flang/proof/probes/non-negative-field/run.fscript`
остаётся зелёной: проб 15, разошлось 0, код 0.

## Где живёт правка

Интервальный анализ границ в `flang/self/types.flang`; раздел «Точное
натуральное» в `docs/flang/SPEC.md`. Правка `flang/self/types.flang` требует
перепечатки самосборной части, спецификация — нет.

Следующий шаг: дешёвый путь — `docs/flang/SPEC.md`, перечень «Чего `неотрицательное` НЕ
делает» (строка 162): сегодня там названы деление, накопитель свёртки и сравнение имени с
именем, а перехода из `число` нет ни словом. Дорогой путь — интервальный анализ в
`flang/self/types.flang`. Красно сегодня: `check suzh.flang` — `FLANG_TYPE`, и `grep -n 'из
.число' docs/flang/SPEC.md` молчит.
