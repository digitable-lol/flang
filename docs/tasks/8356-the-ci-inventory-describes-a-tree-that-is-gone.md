# 8356. Опись проверок снята двоичным 0.6.2 и говорит о дереве, которого нет: 82 цели в снятом файле, столбца памяти нет, числа не сверяет никто

## Шаги воспроизведения

1. Прочитать, чем и когда снята опись:

```
sed -n 3,8p docs/ci-inventory.md
```

2. Сосчитать её строки и столбцы:

```
grep -c -a '^|' docs/ci-inventory.md
sed -n 66p docs/ci-inventory.md
```

3. Сверить имена целей описи с настройками (`.flangrc` — место коротких команд,
   ADR-0049):

```
grep -a '^| [0-9]' docs/ci-inventory.md | awk -F'|' '{gsub(/[ `]/,"",$3); print $3}' | grep -a ':' | sort -u | wc -l
grep -c -a '^script\.' .flangrc
ls ярлыки.flang
```

4. Посмотреть, кто её читает:

```
git grep -l -a 'ci-inventory' -- '*.fscript' '*.mjs' '*.sh'
```

## Что происходит

```
$ sed -n 3,8p docs/ci-inventory.md
Снято 25 августа 2026 на коммите `a3a18a3f` … двоичным `flang 0.6.2` …
Целей в `ярлыки.flang` — 82.                                             код 0
$ grep -c -a '^|' docs/ci-inventory.md
94
$ sed -n 66p docs/ci-inventory.md
| # | цель | код | время | с ключом | причина у красного |
$ … | sort -u | wc -l
74
$ grep -c -a '^script\.' .flangrc
153
$ ls ярлыки.flang
ls: cannot access 'ярлыки.flang': No such file or directory               код 2
$ git grep -l -a 'ci-inventory' -- '*.fscript' '*.mjs' '*.sh'
flang/scripts/code-forgery.fscript
flang/scripts/code-guard.fscript                                         код 0
```

Версия: flang 0.7.23.

Опись считает 82 цели в файле, которого в дереве нет, а коротких команд в
`.flangrc` — 153. Имён целей в её строках 74, и у трёх из них команды нет вовсе:
`установка:npm`, `proofs:emptiness`, `reduction:check`. Столбца памяти в описи
нет ни у одной строки — столбцы «цель, код, время, с ключом, причина». Числа
описи не сверяет ни одна проверка: два сторожа, которые её читают, ищут в ней
имена кодов отказа, а не коды и секунды; `inventory:check` сверяет
`docs/tree-inventory.md`, другой документ.

## Что должно быть

Либо опись переснята прибором на текущем двоичном и её числа сверяет сторож —
тогда у каждой строки есть код, время и пик памяти, а имена целей берутся из
`.flangrc`; либо опись снята с дерева с названной причиной, и тогда ни одна
страница на неё не ссылается. Правило «число ценно только снятое прогоном» —
`docs/zero-bug-policy.md`.

## Обходной путь

Не верить описи и мерить нужную короткую команду руками под `/usr/bin/time -v`.

## Когда задача сделана

Прогон сторожа описи отвечает кодом 0 и называет число строк, снятых текущим
двоичным; строка с целью, которой нет в `.flangrc`, краснит его (это показано
пробой, в которой имя цели нарочно испорчено). Либо файла в дереве нет, причина
записана в сообщении свода, и `links:check` не находит ссылок на него.

## Где живёт правка

`docs/ci-inventory.md` и новый сторож рядом с `scripts/guards/`; вызов в
`.flangrc` и в `.github/workflows`. Кода языка задача не меняет, пересборка
семени (bootstrap regeneration) не нужна. Пять строк о тяжёлых проверках
доказательств мерит задача 1941 — здесь они не переснимаются.
