# 8586. «Дополнить запрос» в postgres.flang считает длину строки заново на каждом витке, и пример проходит без запаса по шагам

## Шаги воспроизведения

1. `grep -c 'Досыпать пробелы' flang/stdlib/postgres.flang`
2. `bootstrap/flang test flang/stdlib/postgres.flang --max-steps 20000000`
   (2 мин 32 с, пик памяти 390 МиБ)
3. `bootstrap/flang test flang/stdlib/postgres.flang` — при умолчании
   (2 мин 52 с, пик 385 МиБ)
4. то же с `--max-steps 33000000` и `--max-steps 37000000` — где лежит порог

## Что происходит

```
$ grep -c 'Досыпать пробелы' flang/stdlib/postgres.flang
0                                                                          код 1
```

Тело функции (строки 325–327; объявление с 301) на каждом из 128 витков зовёт
«Байтов в тексте» от всей строки, а строка растёт со 122 знаков до 250: цена
квадратична по числу досыпанных пробелов.

```
$ bootstrap/flang test flang/stdlib/postgres.flang --max-steps 20000000
FLANG_RECURSION_LIMIT: пример «непечатаемая длина дополняется пробелами: 122
знака запроса требуют 128 пробелов» функции «Дополнить запрос» не прошёл:
функция «Байтов в тексте» исчерпала лимит шагов (20000000) на глубине вызовов 98
flang/stdlib/postgres.flang: примеров 209, прошло 208, не прошло 1          код 1
$ bootstrap/flang test flang/stdlib/postgres.flang
flang/stdlib/postgres.flang: примеров 209, прошло 209, не прошло 0          код 0
```

Предел кончается не у самой «Дополнить запрос», а внутри вызванной ею длины: на
20 000 000 — в «Байтов в тексте» на глубине 98, на 33 000 000 — в «Шаг веса
текста» на глубине 19. Запаса у примера нет: 33 000 000 он не проходит,
37 000 000 проходит, а умолчание — 40 000 000 (`flang/self/bootstrap/compiler.flang`,
«Предел витков проверки»). То есть он просит от 33 до 37 миллионов при
умолчании 40 — запас меньше чем в полтора раза, и следующее обещание на этом
пути уронит файл.

Версия: flang 0.7.23, 3 октября 2026.

## Что должно быть

Пробел в ASCII весит один байт, пересчёт длины на витке не нужен: длина
считается один раз и дальше несётся доводом. Пример проходит при
`--max-steps 20000000`, то есть с запасом вдвое к умолчанию в 40 000 000.

## Обходной путь

Не нужен: при умолчании `flang test` файл проходит.

## Когда задача сделана

```sh
bootstrap/flang test flang/stdlib/postgres.flang --max-steps 20000000
bootstrap/flang check flang/stdlib/postgres.flang --proof --json
```

Первая команда: 209 из 209, код 0 (сейчас 208 из 209, код 1 — она и различает
работу; при умолчании файл проходит и до правки, так что умолчанием мерить
нечего).

Вторая: `totals.claims.grid` не больше 68 — столько сеточных приговоров у файла
сейчас. Ведомость стоит 5 мин 21 с и 930 МиБ, код 0. У «Дополнить запрос» пять
обещаний (два `proved-induction`, два `grid`, одно `proved`) и три примера —
сохранены дословно.

## Где живёт правка

`flang/stdlib/postgres.flang`: шаг с накопителем («Досыпать пробелы» от
запроса, надбавки, запаса и уже посчитанных байтов), «Дополнить запрос»
остаётся оболочкой и зовёт «Байтов в тексте» один раз. Библиотека читается из
дерева, перепечатка не нужна.
