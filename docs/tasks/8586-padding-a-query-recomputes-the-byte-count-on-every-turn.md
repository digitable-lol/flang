# 8586. «Дополнить запрос» в postgres.flang считает длину строки заново на каждом витке, и пример проходит без запаса по шагам

## Шаги воспроизведения

1. `grep -n 'Досыпать пробелы' flang/stdlib/postgres.flang`
2. `bootstrap/flang test flang/stdlib/postgres.flang --max-steps 20000000`
   (прогон идёт около восьми минут, пик памяти около 5 ГиБ)

## Что происходит

```
$ grep -c 'Досыпать пробелы' flang/stdlib/postgres.flang
0                                                                          код 1
```

Тело функции (строка 299) на каждом из 128 витков зовёт «Байтов в тексте» от
всей строки, а строка растёт со 122 знаков до 250: цена квадратична по числу
досыпанных пробелов.

Версия: flang 0.7.23, 30 сентября 2026 (только `grep`).

Прогон примеров не перепроверено; записано на flang 0.7.22:

```
$ bootstrap/flang test flang/stdlib/postgres.flang --max-steps 20000000
примеров 209, прошло 208, не прошло 1                                      код 1
```

Не проходит пример «непечатаемая длина дополняется пробелами: 122 знака запроса
требуют 128 пробелов». При умолчании `flang test` в 40 000 000 шагов он
проходит, прося от 33 до 37 миллионов.

## Что должно быть

Пробел в ASCII весит один байт, пересчёт длины на витке не нужен: длина
считается один раз и дальше несётся доводом. Пример проходит с двойным запасом
к умолчанию.

## Обходной путь

Не нужен: при умолчании `flang test` файл проходит.

## Когда задача сделана

```sh
bootstrap/flang test flang/stdlib/postgres.flang --max-steps 20000000
bootstrap/flang check flang/stdlib/postgres.flang --proof --json
```

Первая команда: 209 из 209, код 0. Вторая: число `claims.grid` не выросло
против прогона до правки. Пять обещаний и три примера «Дополнить запрос»
сохранены дословно.

## Где живёт правка

`flang/stdlib/postgres.flang`: шаг с накопителем («Досыпать пробелы» от
запроса, надбавки, запаса и уже посчитанных байтов), «Дополнить запрос»
остаётся оболочкой и зовёт «Байтов в тексте» один раз. Библиотека читается из
дерева, перепечатка не нужна.
