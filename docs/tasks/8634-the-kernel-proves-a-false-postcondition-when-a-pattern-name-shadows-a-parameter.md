# 8634. Имя образца, совпавшее с параметром, ядро путает с параметром

## Шаги воспроизведения

1. Программа `cap.flang`:

```flang
модуль «Cap»

тип «Ящик»
  вариант «Полный» содержит х: число
  вариант «Пустой»

тотальная функция «Ловушка»
  принимает х: число, я: «Ящик»
  возвращает признак
  обеспечивает «ложь» если х больше 0 то (результат равен да) иначе да
  пример «один»
    дано х равно 1
    дано я равно вариант «Пустой»
    ожидается да
  разбор я
    случай «Полный» с х как х
      то х больше 0
    случай «Пустой»
      то да
```

2. `bootstrap/flang check --proof cap.flang`.

## Что происходит

```
постусловие «ложь» функции «Ловушка» — доказано индукцией по «Ящик»: база 2 случая,
шаг при допущении на частях (0 случаев), правила сведения: разбор цели по условию
cap.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 1: доказано 1, … — код возврата 0
```

На входе `х = 1`, `я = вариант «Полный» с х равным -1` тело возвращает `нет`, и
постусловие нарушено.

Посылку индукции для варианта `«Полный»` ядро строит в
`flang/self/proof-initial.flang` (`«Посылка принципа»`): поле варианта объявляется
именем из образца (`х`), разбираемый довод `я` заменяется конструктором
`«Полный»(х)`, а `результат` — телом случая. Параметр `х` объявлен в той же посылке
тем же именем. В цели `если х больше 0 то ((х больше 0) равен да) иначе да` оба `х`
стали одним, и разбор цели по условию её закрывает.

Та же ошибка у образца `голова х и хвост т` разбора списка, у имени хвоста и у
имени случая в теореме индукцией, совпавшего с переменной свободного утверждения.

## Что должно быть

Ядро не доказывает такое постусловие. Посылка, в которой имя поля (из образца, из
случая теоремы или само имя поля, когда образец его не связывает) совпадает с
параметром функции, с переменной утверждения, со связкой результата или со свободным
именем цели, не строится: принцип индукции отказывает словами «образец разбора
связывает имя «…», которое уже названо параметром…». Когда образец связывает имя
самого разбираемого довода, тело случая не получает подстановки довода: под таким
образцом это имя — поле, а не довод.

## Обходной путь

Назвать имя образца иначе, чем параметры функции: `случай «Полный» с х как «зн»`.

## Когда задача сделана

- исходники ядра (`flang/self/bootstrap/check-with-source-compiler.flang`) на
  `cap.flang` и на тех же формах для списка и для теоремы индукцией отвечают
  «объявлено, не доказано», а на тех же программах со свежим именем образца —
  «доказано», как и раньше;
- после печати семени опровергатель (`bootstrap/flang run-script falsifier:check`)
  перестаёт находить причину `pattern-shadow/pattern-shadows-parameter/false-proof`,
  её строка уходит из `flang/proof/probes/falsifier/expected-failures.tsv`, строка
  `kernel-proves-a-pattern-name-shadowing-a-parameter` в
  `flang/proof/tables/consistency-violations.tsv` становится `closed`;
- checker на записях семьи `flang/proof/checker/tests/families/pattern-shadow/`
  отвечает кодом 1 или 3.

## Где живёт правка

`flang/self/proof-initial.flang` — `«Принцип индукции»` (поле `unread` с отказом
`shadow`), `«Заключение посылки»` (тело без подстановки довода под образцом с его
именем); `flang/self/proofterm.flang` — `«Свернуть принцип суммы»` и `«Отказ
затенения»`: теорема индукцией по сумме отказывает тем же доводом. Ждёт печати семени.
