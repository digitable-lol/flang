# 9233. Зеркало документации догнало каталог кода, адрес сайта остался прежним

Находка не моя: её оставил работник задачи [1505](1505-prose-readmes-next-to-code-move-to-docs.md)
в разделе «чинить не здесь». Каталог кода стал `flang/concurrency/` коммитом
`5ce665a12` (66 файлов), а зеркало документации осталось `docs/flang/conc/`. Плюс
к тому в `docs/flang/` уже появился второй каталог `concurrency/` с одним `README.md`,
который ссылался к соседу через `../conc/` — то есть про одно и то же в дереве
стояли ДВЕ папки.

## Гипотеза до замера

Названа прежде, чем считать: **большинство из 348 вхождений — ссылки на КОД
`flang/conc/*.flang`, уже битые после `5ce665a12`; собственно зеркало
документации даст меньшую долю, навскидку 60–100; прозы (слово не как путь) —
единицы.**

По направлению верно, по числам уточнилось.

## Замер

Дерево уехало с тех пор, поэтому число не 348: в `gh/main` на 24 сентября 2026

```
git grep -c 'flang/conc/'      344 строки в 129 файлах
git grep -o  'flang/conc/'     358 вхождений
```

Разбор 358 по тому, что это за путь:

| вид | вхождений | чем обрамлено |
|---|---|---|
| путь ЗЕРКАЛА `docs/flang/conc/` | **87** в 48 файлах | 69 в обратных кавычках, 18 прочее |
| путь КОДА `flang/conc/` | **271** | 193 в обратных кавычках, остальное проза и кавычки |

Разбор по шаблону `docs/` врёт на 4: столько ссылок в зеркало записаны
относительно и попали в колонку «код». Честный раздел — **зеркало 91, код 267**.

Прозы, где «conc» не путь, нет вовсе: все 358 — пути. Обратные кавычки вокруг
196 из них значат, что это указатели в тексте, а не ссылки: **markdown-ссылок на
`conc/` во всём дереве всего 8**, и сборщик сайта следит только за ними.

Три замера, которых гипотеза не предвидела:

- **Исходящих относительных ссылок из трёх файлов зеркала — 0.** Наружу рвать
  нечего, и глубина каталога при переезде та же.
- **Входящих относительных — 3**, все в `docs/flang/concurrency/README.md`
  (`../conc/X`); в шаблон `docs/flang/conc/` они не попадают и молча пережили бы
  массовую замену.
- **Ещё 4 ссылки в зеркало записаны относительно и тоже мимо шаблона**: у трёх
  цель набрана без `docs/` — просто `flang/conc/SPEC.md` (`docs/DESCRIPTION.md:26`
  и `:539`, `docs/README.ru.md:242`), у четвёртой — на шаг вверх, `../flang/conc/SPEC.md`
  (`docs/adr/0003:6`). Сами скобки ссылки здесь нарочно не набраны: цитата битой
  ссылки в задаче — это битая ссылка в задаче.

## Уклад, которым решён спор о переезде файлов

`docs/flang/` зеркалит `flang/` один в один: `core`, `ct`, `proof`, `self` — имена
совпадают. `conc` был единственным исключением, и держался он только на том, что
переименование кода за собой документацию не потянуло.

## Решение по адресу сайта — главный вопрос ячейки

`spec-conc.html` — внешний адрес: на него могут быть ссылки из чужих закладок,
писем и постов. Рассмотрены три хода.

| ход | цена |
|---|---|
| переименовать адрес в `spec-concurrency.html` + завести переезд | 134-й переезд и лишняя страница навсегда; каждая внешняя ссылка идёт через прыжок; поломка причинена своей рукой |
| **оставить адрес, сменить только `из`** | путь и адрес расходятся — но они и так разные поля |
| не трогать ничего | в `docs/flang/` навсегда две папки про одно |

**Выбран второй.** Доводы — из дерева, не из вкуса:

1. В карте сайта `адрес` и `из` разведены двумя полями нарочно: первое —
   обещание чужой закладке, второе — наше внутреннее дело. Переезд исходника
   не обязан касаться адреса.
2. Прецедент в том же разделе карты: `spec-cat.html` собирается из
   `docs/ct/spec.md`. Краткая форма адреса уже не совпадает с именем каталога, и
   бедой этого никто не считает. Там же стоит комментарий «Адрес не сменился» о
   странице, которая переехала между разделами.
3. Шапка `ПЕРЕЕЗДОВ` говорит прямо: «Список закрыт: сюда попадают только адреса,
   которые уже были опубликованы. Новая страница переезда не заводит — ей неоткуда
   переезжать». Переезд — плата за поломку, причинённую ради чего-то. Здесь
   читателю нечего дать: адрес не транслитный, не врущий и не длинный.
4. Сломать адрес хуже, чем оставить кривой путь: путь читают свои, адрес — чужие.

Проверяемое следствие решения было названо ДО правки: **переездов должно остаться
133, страниц 826**. Прогон после правки это подтвердил.

## Что оставлено и почему

Правило, по которому разобрано каждое вхождение: **путь переписан там, где он
указатель «открой этот файл»; старое имя оставлено там, где оно свидетельство** —
цитата прежнего текста, запись прежнего решения или строка вывода прогона на дату.
Переписать свидетельство значит подделать его.

Оставлено 7 вхождений `docs/flang/conc/`:

| где | почему |
|---|---|
| `docs/tasks/1505:115` | запись о том, на что заменили ссылки README ТОГДА |
| `docs/tasks/1505:119`, `:121` | цитата прежней шапки README |
| `docs/tasks/1505:171`, `:175` | формулировка самой находки — предмет этой задачи |
| `docs/tasks/completed/1418:320` | запись прежнего решения «нарочно не тронуто» |
| `docs/tasks/completed/3017:76` | строка вывода прогона: « 87 docs/flang/conc/SPEC.md» в таблице битых ссылок на дату |

Оставлен также весь пласт **267 вхождений пути КОДА** `flang/conc/`. Это следы
переименования `5ce665a12` в историях: заметки базы знаний (50 файлов), закрытые
задачи (29), ввозы JavaScript вида `../conc/scheduler.js` в записях о снятой
реализации. Предмет отдельный и чувствительный к истории — рядом стоит заметка
`docs/zettel/a-relative-path-outlives-a-directory-move.md`, которая ровно про эту
ловушку. Моя ячейка — зеркало документации, и трогать чужой пласт я не стал.

## Своя ошибка

Довод по адресу я сперва записал в `docs/site/sitemap.mjs` блочным комментарием
на 13 строк — по укладу этого файла, где у каждой страницы рядом стоит причина.
Не учёл, что строки `.mjs` стережутся: `sh .githooks/pre-push` покраснел двумя
проверками (`proza`, `opis-sverka`) — строк в `*.js,*.mjs` стало 24396 против
приметы 24382. Красное завёл я, не дерево: тот же счёт на `gh/main` даёт 24382.

Починить можно было двумя ходами. Первый — перепечатать приметы прибором, которым
сторож и велит (`./ярлык опись:языки`), и поправить `docs/tree-inventory.md:89` и
`docs/javascript-inventory.md:74`. Отвергнут: это чужие файлы вне ячейки, а их
приметы датированы (`от 2026-09-17`), и передатировать чужой замер ради своих
тринадцати строк комментария — плохая плата. К тому же дерево JavaScript выносит,
а не наращивает.

Взят второй: довод свёрнут в хвостовой комментарий на той же строке — добавленных
строк ноль, счёт вернулся к 24382, чужие приметы не тронуты. Полная редакция
довода — здесь, в задаче, где объяснениям и место.
