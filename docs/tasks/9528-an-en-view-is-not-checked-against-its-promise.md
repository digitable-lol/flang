# 9528. Обещание с меткой «en:» не сверяется с обещанием, которое оно переводит, и спецификация об этом молчит

В проектах на flang есть приём: рядом с обещанием ставят второе, с именем,
начатым меткой языка `en:`, чтобы английский читатель видел то же обещание
своими словами. Для компилятора метка — часть имени, и оба обещания независимы.

Приём не выдуман: закрытый список девяти меток (`ar de en es fr hi ja pt zh`)
живёт в `fspec/guard.flang`, функция «Метки языков». В дереве им пользуется один
файл — `fspec/spec/01-discount-cap.flang`, где у обещания стоят оба вида, `zh:`
и `en:`.

## Шаги воспроизведения

1. Файл-проба en.flang:

   ```
   тотальная функция «Смещение»
     принимает «х»: число
     возвращает число
     обеспечивает «смещение не отрицательно» результат не меньше 0
     обеспечивает «en: offset is not negative» результат не меньше -5
     если «х» меньше 0
       то 0
       иначе «х»
   ```

2. `bootstrap/flang check en.flang`
3. `grep -c 'en:' docs/flang/SPEC.md`
4. `grep -c 'en:' docs/flang/proof/SPEC.md`

## Что происходит

```
$ bootstrap/flang check en.flang
en.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет     код 0
$ grep -c 'en:' docs/flang/SPEC.md
0                                                                                    код 1
$ grep -c 'en:' docs/flang/proof/SPEC.md
0                                                                                    код 1
```

Перевод слабее основного обещания (граница -5 вместо 0), и компилятор молчит.
Ни в `docs/flang/SPEC.md`, ни в `docs/flang/proof/SPEC.md` метка `en:` не
названа ни разу.

Версия: flang 0.7.23, 3 октября 2026.

## Что должно быть

Одно из двух:

1. компилятор знает метку языка и сверяет цель такого обещания с целью
   обещания, рядом с которым оно стоит; расхождение — диагностика с названным
   кодом;
2. в `docs/flang/SPEC.md` прямо сказано, что метка `en:` — часть имени и связи
   между обещаниями язык не устанавливает; каждый проект проверяет пары сам.

## Обходной путь

Своя проверка пар в проекте — и она уже написана, не придумывать заново:
`fspec/guard.flang` (ярлык `specs:check`) сличает цели соседних обещаний
текстом и даёт три беды — «два вида одного обещания обещают РАЗНОЕ», «вид
стоит без основного вида», «имя функции несёт метку языка»; подделка на каждую
стоит в `fspec/forgery.flang`. Проверка смотрит только корпус `fspec/spec/**`;
на остальное дерево — и на `flang/stdlib/**` — она не распространяется.

## Когда задача сделана

По первому пути: `bootstrap/flang check en.flang` отвечает кодом 1 и называет
расхождение; та же проба с равными границами — код 0 (сейчас обе дают 0, и
проба с равными границами одна ничего не различает — нужны обе).

По второму пути: `grep -c 'en:' docs/flang/SPEC.md` больше нуля (сейчас 0), и
абзац говорит, что метка — часть имени, связи язык не устанавливает, а пары
проверяет сам проект; абзац называет `fspec/guard.flang` как пример такой
проверки.

## Где живёт правка

Первый путь: проверка обещаний в самосборной части (`flang/self/**`), точное
место не определено; нужна перепечатка (8 ч 34 мин одного ядра по
`docs/reprint-ledger.tsv`) — поэтому второй путь дешевле на три порядка.
Второй путь: `docs/flang/SPEC.md`, раздел «Постусловия функции» (строка 1237),
перепечатка не нужна.
