# 9616. Все 159 мест «доказано без теоремы» — одна причина, и она не там, где казалось

Замер Ч330, главное перепроверено старшим по исходникам.

## Число и его раскладка

Прибор `flang/proof/доля-корпуса.sh --набор корпус`, код 0. Мест «на слово
ядра» 308: П1 «доказано, а теоремы нет» — **159**, П2 — 52, П3 — 97.

**Все 159 — одного вида: `postcondition`.** Другого вида в корпусе нет вовсе:
`zapis.flang:1169` пропускает в запись только `kind=="postcondition"`, а второй
вид обязательства ядра — «мера функции» (`obligations.flang:282`) — в запись не
попадает ни разу.

Кросс-таблица корпуса: 81 «теорема + доказано», **159 «теоремы нет + доказано»**,
119 «теоремы нет + нет вердикта».

## Причина ровно одна, и две другие закрыты замером

Причин могло быть три: (а) ядро теоремы не строит; (б) строит, а запись не
печатает; (в) печатает, но не в том виде. Замер: **(а) = 159, (б) = 0, (в) = 0.**

* `zapis.flang:1446` печатает «теоремы нет» тогда и только тогда, когда поле
  теоремы — ничто. Тот же предикат — развилка маршрута в ядре
  (`proofterm.flang:3166`). Один предикат на две ветки, значит (б) закрыта по
  построению.
* У поля теоремы один источник: `obligations.flang:499` ← «Привязать теорему» ←
  «Свести теорему», а вход туда — блок `теорема «имя»`, **написанный автором в
  исходнике**.
* Счёт в обе стороны: у всех 159 строки `теорема «имя»` в исходнике — **0 из
  159**; у всех 278 «теоремы нет» спрятанных теорем — 0 из 278; обратно, из 81
  напечатанной теоремы стоит в исходнике **81 из 81**; блоков `теорема «` во всех
  86 исходниках ровно **81**. Один в один, утечки нет.

**Опыт, закрывающий (б) намертво.** В `corpus-natural.запись` вписана теорема
ровно в том виде, какой печатает `zapis.flang`: было `код 3`, стало **`код 1`
НЕ СОШЛОСЬ** — «строка 40 исходника — не „теорема …“». Напечатать теорему просто
так нельзя: её ветка сверяет написанное с исходником построчно, и запись
становится ХУЖЕ, а не лучше.

## Что ядро всё-таки делает — и что из этого выбрасывается

Маршрут «Закрыть без теорем» (`proofterm.flang:3232`) даёт не теорему, а узел
вердикта. Подмаршрута два:

| подмаршрут | мест | что доезжает до записи |
|---|---:|---|
| «По объявленному типу» (`:2703`) | **146** | **ни байта** |
| «Разбором по случаям» (`:3113`) | 13 | есть `induction`, принцип и посылки стоят |

Печать читает из узла только `induction` и `steps` (`zapis.flang:1352–1446`).
А «Вердикт по объявлению» несёт `by="declaration"`, `rule`, `byType`, `says`,
иногда `calls` — и, что важнее всего, **делает изъятие**: тот же вызов
прогоняется ЗАНОВО без объявлений, чтобы честно ответить, понадобился ли
объявленный тип. Комментарий там стоит прямо:

    // ПОНАДОБИЛСЯ ЛИ ОБЪЯВЛЕННЫЙ ТИП — вопрос отдельный, и ответ на него
    // ведомость обязана давать правдой, а не по месту в коде. Проверяется
    // ИЗЪЯТИЕМ, а не догадкой: тот же вызов без объявлений.

**Самое дорогое, что ядро вычисляет, в запись не попадает.** Оно платит за второе
сведение — и выбрасывает результат.

### Почему имя правила не годится в довод

Соблазн велик и его стоит назвать вслух. Замер прогоном ядра по пяти файлам
корпуса, задетым породой: **72 узла `by=declaration`, все со `steps=0`**,
и правила у них такие:

| мест | правило |
|---:|---|
| 23 | тождество после переписки допущением |
| 11 | неотрицательность по построению |
| 9 | порядок по построению |
| 7 | разбор цели по условию |
| 7 | ограниченность точным потолком по построению |
| 5 | вхождение по построению |
| 4 | порядок соседних по построению |
| 3 | разбор случаев по внутреннему условию цели |
| по 1 | цель есть допущение; строгий порядок; несовместимые допущения |

`byType`: **да у 10 из 72**, нет у 62 — сходится с прежним замером Ч330
(объявленный тип понадобился в 15 местах из 146).

У самой крупной кучи — 23 места с «тождеством после переписки допущением» —
у чекера **уже есть этот приём**: `перепиской`. Он их не берёт: он пробовал
и не сошёлся (счётчики `тождеств_мимо` и `тождеств_не_сошлось`). Зачесть
их по имени правила значит поверить ядру на слово, дословно тот «рецепт
накрутки», о котором предупреждает КРИТЕРИЙ.md: пять дописанных строк без
единого нового довода переводят утверждение из НЕ ПРОВЕРЕНО в ПРОВЕРЕНО.

### Как выглядел бы настоящий довод — и почему он не здесь

«Цель следует из ОБЪЯВЛЕННЫХ ТИПОВ»: чекер сам читает из исходника типы
доводов, верхнее действие тела и закон об этом действии. Пример разобран:
`Сумма пары` — `принимает первое: нат, второе: нат`, тело `первое плюс
второе`, цель `результат не меньше 0`. Возвращаемый тип (`число`) цели НЕ
даёт — довод сидит в типах **доводов**, а не результата.

Такой проигрыш здесь не написан: машинерии чтения типов доводов в чекере нет
вовсе (это же нашла задача 9951 у `order`), а список законов — предмет задач
5397 и 9951. Это отдельная работа, и она же остаётся настоящим путём к
37,92 %.

### Что прочитано на самом деле — три проверки, все против подделки

Новая `сверить_объявление` зовётся один раз на утверждение (печать вставляет
строки последними и при теореме тоже — `с объявлением` строится поверх
`с теоремой`, `zapis.flang:1441`):

1. **имя правила закрыто списком `PRAVILA`.** Прежде правило сверялось только
   у ПОСЫЛКИ (`сверить_правила`), а на уровне утверждения — нигде: выдуманное
   имя прошло бы молча;
2. **строки идут парой** — печать иначе не умеет;
3. **строение: у маршрута по объявлению не бывает ни посылок, ни принципа.**
   Замер: `cases` пусты **72 из 72**, `steps=0` у 72 из 72, поля `induction`
   нет ни у одного.

### Словарь чекера — вот где на самом деле стоит стена (замер 13 сентября)

Блок `вывод` — единственная форма, которую чекер переигрывает по существу
(`проиграть_вывод`, `шаг_вывода`). Шаг ссылается на правило ведомости, и список
реализованных правил ЗАКРЫТ. Снят прямо из `сверщик.c`, ветки `strcmp(имя, …)`:

    ГипД ГипО И1 И2 Или1 Или2 Кон1 Кон3 Разв2 Св1 Т1 Цел1 Цел2   — 13 правил

`ЗАПРЕТЫ_ВЫВОДА` содержит только имена со «✗» (Н✗, Ч✗, О✗…) — то есть строки
ведомости вида «запрет». Семьи Ч и Тожд там НЕТ: они не запрещены, они просто
не реализованы.

**Как двенадцать мест ложатся на этот словарь:**

| правило места | мест | есть в шаге вывода? |
|---|---:|---|
| Тожд1 «тождество после переписки допущением» | 7 | **нет** |

суммы», `order` П3 «не убывает») и одно из шести мест на слове ядра
(`poddelka-order-arithmetic` «прибавление общего сохраняет порядок») держались на
одном: прибавка у О6 и О5 — ИМЯ объявленного типа `неотрицательное`, а сверщик
брал её только целым литералом. Ведомость говорит шире — О5: «2) Ш — ЧИСЛО», О6:
«2) Б в отрезке [0,кон]», — и лемма О6 в Lean просит ровно «неотр b» и «конечно
b». Нового правила не нужно: нужны посылки из прежних шагов.

### Что сделано

- **сверщик.c:** основание шага «из N M K» (`ОСН_ИЗ3`) и образец строки к нему;
  О5 и О6 берут прибавку-имя, зажатую посылками: шаг M — «Т не меньше Д», шаг K —
  «Т не больше В», Д и В — целые литералы (`прибавка_числом`); прибавка-литерал
  идёт прежней дорогой «из N». +13 строк кода (7091 → 7104).
- **Lean:** «отрезок-числом» (две такие посылки ⇒ числом, неотр, конечно),
  «О5-по-отрезку», «О6-по-отрезку»; ловушка 16 — О6 без потолка прибавки
  (Е = Г = −∞, Б = +∞: справа не-число).
- **zapis.flang:** «Отрезок прибавки записи» (Н3, Пред1, П3 из типа),
  «Шаги прибавки именем записи» («Е не больше ( Е плюс Б )»: лист дна Е, О2,
  отрезок, О6), «Шаги прибавки под охраной записи» (оговорка и сумма: Кон3, О2,
  отрезок, О6; охрана «Е не больше Г» и общая прибавка: отрезок, О5). Строка
  обязательства входа печатается сама — из шага Пред1. Лживые соседи того же
  файла («без дна», «без потолка», «без конечности») в новые ветки не попадают:
  у них нет листа дна либо потолка, печать идёт прежней дорогой.
- **Записи зонда:** `poddelka-order-arithmetic` (887 с, 13,3 ГиБ) и `order`
  (684 с, 12,5 ГиБ); сверщик — код 0 и 0, на слове ядра 0 и 0. В семье
  `по-объявлению`: `order.запись` новая, `order-arithmetic.запись` честна теперь
  кодом 0 (была 3); шесть порч новых шагов — код 1 и причина подстрокой.

### Что осталось до 100 % — двенадцать мест, и ни одно не берётся без решения

После перепечатки остаток 12 = 5 на слове ядра + 4 шага + 3 «калькулятором».
У каждого места нужна либо новая строка ведомости (новое правило — по
`ХРАПОВИК.txt` это «стоп и доклад», строки «покрытие» оно не ест), либо решение
владельца о корпусе или калькуляторе:

| места | чего не хватает | чьё решение |
|---|---|---|
| `abilities` У3, `poddelka-svyortka-shagom`, `poddelka-strict-order` | мера свёртки, растущей ровно на один, и мера «добавить»: семейства меры в ведомости нет | новая строка ведомости + лемма + строка бюджета ADR |
| `equality` Р1 | развёртка вызванного и проекция поля конструктора; ADR-0022 §3.8: «деструктор не входит» | владелец |
| `types` Т1 | разбор конструктора варианта в самой цели; леммы для суммы автора нет | строка ведомости + лемма |
| `abilities` У23, `poddelka-protivorechie` | противоречие пары допущений (ядро: «несовместимые допущения», правило 8); семейства в ведомости нет, а их список закрыт | ADR |
| `sources` К1 | цель — свёртка-признак «равен да»; либо правило, либо переписать цель квантором | владелец (форма цели корпуса) |
| `corpus-bytes`, `corpus-cforms` — 4 шага | вычислитель «по примеру» не знает нулевого знака и `отфильтровать`; вынос по ADR-0023 не положен | владелец (рост калькулятора) |
