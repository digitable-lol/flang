# 9697. О совпадении имени с соседним модулем узнаёт первый совместный ввоз, а не проверка самого модуля

Заявка: https://github.com/digitable-lol/flang/issues/350

Имя функции, типа или объекта занято во всей собранной программе, а не в своём
файле (`docs/guide/project-layout.ru.md`, раздел 4). Но связывание видит только
файлы, которые втянул ввоз: два модуля с одинаковым именем функции порознь
проходят `flang check` чисто, и отказ `FLANG_DUPLICATE_NAME` получает тот, кто
первым ввезёт оба — иногда человек со стороны. В заявке это библиотека на 107
модулей с десятью парами тёзок, накопленными незаметно.

Часть заявки уже закрыта этой же веткой (ADR-0090): место беды связывания
называет файл (`в файле …/pairs-b.flang: функция «Имя пары» объявлена в двух
модулях: …`), а тёзка-помощник ввезённой функции больше не связывается с чужой
функцией молча. Здесь остаётся раннее предупреждение.

## Шаги воспроизведения

Два файла в одном каталоге:

```flang
модуль «Предпорядок»

тотальная функция «Имя пары»
  принимает меньшее: строка, большее: строка
  возвращает строка
  соединить [меньшее, " ≲ ", большее] по ""
```

```flang
модуль «Произведение»

тотальная функция «Имя пары»
  принимает первое: строка, второе: строка
  возвращает строка
  соединить ["(", первое, ", ", второе, ")"] по ""
```

Проба `flang/proof/probes/import-helper-binding/programs/pairs-b.flang` держит
второй из них рядом с первым.

## Что происходит

```
$ bootstrap/flang check pairs-b.flang
модуль «Произведение»: функций 1, из них с доказанным завершением 1; типов 0
pairs-b.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
                                                                          код 0
```

Версия: flang 0.7.25 (`bootstrap/flang` из дерева), снято 11 октября 2026.

## Что должно быть

`flang check pairs-b.flang` называет совпадение «Имя пары» с `pairs-a.flang` и
строку обоих объявлений, не дожидаясь файла, который ввезёт оба. Смотреть надо
там, где искал бы `использует «М»` без пути: каталог файла, каталоги выше, пока
в них есть `.flang`, библиотека рядом с двоичным. Замечание без отказа либо
отказ только под `--strict` — на усмотрение владельца: модули, которые никто не
ввозит вместе, законны. То же для одноимённых `объект` и `тип`; языковой сервер
показывает то же замечание на строке объявления.

## Обходной путь

Свой скрипт: перечислить объявления всех модулей и найти повторы. Каждый
проект пишет его заново, и в редакторе он ничего не подсвечивает.

## Когда задача сделана

В каталоге с обоими файлами выше `flang check pairs-b.flang` называет тёзку из
`pairs-a.flang` со строками обоих объявлений; строка в `expected.tsv` пробы
`import-helper-binding` для `pairs-b.flang` перемерена.

## Где живёт правка

Список исходников для проверки собирает оболочка двоичного
(`flang/src/emit/c/flang_repl.c`, `check_file`): сегодня она кладёт в него
только входной файл и его ввозы. Соседей по каталогу надо либо класть туда же
с пометкой «не ввезён», либо сверять имена отдельным проходом перед
связыванием (`flang/self/link.flang`). Правка оболочки доезжает пересборкой
семени; правка `link.flang` требует перепечатки.

## Правка

`check_file` в `flang/src/emit/c/flang_repl.c` после проверки читает остальные
файлы `.flang` каталога входа, которых нет среди ввезённых, и сверяет имена
функций и типов входа со строками объявлений `функция «…»`, `тотальная функция
«…»`, `тип «…»`, `объект «…»`, `запись «…»` (и английскими) в начале строки.
На каждое совпадение — строка в поток ошибок, код возврата не меняется:

```
$ flang check pairs-b.flang
замечание: «Имя пары» объявлено здесь, строка 3, и в соседнем модуле pairs-a.flang, строка 3: программа, которая ввезёт оба модуля, получит FLANG_DUPLICATE_NAME
pairs-b.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет   код 0
```

Двоичный собран копией `bootstrap/` с этой оболочкой (16 октября 2026). Сверка
текстом, а не разбором: разбор соседей стоил 11 → 41 с на `flang/stdlib/aes.flang`
(55 соседей), сверка строк — 0 с. Каталоги выше и библиотека рядом с
двоичным не смотрятся. Тот же двоичный на `flang/stdlib/aes.flang` называет три
настоящих тёзки библиотеки: «Ход начала» и «Шаг начала» (`hmac.flang`),
«Прибавить единицу» (`math-classics-lists.flang`).

Строка `pairs-b.flang` таблицы `import-helper-binding` перемерена: ждёт
«замечание: «Имя пары» объявлено здесь» и до печати красна. Проба
`flang/proof/probes/parse-and-import`, строка `namesake-second.flang`.
