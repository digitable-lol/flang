# 9902. Предел прогона поднимается у «check» и не поднимается у «emit»

## Два ключа, которые выглядят одинаково и делают разное

Снято прогонами 23 сентября 2026, двоичный из семени ствола, проба —
`flang/proof/probes/run/programs/without-statements.flang` (четыре строки,
ввозов нет):

```
$ flang emit <проба> --target c --out <кат> --max-steps 1
проверено перед печатью — разбор, типы, завершаемость и ядро доказательств.
код 0                                       ← прогон НЕ оборвался на 1 шаге
$ grep 'define FL_MAX_STEPS' <кат>/flang_runtime.h
#define FL_MAX_STEPS 1                      ← единица уехала в ВЫВОД, клеймом

$ flang check <проба> --предел-шагов 1
FLANG_RECURSION_LIMIT: функция «Открыть строку» исчерпала лимит шагов (1)
  на глубине вызовов 0
… не проверено — замечаний 1                код 1   ← оборван ЭТОТ прогон
```

Справка двоичного говорит то же самое словами: у `emit` — «предел шагов,
ВПЕЧАТЫВАЕМЫЙ в напечатанную программу… Своему прогону печати он не говорит
ничего»; у `check` — «поднять предел шагов ПРОВЕРЯЮЩЕГО на этот прогон».

## Чего нет: ключа на предел прогона у «emit»

```
$ flang emit <проба> … --предел-шагов 1   flang emit: непонятный ключ, код 2
$ flang emit <проба> … --step-limit 1     flang emit: непонятный ключ, код 2
$ flang --предел-шагов 1 emit <проба> …   неизвестная команда,        код 2
```

В исходниках то же: `fl_max_steps_default_set` зовётся ровно из ОДНОГО места
на всё дерево — из разбора доводов `check` (`bootstrap/flang_repl.c`, он же
`flang/src/emit/c/flang_repl.c`). Разбор доводов `emit` кладёт `--max-steps`
в поле пожелания печати (`wish.steps`) и предела текущего прогона не трогает.

## Почему это дыра, а не неудобство

У ГЛУБИНЫ близнец есть: `--предел-глубины N` — ключ самого бинарника, стоит
ПЕРЕД командой и годится при любой, печать включая (`flang --предел-глубины
100000 emit <проба> …` — код 0, тот же заход). У шагов такого нет, и именно
поэтому здесь ошибаются по аналогии.

Следствие: **единственный способ поднять потолок печати — пересобрать двоичный
руками**, то есть выйти из языка. Рецепт записан в шапке `scripts/bootstrap-reprint.sh`
и состоит из четырёх шагов: скопировать `bootstrap/*.c` и `*.h` в пустой
каталог, поправить в копии `#define FL_MAX_STEPS` (в напечатанном заголовке
строка БЕЗУСЛОВНАЯ, и `-D` её не перебьёт), собрать `make`, звать печать с
`FLANG=<путь>`. Три шага из четырёх — редактор и компилятор C.

Цена названа делом: 23 сентября 2026 шапку «упростили» до «одна строка
`MAX_STEPS=`, пересборка не нужна» — правка неверна, печать перезапустили на
прежнем двоичном, она пошла бы под тем же старым потолком и умерла бы на нём.
Сняли через две минуты; двоичный пересобрали руками по тем же четырём шагам.

## Цена починки — прочитана в дереве, а не прикинута

Гипотеза до замера: «правка стоит перепечатки», шесть с лишним часов.
**Замер её не подтвердил.**

* Доводы `emit` разбирает не напечатанный код, а рукописный C —
  `flang/src/emit/c/flang_repl.c`. В семя он попадает КОПИЕЙ («шапка +
  источник», `scripts/seed/seed-runtime-is-source.sh`), а не печатью.
* Значит семя обновляется быстрым пересевом
  (`scripts/seed/seed-refresh.sh`, задача 3388). Оговорка его же шапки:
  пересев законен, «пока замыкание и пределы не тронуты относительно
  отпечатка», — так что правка, едущая вместе с поднятием потолка, печать всё
  равно потребует.
* Эталон на самом языке `flang/self/cli.flang` в замыкание печати НЕ входит:
  имени его модуля «Командная строка flang» в `bootstrap/compiler_flang.c` нет
  ни разу (`grep -c` → 0). Перепечатки правка там не стоит, но ехать обязана
  вместе: за парой следят `flang/scripts/cli-keys-guard.fscript` (ключи и
  команды против эталона) и `scripts/guards/seed-parses-sources-guard.sh`
  («ключ есть в исходниках и нет в семени: семя старее»).
* Самого ключа заводить не надо: `--предел-шагов` и `--step-limit` у эталона
  уже есть и уже ложатся в то же поле, что `--max-steps`. Не хватает поведения
  у команды `emit` и строки в справке.

## Что предлагается сделать

Два пути, и второй лучше первого ровно тем, что убирает саму возможность
ошибиться по аналогии.

1. **Узкий.** Дать `emit` ключ `--предел-шагов` / `--step-limit` с тем же
   поведением, что у `check`: строгий разбор числа (`human_steps`),
   `fl_max_steps_default_set` плюс `repl_ctx.max_steps`. `--max-steps` остаётся
   клеймом на напечатанном.
2. **Симметричный глубине.** Сделать `--предел-шагов` ключом САМОГО бинарника
   перед командой, как `--предел-глубины`, — тогда он годится при любой
   команде, и пара «клеймо / прогон» читается одинаково для шагов и глубины.

Чего делать НЕ надо: сливать `--max-steps` и `--предел-шагов` в один ключ.
Клеймо на будущем семени и бюджет текущего прогона — разные числа: печать
23 сентября шла под потолком 4 трлн и клеймила 4 трлн, но это совпадение, а не
правило.

## Приём

* `flang emit <проба> --target c --out <кат> --предел-шагов 1` обрывается
  `FLANG_RECURSION_LIMIT`, код 1, и ни одного файла не записано;
* `flang emit <проба> … --max-steps 1` по-прежнему печатает и клеймит
  `#define FL_MAX_STEPS 1` — прежнее поведение не тронуто;
* оба ключа рядом: прогон идёт под `--предел-шагов`, в вывод уезжает
  `--max-steps`, и числа разные;
* справка `flang emit --help` называет оба ключа и говорит, какой из них про
  какой прогон;
* рецепт «как поднять предел» в шапке `scripts/bootstrap-reprint.sh` сокращается с
  четырёх шагов до одного вызова, и заход печати под поднятым пределом
  проходит.

### Приём — снято прогонами на собранном двоичном

Проба `flang/proof/probes/run/programs/without-statements.flang`:

| вызов | вышло |
|---|---|
| `emit … --предел-шагов 1000` | «ЗАПАС ШАГОВ НА ИСХОДЕ: „Разбор исходника" съел 2302 шагов из 1000 (230 %)», код 1, файлов 0 |
| `emit … --предел-шагов 1` | то же, «2302 шагов из 1 (230200 %)», код 1, файлов 0 |
| `emit … --max-steps 7` | код 0, файлов 6, `#define FL_MAX_STEPS 7` — прежнее поведение |
| `emit … --предел-шагов 500000000 --max-steps 7` | код 0, файлов 6, клеймо 7 — прогон под одним числом, вывод под другим |
| `check … --предел-шагов 1` | как прежде: обрыв, код 1 |
| `flang --help` | называет ключ рядом с `--depth-limit` |

### Побочная находка: бинарник врал о себе при малом пределе

При `--предел-шагов 1` первый же вызов давал не обрыв, а
«человеческие команды есть только у компилятора flang, а эта программа — не
он». Причина: `repl_is_compiler()` спрашивает «кто я», разбирая пустую строку,
и этот разбор шёл из бюджета, названного человеком. Предела 1 не хватало даже
на него, вызов возвращал отказ, и бинарник делал вывод, что он не компилятор.
Пока предел брался только из сборки, различить это было нельзя.

Починено там же: на время вопроса предел поднимается до вшитого при сборке
(`FL_MAX_STEPS`) и тут же возвращается. Бюджет, названный человеком, тратится
только на работу, которую человек заказал.
