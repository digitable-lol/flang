# 9968. Пакет нельзя поставить по имени и нельзя опубликовать: команд установки и реестра нет

Задача общая для трёх шагов: создать пакет, поставить его, поделиться им.
Части ведутся задачами 3401, 3402 и 3403; устройство описано в
`docs/adr/0021-packages-are-installed-over-the-network-and-locked-locally.md`.
Эта задача закрывается сквозным прогоном.

## Шаги воспроизведения

1. `bootstrap/flang --help | grep -n 'package\|lock\|new'`
2. `bootstrap/flang install x`
3. `bootstrap/flang package new x`

## Что происходит

```
$ bootstrap/flang --help | grep -n 'package\|lock\|new'
12:  flang lock <файл>                  замок: сами зависимости, а не ссылки на них
13:  flang package <файл>               пакет: замок с именем, версией и ведомостью
14:  flang new <имя>                    новый пакет с нуля: модуль, fspec/, манифест
$ bootstrap/flang install x
flang: неизвестная команда «install». «flang --help» — что умеет бинарник.     код 2
$ bootstrap/flang package new x
flang package: непонятный ключ «x»                                              код 2
```

Создание есть (`flang new`). Установки, разрешения версий и публикации нет.
`scripts/registry-example/` держит образец формата реестра и запросов к нему.

Версия: flang 0.7.23, 30 сентября 2026.

## Что должно быть

Мерка из `docs/road-to-1-0.md`, пункт 6: чужой человек ставит пакет одной
командой, и его сборка воспроизводима.

## Обходной путь

Положить исходники зависимости рядом со своими и ввозить модуль по имени.

## Когда задача сделана

Сквозной прогон одной пробой: пакет Б создан и опубликован в реестр (хватит
файлового), пакет А объявляет зависимость от Б, ставится одной командой, и
повторная установка даёт тот же замок байт в байт. Публичный сервис реестра с
учётными записями издателей в задачу не входит.

## Где живёт правка

`flang/self/cli.flang` (разбор команд `lock`, `package`, `new`) и тот же разбор
в `flang/src/emit/c/flang_repl.c`; формат — `scripts/registry-example/`. Правка в
`flang/self/**` требует перепечатки самосборной части.
