# 9970. Сборка компилятором tcc работает, но её ответы не сверены с cc на корпусе и в CI её нет

Вопрос владельца: достаточно ли TinyCC вместо gcc и clang. Довод тот же, что у
малой проверяющей программы: компилятор, который человек может прочитать
целиком, сужает место для скрытой подмены.

## Шаги воспроизведения

1. `tcc -v`
2. `tcc -std=c99 -o flang-tcc bootstrap/*.c -lm -lpthread`
3. `./flang-tcc --version`
4. `./flang-tcc check flang/stdlib/optional.flang`
5. `grep -rn 'tcc' .github/workflows/`

## Что происходит

```
$ tcc -v
tcc version 0.9.27 (x86_64 Linux)
$ tcc -std=c99 -o flang-tcc bootstrap/*.c -lm -lpthread
                                                                    код 0, 1,28 с
$ ./flang-tcc --version
flang 0.7.23
оболочка 9f361fce: правит строку (стрелки, слова, история, Tab), цвет digitable
$ ./flang-tcc check flang/stdlib/optional.flang
модуль «Optional»: функций 11, из них с доказанным завершением 11; типов 1
flang/stdlib/optional.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
                                                                    код 0, 7,91 с
$ grep -rn 'tcc' .github/workflows/
                                                                    код 1
```

Тот же `check` двоичным из `make -C bootstrap` — 1,36 с и тот же ответ слово в
слово: двоичный от tcc медленнее в 5,8 раза, но отвечает то же. Обе сборки
печатают одну и ту же пару строк на `--version`. Дальше одного файла сверка не
шла. Корпус, по которому её вести, — 115 файлов: `flang/stdlib` 53,
`flang/ct` 13, `flang/proof/examples` 49.

Версия: flang 0.7.23.

## Что должно быть

Ответ на вопрос владельца с прогоном: двоичный от tcc даёт те же ответы и коды
возврата, что двоичный от cc, на всём корпусе, либо расхождения названы
конструкцией C и строкой.

## Обходной путь

Не нужен: основной путь сборки — `cc`.

## Когда задача сделана

1. Архив выпуска (`bootstrap/flang io scripts/release/release-in-c.fscript`)
   собран tcc; код и вывод названы.
2. Двоичный от tcc проходит проверки раздела `test do` из
   `packaging/homebrew/flang.rb`.
3. `check` по всем 115 файлам (`flang/stdlib` 53, `flang/ct` 13,
   `flang/proof/examples` 49) двумя двоичными даёт одинаковые ответы и коды;
   расхождения названы поимённо. Счёт времени: по мерке одного файла двоичный
   от tcc идёт в 5,8 раза дольше, то есть прогон надо брать с запасом.
4. Названо прогоном, чего tcc не умеет из того, что печать использует.
5. Решение: заводить ли tcc вторым путём сборки в `.github/workflows/`, и что
   для этого нужно на раннере.

## Где живёт правка

Сверка — новый `.fscript` в `scripts/targets/` и ярлык в `.flangrc` строкой
`script.<имя>` (ADR-0049); шаг CI — `.github/workflows/binary.yml`.
Перепечатка не нужна.
