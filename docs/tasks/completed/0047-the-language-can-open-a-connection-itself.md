# 0047. Программа сама открывает соединение — без неё службу не написать

**Это главное, чего не хватает до цели «язык, пригодный для любых служб».**

Сегодня программа на flang сеть **не трогает вовсе**. Она разбирает и печатает
запросы HTTP, говорит на языке PostgreSQL, читает файл базы SQLite — но байты ей
приносит и уносит кто-то снаружи. Позвать соединение сама она не может.

Отсюда прямое следствие: **настоящую службу на flang написать нельзя.** Всё
остальное к этому готово — процессы, надзор, горячая замена (проверена на живом
узле 25 августа 2026), разбор протоколов.

## Почему так вышло — это решение, а не забывчивость

Наружу ведёт ровно один путь: словарь поручений. Программа не зовёт чужой код —
она **возвращает поручение как данные**, а исполняет его хозяин. Именно поэтому
про программу есть что доказывать: у неё нет побочных действий.

Словарь закрыт намеренно. Позвать функцию из чужой библиотеки нельзя ни через
`.so`, ни системным вызовом. Разбор способов расширения — в задаче 0018, и её
надо прочесть ПЕРВОЙ: там названы два пути и их цена.

## Что решить

**Не «добавить сокеты», а выбрать форму.** Возможные направления, по возрастанию
цены:

1. **Новые поручения в словарь** — «открыть соединение», «послать октеты»,
   «принять октеты», «закрыть». Дёшево, вписывается в то, что уже есть, ничего в
   языке не ломает. Хозяин по-прежнему делает всю работу.
2. **Соединение как процесс** — у нас уже есть процессы и надзор; соединение
   могло бы быть процессом, который отвечает на письма. Дороже, но ложится на
   слой, который уже написан и работает.
3. **Общий выход наружу** (задача 0018) — самый дорогой и самый спорный.

**Выбрать самое дешёвое, закрывающее настоящие случаи**, и записать решение как
ADR: почему выбрано это и что отвергнуто.

## Чего делать НЕ надо

**Не ломать «нет побочных действий».** Это то единственное, на чём держатся
доказательства. Если программа начнёт звать сеть напрямую, доказывать про неё
станет нечего, и весь язык потеряет смысл.

**Не вводить аксиом.** В ядре их ноль, охраняется подделками.

## Как понять, что сделано

Служба на flang **поднимается сама** и отвечает на запрос по сети — прогоном, с
дословным выводом. Не «модуль готов», а «вот запрос, вот ответ, вот код возврата».

## Чем закрыта

**Выбрано направление 1 — новые поручения в словарь.** Решение записано
в [ADR-0011](../docs/adr/0011-a-service-stands-on-the-order-dictionary.md),
коммит `dcf72108`; общее правило расширения — ADR-0008
(`docs/adr/0008-layer-boundary.md`), задача 0018.

**Но первое, что здесь сделано, — проверена посылка самой задачи. Она неверна.**

Строка «сегодня программа на flang сеть не трогает вовсе» описывает дерево
двухдневной давности. Последний барьер снят `7ebaabc3` от 23 августа
(«планировщик процессов на C ждёт сеть — шесть поручений соединения исполняются,
а не отказывают», задача 0013), а эта задача заведена `905537bd` **25 августа**.
Правило задачника названо в `tasks/README.md` прямым текстом: «Заведённое как
открытое, но уже сделанное — самая дорогая ошибка этого дерева».

**Прогон: служба на flang поднимается сама и отвечает по сети.** Двоичный
`w-predely` 0.6.2, ворота `PAMYAT=45G`, порт 39281.

```
$ flang io examples/web/shortener/plan-network.flang --plan "Обслужить по сети" &
$ printf 'GET /здоровье HTTP/1.1\r\nHost: x\r\n\r\n' | nc 127.0.0.1 39281
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Content-Length: 5

живой
код возврата nc: 0
```

**Счёт словаря:** поручений **20**, откликов **17**. Соединению принадлежат шесть
поручений и один отклик, и оба хозяина на C их исполняют, а не отказывают:
`flang_repl.c:11422…11607`, `flang_conc.c:1999…2287`.

**Прогон: программа САМА открывает соединение.** Это вторая половина заголовка
задачи, и показана она отдельно — против ПОСТОРОННЕГО сервера (`nc`), а не
против службы на flang: так видно, что соединение открывает именно программа.

```
$ printf 'HTTP/1.1 200 OK\r\nContent-Type: text/plain; charset=utf-8\r\nContent-Length: 11\r\n\r\nживой' | nc -l -p 39281 &
$ flang io examples/service/ask-a-service.flang --plan "Спросить о здоровье"
{"plan":"Спросить о здоровье","result":"HTTP/1.1 200 OK\r\nContent-Type: text/plain; charset=utf-8\r\nContent-Length: 11\r\n\r\nживой","orders":3,"log":[
 {"поручение":{"variant":"Открыть соединение","fields":{"адрес":"127.0.0.1","порт":39281}},
  "отклик":{"variant":"Соединение открыто","fields":{"соединение":1}}},
 {"поручение":{"variant":"Ответить в соединение","fields":{"соединение":1,"содержимое":"GET /здоровье HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\n\r\n"}},
  "отклик":{"variant":"Записано","fields":{"сколько":62}}},
 {"поручение":{"variant":"Прочитать из соединения","fields":{"соединение":1}},
  "отклик":{"variant":"Прочитано","fields":{"содержимое":"HTTP/1.1 200 OK\r\n…\r\n\r\nживой"}}}]}
код возврата: 0

# что посторонний сервер получил от программы:
GET /здоровье HTTP/1.1
Host: 127.0.0.1
Connection: close
```

**Журнал поручений здесь и есть доказательство формы.** Программа не звала сеть:
она вернула три поручения как ДАННЫЕ, и каждое видно в журнале вместе с тем, чем
хозяин ответил. Журнал читается, не выполнив ни одного поручения, — потому про
программу и есть что доказывать.

**Что положено этой работой сверх проверки:**
`examples/service/ask-a-service.flang` — программа из прогона выше. Три поручения
из шести, ни одного нового слова языка. Ведомость доказательства:

```
итог:
  функций 9: тотальных 9, обычных 0
  обещание несёт: композиция 9, структура 0, точный шаг 0, постоянный шаг 0, объявленная мера 0
  сторожей в рантайме: 0 мест
  законов на сетке: 0 (значений в сетках 0); на веру: 0
код возврата: 0
```

**Что отвергнуто и почему** (полностью — в ADR-0011):

* **направление 3, общий шлюз «Позвать чужое»** — ломается не доказуемость
  программы, а сторона хозяина: шесть запретов полномочий, сравнимость хозяев,
  замкнутость набора отказов. Вкладке браузера исполнить его нечем вовсе:
  `dlopen` там не существует;
* **направление 2, соединение как процесс** — надзор перезапускает процесс, а
  разорванное TCP-соединение тем же номером не восстанавливается: перезапущенный
  процесс-соединение отдал бы клиенту живой номер мёртвой трубы. И решающее:
  служба из прогона выше — **план, а не процесс**, и она отвечает.

**Аксиом не введено, побочных действий не заведено:** словарь не вырос ни на
одно поручение, хозяева не тронуты ни одной строкой, «на веру» в ведомости —
ничего.

**Проверено по просьбе наставника: `flang/self/io.flang` читается двоичным.**
Беда с параметрическим типом `«Узел хеша» от «З»`, из-за которой общий двоичный
не читает `flang/self/interpret.flang`, этого файла НЕ касается:

```
$ flang check flang/self/io.flang
модуль «Проверка планов»: функций 252, из них с доказанным завершением 219; типов 25; файлов вместе с импортами 5
без доказанного завершения: «Переписать узел» «Переписать поля» «Переписать список» «Значением тега» «Вызовом диспетчера» «Имена в поле при понижении» и ещё 27
flang/self/io.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
код возврата: 0
```

Правки в нём, впрочем, не понадобилось ни одной: выбранная форма ничего не
просит ни у словаря, ни у `flang/self/**`, ни у перепечатки семени. Работа
показана **со стороны хозяина** — готовым `flang io`, без единой строки C.

**Долги, названные прогоном, а не починенные** (оба — в чужом
`examples/web/shortener/`): `Content-Length` считается знаками, а не октетами
(тело `нет такого пути` — 15 знаков против 28 октетов, клиент получает обрезанное
`нет тако`); путь процентами даёт 404 там, где пример в файле обещает 200, то
есть из браузера эта служба не работает. Подробности — в заметке
`docs/zettel/network-a-service-on-flang-already-answers-over-the-socket.md`.
