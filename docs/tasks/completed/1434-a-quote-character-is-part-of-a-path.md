# 1434. Кавычка в имени каталога — след сорвавшегося переноса

## Чем измерено

21 сентября 2026, ветка `a/derevo-revizia` от `gh/main`. Раздел 5 ревизии
[docs/tree-layout-audit.md](../tree-layout-audit.md).

```sh
$ git -c core.quotepath=false ls-files | grep '^"'
"docs/examples/frameworks/react-ts-pure/\"examples/frameworks/react-ts-pure/\\320\\227\\320\\220\\320\\234\\320\\225\\320\\240.md\""
```

Имена на диске, без экранирования git:

```sh
$ ls -la 'docs/examples/frameworks/react-ts-pure/"examples/frameworks/react-ts-pure/'
-rw-rw-r-- 1 a dev 0 \320\227\320\220\320\234\320\225\320\240.md"
```

То есть:

* внутри `docs/examples/frameworks/react-ts-pure/` лежит каталог с именем `"examples`
  — кавычка входит в имя;
* в нём повторён весь путь второй раз: `frameworks/react-ts-pure/`;
* в глубине — файл, чьё имя **буквально** `\320\227\320\220\320\234\320\225\320\240.md"`:
  обратные косые и цифры — настоящие знаки имени, а не экранирование. Это октальная
  запись слова `ЗАМЕР` в UTF-8 плюс залетевшая кавычка.

| | |
|---|---:|
| лишних каталогов | **3** |
| файлов | **1**, размером **0 байт** |
| кириллицы в имени | **нет** — только её октальная запись текстом |
| путей в дереве, которые `git ls-files` печатает в кавычках | **1** (этот) |

## Как это вышло

```sh
$ git log --oneline --diff-filter=A -- 'docs/examples/frameworks/react-ts-pure/"examples*'
bfb4f0278 Пример react-ts-pure перенесён из ветки на новый путь
```

Перенос взял **вывод `git ls-files` как есть** — уже закавыченный и с октально
экранированной кириллицей — и подставил его в команду как путь. Оболочка честно завела
каталог `"examples` и файл с обратными косыми в имени. Содержимого файл не получил
вовсе: он пуст.

## Чем это мешает

* Кавычка в имени — не переносимый знак: на Windows такой путь не выгружается, и клон
  дерева там обрывается на этом файле.
* `git ls-files` печатает путь в кавычках даже с `core.quotepath=false`, поэтому всякий
  построчный разбор его вывода на этом пути сбивается — в ревизии дерева его пришлось
  считать отдельно от остальных 3679.
* Ни один сторож имён его не судит и судить не может: кириллицы в имени нет (только её
  октальная запись), а сторож транслита в `docs/examples/` не смотрит вовсе.

## Что сделать

1. Снять файл и три пустых каталога:

   ```sh
   git rm -r 'docs/examples/frameworks/react-ts-pure/"examples'
   ```

2. Проверить, что содержимое нигде не потеряно: файл пуст (0 байт), то есть терять
   нечего; если замер примера `react-ts-pure` нужен — он заводится заново рядом с самим
   примером, обычным именем по правилу дерева.
3. Убедиться, что ссылок на этот путь нет.

## Чего НЕ делать

* Не трогать сам пример `react-ts-pure` — его состав (`src/`, `core/`, `printed/`,
  `README.md`, `package.json`, `vite.config.ts`) к этой беде отношения не имеет.
  `package.json` здесь законен: `no-package-json-guard.sh` прямо называет
  `docs/examples/frameworks/*/package.json` как чужие проекты-примеры.
* Не «чинить» имя переименованием в `ЗАМЕР.md`: файл пуст, а кириллическое имя в
  `docs/` — отдельное правило (задачи 1419 и 1430) и отдельная ведомость.
* Не переименовывать заодно другие имена в `docs/examples/`.
