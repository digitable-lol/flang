# 3123. Квантор по элементам есть в цели и отсутствует в предусловии

Решение: [ADR-0037](../../adr/0037-second-order-is-a-finite-conjunction-over-function-tags.md) §4.2.

## Чем измерено

Прогон 13 сентября 2026, двоичный `bootstrap/flang` 0.7.19 из дерева `main`
`87fbd112`, `flang check <проба> --proof`:

| строка | исход |
|---|---|
| `требует «каждая неотрицательна на единице» для всех ф из функции: (ф от 1) не меньше 0` | `FLANG_PARSE … «для всех» связывает элементы списка только для цели целиком` |
| `обеспечивает «каждое применение неотрицательно» для всех р из результат: р не меньше 0` | разобрано, ведомость «сетка 1» |
| `требует «ф неотрицательна на единице» (ф от 1) не меньше 0` о параметре-функции | разобрано; постусловие `результат не меньше 0` при теле `ф от 1` **доказано** правилом «цель есть допущение» |

Третья строка — главная: предусловие о функции-параметре ядро уже читает
допущением. Не хватает только формы «о каждой функции списка».

## Где дыра

- `flang/self/parser.flang`: «Строка предусловия» (строка 4201) зовёт
  «Разобрать выражение»; «Строка постусловия» (4175) зовёт «Разобрать цель» с
  областью `["результат"]`. Отказ печатает строка 3746 — слово `forall` в
  выражении.
- `flang/self/types.flang`: «Под предусловиями» (около 7220) сужает имена
  условием `требует`, как условием `если`. Квантору сужать нечего, но и падать
  на нём нельзя. Тип цели-квантора у постусловия уже считается — тем же местом
  типизировать и предусловие.
- `flang/self/interpret.flang`: узел `forallIn` (строка 2357) вычисляется
  свёрткой с началом `да` — проверка входа на границе его уже умеет.
- `flang/self/proof-kernel.flang`: «Все элементы по построению» первым делом
  спрашивает «Есть допущением» и «с переименованием» — узел `требует` приезжает в
  факты как есть, значит Т1/Т2 закроют цель, совпадающую с предусловием.
- Печать: ни один из десяти печатников `flang/self/emit-*.flang` слова
  `forallIn` не содержит; `flang emit --target c` на программе с квантором в
  `обеспечивает` отвечает «печать отказала — неизвестный вид выражения
  «forallIn»». Это не новая дыра, а та же, что у постусловия; она названа
  задачей 7098 и в эту работу не входит.

## Что сделать

1. «Строка предусловия» — через «Разобрать цель» с областью параметров, без
   «результат» (слово `результат` в `требует` остаётся отказом, как сегодня).
   Английская запись `for all e from L: P` — той же дорогой, новых слов нет.
2. Типизатор: цель `требует` типизируется как цель постусловия — имя элемента
   типом элемента, список обязан быть списком, тело — признак; «Под
   предусловиями» узел-квантор пропускает, не сужая.
3. Ядро: проба-тождество — `требует «все положительны» для всех х из хс: х больше 0`,
   `обеспечивает «на выходе все положительны» для всех у из результат: у больше 0`,
   тело `хс` — обязана закрыться Т2 (переименование связанной). Вложенный
   квантор (ADR-0026 §11 п.15) — тем же путём, без отдельного случая.
4. Сверщик (`flang/proof/чекер/сверщик.c`, чтение `требует` из исходника около
   строки 1011): строка-квантор читается допущением и сличается с формулой Т1/Т2
   через тот же `все_элементы_вывода`. Не больше 15 строк кода — они входят в
   бюджет ADR-0037 §4.5.
5. Место вызова: `«Ф» от (приписать 1 к пустой список)` снимается Э3 и счётом
   уже сегодня — проверить и положить пробой; выписанный `[1, 2]` — задача 4058.
6. Пробы — в семью `все-элементы`: честная пара с записью, снятой толкованием
   (зонд `flang/self/bootstrap/zond-k7.flang`), и подделки: квантор в `требует` о
   ДРУГОМ списке; Т1, указывающий на строку `требует` без квантора.
7. Слово: `docs/flang/SPEC.md` (раздел о `требует`), `docs/flang/proof/SPEC.md`,
   ADR-0026 §11 п.5 — отметка, что наследник заведён и чем закрыт.

## Чего не делать

- Не печатать `forallIn` в десять целей — задача 7098.
- Не трогать строку `для всех л обеспечивает …` перед словом: там имя переменной
  индукции (ADR-0026 §11 п.1–2), а не квантор по элементам.
- Не заводить новых слов и не расширять грамматику сверх формы п.14.
- Не трогать `bootstrap/**`.
