# 6427. Хозяин на C зовёт вердикт запуска

## Чем измерено

18 сентября 2026, ветка `a/partiya-2-semeni`, семя партии №2 (коммит печати `e3aa974c5`,
исходники `dc1412949`), двоичный `bootstrap/flang` собран `make -C bootstrap` из этого семени.

`sh flang/proof/probes/run/run.sh` (двоичным, без зонда): **проб 13, разошлось 13**,
записи `/srv/tmp/proby-zapuska.GCBjTG`. Разошлось не потому, что решение не доехало, а
потому, что доехала ровно та половина, которую печатает семя:

| проба | ждём | двоичный партии №2 даёт |
|---|---|---|
| `сетка`, `на-веру`, `ложь` — `run` без ключа | код 3, «не доказано» | **код 1**, `FLANG_UNPROVED: не доказано: утверждений 1: доказано 0, сетка 0, на веру 1 — запуск только по явному согласию: --на-веру` |
| `тождество`, `типом`, `индукция`, `без-утверждений` — `run` | код 0, «доказано: утверждений N» | код 0, печатает значение, строки вердикта нет |
| `сетка`, `на-веру`, `ложь` — `run --на-веру` | код 0 и запуск | код 2, `flang run: непонятный ключ «--на-веру»` |
| `план-доказан` — `io` | код 0, «доказано: утверждений 1» | код 0, `{"plan":…}`, строки вердикта нет |
| `план-на-веру` — `io` без ключа | код 3, «не доказано» | код 1, `FLANG_UNPROVED` |
| `план-на-веру` — `io --на-веру` | код 0 и запуск | код 2, «непонятный ключ» |

Отказ работает: недоказанная программа двоичным НЕ считается. Это заслуга пункта 6
ADR-0045 — старые точки входа «Прогон исходников» и «План исходников» сохранили подпись и
зовут новые без довода согласия, поэтому перепечатка без правки хозяина запретила запуск,
а не разрешила его. Ровно этого и добивались: недоделанная правка ошибается в сторону
отказа.

Остались три вещи, и все три названы в ADR-0045 §9 пунктом 1 заранее:

1. `run_file` (`flang/src/emit/c/flang_repl.c:9667`) зовёт «Прогон исходников» и любой
   неуспех печатает кодом 1 — значит отказ вердикта приходит кодом 1, а не 3.
2. Строка вердикта («доказано: утверждений N») хозяину не видна вовсе: «Прогон исходников»
   отдаёт только поле «прогон», а «строка» и «код» остаются в «Итоге запуска».
3. Разбор доводов в C (`run_file`, `io_file`) не знает ключа `--на-веру` и его латинского
   двойника `--trust`.

## Что делаем

Хозяин зовёт новые точки входа и отдаёт человеку то, что они посчитали:

* `run_file` — «Запуск исходников» от семи доводов (седьмой — признак согласия), `io_file`
  — «Поиск плана исходников» от четырёх;
* поле «строка» печатается в поток ошибок ДО вычисления, если оно не пусто;
* не «запущено» — возврат равен полю «код» (это 3), а не единице;
* ключи `--на-веру` и `--trust` разбираются у `run` и `io`; у остальных команд они
  остаются непонятным ключом с кодом 2, как велит ADR-0045 §3 пункт 4.

Слово проб для строк с ключом меняется с «запущено да» на «доказанность не считалась»:
«запущено да» печатал только зонд (это поле его ответа), а строку «на веру: доказанность
не считалась — запуск по явному согласию (--на-веру)» печатают ОБА пути. Одна таблица
ожиданий на два пути — иначе таблиц стало бы две, и разъехались бы они молча.

## Фальсификатор

Недоказанная программа без ключа даёт код 0 или код 1 — задача не сделана. Доказанная
программа не печатает строки вердикта — не сделана. Ключ не принят — не сделана.

## Как проверить

`sh flang/proof/probes/run/run.sh` — «сошлось всё: проб 13, разошлось 0 (путь:
двоичным)». Тот же прогон `--по-записям` по записям зонда — та же таблица ожиданий
сходится и на пути зонда.

## Чем кончилось

Фальсификатор задачи прогнан 22 сентября 2026 на стволе `d0763e8b6`, двоичный
`bootstrap/flang` 0.7.21 из семени этого дерева:

```
sh flang/proof/пробы-запуска/прогон.sh
  сошлось всё: проб 13, разошлось 0     (18 сентября на семени партии №2: разошлось 13)
```

Ни одна из трёх ветвей фальсификатора не срабатывает:

* недоказанная программа без ключа даёт **код 3** (не 0 и не 1) — `сетка`, `на-веру`,
  `ложь` под `run`, `план-на-веру` под `io`;
* доказанная печатает строку вердикта — «доказано: утверждений 1» у `тождество`, `типом`,
  `индукция`, `план-доказан`;
* ключ принят — `--на-веру` у `run` и у `io` даёт код 0 и строку «доказанность не
  считалась» (прежде было «непонятный ключ», код 2).

То есть три вещи, названные в замере как оставшиеся (код возврата у `run_file`, строка
вердикта хозяину, разбор `--на-веру`/`--trust` в C), в стволе стоят.
