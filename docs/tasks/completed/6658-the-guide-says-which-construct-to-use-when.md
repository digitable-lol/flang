# 6658. Страница «какую конструкцию когда брать», карта конструкций и случаи применения

Заявка: поручение владельца от 27 сентября 2026, без заявки на GitHub.

## Что было не так

Страницы, которая по действию называет конструкцию, на сайте не было.
Справочник конструкций отвечает «как это пишется», а не «что брать». Код писали
лестницами `если … иначе если` по привычке из других языков.

Снято 27 сентября 2026 на `scripts/guards/*.fscript`:

```
$ grep -c '^ *если' scripts/guards/*.fscript      сумма 340
$ grep -c 'иначе если' scripts/guards/*.fscript   сумма 190
$ grep -c '^ *разбор' scripts/guards/*.fscript    сумма 265
$ grep -c '^ *свёртка' scripts/guards/*.fscript   сумма 145
```

Версия: `flang 0.7.22`.

| Что | Где |

Схемы лежат в страницах блоками `mermaid`. Сборщик сайта рисует их сам во
встроенный SVG (`docs/site/diagram.mjs`), поэтому готовых картинок рядом нет и
чужих скриптов страница не грузит.

## Что выяснилось прогоном

1. `разбор (условие)` со случаями `да` и `нет` хуже `если`. Одна и та же функция
   с одним и тем же обещанием: с `если` — «доказано», с разбором по признаку —
   «сетка 2 значения». Файлы `two-outcomes.flang` и `flag-match-unproved.flang`.
2. Рекурсия по `неотрицательное` с дном в `разбор (предел не больше 0)` не
   проходит: `FLANG_NOT_TOTAL`. Спуск читается только из `если`.
3. Слово `правило` занято языком, именем параметра быть не может: `FLANG_PARSE`.
4. Форма `в монаде` и объявления процессов дают у `flang check` код 2, поэтому
   в случаи применения не вошли: условие было «код 0».
5. На лестнице обещание «цена положительна» ложно, на разборе по сумме оно
   доказано индукцией по типу.
