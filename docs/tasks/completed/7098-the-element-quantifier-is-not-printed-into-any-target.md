# 7098. Квантор по элементам живёт в ядре и вычислителе, а печать его не знает

Основание: [ADR-0037](../../adr/0037-second-order-is-a-finite-conjunction-over-function-tags.md) §6;
дыра — от ADR-0026 §11 п.14, где печать не называлась.

## Чем измерено

13 сентября 2026, двоичный `bootstrap/flang` 0.7.19 из дерева `main` `87fbd112`.
Программа с `обеспечивает «каждое применение неотрицательно» для всех р из результат: р не меньше 0`:

```
flang emit <проба> --target c --out <каталог>
flang emit: печать отказала — неизвестный вид выражения «forallIn»
```

В десяти печатниках `flang/self/emit-{c,cpp,csharp,elixir,go,java,js,python,rust,ts}.flang`
слово `forallIn` не встречается ни разу. Вычислитель знает узел
(`flang/self/interpret.flang`, строка 2357, «Вычислить все элементы» — свёртка с
началом `да`).

## Что сделать

1. В каждом печатнике — узел `forallIn` той же свёрткой, что у вычислителя: на
   пустом списке истинно, короткое замыкание на первом «нет» законно, потому
   что тело — признак без эффектов.
2. Пробы печати — по одной на цель, из `flang/proof/checker/tests/families/all-elements/`:
   напечатанное сторожит постусловие на примере из программы и роняет
   `FLANG_PROPERTY` на подделке `[3, 0, 5]` (README семьи).
3. Ключ `--no-postconditions` (задача 9601) печатает без сторожей — квантор в
   `требует` под ним печатается всё равно: предусловие проверяется на границе.

## Чего не делать

Не менять форму узла ради печати и не трогать ядро: дыра — только в десяти
печатниках.

## Как поймём, что сделано

`flang emit` на программах семьи `все-элементы` — код 0 во все десять целей;
напечатанное на честном примере проходит, на подделке роняет свойство;
`flang test` на каждом печатнике зелёный.

ни до правки, ни после.

### Что сделано

* **Девять целей — одной свёрткой.** «Квантор по элементам свёрткой» в
  `flang/self/defunc.flang` делает из узла `forallIn` узел `fold` той же формы, что
  строит вычислитель («Свёртка всех элементов», `interpret.flang`): начало `да`,
  накопитель «накопитель (все элементы)», шаг `если накопитель то тело иначе нет`.
  Пример в функции сверяет узел целиком. Печатники Go, Rust, Java, C#, Elixir, Python
  и JavaScript на `forallIn` зовут свою печать свёртки от этого узла; TypeScript едет
  печатью JavaScript. Функцию вычислителя ввезти в печатники нельзя — модуль
  вычислителя сам ввозит «Печать в C», вышел бы круг, — поэтому форма повторена в
  модуле понижения, который ввозят все десять печатников. Вычислитель, ядро и
  форма узла не тронуты.
* **C и C++ — своим правилом.** Свёртку в C сличитель не переигрывает (правило
  «свёртка» без сличения), а у узлов, собранных понижением, нет места в исходнике,
  так что якорь им не проверить. Поэтому «Печать всех элементов» в
  `flang/self/emit-c.flang` печатает прямой цикл: список через `fl_require_list`
  (метка «свёртка», как у вычислителя), накопитель `bool … = true`, условие цикла
  `накопитель && индекс < длина` — цикл встаёт на первом «нет», элемент по индексу,
  признак тела через `fl_cond`; значение узла — `fl_flag(накопителя)`. C++ печатается
  тем же печатником C.
* **Правило «все-элементы»** — строка в `flang/translation/PRINT-RULES.tsv`, имя в
  `RULES[]` и `replay_all_elements` в `flang/translation/matcher.c`. Переигрывается
  каждая строка правила по значениям детей; якорь — слова «для всех» на месте узла;
  на слово принято одно — что тело читает элемент именно этим именем C (как у
  правила «переменная»).

### Чего здесь нет

* **`--no-postconditions`** снимает постусловия у хозяина до печати (замер выше: код 0 и
  «ПОСТУСЛОВИЯ СНЯТЫ»). Предусловий он не трогает («ЧЕГО КЛЮЧ НЕ СНИМАЕТ» в
  `flang/src/emit/c/flang_repl.c`), и печатаются они той же дорогой, что в пробах выше.
  Прогоном с ключом это не проверено: ключ есть только у двоичного, а печатников ветки
  в двоичном нет до перепечатки.
* **Двоичный `bootstrap/flang`** отвечает прежним отказом до перепечатки семени
  (задача 5190); «код 0 во все десять целей» здесь снят печатниками этой ветки через
  JavaScript, а не двоичным.
