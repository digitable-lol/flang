# 7359. Спуск по строке — через список знаков, а не через тип знака

Решение: [ADR-0040](../adr/0040-a-simplifier-rewrites-by-proved-equalities-and-prints-every-step.md) §2.5;
основание — `docs/flang/proof/SPEC.md`, «Что дальше» п.7.

## Чем измерено

По спецификации ядра: 19 функций `flang/stdlib/strings.flang`, индукции доступна
одна, и та за работу над списком. Причина названа там же: у строки голова — тоже
строка, и правило «поле того же типа» назвало бы местом спуска оба поля.
Переснять на 0.7.19 первым делом: сколько функций `strings.flang` несут
обещания, сколько из них «доказано», сколько упирается в спуск по строке.

## Что сделать

1. Ш0 — переснять числа выше прогоном; выписать формы спуска по строке в корпусе
   (`разложить на символы`, `первый знак`/`остаток`, `начинается с`).
2. Решение по ADR-0040 §2.5: носитель индукции — список знаков: строка читается
   `разложить … на символы`, принцип берётся у списка (Инд по списку уже есть),
   обратный переход — склейкой; строка ведомости и лемма Lean о том, что
   `разложить` и склейка взаимно обратны (в модели тексты — списки знаков,
   `Модель.lean` «Текст»).
3. Ядро: распознать спуск по строке в теле (форма из Ш0) и подать принцип списка;
   печать блока и приём сверщика — по образцу принципа списка.
4. Пробы: `strings.flang` — число «доказано» до/после; подделка: спуск, который не
   укорачивает строку, — отказ.

## Чего не делать

Тип знака не заводить; поверхность языка не менять; `bootstrap/**` не трогать.

## Как поймём, что сделано

Число доказанных обещаний `strings.flang` выросло и названо; «склейка
ассоциативна» доказывается индукцией (вместе с 4722); подделка отвергнута;
Lean принял лемму; ДОКАЗУЕМ.

**Шапка задачи и ADR-0040 §2.5 описывают снятый отказ.** Принцип индукции у строки
есть с 20 августа 2026 (`c14cd749e`): разбор строки на `пусто` / `голова и хвост`,
голова — «строка длиной 1» («Тип знака», `flang/self/proof-initial.flang`), место `X`
— только хвост; К3 и К4 карты целей доказаны им. Единственное «доказано индукцией»
в `strings.flang` — «Первый символ» тем же принципом.

Спуск по строке в библиотеке пишут не разбором, а свёрткой по знакам:
`свёртка (разложить Т на символы) …` — 44 места в `flang/stdlib`, из них 19 —
тело функции целиком (`grep` по `flang/stdlib/*.flang`). Такое тело принципа не
получало вовсе: принцип свёртки брал только список-ПАРАМЕТР («Свёртка по тому
имени»). И обратного хода от знаков к строке у ядра не было: «разложил и склеил без
разделителя — исходное» у «Символы» стояло сеткой.

### Что сделано

* **Тожд3 — склейка разложения** (`flang/self/proof-kernel.flang`, «Сошлись без
  склеек разложения» и соседи в конце файла): правило тождества после всех прежних
  проб снимает с обеих сторон форму `соединить (разложить Т на символы) по ""` → `Т`
  обходом дерева. Печать (`zapis.flang`, «Форма склейки разложения записи»)
  выпускает ход `переписать формой ⟨…⟩ = ⟨Т⟩ законом «Склейка разложения»`, сверщик
  пересобирает правую сторону сам (`форма_законом`, +8 строк кода).
* **Инд4 — свёртка по знакам строки** (`proof-initial.flang`, `proofterm.flang`):
  тело `свёртка (разложить Т на символы) …` при строке-параметре `Т` читается тем же
  принципом свёртки, что тело над списком-параметром; элемент витка объявлен знаком
  («Тип знака»), пройденный кусок — списком знаков, строка в цели — склейкой куска
  («Кусок пройденного»). Разложение другой строки и куски `разделить` принципа не
  получают («Строка под разложением» требует имя, равное переменной индукции).
* Ведомость — строки `Тожд3`, `Инд4`; Lean — «Тожд3», «Инд4», «Инд4-знак»,
  встречные «Тожд3-со-связкой-ложна», «Инд4-чужой-список-ложна», ловушки 60 и 61;
  семья проб `flang/proof/чекер/пробы/семьи/string-by-characters/`.

### Чего здесь нет и почему

* **Узел fold по знакам строки сверщик не переигрывает.** Приём был написан для
  домена «результат не меньше 0» и снят: ядро такой узел в этом домене не печатает
  (неотрицательность свёртки закрывает Н7 без принципа), а «не больше» у сверщика не
  принят и для свёртки по списку. Место «Последний знак» остаётся на слове ядра —
  код 3, как у свёртки по списку в том же домене.
* **«Склейка ассоциативна»** этой задачей не доказывается: закон нужен о функции
  «Склеить», и берёт его переписка по доказанному утверждению — задача 4722 (PR #45,
  другой исполнитель, открыт).
* Цели, связывающие результат с длиной строки через пройденный кусок
  (`результат равен (длина текст)` у счёта знаков), ядро по-прежнему не доказывает:
  для `длина (соединить (добавить э к п) по "")` у него нет равенства — «Мера склейки
  списком» знает только выписанный список.
