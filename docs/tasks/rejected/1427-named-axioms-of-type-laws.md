## Откуда задача

Ветка `r/vliv-typzakony` (7 сентября) несла готовую работу — «вариант А»:
закрытый список `AKSIOMY[]` в сверщике, новый разряд числителя `aksiom_mest`,
проба-подделка `porog5`, обязанная краснеть. В стволе нет ни того, ни другого
(проверено: `AKSIOMY` 0 вхождений, `porog5` 0 файлов).

Взять её код нельзя, и это померено: основа ветки отстаёт на 785 коммитов, а за
это время сверщик переписан на кириллические имена. Её десять участков опираются
на `Sp bedy`, `na_slovo`, `iz_obyavlennogo`, `razborom_celi`, `bez_teoremy` —
ВОСЬМИ из десяти якорей в сегодняшнем файле нет вовсе. Ствол за тот же срок
изменил сверщик на +7851/−3173 в 98 участках против 10 у ветки. Поэтому ветка
влита стратегией «ours», а замысел переизлагается здесь.

## Замысел, дословно из ветки

Закрытие узла «по объявлению» — это НЕ «на слово ядра» и НЕ «снято
калькулятором», а третья, НАЗВАННАЯ порода: узел закрыт проверяемой аксиомой о
типе и потому идёт в ЧИСЛИТЕЛЬ доли отдельным разрядом.

Разделение труда: имя правила из записи («правило «неотрицательность по
построению»») лишь ВЫБИРАЕТ аксиому из закрытого списка; ПРИМЕНЕНИЕ сверщик
перепроверяет сам, читая объявления типов из исходника, привязанного SHA-256.
Имени на веру берётся ровно столько, чтобы выбрать проверку; сама проверка своя.
Список закрыт: правила, которого в списке нет, узел не закрывает.

## Что входит в доверенную базу — и это главное решение

Дно 0 у отрезочных типов `нат` и `неотрицательное`. Это факт типа, читаемый в
каноне: `flang/self/types.flang:405` объявляет отрезок с «низ» равным 0,
`:877` ставит `неотрицательное ≤ целое ≤ число`.

Тип `вес` в аксиому НЕ входит: канон (`:429`) объявляет его своим видом,
допускающим бесконечность, а не отрезком с дном 0.

Растёт доверенная база НЕЗАВИСИМОГО СВЕРЩИКА, не ядра-прувера — субъекты разные.

## Цена по замеру ветки

+101 строка `checker.c`, +26 строк `corpus-share.sh`. Её собственный замер:
375/617 = 60,78 % → 378/617 = 61,26 % (+3 места, знаменатель тот же). Сегодня
корпус другой (651), и число надо снять заново — старое в дело не брать.

## Как понять, что сделано

1. `AKSIOMY[]` в сверщике закрыт, и правило вне списка узел не закрывает.
2. Проба-подделка `porog5` краснит: подложенная аксиома отвергается кодом 1.
3. Доля печатает третий разряд числителя отдельной строкой.
4. Гейт ДОКАЗУЕМ, набор подделок 34 из 34, проб на подлог принято кодом 0 — ноль.
5. Число мест «на слово ядра» снято заново прогоном, а не перенесено из ветки.

## Почему отклонена

решение: a — 27 сентября 2026

Устарела: цель взята другим путём, а сам путь отвергнут решением.

Задача предлагала закрытый список аксиом о типах в независимой проверяющей
программе, чтобы места, закрытые «по объявлению», пошли в числитель покрытия.
[ADR-0022](../../adr/0022-a-type-fact-travels-as-a-derivation.md), раздел 8А,
разбирает ровно этот путь и отвергает его: та же доля достигается выводом факта
о типе без роста доверенной базы, а ложная аксиома — тихая дыра.

Прогон 27 сентября 2026 на `gh/dev` `d88fb4efb`, двоичный 0.7.22:

```
grep -c 'AKSIOMY' flang/proof/checker/checker.c     → 0
git ls-files | grep -c -i porog5                    → 0
bootstrap/flang io scripts/provability.fscript --plan Verdict --timeout 900000   → ДОКАЗУЕМ, код 0: доля 100.00 % (650 из 650),
                               подделок 543, принято кодом 0 — 0
flang io flang/scripts/kernel-forgeries.fscript --plan 'Аксиом ноль' --на-веру
                             → «аксиом ноль, нарушений 0», код 0
```

Покрытие корпуса уже 100 %, мест на слово компилятора в нём 0 — добавлять в
числитель нечего. Места, которые остаются на слово компилятора в программах
пользователя, ведёт задача 2748, и среди её трёх путей аксиом нет.

Если делать всё-таки придётся: нужен новый ADR, отменяющий раздел 8А ADR-0022 и
правило «аксиом ноль» из ADR-0014.
