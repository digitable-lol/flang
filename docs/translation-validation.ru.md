# Проверка перевода в C по эталону

Генератор C `flang/self/emit-c.flang` превращает проверенную программу в текст на C. Проверка
перевода (translation validation) для каждой функции отвечает на вопрос: вычисляет ли
напечатанный C то же, что исходник в эталонной семантике
([reference-semantics.ru.md](reference-semantics.ru.md)). Генератор она не доказывает — она
проверяет каждую напечатанную программу. Решение —
[ADR-0163](adr/0163-the-printed-c-is-validated-function-by-function-against-the-reference.md).

```
bootstrap/flang run-script translation:validate
bootstrap/flang run-script translation:validate -- --all
```

Первая команда берёт `flang/proof/examples` и `docs/examples/pythagoras`; с `--all` — ещё и
каждый файл `docs/examples`.

## Как идёт прогон

План `flang/translation/validation.fscript` берёт каждый файл корпуса и для каждого:

1. читает дерево `flang ast` и печатает C `flang emit --target c`;
2. собирает напечатанный модуль с прогонщиком `flang_cli.c` и рантаймом и снимает вердикты ядра
   `flang check --proof --json`;
3. просит у `flang/proof/lean/Semantics/Validate.lean plan` свидетелей каждой функции и ответ
   эталона на каждом;
4. шлёт те же вызовы прогонщику C строками JSON и читает его ответы обратно через
   `Validate.lean canon`, чтобы обе стороны печатала одна и та же печать;
5. сравнивает два ответа строка в строку;
6. сравнивает функцию символьно (ниже).

У каждого шага есть предел времени; файл, который в него не уложился, называется вместе с шагом.

Ответ — значение или отказ с кодом. Эталон проверяет предусловия вызванной функции до тела и
постусловия после, как и напечатанный C, поэтому отказ `FLANG_PRECONDITION` или `FLANG_PROPERTY`
сравнивается так же, как значение. Числа сравниваются по кратчайшей десятичной записи со знаком
нуля — это одна строка на каждое значение двойной точности. Строка, где у эталона кончилось
топливо или программа на C упёрлась в предел глубины или памяти, не сравнивается и считается
отдельно.

## Какие входы

Свидетели берутся из объявленных типов параметров:

| тип | свидетели |
|---|---|
| признак | оба значения |
| вариант без полей | сам вариант |
| `число` | ноль, минус ноль, малые целые, половины, десятые, наибольшее и наименьшее конечные |
| `нат`, `неотрицательное` | неотрицательные целые до 2⁵³−1 |
| `целое` | целые обоих знаков |
| строка | пустая, латиница, кириллица, строка с пробелом |
| список | пустой и списки из одного–трёх свидетелей типа элемента |
| запись, вариант с полями | сочетания свидетелей полей; рекурсивная сумма разворачивается дважды |
| параметр типа | на его место ставится `число` |

К свидетелям добавляются примеры функции и границы: каждый числовой литерал, с которым сравнение
в теле, в предусловии или в постусловии сравнивает значение, вместе с двумя соседними числами
двойной точности, по очереди на месте каждого числового параметра (только где подходит
объявленному типу). Когда у всех параметров конечный тип (признаки,
варианты без полей, записи и суммы из них) и произведение областей не больше 512, свидетели —
это вся область: совпадение на всех значит совпадение на любом входе. У функции без параметров
область из одной точки.

## Символьное сравнение

Для функции без циклов `Semantics/Symbolic.lean` строит два дерева решений и сравнивает их узел в
узел:

- по дереву исходника — обходом эталонной семантики, где параметры остаются именами: лист —
  терм значения или код отказа, внутренний узел — условие или вызов другой функции модуля;
- по напечатанному C — символьным исполнением малого подмножества операторов C: объявления и
  присваивания `fl_value`, `fl_number`, `fl_flag`, `fl_equal`, `fmod`, арифметика и сравнение
  чисел двойной точности (`a * b + 0.0`, `a / b + 0.0` и `fmod(a, b) + 0.0` — умножение, деление
  и остаток языка, у которых нулевой итог равен `+0`; голые `*`, `/` и `fmod` — операции двойной
  точности, и с операцией языка они не равны), `fl_cond`, `fl_pre`, `fl_post` с их отказом, проверки «это число»,
  проверки варианта и чтение полей, текстовые константы (с проверкой числа байт и знаков), вызовы
  функций модуля и обёртка рекурсии. Дерево C начинается с двери `_call`, поэтому предусловия,
  напечатанные там, тоже сравниваются.

Равные деревья значат: на любом входе функция на C принимает те же решения и вычисляет те же
термы, что эталон, если то же верно о вызываемых ею функциях; рекурсию покрывает индукция по
глубине вызова. Функция доказана символьно, когда её деревья равны и каждая вызываемая ею функция
тоже доказана (символьно или перебором всей области). До постройки дерева C дерево эталона
вычисляется на каждом свидетеле и обязано дать ответ эталона; расхождение — ошибка символьного
обхода, и функция выводится из сравнения.

Постусловие, которое доказало ядро, в C не печатается. Такое постусловие не входит и в дерево
эталона, поэтому доказательство в этой части стоит на ядре, и вердикт считает такие функции.

Сравнение синтаксическое. Оно отвергает код, который отличается формой, но не значением: C,
проверяющий `x > -5e-324` вместо `x >= 0`, отвечает одинаково на каждом числе двойной точности и
всё равно отвергается. Отвергнутая им функция остаётся при своих свидетелях.

## Что говорит вердикт

```
СООТВЕТСТВИЕ ПРОВЕРЕНО для N функций, вне валидации M
  доказано для D: перебором всей области P (из них без параметров Z), символьно S
  из символьных опираются на постусловия, доказанные ядром, Y
  на свидетелях без доказательства W; сличено свидетелей K
  символьно не сошлось X; символьно сошлось, но опирается на недоказанные вызовы V
  причины вне символьной проверки: <причина> — <число>; …
  причины вне валидации: <причина> — <число>; …
не напечатано или не собрано файлов F: …
расхождений D
```

- **перебором всей области** — функция на C совпадает с эталоном на всей своей области.
- **символьно** — деревья решений функции на C и эталона равны.
- **на свидетелях без доказательства** — функция на C совпадает на каждом сличённом свидетеле. Это тест, а не
  доказательство: ошибка на входе, который не стал свидетелем, остаётся незамеченной.
- **вне валидации** — функция не проверена, и причина названа: параметр-функция или каждый
  свидетель упёрся в предел.
- **не напечатано** — генератор отказал файлу; так по замыслу отказывают подделки ядра из
  примеров.

Любое расхождение роняет план и называется обоими ответами.

## Границы в CI

Работа `translation-validation` файла `.github/workflows/ci.yml` идёт на каждый push в `main` и
`dev` и на каждый pull request. Она передаёт плану пол и три потолка:

| ключ | граница |
|---|---|
| `--validated-floor` | функций со СООТВЕТСТВИЕМ ПРОВЕРЕНО — не меньше |
| `--proved-floor` | функций, доказанных перебором всей области или символьно, — не меньше |
| `--outside-ceiling` | функций вне валидации — не больше |
| `--unprinted-ceiling` | файлов, которые не напечатаны или не собраны, — не больше |

Число за границей роняет план строкой «пол … не достигнут» или «потолок … превышен». Второй шаг
той же работы запускает план с полом доказанных на единицу выше и потолком вне валидации на
единицу ниже и требует, чтобы он упал с обеими строками: граница, которую план перестал читать,
не останется зелёной. Поднять пол или опустить потолок — правка чисел в работе вместе с
изменением, которое их сдвинуло.

## Подделки

Тот же план портит напечатанный C честных программ, по одной правке, и требует, чтобы проверка
отвергла каждую: знак операции, литерал ветви, граница предусловия, шаг рекурсии, текстовая
константа, переставленные операнды, скрытая точка (проверка постусловия, которая отказывает на
одном значении, не взятом ни одним свидетелем) и граница внутри суммы (предусловие над `m² + n²`).
Подделка отвергнута, когда разошёлся свидетель или не сошлось символьное сравнение. Подделка, которую не удалось построить (её строки больше
нет в напечатанном C), тоже роняет план.

## Что остаётся на доверии

Символьное сравнение добавляет к доверенному ещё две вещи: смысл, который оно даёт исполняемому
подмножеству C (`Semantics/Symbolic.lean`: `+`, `<`, `*`, `/`, `fmod` над числами C — операции
двойной точности эталона, `x + 0.0` над итогом `*`, `/` или `fmod` — умножение, деление или
остаток языка, помощники рантайма `fl_add` и подобные — операции языка), и ядро — для
постусловий, которые оно доказало, а генератор не напечатал.

Дерево, которое печатает `flang ast`: его читает эталон, и тот же разбор читает генератор, поэтому
ошибка разбора, меняющая смысл программы, здесь не видна. Сама эталонная семантика и Lean, который
её исполняет. Рантайм C `flang/src/emit/c/flang_runtime.c` и прогонщик `flang_cli.c` — они входят
в каждый сличённый ответ C. Компилятор C и libc. Команды оболочки в плане, которые копируют,
правят и передают файлы. Генератору, сличителю протокола и вычислителю `flang/self/interpret.flang`
проверка не доверяет.
