# Что доказуемость даёт разработчику сегодня — и чего не даёт

Снято 11 сентября 2026 на коммите `2c40752d0` (выпуск 0.7.17) двоичным
`bootstrap/flang`, собранным из этого дерева. Все выводы ниже — с прогона, не
пересказ. Английская редакция — [`what-provability-gives-today.md`](what-provability-gives-today.md).

Коротко. Вы пишете у функции, что она требует от входа и что обещает о
результате. `flang check --proof` либо доказывает обещание обо всех входах и
отвечает кодом 0, либо говорит словами, что не доказал, и отвечает кодом 3.
Доказательство компилятора можно выписать в файл и отдать отдельной программе
на C, которая компилятору не верит и переигрывает его ходы. Всё остальное —
границы: что на этом языке обещаний записать нельзя, что доказательством не
покрыто и сколько до этого осталось.

## Как это работает: две функции и три прогона

Первая функция обещает, что итог заказа не меньше стоимости товаров.

```flang
модуль «Заказ»

тотальная функция «Итог заказа»
  принимает товары: неотрицательное, доставка: неотрицательное
  возвращает число
  обеспечивает «итог не меньше стоимости товаров» результат не меньше товары
  пример «сто и десять»
    дано товары равно 100
    дано доставка равно 10
    ожидается 110
  товары плюс доставка
```

```
$ flang check --proof заказ.flang
…
что высказано и чем это несётся:
  постусловие «итог не меньше стоимости товаров» функции «Итог заказа» — доказано по
  объявленным типам аргументов: цель сведена правилом «порядок по построению» —
  утверждение обо ВСЕХ входах, а не о написанных; теоремы при нём нет и не нужно
…
заказ.flang: ПРОВЕРЕНО САМОСТОЯТЕЛЬНО — утверждений 1: доказано 1, условно 0, сетка 0,
объявлено, не доказано 0, отвергнуто 0, нарушено 0; … — код возврата 0
```

Обо всех входах: не о 100 и 10 из примера, а о любых двух неотрицательных
числах. Теорему писать не пришлось — правило ядро применило само.

Вторая функция обещает, что скидка не сделает цену отрицательной, и требует от
вызывающего, чтобы скидка не превышала цену.

```flang
модуль «Скидка»

тотальная функция «Цена со скидкой»
  принимает цена: неотрицательное, скидка: неотрицательное
  возвращает число
  требует «скидка не больше цены» скидка не больше цена
  обеспечивает «скидка не делает цену отрицательной» результат не меньше 0
  цена минус скидка
```

```
$ flang check --proof скидка.flang
…
  постусловие «скидка не делает цену отрицательной» функции «Цена со скидкой» —
  объявлено, не доказано: ни теоремы, ни примеров. Его считает рантайм после каждого
  возврата — на тех входах, которые придут
…
скидка.flang: НЕ ПРОВЕРЕНО — утверждений 1: доказано 0, условно 0, сетка 0,
объявлено, не доказано 1, … — код возврата 3
```

Утверждение верно — при таком предусловии разность и правда не меньше нуля, —
но ядро этого правила не знает: у правила «Неотрицательно» нет случая вычитания
(`flang/self/proof-kernel.flang:2664`, [ADR-0032](adr/0032-one-missing-rule-and-three-other-logics.md) §2).
Важно, что происходит с недоказанным: оно не притворяется выполненным. Код 3,
слова «объявлено, не доказано», и в напечатанной программе это условие
проверяет рантайм на каждом возврате. Если бы у функции был пример, ядро сказало
бы «сетка 1 значение — это НЕ доказательство»: пример посчитан, доказательства
нет.

Третий прогон — независимая проверка. Ядро выписывает запись своего
доказательства, а `flang/proof/чекер/сверщик.c` — программа на C, в которой
нет ни строки компилятора, — читает исходник и запись и переигрывает ходы:

```
$ flang check --proof заказ.flang --записать заказ.запись      # код 0
$ make -C flang/proof/чекер && flang/proof/чекер/сверщик заказ.flang заказ.запись
НЕ ВЗЯЛСЯ (строк причин 1; мест на слово ядра 1): утверждение «итог не меньше
стоимости товаров»: значение «по объявлению да» — сверщик не повторяет изъятие
объявленного типа, место на слове ядра
НЕ ПРОВЕРЕНО — запись не противоречит исходнику, но доказательством это не является
… Привязка к программе: SHA-256 сошёлся.                                  код 3
```

Это честный ответ, и он важнее красивого. На этой функции ядро доказало цель
«по объявлению» — из того, что оба довода объявлены неотрицательными, — а у
сверщика приёма на такой ход пока нет: он не подтверждает и не опровергает, а
называет место, где верит ядру на слово. Таких мест в наборе записей
компилятора осталось 26 из 651 (раздел «Сколько осталось»). Там, где ядро
записало ходы, сверщик их переигрывает: по 88 записям набора он переиграл 625
обязательств, и на 401 нарочной подделке — подменённое тело, чужая строка,
вычитание под видом сложения — ответил отказом (`./ярлык чекер:проверка`).

## Что можно записать, а что нельзя

Слов доказательств девять (`flang/self/lexer.flang:1220`): `требует`,
`обеспечивает`, `для всех`, `утверждаем`, `индукция по`, `по свойству`,
`по примеру`, `по предположению`, `следовательно доказано`.

Выразимо и доказывается сегодня:

- неравенства и равенства над числами: `результат не меньше товары`,
  `результат равен (акк плюс 1)`;
- длины списков и порядок: «приписывание удлиняет ровно на один», «взятие не
  удлиняет»;
- утверждение с условием: `если эл меньше цель то (результат равен …) иначе да`;
- индукция по объявленной сумме, по отрезку `неотрицательное` и по свёртке —
  когда теорема написана словами;
- предусловие `требует`: проверяет вызывающий, в напечатанном коде оно стоит
  ноль байт;
- один квантор — «для всех входов этой функции»: `для всех` связывает ровно
  одно имя, и оно обязано быть параметром ([ADR-0026](adr/0026-quantifiers-over-any-type-are-a-kernel-change.md) §2.1).

Невыразимо — не «пока не доказывается», а записать негде:

- **∃**: «существует список, на котором…» — знак и слово в языке встречаются
  0 раз (ADR-0026 §2.3);
- **утверждение не при функции**: «для всех списков длина сортировки равна
  длине входа» как самостоятельное утверждение — нет (ADR-0026 §2.1);
- **состояние во времени**: «инвариант держится на каждом шаге» —
  `обеспечивает` при `процесс` даёт отказ разбора `FLANG_PARSE`
  ([ADR-0032](adr/0032-one-missing-rule-and-three-other-logics.md) §3.1);
- **эффекты**: «план не пишет в файл, которого не заводил» — доказывающие слои
  о `план` не знают ничего: 0 вхождений в ядре, обязательствах и типах
  (ADR-0032 §3.2);
- **параллелизм**: «два процесса не трогают одно состояние» — понятия
  разделения владения в языке нет (ADR-0032 §3.3);
- **вычитание под предусловием** — выразимо, но не доказывается (второй прогон
  выше); это одно недостающее правило, задача 1403.

## Что доказательством не покрыто

- **Собранный код.** `flang check` доказывает исходник. Что `flang emit
  --target c` напечатал ту же программу, не проверяет никто: печатник не
  доказан. То же у Coq, Lean и Idris; CompCert закрывает только C → машина.
  Решение — [ADR-0030](adr/0030-the-printer-proves-each-run-not-itself.md):
  проверять каждый запуск печатника, а не печатник целиком; задачи 1401, 1402.
- **`flang run`.** Вычислитель внутри двоичного не доказан.
- **Категорная поверхность и процессы.** Моноиды, монады, функторы,
  `процесс`/`надзор` двоичный разбирает и называет непроверенными, код 2.
- **Сетка.** Примеры считаются, а не доказываются; `flang check` их даже не
  прогоняет — это делает `flang test`.
- **Космос, медицина, авиация.** Стандартам нужна прослеживаемость,
  квалификация инструмента, доказанные границы отклика, поведение при отказе
  железа — ничего из этого нет, и процент доказанного это не заменяет
  ([ADR-0031](adr/0031-certification-is-a-process-not-a-property-of-the-language.md)).
  Две строки разобраны отдельно: «завершится за N шагов» есть только анализом
  (`flang/self/bounded.flang`) и в запись доказательства не печатается
  ([ADR-0033](adr/0033-termination-is-not-a-bound-on-steps.md)); отказ
  ввода-вывода приходит данными, но 79 обработчиков из 309 глотают его словом
  `случай любое`, а отказ железа язык не видит вовсе
  ([ADR-0034](adr/0034-hardware-failure-is-described-not-proved.md)).
  На этом языке такой софт сегодня писать нельзя, и мы этого не обещаем.

## Что значит «96 %»

```
sh scripts/доказуемость.sh          → ДОКАЗУЕМ                       (11 сентября 2026, ≈18 с)
sh flang/proof/доля-корпуса.sh --проигрыванием
→ доля-проигрыванием = 625 / 651 = 96.01 %
  на слово ядра: посылок и утверждений 16; шагов 4; снято калькулятором 6
```

96,01 % — доля мест в **собственных записях доказательства компилятора** (88
записей по `flang/proof/map/`, `flang/proof/examples/` и библиотеке), где
независимый сверщик переиграл ход ядра. Не «96 % программ доказаны», не «96 %
утверждений дерева», не утверждение о собранном коде. Слово ДОКАЗУЕМ выводится
из четырёх чисел: в сверщике нет вычисляющего шага; доля выше порога 95 %;
401 подделка отвергнута и 197 честных записей приняты; набор проб не ослаб.
Правила вывода — 88 — проверены и ядром Lean 4, 85 лемм
([`lean-checks-the-inference-rules.md`](lean-checks-the-inference-rules.md)).

## Повторить

```
make -C bootstrap -j8
./bootstrap/flang check --proof заказ.flang                      # код 0
./bootstrap/flang check --proof скидка.flang                     # код 3
./bootstrap/flang check --proof заказ.flang --записать заказ.запись
make -C flang/proof/чекер && flang/proof/чекер/сверщик заказ.flang заказ.запись   # код 3, место названо
sh scripts/доказуемость.sh                                       # ДОКАЗУЕМ
```

Тексты двух функций — выше, целиком; сохраните их как `заказ.flang` и
`скидка.flang`.
