# Замкнутая цель под охраной берётся НЕСТРОГИМ знаком, если она про число, только равенством, если про длину, и не берётся строгим никогда

Страница «Какие обещания ядро берёт» правилась по этому месту дважды за сутки и
оба раза слишком широко. Сперва стояло «знак сравнения не имеет значения»;
26 августа это заменили на «замкнутая цель считается только РАВЕНСТВОМ». Верны
обе половины, но каждая про своё, и различает их не знак, а ЧТО стоит в цели.

```flang
// ЧИСЛО: охрана из тела, ветвь — литерал 1, цель — НЕРАВЕНСТВО
обеспечивает «…» если показатель не больше 0 то (1 не больше результат) иначе да   ДОКАЗАНО

// ДЛИНА ЛИТЕРАЛА: та же охрана, та же ветвь, цель — НЕРАВЕНСТВО над длиной
обеспечивает «…» если не (номер меньше 0 или номер больше 6) то (5 не больше (длина результат)) иначе да   сетка
```

Ядро подставляет значение ветви в цель и считает её. Пока в цели стоит само
значение, годятся `равен` и нестрогое `не больше`. Как только между значением и
сравнением встаёт `длина`, остаётся один `равен`. А строгий знак не берётся
нигде — ни над числом, ни над длиной.

**Границу по строгости видно на ОДНОЙ функции**, где меняется только знак, а
охрана, тело и ветвь стоят те же (`«Степень»`, `numbers.flang`, тело
`если показатель не больше 0 то 1 иначе основание умножить на …`):

```flang
если показатель не больше 0 то (результат равен 1)     иначе да   ДОКАЗАНО
если показатель не больше 0 то (1 не больше результат) иначе да   ДОКАЗАНО
если показатель не больше 0 то (результат больше 0)    иначе да   сетка
```

Третья снята обратно. Порознь то же подтвердилось на другом файле и другой
функции: у `«Десять в степени json»` (`json.flang`) тело начинается той же
охраной и той же ветвью-литералом, и `если (показатель не больше 0) то
(результат больше 0) иначе да` — сетка.

Это уточняет, а не отменяет запись справочника «строгое неравенство против
литерала у функции с замкнутым результатом — пишите смело»: там речь о функции,
у которой ВЕСЬ результат литерал и охраны нет вовсе. Под охраной строгий знак
не берётся.

**Чем подтверждено.** Прогон 26 августа 2026 через ворота, двоичный
`/srv/flang-rabota/w-predely/bootstrap/flang`,
`check flang/stdlib/numbers.flang --proof` без ключа предела; база и итог сняты
порознь: `утверждений 54: доказано 33` → `утверждений 58: доказано 37`, сетка
21 → 21. Четыре обещания, все с охраной, списанной из тела знак в знак:

| функция | обещание | ветвь тела | вердикт |
|---|---|---|---|
| «Степень» | `если показатель не больше 0 то (1 не больше результат) иначе да` | литерал `1` | **доказано** |
| «Факториал» | `если число не больше 1 то (число не больше результат) иначе да` | литерал `1` | **доказано** |
| «Факториал» | `если число не больше 1 то (1 не больше результат) иначе да` | литерал `1` | **доказано** |
| «Цифры» | `если число меньше 10 то ((длина результат) равен 1) иначе да` | `[число]` | **доказано** |

Второе из четырёх стоит особняком и объясняет механику: после подстановки ветви
цель становится `число не больше 1`, то есть САМОЙ ОХРАНОЙ, — ядру довольно
допущения, считать нечего.

Четвёртое — про длину, и оно взялось потому, что знак `равен`. Отрицательная
половина того же наблюдения снята соседом в тот же день на `datetime.flang`
(«Имя дня недели», две пробы про длину неравенством — сетка) и на `tls.flang`
(шесть ярусов `(длина результат) больше 0` — сетка).

**Чем это ограничено.** Про длину ОДНОЭЛЕМЕНТНОГО списка (`[число]`) равенство
берётся; про длину `элемент N в [список]` не берётся и равенством — там мешает
не знак, а способ достать значение.

**Что из этого следует для авторов.** Увидев `не больше` или `меньше` над
результатом, не бросайте обещание как безнадёжное: спишите охрану из тела и
посмотрите, сводится ли ветвь к литералу. Если да — пишите неравенство смело.
Если между результатом и сравнением стоит `длина`, переписывайте на `равен`
конкретному числу.
