# Веер запусков двоичного помещается в ОДНО поручение плана — через `sh -c`

Замерено 23 августа 2026, ветка `b/skripty-5` от ствола `3508e4e9`.

Ввод-вывод flang — машина продолжений: одно поручение, один отклик, строго
последовательно. Поручения «сделать N разом» в закрытом списке из 18 нет. Отсюда
делали вывод, что программа, чья работа — тысячи запусков двоичного, разведённых
по потокам (`flang/scripts/razlichitelnyy-poisk.mjs`: 8 610 запусков,
`real 1m4s / user 12m30s`), после перевода на flang перестанет быть пригодной
для ярлыка: последовательно та же работа идёт не минуту, а 12,5 минут.

**Вывод неверен, и вот замер.** Веер уходит в оболочку ОДНИМ поручением
`«Запустить процесс»` с программой `sh`:

```flang
вариант «Запустить процесс» с программа равным "sh" и аргументы равным
  ["-c", "printf '%s\\0' proba*.flang | xargs -0 -P 16 -n 1 bootstrap/flang check"]
```

План с таким шагом проходит `flang check` («функций 4, из них с доказанным
завершением 4; замечаний нет») и отрабатывает `flang io` кодом 0, отвечая
`"orders": 1` — поручение РОВНО ОДНО, машина продолжений не нарушена.

Числа на 32 пробных файлах, тот же двоичный, та же машина:

| | real | user |
|---|---:|---:|
| `xargs -0 -P 1` (последовательно) | 0,663 с | 0,484 с |
| `xargs -0 -P 16` (веером) | **0,071 с** | 0,480 с |

Ускорение 9,3×, `user` тот же — значит работа та же, разведена по ядрам.
В самом плане `real 0,311 с` при `user 0,598 с`: `user` больше `real`, то есть
параллельность видна и изнутри хозяина.

**Оболочка здесь не обход языка.** Так уже написано в дереве:
`scripts/occupied-names-guard.flang` зовёт `sh -c` с `xargs` внутри (около четырёх
тысяч вопросов пачкой), `scripts/child-timeout.flang` зовёт двоичный тем же
`sh -c`. Тот же приём и в самом `.mjs`: он тоже не имеет потоков, он тоже
разводит работу по процессам.

## Чего замер НЕ говорит

Веер `razlichitelnyy-poisk` — не один `xargs`, а конвейер из двух фаз с
ветвлением на каждой единице: сперва `check --proof --json`, потом по РЕЗУЛЬТАТУ
разбора решается, какие пробы `run --function` гонять. Одним `xargs` это
выражается, только если решение перенести внутрь оболочки — то есть написать
логику на shell/awk. Это не JavaScript, но и не flang, и как размен оно не
лучше. Пригодный путь — **две волны**: первая волна веером считает `check` по
всем делам, план разбирает ответы, вторая волна веером гонит пробы. Ветвление
остаётся в языке, оболочка несёт только «прогнать список команд». Работа не
сделана, но препятствия в языке под неё нет.

Второй предел, не снятый этим замером: ВЫВОД. Хозяин приносит `вывод` строкой
целиком, а 8 610 прогонов `check --proof --json` дают её очень большой. В пробе
хвост резался `tail -c 200`. Веер, чей ответ не влезает, придётся сажать на файл
(`«Записать файл»` + `«Прочитать файл»`) — так и сделано в
`scripts/occupied-names-guard.flang`.
