# Свёртка, забирающая каждое совпадение, оставляет ПОСЛЕДНЕЕ — и это ловушка на разборе по меткам

Поиск «первого подходящего» пишется свёрткой так:

```flang
свёртка пункты начиная с "" как найдено и пункт
  если (найдено равен "") и притом ((пункт.«имя») равен имя)
    то (пункт.«вердикт»)
    иначе найдено
```

Без условия `найдено равен ""` свёртка забирает КАЖДОЕ совпадение и до конца
списка доезжает последнее. На чистых данных разницы нет; на разборе чужого
текста по меткам она решает всё, потому что имя в разбираемом ответе стоит не
один раз.

**Чем подтверждено.** Ветка `u/port5`. `flang/scripts/kernel-forgeries.flang`
(ярлык `poddelki:check`) был красным до меня: «нарушений: 4 … утверждения «выбор
с ложной ветвью» в отчёте нет — подделка разошлась с проверкой», хотя
утверждение в отчёте было. Разбор режет ответ `flang check --proof --json` по
`"kind":"` и разбирает каждый кусок; на
`flang/test/fixtures/poddelka-istinnaya-vetv.flang` таких кусков 23, и «выбор с
ложной ветвью» встречается дважды:

```
[{"имя":"выбор с ложной ветвью","вердикт":"declared"},
 {"имя":"одно из двух","вердикт":"declared"},
 {"имя":"выбор с ложной ветвью","вердикт":""},  …]
```

Второе вхождение приезжает из текста `says` и из дерева выражения, где поля
`verdict` нет вовсе, — «Поле отчёта» отдаёт `""`. Пустой вердикт проверка читала
как «утверждения в отчёте нет». Одна строка условия — и `poddelki:check`
отвечает кодом 0.

**Чему учит.** Разбор чужого ответа по меткам обязан считаться с ПОВТОРАМИ имени.
Пустое поле у повтора — не «нет данных», а «эта копия не та»; свёртка должна
останавливаться на первом непустом, а не собирать до конца.
