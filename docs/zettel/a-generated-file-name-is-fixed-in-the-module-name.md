# Имя порождённого файла чинится в имени модуля, а не в генераторе кода

Генератор кода в C берёт имя файла от имени модуля: `модуль «Компилятор flang»`
→ `kompilyator_flang.c`. Транслит в имени файла запрещён правилом дерева
(`docs/guide/naming.ru.md`), и починить это можно двумя рычагами — переименовать
модуль либо завести в генераторе отображение «модуль → имя файла». **Правильный
рычаг — имя модуля, и довод не «дешевле», а «второй путь чинит своё дерево за
счёт чужого».**

Договор «имя модуля доезжает до цели своим именем» — общий для всех восьми
генераторов и записан в `flang/src/target-occupied.mjs`. Особый случай в нём
чинил бы ровно одну программу — нашу, — а всякий, кто завтра напишет
`модуль «Мой калькулятор»`, по-прежнему получит `moy_kalkulyator.c`. Тот же довод
уже записан в самом `target-occupied.mjs` про столкновение `модуль «JSON»` с
библиотекой Python, только там он читается наоборот: там переименование модуля
отвергнуто, потому что беда приходит к КАЖДОМУ, а здесь принято, потому что
правило про имена файлов — правило НАШЕГО дерева и связывает наши файлы.

**Имя модуля-обёртки — единственное из `flang/self/`, которое куда-то доезжает.**
Имена семи слоёв («Лексер flang», «Проверка типов», …) связывание сливает в одно
плоское пространство, и в напечатанном их нет вовсе. Имя обёртки становится сразу
четырьмя вещами: именем файла (`compiler_flang.c`, `.h`), именем библиотеки
(`libcompiler_flang.a`), стражем заголовка (`COMPILER_FLANG_H`) и приставкой
каждого внешнего символа C (`compiler_flang_call`). Поэтому цена переименования
ограничена одним модулем, а выгода — всеми четырьмя поверхностями сразу.

**Порядок слов выбран замером, а не вкусом.** Естественное английское
«Flang compiler» дало бы `flang_compiler.c` — а приставка `flang_` занята самим
генератором (`flang_runtime.c`, `flang_cli.c`, `flang_repl.c`), и по ней в дереве
отличают файл рантайма от файла программы: 20 мест в проверках вида
`!path.startsWith("flang_")`. У главной программы дерева признак перестал бы
работать. «Compiler flang» держит и правило про транслит, и признак, и порядок
слов остальных семи слоёв.

**Чем подтверждено.** Ветка `work/zelenyy-stvol`, 19 августа 2026.
`node scripts/bootstrap-c.mjs --check` — 7 файлов, 14 447 823 байта;
`FTS_REQUIRE_TOOLCHAINS=c node --test flang/test/self-bootstrap.test.mjs` — 37 из
37 за 22 минуты, неподвижная точка сошлась побайтово у свидетеля, flang₁ и flang₂;
`make -C bootstrap CFLAGS="-std=c99 -Wall -Wextra -Werror -pedantic -O2"` — без
предупреждений. Переименование дешевле, чем кажется по размеру диффа: 124 431
байт из `compiler_flang.c` ушли сами собой, потому что приставка каждого символа
стала на три знака короче (11 545 172 → 11 420 741).

**Чем ограничено.** Про имя, которое доезжает до чужого пространства имён. Имена
ВНУТРИ порождённого кода транслитерируются и остаются транслитом законно — это
названо в `docs/guide/naming.ru.md` отдельным исключением: имя помощника в
JavaScript кириллицы не принимает, и печатающая функция повторяет напечатанное
дословно.

**Чем это стало 29 августа 2026.** Один случай стал правилом: Р7 в
`docs/guide/naming.ru.md` — «имя модуля пишется латинскими буквами», — и сторож
у него свой, `scripts/module-name-guard.flang`. Рычаг тот же, что назван здесь,
и довод тот же; изменилась только область: не один модуль-обёртка, а весь
корпус, который печатается, — `flang/stdlib`, `flang/core`, `examples`.
Приведено 206 модулей из 210, остаток — четыре имени `flang/core` — записан
долгом поимённо, потому что они стоят во входе перепечатки.
