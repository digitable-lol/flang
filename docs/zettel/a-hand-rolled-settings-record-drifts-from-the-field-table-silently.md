# Второй, ручной список полей записи «Настройки» отстал от таблицы EMIT_FIELDS_C и ронял КАЖДЫЙ ввод живой оболочки, а не только «разложить … на символы»

У записи «Настройки», которую печать цели «c» требует от вызывающего, один
хозяин по именам полей — таблица `EMIT_FIELDS_C` (`flang_repl.c`, 17 полей).
`repl_compile` (та же функция, что печатает и собирает КАЖДУЮ строку живой
оболочки в C) строит такую же запись ВТОРОЙ раз, вручную, массивами
`names[]`/`values[]` — и когда цель «c» выучилась печатать процессы
(`flang_conc.h`/`.c`, два новых поля «планировщик заголовок»/«планировщик
исходник»), этот второй список остался на пятнадцати. Компилятор об этом
молчал: типов у литерального `names[15]` нет, несовпадение с таблицей не
проверяется нигде до вызова.

`flang/self/emit-c.flang` читает оба новых поля БЕЗУСЛОВНО, строя «заголовок
движка»/«исходник движка» (строки 5709–5710), и только ПОТОМ решает, класть ли
готовые файлы в ответ — по «конкурентно» (строка 5711: список процессов
пуст → «файлы движка» = пустой список). Значит отказ ловит не программу с
процессом, а ЛЮБУЮ строку живой оболочки: `1 плюс 1` падает так же, как
`разложить "мир" на символы».

**Чем подтверждено.** Ветка `а/repl-sessiya-zhivoy-vvod`, коммит `47bebf1c`,
поверх `dev` `049b0f04` (клон `/srv/tmp/dokazuemyy/Ч390-repl-sessiya/клон`).
Живой ввод собран через настоящий псевдотерминал (`python3` + модуль `pty`,
не труба: труба переключает двоичный на JSON-прогонщик по `isatty(0)` и до
`repl_compile` не доходит вовсе, поэтому класс беды трубой не виден и в CI
таким способом не ловится).

До правки (`bootstrap/flang` из `dev` как есть) — пять разных строк в ОДНОЙ
живой сессии, все одинаково:
```
» 1 плюс 1
FLANG_UNKNOWN_NAME: запись не содержит поле «планировщик заголовок»
FLANG_CLI: печать сессии в C прекращена
```
и так же на `разложить "мир" на символы`, `отобразить [1, 2, 3] как эл → …`,
`свёртка [1, 2, 3] начиная с 0 …`, `отфильтровать [1, 2, 3] где эл → …`.

После правки (`names[17]`/`values[17]`, два новых поля — пустая строка, тем
же способом, каким уже пусты «рантайм заголовок»/«рантайм исходник») — все
пять дают значение: `2`, `["м", "и", "р"]`, `[2, 4, 6]`, `6`, `[2, 3]`.

Проба порчей: `git checkout 049b0f04 -- flang/src/emit/c/flang_repl.c
bootstrap/flang_repl.c`, пересборка — все пять снова красные, слово в слово тот
же текст отказа. `git checkout HEAD --` вернул правку, пересборка — снова
зелёные.

Сверено: `repl_compile` — единственное место в `flang_repl.c`/`flang_cli.c`,
которое зовёт «Напечатать связанное» (`grep -n '"Напечатать связанное"'`
даёт ровно одно вхождение-вызов). Других мин этой формы для цели «c» в
рукописной оболочке нет.

**Чем ограничено.** Правка настоящая — в `flang/src/emit/c/flang_repl.c`.
`bootstrap/flang_repl.c` тоже поправлен, но ТОЛЬКО для локальной сборки и
пробы в этом клоне: это не замена перепечатки семени. Полная копия файла
поверх `bootstrap/` не работает вообще —
[[the-seed-cannot-be-patched-by-hand-it-will-not-link]] уже мерил это отдельно
(`fl_program_call`/`fl_program_entry`, код 2 при связывании). Здесь сработало
только потому, что правка добавляет два элемента массива через
`repl_value_say` — функцию, которая в старом семени уже была, — и не тянет
за собой ни одного нового символа рантайма.

Другие семь целей печати (go, rust, java, js, elixir, python, csharp) — свои
списки `EMIT_FIELDS_*`; `repl_compile` печатает только «c» (жёстко, `--target`
у сессии нет), поэтому тот же класс расхождения для других целей здесь не
проверялся.

Не проверялись и другие ~15 вызовов `repl_value_record(names, values, N)` в
`flang_repl.c` — они строят записи другой формы (HTTP, свидетели и т. д.) и
«Напечатать связанное» не зовут.
