# Словарь хешем стал параметрическим по значению, и параметр ввоз переживает — ломала ввоз ЧУЖАЯ КОПИЯ МОДУЛЯ

`flang/stdlib/hashmap.flang` был словарём строка → строка. Теперь он словарь
строка → «З»: `тип «Звено» от «З»`, `тип «Узел хеша» от «З»`, семнадцать функций
из двадцати четырёх объявлены `от «З»`. Сам файл проверку проходит целиком, и
ведомость доказательств от прежней НЕ ОТЛИЧАЕТСЯ ни одним числом:

```
БЫЛО:  утверждений 41: доказано 16 (индукцией 2) (без теоремы 13), сетка 25,
       объявлено, не доказано 0; сторожей в рантайме: 0 мест
СТАЛО: утверждений 41: доказано 16 (индукцией 2) (без теоремы 13), сетка 25,
       объявлено, не доказано 0; сторожей в рантайме: 0 мест
```

Сдвинулось ровно одно: «Словарь из ключей» несёт завершение СТРУКТУРОЙ, а не
композицией (композиция 18 → 17, структура 6 → 7). Его тело переписано со
свёртки на разбор списка, и об этом ниже.

## Зачем это делалось

Ради `«Найти описание»` в `flang/self/interpret.flang`: линейный перебор списка
описаний съедает 87,7 % витков проверки `flang/self/proof-kernel.flang` — замер
в [[linear-lookup-of-a-declaration-eats-88-percent-of-check-loops]]. Вычислителю
нужен словарь строка → «Описание вычислителя», а прежний `hashmap.flang` умел
только строка → строка.

Из двух путей — параметрический тип или своя копия дерева внутри
`interpret.flang` — взят первый: одно дерево на язык, а не два, и годится он не
только этому месту.

## ЧТО ЛОМАЛО ВВОЗ — ГЛАВНОЕ В ЭТОЙ ЗАПИСКЕ

**24 августа, правка.** Ниже стояло «параметр типа НЕ ПЕРЕЖИВАЕТ ВВОЗА», и это
неправда. Параметр ввоз переживает. Ввозился не этот файл.

Отказ был настоящий и слово в слово такой:

```flang
модуль «Проба»
  использует «Словарь хешем»

тотальная функция «Проба»
  принимает «з»: «Звено» от строки
  возвращает строка
  «Ключ звена» от «з»
```

```
FLANG_TYPE_ARGS, строка 4, столбец 1: тип «Звено» объявлен от нуля параметров,
                                      а применён к 1 аргументу
```

И диагностика не врала: у того «Звена», которое приехало по ввозу, параметров
ДЕЙСТВИТЕЛЬНО ноль. Только приехало оно не отсюда, а из
`/srv/flang-rabota/u-teoremy-hashmap-hm-BAZA.flang` — чужого черновика, который
объявляет тот же `модуль «Словарь хешем»` и является копией `hashmap.flang` ДО
параметризации (`тип «Звено»` без `от «З»`, строка 195).

Доказано strace, а не рассуждением. Проба лежала в корне дерева, ввозила
«Словарь хешем»; открыты за прогон:

```
openat("/srv/flang-rabota/u-teoremy-hashmap-hm-BAZA.flang", O_RDONLY) = 3
openat("/srv/flang-rabota/u-teoremy-hashmap-hm-BAZA.flang", O_RDONLY) = 3
openat("/srv/flang-rabota/w-predely/flang/stdlib/hashmap.flang", O_RDONLY) = 3
```

`flang/stdlib/hashmap.flang` ЭТОГО дерева не открывался ни разу.

**Пара прогонов, которая это решает** — один двоичный, одно дерево, одна проба,
разница только в том, какой каталог отдаёт модуль:

| где лежит проба | откуда взят «Словарь хешем» | ответ |
|---|---|---|
| каталог, куда положены `hashmap.flang` + `numbers.flang` этого дерева | оттуда же | `проверено — замечаний нет`, функций 25, все с доказанным завершением, типов 2 |
| корень дерева (модуль в каталоге не лежит, лежит в `flang/stdlib`) | `/srv/flang-rabota/u-teoremy-hashmap-hm-BAZA.flang` | `FLANG_TYPE_ARGS … объявлен от нуля параметров` |

**Правило поиска модуля по имени** (`repl_places_of`/`repl_find_module`,
`bootstrap/flang_repl.c`) — вот оно целиком, и в нём вся беда:

1. каталог ввозящего файла;
2. ВВЕРХ по предкам, пока в предке есть хоть один `.flang`;
3. и только потом библиотека рядом с двоичным (`flang/stdlib`, `flang/core`,
   `FLANG_MODULE_DIR`).

Побеждает ПЕРВОЕ место, где имя нашлось, и вглубь ни одно место не заходит.
Каждое дерево здесь лежит в `/srv/flang-rabota`, а в нём россыпью чужие
черновики — значит шаг 2 всегда перекрывает шаг 3, то есть чужой черновик
всегда сильнее библиотеки проверяемого дерева. Молча.

Таких черновиков в общей зоне сейчас ДВА, и второй хуже первого:

* `u-teoremy-hashmap-hm-BAZA.flang` — `модуль «Словарь хешем»`, копия до
  параметризации;
* `u-dok-hash-z1.flang` — `модуль «SHA-256»`, 534 строки против 992 в
  `flang/stdlib/sha256.flang`.

Ни один из них не мой, и трогать их не мне — но всякий, кто из своего дерева
ввозит «Словарь хешем» или «SHA-256» и не держит модуль в каталоге пробы,
проверяет не то, что думает.

**ПОЧЕМУ ПРЕЖНЯЯ ЗАПИСКА ОТМЕЛА ЭТУ ПРИЧИНУ И ОШИБЛАСЬ.** Здесь стояло: «чужой
файл отмётен прогоном в чистом каталоге `/srv/tmp`, где лежат только
`hashmap.flang` и `numbers.flang`, — отказ тот же слово в слово». Каталог
`/srv/tmp` не чист: в нём 139 файлов `.flang`, и среди них
`/srv/tmp/orig-hashmap.flang` — ТРЕТЬЯ копия того же `модуль «Словарь хешем»`,
тоже до параметризации (`тип «Звено»`, строка 195, положена 22 августа). Проба в
чистой комнате, где на полке лежит та же подмена. Отсюда правило для следующего:
контрольный каталог — это каталог, ПРОВЕРЕННЫЙ на имена модулей, а не каталог с
подходящим названием; и проверяется он не глазами, а `strace`, потому что имя
взятого файла компилятор до сих пор не печатал.

**ЧТО СДЕЛАНО, ЧТОБЫ ТРЕТЬЕГО РАЗА НЕ БЫЛО.** `repl_find_module` теперь
досматривает ОСТАЛЬНЫЕ места и, если имя модуля объявлено где-то ещё, печатает
в stderr одну строку на модуль:

```
flang: модуль «Словарь хешем» взят из /srv/flang-rabota/u-teoremy-hashmap-hm-BAZA.flang; тот же модуль объявляют также: /srv/flang-rabota/w-predely/flang/stdlib/hashmap.flang
```

На код возврата это не влияет — это не отказ, а имя файла, которого не хватало.
Правка в `flang/src/emit/c/flang_repl.c` — в ХОЗЯЙСКОЙ половине, не в
`flang/self/**`. До общего двоичного она доедет перепечаткой семени; прогоны
выше сняты своей сборкой с тем же самым текстом.

Шесть черт формы объявления, проверенных прежней запиской (имя варианта = имя
типа; непараметрическое поле перед параметрическим; вложение параметрического в
параметрический; самоссылка; свой ввоз у владельца; инстанцирование конкретным
внутри владельца), проверены не зря — они и правда ввозятся. Просто искали не
там: изъяна языка здесь нет вовсе.

## Три утверждения, которые пришлось переписать, и почему это не потеря

У строк был приём «заведомо невозможное запасное»: `соединить значение с "◊"` —
строка на знак длиннее значения, совпасть с ним не может, и потому «нашлось»
отличалось от «не нашлось». У параметра типа такого значения нет: «З» может быть
чем угодно, и приписать к нему знак нечем.

* `«Вложить»` и `«Положить в словарь»`: запасным стало САМО значение, а рядом
  добавлен сомножитель «ключ есть» (`«Искать признак»` / `«Есть ключ в
  словаре»`). Сила та же: раз ключ есть, запасное не берётся вовсе, и равенство
  пиннит именно найденное. Положи функция не то значение — поиск вернёт его, и
  равенство станет ложью.
* `«Есть ключ в словаре»`: прежде — два разных запасных ("◊а" и "◊б"), которые
  одно значение не может дать оба. Стало сказано прямо про звенья: ключ есть
  ровно тогда, когда среди `«Звенья словаря»` есть звено с этим ключом. Это не
  слабее, а честнее: ни запасных, ни оговорки «и всё равно какое».

Ведомость это подтверждает числом: доказано было 16, стало 16.

## «Словарь из ключей»: свёртка → разбор

Начальное значение свёртки типизируется БЕЗ ожидаемого типа, и `вариант «Пустое
место»` сам по себе не говорит, какая «З» у его словаря, — выходит
FLANG_TYPE_PARAM. Тот же угол описан в шапке `optional.flang` (функция «Найти не
меньше»). У ветви `разбор` ожидание есть — оно взято из строки `возвращает`.
Порядок вставки при этом стал обратным, на смысле не сказалось: ключ сам себе
значение.

Ровно этим же способом придётся строить и словарь описаний в `«Подготовить»`.
