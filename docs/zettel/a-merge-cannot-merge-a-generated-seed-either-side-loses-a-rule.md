# Слияние не умеет сливать напечатанное семя: любая сторона теряет правило, и на стволе `4c1b6aef` потерялась индукция по строке

`bootstrap/*.c` — не исходник, а **печать** исходников. Когда две ветки
перепечатали семя каждая по-своему, слияние выбирает одну сторону целиком, и
правило, добытое другой, из компилятора исчезает, оставшись в `flang/self/`.
Ни один сторож этого не видит: исходники на месте, дерево чистое, сборка идёт.

**Что случилось.** Ствол `4c1b6aef` — слияние двух родителей:

| сторона | что дала ядру | md5 `bootstrap/compiler_flang.c` |
|---|---|---|
| `82312ae7` (23:00) | замкнутость цели у прямого шага «по примеру» | `61a76ae9…` |
| `c14cd749` (23:13, через `9e6bf406`) | принцип индукции по строке | `444f5397…` |

У слияния семя `61a76ae9…`, то есть сторона `82312ae7`. Исходники при этом
содержат обе правки: `flang/self/proof-initial.flang` совпадает байт в байт с
версией из `c14cd749`.

**Чем подтверждено.** Двоичный, собранный из семени ствола, на
`flang/test/fixtures/poddelka-indukciya-po-stroke.flang` отвечает

```
FLANG_PROOF_INDUCTION_TYPE … индукция теоремы «знаков ноль» идёт по «текст»,
а у этого типа (строка) принципа индукции нет
```

Двоичный из соседней копии `/srv/flang-rabota/u-stroka-ind` (те же
`proof-initial.flang` и `types.flang`, семя перепечатано на своей ветке) на том
же файле доходит до шага:

```
FLANG_PROOF_INDUCTION_STEP … шаг «голова и хвост» не сведён к допущениям
на части «хвост»
```

То есть правило есть в дереве и нет в компиляторе, который это дерево собирает.

**Почему это класс, а не случай.** Напечатанный файл под версионным контролем
слить нельзя в принципе: правильного результата нет ни на одной стороне, а
трёхсторонний слияльщик об этом не знает и молча берёт одну. Единственное
лечение — **перепечатать после слияния** (`sh scripts/raskrutka.sh`,
`make -C bootstrap`, затем `sh scripts/raskrutka.sh --check` вторым поколением).
Единственный сторож, который это ловит, — `--check`; всё остальное зелено.

**Чем ограничено.** Речь только про `bootstrap/`. Прочие напечатанные файлы
дерева (страницы сайта, `CHANGELOG`) той же болезнью болеют, но правил ядра не
несут, и потеря там видна глазом.
