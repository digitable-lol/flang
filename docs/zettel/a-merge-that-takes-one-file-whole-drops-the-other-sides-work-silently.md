# Слияние, взявшее файл «целиком у них», роняет чужую работу молча — и ADR остаётся стоять с пометкой «реализовано»

Октетная пара поручений была написана у хозяина в C и через восемь часов исчезла
из дерева. Никто её не удалял: разрешая конфликт в рантайме, взяли
`flang/src/emit/c/flang_repl.c` целиком у одной стороны и вручную наложили
обратно ОДИН кусок другой стороны из трёх. ADR-0004 при этом продолжал говорить
«Состояние: реализовано» и ссылаться на файлы, которых в дереве уже не было.

**Чем подтверждено.** `git log -S"Прочитать октеты из соединения" -- flang/src/emit/c/flang_repl.c`
даёт ровно два коммита: `9682dece` (добавил, +55 строк) и `8dd40e5e` (убрал).
Описание `8dd40e5e` называет, что сделал: файл «взят у `svod/vosem` ЦЕЛИКОМ … и на
неё наложен единственный кусок моей работы, который в ней отсутствовал: ключ
`--timeout`». Кусков было три — ключ, октетная пара и `«Запустить процесс с
вводом»`; вернули один. `grep -c октет` по файлу: было 9, стало 0, восстановлено 9.
Пропажа `«Запустить процесс с вводом»` держится до сих пор (0).

**Почему это прошло молча.** Всё, чем проверяли слияние, зеленело: сборка под
`-Werror`, `flang --version`, `flang check`, `flang emit --help`. Ни одна из этих
команд не ЗОВЁТ поручение у хозяина. Программа, которая зовёт
(`examples/io/oktety-po-provodu.flang`), в дереве лежала, но её никто не
запустил, а проверка `flang/test/oktety.test.mjs` не входит в путь, которым это
дерево проверяют.

**Чему учит.** Слово «целиком у них» в разрешении конфликта — это не разрешение,
а откат. Оно законно ровно тогда, когда перед ним посчитано, сколько кусков своей
стороны в этот файл придётся вернуть, и каждый назван поимённо. Счёт «кусков
было N, вернул N» стоит одной строки в описании коммита и ловит ровно этот класс
пропажи.

**Чем ограничено.** Автослияние здесь ни при чём — конфликт разрешал человек, и
его довод («их версия несёт разбор восьми целей») был верным. Неверна была только
арифметика возврата.
