# Модуль находится по имени из своей первой строки, а места поиска — свой каталог, каждый каталог выше и библиотека компилятора

`использует «Списки»` без пути. Ключ поиска — строка `модуль «Списки»`, стоящая
первой в файле; имя файла и его каталог роли не играют. Это не новый ключ:
связывание УЖЕ требовало, чтобы имя во ввозе совпадало с именем модуля
(`FLANG_IMPORT_NAME`), и на дереве 20 августа 2026 это выполнено у **206 ввозов
из 206 разрешимых**. По нему просто начали искать.

Форма занята, а не заведена: `использует «Списки»` без `из` разбор до сегодня
отвергал (`FLANG_PARSE`, «после имени категории ожидалось 'из'»). Новых слов в
языке — ноль.

## Места выбраны замером, а не вкусом

Мерилось на всех 210 ввозах дерева, у которых есть путь. Считалось, сколько
ввозов правило приводит РОВНО в тот файл, который назван путём сегодня.

| правило | тот же файл | не найден | спор имён | ЧУЖОЙ файл |
|---|---:|---:|---:|---:|
| только свой каталог | 107 | 103 | 0 | 0 |
| свой каталог + библиотека | 172 | 38 | 0 | 0 |
| **+ каждый каталог выше, пока в нём есть `.flang`** | **200** | 9 | **0** | 1 |
| + непосредственные подкаталоги каждого предка | 204 | 5 | 0 | 1 |
| обход ВСЕГО дерева от корня | 206 | 0 | **1** | **3** |

Решающая строка — последняя, и решает в ней не «206», а «3». Обход всего дерева
**молча переставляет три ввоза на чужой модуль**: `docs/zamer-teorkat/
iso-object-to-category.flang` ссылается на несуществующий
`examples/cat/moduli/zakazy.flang`, а глобальный указатель находит по
имени «Заказы» совсем другой файл — `examples/cat/modules/orders.flang`.
Сломанный ввоз перестаёт быть сломанным и начинает работать не с тем модулем.
Плюс один спор имён на сгенерированных прогонах `benchmarks/model-authoring/out/`.

Отсюда общее: **вглубь искать нельзя.** По всему дереву 861 файл `.flang`, у 601
есть имя модуля, 417 имён различны, а **27 имён носят 211 файлов** — почти все в
`benchmarks/model-authoring/out/**` (машинные повторы одной задачи) и пять пар в
примерах (`Фибоначчи`, `Палиндром`, `Римские числа`…). Указатель по всему дереву
неоднозначен на 27 именах; список мест — ни на одном.

Разница между третьей и четвёртой строкой — четыре ввоза, и она не окупает
второго условия в правиле. Взято третье.

## Что осталось с путём и почему это правильно

Из 109 ввозов через `../` осталось 8, и каждый — обращение в ЧУЖУЮ ветку дерева
или к пакету: `scripts/` → `flang/self/`, `flang/проверки/` →
`flang/self/bootstrap/`, `flang/test/fixtures/` → `flang/self/`,
`examples/library-api/lib/` → соседний `stdlib/`, `docs/examples/package/shop/`
→ `discount.flang-package`, и три мёртвых ввоза `docs/zamer-teorkat/` (файлов,
на которые они ссылаются, в дереве нет — это выяснилось этим же замером).

Путь, написанный руками, теперь значит ровно одно: «я знаю, что тянусь в
сторону». Каталог можно назвать и один раз — `FLANG_MODULE_DIR`, каталоги через
двоеточие.

## Как это переживёт менеджер пакетов

Разрешение по имени сидит в `flang/self/link.flang` и работает **по списку
исходников**, а не по диску: диска у языка нет. Кто наполнит список — дело
хозяина. Отсюда три следствия, и все три сегодня уже верны:

1. программа, собранная **из замка** (`flang.lock`, схема 2 — путь и исходник
   строкой), находит имя тем же кодом и диска не касается вовсе;
2. склад менеджера — это ещё одно **место**, а не новое правило;
3. два пакета, привёзшие одно имя, дают `FLANG_IMPORT_AMBIGUOUS` с обоими
   путями — тот же отказ, что и два одноимённых файла на диске. Молчаливый выбор
   первого зависел бы от порядка `readdir`, а он не назван нигде.

**Чем подтверждено.** Ветка `u/imena`. Замеры — `link-collision-guard.mjs`
(замыкание компилятора: 29 файлов, 7249 видимых объявлений, 0 столкновений) и
прогоны `bootstrap/flang check` на дереве. Правило повторено в трёх местах, и
разойтись им нельзя: `flang/self/link.flang` (по списку исходников),
`flang/src/emit/c/flang_repl.c` (`repl_find_module` — по диску),
`flang/scripts/link-collision-guard.mjs` (обходом текста).

**Чем ограничено.** Имя ищется В КАТАЛОГЕ, подкаталоги не просматриваются.
Каталог без единого `.flang` останавливает подъём — значит проект, у которого
между слоями лежит пустой каталог, потеряет верхнюю часть дороги. Одноимённые
модули в разных местах дают разный ответ разным файлам (обычное затенение, как у
`#include "…"` в C).

**Поправка 24 августа 2026.** Здесь стояло, что затенение «ловится
`FLANG_DUPLICATE_NAME` на первом же объявлении». Не ловится: `FLANG_DUPLICATE_NAME`
про два объявления в ОДНОЙ программе, а при затенении второго в программе нет —
поиск оборван на первом месте, и своего файла компилятор не открывает вовсе.
Цена этой строки — час чужой работы и записка, разошедшаяся с правдой:
[[a-stray-draft-above-the-tree-shadows-the-library-silently]]. Теперь
затенение говорится вслух — строкой в stderr, с именем взятого файла и именами
перекрытых.
