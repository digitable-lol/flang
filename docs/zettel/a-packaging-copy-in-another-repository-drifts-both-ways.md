# Копия упаковщика, живущая в чужом репозитории, расходится с деревом в обе стороны, и ни одна проверка этого дерева этого не видит

У нас два упаковщика, и у каждого копия в отдельном репозитории: формула
Homebrew (`packaging/homebrew/flang.rb` → `digitable-lol/homebrew-tap`) и плагин
asdf (`packaging/asdf/bin/*` → `digitable-lol/asdf-flang`). Обе копии за один
день разошлись с деревом — и в **разные** стороны. Дерево при этом зелёное: ни
одна проверка не смотрит в чужой репозиторий, а посмотреть можно только сетью.

**Чем подтверждено.** 19 августа 2026, дерево `work/zelenyy-stvol` на
`0ac93b38`, обе опубликованные копии скачаны и сверены с деревом:

- **Опубликованная формула ушла вперёд.** В tap лежит `version "0.5.1"` с хешем
  `ef2cbcbe…`, совпадающим с архивом релиза посимвольно; в дереве
  `packaging/homebrew/flang.rb` всё ещё `version "0.5.0"` и хеш `7dc75fec…`.
- **Опубликованный плагин отстал.** `bin/list-all` совпадает с деревом
  побайтово, а `bin/install` — нет: в дереве он принимает оба имени выхода
  сборки, в опубликованном стоит только старое `install -m 0755
  "${build}/flang_cli"`.

Цена второго расхождения измерена прогоном самих скриптов плагина (Node
физически убран из `PATH`):

```
bin/download 0.5.1 → девять файлов
bin/install  0.5.1 → cc … -o flang …
                     install: No such file or directory     ← отказ
bin/install  0.5.0 → «flang 0.5.0 установлен»
```

То есть `asdf install flang 0.5.1` падает **последним шагом**, уже собрав
компилятор: `Makefile` архива 0.5.1 кладёт `flang`, а скрипт ищет `flang_cli`.
Починка написана и лежит в дереве — но ставят люди не дерево, а репозиторий
плагина.

**Чему учит.** Переименование выхода сборки (`flang_cli` → `flang`) знали три
независимых потребителя: формула, `scripts/build-release-c.mjs` и `bin/install`
плагина. Первые два починены к выпуску 0.5.1, третий — нет, и узнать это можно
было **только запустив чужую копию**: grep по дереву её не находит, потому что в
дереве она уже правильная.

Признак, по которому такое ищут заранее: **любой файл под `packaging/`, у
которого есть опубликованный близнец в другом репозитории.** Сегодня их два.
Проверка «копии совпали» обязана скачивать близнеца, иначе она проверяет копию
против себя же.

**Чем ограничено.** Ни `brew`, ни `asdf`, ни `mise` на машине нет. Сверены байты
скачанных копий и прогнаны три скрипта плагина — но не сам asdf (`plugin add`,
разводка версий, shim) и не brew (разбор формулы как Ruby, `bin.install`,
песочница). Направление расхождения на завтра может быть уже другим: это снимок,
а не свойство.
