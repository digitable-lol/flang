# Обещание, дописанное звену хвостового круга, стирает батут из напечатанного кода — и главный цикл вычислителя становится рекурсией по стеку

Печать в C сворачивает хвостовую рекурсию двумя приёмами: самовызов в хвосте —
в `for (;;) … continue;`, взаимный хвостовой круг — в батут (`fl_trampoline`).
Оба приёма стоят на одном признаке, и он записан ДОКАЗАННЫМ обещанием в самой
печати (`flang/self/emit-c.flang`):

```flang
// Функция с постусловиями хвостовых вызовов не имеет: интерпретатор тоже не
// переиспользует кадр, которому есть что проверить после возврата.
функция «Хвостовые вызовы»
  обеспечивает «у функции с постусловиями хвостовых вызовов нет»
    если (длина («функция».«постусловия»)) больше 0 то результат равен пустой список иначе да
```

Отсюда цепочка, у которой нет ни одного лишнего звена:

```
дописали «обеспечивает» звену круга
  → у звена НЕТ хвостовых рёбер («Хвостовые вызовы» отдаёт пустой список)
  → в графе хвостовых рёбер круга больше нет
  → «Циклические функции» компоненту не берёт (в ней меньше двух имён)
  → батут не печатается
  → круг стал настоящей рекурсией по стеку хозяина
```

**Ничего в теле не изменилось. Изменилась только объявленная спека.**

## Как это выглядело на дереве

`flang/self/interpret.flang`: `«Прогон»` → `«Виток»` → `«Дальше после шага»` →
`«Прогон»`. Главный цикл вычислителя, зов на каждом ребре — в хвосте.

В напечатанном компиляторе дерева (`bootstrap/compiler_flang.c`, печать от
23 августа 2026 из `58b037c2`) стоит:

```c
/*
 * Функция flang «Прогон».
 * Взаимная хвостовая рекурсия с «Дальше после шага», «Виток»: вызовы идут через батут.
 */
```

В том дереве у всех трёх звеньев не было ни одного `обеспечивает`. 23 августа в
12:26 UTC коммит `ea59db47` «Вычислитель: утверждения о поведении у 158 функций»
дописал в файл 156 обещаний — по одному на каждое звено в том числе. С этого
момента круг печатается рекурсией: **три кадра стека хозяина на каждом витке
машины.**

## Счёт по дереву

Признак «даровое ребро» — зов в хвостовой позиции у зовущей БЕЗ постусловий,
тот же, по которому строит рёбра сама печать. Посчитано по всем
`flang/self/**`, `flang/stdlib/**`, `flang/conc/**`:

| | функций | в батутах (групп) | самовызовов в `for(;;)` |
|---|---:|---:|---:|
| 23 августа, `58b037c2` | 10 108 | 155 (57) | 318 |
| 27 августа | 11 589 | 87 (30) | 141 |

Плоский стек потеряли **262 функции**, распалось **30 батутных групп из 57**.
Разметка сверена с напечатанным C по именам: там батут у 145 функций, здесь по
тому же дереву 155, совпало 129 — расходятся однофамильцы из разных файлов и
функции вне замыкания одной точки входа. Оба числа таблицы сняты одной
разметкой.

Причина роста видна в том же счёте: доля функций с обещанием за четверо суток
поднялась с **7 % (667 из 9 636)** до **66 % (7 099 из 10 819)**.

## Правило без единого исключения — проверено на самом напечатанном компиляторе

`bootstrap/compiler_flang.c` разобран по функциям — 7 228 штук — и у каждой
посчитано, что в ней стоит:

```
со сторожем при работе (fl_post)                72
с батутом (fl_trampoline)                      145
с самовызовом, свёрнутым в for(;;)             257

ПЕРЕСЕЧЕНИЕ сторож × батут                       0
ПЕРЕСЕЧЕНИЕ сторож × цикл                        0
```

**Ни одна функция напечатанного компилятора не имеет одновременно проверки при
работе и плоского стека.** Плоский стек и сторож при работе взаимно
исключающи — и не по замыслу оптимизатора, а по одной строке в «Хвостовые
вызовы».

## Что этим признаком НЕ ловится

Круг, у которого зов стоит не в хвостовой позиции — аргументом другого зова или
внутри `отобразить`, — платит кадром и без всяких обещаний, и снятие сторожа ему
не поможет. По дереву раскол ровный:

```
кругов всего                                        541
  даровых уже сейчас                                128
  платят ТОЛЬКО из-за обещаний                      214
  платят и без обещаний (зов не в хвостовой позиции) 199
```

Пример второго рода — `«Овеществить»` ↔ `«Овеществить поля»` в том же
`interpret.flang`: спуск идёт через `отобразить`, и постусловие там ни при чём
(замер соседей, `576149cf`: вложенный вход на 1 000 уровней даёт глубину 1001 и
с обещанием, и без него).

## Отчего это ловится поздно и не тем именем

Отказ приходит не от того, кто копил кадры, а от того, кому кадра не хватило
последним. Перепечатка 27 августа 2026 умерла так:

```
FLANG_RECURSION_LIMIT: функция «Овеществить» превысила предел глубины вызовов (200000) на глубине 200001
```

`«Овеществить»` столько кадров не берёт, и это снято прогоном на НАСТОЯЩЕЙ
функции (проба ввозит `flang/self/interpret.flang` модулем): список из 1 000
скаляров — глубина 4, из 10 000 — 5, запись с 1 000 полями — 5. Длина не стоит
ничего, потому что спуск идёт через `отобразить`, а `отобразить` и у
вычислителя (`«Кадр шага обхода»`), и у печати в C (`for (size_t …)`) — цикл.
Кадр берётся на ярус вложенности, а вложенность настоящих деревьев двузначная:
наибольшая вложенность скобок во всём дереве — 36, самый глубокий напечатанный
AST — 62 яруса JSON.

## Что с этим делать, не трогая обещаний

1. **Дать функции `пример`.** Снятие сторожа при печати
   (`flang/self/bootstrap/compiler.flang`) требует вердикта `доказано` И
   `grid > 0` — хотя бы одного `пример`. Снятое обещание в напечатанный код не
   едет, значит хвостовые рёбра на месте, значит батут возвращается. Обещание
   остаётся в исходнике и остаётся проверяемым у `flang run` и `flang test`.
   Замер: из 77 звеньев распавшихся групп **62 без единого примера**, готовых к
   снятию групп — **ноль**.
2. **Снять обещание с кольца, не убирая его:** тонкая обёртка с `обеспечивает`,
   тело без него, в круге — тело. Проверка становится разовой, а не пооборотной.
3. **Разрезать круг явным состоянием** — `«Словарь описаний»` (10 005 кадров →
   13) и коммит `3991810f` (круг печати литералов 51 → 46).

## Цена входа обратно: посчитана по каждой распавшейся группе

Вернуть батут можно, не тронув ни одного обещания: снятие сторожа при печати
требует вердикта `доказано` И `grid > 0`, а `grid` — это просто число `пример`ов
функции. Значит недостающее — примеры, и их можно пересчитать поимённо.

```
распавшихся групп                     30
звеньев в них                         77
звеньев с обещанием и БЕЗ примера     62
групп, готовых к снятию уже сейчас     0
```

Но распределение неровное, и это делает работу подъёмной: **22 группы из 30
нуждаются в одном-двух примерах.**

| нужно примеров | групп | самые крупные |
|---:|---:|---|
| 1 | 6 | 8 звеньев `interpret.flang` («Описания программы»), 3 звена `lexer.flang` («Читать юникод») |
| 2 | 16 | `lexer.flang` («Сканировать», «Уложить литерал»), `parser.flang` ×4, `types.flang` ×2 |
| 3 | 8 | `interpret.flang` («Прогон», «Виток», «Дальше после шага»), `types.flang` («Тип узла») |

**Приход мерится длиной того, по чему ходит круг, а не числом звеньев.**
`«Сканировать»` — главный проход лексера ПО СТРОКЕ исходника, один кадр на
символ, пока самовызов не свёрнут в `for(;;)`. Длины строк дерева, снятые
прогоном по `flang/self/**`:

```
строк длиннее  2 000 символов   20
строк длиннее 10 000 символов    3   (все в emit-python.flang)
самая длинная                90 286  символов — emit-python.flang:2956
```

**90 286 кадров на одну строку** — почти половина предела 200 000, на котором
умер заход 27 августа. И сама эта строка — машинописное `обеспечивает`.

## Двенадцать примеров возвращают ВСЕ круги, чья глубина растёт со входом

Из 30 распавшихся групп опасны не все: круг страшен тогда, когда число его
оборотов растёт с размером входа. Таких шесть, и вот они целиком — с тем, чего
каждой не хватает:

| по чему растёт | звеньев | где | обещаний в круге |
|---|---:|---|---:|
| по виткам машины — миллиарды | 3 | `interpret.flang` «Прогон», «Виток», «Дальше после шага» | 3 |
| по функциям программы — 6 000+ | 8 | `interpret.flang` «Описания программы» и семья | 1 |
| **по символам строки исходника — до 90 286** | 2 | `lexer.flang` «Сканировать», «Уложить литерал» | 2 |
| по символам строкового литерала | 3 | `lexer.flang` «Читать в кавычках» и семья | 1 |
| по ярусам выражения | 3 | `types.flang` «Тип узла» и семья | 3 |
| по ярусам выражения | 2 | `totality.flang` «Обойти», «Обойти пусть» | 2 |

Сумма последнего столбца — **12**. Столько функций надо снабдить примером (и
получить по ним вердикт `доказано`), чтобы плоский стек вернулся всюду, где
глубина зависит от входа. Остальные 24 распавшиеся группы ходят по данным
ограниченного размера и ждут своей очереди.

## Поправка к «двенадцати»: семь из них примером не открыть

Пример даёт `grid > 0` — это лишь ПОЛОВИНА условия снятия. Вторая половина —
вердикт ядра `доказано`, и по форме обещания видно заранее, будет он или нет.
Разбор всех двенадцати:

**Семь — утверждения о монотонности:**

```
«Прогон»          («м».«витки») не больше (результат.«витки»)
«Виток»           ((«м».«витки») плюс 1) не больше (результат.«витки»)
«Тип узла»        (длина «беды») не больше (длина результат.«беды»)
«Тип выражения»   то же
«Тип пусть»       то же
«Обойти»          (длина «вызовы») не больше (длина результат.«вызовы»)
«Обойти пусть»    то же
```

Такому обещанию пример не помогает: чтобы ядро сказало «доказано», нужна
индукция по разбираемому узлу, а не сетка значений. **Это работа доказательства,
а не работа примера.**

**Пять — формы, которые ядро берёт** (`docs/site/kak-dokazat.ru.md`, форма 1
«охрана повторяет условие тела» и форма 10 «теорема по свойству на голом
вызове»): `«Дальше после шага»`, `«Описания программы»`, `«Читать юникод»`,
`«Сканировать»`, `«Уложить литерал»`.

Отсюда честная разбивка работы: **примером открываются пять кругов из шести
частично, а полностью — только те, где ВСЕ звенья с обещаниями имеют берущуюся
форму.** Остальное упирается в доказательство монотонности, и планировать это
надо как доказательство, а не как дописывание примеров.

## Обратный ход проверен: пример возвращает батут, и это видно в напечатанном C

Дописан ТОЛЬКО `пример` трём функциям `flang/self/lexer.flang` — ни строки тела,
ни одного `обеспечивает`. Печать в C, чистое дерево против правленого:

```
          батут   for(;;)   fl_post   снято ядром
ДО lexer      3         4        37            60
ПОСЛЕ lexer   6         5        34            63
```

| функция | ДО | ПОСЛЕ |
|---|---|---|
| «Читать юникод» | рекурсия по стеку | **БАТУТ** |
| «Уложить литерал» | рекурсия по стеку | **БАТУТ** |
| «Сканировать» | рекурсия по стеку | **ЦИКЛ `for(;;)`** |

Ушли ровно три сторожа — те самые, что целились, — новых не появилось. Примеры
прошли на настоящих функциях: `hotswap` 157/157, `lexer` 139/139.

**Приход у `«Сканировать»` — это проход лексера по строке, кадр на символ.** Самая
длинная строка дерева — 90 286 символов (`emit-python.flang:2956`, и сама она
машинописное `обеспечивает`). До правки одна эта строка стоила 90 286 кадров при
пределе 200 000; после — ноль.

### Отрицательное того же замера: пример не всегда достаточен

`hotswap.flang` не вернулся: `батут 1 → 1`, `fl_post 174 → 174`, снято `130 →
130`. Пример есть, вердикта `доказано` нет — обещание там охрана-зеркало над
`разбор` с заключением-ЛИТЕРАЛОМ, и оно не взялось. Это ложится к шестидесяти
таким же (`the-empty-branch-of-a-match-is-shut-in-both-spellings.md`)
шестьдесят первым случаем. Вторая половина беды в том, что группе нужны ОБА
звена, а у соседнего обещание монотонности, которое примером не открыть вовсе.

**Отсюда правило отбора, которое стоило прогона:** прежде чем дописывать
пример ради снятия сторожа, посмотри на ФОРМУ обещания. Ветвь `пусто` у
тела-`разбора` не берётся ни при каком заключении, а утверждение о монотонности
не берётся без индукции — в обоих случаях пример потрачен зря.

## Поправка к счёту: «ждут примера» считается по ВЕДОМОСТИ, а не по слову «пример»

Число «22 группы из 30 ждут одного-двух примеров» выведено неверным признаком и
снимается. Считалось наличие `пример` у звена (`grid > 0`), а условий снятия
сторожа ДВА: `grid > 0` **И** вердикт ядра `доказано`. Первое — необходимое, а
решает второе.

Насколько эти два счёта расходятся, снято соседом на `types.flang`: семь
распавшихся групп, у двух ломающих обещаний `сетка`, у пяти «объявлено, не
доказано», **`доказано` нет ни у одного**. Четыре дописанных примера дали
`flang test` 237/237 и **ни одного нового шага батута** в напечатанном C.
То есть примера там не ждала ни одна из семи групп: счёт по слову дал семь, счёт
по вердикту — ноль.

**Обратный случай — тоже замер, и он мой.** В `lexer.flang` четыре обещания
после дописанных примеров ушли из напечатанного кода, а `«Сканировать»` и
`«Открыть строку»` стали циклами. Ведомость это подтверждает прямо: у всех
четырёх — **`доказано`** (`утверждений 96: доказано 90`). Вердикт был и до
примеров; не хватало ровно `grid > 0`.

**И третий случай, тоже мой и отрицательный.** `hotswap.flang`: после двух
примеров вердикт `«у пустых полей варианта размер единица»` — **`сетка 2
значения`**, а у соседнего звена `«узел весит не меньше единицы»` — **`сетка`**.
Ни одного `доказано`, и батут не вернулся. Пример перевёл обещание из
«объявлено, не доказано» в «сетка» — и только.

**Что различает эти два случая — форма цели.** У `types.flang` цели вида
`(длина X) не больше (длина <выражение о результате>)`; правил на форму цели у
ядра три — «не меньше 0», «не больше конечного литерала», «равно», — и этой
среди них нет, цель не берётся вовсе. У `lexer.flang` цели — охрана-зеркало и
голый вызов, формы 1 и 10. Поучительная пара внутри одной группы `types.flang`:
`«Одинаковые типы»` доказано разбором цели по условию (тело начинается с `если`,
условие цели совпадает с условием ветвления), а `«Одинаковые виды»` с тем же по
смыслу утверждением уходит на сетку — тело `разбор`, делить нечего. **Один
смысл, две записи, разный исход.**

**Приём, которым это снимается дешевле ведомости.** Снятие сторожа видно прямо в
напечатанном C: пропал `fl_post` — значит вердикт был `доказано`. Это не косвенный
признак, а сам вывод ядра, и берётся он тем же разбором печати, каким считаются
батуты.
