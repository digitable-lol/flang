# Поля записи через строку не переносятся, а список в квадратных скобках — переносится

`ярлыки.flang` держал 143 цели по одной строке на цель — три поля в строку, самая
длинная 1148 знаков. Чтобы убрать горизонтальную прокрутку, надо было разложить
запись на несколько строк. Прогоном выяснилось, ЧТО именно переносится, а что нет.

**Не переносится ничто из цепочки `с … и …`.** Отвергнуты разбором все три записи:
перенос перед `с`, перенос перед `и`, и то же в круглых скобках. Сообщение —
`FLANG_PARSE: неожиданное 'с'` (или `'и'`). Это касается и `запись «Имя» с …`, и
`вариант «Имя» с …`: цепочка полей обязана уместиться в одну физическую строку.
Подтверждение по дереву: во всех 970 файлах `.flang` нет НИ ОДНОЙ строки,
начинающейся с `и «` или `с «`.

**Не переносится и `обеспечивает`, `принимает`, `ожидается`.** Перенос условия
постусловия — `не разобрана конструкция`; перенос списка параметров —
`ожидалось имя параметра`.

**Переносится список в квадратных скобках.** Внутри `[ … ]` перевод строки
разрешён, и этого хватает: длинное поле записывается как
`(соединить ["кусок ", "кусок"] по "")`, а список кусков ложится на сколько угодно
строк. Значение сохраняется знак в знак — проверено примерами и побайтовым
сличением вывода `flang run ярлыки.flang --function «Перечень»` до и после.

**Обратный слэш в конце строки НЕ склеивает строковую постоянную.** Ожидание было
как в C; на деле `"часть один \` + перевод + `часть два"` даёт `"часть один \nчасть два"` —
в значении появляется настоящий перевод строки. Для переноса длинной постоянной
этот путь не годится, годится только `соединить … по ""`.

**У `соединить` нет формы без разделителя.** `соединить ["раз ", "два"]` —
`у 'соединить' ожидалось 'с' или 'по'`. Пишется `соединить [ … ] по ""`.

**Чего это стоит.** В примерах (`пример` / `дано` / `ожидается`) значение обязано
быть ЛИТЕРАЛОМ — `соединить` там отвергается со словами «примеры не вычисляются».
Поэтому записи, лежащие внутри примеров, и длинные ожидаемые строки укоротить
нечем, и предел файла задают именно они, а не данные.
