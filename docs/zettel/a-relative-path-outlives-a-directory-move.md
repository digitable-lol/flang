# Переезд каталога поиск по полному пути не ловит: ссылка вида «../каталог» переживает его молча

Когда каталог переезжает, старые ссылки на него ищут его полным путём —
`git grep 'flang/проверки'`. Такой поиск не видит путей, записанных
относительно соседнего каталога: `"../проверки"` в `flang/scripts/…` или
`import("../conc/scheduler.js")` в `flang/test/…`. После переезда они указывают
в пустоту, а проверка, которая по ним ходит, может ничего не заметить.

**Чем подтверждено.** Задача 1418, 14 сентября 2026, три переезда. Поиск по
полному пути вне истории после Ш1 назвал ноль живых ссылок на `flang/проверки`,
и переезд был записан как законченный. Остались три относительные ссылки,
найденные уже при подготовке следующего переезда поиском по короткому имени с
приставкой `../`:

- `flang/scripts/closed-length-guard.flang:668` — перечень ровно из 21 каталога,
  которые обходит сторож длины; `"../проверки"` и `"../conc"` стоят в нём
  относительно `flang/scripts`. Число каталогов закреплено `обеспечивает`,
  поэтому пропавший каталог не укорачивает перечень, а молча выпадает из обхода;
- `flang/test/planirovshchik-celi.test.mjs:60` и `svyaz-celi.test.mjs:56` —
  `await import("../conc/scheduler.js")` и `"../conc/link.js"`.

После замены (`"../test"`, `"../concurrency"`, `"../concurrency/*.js"`)
`./ярлык длина:проверка` отвечает тем же, что на стволе: обещаний о длине 405,
судимо 284, все сошлись.

**Как искать.** Кроме полного пути — короткое имя переезжающего каталога с
приставкой `../`, в кавычках и без: `git grep -n -P '(?<!flang/)(?<![\w.-])conc/|\.\./conc\b'`.
По этому поиску нашлись все три; ложных совпадений — перечни подкаталогов в
прозе («proof/, conc/, ct/»), которые тоже надо править.

**Чем ограничено.** Путь, собранный из кусков (`соединить ["../", имя]`), не
найдёт и этот поиск: там нужен прогон проверки, которая по пути ходит.
