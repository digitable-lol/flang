# Прогон на чужой машине превращает отсутствующий тулчейн из пропуска в провал — иначе половина целей не проверена ни разу

`scripts/test-remote.sh` гоняет набор на хосте, где стоят все девять тулчейнов.

**Зачем.** Тест цели печати доказывает кодогенерацию тем, что настоящий
компилятор принял порождённый код. Девяти тулчейнов на ноутбуке обычно нет, и
тесты отсутствующих молча пропускаются — набор зелёный, а половина целей не
проверена ни разу. Так ушёл выпуск 0.4.6 с дефектом кодогенерации Go. Лечится не
уговорами, а местом прогона: на хосте, где стоят все девять, пропусков нет по
построению, и там же прогон быстрее — ядер больше. `FTS_REQUIRE_TOOLCHAINS=all` —
главное отличие удалённого прогона от местного.

**Почему девять, а не восемь.** Список id, которые знает
`flang/test/toolchain-guard.mjs`, — восемь; девятой, cpp, в нём нет, её
компилятора не просил никто, и хост без g++ давал «НАБОР ПРОЙДЕН». Отсюда своя
проверка, и она до синхронизации: платить за rsync и прогон, чтобы узнать про
нехватку в конце, незачем.

**Умолчания.** Хост задаёт `FLANG_REMOTE`, умолчания нет намеренно: чужая
машина не должна называться в дереве. Каталог на хосте — под кэшем, а не рабочий
клон: содержимое копии одноразовое, её затирает каждый прогон, и настоящему
клону это стоило бы веток. PATH для неинтерактивного ssh выставляется явно: Go,
Rust и Elixir нередко лежат в `/usr/local`, а `~/.local/bin` добавляет только
login shell, до которого не доходим. `node_modules` и `dist` не едут — продукты
сборки; копировать чужую сборку — мерить не то.

**Чем подтверждено.** Выпуск 0.4.6; 3 сентября 2026 снят шаг `npm ci` вместе с
npm: зависимостей у дерева ноль, `package-lock.json` удалён, и без замка `npm ci`
отвечает кодом 1 («can only install with an existing package-lock.json») —
шаг ронял бы прогон, ничего не поставив. Двоичный собирает `./ярлык` на той
стороне.

**Чем ограничено.** Восемь тулчейнов роняет сам прогон, девятый — своя проверка;
список пар «команда:цель» набран здесь руками и стоит в ведомости перечней.
