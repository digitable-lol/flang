# На негодном октете прогонщик обязан отказать одинаково на всех целях — а было пять разных поведений, и отказом не было ни одно

`scripts/guards/bad-octet-guard.sh` судит прогонщики всех целей печати одной и
той же программой на одном и том же входе.

**Замер 22 августа 2026.** Одна напечатанная программа, один негодный октет во
входной строке — и пять разных поведений у восьми целей:

| цель | было | код |
|---|---|---|
| c | возил октеты как есть, отвечал FLANG_UNKNOWN_NAME на них | 0 |
| go | подменял октет знаком замены U+FFFD, ответ тот же | 0 |
| java, csharp, js | то же | 0 |
| elixir | звал не-текст «неразборчивым запросом» | 0 |
| rust | молча обрывал цикл: ни ответа, ни отказа | 0 |
| python | падал трассировкой UnicodeDecodeError, а при LC_ALL=C и C.UTF-8 протаскивал октет суррогатом и отвечал | 1 / 0 |

Худшее — Rust: код 0 и тишина читаются как «всё хорошо», а работа не сделана.
Пять целей отвечали о содержимом, которое сами же подменили, — врали тихо. У
Python поведение зависело от локали хозяина. Снято прогоном на этой машине (cc
15.2, rustc 1.97.1, openjdk 26, dotnet 10.0.110, node 26.7, python 3.14.4, elixir
на OTP-29). Образец поведения у языка уже был: `FLANG_IO_NOT_TEXT` у текстовой
пары ввода-вывода называет номер октета, его значение и чем возить октеты
(`docs/adr/0006-octets-for-files.md`); прогонщики сведены к нему.

**Что проверяется — две вещи, и вторая без первой ничего не стоит.** Здоровый
вход проходит: три запроса (пустая строка, CRLF, последняя строка без перевода)
дают три ответа и код 0 — без этой половины сторож был бы зелен у прогонщика,
который отказывает всегда. Негодный октет отказывает: код не ноль, а поток
ошибок — побайтово тот же текст, что у остальных; девять похожих текстов — это и
есть девять разных поведений. Эталон записан в сторожe, а не берётся у первой
отозвавшейся цели: сторож, сверяющий цели друг с другом, зеленеет и тогда, когда
все девять сломаны одинаково. Строк во входе три нарочно: ответ на первую обязан
остаться, третья — работа, которую молчащий прогонщик не делает.

**Долг, названный вслух.** Цель js вычтена, и вычитание красит с двух сторон:
прогонщик JavaScript — рукописный `flang/src/emit/js/flang_cli.js`, а править
рукописный JavaScript запрещено. Поэтому js судится обратным ожиданием: обязан
вести себя плохо, и в день, когда начнёт отказывать как все, сторож покраснеет и
потребует снять вычитание.

**Мелочи, которые стоили прогонов.** У cpp договор ключа `--runtime` свой
(замер 5 сентября 2026): восемь целей ждут каталог самой цели, девятая — корень
`flang/src/emit`. Через ворота `flang-vorota` звать с `PAMYAT=150G`: ворота ставят
RLIMIT_AS 40 ГиБ, а JVM, .NET и cargo резервируют адресное пространство впрок —
`dotnet build` упал «Out of memory» из Roslyn на ровном месте. Свой каталог
сторож убирает только зелёный: на 6 сентября 2026 в `/srv/tmp` лежало 86
каталогов «storozh-oktet.*» на 525 МБ — сторож не убирал за собой ни разу, а
машина общая на 27 человек; красный каталог остаётся, потому что на него
ссылается строка «работа: …». Столбцы таблицы разделителем: printf в bash считает
байты, кириллица идёт по два.

**Чем подтверждено.** Замеры 22 августа, 5 и 6 сентября 2026, названные выше;
рецепты сборки те же, что в `docs/ifl/measure-across-targets.sh`.

**Чем ограничено.** Код 2 («тулчейна нет») — не пройденная проверка (AGENTS.md).
Проба `--порча` возвращает Rust к прежней болезни в копии дерева прогонщиков и
требует, чтобы сторож покраснел.
