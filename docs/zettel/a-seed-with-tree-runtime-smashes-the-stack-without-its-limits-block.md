# Семя с рантаймом дерева бьёт стек, если не перенести блок настроек из его шапки

Рецепт «собрать двоичный в `/srv/tmp` из семени ствола с рантаймом дерева» —
тот, которым проверяются правки в `flang/src/emit/c/*` без перепечатки, — требует
перенести из `bootstrap/flang_runtime.h` **блок настроек**, напечатанный
бэкендом. Если вместо этого положить поверх `flang_runtime.h` дерева как есть,
двоичный **соберётся начисто** (`-Wall -Wextra -Werror -pedantic`) и на первом же
`check` умрёт с `*** stack smashing detected ***`, не напечатав ни байта.

Ошибка молчит там, где её ищут: компилятор доволен, отказ приходит без имени шага
и без диагностики flang, а команда, которая проверяется, к нему отношения не
имеет.

## Отчего именно бьёт

Шапка `bootstrap/flang_runtime.h` несёт значения **этой напечатанной программы**:

```
#define FL_INDEX_BASE 1
#define FL_MAX_DEPTH 20000
#define FL_MAX_STEPS 1000000000
#define FL_MAX_TAIL_ARGS 9
#define FL_MAX_ARGS 14
```

В рантайме дерева те же имена объявлены через `#ifndef` с умолчаниями, и одно из
них меньше напечатанного: `FL_MAX_TAIL_ARGS` — **4** против **9**. А им размечен
массив НА СТЕКЕ:

```c
struct fl_bounce {
  fl_step next;
  fl_value args[FL_MAX_TAIL_ARGS];
};
```

Семенной `compiler_flang.c` делает хвостовые вызовы с девятью доводами, кладёт
девять значений в четыре места — и канарейка ловит запись за краем.

**Разведено одной переменной.** Двоичный, собранный из семени с рантаймом дерева
и с восстановленным ТОЛЬКО `FL_MAX_TAIL_ARGS 9` (остальные умолчания дерева на
месте), `check` проходит и отвечает по делу. Значит бьёт именно оно, а не
`FL_MAX_ARGS`, не глубина и не пределы шагов.

**Остальные потерянные значения падают ГРОМКО, и в этом вся разница.**
`FL_MAX_STEPS` 1 000 000 000 → 1 000 000 даёт внятное «ЗАПАС ШАГОВ НА ИСХОДЕ:
„Разбор исходника“ съел 1 001 728 витков из 1 000 000» и код 1. Порча памяти —
одна: `FL_MAX_TAIL_ARGS`.

**Чем подтверждено.** Ствол `da47cbdf`, 28 августа 2026. Пять двоичных в
`/srv/tmp`, все из `bootstrap/compiler_flang.*` байт в байт, `make -j8`, LTO,
проба `flang check examples/cat/natural-square.flang`:

| сборка | итог |
|---|---|
| семя целиком, как в `bootstrap/` | работает, код 2 |
| семя + `flang_cli.c` дерева | работает, код 2 |
| семя + `flang_runtime.{c,h}` дерева | **`stack smashing`, код 134** |
| то же + восстановлен один `FL_MAX_TAIL_ARGS 9` | работает |
| семя + рантайм дерева с перенесённым блоком | работает, код 2 |

`flang_repl.c` дерева поверх семенного рантайма не собирается вовсе
(`implicit declaration of fl_say_text`), то есть репл дерева тянет за собой и
рантайм дерева — обойти перенос блока, взяв рантайм семени, нельзя.

**Чем ограничено.** Это про наложение рантайма дерева на семя, и только.
Настоящая перепечатка печатает блок сама, и там его потерять негде. Числа `9` и
`14` принадлежат ЭТОМУ семени: у другой напечатанной программы они другие, и
вписывать девятку руками нельзя — переносить надо блок целиком, из шапки того
семени, из которого собираешь.

Замечание в самой шапке — «в самом рантайме те же имена объявлены через
`#ifndef`, поэтому он собирается и без этого блока» — верно про сборку и ничего
не говорит про работу. Ловушка ровно здесь.
