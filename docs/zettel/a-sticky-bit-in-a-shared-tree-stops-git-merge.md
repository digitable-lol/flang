# Липкий бит на чужом каталоге останавливает `git merge` целиком, а обходится одним коммитом

`git merge github/main` отказался на первом же файле: «unable to unlink old
`flang/test/zapis/vedomost-etalona.json`: Operation not permitted». Слияние при
этом не начиналось — ни `MERGE_HEAD`, ни изменённых отслеживаемых файлов, зато в
дереве осталось 40 неотслеживаемых, которые git успел записать до отказа.

Причина не в правах на файл, а в правах на КАТАЛОГ. `flang/test/zapis`
принадлежит другому пользователю и несёт липкий бит (`drwsrwsr-t`); при нём
удалить файл может только владелец файла, владелец каталога или root, и никакой
ACL этого не отменяет. Писать в файл при этом можно — право даёт запись группы.
А git обновляет файл не записью, а «удалить и создать».

Обход берётся из этой же разницы: **записать нужное содержимое В файл на месте**
(усечением, без удаления инода) и закоммитить отдельно. После этого обе стороны
слияния несут один и тот же блоб, и трогать файл слиянию незачем.

```
git cat-file blob <блоб-ствола> > путь/к/файлу     # усечение, не удаление
git add путь/к/файлу && git commit
git clean -fd                                       # убрать 40 недописанных
git merge github/main
```

Перед этим стоит проверить, сколько таких файлов вообще: пройти список
`git diff --name-only HEAD github/main` и для каждого спросить, есть ли на его
каталоге липкий бит и не мой ли владелец. Из 206 файлов слияния таким оказался
**ровно один** — иначе обход пришлось бы повторять вслепую.

**Чем подтверждено.** 18 августа 2026, `/srv/flang-rabota/vypil`, ветка
`work/checks-in-flang`. Каталог `flang/test/zapis` — `m:m`, режим `drwsrwsr-t`,
ACL `group:dev:rwx`; пользователь `b` из группы `dev`. Файл 2 226 492 байта,
блоб ствола `8f447ac0`.

**Чем ограничено.** Работает, когда сторона ствола нас устраивает целиком: мы
кладём в файл ровно её содержимое. Если файл надо СЛИТЬ, а не взять одной
стороной, содержимое придётся собрать руками и положить тем же усечением —
git всё равно не сможет его переписать сам.
