# Чужой черновик каталогом выше перекрывает библиотеку дерева молча, и ловушка стоит ровно в корне репозитория

Поиск модуля по имени идёт по местам в таком порядке (`repl_places_of` и
`repl_find_module`, `flang/src/emit/c/flang_repl.c`):

1. каталог ввозящего файла;
2. ВВЕРХ по предкам, пока в очередном предке есть хоть один `.flang`;
3. и только потом библиотека рядом с двоичным (`flang/stdlib`, `flang/core`,
   `FLANG_MODULE_DIR`).

Побеждает первое место, где имя нашлось. Значит **предок сильнее библиотеки**:
чужой файл, лежащий выше по дереву, подменяет модуль библиотеки целиком.
Правило выбрано замером и выбрано верно — см.
[[a-module-is-found-by-the-name-on-its-first-line]], — но у него есть цена, и
здесь она заплачена.

## Где именно стоит ловушка

`flang/` не содержит ни одного `.flang` прямо в себе — только подкаталоги.
Поэтому для любого файла из `flang/stdlib/**`, `flang/self/**`, `flang/core/**`
подъём обрывается сразу же, на первом шаге вверх, и наружу дерева не выходит
никогда. Библиотека в безопасности.

А вот файл, положенный **в корень репозитория**, поднимается дальше: корень
лежит в `/srv/flang-rabota`, там `.flang` есть, и модуль ищется среди чужих
черновиков общей рабочей зоны. Корень — это ровно то место, куда естественно
кладётся быстрая проба на пять строк.

|---|---|---|

| `u-dok-hash-z1.flang` | `модуль «SHA-256»` | `flang/stdlib/sha256.flang`, 534 строки против 992 |

Плюс `/srv/tmp/orig-hashmap.flang` — третья копия «Словаря хешем», тоже старая.

## Чем это кончилось

Агент сделал `flang/stdlib/hashmap.flang` параметрическим по значению
(`тип «Звено» от «З»`). Внутри файла параметр работал; проба в корне дерева
отвечала:

```
FLANG_TYPE_ARGS, строка 4: тип «Звено» объявлен от нуля параметров,
                           а применён к 1 аргументу
```

Час ушёл на поиск изъяна языка. Изъяна нет: «Звено» приезжало из
`u-teoremy-hashmap-hm-BAZA.flang`, а `flang/stdlib/hashmap.flang` не открывался
ни разу (проверено `strace`). Разбор целиком —
[[slovar-hesha-stal-parametricheskim-a-parametr-ne-perezhivaet-vvoza]].

## Почему затенение НЕ ловится `FLANG_DUPLICATE_NAME`

Так было записано в соседней заметке, и это неверно. `FLANG_DUPLICATE_NAME`
ловит два объявления, попавшие в ОДНУ программу. При затенении второго
объявления в программе нет вовсе: место найдено первое, поиск оборван, чужой
файл занял место своего. Двойного имени нет — есть одно, и не то.

Отсюда общее правило: **отказ, который жалуется на содержимое ввезённого
модуля, обязан быть проверен на то, ТОТ ЛИ ЭТО ФАЙЛ, — раньше, чем на смысл
жалобы.** Диагностика при этом не врёт: у приехавшего «Звена» параметров
действительно ноль.

И следствие для контрольных прогонов: каталог считается чистым не по названию, а
по списку имён модулей в нём и во всех его предках. `/srv/tmp` названием чист, а
`.flang`-файлов в нём 139.

## Что сделано

`repl_find_module` теперь досматривает остальные места и, если то же имя модуля
объявлено ещё где-то, печатает в stderr одну строку на модуль:

```
flang: модуль «Словарь хешем» взят из /srv/flang-rabota/u-teoremy-hashmap-hm-BAZA.flang; тот же модуль объявляют также: /srv/flang-rabota/u-parametr-vvoza/flang/stdlib/hashmap.flang
```

Один и тот же ПУТЬ сам себя не затеняет — иначе строка врала бы на каждом файле
библиотеки: каталог ввозящего и библиотека рядом с двоичным сплошь и рядом один
и тот же каталог, а от повтора берегётся только подъём вверх.

На код возврата строка не влияет: это не отказ, а имя файла, которого не
хватало. Проверено обоими концами — на пробе с затенением строка есть, на
`flang check flang/stdlib/hashmap.flang` её нет (24 функции, все с доказанным
завершением, замечаний нет).

Правка лежит в `flang/src/emit/c/flang_repl.c` — в ХОЗЯЙСКОЙ половине, не в
`flang/self/**`. Прогонялась она собранной: тот же блок положен в
`bootstrap/flang_repl.c` рабочей копии, `make` в `bootstrap/`, и обе пробы выше
сняты этим двоичным; сдаётся ровно тот же текст (сверено `diff`). До общего
двоичного правка доедет перепечаткой семени — приёмная `bootstrap/**` не берёт,
и это правильно. Сам исходник собирается начисто своими заголовками:
`cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -I flang/src/emit/c`, код 0.

## Что осталось поправить не мне

`flang/stdlib/hashmap.flang` в ветке `u/slovar-opisaniy` (коммит `07783d1b`) в
шапке несёт неправду — «⚠ ВВОЗИТЬ ЕГО ПОКА НЕЛЬЗЯ … Параметр типа не переживает
ввоза». Файл чужой, тысяча строк, и переписывать его в своей ветке значило бы
сделать чужую работу второй раз. Кто будет вливать ту ветку — замените этот
абзац на:

```
// ВВОЗИТЬ ЕГО МОЖНО. Здесь стояло обратное — «параметр типа не переживает
// ввоза», — и это была неправда: ввозился не этот файл. Модуль «Словарь хешем»
// объявляет ещё и черновик `/srv/flang-rabota/u-teoremy-hashmap-hm-BAZA.flang`,
// копия ДО параметризации, а каталог-предок просматривается раньше библиотеки —
// и «Звено» приезжало оттуда, без параметров. Проверено strace: этот файл не
// открывался вовсе. В каталоге, где модуль берётся отсюда, ввоз чист:
// `принимает «з»: «Звено» от строки` — функций 25, все с доказанным
// завершением, замечаний нет.
```

И тогда же снимается то, что этой неправдой держалось: словарь можно подключать
к `«Найти описание»` в `flang/self/interpret.flang` — ради чего он и делался.
