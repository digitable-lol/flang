# Отличить путь от кода в обратных кавычках можно синтаксисом, и это находит в разы больше мёртвых улик, чем видела прицельная выборка B5

[[a-path-in-backticks-is-checked-against-nothing]] показала, что путь в обратных
кавычках не сверяется вообще. Здесь — как его сверять, не путая с именем функции,
кодом отказа и куском кода, и что вышло, когда `scripts/link-guard.flang` научили
это делать.

**Мера.** Строчный (не огороженный) кусок в обратных кавычках считается путём,
если: не начинается с `/` (это адрес вне дерева этого репозитория); не содержит
ни одного из 24 символов, которые в пути не встречаются, а в коде или прозе —
обычное дело (пробел, скобки, кавычки, `$`, `→` и т. п.); хвост после первого
`:` или `#` отрезан; не оканчивается на голое расширение без имени перед ним
(`.flang` — упоминание расширения, не файла); оканчивается на одно из 16
расширений, которыми в этом дереве называют файлы-улики (тот же список, что
собрала B5: `mjs, flang, md, sh, yml, yaml, json, tsv, py, c, rs, go, ex, java,
cs, ts`). Огороженные (тройными кавычками) блоки не разбираются на пути вовсе —
осознанно, ради простоты и меньшего числа ложных тревог.

Существование пути в коде проверяется мягче, чем у markdown-ссылок: сверх трёх
обычных способов прочесть путь добавлен четвёртый — путь также считается живым,
если файл с ТАКИМ ЖЕ ИМЕНЕМ есть где угодно в дереве. Без этого 115 упоминаний
из 444 живых улик B5 покраснели бы зря: прозе свойственно называть файл короче
настоящего пути, когда каталог уже назван предложением раньше.

**Чем подтверждено.** Прогон настоящего двоичного (`c15f669f`, скопирован в
клон и запущен оттуда) на ветке `main`, коммит `03fb4060`, дерево 1016
файлов `.md`:

- на 132 мёртвых уликах B5 — 127 покраснели (96 %); 5 не найдены КАК КАНДИДАТ
  вовсе: 2 — абсолютный путь `/srv/...` (сознательно не считается путём этого
  дерева), 1 — упомянут только внутри огороженного блока (сознательно не
  разбирается), 2 — обрывок склейки в собственном регэкспе B5, не отдельный
  токен в тексте;
- на 444 живых уликах B5 — все 444 остались зелёными, 0 ложных тревог;
- на всём дереве: путей в кавычках проверено 11 019, битых 2131 (в 635
  различных целях). Из них 127 целей совпадают со списком B5. Из оставшихся
  508 целей проверка историей git (`git log --diff-filter=D --all`) нашла
  коммит удаления у 344 (940 упоминаний) — это мёртвые улики, которых прицельная
  выборка B5 не видела вовсе, потому что искала только рядом со словами вроде
  «закрыто»/«сторож». Для 164 целей (253 упоминания) коммита удаления не
  нашлось — кандидаты в ложную тревогу: явно шаблонные имена курса
  (`026-remove-duplicates...flang`), примеры для чужого языка в
  `docs/site/embedding.md` (`Factorial.cs`, `Field.java`), плейсхолдеры
  (`X.flang`, `NNNN-english-words.md`).

**Чем ограничено.** Проверка историей git занижает число подтверждённых мёртвых
улик: `git log` не понимает `..` в pathspec, поэтому упоминания вида
`../../flang/src/a.mjs` не находят свой коммит удаления, даже если путь
действительно мёртв. Часть из 164 «кандидатов в ложную тревогу» на деле
подтверждённые мёртвые улики, просто не через этот метод. Отдельно: время
прогона выросло примерно в 8 раз (45 с → около 380 с на этом дереве) —
цена лишних `свёртка`/`содержит` на тысячах кандидатов из кавычек.
