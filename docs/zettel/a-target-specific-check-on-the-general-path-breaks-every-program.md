# Проверка, знающая только один целевой язык, на общей дороге ломает ВСЕ программы: «Static» перестала проходить `flang check`, хотя её печатают в Go

«Проверить столкновения» (`emit-c.flang`) засевает таблицу занятых имён списком
«Зарезервировано в C» — сорок девять C-шных слов. Правило это целевое: у Go,
Rust, JS и C# свои списки и свои правила («Проверить столкновения Go» и далее), а
у `cpp`, `elixir`, `java` и `python` правила нет вовсе — проверка есть у пяти
целей печати из девяти.

Когда обёртку над C-шным правилом позвали из `repl_check_sources` — общей
дороги, по которой ходят `check`, `emit`, `package` и оболочка, — программа с
функцией «Static», которую печатают в Go и никогда в C, **перестала проходить
`flang check`**. Отказ приходил по поводу языка, которого у команды `check` нет
вовсе: целевой язык появляется только у `emit --target`.

Сам текст замечания в отрыве от печати читается неверно: на месте второго ИМЕНИ
там подставлена строка «зарезервировано в целевом языке: static». При печати в C
понятно, о каком языке речь; у `check` — не понятно ни о каком.

**Куда это кладётся.** В **строку таблицы целей** (`EMIT_TARGET_TABLE`,
`flang_repl.c`), полем `collision` — именем обёртки на flang или `NULL`, если
проверки у цели нет. Таблица и заведена под «что двоичный знает о цели печати
одной строкой»: там уже лежат слово ключа `--target`, имя точки входа и имена
файлов рантайма, и пустое имя файла там уже значит «поля у цели нет по
существу». `check`, `package` и оболочка шлют `NULL`; `emit` шлёт то, что стоит
в строке выбранной цели.

**Признак, ловящий такую ошибку заранее.** Если проверка засевается СПИСКОМ,
привязанным к одному целевому языку, — её нельзя звать оттуда, где целевой язык
не выбран. Общая дорога вправе спрашивать только то, что верно для всех целей
сразу.

**Чем подтверждено.** Ветка `a/починка-сторожа`, свод `f6ce7102`, 1 сентября
2026. Двоичный с проверкой на общей дороге против двоичного без правки:

```
общая дорога:  flang check зарезервировано.flang            → КОД 1
               FLANG_CLI: имена «Static» и «зарезервировано в целевом языке:
               static» дают один идентификатор «static»
строка цели:   flang check зарезервировано.flang            → КОД 0, stderr пуст
оба:           flang emit  зарезервировано.flang --target go → КОД 0, файлов 5
```

После переноса в строку цели `flang check`, `flang check --proof`, `flang
package` и оболочка на восьми программах дают вывод **байт в байт** такой же,
как двоичный без правки; меняется только `emit --target c`.

**Побочно закрылось расхождение** `check` и `check --proof` на одном файле: с
проверкой на общей дороге они давали разные вердикты (1 и 0), потому что
`--proof` идёт не через `repl_check_sources`, а через `proof_file`. Обе дороги
теперь шлют `NULL` и снова согласны.

**Чем ограничено.** Обёртки для остальных четырёх целей, у которых проверка есть
(Go, Rust, JS, C#), не написаны — поле стоит `NULL`. У каждой свой тип входа
(«Общее Rust», «Общее CSharp», «Раздача JS»), поэтому одной обёрткой на всех не
обойтись. Сегодня это значит: печать в Go узнаёт о столкновении по-прежнему
только на печати.
