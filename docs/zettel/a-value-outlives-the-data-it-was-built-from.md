# Значение flang переживает данные, из которых собрано, — и в C это ловится только прогоном

Конструкторы значений в напечатанном рантайме C имена полей и вариантов БЕРУТ, а
не копируют: `fl_variant_new` делает `variant->name = name`, и то же с именами
полей. Для напечатанного кода это верно и бесплатно — имена там строковые
литералы, живущие столько же, сколько программа. Для хозяина, собирающего
значение из данных, приехавших с провода, это ловушка.

**Что было.** Хозяин узла на C разбирал кадр в своё дерево JSON, собирал из него
значение flang и освобождал дерево на следующем кадре. Имена внутри значения
указывали в освобождённую память, и обработчик получал
`FLANG_MATCH_NOT_EXHAUSTIVE: разбор не покрывает значение <мусор>` — то есть имя
варианта, прочитанное из чужой памяти (в журнале оно выглядело набором
непечатаемых байтов). Рукопожатие при этом сходилось, связь работала, журнал
выглядел здоровым: ломалось ровно одно место — вызов обработчика.

**Чем лечится.** Имя копируется В АРЕНУ, где живёт и само значение:
`fl_text(ctx, имя, длина, &строка, &беда)` кладёт копию с нулём на конце, и
`строка.as.string.utf8` живёт ровно столько же, сколько значение.

**Класс, а не случай.** Правило шире одного языка: **всё, на что значение
ссылается по указателю, обязано жить не меньше значения.** Признак, по которому
третий случай ищется заранее: конструктор рантайма принимает `const char *` и не
обещает копии, а вызывающий передаёт указатель, полученный из ДАННЫХ, а не из
литерала. У остальных семи хозяев ловушки нет по построению — там имена ездят
владеющими строками (`String`, `Rc<str>`, `binary`, `str`).

**Чем ограничено, и почему это важно.** Сверка восьми целей на такую ошибку не
краснеет и краснеть не может: она сверяет ЗНАЧЕНИЯ, посчитанные напечатанным
кодом, а ошибка живёт в хозяине. Прогон работы поймал её сразу — это ещё один
случай к тому, что прогон работы и сверка целей ловят разное.

**Чем подтверждено.** `flang/conc/bin/node.c`, ветка `u/uzel`, коммит `afb42a9a`;
прогон `flang/test/uzel-celi.test.mjs`, пара «c ↔ python».
