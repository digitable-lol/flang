# Блок кода в документации, который обязан отказать, помечается внутри самого блока — иначе проверка страниц запрещает показывать настоящие отказы

Проверка, вынимающая блоки кода из готовой страницы и гоняющая на них
компилятор, ставит скрытое требование: **всё показанное обязано собираться**.
Требование это ложное, и цена его — сама честность текста.

Хороший учебный текст показывает отказы: пример, который не сходится на минус
нуле; программу, у которой два примера из трёх красные. Под правилом «каждый
блок проходит check» такие места пришлось бы вынести из проверки — а вынесенное
из проверки протухает первым, потому что именно там текст обещает конкретную
диагностику.

**Решение: ожидаемый исход объявляется в самом блоке, комментарием языка.**

```
// ОЖИДАЕТСЯ ОТКАЗ: этот блок НЕ собирается, и в этом всё дело.
модуль «Минус ноль»
…
```

Проверка читает пометку и **меняет знак ожидания**: такой блок обязан дать
ненулевой код возврата, а нулевой считается провалом. То есть правило работает в
обе стороны — чинится язык, перестаёт отказывать блок, и проверка краснеет,
требуя переписать текст.

**Почему пометка внутри блока, а не второй вид ограды.** Ограда с чужим именем
(```` ```flang-otkaz ````) выключила бы подсветку: она красит по имени языка, а
незнакомое имя для неё — запрет. Пометка комментарием остаётся частью программы:
её видит и лексер, и читатель, и она объясняет ему то же самое, что проверке.

**Разделение оград тем же решением становится контрактом.** Ограда с именем
языка — обещание автора «этот блок целиком собирается»; голая ограда — отрывок
(одна строка постусловия, скелет `разбор`а, вывод команды), который программой
не является и в проверку не попадает. Без такого разделения обещание «каждая
программа страницы проверена» нечем держать: в первом же прогоне 22 блока из 25
оказались отрывками, и общий вердикт был бы красным всегда.

**Чем подтверждено.** Курс `docs/kurs/` на ветке `vypusk/kurs`, коммит
`cb3b7a18`. Проверка написана на самом flang (`docs/kurs/proverka.flang`, план
`flang io`: перечислить каталог, прочитать страницы, вынуть блоки, записать во
временные файлы, позвать `flang check` процессом). Первый прогон по 14 страницам:
вынуто 25 блоков, не прошло 14. После разделения оград и трёх пометок:
**вынуто 17, не прошло 0**, из них три блока обязаны были отказать и отказали.

**Чем ограничено.** Проверка сверяет только **код возврата**, а не текст
диагностики. Блок, обязанный отказать по `FLANG_EXAMPLE`, отказавший по
`FLANG_PARSE`, она засчитает. Сверку кода диагностики стоит добавить тем же
приёмом — дописать его в ту же пометку, — но это ещё не сделано, и потому здесь
названо, а не обещано.
