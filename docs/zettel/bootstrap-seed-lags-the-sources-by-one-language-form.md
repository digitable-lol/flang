# Закоммиченная точка раскрутки отстала от исходников на одну форму языка, и из-за этого двоичный компилятор не проверяет три своих собственных модуля

`flang/self/lexer.flang` знает форму `символ по коду ЧИСЛО` (`charFromCode`,
четыре вхождения в таблицах слов). В `bootstrap/compiler_flang.c` строки
`charFromCode` нет ни одной. Значит собранный из точки раскрутки двоичный
компилятор эту форму не разбирает:

```
flang check проба.flang
FLANG_PARSE, строка 6, столбец 10: не разобрана конструкция: неожиданное 'по'
```

Тем же отказом падает `flang check flang/self/interpret.flang` (строка 2801,
`символ по коду «код»`), а за ним — всё, что через него ввозится:
`flang check flang/self/conc.flang` даёт 21 отказ вида «тотальная функция …
вызывает неизвестную функцию «Знач по ключу»», и `flang test` на нём отвечает
«примеры не запускались — программа не прошла проверку».

**Практическое следствие, из-за которого это стоит отдельной заметки.** Слой
процессов сейчас не проверяется ничем: категорную поверхность и процессы
двоичный не судит по построению (говорит об этом прямо и отвечает кодом 2), а
эталон планировщика `flang/self/conc.flang` тем же двоичным не проверяется
из-за устаревшего семени. Реализации на JavaScript больше нет (коммит
`fe8e8a37`), `npm test` не запускается вовсе — `scripts/preflight.mjs` ввозит
удалённый `flang/src/targets.mjs`. То есть правку в планировщик сегодня
**нечем проверить прогоном**, и это надо знать до того, как её начать.

**Чем подтверждено.** Ветка `u/ssylka` на основании `github/main` `7e8495ec`,
`bootstrap/` без единой правки в рабочем дереве, двоичный собран `make -C
bootstrap`, `flang --version` → 0.5.1. Все четыре отказа получены прогоном.

**Круг разомкнут — проверено прогоном, а не выведено.**
`flang emit flang/self/bootstrap/compiler.flang --target c --out КАТАЛОГ` идёт
10 минут 3 секунды и не печатает ни одного файла: тот же `FLANG_PARSE, строка
2801` на `символ по коду`, за ним каскад «неизвестный тип «Знач»», «неизвестный
тип «Итог прогона»», и сверх того `FLANG_RECURSION_LIMIT` — «Беды ядра» съели
40 000 001 виток из 40 000 000. Двоичный не воспроизводит сам себя.

**Чем лечится — и здесь курица с яйцом.** Перепечатывает точку раскрутки сам
двоичный (`sh scripts/raskrutka.sh`), а печатать он должен `compiler.flang`, в
замыкание которого входит `interpret.flang` — тот самый файл, который он не
разбирает. Руками `bootstrap/**` не правится: это семь напечатанных файлов,
сверяемых байт в байт. Значит либо форма `символ по коду` уезжает из
`interpret.flang` до перепечатки, либо семя поднимается тем же обходным путём,
каким поднимали предел шагов (раздел «КАК ПОДНЯТЬ ПРЕДЕЛ» в
`scripts/raskrutka.sh`): собрать промежуточный двоичный руками и печатать им.
