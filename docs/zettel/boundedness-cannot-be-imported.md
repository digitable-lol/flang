# Оценку витков нельзя ввезти ни в один слой компилятора: имена совпадают, а переименования при ввозе в языке нет

`flang/self/bounded.flang` объявляет имена вроде «Кадр», «Состояние», «Описание
функции», «Найти описание» — то есть ровно те слова, которыми любой другой слой
компилятора называет свои же вещи. Ввезти его в такой слой нельзя: язык считает
объявление одного имени в двух модулях ошибкой сборки `FLANG_DUPLICATE_NAME`, а
переименования при ввозе (`как`) в языке нет вовсе. Список `только …` от этого
не спасает: он не тянет зависимости за собой, поэтому назвать в нём приходится
ВСЕ имена, до которых достаёт нужная функция, — включая совпавшие.

**Чем подтверждено.** Пересечение верхних имён `bounded.flang` со слоями:

| слой | совпавших имён |
|---|---|
| `types.flang` | 4 |
| `totality.flang` | 4 |
| `interpret.flang` | 3 |
| `emit-elixir.flang`, `emit-csharp.flang` | 3 |
| `emit-c.flang`, `emit-js.flang`, `emit-python.flang` | 2 |

Попытка ввезти «Оценить витки» в `flang/self/conc.flang` (а он ввозит
`interpret.flang` целиком) дала две диагностики `FLANG_DUPLICATE_NAME` —
«Может быть описание» и «Найти описание», — и обе достижимы из «Оценить витки»,
то есть обойти их списком `только` нельзя.

**Что стоило обойти.** Три переименования внутри `bounded.flang` (10 вхождений:
«Кадр» → «Кадр вызова», «Может быть описание» → «Может быть описание оценки»,
«Найти описание» → «Найти описание оценки») плюс ОДНА строка в проверке
`flang/test/self-bounded.test.mjs`, которая звала «Кадр» по имени. После этого
ввоз прошёл, и слой планировщика собрался.

**Чему учит.** Дешевле переименовать, чем городить обход, — но цена растёт с
каждым следующим потребителем: чтобы тот же анализ ввезли `totality.flang` и
`types.flang`, придётся развести ещё восемь имён. Общего имени у слоя нет, и
пока его нет, каждое такое соединение будет стоить отдельного переименования.
