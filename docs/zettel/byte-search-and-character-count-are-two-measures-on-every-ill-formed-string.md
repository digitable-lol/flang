# Байтовый поиск и знаковый счёт — это две меры на всякой строке, которая не является правильным UTF-8

SPEC (раздел 5) с 20 августа 2026 обещает: «Все формы над строкой считают ЗНАКИ».
Обещание было выполнено только у трёх целей из восьми — у тех, где строка UTF-16
(JavaScript, Java, C#), — и подпёрто доводом, который **неверен**: «в UTF-8 (C, Go,
Rust, Elixir) и в последовательности кодовых точек (Python) такого значения нет
вовсе». Значение есть. Строка у C, Go и Elixir — произвольные октеты, и негодные
октеты в язык приезжают.

## Улика: контрпример втаскивается ЗАПУСКОМ, а не только библиотечным входом

Считалось, что этот класс ошибок прогоном не ловится: «разбор доводов `flang run
--args` его отвергает». Отвергает он только запись `\uXXXX` с суррогатом. Сырые
октеты проходят насквозь:

```
flang run проба.flang --function «Длина» --args "$(printf '{"текст": "\274\320"}')"
→ 1
```

Замер на точке раскрутки `55292de6` (двоичный собран из неё же):

| прогон | ответ | почему он ложь |
|---|---|---|
| `«мама» содержит` октеты `BC D0` | да | ни один знак «мамы» им не равен, и ни одна подстрока его не даёт |
| `«мама» начинается с` октета `D0` | да | первый знак «мамы» — «м», то есть `D0 BC` |
| `разделить «маму»` по октету `D0` | 5 кусков | в «маме» четыре знака, куски — половинки знаков |
| `длина` строки `BC D0` | 1 | а `разложить … на символы` даёт **два** куска |
| `пусто` строки из одного `BC` | да | при этом `содержит` её находит, а `разделить` отвергает как пустую |

Последняя строка таблицы — не только расхождение мер. `«разложить … на символы»`
выделяет массив по `длине`, а кладёт в него по своей нарезке: на строке,
начинающейся октетом продолжения, кусков на один больше, чем ячеек, и последний
пишется **за конец массива**. Ячейку за концом арена отдаёт следующему, кто
попросит, и второй кусок НЕИЗМЕНЯЕМОГО списка меняет тип сам собой — прогон
драйвера на C, зовущего рантайм напрямую:

```
до правки:    кусков 2: «BC»(строка) «D0»(строка)  → после чужого выделения:
              кусков 2: «BC»(строка) ТИП 1, ЧИСЛО 777
после правки: оба раза «BC»(строка) «D0»(строка)
```

AddressSanitizer этой записи не показывает: она внутри большого блока арены.
Аренный распределитель прячет выход за границу от сторожа памяти — это стоит
помнить всякий раз, когда «ASan молчит» принимают за доказательство.

## Где кончалась одна мера и начиналась другая

| форма | мера до правки | где |
|---|---|---|
| `длина`, `подстрока`, `символ … в …`, `разложить`, `пусто`, `голова и хвост` | знаки | C, Go, Elixir |
| `содержит`, `начинается с`, `разделить … по …` | **октеты** | C (`memcmp`), Go (`strings.Contains`), Elixir (`String.contains?`) |
| `соединить` | октеты, без сторожа стыка | C, Go, Elixir |
| `голова и хвост` | **графемы** | Elixir (`String.first`, `String.slice`) |

Графемы у Elixir расходились не на негодных октетах, а на **обычном тексте**: «е»
с комбинирующим ударением (U+0435 U+0301) — одна графема и две кодовые точки. Семь
целей отвечали `длина головы` = 1, Elixir — 2. Обход строки по «голова и хвост»,
то есть ровно тот, который SPEC советует, видел там один знак вместо двух.

## Чем сведено к одной мере

Началом знака считается первый октет строки всегда, дальше — все, кроме октетов
продолжения. По этому делению считают, режут, адресуют и ищут все формы: у
найденного вхождения оба края обязаны стоять на границе знака. `соединить`
отказывает на стыке, где октет продолжения прирос бы к последнему знаку левой
строки, — тем же отказом, каким цели с UTF-16 отвечают на слипание половин
суррогатной пары.

Плата, замеренная: `flang check` на `flang/stdlib/strings.flang` (90 КБ), лучшее из
семи — 2,14 с до правки, 2,30 с после, то есть около 7 %. Ответы на всяком
правильном UTF-8 не изменились ни в одной программе дерева.

## Граница, которую эта правка НЕ снимает

Внутри цели мера теперь одна. Между целями число знаков у негодной строки разное, и
это свойство хранения: `E0 80 41` в C — два знака, в Go — три (его декодер отдаёт
руну ошибки на каждый октет), в UTF-16 такой строки нет, в Python и Rust её не
бывает вовсе. Свести и это к одному ответу можно только запретом негодной строки на
входе в язык — а он отнял бы у `«Прочитать файл»` двоичное чтение и заставил бы
`«Прочитать из соединения»` отказывать на куске TCP, законно разрезавшем знак.
