# Проверки переезжают на flang планами ввода-вывода, а упираются в журнал поручений

Проверка не разбирает `.flang` сама — она запускает компилятор и читает ответ.
Значит, это план из поручений, и словарь `flang io` покрывает всё, что ей нужно:
`Запустить процесс` даёт `git ls-files` и сам компилятор, `Прочитать файл` —
исходники, а решение остаётся тотальными функциями с примерами. Три проверки
переехали так за один заход и отвечают то же, что отвечали на JavaScript.

**Чем подтверждено.** Ветка `u/osnastka`, коммиты `ef6764d5`, `69b26db7`,
`55214e34`. `scripts/storozh-ssylok.flang` — 880 ссылок в 467 файлах Markdown,
битых 2, ровно те же две, что называл `scripts/link-guard.mjs`, 4,3 с.
`scripts/storozh-licenzii.flang` — 81 публикуемый исходник, 0 отказов, 2,8 с.
`flang/scripts/poddelki-yadra.flang` — 3 подделки, аксиом ноль, 2,0 с.

**Что мешает следующим, числом.** `flang io` печатает журнал ВСЕХ поручений и
молчать не умеет: ключей `--quiet`/`--no-log` нет. На зелёном ответе сторож
ссылок пишет 6,8 МБ, лицензионный — 3,7 МБ; полезная строка стоит первой
(`"result"` идёт до `"log"`), но её приходится вырезать. На провале журнала нет
вовсе — там печатается только `{"error":…}` и код 1, и это как раз то, что нужно
проверке. Из-за журнала не переносится `code-guard`: ему нужно прочесть 1136
исходников, 45 МБ, и зелёный ответ стал бы нечитаемым.

**Поправка (ветка `u/port5`).** Здесь стояло «из-за журнала не переносится
`code-guard`». Он перенесён — `flang/scripts/code-guard.flang`, ярлык
`codes:check`, — и упор снят не терпением, а сменой вопроса к хозяину: файлы
читать не надо вовсе. Вместо 1136 чтений идут ДВА `git grep`, и весь ответ
разбирается строками:

```
git -C ../.. grep -n -I -e FLANG_ -- '*.md'        936 строк, 150 КБ
git -C ../.. grep -h -I -e FLANG_ -- . ':!*.md' …  1938 строк, 775 КБ
```

Журнал получается 1,2 МБ вместо 45 МБ, прогон — 7,5 с против 1,2 с у
предшественницы, вердикт совпал знак в знак (4 нарушения, те же имена и места).
Мера общая: **если проверке нужны не файлы, а вхождения, спрашивать надо
вхождения** — тогда журнал поручений перестаёт быть препятствием, потому что
поручений становится два.

Заодно ушёл дефект, которого у чтения-с-диска было не видно: обход файловой
системы читал НЕОТСЛЕЖИВАЕМЫЕ продукты сборки. Замерено: после прогона
`packaging/postinstall.mjs` в дереве появился каталог `dvoichnyy/`, и вердикт
`code-guard.mjs` изменился. `git grep` их не видит по построению.

**Отвергнуто.** Обходить это через `«Показать»` нельзя: двоичный не отвечает на
него `«Сбой»`, как обещает `flang/cat/SPEC.md`, а прекращает весь прогон —
`{"error":"у двоичного хозяина нет экрана"}`, код 1, и план отклика не видит.
То есть у плана нет ни одного способа сказать человеку хоть слово до конца
работы.

**Позднее измерение отменяет предыдущий абзац наполовину.** На двоичном 0.5.1
`«Показать»` приходит откликом `«Сбой»` с кодом `FLANG_IO_NO_SCREEN`, и прогон
после него продолжается — см. [[pokazat-otvechaet-sboem-a-ne-ronyaet-progon]].
Сказать человеку слово до конца работы по-прежнему нечем, но попытка перестала
быть смертельной.

**Что оказалось НЕ нехваткой.** Ни одной новой команды двоичному не
понадобилось: `check --proof --json`, `check` и `io` покрыли все три переноса.
Разбор ответа — по меткам ключей, как в `fspec/guard.flang`, и по той же
причине (см. [[proverka-zovushchaya-kompilyator-perenositsya-na-flang-mehanicheski]]:
у `flang/stdlib/json.flang` нет доступа к полю по имени, а три его собственных
утверждения имеют вердикт `grid`). Прогонщик (`{"fn":…}` на вход) при этом
открывает только функции самого компилятора — `«Разобрать json»` через него не
зовётся; проверке он и не нужен.

**Приёмы, которые пришлось найти.**

- Существование пути проверяется не обращением к диску, а одной строкой
  `git ls-files`: путь есть, если в ней встречается «\n путь \n», каталог —
  если «\n путь /». Поиск подстроки встроенный, поэтому 880 ссылок стоят долей
  секунды. Замер: оба способа отвечают одинаково по каждой из 880, расхождений 0.
- Разбор ссылок `[текст](цель)` без регулярных выражений — разделением по `](`
  с двумя проверками (открывающая скобка на той же строке, закрывающая после).
  На 467 файлах даёт ровно те же 880 ссылок, что маска на JavaScript.
- Пара слов `голова и хвост` занята языком под образец списка, и в списке
  доводов вызова её не написать: `«Ф» от голова и хвост и (…)` не разбирается.
  Лечится порядком доводов, а не переименованием — имена образца закреплены.
- Тело функции обязано быть ОДНОЙ строкой: цепочка `и притом`, разложенная на
  три строки, читается как «у функции больше одного тела».
- Пример не вычисляется: `ожидается вариант «Х» с поле равным («Функция»)` —
  отказ, нужен литерал целиком.
- `нат` не замкнут по сложению: при `позиция: нат` выражение `позиция плюс 1`
  имеет тип `число`, и объявить счётчик натуральным нельзя без потери типа на
  первом же шаге.
