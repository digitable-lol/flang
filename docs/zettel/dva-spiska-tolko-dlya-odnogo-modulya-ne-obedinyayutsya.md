# Два разных списка `только` для одного модуля в одном замыкании не объединяются, и имя, названное лишь одним из них, становится неизвестным

Если два файла замыкания ввозят один и тот же модуль с разными списками
`только`, видимым оказывается не объединение списков. Имена, названные лишь в
одном из них, компилятор объявляет неизвестными — и в файле, который их сам же
и просил.

Наблюдение, из которого это выведено. `flang/examples/db/postgres-plan.flang`
ввозит:

```
использует «UTF-8» только «Кодовые точки текста», «Кодовые точки из байтов»,
  «Ход разбора utf8», «Начало разбора utf8», «Начать байт», «Шаг разбора utf8»,
  «Закрыть разбор utf8»
```

а `flang/stdlib/postgres.flang`, который тот же план ввозит целиком, — тот же
модуль, но короче:

```
использует «UTF-8» только «Байтов в точке», «Одинокий суррогат»
```

`flang check` на плане отвечает:

```
FLANG_UNKNOWN_NAME: неизвестная функция «Кодовые точки текста»
FLANG_UNKNOWN_NAME: неизвестная функция «Кодовые точки из байтов»
```

— то есть видны два имени из короткого списка, а семь из длинного пропали, хотя
просил их сам проверяемый файл.

**Чем подтверждено.** Прямая подмена: в короткий список дописаны семь имён из
длинного, и отказ ушёл (появился следующий, про другое имя, — уже настоящее
столкновение объявлений). Ничего другого при этом не менялось. 21 августа 2026,
ветка сборки `svod/u2`, двоичный собран из точки раскрутки того же дерева.

**Чем это кусает.** Модуль библиотеки, начавший ввозить соседа выборочно,
молча сужает этого соседа для ВСЕХ, кто ввозит модуль дальше по цепочке. Правка
выглядит местной — добавили одну строку `использует … только` в свой файл, — а
ломается чужой файл, который этой строки не видит и своего списка не менял.

**Чего отсюда не следует.** Здесь не разбиралось, какой из двух списков
побеждает — первый по обходу, последний или самый короткий. Померено только то,
что объединения не происходит.

**Чем ограничено.** Один случай, один вид ввоза (по имени модуля). На ввозе
через путь то же самое не проверялось.
