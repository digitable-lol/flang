# Закоммиченный в `main` двоичный отстал от исходников того же коммита: им не разбирается `stdlib/lists.flang`

На `github/main` (`5dba79c5`) собранный из `bootstrap/*.c` компилятор отвечает на
файл собственной стандартной библиотеки:

```
FLANG_PARSE в файле flang/stdlib/lists.flang, строка 666, столбец 103:
у 'если' нет ветки 'то'
```

Двоичный, напечатанный из исходников ТОГО ЖЕ коммита (`sh scripts/raskrutka.sh`
плюс `make -C bootstrap`), тот же файл разбирает без замечаний. Значит
закоммиченное семя — не то, что печатают текущие исходники, и точка раскрутки с
деревом разъехалась.

**Чем это опасно.** Ведомость корпуса считается двоичным
(`flang/scripts/proof-ledger.mjs` зовёт `flang check --proof --json`), поэтому
файл, который двоичный не берёт, из ведомости просто ВЫПАДАЕТ вместе со всеми
своими утверждениями — и с утверждениями всех, кто его импортирует. Ведомость при
этом зеленеет: «без ведомости» — обычная строка, каких там четыре десятка.

Разница на числах, замер 21 августа 2026: закоммиченным двоичным ведомость даёт
файлов 251, высказано 882, доказано ядром 341; двоичным из тех же исходников —
файлов 255, высказано 961, доказано ядром 364. То есть **79 утверждений и 23
доказательства не видно** просто потому, что мерили устаревшим семенем.

**Правило на будущее.** Замер «до и после» на ядре доказательств обязан брать оба
двоичных, НАПЕЧАТАННЫЕ из своих исходников. Взять «до» у закоммиченного семени —
значит сравнить не два ядра, а два разных корпуса, и приписать своей правке чужой
прирост.

**Чем подтверждено.** Ветка `u/dlina`. Двоичный из `git show HEAD:bootstrap/*` +
`make` — отказ на `lists.flang`; двоичный из `raskrutka.sh` на том же дереве —
проходит. Обе ведомости сняты одним и тем же `proof-ledger.mjs`.

**Чем ограничено.** Причина расхождения не искалась: неизвестно, отстало ли семя
на одну правку разбора языка или на несколько, и когда именно.
`sh scripts/raskrutka.sh --check` на чистом `main` не прогонялся.
