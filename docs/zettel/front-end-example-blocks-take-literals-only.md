# В примере годятся только литералы, и ещё две грабли записи, стоившие прогонов

Три отказа, снятые 26 августа 2026 при дописывании примеров в `flang/self/**`
двоичным `/srv/flang-rabota/w-predely/bootstrap/flang`. Ни один не про силу ядра:
это разбор ключей и разбор примера, то есть прогон кончается, не дойдя до дела.

## 1. `ожидается` и `дано` берут ЛИТЕРАЛ, а не вызов

Тело функции вправе звать нульместную функцию; блок примера — нет.

```flang
// тело — так можно
запись «Описание функции» с … и «тело» равным «Узел ничто» и «мера» равным («Без меры»)

// пример — так НЕЛЬЗЯ
  ожидается (запись «Описание функции» с … и «тело» равным «Узел ничто» …)
```

```
FLANG_PARSE, строка 2331, столбец 15: не разобрана конструкция: ожидалось
литеральное значение — примеры не вычисляются: годятся число, строка, 'да',
'нет', 'ничто', список из них, 'запись «Имя» с «поле» равным …' и
'вариант «Имя» с поле равным …'
```

Отказ называет причину прямо, и это редкость — но он приходит на ВЕСЬ файл, а не
на одну функцию: примеры не запускаются вовсе, и остальная работа остаётся
непроверенной.

**Лечится подстановкой самого литерала.** `«Узел ничто» = вариант «Значение
скаляра» с «скаляр» равным (вариант «Скаляр ничто»)` — его и пишут:

```flang
  ожидается (запись «Описание функции» с … и «тело» равным
    (вариант «Значение скаляра» с «скаляр» равным (вариант «Скаляр ничто»)) …)
```

Практический порядок: прежде чем писать пример нульместному «конструктору»,
разверните все вызовы в его теле до литералов. Если развернуть нечем — примера у
этой функции не будет, и её доказанные постусловия останутся сторожами.

## 2. Ёлочки внутри заголовка примера рвут заголовок

Заголовок примера сам стоит в ёлочках, вложенные не экранируются:

```flang
  пример «Сам «н» — часть себя глубины ноль»     // рвёт разбор
  пример «Сам параметр — часть себя глубины ноль» // так
```

Отдельно неприятно тем, что ловится это только прогоном, а глазами читается как
обычный русский текст. Проверять дёшево: заголовок примера не должен содержать
ни `«`, ни `»` внутри.

## 3. Потолок шагов: `emit` его не поднимает ничем

Три прогона, и они складываются в одно правило. Двоичный
`/srv/flang-rabota/w-predely/bootstrap/flang`, 26 августа 2026.

```
$ flang emit … --предел-шагов 5000000000
flang emit: непонятный ключ «--предел-шагов»          ← русский ключ ОТВЕРГНУТ

$ flang emit … --max-steps 3000000000
напечатано файлов 6, байт 320318                       ← ASCII-синоним ПРИНЯТ

$ flang emit flang/self/link.flang … --max-steps 3000000000
FLANG_RECURSION_LIMIT: функция «Найти описание» исчерпала лимит шагов
(1000000000) на глубине вызовов 46                     ← и НЕ ПРИМЕНЁН
```

То есть `--max-steps` у `emit` **принимается молча и на потолок ядра не влияет**:
прогон умер на том же миллиарде, что и без ключа. Это хуже отказа — отказ виден
сразу, а принятый и забытый ключ читается как «я поднял предел», хотя не поднял.

У `check` тот же ключ работает: `check flang/self/link.flang --proof
--предел-шагов 3000000000` уходит далеко за миллиард, тогда как `emit` того же
файла умирает на нём за минуту.

**Практическое следствие, и оно неприятное.** Число «проверок при работе снято
N» печатает ТОЛЬКО `emit`. Значит у файла, чьё замыкание не влезает в вшитый
миллиард, этого числа не получить вовсе: `check` досчитает, но такой строки не
напечатает, а `emit` напечатал бы, да не досчитает.

Так и вышло с `link.flang`. До дописывания примеров его `emit` проходил с
предупреждением «ЗАПАС ШАГОВ НА ИСХОДЕ: съел 860 412 444 витков из 1 000 000 000
(86 %)». После — 1 000 000 001 из 1 000 000 000, и печать отменена. Работа тут
ни при чём: **предупреждение о 86 % было сказано заранее и оказалось точным
предсказанием.** Читайте эту строку как срок годности замера, а не как шум.
