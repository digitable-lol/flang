# В примере годятся только литералы, и ещё две грабли записи, стоившие прогонов

Три отказа, снятые 26 августа 2026 при дописывании примеров в `flang/self/**`
двоичным `/srv/flang-rabota/w-predely/bootstrap/flang`. Ни один не про силу ядра:
это разбор ключей и разбор примера, то есть прогон кончается, не дойдя до дела.

## 1. `ожидается` и `дано` берут ЛИТЕРАЛ, а не вызов

Тело функции вправе звать нульместную функцию; блок примера — нет.

```flang
// тело — так можно
запись «Описание функции» с … и «тело» равным «Узел ничто» и «мера» равным («Без меры»)

// пример — так НЕЛЬЗЯ
  ожидается (запись «Описание функции» с … и «тело» равным «Узел ничто» …)
```

```
FLANG_PARSE, строка 2331, столбец 15: не разобрана конструкция: ожидалось
литеральное значение — примеры не вычисляются: годятся число, строка, 'да',
'нет', 'ничто', список из них, 'запись «Имя» с «поле» равным …' и
'вариант «Имя» с поле равным …'
```

Отказ называет причину прямо, и это редкость — но он приходит на ВЕСЬ файл, а не
на одну функцию: примеры не запускаются вовсе, и остальная работа остаётся
непроверенной.

**Лечится подстановкой самого литерала.** `«Узел ничто» = вариант «Значение
скаляра» с «скаляр» равным (вариант «Скаляр ничто»)` — его и пишут:

```flang
  ожидается (запись «Описание функции» с … и «тело» равным
    (вариант «Значение скаляра» с «скаляр» равным (вариант «Скаляр ничто»)) …)
```

Практический порядок: прежде чем писать пример нульместному «конструктору»,
разверните все вызовы в его теле до литералов. Если развернуть нечем — примера у
этой функции не будет, и её доказанные постусловия останутся сторожами.

## 2. Ёлочки внутри заголовка примера рвут заголовок

Заголовок примера сам стоит в ёлочках, вложенные не экранируются:

```flang
  пример «Сам «н» — часть себя глубины ноль»     // рвёт разбор
  пример «Сам параметр — часть себя глубины ноль» // так
```

Отдельно неприятно тем, что ловится это только прогоном, а глазами читается как
обычный русский текст. Проверять дёшево: заголовок примера не должен содержать
ни `«`, ни `»` внутри.

## 3. Потолок шагов: у `emit` его не поднять, и мерить надо запас, а не прибавку

Умолчание вшито в двоичный: `bootstrap/flang_runtime.h:11` →
`#define FL_MAX_STEPS 1000000000`. Число `MAX_STEPS=4000000000` в
`scripts/raskrutka.sh` — настройка ПЕРЕПЕЧАТКИ, а не двоичного, и путать их
дорого: ключ `--предел-шагов` **ЗАДАЁТ** предел, а не поднимает, так что
поставленный «с запасом» миллион его понижает вдесятеро.

### Строка «ЗАПАС ШАГОВ НА ИСХОДЕ» — это порог ровно в половину

`bootstrap/flang_repl.c:1288`:

```c
if (!repl_call_quiet && repl_ctx.max_steps > 0 && repl_ctx.steps > repl_ctx.max_steps / 2)
```

Отсюда важное: **отсутствие этой строки — это измеренное «ниже 50 %», а не
молчание.** Её можно и нужно читать как замер.

### Ключ у `emit` принимается и не применяется

Три прогона двоичным `/srv/flang-rabota/w-predely/bootstrap/flang`:

```
emit … --предел-шагов 5000000000   → flang emit: непонятный ключ «--предел-шагов»
emit … --max-steps 3000000000      → ключ ПРИНЯТ, печать прошла
emit link.flang … --max-steps 3e9  → FLANG_RECURSION_LIMIT: «Найти описание»
                                      исчерпала лимит шагов (1000000000)
```

`--max-steps` у `emit` **принимается молча и на потолок ядра не влияет**. Это
хуже отказа: отказ виден, а принятый и забытый ключ читается как «предел
поднят». У `check` тот же ключ работает.

**И отсюда ловушка при снятии базы.** Если базовый замер снят с
`--предел-шагов 5000000000`, то порог предупреждения при нём 2.5 млрд, и
«предупреждения нет» в таком прогоне НЕ ГОВОРИТ НИЧЕГО о том, влезает ли файл в
умолчание. Базу надо снимать тем же пределом, каким будут мерить потом.

### Ломает не прибавка, а тонкий запас — замер на двух файлах разом

Один и тот же набор из 268 дописанных примеров, два файла контура компилятора:

| прогон | до | после |
|---|---|---|
| `check parser.flang --proof` | 668 929 200 (66 %) | 671 599 190 (**67 %**) |
| `emit link.flang` | 860 412 444 (86 %) | **1 000 000 001 — печать отменена** |

В `parser.flang` те же примеры стоили **+2 669 990 витков, то есть +0.27
пункта**, и файл как проверялся, так и проверяется. В `link.flang` тот же набор
уронил прогон — не потому, что он дорогой, а потому, что **запас там был 14 %,
о чём предупреждение сказало заранее.**

Правило: смотреть не на то, сколько прибавила правка, а на то, сколько запаса
было ДО неё. Файл выше 50 % — это файл, у которого следующая правка может
оказаться последней.

### И почему дешёвый `check` этого не ловит

`check` без `--proof` ведомости не считает и в предел не упирается — он пройдёт
и на файле, который с `--proof` уже не проверяется. `flang test` не считает её
тоже. Значит зелёные примеры и зелёный дешёвый `check` про предел не говорят
ничего: смотреть надо полный `check --proof` без ключа предела.
