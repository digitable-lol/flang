# Охрана берётся не только из ВЕРХНЕГО `если`: замеры на стенде, приложениях и правиле приёмки спек

Справочник `docs/site/kak-dokazat.ru.md` говорит про форму 1: охрана обещания
списывается из тела дословно, и тело при этом «начинается ветвлением». Четыре
замера 26 августа 2026 расширяют это тремя случаями, где верхнего `если` нет
вовсе, а форма всё равно работает, и одним, где не работает.

**Чем подтверждено.** `check --proof` двумя двоичными:
`/srv/flang-rabota/w-predely/bootstrap/flang` (сборка 23 августа) на `web/**` и
`bootstrap/flang` этого дерева (0.6.2) на `fspec/policy.flang`.

## 1. `если` внутри строящегося варианта — берётся

У `«Ждать»` (`web/app/hailstone.flang`) тело — построение варианта, а ветвление
спрятано в поле:

```flang
вариант «Сделать» с поручение равным (вариант «Ждать событие» с срок равным (если полёт.бежит то 350 иначе 0)) и потом равным полёт
```

Обе половины, списанные с этого внутреннего `если`, **доказаны**:

```flang
обеспечивает «…» если не полёт.бежит то (результат равен (вариант «Сделать» с поручение равным (вариант «Ждать событие» с срок равным 0) и потом равным полёт)) иначе да
обеспечивает «…» если полёт.бежит то (… срок равным 350 …) иначе да
```

## 2. Связанное `пусть`, подставленное в охрану ВЫРАЖЕНИЕМ, — берётся

Справочник знал это по `registry.flang`. Подтверждено на двух функциях
`web/stand.flang`, чьё тело начинается связыванием, а `если` стоит вторым:

```flang
пусть хвост равно (если путь начинается с "/" то (подстрока путь с 2 по (длина путь)) иначе путь)
если («Путь уводит вверх» от хвост) или (пусто хвост) то "" иначе хвост
```

Охрана, где `хвост` заменён своим определением ЦЕЛИКОМ и дважды, и заключение
`результат равен ""` — **доказано**. То же у `«Файл по цели»`. Обе функции до
этого несли по одному сеточному обещанию, и оба остались сеткой: приём не
чинит старое обещание, а даёт рядом новое и доказанное.

## 3. Охрана, называющая литерал, которого в теле НЕТ, — сетка. Отрицание условия тела — доказано

Самый резкий из четырёх. У `«Доказано»` (`fspec/policy.flang`) тело —

```flang
(пункт.«вердикт» равно "proved") или (пункт.«вердикт» равно "proved-induction")
```

Три обещания вида «если вердикт равно `"grid"` / `"declared"` / `"violated"`, то
результат равен `нет`» — **все три сетка**: чтобы их свести, ядру нужно знать,
что `"grid"` не равно ни одному из двух литералов тела, а правила несовпадения
строк у него нет. Та же мысль, записанная ОТРИЦАНИЕМ УСЛОВИЯ ТЕЛА, —

```flang
обеспечивает «…» если не ((пункт.«вердикт» равно "proved") или (пункт.«вердикт» равно "proved-induction")) то (результат равен нет) иначе да
```

— **доказана**, и она вдобавок сильнее: говорит про все прочие вердикты, а не
про три названных. Три сетки заменены одним доказанным.

**Правило, которое из этого следует:** литералы в охране берите ИЗ ТЕЛА. Свой
литерал в охране — это уже не «списано дословно», даже когда тип тот же.

## 4. Разложение конъюнкции на строковых целях — ноль из четырёх

`web/stand.flang`, четыре составных обещания про строки (`начинается с`,
`содержит`, `«Заканчивается на»`), разложены на семь. Прибавка **ноль**:
знаменатель 128 → 135, `доказано` 43 → 45 (и оба прироста — из пункта 2, не из
разложения), `сетка` 85 → 90. Всё разложение откачено.
