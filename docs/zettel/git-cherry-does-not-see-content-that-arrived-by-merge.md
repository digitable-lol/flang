# `git cherry` не видит содержимое, приехавшее в ветку слиянием, — «своего ноль» надо перепроверять сравнением деревьев

`git cherry ствол ветка` отвечает на вопрос «какие патчи ветки в стволе ещё не
лежат» и отвечает честно — но **разбирает только обычные коммиты, а коммиты
слияния пропускает целиком**. Между тем содержимое умеет попадать в ветку именно
слиянием: разрешая конфликт, автор пишет в коммит слияния файл, которого нет ни у
одного из двух родителей. Такой файл для `git cherry` невидим, и ветка отчитается
«своего ноль», держа в дереве работу, которой в стволе нет.

Проверять надо **вторым вопросом и по деревьям, а не по истории**:

```
git diff --name-status ствол ветка | grep '^A'
```

Это файлы, которые в ветке есть, а в стволе нет, — независимо от того, каким
коммитом они там появились. Список обычно короткий, и каждую строку в нём надо
объяснить: либо файл в стволе сознательно удалён, либо переименован, либо это
настоящая невлитая работа.

**Оба ответа нужны, ни один не заменяет другого.** `git cherry` ловит правку
существующего файла, сравнение деревьев её не видит вовсе. Сравнение деревьев
ловит новый файл из слияния, `git cherry` не видит его вовсе.

**Чем подтверждено.** 19 августа 2026, ветка `work/checks-in-flang`
(`/srv/flang-rabota/vypil`). `git cherry github/main FETCH_HEAD` дал два патча, и
оба уже лежали в стволе по существу. Сравнение деревьев дало семнадцать файлов, и
пятнадцать из них объяснились сознательным удалением (`3a6c59f2`, «Свидетель
законов выброшен: семь модулей на JavaScript») — а две заметки базы знаний,
`an-exit-code-cannot-come-from-a-named-failure.md` и
`a-wrapper-that-rejects-on-nonzero-exit-hides-the-result.md`, оказались настоящей
невлитой работой. Приехали они в ветку коммитом слияния `b3dfe005`; ни у одного
из его двух родителей их нет — проверено `git cat-file -e` по обоим. Нашлись
только через `git log --full-history`, обычный `git log <путь>` их тоже не
показывает.

**Чем ограничено.** Второй вопрос закрывает НОВЫЕ файлы. Правка внутри файла,
дописанная в коммите слияния, невидима обоим приёмам, и третьего дешёвого приёма
для неё нет — остаётся читать сами коммиты слияния (`git show -c`). На перечне из
двадцати трёх рабочих копий такой правки не нашлось, но искали её не переписью, а
выборочно: утверждать, что её не бывает, оснований нет.
