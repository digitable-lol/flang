# `git ls-files | grep '\.flang$'` насчитал 390 файлов там, где их 826: git берёт пути с не-ASCII в кавычки

Замер «сколько файлов `.flang` в дереве» дал два ответа сразу: `find` — **826**,
а `git ls-files | grep -c '\.flang$'` — **390**. Оба вывода выглядели
достоверно, и из меньшего следовал ложный вывод: «436 файлов не под версией».

Причина — в выводе git, а не в дереве. По умолчанию включён `core.quotepath`,
и путь, где хоть один знак вне ASCII, печатается в двойных кавычках с
восьмеричными подстановками:

```
benchmarks/model-authoring/out/M3/records.jsonl
"benchmarks/model-authoring/out/M3/\320\260/r0/a1-summa-do.flang"
```

Строка кончается не на `.flang`, а на `.flang"` — и якорь `$` в регулярном
выражении мимо. Пропали ровно те 436 файлов, что лежат в каталогах, названных
русскими буквами (`а`, `б`, `р` — имена ходов замера).

**Как считать правильно** — любой из двух способов, оба проверены на этом же
дереве и оба дают 826:

```
git -c core.quotepath=false ls-files | grep -c '\.flang$'
git ls-files -z | tr '\0' '\n' | grep -c '\.flang$'
```

**Чем подтверждено.** 20 августа 2026, ветка сборки `svod/granica`, коммит
`d44898e0`. Три замера подряд: `find` 826, `git ls-files` 390,
`git -c core.quotepath=false ls-files` 826. Разница 436 — все файлы под
`benchmarks/model-authoring/out/*/{а,б,р}/`.

**Чем ограничено.** Только про имена вне ASCII, и потому ловушка молчит ровно
до того дня, когда в дереве заводят русский каталог. Здесь это язык, у которого
русские имена — не украшение, так что молчать она перестанет ещё не раз. На
`git status` и `git diff` то же правило распространяется: они кавычат так же.
