# Запас шагов — общий кошелёк замыкания, а не свойство файла

Проверка `flang check` считает витки не по файлу, а по ВСЕМУ ЗАМЫКАНИЮ: файл
вместе со всем, что он ввозит. Предел один на прогон — 1 000 000 000 витков,
вшитое умолчание (`bootstrap/flang_runtime.h:11`). Отсюда следствие, которое
дорого стоит, если о нём не знать: **обещание, дописанное в модуль-основание,
тратит запас у КАЖДОГО, кто этот модуль ввозит.**

## Замер

26 августа 2026, `scripts/**`. В `scripts/releases.flang` — чистом модуле,
считающем страницу «Выпуски», — не стояло ни одного обещания. Дописано 30,
все верные и все в формах, которые ядро берёт. Прогон:

```
ЗАПАС ШАГОВ НА ИСХОДЕ: «Ведомость исходников» съел 1000000001 витков
из 1000000000 (100 %)
FLANG_RECURSION_LIMIT: функция «Есть вызов в полях» исчерпала лимит шагов
```

И вместе с ним перестали проверяться ОБА плана, которые его ввозят, —
`releases-page.flang` и `releases-page-verify.flang`, — хотя в них самих
дописано было по десятку, а не по тридцати. Снятие девяти обещаний в основании
запаса не вернуло: 21 обещание в `releases.flang` дают те же 100 %.

## Как читать предупреждение

Строка «ЗАПАС ШАГОВ НА ИСХОДЕ» печатается строго при `витков > предел / 2`
(`bootstrap/flang_repl.c:1288`). Значит:

* строки нет — это **измеренное «ниже 50 %»**, а не молчание;
* строка есть — названный процент и есть срок годности вашего замера.

⚠ **База, снятая с поднятым `--предел-шагов`, немая.** Порог предупреждения
считается от того же предела, поэтому при `--предел-шагов 5000000000` строка
молчит до 2,5 млрд, и «предупреждения нет» не говорит ничего о том, влезает ли
файл в умолчание. Базу снимают БЕЗ ключа.

## Порядок, который из этого следует

1. Снять базу каждого файла БЕЗ ключа и записать процент.
2. Файл ниже 50 % — дописывать можно, меряя после каждой партии.
3. Файл выше 85 % — не трогать вовсе или снимать ровно столько, сколько
   дописали.
4. **Прежде чем дописывать в модуль-основание, снять базу у всех, кто его
   ввозит.** Сам правленый файл может остаться зелёным, а упадут ввозящие: у
   них к его обещаниям добавляются свои.

Ломает не прибавка сама по себе, а тонкий запас: один и тот же набор правок
проходит там, где было 33 % свободных витков, и валит файл, где было 14 %.
