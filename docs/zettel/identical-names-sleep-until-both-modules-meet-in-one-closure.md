# Одинаковые имена в двух модулях библиотеки спят, пока оба модуля не встретятся в одном замыкании, и ввоза второго уровня для встречи достаточно

Одно и то же имя, объявленное в двух модулях библиотеки, само по себе не отказ.
Отказ `FLANG_DUPLICATE_NAME` приходит тогда и только тогда, когда оба модуля
попали в замыкание одной программы. Поэтому такие пары живут в дереве годами и
вылезают в тот день, когда кто-то ввёз соседа — причём **ввозить оба модуля
напрямую не нужно: хватает того, что второй приезжает по чужому `использует`**.

Живой случай. `examples/db/postgres-plan.flang` ввозил драйвер базы
(`postgres.flang`) и, выборочно, `utf8.flang`. Обе — прямо. А `utf8.flang` сам
ввозит `«Числа»`, и вместе с ним в замыкание приезжает `numbers.flang`. Своя
`«Целая часть»` была и в драйвере, и в числах:

```
FLANG_DUPLICATE_NAME, строка 149, столбец 1: функция «Целая часть» объявлена в
двух модулях: flang/stdlib/postgres.flang и flang/stdlib/numbers.flang
```

Автор плана про столкновение ЗНАЛ и обошёл его: написал разложение кодовой точки
в байты своей рукой, лишь бы не ввозить `«Байты текста»`, которое тянет за собой
`«Целая часть»`. Обход не сработал, потому что `«Целая часть»` приезжала не
оттуда, а из `utf8.flang`, ввезённого выборочно и по другой причине. **Обход
столкновения, рассчитанный на один путь ввоза, не закрывает второй.**

**Сколько таких пар в библиотеке.** Счёт по всем модулям `flang/stdlib/`:
542 объявления верхнего уровня, из них имён, объявленных более чем в одном
модуле, — девять:

| имя | где объявлено дважды |
|---|---|
| Целая часть | postgres + numbers |
| Значение параметра | http + postgres |
| Цифра числом | postgres + strings |
| Чётное | higher-order + numbers |
| Максимум, Минимум, Сумма, Произведение, Сортировать, Приписать в начало | higher-order + lists |

Из девяти сработала одна. Остальные восемь спят, и проверено, что спят по делу:
посчитаны замыкания всех 953 файлов `.flang` дерева — ни в одном оба модуля пары
не встречаются. То есть это не «пронесло», а «пока некому свести».

**Чем ловить заранее.** Быстрая проверка столкновений считает ТОЛЬКО замыкание
компилятора — 29 файлов. Библиотеки и примеров она не видит вовсе и на все
девять пар отвечает «столкновений 0». Чтобы найти спящие пары, нужен отдельный
счёт: имена по модулям библиотеки плюс замыкания всех файлов дерева.

**Как разводили и почему потом отменили.** Сначала имя развели суффиксом слоя:
у драйвера `«Целая часть»` стала `«Целая часть протокола»`. Это чинит отказ, но
оставляет в дереве вторую реализацию того же. Правильнее оказалось снять копию
совсем и ввозить общую из `«Чисел»` — так и сделала ветка `u/imena-razvesti`.
**Суффикс — лечение симптома; лечение причины — убрать копию.**

**Чем подтверждено.** 21 августа 2026, ветка сборки `svod/u2`, ствол `9e6bf406`.
Отказ снят прогоном `flang check examples/db/postgres-plan.flang` (код 1);
тот же файл в стволовой редакции, с ввозом через путь вместо ввоза по имени,
падает тем же отказом — вид ввоза здесь ни при чём.

**Чем ограничено.** Счёт замыканий считает `использует` обходом текста и не
знает про имена, приходящие иначе. Пары по именам ТИПОВ здесь не считались,
только по функциям.
