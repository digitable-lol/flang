# Тело-«если» получило посылку индукции, и это дало по библиотеке ноль

23 августа 2026, ветка `u/posylka-indukcii-telam`, основание `e98eadb9`.

**Что сделано.** Путь постусловия БЕЗ теоремы читал две формы тела — `разбор` и
`свёртка`. Третьей стало `если`: принцип по отрезку `нат` («Принцип по числу» в
`proof-initial.flang`) у ядра БЫЛ, доказан и читает ровно такое тело, но звался
только из написанной рукой теоремы. Правка — три функции в
`flang/self/proofterm.flang` и одна изменённая строка.

**Форма тела была выбрана по замеру, а не по догадке.** Тел в `flang/stdlib`
теперь 576, и раскладываются они так: `разбор` 179 (охвачено), **`если` 108**,
прочее (арифметика, поле, построение) 94, `свёртка` 73 (охвачено), `вызов` 67,
`пусть` 32, построение 13, встроенная форма 10. `если` — самый крупный
неохваченный вид, крупнее `вызов`а.

**Работает: проверено прогоном.** `flang/proof/examples/if-over-a-segment.flang`,
три постусловия, теорем ноль: старый компилятор — доказано 0 из 3, новый — 3 из
3, «доказано индукцией по «нат»». Настоящая функция библиотеки берётся тоже:
«Факториал» из `numbers.flang` с постусловием `результат не меньше 0` идёт
0 → 1.

**По библиотеке это дало ноль.** Парный замер поимённо, 17 долей из 26,
утверждений 566: было доказано 124, стало 124, дельта +0. Потеряно тоже 0.

**Почему ноль, и это главное.** Тел-`если` 108, но условие по параметру,
объявленному `нат`, — всего у **четырёх** («Поиск в диапазоне», «Степень»,
«Дополнить запрос», «Разобрать поток Redis»). Остальные 104 ветвятся по строкам,
спискам и `число`, а по `число` принципа нет и не будет: в носителе живёт `+∞`,
у которого «х минус 1» равно самому «х».

И у этих четырёх посылка теперь СТРОИТСЯ, а упирается всё в ФОРМУ УТВЕРЖДЕНИЯ:
`если (основание равен 1) то (результат равен 1) иначе да`, `1 не больше
результат`. Это ровно тот же переезд узкого места, который записан за 16 августа
([[bottleneck-moved-to-body-shape]]): форма тела перестала быть стеной, стеной
осталась форма утверждения.

**Что оказалось уже сделанным.** Тело-`пусть` (32 тела) индукцией берётся давно:
«Нормализовать» разворачивает `пусть` перед чтением, и `разбор` под ним читается
как обычный. Проверено прогоном на `пусть свои равно элементы / разбор свои` —
доказано индукцией. Отдельного правила ему не нужно.

**Тело-вызов: убывания взять негде, и это не пробел.** «Функция есть один вызов
соседа» рекурсии не содержит вовсе — значит и допущения строить не из чего, а
подстановка тела в цель у ядра уже есть отдельным ходом («По объявленному
типу»). Самовызов на верхнем уровне тела-вызова — это цикл без дна. Списка
меньшего размера без `разбор`а в языке не построить, поэтому структурного
убывания у тела-вызова нет по устройству языка, а не по слабости ядра.

**Подделка стоит и держит.** `forgery-if-without-descent.flang` — четыре функции,
у которых спуска нет (вызов на самом значении; вверх через второй параметр;
спуск на два при дне по одному; база зовёт себя). Все четыре и на старом, и на
новом отвечают «объявлено, не доказано». Та же подделка теоремой
(`…-teorema.flang`) отвергается кодом `FLANG_PROOF_INDUCTION_DESCENT`, код
возврата 1. Без спуска посылка была бы круговой — «допустим P(терм), докажем
P(того же терма)» закрывается правилом «цель есть допущение», и ведомость
напечатала бы «доказано» о функции, которая не возвращается вовсе.

**Подделку пришлось переписать, и это стоит помнить.** Первая версия ходила
вверх (`«Ф» от (н плюс 1)`) и до ядра НЕ ДОХОДИЛА: типизатор отвечает FLANG_TYPE
(«ожидался нат, получен число») раньше. Подделка, не доходящая до места, которое
мерит, не мерит ничего.

**Проверка на пустоту разошлась на двух заглушках, ровно как предупреждали.**
Три обещания честной половины (`результат не меньше 0`): при заглушке `0`
переживают подмену все три (пустых 3 из 3), при заглушке `0 минус 1` — ни одно
(пустых 0 из 3). Обещания эти слабые, и выдавать их за содержательную прибавку
нельзя.
