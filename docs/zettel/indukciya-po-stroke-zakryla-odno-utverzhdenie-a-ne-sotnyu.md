# Индукция по строке закрыла ОДНО утверждение на весь корпус, а не сотню: за стеной стоит вторая

Считалось, что «у строки нет принципа индукции» — самое узкое место
доказуемости: около сотни утверждений трёх модулей (`http` 25, `json` 12,
`postgres` 65) не доказывались ни одно. Принцип индукции по строке сделан и
работает. Прирост по всему корпусу (`flang/stdlib` + `examples`) —
**одно утверждение**.

Причина не в силе принципа, а в том, что **тела написаны не тем**. Индукция
цепляется к телу, написанному `разбор <строка>`. Замер по библиотеке:

| где | утверждений | из них тело «разбор строки» |
|---|---:|---:|
| вся `flang/stdlib` | 454 | **4** |
| `http` | 25 | 1 |
| `json` | 12 | 0 |
| `postgres` | 65 | 0 |
| `strings` | 36 | 1 |
| `strlists` | 13 | 1 |
| `tree` | 18 | 1 |

В `json` и `postgres` разбора строки нет вовсе: там разбирают **список знаков**
(`знаки: список строка`), а не строку. Тела `http` — свёртка по
`разложить текст на символы` и цепочки `разделить`/`соединить`. То есть сотня
утверждений стоит не за стеной «нет индукции по строке», а за другими.

## Прежний отказ был неверен, и вот чем

В ядре стояло написанное словами объяснение, почему строке принцип не дать: «у
строки голова — тоже строка, значит местом `X` оказались бы ОБА поля, и принцип
потребовал бы два допущения вместо одного». **Типизатор говорит другое.**
`Связать части строки` (`flang/self/types.flang`) связывает образец так:

```
голова : строка длиной 1        хвост : строка
```

Это разные типы, и на разнице стоит тотальность `код символа` от головы.
Значит функтор читается без выбора: `F(X) = 1 + (знак × X)`, место `X` — только
хвост. Отказ был написан по памяти, а не по типизатору.

## Что именно даёт правильное чтение и на чём оно держится

Голова обязана остаться коэффициентом, и довод не «так удобнее», а «иначе
ложь»: у строки из одного знака **голова равна целому** (`"а"` → голова `"а"`,
хвост `""`), поэтому допущение о голове было бы допущением о доказываемом.
Проверено снятием правки: если у головы убрать «длиной 1» и оставить простой тип
строки, ядро печатает

```
постусловие «всякая строка даёт ноль» функции «Врёт головой» —
доказано индукцией по «строка» … утверждение обо ВСЕХ входах типа «строка»
```

про функцию, которая **ни на одной непустой строке не возвращается**
(`flang run … --args '{"текст":"а"}'` → `FLANG_RECURSION_LIMIT`, глубина 20001).
То есть вердикт становится не «другим», а НЕВЕРНЫМ. Обе подделки на новое
чтение лежат в `flang/test/fixtures/poddelka-indukciya-po-stroke.flang`.

## Вторая недостача, без которой принцип бесполезен: пример с `""`

Принцип породился сразу, а база не закрывалась ничем: `Вариант образца` читала
конструктор только у списка (по длине) и у записи (по полю `variant`), а
`дано текст равно ""` приезжает СКАЛЯРОМ. Отказ дословно: «пример «Пустая
строка» задаёт «текст» как не вариант, а случай разбирает «пусто»». Пустая
строка — это и есть `пусто` у строки, и после того, как чтение добавлено, база
закрывается примером.

Чужой сумме имя `пусто` не занять, и держит это типизатор, а не осторожность в
ядре: `тип «Своё» вариант пусто` отвергается («образец „пусто“ применим к списку
и строке, а разбирается „Своё“»), а пример со строкой при параметре объявленного
типа — вторым отказом («аргумент не соответствует типу»).

## Где стена теперь — дословно

После принципа отказ `FLANG_PROOF_INDUCTION_TYPE` («у этого типа принципа
индукции нет») исчез на всех пробах и сменился двумя другими. Ядро **ничего не
знает о длине частей строки**:

* `длина голова` — про голову не выводится ничего. Цель `(длина результат) не
  больше 1` у «Первого символа» отвергается: «ограниченность точным потолком по
  построению не проходит». Тип головы в объявлении записан `{kind:"string",
  length:1}`, и этот факт УЖЕ едет в посылку (`declarations` в
  `flang/proof/initial.mjs`), но `известноеПоТипу` его не читает: она умеет
  только «имя типа `нат` → не меньше 0»;
* `длина текста = 1 + длина хвоста` — уравнения ветви для строки нет. У списка
  оно есть (`поРазбору`), и на нём стоит половина доказанного про списки;
* `мераПостроения` (`flang/proof/reduce.mjs`) знает список-литерал,
  строку-литерал, `если`, `разбор`, `отобразить`, `добавить`/`приписать` —
  и не знает `соединить`.

Пока этих трёх фактов нет, из четырёх утверждений с подходящей формой сводится
ровно одно.

**Чем подтверждено.** Ветка `u/stroka-indukciya`, основание `fd3721e3`, двоичный
перепечатан из исходников трижды (`sh scripts/raskrutka.sh` + `make -C bootstrap
-j8`). Вердикт брался у `bootstrap/flang check … --proof`, не у пробника.
Сравнение двух двоичных по `flang/stdlib/*.flang` и `examples/*/*.flang`:
различие ровно в двух файлах, и оба — один модуль `wal`, постусловие «хвост не
длиннее целого» функции «Хвост строки» перешло из «сетка 4 значения» в
«доказано индукцией по „строка“ … правила сведения: порядок по построению».
Теоремы при нём НЕ написано — ядро закрыло само. Примеры библиотеки 1216 из
1216 до и после; раздел «принято на веру» — «ничего».

**Чем ограничено.** Прирост мерен на корпусе БЕЗ дописанных теорем: сколько
даст индукция по строке, если теоремы написать руками, не измерено — пять проб
с приписанными теоремами (`strings`, `http` ×2, `strlists`, `json`) не закрылись
ни одна, все по причинам из раздела «где стена теперь». Утверждения `postgres`
не пробовались теоремой вовсе: там строка не разбирается ни в одном теле.
