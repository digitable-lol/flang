# Прогонщик корпуса написан на flang целиком; на C осталось 59 строк невыразимого и 419 строк перевозки

Инструмент языка можно писать на самом языке дальше, чем кажется. У `flang test`
по корпусу (каталог и маска вместо одного файла) на flang написано ВСЁ, что
решает: что считать корпусом, куда идти обходу, в какие каталоги не заходить,
какие пути брать, в каком порядке, какими словами отчитаться, что напечатать
машине и с каким кодом выйти — `flang/self/bootstrap/corpus.flang`, 760 строки,
из них 548 кода.

На C (`flang/src/emit/c/flang_repl.c`, +607 строк, из них 478 кода) осталось
три вещи, и только они по-настоящему невыразимы в языке:

```
перечисление каталога (opendir/readdir/lstat)   37 строк
чтение файла                                    15 строк
часы (gettimeofday)                              7 строк
                                            ─────────────
невыразимо на flang                             59 строк
```

Остальные 419 строк кода на C — **перевозка**: собрать список путей в значение
языка, разобрать ответ обратно в строки C, вырастить массив итогов, склеить
команду. Они не про эффекты и на flang выразимы полностью. Живут они на C по
одной измеренной причине, названной ниже.

## Почему цикл по файлам обязан жить у хозяина

Область памяти не отдаёт ничего до конца вызова ([[arena-never-releases]]).
Значит написать «связать и прогнать все 334 файла одним вызовом» нельзя: разбор,
типы и прогон ОДНОГО файла стоят от 55 МиБ до 8,6 ГиБ, и триста файлов в одной
области — это десятки гигабайт.

Поэтому цикл стоит на C, а область сбрасывается на каждом файле. Сброс работает:

```
пик прогона всего каталога flang/core/ (4 файла)   750 МиБ
пик прогона самого тяжёлого из них по отдельности  693 МиБ
```

То есть корпусный прогон держит пик САМОГО ТЯЖЁЛОГО файла, а не сумму. Отдавать
память между файлами (`fl_arena_release` вместо `fl_arena_reset`) поэтому не
нужно: замер даёт разницу 57 МиБ на четырёх файлах, а не порядок.

## Что из этого следует для других инструментов языка

Граница проходит не там, где её обычно проводят. «Инструмент — это эффекты,
значит инструмент на хозяине» — неверно: эффектов в прогонщике корпуса на 59
строк из 1367. Верное правило: **на flang пишется всё, кроме системных вызовов;
на хозяине остаётся то, чем управляют памятью и временем жизни**.

**Чем подтверждено.** Ветка `vypusk/progonshchik`, коммит «flang test берёт
каталог и маску». Строки — `git diff --numstat` и разбор по функциям. Память —
`/usr/bin/time -v` на `bootstrap/flang test flang/core/` (750 568 КиБ) и на
`bootstrap/flang test flang/core/parser.flang` (693 664 КиБ); самый тяжёлый файл
дерева `flang/self/bootstrap/compiler.flang` — 8 576 576 КиБ за 220 с.

**Чем ограничено.** Про инструмент, у которого вход — файлы дерева, а выход —
отчёт. Инструмент, которому нужен сокет или подпроцесс, упрётся в другое: у
языка есть поручения (`flang io`), но цикл поручений принадлежит хозяину
([[cikl-porucheniy-prinadlezhit-hozyainu-a-ne-yazyku]]).
