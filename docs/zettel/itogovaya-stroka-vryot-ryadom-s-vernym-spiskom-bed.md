# Итоговая строка проверки врёт рядом с верным списком бед — порча смотрит на список и этого не видит

Проверка, которая печатает и СПИСОК бед, и ИТОГОВУЮ строку, имеет два места, где
может соврать, а порча обычно проверяет одно: она смотрит, появилась ли беда в
списке, и на итоговую строку не глядит вовсе. В `scripts/storozh-vypuska.flang`
это выглядело так: на порче «дерево обещает версию 9.9.9» список назвал три беды
верно (выпуска нет — 404; ссылка формулы отдаёт 404; кран отдаёт другую версию),
а строкой ниже стояло «проверено: выпуск v9.9.9 есть и архив на месте».

Лечение — не «поправить текст», а сменить то, о чём строка говорит: она обязана
называть СПРОШЕННОЕ, а не НАЙДЕННОЕ. «Выпуск vX спрошен у GitHub: выпуск,
вложение, хеш формулы и версия крана — итог по каждому выше» не может разойтись
со списком бед по построению, потому что ничего о результате не утверждает.

**Чем подтверждено.** Ветка `u/port3`, 21 августа 2026, коммит `32acd6b6`.
Три прогона после правки: обычный — бед 2; порча «9.9.9» — бед 3 и честная
итоговая строка; `api.github.invalid` — беда 1 плюс «существование выпуска НЕ
ПРОВЕРЕНО». Соседняя работа наткнулась на тот же класс в другом виде: у неё
итоговая строка падала `ReferenceError` на зелёном пути, пока порча зеленела.

**Чем ограничено.** Про проверки, у которых ответ состоит из двух частей. Там,
где итог строится ТОЛЬКО из пустого списка бед (`разбор беды / случай пусто`),
разойтись нечему — и это довод в пользу такой формы.
