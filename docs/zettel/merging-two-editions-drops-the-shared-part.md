# Слияние двух редакций одного файла роняет общий кусок, и разбор этого не видит

Когда один и тот же файл переписали двое и слияние свели вручную, пропасть может
не строка, а целый блок объявлений — тот, который был в обеих редакциях и
поэтому не выглядел ничьим. Программа на JavaScript после этого РАЗБИРАЕТСЯ без
замечаний: имена связываются при работе, а не при разборе. Красное появляется
только у того, кто прогон запустил.

**Чем подтверждено.** Ветка `u/port5`. В `flang/scripts/binary.mjs` (717
строк, помощник, через который проверки спрашивают двоичный) не оказалось четырёх
объявлений:

```
памятьОтветов   упоминаний 3, объявлений 0
ключВопроса     упоминаний 4, объявлений 0
изЗначения      упоминаний 1, объявлений 0
вЗначение       упоминаний 1, объявлений 0
```

Обе звавшие их проверки — `target-occupied-guard.mjs` (ярлык `занятые:проверка`) и
`weight-gain.mjs` — падали `ReferenceError: ключВопроса is not defined`. Унесло
их слияние `df055a6b`, само названное «канал к двоичному сращён из двух
независимых редакций». Текст уцелел в соседних рабочих копиях того же дерева
(`/srv/flang-rabota/svod-st2` и ещё шесть, строки 349—377) и вернулся оттуда
дословно.

**Чем ограничено.** На flang так не выйдет: неизвестное имя — это
`FLANG_UNKNOWN_NAME` при проверке, до всякого запуска. Беда эта ровно про языки,
где имя связывается в момент обращения.

**Чему учит.** После ручного слияния файла на JavaScript одного «разбирается» и
одного `git diff` мало: надо запустить каждого, кто этот файл ввозит. Дешёвая
замена — счёт «упоминаний против объявлений» по каждому имени, он ловит ровно
этот класс.
