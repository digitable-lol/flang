# Служба на flang уже отвечает по сокету — задача 0047 описывала дерево двухдневной давности

Задача 0047 названа «главным, чего не хватает до цели „язык, пригодный для любых
служб“», и стоит на посылке: «Сегодня программа на flang сеть **не трогает
вовсе** […] Позвать соединение сама она не может. Отсюда прямое следствие:
настоящую службу на flang написать нельзя». Посылка **неверна**, и проверяется
это одним прогоном, а не разбором.

**Чем подтверждено.** Двоичный `w-predely` 0.6.2 от 23 августа, дерево
`u-network` на стволе `9ad072b1`, прогон через ворота `PAMYAT=45G`.

```
$ flang io examples/web/shortener/plan-network.flang --plan "Обслужить по сети" &
$ printf 'GET /здоровье HTTP/1.1\r\nHost: x\r\n\r\n' | nc 127.0.0.1 39281
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Content-Length: 5

живой
код возврата nc: 0
```

Служба поднимается **сама**: план открывает слушающий сокет поручением
`«Принять соединение»`, читает `«Прочитать из соединения»`, отвечает `«Ответить
в соединение»` и возвращается к приёму. Хозяин — двоичный на C, не Node: реализация
на JavaScript снята коммитом `fe8e8a37`, и комментарий в `plan-network.flang`,
обещающий запуск через `node examples/web/shortener/serve-network.mjs`, устарел
вместе с ней.

**Почему задача разошлась с деревом.** Последний барьер снят `7ebaabc3` от
23 августа («планировщик процессов на C ждёт сеть — шесть поручений соединения
исполняются, а не отказывают», задача 0013). Задача 0047 заведена `905537bd`
**25 августа**, то есть через двое суток. На дереве двадцать исполнителей, и
задачник за ними не поспевает: цена такой рассинхронизации — смена, потраченная
на изобретение сделанного. Проверять посылку задачи прогоном **до** начала
работы дешевле, чем закрывать задачу.

**Счёт словаря на сегодня.** Поручений **20**, откликов **17**
(`flang/self/parser.flang`, три списка-данных). Соединению принадлежат шесть
поручений — `«Открыть соединение»`, `«Принять соединение»`, `«Прочитать из
соединения»`, `«Ответить в соединение»` и октетная пара — и один отклик,
`«Соединение открыто»`. Ни `«Закрыть соединение»`, ни чего-либо ещё сетевого в
словаре нет, и это решение ADR-0002, а не пропуск.

**Что попутно снято тем же прогоном** — две беды `examples/web/shortener/`,
названные, а не починенные:

* `Content-Length` считается **знаками**, а не октетами. Тело `нет такого пути`
  — 15 знаков и 28 октетов, в заголовке стоит `Content-Length: 15`, и клиент
  читает обрезанное `нет тако`. Зазор назван в `plan-network.flang` словами;
  здесь он назван числом;
* путь **процентами** живым прогоном не раскодируется. Два запроса к одной
  поднятой службе, отличаются только записью пути:
  `GET /здоровье` → `200 OK`, `живой`;
  `GET /%D0%B7%D0%B4%D0%BE%D1%80%D0%BE%D0%B2%D1%8C%D0%B5` → `404 Not Found`.
  Второй — тот самый путь, для которого в `service.flang` стоит пример «браузер
  прислал путь процентами — маршрут тот же», ожидающий `живой`. Кириллический
  путь браузер кодирует всегда, значит **из браузера эта служба не работает**, а
  из `nc` работает.

Решение по форме: [ADR-0011](../adr/0011-a-service-stands-on-the-order-dictionary.md).
