# Девяти обработчикам из десяти вытеснение не нужно: срок известен до запуска

По корпусу процессов **55 мест из 60**, куда планировщик зовёт чужой код, имеют
ПОСТОЯННУЮ оценку витков, и наибольшая из них — **47 витков**. Растущих оценок
ноль. Без оценки остались пять. Значит вопрос «как вытеснять длинный
обработчик» для девяти случаев из десяти вообще не возникает: про них известно
ДО запуска, что они уложатся в любой квант от 47 витков.

Это то место, где мы не догоняем BEAM, а делаем то, чего она не может: BEAM
считает редукции каждому процессу на ходу, потому что про свой код не знает
ничего и знать не может.

**Чем подтверждено.** Прогон `оценитьВитки` по всем связанным программам дерева,
у которых есть `процесс` (15 программ, 60 пар «обработчик + начальное
состояние»), ветка `vypusk/svoya-mashina`. Разбивка: постоянная оценка 55,
растущая 0, оценки нет 5. Пять без оценки: три зовут `крутить` (нетотальный
разбор пакета, у двух объявлен запас 2000 витков — это сделано нарочно), один
зовёт `НОД` (доказан числовой мерой, а оценка числовую рекурсию не умеет), один
зовёт `Обслужить` в примере веб-службы.

**Что из этого сделано.** Предел пробега в эталоне планировщика
(`flang/self/conc.flang`) берётся теперь ДОКАЗАННЫМ потолком, а не запасом.
Было: тотальному обработчику планировщик давал миллион витков — всем одинаково.
Стало: 47 там, где доказано 47. Разница между «не дольше 47 витков ни при каком
входе» и «не дольше миллиона, а на деле как повезёт» — это и есть весь смысл
шага.

**Побочное следствие, ради которого стоило делать именно так.** Ограниченность
из свойства «на посмотреть» стала несущей: заниженная оценка теперь роняет
побайтовую сверку планировщика со свидетелем. Проверено порчей — доказанный
потолок занижен ровно на ОДИН виток, и сверка дала **336 расхождений из 336**.
До правки занижение оценки не роняло ничего.

**Чем ограничено.** Сделано только у эталона на flang. В напечатанный C потолок
не уехал: план процессов печатает единственное место, и это
`flang/src/emit/c.mjs` — реализация на JavaScript, которую решено выбрасывать;
в `flang/self/emit-c.flang` печати плана процессов нет ВОВСЕ (ноль вхождений
`fl_conc_node`). То есть дорога к цели C идёт либо через правку выбрасываемого
JavaScript, либо через перенос печати плана на flang, и второе — отдельная
работа.

Пяти обработчикам без оценки потолок остаётся ОБЪЯВЛЕННЫМ: 2000 витков там, где
запас назван в исходнике, и миллион там, где не назван. Вытеснение по кванту им
по-прежнему нужно, и в эталоне на flang его нет (у свидетеля на JavaScript есть —
`options.квант`, шаг В2).
