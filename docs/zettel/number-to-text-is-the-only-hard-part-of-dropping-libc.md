# Уйти от libc мешает одно место рантайма — перевод числа в текст

Программа, которая строит текст, просит у libc 12 имён вместо 5. Одиннадцать из
двенадцати закрываются мелочью. Вся цена сидит в паре `snprintf("%.*e")` +
`strtod`, и просит их **одна функция** — `fl_number_text`.

**Чем подтверждено.** Ветка `u/sloy`, повтор: `sh benchmarks/systems/measure.sh`.
Настоящая программа — разбор `fstab(5)`, `benchmarks/systems/fstab.flang`.

Двенадцать имён в 38 местах: `memcpy` `snprintf` `strlen` `strcmp` `memcmp`
`malloc` `free` `vsnprintf` `strtod` `strtol` `memset` `__errno_location`.

Кто что тянет (`objdump -dr` по рантайму):

| символ | откуда |
|---|---|
| `strcmp` | равенство, поиск поля, разбор варианта по имени |
| `memcmp` | равенство, `содержит`, `начинается с`, `разделить` |
| `snprintf` `strtod` `strtol` `memset` | **`fl_number_text`** и тексты диагностики |
| `strtod` `__errno_location` | `к числу` |

**Почему пара тяжёлая.** `fl_number_text` печатает число по правилу ECMAScript
`Number::toString`, а оно требует **кратчайшей** десятичной записи, читающейся
обратно в то же самое число. Рантайм ищет её перебором точности от 1 до 17:
печатает `%.*e` и читает обратно `strtod`. То есть ему нужны **обе половины**
задачи «double ↔ десятичная запись», и обе правильно округлённые. Это задача
Стила—Уайта (dtoa / Grisu / Ryu) — отдельная работа на тысячи строк с таблицами
степеней десяти.

**Измеренная граница дешёвого пути.** `benchmarks/without-libc/text-layer.c` —
118 строк — делает эту пару **только для целых |v| ≤ 2^53**, где десятичная
запись точна и считается целочисленной арифметикой. Сверка с glibc: **24 пробы
от 0 до ±(2^53−1) совпали знак в знак**, первая расходящаяся — `0.5`. Разбору
fstab и всякой программе, печатающей счётчики, этого хватает; дробям — нет, и
это сказано в шапке файла, а не умолчано.

**Что это даёт числом.** Тот же разбор fstab: **58 392 байта** без libc против
**902 376** статически с glibc — в 15,5 раза меньше. Ответ на настоящем
`/etc/fstab` этой машины совпадает у всех трёх прогонов (вычислитель языка,
родной двоичный, без libc): «точек 4, бед 0, корней 1».

**Чем ограничено.** Замер снят на x86_64 Linux и gcc. Правило «одна функция
держит всю цену» от этого не зависит, а числа могут.
