# Одна форма цели держит пятую часть всего недоказанного: 446 обещаний вида «длина против длины»

У ядра три правила на форму цели — «не меньше 0», «не больше конечного
литерала», «равно». Всё, что в них не попало, ядро не берёт вовсе: вердикт
«объявлено, не доказано», а не «сетка». Вопрос был — во что это обходится
дереву. Ответ снят счётом, а не прикидкой.

## Как считано

Слито **1340 ведомостей** (`flang check --proof`), снятых разными работами по
разным областям — библиотека, ядро, крипто, строки, провод, примеры. Каждое
постусловие сопоставлено с текстом его цели в сегодняшнем дереве по паре
«функция + имя обещания»; где одна и та же цель встречалась в нескольких
ведомостях с разным словом, бралось лучшее.

```
обещаний (уникальных, сопоставленных с целью)   11 426
из них «объявлено, не доказано»                  2 203   (19 %)
цель не нашлась в сегодняшнем дереве             1 670   — ведомости снимались на
                                                          других ветках, в счёт не взяты
```

## Форма цели против вердикта

```

условная «если … иначе да»                   2917    230      915   4062     72 %

дизъюнкция «или»                             1180    105       40   1325     89 %
не больше ⟨выражение⟩                         250     93      364    707     35 %
конъюнкция «и притом»                         322    138       92    552     58 %
принадлежность «содержит»                     326     55      113    494     66 %

не меньше 0  ⟵ правило есть                    61     17       26    104     59 %
```

## Что даёт одно правило

Незакрытые цели вида «⟨длина⟩ не больше/не меньше ⟨длина⟩» — **446 штук, 20 % от
всех 2203 недоказанных**, и это одна семья: 311 записаны через «не больше», 135 —
зеркально через «не меньше». Смысл у всех один: накопитель, проходя через
рекурсивный вызов, не убывает (или результат не длиннее входа).

```
(длина «готовые») не больше (длина результат)
(длина результат) не больше ((длина «элементы») плюс (длина «найденные»))
```

Ни одна другая форма такой кучи не даёт: следующие по величине — условные (892)
и равенства (413), но у равенств **правило уже есть**, и они недоказаны по другой
причине (см. ниже).

**Оговорка, без которой число врёт.** «Разблокировать» — это стать пригодным для
правила, а не быть доказанным. Правило необходимо, но не достаточно: у формы
«равно» правило есть, и всё равно 413 целей не доказаны — 12 %. По наблюдаемой
доле взятого у форм, где правило ЕСТЬ (58…83 %), новое правило про длины закрыло
бы из 446 примерно **260…370**. Твёрдое число здесь — 446 пригодных; закрытое —
вилка с названным основанием.

## Что даётся даром, без правки ядра

Обратный ход дешевле любого правила и уже показан образцом. «Одинаковые типы»
доказаны правилом «разбор цели по условию» **только потому**, что тело начинается
с `если`, и условие цели совпадает с условием этого `если`. У «Одинаковых видов»
та же по смыслу мысль записана иначе, тело — `разбор`, и цель уезжает на сетку.

Среди недоказанных условных целей:

```
189  тело начинается с «если»   ← переписывается дёшево, тот самый образец
447  тело начинается с «разбор»
509  тело иное
```

**189 целей** стоят рядом с телом, у которого `если` уже есть, — им не хватает
только согласования условия цели с условием тела. Это верхняя граница дешёвых:
переписывание меняет ЗАПИСЬ, а не смысл, только когда обе формулировки истинны на
одних входах; где не так, обещание менять нельзя.

## Что из этого следует

1. **Правило про длины — самое дорогое место дерева.** Одна семья, 446 целей,
   пятая часть всего недоказанного. Это готовое обоснование работы над ядром.
2. **189 целей закрываются без ядра вовсе** — переписыванием цели под `если`,
   который в теле уже стоит. Это дешевле и делается сегодня.
3. **Правило не равно доказательству.** 413 равенств недоказаны при живом
   правиле; значит и после нового правила часть 446 останется. Считать надо
   вилкой, а не одним числом.

## Чем подтверждено

Слияние 1340 ведомостей `flang check --proof` из `/srv/tmp/**`, сопоставление с
целями по всему дереву (`flang/self`, `core`, `stdlib`, `conc`, `proof`,
`examples`, `scripts`, `fspec`), разбор форм и перекрёстная таблица. Счёт
воспроизводится: `/srv/tmp/u-trampolines/itogo.py`. 27 августа 2026.

## Поправка 28 августа 2026: число верное, но на вопрос «что даст правило» оно не отвечает

Счёт воспроизведён на дереве `9f66073f` тем же способом (слито 1375 ведомостей
из `/srv/tmp/**`): семья «⟨длина⟩ против ⟨длина⟩» со словом «объявлено» — **462
цели** против 446 от 27 августа. Само число держится. Три вещи под ним — нет.

**Первое: правило про сложение касается двадцати целей из 462, а не всех.**
Задача 1290 назвала недостающее правило механизмом — это монотонность сложения
по порядку (`x не больше y` ⟹ `z плюс x не больше z плюс y`). Слово `плюс` в
границе есть у **20** целей семьи. У остальных **442** сложения нет вовсе, и это
другая беда: «накопитель не убывает».

**Второе: семья едина только по записи цели.** Тела у этих 442 разложились так:

```
226  пусть
 50  если
 44  разбор, рекурсивна
 37  разбор
 32  свёртка          ← уже свёртка, и всё равно не доказано
 23  если, рекурсивна
 19  иное
 10  пусть, рекурсивна
```

Ни одна форма не даёт большинства, и 32 написаны той самой свёрткой, которая на
пробе доказывается. Значит «одна семья, один рычаг» — неверно, и разложение по
механизму ещё не сделано.

**Третье, и самое дорогое: вердикты под числом не все воспроизводятся.**
Ведомости слиты из `/srv/tmp/**` — с разных веток, разными сборками, за разные
дни. Проверено сегодняшним `bootstrap/flang` на тех кандидатах, до которых он
дотягивается, — а дотягивается он до всех семнадцати:
**17 проверено, 6 сошлись, 11 разошлись.**

| файл | кандидатов | сегодня |
|---|---:|---|
| `flang/stdlib/trust-store.flang` | 5 | «объявлено» — сошлось 5 из 5 |
| `flang/stdlib/sqlite.flang` | 1 | «объявлено» — сошлось 1 из 1 |
| `flang/stdlib/sets.flang` | 6 | **«сетка»** — разошлось 6 из 6 |
| `flang/stdlib/higher-order.flang` | 2 | **«сетка»** — разошлось 2 из 2 |
| `flang/stdlib/datetime.flang` | 2 | **«сетка»** — разошлось 2 из 2 |
| `flang/stdlib/strlists.flang` | 1 | **«сетка»** — разошлось 1 из 1 |

*Здесь стояло «13 проверено, 5 сошлись, 8 разошлись»: четыре кандидата в
`datetime`, `sqlite` и `strlists` были досчитаны позже, каждый файл считается
дольше десяти минут. Доля разошедшихся от этого выросла с 8/13 до 11/17.*

Разница между «объявлено» и «сетка» здесь не мелочь: всё определение семьи
построено на том, что ядро такие цели «не берёт вовсе». Две трети проверенных оно
берёт.

**Что из этого следует.** 462 — верхняя граница по ЗАПИСИ, снятая по разнородным
ведомостям. Числа «сколько закроет правило» из неё не выводится; для правила про
сложение оно не больше 20. Разложение остальных 442 по механизму — работа,
которая ещё не сделана.
