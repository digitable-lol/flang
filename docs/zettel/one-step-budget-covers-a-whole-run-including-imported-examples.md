# Предел шагов у прогона примеров — один на весь запуск, и примеры ввезённых модулей считаются в него же

`FL_MAX_STEPS` = 200 000 000 (`scripts/raskrutka.sh`) — это потолок ОДНОГО
запуска `flang test` или `flang check`, а не потолок одной функции и не потолок
одного примера. Модуль, который что-то ввозит, платит и за примеры ввезённого:
`flang test` файла из двух строк, ввозящего `sha256.flang`, прогоняет 92 примера,
из которых 91 чужой.

Для дешёвых модулей это незаметно. Для криптографии — стена. Семь контрольных
векторов RFC 4231 в `flang/stdlib/hmac.flang` стоят **186 363 398 витков, 93 %
потолка**. Любой пример вывода ключа, поставленный в тот же файл, обрывает прогон
отказом `FLANG_RECURSION_LIMIT`, и это проверено: `scram.flang` с примером на
один виток PBKDF2 съел ровно 200 000 001 виток и упал.

**Чем это лечится и чем не лечится.** Не лечится делением на функции: потолок
общий. Лечится делением на ФАЙЛЫ плюс `только` в строке ввоза — имя, не попавшее
в список, уходит из программы вместе со своими примерами. Так `kdf.flang` ввозит
`hmac.flang` без `«Подпись шестнадцатеричным»` и не платит за семь векторов.

**Чем подтверждено.** Прогоны на ветке `u/hmac`, 20 августа 2026:
`flang test flang/stdlib/hmac.flang` — 127 примеров, 87 с, 93 % потолка;
`flang test flang/stdlib/kdf.flang` — 129 примеров, 57 с, 61 %;
`flang test flang/stdlib/` целиком — 21 файл, 1343 примера, 0 не прошло, 19 минут
(там потолок считается по файлу, а не на весь обход).

**Отсюда следствие для расстановки примеров.** Опубликованный вектор с большим
числом витков (RFC 6070 с c = 4096, RFC 7677 с i = 4096) примером быть не может
вовсе: 4096 витков — это 16 384 сжатия блока SHA-256, около пяти часов
толкователем. Такой вектор проверяется прогоном напечатанного JavaScript
(`flang emit --target js`, 56 с) — и это тот же исходник, напечатанный тем же
компилятором, а не вторая реализация.

**Замер по цепочке ввоза, снятый на этой работе** (ветка `u/hmac`):

| файл | глубина ввоза | витков | доля потолка |
|---|---:|---:|---:|
| `hmac.flang` | sha256 | 186 363 398 | 93 % |
| `kdf.flang` | sha256 → hmac | 123 523 531 | 61 % |
| `sha1.flang` | sha256 → hmac → kdf | 103 361 768 | 51 % |
| `scram.flang` | то же + base64 | **200 000 001** | **обрыв** |
| `postgres-scram-plan.flang` | scram + postgres | **не досчитал за 30 минут** | — |

`scram.flang` вошёл в потолок только после того, как из строки ввоза убрали
`«Вывод ключа»`: солёный пароль SCRAM — это ровно один кусок PBKDF2, и
`«Кусок вывода»` даёт то же значение, не таща за собой два примера вывода ключа.

**Что из этого следует.** Глубина ввоза стоит денег, и цена не в разборе, а в
ЧУЖИХ ПРИМЕРАХ. Модуль, стоящий четвёртым в цепочке, платит за примеры первых
трёх целиком. План, стоящий пятым, `flang check` не проходит вовсе. Настоящая
починка — не резать примеры, а перестать прогонять чужие: прогон примеров нужен
ядру только там, где на них ссылается обоснование «по примеру» (об этом же
говорит комментарий в `scripts/raskrutka.sh`).
