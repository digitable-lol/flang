# Выборочный ввоз обязан перечислить и те имена, которые зовёт КОНТРАКТ функции, а не только её тело

`использует «Числа» только «Чётное»` не работает. Компилятор отвечает

```
FLANG_UNKNOWN_NAME, строка 183, столбец 66: неизвестная функция «Делится на»
```

— потому что у ввозимой «Чётное» постусловие звучит «чётность есть делимость на
два» и разрешается в той же плоской таблице имён, что и тело. Просьба `только`
сужает таблицу целиком, вместе с контрактом, и имя из постусловия исчезает
наравне с любым другим.

Отсюда правило: в список `только` попадает **транзитивное замыкание по вызовам
тела И контракта**. Замерено на трёх ввозах:

| ввоз | нужно имён | зачем лишние |
|---|---|---|
| «Чётное» из «Чисел» | 3 | «Чётное» → «Делится на» → «Целочисленное деление», обе цепочки из постусловий |
| «Цифра числом» из «Строк» | 3 | «Цифра числом» → «Это цифра» → «Позиция подстроки», обе из постусловий |
| «Целая часть» из «Чисел» | 1 | оба её постусловия написаны одной арифметикой, без вызовов |

Практический вывод для того, кто разводит библиотеку: **функция с «бедным»
контрактом ввозится дешевле, чем функция с богатым.** Это ровно наоборот тому,
чего ждёшь: сильное утверждение — благо, а платит за него место ввоза, причём
именами, которые ему самому не нужны и которые могут столкнуться с его
собственными.

**Как искать нужный список, не гадая.** Ввезти одно имя, прогнать `check`,
дописать то, что назвал `FLANG_UNKNOWN_NAME`, повторить. Диагностика называет по
одному имени за раз и печатает строку — три круга закрывают самый длинный случай
в библиотеке.

**Чем подтверждено.** Ветка `u/imena-razvesti`, двоичный из неё же (0.5.1).
Прогоны `bootstrap/flang check flang/stdlib/higher-order.flang` и
`… postgres.flang` до и после дописывания имён.

**Чем ограничено.** Проверено только на функциях. Как ведёт себя `только` с
типами, у которых поля ссылаются на другие типы, здесь не мерилось.
