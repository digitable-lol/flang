# Печать плана обещана наизнанку: семь целей молча забывают план, восьмая отказывает не про него

Спецификация категорной поверхности называет у печати плана ровно два законных
исхода — цель либо печатает объявление целиком, либо отказывает, назвав план по
имени, — и отдельно называет третий исход худшим: «модуль собирается, код
возврата ноль, диагностик ноль, а работать он не умеет». Прогон по всем восьми
целям показал, что сегодня **в этот худший исход попадают семь целей из восьми**,
а обещанная таблица «цель → исход» переставлена местами.

**Чем подтверждено.** 21 августа 2026, `bootstrap/flang` из ствола `0446d33f`,
программа `flang/examples/wal/append-plan.flang`:

| цель | код | что вышло |
|---|---:|---|
| `c` | 0 | файлов 6, байт 395 249 |
| `go` | 0 | файлов 5, байт 168 041 |
| `rust` | 0 | файлов 7, байт 209 019 |
| `java` | 0 | файлов 8, байт 209 153 |
| `elixir` | 0 | файлов 4, байт 205 589 |
| `python` | 0 | файлов 4, байт 159 274 |
| `csharp` | 0 | файлов 9, байт 243 115 |
| `js` | 1 | `FLANG_UNKNOWN_NAME: запись не содержит поле «исходник исполнителя»` |

**Замер повторён 22 августа 2026** на стволе `3dcbed14`, той же программой, по
одной цели за раз — и он разошёлся с прежним у восьмой:

| цель | код | что вышло | план в выводе |
|---|---:|---|---|
| `c` | 0 | файлов 6, байт 409 700 | нет |
| `go` | 0 | файлов 5, байт 169 517 | нет |
| `rust` | 0 | файлов 7, байт 210 046 | нет |
| `java` | 0 | файлов 8, байт 210 596 | нет |
| `elixir` | 0 | файлов 4, байт 207 363 | нет |
| `python` | 0 | файлов 4, байт 160 604 | нет |
| `csharp` | 0 | файлов 9, байт 247 827 | нет |
| `js` | 0 | файлов 2, байт 131 484 | **есть** |

`js` больше не падает на `FLANG_UNKNOWN_NAME` и печатает план целиком: в
`dopisat_v_zhurnal.js` стоят `const $io`, `export function ioPlan()` и
`export function ioRun(имя, исполнить, настройки)`. Байты у остальных семи
подросли — дерево двигалось. Это и есть довод в пользу сверки: замер месячной
давности уже неверен, а узнать это можно было только прогоном.

Спецификация обещала: печатает `js`, семь остальных отказывают кодом
`FLANG_PLAN_UNSUPPORTED`. Кода этого в исходниках на тот день не было вовсе — ни
одной строкой; он ушёл вместе с реализацией, которая его выдавала. Половина
обещания сошлась, вторая нет: семь молчали вместо отказа. Код вернулся 22
августа 2026, и запись о нём снята из списка отсрочек сторожа кодов.

В напечатанном у семи зелёных нет ни описателя плана, ни исполнителя: поиск по
их выводу не находит ни `ioPlan`, ни `ioRun`, ни `$io`. Функции начала и шага
печатаются как обычные функции — звать их некому.

**Класс, а не случай.** Обещание без проверки уезжает не к нулю, а к
ПРОТИВОПОЛОЖНОСТИ, и молчит об этом. Ноль заметен: команда не работает вовсе.
Противоположность незаметна: команда работает, код возврата нулевой, а делает
она обратное обещанному. Признак, по которому такое ищут заранее: в прозе стоит
таблица «вход → исход», а прогона, который бы её гонял, нет.

**Чем кончилось, 22 августа 2026.** Выбран второй из двух законных исходов —
отказ. Семь целей без исполнителя плана теперь отвечают
`FLANG_PLAN_UNSUPPORTED`, называют план по имени, возвращают 1 и не пишут ни
файла; `js` печатает объявление целиком и возвращает 0. Решение — одна функция
«Отказ по плану» в `flang/self/bootstrap/compiler.flang`, по вызову на каждую
из семи точек входа печати.

Довод в пользу отказа, а не предупреждения: предупреждение оставило бы в дереве
модуль, который выглядит рабочим и не работает, а код возврата в оснастке
читают редко. Цена отказа замерена: программ с объявлением `план` в дереве 77, и
ни одна из них ни одним прогоном дерева в эти семь целей не печатается —
перестало печататься ровно то, что и до этого не работало.

Сверка написана: `scripts/plan-v-celyah.flang`, различитель изъятием. Прогон
даёт «целей 8: печатают 1, отказывают честно 7, молчат 0» кодом 0. Подделка
проверена: подмена одной строки таблицы («python» → «печатает») даёт код 1 и
называет ровно эту строку.

**Как строить проверку — разложено, но не написана.** Дискриминатор «есть ли
план в напечатанном» по восьми языкам текстом не берётся: искать `ioPlan` в семи
разных синтаксисах — это семь хрупких правил. Механический и языконезависимый
способ один — **изъятие**: напечатать программу дважды, с объявлением `план` и
без него, и сравнить выводы. Совпали — план не дал ничего, то есть забыт молча.
Цена: два прогона печати на цель, шестнадцать на восемь целей. Образец такой
проверки, которая портит настоящий файл дерева и обязательно возвращает его на
любом исходе, — `flang/scripts/podlog-koda.flang`.

**Чем ограничено.** Замер снят на одной программе с планом
(`append-plan.flang`). Программ с объявлением `план` в дереве **77** (счёт 22
августа 2026: `git ls-files` по `*.flang`/`*.fts`, строка, начинающаяся с
`план «`); на остальных семидесяти шести не повторён. Утверждение «исполнителя нет ни у одной цели» опирается на поиск по
выводу, а не на попытку запустить напечатанное.
