# Примеров по корпусу прогоняется вдвое больше, чем объявлено, а девять файлов на 11 683 строки отчитываются чужими

Считать примеры дерева поиском строк `пример «` — значит получить не то число,
которое покажет прогон. На дереве `vypusk/progonshchik` (основание `bbe2b370`,
20 августа 2026), корпус `flang/` + `docs/` — 334 файла `.flang`:

```
объявлено строкой «пример «…»»                 3947   в 287 файлах
прогнано командой flang test по одному файлу   8408   в 290 взятых файлах
```

Разница не ошибка счёта, у неё три названные причины, и все три проверяемы:

**1. Замыкание импортов — главная.** `flang test файл.flang` связывает файл с
его зависимостями и гоняет примеры ВСЕЙ связанной программы, а не только
входного файла. Примеры библиотеки поэтому считаются заново у каждого, кто её
подключил. Разложение: у 223 взятых файлов без единого `использует` прогнано
3077 примеров при 2817 объявленных; у остальных 67 файлов с импортами — 5331
прогнанный пример при 959 объявленных, то есть в пять с половиной раз больше.

**2. Поверхности языка, кроме русской.** `example`, `ekzemplo`, `示例` — то же
слово языка, и поиск по `пример` их не видит. 16 файлов дерева
(`examples/rosetta/*-english.flang`, `examples/surfaces/*.eo.flang`
и `*.zh.flang`) объявляют по этому счёту ноль примеров, а прогоняют 233.

**3. Прогоны модели процессов.** `прогон «имя»` в файлах `flang/conc/**` —
это тоже пример для `flang test`: 11 файлов, объявлено 17, прогнано 45.

## Худшее следствие: файл без единого своего примера отчитывается чужими

Из первой причины прямо следует дыра, и она хуже расхождения чисел. Слой,
у которого своих `пример`ов нет НИ ОДНОГО, всё равно печатает зелёный отчёт —
о примерах, которые приехали к нему по `использует`:

```
$ flang test flang/self/carriers.flang
flang/self/carriers.flang: примеров 91, прошло 91, не прошло 0
```

Все девяносто одна — из `totality.flang`. О самом файле (176 строк) не сказано
ничего, и прочитать это по отчёту было нельзя.

**Таких файлов в дереве девять на 11 683 строки, и пять из них — весь слой
доказательств:**

| файл | строк | прогнано | своих |
|---|---:|---:|---:|
| `flang/self/proof-kernel.flang` | 3970 | 40 | 0 |
| `flang/self/proofterm.flang` | 2702 | 40 | 0 |
| `flang/self/proof-initial.flang` | 1948 | 40 | 0 |
| `flang/self/factcheck.flang` | 1420 | 18 | 0 |
| `flang/self/obligations.flang` | 536 | 40 | 0 |
| `flang/self/functor-oracle.flang` | 375 | 52 | 0 |
| `flang/self/law-oracle.flang` | 370 | 52 | 0 |
| `flang/self/sets-oracle.flang` | 186 | 52 | 0 |
| `flang/self/carriers.flang` | 176 | 91 | 0 |
| **итого** | **11 683** | **425** | **0** |

Четыреста двадцать пять зелёных примеров, ни один из которых не про эти файлы.

Прогонщик корпуса поэтому считает ДВА числа, а не одно, и называет такие файлы
вслух:

```
flang/self/carriers.flang: СВОИХ примеров нет ни одного — все 91 приехали
по «использует», и о самом файле не сказано ничего
корпус «flang/self/c*.flang»: файлов 4, взято 4, отказано 0,
примеров 216 (своих 40), без своих примеров 1, прошло 216, не прошло 0
```

**Счёт «своих» сверен с поиском строк на 284 файлах: сошлось на 279.** Пять
расхождений объяснены поимённо и все пять — известные факты, а не ошибки счёта:
два файла (`docs/benchmark/13-even.flang`, `16-success.flang`) не
разбираются вовсе, и счётчик честно отдаёт ноль; `docs/спецификации/слой-отказов.flang`
держит один пример внутри `утилита` FTS, о чём написано в нём самом; а
`cat/modules/orders.flang` и `cat/order-shipment.flang` объявляют примеры при
стрелке (`морфизм … даёт`), и те живут в `morphisms`, а не в `functions` — это
записанный долг «Прогона примеров исходников».

Красным такой файл не становится, и это решение, а не недосмотр: у слоя
доказательств своих примеров нет по устройству, и красный корпус на этом
основании потребовал бы списка исключений — то есть места, куда однажды
допишут настоящую поломку. Он назван и сосчитан; решать, долг это или нет,
человеку.

## Почему это важно знать заранее

Число «сколько у нас проверок на flang» ходит по заданиям и отчётам, и оно
разное в зависимости от того, что спрашивали. Правильных ответов два, и путать
их нельзя:

- **сколько написано** — 3947 (плюс невидимые поиску, см. выше). Это работа
  автора: столько утверждений человек напечатал руками;
- **сколько выполняется за один прогон корпуса** — 8408. Это работа машины, и
  она больше, потому что библиотечный пример перепроверяется на каждом
  подключении.

Ни одно из двух не «правильнее». Но сверять прогон одной реализации с прогоном
другой можно только по второму, а планировать перенос проверок — только по
первому.

## Числа по всему корпусу, снятые прогонщиком

Прогон `bootstrap/flang test <каталог> --json` по `flang/` и `docs/` целиком —
335 файлов, 300 взято, 35 отказано:

```
примеров прогнано          7703
  из них СВОИХ             3964   (51 %)
  из них ввезённых         3739   (49 %)
файлов на чужих примерах      9   (425 примеров, все в flang/self)
потеряно своих с отказами   204   (файл не взят — его собственные проверки не шли)
прошло 7701, не прошло 2
```

Почти ПОЛОВИНА зелёных примеров корпуса — перепроверка библиотеки у очередного
её пользователя. В самоприменяющемся слое доля ещё резче: `flang/self/*.flang`
— 51 файл, прогнано 2477 примеров, СВОИХ из них 672, то есть три четверти
зелени приехало по `использует`. Это не бесполезная работа (пример библиотеки, сломавшийся
только в чужом замыкании, — настоящая находка), но считать её за проверку
файла, в отчёте которого она стоит, нельзя.

Счёт «своих» сверен с независимым поиском строк на всех 335 файлах: 4189 против
4168, расхождений пять, и каждое названо (см. выше).

**Чем подтверждено.** Свидетель на Node (`node flang/bin/flang.mjs test` по
одному файлу, 334 файла) и двоичный (`bootstrap/flang test flang/` и
`bootstrap/flang test docs/`) дают одинаковые числа: на `docs/` — 47 файлов,
17 взято, 30 отказано, 378 примеров, 377 прошло, 1 не прошло, и пофайлово
расхождений ноль. Счёт объявленных — `grep -ac '^ *пример «'` по тому же списку
файлов.

**Чем ограничено.** Числа сняты на одном основании; в дереве работают
пятнадцать агентов, и через день они будут другими. Верна не величина, а
соотношение и его разложение по трём причинам.
