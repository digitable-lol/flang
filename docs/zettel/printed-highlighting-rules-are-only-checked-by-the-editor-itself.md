# Напечатать правила подсветки из таблицы языка мало: съедает слова сам редактор, и увидеть это можно, только спросив его о каждом слове

Подсветка, печатаемая из таблицы ключевых слов, кажется защищённой от
расхождения с языком: добавили слово — правила перепечатались. Защита неполная.
Между напечатанным файлом и раскрашенным текстом стоит РАЗБОРЩИК ПРАВИЛ самого
редактора, и он умеет молча выбросить строку целиком.

У Vim это делает `syn keyword`: он читает хвост своей строки как СВОИ ключи
(`contained`, `nextgroup`, `fold`…), и первое слово, похожее на ключ, обрывает
список. Английская поверхность flang содержит слово `contains` — настоящую фразу
понятия `contains`. Строка

```vim
syn keyword flangKeyword если то иначе fold contains add 如果 не меньше
```

регистрирует ЧЕТЫРЕ слова из тринадцати: `если`, `то`, `иначе`, `fold`. Всё,
начиная с `contains`, пропадает. Ни ошибки, ни предупреждения, ни ненулевого
кода — файл загружается, подсветка «работает».

**Чем подтверждено.** Ветка `vypusk/vim`, 20 августа 2026. Строка выше подана
Vim 9.2 (`vim -Nu NONE -es`), и вид каждого знака спрошен через
`synIDattr(synID(строка, столбец, 1), 'name')`: у первых четырёх слов —
`flangKeyword`, у остальных девяти — пусто.

**Чем чинится.** Все 629 фраз печатаются ОДНИМ `syn match` с перечислением
внутри `\%(…\)`: фраза попадает в шаблон в кавычках, и разбирать её как ключ
редактору нечем. Порядок ветвей при этом становится частью правильности — Vim
берёт первую подошедшую, а не самую длинную, — поэтому фразы печатаются от
длинных к коротким.

**Чем стережётся.** `flang io scripts/vim-highlight-check.flang` печатает файл со всеми
фразами таблицы, открывает его настоящим Vim и настоящим Neovim и требует, чтобы
каждая покрасилась целиком. На целых правилах: Vim 9.2 — 629 из 629, Neovim
0.12.4 — 629 из 629. Снятая из шаблона одна фраза `contains` даёт код 1 и строку
`ПРОПУЩЕНА: contains`.

Класс шире Vim: **всякий напечатанный файл правил проверяется тем, кто его
читает, а не глазами и не сравнением с источником.** Источник может быть верен,
печать — точна, а потребитель всё равно поймёт написанное иначе, и промолчит.

**Чем ограничено.** Проверено на Vim 9.2 и Neovim 0.12.4. Про tree-sitter и
Chroma по-прежнему ничего не сказано — у них свои разборщики правил и, скорее
всего, свои способы промолчать.

## Дополнение: TextMate (VS Code) промолчал бы иначе, и список опасных знаков у него СВОЙ

24 августа 2026, ветка `b/docs-editors`. Правила для VS Code напечатаны из той
же таблицы (`scripts/vscode-rules.flang`), и предсказание «свой способ
промолчать» подтвердилось — но способ оказался не тот.

Беды `syn keyword` у TextMate нет вовсе: грамматика лежит в JSON, все фразы
едут одним шаблоном Oniguruma, и разбирать фразу как свой ключ редактору нечем.
Зато есть своя: **негодную грамматику VS Code выбрасывает молча** — ни ошибки,
ни предупреждения, файл просто остаётся серым.

И главное, ради чего это записано: **список знаков, опасных для шаблона, у двух
редакторов НЕ СОВПАДАЕТ, и заимствовать его нельзя.** У Vim в режиме `\%(…\)`
знаки `( ) { } ? +` — обычные, поэтому их нет в списке опасных для Vim (там 14
знаков). В Oniguruma они значащие. Фраза со скобкой прошла бы охрану Vim и
сломала бы грамматику VS Code. Поэтому у `vscode-rules.flang` свой список из 15
знаков, а не ввезённый из `language-words.flang`.

Класс уточняется: **у каждого потребителя напечатанных правил своя охрана
экранирования, потому что у каждого свой язык шаблонов.** Одна общая охрана на
двух потребителей выглядит как две и молчит там, где второй уже сломан.

**Чем подтверждено.** Настоящий разборщик TextMate — `vscode-textmate` 9 на
`vscode-oniguruma` (тот самый, что внутри VS Code), 633 фразы таблицы: покрашено
633 из 633. Четыре поверхности записи на одной и той же программе
(`examples/rosetta/factorial.flang`, `factorial-english.flang`,
`examples/surfaces/factorial.eo.flang`, `factorial.zh.flang`) дали одинаковые
числа — 118 ключевых слов, 66 имён в ёлочках, 35 чисел в каждом. Взгляд назад и
вперёд `(?<![\p{L}\p{N}_])…(?![\p{L}\p{N}_])` держит границу слова на всех
четырёх, включая китайскую. Две порчи дали код 1: снятая фраза `свёртка` —
«не покрашено: 1, свёртка»; переставленная вперёд короткая ветвь `к числу` —
«не покрашено: 1, к числу или беда», то есть порядок ветвей у Oniguruma часть
правильности ровно так же, как у Vim.

**Поправка к числам выше.** Здесь стояло «629 фраз» и «629 из 629». На 24
августа таблица ведёт **633 фразы (150 понятий)**: прибавилось понятие
`character by code` четырьмя поверхностями. А `editors/vim/syntax/flang.vim` в
стволе **всё ещё говорит «Понятий 149, фраз 629»** и с таблицей побайтово не
совпадает — то есть напечатанные правила Vim отстали, и `vim-highlight-check`
на них сегодня покраснел бы. Это ровно та беда, от которой печать и заводилась:
защита работает только вместе с прогоном, который её проверяет.
