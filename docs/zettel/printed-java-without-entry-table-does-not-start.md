# Вычтенный в сверке блок «границы входа» был не лишней частью, а дырой: напечатанная Java без него не запускается вовсе

Пять эталонов печати на flang (`emit-elixir`, `emit-js`, `emit-java`,
`emit-python`, `emit-csharp`) не печатали таблицу объявленных типов параметров.
Побайтовая сверка со свидетелем на JavaScript при этом зеленела — потому что
блок из вывода свидетеля **вычитался** перед сравнением
(`flang/test/entry-debt.mjs`). Вычитание выглядело честным приёмом: расхождение
одно, названо, остаток сверяется байт в байт.

Оно и было бы честным, будь блок украшением. Замер показал обратное.

**Улика, снятая прогоном.** Берём вывод двоичного для
`examples/rosetta/fizzbuzz.flang`, вырезаем ровно тот блок, который
вычитала сверка, и собираем:

    javac -encoding UTF-8 *.java      → код 0, ни одного замечания
    java -cp . FlangCli FizzBazz      → Exception in thread "main"
                                        java.lang.NoSuchMethodException: FizzBazz.entry()
                                          at FlangCli$Program.<init>(FlangCli.java:415)

То есть `javac` молчит, а программа не доходит до первой строки запроса:
прогонщик берёт метод `entry()` отражением при загрузке класса и сверяет по
таблице каждое пришедшее снаружи значение
(`Flang.checkEntry(program.entry(), …)`, `FlangCli.java:479`). Нет блока — нет
метода — нет запуска. Сверка зеленела на 163 программах, ни одна из которых не
запустилась бы.

**Почему `javac` молчит, а сверка зеленеет — это одна и та же ошибка.** Оба
судят по тому, что видят: компилятор Java не видит отражения, а сверка не видела
вычтенного. Признак, по которому такое ищется заранее: **если проверка что-то
вычитает, снимает или нормализует перед сравнением — спросить, что случится с
продуктом, если вычтенного не будет вовсе.** Не «расходится ли ещё что-то»,
а «работает ли то, что осталось».

**Цена закрытия.** Печать границы входа для Java — 128 строк на flang
(«Печать границы входа Java» и девять её спутников), таблица приезжает
настройками, как и текст рантайма: решить, какой у параметра объявленный тип, —
работа слоя типов, а не печати. Вычитание снято целиком, сверяются полные файлы:
20 проверок из 20, включая печать эталоном собственного исходника. У Rust вышло
128 строк, у Go — 104: цена у всех целей одного порядка, потому что блок один и
тот же, меняется только синтаксис литерала.

**Чего это НЕ закрывает.** У двоичного таблица всё равно пустая на чужой
программе: строит её `таблицаВхода` из `flang/src/types.mjs`, и пары на flang у
неё нет ни одной строки. Двоичный подставляет впечатанную таблицу, только если
она подходит программе (сверка пар «функция, параметр»), и об этом говорит
числом. Замер по корпусу 163 программ, цель java: расходится только границей
входа 158, чем-то ещё 1. Для сравнения, у давно втащенной цели `c` — 149 и 12.
То есть блок теперь печатается обеими сторонами, но заполняется по-разному, и
планка «расхождений ноль» упирается уже не в печать, а в отсутствие слоя типов
на flang.

**Чем подтверждено.** Ветка `rabota/vosem-java` поверх ствола `061b09c9`.
Прогоны: `node --test flang/test/self-emit-java.test.mjs` (20 из 20 без
вычитания), `javac`/`java` на выводе двоичного и на выводе Node,
попрограммная сверка двоичного с Node на `examples` и `flang/stdlib`.

**Чем ограничено.** Про elixir, js, python и csharp здесь только то, что долг у
них того же рода; запуск их вывода без блока не проверялся.
