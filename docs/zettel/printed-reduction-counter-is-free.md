# Счётчик витков в напечатанном коде уже стоит и не стоит ничего: миллиард витков, разница нулевая

Развилка «вносить ли вытеснение прямо в напечатанный код» упиралась в цену
счётчика редукций при работе. Цена измерена: **нулевая**, и счётчик **уже
напечатан** — заводить его не надо.

**Где он.** Печать в C ставит `FL_TRY(fl_tick(ctx, "Имя", error));` в хвостовой
цикл рекурсивной функции — `flang/self/emit-c.flang:3295`, функция
`«Хвостовой цикл»`. Сам счётчик — `fl_tick` в
`flang/src/emit/c/flang_runtime.c:841–859`.

**Сколько его.** В программе БЕЗ рекурсии — ноль вхождений: печать
`flang/conc/examples/counter.flang` в C дала `grep -c fl_tick` → **0**. В
хвостовой рекурсии — **ровно один на виток цикла**. То есть композиционно и
структурно доказанные функции не платят вовсе, а платит только настоящая
рекурсия.

**Замер.** Программа: `тотальная функция «Вниз»`, спуск по `нат` на 1. Печать в
C по умолчанию (`-std=c99 -O2 -flto`), запуск через `flang_cli --json`, пять
прогонов на вариант, машина `dev`.

| | 10⁹ витков, с |
|---|---|
| как печатается (счётчик есть) | 0,91 0,92 0,91 0,90 0,90 |
| строка `fl_tick` удалена | 0,92 0,90 0,90 0,91 0,91 |

Разница **в пределах шума**, обе средние 0,908 с → **0,908 нс на виток**.
Линейность проверена: 0 / 10⁸ / 5·10⁸ / 10⁹ витков дали 0,00 / 0,09 / 0,46 /
0,90 с — цикл не свёрнут оптимизатором.

**Счётчик при этом живой, а не мёртвый код.** Тот же прогон с
`"steps":"1000"`: сборка со счётчиком отвечает
`FLANG_RECURSION_LIMIT: функция «Вниз» исчерпала лимит шагов (1000)`, сборка без
счётчика считает до конца и отвечает `{"ok":true,...}`. Значит нулевая разница
во времени — это цена настоящей проверки, а не отсутствия проверки.

**Согласуется с прежними замерами.** `docs/benchmark-speed.md:415–423`: сборка
«`fl_tick` убран» против обычной по пяти задачам даёт 0,9…8,9 %, целиком внутри
разброса. `RESILIENCE.md:726–737`: виток `fl_tick` 2,412 нс, виток с ОТДЕЛЬНОЙ
проверкой кванта 2,365 нс — знак отрицательный, шум прибора 0,006 нс.

**Что из этого следует для вытеснения.** Дорого не считать, а **выйти**.
Счётчик есть и бесплатен; чего нет — способа вернуть управление планировщику из
середины вызова, потому что в напечатанном C кадры лежат на стеке C. Поэтому
цена вытеснения в напечатанном коде — это не цена счётчика (ноль), а цена
выбранной сделки: либо переигрывать пробег заново (В2: переплата 2,73×, ноль
байт), либо тащить продолжение (В4: 799 кадров на 400 элементов).

**Чем ограничено.** Одна задача, одна цель, хвостовая рекурсия. На нехвостовой
рекурсии `fl_tick` в цикл не печатается вовсе — там витки считает `fl_enter`
по глубине, и это другой замер.
