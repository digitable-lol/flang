# Приписанная теорема ЗАСЛОНЯЕТ сведение, которое ядро делает само: 45 потерь из 55 прогонов, и три из них тихие

Ядро снимает постусловие САМО, сведением цели с телом функции, и говорит об
этом прямо: «теоремы при нём нет и не нужно». Приписать теорему к такому
обещанию — не «добавить доказательство», а **отнять** его: путь сведения после
этого не пробуется вовсе.

## Замер, 23 августа 2026

К каждому обещанию, которое ядро закрывает само, приписана теорема — 55
прогонов `flang check --proof --json` через ворота, по одному файлу за раз,
девять файлов библиотеки (base64, dictionary, higher-order, logic, numbers,
numtree, optional, result, sets). Обоснование выбрано так, как выбрал бы человек
по методичке: `по свойству «X»`, где X — постусловие функции, которую тело
ДЕЙСТВИТЕЛЬНО зовёт (23 прогона), иначе `по примеру` (32 прогона).

```
вердикт «доказано» потерян                   45 из 55
  программа отвергнута целиком, код 1        42   ведомости нет вовсе
  ТИХО: код 0, ведомость на месте             3   доказанных стало меньше
на подмножестве «по свойству»                15 из 23   — две трети
```

Две трети на подмножестве — та же доля, что в улике «23 из 35», померенной
накануне на доле «множества и словарь» другим исполнителем.

Наивный вариант (ко всем 55 обещаниям приписано `по примеру «первый пример»`)
даёт 53 потери из 55: `по примеру` не берёт цель со свободным именем, и файл
отвергается.

## Заслон работает двумя способами, и оба — одна строка ядра

**ГРОМКИЙ.** Теорема не сошлась — программа отвергнута, ведомость не печатается,
и своё сведение ядро НЕ пробует. Проверено прогоном, а не по коду:

```
чистый flang/stdlib/base64.flang
  постусловие «тройка байтов даёт ровно четыре знака» — доказано сведением
  утверждений 30: доказано 10                       код возврата 0

+ теорема «тройка байтов даёт ровно четыре знака»
    по свойству «первая шестёрка неотрицательна, пока байт конечен»
  FLANG_PROOF_STEP: не выведено заключение …        код возврата 1
  ведомости нет вовсе
```

Обоснование здесь ЗАКОННОЕ — «Первая шестёрка» действительно зовётся из тела, —
просто цель им не берётся. Ядро могло бы ответить «доказано, а теорема
негодная»; вместо этого пропали все десять доказательств файла.

**ТИХИЙ, и он опаснее.** Теорема сошлась — и всё равно отняла:

```
чистый flang/stdlib/base64.flang            утверждений 30: доказано 10   код 0
+ теорема «знак азбуки — ровно один знак»
    по свойству «в азбуке ровно 64 знака»   утверждений 30: доказано  8   код 0

  «Знак 64»         знак азбуки — ровно один знак           доказано → доказано
  «Тройка байтов»   тройка байтов даёт ровно четыре знака    доказано → сетка
  «Шаг кодирования» третий байт закрывает тройку …          доказано → сетка
```

Ни замечания, ни ненулевого кода. Единственное отличие файлов — восемь строк
теоремы в конце. То же на `dictionary.flang`: теорема при «удаление не удлиняет
словарь» роняет ведомость с 11 до 10, отнимая «запись удлиняет словарь не больше
чем на одну связь».

## Почему

`flang/self/proofterm.flang`, «Проверить доказательства»:

```
пусть «без теоремы» равно (отфильтровать «постусловия» где «о» →
    «Это ничто» от («Взять поле» от «о» и "proof"))
пусть «закрытые» равно («Закрыть без теорем» от «без теоремы» и … )
```

`закрытые` — это неподвижная точка «что ядро закрыло само», и из неё берутся
ДВЕ вещи: вердикт для ведомости («Свод по объявлению») и **факты по вызову**
(«Дописать факт вызванного» проверяет `(«оплаченное».«доказанные») содержит
(«Ключ факта» от кого и имя)`). Обещание, к которому привязана теорема, в этот
список не попадает НИКОГДА — ни доказанное теоремой, ни доказуемое ядром.
Оттуда обе беды разом: своё сведение не пробуется, и чужие доказательства,
стоявшие на этом факте, разваливаются.

Второе место — там же, «Проверить постусловие терма»:

```
если «Это ничто» от («Взять поле» от «обязательство» и "proof")
  то «Свод по объявлению» …    вердикт берётся у неподвижной точки
  иначе «Свод по терму» …      считается ТОЛЬКО теорема
```

Отката на своё сведение нет. «Обстановка терма» вдобавок заводится с
`«факты» равным пустой список` — теоремному пути факты по вызову не выдаются
вовсе.

## Что чинить, если чинить

Меньшая половина, и она снимает ТИХИЙ класс целиком: подавать в «Закрыть без
теорем» ВСЕ постусловия, а не только бестеоремные. Тогда факт по вызову
существует независимо от того, написал ли кто-то рядом теорему.

Большая половина: при непустом `proof` брать вердикт теоремы, когда она
доказала, и вердикт ядра — когда нет, а негодную теорему называть ОТДЕЛЬНОЙ
бедой со своим кодом. Это меняет коды возврата на корпусе (сегодня негодная
теорема отвергает программу) и потому решается владельцем.

**Подделка, без которой правку принимать нельзя.** Ядро не должно начать верить
теореме как факту по вызову: теорема доказывает НАЗВАННОЕ утверждение, а факт по
вызову — это утверждение о вызванной функции, за которое ручается сведение.
Проба: обещание A, которое ядро само НЕ закрывает, закрыто теоремой; обещание B
зовёт A. После правки B обязано остаться сеткой. Честная половина: то же A,
закрываемое ядром, — B обязано стать доказанным.

**Цена.** Оба места — `flang/self/proofterm.flang` (не `proof-kernel.flang`).
Ответ «Проверить доказательства» сличается с близнецом `src/proofterm.mjs`
ПОБАЙТОВО — правка двойная. Перепечатка точки раскрутки обязательна и в том же
коммите.

## Сторож

Сторожа на убыль доказанного не было вовсе. Заведён:
`flang/scripts/storozh-dokazannogo.flang` — читает записанный пол
(`dokazannoe-vedomost.txt`), снимает ведомость каждого файла и краснеет кодом 1,
если доказанных стало меньше. План «Порча» подкладывает ту самую теорему в
base64.flang и требует, чтобы сторож покраснел: «порча замечена: сторож
доказанного ответил кодом 1 и назвал «УБЫЛО: base64.flang — было доказано 10,
стало 8»».

## Правило работы, до всякой починки

Никогда не приписывай теорему к обещанию, которое УЖЕ доказано. Сперва сними
ведомость и смотри только на недоказанные. И считай итог целиком: если после
работы доказанных стало меньше — ты не прибавил, а отнял.
