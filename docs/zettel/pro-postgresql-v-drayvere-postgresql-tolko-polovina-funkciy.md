# Про PostgreSQL в драйвере PostgreSQL — меньше половины функций: 39 из 83, остальные 44 годятся любой базе

Вопрос владельца: «мы пишем коннектор для postgres, а как с другими бд
поступать?» Ответ «писать ещё один такой же на каждую» плох ровно настолько,
насколько велика в драйвере доля кода, который к PostgreSQL отношения не имеет.
Доля посчитана.

`flang/stdlib/postgres.flang` на 21 августа 2026: **83 функции, 11 типов**.
Разложены на три кучи по правилу, а не на глаз:

| куча | правило отнесения | функций |
|---|---|---:|
| только протокол PostgreSQL | называет метку сообщения, номер версии протокола, номер типа колонки или вариант `«Весть»` поимённо | **39** |
| про любой провод | в подписи и теле только `строка`, `число`, `список строки` и разборные типы октетов; ни одной постоянной протокола | **31** |
| про любую базу | вид ОТВЕТА: строки, отказ, метка итога, значение поля | **13** |

Тридцать одна «про провод» вынесена в `flang/stdlib/provod.flang` и оттуда
ввозится обратно. Проверено прогонами до и после переезда: `flang test
flang/stdlib/postgres.flang` — 173 примера, прошло 173 в обоих случаях;
`flang io flang/examples/db/postgres-plan.flang` против настоящего PostgreSQL
17.10 — 14 поручений, код 0, тот же ответ до знака.

**Что оказалось общим на самом деле, а что только казалось.** Задание называло
шесть кандидатов заранее. Сошлись не все:

| кандидат | вышло |
|---|---|
| рамка сообщения на проводе | **нет.** Резка потока на куски общая, а сама рамка у PostgreSQL «буква + длина вместе с собой» и общей быть не может |
| разбор целых в сетевом порядке | **да**, целиком: `«Взять целое»`, `«Четыре октета»`, `«Два октета»` |
| вход по паролю (SASL/SCRAM) | **да, и он уже общий** — `scram.flang`, RFC 5802, ни строки про PostgreSQL |
| пул соединений | **нечего выносить**: соединение держит план, у программы на flang сокета нет по устройству языка |
| повтор при обрыве | то же — это дело плана |
| описание таблицы результата | **нет.** У PostgreSQL это сообщение `T`, и драйвер берёт из него одно число — количество колонок |

**Какую форму выбрали и почему.** Из четырёх развилок задания взята четвёртая с
половиной: вынести то, что уже доказано общим (провод), и НЕ обобщать остальное,
пока рядом не встанет второй драйвер. Довод числом: тринадцать функций «про
любую базу» работают над типом `«Весть»`, а он перечисляет сообщения PostgreSQL
поимённо. Чтобы вынуть его, надо знать, у скольких баз ответ устроен так же, —
а это и есть «обобщать по двум примерам, а не по одному».

Развилку «описание протокола данными, а исполнитель общий» отвергли не по вкусу:
исполнитель обязан быть функцией, принимающей таблицу сообщений параметром, а
именно этого в языке нет — функция как ЗНАЧЕНИЕ есть, а передача её туда, где
она приезжает данными, снимается дефункционализацией и требует видеть всю
программу целиком. Категорную поверхность отложили по той же причине: пока
драйвер один, объявлять категорию не из чего — функтор нужен между двумя.

**Почему второго драйвера так и нет: на машине нет второй базы.** Это не довод
и не отговорка, а замер, и он повторяется одной командой:

| чем проверено | что вышло |
|---|---|
| `ss -lnt` | слушают только PostgreSQL (5432, 55432, 55433, 55434) и Neo4j (7474/7475, 7687/7688) |
| проба порта на 3306, 6379, 8123, 9000, 9042, 27017, 11211, 1521, 1433 | закрыты все |
| `command -v` на mysql, mysqld, mariadb, redis-server, redis-cli, clickhouse, clickhouse-server, mongod, cqlsh, valkey-server, memcached, etcd | не установлено ни одной |
| `dpkg -l` | из баз только `libsqlite3` и `libhiredis` — библиотеки, не службы |
| `podman ps` | «invalid internal status, try resetting the pause process» — контейнеры не поднимаются |

Сеть с машины есть (`curl https://github.com/` отвечает 200), поэтому вторую
базу можно СОБРАТЬ из исходников, как собран весь остальной стек. Но это уже
подъём службы на общей машине, и решать это не тому, кто пишет драйвер.

Кандидатом на второй драйвер выбран **Bolt (Neo4j)**, и выбран по доводу, а не
по доступности: он максимально НЕ похож на PostgreSQL, а значит проверяет
разбиение по-настоящему. Рамка у него не «буква + длина», а куски по два октета
с нулевым куском в конце; значения не текст, а PackStream — двоичная запись с
метками типов; вход отдельным сообщением, а не полем пуска. Всё, что у него
общего с PostgreSQL, — ровно то, что уехало в «Провод»: октет, целое в сетевом
порядке, резка потока. Если разбиение верно, второй драйвер напишется без
единой новой функции про байты; если нет — это станет видно на первом же
сообщении.

**Чем ограничено.** Второго драйвера в дереве нет, и потому это разбиение — про
один пример. Считать его подтверждённым нельзя до тех пор, пока второй драйвер
не возьмёт `«Провод»` и не покажет числом, сколько из 31 функции ему пригодилось.
