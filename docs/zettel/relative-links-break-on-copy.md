# Относительная ссылка ломается ровно при копировании каталога — и первой ломается та, ради которой всё написано

Каталог, который живёт в двух местах, не может нести относительную ссылку
НАРУЖУ себя. Внутри себя — может: соседи остаются соседями при любом
копировании. А ссылка вида `../что-то` верна ровно в одном из двух мест и в
другом указывает в пустоту.

**Чем подтверждено.** `docs/zettel/README.md` отправлял читателя к передаче
состояния ссылкой `[../HANDOFF.md](../HANDOFF.md)`. В репозитории она верна:
`docs/zettel/../HANDOFF.md` = `docs/HANDOFF.md`, и сборка сайта её
принимает — 0 битых ссылок. В копии `/srv/flang-znanie/`, куда база кладётся для
всех пользователей машины, `HANDOFF.md` лежит РЯДОМ с `README.md`, поэтому
`../HANDOFF.md` = `/srv/HANDOFF.md`, и такого файла нет.

**Обиднее всего то, КАКАЯ ссылка сломалась.** Абзац при ней написан ровно для
того, кто начинает «с чистого листа или с другой учётной записи», — то есть для
того, кто читает копию, а не репозиторий. Проверка ссылок в сборке сайта врать
не начала: она честно проверяла тот экземпляр, который у неё был.

**Как починено.** Ссылка снята, оба пути названы текстом таблицей «откуда
читаете → путь». Тогда самодостаточны оба места, и ни один прогон не обязан
знать про существование второго. В `.claude/skills/flang-zettel/SKILL.md` к
команде обновления копии дописан второй шаг — копировать вместе с заметками и
`docs/HANDOFF.md`, иначе рядом с копией по-прежнему нечего открыть.

**Признак класса, по которому третий случай ищется заранее.** Любой файл,
который копируется в другое место дерева или машины, обязан ссылаться либо на
соседей, либо словами. Проверка «битых ссылок ноль» на ИСТОЧНИКЕ про копию не
говорит ничего: у копии другой родитель.

**Чем ограничено.** Про ссылки внутри каталога это неверно — `[[слаг]]` и
`(сосед.md)` переживают копирование целиком, и трогать их не надо.
