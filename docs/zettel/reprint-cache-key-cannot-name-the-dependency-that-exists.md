# Кэш перепечатки по отпечатку неверен не редко, а по устройству: зависимость идёт ВВЕРХ по ввозам, а ключ смотрит вниз

Задача 0040 предлагала пропускать работу над файлом, который не менялся, и брала
готовый ключ из `scripts/otpechatok-semeni`: «хеш содержимого плюс хеши
зависимостей». Ключ такой формы не выражает ту зависимость, которая у печати
есть.

## Напечатанные байты зависят от вердикта ядра о ВСЕЙ программе

`«Суд ядра о программе»` (`flang/self/bootstrap/compiler.flang`) возвращает
`«снятые»`, а `«Программа без снятых постусловий»` вычёркивает доказанные
сторожа из напечатанного кода. В семени это видно числом: на
`bootstrap/compiler_flang.c` в 21 374 208 байт осталось **77 строк `fl_post` и
одна `fl_pre`** — остальные сняты решением ядра.

## Пять мест, где вердикт выходит за файл и его зависимости

* **`«Снять предусловия» от «программа»`** (`flang/self/proofterm.flang:3459`)
  собирает МЕСТА ВЫЗОВА по всей программе. Место вызова функции `F` лежит в
  файлах, которые ввозят `F`, — то есть выше по ввозам, а не ниже. Список
  `«неоплаченные»` кормит седьмой ход (`proofterm.flang:2408`), и тот
  отказывается пользоваться постусловием функции, чьё `требует` где-то не
  оплачено.
* **`«Закрыть без теорем»`** — неподвижная точка: каждая попытка читает уже
  накопленное `«закрытые»`.
* **`«Пометить условные»` и `«Твёрдые ключи»`** — послепроход по всем вердиктам
  сразу.
* **`«Свести теоремы»`** (`obligations.flang`) — свёртка: вторая теорема того же
  имени видит первую закрытой.
* **`«По свойству»`** ищет постусловие вызванной функции ПО ИМЕНИ во всей
  программе.

Первые четыре уже названы задачей 0033 в разделе «НЕ НЕЗАВИСИМО»: там они мешали
раскладке по ядрам, здесь они ломают ключ кэша.

## Показано прогоном, 26 августа 2026

Три файла, двоичный `/srv/flang-rabota/w-predely/bootstrap/flang`, ворота
`PAMYAT=45G`. `nizh.flang` не ввозит ничего — значит его ключ есть хеш его
самого, и в обоих прогонах он один: `md5 a92597019297e59b64d76b5badf490f6`.

```
check --proof verh-payer.flang    код 0   emit → verh_platyaschiy.c, 9453 байта
check --proof verh-debtor.flang   код 1   FLANG_PRECONDITION_CALL, каталог печати ПУСТ
```

Разница между прогонами — только в файле, который ввозит `nizh.flang`. Ключ
совпал знак в знак, а правильный ответ о `nizh.flang` сменился с «вот его
напечатанные байты» на «печатать нельзя».

## Единицы «файл» у печати нет ни на входе, ни на выходе

Перепечатка — ОДИН вызов `emit`. Печать в C даёт один файл на всю программу:
семя — `compiler_flang.c` на 21,4 МБ на все 40 исходников; проба
`emit flang/self/lexer.flang` — один `lekser_flang.c`, где функции обоих файлов
замыкания лежат вперемешку. «Прошлого результата файла» не существует.

## Верный ключ уже есть и уже отвечает

Ключ, который верен, — хеш всей программы целиком. Это
`sh scripts/raskrutka.sh --bystro`, он стоит секунды. Сегодня его ответ:
**43 входа печати из 44 разошлись с семенем** (не менялся один —
`flang/self/bootstrap/corpus.flang`), и вдобавок разошлась мета: в отпечатке
`предел-шагов 1000000000`, в `scripts/raskrutka.sh` — `4000000000`, а предел
уезжает в напечатанный байт.

⚠ **Числа меты сошлись перепечаткой 30 августа 2026: в обоих местах теперь
`1400000000000`.** Довод заметки от этого не меняется — он о том, что ключ кэша
не умеет назвать зависимость, — но приведённое расхождение меты сегодня уже не
воспроизведётся.

То есть верный кэш попадает в 2,3 % входов, а неверный попадает часто и молчит.
