# Занятые слова цели доезжали до напечатанного кода: проверки зелёные, а собрать нельзя — 14 разных мест на четырёх целях из восьми

Программа из шести строк проходила `flang check` без замечаний и не собиралась
после `flang emit --target c`:

    тотальная функция «Сумма»
      принимает до: нат
      ...
          иначе до плюс («Сумма» от (до минус 1))

    proba_summy.c:13:63: error: expected ‘;’, ‘,’ or ‘)’ before ‘do’

Имя `до` транслитерируется в `do`. Экранирование в печати есть и работает: вызов
десятью строками ниже зовёт параметр `do_2`. А ПОДПИСЬ тела рекурсивной функции
брала имя сырой транслитерацией — `«Змейка» от («параметр».«имя»)` вместо уже
посчитанных «идентификаторов». Одно место на весь печатник.

**Дыра не одна и не только в C.** Прогон по спискам занятого, спрошенным у самой
печати, — каждое слово в шести позициях (параметр простой функции, параметр
рекурсивной, параметр взаимной рекурсии, связка `пусть`, поле записи, поле
варианта) плюс имя модуля:

| цель | слов занято | ломалось |
|---|---:|---|
| c | 49 | подпись тела рекурсивной (все 49 слов), `args`/`bounce` в батуте, `values`/`out` в фабрике, `region` в обёртке; имя модуля: `Fl`, `Flang runtime`, `Flang cli` |
| go | 76 | — |
| rust | 58 | поле `fields` в фабрике; имя модуля: 51 слово из 57 |
| java | 94 | — |
| js | 53 | имя модуля `Flang cli` — программа печаталась ПОВЕРХ прогонщика |
| python | 78 | имя модуля: 32 слова из 77 |
| csharp | 141 | имя модуля: `System`, `StringBuilder` |
| elixir | 84 | имя модуля: `False`, `True`, `Nil` |

Всего именем модуля не собиралось **89 программ из 630**.

**Общая причина у всех — не забытый вызов, а НЕПОЛНЫЙ СПИСОК занятого.** Мест,
зовущих экранирование, в каждом печатнике 18—23, и мимо них шло ровно одно
(подпись `_body` в C). Остальные тринадцать бед — экранирование звалось, но
список, от которого оно отталкивалось, не содержал нужного слова:

* имена, которые печать раздаёт СЕБЕ, стояли в отдельном списке («Занято в
  теле» у C), а параметры отталкивались от списка ключевых слов;
* имя модуля отталкивалось только от имён библиотеки цели («Занято целью X») и
  не отталкивалось ни от ключевых слов, ни от файлов, которые печать кладёт
  рядом.

**Самая опасная из них — не отказ сборки, а тихо иное значение.** Поле записи с
именем `values` давало в фабрике C

    fl_value values[2];
    values[1] = values;   /* «values» */

Здесь это ловится типами C. Совпади типы — программа собралась бы и считала
другое.

**Чем подтверждено.** Ветка `u/slova-c` над `fd3721e3`. Пробные программы
строятся ИЗ СПИСКОВ САМОЙ ПЕЧАТИ (`«Зарезервировано в C»`, `«Занято в теле»`,
… спрошены у двоичного), печатаются восемью целями и собираются восемью
настоящими компиляторами (cc 15.2, go, rustc 1.97, javac 26, node 26, elixirc
OTP-29, python 3.14, dotnet 10). Сторож — `node flang/scripts/slova-celey.mjs`,
подделка — `flang/test/fixtures/poddelka-slova-celey.flang`.

**Чем ограничено.** Сторож не ЗАПУСКАЕТ собранное: вопрос здесь один —
собирается ли. Что напечатанное считает верно, меряют примеры библиотеки.
Проверены имена в семи позициях; имена функций, типов и вариантов проверены
отдельно и там печать ОТКАЗЫВАЕТ (c, js, rust, java, csharp) или экранирует
(go, python, elixir) — тихой порчи нет ни у одной.

**Побочно измерено:** печать программы с сотнями ТИПОВ у java, elixir и csharp
идёт больше двадцати пяти минут (342 типа — не дождались), тогда как c, go,
rust, python, js справляются за минуты. Это та же беда, что в
[[java-printer-rebuilds-the-taken-name-list-per-function]], только видна и на
двух других целях.
