# Возврат работы, потерянной чужим слиянием, из второй ветки даёт не конфликт, а недостижимый случай — и файл молча выпадает из всех замеров

21 августа 2026 ветка `u/hmac` потеряла в стволе разбор входа SASL. Дальше
случилось два независимых исправления:

- `c1ff756d` «Возвращён разбор SASL, потерянный при чужом сведении» — вернул
  прежний код как был;
- `7587800e` «Вход по scram: четыре RFC-2202 вектора…» — в другой ветке написал
  тот же разбор заново, точнее (список способов читается «Текстом до нуля», а не
  «Текстом знаков»).

Обе ветки влиты. Git развёл их **без единого знака конфликта**: правки попали в
разные места одного постусловия, и текстовому сведению они не мешали. В
`flang/stdlib/postgres.flang` в постусловии функции «Разобрать вход» встали ДВА
набора случаев `«Нужен SASL»`, `«Продолжение SASL»`, `«Конец SASL»` — второй
недостижим.

**Последствие тяжелее самой ошибки.** `flang check` на этом файле отвечал тремя
`FLANG_MATCH_UNREACHABLE` и кодом 1, а всякий замер доказуемости берёт ведомость
у `flang check --proof` — то есть у файла, который проверку не прошёл, ведомости
нет вовсе. Драйвер PostgreSQL, самый большой файл библиотеки, **не входил в счёт
«столько-то утверждений, столько-то доказано» ни одним числом**, и заметить это
по самому счёту нельзя: он просто меньше, а не красный.

**Чем подтверждено.** Ветка `u/bazy-dannyh` от `422f42a3`, двоичный собран из
той же точки.

```
до:     flang check flang/stdlib/postgres.flang   → 3 замечания, код 1
после:  то же                                     → замечаний нет, код 0
```

Снятие лишнего набора (18 строк) вернуло в счёт библиотеки **60 утверждений, из
которых ядро доказывает 4** (3 напрямую, 1 индукцией; остальные 56 — «на сетке»,
то есть прогнаны по примерам и не доказаны). Счёт снят
`flang check --proof --json` с отбором своих объявлений: в связанном дереве
утверждений 95, из них 35 приезжают из `provod.flang` и `numbers.flang`.

**Тем же слиянием чинится и записанный долг.** Заметка
[[vetka-vlita-a-eyo-raboty-v-stvole-net]] называет «Начало SASL» и «Ответ SASL»
пропавшими из ствола. На `422f42a3` они **на месте** (строки 272 и 297 драйвера),
и `bootstrap/flang io scripts/storozh-srashchivaniya.flang` отвечает «званых
которых нет 0», код 0. Долг закрыт тем самым коммитом `c1ff756d`, который и
породил недостижимый случай: одна и та же правка закрыла долг и завела ошибку.
Проверка плана SCRAM это подтверждает: до правки
`flang check examples/db/postgres-scram-plan.flang` отвечал теми же тремя
замечаниями и кодом 1 (замечания приезжали из ввоза драйвера), после — код 0.

**Чему учит.** Счёт имён из соседней заметки ловит ПРОПАЖУ, но не ловит ВОЗВРАТ
задним числом: имя в дереве есть, значит по счёту всё цело. Второй признак того
же рода поломки — **файл, у которого нет ведомости**. Его стоит спрашивать
отдельно: «сколько файлов библиотеки не отдали ведомость и почему», а не только
«сколько утверждений доказано». Молчащий файл и файл без утверждений в общем
числе неразличимы.

**Чем ограничено.** Недостижимый случай нашёлся потому, что он оказался в
ПОСТУСЛОВИИ, где компилятор судит полноту разбора. Тот же дубль в теле функции
дал бы просто мёртвую ветку, и её никто бы не назвал.
