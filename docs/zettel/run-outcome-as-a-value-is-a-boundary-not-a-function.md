# Отказ прогона, отданный значением, — граница, а не одна функция: её ловят исключением 33 места, а не одно

Оракул поиска нарушений на сетке (`flang/src/grid.mjs`) не переносился на flang
не потому, что у него хитрый оракул, а потому, что он **ловит отказ прогона
примера исключением языка-хозяина**, а исключений у flang нет by design. Правка
казалась частной («нужна для grid») — измерение показало обратное.

**Чем подтверждено.** Обход всех `.mjs` дерева (`flang/src`, `flang/bin`,
`flang/proof`, `flang/scripts`, `flang/conc`, `scripts`, `flang/test`) с поиском
блоков `try`, внутри которых стоит вызов прогона (`evaluate`, `createRuntime`,
`runtime.call`, `доиграть`, `начать`). Ветка `work/otkaz-znacheniem`, 19 августа
2026, дерево `github/main` `9e2f3265`.

Мест — **33**: 13 в рабочем коде и 20 в проверках.

| файл | мест |
|---|---:|
| `flang/src/proofterm.mjs` | 3 |
| `flang/src/compat.mjs` | 2 |
| `flang/src/conc.mjs` | 2 |
| `flang/src/factcheck.mjs`, `functor.mjs`, `grid.mjs`, `hotswap.mjs`, `repl.mjs` | по 1 |
| `flang/conc/bench.mjs` | 1 |
| проверки (20 файлов) | по 1 |

То есть «отказ прогона значением» — это не услуга оракулу, а **граница всякого,
кто исполняет чужой код и не должен падать**: факт-чекинг, песочница, оболочка,
планировщик, будущий языковой сервер.

## Четыре вида, и каждый заслужен потребителем

Замкнутая сумма исхода: `значение`, `отказ`, `предел`, `не готова`
(`ВИДЫ_ИСХОДА` в `flang/src/interpret.mjs`; тип «Исход прогона» в
`flang/self/interpret.flang`).

Два последних — те самые, которых у пары «значение либо исключение» **нет
вовсе**, и оба уже различались руками до того, как стали видами:

- **предел** — `factcheck.mjs` («ответ не может быть дан за отведённый бюджет»),
  `compat.mjs` (у тотальной функции упор в предел значит не то же, что у
  обычной), `grid.mjs` (пример, упёршийся в предел, — «не искали», а не
  «нарушение»);
- **не готова** — `grid.mjs` держит для этого ОТДЕЛЬНЫЙ `try` вокруг
  `createRuntime`: у неготовой программы не проверен ни один пример, а не «первый
  отказал».

Вида под «вычислитель сломался» нет нарочно: исключение, которое не диагностика
flang, — дефект реализации, а не исход программы, и оно летит наружу как летело.
Тем же доводом `flang/src/failures.mjs` не пускает `FLANG_INTERNAL` в свой список
видов отказа процесса.

## Что оказалось дешевле, чем ожидалось

Перенос `grid` упирался не в отсутствие функций первого класса. Вычислитель
зовётся ПО ИМЕНИ, и это язык умеет — так уже сделано в `self/oracle.flang` и
`self/proof-kernel.flang`. Проверено отдельным модулем: 24 строки на flang,
которые поверх «Вызвать исходом» отдают ровно три ответа оракула сетки
(`дошёл` / `отказал` с кодом / `тень не собралась`), проходят `flang check` без
единой диагностики. Цена та же, что заплатил `oracle.flang`: такие функции
**обычные, а не тотальные**, — и это честно, потому что считается чужая
программа.

**Чем ограничено.** Плоская запись «Итог прогона» из `self/interpret.flang` не
убрана, а стала ПРОЕКЦИЕЙ суммы (одна тотальная функция): её ещё зовут шесть
файлов — `conc`, `oracle`, `law-oracle`, `repl`, `proof-kernel`, `compiler`.
Проекция теряет ровно те два различия, ради которых сумма и заведена, поэтому
новым потребителям она не годится. И 33 места, ловящие отказ исключением, на
значение НЕ переведены: переведены 3 (в `self-interpret.test.mjs`), а остальные
30 продолжают ловить бросок — с той разницей, что бросок теперь **производный**:
`call` у свидетеля есть тонкая обёртка над `исход`, дорога одна.
