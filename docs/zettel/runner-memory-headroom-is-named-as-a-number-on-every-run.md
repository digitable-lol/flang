# Снятие работы по памяти неотличимо от отказа по существу, пока запас раннера не назван числом

`scripts/memory-headroom.sh` не ставит предела и никого не снимает: он смотрит и
называет, сколько памяти оставалось раннеру, и кладёт число в сводку прогона.

**Зачем.** Три случая за неделю, и каждый диагностировали по нескольку раз и
по-разному: `flang check flang/self/parser.flang` — 37,1 ГиБ, `io
scripts/guards/name-splicing-guard.flang` — 31,6 ГиБ, `io
scripts/guards/link-guard.flang` — 15,0 ГиБ (замеры 30 августа 2026). У раннера
GitHub 15,61 ГиБ — число снято с самого раннера (`MemTotal`, прогон 33316181246),
а не с рекламной страницы; из них 0,95 ГиБ держат агент, кэш и службы, прогону
остаётся около 14,66. Первые два не влезали, и в журнале это выглядело так:
начало печатается, три минуты тишины и «The runner has received a shutdown
signal» либо «exit code 143» — ни кода по существу, ни имени файла, ни слова про
память. Третий, `link-guard`, считался зелёным — и был им 22 августа при 571
файле; сегодня ему нужно 15,02 ГиБ при 14,66 свободных, и узнать об этом было
неоткуда: `ci.yml` ходит только на тег.

**Почему не предел.** Предел на адресное пространство у flang неверен: адресного
ему нужно вдвое-впятеро больше занятого, и такой предел снял бы то, что влезает.
Своей контрольной группы на раннере GitHub нет.

**Четыре исхода, и в этом всё дело:** работа упала при малом остатке — НЕ ВЛЕЗЛО;
упала при памяти вдоволь — упала ПО СУЩЕСТВУ; прошла впритык — влезла, запас
назван; прошла с запасом — строка с числами. Второй исход не менее важен первого:
он снимает подозрение с памяти, когда дело не в ней.

**Чего сторож не ловит.** Раннера, убитого целиком: отчёт выполнять некому, и
признак ровно один — сводка пуста при красной работе. Пика одного шага:
наблюдатель смотрит на машину целиком — и это ровно то число, по которому работу
снимают. `/usr/bin/time -f %M` не годится: снятый прогон не доживает до печати, а
в части песочниц `getrusage` отдаёт ноль (см. `flang/scripts/memory-guard.flang`).

**Чем подтверждено.** Замеры 30 августа 2026; работа `ci(binary)` от того же
дня (коммит `c194a2a0`) упала, забыв `FLANG_TMP`, — умолчание `/srv/tmp` для своей
машины, на раннере такого каталога нет.

**Чем ограничено.** Итог кладётся в два места (сводка и лог) — сводку не
забирают при убитом раннере, лог остаётся всегда. Мерки нет (macOS без `/proc`) —
код 0 словами: отсутствие мерки — свойство машины, а не беда дерева. Запас, ниже
которого «влезло» неправда, — гигабайт, не ноль: последние сотни мегабайт машина
отдаёт свопом.
