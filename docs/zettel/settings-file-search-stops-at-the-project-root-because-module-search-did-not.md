# Поиск файла настроек обрывается на корне проекта, потому что поиск модулей этого не делал — и однажды взял чужой черновик

Файл `.flangrc` читают `scripts/flangrc.sh` (оболочка собирает источники,
`scripts/settings-file.flang` решает) и стережёт `scripts/guards/flangrc-guard.sh`.
Оба устроены вокруг одного решения: подъём вверх по каталогам обязан иметь
названную границу.

**Почему оболочка, а решает flang.** Замер 8 сентября 2026, двоичный 0.7.14: у
хозяина `flang io` поручения «Прочитать переменную среды» нет — на него приходит
`FLANG_IO_UNKNOWN: хозяин не знает поручения «Прочитать переменную среды»`;
«Прочитать доводы» нет тоже. Собрать источники программа на flang сегодня не
может физически. Оболочка собирает, flang решает — ровно так же разделены
`ярлык` и `ярлыки.flang`, и по той же причине.

**Где ищется файл и почему поиск не может уйти наверх.** Проектный `.flangrc`
ищется от начального каталога вверх, и подъём обрывается на каталоге с корневой
приметой — `.flangrc`, `.git` или `flang.package`, — включая сам этот каталог.
Приметы по дороге не встретилось (до `$HOME` или до корня файловой системы) —
проектного файла нет вовсе: подъём не «доходит докуда дошёл», он объявляется
несостоявшимся. Это починка уже случившейся беды: поиск модулей поднимается
вверх, пока в очередном предке лежит хоть один `.flang`, и 8 сентября 2026 сборка
сайта взяла модуль «JSON» из чужого черновика `/srv/tmp/json.baseline.flang`,
ответив кодом 0 (задача 3127). Настройки опаснее модуля: подменённый `.flangrc`
меняет не одну сборку, а язык, которым программа отвечает человеку. Второй
довод — уже принятый в дереве: манифест `flang.package` ищется только рядом со
входным файлом (`pkg_declaration` в `flang/src/emit/c/flang_repl.c`); у настроек
подъём есть, потому что у проекта бывает подкаталог с исходниками, но у него
названа граница. Замер, показывающий, зачем границы названы поимённо: на этой
машине лежит `/tmp/.git`, и поиск из любого временного каталога дошёл бы до него.

Порядок проверки внутри каталога тоже часть правила: сперва `.flangrc`, потом
корневые приметы. Раз `.flangrc` сам обрывает подъём, дальний файл не
перекрывает ближний ни при какой раскладке каталогов.

**Почему имена переменных среды латиницей.** Замер 8 сентября 2026: `bash -c
'FLANG_ЯЗЫК=ru'` — «command not found», код 127; dash — то же; zsh — код 0.
Переменная, которую в двух оболочках из трёх нельзя задать, — ловушка. Ключи
файла остаются русскими: файл читает flang. Ключ `версия` зовётся
`FLANG_PROJECT_VERSION`, а не `FLANG_VERSION`: так уже зовётся `#define` версии
самого двоичного, а ключ говорит про проект, и одно имя на два числа развело бы
их молча.

**Почему сторож на оболочке и как устроена проба порчи.** Сторож на flang,
лежащий в `scripts/`, ввозит соседей по имени и ищется тем же подъёмом — его
самого можно подменить черновиком из общей зоны; и сторож нужен, когда
`bootstrap/flang` не собран. Поэтому судится вывод читателя `--места` и `--файл`,
без двоичного; значение спрашивается только при собранном двоичном, и его
отсутствие сказано вслух. Настоящее дерево для пробы не годится в обе стороны
(покрасить — положить файл выше корня в чужую зону, позеленить — убрать чужой
файл), поэтому проба строит игрушечное дерево с `.git` (без него подъём ушёл бы
до `/tmp/.git`) и гоняет двух читателей: целого и с вынутым обрывом подъёма.
Портится названное условие, а не номер строки. Испорченный читатель лежит в
игрушечном `scripts/` рядом со ссылкой на настоящий `bootstrap/` — иначе он
краснел бы не тем. Кода 1 мало: требуется именно нарушение «ВНЕ дерева».

**Чем подтверждено.** Замеры 8 сентября 2026: `FLANG_IO_UNKNOWN`, три оболочки,
`/tmp/.git`, задача 3127.

**Чем ограничено.** JSON для «Выбранное значение» собирается python3, а не
printf: значение может нести кавычку и перевод строки. Порядок в `--откуда`
повторяет порядок «Выбранное значение» и разойтись им нельзя.
