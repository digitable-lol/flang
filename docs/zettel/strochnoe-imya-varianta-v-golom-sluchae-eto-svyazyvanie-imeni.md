# Строчное имя варианта в голом «случай «имя»» читается как связывание имени, а не как вариант

`случай «Пришёл пульс»` разбирает вариант. `случай «отложить»` для варианта
`«отложить»` — НЕТ: он связывает всё значение с именем «отложить», то есть
работает как `любое`, и все следующие случаи становятся недостижимы.

Диагностика при этом говорит правду, но не про то место:

```
FLANG_MATCH_UNREACHABLE: случай недостижим: предыдущий случай «любое» покрывает всё
```

Указатель на место — `null`, слова «любое» в исходнике нет, и искать приходится
перебором функций. У меня это заняло несколько заходов на файле в 500 строк.

**Различает случаи РЕГИСТР ПЕРВОЙ БУКВЫ.** С прописной имя ищется среди
вариантов, со строчной — вводится как новое. Поэтому в `flang/conc/link.flang`
голая форма работала всегда: там все варианты названы с прописной.

**Лечится явным словом:** `случай вариант «отложить»`. Оно разрешено и для
вариантов без полей.

**Где ждать снова.** Строчными в этом дереве названы имена ДЕЙСТВИЙ ЯЗЫКА —
`отправить`, `через`, `отложить`, `продолжить`, `остановить`, `поручить`,
`породить`. То есть попадёт в эту ловушку всякий, кто разбирает действие
процесса, а таких мест будет тем больше, чем дальше едет перенос рантайма на
flang.

**Чем подтверждено.** Воспроизведено на отдельной пробе в семь строк: тип с
вариантами `«отправить»`, `«отложить»`, `«продолжить»`, `«остановить»` и разбор
по нему дают две диагностики `FLANG_MATCH_UNREACHABLE`; замена двух голых
случаев на `случай вариант …` делает файл валидным без единой другой правки.
