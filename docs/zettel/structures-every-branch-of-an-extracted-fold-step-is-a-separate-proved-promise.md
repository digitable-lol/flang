# У вынесенного шага свёртки открыта каждая ветвь тела, а не только первая

Приём «вынести шаг свёртки из лямбды» описан на странице
[«Какие обещания ядро берёт»](../site/kak-dokazat.ru.md) и там же измерен:
18 дописанных обещаний, 18 доказанных. Но записан он так, будто у шага бывает
одно обещание. Это не так: **у шага с телом-`если` открыты ОБЕ ветви, и вторая
доказывается тем же правилом, что первая, ничего не стоя сверх одной строки.**

Половина шагов библиотеки стояла с обещанием только про одну ветвь — обычно про
`то`. Дописывание `иначе` той же формой,

```flang
// тело шага
если ход содержит буква
  то «Заменить» от ход и буква и («Заглавная буква» от буква)
  иначе ход

// стояло: только вторая ветвь
обеспечивает «буквы нет — ход не трогается»
  если не (ход содержит буква) то результат равен ход иначе да

// дописано: первая, равенством ТЕРМУ ТОЙ ЖЕ ВЕТВИ
обеспечивает «буква есть — весь ход заменяется заглавной»
  если ход содержит буква
    то (результат равен («Заменить» от ход и буква и («Заглавная буква» от буква)))
    иначе да        ← ДОКАЗАНО
```

даёт доказанное обещание сразу. Заключение при этом не обязано быть литералом:
годится терм той же ветви, в том числе вызов с доводами и целая запись
(`результат равен (запись «Обрезка справа» с «готово» равным … и «пробелы»
равным "")` — доказано).

**Ярусов берётся не меньше трёх.** У «Шага обрезки слева» тело двухъярусное, и
обещание про внутреннюю ветвь, записанное вложенной охраной,

```flang
если не (ход.«началось»)
  то (если не (знак равен " ") то (результат равен (запись … )) иначе да)
  иначе да
```

тоже доказано.

**Чем подтверждено.** Ветка `u/library-structures`, двоичный
`/srv/flang-rabota/w-predely/bootstrap/flang`, `check --proof`. На
`flang/stdlib/strings.flang` дописано девять обещаний, взялось семь, и все
семь — либо вторая ветвь уже вынесенного шага, либо шаг, вынесенный из
последних двух лямбд модуля:

```
было:  утверждений 102: доказано 43 (из них индукцией 1), сетка 59
стало: утверждений 109: доказано 50 (из них индукцией 1), сетка 59
```

Знаменатель вырос ровно на число доказанных: ни одно из дописанного не
осело в сетку.

То же на двух соседних модулях, теми же двумя ходами и тем же двоичным:

```
flang/stdlib/lists.flang      51 / 23 / 28  →  59 / 31 / 28
flang/stdlib/strlists.flang   19 /  6 / 13  →  21 /  8 / 13
flang/stdlib/dictionary.flang 29 / 21 /  8  →  32 / 24 /  8
```

Сетка не выросла ни в одном из четырёх модулей — а значит приём не «пробует
наугад»: если ветвь тела списана в охрану дословно и заключение — терм той же
ветви, обещание берётся.

**Граница приёма не сдвинулась.** Наверх, к самой свёрточной функции, ни одно
из этих обещаний не поднялось — у «В верхний регистр», «Обрезать справа» и
«Только цифры» вердикты остались прежними. Это то же, что уже записано в
[[left-fold-is-blocked-because-the-fold-rule-does-not-read-the-callee-postcondition]]:
уровень шага открыт, уровень свёртки закрыт, и дописывание шагу этой стены не
трогает. Прибавка идёт целиком из новых обещаний о самом шаге.

**Что при этом НЕ работает, и это тоже замер.** Вид цели «начинается с» у ядра
есть, но правила «начало по построению» через `соединить` — нет. Два места, оба
с телом-склейкой, оба сетка:

```flang
тело: соединить (соединить ход с разделитель) с часть
обеспечивает «склейка начинается накопленным» результат начинается с ход   // сетка

тело: соединить буква с ход
обеспечивает «обращённое начинается свежей буквой» результат начинается с буква // сетка
```

Обе правки откачены: знаменатель они растят, числитель — нет.
