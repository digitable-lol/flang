# Терм в сверщике можно держать строкой, потому что flang скобит каждую двуместную форму

Проигрыватель сведения обязан делать с термом три вещи: находить подтерм,
заменять его целиком и разрезать по знаку верхнего уровня. Обычный способ —
разобрать терм в дерево, но разборщик языка внутри сверщика — это второй
компилятор, и «сверщика можно прочитать за вечер» перестало бы быть правдой.

Дерево не понадобилось. В flang каждая двуместная форма пишется в скобках
(`(«Высота» от х) плюс 1`), поэтому ПОДТЕРМ — ЭТО ПОДСТРОКА СО СБАЛАНСИРОВАННЫМИ
СКОБКАМИ. Отсюда три приёма, и все на встроенных строковых:

- **разрез по верхнему знаку**: разбить наивно по `" знак "`, потом склеивать
  куски обратно, пока счёт скобок не сойдётся. Склеенный кусок и есть часть
  верхнего уровня;
- **замена подтерма**: `соединить (разделить … по …) по …`, то есть замена
  подстроки — но по ПРОБЕЛЬНЫМ КРАЯМ, иначе имя `х` находится внутри `хвост`;
- **лишние скобки**: `( ( X ) )` и `( X )` — один терм, а строки разные. Ловится
  так: место вставки бывает уже в скобках, и тогда меняется ` ( что ) ` целиком,
  а не голое ` что `. Два прохода вместо одного.

**Чем подтверждено.** `flang/proof/сверщик.flang`, раздел «термы: канонический
вид» — 189 строк решений на всё вместе. Прогон
`sh flang/proof/подделки/сведение.sh` проходит на двух программах с вложенными
вызовами (`«Высота» от («Копия» от х)`) и ветвлением в теле.

**Чем ограничено.** Строковый литерал со скобкой внутри собьёт счёт скобок. В
целях доказательств такие не встречаются; встретится — сверщик ОТКАЖЕТ (счёт не
сойдётся), а не примет молча, то есть ошибка падает на безопасную сторону.
