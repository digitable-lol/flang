# Двоичный хозяин не знает поручения «Запустить процесс с вводом», хотя словарь его объявляет

`flang/cat/SPEC.md` перечисляет шестнадцать поручений и говорит: «на каждое
поручение обязан ОТВЕТИТЬ КАЖДЫЙ хозяин… Что осталось невозможным — это
`FLANG_IO_UNKNOWN`: «хозяин не знает такого поручения» означает, что хозяин
отстал от словаря языка, и вот этого быть не должно ни у кого». Быть — есть.

**Чем подтверждено.** Ветка `u/port5`, прогон
`bootstrap/flang io flang/scripts/kernel-forgeries.flang` версии 0.5.1:

```
• flang/test/fixtures/poddelka-krug-pri-rabote.flang:
  собранная программа не запустилась —
  хозяин не знает поручения «Запустить процесс с вводом»
```

**Чем это дорого.** Подать что-нибудь на вход чужой программе — обычное дело
проверки: спросить собранный `flang_cli`, померить пик через `/usr/bin/time`,
прогнать пачку вопросов через прогонщик двоичного одним процессом. Всё это
приходится делать через оболочку:

```
вариант «Запустить процесс» с программа равным "sh" и аргументы равным
  ["-c", "printf '%s\n' '<запрос>' | <программа>"]
```

Работает, но втаскивает в проверку кавычки оболочки: запрос обязан не содержать
одинарной кавычки и обратной косой. В двух переносах (`kernel-forgeries.flang`,
`memory-guard.flang`) это верно и проверено, но правило это негласное — язык
его не держит.

**Чем ограничено.** Речь только о двоичном хозяине. `«Запустить процесс»` (без
ввода) он знает и отвечает как обещано, двумя откликами.

**Что рядом казалось невыразимым и выразилось.** Здесь стояло: «пачка вопросов
прогонщику построчно — тот приём, которым `flang/scripts/target-occupied-guard.mjs`
укладывает 800 с лишним вызовов в один процесс, — на flang без этого поручения
не выражается вовсе». Это оказалось неверно, и опровергнуто прогоном:
`scripts/occupied-names-guard.flang` укладывает около четырёх тысяч вопросов в 87
поручений и 7 секунд. Пачка ПИШЕТСЯ ФАЙЛОМ («Записать файл»), а потомку
подаётся перенаправлением: `sh -c 'cd .. && exec bootstrap/flang < output/…'`.

Через файл кавычки оболочки не проходят вовсе, и негласное правило «в запросе не
должно быть одинарной кавычки и обратной косой» перестаёт быть нужным: в argv
едет только имя файла. То есть поручение «Запустить процесс с вводом» нужно не
для того, чтобы приём стал возможен, а для того, чтобы он не шёл через
посредника; строка `sh -c` с перенаправлением — цена, а не преграда.
