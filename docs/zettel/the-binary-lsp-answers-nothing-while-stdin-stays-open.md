# Двоичный `flang lsp` не отвечает, пока стандартный ввод открыт, — и потому редактору не годится, хотя побайтовую сверку проходит

Языковой сервер, втащенный в двоичный `flang`, копит ответы до **закрытия
стандартного ввода**. Редактор ввод не закрывает никогда: он держит его открытым
весь сеанс и ждёт ответов по ходу дела. Значит в редакторе двоичный сервер
выглядит просто висящим — ни диагностик, ни подсказок, ни единого сообщения об
ошибке.

**Чем подтверждено.** Одно и то же сообщение `initialize` подано двум серверам,
ввод в обоих случаях держится открытым четыре секунды
(`editors/vim/checks/stream.sh`, ветка `vypusk/vim`, двоичный собран из этого
же дерева `make -C bootstrap`):

```
двоичный flang lsp: при открытом вводе 0 байт, после закрытия 334 байт
flang-lsp на Node:  при открытом вводе 334 байт, после закрытия 334 байт
```

Замер по секундам: за 2 секунды при открытом вводе — 0 байт; после закрытия все
334 байта пришли разом. Свидетель на Node отвечает за 0,1 секунды.

**Почему этого не увидела побайтовая сверка.** Сверка подаёт серверу ГОТОВЫЙ
сценарий сообщений и закрывает ввод. При таком способе оба сервера отвечают
одинаково — 11 сообщений, 155 956 байт, расхождений 0, — потому что закрытие
ввода наступает сразу и разница исчезает. Сверка сравнивала СОДЕРЖИМОЕ ответов,
а сломано было ВРЕМЯ их появления, и на это у неё нет ни одного измерения.

Класс шире случая: **побайтовая сверка со свидетелем слепа ко всему, что
касается времени и потоковости.** Всё, что живёт в режиме «долгий процесс,
который отвечает по ходу дела», — языковой сервер, наблюдатель за файлами,
сервер на сокете — обязано проверяться замером с ОТКРЫТЫМ вводом, а не подачей
сценария.

**Что из этого следует.** Обещание «Node для редактора больше не нужен» сегодня
неверно: подсветка в Vim и Neovim работает без Node, а языковой сервер — нет.
Поиск сервера в `editors/vim/autoload/flang.vim` двоичный по умолчанию НЕ берёт
и говорит человеку, почему; включается он явно —
`let g:flang_dvoichnyy_lsp = 1`. Когда двоичный научится отвечать на лету,
`flang io scripts/lsp-check.flang` скажет об этом строкой, и порядок поиска
можно будет переставить.

**Чем ограничено.** Померено на одном сообщении `initialize` и на Linux. Где
именно копится ответ — в чтении ввода, в печати вывода или в цикле хозяина, —
замер не различает: он меряет то, что видит редактор.
