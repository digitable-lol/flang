# Срок потомка у хозяина — главное препятствие для переноса долгих проверок, и в справке его нет

Хозяин `flang io` режет КАЖДОГО потомка сроком; умолчание — 30 000 мс. Проверка,
которая запускает что-нибудь долгое (сборку, печать точки раскрутки, прогон
другого плана), на умолчании убивает собственный опыт и отвечает «смотреть
нечем» — то есть выглядит сломанной, не будучи сломанной. Ключ `--timeout N`
у двоичного ЕСТЬ и работает, но в `flang io --help` он не назван вовсе, поэтому
находится он только тем, кто уже упёрся.

**Чем подтверждено.** Ветка `u/port3`, база `ff8ad5d0`, двоичный 0.5.1.

- `scripts/bootstrap-point-by-binary.flang` без ключа: потомок убит на 30-й секунде,
  план ответил `FLANG_TOCHKA_UBITA … сигналом SIG9`. Сама работа
  (`sh scripts/bootstrap-c.sh --check`) идёт **18 м 50 с** и берёт **24,1 ГБ**
  (`/usr/bin/time -v`, пик 24 127 504 КБ). Нужен `--timeout 2400000`.
- `scripts/child-timeout.flang` без ключа: отказ на четвёртом опыте за 35 с;
  с `--timeout 120000` — восемь опытов за 67 с.
- Значения ключа: `0`, `-5`, `много` отвергаются кодом 2 («кривой вызов»);
  **`1.5` двоичный принимает молча**, а удалённый хозяин на JavaScript отвечал
  кодом 2. Это расхождение, а не свойство.
- Истёкший срок приходит плану как `«Процесс убит»` с сигналом `SIG9`. Удалённый
  хозяин отдавал `«Сбой»` с кодом `FLANG_IO_TIMEOUT`. Значит проверка, перенесённая
  на двоичный, обязана сверять КОД ВОЗВРАТА, а не текст отказа.

**Чем ограничено.** Про двоичный 0.5.1 и про поручение `«Запустить процесс»`.
Поручения `«Запустить процесс с вводом»` двоичный хозяин не знает вовсе —
отвечает `FLANG_IO_UNKNOWN`, хотя поручение объявлено в `flang/cat/SPEC.md`;
половина прежней проверки `flang/test/potomok.test.mjs`, где хозяин пишет
потомку в ввод, из-за этого не проверяема ничем.
