# Закрытый список правил сверщика разошёлся с ядром: было восемь, стало тринадцать

Сверщик доказательств (`flang/proof/сверщик.flang`) держит закрытый список имён
правил сведения и отвергает запись, сославшуюся на что-то вне списка. Про него
говорили: «было „верю трём тысячам строк ядра“, стало „верю восьми названным
теоремам“». Список был написан на глаз, и с ядром он не совпадал **ни с одной
стороны**.

## Улика снята прогоном, а не чтением

```
./bootstrap/flang check flang/test/fixtures/ohrana-daet-fakt.flang \
    --proof --записать /srv/tmp/…/z
sh flang/proof/сверить.sh flang/test/fixtures/ohrana-daet-fakt.flang /srv/tmp/…/z
→ код 1
  НЕ СОШЛОСЬ: теорема «у хорошего дерева левое хорошо»: запись ссылается на
  правило сведения, которого сверщик не знает: разбор цели по условию
```

Программа честная, запись честная, ядро закрыло посылку шага правилом «разбор
цели по условию» — и сверщик назвал это подделкой.

## Числа

Поле `правило` записи «Сведение» заполняется ровно в одном месте ядра — функцией
«Принято правилом» (`flang/self/proof-kernel.flang`). Её доводов четырнадцать:
тринадцать имён и пустая строка.

| | |
|---|---:|
| имён в прежнем списке | 8 |
| из них ядро и правда ставит | 6 |
| ставит, а в списке не было | 7 |
| числились в списке, но не ставятся никогда | 2 |
| имён на самом деле | **13** |

Семь недостающих: «порядок соседних по построению», «несовместимые допущения»,
«вычисление замкнутой цели», «разбор цели по условию», «цель-выбор с истинной
ветвью», «разбор случаев по дизъюнкции в допущении», «разбор случаев по
внутреннему условию цели».

Два лишних — обе развёртки: «развёртка по конструктору» и «развёртка определения
без вызовов». Ими ядро помечает **другое** поле, «развёрнуто», и в запись оно не
едет вовсе (`unfolded` у сборщика терма нет поля). Сторожить в записи нечего,
поэтому они убраны: правило, которое числится проверяемым и не проверяется, хуже
отсутствующего. 6 + 7 = 13, а не 8 + 7 = 15.

## Третья беда, найденная тем же прогоном

Закрытый список спрашивался только у утверждения, при котором в исходнике
НАПИСАНА теорема («Сверить правила» звалась из «Сверить теорему» и больше
ниоткуда). Посылки с названным правилом ядро ставит и там, где теоремы нет ни
строки: `flang/proof/map/substantive.flang`, «С5 сохранение: длина выросла на
один» — `теоремы нет`, а посылка шага закрыта правилом «разбор цели по условию».
Такая запись проходила мимо списка целиком.

Замер до и после на одной и той же порче (имя подменено на «правило моего
сочинения»):

```
старый сверщик → код 0, «сошлось: утверждений 7 …»
новый сверщик  → код 1, «утверждение «С5 сохранение: длина выросла на один»:
                  запись ссылается на правило сведения, которого сверщик не
                  знает: правило моего сочинения»
```

## Сторож, чтобы не разошлось снова

`flang/proof/сверка-правил.sh` — две половины, и одна без другой ничего не значит:

- **сличение списков.** Имена берутся из исходника ядра (доводы «Принято
  правилом»), список — из исходника сверщика, сличаются знак в знак. Довод
  четвёртого вида (не литерал, не имя функции, не известный проходной) —
  беда, а не умолчание.
- **живой прогон.** Каждое имя, названное первой половиной, подставляется в
  настоящую запись доказательства, и сверщик обязан её принять; имя вне набора —
  отвергнуть и назвать. Двумя дорогами: с написанной теоремой и без неё.

Второго списка имён нигде нет: оболочка берёт их у первой половины и гоняет.

## Половины разделены 31 августа 2026, и «ничего не значит» сужено

«Одна без другой ничего не значит» — про СЛОВО «сошлось», а не про прогон.
Ключ `--только-первая` гоняет одно сличение списков и печатает не то слово: он
говорит, что́ проверил, и сам называет, чего не спрашивал. Первая половина
стоит 76,4 с (со сборкой семени 3 мин 07 с) против 17 мин 46 с (19 мин 37 с)
у обеих — поэтому она ходит на каждый пуш работой `pravila-spisok`, а обе
половины остаются на метке.

Что при этом уходит с пуша — проверено подделками, а не оценено. Из семи порч
таблицы выше первые пять краснит одна первая половина. Две новых порчи первая
половина НЕ ловит, и обе правят потребителя списка, не трогая в списке ни знака:

| порча | первая половина | вторая половина |
|---|---|---|
| «посылка » у потребителя списка написано с большой буквы | зелена, код 0 | 4 провала из 23 |
| одно имя отфильтровано у потребителя списка | зелена, код 0 | честная запись отвергнута: «правило сведения, которого сверщик не знает: разбор цели по условию» |

Вторая строка важнее первой: это СИМПТОМ 23 августа — честная запись отвергнута
как подделка — при зелёной первой половине. Отсюда слова ключа говорят про
ТЕКСТ списка, а не про то, чем сверщик пользуется на прогоне.

Попутно найдено и НЕ починено: проверка «отказ называет подставленное имя»
смотрит на текст вывода и не смотрит на код возврата. Сверщик печатает журнал
поручений вместе с содержимым прочитанных файлов, а подставленное имя стоит в
самой записи, — поэтому под первой из двух порч эта проверка зелена, хотя
ничего не отвергнуто.

Проверен семью порчами, каждая даёт код 1:

| порча | что сказал |
|---|---|
| имя ядра убрано из списка сверщика | «ядро ставит имена, которых в закрытом списке сверщика НЕТ: разбор цели по условию» |
| в список дописано лишнее имя | «есть имена, которых ядро поставить не может: правило моего сочинения» |
| новое правило заведено в копии ядра | «правило, заведённое завтра» + «цель есть допущение» лишним |
| довод «Принято правилом» — выражение | «довод не разобран: (соединить [цель] по )» |
| у «Принято правилом» новый проходной довод | «появился проходной довод, о котором сторож не знает: новое имя» |
| опорное имя пропало из записи | «подменять нечего, и молча сделать вид, что опыт состоялся, нельзя» |
| снята правка «Без теоремы» | «чужое правило у утверждения без теоремы не отвергнуто как надо — код 0» |

Последняя — та самая проверка «снять правку и посмотреть, что покраснеет»: без
неё сторож ходил бы зелёным по починке, которой нет. Чтобы она была возможна,
`сверить.sh` берёт путь сверщика из `SVERSHCHIK`, а `сверка-правил.sh` этот путь
выставляет обеим половинам — иначе порча краснела бы в одной и молчала в другой.
