# Дорогая развёртка длин и недоказуемые цели про длины — РАЗНЫЕ места: развёртка стоит 17 % вызовов ядра и 8 % времени, а стоит она там, где недоказанного нет вовсе

Два замера, снятые порознь, читались как один: профиль назвал развёртку длин
шестой частью работы ядра, а счёт целей назвал семью «длина против длины» пятой
частью всего недоказанного. Свести их в одно место не вышло, и это
отрицательный результат: **дорогое место и недоказуемое место не совпадают ни
по файлу, ни по механизму.**

## 1. По вызовам шестая часть, по времени — вдвое меньше

Профиль пульсом того же рода, каким снята
[[the-function-named-when-the-limit-runs-out-is-not-where-the-time-goes]], но с
разделением на две части прогона (см. пункт 2).

`flang/stdlib/postgres.flang`, **доказательная часть 110 с, 7518 выборок**,
разрешение времени 1 с = 0,91 %:

| функция | доля ВЫЗОВОВ | доля ВРЕМЕНИ |
|---|---:|---:|
| «Развернуть поле длины» | 9,2 % | 5,5 % |
| «Развернуть длину звена» | 8,0 % | 2,7 % |
| **две вместе** | **17,2 %** | **8,2 %** |

`flang/stdlib/http.flang`, 50 с, 3871 выборка: по вызовам 18,0 %, по времени
2,0 %. Разрешение там 1 с = 2 %, то есть вся доля — одна выборка; число
годится как знак, а не как величина.

**Что из этого следует.** Доля по вызовам завышает цену примерно вдвое:
развёртка длин ДЁШЕВА НА ВЫЗОВ. Прежнее «16,5 % работы» — это 16,5 % вызовов,
и как утверждение о времени оно неверно.

**Чего снять не удалось.** Разбивки числа шагов ПО ФУНКЦИЯМ в дереве нет:
счётчик шагов (`repl_ctx.steps`) сбрасывается на каждом ШАГЕ ПРОВЕРКИ
(`repl_call`, `flang_repl.c`), и мельче шага проверки он не делится. Поэтому
«по шагам» здесь снято только на уровне стадии: у `http.flang` шаг «Ведомость
исходников» съел **1 112 780 757** витков, у `postgres.flang` —
**3 805 130 568** (строка «шагов N из M» в stderr). Вторая мера доли длин —
время, а не шаги, и так она и записана.

## 2. Профиль склеивает две работы, и без их разделения ответ меняется вдвое

`check --proof` — это ДВЕ работы подряд, и в профиле они стоят рядом. Окна по
20 секунд, `postgres.flang`:

```
  окно, с   выборок   длины %   толкователь %
   0- 20        157      0,0 %          42,0 %
  20- 40       1456     15,0 %           0,5 %
  40- 60       1616     17,6 %           0,1 %
  60- 80       1675     17,6 %           0,0 %
  80-100       1754     17,2 %           0,0 %
 100-120       1113     17,2 %           2,4 %
 120-140        112      0,0 %          95,5 %
 140-160         80      0,0 %          96,2 %
```

До 110-й секунды идёт доказательство, после — ПРОГОН ПРИМЕРОВ (функции
`«Овеществить»`, `«Найти в обстановке»`, `«Знач равны»` — все из
`flang/self/interpret.flang`, то есть толкователь, а не ядро). На целом прогоне
доля длин по времени выходит 4,9 %, на доказательной части — 8,2 %.

Почему примеры вообще здесь: ядро зовёт `«Прогоны для ядра»`, а тот, если в
программе есть хоть одна теорема, прогоняет ВСЕ примеры программы — это уже
названо в шапке `scripts/raskrutka.sh` и здесь подтверждено профилем.

**Правило, которое из этого следует.** Профиль `check --proof` без разделения на
доказательство и прогон примеров меряет две разные работы одним числом. Границу
видно по тому, из какого файла функции: `proof-kernel.flang` против
`interpret.flang`.

## 3. Дорого там, где недоказанного нет

`flang/stdlib/http.flang` — файл, на котором и снят исходный профиль:

```
утверждений 154: доказано 81, сетка 73, объявлено, не доказано 0
```

**Ноль** целей вида «объявлено, не доказано» — и при этом 18 % вызовов ядра
уходит в развёртку длин. То же у `flang/stdlib/sets.flang`: `объявлено, не
доказано 0` при шести целях, числящихся в семье.

Причина видна в исходнике: `«Развернуть длину звена»` применяется к цели и к
КАЖДОМУ допущению безусловно (`proof-kernel.flang`, строки 7540 и 7569), а не
только там, где в цели есть `длина`. Её цена — от РАЗМЕРА цели и допущений, а не
от числа целей про длины. Поэтому дорогой файл и файл с недоказанными целями про
длины — разные файлы, и связи между двумя замерами нет.

## 4. Недостающий ход назван, и он уже семьи

Из [[two-missing-bound-rules-not-one-and-both-are-false-on-ieee-numbers]] и
[[what-the-kernel-cannot-do-is-a-statement-about-the-seed-not-the-language]]:
сложение под известной границей в ИСХОДНИКЕ уже есть, в семени нет. Остаётся
второе — переходность по символьным величинам. Она **отсутствует нарочно**, и
довод написан при `«Есть порядок»` в `proof-kernel.flang`:

> Транзитивности через ЧУЖОЙ терм здесь нет и не будет: искать середину значило
> бы завести перебор, а поиска у ядра нет ни одного.

**Замер сузил недостающее ещё вдвое.** Корпус
`flang/proof/подделки/переходность.flang` держит всё прочее и меняет только вид
звеньев цепочки:

| проба | цепочка | вердикт |
|---|---|---|
| К1 | один вызов, граница | доказано |
| К2 | один вызов, равенство | доказано |
| **Ч3** | **равенство, затем граница** | **доказано** |
| Ч1 | граница, затем граница | сетка |
| Ч2 | граница трижды | сетка |

Ч3 берётся без всякой переходности: равенство ядро ПОДСТАВЛЯЕТ, и середина
исчезает сама. Значит не хватает не «переходности», а её узкого случая —
**хода между двумя НЕРАВЕНСТВАМИ**.

Правило, которое из этого следует, названо посылкой и заключением:

* **посылки:** `А не больше Б` и `Б не больше В` — обе среди уже собранных
  порядков (`«порядки»`), середина `Б` сличается с обеими сторонами тем же
  `«Одинаковы»`, каким ядро сличает цель с допущением;
* **заключение:** `А не больше В`;
* **обязательная посылка сверх этого:** все три величины лежат в области с
  полным порядком — длина списка, `нат`, — а не в `число`. На `число` вывод
  ЛОЖЕН: «не число» вне порядка, и ядро само отвечает `FLANG_BOUND_ON_NAN`;
* **чем это не ослабляет ядро:** новых доверенных сущностей не вводится, оба
  звена уже доказаны. Цена — тот самый перебор середины: по списку `«порядки»`
  на каждый спрос, и это ровно то, от чего при `«Есть порядок»` отказались. Цену
  надо мерить, а не обещать.

## 5. Приёмка написана и сегодняшнее её состояние снято

`flang/proof/подделки/переходность.flang` — десять утверждений: две основы, два
контроля, три честных случая, три подделки. Подделки ложны на своих входах и
обязаны остаться недоказанными; контроли доказаны и обязаны такими остаться.

```
утверждений 10: доказано 5, сетка 5, объявлено, не доказано 0
```

Правило принято, если Ч1 и Ч2 стали «доказано», а К1, К2, Ч3 остались
«доказано» и Д1…Д3 остались слабее «доказано».

**Подделка Д2 попутно показала, чего корпус не поймает.** В первой редакции у
неё стоял пустой пример, и прогон примеров снял её ДО ядра
(`FLANG_PROPERTY: нарушено свойство`), а вместе с ней и весь отчёт по файлу.
Пример пришлось взять непустой. Отсюда: подделка, ловящаяся своим же примером,
правило не проверяет вовсе — она до правила не доходит.

## 6. Семья живёт в исходниках компилятора, а не в библиотеке

Разбор 462 кандидатов (`/srv/tmp/a-1290/kandidaty.json`) по области дерева:

```
flang/self (исходники компилятора)   444   96,1 %
flang/stdlib (библиотека)             17    3,7 %
прочее                                 1    0,2 %
```

Те же 17 из библиотеки — это ровно те, на которых снята сверка вердиктов в
поправке к [[one-goal-shape-blocks-a-fifth-of-all-unproven-promises]] (11 из 17
разошлись). **Остальные 445 не проверены ни разу и сегодня непроверяемы**:
каждый файл компилятора берёт от 16 до 28 ГиБ и десятки минут, а `iso.flang` —
самый малый из них, 470 строк — при 16 ГиБ отвечает `FLANG_MEMORY`.

Разбор тех же 462 по механизму (чтение тел, НЕ прогон):

```
158  34,2 %  результат идёт через цепочку вызовов  ← сюда бьёт переходность
202  43,7 %  один вызов либо иное с вызовами
 76  16,5 %  функция рекурсивна (накопитель)
 20   4,3 %  сложение под границей
  6   1,3 %  без вызовов вовсе
```

**Это счёт по записи тела, а не по прогону**, и разойтись с прогоном он может
так же сильно, как разошёлся счёт по записи цели. Верхняя граница для правила
переходности — 158; сколько из них закроется, сегодня не снято ничем.

## Чем подтверждено

Прогоны 28 августа 2026, очередь на тяжёлые прогоны. Профили — двоичный
`/srv/tmp/a-4134/flang` (семя ствола `6aa594fc` плюс рантайм дерева, в котором
живёт пульс); `bootstrap/` и рантайм между `6aa594fc` и деревом замера
`da47cbdf` не менялись — `git diff --stat` по ним пуст. Ведомости и корпус —
`bootstrap/flang` дерева `da47cbdf`, md5 `82f9ac40`, собран `make -C bootstrap`.
Свод профиля — `/srv/tmp/a-4134/svod.py`. Разбор кандидатов —
`/srv/tmp/dliny-granicy/mehanizm.txt`.

## Чем ограничено

* **Доля времени снята на двух файлах библиотеки**, `postgres.flang` и
  `http.flang`. На файлах компилятора — где и лежат 96 % семьи — не снята: они
  не помещаются в память, отпущенную одному прогону.
* **`postgres.flang` не досчитан до конца**: он падает в прогоне примеров
  (`FLANG_RECURSION_LIMIT` у «Байтов в тексте», 40 000 000 шагов). На
  доказательную часть, которой мерена доля длин, это не влияет — она кончилась
  до падения, — но полной ведомости по файлу нет.
* **Что исходник ядра доказывает эти цели — не проверено и сегодня непроверяемо**:
  нужен двоичный из нынешнего дерева, то есть перепечатка. Всё сказанное про
  вердикты — про семя.
* Разбор 462 по механизму — чтение тел. Прогоном подтверждён только вид цепочки
  на своём корпусе, а не на кандидатах дерева.
