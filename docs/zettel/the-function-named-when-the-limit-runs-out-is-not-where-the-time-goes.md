# Функция, названную которой печатает отказ при исчерпании предела, — не та, где уходит время

Дерево называет виновником сверхлинейной проверки `«Есть вызов в полях»`
(задачи 5732, 6818, 0051; `proof-kernel.flang:2057`). Названа она двоичным — но
названа по ОДНОМУ МГНОВЕНИЮ: это функция, оказавшаяся на вершине стека в тот миг,
когда кончился предел шагов. Распределением это не является.

Профиль пульсом на том же роде работы: **6 выборок из 2005, 0,3 %**. В первую
дюжину она не попадает.

библиотеки — развёртка длин.

## Две колонки нужны обе, и вот зачем

Пульс срабатывает раз в N ВЫЗОВОВ, поэтому доля выборок — это доля вызовов.
Время берётся из промежутков между соседними выборками. Разница колонок и есть
находка: **«Читать имя» — 0,2 % вызовов и 6,4 % времени, «Слово пустотой» — одна
выборка и 3,7 % времени.** Эти две по вызовам не видны вовсе, а по времени стоят
в первой шестёрке: они дороги НА ВЫЗОВ. Профиль по одним выборкам их бы потерял.

## Цена прибора — измерена, а не оценена

`trust-store.flang`, тот же двоичный, тот же прогон:

```
без пульса                 133,33 с
пульс раз в 100 000        133,24 с
```

То есть в пределах разброса. На коротком файле (`sets.flang`, 1,45 с) проверены
и частые шаги: раз в 10 000 — 1,44 с, раз в 1000 — 1,47 с, то есть **+1,4 % в
худшем случае**. Прибор можно ставить не думая.

## Чем этот профиль ограничен

* **Пульс называет функцию, в которую ВХОДЯТ** (`fl_enter`). Время, проведённое
  в длинном цикле внутри одного вызова, припишется тому, кто вошёл последним, а
  не тому, кто считает. Для рекурсивного кода — а ядро такое — это редко, но
  назвать надо.
* **Разрешение времени — секунда.** На прогоне короче полуминуты колонка времени
  шум: у `sets.flang` весь прогон 2 с, и деление на две функции по 50 % ничего не
  значит. Считать её можно от сотни секунд.
* **Профиль не говорит, ПОЧЕМУ функция дорога** — сколько её зовут и сколько она
  считает внутри, пульс не различает.
