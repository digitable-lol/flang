# Ворота раздают места по ЗАПРОШЕННОМУ пределу, а не по съеденной памяти — и просьба «с запасом» отнимает места у всех

Правило работы говорит «модуль библиотеки — `PAMYAT=45G`». Замер 27 августа 2026
показал, что для `flang check` эта цифра завышена в восемьдесят раз и что платит
за неё не только просящий.

## Как ворота считают места

`/srv/flang-rabota/vorota/flang-vorota` считает потолок мест делением доступной
памяти на ЗАПРОШЕННЫЙ предел, а не на измеренный расход:

```sh
zapas_gib=$(( dostupno_gib - POL_GIB ))
potolok=$(( zapas_gib / predel_gib ))
[ "$CHISLO" -gt "$potolok" ] && CHISLO=$potolok
```

Отсюда прямое сравнение, снятое на одной машине в одну минуту:

```
PAMYAT=8G  → ворота: слотов 8, занято 8, предел на процесс 8G
PAMYAT=45G → слотов 8 при пределе 45G не помещается (доступно 426 ГиБ, пол 45); беру 6
```

**Просьба в 45G своими руками отнимает два места из восьми** — и не у себя одного,
а у всей очереди: слоты общие.

## Сколько на самом деле берёт проверка

Замер `/usr/bin/time -f '%M'` вокруг настоящего прогона под воротами,
`flang check flang/stdlib/wire.flang` (94 утверждения, 91 обещание в файле):

```
ПИК_КИБ=596052        то есть 0,57 ГиБ
```

Запрошено при этом было 45 ГиБ — в **79 раз** больше пика. Соседний замер
координатора по ядру доказательства даёт `VmPeak` 0,80–1,61 ГиБ, того же порядка.

## Что из этого следует

Просить надо по замеренному пику с запасом, а не «сколько не жалко». Запас в
десять раз (8G при пике 0,57 ГиБ) ворота ещё не режет: при 8G потолок мест
остаётся полным.

**Оговорка, без которой число соврёт.** `ulimit -v`, который ставят ворота,
ограничивает АДРЕСНОЕ ПРОСТРАНСТВО, а `%M` у `time` меряет пиковый RSS; первое
бывает заметно больше второго. Поэтому запас нужен, и мерить лучше тот же файл,
который собираетесь гонять: 0,57 ГиБ снято на модуле библиотеки, а не на файле
компилятора и не на ядре.

**Чего этот замер НЕ говорит, и это выяснилось ДОРОГО.** Он про `check` МОДУЛЯ
БИБЛИОТЕКИ, и переносить его на другие файлы нельзя. Тем же заходом, тем же
пределом `PAMYAT=8G`, по файлам компилятора:

```
flang/self/lexer.flang   | код 0 | проверено, замечаний нет
flang/self/proof.flang   | код 1 | оболочка: кончилась память
flang/self/cli.flang     | код 0 | проверено, замечаний нет
```

`«оболочка: кончилась память»` — это `ulimit -v`, поставленный воротами, а не
машина: восьми гибибайт файлу компилятора не хватает.

⚠ **И нехватка предела приходит ДВУМЯ разными строками, а не одной.** На тех же
восьми гибибайтах:

```
flang/self/repl/repl.flang           | код 1 | оболочка: кончилась память
flang/self/bootstrap/compiler.flang  | код 1 | FLANG_MEMORY: недостаточно памяти
                                              FLANG_CLI: компилятор не связал сессию
                                              не проверено — замечаний 1
```

Первую печатает оболочка, когда `ulimit` убивает процесс; вторую — сам
компилятор, когда упирается в тот же предел изнутри и успевает пожаловаться.
Вторая выглядит как ОТКАЗ ПРОВЕРКИ («не проверено — замечаний 1») и легко
читается как беда в файле. Отбирая упавшие по памяти, ищите оба образца, иначе
половина пересъёма потеряется молча. Правило работы называет для
них `PAMYAT=60…80G`, и этот замер его подтверждает, а не опровергает.

**Пики по классам, снятые одним заходом `/usr/bin/time -f '%M'`:**

| что гоняли | пик | во сколько раз против 45G |
|---|---:|---|
| `flang/stdlib/wire.flang`, `check` | 0,57 ГиБ | 79 раз меньше |
| `flang/stdlib/wire.flang`, `check --proof` | 0,67 ГиБ | 67 раз меньше |
| `flang/self/repl/repl.flang`, `check` | **12,5 ГиБ** | втрое меньше |
| `flang/self/proof.flang`, `check` | **26,7 ГиБ** | вдвое меньше |

Разброс между классами — сорок семь раз. Правило работы «модуль библиотеки 45G,
файл компилятора 60…80G» этими числами подтверждается для файлов компилятора и
опровергается для модулей библиотеки: там 45G завышено на два порядка.

Значит правило звучит так: **мерить надо тот класс файлов, который собираешься
гонять, и просить по его пику.** Модуль библиотеки — единицы гибибайт; файл
компилятора — десятки; перепечатка семени — сотни (замер прежний: 5 ч 30 мин, пик
259 ГБ). Одно число на все три класса не годится ни в большую сторону, ни в
меньшую: завышенное отнимает места у очереди, заниженное роняет прогон впустую.

## Соседняя грабля той же смены: убитый скрипт оставляет прогон сиротой

Убийство скрипта по его PID не убивает потомка, стоящего под воротами: обёртка
переживает родителя, достаётся systemd (`ppid` равен 1) и продолжает **держать
слот**, а заодно пишет в тот же файл вывода, что и новый прогон. Ловится
`ps -eo pid,ppid,args | awk '$2==1 && /flang-vorota/'`. Убивать надо группу
процессов, а не скрипт.
