# Ворота пропускают код команды насквозь: один код 75 не отличает отказ ворот от команды, вернувшей 75

`scripts/targets/targets-inventory.sh` снимает опись целей — имя, код возврата,
время, причина — строками таблицы markdown в тот же вид, что
`docs/ci-inventory.md` (задача 0042). Опись, снятая руками, не повторяется:
следующий снимет её иначе. А главное — поточный цикл `echo "$имя КОД=$?"`
попадает в ловушку, ради которой заведена задача.

Ворота памяти, не дождавшись места, отвечают кодом 75 (EX_TEMPFAIL) и команду
не запускают вовсе. Задача 0042 предполагала, что этого кода довольно для
распознания: «настоящие коды команд с ним не пересекаются».

**Чем подтверждено.** Прогон 26 августа 2026:

    CHISLO=1 ZHDAT=2 flang-vorota -- sh -c 'echo ПРОГОН-ПОШЁЛ'   → код 75
    flang-vorota -- sh -c 'exit 75'                              → код 75

Первое — отказ ворот, команда не запускалась. Второе — команда отработала и
сама вернула 75. Ворота пропускают код команды насквозь, и по коду эти два
события неразличимы. Различает их только строка в stderr:

    ворота: за N с место не освободилось, прогон не начат

Поэтому опись проверяет оба признака — код 75 и строку отказа в выводе — и
такую цель пишет как «переснять», а не как вердикт.

**Чем ограничено.** Прогоны идут через ворота, как велит AGENTS.md («не
больше двух разом»), и ворота же — источник кода 75. Имена латиницей, как в
`scripts/raskrutka.sh`: ни dash, ни bash не принимают кириллицу в именах.
