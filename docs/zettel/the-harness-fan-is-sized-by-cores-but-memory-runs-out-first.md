# Веер оснастки считается по ядрам, а кончается память — и правило «не больше двух прогонов» тут не помогает

Инструмент дерева, разводящий прогоны компилятора по ядрам, берёт число потоков
из числа процессоров и о памяти не спрашивает. На машине с 256 ядрами это даёт
64 прогона разом; один разбор большого файла держит до 11 ГиБ, один
`flang check --proof` — от 5 до 50 ГиБ. Семьсот гигабайт при четырёхстах
девяноста девяти.

**Чем подтверждено.** Ночь на 21 августа 2026: заморозка машины на 87 минут
(04:02:28 → 05:29:25), убийца памяти сработал 12 раз, жертвой каждый раз был
`flang`, RSS жертв 44,4 · 44,3 · 50,6 · 50,6 · 44,4 · 39,4 · 24,5 · 23,5 ГиБ,
`constraint=CONSTRAINT_NONE` — то есть кончилась вся память машины, а не лимит.
Убило пользовательские менеджеры двух учётных записей и снесло сессии.

Источник — `flang/scripts/binary.mjs`, и не в одном месте, а в трёх:
`прогреть`, `прогретьВедомости`, `токеныМногих`. У всех трёх одна строка:

```js
const сколько = потоков || Math.max(1, Math.min(64, cpus().length))
```

**Главное в этой заметке — не сама строка, а то, кто её зовёт.** Веер запускает
не человек и не агент, а оснастка, стоящая через две ступени:

```
docs/site/site-numbers.mjs  →  flang/scripts/proof-ledger.mjs  →  binary.mjs
```

То есть `./ярлык числа`, `./ярлык числа:проверка` и `./ярлык доказательства:ведомость` —
безобидные с виду ярлыки, каждый из которых кладёт машину. Правило работы «не
больше двух прогонов `flang` разом» здесь не спасает: тот, кто его соблюдает,
всё равно получает 64, потому что разводит их не он.

**Отсюда признак класса.** Опасен не прогон, а умолчание в инструменте. Ищи
заранее: всякое место, где число одновременных процессов выведено из
`cpus().length`, `nproc` или `-j$(nproc)`, а память при этом не спрошена. Правило
для флага — не «сколько ядер», а «сколько поместится»: бюджет на процесс, делённый
на свободную память, и не больше половины свободной.

**Чем ограничено.** Числа RSS взяты из журнала убийцы памяти, а не измерены
подряд по одному прогону; разброс 23–50 ГиБ — это разные файлы, а не разброс на
одном. Причина заморозки на 87 минут по журналу не разложена: сказано, что
памяти не стало, но какая доля пришлась на веер, а какая на чужие прогоны, не
посчитано.
