# Лицензионный гейт берёт новый каталог под опубликованным путём сразу, и первый же файл без шапки красит CI

Гейт лицензионной разметки выводит список проверяемых файлов ИЗ ДЕРЕВА — по полю
`files` в `package.json`, а не из записанного перечня. Поэтому новый каталог,
заведённый под уже опубликованным путём, попадает под проверку с первого файла,
и о шапке SPDX никто не вспоминает: каталог новый, а правило старое.

**Чем подтверждено.** Задание `licensing` в CI было красным на теге выпуска
`v0.5.0` (прогон 32088946127) и оставалось красным на стволе полтора суток.
Причина — шесть файлов `flang/conc/zamer/` (`build.mjs`, `build-ex.mjs`,
`gen.mjs`, `stenka.mjs`, `tipy.mjs`, `razmery.c`), заведённых без двух строк
шапки, тогда как сосед `flang/conc/bench.mjs` их несёт. `flang/conc` перечислен
в `files`, значит новый подкаталог был в области с самого начала. После дописи
шапок: «4 проверк(и) пройдено, 121 файлов просмотрено, 0 отказов».

**Чем ограничено.** Само устройство гейта — вывод списка из дерева — правильное и
менять его нельзя: перечень списком означал бы, что новый файл уезжает наружу
непомеченным и молча. Красный CI здесь не дефект гейта, а его работа.

**Чему учит.** Цена этой правильности — то, что каталог для замеров, заведённый
«на разок», немедленно становится публикуемым исходником со всеми обязательствами.
Полтора суток красного CI на релизном теге стоили двух строк, которые пишутся за
секунду в момент заведения файла и не пишутся никогда потом.
