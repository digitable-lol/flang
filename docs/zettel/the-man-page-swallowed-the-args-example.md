# Страница `man` показывала вместо примера `--args` обрывок `'{`, и проверка была зелёной

В `packaging/flang.1` пример ключа стоял так:

```
.IR "'{\"н\":10}'" )
```

Набранная страница показывала `Аргументы (--args '{  сверяются объявленным
типам …`: всё после первой внутренней кавычки пропадало вместе с закрывающей
скобкой. Причина в кавычках: аргумент макроса уже взят в кавычки, и `\"` внутри
него обрывает аргумент, а не даёт знак. Лечится заменой на `\(dq`:

```
.BR \(aq{\(dqн\(dq:10}\(aq )
```

Строка живёт в дереве с 18 августа 2026 (`271de16d`), и проверка
`flang/test/manpage.test.mjs` всё это время была зелёной. Это не недосмотр
одного теста, а его граница: он требует, чтобы
`groff -ww -z` не выдал ни одного предупреждения, чтобы нашлись разделы и чтобы
названные коды бед существовали. Потерянный текст не предупреждение — набор
прошёл, просто напечаталось не то. Ни одна проверка не сличает набранную
страницу с тем, что в ней написано.

**Чем подтверждено.** `groff -K utf8 -man -Tutf8 packaging/flang.1` до правки и
после, ветка `work/adr-pakety`, версия 0.5.0. До: строка `--args '{`. После:
`--args '{"н":10}')`. `node --test flang/test/manpage.test.mjs` — 5 из 5 зелёных
в обоих случаях.

**Чему учит.** Страницу `man` мало набрать без предупреждений — надо прочитать
набранное. Всякий пример с кавычками внутри макроса `.BI`/`.IR`/`.RB` стоит
проверять глазами на выводе `groff`, а не в исходнике.

**Чем ограничено.** Найдено на одном месте страницы; сплошного сличения
«в исходнике есть — в наборе есть» никто не делал, и других таких мест на
странице могло остаться сколько угодно.
