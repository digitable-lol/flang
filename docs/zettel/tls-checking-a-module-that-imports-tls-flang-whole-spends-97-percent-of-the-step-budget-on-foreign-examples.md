# Проверка модуля, ввозящего `tls.flang` целиком, съедает 97 % предела шагов на примерах ЧУЖИХ модулей — своих там почти нет

Замер 26 августа 2026, новый модуль `flang/stdlib/tls-handshake.flang` (711
строк, 307 функций), двоичный `w-predely` с поднятым пределом:

```
$ flang check flang/stdlib/tls-handshake.flang
ЗАПАС ШАГОВ НА ИСХОДЕ: «Беды примеров при проверке» съел 977952170 витков из
1000000000 (97 %).
модуль «Рукопожатие TLS»: функций 307, из них с доказанным завершением 307;
типов 25; файлов вместе с импортами 8
```

**Триста семь функций — это не мои.** Своих в файле около сорока; остальные
приехали ввозом: `tls.flang` ввозит `hmac.flang` ЦЕЛИКОМ, а тот — `sha256.flang`,
и вместе с ними приезжают их примеры. Строка `использует «Записи TLS» из
"tls.flang"` без `только` тянет за собой контрольные векторы RFC 4231 и FIPS
180-4, и считаются они в предел ВЫЗЫВАЮЩЕГО файла.

Это ровно то, о чём предупреждает шапка `kdf.flang`: «Прогон примеров одного
файла — это ОДИН такой предел на весь запуск, и примеры ввезённых модулей
считаются в него же. Семь контрольных векторов RFC 4231 в `hmac.flang` стоят
186 363 398 витков — 93 % предела». Там это записано про предел 200 000 000;
здесь предел поднят впятеро, и всё равно 97 %.

## Что из этого следует для того, кто пишет НОВЫЙ модуль поверх криптографии

**Ввоз без `только` — не «удобнее», а дороже на всю чужую поверку.** Каждая
правка в своём файле оплачивается прогоном чужих векторов заново, и прогон
стоит минуты, а не секунды. Список `только` пишется один раз и снимает эту
плату навсегда.

**Список `только` обязан быть ТРАНЗИТИВНЫМ, и брать его надо из шапки того
файла, который ввозите.** `tls.flang` ввозит `der.flang` семью именами, а не
всеми тридцатью двумя — значит и вам из `der.flang` через него видны те же
семь, и просить восьмое бесполезно: в пространстве имён `tls.flang` его нет.
