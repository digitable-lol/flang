# Одна закрытая запись в 37 октетов стоит 88 секунд — значит настоящий сервер положит трубку раньше, чем клиент на flang её расшифрует

Замер 26 августа 2026, через ворота, двоичным `w-predely` 0.6.2:

```
$ /usr/bin/time flang io examples/https/rfc8448-records.flang \
      --plan "Сверка с RFC 8448" --max-steps 4000000000
{"plan":"Сверка с RFC 8448","result":"сборка закрытой записи: сошлось;
 обратный ход: сошлось; сертификатов 1, октетов DER в первом 432,
 первый октет DER 48","orders":0,"log":[]}
ЗАМЕР: 87.93 с, пик 3309356 КиБ
код 0
```

Работы в прогоне ровно три: **зашифровать** 37 октетов AES-128-GCM,
**расшифровать** обратно те же 37 и разобрать сообщение Certificate в 445
октетов (это списочные действия, они дёшевы). То есть **два действия AEAD над
37 октетами стоят около 88 секунд**.

С меньшим пределом шагов прогон не проходит вовсе: при умолчании
`--max-steps 10000000` он падает
`FLANG_RECURSION_LIMIT: функция «Исключающее или байтов» исчерпала лимит шагов
(10000000) на глубине вызовов 13`.

## Почему это запор, а не медленность

Настоящий узел в ответ на наш ClientHello присылает третьей записью **3829
октетов закрытого текста** (замер того же дня, `example.com:443`, прогон
`examples/https/tls-hello-to-a-real-host.flang`: «октетов принято 3934, целых
записей 3»). Это в сто раз больше тридцати семи.

Даже если считать линейно и щедро — только расшифровка, без шифрования, — выйдет
**больше часа на одну запись**. Рукопожатие TLS столько не живёт: сервер
закрывает соединение по своему сроку, и никакого терпения тут не хватит, потому
что ждёт не наша сторона.

**Отсюда вывод, который важнее самого числа.** Три запора, названные раньше
(обмен ключами не ввозится из-за имени `«Нули»`, RSA-PSS нет вовсе, секрета
взять неоткуда), — устранимы работой. **Этот четвёртый работой по TLS не
устраняется**: он про цену вычислителя, а не про недостающий код. Пока
AES-GCM считается поразрядной арифметикой без единой битовой операции, живое
защищённое соединение к настоящему узлу на flang **не пройдёт по времени**, даже
когда всё остальное будет написано.

Что это НЕ значит: считать TLS на flang незачем. Сверка с RFC 8448 сошлась знак
в знак, и она сошлась бы так же, будь вычислитель хоть вдесятеро медленнее:
формула проверяется не скоростью.
