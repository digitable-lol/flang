# Точный шаг по `нат` доказывает только ПРЯМУЮ рекурсию: цикл через три функции ядро отвергает

Обещание «точным шагом» (`flang/src/totality.mjs`) держится на том, что тип
`нат` даёт обе границы отрезка, и потому `н минус 1` точно меньше `н`. На
функции, которая зовёт сама себя, это работает. На цикле из нескольких функций —
не работает, даже когда уменьшение стоит на том же самом параметре и передаётся
насквозь.

**Чем подтверждено.** Ветка `vypusk/biblioteka`, `flang/stdlib/postgres.flang`.
Три цикла отвергнуты с одним и тем же текстом «не убывает … снизу «запас» ничем
не ограничен»:

| цикл | длина цикла |
|---|---|
| «Разобрать поток» → «Сложить поток» | 2 функции |
| «Собрать поля» → «Собрать ячейки по длине» → «Собрать ячейки по набору» | 3 функции |
| «Дополнить запрос» (сама себя) | 1 функция |

Третья — прямая, и она отвергалась по ДРУГОЙ причине: проверка дна стояла внутри
`или` (`если годно или (запас не больше 0)`). Ядро ищет проверку вида
«`если ПАРАМЕТР не больше 0`» и внутри `или` её не видит.

После перестройки в прямую рекурсию — вложенным `разбор` вместо вызова соседа —
все три приняты, и никаких сторожей в напечатанный код не добавилось: носитель
остался «точным шагом».

**Ещё одно, отдельно.** Проверка `если запас равен 0` НЕ годится ни для
тотальности, ни для типов: `нат минус 1` без неё имеет тип `целое`, и вызов
падает на границе. Годится только `не больше 0`. Замерено на двух функциях-
близнецах, отличавшихся ровно этим словом: с `равен` — две диагностики, с `не
больше` — ноль.

**Чем ограничено.** Проверялось только на `нат`. Объявленная мера (`убывает х`)
циклы, по-видимому, переживает — но она ставит сторож в напечатанный код и
утраивает время функции, то есть это не та же цена.
