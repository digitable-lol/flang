# `только` не провозит типы — поэтому общий модуль с собственными типами берётся целиком, со всеми его именами

Заметка [[only-import-must-list-what-the-contract-calls]] кончалась словами «как
ведёт себя `только` с типами, здесь не мерилось». Померено.

Два файла, `a.flang` объявляет тип «Пара» и функцию «Завернуть», возвращающую
этот тип; `b.flang` разбирает результат.

```
использует «Проба типа» из "a.flang" только «Завернуть»
  → FLANG_UNKNOWN_NAME: неизвестный тип «Пара»
    FLANG_UNKNOWN_NAME: неизвестный конструктор варианта «Есть»
    код возврата 1

использует «Проба типа» из "a.flang"
  → примеров 2, прошло 2, код возврата 0
```

То есть `только` сужает таблицу имён целиком, вместе с типами и конструкторами
вариантов, а назвать тип в списке нельзя: список читается как список функций.
Функция, возвращающая собственный тип модуля, через `только` не ввозится
никогда.

**Что из этого следует для того, кто разводит библиотеку.** Общий модуль,
который несёт свои типы, ввозится ТОЛЬКО целиком — а значит, приносит в
программу все свои имена разом, со всеми возможными столкновениями. Отбора
здесь нет и не будет, пока `только` не научится принимать имена типов.

Практически это разворачивает совет из соседней заметки. Там вывод был «функция
с бедным контрактом ввозится дешевле». Здесь добавляется второе: **модуль без
собственных типов ввозится дешевле модуля с типами**, потому что первый можно
взять по одному имени, а второй — только весь.

**Где это уже стоило решения.** `flang/stdlib/wire.flang` (общая половина
двоичного протокола, вынутая из драйвера PostgreSQL 21 августа 2026) несёт пять
своих типов: «Печать», «Набор байтов», «Разбор целого», «Разбор строки», «Разбор
числа». Поэтому `postgres.flang` ввозит его строкой без `только` — и получает
все 32 его имени. Пересечение этих имён с именами всех остальных модулей
библиотеки посчитано: одно, «Цифра числом» в `strings.flang`. Оно и было там до
переезда, потому что `postgres.flang` объявлял это имя сам.

**Чем подтверждено.** Ветка `u/drugie-bazy`, двоичный из `bootstrap/` этой же
ветки (0.5.1). Прогоны `bootstrap/flang test` на паре пробных файлов (коды 1 и
0 выше) и `bootstrap/flang check flang/stdlib/postgres.flang` — «функций 84,
типов 11, файлов вместе с импортами 3, замечаний нет».

**Чем ограничено.** Мерено на сумме типов с вариантами. Записи и параметрические
типы не пробовались. Ввоза типа БЕЗ функций (только `тип`) не пробовалось.
