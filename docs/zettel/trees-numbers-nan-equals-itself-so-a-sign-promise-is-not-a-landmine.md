# «Не число» РАВНО самому себе, и потому обещание про знак не мина

В IEEE-754 сравнение с `не числом` ложно всегда — включая `NaN === NaN`. В
`flang/stdlib/numbers.flang` это сказано в шапке дословно и про ПОРЯДОК верно:
`не число не меньше 0` есть `нет`. Про РАВЕНСТВО — неверно: `равен` во flang
отвечает `да`.

Отсюда следствие, ради которого проба и ставилась. Обещание

```flang
обеспечивает «знак, умноженный на модуль, даёт само число»
  (результат умножить на («Абсолютное значение» от число)) равен число
```

стоит без оговорки о конечности и остаётся сеткой, то есть уезжает проверкой при
работе. Ход рассуждения «на не-числе знак ноль, ноль умножить на не-число есть
не-число, а не-число не равно не-числу — значит проверка упадёт на первом же
`0 делить на 0`» ВЫГЛЯДИТ верным и НЕВЕРЕН. Обещание истинно и на не-числе.

**Чем подтверждено.** Прогон 26 августа 2026,
`flang test /srv/tmp/u-trees-numbers/proba-nan.flang` через ворота. Тела «Знака»
и «Абсолютного значения» подставлены дословно, довод — `0 делить на 0`:

```flang
тотальная функция «Знак на модуль даёт само не-число»
  возвращает признак
  пример «Сравнение с не-числом ложно всегда»
    ожидается нет
  ((если (0 делить на 0) больше 0 то 1 иначе (если (0 делить на 0) меньше 0 то 0 минус 1 иначе 0)) умножить на (если (0 делить на 0) меньше 0 то 0 минус (0 делить на 0) иначе (0 делить на 0))) равен (0 делить на 0)
```

```
пример «Сравнение с не-числом ложно всегда» не прошёл: ожидалось false, получено true
```

Пример написан НАРОЧНО с ожиданием `нет`, чтобы отказ назвал настоящее значение.
Оно `да`: `не число равен не число` истинно.

**Что из этого следует для авторов.** Оговаривать конечность нужно там, где в
цели стоит ПОРЯДОК (`не больше`, `меньше`, `не меньше`) — как это сделано у «В
кольцо» и «Больше из двух» в `hashmap.flang`. Там, где стоит `равен`, оговорка
не нужна и только сузила бы обещание даром.
