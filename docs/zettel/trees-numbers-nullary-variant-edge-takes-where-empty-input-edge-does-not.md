# Край по нульместному варианту берётся девять раз из девяти, край по пустому входу — ноль из шести

У функции, чьё тело — `разбор` по ОБЪЯВЛЕННОЙ СУММЕ, край берётся охраной
«разбираемое равно нульместному варианту», и берётся он всегда, если ветвь этого
варианта — терм:

```flang
обеспечивает «у листа размер ноль» если дерево равен (вариант «Лист») то (результат равен 0) иначе да
```

У функции, чьё тело — свёртка или `разбор` ПО СПИСКУ, та же по смыслу мысль,
записанная равенством пустому входу, не берётся ни разу:

```flang
обеспечивает «из пустого списка выходит пустое дерево» если элементы равен пустой список то (результат равен (вариант «Пустое»)) иначе да
```

Разница не в цели и не в знаке — в том, есть ли ядру чем разбить цель. Начало
свёртки и ветвь `случай пусто` оно в цель не подставляет; вариант объявленной
суммы — подставляет.

**Чем подтверждено.** Прогоны 26 августа 2026 через ворота,
`/srv/flang-rabota/w-predely/bootstrap/flang check … --proof`.

ПОЛОЖИТЕЛЬНАЯ сторона, `flang/stdlib/tree.flang`, одна правка на девять функций:

```
утверждений 43: доказано 12, сетка 31      ← база
утверждений 52: доказано 21, сетка 31      ← после
```

Девять из девяти, сетка не выросла ни на одну. Ветви были: литерал (`0`, `нет`,
`да`, `пустой список`), сам довод (`узел`) и конструктор варианта с вызовом
внутри (`вариант «Узел» с … приоритет равным («Хеш строки» от ключ) …`) — вызов
внутри конструктора помехой не оказался.

ОТРИЦАТЕЛЬНАЯ сторона, шесть проб в двух файлах, все шесть — сетка:

| где | охрана | тело |
|---|---|---|
| `numtree.flang`, «Дерево из чисел» | `элементы равен пустой список` | свёртка |
| `numtree.flang`, «Сортировать деревом» | `элементы равен пустой список` | голый вызов над свёрткой |
| `tree.flang`, «Дерево из ключей» | `ключи равен пустой список` | свёртка |
| `tree.flang`, «Хеш строки» | `текст равен ""` | свёртка по знакам |
| `tree.flang`, «Строка раньше» | `первая равен ""` | `разбор` по строке |
| `numtree.flang`, «Есть число» | разложение конъюнкции надвое | `разбор` по сумме |

`tree.flang` 21 → 21 при сетке 31 → 34, `numtree.flang` 7 → 7 при сетке 6 → 9.
Всё откачено.

**Чем ограничено.** Вариант С ПОЛЯМИ восстанавливается в охране только там, где
у полей есть функции доступа. В `hashmap.flang` они есть у «Грозди» («Звенья
грозди», «Спуск грозди») — и край «у грозди глубина один» доказался. У «Дерева
чисел» и у «Дерева» доступа к полям нет вовсе, и половина «Развилка»/«Узел»
закрыта не слабостью ядра, а отсутствием терма, которым вариант собрать.
