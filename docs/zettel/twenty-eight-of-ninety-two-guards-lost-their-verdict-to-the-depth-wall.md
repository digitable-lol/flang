# Стена глубины отняла приговор у 28 сторожей из 92 и остановила примеры у 74 файлов из 105 — радиус назван парой двоичных на одном дереве

Про **причину** — соседняя заметка
[[plans-run-on-the-previous-seed-until-the-machine-loop-gets-its-trampoline-back]]
и её предшественница
[[a-promise-added-to-a-tail-cycle-deletes-the-trampoline-from-the-printed-code]]:
перепечатка `52996005` (30 августа 2026) увезла в семя круг машины без батута,
и каждый виток вычислителя стоит трёх кадров стека хозяина.

Здесь не причина, а **радиус**: сколько проверок дерева от этого перестало
выносить приговор. Догадка тут не годится, потому что «сломано многое» не
отвечает на вопрос ведущего захода — печатать ли семя снова.

## Как мерено: два двоичных, одно дерево, один список

Дерево — ствол `4233c18c` (30 августа 2026), обе рабочие копии клонированы из
него в одну минуту и после каждого прогона возвращались в чистое состояние
(`git checkout -- . && git clean -fd`, ловушка на сигнал; `git status` пуст в
обеих).

| двоичный | md5 | байт | откуда |
|---|---|---:|---|
| **старый** | `f32d89f5` | 14 065 960 | семя ДО перепечатки 30 августа |
| **новый** | `4e32f9f7` | 23 122 912 | `make -C bootstrap` из нынешнего ствола |

Прогоны — через ворота, по одному зараз, `PIK=12G PAMYAT=60G`; срок 120 с на
ярлык, 60 с на файл корпуса. Пик занятой памяти снимался
`/usr/bin/time -f '%M'` вокруг каждого прогона и ни разу не дошёл до 1,9 ГиБ.

**Контрольный опыт, с которого всё началось**, повторён обоими:

```
flang io flang/scripts/tasks.flang --plan 'Задачник цел'
  старый: код 0, «задачник цел: всего задач 150: свободно 32, в работе 37, сделано 79, отменено 2»
  новый:  код 3, FLANG_RECURSION_LIMIT: функция «Дальше после шага»
                 превысила предел глубины вызовов (20000) на глубине 20001
```

`лицензии:проверка` 78.

### Стена доезжает и через подпрогон, и об этом сторож говорит честно

Трое краснеют не своим отказом, а тем, что позвали умершего:

* `коды:подлог` — «сторож кодов ответил кодом 3 — это **сломанный инструмент,
  а не приговор**», и дальше дословный отказ глубины;
* `сайт` и `сайт:проверка` — «Сборка сайта ОТКАЗЫВАЕТ. Беды: · контраст
  подсветки: прогон плана ответил кодом 3 — FLANG_RECURSION_LIMIT…», **всего
  бед: 1**, и эта одна — стена.

Порода важная: у такого сторожа краснота от настоящей поломки дерева ничем не
отличается от красноты от сломанного инструмента, если не читать текст.

### Ложное совпадение, на котором легко ошибиться

Поиск `FLANG_RECURSION_LIMIT` по выводу ярлыка **врёт**. План `flang io` кладёт
в свой ответ содержимое каждого прочитанного файла, а имя кода стоит в прозе
дерева — в `docs/`, в исходниках сторожей, в этой самой заметке. Первый счёт по
вхождению дал 37 «мёртвых» ярлыков; из них `расширения:проверка` и
`дарвин:проверка` вернули код 0 и настоящий приговор. Считать надо строку,
НАЧИНАЮЩУЮСЯ с `FLANG_RECURSION_LIMIT: функция`, и отдельно разбирать
ненулевые коды: разница между 37 и 35 — ровно две ложные жертвы.

## Примеры: 74 файла из 105 не запускаются вовсе

Выборка — **весь корпус на flang, который дерево проверяет примерами**:
`flang/stdlib/*.flang` (42) + `flang/self/*.flang` верхнего уровня (57) +
`flang/conc/*.flang` (6) = 105 файлов. Взята целиком, а не наугад: это три
законченных множества, и «выборка» из них не потребовала бы объяснения, какая
она. Срок — 60 с на файл, `flang test <файл>`.

| | старый | новый |
|---|---:|---:|
| прошёл (код 0) | **35** | **17** |
| стена ГЛУБИНЫ | **0** | **74** |
| стена ШАГОВ | 54 | 0 |
| не уложился в 60 с | 16 | 14 |

| старый → новый | сколько |
|---|---:|
| прошёл → **глубина** | 18 |
| шаги → **глубина** | 40 |
| не уложился → **глубина** | 16 |
| прошёл → прошёл | 17 |
| шаги → не уложился | 14 |

По областям у нового двоичного: `flang/self` — 45 файлов на стене из 57,
проходит **один** (`cli.flang`); `flang/stdlib` — 27 из 42 на стене, проходит
12; `flang/conc` — 2 из 6 на стене, проходит 4.

**Два предела — разные вещи, и это видно в тексте отказа.** У старого двоичного
все 54 отказа звучат как `исчерпала лимит шагов (1000000000)` на глубине вызовов
от 0 до 118 — то есть примеры **шли** и не уложились в бюджет. У нового все 74
звучат одинаково: `превысила предел глубины вызовов (20000) на глубине 20001` —
то есть не пошли вовсе.

## Что это значит для следующей перепечатки

**Три обещания на трёх звеньях круга стоят в дереве и сегодня** — снято
`grep` по стволу `4233c18c`, `flang/self/interpret.flang`:

```
:1226 «Прогон»             обеспечивает «прогон витков не теряет»
:1236 «Виток»              обеспечивает «виток тратит не меньше одного шага»
:1255 «Дальше после шага»  обеспечивает «машина с бедой дальше не идёт»
```

Печать в C отдаёт функции с постусловием пустой список хвостовых рёбер, значит
**перепечатка сегодня напечатает ровно тот же круг без батута**. Заход стоит
5 ч 30 мин и 259 ГБ (замер 24 августа) и не меняет ни одного из чисел выше.

**Сама печать при этом не умирает на первых минутах — это проверено, и это
отрицательный результат.** Новым двоичным:

```
flang emit flang/self/bootstrap/compiler.flang --target c --out … --cli --repl \
  --runtime flang/src/emit/c --max-steps 1400000000000 --max-depth 20000
  → срок 360 с, код 124 (снят по сроку, не отказом)
  → последняя строка: «шагов 19 283 607 539 из 1 400 000 000 000 (1 %),
                       идёт „Связать исходники“, 7,7 ГиБ»
```

Шесть минут работы, стены глубины на этом отрезке нет. Дальше не мерено:
перепечатка стоит часы, а `--max-depth` в `scripts/raskrutka.sh:376` равен
**ровно тем же 20 000**, что и умолчание, — запаса у неё не заложено.

Отсюда довод, а не догадка: **перепечатывать сейчас нечего ради.** Новое семя
будет побайтово другим и функционально тем же, а цена — полдня машины и
единственный оставшийся годный инструмент. Старый двоичный `f32d89f5` сегодня —
не запасной, а рабочий: им сняты все 92 «старых» столбца выше и им же
спрашивается номер задачи.

## Что осталось не мерено, и почему это тоже результат

**Одиннадцать ярлыков не гонялись**, каждый по названной цене:

| ярлык | почему не мерен |
|---|---|
| `сборка` | не проверка, а сборщик двоичного |
| `раскрутка` | сама перепечатка: 5 ч 30 мин, 259 ГБ, пишет в `bootstrap/` |
| `раскрутка:проверка` | печатает точку раскрутки заново: 18 м 50 с, 24,1 ГиБ |
| `точка:проверка` | то же другим путём: ~18 мин, ~24 ГиБ |
| `установка:npm` | ходит в сеть и ставит пакет, срок в строке ярлыка 40 мин |
| `выпуск:проверка` | ходит на GitHub |
| `браузер:стенд` | поднимает сервер и не завершается по построению |
| `браузер:проба` | нужен живой Chrome и `TMPDIR` |
| `тесты` | набор целиком, дублирует остальные |
| `тесты:по-ssh` | нужна чужая машина с восемью тулчейнами |
| `столкновения:пересчёт` | тридцать минут по собственной шапке |

**Семь ярлыков и 14 файлов корпуса не уложились в срок** — их состояние не
установлено ни тем двоичным, ни другим, и в числа стены они не входят.

**Доля ведомостей не мерена нарочно** — её в ту же смену снимал сосед. По самому
файлу `scripts/proved-share-ledger.txt`: строк описи 508, из них с прочерком в
поле «доказано» — 154. Сколько из этих 154 стоят прочерком именно из-за
глубины, а не по прежним причинам, — вопрос к его замеру, не к этому.

## Побочная жертва той же перепечатки, но другой породы

`браузер:собрать` — единственный ярлык, ушедший из зелёного не в стену:
старый двоичный код 0, новый код 1 и
`FLANG_PROPERTY: нарушено свойство «пробельные — пробел, табуляция, перевод
строки и возврат каретки» функции «Пробельные JS»`. Это не глубина, это
отдельная поломка печати в JavaScript, приехавшая тем же семенем. Её стоит
завести отдельно: пока батут заслоняет собой всё, такие одиночки теряются.
