# Из npm и из brew приезжали разные компиляторы: на одном корпусе они разошлись на 54 вызовах из 59

Человек, поставивший язык через `brew`, и человек, поставивший его через `npm`,
получали **две разные программы под одним именем `flang`**. Из brew приезжал
двоичный компилятор, из npm — вторая реализация на JavaScript. Расхождение
меряли впервые: 59 вызовов одного корпуса, побайтовая сверка кода возврата,
вывода и потока ошибок — **54 расхождения**.

Совпали ровно пять вызовов, и все пять — машинные: `ast` и `lock` на исправных
файлах. **Всё, что читает человек, расходилось: все двенадцать справок, все
тексты отказов, весь человеческий вывод `check` и `test`.** Причина не в
небрежности: человеческий вход двоичного — это отдельный написанный руками файл
на C (`flang/src/emit/c/flang_repl.c`), а человеческий вход второй реализации —
`flang/bin/flang.mjs`. Два интерфейса, написанных порознь, и ничто их не
сверяло.

**Чем подтверждено.** Ветка `vypusk/npm-dvoichnyy`, 20 августа 2026. Корпус и
сверка написаны на самом flang: `packaging/install-parity.flang` — план
ввода-вывода, который запускает обе установки поручением «Запустить процесс» и
сравнивает три поля отклика. Прогон: `flang io packaging/install-parity.flang`.
До правки 54 расхождения, после — 7. Проверка в наборе:
`flang/test/ustanovka-npm.test.mjs`. Подделка сторожа: убрать в запускателе
разбор цели печати — сверка даёт 48 расхождений вместо 7 и краснеет.

**Почему после правки не ноль, и почему ноль был бы хуже.** Пакет обязан уметь
БОЛЬШЕ бинарника: у двоичного нет семи целей печати (js, go, rust, python, java,
csharp, elixir) и языкового сервера, а у пакета они есть. Оставшиеся 7
расхождений — ровно эти семь целей, поимённо. Поэтому проверка требует не
«расхождений ноль», а «расхождения ровно там, где объявлено»: список сверяется
именами, и лишнее имя красит прогон.

**Дополнение 21 августа 2026: расхождений стало НОЛЬ, и проверка покраснела от
этого.** Реализацию на JavaScript удалили, все восемь целей печати переехали в
замыкание двоичного, а список `ЦЕЛИ_ЧЕРЕЗ_NODE` в `packaging/flang-launch.mjs`
опустел. Прогон на ветке `u/port3`: **59 вызовов, 0 расхождений** — две
установки стали одним компилятором целиком. Проверка
`flang/test/ustanovka-npm.test.mjs` при этом КРАСНАЯ, и красная ровно этим: она
требует, чтобы расхождений было семь и чтобы это были имена семи целей, а
получает пустой список. Второй её отказ — из того же корня: `flang emit
primer.flang --target js` без `--out` больше не печатает в стандартный вывод
(«назовите, куда печатать»), потому что печатал так только удалённый хозяин.

То есть у этой проверки **главное утверждение осталось без предмета**: сверять
теперь надо не «расхождения ровно там, где объявлено», а «расхождений ноль». Это
не починка числа в одном месте: изменилось то, что проверка утверждает.

**Четыре расхождения, найденные владельцем за вечер, воспроизведены все:**

| что | двоичный | на Node |
|---|---|---|
| `emit --target c --out НОВЫЙ-КАТАЛОГ` | отказ, каталог не заводит | заводит и печатает |
| тексты отказов | свои | свои другие |
| `test` на непрошедшем примере | «ожидалось 5» | `"expected":5,"actual":4` |
| `run --args` со списком в значении | «ждался плоский объект скаляров» | берёт |

Первое из них — не только расхождение, но и **потеря для того, кто ставил через
npm**: после перехода `flang emit --out` требует, чтобы каталог существовал.
Названо прямо, а не спрятано.

**Ловушка npm, измеренная тут же.** Начиная с 7-й версии npm **прячет вывод
удавшихся скриптов установки** (проверено на npm 11.19.0; показывает его
`npm install --foreground-scripts`). Значит объяснение, напечатанное из
`postinstall`, человек не увидит. Из этого следует правило: **текст отказа
обязан печататься не при установке, а при первом вызове команды** — там его не
спрятать. Установка при этом не роняется: упавший `postinstall` оставил бы
человека вообще без пакета, то есть ещё и без языкового сервера и семи целей,
которые Node даёт и без бинарника.

**Отвергнутый путь: молчаливый откат на реализацию Node, когда бинарника нет.**
Довод не «дорого», а «мимо цели»: молчаливая подмена компилятора под одним
именем — это ровно та беда, ради которой всё переделывалось. Вместо отката —
отказ с кодом 3 («сломался инструмент»), названной причиной и командой починки.

**Чем ограничено.** 59 вызовов — не корпус языка, а корпус ИНТЕРФЕЙСА: он ловит
разницу в том, что команда печатает и каким кодом отвечает, и ничего не говорит
о разнице в разборе программ. `repl` в корпус не берётся вовсе — голым вызовом
он открывает оболочку и сверка повисла бы. Совсем без доводов не зовётся ни одна
команда: реализация на Node без файла идёт читать стандартный ввод и висит до
тридцатисекундного срока хозяина (измерено: на вызове `["check"]` план сдавался
с FLANG_IO_TIMEOUT).
