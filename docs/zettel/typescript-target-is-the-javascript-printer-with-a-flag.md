# Цель TypeScript — это печать в JavaScript с признаком «типизировано», а не десятый печатник

Заметка [[typescript-target-buys-almost-nothing]] верно посчитала, что строгий
`tsc` по нашей печати в JavaScript даёт 2523 замечания, из них 2109 — «у
параметра молча тип `any`» во внутренней машинерии, и что отдельный печатник
на 4000 строк ради этого не окупается. Владелец 8 сентября 2026 попросил цель
TypeScript всё равно — «чтобы рабочий был». Дорога, по которой она обошлась
без нового печатника и без второго рантайма:

* печать в JavaScript получает ОДИН признак в «Общее JS» — «типизировано»; при
  нём подписи функций, фабрики записей, конструкторы вариантов, таблица
  `$PROGRAM` и хвосты планов печатаются с типами (`export function f(n:
  number): number`, `export type Zapis = { "поле": number }`, `export type
  Summa = $FlangVariant`), а тела остаются теми же байтами;
* 2109 «молчаливых any» рантайма не лечатся, а ОБХОДЯТСЯ: рантайм печатается
  соседним файлом `flang_runtime.js` из тех же 93 кусков и не проверяется
  (`allowJs`, `checkJs: false`), а его типы `tsc` выводит из JavaScript сам;
* `flang/self/emit-ts.flang` — 30 строк: запись «Настройки TS» и один вызов
  общей печати.

**Чем подтверждено.** Ветка `r/emit-ts`, дерево `/srv/tmp/dokazuemyy/emit-ts`.
На 19 программах (`examples/rosetta/*` без английских двойников,
`flang/conc/link.flang`, `flang/conc/examples/{distributed,counter}.flang`,
`examples/wal/append-plan.flang`, `flang/stdlib/result.flang`) `tsc -p .`
(`strict`) даёт код 0, а прогонщик `flang_cli.js` на вопросах из ВСЕХ
`пример`ов программы отвечает через `.ts` теми же байтами, что через `.js`
цели `js` (таблица в отчёте задачи 8596). Вывод цели `js` при этом не сдвинулся
ни на байт: печать factorial старым двоичным и новым исходником совпала `cmp`.

**Что пришлось добавить в тела, чтобы строгий режим сошёлся** — три вещи, и
все в TS-ветке печати, JavaScript не тронут:

| замечание `tsc` | где | лечение |
|---|---|---|
| TS7034/7005 «`any[]` не выводится» | `let akk = []`, `const $t2 = []` | `: any` у временных и накопителей, `: any[]` у итога отображения |
| TS2366 «функция не всегда возвращает», TS2322 «`string \| undefined`» | ветвь `$matchFail(x)` и помощники, кончающиеся `$fail(...)` | в TS-выводе `$fail` и `$matchFail` печатаются с JSDoc `@returns {never}` — тогда вывод типов из JavaScript даёт `never`, и ветви закрываются |
| TS2339 «`import.meta.url`» | обёртка `$callDeep` | `lib: ["es2022", "dom"]` в `tsconfig.json` |

**Чем ограничено.** Сумма типов печатается как `$FlangVariant`, не как
размеченное объединение по вариантам: тела разбирают варианты помощниками и
`instanceof`, и строгое объединение дало бы красное там, где код верен.
Временные внутри тел — `any`. Договор типов стоит на подписях, и ровно это
покупает цель: `tsc` проверяет вызовы напечатанных функций у того, кто их
ввозит.
