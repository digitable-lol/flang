# Ветвь `разбор` по варианту без полей берётся равенством варианту, а `не результат` на такой ветви — нет

[[if-branches-unfold-both-ways-but-list-match-does-not]] назвала приём:
ветвь `разбор`а по варианту БЕЗ ПОЛЕЙ закрывается, если условие обещания писать
не образцом `случай вариант «X»`, а РАВЕНСТВОМ варианту. Замер на `wire.flang`
и `redis.flang` — двух модулях, которые целиком состоят из откликов-вариантов, —
уточняет границу приёма в двух местах.

**Первое: `случай любое` приёму не мешает.** Прежний вывод был обратный —
«`случай любое` в теле убивает индукцию по сумме», и он верен: заключение посылки
индукции ядро строит только с ИМЕНОВАННОЙ ветви. Но индукция здесь и не нужна.
Тело `разбор ответ / случай вариант «Набор Redis» … / случай любое то …`
закрывается на свёрнутой ветви правилом «разбор случаев по внутреннему условию
цели»:

```
обеспечивает «…» (не (ответ равен (вариант «Ничего Redis»))) или (результат равен («Текст простого ответа» от ответ))
```

доказано, хотя `«Ничего Redis»` в теле не разбирается по имени вовсе.

**Второе: на такой ветви решает ВИД ЦЕЛИ, и разница ровно в одном знаке.**
Одно и то же обещание о теле `случай любое то нет`:

```
(не (ответ равен (вариант «Ничего Redis»))) или (не результат)        → сетка
(не (ответ равен (вариант «Ничего Redis»))) или (результат равен нет) → ДОКАЗАНО
```

Правил вида цели у ядра шесть — «не меньше 0», «не больше конечного литерала»,
«не больше терма», «равно», «содержит», «не убывает». Голого признака среди них
нет, `равно` есть. При этом на ветви `если` голый признак проходит — замерено на
«Знак испорчен» из `wire.flang`: цель `(не ((длина знак) равен 0)) или (не
результат)` доказана при теле-`если`. То есть дело не в форме цели самой по
себе, а в том, что сведение по `случай любое` до неё не доводит.

**Третье, подтверждено заново: вариант С ПОЛЯМИ так не берётся.** Ни одной цели
на «Беда Redis», «Слово Redis», «Целое взято», «Строка взята» закрыть не удалось —
имена полей в обещании связать нечем.

**Поправка 24 августа: вариант С ПОЛЯМИ берётся — если поле восстановить
доступом из самого разбираемого.** Здесь стояло, что имена полей в обещании
связать нечем. Связывать их и не надо: поле подставляется термом, читающим его у
разбираемого значения тем же доступом, каким его читает тело.

```
обеспечивает «у узла-списка полей нет»
  если «узел» равен (вариант «Значение списка» с «элементы» равным («Элементы узла в монаде» от «узел»))
    то результат равен пустой список иначе да        → ДОКАЗАНО
```

Годится и нульместная функция, возвращающая вариант: охрана
`если «узел» равен («Узел ничто в монаде») то …` доказывается так же — ядро
разворачивает плоское определение прямо в охране.

Замер: `flang/self/monad-expand.flang` — 17 таких обещаний, доказаны 17 из 17;
`flang/self/bounded.flang` — 9 из 9. Ветка `b/self-bounded`, двоичный из
`bootstrap/` над `462a24cf`.

**Граница поправки названа тем же прогоном.** Ход упирается не в поля, а в то,
что стоит в ветви: где ветвь — литерал, имя или вызов от восстановленного поля,
цель берётся; где ветвь ведёт в `отфильтровать` по восстановленному списку
(«Есть поле у узла в монаде», «Взять поле в монаде»), не берётся — обе пробы
остались объявленными.

**Заодно снята мерка глубины у дизъюнкции по условиям на пути.** У «Байтов в
знаке» четыре яруса `если`; пять обещаний, написанных дизъюнкцией по условиям
пути, доказаны все пять. А тот же смысл, записанный одним `равен` с `если`
ВНУТРИ цели — `(длина результат) равен (если C то 1 иначе 0)` — остаётся на
сетке: ядро делит цель по условию, но не разбирает `если`, стоящий под `равен`.

**Два отрицательных замера с той же доли, чтобы их не переоткрывали.** Зеркало
`A не меньше B` → `B не больше A` само по себе не дало НИЧЕГО: «Байтов в тексте»
(`provod`), «Грузы» и «Разобрать поток Redis» (`redis`) как стояли на сетке, так
и стоят. Перепись `не результат` → `результат равен нет` тоже дала ноль там, где
тело — свёртка («Есть порча», «Есть отказ Redis»): до вида цели сведение просто
не доходит, и менять вид цели незачем. То есть форма цели решает ТОЛЬКО когда
сведение до неё довело; в остальных местах это пустая правка.

**Цена проверки на пустоту здесь нулевая, и это стоит сказать.** Ни одного
доказательства на теореме: все 27 прибавленных ядро сводит само. Поэтому подмена
тела заглушкой не ломает ни одной ссылки на вызов, и все 27 остаются СУДИМЫМИ —
вердикт под заглушкой становится «объявлено, не доказано», а не «не судили».

**Чем подтверждено.** Ветка `b/provod-2` над `18f92b6b`, двоичный из
`bootstrap/`. Парный замер `flang check --proof --json`, считаются свои
утверждения файла: `wire.flang` 16 из 43 → 29 из 62, `redis.flang` 10 из 39 → 24 из 70. Теорем
не написано ни одной. Каждое прибавленное прогнано подменой тела заглушкой той
же подписи: из 13 прибавленных в `wire.flang` подмену пережили 3, из 14 в
`redis.flang` — одно («отсутствие значения отказом не считается»: заглушка `нет`
и есть та цель).
