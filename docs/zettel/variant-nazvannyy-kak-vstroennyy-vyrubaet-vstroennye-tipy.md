# Вариант суммы, названный как вариант встроенного `«Отклик»`, отключает ВСЕ встроенные типы ввода-вывода, а диагностика жалуется на другое

Программа с планом получает от языка три встроенные суммы — `«Поручение»`,
`«Отклик»`, `«Продолжение»`. Если своя сумма объявит вариант с именем, уже
занятым вариантом `«Отклик»` (например `«Записано»`), встроенные типы перестают
существовать для всего модуля. Диагностика при этом говорит

```
FLANG_UNKNOWN_NAME, строка 78, столбец 1: неизвестный тип «Отклик»
```

— то есть указывает на КАЖДУЮ функцию, которая честно принимает `«Отклик»`, и ни
разу не называет ни настоящую причину, ни строку с одноимённым вариантом.

Ошибка выглядит как «встроенных типов нет в этом файле», и первая мысль —
что план объявлен неправильно или файл не признан планом. На самом деле план
разобран, а столкновение имён вариантов сняло ввоз всей тройки.

**Чем подтверждено.** Ветка `vypusk/vim`, 20 августа 2026. Файл
`scripts/proverka-vim.flang` с состоянием плана

```flang
тип «Ход»
  вариант «Пишем слова»
  вариант «Записано»          // ← имя занято вариантом «Отклик»
```

давал 11 замечаний, из них 5 — «неизвестный тип «Отклик»». Переименование
одного варианта в `«Слова записаны»`, без единой другой правки, дало
«проверено — замечаний нет».

**Что это стоило.** Заход был потрачен на поиск ошибки в объявлении плана и в
порядке функций — то есть ровно там, куда указывала диагностика.

**Как чинить по существу.** Отказ обязан называть столкновение: «вариант
«Записано» уже объявлен встроенной суммой «Отклик»» — с местом СВОЕГО
объявления. Это тот же род беды, что описан в
[[a-dictionary-field-named-like-a-keyword-cannot-be-read]]: имя, занятое
языком, тихо меняет смысл соседнего кода.

**Чем ограничено.** Проверено на двоичном `flang` 0.5.0, собранном из этого
дерева. Столкновение проверялось только с вариантами `«Отклик»`; как ведут себя
столкновения с `«Поручение»` и `«Продолжение»`, не проверялось.
