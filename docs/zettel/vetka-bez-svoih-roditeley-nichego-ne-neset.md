# Ветка, у последнего коммита которой ОБА родителя уже в стволе, не несёт ничего — сколько бы конфликтов ни насчитал `merge-tree`

Число конфликтующих файлов — не мера работы, оставшейся в ветке. Оно мера того,
насколько разъехались точки ветвления. Две ветки при сведении в один ствол
показали 80 и 52 конфликтующих файла при 3 и 1 невлитом коммите — и обе после
проверки оказались пустыми: содержимое давно в стволе, а конфликты давал повтор
чужого слияния поверх устаревшего дерева.

**Проверка занимает секунду и отвечает по существу.** Взять невлитые коммиты и
спросить о родителях каждого коммита слияния:

    git log --oneline github/main..ВЕТКА
    git log -1 --format='%P' <коммит-слияния>
    git merge-base --is-ancestor <родитель> github/main   # для КАЖДОГО родителя

Если у коммита слияния оба родителя — уже предки ствола, то своей истории он не
приносит: всё, что он мог бы дать, это его собственное разрешение конфликта, а
ствол те же две стороны уже свёл сам. Сливать такую ветку — значит проводить
второе, независимое разрешение того же столкновения поверх дерева, ушедшего
вперёд.

**Чем подтверждено (19 августа 2026, ствол `e56d33d7`).**

| ветка | невлитых коммитов | конфликтующих файлов | своего содержимого |
|---|---:|---:|---|
| `work/checks-in-flang` (дерево `vypil`) | 3 | 80 | **одна строка** |
| `work/length-remembers` (дерево `tipy`) | 1 | 52 | **ноль** |

У `work/length-remembers` единственный невлитый коммит — слияние `5d4c7903`,
родители `297c120e` и `db43fb4a`, оба предки ствола (`merge-base --is-ancestor`
даёт «да» для обоих). Из 1524 файлов её дерева 17 не совпали ни с одним из
родителей — это её ручное разрешение; ствол те же две стороны свёл своим
слиянием (`adc7de8f` внутри `83683ab5`, 35 спорных кусков вручную). Дерево ветки
при этом отстало от ствола на 468 файлов и 42 313 строк.

У `work/checks-in-flang` из трёх коммитов один — слияние с теми же свойствами,
второй правит `CHANGELOG.md`/`changelog.json` (файлы ПОРОЖДЁННЫЕ, и версия ветки
на 73 строки СТАРШЕ стволовой), третий добавляет две заметки базы знаний — обе
уже в стволе: одна побайтово та же, вторая отличается переходом словаря,
сделанным стволом позже, плюс одной строкой «Связано». Эта строка и была всем,
что удалось перенести.

**Чего проверка НЕ ловит, и это важно.** Слияние, оба родителя которого в
стволе, всё же может нести ручной текст, которого нет нигде: разрешение
конфликта пишется руками. Поэтому вторым шагом идёт пересчёт по деревьям —
сколько файлов ветки не совпадают НИ С ОДНИМ родителем:

    git ls-tree -r <ветка> | ... сравнить blob-хеши с обоими родителями

Ноль таких файлов означает «нечего терять» строго. Ненулевое число (здесь 17)
означает «надо посмотреть глазами», а не «надо сливать»: если ствол уже свёл те
же две стороны сам, его разрешение новее.

**Чем ограничено.** Проверка отвечает про КОММИТЫ, а не про намерения. Ветка,
у которой есть свои обычные (не сливающие) коммиты, под неё не попадает — там
считать содержимое надо по-настоящему.
