# Втащенная цель печати работает в двоичном СРАЗУ — через прогонщик JSON; ключа `--target` не хватает только человеку

**Поправка того же часа, и она опровергает заголовок, стоявший здесь раньше.**
Здесь стояло: «втащить цель в замыкание — половина работы: вторая половина живёт
в оболочке на C, и без неё двоичный по-прежнему отвечает «цели нет»». Первая
половина верна, вторая — нет, и опровергнута прогоном.

У двоичного ДВА входа, а не один. Человеческий (`flang emit`, `flang check`,
`repl`) живёт в `flang/src/emit/c/flang_repl.c` и знает одну цель. Но есть
второй — прогонщик JSON (`flang/src/emit/c/flang_cli.c`), и он умеет звать
ЛЮБУЮ функцию связанной программы по имени:

```
echo '{"fn":"Печать в C-шарп от исходников","args":[…]}' | ./bootstrap/flang --json
```

Этого хватает целиком. Замер: двоичный напечатал C# для **107 программ корпуса
из 107**, ноль отказов, 0,24 с на программу. Сверка с эталоном на JavaScript
(`flang/src/emit/csharp.mjs`) на той же программе: **963 файла, 856 совпали
побайтово сразу**, остальные 107 — после вычитания одного названного блока
(«Граница входа», которую эталон на flang не печатает вовсе,
[[granica-vhoda-ne-napisana-u-pyati-celey-i-eto-vidno-tolko-syrym-diffom]]).
Расхождений сверх этого блока — **ноль**.

То есть ошибка рассуждения была такая: я померил ответ ОДНОЙ команды
(`flang emit --target csharp` → «цели нет») и заключил из него, что двоичный цель
не умеет. Признак, по которому это ловится: у напечатанной программы есть
`FL_PROGRAM_CALL` — вызов по имени, — и всё, что объявлено в замыкании,
достижимо через него без единой строки C.

Ниже — то, что остаётся верным: чего не хватает ЧЕЛОВЕЧЕСКОМУ входу.


Печать в C# в замыкании двоичного: 446 различных имён функций с суффиксом
`sharp` в напечатанном `bootstrap/compiler_flang.c`, 413 в таблице символов
собранного бинарника. Команда `./bootstrap/flang emit файл.flang --target csharp`
при этом по-прежнему отвечает «цели «csharp» в этом бинарнике нет» — и это
единственное, чего не хватает, потому что через прогонщик JSON цель уже
работает.

**Где именно.** `flang/src/emit/c/flang_repl.c`: разбор ключей и отказ по
неизвестной цели — строки 6172—6182 (`if (strcmp(target, "c") != 0)`), сборка
записи настроек печати и вызов точки входа — строки 6273—6291, справка — строки
261, 328, 337. Сама функция `emit_file` — 315 строк.

**Сколько работы.** Оценка (не замер): около 100 строк C на цель —
разбор `--target` в выбор ветки (≈12), поиск каталога рантайма цели по своему
опознавательному файлу (≈30; для C это `flang_runtime.h` без шапки
«Сгенерировано», для C# это был бы `Value.cs`), чтение шести файлов `.cs`
(≈20), сборка записи «Настройки шарп» из двенадцати полей и вызов (≈30),
справка (≈6).

**Почему это НЕ пишется на flang.** Не из-за выбора: на стороне flang эта работа
уже сделана и заняла 37 строк (`flang/self/bootstrap/compiler.flang`, две точки
входа). Оставшееся — три вещи, которых в языке нет вовсе: чтение аргументов
командной строки, чтение файлов с диска и выбор ветки по строке аргумента. Язык
чистый, ввода-вывода в нём нет; всё это принадлежит хозяину, и хозяин у
двоичного один — оболочка на C.

**Отсюда правило для планирования.** Оценивая «двоичный печатает во все восемь
целей», считайте ДВЕ величины, а не одну: строки на flang (втаскивание,
разведение имён, точка входа) и строки на C (ключ, рантайм цели, настройки).
Первая у C# вышла 37, вторая — около 100 и не написана. Для восьми целей вторая
величина — это ≈700 строк C в одном файле, и она не делится между агентами:
все семь правок ложатся в одну функцию `emit_file`.

**Ещё одно, что стоит знать до планирования: рантайм цели едет в вывод дословно
с диска.** Для C# это шесть файлов `flang/src/emit/csharp/*.cs`, 136 716 байт
(`Value.cs` 31 930, `Field.cs` 1 831, `FlangError.cs` 3 259, `Ctx.cs` 5 675,
`Flang.cs` 69 366, `FlangCli.cs` 24 655). В релизном архиве
(`scripts/build-release-c.mjs`) их нет: архив — это семь напечатанных файлов
плюс страница руководства. Двоичный ищет рантайм в `--runtime`,
`$FLANG_RUNTIME_DIR`, `../flang/src/emit/c` и `../share/flang/c`; последнего
каталога в архиве тоже нет, то есть ТОТ ЖЕ пробел уже существует у цели C и
просто не замечен, потому что при печати самого себя каталог исходников рядом.

**Чем подтверждено.** Ветка `rabota/vosem-csharp`, коммит `70bf3c28`. Прогон
двоичного по корпусу — оснасткой вне дерева, которая строит замыкание импортов,
собирает запрос прогонщика и разворачивает ответ; корпус тот же, что у
`flang/test/self-emit-csharp.test.mjs`. Числа
имён — `grep -oE 'compiler_flang_[a-z0-9_]*sharp[a-z0-9_]*'` по
`bootstrap/compiler_flang.c` и `nm` по `bootstrap/flang`. Ответ двоичного —
прогоном. Строки в `flang_repl.c` — `sed`. Размеры рантайма — `stat`.
