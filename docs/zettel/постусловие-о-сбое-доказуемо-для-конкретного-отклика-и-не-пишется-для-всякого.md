# Постусловие о сбое доказуемо для конкретного отклика и не пишется для всякого

Замерено 11 сентября 2026 на ветке `r/adr-otklik-otkaz` поверх `gh/dev`
`2c40752d0`, двоичный `bootstrap/flang` 0.7.17, при подготовке
[ADR-0034](../adr/0034-hardware-failure-is-described-not-proved.md).

**Что проверялось.** К обработчику «После каталога» из
`examples/io/temp-directory.flang` (разбирает «Отклик», на «Сбой» отвечает
«Провал» с тем же кодом) приписывались постусловия трёх форм.

| форма условия | исход |
|---|---|
| `если отклик равен (вариант «Сбой» с код равным "…" и сообщение равным "…") то результат равен (вариант «Провал» с код равным "…" …) иначе да` | **доказано**, правило «разбор цели по условию» |
| то же под `для всех отклик обеспечивает …` | **доказано**, то же правило |
| `если отклик равен (вариант «Сбой» с код **как** код и сообщение **как** сообщение) то результат равен (вариант «Провал» с код равным код …) иначе да` | `FLANG_PARSE: после имени поля ожидалось 'равным'` |

**Что это значит.** Ядро разворачивает ветвь разбора по варианту (это уже
знал зеттель об обещании с условием по варианту), но поля в условии
постусловия только сравниваются с литералами — связать их именем нечем. Поэтому
«всякий сбой отдаётся наружу со своим кодом» — самое нужное утверждение о слое
ввода-вывода — сегодня не пишется; пишется только «этот конкретный сбой
отдаётся с этим кодом».

**Соседний замер той же сессии.** Полнота разбора откликов проверкой типов
обходится словом `случай любое`: без ветви «Сбой» и без «любое» —
`FLANG_MATCH_NOT_EXHAUSTIVE`, с «любое» — проверка довольна, красен только
рукописный пример. По дереву (без `flang/self/`): обработчиков, разбирающих
«Отклик» сами, 215 — с ветвью «Сбой» 136, с «любое» без «Сбой» 79, ни того ни
другого 0.

**Отвергнутый путь.** Не пробовать выразить «всякий сбой» через `пусто` или
через длину — разбор суммы и списочный разбор сведения между собой не имеют
(тот же соседний зеттель).

Соседи: [[обещание-с-условием-по-варианту-разворачивает-ветвь-разбора]],
задача 1410.
