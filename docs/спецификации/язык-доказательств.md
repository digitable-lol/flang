**Главный вывод, и он не тот, которого ждали.** Утверждение «в flang нет языка
доказательств» — неверно, и это проверено прогоном. Язык есть, теоремы пишутся,
ядро их принимает. Неверно другое: **шаг доказательства не может нести
промежуточный факт**. Автор вправе только выбрать обоснование для той цели,
которую ядро построило само; сказать «сначала верно вот это, а из этого следует
цель» нечем. Поэтому труд и не масштабируется: писать нечего не потому, что нет
слов, а потому, что слова говорят ровно об одном заранее известном месте.

### 1.2. Разделение недоказанных: форма цели против ненаписуемого шага

Правил, спрашивающих ВИД цели, у ядра пять, и ядро называет их само в тексте
отказа (`flang/proof/reduce.mjs:1110`, тот же текст в
`flang/self/proof-kernel.flang`):

> у цели этого случая нет вида, к которому у ядра есть правило: правил пять —
> «не меньше 0», «не больше конечного литерала», «не больше терма», «равно» и
> «содержит» … Вида цели не спрашивает только шестое, «цель есть допущение».

Форма цели считается **у листьев**, а не у верхнего узла: `если` ядро делит
своим ходом «разбор цели по условию» (предел 4), `пусть` разворачивает
нормализация, замкнутый признак `да` закрывается вычислением.

```
A. хотя бы один лист цели не попадает ни в одно из шести правил:  153
B. все листья попадают в правила, но вывод не сошёлся:            240
```

Формы листьев у недоказанных (одно утверждение даёт несколько листьев):

```
257  равно                      19  не меньше 0
164  признак да (закрывается)    8  содержит
100  признак нет                 6  не меньше литерала
 31  не больше терма             6  равно признаку
 30  не больше литерала          3  имя
 27  разбор в цели               3  голый вызов
 20  не меньше терма             1  не равно
```

**Что здесь важно и легко перепутать.** Формы `не меньше <терм>` и
`не меньше <литерал, кроме нуля>` правила НЕ имеют — при том, что зеркальная
`не больше <терм>` имеет. Это не догадка: теорема с целью `результат не меньше 1`
получает дословный отказ «у цели этого случая нет вида, к которому у ядра есть
правило», а та же теорема с целью `1 не больше результат` доходит до шага и
отказывает уже по другой причине. То есть **одно и то же математическое
утверждение, записанное двумя способами, попадает в разные половины таблицы**.

Итог разделения, словами: **две трети недоказанного (240 из 393) упираются не в
вид цели, а в отсутствующий шаг** — ядро берётся за цель и не доводит.

### 1.3. Правила ядра сегодня

Ядро — `flang/self/proof-kernel.flang`, и только оно: реализации на JavaScript
в дереве больше нет, ссылка `flang/proof/reduce.mjs:590` мертва.

**Правил ВОСЕМЬ**, и называет их само ядро, в текстах отказов:

| имя | что берёт |
|---|---|
| `неотрицательность по построению` | `Е не меньше 0`, где `Е` собрано из неотрицательного |
| `ограниченность точным потолком по построению` | `Е не больше <конечный литерал>` |
| `порядок по построению` | `Е не больше <терм с известными границами>` |
| `тождество после переписки допущением` | `А равно Б` после переписки допущениями |
| `вхождение по построению` | `Л содержит Э`, где `Э` стоит в `Л` по построению |
| `порядок соседних по построению` | `Л не убывает`, где порядок соседей виден по построению |
| `цель есть допущение` | цель совпала с допущением знак в знак |
| `несовместимые допущения` | случай недостижим: пара допущений не выполнима вместе |

Первые шесть — про ФОРМУ цели, и ровно их ядро перечисляет в отказе «у цели
этого случая нет вида, к которому у ядра есть правило». Два последних вида цели
не спрашивают.

**Здесь стояло «сличение синтаксическое» — это беднее правды.** Тождество читает
`плюс` и `умножить на` с точностью до порядка соседей ОДНОГО узла (через скобки
переставлять нельзя: ассоциативность в IEEE-754 ложна), переписывает `длина`
равным выражением у восьми встроенных форм и берёт свёртку, растущую ровно на
один.

**Перечень внутри каждого правила длиннее этой таблицы на 28 умений.** Полный
список с уликами и прогонами — `flang/proof/SPEC.md`, раздел «Восемь правил ядра
и 28 умений, которых в описании не было»; сам список — `flang/proof/УМЕНИЯ.tsv`;
улики — `flang/proof/map/abilities.flang` (28 утверждений, доказано 28, код 0);
сторож на расхождение — `bootstrap/flang io scripts/kernel-abilities-guard.flang`.

Плюс два хода, которые ничего не выводят, а подают цель правилам:
`вычисление замкнутой цели` и `разбор цели по условию` (предел ветвления 4).

Плюс принципы индукции: объявленная сумма (начальность), встроенный список (два
образца), отрезок `неотрицательное` (две границы и строгий спуск), свёртка тела (конечность
числа витков) — и **строка**. Здесь стояло «у `строка` принципа нет — проверено
прогоном»: это НЕВЕРНО и опаснее пропуска, потому что по такой строке человек не
станет писать доказательство, которое проходит. Прогон:

```
bootstrap/flang check --proof flang/proof/map/abilities.flang
  постусловие «У8 голова строки — ровно один знак» функции «Первый знак» —
  доказано индукцией по «строка»: база 1 случай, шаг при допущении на частях
  (1 случай), правила сведения: ограниченность точным потолком по построению
```

Индукция по строке закрывает цели о МЕРЕ строки; про содержимое строки она
молчит — у цели о содержимом нет вида. У `признак` принципа действительно нет.

## 2. Что в языке УЖЕ есть, и это надо сказать первым

Гипотеза «написать доказательство руками нельзя: языка доказательств нет»
**опровергнута прогоном**.

Поверхность (девять слов, `flang/proof/SPEC.md`, раздел 1):

```flang
теорема «факториал не меньше нуля»
  дано число: неотрицательное
  утверждаем результат не меньше 0
  индукция по число убывает число
    случай 0
      то по примеру «Ноль факториал»
    случай любое
      то по предположению
  следовательно доказано
```

Прогон этой теоремы, дописанной к `flang/stdlib/numbers.flang`:

```
постусловие «…» функции «Факториал» — доказано индукцией по «неотрицательное»:
база 1 случай, шаг при допущении на убывшем «число» (1 случай),
правила сведения: неотрицательность по построению
```

То есть теорема в библиотеке **пишется и принимается**. Заметка
[[claims-about-length-are-two-thirds-of-what-the-kernel-refuses]] утверждает
обратное («в `flang/stdlib` теорему писать НЕЛЬЗЯ: восемь слов не имеют
продукции в `flang/self/parser.flang`») — это устарело: продукции написаны
(`flang/self/parser.flang:6199` и далее), и проба это подтверждает.

Обоснований шага четыре, и все четыре в дереве работают — включая `по свойству`,
про которое `flang/proof/SPEC.md` в перечне «что ядро НЕ доказывает» до 23
августа 2026 писал «не берёт, по-прежнему». Берёт: прогон
`flang/proof/examples/body-forms.flang` даёт `«Выше на два» — доказано: терм
принят ядром, 1 шаг`, а вся теорема там — один шаг
`по свойству «высота неотрицательна»`. Круг (ссылка на доказываемое сейчас
постусловие) при этом по-прежнему запрещён:
`по примеру «…»` (154 вхождения), `по предположению` (54), `по свойству «…»`
(31), `по закону «…»` (17). Теорем в дереве **87**: 34 в
`flang/proof/examples`, 3 в `flang/self`, 3 в `examples`, остальные — в
проверках.

Цепочка шагов тоже есть: `затем <утверждение> по <обоснование>`
(`flang/self/parser.flang:6478`).

### Чего нет — одной строкой из самого ядра

```
flang/self/proofterm.flang:914
  «выписанное утверждение шага — не заключение этого места. Заключение ядро
   СТРОИТ по объявлению и телу функции, и подменить его написанным нельзя;
   уберите утверждение или напишите то же самое»
```

**Утверждение, выписанное в шаге, обязано совпасть с целью, которую ядро
построило само.** Значит `затем` — не звено вывода, а второй способ обосновать
ту же самую цель. Промежуточного факта в доказательстве написать нечем.

И вторая половина той же дыры, тоже в дереве: цепочка **уже копит** список
известного (`Ход цепочки`, поле `известно`, пополняется в
`Шагнуть по цепочке`), но использует его **только в тексте отказа**
(`flang/self/proofterm.flang:1128`). Факт, добытый первым шагом, второму шагу
недоступен.

## 3. Замер гипотезы: переформулировкой не берётся

Метод: берётся недоказанное утверждение `flang/stdlib`, строка `обеспечивает`
заменяется на переформулировку того же смысла, файл прогоняется
`flang check --proof`. Затем то же утверждение пробуется теоремой сегодняшней
нотации. Прогон — `.scratch/opyt.mjs`.

### 3.1. `lists.flang` «сортировка не теряет и не добавляет элементов»

Цель `(длина результат) равен (длина элементы)`, тело — свёртка
`«Вставить по порядку»`. Лемма «вставка удлиняет список ровно на один» **уже
доказана в том же файле**.

| проба | исход |
|---|---|
| как есть | сетка 2 значения |
| `не больше` вместо `равно` | сетка |
| `не меньше` вместо `равно` | сетка |
| приём «`равен да`» | сетка |
| зеркалим дерево условий тела | сетка |
| ослабление «результат не пуст при непустом входе» | сетка |
| теорема: индукция по списку, шаг `по предположению` | ОТВЕРГНУТА |
| теорема: шаг `по свойству «вставка удлиняет список ровно на один»` | ОТВЕРГНУТА |
| теорема: цепочка `затем …` с промежуточным фактом | ОТВЕРГНУТА |

Отказ последней — тот самый: «выписанное утверждение шага — не заключение этого
места».

### 3.2. `numbers.flang` «факториал не меньше единицы»

Цель `1 не больше результат`, тело — `если`-рекурсия по `неотрицательное`.

Шесть переформулировок — все **сетка**. Теорема на форме `результат не меньше 1`
— отказ «у цели нет вида, к которому есть правило». Теорема на родной форме
`1 не больше результат` — база закрывается примером, **отказывает только шаг**:
нужно `1 ≤ число × Факториал(число−1)` из `1 ≤ Факториал(число−1)`, а правила
умножения у ядра нет.

**Контроль** (обязателен, иначе замер меряет прибор): та же нотация на цели
`результат не меньше 0` — **ДОКАЗАНО индукцией по «неотрицательное»**. Прибор работает.

### 3.3. Ещё два

`sets.flang` «множество из списка не длиннее списка» — 3 переформулировки сетка,
ослабление до «не меньше 0» проходит **даром** (заглушка его переживает),
теорема отвергнута на базе свёртки. `strings.flang` «разбиение даёт хотя бы одну
часть» — 3 переформулировки сетка, ослабление до «не меньше 0» проходит даром,
теорема отвергнута словами «у типа `строка` принципа индукции нет».

### 3.4. Свод: сколько недоказанного берёт сегодняшняя теорема

Прогон `.scratch/svod-teorem.mjs` по пяти модулям (`logic`, `optional`,
`result`, `numtree`, `dictionary`): **30 недоказанных утверждений, от 1 до 6
шаблонов теоремы на каждое** (ссылка на каждую доказанную лемму модуля;
индукция по каждому подходящему параметру с базой по каждому примеру).

```
пробовано утверждений: 30; закрыто сегодняшней теоремой: 0
```

**Ноль.** Гипотеза подтверждена: ни переформулировка, ни сегодняшняя теорема
недоказанное не берут.

## 4. Сравнение с существующими

Правильный сосед у flang — **не** Coq и не Lean.

| | кто ищет | язык доказательств | доверенное ядро | чем проверено само ядро | автоматика не справилась |
|---|---|---|---|---|---|
| **Coq** | человек | есть, богатый (Gallina + Ltac) | ~20 тыс. строк OCaml | вторая проверка термов, чужие реализации | пишешь тактику или терм руками |
| **Lean 4** | человек | есть (тактики + термы) | ~10 тыс. строк C++ | внешние проверяльщики (`lean4checker`, `trepplein`) | пишешь руками |
| **Isabelle/HOL** | человек | есть (Isar) | ядро LCF, тысячи строк ML | тип `thm` абстрактен: терм собирается только правилами | пишешь Isar-доказательство |
| **Dafny** | **машина** (SMT) | почти нет: `assert`, `calc`, `invariant`, лемма-функция | Z3 (сотни тысяч строк) + переводчик | не проверено ничем: SMT — оракул | подсказки-`assert`, ручная лемма, ослабление спецификации |
| **F\*** | машина, потом человек | есть (тактики Meta-F\*) | Z3 + ядро проверки типов | ядро проверяемо, SMT — нет | пишешь лемму или тактику |
| **Why3** | **машина** (много решателей) | почти нет: `assert`, `cut`, лемма | набор решателей, ядру не доверяет | сессия хранит, каким решателем закрыто | делишь цель, зовёшь другой решатель, пишешь лемму |
| **flang, 20 августа 2026** | **только ядро** | есть, но шаг не несёт промежуточного факта | **7036 строк** (`proofterm.flang` 2716 + `proof-kernel.flang` 4320) | подделки, эталон, аксиом ноль | **ничего**: утверждение уходит в «сетку» |

**Строка flang в этой таблице снята 20 августа и с тех пор изменилась в двух
клетках.** Шаг научился нести промежуточный факт (`затем … по свойству «…»`,
`flang/proof/SPEC.md`, раздел «Десятое ЗНАЧЕНИЕ без десятого слова»), и значит
последняя клетка читается не «ничего», а «пишешь теорему»: ровно то, что делают в
Coq, Lean и Isabelle. Теорем в дереве языка **160** в 62 файлах, из них **53** в
`flang/stdlib` (`grep -rc '^\s*теорема ' flang --include=*.flang`, 24 августа
2026). Правил у ядра стало **одиннадцать**
(`grep -c 'тотальная функция «Правило' flang/self/proof-kernel.flang`) — в §0
выше их шесть, и это число того же 20 августа.

**Почему сосед всё же Dafny и Why3, а не Coq.** Не по мощности логики и не по
наличию языка доказательств — он есть у обоих соседей и у нас. По трём другим
чертам: (1) первым делом доказательство ищет машина, и на большей части
утверждений человек не пишет ничего — в вердикте это стоит отдельным числом
(`утверждений 177: доказано 114 … из них без теоремы 54` — замер на `flang/stdlib/sha1.flang` с импортами); (2) когда машина не справилась,
написанное руками доказательство остаётся структурным разбором цели, а не языком
тактик — тактик нет вовсе, и это выбор, а не недоделка (тактика ищет, поиск
нетотален, значит на flang её не написать); (3) спецификация живёт при коде, а не
в отдельном файле теорем. У Coq и Lean первый и третий пункты противоположны.

**И одна черта, которой у соседей нет.** У Dafny и Why3 доверенное ядро — SMT-решатель,
который никем не проверяется. У flang аксиом **ноль**, и это стережётся отдельно
(`flang/src/proofterm.mjs`, `АКСИОМЫ = Object.freeze([])`; в дереве проверяется
подделками `flang/scripts/poddelki-yadra.mjs`). Это преимущество, и его нельзя
потерять, добавляя язык доказательств.

**Разрыв, которого таблица не показывает, и он не про механизм.** В Coq и Lean
никто не доказывает с нуля — берут готовую лемму. Готовых доказанных лемм: mathlib
свыше 200 000, у нас на 20 августа было **62 на всю библиотеку**. Это и есть
настоящая дистанция: не «у них пишут руками, а у нас машина», а разница в объёме
накопленного. Закрывается она не правилами ядра, а трудом — если труду есть куда
прикладываться.

## 5. Устройство языка доказательств: спека

### 5.1. Главный приём — занять форму, которую разбор УЖЕ отвергает

Из шести заказанных шагов **три с половиной** пишутся сегодняшними словами.
Занятость проверена прогоном `node flang/scripts/word-occupancy.mjs` по 477
файлам корпуса.

| шаг | как пишется | новых слов |
|---|---|---|
| индукция по списку | `индукция по элементы` + `случай пусто` / `случай голова и хвост` | **0** — есть |
| индукция по числу | `индукция по н убывает н` + `случай 0` / `случай любое` | **0** — есть |
| ссылка на лемму | `по свойству «имя»` | **0** — есть |
| подстановка равного | `затем <равенство> по свойству «имя»`, дальше правило тождества переписывает | **0** — форма разбирается, ядро её отвергает |
| разбор случаев | `разбор случаев <терм>` / `случай …` | 1 фраза, `по случаям` свободна (0 голых) |
| переписывание по определению | `по определению «Имя»` | 1 фраза, `по определению` свободна (0 голых) |

Занятость кандидатов, прогон:

```
«имеем»           голым именем 0 — свободно
«определению»     голым именем 0 — свободно
«по определению»  голым именем 0 — свободно
«лемма»           голым именем 0 — свободно
«по лемме»        голым именем 0 — свободно
«по случаям»      голым именем 0 — свободно
«подставив»       голым именем 0 — свободно
«обобщённо»       голым именем 0 — свободно
«случаи»          голым именем 14 — СЛОМАЕТСЯ (flang/proof/kernel.flang и др.)
«откуда»          голым именем 21 — СЛОМАЕТСЯ
```

### 5.2. Как выглядит доказательство — строкой кода

Форма уже разбирается сегодня; меняется только то, ЧТО ядро с ней делает.

```flang
теорема «сортировка не теряет и не добавляет элементов»
  дано элементы: список числа
  утверждаем (длина результат) равен (длина элементы)
  индукция по элементы
    случай пусто
      то по примеру «Пустой список»
    случай голова и хвост
      затем (длина («Вставить по порядку» от голова и («Сортировать» от хвост)))
            равен ((длина («Сортировать» от хвост)) плюс 1)
            по свойству «вставка удлиняет список ровно на один»
      затем (длина («Сортировать» от хвост)) равен (длина хвост)
            по предположению
      то по предположению
  следовательно доказано
```

Читается это так: первая строка `затем` вводит **промежуточный факт** —
инстанцию уже доказанной леммы на конкретном вызове; вторая вводит допущение
индукции как факт; последняя строка закрывает построенную ядром цель, и правило
тождества переписывает её обоими фактами.

**Ни одного нового слова.** Сегодня эти три строки разбираются и отвергаются
ядром с текстом «подменить его написанным нельзя».

Ещё два шага, которым слово нужно:

```flang
    разбор случаев первый           // 1 фраза, «по случаям»/«разбор случаев»
      случай да
        то по определению «Не так»  // 1 фраза, «по определению»
      случай нет
        то по примеру «Оба нет»
```

### 5.3. Правила, по которым проверяется шаг

Проверяльщик остаётся **свёрткой по конечному дереву без единого поиска**. Каждый
шаг отвечает на один вопрос «выведено ли это из уже известного НАЗВАННЫМ
правилом», и отвечает да или нет.

1. **Промежуточный факт.** `затем <У> по <обоснование>`, где `<У>` не совпадает с
   построенной ядром целью. `<У>` доказывается тем же обоснованием и теми же
   правилами сведения, что и цель, — но из уже известного. На успехе `<У>`
   пополняет список известного. Поиска ноль: подстановку называет сам автор,
   правило названо словом.
2. **Накопление.** Известное к шагу N — это гипотезы `дано`, предусловия функции,
   допущения индукции этого случая и факты шагов 1…N−1. Ничего больше.
3. **Закрытие обязательно.** Цепочка принимается, только если ХОТЯ БЫ ОДИН шаг
   закрыл построенную ядром цель. Цепочка из одних промежуточных фактов —
   **отвергается**. Это и есть первая подделка: доказательство, которое ничего не
   доказало, но выглядит как доказательство.
4. **Круг запрещён**, как и сегодня: ссылка `по свойству` на доказываемое сейчас
   постусловие отвергается.
5. **Аксиом ноль.** Ни один шаг не добавляет посылки, которой не было: лемма —
   это постусловие, проверяемое на каждом возврате (свойство языка, а не
   допущение); допущение индукции даёт принцип, читаемый с объявления.

### 5.4. Чем это НЕ является

**Тактик нет и не будет.** Тактика — метапрограмма, ворочающая цель поиском;
поиск нетотален, а всё в flang либо тотально, либо объявлено обычным. Решение
записано в `flang/proof/SPEC.md` и не меняется.

**Проверяльщик ничего не ищет.** Всё, что он делает при новом правиле, — проверяет
написанное автором утверждение теми же шестью правилами, которыми проверяет цель.

## 7. Три развилки

### Развилка 1 — только автоматика (как сегодня)

Расширять ядро правилами: каждая новая форма цели — новое правило.

**Что станет доказуемо.** По разложению: 153 утверждения `flang/stdlib` упираются
в форму цели. Самые крупные куски — `не меньше <терм>` и `не меньше <литерал>`
(26 листьев), `разбор в цели` (27), `голый вызов` (3). Замер прошлых недель
говорит, чего стоит ожидать: правило «порядок с границей-термом» дало **одно из
семи**; два заказа на правила закрыли **ноль**; автоматическая индукция по
`разбор`у дала **9** при заказанных 12.

**Цена.** Правка ядра на каждую форму. Подделка на каждое правило. Труд **не
масштабируется**: правило может писать только тот, кто правит ядро, и двое в
ядре мешают друг другу.

### Развилка 2 — автоматика плюс язык доказательств

Ядро пробует само; не вышло — человек или модель пишет шаги.

**Что станет доказуемо.** Прямо адресуются 240 утверждений из 393 — те, где форма
цели у ядра есть, а вывод не сошёлся. Сколько из них возьмётся, честно сказать
можно только прогоном по мере появления шагов; обещать долю здесь — оценка
вместо замера.

**Цена.** Новая поверхность языка: 0 новых слов для промежуточного факта, 2 фразы
для разбора случаев и переписывания по определению. Правка одного файла ядра.
Печать не трогается (0 байт). Подделка на каждый шаг обязательна.

**Главное — труд масштабируется.** Доказательство пишется в файле библиотеки, а
не в ядре. Десять исполнителей по десяти файлам не встречаются ни в одной строке.

### Развилка 3 — только проверяльщик

Отказаться от поиска, всё писать руками.

**Что станет доказуемо.** То же, что во второй развилке.

**Цена.** Переписать 62 уже доказанных утверждения `flang/stdlib` (и 224 по всему
дереву) в явные доказательства — при том, что 135 из 224 сегодня закрываются
вовсе без теоремы, сведением цели с телом. Плюс потеря даровых закрытий, которые
ничего не стоят и краснеют при регрессе. Развилка отвергается по числу: 224
переписанных доказательства — цена, за которую не покупается ничего, чего не даёт
вторая.

## 8. Что это даёт ИИ

Прямо и без рекламы.

**Сегодня модель не может помочь.** Единственное, что ей доступно, — переставлять
слова в утверждении и надеяться, что ядро возьмёт форму. Замер: 30 недоказанных
утверждений, до 6 переформулировок и шаблонов теоремы на каждое — **закрыто 0**.
Труд не масштабируется не фигурально, а буквально: работы нет.

**С языком доказательств модель пишет доказательство, а машина его проверяет.**
Соврать нельзя по построению: проверяльщик — свёртка по конечному дереву, каждый
шаг обязан быть выведен НАЗВАННЫМ правилом из уже известного, аксиом ноль, поиска
ноль. Модель, выдумавшая шаг, получает отказ с именем правила и местом в файле —
ровно тот сигнал, по которому обучаются и по которому чинят.

**Доказательство короткое и механическое.** Разбор одного случая — та самая
«сортировка не теряет элементов» из 5.2: три строки `затем`, каждая называет
лемму, уже доказанную в том же файле. Это не творчество, это подстановка. Именно
такую работу модель делает хорошо, а человек делает медленно.

**Чего это НЕ даёт.** «Доказано» не значит «правильно»: доказывается написанная
спецификация. Живой случай в дереве — «Чётное», где ведомость печатает «доказано
обо ВСЕХ входах», а ошибка на −4 остаётся, потому что функция и её напарница
ошибаются одинаково.

## 8-бис. ЧТО СДЕЛАНО: первый шаг реализован и предъявлен прогоном

Правило **«промежуточный факт»** написано, семя перепечатано, компилятор собран.

### Что изменилось в записи — ничего

Ноль новых слов. Запись `затем <утверждение> по <обоснование>` разбиралась и
раньше; узел шага уже нёс поле `claim`. Отвергало её ядро — теперь оно её
принимает и обязано ДОКАЗАТЬ выписанное.

```flang
теорема «сортировка деревом не теряет и не добавляет чисел»
  дано элементы: список числа
  утверждаем (длина результат) равен (длина элементы)
  по свойству «в дереве ровно столько чисел, сколько в списке»
  следовательно доказано
```

### Порядок проверки, а не порядок чтения

Грамматика требует, чтобы ПЕРВЫЙ шаг случая стоял сразу за `то` и начинался
словом обоснования: выписать при нём утверждение нельзя. Значит промежуточный
факт физически не может стоять раньше закрывающего шага. Поэтому ядро проверяет
сперва шаги С ВЫПИСАННЫМ утверждением, потом закрывающие. Это не поблажка:
промежуточный факт выводится из допущений и фактов, добытых до него, а о цели не
знает ничего.

### Цена, снятая с дерева

| что | число |
|---|---|
| правка ядра | **1 файл**, `flang/self/proofterm.flang`, +173 / −17 строк |
| из них кода | **95 строк**; довода в комментарии — 78 |
| проверяльщик вырос | 2716 → **2872** строки (+5,7 %) |
| доверенное ядро всего | 7036 → **7192** строки (+2,2 %) |
| лексер, разбор, типы, вычислитель | **0 строк** |
| восемь генераторов кода, семь рантаймов | **0 строк** |
| точка раскрутки | перепечатана в том же коммите |

### Подделки: три, и все три отвергнуты

`flang/test/fixtures/poddelka-promezhutochnyy-fakt.flang`,
прогон `node flang/scripts/poddelki-yadra.mjs`:

```
poddelka-promezhutochnyy-fakt.flang: отвергнут словами
  «ни один шаг не закрыл заключение этого места»
poddelka-promezhutochnyy-fakt.flang: отвергнут словами
  «теорема «длина не больше нуля»: не выведено заключение из постусловия»
poddelka-promezhutochnyy-fakt.flang: отвергнут словами
  «теорема «длина всегда ноль»: не выведено заключение из постусловия»
аксиом ноль: слово «аксиома» в ядре стоит только под названными доводами
подделки отвергнуты: 10 файлов, аксиом ноль, нарушений 0
```

Первая подделка — самая важная: цепочка доказывает ВЕРНЫЙ промежуточный факт и
не трогает цель. Все её шаги приняты, а постусловие ложно на всяком входе. Ядро
отвергает её отдельным условием «закрыть заключение обязан хоть один шаг».

Отказ здесь **жёсткий**, а не «объявлено, не доказано»: написанное
доказательство, которое не сходится, — ошибка в файле, и молчать о ней нельзя.

### Две настоящие цели библиотеки закрыты написанными доказательствами

`flang/stdlib/numtree.flang` «сортировка деревом не теряет и не добавляет чисел»
и `flang/stdlib/utf8.flang` «длина в байтах не меньше длины в символах» —
до этой работы обе стояли «сетка», теперь:

```
постусловие «сортировка деревом не теряет и не добавляет чисел»
  функции «Сортировать деревом» — доказано: терм принят ядром, 1 шаг —
  утверждение обо ВСЕХ входах
```

Доказательство у обеих — **пять строк**, и обе нашлись механическим перебором
(`по свойству «L»` по всем постусловиям модуля), а не озарением. Это и есть
работа, которую можно раздать: она ищется перебором и проверяется машиной.

### ИЗМЕРЕННЫЙ НОЛЬ: утверждения, которое берётся ТОЛЬКО промежуточным фактом, в библиотеке не нашлось

Это надо сказать прямо, а не спрятать. Написан перебор
(`.scratch/dvavfakta.mjs`): на каждое недоказанное утверждение строятся цепочки
двух видов —

* плоская: `затем <инстанция леммы L₁> по свойству «L₁»` плюс закрывающий шаг
  `по свойству «L₂»`, по всем парам постусловий функций, которые тело зовёт;
* с индукцией по списку: тот же промежуточный факт внутри случая `голова и хвост`.

Инстанция собирается текстом: параметры вызванной функции заменяются на
аргументы вызова, `результат` — на сам вызов. У каждой удачи **снимается
правка**: та же теорема без строки `затем`. Засчитывается только то, что без неё
НЕ берётся.

```
18 модулей flang/stdlib, 1545 цепочек — взялось только с промежуточным фактом: 0
```

(Два самых крупных модуля, `postgres` и `sha256`, сняты по времени: перебор пар
там квадратичен по числу постусловий.)

**Что это значит и чего не значит.** Не значит, что правило бесполезно: без него
в языке нельзя записать вообще никакой вывод из двух фактов, а подделки
показывают, что дверь закрыта плотно. Значит другое — **следующий упор не здесь**,
и он назван прогоном:

1. **База свёртки.** У утверждения, связывающего результат со ВСЕМ входным
   списком, при теле-свёртке посылка «начало свёртки» получается ложной: ядро
   строит `цель[результат := начало]`, а там свободен весь список. Дословно:
   «в заключении случая „начало свёртки“ свободны „элементы“». Никакая лемма
   этого не чинит — нужно **обобщённое утверждение** (инвариант накопителя,
   говорящий про обработанную часть), а его в языке высказать нечем.
2. **Формы цели `не меньше <терм>` и `не меньше <литерал ≠ 0>`** — правила нет
   вовсе, 26 листьев.
3. **Разбор случаев** — 27 листьев «разбор в цели» плюс тела-`если`.

### Печать: доказательство не едет в код, а доказанное постусловие УБИРАЕТ код

Два разных числа, и путать их нельзя.

**Текст доказательства печатается в ноль байт** — замер на программе с теоремой и
без, суммарные байты у всех восьми целей равны (см. 6.2).

**А доказанное постусловие снимает сторожа из напечатанного кода.** Замер на
`flang/stdlib/numtree.flang` с написанным доказательством и без него:

```
c:      301 148 против 301 996  →  −848 байт
python: 104 386 против 104 973  →  −587 байт
js:      69 767 против  70 338  →  −571 байт
```

То есть доказательство не только ничего не стоит в печати — оно **делает
напечатанный код меньше и быстрее**, снимая проверку, которая иначе считается при
каждом возврате.

### Примеры библиотеки

```
корпус «flang/stdlib/»: файлов 20, взято 20, отказано 0,
примеров 1216 (своих 1216), прошло 1216, не прошло 0
```

## 9. Порядок работ

По убыванию пользы, порядок уточнён замером раздела 1.2:

1. **Промежуточный факт** (`затем <У> по <обоснование>`) — он же ссылка на лемму
   на произвольном терме, он же подстановка равного. Ноль новых слов, один файл
   ядра. Адресует самый крупный кусок — 240 утверждений формы «вывод не сошёлся».
2. **Разбор случаев** — 27 листьев «разбор в цели» плюс все тела-`если`, где
   нужный факт лежит в ветви.
3. **Переписывание по определению** — машинерия развёртки в ядре уже есть
   (`Развёртка по конструктору`, `Развёртка плоского определения`), не хватает
   двери из доказательства.
4. **Правило порядка снизу** (`не меньше <терм>`) — 26 листьев, но это правило
   ядра, а не шаг: труд не масштабирует.

Каждый шаг — свой коммит, своя подделка, своё настоящее утверждение из
`flang/stdlib`, предъявленное прогоном.
