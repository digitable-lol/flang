# Поддержка `.flang` в редакторах

## Что здесь лежит

```
editors/
  vim/         подсветка .flang и языковой сервер для Vim и Neovim
  flang-lsp/   как настроить VS Code и Neovim на языковой сервер .flang
  linguist/    заявка в github-linguist на язык .flang
  README.md    этот файл
```

## Чего здесь нет

**Подсветка `.flang` есть для Vim и Neovim** — `editors/vim/`. Остальные
редакторы (VS Code, tree-sitter, Chroma) по-прежнему без неё, и это
неоплаченный долг: языковой сервер даёт диагностики, подсказки и переход к
объявлению, а раскраски текста нет. Кому понадобится раньше — тому и писать.

Работа эта кажется большой: четыре грамматики на один язык — около двадцати
одной тысячи строк, включая порождённый tree-sitter разбор. Но оценка
обманчива: правила Vim заняли **46 строк, и ни одна не написана руками** — они
печатаются из таблицы ключевых слов языка программой на самом flang
(`scripts/vim-highlighting.flang`). Список слов, набранный отдельно, — это второе
описание языка, и оно расходится с первым в первый же день.

## `vim/`

Подсветка и языковой сервер для Vim 8/9 и Neovim. Ставится одной строкой
менеджера плагинов; правила подсветки печатаются из таблицы языка; и то и
другое проверяется настоящим редактором, запущенным без окна и человека
(`flang io scripts/vim-highlight-check.flang`, `flang io scripts/lsp-check.flang`).

Там же измерено и названо, почему языковой сервер в редакторе сегодня всё ещё
требует Node: двоичный `flang lsp` не отвечает, пока стандартный ввод открыт.

## `flang-lsp/`

Единственное, что здесь про язык: как показать редактору `flang-lsp` — языковой
сервер `.flang`, который ставится вместе с пакетом (`flang/src/lsp.mjs`,
`flang/bin/flang-lsp.mjs`). Он даёт живые диагностики той же дорогой, что
`flang check`, дополнение, подписи при наведении и переход к объявлению. Это не
подсветка: сервер знает про смысл текста и ничего не знает про его цвет.
