# `flang-lsp` — языковой сервер для `.flang`

Всё остальное в `editors/` — про подсветку `.fts`: грамматики, которые
раскрашивают текст и ничего о нём не знают. Здесь другое: сервер, который
разбирает файл, проверяет типы, доказывает завершаемость и разговаривает с
редактором по [LSP](https://microsoft.github.io/language-server-protocol/).

Клиента (расширения, плагина) тут нет намеренно: и VS Code, и Neovim умеют
запускать сторонний LSP-сервер тремя строчками настройки, а расширение —
это ещё один пакет, который придётся выпускать и обновлять отдельно от языка.

## Что сервер умеет

| Умеет | Как это выглядит |
| --- | --- |
| **Диагностика на лету** | Та же, что у `flang check`: разбор, типы, завершаемость, разбор суждений, законы морфизмов и функторов, проверки процессов и надзора. Тем же кодом (`FLANG_TYPE`, `FLANG_NOT_TOTAL`, `FLANG_MATCH_NOT_EXHAUSTIVE`, `FLANG_UNKNOWN_PROCESS`, …) и тем же текстом. |
| **Дополнение** | Ключевые слова (обе поверхности языка, прямо из таблицы лексера), имена функций и типов модуля, имена из импортированных модулей, поля записей после точки, варианты суммы после `случай`. |
| **Сигнатура при наведении** | Что принимает, что возвращает, доказано ли завершение. Для процесса, надзора, морфизма, записи и суммы — их объявление. |
| **Переход к объявлению** | Функция, тип, морфизм, процесс, надзор, прогон — в том числе в импортированном модуле. |

Чего не умеет — и почему:

- **Переименование, правки, форматирование.** Их нет и не обещано: это была бы
  вторая реализация языка рядом с первой.
- **Дополнение по типу произвольного выражения.** Поля предлагаются по типу
  параметра функции, в теле которой стоит курсор; для более сложного выражения
  предлагаются поля всех записей, и каждое подписано своим типом. Причина: тип
  выражения выводится только по разобранной программе, а дополняют как раз
  тогда, когда строка ещё не дописана.
- **Диагностика без места.** Если у диагностики нет ни строки, ни файла (так
  бывает у сообщений вида «тип объявлен в двух модулях: A и B» — они называют
  файлы словами), сервер отправляет её в журнал редактора, а не подчёркивает
  наугад первую строку открытого файла.
- **Имена в файле, который ни разу не разобрался.** Пока текст не разобрался,
  сервер дополняет именами из последнего удачного разбора — а если удачного не
  было ни разу (файл открыли уже сломанным), остаются одни ключевые слова.
  Диагностика при этом всегда от текущего текста, не от последнего удачного.

Диагностика импортированного модуля показывается **в его собственном буфере**,
а не в открытом. Ради этого имя файла появилось в самом языке — в местах,
которые проставляет связывание (`stampFile` в `flang/src/link.mjs`), — а не в
сервере: место рождается при разборе, и восстанавливать его догадками в сервере
значило бы однажды догадаться неправильно.

Проставляется имя по просьбе (`attributeFiles`), и просит его только тот, кто
показывает диагностику человеку. Печать AST от этого не меняется, и не должна:
у языка две реализации связывания — на JS и на самом flang, — а тест
самораскрутки сверяет их печать побайтово. Поэтому `flang ast` и `flang check`
имени файла в JSON не выводят: AST описывает программу, а не то, из каких
файлов её собрали.

## Запуск

Сервер ставится вместе с пакетом и работает по stdio:

```bash
npm i -g @digitable-lol/flang
flang-lsp --stdio
```

Из репозитория без установки — `node flang/bin/flang-lsp.mjs --stdio`.

Вручную его запускать незачем: он молча ждёт сообщений протокола. Запускает его
редактор.

## VS Code

Расширения в Marketplace нет, но клиент к готовому серверу — это несколько
строк. Заведите папку расширения (например `~/.vscode/extensions/flang-lsp/`) с
двумя файлами.

`package.json`:

```json
{
  "name": "flang-lsp",
  "version": "0.1.0",
  "engines": { "vscode": "^1.75.0" },
  "activationEvents": ["onLanguage:flang"],
  "main": "./extension.js",
  "contributes": {
    "languages": [
      { "id": "flang", "extensions": [".flang", ".fl"], "configuration": "./language-configuration.json" }
    ]
  },
  "dependencies": { "vscode-languageclient": "^9.0.0" }
}
```

`extension.js`:

```js
const { LanguageClient, TransportKind } = require("vscode-languageclient/node")

let client

exports.activate = () => {
  client = new LanguageClient(
    "flang",
    "flang",
    { command: "flang-lsp", args: ["--stdio"], transport: TransportKind.stdio },
    { documentSelector: [{ scheme: "file", language: "flang" }] },
  )
  client.start()
}

exports.deactivate = () => client?.stop()
```

Дальше `npm i` в папке расширения и перезапуск VS Code. Если `flang-lsp` не в
`PATH`, пропишите в `command` полный путь до `flang/bin/flang-lsp.mjs` и
`"node"` первым аргументом.

`language-configuration.json` можно взять любой минимальный — комментарий в
flang такой же, как в FTS (`//` и `/* */`).

## Neovim (0.11 и новее)

Достаточно `vim.lsp.config` и одной строки о том, что `.flang` — это `flang`:

```lua
vim.filetype.add({ extension = { flang = "flang", fl = "flang" } })

vim.lsp.config.flang = {
  cmd = { "flang-lsp", "--stdio" },
  filetypes = { "flang" },
  -- Корень проекта: рядом с package.json или .git; при отсутствии — каталог файла.
  root_markers = { "package.json", ".git" },
}
vim.lsp.enable("flang")
```

На Neovim 0.10 и старше — тот же сервер, но через `vim.lsp.start`:

```lua
vim.filetype.add({ extension = { flang = "flang", fl = "flang" } })

vim.api.nvim_create_autocmd("FileType", {
  pattern = "flang",
  callback = function(событие)
    vim.lsp.start({
      name = "flang",
      cmd = { "flang-lsp", "--stdio" },
      root_dir = vim.fs.dirname(vim.fs.find({ "package.json", ".git" }, { upward = true })[1])
        or vim.fn.fnamemodify(vim.api.nvim_buf_get_name(событие.buf), ":h"),
    })
  end,
})
```

Дополнение вызывается `<C-x><C-o>` (или `vim.lsp.completion.enable` на 0.11),
наведение — `K`, переход к объявлению — `gd`.

## Проверка, что всё живо

```bash
node flang/bin/flang-lsp.mjs --help     # сервер на месте
node --test flang/test/lsp.test.mjs     # разговор с настоящим процессом
```

Тесты запускают сервер отдельным процессом и говорят с ним рамками
`Content-Length`, а не зовут его функции: половина того, что ломается в
языковом сервере, ломается именно в транспорте.
