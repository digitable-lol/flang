# flang в Vim и Neovim

Подсветка `.flang` и языковой сервер. Ставится одной строкой; проверяется
прогоном, а не на глаз.

```
editors/vim/
  syntax/flang.vim      правила подсветки — НАПЕЧАТАНЫ, не написаны
  ftdetect/flang.vim    .flang → тип файла flang
  ftplugin/flang.vim    отступ, комментарии, ёлочки парой
  autoload/flang.vim    поиск языкового сервера — одна реализация на оба редактора
  plugin/flang.vim      Vim 8/9: сервер через vim-lsp
  plugin/flang.lua      Neovim: сервер через встроенный vim.lsp
  lua/flang/init.lua    то же, если хочется звать руками
  checks/               прогоны: настоящий редактор, без окна и человека
```

## Установка

| Менеджер | Строка |
| --- | --- |
| **lazy.nvim** | см. ниже — подкаталога репозитория он не умеет |
| **vim-plug** | `Plug 'digitable-lol/flang', { 'rtp': 'editors/vim' }` |
| **packer.nvim** | `use { 'digitable-lol/flang', rtp = 'editors/vim' }` |
| **руками** | `git clone https://github.com/digitable-lol/flang` и `set runtimepath^=/путь/к/flang/editors/vim` |

Подкаталог нужен потому, что плагин живёт ВНУТРИ репозитория языка: отдельный
репозиторий пришлось бы выпускать и обновлять в такт с языком, а расходятся
такие пары молча.

lazy.nvim ключа `rtp` не имеет (проверено по `lua/lazy/types.lua`), поэтому
каталог добавляется руками — и файлы `ftdetect` читаются явно, иначе они
опоздают к открытию первого буфера:

```lua
{
  "digitable-lol/flang",
  config = function(plugin)
    vim.opt.runtimepath:prepend(plugin.dir .. "/editors/vim")
    vim.cmd("runtime! ftdetect/*.vim")
    require("flang").setup()
  end,
}
```

### Языковой сервер ставится отдельно

Плагин сервер не несёт — он его ИЩЕТ. Сам сервер приезжает с пакетом:

```bash
npm install -g @digitable-lol/flang     # даёт flang-lsp в PATH
```

Ищется он в четырёх местах, по порядку:

1. `flang-lsp` в `PATH` — пакет npm, поставленный глобально;
2. `node_modules/.bin/flang-lsp` — тот же пакет в этом проекте;
3. `flang-lsp` рядом с самим редактором — сборка «всё в одном каталоге»;
4. `flang/bin/flang-lsp.mjs` в дереве языка (вверх от открытого файла) — для
   работы над самим языком.

Не нашлось — редактор говорит об этом строкой, перечисляет все четыре места и
напоминает, что подсветка работает и без сервера. Молчать здесь нельзя:
редактор без подсказок выглядит точно так же, как редактор со сломанным сервером.

### Почему двоичного `flang lsp` в этом списке нет

У двоичного `flang` (Homebrew, asdf) подкоманда `lsp` есть, и на закрытом вводе
она отвечает правильно. **Редактору она не годится: пока стандартный ввод
открыт, сервер не присылает ни одного байта.** Померено `checks/stream.sh`:

```
двоичный flang lsp: при открытом вводе 0 байт, после закрытия 334 байт
flang-lsp на Node:  при открытом вводе 334 байт, после закрытия 334 байт
```

Редактор ввод не закрывает никогда, поэтому двоичный сервер выглядел бы просто
висящим. Взять его всё равно можно — `let g:flang_dvoichnyy_lsp = 1`, — но по
умолчанию он не берётся: молчащий сервер неотличим от сломанного.

Когда двоичный научится отвечать на лету, `scripts/lsp-check.flang` скажет
об этом строкой, и порядок поиска можно будет переставить. Тогда Node для
редактора станет не нужен вовсе.

### Клиент для Vim 8/9 — vim-lsp, и вот почему именно он

У Vim своего клиента LSP нет, ставится сторонний. Выбран
[vim-lsp](https://github.com/prabirshrestha/vim-lsp) по одному доводу — чем он
платит:

- **coc.nvim** требует Node. Вся затея в том, чтобы редактору Node не был нужен;
  клиент, тянущий его сам, сводит её на нет.
- **yegappan/lsp** хорош, но требует Vim 9.0 — то есть отрезает весь Vim 8, а
  он и есть тот случай, ради которого этот файл написан.
- **vim-lsp** — чистый VimScript, Vim 8.0.1453 и новее, внешних зависимостей
  ноль (кроме `async.vim` того же автора).

```vim
Plug 'prabirshrestha/async.vim'
Plug 'prabirshrestha/vim-lsp'
Plug 'digitable-lol/flang', { 'rtp': 'editors/vim' }
```

Регистрация происходит сама. В Neovim `plugin/flang.vim` не работает вовсе —
там встроенный `vim.lsp`, и два клиента на один буфер дали бы две одинаковые
диагностики на каждую строку.

Подсказки: дополнение `<C-x><C-o>`, наведение `K`, переход к объявлению `gd`.

## Подсветка

**Правила напечатаны из таблицы ключевых слов языка, а не написаны руками.**
Список слов, набранный отдельно, — это второе описание языка; оно разойдётся с
первым в тот день, когда в язык добавят слово, и никто не заметит.

```bash
flang io scripts/vim-highlighting.flang     # перепечатать editors/vim/syntax/flang.vim
```

Печатает `scripts/vim-highlighting.flang` — программа на самом flang. Слова берёт
из `«Куски таблицы»` (`flang/self/lexer.flang`) — той самой таблицы, которой
язык читает свои файлы. Сегодня в ней **149 понятий и 629 фраз**.

Печать разложена на четыре файла, и разложена не для красоты:

| Файл | Что делает |
| --- | --- |
| `scripts/language-words.flang` | таблица языка → список фраз |
| `scripts/vim-rules.flang` | список фраз → текст файла правил (чистые функции) |
| `scripts/vim-highlighting.flang` | план: записать этот текст в дерево |
| `scripts/vim-highlight-check.flang` | план: сверить дерево с этим текстом и спросить редакторы |

Текст правил считается ОДНИМ местом, поэтому «перепечатать забыли» не может
пройти незамеченным: проверка читает файл из дерева и сравнивает его с тем, что
печатается сейчас. Разошлось — код 1 и строка «перепечатайте».

### Красятся все четыре поверхности сразу

Файл может быть написан по-русски, по-английски, на эсперанто или иероглифами.
Правила красят слова всех четырёх, и это не удобство, а повторение того, что
делает язык: `keywordId` ищет фразу в ПЛОСКОЙ таблице, где поверхности лежат
вперемешку, — ключевым слово становится независимо от того, на какой поверхности
написан файл. Поверхность большинством голосов (`surfaceOfTokens`) язык считает
для другого: ею выбирается ЯЗЫК ДИАГНОСТИКИ, а не набор слов. Красить по
большинству значило бы завести правило, которого у языка нет.

### Пять видов, и все пять — виды токенов лексера

| Вид | Что это | К чему привязан |
| --- | --- | --- |
| `flangKeyword` | ключевое слово любой поверхности | `Keyword` |
| `flangName` | имя в ёлочках `«…»` | `Identifier` |
| `flangYolochki` | сами ёлочки | `Delimiter` |
| `flangString` | строка в кавычках | `String` |
| `flangNumber` | число | `Number` |
| `flangComment` | `//` и `/* */` | `Comment` |

**Имя в ёлочках — отдельный вид нарочно.** `«…»` — часть языка на всех четырёх
поверхностях, а не русская типографика: закавыченное имя ключевым словом стать
не может никогда. Красить его как ключевое слово значило бы сказать неправду о
языке.

Шестого вида нет. Имена без ёлочек, стрелки, скобки и отступы не красятся:
подсветка знает ровно то, что знает лексер, и придумывать сверх этого ей нельзя.

## Проверки

Всё проверяется НАСТОЯЩИМ редактором, запущенным без окна и человека. Прогоны
написаны на flang — оболочка появляется только там, где словаря поручений языка
не хватает (и там сказано, где именно).

```bash
flang io scripts/vim-highlight-check.flang     # подсветка
flang io scripts/lsp-check.flang     # языковой сервер
```

`vim-highlight-check.flang` печатает файл со всеми 629 фразами таблицы, открывает его
настоящим Vim и настоящим Neovim и требует, чтобы **каждая** покрасилась
ключевым словом целиком. Потом переводит четыре файла дерева в HTML командой
`:TOhtml` и считает раскрашенное по видам.

Проверка не косметическая. `syn keyword` умеет съесть слово МОЛЧА: он разбирает
хвост своей строки как ключи, и `contains` — настоящая фраза английской
поверхности — обрывает список, унося всё, что стояло после него. Ни ошибки, ни
предупреждения. Именно поэтому правила печатаются одним `syn match` с
перечислением, а не набором `syn keyword`; и именно поэтому у каждой фразы
спрашивают редактор.

`lsp-check.flang` меряет, отвечает ли сервер при открытом вводе, потом
открывает в Neovim заведомо неверный файл и ждёт диагностику, потом верный — и
проверяет переход к объявлению и наведение. Vim 8/9 через vim-lsp проверяется
тем же прогоном, если рядом положен сам vim-lsp:

```bash
git clone --depth 1 https://github.com/prabirshrestha/vim-lsp.git   ~/vimlsp/vim-lsp
git clone --depth 1 https://github.com/prabirshrestha/async.vim.git ~/vimlsp/async.vim
FLANG_VIM_LSP=~/vimlsp flang io scripts/lsp-check.flang
```

Нет переменной — проверка Vim 8/9 честно говорит «ПРОПУЩЕНА» и не красит прогон
в зелёный молча.
