# Расширение VS Code для `.flang`

Подсветка и языковой сервер `.flang`, `.fp`, `.фп` и `.фланг` в одном пакете.

В Marketplace его нет и никто туда его не выкладывал: здесь лежит готовый к
сборке пакет, который ставится локально одной командой. Как выложить, когда
это понадобится, сказано в конце.

## Что внутри

```
editors/vscode/
  package.json                    объявление расширения
  extension.js                    запуск языкового сервера
  language-configuration.json     комментарии, скобки, ёлочки
  syntaxes/flang.tmLanguage.json  правила подсветки — напечатаны, не написаны
  .vscodeignore                   чего не класть в собранный пакет
  .gitignore                      node_modules и собранный .vsix — не в дерево
  README.md                       этот файл
```

## Что оно даёт

| Что | Состояние |
| --- | --- |
| Подсветка `.flang`, `.fp`, `.фп`, `.фланг` | работает |
| Подсветка всех четырёх поверхностей записи | работает |
| Диагностика, дополнение, подпись при наведении, переход к объявлению | сервер отвечает только на закрытом вводе — в живом редакторе молчит |

Последней строкой сказано главное, и умолчать об этом нельзя: **пока стандартный
ввод открыт, языковой сервер не присылает ни байта**, а редактор ввод не
закрывает никогда. Подсветка работает независимо от сервера, а диагностику
сегодня даёт команда — `flang check путь/к/файлу.flang`, её удобно повесить
задачей в `.vscode/tasks.json`. Настройки запуска сервера в расширении есть и
верны; они понадобятся, когда сервер научится отвечать на лету.

## Поставить у себя

Собрать пакет и поставить:

```bash
cd editors/vscode
npm install
npx vsce package          # получится flang-0.1.0.vsix
code --install-extension flang-0.1.0.vsix
```

Без сборки, прямо из дерева языка, — положить (или связать ссылкой) этот
каталог в `~/.vscode/extensions/`:

```bash
ln -s "$PWD/editors/vscode" ~/.vscode/extensions/flang
```

и перезапустить VS Code. Подсветка заработает сразу; для сервера нужен ещё
`npm install` в этом каталоге.

## Настройки

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `flang.server.command` | `flang-lsp` | чем запускать сервер |
| `flang.server.args` | `["--stdio"]` | доводы запуска |
| `flang.server.enabled` | `true` | выключите, если нужна только подсветка |

Сервер ставится вместе с языком (`npm i -g @digitable-lol/flang`), поэтому по
умолчанию он просто берётся из `PATH`. Если языка в `PATH` нет, поставьте в
`flang.server.command` полный путь.

**Списка мест, где искать сервер, здесь нет нарочно.** Такой список — пять мест
по порядку, с объяснением, почему двоичный сервер сегодня не первый, — живёт в
`editors/vim/autoload/flang.vim`. Вторая копия разошлась бы с первой в первый же
день, и разошлась бы молча: человек видел бы «сервер не найден» в одном
редакторе и работающие подсказки в другом. Поэтому здесь одна команда, и её
можно поменять.

## Подсветка напечатана, а не написана

`syntaxes/flang.tmLanguage.json` **править руками нельзя** — правка пропадёт при
следующей перепечатке, и заметить пропажу будет некому.

Слова берутся из той самой таблицы, которой язык читает свои файлы
(`«Куски таблицы»` в `flang/self/lexer.flang`). Список ключевых слов, набранный
в файле подсветки отдельно, — это второе описание языка, и оно расходится с
первым в тот день, когда в язык добавят слово.

```bash
flang io scripts/vscode-highlighting.flang     # перепечатать
flang io scripts/vscode-highlight-check.flang  # проверить, что не отстало
```

Проверка отвечает на два вопроса: та ли грамматика лежит в дереве, что
печатается из таблицы сейчас, и названы ли в `package.json` три расширения
имени файла, которые эта проверка знает (`.фланг` в её список ещё не вписан —
см. `docs/adr/0018-file-extensions-are-one-list.md`). Отстала грамматика — отказ `FLANG_VSCODE_USTARELA`; пропало
расширение — `FLANG_VSCODE_RASSHIRENIE`.

Видов подсветки ровно пять, по одному на вид токена языка: ключевое слово, имя
в ёлочках, строка, число, комментарий. Шестого нет — подсветка не имеет права
знать о языке больше, чем знает сам язык.

Красятся все четыре поверхности записи сразу — русская, английская, эсперанто и
китайская. Так делает сам язык: ключевым слово у него становится по плоской
таблице, где поверхности лежат вперемешку.

## Почему здесь есть JavaScript

В этом дереве на JavaScript ничего нового не пишут. `extension.js` — исключение,
и оно не про удобство: точка входа расширения VS Code — модуль, который редактор
загружает в свой процесс Node, и другого способа подключиться у него нет.

Плата названа и удерживается числом. В `editors/vscode/extension.js` — 46
строк, из них **19 строк кода** и 22 строки объяснения, зачем они здесь. Ни
одна из девятнадцати ничего не знает о языке: разбор, типы, завершаемость,
подсказки — всё это делает сервер, написанный на самом flang, а подсветку даёт
напечатанный файл. На JavaScript здесь только запуск сервера и передача ему
слов протокола.

## Выложить в Marketplace

Расширение к этому готово, но не выложено: у публикации есть владелец и
издательское имя, и заводить их за него нельзя.

1. Завести издателя (`publisher`) в [Visual Studio Marketplace](https://marketplace.visualstudio.com/manage)
   и получить токен доступа в Azure DevOps.
   В `package.json` уже стоит `"publisher": "digitable-lol"` — если имя издателя
   выйдет другим, поправьте эту строку.
2. Выложить:

```bash
cd editors/vscode
npx vsce publish            # спросит токен
```

Что `vsce` скажет при сборке и почему это не беды:

- **`LICENSE … not found`** — лицензия у языка одна и лежит в корне дерева
  (`LICENSE`, BSD-2-Clause). Второй копии здесь заводить не стали; перед
  публикацией её можно скопировать сюда, и предупреждение уйдёт.
- **`This extension consists of … files`** (на 24 августа 2026 их 322, и почти
  все — не наши) — это `vscode-languageclient`, библиотека клиента протокола.
  Убрать её можно только сборщиком, а сборщик — ещё один пакет на JavaScript;
  сегодня это дороже, чем размер пакета в 470 КБ.
