# flang for VS Code

**[Documentation](https://digitable-lol.github.io/flang/en/editor.html)** ·
**[Документация](https://digitable-lol.github.io/flang/editor.html)**

Syntax highlighting and a language-server client for flang files (`.flang`, `.fp`, `.фп`, `.фланг`). The English documentation is behind the first link above; the text below is in Russian.

Подсветка и клиент языкового сервера для файлов `.flang`, `.fp`, `.фп` и
`.фланг`. Расширение лежит в дереве языка (`editors/vscode/`), собирается и
ставится локально; в Marketplace не выложено.

## Что внутри

```
editors/vscode/
  package.json                    объявление расширения: язык, грамматика, настройки
  extension.js                    запуск языкового сервера
  language-configuration.json     комментарии, скобки, ёлочки парой
  syntaxes/flang.tmLanguage.json  правила подсветки — напечатаны из таблицы языка
  .vscodeignore                   что не класть в собранный пакет
  .gitignore                      node_modules и собранный .vsix — не в дерево
  README.md                       этот файл; Marketplace показывает его описанием
```

## Что даёт

| Что | Состояние |
| --- | --- |
| Подсветка `.flang`, `.fp`, `.фп`, `.фланг` | работает |
| Подсветка всех четырёх поверхностей записи (русская, английская, эсперанто, китайская) | работает |
| Диагностика, дополнение, подпись при наведении, переход к объявлению | сервер отвечает только после закрытия ввода; в живом редакторе молчит |

Ограничение сервера: пока стандартный ввод открыт, `flang lsp` не присылает
ответов, а редактор ввод не закрывает. Подсветка от сервера не зависит.
Диагностику даёт команда `flang check путь/к/файлу.flang`; её можно повесить
задачей в `.vscode/tasks.json` с `"command": "flang check ${file}"`. Настройки
запуска сервера в расширении верны и понадобятся, когда сервер начнёт
отвечать на открытом вводе.

## Поставить

Собрать пакет и поставить:

```bash
cd editors/vscode
npm install
npm run package                        # vsce package → flang-0.1.0.vsix
code --install-extension flang-0.1.0.vsix
```

Имя и версия файла `.vsix` берутся из `package.json`.

Без сборки, из дерева языка — связать каталог ссылкой в
`~/.vscode/extensions/` и перезапустить VS Code:

```bash
ln -s "$PWD/editors/vscode" ~/.vscode/extensions/flang
```

Подсветка заработает сразу; для запуска сервера нужен ещё `npm install` в этом
каталоге (зависимость `vscode-languageclient`).

## Настройки

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `flang.server.command` | `flang-lsp` | чем запускать сервер |
| `flang.server.args` | `["--stdio"]` | доводы запуска |
| `flang.server.enabled` | `true` | выключить, если нужна только подсветка |

Отдельной команды `flang-lsp` в дереве языка нет — сервер зовётся как
`flang lsp`. Если в `PATH` нет и этой команды, поставьте в
`flang.server.command` команду `flang` или полный путь до неё, а в
`flang.server.args` — `["lsp", "--stdio"]`.

Списка мест, где искать сервер, в расширении нет: такой список один и живёт в
`editors/vim/autoload/flang.vim`; вторая копия расходилась бы с первой.

## Подсветка напечатана, а не написана

`syntaxes/flang.tmLanguage.json` руками не правится: правка пропадёт при
следующей перепечатке. Слова берутся из таблицы, которой язык читает свои файлы
(«Куски таблицы» в `flang/self/lexer.flang`), программой на flang:

```bash
flang io scripts/vscode-highlighting.flang     # перепечатать
flang io scripts/vscode-highlight-check.flang  # проверить, что не отстало
```

Проверка отвечает на два вопроса: та ли грамматика лежит в дереве, что
печатается из таблицы сейчас (отказ `FLANG_VSCODE_USTARELA`), и названы ли в
`package.json` расширения имени файла, которые проверка знает (отказ
`FLANG_VSCODE_RASSHIRENIE`). Проверка знает три расширения; `.фланг` в её
список не вписано — см. `docs/adr/0018-file-extensions-are-one-list.md`.

Видов подсветки пять, по одному на вид токена языка: ключевое слово, имя в
ёлочках, строка, число, комментарий. Красятся все четыре поверхности записи
сразу, потому что так устроена сама таблица: поверхности лежат в ней
вперемешку.

## Почему здесь JavaScript

Точка входа расширения VS Code — модуль, который редактор загружает в свой
процесс Node; другого способа подключиться нет. `extension.js` только читает
три настройки и запускает сервер; разбор, типы, завершаемость и подсказки
делает сервер, написанный на flang, а подсветку даёт напечатанный файл.

## Выложить в Marketplace

Не выложено: у публикации есть владелец и издательское имя, и заводить их за
него нельзя.

1. Завести издателя в [Visual Studio Marketplace](https://marketplace.visualstudio.com/manage)
   и получить токен доступа в Azure DevOps. В `package.json` стоит
   `"publisher": "digitable-lol"`; если имя издателя выйдет другим, поправить
   эту строку.
2. Выложить: `cd editors/vscode && npx vsce publish` (спросит токен).

`vsce` предупредит, что в каталоге нет файла лицензии: лицензия у языка одна и
лежит в корне дерева (`LICENSE`, BSD-2-Clause); перед публикацией её можно
скопировать сюда. Предупреждение о числе файлов в пакете — это библиотека
`vscode-languageclient`; убрать её можно только сборщиком, а сборщик — ещё
один пакет на JavaScript.
