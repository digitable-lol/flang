# Распределитель памяти как чистый автомат

`allocator.flang` — проверка утверждения, а не замена рантайма: **можно ли
написать malloc на flang и что про него возьмёт ядро.**

Приём тот же, что у `examples/driver/uart.flang`: куча — это ДАННЫЕ (список
свободных отрезков), запрос — событие, распределитель — чистая функция

```flang
тотальная функция «Шаг кучи»
  принимает куча: «Куча», запрос: «Запрос»
  возвращает «Отклик кучи»
```

Он не трогает память. Он ОТВЕЧАЕТ, что теперь считать занятым.

## Честная граница — она названа первой, а не в сноске

**Это НЕ замена malloc в напечатанном на C рантайме.** Тот зовётся раньше, чем
есть куча: рантайму нужна память до того, как появится первый `«Куча»`.
Отвечено здесь на другой вопрос — **выразим ли распределитель на flang и что
про него доказуемо**. Ответ на оба: да, и вот сколько.

## Что доказано — прогоном, а не обещанием

```
flang check examples/allocator/allocator.flang --proof
утверждений 90: доказано 82 (из них индукцией 3) (из них без теоремы 79), сетка 7, объявлено, не доказано 1
```

**Было 89 / 79 / 7 / 3 — до 26 августа 2026** (задача 0050). Разница вся в одном
месте: «Пройти свободные» стала принимать сам список свободных отрезков вместо
кучи, и оба её обещания доказались ИНДУКЦИЕЙ по свёртке. Разбор — ниже, в «Стене
свёртки».

Пять свойств, заказанных владельцем, — по одному:

| # | свойство | вердикт |
|---|---|---|
| 1 | **выданные отрезки не пересекаются** | доказано **равенством** («остаток начинается ровно там, где кончается выданное»); **неравенством — сетка**; на замкнутом следе двух выдач — доказано вычислением |
| 2 | **возвращённое не теряется** | доказано структурно («вместо взятого отрезка встаёт его остаток», «отрезок встаёт в список свободных»); **суммой длин — только на замкнутом следе**; `(д минус с) плюс с равно д` ядро не берёт |
| 3 | **выданный адрес лежит внутри кучи** | доказано на замкнутом следе (`(адрес плюс 64) не больше 4096`); **в общем виде — сетка**, нет монотонности сложения |
| 4 | **отказ честен** | **доказано целиком и в общем виде** — 5 обещаний, и в выдаче, и в возврате |
| 5 | **инвариант шага** | доказано на замкнутом следе трёх шагов; **в общем виде — не берётся**, но не из-за свёртки: см. ниже |

Полностью, без оговорок, взялось **свойство 4**. Свойства 1 и 2 взялись в
структурной записи (равенство терму), но не в арифметической. Свойства 3 и 5 —
только на замкнутом следе.

## Что взялось целиком: уровень шага

Все девять обещаний «Шага выдачи», все семь «Шага вставки», четыре из пяти
«Шага годности» — доказаны. Это и есть главный вывод по цене: **уровень шага
свёртки открыт полностью**, и распределитель, разложенный на шаги, доказуем
почти весь.

```
«ВЗЯТОЕ НЕ ОТБИРАЕТСЯ: уже взято — остаётся взятым»            — доказано
«ВЫДАЁТ ТОЛЬКО ИЗ ОТРЕЗКА: адрес выдачи есть начало отрезка»   — доказано
«НИЧЕГО НЕ ПОТЕРЯНО: вместо взятого отрезка встаёт его остаток» — доказано
«ПОРЯДОК: новый встаёт ровно перед этим отрезком»               — доказано
«ОТКАЗ ЧЕСТЕН: места нет — куча не изменилась»                  — доказано
```

## Что НЕ взялось — десять обещаний, и это замер

Каждое из десяти оставлено в файле нарочно и упирается в **названное**
отсутствующее правило ядра. Формы проверены отдельным пробным файлом, где они
стоят голыми, без распределителя вокруг.

### 1. Арифметики неравенств у ядра нет вовсе

```
«а не больше (а плюс б)» при а: нат, б: нат                — объявлено
«а не больше результат.«левое»», где поле равно а          — объявлено
«(результат плюс б) равен а» при теле «а минус б»          — объявлено
«если не (а меньше б) то ((в плюс б) не больше …) иначе да» — объявлено
```

Ни рефлексивности `не больше`, ни монотонности сложения, ни закона
`(а минус б) плюс б равно а`. Поэтому «выданное внутри кучи» и «ничего не
потеряно», записанные **неравенством или вычитанием**, остаются сеткой при
любой охране; записанные **равенством терму той же ветви** — доказываются все.

**Практический вывод для следующего:** границы отрезка пишите равенствами, а
не неравенствами. `результат.«остаток».«начало» равен (результат.«адрес» плюс
сколько)` — доказано; та же мысль как `(результат.«адрес» плюс сколько) не
больше результат.«остаток».«начало»` — сетка.

### 2. Тип `нат` на поле записи не удерживается

`нат плюс нат` даёт `число`:

```
FLANG_TYPE, строка 52: функция «Конец отрезка» объявлена как нат, а тело даёт число
```

Поэтому `«начало»` и `«длина»` отрезка объявлены как `число`, и
неотрицательности у них нет уже по типу. Обещание «конец не левее начала» на
таком отрезке не просто не доказано — оно **неверно** при отрицательной длине.
Отказ ядра здесь честен, и чинится он не записью обещания, а правилом
`нат плюс нат : нат`, которого в ядре нет.

### 3. Стена свёртки — её здесь НЕТ, и это перемерено 26 августа 2026

Здесь стояло: «Пройти свободные» обещает «просят столько же» и «свободных
отрезков остаётся столько же» — оба объявлены; постусловие самой свёртки наверх
не поднимается». **Второе неверно.** Подъём у ядра ЕСТЬ и работает в нынешнем
напечатанном семени — принцип свёртки, `flang/self/proof-initial.flang`:

```
P(И, пусто) ∧ (для любых а, п, э: P(а, п) ⟹ P(Т, п ++ [э]))  ⟹  P(свёртка L …, L)
```

Улика лежала в этом же файле: у «Пройти вставку» — тоже свёрточной функции —
постусловие стояло **«доказано индукцией»** и до всякой правки.

Разница между двумя проходами была ровно одна. «Пройти вставку» свёртывает
`свободные` — ГОЛЫЙ ДОВОД. «Пройти свободные» свёртывала `куча.«свободные»` — а
принцип читается только тогда, когда свёртка идёт по переменной индукции знак в
знак («Свёртка по тому имени»: разбираемое обязано быть узлом-именем с именем
параметра). Доступ к полю именем не является, и принципа не читалось вовсе.

Правка — в подписи, не в обещании: проход берёт сам список.

```
до:    принимает куча: «Куча», сколько: нат      свёртка куча.«свободные» …
после: принимает свободные: список «Отрезок», сколько: нат   свёртка свободные …

«просят столько же, сколько запросили»     объявлено → ДОКАЗАНО ИНДУКЦИЕЙ
«свободных отрезков остаётся столько же»   объявлено → ДОКАЗАНО ИНДУКЦИЕЙ
```

Витку понадобилось одно новое обещание «Шага выдачи» — БЕЗ охраны, о росте
собранного ровно на один какой бы из трёх ветвей шаг ни пошёл. Охранные
половины, стоявшие там раньше, витку не годятся: виток о ветвях шага не знает.
Оно дописано и доказано.

**Про свойство 5 оговорка остаётся, но причина у неё другая.** Универсального «из
годной кучи выходит годная» по-прежнему нет — но не потому, что годность
считается свёрткой, а потому, что «Годная куча» свёртывает `куча.«свободные»` из
довода-записи и при этом не обещает ничего вовсе, а «Шаг кучи» ветвится по
функции с телом-`разбор` (см. пункт 4 ниже).

### 4. Замкнутый счёт ломается на `разбор`

След из трёх шагов идёт через «Выдать» и «Вернуть кусок», а не через «Шаг кучи»,
и это не украшательство:

```
(«Годная куча» от («Выдать»   от («Свежая куча») и 64).«куча») равен да  — ДОКАЗАНО
(«Годная куча» от («Шаг кучи» от («Свежая куча») и …).«куча») равен да  — объявлено
```

Разница одна: «Шаг кучи» ветвится по «Это взятие», а у той тело — `разбор`.
**Свёртки замкнутому счёту не мешают, `разбор` мешает.** Связь следа с
автоматом держат два доказанных обещания самого «Шага кучи»: «взятие идёт в
выдачу» и «возврат идёт в возврат».

## Обещания здесь не пустые — проверено подделкой

Доказанность в отчёте стоит ровно столько, сколько стоит проверка. Две пробы,
обе прогоном:

```
тотальная функция «Три» возвращает число
  обеспечивает «три равно четырём» результат равен 4
  3
```

```
flang check small-lie.flang          → проверено, замечаний нет   (!)
flang check small-lie.flang --proof  → объявлено, не доказано
```

**Первая строка — предупреждение всем, кто читает отчёты `check`:**
`замечаний нет` про обещания не говорит НИЧЕГО, постусловия судит только
`--proof`. Вторая строка — то, ради чего проба ставилась: замкнутую цель ядро
считает по-настоящему, и ложную не «доказывает».

Третья проба — уже по самому файлу. В обещании «свободного стало ровно на
выданное меньше» число 4032 заменено на 4033, больше ничего:

```
было:  утверждений 89: доказано 79, сетка 7, объявлено, не доказано 3
стало: утверждений 89: доказано 68, сетка 7, объявлено, не доказано 14
```

**Сдвиг одного числа на единицу уронил одиннадцать доказанных.** Обещания следа
держат друг друга: цели, посчитанные от «Отклика первой выдачи», рушатся вместе
с ним. Числа 4032, 3968, 64 и 2 — посчитанные факты, а не украшение.

## Приёмы, которые дали прибавку 51 → 79

| приём | что сделал |
|---|---|
| охрана списана из тела дословно | вся семья «ОТКАЗ ЧЕСТЕН» и весь уровень шага |
| заключение — равенство терму той же ветви, а не неравенство | «НЕ ПЕРЕСЕКАЮТСЯ» и «НИЧЕГО НЕ ПОТЕРЯНО» |
| шаг свёртки вынесен из лямбды в обычную функцию | «Шаг выдачи», «Шаг вставки», «Шаг годности» — 20 доказанных |
| замкнутая цель | весь след из трёх шагов, 15 доказанных даром |
| охрана «равенство варианту» вместо охраны-вызова | «Шаг кучи»: сетка → доказано, обе ветви |

Последняя строка стоила одного пробного прогона и заслуживает отдельного слова:
охрана-вызов `если («Это взятие» от запрос) то …`, списанная из тела знак в
знак, **не взялась ни со скобками, ни без**. Взялась охрана
`если запрос равен (вариант «Взять» с сколько равным («Сколько просят» от запрос)) то …`.

## Чего здесь нет

**Слияния соседних свободных отрезков.** Возврат вставляет отрезок по порядку
начал и не сливает его с соседями, поэтому куча дробится. Это настоящий изъян
настоящего распределителя, и он здесь не спрятан: слияние — ещё один шаг
свёртки, доказуемый теми же приёмами, и его просто не написали.

**Живучести.** Доказано, что каждый шаг переводит кучу из состояния в
состояние. Не доказано, что распределитель когда-нибудь отдаст память тому, кто
ждёт, — это свойство бесконечной последовательности, а не одного шага.
