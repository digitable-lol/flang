# Контроллер MSI моста PCIe JH7110 — переписан на flang

Переписывание драйвера из работающего ядра. Проверялось одно утверждение:
перенос ядра ОС на язык с доказательствами упирается в объём, а не в возможность.

## Что переписано и откуда взято

| откуда | что |
|---|---|
| `sys/arch/riscv/starfive/jh7110_pcie_msi.c` | 490 строк — сам контроллер |
| `sys/arch/riscv/starfive/jh7110_pcievar.h` | 195 строк — типы и адреса регистров |

Плата — VisionFive 2 (StarFive JH7110), мост PLDA XpressRICH. В апстриме NetBSD
этого драйвера нет: путь INTx на этом чипе штормит и обработчики залипают,
поэтому в нашей ветке написан свой MSI-контроллер. Оригинал загружает систему до
PID 1 на живой плате.

Здесь — `msi.flang`, 442 строки, 25 функций, 95 обещаний.

**Границы.** В ядро это не собирается, на плате не пробовалось, заменять рабочий
драйвер им никто не предлагает. Написано ради доказательств; исходное дерево
NetBSD при этой работе только читалось.

## Приём: драйвер ничего не пишет, он отвечает, что записать

Тот же приём, что у `../uart.flang`. Каждая функция чистая: «состояние
контроллера и событие → новое состояние, список записей в регистры и список
разрядов, которые надо раздать».

```flang
тотальная функция «Занять вектор»
  принимает контроллер: «Состояние MSI», вектор: нат, безопасен: признак
  возвращает «Отклик MSI»
```

Записывает и зовёт обработчики хозяин на C. Его работа — цикл:

```c
отклик = razdat_preryvanie(состояние, RD4(sc, 0x194 /* PLDA_ISTATUS_MSI */));
for (i = 0; i < отклик.разрядов; i++) {
    /* сброс лежит ВНУТРИ разряда, переставить его после вызова нельзя */
    *(volatile uint32_t *)отклик.разряды[i].сброс.адрес =
                          отклик.разряды[i].сброс.значение;
    if (отклик.разряды[i].звать)
        вызвать_обработчик(отклик.разряды[i].вектор);
}
```

Порядок «сначала W1C, потом обработчик» здесь держится строением данных.
В оригинале его держит комментарий:

```c
/* Clear each vector bit BEFORE invoking its handler, so an edge that
   arrives while the handler runs re-sets the bit and is caught on the
   next iteration rather than being lost. */
WR4(sc, PLDA_ISTATUS_MSI, __BIT(v));	/* W1C first */
if (mh->mh_func != NULL) ... mh->mh_func(mh->mh_arg);
```

Здесь сброс — поле разряда. Переставить его местами нельзя: переставлять нечего,
это одно значение.

## Что заказывали доказать — и что вышло

| заказано | вердикт |
|---|---|
| 1. Номер вектора в пределах — их 32 | **доказано**, двумя половинами |
| 2. Дверной звонок пишется по своему адресу `0x190` и только по нему | **доказано** |
| 3. Разбор битовой маски не теряет векторов | **доказано на шаге**, на свёртке — нет |
| 4. Инвариант шага: из годного состояния выходит годное | **доказано** у раздачи; у занятия и освобождения — нет |
| 5. Отказ честен: на неизвестный вектор — названный отказ | **доказано**, шестью обещаниями |

### 1. Номер вектора в пределах

Оригинал: `if (vec >= JH7110_PCIE_NUM_MSI) return NULL;`

```
«JH7110_PCIE_NUM_MSI — тридцать два»                 ДОКАЗАНО
«ВЕКТОР МЕНЬШЕ ТРИДЦАТИ ДВУХ — СВОЙ»                 ДОКАЗАНО
«ВЕКТОР ОТ ТРИДЦАТИ ДВУХ И ВЫШЕ — ЧУЖОЙ»             ДОКАЗАНО
```

На железе эта граница даёт молчаливую порчу: `sc->sc_msi[32]` пишет за конец
массива в соседнее поле softc.

### 2. Дверной звонок — по своему адресу и только по нему

Адреса списаны из `jh7110_pcievar.h` дословно, шестнадцатеричные переведены в
десятичные (в языке шестнадцатеричных литералов нет), и каждый перевод доказан
замкнутой целью:

```
«PLDA_IMSI_ADDR — 0x190, оно же 400»                 ДОКАЗАНО
«PLDA_IMASK_LOCAL — 0x180, оно же 384»               ДОКАЗАНО
«PLDA_ISTATUS_LOCAL — 0x184, оно же 388»             ДОКАЗАНО
«PLDA_ISTATUS_MSI — 0x194, оно же 404»               ДОКАЗАНО
«PLDA_IMASK_INT_MSI — двадцать восьмой бит»          ДОКАЗАНО
«ЗВОНОК НЕ ПУТАЕТСЯ С ОСТАЛЬНЫМИ ТРЕМЯ»              ДОКАЗАНО
«ЗВОНОК ПИШЕТСЯ ПО СВОЕМУ АДРЕСУ И ТОЛЬКО ПО НЕМУ»   ДОКАЗАНО
«W1C ПИШЕТСЯ ПО PLDA_ISTATUS_MSI И ТОЛЬКО ПО НЕМУ»   ДОКАЗАНО
«МАСКА ПИШЕТСЯ ПО СВОЕМУ АДРЕСУ, А НЕ ПО ЗВОНКУ»     ДОКАЗАНО (занятие и освобождение)
```

Слово «только» несут два обещания разом: первое — равенство всего списка записей
терму (`результат.«записи» равен [ … ]`), то есть других записей в отклике нет
вовсе; второе — что регистр маски со звонком не совпадает, и это часть годности
состояния.

### 3. Разбор маски не теряет векторов

Оригинал перебирает 32 бита слова `PLDA_ISTATUS_MSI`. Побитовых операций в языке
нет вовсе, поэтому `msi & __BIT(v)` записан спуском по остаткам от двух, а
`1U << vec` — умножением. Спуск точный: слово целое и неотрицательное, значит
`(слово − остаток) / 2` делится нацело.

```
«ВЗВЕДЁННЫЙ БИТ ДАЁТ РОВНО ОДИН РАЗРЯД»              ДОКАЗАНО
«ВЗВЕДЁННЫЙ БИТ РАСТИТ СЧЁТ РОВНО НА ОДИН»           ДОКАЗАНО
«СБРОШЕННЫЙ БИТ РАЗРЯДА НЕ ДАЁТ»                     ДОКАЗАНО
«СБРОШЕННЫЙ БИТ СЧЁТА НЕ РАСТИТ»                     ДОКАЗАНО
«НЕ ТЕРЯЕТ ВЕКТОРОВ (ИНВАРИАНТ ЦИКЛА)»               ДОКАЗАНО, но обещание ПУСТОЕ — см. ниже
«НАЧАЛО РАЗДАЧИ УДОВЛЕТВОРЯЕТ ИНВАРИАНТУ»            ДОКАЗАНО
```

Четыре первых — и есть «сколько бит взведено, столько разрядов и выйдет», только
сказанное на одном шаге: взведённый бит прибавляет ровно один разряд и ровно
единицу к счёту, сброшенный не прибавляет ничего. Вместе с доказанным началом
раздачи это ровно та индукция, которую в интерактивном прувере пишут теоремой.
Ядро её за нас не складывает: постусловие самой свёртки наверх не поднимается —
названная граница приёма.

### 4. Инвариант шага

```
«ШАГ СОХРАНЯЕТ ГОДНОСТЬ ЦЕЛИКОМ: из годного состояния выходит годное»
   у «Раздать прерывание»       ДОКАЗАНО
   у «Занять вектор»            сетка
   у «Освободить вектор»        объявлено, не доказано
```

У раздачи взялось, потому что раздача состояния не меняет. У занятия и
освобождения не взялось: там годность упирается в две вещи, которых ядро не
умеет (длина после свёртки и граница маски неравенством).

Что от инварианта всё-таки доказано у занятия и освобождения:

```
«ОТКАЗ ЧЕСТЕН: на чужом векторе состояние не трогают»    ДОКАЗАНО
«ЗВОНОК ЗАНЯТИЕМ НЕ МЕНЯЕТСЯ: свой вектор»               ДОКАЗАНО
«АДРЕС МАСКИ ЗАНЯТИЕМ НЕ МЕНЯЕТСЯ: свой вектор»          ДОКАЗАНО
«ЗАНЯТИЕ ВЗВОДИТ БИТ ВЕКТОРА В МАСКЕ»                    ДОКАЗАНО
«ОСВОБОЖДЕНИЕ СБРАСЫВАЕТ БИТ ВЕКТОРА В МАСКЕ»            ДОКАЗАНО
«ДЛИНА РАСТЁТ РОВНО НА ОДИН» (шаг правки таблицы)        ДОКАЗАНО, обе ветви
```

Третье условие годности («регистр маски не совпал со звонком») сохраняется
доказанно; первые два — нет.

### 5. Отказ честен

Единственное место, где переписывание отступает от оригинала нарочно. В C
неизвестный вектор даёт `return NULL` — тишину, которую вызывающий волен не
заметить. Здесь отказ назван словами и лежит в отклике полем.

```
«ОТКАЗ ЧЕСТЕН: чужой вектор назван словами»              ДОКАЗАНО (занятие и освобождение)
«ОТКАЗ ЧЕСТЕН: на чужом векторе в железо не пишут»       ДОКАЗАНО (занятие и освобождение)
«ОТКАЗ ЧЕСТЕН: на чужом векторе состояние не трогают»    ДОКАЗАНО (занятие и освобождение)
«СВОЙ ВЕКТОР ОТКАЗА НЕ ДАЁТ»                             ДОКАЗАНО (занятие и освобождение)
```

## Проверка на пустоту: одно доказанное обещание оказалось украшением

Доказанное обещание может ничего не проверять. Проверка — подменить тело
заглушкой той же подписи и снять отчёт заново; что осталось доказанным, то пусто.
Заглушек надо две, нулевая и ненулевая.

**«Шаг раздачи», 13 обещаний, две заглушки** (`…«взведено» равным 0 и «разряды»
равным пустой список` и `…«взведено» равным 1 и «разряды» равным [один разряд]`):

| обещание | нулевая | ненулевая |
|---|---|---|
| «ВЗВЕДЁННЫЙ БИТ ДАЁТ РОВНО ОДИН РАЗРЯД» | отпало | отпало |
| «ВЗВЕДЁННЫЙ БИТ РАСТИТ СЧЁТ РОВНО НА ОДИН» | отпало | отпало |
| «СБРОШЕННЫЙ БИТ РАЗРЯДА НЕ ДАЁТ» | отпало | отпало |
| «СБРОШЕННЫЙ БИТ СЧЁТА НЕ РАСТИТ» | отпало | отпало |
| «W1C ПИШЕТСЯ ПО PLDA_ISTATUS_MSI И ТОЛЬКО ПО НЕМУ» | отпало | отпало |
| остальные восемь | отпали | отпали |
| **«НЕ ТЕРЯЕТ ВЕКТОРОВ (ИНВАРИАНТ ЦИКЛА)»** | **пережило** | **пережило** |

Двенадцать из тринадцати содержательны. Тринадцатое — украшение, и это надо
сказать вслух: «если до шага разрядов было столько же, сколько взведённых, то и
после» верно при любом теле, лишь бы само оно было сбалансировано. Заглушка
`0 разрядов / счёт 0` его удовлетворяет, заглушка `1 разряд / счёт 1` тоже.

Инвариант не пуст как мысль, но пуст как запись. Содержание несут четыре
обещания над ним — те, что пришпиливают прирост к конкретному числу и падают на
обеих заглушках. Оставлен и назван: вычеркнуть его — значит потерять
формулировку, ради которой всё писалось.

**«Запустить контроллер», две заглушки** (отклик с нулевым состоянием и пустым
списком записей; отклик с единицами в полях и двумя записями по адресу 1):

| обещание | нулевая | ненулевая |
|---|---|---|
| **«ЗВОНОК ПИШЕТСЯ ПО СВОЕМУ АДРЕСУ И ТОЛЬКО ПО НЕМУ»** | **отпало** | **отпало** |
| «ЗАПУСК ЗАПОМИНАЕТ ЗВОНОК» | отпало | отпало |
| «ЗАПУСК ПИШЕТ РОВНО ДВЕ ЗАПИСИ» | отпало | пережило |
| «ЗАПУСК ОБНУЛЯЕТ МАСКУ ВЕКТОРОВ» | пережило | отпало |
| «ЗАПУСК ОБНУЛЯЕТ ТАБЛИЦУ ОБРАБОТЧИКОВ» | отпало | пережило |
| «ЗАПУСК ВКЛЮЧАЕТ MSI НА КОНТРОЛЛЕРЕ» | отпало | пережило |
| «ЗАПУСК СТАВИТ ТРИДЦАТЬ ДВА ВЕКТОРА» | отпало | пережило |
| «ЗАПУСК РАЗРЯДОВ НЕ РАЗДАЁТ» | пережило | пережило |
| «ЗАПУСК ОТКАЗА НЕ ДАЁТ» | пережило | пережило |

Главное обещание про звонок содержательно: обе заглушки его роняют. Остальные
ведут себя ровно так, как описано в справочнике: каждое пусто при подходящей
заглушке и содержательно при зеркальной, а держит функцию пара.

Две последние строки — оговорка про сами заглушки, не вывод про обещания: у обеих
подмен разряды пусты и отказ пуст, поэтому эти два обещания никакая из них
проверить не могла. Нужна третья заглушка, с непустым списком разрядов и непустым
отказом; она не снималась.

**«Вектор в пределах», заглушки `да` и `нет`** — тот самый случай, когда пуста
каждая половина поодиночке, а прижимает пара:

| обещание | заглушка `да` | заглушка `нет` |
|---|---|---|
| «ВЕКТОР МЕНЬШЕ ТРИДЦАТИ ДВУХ — СВОЙ» | **пережило** | отпало |
| «ВЕКТОР ОТ ТРИДЦАТИ ДВУХ И ВЫШЕ — ЧУЖОЙ» | отпало | **пережило** |

Ни одна заглушка не проходит обе. Границу держат обе вместе, и в этом виде она
содержательна.

## Вынесенный предикат: замер до и после

Проверка младшего бита — `(ход.«слово» остаток от 2) равен 1` — стояла в
«Шаге раздачи» тринадцать раз: двенадцать охран обещаний и охрана самого тела.
Вынесена в отдельную функцию:

```flang
тотальная функция «Младший бит взведён»
  принимает слово: число
  возвращает признак
  обеспечивает «младший бит — это остаток от двух» результат равен ((слово остаток от 2) равен 1)
  обеспечивает «это тот же нулевой разряд, что читает Бит взведён» результат равен («Бит взведён» от слово и 0)
  (слово остаток от 2) равен 1
```

Вопрос был не про красоту, а про цену: ядро сводит цель с телом, и охрана,
ставшая вызовом чужой функции, могла разорвать сведение. Снята поимённая
ведомость вердиктов до и после, 93 строки против 95:

```
$ diff до.вердикты после.вердикты
> постусловие «младший бит — это остаток от двух» — доказано
> постусловие «это тот же нулевой разряд, что читает Бит взведён» — сетка
```

Других расхождений нет: все 93 прежних обещания сохранили вердикт до единого.
Вынос охраны в вызов стоил ноль доказательств. Второе обещание нового предиката —
сетка, и это ожидаемо: справа рекурсивная функция, ядро проверяет равенство на
конечном наборе значений.

## Чего доказать не вышло — девять обещаний, и вот почему

```
утверждений 95: доказано 86, сетка 4, объявлено, не доказано 5
```

**Пять — про `элемент N в списке`.** Переписки «N-й элемент списка» у ядра нет
вовсе; та же дыра названа в `../README.md` у драйвера UART.

```
«ПЕРВАЯ ЗАПИСЬ ИДЁТ ПО АДРЕСУ 400 — PLDA_IMSI_ADDR»        объявлено
«ЗВОНОК ПЕРЕПИСЫВАЕТСЯ САМИМ СОБОЙ: перевзвод захвата»     объявлено
«ВТОРАЯ ЗАПИСЬ ИДЁТ ПО АДРЕСУ 384 — PLDA_IMASK_LOCAL»      объявлено
«ЗАПИСАННОЕ В РЕГИСТР И ЕСТЬ НОВАЯ МАСКА»                  сетка
«БЕЗ ОБРАБОТЧИКА БИТ ВСЁ РАВНО СБРАСЫВАЕТСЯ, НО НЕ ЗОВЁТСЯ» сетка
```

Потери смысла тут почти нет: то же самое сказано целиком, равенством всего списка
записей, и это доказано («ЗВОНОК ПИШЕТСЯ ПО СВОЕМУ АДРЕСУ И ТОЛЬКО ПО НЕМУ», «W1C
ПИШЕТСЯ ПО PLDA_ISTATUS_MSI И ТОЛЬКО ПО НЕМУ»). Поштучные обещания оставлены
нарочно — чтобы дыра осталась видна.

**Одно — граница свёртки.**

```
«ТАБЛИЦА НЕ МЕНЯЕТ ДЛИНЫ» функции «Правка вектора»         объявлено
```

Шаг правки доказан целиком: обе ветви удлиняют накопитель ровно на один, номер
растёт на один, цель не меняется. Сложить 32 шага в «длина не изменилась» ядро не
умеет — постусловие свёрточной функции наверх не поднимается. Названная граница
приёма, не недосмотр записи.

**Два — годность после занятия и освобождения.** Оба упираются в то же самое:
годность требует «векторов ровно 32», а таблица пересобирается свёрткой (см.
выше), и «маска умещается в 32 разряда», а это неравенство над термом —
арифметики неравенств у ядра нет.

## Что взято, а что оставлено

Взято (сердце драйвера):

* разбор слова `PLDA_ISTATUS_MSI` и раздача по векторам — `jh7110_pcie_msi_dispatch()`;
* установка обработчика с проверкой границы и взведением бита в маске
  root-порта — `jh7110_pcie_msi_intr_establish()`;
* снятие обработчика со сбросом того же бита — ветвь MSI в
  `jh7110_pcie_intr_disestablish()`;
* запуск: чтение звонка, перевзвод захвата MSI, обнуление таблицы, снятие маски
  MSI на контроллере — `jh7110_pcie_msi_init()`;
* все адреса регистров и константы из `jh7110_pcievar.h`.

Оставлено (и почему):

* **`jh7110_pcie_msi_program()`** — программирование capability MSI самого
  устройства. Смещения там не литералы: их находит `pci_get_capability()` в
  конфигурационном пространстве во время работы. Переписывать это данными можно,
  но пришлось бы вместе с моделью конфигурационного пространства PCI — на срок не
  помещалось.
* **`jh7110_pcie_msi_find_run()` и `jh7110_pcie_msi_alloc_common()`** — поиск
  выровненного отрезка свободных векторов степени двойки. Законченная и вполне
  доказуемая часть; просто не влезла. Заявка честная: взята раздача, разбор
  маски, установка, снятие и запуск; распределение векторов не взято.
* `jh7110_pcie_intr_alloc()` — переговоры MSI/MSI-X/INTx и откат на INTx.
* `jh7110_pcie_msix_*` — в этом мосте MSI-X нет, все три функции отдают `ENODEV`.
* `mutex`, `kmem_alloc`, `KERNEL_LOCK`, отладочные `printf` — у них нет
  соответствия в чистой функции; это работа хозяина.

## Как читать `постоянным шагом` в отчёте

Из 25 функций 23 тотальны композицией, а две — «Вес вектора» и «Бит взведён» —
постоянным шагом, и на них ядро ставит сторожа в напечатанный код (2 места).
Причина в типах: `нат минус 1` даёт `число`, обратно в `нат` оно не втекает,
поэтому спуск идёт по `число`, а на IEEE-754 постоянный шаг не всегда меняет
величину. Цена названа в отчёте.

## Что вышло по числам

490 строк C — это 442 строки flang, из которых 86 обещаний из 95 доказаны, и
проверка занимает две секунды. Недоказанные девять упираются не в железо и не в
драйвер, а в три названные дыры ядра доказательств: `элемент N в списке`, подъём
постусловия через свёртку и арифметика неравенств.

Железо во всём этом занимает шесть строк C у хозяина — те, что кладут
`отклик.записи` по адресам. Остальное — логика состояний, и она доказуема.
