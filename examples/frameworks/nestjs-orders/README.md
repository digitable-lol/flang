# flang + NestJS: REST-служба заказов

Сервер на NestJS, решение — на flang. Хозяин (Nest) принимает HTTP-соединение и
отдаёт ответ; маршрут, коды и проверку обязательных полей считает
доказанно-тотальное ядро `orders_api.js`.

```
core/orders-api.flang           решение: метод+путь+строка запроса → код+тело
printed/orders_api.js          то же ядро, напечатанное в JS (zero-dep, ESM)
printed/flang_cli.js           прогонщик ядра для CLI-проверки границы входа
src/orders.controller.ts        хозяин: принять запрос, позвать ядро, отдать ответ
src/app.module.ts               модуль Nest
src/main.ts                     подъём сервера
```

## Граница

На flang написано то, что **решает**: разбор строки запроса в параметры,
проверка обязательных полей, маршрутизация по методу и пути, коды ответа
(201/200/400/404/405). Все функции тотальны — служба доказано завершается на
любом входе, и кривой запрос её не роняет.

Хозяину (Nest) остаётся то, что **ждёт и держит соединение**: сокет, разбор
HTTP, статус-код в ответе. Контроллер приводит вход к тому виду, что понимает
ядро (см. ниже), и вызывает одну функцию — `Обработать запрос`.

## Стык и две тонкости приведения

`src/orders.controller.ts` импортирует напечатанный модуль напрямую:

```ts
import { obrabotatZapros, kodOtveta, teloOtveta } from '../printed/orders_api.js'
```

`Обработать запрос` → `obrabotatZapros(метод, путь, хвост)`. Две вещи хозяин
приводит сам, и обе видны в контроллере:

- **путь** express отдаёт percent-encoded (`/заказы` приходит как `/%D0%B7…`), а
  ядро сверяет с русским `/заказы` — поэтому путь раскодируем через
  `decodeURIComponent`;
- **строку запроса** собираем из уже разобранного express-ом `req.query`
  (ключи и значения там уже декодированы) в вид `товар=ч-1&количество=2`.

Ядро тотально и на кривом входе, поэтому URIError на битом пути хозяин гасит и
отдаёт путь как есть — ответом будет 404, а не падение.

## Живой прогон (проверено)

Сервер поднят, шесть запросов, ответы ядра:

```
POST /заказы?товар=ч-1&количество=2  -> 201  заказ принят: ч-1
POST /заказы?количество=2            -> 400  не хватает полей: товар
GET  /заказы?номер=77                -> 200  заказ 77
GET  /заказы?товар=ч-1               -> 400  не хватает полей: номер
DELETE /заказы                       -> 405  метод не поддержан
GET  /склад                          -> 404  нет такого пути
```

Известный путь с неверным методом — 405, неизвестный путь — 404: это разные
ответы, и оба решает ядро.

## Проверка без сервера

Ядро zero-dep, Nest поднимать не нужно:

```
node --input-type=module -e 'import("./printed/orders_api.js").then(m=>{
  const o = m.obrabotatZapros("POST","/заказы","товар=ч-1&количество=2");
  console.log(m.kodOtveta(o), m.teloOtveta(o)); // 201 заказ принят: ч-1
})'
```

## Запуск фреймворком

```
npm install
npm run typecheck   # tsc --noEmit
npm run build       # tsc -> dist/
PORT=3000 npm start # поднять сервер
```

## Переиздать ядро

Из корня дерева flang (библиотечные модули `Strings`/`Dictionary`/`String sets`
берутся из дерева):

```
bootstrap/flang emit examples/frameworks/nestjs-orders/core/orders-api.flang \
  --target js --out examples/frameworks/nestjs-orders/printed
```

Файлы в `printed/` печатает компилятор — руками их не правят, правят
`core/orders-api.flang` и печатают заново.
