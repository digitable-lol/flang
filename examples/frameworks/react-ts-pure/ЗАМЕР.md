# Замер: react-ts-pure против react-invoice (и vue-roman)

Снято 8 сентября 2026 на одной машине (Linux, node v26.7.0, npm 11.19.0,
Google Chrome 151.0.7922.108 без интерфейса), сборки `vite build` каждого
примера, отданные статическим сервером с `127.0.0.1` без сети и без
искусственного замедления процессора. Задача — `tasks/10006-*.md`.

Версии: react 18.3.1, react-dom 18.3.1, vite 6.4.3, typescript 5.7.3,
@vitejs/plugin-react 4.7.0, vue 3.5.42; измерители — web-vitals 6.2.1
(внедрён в страницу через puppeteer 25.10.0), lighthouse 13.4.1; компилятор
flang 0.7.14 (`bootstrap/flang`, собран `make -s -C bootstrap`).

Что считает компилятор в `react-ts-pure` и никто не считал в `react-invoice`:
границы количества (`Зажать` — доказанно одна из трёх точек), сохранение
числа товаров и позиций любым действием редьюсера (индукция по типу
«Действие»), запись рублей (запятая и знак рубля в каждой строке — на сетке
примеров), данные каталога и начальные количества (пример прогоняется при
каждой проверке). В `react-invoice` эти четыре вещи — `Math.max`, `useState`,
`toLocaleString`, литерал `tovary` — живут в TSX и проверяются только глазами.

весила сотни байт: в гзипованном бандле React 18 с react-dom занимает
≈ 45 КБ из 50, ядро flang — единицы килобайт. Бандл — не то место, где эта
граница видна.

## Вывод

- **Web Vitals не различают примеры.** FCP/LCP ≈ 80 мс у обоих React-примеров
  локально и ≈ 1 500 мс под эмуляцией мобильного у Lighthouse (оценка 100 и
  там и там); CLS 0; INP 16 мс у обоих; TBT 0. Разница внутри шума прогонов
  (разброс FCP 68–92 мс). Это ожидаемо: предметная логика в обоих примерах —
  доли миллисекунды, а всё время страницы — это React и react-dom. vue-roman
  быстрее (FCP ≈ 60 мс, LCP ≈ 1 050 мс у Lighthouse) только потому, что Vue
  вдвое легче React.
- **Польза переноса — не в скорости, а в том, что стало проверяемо.** Из 15
  строк логики в TSX ни одну не проверял ни `tsc`, ни тесты; в `react-ts-pure`
  вся логика — 23 тотальные функции, 16 обещаний (10 доказаны, 6 на сетке),
  48 исполняемых примеров, и ноль строк, которые нужно читать глазами, чтобы
  понять, что делает страница. Признак измеримый: `npm run storozh` → код 0,
  «логики 0 строк: файлов .tsx 4, строк кода 36»; на `react-invoice/src` тот же
  сторож → код 1, 5 строк названы.
- **Цена**: +4 % к бандлу и 358 строк flang против 271 (в них — запись
  рублей с разрядами, которую раньше делал `toLocaleString` браузера).

## Что НЕ измерено

- Полевые данные (реальные пользователи, сеть, слабые устройства) — нет.
- Замедление процессора вне Lighthouse не включалось; локальные значения
  (80 мс) — потолок скорости машины, а не пользователя.
- INP снят по шести кликам / четырём вводам; при сотнях взаимодействий или на
  тысячах позиций различие может появиться — здесь оно не проверялось.
- Точная стоимость самой логики (микросекунды на `shag`/`itogi`) не снималась:
  на масштабе Web Vitals она нулевая, отдельного микробенчмарка не делалось.

## Как повторить

```
make -s -C bootstrap
for e in react-invoice react-ts-pure vue-roman; do (cd examples/frameworks/$e && npm install && npm run build); done
# статический сервер на dist/ каждого; затем web-vitals через puppeteer по сценарию выше
# и lighthouse --only-categories=performance трижды; медианы.
npm run storozh                     # в react-ts-pure: логики 0 строк
```

Скрипты измерения (serve.mjs, vitals.mjs, lh.mjs) лежали во временном каталоге
и в дерево не положены — JavaScript в дереве убывает по правилу проекта; их
устройство описано выше словами, достаточными для повторения.
