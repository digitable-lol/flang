# Стык: flang считает решение, хозяин на C исполняет

Здесь лежит граница между двумя слоями, проведённая на одной маленькой
программе и прогнанная целиком: напечатана в C, собрана системным `cc`,
запущена, вывод приведён ниже.

```
gatekeeper.flang   решение: кого пропустить, кому отказать, с каким кодом
host.c             исполнение: цикл, ввод-вывод, изменяемое состояние
run.sh             напечатать, собрать, прогнать
```

## Признак, по которому проведена граница

Не «низкий уровень», не «трогает железо» и — вопреки первому впечатлению — не
«завершается или нет». Признак один, и он записан решением дерева
(`docs/adr/0008-layer-boundary.md`):

> **На flang пишется то, что РЕШАЕТ. Хозяину остаётся то, что ЖДЁТ и что держит
> управление между двумя решениями.**

Довод «язык запрещает бесконечный цикл» неверен, и это снято прогоном. Файл на
четыре строки, в дереве он не лежит — повторите сами:

```
$ cat вечный.flang
модуль «Вечный цикл»

функция «Крутить»
  принимает н: число
  возвращает число
  «Крутить» от (н плюс 1)

$ flang check вечный.flang; echo $?
модуль «Вечный цикл»: функций 1, из них с доказанным завершением 0; типов 0
без доказанного завершения: «Крутить»
вечный.flang: проверено — разбор, типы, завершаемость, ядро и примеры; замечаний нет
0
```

Функция без условия остановки проходит проверку с кодом ноль. Язык запрещает не
бесконечный цикл, а ЛОЖЬ о завершении: пометка `тотальная` — обещание, и
проверяется именно оно.

Планировщик — привычный пример «того, что на flang не напишешь» — в дереве
написан целиком:

```
$ flang check flang/conc/scheduler.flang; echo $?
модуль «Планировщик узла»: функций 73, из них с доказанным завершением 73; типов 17; файлов вместе с импортами 2
0
```

Поэтому цикл в `host.c` стоит на C не потому, что он бесконечный. Он стоит там
из-за одной строки внутри: `fgets` **ждёт**. Слова для ожидания в языке нет ни
одного, а управление между двумя решениями обязано выйти наружу — звать хозяина
по имени программа не может, доступа к миру у неё нет.

Всё, что остаётся по эту сторону, — решения, и их больше, чем кажется: разбор
запроса, проверка прав, ограничение частоты, переход состояния протокола, коды
ответа. В этом примере — восемь функций, все тотальные, ни одна ничего не
делает.

## Как слои разговаривают

Хозяин строит значение, зовёт одну функцию и исполняет то, что она вернула:

```c
privratnik_sozdat_vrata(&ctx, /* запас, ёмкость, уровень, счётчики */ …, &gate, &error);
privratnik_variant_zapros(&ctx, fl_number(need), &event, &error);
privratnik_enter(&ctx, "Шаг привратника", args, 2, &decision, &error);
```

Зовётся `enter`, а не `call`, и разница здесь по существу. Напечатанный
заголовок объявляет обе двери и сам объясняет разницу: `call` — вычисление,
объявленные типы доводов оно не сверяет; `enter` — граница входа, она сверяет
типы **до** вызова. Значения здесь приходят от человека со стандартного ввода,
то есть снаружи, и доказательство завершения стоит на типе: значение вне типа
выносит вместе с типом и доказательство.

Обратно наружу не течёт ничего. У функций в `gatekeeper.flang` нет способа
что-либо сделать — они могут только вернуть значение.

## Что проверено, а что доказано

```
flang check examples/host-boundary/gatekeeper.flang --proof
  функций 8: тотальных 8, обычных 0
  обещание несёт: композиция 8, структура 0, точный шаг 0, постоянный шаг 0, объявленная мера 0
  утверждений 31: доказано 22 (из них без теоремы 22), сетка 9, объявлено, не доказано 0

flang test examples/host-boundary/gatekeeper.flang
  примеров 15, прошло 15, не прошло 0
```

Двадцать два утверждения из тридцати одного ядро закрыло само, без единой
теоремы, и в напечатанный код проверки на них не поехали — печать говорит об
этом первой же строкой: **«проверок при работе снято 22»**. Недоказанное
обещание поехало бы проверкой на каждом возврате, и это дороже, чем кажется:
ложное обещание опаснее отсутствующего.

## Предусловие — это и есть договор границы

У «Шаг привратника» стоит `требует «запас не выше ёмкости»`. Проверка на него
попадает в напечатанный код ровно там, куда значение приезжает извне.

Хозяин нарушает его **нарочно**, последним действием после конца ввода, — чтобы
видно было, что проверка стоит и что отказ приезжает статусом, а не падением:

```
хозяин: нарочно порчу довод — запас 4 при ёмкости 3
граница отвергла довод: FLANG_PRECONDITION — не выполнено требование «запас не выше ёмкости» функции «Шаг привратника»
```

Обратное правило тоже здесь, и оно стоило одной переделки. Предусловие
`требует «запас есть»` сначала стояло на внутренней функции «Пропуск врат», и
компилятор отказался: `FLANG_PRECONDITION_CALL` — вызов из «Запрос к вратам»
предусловие не снимает. Ветка `если` в вызывающем допущением не становится;
снять предусловие надо доказательством в месте вызова, и вид условия обязан
быть одним из шести, которые ядро умеет закрыть. Отсюда правило: **`требует`
ставится на функцию, которую зовёт хозяин, а внутренние обходятся
обещаниями.**

## Чего здесь нет

**Живучести.** Доказано, что каждый шаг переводит врата из годного состояния в
годное. Не доказано, что следующее событие вообще придёт: это свойство
бесконечной последовательности, а не одного шага, и живёт оно у хозяина.

**Новизны в самой границе.** Она проведена и объяснена раньше, решением
`docs/adr/0008-layer-boundary.md`, и там же прогнан стык через словарь поручений:
`examples/io/фильтр-пакетов.flang`. Здесь тот же стык взят с другой стороны —
не поручением, а печатью в C и рукописным хозяином, у которого свой цикл и своя
точка входа.

**Точки входа у напечатанного кода.** Печать позвана с ключом `--no-cli`: `main`
здесь свой, в `host.c`, а две функции `main` в одной сборке не слинкуются.

**Указателей и ручного освобождения.** Их нет в языке, и на их отсутствии стоит
доказательство завершаемости целиком. Память напечатанного модуля живёт ареной,
и хозяин отдаёт её каждый виток одним вызовом `fl_arena_reset` — всё, что
построил flang, к этому моменту уже переписано в состояние хозяина.

Рядом та же граница, проведённая по тому же признаку на других задачах:
`examples/io/фильтр-пакетов.flang` — на сетевом фильтре, через словарь
поручений; `examples/driver/` — на железе; `examples/web/orders-api.flang` — на
службе REST; `examples/io/link-report.flang` — на вводе-выводе.
