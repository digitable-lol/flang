# Служба на процессах

Проверка главного заявления цели — «язык со своей альтернативой OTP, пригодный
для написания любых служб» — не примером на три функции, а службой.

Одна служба, четыре файла, два разных хозяина:

| файл | что это | кто исполняет |
|---|---|---|
| `core.flang` | ядро: разбор HTTP, маршрут, счёт, печать ответа | никто — чистые функции |
| `service.flang` | три процесса, надзор, запас витков, прогоны | планировщик конкурентности |
| `serve.flang` | план: слушает порт, отвечает в соединение | цикл поручений хозяина |
| `ask.flang` | клиент: сам открывает соединение и спрашивает | цикл поручений хозяина |

Решает во всех четырёх одно и то же место — `core.flang`. Разбор запроса,
маршрут и печать ответа не знают, кто принёс байты.

## Что служба делает

```
GET /здоровье     → 200, тело «живой»
GET /длина/<н>    → 200, тело «<число шагов цепочки Коллатца от н до единицы>»
всё остальное     → 404, 405 или 400
```

Коллатц выбран не для красоты. Про завершение этой цепочки не знает никто —
гипотеза открыта с 1937 года. Значит анализ завершаемости flang её тотальной не
объявит, и обработчик, который её зовёт, **обязан** назвать запас витков. А
цепочка от нуля не сходится никогда: `GET /длина/0` — ядовитый запрос, на
котором счётчик падает по-настоящему.

## Прогоны

Служба и клиент — оба на flang, `curl` и `nc` не участвуют:

```sh
flang io examples/service-on-processes/serve.flang --plan "Обслужить по сети" &
flang io examples/service-on-processes/ask.flang  --plan "Спросить о здоровье"
flang io examples/service-on-processes/ask.flang  --plan "Спросить о длине"
flang io examples/service-on-processes/ask.flang  --plan "Спросить о нуле"
```

Процессы и надзор живьём — печатью в цель, у которой планировщик есть. Целей
таких две, и они отвечают одним и тем же.

**Свой планировщик flang, без BEAM** (`flang/src/emit/js/flang_conc.js`
печатается внутрь модуля):

```sh
flang emit examples/service-on-processes/service.flang --target js \
      --out <кат> --runtime flang/src/emit/js
node --input-type=module -e 'import("<кат>/sluzhba_na_processah.js").then(m =>
  console.log(JSON.stringify(m.concRun(
    "счётчик упал на ядовитом запросе — надзор поднял, служба отвечает дальше",
    { семя: 1 }))))'
```

**Настоящее дерево супервизоров OTP на BEAM:**

```sh
flang emit examples/service-on-processes/service.flang --target elixir \
      --out <кат> --runtime flang/src/emit/elixir
make -C <кат> build
echo '{"run":"счётчик упал на ядовитом запросе — надзор поднял, служба отвечает дальше"}' \
  | elixir -pa <кат>/_build -e 'Flang.Cli.main(["SluzhbaNaProcessah"])'
```

Примеры и отчёт о доказательствах:

```sh
flang test  examples/service-on-processes
flang check examples/service-on-processes/core.flang --proof
```

## Что здесь видно такого, чего у обычного языка нет

1. **Ядовитый запрос убивает СЧЁТЧИК, а не службу.** Пока счёт живёт в отдельном
   процессе, его смерть стоит одного ответа. У половины-плана, где надзора нет,
   тот же запрос уносит службу целиком — и это не рассуждение, а два прогона
   рядом.
2. **Перезапуск точен.** У счётчика «сосчитано» равно единице, хотя сосчитано
   было дважды: первый счёт поднял до единицы, падение вернуло к нулю — тому же
   начальному ЗНАЧЕНИЮ, что при заводе, — третий поднял снова.
3. **Запас витков назван у каждого обработчика.** Ни один из трёх не помечен
   `тотальная`, и границу им ставит язык, а не автор.

## Чего у этой службы нет, и это названо

* **Двух половин, слитых в одну.** Сетевую половину исполняет цикл поручений
  двоичного, половину на процессах — планировщик цели печати. Хозяин, у которого
  есть и сеть, и процессы разом, один — рантайм C (`flang/src/emit/c/flang_conc.c`),
  и он сегодня недостижим: печать конкурентности в C не попала в закоммиченное
  семя (задача 0041). До перепечатки семени служба на процессах сети не видит.
* **Судьи у процессов и надзора.** `flang check` отвечает про них дословно:
  «названное выше не судит НИКТО». Правила `процесс`, `надзор` и `прогон` живут в
  слое, которого в замыкании двоичного нет, — значит и строка `с запасом N
  витков` сегодня никем не принуждается. Проверено отрицательным контролем:
  `examples/web/shortener/handler-without-budget.flang`, написанный как улика
  «программа без запаса не собирается», нынешним двоичным **собирается**.
* **Keep-alive.** Принятое соединение живёт один обмен (ADR-0002).
* **Нескольких соединений разом.** «Продолжение» несёт одно поручение.
