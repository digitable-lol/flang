# API маркетплейса из трёх служб

Каталог, корзина и заказы — три модуля, разложенные так, как их разложили бы по
службам: у каждого свой тип состояния и свои правила, а связывает их только
`использует`. Четвёртый файл — шлюз: он принимает текст запроса и отдаёт текст
ответа, а между ними нет ни одной строки, написанной не на flang.

```
catalog.flang   136   товары, цена, остаток, «сколько выдать»
cart.flang      130   позиции, счёт, скидка ступенями (uses catalog)
orders.flang    245   состояния заказа и переходы между ними
gateway.flang   482   коды ответа, маршруты, байты пришли — байты ушли
                ─────
                993   строк, и все на flang
```

Опирается на `flang/stdlib/http.flang` — разбор запроса, печать ответа,
разбор параметров тела.

## Что она делает

| метод | путь | ответ |
|---|---|---|
| GET | `/здоровье` | 200 `живой` |
| GET | `/товары` | 200, по строке на товар |
| GET | `/товары/{артикул}` | 200 или 404 |
| GET | `/корзина` | 200, счёт по строке на позицию |
| POST | `/корзина` | 201 + пересчитанный счёт; тело `артикул=…&количество=…` |
| DELETE | `/корзина` | 204 |
| GET | `/заказы` | 200, по строке на заказ |
| POST | `/заказы` | 201 + номер заказа; корзина пустеет |
| GET | `/заказы/{номер}` | 200 или 404 |
| POST | `/заказы/{номер}/{действие}` | 200 или 422 |

Отказы: 400 негодный запрос, 404 нет пути, товара или заказа, 405 метод не тот
для известного пути (а не 404 — служба не врёт о причине), 409 на складе меньше,
чем просят, 413 тело запроса длиннее 2048, 422 переход по состояниям запрещён.

## Как посмотреть

```sh
export LC_ALL=C.UTF-8
bootstrap/flang check examples/web/marketplace/catalog.flang --proof
bootstrap/flang check examples/web/marketplace/cart.flang    --proof
bootstrap/flang check examples/web/marketplace/orders.flang  --proof
bootstrap/flang check examples/web/marketplace/gateway.flang --proof
```

## Где проходит граница языка

Сокета здесь нет. Слушающего порта нет. Ждать байтов язык не умеет и уметь не
будет: программе на flang не дано доступа к миру, иначе не доказать ни
завершаемость, ни то, что от повторного вызова с теми же доводами ответ тот же.
Кто принимает соединение и держит его — хозяин.

Рядом, в `examples/web/shortener/`, та же граница проведена и доведена до конца:
там лежит служба, которую хозяин водит по настоящему сокету.

## Что доказано, а что проверено

Слова отчёта не взаимозаменяемы:

- **доказано** — утверждение обо ВСЕХ входах;
- **сетка N** — посчитано на N значениях автора; это не доказательство;
- **объявлено, не доказано** — утверждение высказано, доказательства при нём нет;
- **НАРУШЕНО** — найден и показан противоречащий случай.

Доказано индукцией по объявленной сумме:

1. `код ответа из объявленного набора` — по «Исход», база 9 случаев;
2. `пояснение кода непусто` — то же, 9 случаев: утверждение о связи нашего
   набора исходов с таблицей пояснений в библиотеке;
3. `из конечного состояния переходов нет` — по «Состояние заказа», 6 случаев;
4. `у состояния есть непустое название` — то же, 6 случаев.

Доказано сведением цели с телом функции:

5. `выдаём либо всё, что просят, либо весь остаток` — разбор случаев по
   внутреннему условию цели;
6. `после добавления позиций ровно на одну больше` — тождество после переписки;
7. `скидка бывает только нулевая, пятипроцентная или десятипроцентная` — разбор
   случаев по внутреннему условию цели.

Проверено сеткой — то есть НЕ доказано, и это написано здесь, а не спрятано:

8. `из конечного состояния не разрешён никакой переход`;
9. `пустая корзина стоит ноль`;
10. `со скидкой платят не больше, чем без неё`;
11. `в строке счёта назван артикул`.

Все четыре упираются в одно, и это сказано самим компилятором — если написать
при них теорему, он отвечает `FLANG_PROOF_INDUCTION_BRANCH` и объясняет, что
заключение случая читает из ДВУХ форм тела и ниоткуда больше: с ветви `разбор`
по той же переменной и с начала и шага `свёртка` по той же переменной. У всех
четырёх тело сворачивает не саму переменную, а вычисленный из неё список
(`«Переходы из» от откуда`, `корзина.«позиции»`) — цеплять доказательство не к
чему.

Развернуть их в `разбор` по переменной можно, но для `«Переход разрешён»` это
значит завести вторую копию таблицы переходов рядом с `«Переходы из»`. Разъезд
двух копий — ровно то, от чего этот пример и стережёт теоремой; цена
доказательства вышла бы больше цены честной пометки. Пометка честная — слово
«доказано» стоит только там, где утверждение про все входы.

**У десятого утверждения в записи есть оговорка про конечность, и она не
украшение.** В первой редакции оно было написано просто `результат не больше
сумма` — и это ЛОЖЬ, показанная прогоном: при сумме `0 делить на 0` (не число) и
при минус бесконечности тело даёт не число, а «не число не больше чего угодно»
ложно. Утверждение стояло с пометкой `сетка 3`, и три значения автора этого не
поймали: сетка не ищет нарушений там, куда автор не заглянул. Условие
`(сумма минус сумма) равен 0` верно ровно для конечных чисел и отсекает оба
случая.

## Почему обещания записаны именно так

Утверждение может быть доказано и при этом не говорить ничего. Проверяется это
подменой тела заглушкой той же подписи: если с телом `0` утверждение всё ещё
доказано, оно верно про ЛЮБУЮ функцию такой подписи, а про эту не говорит
ничего.

Поэтому здесь нет ни одной односторонней верхней границы вроде «результат не
больше 30». Вместо них:

- перечисление значений — `(результат равен 0) или (результат равен 5) или
  (результат равен 10)`;
- равенство длин — `(длина результат.«позиции») равен ((длина корзина.«позиции»)
  плюс 1)`;
- связь двух функций одного файла — `(«Конечное» от этап) равен ((длина
  результат) равен 0)`.

Цены и суммы — целым числом копеек, а не рублями дробным числом: `0,1 плюс 0,2`
в машинных числах не даёт `0,3`, и счёт из трёх позиций разошёлся бы с суммой.
