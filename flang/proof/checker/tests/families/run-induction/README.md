# Семья «прогон-индукция»: чем закрывается утверждение о прогоне (задача 1404, Ш1)

Задача [1404](../../../../../../docs/tasks/1404-utverzhdenie-o-posledovatelnosti-shagov.md),
основание — [ADR-0032](../../../../../../docs/adr/0032-one-missing-rule-and-three-other-logics.md)
§3.1. Соседняя семья [`прогон`](../run/README.md) — шаг Ш0: сверщик читает строку
`прогон «Ф» шаг «Ш» строка N`. Здесь — шаг Ш1: ядро эту строку ПЕЧАТАЕТ, а
утверждение закрывает индукцией по списку свёртки (правила ведомости Инд2 и Инд3).

## Что лежит

| файл | чем снят | что показывает |
|---|---|---|
| `letters.фп` | рукой | тот же малый прогон, что в семье «прогон»: шаг «В ящик», прогон «Все в ящик» — свёртка по списку писем, и свободное утверждение о ней |
| `letters.record` | `flang check … --proof --записать`, двоичный 0.7.18 | запись ДО перепечатки семени: строки «прогон» в ней нет, вердикт носит правило «цель есть допущение» |

## Почему запись здесь — «до», а не «после»

Правка `flang/self/zapis.flang` и `flang/self/proof-kernel.flang` доходит до
собранного компилятора ТОЛЬКО перепечаткой семени (около девяти часов). До неё
двоичный печатает запись по старому коду, и она здесь и лежит — чтобы после
перепечатки разницу было видно `diff`-ом, а не на память. После перепечатки в
блоке `вид statement` обязана появиться строка

```
  прогон «Все в ящик» шаг «В ящик» строка 16
```

сразу под связываниями, а поле `правило` — перестать быть «цель есть допущение»
там, где база и шаг индукции закрылись.

## Чего здесь НЕТ и почему

**Ходов базы и шага в записи нет.** Первичных ходов у сверщика ровно тринадцать,
и список закрыт (`checker.c`, `ход_шага`); ход, которого он не знает, роняет
ЧЕСТНУЮ запись кодом 1, а не оставляет её на слове ядра. Переигрывание индукции
по прогону — это шаг Ш2 задачи, и до него печать ходов сделала бы красным весь
набор проб. Порядок тот же, каким шли Ш0 и правило Пред1: сверщик раньше ядра.
