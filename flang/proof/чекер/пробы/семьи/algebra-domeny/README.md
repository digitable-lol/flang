# Семья «algebra-domeny»: узел algebra с доменами «не больше» и «охрана»

Ячейка К11+ кластера 6202/6203 (9 сентября 2026, ветка `r/a-lovushka-dopolnenie`
от `gh/dev bc1ff161e`). Узел вердикта «разбором по случаям» на носителе `algebra`
сверщик проигрывает в пяти доменах цели (`проиграть_узел_algebra`):
неотрицательность, тождество, **порядок «не больше»**, **охрана «если У то Ц
иначе да»**, булева цель. У двух выделенных проб вне корпуса не было — ловушка
проверки 1 (`пробы/ловушка/ВИДЫ.tsv`) их не стерегла. Теперь стережёт: видов
31 → 33.

проиграть, — третий исход с названным случаем, а не приёмка и не отказ; ровно
так же ведут себя мутанты `Ч363`/`Ч131-algebra`.

## Что выяснилось (названо, не спрятано)

Ядро (`bootstrap/flang` 0.7.16 из worktree `r4135`, только чтение) печатает у
`ohrana.flang` посылку «Пусто» с правилом «вычисление замкнутой цели» (цель
ветви — `если да то да иначе да`), а «Узел» — «разбор цели по условию». Такой
узел со СМЕШАННЫМИ правилами приём оставляет вне (`вне приёма сверщика 1`,
код 3): домен охраны требует «разбор цели по условию» у каждой названной
посылки. В корпусе тот же узел (`ohrana-daet-fakt.запись`) проигрывается только
потому, что при теореме база закрыта шагом автора (`правило «»`). Честная
запись здесь несёт у «Пусто» правило «разбор цели по условию» — сверщик его
проверяет по существу (`в_то` = `да`), и это не ложь о программе, а расхождение
имени правила у ядра. Место для приёма: допускать у домена охраны базу с
булевым правилом — отдельная ячейка, не эта.
