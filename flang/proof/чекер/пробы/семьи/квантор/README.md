# Семья «квантор»: имена за «для всех» — списком (ADR-0026 К2/К6)

Ячейка К2/К6 кластера 6202/6203 (10 сентября 2026, ветка `r/a-k2` от `gh/dev
8ca255ce6`). Контракт — `ПЕРЕДАЧА/stack-B/kontrakt-kvantory.md` §К2 и К6:

- исходник: `для всех а и б обеспечивает «И» …`; вложенное `для всех а для всех б
  обеспечивает …` — то же самое;
- запись: в блоке постусловия сразу после `  вид postcondition` строка
  `  для всех «а» «б» строка N` (N — строка постусловия, имена в порядке написания).

Что делает сверщик: имена за «для всех» читает СПИСКОМ (`имена_квантора`; прежде —
одно первое слово, и `для всех а и б` с индукцией по «б» получало ложный отказ —
матрица ADR-0026, З3); принцип обязан идти по одному из названных; строка записи
сличается знак в знак; стоять она обязана сразу после `вид postcondition`.

## Строки нет — что тогда (решение overagent'а 10 сентября 2026)

- одно имя за «для всех» (так пишет и сегодняшнее ядро) — вывод побайтно как у
  сверщика до К2, пока `СТРОКИ_КВАНТОРОВ_ОБЯЗАТЕЛЬНЫ` = 0;
- два имени и больше (сегодняшнее ядро такой программы не пропускает) — код 1
  всегда: за отсутствие строки «проверено» не выдаётся (подделка п4);
- переключатель включит overagent в партии перепечатки кванторов, после
  пересъёмки корпуса. Строгий режим проверяется уже сейчас: `прогон.sh` собирает
  копию сверщика с 1 и прогоняет на ней три записи ниже.

## Что здесь лежит

Все записи РУКОТВОРНЫЕ: ядро строку `для всех «…»` ещё не печатает, а программу с
двумя именами за «для всех» сегодняшний разбор не пропускает.

| файл | класс | код | что это |
|---|---|---:|---|
| `два-имени.{flang,запись}` | честная | 3 | `flang/proof/examples/precondition.flang`, строка 68 — `для всех дно и стопка`; запись корпуса с пересчитанной шапкой и строкой `для всех «дно» «стопка» строка 68`. Индукция по «стопка» — по ВТОРОМУ имени: сверщик dev — код 1 (ложный отказ З3). 3, а не 0, по наследству: запись корпуса даёт тот же код с тем же выводом (кроме sha256) |
| `имя-вне-списка.flang` | исходник подделки | — | та же строка — `для всех дно` |
| `одно-имя.запись` | честная | 0 | запись корпуса `corpus-length` + `для всех «элементы» строка 37`; вывод побайтно как без строки |
| `строгий-честная.запись` | честная, строгий режим | 0 | запись семьи «объявление» `corpus-length` + строка `для всех` — полная запись |
| `строгий-без-строки.запись` | строгий режим | 1 | та же без строки `для всех` (в мягком режиме — 0) |
| `порча/п1`…`п3` | подделка | 1 | пропущено имя, лишнее имя, другой порядок |
| `порча/п4` | подделка | 1 | строки нет при двух именах в исходнике — никогда не 0 |
| `порча/п5`, `п6` | подделка | 1 | чужая строка постусловия; строка не сразу после `вид postcondition` |
| `порча/п7` | подделка | 1 | исходник `для всех дно`, принцип по «стопка» — индукция по имени вне списка |
| `порча/п8` | подделка | 1 | строка `для всех` при постусловии без квантора (`binder-wall-map`, строка 60) |

Шапки записей с изменённым исходником посчитаны по файлу (строк, знаков, два
многочленных отпечатка, SHA-256) тем же счётом, что сверяет `сверить_шапку`.

## Чего здесь нет

- Эталонов ядра (`ПЕРЕДАЧА/stack-B/golden-kvantory/`) на момент ячейки нет; после
  них — сличить печать ядра с этими записями.
- Имя в ёлочках с « и » внутри (`«а и б»`) список рвёт — в корпусе таких имён нет.
- Повтор имени (`для всех а и а`) отвергает ядро; сверщик отдельной проверки не
  держит.
