## Ячейка 5: прямая теорема «по предположению» (10 сентября 2026)

Прямая теорема (без «индукция по») с целью «результат не меньше 0» и единственным
шагом «по предположению» верна ровно тогда, когда тело функции неотрицательно по
построению при её предусловиях (`требует «…» Т не меньше К`): других допущений у
прямой теоремы нет. Сверщик это проигрывает (`прямая_по_предположению` в
`сверить_шаги`) тем же `неотрицательно_algebra`, что у узла `algebra`: литерал,
«длина», допущение `требует` (правило Н2), «плюс» (Н5), обе ветви «если», один шаг
развёртки плоской функции. Не сошлось — шаг, как прежде, на слове ядра.

| что | было → стало |
|---|---|
| корпус `precondition` («удвоенное неотрицательно», тело `н плюс н`) | 3 → 0 |
| проба `Ч56/precondition-dereva`, семья `квантор/два-имени` (тот же шаг) | 3 → 0 |
| корпус `four-words` («удвоенное неотрицательно», тело `н умножить на 2`) | 3 → 3: произведения в `неотрицательно_algebra` нет — это правило Н8, его приём у Lead-E |

| файл | класс | код | что это |
|---|---|---:|---|
| `тело-не-неотрицательно.{flang,запись}` | подделка (никогда не 0) | 3 | исходник `precondition` с телом `н минус 1` (при н = 0 даёт −1); запись — запись корпуса с пересчитанной шапкой. Сверщик оставляет шаг на слове ядра; копия, у которой проверка тела всегда «да», принимает запись кодом 0 |

## Ячейка 4 — не взята (решение overagent'а)

«По примеру» с целью-свёрткой (`corpus-cforms` ×3, `corpus-bytes`) требует от
вычислителя сверщика отбора списков и трёх слоёв функций-помощников, а
`corpus-bytes` — строк с нулевым знаком. Это второй вычислитель языка внутри
сверщика; места остаются на слове ядра с названной причиной.

Причина называется в самом отказе (`ПРИЧИНА_СЧЁТА` в `сверщик.c`): вычислитель
ставит её там, где сдаётся по решению, — на `отфильтровать … где …` и на
разложении строки с нулевым знаком, — и «вид цели … сверщику незнаком»
дописывает её через тире. Где причина не поставлена, текст прежний байт в байт
(сплошная сверка: из 381 записи разошлись только эти две, коды 3/3).
Проба в `прогон.sh` («ячейка 4: причина названа») ждёт код 3 и подстроку
причины; копия сверщика, которая причину не ставит, её роняет.

## Узел binder-wall-map: охрана и выбор с тем же условием (10 сентября 2026)

Постусловие «разбор: при положительном пороге ноль или один» — цель-охрана
`если порог больше 0 то (результат равен 0) или (результат равен 1) иначе да`,
а тело каждого случая — `(если порог больше 0 то К иначе 5)`. Прежде узел охраны
(`охраной_случая`) искал обещанное только среди конъюнктов охраны и отказывал.
Теперь, если в Ц стоит выбор с ТЕМ ЖЕ условием, условие это под охраной есть
«да» (Р1 и гипотеза ГипО; Р3 — внутреннее условие совпало с внешним, хода нет),
и замкнутую Ц закрывает Выч (`половина_закрыта`). Меняется только условие выбора
знак в знак (`если У то`), а не всякое вхождение текста У; связыватель в Ц —
отказ. Правил ведомости не прибавлено: Р1, ГипО, Р3, Выч в ней уже есть.

| что | было → стало |
|---|---|
| корпус `binder-wall-map`: утверждение и две посылки | на слове ядра 3 → 0 (запись остаётся 3: «свёртка: счёт неотрицателен» — Н7, у Lead-E) |

| файл | класс | код | что это |
|---|---|---:|---|
| `охрана-то-же-условие.{flang,запись}` | честная | 0 | функция «Порог под разбором» из `binder-wall-map` байт в байт; запись — её блоки из записи корпуса, строки перенумерованы, шапка пересчитана. Прежний сверщик — 3 |
| `охрана-ложный-вывод.{flang,запись}` | подделка (никогда не 0) | 3 | ветвь «голова и хвост» даёт 2 — обещание ложно. Копия сверщика без замыкания (`половина_закрыта` → «да») принимает её кодом 0 |
| `охрана-другой-порог.{flang,запись}` | подделка (никогда не 0) | 3 | внутреннее условие `порог больше 1` — не охрана (при пороге 0,5 выходит 5). Отвергает её само сличение условия знак в знак; копии, которая сличала бы условие вольнее, простой правкой не собрать — довод здесь пара «честная 0 / эта 3», отличающаяся одним условием |

Не опровергнуто ни одной пробой: условие «связыватель в Ц — отказ» (страховка).
