# asdf-flang

Плагин [asdf](https://asdf-vm.com) для языка [flang](https://github.com/digitable-lol/flang).

```bash
asdf plugin add flang https://github.com/digitable-lol/asdf-flang.git
asdf install flang latest
asdf global flang latest
flang --help
```

[mise](https://mise.jdx.dev) понимает те же плагины:

```bash
mise plugin add flang https://github.com/digitable-lol/asdf-flang.git
mise use -g flang@latest
```

## Что нужно на машине

Компилятор C и `make`. Больше ничего.

Это не аскетизм, а устройство релиза: компилятор flang написан на самом flang и
печатается в C, поэтому в архиве лежит уже напечатанный C99. Ставящему не нужен
ни Node, ни сам flang. Так же поступают другие самоприменяющиеся языки — Go
долго возил сгенерированный C, Nim возит до сих пор.

## Что ставится

| | |
|---|---|
| `bin/flang` | компилятор: разбор, типы, завершаемость, разбор суждений, печать в C, оболочка `flang repl` |
| `lib/libkompilyator_flang.a` | тот же компилятор библиотекой — чтобы встраивать |
| `include/*.h` | заголовки рантайма и компилятора |

**Оболочка есть, и три каталога выше — не случайность.** Вычислителя в бинарнике
нет: он умеет разобрать, проверить и напечатать, но не выполнить. Поэтому
`flang repl` вычисляет так, как этот бинарник может, — печатает сессию в C,
собирает её системным `cc` против `lib/libkompilyator_flang.a` и заголовков из
`include/` и запускает. Собирается при этом только сессия: рантайм уже готов,
поэтому счёт идёт на доли секунды.

Без `cc` оболочка не выключается — она по-прежнему проверяет разбор, типы и
завершаемость, то есть делает ровно то, что бинарник умеет, — и говорит об этом
один раз при запуске. Где искать `cc` и каталоги, можно назвать явно:
`FLANG_CC`, `FLANG_LIB_DIR`, `FLANG_INCLUDE_DIR`.

Остальные семь целей печати живут в полном инструментарии, а ему нужен Node:

```bash
npm install -g @digitable-lol/fts
```

## Из ветки поставить нельзя

`asdf install flang ref:main` откажет намеренно. В репозитории компилятор лежит
исходником на самом flang, и чтобы получить из него первый бинарник, нужен
Node — то есть ровно та зависимость, от которой плагин избавляет. Молча тянуть
Node за спиной у человека, который поставил язык «без зависимостей», было бы
обманом; отказ с объяснением честнее.

## Проверка после установки

Плагин не считает установку удавшейся по факту появления файла. Он подаёт
собранному компилятору модуль и требует, чтобы тот насчитал в нём ровно одну
связанную функцию. Битая установка падает здесь, а не у человека при первом
запуске.

---

**Где это лежит.** Здесь — исходник плагина, в репозитории самого языка, рядом
с формулой Homebrew: две упаковки одного релиза удобнее править вместе, чем в
разных местах. Чтобы `asdf plugin add flang` работал, эти файлы должны стоять
корнем отдельного репозитория `digitable-lol/asdf-flang` — так устроен asdf, он
клонирует плагин целиком.
