# asdf-flang

Плагин [asdf](https://asdf-vm.com) для языка [flang](https://github.com/digitable-lol/flang).

```bash
asdf plugin add flang https://github.com/digitable-lol/asdf-flang.git
asdf install flang latest
asdf set -u flang latest
flang --help
```

Третья строка — `asdf set`, а не `asdf global`: команды `global` и `local` в asdf
**удалены** версией 0.16.0, и человек на любом сегодняшнем asdf получал на ней
ошибку. Ключ `-u` пишет версию в домашний `.tool-versions`, то есть делает ровно
то, что делала `global`. На asdf старее 0.16 работает прежнее слово.

[mise](https://mise.jdx.dev) понимает те же плагины:

```bash
mise plugin add flang https://github.com/digitable-lol/asdf-flang.git
mise use -g flang@latest
```

## Что нужно на машине

Компилятор C и `make`. Больше ничего.

Это не аскетизм, а устройство релиза: компилятор flang написан на самом flang и
печатается в C, поэтому в архиве лежит уже напечатанный C99. Ставящему не нужен
ни Node, ни сам flang. Так же поступают другие самоприменяющиеся языки — Go
долго возил сгенерированный C, Nim возит до сих пор.

## Что ставится

| | |
|---|---|
| `bin/flang` | компилятор: `flang check файл.flang` — разбор, типы, завершаемость; `flang repl` — оболочка; `flang --help` — остальное |
| `lib/libcompiler_flang.a` | тот же компилятор библиотекой — чтобы встраивать |
| `include/*.h` | заголовки рантайма и компилятора |
| `share/flang/<цель>/` | ИСХОДНИКИ рантайма цели печати — то, что `flang emit` дословно кладёт в вывод. Каталогов девять, по одному на цель |

**Последняя строка появилась не для полноты.** Без неё `flang emit` не работал
ни у одного поставившего: бинарник ищет исходники рантайма в
`../share/flang/<цель>` от себя самого, а туда не клал ничего никто — имя
встречалось во всём дереве только как путь ПОИСКА. Напечатанные копии, лежащие
в корне архива рядом, для этого не годятся: печать отвергает их по шапке
«Сгенерировано flang», потому что они несут пределы самого компилятора, а не той
программы, которую печатают.

**И до 5 сентября 2026 каталог был ОДИН — `c`.** Плагин клал `runtime-c` в
`share/flang/c`, и восемь остальных целей (`cpp`, `csharp`, `elixir`, `go`,
`java`, `js`, `python`, `rust`) у поставившего не работали, хотя обещаны и в
`man`, и в обоих README, и в справке двоичного. Теперь плагин переносит корень
`runtime/` целиком — 32 файла девяти целей, — а его собственная проба после
установки печатает в двух целях (`c` и `js`) и считает девять каталогов: не лёг
хоть один — установка краснеет, а не молчит. Чинилось задачей 7261.

Корень переносится целиком, а не цель за целью, потому что у цели `cpp`
договор другой: она отсчитывает пути от `share/flang`, а не от своего каталога
— три файла из четырёх берёт из `c/`, и только своё `cpp/flang_cpp.hpp` из
`cpp/`.

**Оболочка есть, и каталоги выше — не случайность.** Вычислителя в бинарнике
нет: он умеет разобрать, проверить и напечатать, но не выполнить. Поэтому
`flang repl` вычисляет так, как этот бинарник может, — печатает сессию в C,
собирает её системным `cc` против `lib/libcompiler_flang.a` и заголовков из
`include/` и запускает. Собирается при этом только сессия: рантайм уже готов,
поэтому счёт идёт на доли секунды.

Без `cc` оболочка не выключается — она по-прежнему проверяет разбор, типы и
завершаемость, то есть делает ровно то, что бинарник умеет, — и говорит об этом
один раз при запуске. Где искать `cc` и каталоги, можно назвать явно:
`FLANG_CC`, `FLANG_LIB_DIR`, `FLANG_INCLUDE_DIR`.

Остальные семь целей печати живут в полном инструментарии, а ему нужен Node:

```bash
npm install -g @digitable-lol/flang
```

## Из ветки поставить нельзя

`asdf install flang ref:main` откажет намеренно. В репозитории компилятор лежит
исходником на самом flang, и чтобы получить из него первый бинарник, нужен
Node — то есть ровно та зависимость, от которой плагин избавляет. Молча тянуть
Node за спиной у человека, который поставил язык «без зависимостей», было бы
обманом; отказ с объяснением честнее.

## Проверка после установки

Плагин не считает установку удавшейся по факту появления файла. Он подаёт
собранному компилятору модуль и требует, чтобы тот насчитал в нём ровно одну
связанную функцию. Битая установка падает здесь, а не у человека при первом
запуске.

---

**Этих файлов две копии, и это не небрежность.** Правятся они в репозитории
языка, в `packaging/asdf/`, рядом с формулой Homebrew: две упаковки одного
релиза удобнее держать вместе. А работать обязаны корнем отдельного репозитория
[`digitable-lol/asdf-flang`](https://github.com/digitable-lol/asdf-flang) — так
устроен asdf, он клонирует плагин целиком. Поэтому `packaging/asdf/` — источник,
а корень `asdf-flang` — копия, обновляемая той же правкой:

```bash
cp -R packaging/asdf/. ../asdf-flang/
git -C ../asdf-flang commit -am "…" && git -C ../asdf-flang push
```

Копии обязаны совпадать побайтово, и за этим следит
`flang/test/asdf-plugin-published.test.mjs`: он скачивает опубликованный плагин
и сверяет с `packaging/asdf/` файл за файлом, называя разошедшиеся поимённо.
Сторож заведён не впрок: ровно так разошлись формула Homebrew и её копия в tap,
и `brew` три релиза подряд ставил версию, отставшую от обещанной.
