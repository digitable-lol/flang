# 0024. Замер «вариант с полями берётся» перемерен на одном двоичном

Два замера противоречат друг другу. Один говорит «вариант с полями берётся, 26 из
26». Другой — шесть проб, все остались «объявлено». Один из двоих мерил не то, и
пока это не разобрано, страница приёмов держит первую версию, и в ней это сказано
прямо.

Разобрать так же, как разобрали расхождение о строгих неравенствах (задача 0010):
взять у автора первого замера файл пробы и строку отчёта, прогнать на своём
двоичном, назвать, что именно расходится.

## Как понять, что сделано

Один файл пробы, один двоичный, один вывод — и правка страницы
`docs/site/kak-dokazat.ru.md` под то, что вышло.

## Чем ограничено

Двоичные у сторон разные, и это первое, что надо исключить: правки ядра доезжают
до собранного компилятора только перепечаткой (задача 0003).

## Что сделано (ветка `u/remeasure-record-variant`, 26 августа 2026)

**Коротко.** Оба замера верны, и меряли они разное. Замер «вариант с полями
берётся» воспроизведён знак в знак. Догадка, записанная на странице как
«что именно решает — не выяснено» — будто дело в том, разбирают довод или
результат вызова, — **опровергнута прогоном**. Двигают вердикт две другие вещи:
что стоит под `иначе` и какого вида цель.

Всё ниже снято ОДНИМ двоичным `/srv/flang-rabota/w-predely/bootstrap/flang`
через ворота, `PAMYAT=45G` на пробах и `PAMYAT=80G` на файлах компилятора.

## Замер А воспроизведён

Прогон `check --proof` по обоим файлам, вердикты разобраны поимённо по всем
обещаниям, у которых охрана — равенство разбираемого варианту:

| файл | охрана-равенство варианту | доказано |
|---|---|---|
| `flang/self/monad-expand.flang` | с полями | **17 из 17** |
| `flang/self/monad-expand.flang` | без полей | 5 из 6 |
| `flang/self/monad-expand.flang` | нульместному вызову | 3 из 3 |
| `flang/self/bounded.flang` | с полями | **6 из 6** |
| `flang/self/bounded.flang` | без полей | 7 из 10 |
| `flang/self/bounded.flang` | нульместному вызову | 2 из 2 |

Итого приём 10 в двух файлах — **40 из 44**.

Строки отчёта целиком:

```
monad-expand.flang  утверждений 127: доказано 65 (из них индукцией 2) (из них без теоремы 63), сетка 7, объявлено, не доказано 55
bounded.flang       утверждений 366: доказано 216 (из них индукцией 2) (из них без теоремы 212, объявленным типом 2), сетка 17, объявлено, не доказано 133
```

«17 из 17 в monad-expand» сходится знак в знак. «9 из 9 в bounded» сегодня не
проверить: таких обещаний в файле шесть, доказаны все шесть, а строк, из которых
складывалась девятка, в нынешнем тексте нет — файл правили после того замера.

**Главное — где стоят четыре невзявшихся: ВСЕ ЧЕТЫРЕ у варианта БЕЗ полей.**
То есть поля не мешают ничему, и спор шёл не о том.

## Что расходилось

Проба `examples/proof-probes/variant-with-fields.flang` — один модуль, одна сумма
с полями, одна мысль, записанная двадцатью тремя способами; в каждой паре
меняется ровно одно.

```
утверждений 23: доказано 21 (из них индукцией 1) (из них без теоремы 20), сетка 0, объявлено, не доказано 2
```

| что меняется в записи | вердикт |
|---|---|
| разбирают довод | доказано |
| разбирают результат вызова | доказано |
| охрана отрицанием, довод | доказано |
| охрана отрицанием, вызов | доказано |
| поле литералом, а не доступом | доказано |
| ветвь зовёт функцию с доводами, цель тем же вызовом | доказано |
| ветвь зовёт, цель развёрнута до `(длина результат) равен ((длина «числа») плюс 1)` | доказано |
| под `иначе` стоит второе утверждение | **не берётся** |
| цель — голый признак с отрицанием | **не берётся** |

Пара, различающаяся ровно этим, лежит и в дереве — `monad-expand.flang`, одна
функция «Есть отказ», одна охрана:

```
если «может» равен (вариант «Отказа нет») то результат равен нет иначе результат равен да  объявлено
если «может» равен (вариант «Отказа нет») то результат равен нет иначе да                  ДОКАЗАНО
```

**А запись, которой, судя по всему, мерил замер Б, — не замер вовсе.** Охрана,
называющая вариант с полями и не дающая полю терма, отвергается типизацией, и
файл не проверяется ни на одно обещание:

```
если «груз» равен (вариант «Есть») то …
FLANG_TYPE, столбец 78: конструктор «Есть» требует поле «вес» (число)
```

То есть «шесть проб остались объявленными» и «26 из 26» — про разные записи, а
не про одну, померенную дважды.

## Чего воспроизвести НЕ удалось, и это сказано прямо

Две строки таблицы про планировщик (`flang/self/conc.flang`) — охрана отрицанием
и охрана вариантом с полями — на малой пробе доказываются обе. Форма планировщика
воспроизведена отдельно (ветвь отдаёт сам довод против ветви, зовущей функцию с
доводами, цель про длину, сводимая только постусловием вызванной) — тоже
доказано, все четыре. Значит причина у планировщика своя и остаётся неназванной;
на странице так и написано. Опровергнуто только то, что она в разбираемом.

Тех двух записей в `conc.flang` сегодня нет — их снял автор замера, — поэтому
сверить их на своём двоичном нечем; сверялась форма, а не те самые строки.

## Заодно: три строки страницы, которые ствол уже опроверг

Правлены той же веткой, потому что страницу держит один исполнитель.

* **«уровень свёртки закрыт» — неверно.** Подъём постусловия через свёртку у
  ядра есть («Принцип свёртки», `flang/self/proof-initial.flang`) и работает в
  нынешнем напечатанном компиляторе. Закрыты две ФОРМЫ записи тела — свёртка под
  проекцией и свёртка по полю довода, — и обе снимаются правкой программы.
  Числа соседа по задаче 0050: MSI 86 → 90 доказанных, распределитель памяти
  79 → 82; по обеим программам «объявлено» 8 → 5.
* **«свёртка над пустым списком: правила у ядра нет»** — правило есть в
  исходнике (`5ef6f3fe`), в напечатанном семени его нет, доедет перепечаткой.
  Помечено как в разделе «3-тер». Проба на сегодняшнем двоичном:
  `утверждений 2: доказано 0, сетка 0, объявлено, не доказано 2` — и оговорено,
  что доказывает она узкое: отказ ядра причины не называет, значит из «0 из 2»
  следует только «на этом двоичном, в этой записи».
* **`элемент N в списке`** — на странице этой строки не было вовсе; дописана.
  Переписка есть (`0f1a2e17`), читает три равенства по построению списка и не
  читает выписанный `[а, б]`; четвёртое равенство дописано соседом (`dc2a42e1`),
  замер прямым вызовом правила на восьми входах приведён таблицей. В семени
  этого нет. Оговорено и то, чего оно не откроет: в `flang/stdlib` все
  шестнадцать мест `элемент … в [ … ]` имеют номер именем, литеральных ноль.
