# 0029. Девятой цели печати «typescript» не будет, пока узел программы не типизирован

Задача заведена закрытой нарочно: вопрос «почему среди целей печати есть `js`,
но нет `typescript`» задавался уже дважды, и без записанного довода будет задан
третий раз.

## Почему отменена

**Покупать почти нечего.** JavaScript — синтаксически годный TypeScript, а
пометки типов `emit-js` печатает уже сегодня, JSDoc-ом. `tsc` работает по нашей
печати **прямо сейчас**, без единой новой строки в дереве.

Замер на 36 программах `examples/leetcode`, напечатанных в `js` двоичным
компилятором: 18 330 строк, 1317 функций, 702 пометки типа.

| пометка | сколько | доля |
|---|---:|---:|
| настоящий тип (`number`, `Array<string>`, запись полями) | 519 | 73,9 % |
| слабая (`Array` без элемента, `Function`, `Promise<any>`) | 120 | 17,1 % |
| прямо `*`, то есть `any` | 63 | 9,0 % |

`tsc` по той же печати:

| режим | замечаний |
|---|---:|
| `allowJs + checkJs`, `strict: false` | 87 |
| то же, `strict: true` | 2523 |

Из 2523 строгих — **2109 это `TS7006`, «у параметра молча тип `any`»**. Против
488 напечатанных `@param` это и есть цена вопроса: пометки покрывают публичную
поверхность, а строгий режим требует тип на каждом из ~2600 мест параметра,
включая внутреннюю машинерию, оставшуюся после снятия функций-значений.

**Больше и не выйдет**, пока узел разобранной программы — обобщённое значение:
печать типов не знает, потому что типизированного AST нет (`SPEC.md:1605`,
`types.flang:24`). Это задача 0028, и TypeScript — её следствие, а не отдельная
работа.

## И цена в перепечатке названа

Все восемь печатников ввозятся в `flang/self/bootstrap/compiler.flang` — то есть
попадают в семя. Счёт 24 августа:

```
30 491 из 110 849 строк flang/self   — 27,5 %
 1815 из  6 441 обещания             — 28,2 %
```

Девятый добавил бы около 4400 строк и около 150 обещаний в то, что печатается
при **каждой** перепечатке. А обещания — ровно то, что делает её дорогой: два
замера одного дерева дали 1 ч 53 мин / 85 ГиБ с ними против 19 мин 45 с /
23 ГиБ без них.

## Что вместо: пять правок внутри печати, а не девятая цель

Замерено тем же заходом. Порядок — по измеренной пользе, не по удобству
рассказа. Номера строк — по дереву замера.

| правка | из 87 | из 2523 | чем подтверждено |
|---|---:|---:|---|
| 1. реестр функций `new Map` | **79** | **79** | замер: все 79 `TS2769` одного вида |
| 2. голый `Array` в пометке | 0 | **48** | вывод из двух замеров, не прямой |
| 3. `Function` и `Promise<any>` | 0 | 0 | замер: пометки есть, потому и не считаются |
| 4. `// @ts-check` первой строкой | 0 | 0 | по построению: `checkJs` уже был снаружи |
| 5. `.d.ts` из «Границы входа» | 0 | 0 | не про проверку `.js` вовсе |
| **печатью всего** | **79 (91 %)** | **127 (5 %)** | |

**Нестрогий режим чинится печатью почти целиком; строгий — на двадцатую часть.**

## Сделано: нестрогий режим закрыт целиком, 87 → 0

Коммит `d8868b2e` (влит `b961a5b6`). Первая правка дала ровно обещанные 79.
Оставшиеся 8 снял приём, которого в этом разделе не было: **конструктор
варианта с полями печатался как `Uzel(fields = {})` при пометке, требующей все
поля** — противоречие внутри одной напечатанной строки. Работу не меняет
(`$FlangVariant` подставляет `{}` сам), а замечание переезжает с бессмысленной
подстановки на настоящий вызов с недостающим полем.

На всех 70 печатающихся программах: 178 → 0. Строгий режим за те же правки
2523 → 2436.

**Голый `Array` не чинён, и это верно:** `TS2314` — диагностика
`noImplicitAny`, в нестрогом режиме не срабатывает вовсе. 48 голых `Array` при
нуле `TS2314` — то есть в 87 они не входили никогда. Точка печати найдена: две
дословные строки JSDoc в рантайме цели (`«Текст deepEntry JS»`,
`«Текст callDeep JS»`), 24 файла × 2.

Оговорка к слову «проходит»: ноль — про **напечатанный модуль**. Прогонщик
приносит свои 504 (`TS2591` без `@types/node`, `TS2810` на `new Promise()`), но
он не печатается — уезжает в вывод дословно с диска.

**1. Реестр функций.** `«Таблица программы JS»`, постоянная
`"  functions: new Map(["` (около 3851–3865). `@type` на `$PROGRAM` до вывода
внутри `new Map([...])` не доходит: TypeScript берёт тип пары из ПЕРВОЙ строки и
ругается на каждую следующую с другой сигнатурой. Лечится приведением на самом
литерале массива: `new Map(/** @type {[string, Function][]} */ ([` с закрывающим
`])),`. Одна строка печати, 79 из 87 замечаний.

**2. Голый `Array`.** `TS2314` ровно 48, и голых `Array` в пометках ровно 48 —
совпадение точное, но по отдельности правка не прогонялась. Точка печати **не
найдена**: `«Пометка вида типа JS»` (2478) для вида `list` печатает
`Array<…>` с элементом и голого `Array` дать не может, значит печатается
где-то ещё. И оговорка: `Array` → `Array<*>` замечание снимет, не добавив ни
бита сведений. Настоящий элемент нужен для пользы, а не для тишины.

**3–5** замечаний не снимают вовсе. `Function` (48 мест) и `Promise<any>`
(24) существуют как пометки, потому в счёт и не входят — выигрыш там в
сведениях для потребителя, и он не измерен. `// @ts-check` ценна не числом, а
тем, что включает проверку у того, кто своего `tsconfig` не заводил, — то есть
это замена варианту с `tsconfig`, а не добавка к нему. `.d.ts` строится из
`«Граница входа JS»` (3835), где `entry: { types, fields, variants, params }`
уже собран.

## Граница: что чинится печатью, а что нет

**Чинится печатью** всё, у чего есть **синтаксическое объявление в исходнике на
flang**: параметры (`принимает х: тип`), возврат (`возвращает тип`), поля
записи, начинка вариантов суммы, таблица границы входа. Это те самые 702
пометки — тип уже лежит в узле, печать его просто не всегда выписывает.

**Не чинится печатью** — типы того, что **печать выдумывает сама**: раздатчик
после снятия функций-значений, кадры батута, накопитель свёртки, запись
окружения замыкания, общий носитель `$FlangVariant`. У них нет объявления на
flang, которое можно скопировать; их тип существует только как вывод по всей
программе.

**2109 `TS7006` делятся по этой линии, и деления никто не мерил.** Косвенное:
пометок `@param` 488 при ~2597 местах параметра и 1317 функциях, а `возвращает`
в flang обязателен у каждой функции — значит часть из 2109 это «тип объявлен, но
JSDoc в этом месте не печатается», то есть чинится печатью. Какая часть —
считается одним прогоном: разметить места `TS7006` на «внутри функции,
порождённой печатью» и «внутри функции из исходника». Прогон не сделан.

## Важная поправка к связке с 0028

Здесь раньше стояло «после 0028 те 2109 мест получат настоящий тип». **Это
неверно, и опровержение записано до того, как кто-то на него понадеялся.**

Типизированный AST даёт объявленные типы в типизированном виде. **Выведенных
типов промежуточных выражений он сам по себе не даёт.** Типы раздатчика, кадров
батута и накопителя свёртки не появятся оттого, что узел стал типизированным —
их надо ВЫВЕСТИ отдельным проходом по всей программе, и такого прохода 0028 не
обещает.

Так что 0028 снимает часть «тип объявлен, но не выписан», а остальное требует
своей работы, которой ещё нет ни в одной задаче. Сколько чего — тот самый
неснятый прогон выше.
