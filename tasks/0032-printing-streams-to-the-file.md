# 0032. Печать пишет в файл по ходу, а не копит двадцать мегабайт в памяти

Замер 24 августа 2026, четвёртая перепечатка на четвёртом часу:

```
$ cat /proc/<pid>/io
read_bytes:   197582848      исходники прочитаны в начале
write_bytes:  4096           на диск ушло ЧЕТЫРЕ КИЛОБАЙТА
```

`bootstrap/compiler_flang.c` — двадцать один мегабайт — собирается в памяти
целиком и пишется одним куском в самом конце. До конца работы на диске нет
ничего: каталог вывода пуст.

Из этого следуют сразу три беды, и третья хуже всех:

1. Пик памяти включает весь накопленный вывод.
2. Пока печать не кончилась, наблюдать нечего — см. задачу 0031.
3. **Прогон, снятый на 99 % пути, не оставляет ничего.** Четыре часа работы
   пропадают целиком.

## Что делать

Печать компилятора — это цикл по функциям верхнего уровня. Между двумя
функциями живого почти ничего не остаётся, кроме накопленного вывода. Значит
граница есть, и она естественная: **напечатал функцию — дописал в файл —
отпустил**.

Проверить, стоит ли на этой границе отметка арены (`fl_mark`), и если стоит —
что мешает на откате отдать куски системе. Задача 0004 уже сделала откат
отдающим, здесь остаётся связать его с записью.

## Как понять, что сделано

Во время перепечатки файл вывода **растёт**:

```sh
watch -n5 ls -la <вывод>/compiler_flang.c
```

И пик памяти снят до и после, одной командой на одном дереве
(`/usr/bin/time -v`, строка `Maximum resident set size`). Отрицательный
результат полноценный: если запись по ходу роняет скорость вдвое ради −20 %
памяти — это ответ, и его надо записать врезкой рядом с ареной.
