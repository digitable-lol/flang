# 0035. Обещания словаря доказаны ядром, и вставка перестаёт обходить словарь

Задача 0020 назвала перебор в `«Найти описание»` самой дорогой строкой дерева:
**874 595 885 витков из 1 000 220 887 (87 %)** при проверке `proof-kernel.flang`,
средний обход 577 элементов.

Словарь подключили. **Ускорения не вышло, и причина оказалась неожиданной.**

Сам поиск подешевел ровно как считали — 22,1 витка на зов вместо 41,5. А общий
счёт вырос:

```
                        витков всего      на зов
лексер, перебор           8 092 531        41,5
лексер, словарь           8 631 340        22,1     +6,7 %
interpret, перебор      323 015 152        19,0     501 с
interpret, словарь    1 000 141 910 ⟵ предел      2415 с, код 1
```

**Разгадка: обещания `flang/stdlib/hashmap.flang` ядро не доказало.**

```
flang/stdlib/hashmap.flang
утверждений 41: доказано 16, сетка 25, объявлено 0
```

Недоказанное обещание едет в напечатанный код **проверкой при работе**. Проверка
у `«Положить в словарь»` зовёт `«Есть ключ в словаре»`, та — `«Звенья словаря»`,
а это обход всего словаря целиком. Каждая вставка обходит всё уже уложенное:
построение на N ключах стоит N²/2.

**Словарь оказался медленным именно потому, что он не доказан.** Это же и есть
довод в пользу всей затеи: доказательство здесь не украшение, а то, что убирает
проверки из напечатанного кода. Дословно из журнала печати: «проверок при работе
снято 3: постусловие доказано ядром обо всех входах — в напечатанный код оно не
едет».

## Что делать

Закрыть 25 обещаний на сетке ядром. Тогда проверки исчезнут, и вставка перестанет
быть обходом.

Мерить не временем, а витками: машина под нагрузкой, время шумит. Готовая
оснастка и три двоичных со счётчиками — в `/srv/flang-rabota/u-slovar-podklyuchenie`.

Второй, независимый ход: обход обёрток (звать `«Вложить»` и `«Искать»` напрямую)
уронил построение на лексере с 3 359 945 витков до 917 754 — **в 3,7 раза**, при
том же ответе байт в байт.

## Как понять, что сделано

```
flang check flang/stdlib/hashmap.flang --proof
утверждений 41: доказано <больше 16>, сетка <меньше 25>
```

и `check --proof flang/self/interpret.flang` со словарём укладывается в предел, а
витков в нём меньше, чем у перебора (база: 323 015 152).

## Чем закрыта

Ветка `u/hashmap-dokazat`, коммит правки — `flang/stdlib/hashmap.flang`.
Прогон, которым снят вердикт (двоичный по абсолютному пути, ключ `--proof`):

```sh
PAMYAT=45G /srv/flang-rabota/vorota/flang-vorota -- \
  /srv/flang-rabota/w-predely/bootstrap/flang check flang/stdlib/hashmap.flang --proof
```

```
было:  утверждений 41: доказано 16 (индукцией 2) (без теоремы 13), сетка 25
стало: утверждений 41: доказано 26 (индукцией 2) (без теоремы 23), сетка 15
```

Знаменатель тот же — 41. Из сетки ушло десять: девять закрыты доказательством,
одно снято как избыточное.

### Поимённо: было сетка → стало доказано

| функция | обещание (как записано теперь) | чем взялось |
|---|---|---|
| «Гнездо» | из пустого списка звеньев выходит пустое место | охрана списана из тела (тело разглажено) |
| «Развести» | кончился путь — разводить негде: выходит то же гнездо из слитых звеньев | охрана списана из тела (тело разглажено) |
| «Вложить» | в пустое место вкладывается одиночка с этим звеном и этим спуском | равенство варианту в охране |
| «Искать» | где признака нет, поиск отдаёт запасное | равенство варианту в охране |
| «Искать признак» | в пустом месте ключей нет | равенство варианту в охране |
| «Положить в словарь» | в пустой словарь кладётся одиночка с этим ключом, значением и хешем | равенство варианту в охране |
| «Есть ключ в словаре» | в пустом словаре ключей нет | равенство варианту в охране |
| «Звенья словаря» | у пустого места звеньев нет | равенство варианту в охране |
| «Звенья словаря» | у грозди звенья — весь её набор | равенство варианту с полями через проекции |
| «Словарь из ключей» | из пустого списка ключей выходит пустое место | охрана списана из тела (тело разглажено) |

Снято без доказательства: «больше из двух не меньше обоих» у «Больше из двух» —
его содержание несут две уже доказанные соседки («больше из двух — одно из
двух» и «выбор идёт по сравнению»), а само оно упиралось в порядок, которого у
ядра нет.

### Что ослаблено — названо прямо

Шесть обещаний вместо утверждения обо всех узлах говорят теперь про ОДНУ ветвь
разбора: у «Гнезда», «Развести», «Вложить», «Положить в словарь», «Есть ключ в
словаре» и «Звеньев словаря». Все шесть прежних записей звали «Звенья словаря»
или `отфильтровать` — то есть ОБХОД ВСЕГО СЛОВАРЯ на каждый возврат, и ехали
этим обходом в напечатанный код проверкой при работе. Ровно та цена, ради
которой задача заведена. Теперь ни одно обещание словаря обхода не содержит.

Пять из десяти новых доказанных говорят про ветвь, где тело отдаёт дно своего
типа, — такие заглушку той же подписи переживают; заглушками это не перемерено.

### Что осталось сеткой (15) и почему

Тринадцать — про арифметику: границы остатка («кольцо неотрицательно», «кольцо
меньше модуля», оба хеша, цифры и сборка пути) и строгие неравенства «Целой
части» (два из них живут в `numbers.flang`, а не здесь). Правила «остаток
отрицательного больше минус модуль» у ядра нет, строгого вида цели над термом —
тоже. Ещё две: «вписанное звено стоит последним» (последний элемент
`добавить X к списку` ядро термом не читает) и «где есть звенья, там есть и
глубина» (граница в общем виде, а не край; максимум для этого был вынут из
«Больше из двух» прямо в тело — не помогло).

Второй ход задачи — обход обёрток при построении — здесь не трогался.
