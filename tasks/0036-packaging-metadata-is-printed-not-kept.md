# 0036. package.json печатается пакетировщиком на flang, а не лежит написанным руками

Замер 24 августа 2026, всё прогоном:

```
package-lock.json           20 строк, зависимостей "resolved" — НОЛЬ
пакет @digitable-lol/flang  https://registry.npmjs.org → {"error":"Not found"}
релизов на GitHub           5, последний v0.6.2 от 22 августа
тегов в дереве              21
работа publish-npm.yml      есть, гоняется на тегах
```

**Пять тегов, пять релизов на GitHub, ноль пакетов в npm.** Половина выпускного
пути не сработала ни разу, а оснастку под неё дерево носит: `package.json`,
пустой `package-lock.json`, `packaging/postinstall.mjs`,
`packaging/flang-launch.mjs`, `flang/bin/flang-lsp.mjs`, `engines: node >= 20`.

Отдельно: **зависимостей у проекта нет вовсе**. `package-lock.json` — двадцать
строк церемонии вокруг пустоты.

## Чего делать НЕЛЬЗЯ сходу

`package.json` сегодня **несущий**, и это записано в коде:

```
docs/site/site-numbers.mjs:180
/** Версия выпуска — из `package.json`, а не из памяти. */
```

Подстановка `{{выпуск.версия}}` на всех 587 страницах сайта читает версию
оттуда. Убрать файл, не перенеся источник версии, значит сломать сборку сайта.

Версия сейчас записана ещё в четырнадцати местах (`changelog.json`,
`CHANGELOG.md`, `docs/site/numbers.json`, `flang/scripts/npm-install.flang`,
три файла библиотеки, шесть в документации). Проверено — **все сходятся на
0.6.2**, расхождения нет. Но сходятся они трудом, а не устройством.

## Что делать

Пакетировщик на самом flang, как всё остальное в этом дереве:

1. **Один источник** — объявление пакета на flang: имя, версия, описание,
   список путей, точки входа. Оттуда же берёт версию сборка сайта.
2. **Цель ярлыка**, печатающая `package.json` из этого объявления. Печать в JSON
   у языка есть (`«Печать JSON»` в словаре поручений), запись файла есть
   (`«Записать файл»`, проверено прогоном).
3. **`package-lock.json` убрать.** Зависимостей ноль; `npm install` напишет его
   заново за секунду, если понадобится.
4. Список `files` (22 пути) **считать из дерева**, а не держать написанным. Он
   сейчас точен — все 22 существуют, — но он ручной, и первая же перестановка
   каталогов его разойдёт молча.

## Решение, которое надо принять до работы

**Нужен ли нам npm вообще.** Каналов доставки уже два — GitHub-релиз с архивом C
и формула Homebrew (`packaging/homebrew/flang.rb`), плюс asdf. Третий канал не
работал ни разу.

Если ответ «не нужен» — задача становится вдвое проще и заодно уносит из дерева
три `.mjs`. Если «нужен» — сперва починить публикацию, потом печатать метаданные.

Отрицательный ответ («npm выкидываем») тоже закрывает задачу.

## Как понять, что сделано

```sh
./ярлык пакет
```

печатает `package.json`, и он совпадает с прежним по смыслу (имя, версия, bin,
files), а версия в нём и версия на собранном сайте берутся из ОДНОГО места.
Проверяется тем, что правка версии в одном файле меняет оба.
