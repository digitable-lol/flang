# 10003 — правильная ось для Г4 найдена, и она даёт удвоение гейта одним приёмом

## Почему пришлось менять ось третий раз

За сутки порядок работ по Г4 пересобирали трижды, и каждый раз замер
опровергал предыдущее:

| задача | ось | что сказала | чем опровергнута |
|---|---|---|---|
| 9989 | по файлам | «43 места неоднородны, общего правила нет» | 9991 |
| 9991 | по формам | «шесть форм поперёк файлов, правило закроет 5–15 мест» | 10001 и 9998 |
| 10001 | по формам, замером | «„равен" это 2 места, а не 15; крупнейшая форма — „не больше"» | — |
| 9998 | по формам, замером | правило закрыло 3 места из 5 — **доля не сдвинулась вовсе** | — |

Причина, по которой ось «форма» не работает, устроительная и названа в
9998: **Г4 считает утверждения записей, дошедших до кода 0, а запись
остаётся кодом 3, пока на слове ядра стоит хоть одно место.** Половина
записи — это ноль.

Подтверждено прямо, прогоном по всем 86 записям: множество записей с
кодом 0 и множество записей с нулём мест на слове ядра **совпадают
поэлементно**, 22 и 22. Сегодняшняя доля — 18 из 240 = 7,50 %.

Есть и вторая причина, помельче: 9991 считала постусловия **в
исходнике**, а места на слове ядра — это **остаток после уже
работающих приёмов** (Ч363, Ч365, Ч369). Числа по этим двум счётам
расходятся в разы. Пример ниже — `forms`: девять постусловий без
теоремы в тексте, а на слове ядра остаётся **одно** место.

## Ответ на главный вопрос: да, такие записи есть, и их десять

**Десять записей стоят ровно в ОДНОМ месте от кода 0** и несут вместе
20 утверждений. Это самая дешёвая работа во всём корпусе, и до сих пор
её никто не называл, потому что считали по формам.

|---|---:|---|
| **forms** | **9** | разбор цели по условию |
| order | 2 | разбор цели по условию |
| poddelka-razbor-vnutrennim | 2 | другое (не razborom_celi) |
| corpus-natural | 1 | разбор цели по условию |
| corpus-natural-ceiling | 1 | разбор цели по условию |
| granica-nad-chislom-chestnaya | 1 | разбор цели по условию |

**Восемь из десяти спотыкаются об ОДИН И ТОТ ЖЕ приём** — ветку отказа
`razborom_celi` (`сверщик.c:2710`, счётчик `razbor_ne_zakrylas`,

## Доли числом

| закрыть | мест | доля Г4 |
|---|---:|---|
| сегодня | — | 18/240 = **7,50 %** |
| только `forms` (одна цель!) | 1 | 27/240 = **11,25 %** |
| восемь записей одного приёма | 8 | 35/240 = **14,58 %** |
| первые пять записей таблицы выгоды | 9 | 45/240 = 18,75 % |
| первые десять | 34 | 81/240 = 33,75 % |
| все 64 незакрытые | 241 | 240/240 = 100 % |

**Одна цель в одной функции удваивает гейт с 7,5 % до 11,25 %.** Это
`forms.запись`: чекер уже переигрывает восемь её утверждений из девяти
(«тождество после переписки» 1, «разбор цели по условию» 7), и остаётся
ровно одно.

## Что именно не закрывается — восемь целей, снятых диагностикой

Снято диагностической копией `сверщик.c` **вне дерева** (печать `chya` и
`cel` в ветке отказа; дерево не тронуто, приём тот же, что у 9998/10001):

```
forms                            «Не больше двух»      не ( ( если н больше 0 то 2 иначе 0 ) больше 2 )
order                            «Прибавить неотриц.»  не ( ( н минус н ) равен 0 ) или ( н не больше ( н плюс добавка ) )
granica-nad-chislom-chestnaya    «Квадрат с оговоркой» не ( ( х минус х ) равен 0 ) или ( ( х умножить на х ) не меньше 0 )
poddelka-ogovorka-o-konechnosti  «Квадрат под оговор.» не ( ( х минус х ) равен 0 ) или ( ( х умножить на х ) не меньше 0 )
corpus-natural                   «Сумма пары»          ( первое плюс второе ) не меньше 0
corpus-natural-ceiling           «Разность пары»       ( первое минус второе ) не больше 9007199254740991
poddelka-nachalo-po-postroeniyu  «Обещает первый знак» ( соединить "аб" с хвост ) начинается с "а"
poddelka-protivorechie           «Не врёт противореч.» 1 равен 2
```

Они распадаются на пять приёмов, и **один из них уже написан**:

| приём | записей в одном месте | несут | состояние |
|---|---:|---:|---|
| **условное по ветвям** — обе ветки замкнутые литералы | 1 | **9** | не написан |
| ложный дизъюнкт снимается — замкнутый под-терм ложен | 3 | 4 | не написан |
| граница по типу — нат неотрицателен / не выше потолка | 2 | 2 | не написан |
| начало по построению — склейка начинается левым куском | 1 | 1 | **готов, задача 9998** |
| невыполнимая посылка — `1 равен 2` под недостижимым условием | 1 | 1 | не написан |

Порядок работ отсюда прямой: **условное по ветвям — первым**, оно одно
даёт 3,75 % и закрывает целую запись. Правило 9998 уже лежит готовым и
закрывает девятую запись — его стоит внести заодно.

Те же формы встречаются и у записей, до кода 0 которым далеко (условное
по ветвям — 15 записей, граница по типу — 10, ложный дизъюнкт — 9,
начало по построению — 6). Доли они не дадут, пока запись не добита
целиком, но правило пишется один раз на все.

## Поправка к 9989: подделочные записи закрывать МОЖНО

9989 записала, что 10 из 21 непокрытых мест сидят в намеренных
`poddelka-*`, и «закрытие их условия ослабило бы чекер, а не усилило».
На оси записей это неверно, и вот замер.

**Подделочная запись — это ЧЕСТНАЯ запись ЛЖИВОЙ программы.** Ложь несёт
`вердикт нет вердикта` и в знаменатель не входит вовсе. По всем 29
подделочным записям корпуса: утверждений 126, числятся доказанными 51,
то есть **75 отвергнутых ядром лжей в знаменателе не участвуют**. Ни
одна подделочная запись не даёт кода 1.

Значит закрыть место в подделочной записи — это дать чекеру
самостоятельно проверить то, что ядро в этом файле доказало ЧЕСТНО,
рядом с ложью, которую оно отвергло. Приёма это не ослабляет. Из десяти
записей «в одном месте» четыре подделочные и несут 5 утверждений.

Оговорка: 9989 считала другим счётчиком (`razbor_ne_zakrylas` в разрезе
«разбора цели по условию»), а здесь — места на слове ядра. Множества
могут не совпадать; утверждение выше относится к оси этой задачи.

## Как понять, что сделано

1. Правило «условное по ветвям» внесено, `forms.запись` даёт код 0,
   доля 11,25 % — прогоном `flang/proof/доля-корпуса.sh --набор корпус`.
2. Правило 9998 внесено, `poddelka-nachalo-po-postroeniyu` даёт код 0.
3. Остальные три приёма — доля 14,58 %.
4. На каждое правило проба порчи, и по находке 9992 она обязана менять
   ЧИСЛО, а не только код: набор проб сверяет код возврата и слеп к
   тихому зачёту.
5. A/B по всем 86 записям: расхождений ноль, кроме тех, что переходят из
   кода 3 в код 0.

## Не сделано

Кода в дерево не писалось — это разбор и порядок работ. Двадцать три
незакрытые цели попали в разряд «прочее» и по формам не разобраны: они
все у записей, до кода 0 которым далеко, и на ближайший порядок работ не
влияют. Рост `сверщик.c` под пять приёмов не оценён — оценивать до
написания значило бы гадать.

## ⚑ СДЕЛАНО 5 сентября: первый шаг взят — `forms` закрыта, Г4 7,50 % → 11,25 %

Порядок работ этой задачи проверен делом на самой выгодной его строке.
Предсказание сбылось знак в знак: **одно место — девять утверждений**.

### Чего не хватало — ровно одного способа из семи

Приём «разбор цели по условию» доходил до конца и спотыкался на последнем
шаге. Печатью в ветке отказа снята точная картина (метка временная, в
дерево не попала):

```
[ПОЛ 0] сырое=<не ( ( если н больше 0 то 2 иначе 0 ) больше 2 )>
[ПОЛ 0] делю по <н больше 0>
[ПОЛ 1] сырое=<не ( ( если да то 2 иначе 0 ) больше 2 )>  сжатое=<не ( ( 2 ) больше 2 )>
[ПОЛ 1] НЕ ЗАКРЫЛОСЬ <не ( ( 2 ) больше 2 )>
```

Деление по условию отрабатывало **верно**: подстановка `да`/`нет`, сжатие
выбора до литерала — всё на месте. А дальше в списке из шести способов
`polovina_zakryta` **не было отрицания**, и замкнутое `не ( 2 больше 2 )`
оставалось незакрытым. Общий счётчик (`ocenit_term`) отрицания тоже не
знает — проверено чтением, поэтому двух ответов на один вопрос не возникло.

### Седьмой способ, и почему он стоит рядом с ямой

`не Х` закрыто, когда **замкнутый счёт дал Х определённую ЛОЖЬ**
(`znach_moya` вернула признак, vid 3, ch 0).

Дверь стоит именно на определённом ответе счёта, а НЕ на отказе
`polovina_zakryta`. Закрыть `не Х` оттого, что Х не закрылся, было бы
ложью: незакрытость здесь значит «не берусь», из неё не следует ничего.
Обратная сторона — `не Х` при истинном Х — есть определённая ложь, но
объявлять ложь этот список не вправе, поэтому там просто идём дальше.

### Проба порчи — и она кусает

`пробы/записи/10003-uslovnoe-po-vetvyam/lozhnoe-otricanie.{flang,запись}`:
запись объявляет доказанными два постусловия, ложных по существу.

* **ветвь нарушает цель**: тело `если н больше 0 то 5 иначе 0`, цель
  `не (результат больше 2)`; после деления остаётся `не (5 больше 2)`,
  счёт говорит «истина», значит цель ложна;
* **правая часть не замкнута**: цель `не (результат больше н)`, после
  деления `не (5 больше н)` со свободным `н` — счёт молчит, и правило
  обязано остаться при «не берусь».

Ложность обеих подтверждена **ядром**, а не рассуждением: у каждой функции
стоит пример, её вскрывающий, и `flang check` даёт
`FLANG_PROPERTY: нарушено свойство`, код 1. Записи ядро при этом не
печатает («ведомость не печатается у программы с замечаниями»), поэтому
запись собрана руками, а отпечатки — настоящие, посчитаны тем же качением
по код-точкам, что и в `сверщик.c:365`.

**Проба проверена на себе.** Правило подменено негодным («закрывать `не Х`,
раз Х не закрылся») — набор покраснел ровно на ней:

```
ПРОВАЛ 10003 отрицание не закрывает ложь — ждали 3, вышло 0
подделок 129: … ПРИНЯТО кодом 0 — 1 (обязано быть 0)
провалов: 1
```

Негодное правило выдало **сертификат лжи**; годное — нет. Проба вписана в
`прогон.sh` сразу, не оставлена сторожить вхолостую: две пробы вида уже
пролежали в дереве незваными, и это нашли только задним числом.
