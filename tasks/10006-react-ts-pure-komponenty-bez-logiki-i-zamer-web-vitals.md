# 10006. React + TypeScript как «пустая» разметка: логика — только в flang

## Мысль владельца (дословно, это спека)

> в `examples/frameworks` нужен ещё один пример на react + typescript, но
> учесть, чтобы не было вообще логики JS, и react был просто dummy components
> вёрсткой; а то сейчас в App.tsx в обычном react-примере там код на JS внутри
> есть; а надо отдельный ещё пример, где есть react + typescript, но кода на
> JS/TS около нуля: просто компоненты объявлены и в них подключается сразу же
> код, какой там нужен, от flang; и нужно произвести в целом замер
> эффективности Web Vitals, посмотреть какая польза и прочее.

## Улика ДО, числом

`examples/frameworks/react-invoice/src/App.tsx` — 75 строк, из них логики на
JS/TS **15 строк** (счёт рукой, строки файла):

| строки | что это | вид логики |
|---|---|---|
| 16–19 | каталог товаров литералом (`const tovary = [...]`) | данные |
| 22–23 | `рубли` — деление на 100 и `toLocaleString` | форматирование и арифметика |
| 26 | `useState<Record<string, number>>({...})` с начальными количествами | состояние и данные |
| 28–32 | сборка корзины: `.filter(... > 0)` + `.map(...)` с `?? 0` | условие, переход состояния |
| 53 | `value={кол[...] ?? 0}` | условие по умолчанию |
| 54–55 | `Math.max(0, Number(e.target.value))` | валидация и разбор ввода |

Текстовый сторож (ниже) на том же файле называет 5 строк из 34 строк кода —
по одной на оператор; рукой — 15, потому что он считает строку, а не оператор.

## Что сделано

- `examples/frameworks/react-ts-pure/` — vite + react 18 + typescript 5 (`strict`).
  - `core/storefront.flang` — товары, корзина, действия (`Больше`/`Меньше`/`Сбросить`),
    редьюсер «Шаг», зажим количества в `[0, остаток]`, сумма, скидка ступенями,
    запись рублей «2 500,00 ₽» с разрядами, строки витрины и итоги — готовые
    к показу записи со строками. 23 функции, 16 обещаний: доказано 10 (из них
    индукцией по «Действие» 2), на сетке 6, не доказано 0. 48 примеров, все проходят.
  - `printed/storefront.js` — напечатан `bootstrap/flang emit … --target js`,
    10 проверок при работе снято доказательством.
  - `src/*.tsx` (4 файла, 36 строк кода) — только разметка, `useReducer(shag,
    nachalnayaKorzina())` и `onClick={() => dispatch(Bolshe({...}))}`.
    Типы выводятся `tsc` из напечатанного JS (`allowJs`), `.d.ts` рукой не понадобился.
  - `scripts/markup-without-logic.flang` — сторож на flang (`flang io`): перечисляет
    `../src`, читает каждый `.tsx`, снимает кавычки и `//`-хвост и ищет приметы
    логики (арифметика, сравнения, `?:`, `if`/`switch`, `.filter/.reduce`, `Math.`,
    `Number(`, `toLocaleString`, `let`, `=> {`, `const` без вызова и т. д.).
    Код 0 с итогом «логики 0 строк: файлов .tsx 4, строк кода 36»; на
    `react-invoice/src` — код 1 и 5 названных строк (подлог проверен).
- `ЗАМЕР.md` в примере и копия сводки в `ПЕРЕДАЧА/zamer-webvitals.md`.

## Критерий приёмки

- `bootstrap/flang check core/storefront.flang` → 0; `--proof` → «объявлено, не доказано 0».
- `npm run build` (`tsc --noEmit && vite build`) → 0.
- `npm run storozh` → 0 и «логики 0 строк».
- Замер Web Vitals: одинаковый сценарий на `react-invoice` и `react-ts-pure`
  (и `vue-roman`), не меньше 3 прогонов, медианы, провенанс.

## Что НЕ сделано и почему

- Сторож текстовый, а не по дереву разбора TypeScript: писать его на flang —
  правило дерева (JS из дерева выводится), а разбор TS на flang — отдельная
  работа. Границы названы в README примера: `//` внутри строк, апострофы в
  тексте разметки, оператор на строке без `{`, `(`, `=`.
- Замер на одной машине без сети и без троттлинга CPU (Lighthouse — со своим
  эмулированным мобильным профилем); полевых данных нет.
