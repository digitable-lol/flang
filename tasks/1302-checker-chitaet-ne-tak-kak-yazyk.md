# 1302. Checker читает исходник иначе, чем язык

**Условие «независимый checker отвергает подделку» 31 августа снято.** Три
подложных файла из пятнадцати получили от него **код 0 «проверено
самостоятельно»** — на файлах, которые `flang check` отвергает поимённым
контрпримером.

## Механизм, найденный чтением и проверенный прогоном

Checker разбирает исходник **не лексером языка, а поиском подстрок**:

- вхождение подстроки без границ слова — строка `второе: нат`, спрятанная в
  хвостовом примечании (а это законный flang), засчитывается за объявление типа;
- поиск блока функции по заголовку — функция-приманка `«Двойник» // функция
  «Знаки»` подменяет настоящую;
- счётчики полноты пропускают двойной пробел, поэтому ложное постусловие
  проходит мимо них.

Плюс он берёт путь и sha256 **из проверяемого объекта** — то есть верит тому,
кого проверяет. Урок записан отдельно: **проверяемое не может заверять само себя.**

## Три оговорки, без которых задача решается не та

1. **Набор проб в дереве зелен:** код 0, «подделок 61 … принято кодом 0 — 0».
   Механизм подтверждён чтением (`сверщик.c:170, :411, :556, :1358, :878`), но
   **adversarial-кейса в дереве нет**. Первая половина работы — написать его.
2. **Готовая починка на +48 строк к ствольной линии НЕ прикладывается** —
   писалась для линии в 2587 строк, а в стволе `сверщик.c` на 1566. В стволе
   есть два изъяна из пяти (`сверщик.c:1351`, `:1358`), `blok_funkcii` нет вовсе.
3. Ведомость, лежащая **в том же дереве**, что и подделка, не спасает: правишь и
   файл, и ведомость — снова код 0. Держит только якорь-коммит, названный
   зовущим; `HEAD` якорем не является.

## Чем закрыта

- adversarial-кейс лежит в дереве и краснеет: код 1, не 0 и не 4;
- все накопленные пробы по-прежнему зелены: 61 подделка отвергнута, честные не
  отвергнуты;
- checker зовут с отпечатком из независимого источника — сегодня из 38 мест так
  делает **ноль**, а 23 берут путь из проверяемого объекта.
