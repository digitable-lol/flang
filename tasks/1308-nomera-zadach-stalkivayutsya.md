# 1308. Семь номеров совпали, и ни один сторож не покраснел

31 августа два коммита завели задачи с **одинаковыми семью номерами**:

| номер | коммит `fc2d24ae` 22:27 | коммит `8756d9a0` 22:42 |
|---|---|---|
| 2072 | most-records-of-the-kernel-carry-no-derivation-trace | sbor-slov-obyavlen-dvazhdy |
| 2256 | the-checker-reads-the-source-differently | checker-chitaet-ne-tak-kak-yazyk |
| 2915 | the-lexer-drops-comments | hod-vyvoda-tri-schyota |
| 3902 | a-file-arrived-without-its-licence-line | perepechatka-bez-kontrolnyh-tochek |
| 4717 | lists-typed-by-hand-in-guards | svodka-vypuska-po-poverhnostyam |
| 6545 | the-name-sbor-slov-is-taken-three-times | spiski-nabrannye-rukami |
| 9790 | the-base-that-must-be-trusted-is-measured-whole | parser-iz-tcb-krugooborot |

Семь совпадений подряд — не случайность. Причина: номера раздаются по
состоянию дерева, а второй клон был снят **до** первого коммита. Обе ветки
считали одни и те же номера свободными и выдали их одинаково.

## Почему это не поймали

Проверка задачника не запускается вовсе:

    ./ярлык задачник:проверка
    # код 3
    # В ОТПЕЧАТКЕ НЕТ ТЕЛА СЕМЕНИ: scripts/otpechatok-semeni

Она отказывается работать, пока отпечаток семени снят прибором старше
31 августа. То есть **весь задачник сейчас не проверяется ничем** — не только
на двойные номера, а вообще. Отказ честный (код 3 — не приговор), но
последствие то же: дефект прожил до 1 сентября и нашёлся глазами.

*Уточнение 1 сентября: отказ приходит не из проверки задачника, а из ворот
сборки двоичного. Разбор — в разделе «Сделано 1 сентября» ниже.*

Разошлось на 1 сентября: файлов 183, различных номеров 176.

## Что сделать

1. Проверка на двойной номер, не зависящая от отпечатка семени. Она стоит
   миллисекунды и не должна стоять за прибором, который может отказать:
   `ls tasks/*.md | sed 's|tasks/||; s/-.*//' | sort | uniq -d` — пусто или код 1.
2. Раздача номера не должна зависеть от того, когда снят клон. Либо номер
   выводится из содержания задачи (тогда две одинаковые задачи получат один
   номер, и это правильно), либо занятость проверяется на свежем `origin/main`
   перед самой записью.
3. Разобрать, почему `задачник:проверка` завязана на отпечаток семени. Проверка
   целостности списка задач и проверка происхождения двоичного — разные вещи, и
   первая не должна падать из-за второй.

**Проверка, без которой работа не сдана:** завести нарочно двойной номер и
показать, что проверка краснеет; убрать — что зеленеет. Сторож, зелёный по
построению, — та самая болезнь, которую здесь лечат (задача 1306).

## Сделано 1 сентября 2026, ячейка Ч181

### Пункт 1 — проверка есть, и обе её стороны показаны прогоном

`scripts/task-numbers-guard.sh`, ярлыки `задачник:номера` и
`задачник:номера-подлог`. Ни двоичного, ни git, ни отпечатка семени ей не нужно.

    sh scripts/task-numbers-guard.sh
    # номера задач целы: задач 189, двойных номеров 0     ← код 0

    sh scripts/task-numbers-guard.sh --подлог
    # сторона первая: НОМЕР 0001 ЗАНЯТ НЕ ОДНОЙ ЗАДАЧЕЙ   ← код 1
    # сторона вторая: номера задач целы                    ← код 0
    # обе стороны показаны прогоном.

Подлог заводится во ВРЕМЕННОЙ копии каталога: дерево, в котором гоняют
проверку, портить нельзя даже на секунду — соседний прогон увидит подлог и
запишет его как находку.

Спрашивается заодно второе: сходится ли номер в шапке с именем файла. Это тот же
разряд лжи, и стоит он тех же миллисекунд.

### Пункт 3 — разобрано, и виновата НЕ проверка задачника

Записано было: «`задачник:проверка` завязана на отпечаток семени». Это неверно.
Проверка задачника про отпечаток не знает ничего и двойные номера ловила всегда
(«Беда о двойнике», `flang/scripts/tasks.flang:548`). Отказ приходил из другого
места, и цепочка такая:

1. на свежем клоне нет `bootstrap/flang`;
2. оболочка `ярлык` идёт его собирать и сперва спрашивает
   `sh scripts/raskrutka.sh --telo` — то ли соберётся;
3. `scripts/otpechatok-semeni` в стволе снят прибором старше 31 августа 2026 и
   блока `# ── тело семени ──` не несёт вовсе;
4. `--telo` отвечает «В ОТПЕЧАТКЕ НЕТ ТЕЛА СЕМЕНИ», код 1;
5. `ярлык` переводит это в код 3 и до проверки задачника не доходит.

**Проверено прогоном: собрать двоичный руками — и проверка работает.**

    make -C bootstrap -j8          # код 0
    ./ярлык задачник:проверка      # код 1 и 52 замечания по делу, потом код 0

Тем же отпечатком заперты ещё двадцать ярлыков — все, что «судят о
доказательствах»: `sh scripts/seed-freshness.sh` отвечает «ОТКАЗЫВАЮСЬ СУДИТЬ,
дело не в отставании: разошлось ТЕЛО СЕМЕНИ», код 1, и ключа обхода тут нет
нарочно. Снимается это одной командой — `sh scripts/raskrutka.sh --otpechatok`,
— но она печатает, и потому не моя.
