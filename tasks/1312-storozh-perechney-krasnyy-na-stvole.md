# 1312. Сторож честен, ведомость отстала

`scripts/hand-written-lists.sh` влит коммитом `04c42222`. Проверено прогоном на
стволе `5822d1df`:

    sh scripts/hand-written-lists.sh          # код 0
    # перечней набрано руками: 214 (целей 57, путей 157)
    # из них расходятся с деревом сегодня: 60 (целей 15, путей 45)

    sh scripts/hand-written-lists.sh --check  # код 1
    # перепись: новых 49, мёртвых записей 0

Без ключа сторож только считает (`[ "$mode" = check ] || exit 0`, строка 264) —
это не изъян, а устройство. Со строгим ключом он **красный на чистом дереве**, и
красный по существу: в ведомости `scripts/hand-written-lists-ledger.tsv`
описано **60** расхождений, а в дереве их **60**. Сорок девять без довода.

**Сторож не сломан.** Он говорит правду: дерево грязное. Но пока это так,
`--check` нельзя привязать к ярлыку и к проверкам дерева — он будет красным
всегда и перестанет что-либо значить. Ровно так уже случилось с
`лицензии:проверка` и `ссылки:проверка`: обе красны давно, и на них перестали
смотреть.

## Проверено отдельно: расхождения НЕ от сегодняшних правок

Задачи 1300–1311, заведённые 1 сентября, среди 49 не встречаются ни разу
(`grep -c 'tasks/13[0-1][0-9]'` → 0). Значит долг старше и его никто не считал.

## Мелочь, которую надо снять заодно

Под `LC_ALL=ru_RU.UTF-8` сторож печатает три жалобы `comm: file 2 is not in
sorted order`. Под `C.UTF-8` и `C` — ни одной. То есть `sort` и `comm` внутри
работают в разных порядках, и на машине с русской локалью вывод будет мусорным.
Лечится заданием `LC_ALL` внутри скрипта, а не снаружи.

## Что сделать

1. Разобрать 49 расхождений: какие вычислимы (заменить перечень командой),
   какие человеческие (вписать в ведомость с доводом, почему остаются).
2. Довести `--check` до кода 0 на чистом дереве и привязать к ярлыку.
3. Задать локаль внутри скрипта.

**Проверка, без которой работа не сдана:** внести нарочное расхождение, не
вписанное в ведомость, — `--check` даёт код 1; вписать с доводом — код 0.
Обе стороны прогоном, а не рассуждением.
