# 1314. Проверяльщик разбирает исходник не так, как разбирает его язык

Ячейка Ч209 напала на работу ячейки Ч201 и пробила её **семью подделками**.
Каждая — законный flang (`flang ast` код 0), ядро отвергает каждую поимённо,
а проверяльщик принимает кодом 0.

| приём | в чём изъян |
|---|---|
| П1 хвост-не-тело | у многострочного `если` берётся последняя строка блока — ветка `иначе`, а не значение |
| П2 минус справа налево | режет по ПЕРВОМУ ` минус `: `5 минус 2 минус 1` читается как 5−(2−1)=4, у языка 2 |
| П3 двойник имени | две функции с одним именем: берётся первая по подстроке, ядро файл отвергает как непрограмму |
| П4 довод по-английски | `accepts х: строка` — язык видит параметр, проверяльщик ищет только `принимает ` и зовёт функцию нульарной |
| П4b довод за табуляцией | то же через `принимает<таб>х` |
| П5 ложь через ссылку | цель ссылается на функцию с многострочным телом — берётся её хвост |
| П6 подстрока за краем | у языка отказ «начало 9 вне строки длиной 5», у проверяльщика тихая пустая строка |

**Порода одна:** проверяльщик перечитывает текст программы своими правилами, а
не сверяет запись с тем, что о программе говорит разбор. Это задача 1302, и
теперь она не подозрение, а семь работающих подделок.

## В стволе они НЕ проходят — проверено старшим

Ч209 мерила ветку Ч201 (проверяльщик 1838 строк). Её в дереве нет. Прогон всех
семи по трём ствольным версиям, отпечаток подавался третьим доводом:

| подделка | до вливания (1566) | половина без починки (2361) | **влито (2412)** |
|---|---|---|---|
| все семь | 3 | 3 | **3** |
| честный образец `00-эталон` | 3 | 3 | 3 |

Команда:

    cc -std=c99 -Wall -Wextra -Werror -pedantic -O2 -o сверщик flang/proof/чекер/сверщик.c
    ./сверщик <исходник> <запись> <sha256 исходника>

**Вывод: влитое этими подделками не пробивается.** Но честный образец тоже даёт
3 — значит ствольный проверяльщик ничего не отвергает и ничего не подтверждает.
Подтверждать станет чем только после пересборки (задача 1311).

## Ветку Ч201 вливать нельзя, и её заявка не в зачёт

Ч201 заявила «подтверждено 0 → 4 записи из 86, 0 → 10 утверждений из 240».
**Заявка держится на самозаверении.** Код 0 даётся только при отпечатке,
поданном третьим доводом (`сверщик.c:1729-1733`), а собранный компилятор строку
`отпечаток256` не пишет вовсе — Ч201 брала отпечаток **с того же файла, который
проверяет**.

Замер Ч209: **без третьего довода все 86 записей дают код 3, зелёных 0 из 86, а
не 4.**

Хуже: сошедшийся отпечаток **портит проверяльщика**. Он понижает сверку поля
«исходник» с беды до приметы (`сверщик.c:1740-1751`):

* подделок Ч19 отвергнуто **30 → 28**;
* лжи Ч40 отвергнуто **3 → 0**.

**Отпечаток обязан приходить извне, а не сниматься с проверяемого файла.**

## Два пути, и цена нужна у обоих

1. **Латать по одной.** Семь дыр закрыть, ждать восьмую. Дёшево за раз, дорого
   всегда: каждая новая возможность языка открывает новую щель.
2. **Сменить подход.** Проверяльщик не разбирает текст сам, а сверяет запись с
   тем, что о программе говорит разбор. Порода закрывается целиком.

Цена второго пути в строках не названа. **Пока её нет, выбирать нельзя** — и это
решение владельца, а не замер.
