## Порча, которая правит дерево, при обрыве остаётся в дереве

Найдено не рассуждением, а происшествием: 29 августа прогон нарочной поломки
оборвался на середине и **оставил порчу в дереве** — в `flang/stdlib/base64.flang`
осталась приписанная теорема «знак азбуки — ровно один знак». Восстанавливать
пришлось руками. В тот же день то же самое случилось с `коды:подлог`: ворота
сняли прогон между «подложил» и «убрал», и подложенный код остался в
`docs/what-blocks-1-0.md`.

Это делит нарочные поломки на два образца, и разница не оттеночная:

* **ПРАВЯТ ФАЙЛ ДЕРЕВА** — `коды:подлог`, `доказанное:порча`, `пустота:порча` и
  прочие: пишут порчу на диск, зовут сторожа, снимают порчу. При обрыве по сроку,
  памяти или воротам дерево остаётся грязным, и следующий, кто посмотрит
  `git status`, увидит чужую порчу как свою правку.
* **ПОДМЕНЯЮТ ЧТЕНИЕ** — `столкновения:порча`: порча подкладывается тем же
  способом, каким сторож уже сверяется с выдуманными деревьями
  (`настройки.читать`), файлы на диске не трогаются вовсе. Оборвать такой прогон
  можно в любой миг, и дерево останется чистым.

**Распространять надо второй образец.** Первый годится только там, где сторож
принципиально смотрит на диск чужой программой (`git grep`, `groff`) и подменить
ему чтение нечем; для таких надо хотя бы назвать в «зачем», что прогон правит
дерево, и какой командой откатывать.

## Что сделать

1. **Пройти оставшихся сторожей нарочной поломкой** — по одному, с записанным
   «чисто → порча → откат». Образец, который стоит распространять, —
   `столкновения:порча`: ключ `--порча` у самого сторожа, порча подкладывается
   ЧТЕНИЕМ, дерево не трогается, и три случая разом проверяют, что краснеет он
   на своём и молчит на чужом.
2. **Назвать отдельно тех, у кого поломка дорога или невозможна** — с причиной.
   Это тоже результат: `раскрутка:проверка` и `точка:проверка` печатают заново,
   `установка:npm` ходит в сеть, `выпуск:проверка` — на GitHub.
3. **Разобраться с постоянно красными.** Либо чинить беду, либо записывать долг
   поимённо — как это сделано у сторожа столкновений, где долг судит только
   первый разряд.
4. **Померить, а не предположить, у кого тесно с пределами.** Известное:
   предел хозяина 1 МиБ (`IO_OUT_LIMIT`), у Node без `maxBuffer` тот же 1 МиБ,
   а исчерпание `--max-orders` отвечает `FLANG_IO_LIMIT` — названной бедой, не
   тишиной, значит запас там вопрос удобства.

### Порча, правящая дерево, поймана ещё раз — на себе

сняли прогон между «подложил» и «убрал», и в дереве осталось

### Что починено и чем показано

**1. Ярлыки 9 и 10 зовутся `bash`, а не `sh`** (`ярлыки.flang`, две строки).
Показано ключом самого сторожа, на цели `c`:

    bash scripts/bad-octet-guard.sh --цель c            → код 0, «красных: 0»
    bash scripts/bad-octet-guard.sh --цель c --порча    → «подложено: rust отказывать перестал,
                                                          обрывает цикл молча»
                                                          «rust | МОЛЧА бросил: код 0, ответов 1 из 2
                                                           | КРАСНО: отказа нет»
                                                          «сторож покраснел (код 1) — порча видна»

Порча подкладывается в рабочую копию прогонщика во временном каталоге, дерева
не трогает — тот самый образец, который велено распространять.

**2. `ключевоеСлово` в `flang/scripts/binary.mjs` больше не путает «слова нет»
с «спросить не удалось».** Ненулевой код возврата и неразборчивый ответ теперь
поднимают беду с названным словом. Показано:

    node flang/scripts/claim-guard.mjs                       → код 1 (две протухшие прозы)
    FLANG_BINARY=<код 1> node flang/scripts/claim-guard.mjs  → БЫЛО код 0 «чисто»
                                                               СТАЛО код 1 «лексер не ответил
                                                               про «символ уже в окне»: код 1»

Той же правкой перестал врать `слово:занятость` (53): при мёртвом двоичном он
печатал «голым именем: 0 — свободно», теперь называет беду.

**3. У `слова:проверка` (23) появилась нижняя граница.** Пропущенная цель — не
пройденная проверка, код 2 (тот же уговор, что в `scripts/bad-octet-guard.sh`,
строка 15).

**4. У `доказательства:ведомость` (42) появилась нижняя граница.** Ни одной
снятой ведомости — отказ кодом 2, а не «расхождений нет».

### Что считается пробой, и почему признак именно такой

Прибор узнаёт два состояния и НЕ путает их:

* **проба построена** — есть парный ярлык `X:подлог`/`X:порча`;
* **проба позвана** — в теле `run:` какого-нибудь workflow вызов сторожа
  стоит В УСЛОВИИ `if`, и в том же теле есть `exit 1`. То есть шаг падает
  ровно тогда, когда сторож промолчал.

В долг идут оба рода. Задача говорит «ПОКАЗАНО, что краснеет» — показывает
прогон, а не наличие: построенная и никем не званная проба не срабатывает
никогда и показывает ровно столько же, сколько её отсутствие.

```yaml
          d = json.load(io.open(p, encoding="utf-8"),
                        object_pairs_hook=collections.OrderedDict)
          d["длина:проверка"] = "подлог: у неё проба показана в ci.yml"
          json.dump(d, io.open(p, "w", encoding="utf-8"),
                    ensure_ascii=False, indent=2)
          PY
          if cmp -s "$podlog.do" "$podlog"; then
            rm -f "$podlog.do"; git checkout -- "$podlog"
            echo "ПОДЛОГ НЕ СОБРАЛСЯ: ведомость уже не той формы — поправить подлог" >&2
            exit 1
          fi
          rm -f "$podlog.do"
          if sh scripts/storozha-bez-podloga.sh --check; then
            git checkout -- "$podlog"
            echo "сверка промолчала на закрытом долге — проверять ею нечего" >&2
            exit 1
          fi
          git checkout -- "$podlog"
      - name: у каждого сторожа проба порчи названа
        run: sh scripts/storozha-bez-podloga.sh --check
```

Защита «ПОДЛОГ НЕ СОБРАЛСЯ» стоит в обоих шагах намеренно: оба подлога
прибиты к форме файла, и если форма съедет, `sed`/`python` смолчат, сверка
честно останется зелёной, а шаг покраснеет с неверной причиной. Ту же
защиту координатор дописал трём подлогам задачи 9220.

## ⚑ 5 сентября: семь «готовых проб» прогнаны — врезать нельзя ни одной, и это не лень

Задача ставилась как самая дешёвая в дереве: семь проб написаны, осталось
позвать. Прогон всех семи пар своими руками говорит другое.

### Две из семи УЖЕ ПОЗВАНЫ — прибор считает их долгом ошибочно

```
столкновения:порча   binary.yml:674   - run: node …link-collision-guard.mjs --порча
слово:подлог         binary.yml:996   - run: node …word-guard.mjs --porcha vse
```

Оба стоят **простыми шагами**, без `continue-on-error`. Простой шаг в GitHub
Actions роняет работу при ненулевом коде — то есть краснота требуется, и
врезка верна. Прибор их не видит.

**Почему не видит — по коду.** `storozha-bez-podloga.sh`, раздел «Признак
пробы»: строка обязана начинаться с `if`/`elif`, в теле обязан быть `exit 1`,
и — главное — `zovy_v_stroke` засчитывает вызов, только если в строке стоит
**имя сторожа** (`X:проверка`) или **путь файла сторожа**. Ярлык
`X:порча` для него не сторож, а простой шаг не начинается с `if`.

Проверено тремя опытами на живом дереве (числа: позвана / построена / долг):

```
как есть                                             8 / 7 / 50
простой шаг «- run: ./ярлык слово:подлог»            8 / 7 / 50   не засчитан
шаг «if ./ярлык слово:подлог; then : else exit 1»    8 / 7 / 50   не засчитан
шаг «if node flang/scripts/word-guard.mjs --porcha
     vse; then : else … exit 1; fi»                  9 / 6 / 49   ЗАСЧИТАН
```

**Годная форма найдена**: звать сторожа ПУТЁМ ФАЙЛА с ключом порчи, внутри
`if`, с `exit 1` в ветке `else`. Она и признаку отвечает, и верна по смыслу —
см. следующий раздел.

### Соглашение о коде у этих проб ОБРАТНОЕ тому, что предполагала постановка

Постановка (и образец в самом приборе) исходит из «испорти вход, позови
сторожа, упади если он смолчал» — там проба возвращает 0 при беде.

Эти семь устроены иначе: они **самодостаточны**. Портят вход у себя внутри,
сами зовут сторожа и сами судят. Читано в коде и подтверждено прогоном:

```
scripts/bad-octet-guard.sh:  «СТОРОЖ СЛЕП: на подложенной тишине он остался
                              зелёным» → exit 1;  иначе «порча видна»
word-guard.mjs:              бед === 0 → exit 0;  иначе exit 1
```

То есть **0 = проба удалась**. Форма `if <проба>; then exit 1; fi` для них
неверна: она уронила бы работу ровно тогда, когда всё хорошо.

### Пять из семи звать НЕЛЬЗЯ: сторож красен сам по себе

Замер 5 сентября, двоичный из dev, прогоны без конвейера:

```
сторож                 код   с    проба               код   с
столкновения:проверка   0     4   столкновения:порча    0    18   ← можно
слово:проверка          1     1   слово:подлог          1     5
октет:проверка          1    11   октет:порча           1    13
поверхности:проверка    1     1   поверхности:подлог    —     —
коды:проверка           1    37   коды:подлог           —     —
спеки:проверка          1    73   спеки:подлог          —     —
```

Причина у каждого — настоящий долг дерева, а не изъян сторожа:

* **слово** — 2 нарушения в `flang/test/fixtures/poddelka-slovo-o-dokazannosti.flang`,
  проза против машины. Проба это ВИДИТ и говорит прямо: «без порчи сторож
  УЖЕ красный (2) — мерить подлогом нечего», при том что все шесть порч
  поймала. То есть проба исправна, а работа «Двоичный» красна по делу.
* **октет** — «красных: 4»; проба при этом печатает «сторож покраснел
  (код 1) — порча видна», её ненулевой код приходит от красноты дерева.
* **поверхности** — «разбивка слотов на странице даёт 76, а прогон — 74».
* **коды** — проза в `tasks/completed/0036-…md` называет код отказа,
  которого в дереве нет ни кодом, ни переменной среды.
* **спеки** — «данное согласие не воскрешается данным ранее» доказано у
  `41-consent-scope.flang`, а в проверяемом месте ослаблено.

**Врезать пару к красному сторожу — значит завести вечно красный шаг**, то
есть шаг, который перестанут читать. Поэтому в `ci.yml` не внесено ничего.
