# 1407. Прослеживаемость в обе стороны

Решение: [ADR-0031](../docs/adr/0031-certification-is-a-process-not-a-property-of-the-language.md).

## Зачем

Стандарты сертифицируемых областей требуют, чтобы по каждому требованию можно
было пройти до кода и до проверки, и обратно. У нас все части уже есть, но
связи между ними нет как предмета: постусловие живёт в коде, пример рядом,
запись доказательства связана с исходником отпечатком — а пройти цепочку одной
командой нельзя.

**Это полезно и без сертификации:** требование, потерявшее код, и код,
потерявший требование, сегодня не видны.

## Что сделать

1. **Померь сперва**, что уже связано и чем: сколько постусловий в наборе,
   сколько из них имеют пример, сколько попали в запись доказательства.
2. Сделай, чтобы цепочку можно было пройти **в обе стороны**: от требования к
   коду и проверке, и от строки кода к требованию, которое её оправдывает.
3. Покажи прогоном оба направления на настоящем примере дерева.
4. **Найди разрывы** — требования без проверки и код без требования. Это и есть
   первая польза: их число сегодня никто не знает.

## Чего не делать

- Не выдумывать форму под воображаемого аудитора: делай то, что полезно нам, а
  подгонка под стандарт — отдельная работа после разговора с ним.
- Не обещать в текстах применимости к медицине, авиации, космосу — решение
  0031 §5.4.

## Как поймём, что сделано

Одна команда проходит цепочку в обе стороны и печатает число разрывов.

## Сделано (11 сентября 2026, ветка r/proslezhivaemost)

Прибор — `scripts/traceability-guard.flang`, четыре плана, четыре ярлыка
(`прослеживаемость:проверка`, `:подлог`, `:требование`, `:строка`), все четыре
зовутся из `.github/workflows/binary.yml`. Набор — три каталога из условия
плюс исходники, которые называют сами записи (два лежат в
`flang/proof/чекер/пробы/семьи/носитель/`): без них две записи из 88 показывали
бы в пустоту.

**Замер (свой прогон, `./ярлык прослеживаемость:проверка`, 87 с, код 0):**

| что | сколько |
|---|---:|
| исходников / записей / функций | 101 / 88 / 414 |
| постусловий | 409 |
| из них с примером у той же функции | 322 |
| из них в записи доказательства | 361 |
| из них с вердиктом «доказано» | 244 |
| без примера / без записи / в записи без «доказано» | 87 / 48 / 117 |
| **разрывов требование → проверка** (ни примера, ни доказанной записи) | **62** |
| **разрывов код → требование** (функций без единого постусловия) | **68** |
| запись → код: записей, называющих требование, которого в коде нет | 0 |

Числа сверены вторым разбором на Python (не в дереве): совпали все до одного.
Оба числа разрывов записаны в `scripts/traceability-debt.tsv`; прибор краснеет,
когда они растут, и просит вписать новое число, когда падают.

Из 62 разрывов первой стороны большинство — намеренно ложные постусловия
подделок (`forgery-*.flang`, `poddelka-*.flang`): у них и не должно быть
доказательства. Честных среди них надо отделить отдельной работой — прибор
этого не различает и не обещает.

**Оба направления на настоящем примере** (`flang/proof/map/abilities.flang`):

```
FLANG_TRACE='У1 сумма читается в обратном порядке' ./ярлык прослеживаемость:требование
требование «У1 сумма читается в обратном порядке»
  код:     flang/proof/map/abilities.flang:29, функция «Сумма наоборот»
  примеры: «два и три»
  запись:  flang/proof/чекер/пробы/записи/корпус/abilities.запись — вердикт доказано

FLANG_TRACE='flang/proof/map/abilities.flang:34' ./ярлык прослеживаемость:строка
строка flang/proof/map/abilities.flang:34 лежит в функции «Сумма наоборот» (объявлена в строке 26)
требование «У1 сумма читается в обратном порядке» …(та же цепочка)

FLANG_TRACE='flang/proof/examples/corpus-alphabet.flang:55' ./ярлык прослеживаемость:строка
строка … лежит в функции «Заглавные» (объявлена в строке 53)
РАЗРЫВ: у функции «Заглавные» нет ни одного постусловия — код без требования   (код 1)
```

Довод передаётся переменной среды `FLANG_TRACE`, потому что у `flang io` нет
ключа для доводов, а поручение «Прочитать доводы» двоичный не исполняет
(долг в `scripts/io-dictionary-copies-guard.flang`); прибор читает переменную
через `printenv`.

**Подлог** (`./ярлык прослеживаемость:подлог`, код 1): из текста
`abilities.flang` в памяти вырезается строка
`обеспечивает «У1 сумма читается в обратном порядке»`; прибор отвечает
«записей, называющих требование, которого в коде нет: 1», называет запись и
строку, и долг «код → требование» растёт с 68 до 69. Если строки в файле уже
нет — отдельный отказ «ПОДЛОГ НЕ СОБРАЛСЯ», чтобы холостую пробу не принять за
зелёную.

Чего нет: `требует` (предусловия) в цепочку не входят — записи их не несут;
теоремы не сверяются отдельно (вердикт записи их уже учитывает); честные
разрывы от намеренных подделок прибор не отделяет.
