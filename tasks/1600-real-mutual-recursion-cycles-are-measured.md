# 1600. Круги взаимной рекурсии дерева переписаны, и потерянные батуты названы числом

Заход перепечатки 26 августа 2026 21:07 умер 27 августа в ~11:44 UTC:

```
пределы: шагов 20000000000, глубины 200000
FLANG_RECURSION_LIMIT: функция «Овеществить» превысила предел глубины вызовов (200000) на глубине 200001
```

Память 0,7 ГБ при 448 ГиБ свободных — стена глубины, не памяти.

Спрошено было: что даёт 200 001 — **длина** одного литерала или **глубина**
вложенности. Ответ прогоном: **ни то, ни другое.** `«Овеществить»` — последний,
кому не хватило кадра, а не тот, кто их копил.

Все числа ниже сняты двоичным `/srv/flang-rabota/w-predely/bootstrap/flang`
через ворота (`PAMYAT=45G`) *— двоичный от 23 августа 2026 16:00 UTC, дерево не
установлено, не новее `883fe9a9`*, на дереве `8f5b37e9`.

## 1. «Овеществить» столько кадров не берёт

**Форму уже сняли соседи** — ветка `u/every-superlinear-named`, `576149cf`,
задача 5732:

| вход | глубина |
|---|---:|
| плоский, 100 элементов | 3 |
| плоский, 1 000 элементов | **4** |
| вложенный на 100 уровней | 101 |
| вложенный на 1 000 уровней | **1001** |
| вложенный на 1 000 уровней, БЕЗ постусловия | **1001** |

Длина не стоит ничего, вложенность стоит `d + 1`, **постусловие ни при чём**.

Здесь это подтверждено независимо и на двух входах, которых там не было. Проба
`reify-probe.flang` **ввозит настоящий модуль** и зовёт настоящую функцию:

```flang
использует «Вычислитель flang» из ".../flang/self/interpret.flang"
```

| что подаётся «Овеществить» | глубина |
|---|---:|
| список из 1 000 скаляров | **4** — сошлось с 576149cf знак в знак |
| список из 10 000 скаляров | **5** |
| запись с 1 000 полями (идёт через «Овеществить поля») | **5** |

Причина видна в коде обеих реализаций: спуск по элементам идёт через
`отобразить`, а `отобразить` — это ЦИКЛ, а не рекурсия. У вычислителя это
`«Кадр шага обхода»`, который перекладывается на каждом элементе
(`flang/self/interpret.flang`, «Шаг тела обхода»); у печати в C это
`for (size_t … ) { … }` (`flang/self/emit-c.flang`, «Печать цикла дальше»).
Кадр берётся на ЯРУС ВЛОЖЕННОСТИ, а не на элемент — и берётся он потому, что зов
стоит НЕ в хвостовой позиции, а не потому, что у функции есть `обеспечивает`.
**Признак «обещание покупает кадр» этот класс не находит в принципе, и круг
`«Овеществить»` ↔ `«Овеществить поля»` — не про обещания.**

**Сколько ярусов есть в дереве на самом деле.** Наибольшая вложенность скобок во
всём дереве — **36** (замер координатора). Здесь то же самое снято по другому
следу: напечатан AST файлов `flang/self/**`, `flang/core/**`, `flang/stdlib/**`,
`flang/conc/**` (`flang ast`), и посчитана вложенность JSON:

```
файлов напечатано и разобрано  38
самый глубокий ЛИТЕРАЛ         30 кадров «Овеществить»
самый глубокий AST целиком     62 яруса JSON — то есть <= 124 кадров,
                               даже если бы «Овеществить» шло по нему целиком
```

Двухсот тысяч ярусов в тексте дерева нет. Значит либо значение такой глубины
собирается во время работы, либо `«Овеществить»` вообще не виновата, а лишь
последняя, кому не хватило кадра — ровно та же ловушка, что названа в задаче
0059. Решающий опыт ставит агент 0003: двоичный с НИЗКИМ пределом, печатающий
всю стопку при упоре. **До его ответа `interpret.flang` в общем дереве здесь не
правится.**

## 2. Кто копил: главный цикл вычислителя потерял батут

`«Прогон»` → `«Виток»` → `«Дальше после шага»` → `«Прогон»` — круг из трёх
звеньев, и каждый зов в нём стоит в хвостовой позиции. Печать в C такие круги
переводит на батут, и в НАПЕЧАТАННОМ компиляторе дерева это видно дословно
(`bootstrap/compiler_flang.c:230994`):

```c
/*
 * Функция flang «Прогон».
 * Взаимная хвостовая рекурсия с «Дальше после шага», «Виток»: вызовы идут через батут.
 */
fl_status compiler_flang_progon(fl_ctx *ctx, fl_value p, fl_value m, …) {
  …
  const fl_status status = fl_trampoline(ctx, compiler_flang_progon_step, args, 2, "Прогон", …);
```

`bootstrap/**` напечатан 23 августа из `58b037c2`. В том дереве у всех трёх
звеньев **не было ни одного `обеспечивает`** — проверено `git show`.

23 августа в 12:26 UTC коммит `ea59db47` «Вычислитель: утверждения о поведении у
158 функций» дописал в `interpret.flang` **156 `обеспечивает`**, и среди них —
по одному на каждое из трёх звеньев круга:

```flang
обеспечивает «прогон витков не теряет» («м».«витки») не больше (результат.«витки»)
обеспечивает «виток тратит не меньше одного шага» ((«м».«витки») плюс 1) не больше (результат.«витки»)
обеспечивает «машина с бедой дальше не идёт» …
```

Дальше работает правило, которое стоит ДОКАЗАННЫМ обещанием в самой печати
(`flang/self/emit-c.flang:1409`):

```flang
// Функция с постусловиями хвостовых вызовов не имеет: интерпретатор тоже не
// переиспользует кадр, которому есть что проверить после возврата.
функция «Хвостовые вызовы»
  обеспечивает «у функции с постусловиями хвостовых вызовов нет» если (длина («функция».«постусловия»)) больше 0 то результат равен пустой список иначе да
```

Нет хвостовых рёбер — нет круга в графе этих рёбер; нет круга — `«Циклические
функции»` (`emit-c.flang`) компоненту не берёт (`длина имён больше 1`); нет
компоненты — батут не печатается. **Главный цикл вычислителя в следующем
напечатанном компиляторе — настоящая рекурсия по стеку хозяина, три кадра на
каждом витке машины.** 200 000 кадров — это ~66 тысяч витков; прогон примеров и
прогоны ядра тратят их на порядки больше.

И `«Овеществить»` зовут именно из вычислителя (`interpret.flang`: узел-литерал,
связывание аргументов) — то есть в момент отказа под ней на стопке лежит ровно
этот круг.

## 5. Перепись кругов: сколько их, почём оборот и КТО платит

Круг — компонента сильной связности графа вызовов. Цена оборота `k` —
наименьшее число платных рёбер на каком-либо круге внутри компоненты (0-1 BFS).
Счёта два, и разница между ними и есть цена ОБЕЩАНИЙ:

* `k` — платит ребро, если зов НЕ в хвостовой позиции **либо** у зовущей есть
  постусловие (так считает вычислитель и так печатает C);
* `k без обещаний` — платит ребро, только если зов НЕ в хвостовой позиции (то
  есть если бы печать сняла все обещания).

```
функций разобрано: 10 408   (flang/self/**, flang/stdlib/**, flang/conc/**)
кругов: 541 — взаимных (звеньев > 1): 171, самовызовов: 370
```

| 1 | 79 | 284 | | 1 | 63 | 116 |

Вторые 199 обещаниями не задеты вовсе — там зов стоит аргументом другого зова

## 6. Можно ли разорвать, не трогая ни одного обещания

Да, и способа три; первый — уже готовый и никакого обещания не трогает.

**(а) Дать функции `пример`.** Снятие сторожа при печати
(`flang/self/bootstrap/compiler.flang:862-892`) требует ДВУХ условий: вердикт
ядра `доказано` (или `доказано при условии`) И `grid > 0`, то есть хотя бы один
`пример` у функции. Снятое обещание не едет в напечатанный код — значит
`«функция».«постусловия»` при печати пусто, значит хвостовые рёбра на месте,
значит батут печатается. Обещание при этом остаётся в исходнике и остаётся
проверяемым у `flang run`, `flang test` и на примерах при `flang check`.

Что мешает сегодня — посчитано:

```
распавшихся групп 30, звеньев в них 77
звеньев БЕЗ примера                 62
групп, готовых к снятию уже сейчас   0
```

Ни одна группа не готова. Но цена входа местами в один `пример`:
восьмизвенной группе `«Описания программы»` не хватает примера ровно у ОДНОЙ
функции; трёхзвенной группе лексера — тоже у одной (`«Читать юникод»`).

**(б) Снять обещание с кольца, не убирая его.** Функция делится на тонкую
обёртку с `обеспечивает` и внутреннее тело без него; в круге остаётся тело.
Текст обещания не меняется, но проверяется оно раз на внешний вызов, а не на
каждом обороте. Для обещаний об итоге это то же самое; для пооборотных
инвариантов — слабее, и это надо называть вслух.

**(в) Разрезать круг явным состоянием.** Образец в дереве уже есть: `«Словарь
описаний»` (10 005 кадров → 13) и коммит `3991810f`, где круг печати литералов
в `emit-c.flang` сокращён с 51 звена до 46 записью-нагрузкой. Дороже (а) и (б),
зато не зависит от вердиктов ядра.
