# 1652 — план выдачи номеров не видел архива

## Улика, с которой всё началось

Работник взял номер планом «Номер» и получил **1306**. Номер занят:

```
tasks/completed/1306-spiski-nabrannye-rukami.md
```

Заметил он это только потому, что проверил оба каталога руками.

Счёт плана подтверждал ту же слепоту дословно:

```
план говорит   «занятых номеров 208»
живых задач    209
в архиве       127
```

## Причина: та же, что чинили у сторожа полгода назад в тот же день

Задача 9990 научила **сторожа** задачника читать `tasks/completed/`: завела
`«Каталог архива»`, шаг `«Ждём архив»`, и постановила, что архив участвует
как набор номеров, на которые позволено ссылаться, а шапки его файлов не
сверяются — «поздно требовать сегодняшних правил от закрытого».

**План той правки не получил.** `«Для номера»` перечислял ровно один
каталог — `«Каталог задач»` — и отдавал список в `«Выдача номеров»`.

## Что сделано

Форма взята у сторожа, не выдумана заново:

* новый ход `«Ждём номера архива» содержит имена: список строки`;
* `«Для номера»` после списка задач спрашивает `«Каталог архива»`;
* новая `«После номеров»` собирает оба списка и зовёт выдачу;
* `«Выдача номеров»` приняла второй довод `закрытые` и считает занятые по
  **обоим** каталогам: `«Занятые номера» от («Слить» от имена и закрытые)`.

**Имена БЕЗ номера берутся по-прежнему только из живого каталога** —
закрытым задачам номера не выдают.

**Отсутствие архива — не беда, а пустой архив.** Ветвь `«Сбой»` в
`«После номеров»` выдаёт номер по одним живым. Правило то же, что у
`«После архива»`: отказ означал бы, что номер нельзя выдать, пока
кто-нибудь не закроет первую задачу.

```
flang check       функций 102, из них с доказанным завершением 102, замечаний нет

```

## Проба в обе стороны, на живом дереве

Заведён файл без номера; план выдал ему **5129**. Затем этот номер положен
в **архив** и план позван снова:

```
НОВЫЙ план   5129 занят архивом → выдал 7061, занятых 337
СТАРЫЙ план  тот же файл в архиве → выдал 5129, занятых 209
```

Старый план выдал занятый номер при том же дереве — то есть проба ловит
именно эту беду, а не что-то другое. Пробные файлы удалены, дерево чисто.

## Проба живёт в дереве примером

Чтобы беда не вернулась молча, у `«Выдача номеров»` заведён пример
«Архив тоже занимает номер: 5152 закрыт, и выдан другой».

Число 1800 в нём **не списано с вывода**: оно уже стоит ожиданием у
`«Свободный номер»` в примере «Номер занят — берётся следующая попытка» с
тем же именем и тем же занятым 5152. Первая редакция примера несла
угаданное число, проверка её отвергла — и это ровно тот случай, когда
пример пишется от разбора, а не от вывода.

Второй новый пример — «Архив считается в занятых, даже когда выдавать
нечего»: он сторожит ветвь без выдачи, где число занятых печатается
отдельно.

## Чего эта правка не делает

* **Гонки не снимает.** Двое, взявшие номер одновременно, получат один и
  тот же: план читает каталог, а не занимает номер. Так было и раньше.
* **Третий каталог не учтён.** Задача 9990 отметила, что номера бывают и в
  `release-versions/` — плану он по-прежнему неизвестен, как и сторожу.
