Независимый чекер `flang/proof/чекер/сверщик.c` (1566 строк, влит 31 августа
коммитом `e8380e2d`) ищет в исходнике **подстроку**, а язык читает **токены**.
Пока это так, запись можно свести с программой, которой она не соответствует, и
чекер досмотрит её до конца.

Места названы поимённо, снято чтением файла:

| место | что делает | чем это ловится |
|---|---|---|
| `сверщик.c:170` | `soderzhit(s,p)` — голый `strstr`, без границ слова | имя, вложенное в другое имя, считается найденным |
| `сверщик.c:411` | обкладывает искомое **одним** пробелом с обеих сторон | двойной пробел в исходнике — и терм «не найден» |
| `сверщик.c:556` | ищет заголовок функции подстрокой `"функция «"` | та же строка в комментарии открывает блок |
| `сверщик.c:1358` | считает постусловия `soderzhit(t,"обеспечивает «")`, отсекая только `//` | `обеспечивает` внутри блочного `/* … */` попадает в счёт полноты |

Пятое — не про чтение, а про привязку: **ожидаемый отпечаток берётся из шапки
самой проверяемой записи** (`сверщик.c:878`, `pervaya_s_nachalom(shapka,
"отпечаток256 ")`), когда третьим доводом он не подан. `ЧИТАТЬ.md` объявляет
третий довод необязательным, и сам же в пункте A9 признаёт, что без него
привязка стоит на свёртке, которую ломают за 0,976 с.

## Чего эта задача НЕ утверждает

Наряд, по которому она заведена, говорит: чекер **пропускал ложь до `exit 0`**
на файлах, которые `flang check` отвергает контрпримером. Я этого прогоном не
повторил: набор проб сегодня зелен —

```sh
sh flang/proof/чекер/пробы/прогон.sh     # код 0
```

```
подделок 61: отвергнуто 59, ушло в третий исход 2, ПРИНЯТО кодом 0 — 0
честных  95: принято (0 или 3) 95, отвергнуто 0
```

То есть механизм в коде я подтвердил чтением, а adversarial-кейс, который через
него проходит, в дереве отсутствует. **Первая половина работы — написать этот
кейс.** Пока его нет, «чекер пропускает ложь» — утверждение без прогона, и
чинить по нему нельзя.

Готовая правка на +48 LOC, по наряду, лежит вне дерева.

## Как понять, что сделано

```sh
sh flang/proof/чекер/пробы/прогон.sh
```

1. Кейс, на котором чекер сегодня даёт **0**, а `bootstrap/flang check` — не 0,
   лежит в `flang/proof/чекер/пробы/`. На чекере ДО правки он даёт код 0
   (доказано прогоном, вывод в теле задачи), ПОСЛЕ правки — 1 или 3.
2. Строка «ПРИНЯТО кодом 0 — 0» держится, и число честных отвергнутых остаётся
   нулём: правка не должна купить строгость ценой ложных отказов.
3. `./ярлык чекер:проверка` — код 0.
4. Отпечаток, поданный третьим доводом, при расхождении с шапкой записи даёт
   отказ, а не молчаливое предпочтение шапки.

## Чем ограничено

Чекер нарочно не собирается вместе с компилятором (`ЧИТАТЬ.md`, врезка «судья,
которого собирает подсудимый»). Правка не должна заводить ни одной зависимости
от `bootstrap/`. Сборка — `make -C flang/proof/чекер`, 1,0 с по замеру, стоящему
в `.github/workflows/binary.yml:748`.
