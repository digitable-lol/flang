# 2573 — отпечаток утверждал неправду, и от этого не собиралось дерево

## Беда

В свежем worktree от `gh/dev` любой `./ярлык` давал **код 3** и не начинал
сборку:

```
СБОРКА НЕ НАЧАТА: тело точки раскрутки не сходится с отпечатком.
В ОТПЕЧАТКЕ НЕТ ТЕЛА СЕМЕНИ: scripts/otpechatok-semeni
```

Обходили это, копируя двоичный из чужого каталога — то есть судили дерево
двоичным, про который не знали, откуда он.

## Поправка к постановке задачи 4672

Там записано: «Строки `коммит` в отпечатке dev нет — значит узнать из него
нельзя». **Строка есть**: `коммит 1eb168da…`. Нет в отпечатке ДРУГОГО —
хешей тела семени (`bootstrap/*.c`), то есть выхода печати.

Причина названа датами и проверена:

```
1eb168da  30 августа   прибор ТЕЛА НЕ УМЕЛ   (0 совпадений TELO_METKA)
22d54485   3 сентября  прибор тело умеет     (8 совпадений)
659d4779   4 сентября  этим коммитом семя пришло в дерево
```

## Главное: отпечаток утверждал ЛОЖЬ, а не просто устарел

Он называл коммит `1eb168da`. Сверка тела семени при том коммите с лежащим
в дереве — **разошлись все шесть файлов**:

Семя после `1eb168da` меняли дважды (`f692bab6`, `659d4779`), отпечаток не
обновляли ни разу.

## Настоящий источник печати найден

Тело семени в дереве **побайтно равно** телу при `659d4779` — все шесть
файлов. А сообщение того коммита говорит, из чего печаталось:

> chore(bootstrap): семя обновлено перепечаткой с 3 сентября 04:06 (**22d54485**)
> Взято из уже завершённой и проверенной печати pechat-dev-2/3… Ручных правок
> с прошлого влития семени не было — взято целиком, без гибридной сборки.

## Как снят новый отпечаток

Не пересъёмом на нынешнем дереве — это ровно то, от чего предостерегают
задача 9611 и zettel «Отпечаток, снятый заново, делает красное зелёным».
Снято так:

```sh
git worktree add --detach <кат> 22d54485      # входы — ВРЕМЁН ПЕЧАТИ
cp bootstrap/* <кат>/bootstrap/               # тело — НЫНЕШНЕЕ, оно и есть итог
sh <кат>/scripts/raskrutka.sh --otpechatok
```

Так законно, потому что `commit_of_tree` выводит коммит по ВХОДАМ печати, а
не по всему дереву: подмена `bootstrap/` его не сбивает, и `коммит` выходит
`22d54485` — тот, из чьих входов семя и печаталось.

## Чем эта починка ОТЛИЧАЕТСЯ от той, что запрещена

Запрещённый ход даёт «отставание 0 файлов» — прибор сверяет снимок сам с
собой. Здесь наоборот, сторож называет настоящее отставание:

```
семя отвечает коммиту 22d54485, и он предок HEAD:
  входов в отпечатке 56, пределы совпали, сводов с тех пор 138
  тело семени сошлось с деревом: файлов 7, байт 39470759

ОТСТАВАНИЕ ВХОДОВ ПЕЧАТИ:
  • flang/self/proofterm.flang
  • flang/self/zapis.flang
  • flang/src/emit/c/flang_repl.c
расхождений 3.
```

Три файла — и они сходятся с независимым прибором
`scripts/chto-otstalo-ot-semeni.sh`, который те же `proofterm` и `zapis`
называл своим счётом.

## Заслон в приборе, чтобы это не повторилось

`raskrutka.sh`, режим `stamp`. Отказ `--bystro` советует позвать
`--otpechatok`, совет выполняют не думая — так дерево и получило отпечаток
с ложным коммитом. Различать честный случай от лжи дёшево:

* семя **правлено в рабочем дереве** → перепечатка только что прошла здесь,
  HEAD правда её источник → пускаем;
* семя совпадает с HEAD, но пришло **раньше** (последним трогал коммит S,
  S ≠ HEAD) → печаталось из входов времён S → **отказ**, с указанием, где
  снимать.

Проба в обе стороны:

```
семя не правлено, HEAD ≠ коммит семени  → код 1, назван 659d4779, отпечаток ЦЕЛ
семя правлено в дереве                  → код 0, отпечаток снят
```

Обхода у заслона нет намеренно: обойти его — снова записать в дерево
неправду. Кому нужен отпечаток для старого семени, тот заводит worktree на
коммите-источнике, и это починка, а не обход.

  была бы перепечатка оттуда с побайтовым сравнением — 7–15 часов. Здесь

* Прочие потребители отпечатка не трогались: `flang/scripts/kernel-forgeries.flang`,

  который старый прибор и так дописывал бы.
