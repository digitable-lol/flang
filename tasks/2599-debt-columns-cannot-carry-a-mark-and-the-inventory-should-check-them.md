# 2599 — прибор «долг» заводить нельзя, и вот чем это установлено

## Откуда задача

Задача 3559 правила числа прозы и наткнулась на то, чего починить не смогла:
**столбцы «долг файлов» и «долг строк» в `docs/tree-inventory.md` не имеют
приметы ни в одной строке таблицы.** Расхождение было видно глазом — в
документе `оболочка 61 | 5 249`, опись давала `94 | 11 276`.

Сегодня у сторожа чисел появился пятый прибор (`примеров-в`, задача 2522) —
ровно потому, что «сторожили то, что умели посчитать». Вопрос был: не завести
ли шестой.

## Ответ: не завести. Долг образцом пути не считается

У сторожа пять приборов, и **все пять считают по образцу пути**:

```
строк       wc -l < файл
файлов      git ls-files -- образец | wc -l
строк-в     cat всех подпавших | wc -l
примеров-в  grep -c '^ *пример «'
список      счёт строк в квадратных скобках
```

Долг определяется не образцом, а функцией `«Довод не-долга»`
(`scripts/tree-inventory.flang:154`) — **правилом из четырнадцати ветвей**, где
у каждого исключения свой довод, а дозволенное основание ровно одно: КРУГ
(файл судит или собирает то, чем его самого пришлось бы исполнять). Шапка той
функции говорит прямо: «„мне так дешевле" доводом не бывает: этим доводом
покрывается любой сторож, и храповик перестаёт держать».

Прибор, считающий долг «по образцу», давал бы **другое** число, чем опись, и
приметы разошлись бы с ней молча. Эта порода за сутки ловилась дважды:
`примеров-в` даёт 2713, а прогон 5302 (задача 3274); опись доказанного
считала обязательства одной формой из двух и врала на 194 строки (1574).
Второе определение одного правила — способ разойтись.

## Проверять таблицу должна сама опись

Она уже делает три четверти работы:

* **считает все четыре столбца** — файлов, строк, долг файлов, долг строк;
* **печатает их этой же разметкой**: вывод прогона дословно содержит
  `| оболочка | 105 | 17110 | 94 | 11276 |`;
* **стоит проверкой на каждый пуш** (`binary.yml`, работа «Опись дерева по
  языкам»), и стоит она 17,7 секунды.

Чего она НЕ делает: не читает `docs/tree-inventory.md` (`grep` по
`tree-inventory.md` в её тексте даёт только упоминания в комментариях).
Таблица переписана в документ рукой, и что копия свежая — не сторожит никто.

**Починка принадлежит описи, а не сторожу чисел.** Ей нужен лад, сверяющий
напечатанную таблицу с той, что лежит в документе, — по образцу
`пакет:проверка`, который сверяет `package.json` с объявлением, его
печатающим. Здесь не сделано: `scripts/tree-inventory.flang` не был в
периметре этой работы.

## Приметы, которые всё-таки стоят, стерегли не то число

Разбор дал побочное, и оно хуже отсутствия приметы.

**Опись считает языком не только расширение, но и шебанг у файла без
расширения.** Таких в дереве ровно четыре, найдены поимённо:

```
ярлык
packaging/asdf/bin/download
packaging/asdf/bin/install
packaging/asdf/bin/list-all
```

Отсюда `101 + 4 = 105` и `16725 + 385 = 17110`.

Примета `файлов *.sh = 101` при этом была **ЗЕЛЕНА**, а столбец рядом означал
105. То есть примета certifицировала число, которого столбец не утверждает.

Проверено по всем строкам таблицы — расходится ровно одна:

```
язык       глоб-ф  опись-ф  глоб-стр  опись-стр
оболочка      101      105     16725      17110   ← РАСХОДЯТСЯ
C              38       38    774066     774066
Python         22       22      7744       7744
HTML            4        4      1226       1226
CSS             1        1       559        559
awk             1        1        79         79
Erlang          1        1        69         69
```

Прочие шесть совпадают потому, что у их языков файлов без расширения в дереве
нет. **Это совпадение, а не правило**, и в документе теперь так и написано.

## Что сделано

* строка «оболочка» приведена к числам описи: `105 | 17 110 | 94 | 11 276`;
* её приметы починены **перечислением четырёх файлов** в образце — теперь
  прибор даёт ровно 105 и 17110, то есть стережёт то число, что написано;
* заголовок: `266 файлов вне flang, долг 74` → `270 и 104`, примета заголовка
  починена тем же перечислением;
* врезка про храповик переписана на замер 5 сентября (104 файла, 13 875
  строк); прежние замеры 29 августа и 1 сентября оставлены следом, чтобы виден
  был ход, но названы прямо тем, чем они являются;
* в документ вписан раздел, почему приметы у долга нет и где починка.

```
сторож чисел ДО   код 0, примет 132
сторож чисел ПОСЛЕ код 0, примет 132
```

## Пробы порчи — обе стороны, и вторая доказывает саму задачу

```
ПОРЧА 1: примета оболочки 105 → 106
  собралась (1 вхождение)
  КОД 1, «tree-inventory.md:46: РАЗОШЛОСЬ С ДЕРЕВОМ — файлов *.sh,ярлык,…»

ПОРЧА 2: число ДОЛГА в прозе 94 → 95
  собралась (1 вхождение)
  КОД 0 — сторож молчит

ОТКАТ: КОД 0
```

Вторая порча — это и есть предмет задачи, показанный числом: **число долга
можно подкрутить, и ни один сторож этого не заметит.** Опись при этом
считает верно; она просто не смотрит в документ.

## Что осталось хрупким, и это названо вслух

Появится **пятый** файл оболочки без расширения — опись насчитает 106,
столбец останется 105, и примета останется **зелёной**: новый файл не
подпадёт под её перечисление. Сторож чисел этого не поймает, он сверяет пути,
а не шебанги.

То есть перечисление делает примету верной сегодня, но той же породы
хрупкости не снимает. Снимет только сверка таблицы самой описью.

## Побочно: план «Номер» выдал ЗАНЯТЫЙ номер

Задача заводилась планом «Номер» дерева, как положено. Он ответил:

```
номера из полосы 1000…9999, занятых номеров было 207
  … → 1306-debt-columns-cannot-carry-a-mark-…md
```

**Номер 1306 занят** — `tasks/completed/1306-spiski-nabrannye-rukami.md`.
Поймал не план, а `задачник:проверка` через pre-push хук: «номер 1306 занят
не одной задачей».

Счёт объясняет причину поведением: план назвал 207 занятых — это ровно число
ЖИВЫХ задач; вместе с архивом их **330**. То есть план выводит номер, не
считая архив занятым, а сторож считает.

Задача 9990 научила сторожа читать архив как набор номеров, на которые
позволено ссылаться. План «Номер» той правки не получил.

Здесь номер взят свободным по обоим каталогам (2599) и выведен из имени, а не
«следующий свободный». Сам план не правился — `flang/scripts/tasks.flang` вне
периметра этой работы.

## Не сделано

* Лад сверки в `scripts/tree-inventory.flang` — файл вне периметра работы.
* Столбцы долга по-прежнему без приметы: заводить прибор «долг» отвергнуто
  выше с разбором, а не оставлено по забывчивости.
* План «Номер» не починен — см. раздел выше.
* Число `долг строк` у Python (2 520) и awk (79) не перепроверялось поимённо —
