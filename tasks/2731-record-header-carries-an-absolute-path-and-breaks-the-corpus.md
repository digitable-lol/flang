# 2731 — запись доказательства не переносима между клонами

## Зачем это понадобилось

Задача 8690 нашла, что записи корпуса протухли: напечатаны 3 сентября
двоичным постарше и не несут привязок `пример строка N`, из-за чего шесть
проверок чекера (`сверщик.c:1199`) не отработали ни разу. Перепечатка всех
86 записей нынешним двоичным даёт Г4 **13,75 % → 17,77 %** без единой
строки в чекере.

Перепечатать нельзя: нынешний двоичный пишет в шапку **абсолютный** путь.

```
записано сегодня:  исходник /srv/tmp/dokazuemyy/AA1-put-v-zapisi/клон/flang/proof/map/abilities.flang
в корпусе дерева:  исходник flang/proof/map/abilities.flang
```

## Где путь становится абсолютным

`flang/src/emit/c/flang_repl.c`, `proof_file`:

```c
base = getcwd(buffer, sizeof(buffer)) == NULL ? repl_say(".") : repl_say(buffer);
full = repl_resolve(base, path);      /* repl_resolve абсолютит ВСЕГДА */
...
args[1] = repl_value_say(full);       /* этот довод уезжает в шапку */
```

`repl_resolve` (:1181) при `path[0] != '/'` приписывает `base` и нормализует
— то есть отдаёт абсолютный путь всегда.

## Почему нельзя просто подставить относительный путь

Второй довод `«Ведомость исходников»` служит **сразу двум делам**:

```
compiler.flang:1688  «Связать исходники» от «файлы» и «вход»
compiler.flang:1701  «Текст входа»: свёртка сличает («файл».«путь») равен «вход»
compiler.flang:1691  тот же «вход» уезжает «путём» в «Ведомость проверенного» → в шапку
```

Поиск идёт **точным равенством строк**, и ключ обязан быть абсолютным:
от него разрешаются импорты (`repl_imports_of(text, bytes, full, &queue)`).
Подменить довод целиком — значит поменять ключи замыкания, то есть трогать
разбор импортов.

Развести два дела в самом flang нельзя дёшево: это правка подписи
`«Ведомость исходников»`, а она вступит в силу только перепечаткой, то есть
через часы. Поэтому правка сделана в C.

## Было ли это намеренно — нет, и дерево само это обходит

`args[1] = repl_value_say(full)` стоит в `proof_file` **с первого коммита**
`check --proof` (`068f4ff1`). Регресса не было: так было всегда.

Обходят это в дереве в двух местах, и оба обхода — улика:

* `zapis.flang`, шапка модуля: «Поле „исходник" — примета для человека, а не
  привязка: путь у записи и путь у сверяющего в разных клонах разные.
  Привязку к ИСХОДНИКУ держит ИМЕННО SHA-256»;
* `доля-корпуса.sh`, `vlozhennost()`: «Строка „исходник" нормализуется: ядро
  пишет путь так, как его позвали, и это не предмет спора» — и строка
  ЗАТИРАЕТСЯ (`sed '2s#.*#исходник —#'`) перед побайтовой сверкой.

Записи корпуса, лежащие в дереве, относительные **с первого своего
коммита** (`e8380e2d`, перенос чекера из временного каталога в дерево) —
значит их нормализовали руками при переносе.

**Одно место обхода не имеет**, и оно ломается: `доля-корпуса.sh`
приписывает к прочитанному пути корень дерева —

```sh
s=$root/$(grep -a -m1 '^исходник ' "$z" | cut -d' ' -f2-)
```

С абсолютным путём выходит `$root//srv/…`, исходник не находится, и доля
считается по нулю записей. Измерено координатором: перепечатанный корпус
без нормализации даёт «0 из 86», после нормализации — «43 из 242».

## Тот же принцип у соседней команды, записанный прямо

`flang tokens` (`f189a9cd`, 20 августа) держит противоположное правило и
говорит его словами:

> Путь едет в ответ ТЕМ ЖЕ, каким его набрали: ключ `file` машинного вида
> обязан совпадать с тем, о чём спрашивали, иначе зовущий не узнает свой
> файл в ответе.

`proof_file` этому правилу не следует. Правка приводит его к тому же.

## Починка

Заведён `proof_head_relative` (`flang_repl.c`, перед `proof_file`): перед
записью байтов строка шапки `исходник …` переписывается путём от рабочего
каталога, посчитанным готовым `repl_relative` (:1226, «путь от каталога
`from` к файлу `to`, оба абсолютные»).

Ключ замыкания остаётся абсолютным — импорты разрешаются как прежде.
Привязка не тронута: её держит SHA-256.

Файл **вне** рабочего каталога даёт путь с `../`. Это хуже пути внутри
дерева, но лучше абсолютного: он переносим между клонами с той же
раскладкой, а абсолютный не переносим ни между какими.

## Как понять, что сделано

1. Запись, напечатанная из двух разных каталогов, несёт одинаковый
   `исходник`.
2. Чекер такую запись принимает.
3. `доля-корпуса.sh` на перепечатанном корпусе даёт долю, а не «0 из 86».

## Не сделано

* Корпус в дереве **не перепечатан** — это измерительный прибор, и менять
  его посреди измерения решает владелец (задача 8690).
* Правка не касается `check` без `--proof`: тот записи не пишет.
