# 3120 — поштучный замер двух самых подозрительных файлов

## Что спрашивалось

Восемь файлов библиотеки отложены «по цене»: внести все четырнадцать —
46,3 часа (задача 6234). Оценка получена усреднением, а задача 3274
показала стократный разброс цены примера между файлами. Значит мерить
надо поштучно. Мерены `aes.flang` и `crl.flang`.

## Сперва то, что рушит постановку

**46,3 часа — это НЕ цена внесения примеров.** Задача 6234 считала цену
ПЕРЕПИСИ ПУСТОТЫ: одна ведомость на голый исходник плюс по одной на
каждую функцию с доказанным утверждением. Шапка сторожа
(`flang/scripts/emptiness-guard.flang`, грабля 2) говорит дословно:
перепись **снимает примеры у обоих исходников** перед подменой тела.
Примеры в счёт 46,3 часа не входят вовсе.

**Примеров, которых не хватает, во всех четырнадцати — 120 функций.**

```
файл             функций  без примеров        файл          функций  без примеров
sqlite               101            30        rsa                43             9
tls                  103            19        aes               105             5
ecdsa                 57            17        math-classics      45             0
tls-handshake         54            17        образцы            31             0
trust-store           22            13        der                34             0
x25519                39            10        automaton          63             0
                                              x509               26             0
                                              crl                32             0
```

**В `crl` — НИ ОДНОЙ.** Вносить туда нечего: все тридцать две функции
уже с примерами, и это сделано в августе приёмом из заметки
`certificates-a-proved-promise-without-an-example-still-costs-a-runtime-check`.
В `aes` не хватает пяти.

## Как мерено

Машина общая: 256 ядер, 27 пользователей, load average 20–35 всё время.
Абсолютные секунды завышены и плавают: два ОДИНАКОВЫХ прогона `aes`
дали 241,3 и 365,0 секунды. Поэтому цена примера всюду взята
**разностью двух прогонов, поставленных рядом и в одном режиме**, и
усилена повторением примера N раз:

```
цена = (прогон с N копиями − прогон основы) / N
```

Одиночная вставка на такой машине не мерит ничего: у `crl` разность на
одном примере вышла ОТРИЦАТЕЛЬНОЙ (−2,2 с при шуме основы 4,2 с).

## Цена одного примера в `aes.flang`

Основа: `./bootstrap/flang test flang/stdlib/aes.flang` — 252 примера
(свои 151 плюс 101 ввезённый из `sha256.flang`), 241,29 и 241,31 с в
быстром режиме, 365,00 с в медленном.

```
функция                копий  с усилением   основа    цена одного
Шаг байта поля            20      369,59     365,00      0,23 с
Шифр GCTR 256             20      299,06     241,30      2,89 с
Расшифровать GCM           5      321,67     241,30     16,07 с
```

**Разброс ВНУТРИ файла — в семьдесят раз**, и это ещё не край: пример на
листовой функции (`Подстановка`) прямым прогоном стоит 2 миллисекунды,
то есть в восемь тысяч раз меньше, чем пример на `Расшифровать GCM`.

## Цена одного примера в `crl.flang`

Основа: 331 пример (свои 59 плюс 272 ввезённых через `x509`), пять
прогонов — 168,53 / 169,94 / 170,13 / 171,39 / 172,77 с, среднее 170,55,
разброс 4,2.

```
функция                                копий  с усилением  основа   цена одного
Знак 16 заглавный                        100     169,32    170,55   0 (шум)
Серийный номер шестнадцатеричным (20 октетов)
                                         100     172,87    170,55   0,023 с
Приговор номеру (данные — вложенная запись)
                                         100     182,80    170,55   0,123 с
```

Первая строка вышла **отрицательной** — цена ниже шума; верхняя граница
40 миллисекунд. **Разброс внутри `crl` — от нуля до 123 миллисекунд.**

**Между файлами: 16,07 с против 0,123 с — в сто тридцать раз.**

## Отчего `aes` дорог: названо одной причиной

**Глубина вычисления под примером, и она берётся из того, что в языке
НЕТ побитовых действий.** `«Исключающее или байтов»` (`aes.flang:132`)
считается свёрткой по восьми разрядам, по четыре `остаток от` на разряд.
Дальше лавина, померенная прямым прогоном (порожняк 11,15 ± 0,15 с
вычтен):

```
Удвоить в поле                    0,9 мс
Байт по номеру                    1,8 мс
Подстановка                       2,1 мс
Шаг разряда поля                   65 мс   ← «Сложить блоки» = 16 XOR = 512 делений
Шаг байта поля                     95 мс
Расширение ключа 128              0,87 с
Зашифровать блок 128               3,5 с
Тег GCM (16 байт)                 18,7 с   ← два умножения в поле GF(2^128)
Зашифровать GCM (16 байт)         28,3 с
Расшифровать GCM (16 байт)        29,3 с
```

Пример на `Расшифровать GCM` стоит два десятка секунд при теле в ТРИ
строки и данных в ШЕСТНАДЦАТЬ байт. Дорога не длина и не данные — дорога
глубина.

### Чего причиной НЕ является — проверено на одну переменную

* **Не постусловия при работе.** Сняты все четыре обещания у
  `«Шаг разряда поля»`: 17,67 с против 18,11 с на сотне вызовов —
  разницы нет. Сняты все шесть у `«Байт по номеру»`: 14,44 против 13,84
  на одном блоке. Толкователь постусловия при работе НЕ считает.
* **Не сборка таблицы подстановки.** Сто сборок 256-элементного литерала
  — 11,19 с против порожняка 11,30, то есть НОЛЬ. Литерал не
  пересобирается.
* **Не длина списка при взятии.** Сто взятий из списка в 16 элементов —
  11,19 с, из 256 — 11,10 с. Одинаково.
* **Не размер данных примера.** В `crl` пример на 20 октетах стоит 23 мс,
  на 4 октетах — в шуме. В `aes` пример на 64 байтах данных
  (`Шаг расширения 256`) стоит 79 мс, а на 16 байтах
  (`Расшифровать GCM`) — 16 секунд.

## Пересчёт 46,3 часов

Правило 6234 — «ведомость × (1 + доказанные)» — считало ведомость на
исходнике С примерами. Перепись гоняет её БЕЗ примеров, и это дешевле.
Замерено обоими исходниками:

```
файл          ведомость с примерами   без примеров   во сколько раз
crl.flang            254,61 с            176,50 с          1,44
aes.flang            390,30 с             74,61 с          5,23
```

Числа 6234 при этом воспроизведены в пределах двух процентов (250 → 254,6
и 383 → 390,3), значит разница «с примерами / без» — не дрейф машины.

Отсюда честный пересчёт для двух померенных файлов:

```
файл        доказано   было (6234)   стало (замер)   счёт
crl.flang         51      3,61 ч        2,55 ч       176,50 × 52 = 9178 с
aes.flang        142     15,21 ч        2,96 ч        74,61 × 143 = 10 669 с
                       ────────      ────────
                        18,82 ч        5,51 ч
```

Для остальных двенадцати правило не проверялось. **Оценка по аналогии,
не замер:** если множитель у них между 1,44 и 5,23, то оставшиеся 27,5
часа превращаются в 5,3–19,1 часа, и всего выходит **11–25 часов вместо
46,3**, из которых замерены 5,5.

Само внесение примеров при этом стоит:

```
crl.flang     ноль — вносить нечего, все 32 функции уже с примерами
aes.flang     около 20 секунд к каждому будущему прогону файла
              (0,095 + 0,079 + 0,037 + 3 + 16 — пять недостающих)
```

## Чего замер НЕ говорит

* Не мерена цена подмены тела заглушкой: перепись строит ведомость на
  ПОДМЕНЁННОМ исходнике, а здесь мерена на целом. Заглушка тело
  упрощает, значит 2,55 и 2,96 часа — верхние границы.
* Двенадцать остальных файлов не мерены поштучно вовсе.
* Абсолютные секунды завышены общей машиной. Сравнения между строками
  честные: все сняты одним двоичным, рядом, в одном режиме.
* Пять недостающих примеров `aes` НЕ внесены — это замер, а не правка
  библиотеки. Три дешёвых (`Шаг байта поля`, `Шаг расширения 256`,
  `Полшага расширения 256`) стоят вместе 0,2 секунды и снимают три
  сторожа при работе в напечатанном коде; внести их стоит того. Два
  дорогих (`Шифр GCTR 256`, `Расшифровать GCM`) добавят к прогону файла
  девятнадцать секунд навсегда, и решать это человеку.
