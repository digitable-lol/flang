# 3380. Девятая цель печати — C++

## Чем измерено

Снято 30 августа 2026 на стволе `f9e67fa6`.

**Целей печати ровно восемь**, все написаны на flang и лежат в `flang/self/`:

```
emit-c  emit-csharp  emit-elixir  emit-go  emit-java  emit-js  emit-python  emit-rust
```

C++ среди них нет. Число «восемь» стоит независимо ещё в шести местах прозы
(`docs/README.md:45`, `docs/overview.ru.md:149`, `:258`, `:279`, `:439`,
`docs/lockfile-without-store.md:84`, `:177`, `docs/HANDOFF.md:103`) — то есть
девятая цель тронет и их.

**Задачи на C++ в задачнике нет ни одной:** `grep -rin 'c++\|cpp' tasks/` — ноль
совпадений. Про девятую цель заведено ровно два довода, и оба **не про C++**:

* `tasks/0029-typescript-target-buys-almost-nothing.md` — **отменена**, довод:
  «JavaScript — синтаксически годный TypeScript, покупать почти нечего».
  На C++ этот довод не переносится: у C++ своя объектная модель и свой ABI, и
  ни в одну из восьми целей он не стирается.
* `docs/wasm-via-c.md` и `docs/HANDOFF.md:111` — «девятая цель печати не нужна:
  наш C собирается в wasm без единой правки, 94 программы из 94, расхождений 0».
  И этот довод не переносится: он держится на том, что **C уже собирается**
  в wasm, а C++ из C сам собой не получается.

**Чем подтверждено, что цель достижима.** Соседнее дерево `/home/m/ouroboros`
держит C++ сквозным путём и проверяет его сборкой `g++`
(`/home/m/ouroboros/ARCHITECTURE.md:88`): общее представление значения через
`operator<<`/SFINAE, полные имена `ns::C::m`, выход с оглядкой на исключения
(`std::uncaught_exceptions`), `capture()` на любой возвращаемый тип, рантайм
заголовком `_cpp/ouroboros_runtime.hpp`. То есть механизм не выдуман: он
написан и проверен на другом дереве.

## Что сделать

1. `flang/self/emit-cpp.flang` — цель печати на flang, как остальные семь.
2. `flang/src/emit/cpp/` — рантайм цели. Он уезжает в вывод **дословно**
   (`AGENTS.md`), значит пишется один раз и правится только вместе с целью.
3. Занятые слова цели: `слова:проверка` и `занятые:проверка` (ярлыки 24 и 23)
   считают, сколько модулей столкнулось бы с именами, занятыми целью. Для C++
   список занятых слов больше, чем у C, — его надо снять прогоном, а не
   переписать из C.
4. Пересчитать восьмёрку в семи местах прозы, названных выше, — их сверяет
   `подсчёты:проверка` (ярлык 5).

## Как понять, что сделано

```sh
./ярлык печать:проверка      # числа прозы о печати перемерены прогоном ДЕВЯТИ целей
./ярлык закон:проверка       # печать не печатает того, что проверка того же двоичного отвергает
```

и корпус целиком:

```sh
flang emit <каждая программа корпуса> --target cpp | g++ -x c++ - && ./a.out
```

Число, при котором задача считается сделанной: **столько же программ проходит
на `cpp`, сколько сегодня проходит на `c`** — не «почти столько же». Сегодня на
`cpp` проходит ноль из них, потому что цели нет.

## Замер 30 августа 2026 (исполнитель b): довод «C++ не стирается» не подтвердился на коде

Довод шапки — «у C++ своя объектная модель и свой ABI, и ни в одну из восьми
целей он не стирается» — проверен прогоном. На половине КОДА он неверен, и это
меняет цену задачи в четырнадцать раз.

**Что сделано.** 114 программ корпуса напечатаны в цель «c»,
вывод переименован и переписан по правилам `flang/self/emit-cpp.flang`
(`.h→.hpp`, `.c→.cpp`, три замены включений, свой Makefile, плюс лицо цели
`flang_cpp.hpp`), собран **своим** Makefile под
`g++ -std=c++20 -Wall -Wextra -Werror -pedantic -O2`, и прогнан через ту же
сетку запросов, что и прогонщик цели «c», с побайтовой сверкой ответов.

```
examples/leetcode   программ 82: напечаталось по правилам cpp 82, собралось
                    своим Makefile 82, ответы сошлись с целью c 82, точек 900
flang/stdlib        программ 21: … 21, … 21, … 21, точек сетки 1842
flang/stdlib добор   программ 5: …  5, …  5, …  5, точек сетки 492
flang/stdlib добор2  программ 6: …  6, …  6, …  6, точек сетки 1446
───────────────────────────────────────────────────────────────────────────
всего              114 из 114, расхождений НОЛЬ, точек сетки 4680
```

Сборка идёт **своим** Makefile цели:
`g++ -std=c++20 -Wall -Wextra -Werror -pedantic -O2 -flto`.

900 точек сетки у leetcode — это 407 досчитанных значений и 493 объявленных
отказа: сверка не вхолостую, обе половины ответа задеты. Расхождений ноль.

**Знаменатель назван честно.** Корпус — 124 файла; ДЕСЯТЬ из них не печатаются
И В ЦЕЛЬ «c»: `aes`, `crl`, `hmac`, `kdf`, `postgres`, `scram`, `sha1`,
`sha256`, `tls`, `tls-handshake`. Все десять — один и тот же отказ
`FLANG_RECURSION_LIMIT` внутри САМОГО компилятора («Поле знач по ключу»,
«Дальше после шага»), и он остаётся при пределе глубины 200 000, поднятом
ключом `--предел-глубины`. Ни один из десяти не потерян из-за C++: цель «cpp»
получает уже напечатанное, и печатать ей нечего там, где нечего печатать и цели
«c».

Добор — тот же прогон с `--предел-глубины 200000` вместо вшитых 20 000: он
вернул 11 файлов из 21 (`datetime`, `der`, `ecdsa`, `json`, `numtree`, `redis`,
`sqlite`, `trust-store`, `utf8`, `x25519`, `x509`), и все 11 проходят на «cpp»
так же, как на «c».

**Единственное, что расходится у C и C++ по существу**, — назначенный
инициализатор (`{ FL_STRING, { .string = { … } } }`), которым печатается всякая
текстовая постоянная (`emit-c.flang:2145–2146`). Замер:

| стандарт | собралось из 82 |
|---|---:|
| `cc -std=c99` | 82 |
| `g++ -std=c++17` | **65** |
| `g++ -std=c++20` | 82 |

Все 17 упавших под C++17 упали с одной и той же строкой:
`error: C++ designated initializers only available with -std=c++20`. В C99
инициализатор законен, в C++17 — расширение, в C++20 снова законен. Поэтому цель
объявляет C++20, а не гасит предупреждение ключом.

**Отсюда цена.** Новых строк **750**, а не 10 277, которыми цену девятой цели
называет `docs/cost-of-extension.md`:

| что | строк |
|---|---:|
| `flang/self/emit-cpp.flang` | 322 |
| `flang/src/emit/cpp/flang_cpp.hpp` (лицо цели) | 404 |
| `flang/self/bootstrap/compiler.flang` (точка входа) | +26 |
| `flang/src/emit/c/flang_repl.c` (строка таблицы целей) | +38 |

Рантайм НЕ копируется: `flang_runtime.h`, `flang_runtime.c` и `flang_cli.c`
читаются из каталога цели «c». Копия совпадала бы с подлинником байт в байт, и
правка одного из двух прошла бы незамеченной.

**Занятые слова цели сняты, а не переписаны с C:** заголовков стандартной
библиотеки C++, у которых нет расширения и потому нет различия с именем нашего
файла, — **72**. Вместе с 44 именами цели «c» занято именем модуля **116**.

### Чего этот замер НЕ говорит

Он снят на цели «c», собранной как C++, и на правилах цели «cpp», применённых к
её выводу отдельной программой, — **не на `flang emit --target cpp`**. Этой
команды сегодня нет ни у одного двоичного дерева и не будет до перепечатки:
точка входа «Напечатать связанное в C++» живёт в замыкании `compiler.flang`, а
замыкание доезжает до двоичного только через `bootstrap/compiler_flang.c`.
Перепечатка — 5 ч 30 мин и пик 259 ГБ (задача **6411**).

Правила цели применены к выводу «c» ОТДЕЛЬНОЙ программой, переписанной из
`emit-cpp.flang` буква в букву. Расхождение между этой программой и эталоном
сегодня ловится глазами; настоящая сверка появится ровно тогда, когда двоичный
узнает цель «cpp».

## Что от неё зависит

Ничего. Это лист: ни одна другая задача за девятой целью не стоит, и потому её
можно брать в любой день. Обратное неверно — она сама ждёт, пока `emit-c`
никто не переписывает, иначе рантайм придётся сводить дважды.
