# 3401. Команда, которой делают пакеты, мертва с 29 августа 2026

Замер 8 сентября 2026 на `gh/dev` `5f679521`, двоичный собран в дереве
(`make -C bootstrap -j8`, `bootstrap/flang` 0.7.14). Окружение:
`env -u FLANG_MODULE_DIR LC_ALL=C.UTF-8`.

## Что видно

```
$ bootstrap/flang package docs/examples/package/discount.flang
FLANG_TYPE: функция «Прогоны для ядра» принимает 2 аргум., получено 1
flang package: отчёт о доказательствах не посчитался
код возврата 1
```

Это не свойство примера. Тот же отказ на пакете, который двоичный **сам только
что создал** и который проходит `check`:

```
$ bootstrap/flang new проба                 # код 0, 9 файлов
$ cd проба && ../bootstrap/flang check проба.flang   # код 0, замечаний нет
$ ../bootstrap/flang package проба.flang
FLANG_TYPE: функция «Прогоны для ядра» принимает 2 аргум., получено 1
```

То есть **создать пакет сегодня нельзя вообще ничем**, и вся история «человек
пишет свой пакет и делится им» упирается сюда.

## Причина названа точно

Ведомость доказанного считает C-оболочка, `flang/src/emit/c/flang_repl.c`
(в семени — `bootstrap/flang_repl.c`, сдвиг +9 строк шапки), функция
`pkg_ledger`:

```c
/* bootstrap/flang_repl.c:16008 */
if (repl_call("Прогоны для ядра", &program, 1, &runs) != FL_OK) {
```

А в компиляторе у функции два довода:

```
flang/self/bootstrap/compiler.flang:1138
функция «Прогоны для ядра»
  принимает «программа»: «Значение», «обязательства»: список «Значение»
```

Археология (`git log -S`): команда `package` приехала 19 августа 2026
(`c5c53a3d`), второй довод добавлен 29 августа 2026 коммитом `1a5f81a5`
(«перф(ядро): прогоны для ядра сужены до функций под термом»). Коммит правил
**ровно один файл** — `flang/self/bootstrap/compiler.flang`; C-вызов не тронут.
До него сигнатура была одноместной (`git show 1a5f81a5^`).

Почему никто не заметил: пакетов в дереве восемь, и все собраны ДО 29 августа —
лежат готовыми файлами, `check` их читает, а собирать заново набор проверок
никому не велит.

## Починка проверена прогоном, а не рассуждением

Копия `bootstrap/` в каталоге вне дерева, одна правка (`args[0] = program;
args[1] = obligations;` и вызов с `args, 2`), `make -j8`:

```
$ pochinka/flang package проба.flang
код 0
{"схема":2,"имя":"проба","версия":"0.1.0","вход":"./проба.flang","модули":[…],"печать":"…"}
```

и собранный так пакет **сразу ввозится** чужой программой (`использует «проба»
из "proba.flang-package"`): `check` видит два файла и обе функции.

## Что сделать

1. Правку внести в **источник** `flang/src/emit/c/flang_repl.c` (руками
   `bootstrap/*.c` не трогать — отпечаток прочтёт это как подлог).
2. Доставить быстрым пересевом `sh scripts/semya-osvezhit.sh`: `flang_repl.c`
   не печатается из `flang/self`, а копируется в семя дословно (заслон
   `scripts/semya-rantayma-eto-istochnik.sh`; `diff` источника и семени — ровно
   9 строк шапки). Полная перепечатка **не нужна**.
3. Завести сторожа, которого нет: `flang new` во временном каталоге →
   `flang package` → код 0 → ввоз получившегося пакета чужой программой. Место —
   набор проверок дерева, ярлыком (проверка, которой нет в списке ярлыков, тихо
   мертвеет).

## Приёмка

- `flang new x && cd x && flang package x.flang` — код 0, на выходе JSON схемы 2
  с непустой ведомостью;
- получившийся файл ввозится: `использует «x» из "x.flang-package"` →
  `flang check` код 0;
- ведомость собранного пакета сверена не на одном примере: пересобрать все семь
  пакетов `scripts/registry-example/` и сличить ведомости с тем, что в них
  записано сегодня, — сужение прогонов 29 августа могло изменить приговор на
  пакетах с теоремами (**не проверено**, это часть работы);
- новый сторож краснеет, если правку откатить.
