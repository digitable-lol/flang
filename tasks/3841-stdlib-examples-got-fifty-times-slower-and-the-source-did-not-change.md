# 3841 — сорок четыре минуты из пятидесяти, и виноват не тот, на кого думали

## Как найдено

Владелец спросил прямо: «какого хрена там идет сборка двоичного 49m».
Работник HH1 (задача 6163) разобрал прогон `33895656055` по шагам и
опроверг постановку — **сборка ни при чём**:

```
Собрать точку раскрутки       4 мин 18 с
Проверки на flang (180 штук)      35 с
Примеры stdlib и ядра        44 мин 07 с   ← шапка того же файла обещает 53 с
Опись дерева по языкам            22 с
```

Сорок четыре минуты из пятидесяти даёт один шаг — `binary.yml:318`,
`./bootstrap/flang test flang/stdlib/` и `flang/core/`.

## Обещание датировано, и это решает вопрос

`binary.yml` в шапке (строки 15-16, 37):

```
flang/stdlib   42 файла, 1216 примеров, прошли все    40 с
СНЯТО 2026-08-31 файлов flang/stdlib/*.flang = 42
примеры stdlib и ядра, 1445 штук                      53 с
```

Замер снят **31 августа**. Значит искать надо то, что менялось после.

## Исходники ни при чём — проверено историей

**В `flang/stdlib/` с 31 августа ровно ОДИН коммит**, и тот про
комментарии:

```
49ae5fbb  2026-09-02  чистка(stdlib): журнал вынесен из комментариев, кода не тронуто
```

Первый подозреваемый — `aes.flang`, самый медленный по обходу. Его правки
все **старше** замера:

```
412d0e9a  2026-08-30  proof(aes): тег GCM обеих длин ключа доказан
900f98ef  2026-08-30  proof(aes): двенадцать обещаний о длине доказаны
326dce24  2026-08-26  test(aes): все 209 доказанных обещаний снимают проверку при работе
91ab7281  2026-08-24  proof(aes): AES-128 и AES-256 доказаны 209 обещаниями из 337
```

То есть замер в 40 секунд ЭТОТ ЖЕ ФАЙЛ в этом же виде уже включал.

## Семя менялось дважды — и ОКАЗАЛОСЬ НИ ПРИ ЧЁМ

```
f692bab6  2026-09-03  Семя bootstrap/ обновлено перепечаткой с 30 августа на 3 сентября
659d4779  2026-09-04  chore(bootstrap): семя обновлено перепечаткой с 3 сентября 04:06
```

Гипотеза была: замедлило семя. **Опровергнута замером A/B** — собрано
семя, каким оно было ДО обеих перепечаток (`638a0853`, `flang 0.6.2`), и
те же файлы прогнаны обоими двоичными на одной машине, в одну минуту:

```
файл             СТАРОЕ семя (0.6.2)   НОВОЕ семя (dev)
base64.flang            20 с                 23 с
aes.flang           медленный, >300 с    300 с, код 124
```

Обычный файл идёт одинаково. `aes.flang` медленный на ОБОИХ. Значит
регресса в двоичном нет, и чинить `flang/self/**` не за что.

## Что это значит на самом деле

`aes.flang` — выброс, и он был выбросом всегда. А обещание «42 файла, 1216
примеров, 40 с» **не воспроизводится ни на одном семени**: рядовой файл
берёт двадцать с лишним секунд, и сорока на все сорок два не хватит при
любом двоичном.

То есть беда не «стало медленно», а **«число 40 с в шапке не отвечало
дереву»** — порода, которую в этом дереве ловят весь день: примета,
которую никто не переснимал.

## Подозреваемый в `aes.flang`, названный, но НЕ доказанный

Таблицы подстановки — списки на 517 чисел (прямая и обратная вместе).
Поиск по ним идёт через `«Байт по номеру»`, а та берёт `элемент номер в
байты` — то есть **обращение по номеру к списку**.

У дерева уже есть замер ровно этой породы:
`docs/zettel/a-hash-dictionary-cheapens-the-lookup-and-the-building-costs.md`
и предшествующий ему `linear-lookup-of-a-declaration-eats-88-percent-of-check-loops.md`
— линейный перебор в `«Найти описание»` съедал **88 % витков** проверки, и
чинили его словарём `flang/stdlib/hashmap.flang`.

Плюс `«Байт по номеру»` несёт **шесть постусловий**, и непроказанные из них
проверяются при каждом вызове.

**Почему не чиню.** Гипотеза не доказана: профилировщика у меня нет, а
переписывать криптографический примитив, у которого 209 доказанных
обещаний из 337, ради непроверенной догадки — риск больше выигрыша. Все
209 доказательств пришлось бы проводить заново.

Чтобы гипотезу проверить, нужен замер шагов на одном вызове поиска против
одного вызова без поиска. Это отдельная работа.

## Что делать с шагом CI, пока не починено

Шаг `binary.yml:318` идёт 44 минуты и **не имеет своего срока**. Пока
причина не найдена, предлагаю не прятать беду, а сделать её видимой и
ограниченной. Врезка (файл не мой, ставит координатор):

```yaml
      - name: Примеры stdlib и ядра
        # ЦЕНА ЭТОГО ШАГА ИЗМЕРЕНА И ОНА ВЕЛИКА: 44 мин из 50 у всей работы
        # (задача 6163), при обещанных шапкой 53 с. Обещание не
        # воспроизводится ни на нынешнем семени, ни на семени до перепечаток
        # сентября (задача 3841) — то есть примета в шапке была неверна, а не
        # дерево замедлилось. Срок поставлен, чтобы работа падала по сроку с
        # понятной причиной, а не висела час.
        timeout-minutes: 55
        run: |
          set -eu
          ./bootstrap/flang test flang/stdlib/
          ./bootstrap/flang test flang/core/
```

**Разбивать шаг на файлы не предлагаю**: это спрячет цену в двадцати
строках вместо одной, а суммарные минуты раннера не изменит.

**Исключать медленные файлы НЕЛЬЗЯ.** `aes.flang` — 151 пример на 105
функций, и это единственная проверка криптографии в дереве. Убрать его из
шага значит перестать проверять AES вовсе, а выигрыш — те же минуты, что
уйдут в следующий раз.
