# 3902. Сторож лицензий снова зелен — файл первой волны приехал без своей строки

Первая волна 31 августа погасила зелёного сторожа, и никто этого не заметил.

```sh
bootstrap/flang io scripts/license-guard.flang
```

```
код возврата 1
нарушений лицензионной разметки: 1 на 78 просмотренных файлов:
  · flang/scripts/direct-run.mjs: нет SPDX-License-Identifier в начале файла
```

Файл заведён сегодня коммитом `ab1150b8` («вопрос «меня запустили напрямую?»
задаётся разрешённым путём»), 53 строки. Его сосед по той же работе,
`flang/scripts/direct-run-guard.mjs`, строку несёт — вторая строка файла:

```
#!/usr/bin/env node
/* SPDX-FileCopyrightText: 2026 Digitable (Marat Zimnurov) */
```

а `direct-run.mjs` начинается сразу с блочного комментария о деле.

Правка — одна строка. Заводится задача не ради неё, а ради второго вопроса:
**почему это доехало до ствола.** Сторож лицензий стоит в ярлыках, работает и
краснеет по делу — значит между «ячейка написала файл» и «файл в стволе» его
никто не позвал.

## Как понять, что сделано

```sh
bootstrap/flang io scripts/license-guard.flang    # код 0
```

1. Прогон даёт код 0 и «нарушений 0 на 78 просмотренных файлов».
2. Названо, на каком шаге сторож должен был сработать и не сработал: ярлык есть
   ли в наборе, который гоняется на вливании, или он гоняется только в CI после.
3. Проверено, что краснеет: строка снимается обратно — код 1 с именем файла;
   возвращается — код 0.

## Чем ограничено

Сторож смотрит 78 файлов, а не всё дерево. Расширять его охват — не эта работа:
здесь чинится один файл и один пропущенный шаг. Расширение охвата — предмет
задачи о перечнях, набранных руками.
