# 4025. Ствольный компилятор печатает программу, молча выбросив конкурентность

## Чем измерено

Снято 29 августа 2026 на стволе `5f1078e1`. В закоммиченном семени
`bootstrap/compiler_flang.c` нет ни одного из трёх движков:

```

    printf '%s: ' "$s"; grep -ac "$s" bootstrap/compiler_flang.c; done
fl_conc_plan: 0
fl_conc_process: 0

```

Символа печати конкурентности в C там тоже нет — а для трёх других целей есть:

```
$ grep -ao 'compiler_flang_[a-z_]*konkurentnost[a-z_]*' bootstrap/compiler_flang.c | sort -u

```

`compiler_flang_pechat_konkurentnosti_c` — **ноль вхождений**.

**Причина названа временем двух коммитов, и она сходится до минуты:**

```
$ git log -1 --format='%H %ci %s' 9b4f5307
9b4f5307 2026-08-23 02:03:31 +0000 Печать в C кладёт в вывод движок процессов: два процесса живут без единой строки руками

$ git log -1 --format='%H %ci %s' -- bootstrap/compiler_flang.c
58b037c2 2026-08-23 00:20:28 +0000 Слияние ветки u/bez-javascript-3 в main
```

Печать конкурентности в C легла в исходники на **1 ч 43 мин 03 с ПОЗЖЕ**
последнего коммита в семя. Семя её просто не застало.

**Что теряет собранная служба.** Владелец 29 августа: пять поручений из
двадцати — «Показать», «Ждать событие», «Перечислить каталог», «Запустить
процесс», «Запустить процесс с вводом». Рабочая копия с разбором —
`/srv/flang-rabota/m-network-and-processes`.

## Почему это тише всех прочих бед

Компилятор **не отказывается**. Он печатает программу, и напечатанное собирается
и работает — только без процессов, надзора и прогонов. Программа, которая на
входе объявляла службу под надзором, на выходе становится программой без
надзора, и никакой строки об этом не печатается.

## Что сделать

Перепечатать семя (0003). Отдельной правки эта задача **не требует вовсе** —
исходники правильные с 23 августа. Требуется только, чтобы семя их застало.

До перепечатки — поставить заслон: печать в C, не нашедшая в себе движка
процессов при том, что программа их объявляет, обязана **отказаться**, а не
напечатать половину. Молчаливая потеря половины программы хуже отказа.

## Ведомость держит не отсутствие судьи, а одно слово в строке 1722

Замер соседа по задаче 7205 (срез `flang/core` + `flang/conc`, 29 файлов):
18 файлов помечены крестом, из них 17 — код 2 и «ведомость не печатается … —
processes, supervisors, runs», 68 обязательств. Улика подтверждена здесь тем же
вызовом на своём двоичном: из 19 файлов среза с объявлением
`процесс`/`надзор`/`прогон` этот отказ дают 15 (у `budget.flang` — после
`--предел-глубины 400000`), а `file-read.flang` и `host-io-survey.flang` не
доходят до него, упираясь раньше в `FLANG_MATCH_NOT_EXHAUSTIVE`. Отказ приходит
за 0,25–0,36 с при пике 19–84 МБ: ни срок, ни память ни при чём.

**Вшивать `flang/self/setoid-oracle.flang` некуда — он уже вшит, и он тут ни при
чём.** Измерено тремя способами:

* `flang/self/bootstrap/compiler.flang:30–31` — `использует «Оракул категорий»`
  и `использует «Законы категории»`, то есть `setoid-oracle.flang` и
  `setoid.flang` в замыкании стоят;
* `grep -acE '^(функция|тотальная функция)'` по ним даёт 88 и 176, вместе 264 —
  ровно то число, которое двоичный печатает о себе в самом отказе;
* `grep -acE 'процесс|надзор|прогон'` по `setoid-oracle.flang` даёт **0**.
  Правил о процессах в нём нет ни одной строкой, и открыть ими 68 обязательств
  нельзя ни одного.

**Судья процессов тоже уже вшит.** `использует «Проверка процессов»`
(`compiler.flang:14`) — это `flang/self/processes.flang`; `grep -ac
FLANG_HANDLER_NOT_TOTAL bootstrap/compiler_flang.c` даёт 2. Прогон это
подтверждает: `check` БЕЗ `--proof` на том же `counter.flang` печатает не
«не судит вовсе», а «объявления эти сверены **НЕ ДО КОНЦА** — processes,
supervisors, runs: сверено, что имена сходятся…» и отвечает кодом 2.

**Тогда почему ведомость всё-таки отказывает.** Потому что она спрашивает не тот
список. `«Что бинарник не судил»` (`compiler.flang:1751`) берёт
`«Названия несудимых»` — с вычетом уже судимых ключей; `«Непосчитанное в
бинарнике»` (`:1722`, отказ ведомости) и `«Чего печать не судила»` (`:1783`,
фраза печати) берут `«Названия двух»` — **без вычета вовсе**.

Это не чтение исходников, а замер. Файл, объявляющий только то, что двоичный
судит заведомо:

```
$ bootstrap/flang check examples/cat/modules/orders.flang --proof
ведомость не печатается: в программе объявлено то, чьи законы бинарник не
считает — categories, morphisms. … Судья законов у бинарника ЕСТЬ и вшит в
замыкание … но судит он только категории, морфизмы и преобразования.
```

Одна фраза говорит «законы categories не считает» и тут же «судит категории».
Отказ ведомости срабатывает на ЛЮБОЙ объявленной поверхности, судимой или нет.

**Цена названа местом:** 68 обязательств в 17 файлах держит одно слово в
`flang/self/bootstrap/compiler.flang:1722` — `«Названия двух»` там, где у
соседней функции стоит `«Названия несудимых»`. Правка сюда не вносится: она
целиком в поле задач 5855 и 7205, а строки 1937–1965 того же файла прямо
сейчас правит 7101. Сколько из 68 после такой правки получат приговор, а не
новый отказ, замером **не установлено** — установить это можно только
перепечаткой.
