# 4672 — на свежей выкладке `./ярлык` отказывается собирать

## Как найдено

Координатор влил main в dev (`6ad35c94`) и завёл чистый worktree, чтобы
проверить работу другого работника. `./ярлык задачник:проверка` дал **код 3**,
не начав сборку:

```
двоичного bootstrap/flang нет — собираю из точки раскрутки: make -C bootstrap
СБОРКА НЕ НАЧАТА: тело точки раскрутки не сходится с отпечатком.

В ОТПЕЧАТКЕ НЕТ ТЕЛА СЕМЕНИ: scripts/otpechatok-semeni
Он снят прибором старше 31 августа 2026 — тот покрывал входы печати и не
покрывал её выход.
```

## Это НЕ следствие слияния — проверено

Первая мысль была, что виновато слияние. Неверно:

```
отпечаток на dev до слияния (504f7e3a)   53 строки, тела семени нет
отпечаток на main                         66 строк, тело семени есть
```

Дефект лежал на dev и до слияния. У main отпечаток нового образца — в нём
одиннадцать строк, которых у dev нет: `коммит`, хеши `flang/self/emit-*.flang`,
`io.flang`, `parser.flang`.

При слиянии отпечаток взят от dev **намеренно**: тело семени тоже взято от
dev (810 478 байт против 720 571 у main), а отпечаток обязан быть парным
своему телу. Взять отпечаток main к телу dev значило бы соврать.

## Почему нельзя просто пересъять

Сообщение предлагает `sh scripts/raskrutka.sh --otpechatok`. **Так делать
нельзя**: `raskrutka.sh` снимает отпечаток с НЫНЕШНЕГО дерева и записывает,
что семя напечатано из нынешнего коммита. Семя dev печаталось из другого,
более старого. Пересъёмка здесь — подлог происхождения, ровно та порода,
против которой весь КРИТЕРИЙ.md.

Сам скрипт это знает и говорит прямо (`raskrutka.sh:3050`):

```
Снять заново на том коммите, из которого семя печаталось:
  git worktree add <кат> <коммит> && sh <кат>/scripts/raskrutka.sh --otpechatok
```

## Что надо сделать

1. Установить, из какого коммита напечатано нынешнее семя dev. Строки
   `коммит` в отпечатке dev нет — значит узнать это из отпечатка нельзя, и
   надо искать по истории `bootstrap/`.
2. Если коммит найден — снять отпечаток в worktree на нём.
3. Если не найден — сказать это прямо и ждать идущей перепечатки: она даст
   свежее семя, и отпечаток снимется честно вместе с ним.

## Насколько это мешает

CI не задето: `release.yml:109` зовёт `make -C bootstrap` напрямую, мимо
ярлыка. Мешает человеку и работнику: свежий клон дерева не может собрать
двоичный привычным путём, и обходят это, копируя двоичный из чужого каталога
— то есть судят дерево двоичным, про который не знают, откуда он.
