# 4707 — происхождение функции есть внутри связывания и не доезжает до `ast`

## Откуда взялось

Г5 закрыт числом 1955/1956 = 99,9 % (задача 9987), но с оговоркой, висящей
четыре захода подряд: техника замера живёт в питоновской оснастке **вне
дерева**, а не в компиляторе. Причина названа там же: `flang ast` не несёт
на функции её файла, поэтому инструмент путал функции чужих импортированных
файлов со своими, и обход сделан фильтром в оснастке.

Здесь — разбор, во что это обходится, и однозначный ответ, делать или нет.

## Что проверено живым прогоном

`./bootstrap/flang ast flang/proof/examples/corpus-keywords.flang` на дереве
`7443fedd`, двоичный собран из этого же дерева:

```
ключи функции:        body, examples, name, params, postconditions, returns, span, total
ключи верхнего уровня: flang, functions, legacy, module, theorems, types
```

**Поля происхождения нет ни на функции, ни отдельным списком наверху.**

## Данные УЖЕ СОБРАНЫ при связывании, просто не доезжают

`flang/self/link.flang`, объект `«Связывание»` несёт два разных носителя
происхождения, и второй — ровно то, что нужно:

* `«откуда функций»: список «Пара имён»` (строка 252) — карта имя → файл.
  Годится плохо: имена функций **не уникальны по дереву**, и сам link.flang
  об этом предупреждает (строки 1162-1167, про теоремы: «имена постусловий
  совпадают у НЕСВЯЗАННЫХ файлов… Сличение по имени привезло бы
  доказательство про чужое тело»);
* `«файлы функций»: список строки` — **список, идущий строго параллельно
  списку `«функции»`**. Пополняется в тех же местах и теми же функциями, что
  и сам список функций: `«С функцией»` (строка 359) и `«С повтором функции»`
  (строка 364) — обе добавляют узел в `«функции»` И файл в `«файлы функций»`.

**Приём «взять файл по номеру» уже написан и работает в дереве.**
`«Постусловия своей»` (строки 1221-1226) ходит по списку функций со
счётчиком и берёт `«Файл по номеру» от «файлы» и («акк».«номер»)`. Именно так
теоремы доносятся «по ребру импорта, а не по имени» — link.flang сам выбрал
позиционный список вместо карты имён, и по правильной причине.

**Где обрывается.** `«Собрать итог»` (строка 1149) передаёт `«файлы функций»`
в `«Теоремы программы»`, но в `«Собрать программу»` (строка 1048) — нет.
Итоговая программа собирается из `«функции»` без файлов:

```
пусть «основа» равно [… («Поле списком» от "functions" и «функции») …]
```

## Что нужно добавить — точно

Печатать ничего не надо: JSON делает `«Печать значения»` — общий печатник,
который выводит ровно те поля, что у значения есть. **Новое поле напечатается
само.** В `flang_repl.c` (`ast_file`, строка 10413) правок нет вовсе: он
только зовёт `«Связать исходники»`, `«Отметить меры»`, `«Отметить доказанные»`
и `«Печать значения»`.

Правка — в ОДНОМ файле, `flang/self/link.flang`:

| место | что | строк |
|---|---|---:|
| новая функция «Функции с файлами» | ходит по функциям со счётчиком, каждому узлу добавляет поле `"file"`; списан с «Постусловия своей» | 10–14 |
| `«Собрать программу»`, строка 1048-1051 | принять ещё `«файлы»: список строки`; в «основе» вместо `и «функции»` — `и («Функции с файлами» от «функции» и «файлы»)` | 2 |
| `«Собрать итог»`, строка 1149 | передать `(«после».«файлы функций»)` в вызов | 1 |

Итого **13–17 строк, один файл, ноль строк C**.

Имя поля предлагается `"file"` — рядом со `"span"`, которое уже отвечает на
«где», и в том же английском ключевом словаре, что остальные ключи узла.

## Кто читает `ast` сегодня — формат де-факто публичный внутри дерева

`flang/scripts/binary.mjs` (сам обход), `name-guard.mjs`, `proof-ledger.mjs`,
`word-guard.mjs`. Добавление ПОЛЯ их не ломает: все читают по ключу.

## И вот главное: обход уже существует трижды, и дважды — неверным способом

1. **`отсеятьЧужое` в `flang/scripts/binary.mjs:262`** — общий помощник для
   `name-guard` и `proof-ledger`. Делает так: для каждого импорта **разбирает
   соседний файл целиком заново** (`дерево(сосед)` — ещё один полный
   `flang ast`), собирает имена и **отсеивает по имени**.
   * **цена**: один лишний полный `flang ast` на каждый импорт, рекурсивно.
     По замеру в шапке того же файла (строки 105-106) `flang ast` на крупном
     файле — десятки секунд и 13,1 ГиБ;
   * **верность**: отсев по имени. Файл, объявивший функцию с тем же именем,
     что у соседа, **потеряет собственную функцию**. Это тот самый класс
     ошибки, ради которого link.flang для теорем пошёл «по ребру, а не по
     имени», — а сторожи всё ещё ходят по имени.
2. **Питоновская оснастка Г5** — `привязка-по-файлу.py`, `привязка-полная.py`,
   `привязка-полная-2.py`. Отбирает свои функции по именам, объявленным в
   тексте исходника.
3. **link.flang, «Постусловия своей»** — единственный верный: по позиции.

## Риск перепечатки — назван прямо

`flang/self/link.flang` **компилируется в семя**: имена `Собрать программу` и
`Постусловия своей` встречаются в `bootstrap/compiler_flang.c` 26 раз.
Значит правка **не действует, пока дерево не перепечатано**, и проверить её
сегодняшним двоичным нельзя.

Это не теория: на «исходник ≠ семя» за сутки попались дважды — починка кеша
`d621bda9` есть в исходнике и отсутствует в семени (5 вхождений против 0), и
оценка её действия из-за этого была неверной; и второй раз при разборе
разброса печатей (задача 9996), где кеш искали в исходнике, а печатает семя.

Цена перепечатки измерена сегодня (задача 9996): **~4 ч 25 мин** нынешним
семенем, ~8 ч 45 мин на пару.
