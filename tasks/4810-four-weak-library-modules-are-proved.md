# 4810. Четыре слабых модуля библиотеки доказаны, и у каждого названа своя стена

Ведомость по библиотеке (задача 0054) назвала четыре модуля, у которых
доказано меньше половины обещаний:

```
json.flang         доказано 45 из 109
datetime.flang     доказано 21 из  49
higher-order.flang доказано 28 из  51
numbers.flang      доказано 24 из  45
```

Стены у них РАЗНЫЕ, и валить их в одну кучу нельзя:

* `json` — индукция по типу, спрятанному в список СВОЕГО ЖЕ типа
  (`вариант «Массив json» содержит элементы: список «Значение json»`);
* `datetime` — арифметика без объявленных границ;
* `higher-order` — своя, назвать прогоном;
* `numbers` — строгие неравенства и рефлексивность над типом `число`.

## Что снято прогоном

Двоичный `/srv/flang-rabota/w-predely/bootstrap/flang`, ворота `PAMYAT=45G`,
26–27 августа 2026. «До» и «после» у каждого модуля сняты ОДНИМ значением ключа.

| модуль | предел | доказано до → после | сетка до → после | снято проверок |
|---|---|---|---|---|
| `numbers` | умолчание | **33 → 37** из 54 → 58 | 21 → 21 | 33 → **37** |
| `json` | `8000000000` | **45 → 47** из 109 → 110 | 64 → **63** | не снято |
| `datetime` | `8000000000` | 27 → 27 из 55 → **53** | 28 → **26** | 27 → 27 |
| `higher-order` | умолчание | 48 → 48 из 71 | 23 → 23 | 71 пример прошёл |

`json` при умолчании предела не отвечает НИ ОДНОЙ из трёх команд — `check
--proof`, `test`, `emit`; ключ предела есть только у `check`. Поэтому число
снятых проверок у него «не снято», а не ноль.

## Какая стена оказалась настоящей

* **`json` — та, что названа в самом файле, и она подтвердилась**: у
  `вариант «Массив json» содержит элементы: список «Значение json»` часть
  значения спрятана в СПИСОК своего типа, и предположения индукции у неё нет.
  Прибавка пришла мимо стены: одна правка ТЕЛА («Шестнадцатеричная цифра json»,
  `элемент N в [список строк]` → `символ N в строка`) и одно замкнутое
  равенство над длиной под охраной-вариантом.
* **`datetime` — арифметика без объявленных границ, и лечение ей закрыто в
  библиотеке**: посылку конечности ядро читает сегодня только из типа (`нат`,
  отрезок) или из `требует`, а `требует` в `flang/stdlib` роняет сверку
  самоприменения во всех восьми целях печати. Прибавка ноль; убраны два
  составных двойника.
* **`numbers` — рефлексивность `а не больше а` над типом `число`**, и она НЕ
  снимается охраной-неравенством: четыре пробы, все сетка. Прибавку дало
  другое — замкнутая цель под охраной из тела берётся НЕСТРОГИМ неравенством.
* **`higher-order` — стена НЕ в высшем порядке** (48 из 71 доказано, три
  индукцией). Их две, и обе чужие: край по пустому списку у тела-`разбора` по
  списку и та же арифметика неравенств над `число`.

## Как понять, что сделано

Отчёт о доказательствах по каждому из четырёх, снятый одним двоичным, «до» и
«после», с указанием предела шагов там, где он поднят. Число `доказано`
выросло; всё, что не доказалось, откачено. У каждого модуля названо, какая
стена оказалась настоящей, и чем это подтверждено — прогоном, а не рассуждением.

Ввозящие `numbers.flang` (`hashmap`, `higher-order`, `wire`, `utf8` — у всех
список `только`) проверены отдельным отчётом каждый.
