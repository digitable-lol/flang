# 5501 — один источник версии, бамп одной командой, сторож на дубли

## Беда

Число версии жило руками в нескольких файлах. Сторож `версия:проверка`
(в `.githooks/pre-push`) сверял ровно ПАРУ `package.json` ↔ `#define
FLANG_VERSION`, а остальные места версии только называл. Поднять версию значило
пройти по файлам порознь; забудешь один — покраснеет либо `версия:проверка`,
либо (уже в CI) `справка:проверка`/`формула:проверка`.

## Где живёт версия — разобрано прогоном, не на глаз

`git grep '0\.7\.1[0-9]'` по дереву. Разделено на три рода:

**Дублируют версию (вытекают из одного источника) — 5 файлов, 9 мест:**

| место | что |
|---|---|
| `scripts/emit-package.flang` «Версия» | ИСТОЧНИК (тело + пример) |
| `package.json` `version` | печатается из источника |
| `flang/src/emit/c/flang_repl.c` `#define FLANG_VERSION` | ручной дубль |
| `packaging/flang.1` | `.TH` + две расшифровки `flang X` |
| `packaging/homebrew/flang.rb` | `version` + тег и имя архива в `url` |

**Завязано на архив выпуска (не бамп):** `packaging/homebrew/flang.rb` `sha256` —
снимается с СОБРАННОГО архива, из числа версии не выводится.

**Лишь упоминает (трогать нельзя):** `changelog.json` (выпущенное, судит
`журнал:проверка`), семя `bootstrap/flang_repl.c` (заслон 2573), `README*`,
`docs/site/releases*`, замеры с датой в `.github/workflows/*` и `scripts/*`,
`editors/vscode/package.json` (своя нумерация 0.1.0), `tasks/*`.

## Почему нельзя «читать `#define` из файла» и почему источник — `emit-package.flang`

`#define` в C нельзя вычислить при сборке, не трогая печатаемый
`bootstrap/Makefile` или общий шаблон `emit-c.flang` (задача 9983) — поэтому его
ГЕНЕРИРУЕТ ярлык. Источник выбран `scripts/emit-package.flang` (не новый файл
`VERSION`): он уже помечен «ОДИН ИСТОЧНИК ВЕРСИИ», уже печатает `package.json`, и
`version-guard.flang` уже зовёт его эталоном. Из ручной правки ушли **8 мест**
(всё, кроме источника); бамп — одна команда.

## Что сделано

- `scripts/bump-version.sh` — ярлык `версия`. `./ярлык версия 0.7.13` ставит число
  в источник, `flang_repl.c` (`#define`), `.TH` и обе расшифровки man, три числа
  формулы (version, тег, архив) и перепечатывает `package.json` из источника.
  `sha256`, `changelog`, семя НЕ трогает — намеренно.
- `scripts/version-derivations-guard.sh` — дешёвый сторож (без двоичного, groff,
  sha256sum, сети): сверяет все производные места с источником и при расхождении
  говорит «запусти `./ярлык версия <N>`», а не «поправь руками». Встроен в
  `.githooks/pre-push` (`versii-vezde`), дополняет `версия:проверка`, не заменяет.
- `ярлыки.flang` — заведён ярлык `версия`; число ярлыков 124 → 125.

## Проба

| шаг | итог |
|---|---|
| сторож на чистом дереве (0.7.12) | код 0 |
| развёл руками `flang_repl.c` → 0.7.99 | сторож код 1, назвал файл и `./ярлык версия` |
| развёл руками `.TH` → 0.7.55 | `версия:проверка` СЛЕП (код 0), мой сторож код 1 |
| `./ярлык версия 0.7.13` | 0.7.13 лёг в 5 файлов; `sha256`, семя, changelog нетронуты |
| после бампа: мой сторож, `версия`, `справка`, `пакет` | все код 0 |
| после бампа: `формула:проверка` | код 1 — ТОЛЬКО по `sha256`/архиву (нужен собранный архив выпуска, не в pre-push; краснела бы и при ручном бампе) |
| самопроба `--подлог` | подлог пойман (код 0) |
| `sh .githooks/pre-push` | см. отчёт |

Версия в ветке возвращена к 0.7.12 — задача про механизм, не про сам выпуск.
`формула:проверка` красна по `sha256` — это забота выпуска (собрать архив →
пересчитать `sha256`), не дублирование; доказано экспериментом до правки.
