# 5562 — прибор переназначался молча

## Откуда

Работник Z2 (задача 1931) заметил попутно: `flang/proof/map/**` — не примеры,
а ПРИБОР, и дописанная в клетку теорема подменяет измеряемую величину. Он же
сообщил, что сторож умений этого не ловит. Задача заведена, чтобы починить.

## Что мерит карта и почему теорема её ломает

README карты дословно:

> Здесь лежат маленькие программы, каждая из которых меряет ОДНУ клетку карты
> «что ядро умеет доказывать, а что нет».

Клетка спрашивает: **умеет ли ядро САМО**. Дописанная теорема меняет вопрос на
«доказывается ли это с подсказкой автора». Прибор остаётся на месте, но меряет
уже другое, и в диффе это выглядит как безобидное добавление.

## Дыра подтверждена ЧТЕНИЕМ и ПРОГОНОМ

Пять правил старого сторожа прочитаны поимённо: якорь стоит в ядре, номер стоит
в описании, функция-улика стоит в файле улик, имя правила ядро всё ещё называет,
и счёт «строк списка равен утверждениям в уликах». **Ни одно не смотрит на
теорему.** Счёт не спасает: теорема не добавляет строки `обеспечивает «У`, и
пятое правило остаётся довольным.

Решающий опыт — один и тот же подлог, два сторожа:

```
подлог: теорема «У3 …» дописана в flang/proof/map/abilities.flang

СТАРЫЙ сторож  КОД 0  «умений в списке: 28; ядро, описание и улики сошлись на всех»
НОВЫЙ  сторож  КОД 1  «КАРТА: abilities.flang несёт теорем 1 — клетка меряет,
                       что ядро доказывает САМО, а теорема подменяет вопрос»
```

## Поправка к задаче 1931: `flang check` НЕ слеп

1931 сообщает, что подлог даёт `flang check` код 0 И сторож код 0. **Первая
половина не воспроизвелась.** Три формы теоремы, все на `abilities.flang`:

```
без шага                   FLANG_PROOF_STEP: ни одного шага                     код 1
«по предположению»         FLANG_PROOF_INDUCTION_STEP: стоит вне индукции,      код 1
                           а допущений у этой цели нет ни одного
индукция по свёртке        код 1
```

Ядро строже, чем сказано: сочинить теорему, которую оно примет, в этом файле
непросто — функции там непримитивной рекурсии не имеют. **Дыра в стороже от
этого не меньше** (он обязан ловить подмену прибора независимо от того, поймает
ли её кто-то ещё), но приписывать слепоту ещё и ядру — неверно.

## Починка

`scripts/kernel-abilities-guard.flang`. Сторож теперь **перечисляет каталог
карты** и читает все клетки, а не одну.

Почему перечисление, а не список имён в коде: клетка, заведённая завтра, попадёт
под присмотр сама. Список имён дал бы ровно ту породу, которую чиним, — сторожа,
не видящего нового. **Проверено прогоном**: заведена клетка
`новая-клетка.flang`, которой в коде сторожа нет ни словом, — сторож её назвал.

**Послабление одно и оно именовано: `refusal-*.flang`.** Тот же README:

> Файлы `otkaz-*.flang` обязаны уходить кодом 1: в них написаны теоремы, которые
> ядро отвергает, и измеряемая величина — ровно текст отказа.

Там теорема не подмена вопроса, а сам вопрос. Замер по дереву подтверждает, что
граница проходит ровно здесь:

```
abilities, boundaries, equality, forms, order,
sources, substantive, types                       теорем 0  (восемь клеток)
refusal-boundaries, refusal-order                 теорем 8, 8
refusal-substantive                               теорем 4
```

Код провала свой — `FLANG_KARTA_S_TEOREMOY`, а не общий
`FLANG_UMENIYA_RAZOSHLIS`: расхождение списка умений и подменённая клетка карты
— разные поломки, и чинят их разные люди.

## Проба порчи — четыре случая, все прогнаны

```
чистое дерево                       КОД 0, приговор СЛОВО В СЛОВО прежний:
                                    «умений в списке: 28; ядро, описание и улики
                                     сошлись на всех»
теорема в abilities.flang           КОД 1, названа файлом и числом
теорема в forms.flang               КОД 1  ← покрыта не только одна клетка
новая клетка с теоремой             КОД 1  ← перечисление, а не список имён
refusal-* с 8+8+4 теоремами         КОД 0  ← послабление держит
```

## Цена

```
старый сторож  2290 мс
новый сторож   2619 мс   (+329 мс, +14 %) — одиннадцать лишних файлов
```

`abilities.flang` читается дважды — как улики и как клетка. Один лишний разбор
файла дешевле ветвления, которое пришлось бы объяснять.

`flang check scripts/kernel-abilities-guard.flang` — функций 28, из них с
доказанным завершением 28; типов 6; замечаний нет.

## Три ошибки по дороге, на которых стоит сэкономить время следующему

1. **`возвращает да или нет`** — так булев тип не зовут. В дереве он `признак`.
2. **`случай тголова и тхвост`** — имена в образце списка ЗАКРЕПЛЕНЫ: только
   `голова` и `хвост`. Вложенный разбор двух списков поэтому невозможен;
   пришлось идти по одному списку, а второй брать по номеру.
3. **`принимает список: список строки`** — имя `список` занято словом типа,
   и `(длина список)` даёт `FLANG_UNKNOWN_NAME`.

## Не сделано

* Сторож смотрит только на наличие теоремы. Клетку можно переназначить и иначе
  — например, заменив тело функции на такое, где вопрос уже другой. Это не
  ловится и не ловилось; отдельная работа.
* Послабление привязано к приставке имени файла. Переименовать клетку в
  `refusal-*` и тем выйти из-под присмотра — можно, правка в одну строку. Та же
  порода, что названа в задаче 4258 про знаменатель Г4. Не чинил: признак
  «файл отказов» надёжнее брать из ожидаемого кода возврата, а он сегодня
  записан только в README прозой.
* README карты зовёт файлы `otkaz-*.flang`, а в дереве они `refusal-*.flang`.
  Проза разошлась с деревом; не правил, файл не мой.
