# 5578. Доля доказанного по дереву — одно число и одна оговорка

## Чем измерено

Число записано и живёт в ветке `m/sverka-opublikovannogo`, файл
`scripts/proved-share.json`:

```json
"числитель": 8147,
"знаменатель": 13341,
"доля": "61,1 %",
"снято": "2026-08-28",
"коммит": "da47cbdf",
"двоичный": "82f9ac4018e795ec19955a7ce2a9c1a8",
"как снято": "make -C bootstrap -j8, затем ./bootstrap/flang check <файл> --proof
              по одному файлу за раз, 437 прогонов, 12,7 ч."
```

Владелец 29 августа назвал **8237 из 13 341 = 61,7 %**. В дереве стоит **8147 из
13 341 = 61,1 %**. Расхождение — 90 обязательств, и оно не объяснено ни там, ни
здесь. Я ставлю записанное в дереве число и говорю, что второе не сошлось.

Знаменатель на нынешнем стволе уже сдвинулся. Прогон сверки 29 августа:

```
написано обязательств опубликовано 13341     в дереве 13370     РАЗОШЛОСЬ
числитель 8147 — под вопросом на 119 обязательств из 13341
  файлов сдвинулось 4, ушло 0, прибыло 3
```

## Оговорка, без которой число лжёт

`flang check` судит файл **вместе со всем, что тот ввозит**. Складывать строки
«итог:» по файлам нельзя — сумма считает ввезённое по многу раз. Завышение
измерено, 29 августа:

| где | своих приговоров | всего в отчёте | во сколько раз завышает |
|---|---:|---:|---:|
| `flang/self/proof-kernel.flang` | 44 | 1503 | **34,2** |
| `flang/self/proofterm.flang` | 138 | 1779 | **12,9** |
| по всему дереву | — | — | **2,47** (записано в `proved-share.json`) |

Числитель 8147 посчитан ПРАВИЛЬНО — по своим функциям файла, а не сложением
итогов. Это и есть главная ценность числа, и она пропадёт, если кто-нибудь
пересчитает его сложением.

## Что сделать

1. Разрешить расхождение 8147 против 8237: переснять либо признать одно из
   чисел ошибкой и записать почему.
2. Довести знаменатель до нынешнего дерева: 4 файла сдвинулись, 3 прибыли,
   119 обязательств под вопросом. Переснимать надо только их, а не все 437
   прогонов — ведомость `scripts/proved-share-ledger.txt` держит md5 на файл
   именно для этого.
3. Вписать оговорку про завышение в 2,47 раза **рядом с числом**, а не в
   соседний файл: число без оговорки читается как «61 % дерева доказано», а это
   не то, что оно значит.
4. Влить ветку `m/sverka-opublikovannogo` — без неё ни числа, ни ведомости в
   стволе нет вовсе (соседняя задача про сверку опубликованного).

Форма законная и описана в дереве — `docs/site/language.ru.md:133`:
`для всех п обеспечивает «имя» условие`. Значит счёт по первому слову

Владелец назвал 13 610; сегодня выходит **13 617** — он мерил на день раньше.

**Что оказалось неправдой.** «`git ls-files` без `-z` экранирует кириллицу и
теряет 451 файл из 1154» — **опровергнуто**. Ни одно место в дереве так не
зовёт: `scripts/published-vs-tree.sh:182`, `:249`, `:270` — `git -c
core.quotePath=false ls-files -z`; `flang/scripts/word-guard.mjs:480` и
`scripts/jargon-guard.mjs:231` — с `quotePath=false`; сторожа на flang
(`scripts/tree-inventory.flang:350`, `link-guard.flang:403`,
`error-code-guard.flang:767`, `name-splicing-guard.flang:423`,
`adr-numbers-guard.flang:257`) передают `"-c","core.quotepath=false"` доводом, и
в `link-guard.flang:402` это закреплено примером «Кириллица в путях не должна
приезжать в кавычках». `flang/scripts/per-file-proof-share.py` git не зовёт
вовсе — `os.walk` (строка 87). Арифметика сама по себе верна (451 из 1154 в
восьмеричных экранах), но только если снять `quotePath=false`, чего в дереве
никто не делает.

**Пятый пункт «Что сделать», прибавленный сегодня:** считать знаменатель
разбором программы, а не первым словом строки. Кванторная форма — не
исключение, а вторая законная запись того же обязательства, и первым словом её
не поймать никогда.
