# 5763. Печать ядра — 33 места «разбор цели по условию» ходами

## Откуда

Контракт печатнику и сверщику — `docs/design/proof-object-hody-razbora-celi.md` (задача 6127):
семь новых видов ходов и законов в сверщике (`закон «мера неотрицательна»`, `«квадрат под
оговоркой»`, `«начало склейки»`, `«пустая приставка»`, форма-законы «Закон признака» и
«Вхождение в выписанный список», ходы `связка ⟨…⟩` и `подставить пусть строка N`), правило Б2\*
(условие в скобках у `деление`) и 33 цепочки по одной на место карты калькулятора (§3 контракта).
Все 33 прогнаны рукотворно кодом 0; golden — `пробы/семьи/razbor-celi/`. Печати в
`flang/self/zapis.flang` не было: правило «разбор цели по условию» (и его соседи по тем же
местам — «разбор случаев по внутреннему условию цели», «неотрицательность по построению»,
«ограниченность точным потолком по построению», «начало по построению») уезжали в запись одним
именем (`Строки объявленного правила`), а сверщик снимал место калькулятором `половина_закрыта`.

## Что делается

Новый печатник «Ходы разбора цели постусловия записи» в `zapis.flang` по образцу С1–С5 (задача
2562): текстовый планировщик, который САМ проигрывает цель той же нормализацией, что сверщик,
и печатает только замкнувшуюся цепочку:

1. начальная цель — постусловие с `результат` → вызов; `развернуть` на последнюю строку тела;
   `подставить пусть строка M` на каждое имя из `пусть`-строк, которое стоит в цели;
2. стек целей: литерал `да` → `закрыть истиной`; тождественные стороны → `закрыть тождеством`;
   самый глубокий `если да|нет то … иначе …` → `выбор ⟨…⟩`; первое условие → `деление ⟨У⟩`
   (да-половина до закрытия, потом нет-половина); четыре закона по форме цели; «Закон
   признака» на самой глубокой группе скобок; «Вхождение в выписанный список»; `связка ⟨и
   притом⟩` / `⟨или⟩ левая|правая` (та половина, что закрывается); `вычислить ⟨T⟩ = ⟨V⟩` для
   замкнутого терма (левая сторона равенства, терм под `не`, либо цель целиком) — зеркало
   `оценить_терм` на одиннадцати отношениях, литералах, длине литерала и выписанного списка;
3. не замкнулось — пустой список, место уезжает именем правила, как сегодня.

Печатник зовётся из «Строки утверждения» только там, где семьи тождества и леммы по свойству
промолчали. `obligations.flang` и `сверщик.c` не трогаются.

Шесть мест закрываются только ходом `вычислить ⟨замкнутый терм⟩` — 15 (В2), 30 (Ф1), 32 (Ф3),
43 («литерал начинается приставкой»), 45 (П2), 47 («начинается с а»): владелец решение о
примитиве отложил, ход печатается как в контракте §4 и эти места названы в отчёте отдельно.

## Как проверяется

Как в задаче 2562: интерпретируемая печать (`bootstrap/flang run` обёртки над
«Ведомость проверенного») затронутых записей корпуса — до и после правки; сверщик gh/dev;
плюс прямой прогон планировщика `flang run flang/self/zapis.flang --function «Цепочка разбора
записи»` на 33 местах против текстов контракта §3.

## Критерии приёмки

- [x] Планировщик даёт на 33 местах цепочки контракта §3 (текст в текст).
- [x] Перепечатанные записи затронутых файлов: код 0/3 как прежде, ни одной честной записи код 1;
      «сведений проиграно заново» +1 на место, узлов «разбор цели» −1.
- [x] Незатронутые записи — печать байт в байт та же (интерпретируемая база).
- [x] Набор проб «сошлось всё»; доля корпуса с разбивкой на перепечатанном наборе.
- [x] `flang check flang/self/zapis.flang` код 0; опись, приметы; pre-push — красен только `semyaosv`.

## Итог (снято прогоном 8 сентября 2026; сверщик gh/dev 91abe36b)

**Планировщик против контракта.** На всех 33 местах карты `bootstrap/flang run
flang/self/zapis.flang --function «Цепочка разбора записи»` дал цепочки §3 контракта
ТЕКСТ В ТЕКСТ (33 из 33). Ходов в них 207: выбор 64, развернуть 33, закрыть истиной 27,
деление 23, закрыть тождеством 20, вычислить 13, законы 11, «Закон признака» 6,
связка ⟨или⟩ 4, подставить пусть 3, «Вхождение в выписанный список» 2, связка ⟨и притом⟩ 1.

**Замер по всем 77 местам корпуса** под пятью правилами, которые печатник берёт
(«разбор цели по условию», «разбор случаев по внутреннему условию цели»,
«неотрицательность по построению», «ограниченность точным потолком по построению»,
«начало по построению»): цепочка выходит ровно у 33 — это и есть места карты; у прочих 44
печать молчит. Два места со свёрткой в теле (`corpus-hof` «счёт по условию неотрицателен»,
`corpus-lists` «счёт вхождений неотрицателен») съедали 40 миллионов шагов толкователя —
заведён заслон «Тело планировщику по силам записи» (свёртка, разбор, отображение, стрелка
или цель длиннее 300 знаков → молчание); все 33 места карты он пропускает, самое длинное 148.

**Перепечатка 27 затронутых записей** (интерпретируемая, база снята тем же приёмом на HEAD
и байт в байт совпала с печатью прошлой задачи — дрейфа исходников после двух слияний нет):

| | база | новая |
|---|---:|---:|
| код записи | 0/3 (подделка свёртки 1) | тот же у всех 27 |
| сведений проиграно заново | 182 | **215 (+33)** |
| узлов «разбор цели по условию» | 39 | 6 |
| записей байт в байт | — | 11 из 27 (там, где печать молчит) |

Доля корпуса проигрыванием: **474/665 = 71,28 % → 507/665 = 76,24 %** (+4,96 п.);
«проиграно ходами/тотальностью» 357 → 390; «снято калькулятором (тождество/разбор)» 40 → 7.
Набор проб — «сошлось всё» (подделок 195: отвергнуто 145, третий исход 50, принято кодом 0 — 0;
честных 126 принято). `flang check flang/self/zapis.flang` — код 0.

**Ход `вычислить` стоит в семи местах**, а не в шести: В2, Ф1, Ф3, **Ф4**, «литерал начинается
приставкой», П2, «начинается с а». Шесть названы владельцем (15, 30, 32, 43, 45, 47), седьмое —
Ф4 (место 33 контракта), где §3 тоже требует `вычислить ⟨2 не меньше 0⟩ = ⟨да⟩`. Решение о
примитиве отложено; печать идёт как в контракте §4.

**Чего нет.** Семь мест корпуса под теми же правилами, которые печать не закрывает
(`order` «П3 не убывает», `corpus-natural`/`-ceiling` по одному, `poddelka-order-arithmetic` два,
`abilities` У15 и остальные потолковые) — им нужны факты типа, а не ходы разбора; они уезжают
именем правила, как прежде. Перепечатка семени и регенерация корпуса двоичным — за батчем.
