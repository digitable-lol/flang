# 6131. Приём «вывод»: сверщик проверяет дерево, не зная смысла правил

Основание — [ADR-0022](../docs/adr/0022-a-type-fact-travels-as-a-derivation.md)
§3.10 (форма блока), §6.1 (цена), §6.3 (порядок).

Делать ВТОРОЙ, после 6130 и строго ДО 6132: запись с блоком `вывод`, прочитанная
старым сверщиком, будет отвергнута — сверщик обязан ехать первым. Перепечатки
семени задача НЕ требует: чекер собирается отдельно (`make -C flang/proof/чекер`,
секунды).

## Что сделать

1. В `flang/proof/чекер/сверщик.c`:
   * приём `вывод` — диспетчер по имени правила, по функции на правило; образец
     диспетчера — `ход_шага` (`:1494`), образец цикла — `проиграть_блок` (`:1517`),
     образец локальной проверки закона — `применить_закон` (`:606–672`);
   * новые строки в `ОБРАЗЦЫ[]` (`:5286`) — строка вне белого списка даёт код 1;
   * учёт: место с проигранным выводом идёт в «сведений проиграно заново», а не в
     «на слово ядра».
2. То же во ВТОРОМ чекере `flang/proof/сверщик.flang` (2446 строк) — он читает
   тот же формат.
3. Отказы: на каждый вид — своя строка с названной причиной. Молчаливого «не
   берусь» у нового приёма быть не должно.
4. Золотые пробы `flang/proof/чекер/пробы/семьи/вывод/` по образцу
   `пробы/семьи/razbor-celi/`: на каждое правило — честная цепочка и порча.

## Критерии приёмки

* Рукотворная запись с блоком `вывод` для правила Т1 («цель есть допущение»)
  проигрывается: «сведений проиграно заново» +1, «на слово ядра» −1, код прежний.
* Подделка `flang/proof/чекер/пробы/записи/типы-доводов/vychitanie-ne-sohranyaet`
  с дописанным блоком `вывод`, где стоит вычитание, отвергается **проверкой
  вывода** с названной причиной, а не именной пробой.
* Порча каждого вида (не та форма цели, неверный номер строки, пропущенная
  посылка, лишняя посылка) даёт код 1 и НАЗВАННУЮ причину — по пробе на каждое
  правило ведомости.
* Записи БЕЗ блока `вывод` дают тот же код и ту же долю, что до правки:
  `sh flang/proof/доля-корпуса.sh --набор корпус --проигрыванием` — число в число.
* `sh flang/proof/чекер/пробы/прогон.sh` — зелен; подделок принято кодом 0 — ноль.
* Оба чекера отвечают на одну запись одинаково (сличение выводов побайтно).
* `sh .githooks/pre-push` — код 0.

## Что сделано на 9 сентября 2026

Ветка `r/blok-vyvoda`. Форма блока и границы приёма — в
[docs/design/proof-object-blok-vyvoda.md](../docs/design/proof-object-blok-vyvoda.md).

* Приём `вывод` в `flang/proof/чекер/сверщик.c`: правила Т1, Н1–Н5, П1, П2, П3, П5,
  Разв2 и двенадцать запретов ведомости. Отдельной веткой, а не добавочной, — иначе
  разбор цели снимал те же места вторым счётом.
* Шесть новых образцов строк записи; строка вида вне списка даёт код 1.
* Учёт: место с проигранным выводом идёт в «сведений проиграно заново», снятое
  печатается словами «снято со слова ядра мест» — линейка складывает снятое по всем
  приёмам.
* Семья проб `пробы/семьи/вывод/`: честная запись на восемь мест, две подделки над
  `vychitanie-ne-sohranyaet` (запретом и подменой вычитания суммой) и семнадцать порч по
  одной строке — на каждый вид отказа своя названная причина.
* Замер открытых мест: имя правила из восьми типовых семейств стоит у 51 места из 134
  открытых (утверждений 38, посылок 13). На написанные семейства приходится 25, на
  ненаписанные — 26. Даже все 51 дают 568 из 651 = 87,25 % при пороге 95 %.

## Что осталось

* Семейства О, Д, С, СС, В, Ч ведомости — 26 мест. Имя оттуда сегодня даёт названный
  отказ, а не тихий пропуск.
* Второй чекер `flang/proof/сверщик.flang` приёма не знает: запись с блоком вывода он
  отвергнет как незнакомую. До печати в ядре он обязан поехать следом.
* Печать блока в ядре — задача 6132.

## Чего НЕ делать

* Не растить калькулятор: приём обязан ПРОИГРЫВАТЬ написанное, а не доказывать
  заново. `git grep -c -F 'перепиской(' -- сверщик.c` не должен вырасти
  (проверка 1 гейта Г7).
* Не вкладывать в сверщик систему типов (ADR-0022 §8Б): он знает формы целей и
  номера строк, смыслов не знает.
