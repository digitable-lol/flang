# 6204. Узел со смешанными правилами посылок — в приём

## Что известно из замера

Замер 9 сентября 2026, ветка `r/a-lovushka-dopolnenie` (`gh/dev bc1ff161e`),
ядро `bootstrap/flang` 0.7.16, сверщик из того же дерева. Проба
`flang/proof/чекер/пробы/семьи/algebra-domeny/ohrana.flang` (тип «Д»,
«Хорошее», «Левое хорошее» без теоремы; цель `если («Хорошее» от дерево) то
результат иначе да`):

- ядро печатает у посылки «Пусто» правило **«вычисление замкнутой цели»** (цель
  ветви — `если да то да иначе да`), у посылки «Узел» — **«разбор цели по
  условию»**;
- сверщик (`проиграть_узел_algebra`) выбирает домен цели по правилу КАЖДОЙ
  названной посылки: домен охраны требует «разбор цели по условию» у всех, и
  узел со смешанными правилами уходит **вне приёма** (`вне приёма сверщика 1`,
  код 3), хотя обе половины он умеет: базу — как булеву (`половина_закрыта`),
  шаг — как охрану (`охраной_случая`).

В корпусе тот же узел (`ohrana-daet-fakt.запись`) проигрывается только потому,
что при теореме база закрыта шагом автора и несёт `правило «»`.

Пока приёма нет, честная запись ловушки `ohrana.запись` **правлена руками**:
у «Пусто» стоит «разбор цели по условию» (сверщик проверяет его по существу:
ветвь «то» есть литерал `да`). Пометка об этом — в
`flang/proof/чекер/пробы/ловушка/ВИДЫ.tsv` (колонка «пометка») и в README семьи.

## Что сделать

1. В `проиграть_узел_algebra` домен выбирать не «по правилу каждой посылки
   одинаково», а по цели, и у КАЖДОЙ посылки допускать своё правило из пары
   «правило домена | булево правило» — база, чья цель-ветвь замкнулась до
   литерала, вправе нести «вычисление замкнутой цели».
2. Подделка: узел, у которого база названа булевым правилом, а её цель-ветвь
   НЕ замкнута, — код 1 либо третий исход с названным случаем, не приёмка.
3. Переснять `ohrana.запись` ядром как есть (`bootstrap/flang check --proof
   --записать`), снять пометку в `ВИДЫ.tsv` и в README семьи.
