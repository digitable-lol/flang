# Примеры глубокой печати: около 400 сторожей, которых приёмом «по одному» не взять

## Чем измерено

30 августа 2026 двадцать рук дописывали примеры доказанным функциям
`flang/self/**`. На четырёх файлах подряд одна и та же куча осталась нетронутой,
и каждый раз по одной и той же причине — независимо, разными исполнителями:

| файл | целей осталось | сторожей осталось | из них глубокая печать |
|---|---:|---:|---:|
| `emit-c.flang` | 67 | 96 | **50 целей / 78 сторожей** |
| `emit-python.flang` | 66 | 134 | **50 целей / 112 сторожей** |
| `emit-csharp.flang` | 70 | 137 | **49 целей / 111 сторожей** |
| `emit-java.flang`, `emit-go.flang` | — | — | остаток того же вида |
| **итого** | | | **около 400 сторожей** |

Это сопоставимо со всем, что за смену снято на этих же файлах (737).

## Почему «по одному» не работает

Функции вида `«Печать вызова»`, `«Печать если»`, `«Печать функции»`,
`«Шаг цепочки»` возвращают фрагмент целевого языка в сотни знаков — со
значимыми отступами у Python, с массивом аргументов у C#. Ожидаемое значение
собирается цепочкой из пяти-десяти вложенных вызовов через
`«Печать значения»` и `«Печать хвоста»`, и глазами из тела не выводится.

Снять его прогоном тоже нечем: `flang run --args` берёт **только плоские
скаляры**, а довод здесь — «Состояние» с вложенным «Контекстом». Значит ни
один из трёх обычных способов (вывести из тела, проба замыканием, пробный файл
с падающими примерами) на эту кучу не ложится.

## Приём, который нужен

Снимать ЭТАЛОННЫЙ ВЫВОД прогоном печати на живой программе и разворачивать его
в примеры машинно:

1. взять небольшую настоящую программу на flang;
2. напечатать её в цель (`flang emit … --target <цель>`);
3. сопоставить куски напечатанного с функциями, которые их произвели;
4. выписать примеры из снятого, а не из головы.

Пункт 3 — вся работа: сегодня связи «этот кусок вывода произвела эта функция»
нет ни в каком виде.

## Как понять, что сделано

Число «проверок при работе снято» у `emit-elixir.flang` или `emit-js.flang`
(двух файлов, где `emit` ещё печатает эту строку) выросло на число закрытых
постусловий глубокой печати, и приговоры до/после совпали: вниз ноль, пропало
ноль, новых ноль.

⚠ Мерить придётся быстро: на `emit-java.flang` шаг «Суд ядра о программе» уже
съедает 97 % своего предела в 10⁹ шагов ПОСЛЕ первой правки, а поднять его
нечем — `--предел-шагов` есть только у `check`. Дописанные примеры этот бюджет
едят, то есть работа закрывает себе способ себя измерять.
