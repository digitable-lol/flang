# Двойники есть, а node остался — потому что двойники не доходят

## Откуда вопрос

Владелец спросил дословно: «а зачем binary.mjs? перепиши его на flang».

Ответ на поверхности: `flang/scripts/binary.flang` **уже написан** (613 строк,
ячейка Ч382 задачи 9960) и им пользуются flang-сторожи. `binary.mjs` (848
строк) жив не сам по себе, а как библиотека для семи потребителей на node.

Но при разборе выяснилось другое, и оно крупнее заданного вопроса.

## Опись, которой задача 9960 не сделала

Задача 9960 прямо записала в «Не сделано»: «настоящей описи „46 файлов,
сколько реально перенесено" нет». Вот она, по каталогам `flang/scripts/` и
`scripts/` — 20 файлов `.mjs`:

| куча | сколько | файлы |
|---|---:|---|
| двойник ЕСТЬ | **14** | binary, binary-rules-guard, cli-keys-guard, count-guard, direct-run, direct-run-guard, discriminating-search, link-collision-guard, word-guard, build-changelog, build-changelog-page, jargon-guard, latin-collision-guard, type-collision-guard |
| двойника НЕТ | **6** | claim-guard, name-guard, proof-ledger, target-words, word-occupancy, wasm-run |

Правило самой 9960 было: «Старый `.mjs`-файл НЕ удаляется. Новый `.flang`
живёт рядом». Оно соблюдено — но у него оказалось следствие, которого никто
не назвал.

## Находка: ни один ярлык не переключён на двойника

Из `ярлыки.flang` выписаны все ярлыки, чья КОМАНДА реально зовёт `node`.
Среди них — девять, у которых flang-двойник существует:

```
правила:проверка      -> node flang/scripts/binary-rules-guard.mjs
подсчёты:проверка     -> node flang/scripts/count-guard.mjs
ключи:проверка        -> node flang/scripts/cli-keys-guard.mjs
столкновения:проверка -> node flang/scripts/link-collision-guard.mjs --дерево
столкновения:порча    -> node flang/scripts/link-collision-guard.mjs --порча
поиск:различающий     -> node flang/scripts/discriminating-search.mjs
слово:проверка        -> node flang/scripts/word-guard.mjs
слово:подлог          -> node flang/scripts/word-guard.mjs --porcha vse
журнал / журнал:страница -> node scripts/build-changelog*.mjs
```

**Двойники написаны, а зовут по-прежнему node.** Поверхность node не
уменьшилась ни на файл — при том, что на перенос ушло двенадцать ячеек.

## Почему не переключили — проверено прогоном, а не догадкой

Три двойника прогнаны на настоящем дереве. Двоичный — семя дерева
`235c1966`, собранное из него же.

| двойник | node | flang |
|---|---|---|
| `count-guard` | код 124 (не уложился в 300 с) | **код 3**: «Понизить до шага» исчерпала предел шагов (10 млн) на глубине 54 |
| `link-collision-guard` | известно 4,3 с, код 0 (замер координатора) | **код 3**: «Шаг декларации» исчерпала предел шагов (10 млн) на глубине 5 |
| `discriminating-search` | код 0, выдал разбор | **не уложился** в отведённое время при пределе 500 млн шагов |

Предел по умолчанию у `flang io` — 10 000 000 шагов. Его можно поднять
(`--max-steps`, так уже сделано для `задачник:проверка` — 200 млн). Но
дело не в пределе: `link-collision-guard.flang` при пределе **2 миллиарда**
шагов и десяти минутах срока съел **1 974 043 316 шагов**, доходил до
4,4 ГиБ памяти, полоса хода всё время показывала «0 %» — и не кончил.
Его node-двойник считает то же самое за **4,3 секунды**.

Разница не в разы. Двойник не медленнее — он не сходится вовсе, и это
надо чинить как беду, а не как «дать больше бюджета».

**Попутно подтверждена задача 1722**: прогон `discriminating-search.mjs`
оставил в дереве временный каталог `flang/scripts/ds-XXXXXX/` с
`.flang`-файлами. Убран руками; беда воспроизводится с первого прогона.

**То есть двойники не «дописаны и ждут переключения». Они не доходят до
конца прогона на настоящем дереве.** Это и есть настоящая причина, по
которой node остался: переключить ярлык было нельзя, а сказать об этом вслух
в отчётах ячеек — не сказали.

## Отдельно про `word-guard`: двойник честно неполон, и это записано

Шапка `word-guard.flang` сама говорит: ключа `--porcha` (шесть встроенных
порч) «здесь НЕТ вовсе», `--perepis` тоже не перенесена. А ярлык
`слово:подлог` зовёт именно `--porcha vse`. Значит `word-guard.mjs` не может
быть удалён даже если основной прогон двойника заработает.

## Что это значит для вопроса владельца

`binary.mjs` нельзя ни удалить, ни «просто переписать»: его держат семь
потребителей.

* четыре из них — прогоны в `flang/test/*.mjs` (`uzel-osnastka`,
  `planirovshchik-celi.test`, `flang-bridge`, `svyaz-celi.test`), это
  отдельная и более крупная работа;
* три — сторожи: `word-guard.mjs` (двойник есть, неполон),
  `target-words.mjs` (339 строк, двойника НЕТ),
  `word-occupancy.mjs` (304 строки, двойника НЕТ).

Из `binary.mjs` потребителями используется девять имён: `КОРЕНЬ`,
`позвать`, `путьДвоичного`, `позватьФункцию`, `ведомость`,
`ведомостьИсходника`, `дерево`, `ключевоеСлово`, `токеныМногих`. Из них в
`binary.flang` есть соответствия для семи; `позватьФункцию` и `токеныМногих`
соответствия не нашли (всего в `binary.mjs` 31 вывод, в `binary.flang` 37
функций — счёт не сходится пофункционально, нужен разбор по одному).

## Порог

1. Взять ОДИН двойник (дешевле всего `link-collision-guard`, у него node-
   двойник считает за 4,3 с) и довести его до конца прогона: понять, почему
   съедаются шаги, и уложиться в бюджет, который не стыдно поставить в
   ярлык. Без этого переключать нечего.
2. Переключить ярлык на двойника и показать прогоном, что он даёт то же
   самое, что node. Это правка `ярлыки.flang`.
3. Только после этого удалять `.mjs` — и по одному, с прогоном на каждый.
4. `target-words.mjs` и `word-occupancy.mjs` (339 и 304 строки) — написать
   двойников; без них `binary.mjs` не умрёт.

## Не сделано

Прогнаны три двойника из четырнадцати — вывод «не доходят» проверен на
трёх, на остальных одиннадцати не проверен и переносить его на них нельзя.

не удалён и ни один ярлык не тронут: удалять, не показав работающую замену,
запрещено порогом самой этой задачи.
