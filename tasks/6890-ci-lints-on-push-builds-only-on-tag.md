# 6890. CI линтит на пуше, собирает на теге

Владелец: «ci/cd должен линтить за 5 минут, а собирать что-то за полчаса только
на новый тег; всю сборку в полчаса с минимальным потреблением памяти и цп».

## Беда

`.github/workflows/binary.yml` ходит на голом `push:` (все ветки) и гонял на
КАЖДОМ пуше два куска разряда «десятками минут»:

- `sborka`, шаг «Примеры stdlib и ядра» — `flang test flang/stdlib/` = **44 мин**
  (2713 примеров; core рядом — 15 с);
- работа `self-examples` — `обход-self.sh` по `flang/self/**` = **55 мин**.

`korpus` (полный обход, >1 ч) уже был закрыт тегом. `srashchivanie` (Г6,
`[self-hosted, bolshaya-pamyat]`) на обычном пуше не идёт — не трогали.

## Что сделано (только `binary.yml`)

1. **stdlib ушёл на тег.** Шаг разбит надвое: «Примеры ядра» (184 примера, 15 с)
   остаётся на пуше; «Примеры stdlib» (44 мин) — `if: refs/tags/* ||
   workflow_dispatch`.
2. **`self-examples` закрыта тегом** — тот же `if`, что у `korpus`.
3. **`sborka` берёт двоичный из кеша** (`actions/cache`, ключ = хеш входов
   сборки + флаги), как пять соседних работ. На пуше без правки `bootstrap/**`
   сборки нет вовсе.

## Что теперь НЕ краснеет на пуше (названо поимённо)

- поломка примера в `flang/stdlib/**` (42 файла, 2713 примеров) — ловится на
  теге/руке;
- поломка примера в `flang/self/**` (43 файла под присмотром, 4350 примеров) —
  на теге/руке.

На пуше язык держат: обходчик `обход.sh` (180 проверок), ядро (184 примера),
весь набор сторожей `sborka`/`storozha`. Это решение, не молчаливая дыра.

## Память/ЦП: почему кеш, а не «без LTO»

Замер 6 сентября 2026, `taskset -c 0-3`, чистая пересборка, по два прогона:

```
-O2 -flto=auto   120–123 с   пик 1,6 ГиБ
-O2 (без LTO)    262–264 с   пик 2,2 ГиБ
```

Без-LTO ХУЖЕ по обеим осям: `bootstrap/compiler_flang.c` — 607 354 строки, голый
`-O2` жмёт его одним процессом, `-flto=auto` откладывает и раздаёт LTRANS по
ядрам. Значит рычаг экономии — не смена флагов, а кеш: на неизменном
`bootstrap/**` сборки нет. LTO оставлен (он и быстрее, и легче).

## Проба без GitHub (workflow выключены на GitHub координатором)

- Линт-шаги `sborka` (без сборки), последовательно: **170 с**.
- Линт-шаги `storozha` (измеренные), последовательно: **170 с** + шаг r/7116
  ~46 с ≈ 216 с.
- Работы идут параллельно → потолок пуша ≈ самая длинная (`storozha`) ≈ **3 мин
  36 с** при попадании в кеш. С правкой `bootstrap/**` (редко) +122 с. Под 5 мин.
- Тег-путь: сборка двоичного 122 с + одна цель C (печать+сборка+ответ) 1 с,
  ответ `3628800` верный.

## Не тронуто и почему

- `ci.yml` — уже разделён (zhargon/test/pravila/stale-pages на теге), ходит
  только на main/dev/PR. 19 сборок двоичного там — отдельная находка r/7116.
- `build-macos.yml` — намеренно на каждом пуше (ловит баг видимости `mkdtemp`
  на Darwin), дёшево, есть zettel.
- `install-path.yml` — отфильтрован по путям, не на каждом пуше.
- `release.yml` — только тег. `reprint.yml`/`dvoyniki.yml` — расписание, Г6.
