# 7198. Главное заявление цели проверено службой, а не примером: процессы, надзор, соединение, ответ

Заявление цели дерева звучит так: **«язык со своей альтернативой OTP, пригодный
для написания любых служб»**. Заявление это в задачнике не проверялось ни разу —
проверялись части: процессы (0041), сеть (0047), горячая замена (0021),
сокращатель из браузера (5754). Часть, проверенная порознь, целого не
подтверждает: служба — это не сумма примеров, а одна программа, которая
поднимается, отвечает, держит несколько процессов и **переживает падение
обработчика**.

Эта задача — прогон целого.

## Что сделать

Написать настоящую службу на flang в новом каталоге `examples/` и показать
пятью прогонами, дословным выводом каждого:

1. служба поднимается и отвечает на запрос;
2. служба держит несколько процессов, и это видно состояниями, а не
   объявлением;
3. **обработчик падает — надзор перезапускает, служба продолжает отвечать.**
   Без этого пункта работа не закрыта: это и есть проверка заявления про
   альтернативу OTP;
4. у каждого обработчика назван запас витков, и программа проверкой ПРИНЯТА;
5. `flang check` по всей службе: сколько функций, у скольких доказано
   завершение, сколько утверждений и сколько из них доказано.

Служба обязана быть не примером на три функции, а тем, что можно было бы
поставить: разбор HTTP, маршрут, состояние, ответ в октетах, надзор с порогом
отказов.

## Как понять, что сделано

Пять прогонов выше, каждый — команда, её вывод и код возврата. Числа только
снятые прогоном.

**Отрицательный результат полноценный.** «Служба не держится под отказом, и вот
почему» закрывает задачу не хуже положительного — при условии, что «почему»
названо прогоном, а не рассуждением.

## Чем закрыта

Служба `examples/service-on-processes/` — 4 файла на flang, `curl` и `nc` не
участвуют ни в одном прогоне. Все числа ниже сняты 26 августа 2026 двоичным
`/srv/flang-rabota/w-predely/bootstrap/flang`.

**1. Служба поднимается и отвечает.** `flang io serve.flang --plan "Обслужить по
сети"` слушает 39415, спрашивает её `flang io ask.flang` — тоже программа на
flang:

```
GET /здоровье  → HTTP/1.1 200 OK … Content-Length: 10 … живой         код 0
GET /длина/27  → HTTP/1.1 200 OK … Content-Length: 3 … 111            код 0
GET /длина/0   → HTTP/1.1 400 Bad Request … цепочка не сошлась …      код 0
GET /здоровье  → HTTP/1.1 200 OK … живой   (служба пережила ядовитый) код 0
```

**2. Три процесса, и работа идёт через все три.** Прогон «работа проходит через
все три процесса»: пробегов 4, журнал `["Приёмная","Счётчик","Приёмная","Журнал"]`,
состояния — «принято» 1, «сосчитано» 1, «строки» `["6 → 8"]`.

**3. Обработчик падает — надзор перезапускает, служба отвечает дальше.** Прогон
на СВОЁМ планировщике (цель js, `flang/src/emit/js/flang_conc.js`, BEAM не
участвует):

```
"отказы":[{"процесс":"Счётчик","код":"FLANG_BUDGET_EXHAUSTED",
  "сообщение":"функция «Шагов Коллатца» исчерпала лимит шагов (20000) на глубине вызовов 1"}],
"решения":[{"процесс":"Счётчик","надзор":"Служба шагов","стратегия":"перезапустить"}],
"живые":["Приёмная","Счётчик","Журнал"],
"Приёмная":{"принято":3,"ответы":["…\r\n\r\n8","…\r\n\r\n111"]},
"Счётчик":{"сосчитано":1},"Журнал":{"строки":["6 → 8","27 → 111"]}
```

Тот же прогон на настоящем дереве супервизоров OTP (цель elixir, BEAM) дал те же
состояния и тот же отказ `FLANG_BUDGET_EXHAUSTED`, пробегов 10.

**4. Запас витков назван у каждого обработчика, программа принята.** Три
обработчика с запасами 200000 / 20000 / 2000; `flang check service.flang` —
замечаний нет, код 2 («процессы, надзоры, прогоны бинарник не судит вовсе»).
`flang test examples/service-on-processes` — примеров 829 (своих 92), прошло 829,
не прошло 0, за 148 963 мс, код 0.

**5. Ведомость.** `flang check core.flang --proof`, код 0: функций 77 (тотальных
76), утверждений 113: доказано 32, сетка 81, объявлено-не-доказано 0. Из девяти
собственных обещаний службы доказано шесть.

## Что найдено попутно и не починено

* **Строка `с запасом N витков` сегодня НЕ ПРИНУЖДАЕТСЯ НИКЕМ.** Отрицательный
  контроль: `examples/web/shortener/handler-without-budget.flang`, написанный как
  улика «программа без запаса не собирается», нынешним двоичным принимается —
  «проверено НЕ ДО КОНЦА … прошли», код 2. Правило живёт в слое, которого в
  замыкании двоичного нет.
* **Сеть и процессы не сходятся ни у одного доступного хозяина.** У Elixir и js
  поручений нет вовсе; у C есть и то и другое, но печать конкурентности в C в
  закоммиченное семя не попала (задача 0041).
* **Сторож объявленной меры съедает хвостовой вызов.** У тотальной по мере
  функции запас витков и глубина стека — разные величины: «Шагов Коллатца в
  пределе» с запасом 100000 роняла службу `FLANG_RECURSION_LIMIT` на глубине
  10001. Запас плана поэтому 5000, и число это снято прогоном.
* **Печать в Elixir даёт предупреждение**: `variable t861 in code block has no
  effect` в `fn_napechatat_otvet_sluzhby/1`. Контракт бэкенда обещает печать без
  единого предупреждения.
