# 7205. Файлы без ведомости: работа, которая делится на многих

**Это самая делимая работа дерева.** Файлы независимы: один файл — один прогон —
один приговор. Двадцать человек возьмут двадцать файлов и не помешают друг
другу ничем, кроме мест у ворот.

## Чем это снимается

Приёмом из задачи **6128** и никаким другим. Общий двоичный дерево ядра
прочесть не может вовсе (`FLANG_TYPE_ARGS`). Приём собран и лежит готовым:

* двоичный — `/srv/flang-rabota/m-kernel-ledger/build-kernel/flang` (14 МБ):
  `compiler_flang.c` из семени **дословно**, `flang_runtime.c`/`.h` из
  `flang/src/emit/c/` **дословно**, `flang_repl.c` из дерева плюс заплата ключа
  предела;
* **блок настроек из шапки семени переносить обязательно.** Без него
  `FL_MAX_TAIL_ARGS` падает с 9 до 4 и первый же `check` бьёт стек — записано в
  `docs/zettel/a-seed-with-tree-runtime-smashes-the-stack-without-its-limits-block.md`;
* ключ — `--предел-шагов 400000000000`. Он **задаёт** предел, а не поднимает:
  поставить «с запасом» 400000000 значит опустить его вдесятеро;
* ворота — `env PAMYAT=45G /srv/flang-rabota/vorota/flang-vorota -- …`.

## Как делить работу

По файлам, а не по кучам. Каждый берёт список файлов, объявляет доли
(`/srv/priyom/claim взять <ветка> <файл>…` — доли нужны на **выходы**, а не на
исходники: исходники никто не правит) и пускает по одному-двум прогонам, а не
веером: один прогон берёт 45–60 ГиБ на десятки минут.

Порядок — по возрастанию цены, чтобы дешёвое не ждало дорогого. Цена
определяется **замыканием ввоза**, а не числом обязательств: ядро при 44
обязательствах шло 52 мин при пике 9,65 ГиБ.

**Срок ставить не 150 секунд.** Семьдесят одному файлу из девяноста шести его
не хватило, и это единственное, что их остановило.

## Как понять, что сделано

Для каждого взятого файла есть выход `check --proof` и приговор **по самому
файлу**, посчитанный отдельно от ввезённого:

```sh
python3 <приём>/dolya-fajla.py <файл>.flang <выход>.out
# ДВА СЧЁТА СОШЛИСЬ. Доказано N из M = …
```

Строка «итог:» в счёт **не идёт**: она берёт замыкание и завышает — на ядре в
34,2 раза, на `proofterm` в 12,9.

Задача считается сделанной, когда **число файлов без ведомости равно нулю**, а
каждый файл, который не дался и с приёмом, переехал в другую кучу с названной
причиной — не остался в этой.
