# 8581 — хук перед пушем

## Откуда задача

Просил владелец, дословно: «ты не можешь просто завести pre-push action
который бы и гонял как раз все у нас и тогда бы мы были уверены что пушим
зеленое».

Беда настоящая. CI стоит **134 минуты раннера на пуш** (задача 9420), и
красное всё равно приезжает: на `main` CI был красен с 4 сентября, а на
`dev` он до 5 сентября не ходил вовсе — 74 пуша без надзора, и за это
время незамеченным прошёл регресс гейта Г3.

## Главное решение: в хук идут только дешёвые

Полный набор — те же 134 минуты. Хук такой длины обошли бы через
`--no-verify`, и он стал бы **хуже, чем никакого**: создавал бы чувство
проверенности, не проверяя.

Поэтому взяты только те, что укладываются в секунды, а хук **каждый раз
печатает словами, чего он не проверил**. Молчащий о своих границах хук
врёт самим фактом зелёного вывода.

## Что взято и почему — замер, а не список из наряда

Все девять прогнаны поодиночке (`/usr/bin/time`, машина под нагрузкой):

```
задачник:проверка                          48,5 с   код 0
pol-dokazannogo-sverka.sh                  11,4 с   код 0
лицензии:проверка                           7,8 с   код 0
prose-numbers-guard.sh                      6,1 с   код 0
версия:проверка                             4,2 с   код 0
пакет:проверка                              4,1 с   код 0
kto-zovet-storozhey.sh --check              0,3 с   код 0
storozha-bez-podloga.sh --check             0,2 с   код 0
semya-rantayma-eto-istochnik.sh             0,1 с   код 0
                                    сумма  82,7 с
```

**Хук гонит их параллельно и укладывается в 50 секунд** — потолок держит
`задачник`, самый дорогой из девяти.

## Что отвергнуто и почему

```
./ярлык тесты                    дольше 2 минут — замерено, оборвано таймаутом
набор проб чекера (прогон.sh)    минуты
./ярлык сколько-верим (потолок Г3) минуты, нужен --max-steps 2e9
сборка bootstrap                 5–6 минут (и 322 с только на LTO, задача о цене CI)
семь сторожей дороже 120 с       см. scripts/kto-zovet-storozhey.sh
```

**`scripts/chto-otstalo-ot-semeni.sh` отвергнут по другой причине: он не
умеет краснеть.** Единственный ненулевой выход — `exit 2`, если семени нет
вовсе; отставание он печатает и отвечает нулём. Это отчёт, а не сторож, и
в хуке был бы украшением, создающим вид проверки. Проверено чтением всех
его `exit`.

## Двоичный хук не собирает

`./ярлык` при отсутствии `bootstrap/flang` полез бы собирать — 5–6 минут.
Хук этого не делает: если двоичного нет, четыре проверки, которым он
нужен, пропускаются, и хук **называет их поимённо** вместе с командой
сборки.

## Проба порчи — в обе стороны, настоящим `git push`

Мало прогнать сам скрипт: надо убедиться, что git его зовёт.

```
чистое дерево, git push          хук зелен, пуш прошёл
сломано число в прозе            «порча собралась»: вхождений 999 стало 1 (было 0)
git push со сломанным            ПУШ ОСТАНОВЛЕН, названы сторож, файл, строка,
                                 git: «failed to push some refs»
откат                            хук зелен
git push --no-verify             прошёл, вывода хука нет вовсе (0 вхождений)
```

Дословно из красного прогона:

```
ПУШ ОСТАНОВЛЕН: красных проверок 1.
───── proza ─────
docs/tree-inventory.md:44: ПРИМЕТА ОТОРВАЛАСЬ ОТ ПРОЗЫ — числа 21 нет ни на
этой строке, ни в трёх выше
сторож чисел: числа в прозе разошлись с деревом — мест 1
```

**Оговорка о собственной ошибке при замере.** Код `git push` в конвейере
через `| tail` показал ноль — это код `tail`, а не пуша. Настоящая улика
красноты — строка «failed to push some refs» и то, что ветка в приёмнике
не сдвинулась. Та же грабля, на которой за сутки попались трое.

## Установка

```sh
git config core.hooksPath .githooks
```

Каталог лежит в дереве — значит хук приезжает с клоном и правится как код,
а не переписывается руками в каждом `.git/hooks`.

## Обход оставлен намеренно

`--no-verify` никуда не денется, и бороться с ним нельзя. Вместо этого в
шапке хука написано, когда обход законен: пуш ветки работника, которую не
сливают напрямую; починка самого хука; заведомо красное дерево по
названному долгу. В прочих случаях обход значит «пусть CI жжёт минуты за
меня».

## Попутно исправлено в CONTRIBUTING.md

Там стояло «CI runs on tags and on demand, not on every push» — **сегодня
это перестало быть правдой**: пуш-триггер вернули на `main` и `dev`
(задача 9420). Фраза заменена на верную, и рядом названа цена в 134
минуты.

## Не сделано

* Хук проверяет **рабочее дерево** на момент пуша, а не те коммиты, что
  пушатся. Для вопроса «зелено ли то, что я отправляю» это верно, но
  разница есть, и её стоит знать.
* Набор из девяти не сверяется ни с чем автоматически: заведут нового
  дешёвого сторожа — в хук он сам не попадёт. Прибор для этого есть
  (`scripts/kto-zovet-storozhey.sh` знает цену каждого), связать их —
  отдельная работа.
* Времена сняты на машине под нагрузкой; на тихой будут меньше, но
  порядок тот же.
