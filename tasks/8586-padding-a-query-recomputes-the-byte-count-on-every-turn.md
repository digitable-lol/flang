# 8586. «Дополнить запрос» считает длину заново на каждом из 128 витков

## Почему заведена

30 августа 2026 шаг CI «Примеры stdlib и ядра» краснел на четырёх файлах
библиотеки. Три из них (`json`, `tls`, `tls-handshake`) упирались в предел шагов
САМОГО СЕМЕНИ — миллиард; это лечится перепечаткой и здесь ни при чём.
Четвёртый, `postgres`, упирался в ДРУГОЕ число:

```
flang/stdlib/postgres.flang: пример «непечатаемая длина дополняется пробелами:
122 знака запроса требуют 128 пробелов» функции «Дополнить запрос» не прошёл:
функция «Байтов в тексте» исчерпала лимит шагов (40000000) на глубине вызовов 54
```

40 000 000 — это вшитое умолчание команды `flang test`
(`const char *steps = "40000000"` в `flang/src/emit/c/flang_repl.c`), предел
ВЫЧИСЛЯЕМОЙ программы. Перепечатка семени его не трогает вовсе: `steps` уходит
в довод прогонщика, а не в счётчик рантайма.

Сорвал пример коммит `8ba38d0a` (27 августа 17:43, ветка
`u/library-weakest-modules`, влита как `e3fac622`) — восемь безохранных
дизъюнкций «ответ есть одна из N ветвей тела» в `wire.flang`, одна из них на
шаге свёртки «Шаг веса текста». Она снята коммитом `7ed75077`, и пример снова
проходит. **Но это вернуло красное в зелёное, а не дало запас.**

## Числа перебора предела — их не надо мерять заново

Ствол `1e74933d` (то есть уже с правкой `7ed75077`), двоичный собран из семени
этого же дерева (`make -C bootstrap`), прогон под воротами
(`PAMYAT=16G PIK=6G`, замеренный пик 5,3 ГиБ):

```sh
./bootstrap/flang test flang/stdlib/postgres.flang --max-steps N
```

| N | чем кончилось | время |
|---:|---|---:|
| 30 000 000 | 208 из 209, срывается тот же пример | 496 с |
| 33 000 000 | 208 из 209, срывается тот же пример | 492 с |
| 37 000 000 | **209 из 209** | 499 с |
| 40 000 000 (умолчание) | **209 из 209** | 492 с |

Значит пример просит **между 33 и 37 миллионами при потолке 40**: запаса от
восьми до восемнадцати процентов. По правилу самого дерева («то, что перевалило
за половину, в следующий раз не поместится») это уже не запас. Следующее
обещание, положенное на путь «Байтов в тексте», снова уронит файл — и уронит его
не там, где будет написано.

## Откуда цена

`flang/stdlib/postgres.flang`, тело «Дополнить запрос»:

```
если запас не больше 0
  то запрос
  иначе (если («Четыре октета печатаются» от (надбавка плюс («Байтов в тексте» от запрос)))
           то запрос
           иначе «Дополнить запрос» от (соединить запрос с " ") и надбавка и (запас минус 1))
```

Витков 128 (122 знака запроса, надбавка 6), и на КАЖДОМ «Байтов в тексте»
проходит строку целиком заново — строка при этом растёт со 122 знаков до 250.
Это квадрат по числу досыпанных пробелов. Пробел в ASCII весит ровно один байт,
поэтому пересчёта не нужно вовсе: длину можно нести доводом и прибавлять к ней
единицу на витке.

Обещания при этом проверяются НА КАЖДОМ ВЫЗОВЕ, пока идут примеры, и одно из
обещаний самой «Дополнить запрос» («пробелы сыплются, пока длина не станет
записываемой…») тоже зовёт «Байтов в тексте» — уже от результата. Значит правка
тела снимает примерно половину цены, а не всю. Это надо замерить, а не обещать.

## Что сделать

1. Завести шаг с накопителем — «Досыпать пробелы» от запроса, надбавки, запаса и
   уже посчитанных байтов, — а «Дополнить запрос» оставить оболочкой, считающей
   «Байтов в тексте» ОДИН раз.
2. Сохранить все пять обещаний «Дополнить запрос» и три её примера дословно.
3. Проверить, что **сетка не выросла**: `check --proof --json` на
   `postgres.flang` до и после, сравнить `claims.grid`. Сегодня у `wire.flang`
   она 36, у `postgres.flang` снимается тем же прогоном.
4. Переснять перебор предела и вписать сюда новые числа.

## Как понять, что сделано

```sh
make -C bootstrap -j"$(nproc)"
./bootstrap/flang test flang/stdlib/postgres.flang                      # 209 из 209, код 0
./bootstrap/flang test flang/stdlib/postgres.flang --max-steps 20000000 # 209 из 209, код 0
./bootstrap/flang check flang/stdlib/postgres.flang --proof --json      # сетка не выросла
```

Сделанной задача считается, когда пример проходит при **20 000 000** — то есть с
запасом вдвое к нынешнему умолчанию, а не с восемью процентами. Прогоны — под
воротами, свой пик мерить: `PAMYAT=16G PIK=6G` хватало на всех замерах выше.
