# 8649. npm уходит из дерева: публикации нет, а Windows остаётся без пути установки

Решение владельца: убрать npm. Здесь записано, что именно снято, чем это
проверено и — главное — **что при этом потеряно**. Второе важнее первого:
удалить умеет всякий, назвать цену — нет.

## Что снято поимённо

**Работа CI.** `.github/workflows/publish-npm.yml` (264 строки) делала две
работы сразу: собирала релизный архив C99 и публиковала пакет. Половина про
публикацию удалена, половина про архив живёт дальше в
`.github/workflows/release.yml`. Удалённые шаги:

| шаг | что делал |
|---|---|
| «Установить зависимости» | `npm ci` — и заодно собирал двоичный через `postinstall` |
| «Проверить состав пакета» | `npm pack --dry-run --json`, искал тестовые файлы в тарболе |
| «Проверить, что пакет ставится и отдаёт двоичный» | `npm install` тарбола в пустой каталог, `node_modules/.bin/flang --version` |
| «Проверить, настроен ли секрет» | читал `secrets.NPM_TOKEN`, ставил `configured=yes/no` |
| «Опубликовать» | `npm publish --access public --provenance` |
| «Показать, что было бы опубликовано» | `npm publish --access public --dry-run` |

Вместе с ними снято право `id-token: write` — оно было нужно только провенансу
npm.

**Секрет `NPM_TOKEN` в хранилище GitHub не тронут.** Его читал единственный
шаг, и шага больше нет: задан токен или нет, ни одна работа дерева его теперь
не спрашивает. Убирать сам секрет — решение владельца, не этой правки.

**Поля `package.json`.** Файл остался (он — единственное место, где живёт
версия), но лишился всего, что описывало пакет:

| поле | что в нём было | почему снято |
|---|---|---|
| `bin` | `flang` → `./packaging/flang-launch.mjs`, `flang-lsp` → `./flang/bin/flang-lsp.mjs` | обе обёртки удалены |
| `files` | 24 пути: раскладка публикуемого тарбола | публикации нет — раскладывать нечего |
| `scripts.postinstall` | `node packaging/postinstall.mjs` | файл удалён |
| `scripts.prepublishOnly` | `npm test` | публикации нет |
| `scripts.test` | `./ярлык тесты` | npm подставлял строку и больше ничего |

Добавлено одно поле: **`"private": true`**. Это не напоминание, а замок:
`npm publish` на таком файле отказывает сам, не спрашивая ни токена, ни сети.

**Файлы.** Удалено семь, 1482 строки:

| файл | строк | что это было |
|---|---|---|
| `.github/workflows/publish-npm.yml` | 264 | работа публикации (архивная половина переехала) |
| `flang/scripts/npm-install.flang` | 505 | сквозная проверка пути установки из npm; ярлык `установка:npm` |
| `scripts/commands-via-symlink.flang` | 419 | команды пакета через символьную ссылку; список брался из `bin` |
| `packaging/postinstall.mjs` | 173 | сборка двоичного при `npm install` |
| `packaging/flang-launch.mjs` | 55 | обёртка команды `flang` |
| `flang/bin/flang-lsp.mjs` | 46 | обёртка команды `flang-lsp` (каталог `flang/bin/` исчез) |
| `package-lock.json` | 20 | жил ради `npm ci` в четырёх работах CI |

## ЧТО ПОТЕРЯНО: установка под Windows

Обёртки были `.mjs` **не по прихоти**. `bin` в npm обязан быть файлом, который
запустит `node`, — иначе пакет не ставится под Windows. Так делают esbuild и
swc, и по той же причине. Убрав npm, дерево убрало и этот путь установки.

Что осталось: релизный архив `flang-<версия>-c.tar.gz` (исходники C99 под
`make`) и формула Homebrew. **Homebrew под Windows не ставит. Архив требует
`make` и C99.** Третьей дороги нет.

Смягчает это ровно одно, и это надо сказать честно, а не как утешение:

* **Под Windows этот путь никто никогда не проверял.** Так и записано в шапке
  `.github/workflows/install-path.yml`: «Windows не проверяется ни здесь, ни
  где-либо ещё». Работы CI ходят на ubuntu и macos.
* **Под именем `@digitable-lol/flang` не было выложено ничего.** README обеих
  раскладок говорил это прямо и звал ставить из клона.
* **Даже поставившись, пакет не дал бы Windows работающий компилятор без C99 и
  `make`:** `postinstall.mjs` звал `make`, и без него команда `flang` отвечала
  отказом с кодом 3.

То есть потеряно **обещание**, а не работавшая дорога. Но другого обещания для
Windows у дерева не было, и теперь нет никакого.

### Строка для примечания к выпуску

> **Windows.** Пакет npm убран, и вместе с ним ушёл единственный путь установки,
> который дерево обещало пользователям Windows. Проверен под Windows он при этом
> не был ни разу, и под именем `@digitable-lol/flang` в реестре ничего не
> публиковалось. Сегодня flang ставится из релизного архива C99 (нужны `cc` и
> `make`) или через `brew install digitable-lol/tap/flang`; под Windows это
> означает MSYS2, WSL или другой набор с C99 — родного пути нет.

## Довод, который нельзя потерять вместе с обёрткой

В шапке `packaging/flang-launch.mjs` был записан довод, почему **нет** отката на
реализацию Node, когда двоичного нет. Обёртка удалена; довод переносится сюда
целиком, потому что он о выборе, а не о файле.

**Молчаливая подмена компилятора и есть та беда, ради которой всё
затевалось.** Человек, поставивший язык через `brew`, и человек, поставивший
через `npm`, получали две разные программы под одним именем `flang`: из brew
приезжал двоичный, из npm — вторая реализация на JavaScript. Расхождение
измерено: **54 расхождения из 59 вызовов** одного корпуса, побайтовая сверка
кода возврата, вывода и потока ошибок (`packaging/install-parity.flang`, ветка
`vypusk/npm-dvoichnyy`, 20 августа 2026). Совпали ровно пять вызовов, и все пять
машинные; расходилось всё, что читает человек, — все двенадцать справок, все
тексты отказов, весь человеческий вывод `check` и `test`.

Поэтому запускатель, не найдя двоичного, ОТКАЗЫВАЛ с названной причиной и кодом
3 («сломался инструмент»), а не подставлял тихо второй компилятор. Правило
остаётся правилом дерева и после ухода npm: **две программы под одним именем —
это дефект, даже когда обе работают.**

Разбор целиком:
`docs/zettel/two-installs-answered-differently-on-54-calls-of-59.md`. Сам прибор
(`packaging/install-parity.flang`) в дереве оставлен: он сверяет ЛЮБЫЕ две
установки, а не только npm с brew.

## Что ещё сломалось бы молча и починено здесь же

**Выпуск падал на первом же собственном шаге, и до этой правки — всегда.** Шаг
«Собрать релизный архив C» зовёт `bootstrap/flang`, а собирать его в том файле
было некому: `bootstrap/flang` — продукт сборки и в дереве не лежит, `npm ci`
клал двоичный в `dvoichnyy/`, а единственное место, которое собирает семя само
(`./ярлык`), звалось шагом `npm test` ПОСЛЕ архива. То же самое записано словами
в шапке `./ярлык`: «там `bootstrap/flang` не собирает никто». В
`release.yml` семя собирается явным шагом до архива.

**`flang/scripts/direct-run-guard.mjs` спрашивал у `package.json`, кому можно
держать свою копию функции «запущенНапрямую»** — считал законной копию в файле,
уезжающем в пакет. Раздела `files` больше нет, и вопрос потерял предмет. Список
законных копий назван прямо, одним именем с причиной
(`flang/src/emit/js/flang_cli.js` — покидает дерево, кладётся рядом с
напечатанной программой). Ручной список держит от протухания своя проверка:
имя, которого в дереве нет, красит сторожа.

**`scripts/commands-via-symlink.flang` брал список команд из `bin`** и после
урезания отвечал «в разделе bin пакета команд 0 — package.json урезали?».
Сторож снят вместе с работой `komandy` в `ci.yml`. Порода, которую он ловил
(версия 0.4.0 уехала в реестр молчащей: страж точки входа на Node сравнивал
`import.meta.url` с `process.argv[1]` как строки, а npm кладёт ссылку), умеет
только Node — а точек входа на Node в дереве больше нет. Само написание
запрещено сторожем `flang/scripts/direct-run-guard.mjs`. Живой запуск через
ссылку не потерян: `brew` кладёт двоичный ссылкой из Cellar, и работа `brew`
в `install-path.yml` ставит формулу по-настоящему.

**`scripts/test-remote.sh` гнал `npm ci` на удалённой машине** — без замка он
отвечает кодом 1 и уронил бы прогон, ничего не поставив. Шаг снят; двоичный
собирает сам `./ярлык` на той стороне.

**Ведомость перечней** (`scripts/hand-written-lists-ledger.tsv`) несла запись о
перечне внутри `packaging/flang-launch.mjs`. Запись, переставшая быть
расхождением, красит `перечни:проверка` — снята.

## Что в дереве по-прежнему упоминает npm, и почему это не грех

Остатки названы, а не забыты:

* **`docs/zettel/*`, `tasks/*`, `CHANGELOG.md`, `changelog.json`, `ROADMAP.md`,
  `docs/HANDOFF.md`, `docs/ci-inventory.md`** — записи о том, как было. Журнал
  не переписывают: он тем и ценен, что называет прошлое.
* **`editors/vscode/`** — манифест расширения VS Code и его инструкции. Это
  реестр расширений, а не npm-реестр пакетов; решение владельца его не касалось.
* **`packaging/install-parity.flang`** — прибор сверки двух установок; в его
  шапке npm назван как случай, на котором он был снят.
* **`.github/SECURITY.md`** — область охвата всё ещё называет опубликованный
  пакет.
* **`engines: node >=20` в `package.json`** — это не про npm: число объявляет ту
  версию Node, на которой работают оставшиеся в дереве `.mjs` (набор проверок,
  сборка сайта, печать журнала).
