# 8690 — дело не в чекере: записи корпуса напечатаны старым двоичным

## Как найдено

Задача была собрать описанные, но не влитые правила чекера — прежде всего
9951 («формы не больше/не меньше, +2,08 % Г4»). По дороге выяснилось, что
самый крупный рычаг лежит не в чекере вовсе.

## 1. Обещание 9951 УЖЕ СОБРАНО, и не тем путём

9951 называет четыре записи, каждая из которых держится ровно на одном
месте, и обещает за них +2,08 %. Прогон обоими двоичными:

```
                            ДО правила 9999   ПОСЛЕ (сегодня)
corpus-natural                    код 3            код 0
corpus-natural-ceiling            код 3            код 0
order                             код 3            код 0
granica-nad-chislom-chestnaya     код 0            код 0
```

Три из четырёх закрыло правило 9999 («цель следует из объявленного о
доводах», коммит `f5d378a1`), четвёртая была закрыта и раньше. Обещанные
+2,08 % входят в сегодняшний сдвиг 12,08 → 13,75 %. **Остатка по Г4 у
задачи 9951 нет.**

## 2. ГЛАВНОЕ: 93 шага «по примеру» из 93 не несут привязки

`сверщик.c:1199` описывает работу ячейки Ч71: шаг `по примеру «имя»`
проверяется ШЕСТЬЮ проверками, каждая — чтение исходника. Работать они
могут только если ядро выписало в конец строки шага привязку
`пример строка N`.

```
шагов «по примеру» в корпусе          93
из них С привязкой                     0
без привязки                          93
```

**То есть шесть проверок, написанных, влитых и лежащих в дереве, не
отработали ни разу ни на одной записи корпуса.** Порода известная — оснастка,
которую никто не зовёт (задачи 9990, 7298), — но здесь она внутри самого
прибора Г4.

Причина не в ядре: `flang/self/zapis.flang:742` привязку ПИШЕТ, и в семени
она есть. Записи корпуса напечатаны 3 сентября (`4312a476`) двоичным, у
которого этого ещё не было.

## 3. Что даёт перепечатка записей — замерено

Все 86 записей перепечатаны нынешним двоичным (`flang check <исходник>
--proof --записать`, около секунды на запись, 86 секунд на весь корпус) в
каталог ВНЕ дерева. Ни одна запись в дереве не тронута.

```
привязок «пример строка»    0 → 93

записей код 0               28 → 33
записей код 1 (ложный отказ) 0 →  0
утверждений (числитель)     33 → 43
знаменатель                240 → 240

ДОЛЯ Г4                  13,75 % → 17,92 %
```

Знаменатель и старый числитель сошлись с прибором `доля-корпуса.sh` знак в
знак (33 из 240 = 13,75 %), значит счёт верен.

**Ни одной строки в чекере при этом не менялось.**

## 4. Почему это не накрутка — проверено тремя порчами

Привязка не принимается на слово: проверка 1 требует, чтобы на строке N
исходника стояло ровно `пример «имя»` из обоснования шага.

```
честная перепечатанная запись            код 0
привязка сдвинута на соседнюю строку     код 1  «а там написано „ожидается…"»
привязка на строку, где примера нет      код 1
имя примера подменено, привязка та же    код 1
```

## 5. Потолок этой дороги: 18 записей она не берёт

После перепечатки 18 записей всё ещё держатся только шагами, и причина
названа чекером честно:

```
шаг вне случая не проверен — вид цели
«(свёртка (разложить результат на символы) начиная с да как акк и «з» → …) равен да»
сверщику незнаком
```

Это цели со свёрткой. Чтобы их брать, чекеру нужен вычислитель — то есть
ровно та граница Г3, которую здесь держат намеренно. Дальше этой дорогой
без отдельного решения не пройти.

## Что надо решить владельцу

**Перепечатывать ли записи корпуса в дереве.** Довод за: прибор Г4 сегодня
меряет не чекер, а возраст записей; 10 утверждений из 240 не засчитаны
только потому, что запись старше двоичного. Довод против: корпус — это
измерительный прибор, и перепечатка меняет прибор; делать это надо
отдельным решением и с записанным происхождением, а не походя.

Работник корпус НЕ перепечатывал в дереве — только вне его, для замера.

## Приложение: зеркало порядка и рефлексивность меры — сделаны и ОТКАЧЕНЫ

Второе, что описывала 9951: зеркало (`A не больше B` ⇔ `B не меньше A`) и
рефлексивность на мере (`X не меньше X`, когда X сводится к `длина …`).

Написаны, собраны под `-Werror -pedantic`, работают: запись `boundaries`
идёт с «посылок и утверждений 4, не закрылось 4» на «2 и 2» — ровно тот
сдвиг, что намерил F4.

Равносильность зеркала проверена прогоном ЯДРА, а не принята:

```
числа      «а не больше б» и «б не меньше а» сошлись на 2<3, 3=3, 4>3
не-числа   обе записи дают ОДНУ ошибку «сравнения порядка допустимы
           только для чисел»
```

Попутно это уточняет довод в коде: там написано, что «Т не больше Т»
ЛОЖНО на не-числе; на деле это ошибка типа, а не ложь.

**ОТКАЧЕНО, и вот почему.** Набор проб поймал: подделка
`Ч369/П1-порядок-вместо-равенства` стала приниматься кодом 0 при ожидаемом
3, то есть сломался инвариант «подделок принято кодом 0 — ноль».

Разбор показал, что закрытие ЗАКОННО: мутант меняет
`результат равен (длина элементы)` на `результат не больше (длина элементы)`
при теле `если порог больше 0 то (длина элементы) иначе 0`; постусловие
истинно, `flang check` даёт код 0. Мутанты Ч369 — не лжи, а ослабления,
которыми проверяют, что каждая посылка приёма «разбор цели по условию»
несущая; моё правило закрывает мутанта ДРУГОЙ дверью, посылку не трогая.

Но менять ожидание пробы класса P — значит трогать самый сильный инвариант
дерева, а правило при этом даёт Г4 **ноль** (два места из шести в
`boundaries`, вердикт записи — всё или ничего). Плата за ноль слишком
велика, поэтому правило откачено, а решение вынесено сюда.

Код правила лежит рядом: `tasks/8690-zerkalo-i-refleksivnost.patch` —
накладывается на `flang/proof/чекер/сверщик.c` командой `git apply`. Взять
его можно только вместе с решением по пробе Ч369-П1.
