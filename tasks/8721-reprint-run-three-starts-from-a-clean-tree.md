# 8721. Третий заход перепечатки пускается из чистой копии ствола

## Чем измерено

Рабочая копия `/srv/flang-rabota/m-reprint-2` держит **правленые руками файлы
семени**. Снято 29 августа 2026:

```
$ git -C /srv/flang-rabota/m-reprint-2 status --short -- bootstrap/
 M bootstrap/flang_runtime.c
 M bootstrap/flang_runtime.h

$ git -C /srv/flang-rabota/m-reprint-2 diff --stat -- bootstrap/
 bootstrap/flang_runtime.c | Bin 173362 -> 269485 bytes
 bootstrap/flang_runtime.h | Bin  61209 ->  71592 bytes
```

Правки не мелкие: `flang_runtime.c` вырос в 1,55 раза, заголовок — в 1,17.

Почему это тупик, сказано в `AGENTS.md`, раздел «Три правила, за которые платят
дороже всего», правило 1: `bootstrap/**` печатается перепечаткой, и **приёмная
отвергает коммит, который их трогает.** Довод там же и он не про придирку: git
сливает эти файлы без единого знака конфликта и разводит ствол молча.

Значит из `m-reprint-2` результат захода сдать нельзя ни при каком исходе:
удачный заход даст ветку, которую приёмная отвергнет целиком.

## Что сделать

Завести чистую копию ствола и внести в неё **только** правку в
`flang/self/**` — ту, ради которой заход делается:

```sh
git clone /srv/flang-priyom.git /srv/flang-rabota/<своё-имя>
cd /srv/flang-rabota/<своё-имя>
git fetch /srv/flang-priyom.git main && git checkout -B main FETCH_HEAD
```

Если правка в `bootstrap/flang_runtime.*` из `m-reprint-2` нужна по существу —
её надо сначала объяснить и провести через `flang/src/emit/c/`, откуда рантайм
уезжает в вывод дословно, а не через правку семени. Иначе следующая
перепечатка её сотрёт, и никто не заметит.

## Как понять, что сделано

```sh
git status --short -- bootstrap/     # пусто
sh scripts/seed-freshness.sh          # честный ответ о свежести семени
```

Заход пущен из дерева, в котором `git status -- bootstrap/` молчит, и ветка
захода проходит приёмную (`git push /srv/flang-priyom.git HEAD:refs/heads/…`
без отказа).

## Что от неё зависит

Всё, что ждёт перепечатки: задачи 1853 (процессы), 6818 (список препятствий),
работа над правилами процессов и планов. Пока заход идёт из грязного дерева,
даже удачный заход не превращается в семя.

## Чем закрыта

Закрыта коммитом `52996005` («build(semya): компилятор перепечатан — отставание
семени с сорока пяти файлов до пяти строк», 30 августа 2026, 09:32:52 UTC):
дошедший заход перепечатки был пущен **из чистой копии ствола**, ровно как эта
задача требовала. Подтверждено прогонами 30 августа, не рассуждением.

**Копия захода заведена клоном, а не взята готовой.** Заход 4 шёл в
`/srv/flang-rabota/m-reprint-4`; `git reflog` этой копии:
`clone: from /srv/priyom/stvol`, голова — `f9e67fa6`.

**Семя копии на минуту начала совпадало со стволом:**

```
$ git diff --quiet f9e67fa6 52996005^ -- bootstrap scripts/otpechatok-semeni; echo $?
0
```

**Напечатанное этой копией легло в ствол без единого расхождения** — все семь
блобов `52996005` совпали с рабочим деревом `m-reprint-4`: `совпало 7 из 7`.

Из `m-reprint-2`, о котором эта задача, заход **не шёл**: правленые руками
`bootstrap/flang_runtime.c` и `flang_runtime.h` лежат там и сегодня
(`git diff --quiet HEAD -- bootstrap` даёт `1`), а напечатанный `flang_runtime.c`
ствола весит 275 184 байта против 269 485 у правки в `m-reprint-2` — это разные
файлы, и правка в семя не поехала.

## Что при закрытии выяснилось и в задаче было записано неверно

Раздел «Как понять, что сделано» требовал, чтобы «ветка захода проходила
приёмную (`git push … без отказа`)». **Это требование невыполнимо.** Крючок
`/srv/flang-priyom.git/hooks/pre-receive` (шаг 2) отвергает всякий коммит,
тронувший `bootstrap[^/]*/` или `scripts/otpechatok-semeni`, — исключения для
перепечатки в нём нет. Прогон на самом коммите перепечатки:

```
$ git diff-tree --no-commit-id --name-only -r 52996005 |
    grep -Eq '^(bootstrap[^/]*/|scripts/otpechatok-semeni$)'; echo $?
0
```

Ноль значит «попало под запрет». Пуш прямо в `main` приёмная отвергает тоже.
Семя легло в ствол иначе — прямым коммитом в рабочей копии ствола, и это видно
в её журнале ссылок:

```
52996005 HEAD@{2026-08-30 09:32:52 +0000}: commit: build(semya): компилятор перепечатан — …
db12d317 HEAD@{2026-08-30 09:32:37 +0000}: reset: moving to origin/main
```

`commit:`, а не `commit (merge): chore(svod): влита …`, как у всякой влитой
ветки.
