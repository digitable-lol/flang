## 1. Откуда берётся теорема — прогоном, а не чтением

Счёт по 86 исходникам корпуса и 86 записям:

```
блоков «теорема «…»» в исходниках   81
строк «теорема «…»» в записях       81
строк «теоремы нет»                278            81 + 278 = 359 = все утверждения
```

Источник у поля теоремы **один — блок `теорема «имя»`, написанный автором**.
Утечки нет: сколько написано, столько и напечатано. Ни «ядро не печатает», ни
«запись теряет» — обе гипотезы дают ноль.

## 3. Теоремы там быть НЕ МОЖЕТ, и это говорит само ядро

Опыт на самом частом виде: `abilities.flang`, У1 «сумма читается в обратном
порядке» — `принимает а: число, б: число`, цель `результат равен (б плюс а)`,
тело `а плюс б`. Дописана теорема, перебраны ВСЕ пять входов языка. Ядро
отказало пять раз из пяти, каждый раз своей причиной:

```
теорема без шага          FLANG_PROOF_STEP  «ни одного шага»
по примеру «два и три»    FLANG_PROOF_STEP  в цели свободны «а», «б» — значений
                                            бесконечно много, а пример один
по свойству «У1 …»        FLANG_PROOF_STEP  ссылается на то самое постусловие,
                                            которое доказывается, — это круг
по закону «…»             FLANG_PROOF_STEP  ни моноида, ни монады, ни изоморфизма
                                            с таким именем не объявлено
по предположению          FLANG_PROOF_INDUCTION_STEP  вне индукции, а допущений
                                            нет: ни посылки, ни `требует`
индукция по а             FLANG_PROOF_INDUCTION_TYPE  у типа «число» принципа
                                            индукции нет
```

Замер, много это или мало. Место закрыто для теоремы, если у функции нет
носителя индукции (ни объявленной суммы, ни встроенного списка, ни `нат`), нет
`требует`, в цели есть свободные имена, в модуле нет закона и тело не зовёт
другую функцию. Таких мест **53 из 161**. Это нижняя оценка: наличие носителя
или `требует` — вход, а не доказательство.

**Вывод по пункту 3 наряда: для трети породы П1 теоремы быть не может в
принципе. Написать её там нельзя не по лени, а по устройству языка.**

## 4. Чинить на стороне ядра нечего — и вот почему

У маршрута `by="declaration"` **нет объекта доказательства**. Ядро не выводит
цель, а РЕШАЕТ её: подставляет тело вместо `результат`, нормализует и сличает с
закрытым списком образцов (17 правил, `flang/self/proof-kernel.flang`). Всё, что
из этого остаётся, — имя сработавшего правила и признак «понадобился ли
объявленный тип», и оба уже печатаются (`zapis.flang:1355`, с `818a2a7c`), и
чекер их уже читает и сверяет (`сверщик.c:1948`, задача 9616). Больше печатать
нечего: `steps` у этого маршрута 0, `cases` пусты, поле `calls` во всём корпусе
встречается **один** раз.

Довод под эти 91 место — это derivation object: цепочка переписок, каждую из
которых чекер может проверить сам. Его в ядре не существует.

**ЦЕНА, названная числами.** Строить его — значит протянуть цепочку через всю
нормализацию и все семнадцать правил: `proof-kernel.flang` строки 1319–8271, то
есть **6952 строки из 8949**. Плюс печать (`zapis.flang`, ~20–40 строк) и плюс
проигрыватель в `сверщик.c` (3808 строк сегодня), которому для проверки цепочки
нужен переписыватель термов — ровно то, чего у чекера нет нарочно
(`сверщик.c:1122` «вычислителя у него нет»). Плюс полная перепечатка семени.
Это работа величиной в неделю на трёх работников, а не правка.

## 5. Что сделано вместо этого — и это дало 5 записей

**Замер тут не мой, а задачи 8690**, лежавшей свободной с пометкой «решение о
перепечатке корпуса за владельцем»; путь к ней открыла 2731, починившая
абсолютный путь в шапке записи. Здесь перепечатка выполнена В ДЕРЕВЕ и померена
после, а не в каталоге вне его.

Записи корпуса не трогали с `4312a476`, а семя с тех пор перепечатано **трижды**
(`f692bab6`, `659d4779`, `6e12ee19`). Печать за это время научилась трём вещам,
которых в записях корпуса не было ни строкой:

* хвост ` пример строка N` у шагов `по примеру` (та самая привязка Ч71/Ч178);
* оглавление списочных литералов (`таблиц N`, `таблица «…» открыта …`, Ч87);
* строки `правило «…»` и `по объявлению да|нет` (`818a2a7c`).

Перепечатка всех 86 нынешним двоичным: **67 записей изменились, +463 строки,
−108**. Ни одна не покраснела.

```
                      было              стало
по ЗАПИСЯМ       28 из 86  32.56 %   33 из 86  38.37 %
по УТВЕРЖДЕНИЯМ  33 из 240 13.75 %   43 из 242 17.77 %
```

Знаменатель по утверждениям 240 → 242: `boundaries` получила два вердикта
«доказано», которых прежний двоичный не давал. Знаменатель по записям — 86, как
решил владелец.

Пять новых зелёных — `corpus-cident`, `corpus-fullwidth`, `corpus-marks`,
`precondition`, `traffic-light`. Ни одна не «ПРОВЕРЕНО ВПУСТУЮ»: у каждой
«числятся доказанными» больше нуля и «на слово ядра» ноль.
Порода, которая их отпустила, — **П3, а не П1**: шагов по примеру проверено по
существу 33 из 93.

## 6. Побочно найдено и починено: линейка себе не верила

`доля-корпуса.sh` сличает два прибора тождеством «П3 = поле чекера «шагов»».
Тождество держалось только потому, что ни один шаг в записях не нёс привязки:
снимать было нечего. С перепечаткой привязку несут 93 шага, 29 из них чекер
снимает со слова ядра — и линейка объявила это РАСХОЖДЕНИЕМ на 18 записях из 86
и уронила прогон кодом 1.

Починено ровно тем же приёмом, каким Ч363 чинила П1: из П3 вычитается число
самого чекера — «Шагов по примеру проверено по существу». Расхождений 0,
самопроверка прибора — девять проб из девяти.
