# 9350. Два сторожа ищут по дереву с пропуском двоичных и потому врут молча

Отделено от задачи 4929: там разобран сторож столкновений имён, здесь —
двое других, которые из-за того же нулевого байта видят дерево неполным.
Оба сегодня ЗЕЛЁНЫЕ, и в этом вся беда: они зелены не потому, что чисто,
а потому, что не досмотрели.

Замеры сняты 29 августа 2026 на ветке `m/guillemets-name-by-layer`.

## Кто и на сколько недосматривает

### `flang/scripts/code-guard.flang` — ярлык `коды:проверка`

Зовёт `git grep -n -I -e FLANG_ -- '*.md'`. Ключ `-I` выбрасывает файлы,
которые git считает двоичными:

```
git grep -n -I -e FLANG_ -- '*.md'   → 430 файлов, 2019 строк
git grep -n -a -e FLANG_ -- '*.md'   → 431 файл,   2020 строк
```

Пропадает `docs/zettel/the-binary-host-cuts-content-at-the-first-zero-octet.md`:
в нём три нулевых байта, первый на смещении 2636 — ВНУТРИ восьмитысячного окна,
по которому git нюхает двоичность. Заметка о том, что нулевой октет обрывает
содержимое, выпала из сторожа ровно по своей же причине.

Сегодня вердикт от этого не меняется: единственный код в потерянном файле —
`FLANG_IO_READ` — стоит ещё в пяти местах прозы. Механизм сломан, ответ спасён
случайностью.

**И сторож сейчас не работает вовсе**, уже не из-за байта:

```
$ bootstrap/flang io flang/scripts/code-guard.flang
код 1
{"error":"git не запустился: программа «git» напечатала больше 1048576 байт",
 "code":"FLANG_KOD_NECHEM_SMOTRET"}
```

Вывод второго `git grep` — 1 158 029 байт при пределе 1 048 576. Отказ ЧЕСТНЫЙ
(сторож говорит «смотреть нечем», а не «чисто»), но проверка `коды:проверка` на
этой ветке красная и ничего не сверяет.

Отдельно, тем же ключом `-I`, но не из-за нулевого байта: вторая команда теряет
весь `bootstrap/` — у него `-diff` в `.gitattributes`, `git check-attr diff --
bootstrap/compiler_flang.c` отвечает `unset`. Разница — 3442 строки против 6304.

### `scripts/manpage-guard.flang` — ярлык `справка:проверка`

Функция `«Доводы grep»` зовёт настоящий `grep` без `-a`:

```
["-rh", "FLANG_", "../flang/self", "../flang/src/emit/c/flang_runtime.c", …]
```

GNU grep на нулевом байте печатает совпадения ДО него и глушит всё после:

```
без -a: 809 строк
с  -a: 810 строк
```

Теряется ровно `flang/self/link.flang:1247` с `FLANG_IMPORT_NOT_FOUND`.

Прогон сторожа отвечает кодом 0 и «набор чист … кодов бед 37 и все существуют».
**Вердикт верен по везению:** тот же код стоит в `link.flang` ещё на строках 813
и 837, до нулевого байта. Перенеси последнее вхождение любого кода за строку
1005 — и сторож объявит код несуществующим, оставаясь зелёным по форме.

## Что сделать

1. `code-guard.flang`: заменить `-I` на `-a` в обеих командах `git grep` и
   пересчитать, что сторож увидит с `bootstrap/` в поле зрения — там 2862
   лишних строки, и они могут потребовать своего отбора, а не просто ключа.
2. `code-guard.flang`: развязать предел в 1 048 576 байт — либо разбить поиск
   на части, либо поднять предел, либо спрашивать git по файлам. Сторож,
   отвечающий «смотреть нечем», не сторож, даже когда отказ честный.
3. `manpage-guard.flang`: приписать `-a` к `«Доводы grep»` и поправить
   обещание `«длина постоянного списка — Доводы grep»` — доводов станет восемь.
4. Проверить нарочной поломкой: перенести вхождение кода за строку 1005 в
   `link.flang` (во временной копии) и убедиться, что сторож краснеет.

## Как понять, что сделано

Оба ярлыка отвечают кодом 0 на чистом дереве и кодом 1 на нарочной поломке,
и числа строк с `-a` и без `-a` у них совпадают.
