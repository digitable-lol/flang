# 9955. Проверки, которые стоят копейки, а платятся часами

Найдено Ч353, 2 сентября 2026, при разборе цены печати. Делать ПОСЛЕ 9953:
сперва цена стадии, потом порядок проверок.

Порядок в дереве сегодня: связывание → типы → тотальность → процессы →
столкновения имён → суд ядра → категории → **ПЕЧАТЬ** → создание каталога →
запись файлов. Три вещи стоят за печатью, хотя ни одна от неё не зависит.

|---|---|---|---|---|---|
| 1 | каталог `--out` создаётся | `flang/src/emit/c/flang_repl.c:9390`, `if (code == 0 && one == NULL && !emit_make_dir(out))` | вся печать | сразу после разбора ключей: путь известен из `argv` | ~3 строки, перенести вызов |
| 2 | «файла «X» печать не даёт» при `--file X` | `flang_repl.c:8877`, внутри `emit_files_out`, код 2 | вся печать | после связывания: набор имён известен из строки цели плюс имя модуля | ~15 строк |
| 3 | пять из шести исходников рантайма читаются в `emit_call` | `flang_repl.c:9155` пробует ТОЛЬКО `flang_runtime.h` (`probe` строки цели) | связывание + типы + тотальность + суд ядра | в той же пробе спрашивать все файлы строки цели | ~10 строк |

## Почему это не мелочь

Печать компилятора на стенде без суда ядра — **7084 с**, из них сама печать
**6450 с** (замер 2 сентября, `scripts/raskrutka.sh`, коммит `c17c565c`). С судом
ядра — 10,4 часа. Любая из трёх ошибок выше сегодня стоит ровно этого времени, а
считается за миллисекунды.

Ошибка 1 достижима буднично: `--out` в каталог без права записи, на полный диск
или с опечаткой в пути.
Ошибка 3 достижима при установке не из дерева: `--runtime` показывает на
каталог, где `flang_runtime.h` есть, а `flang_conc.c` нет.

## Как проверить правку

На каждую — красная проба ДО и зелёная ПОСЛЕ, и обе с временем:

1. `flang emit <малый файл> --target c --out /proc/нельзя-сюда` — сегодня отказ
   приходит после печати; после правки обязан прийти до связывания. Мерить
   секундами, а не словами.
2. `flang emit <малый файл> --target c --file нет-такого.c` — то же.
3. `--runtime` на каталог, где лежит только `flang_runtime.h`, — то же.

Проверять надо, что отказ не только БЫСТРЕЕ, но и остался отказом: код возврата
тот же, что был.
