# 9959 — двоичный называл себя версией на два релиза позади

**Как нашлось.** Владелец поставил через Homebrew: `brew` сказал «flang
0.7.0 already installed and up-to-date». `flang --version` ответил
«flang 0.6.2». Не опечатка, не кеш — воспроизведено с нуля: скачан
настоящий `flang-0.7.0-c.tar.gz` с релиза, собран, `--version` дал
`0.6.2`.

**Причина.** `#define FLANG_VERSION "0.6.2"` — строка, вписанная вручную в
`flang/src/emit/c/flang_repl.c` (рантайм цели печати C) и продублированная
в замороженном семени `bootstrap/flang_repl.c`. Эта строка никогда не
была связана с `package.json` — ни один сторож, ни один сборщик её не
трогает. Когда версию поднимали для 0.6.2, для 0.7.0 и для всех прежних
релизов, эту строку просто забывали.

**Почему это не разовая опечатка, а системная дыра.** Есть шесть мест,
называющих версию проекта, и все шесть обновляются независимо, руками:
`package.json`, `docs/site/numbers.json` (задача, закрытая сегодня раньше),
`packaging/homebrew/flang.rb` — и вот эта, седьмая, которую никто до
сегодня не находил, потому что `flang --version` никто не сверял с
реальным номером релиза при выпуске.

**Починка.** Хотфикс, не переиздание: та же кодовая база 0.7.0, три
места со строкой версии правлены на «0.7.1» (`flang/src/emit/c/flang_repl.c`,
`bootstrap/flang_repl.c`, `package.json`). Архив v0.7.0 уже опубликован и
захеширован формулой Homebrew — переиздать его под тем же номером
нельзя, отсюда новый патч-релиз, а не тихая правка.

**Что осталось сделать, не входит в этот хотфикс.**
1. Найти способ, которым версия попадает в печатаемый C, и завязать его
   на `package.json` (или на общий источник правды), чтобы бампить надо
   было один раз, а не в семи местах руками.
2. Сторож, проверяющий, что `--version` собранного двоичного совпадает с
   тегом релиза — как часть выпускного пути, до публикации, а не после
   жалобы пользователя.
3. Свести все места, называющие версию проекта, в опись — сегодня их не
   меньше шести, и список не полный: искали по факту, не по системе.
