# 9961 — `flang new <пакет>`: максимально простой старт

Владелец: «Инструмент flang new <package>: максимально простой старт.
Программист пишет команду, и у него создаётся готовая структура папок,
включая настроенный fspec/ и базовые файлы с ключевым словом тотальная
функция.»

## Зачем

Сегодня `flang --help` знает `flang lock <файл>` (замок зависимостей) и
`flang package <файл>` (замок с именем, версией и ведомостью) — но
СОЗДАТЬ новый пакет с нуля нечем. Первый опыт с языком — минуты до первой
`тотальная функция`, не поиск по докам, какие файлы и в каком порядке
завести руками. Подкоманды `flang new` в дереве нет вовсе (проверено:
`grep -n "new" flang/self/cli.flang`, `grep -rn "flang new" docs/ tasks/`
— пусто).

## Что должна делать команда

`flang new <имя>` создаёт каталог `<имя>/` и кладёт в него:

1. **Базовый модуль** — файл вида `<имя>.flang` (или по принятой в дереве
   раскладке модулей, см. `docs/guide/naming.ru.md`) с одной настоящей
   `тотальная функция`, не заглушкой: с примером (`пример «…» ожидается
   …`), чтобы `flang check` на свежесозданном пакете сразу отвечал «функций
   1, из них с доказанным завершением 1», а не пустотой. Первое, что видит
   программист после `flang new` — зелёный ответ на непустую программу.
2. **`fspec/`, настроенный и рабочий** — по образцу корневого `fspec/`
   (`fspec/README.md`, `fspec/guard.flang`, `fspec/spec/*.flang`): каталог
   `spec/` с одной спекой-примером (доказанное правило предметной
   области, не декоративная), и `guard.flang`, который её проверяет.
   `bootstrap/flang io <пакет>/fspec/guard.flang` на свежесозданном
   пакете обязан отвечать «спеки согласны» сразу после `flang new`, без
   правок руками.
3. **Манифест пакета** — что-то совместимое с уже существующим `flang
   package <файл>` (прочитать его код первым делом, не гадать формат:
   `flang/self/cli.flang` или где он на самом деле реализован — команда
   в `--help` есть, реализацию найти и прочитать). Имя, версия, пустая
   ведомость.
4. **README** — не шаблонная вода, а то же самое «minutes to first total
   function», что даёт сама команда: как собрать, как проверить, как
   добавить спеку.

## Как проверить, что сделано, а не «выглядит сделанным»

- `flang new проба` в чистом временном каталоге → код 0.
- `flang check проба/проба.flang` (или как файл назовётся по конвенции)
  сразу после — код 0, функций ≥1, доказанных ≥1, БЕЗ правок вручную.
- `bootstrap/flang io проба/fspec/guard.flang` сразу после — «спеки
  согласны», БЕЗ правок вручную.
- Повторный `flang new проба` в тот же каталог — не молча перезаписывает
  чужую работу (спросить, что тут правильно: отказ с кодом и причиной,
  или явный ключ `--силой`/`--force`).
- Проба порчей: `flang new` с недопустимым именем пакета (пробел,
  зарезервированное слово, уже занятое системное имя) — понятная беда, не
  полусозданный каталог.

## Не входит в объём этой задачи

Публикация пакета, разрешение версий чужих зависимостей, реестр — это
`flang lock`/`flang package`/`scripts/registry-example/` (см. пункт 6
`docs/road-to-1-0.md`, «Полноценная история пакетов и модулей», ещё почти
ничего не сделано и отдельная, более крупная задача). `flang new` — это
только генератор стартовой структуры для уже существующего однопакетного
мира, не менеджер зависимостей.
