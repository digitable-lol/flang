# 9962 — список «горячих тасков»: три уровня недостающих библиотек

Владелец: «Список «Горячих тасков»: Чётко пропишите, какие библиотеки
нужны экосистеме. Разбейте их по уровням: простые (парсеры
CLI-аргументов, обёртки над строками), средние (математика, UUID,
работа с датами), сложные (протоколы, парсеры специфичных форматов
данных).»

## Зачем

Стороннему автору сегодня нечем выбрать задачу по силам: нет списка
«вот тут не хватает библиотеки, вот её примерный объём». Хакатон или
любой внешний вклад начинается с вопроса «а что писать» — эта задача
даёт на него ответ трижды: коротко, средне, дорого.

## Что уже есть — проверить ПЕРВЫМ делом, не дублировать

`flang/stdlib/` сегодня — 42 файла (`ls flang/stdlib/*.flang`):
криптография (`aes`, `ecdsa`, `hmac`, `kdf`, `rsa`, `sha1`, `sha256`,
`x25519`, `scram`), сертификаты и TLS (`x509`, `der`, `crl`, `tls`,
`tls-handshake`, `trust-store`), структуры данных (`hashmap`,
`dictionary`, `tree`, `numtree`, `sets`, `lists`, `strlists`,
`optional`, `result`), кодирование (`base64`, `utf8`, `json`, `wire`),
сеть (`http`, `postgres`, `redis`, `registry`), математика
(`math-classics`, `math-classics-lists`, `numbers`), текст (`strings`,
`automaton`, `higher-order`, `logic`), дата и время (`datetime`).

Это значит: «математика» и «работа с датами» из среднего уровня — НЕ
пустое место, там уже есть основа, задача — найти, чего именно не
хватает ВНУТРИ них (первым делом прочитать `datetime.flang` и
`math-classics*.flang` целиком, а не просто увидеть имя файла и решить,
что тема закрыта). UUID — судя по списку файлов, отсутствует вовсе.
CLI-парсер аргументов ДЛЯ ПРОГРАММ ПОЛЬЗОВАТЕЛЯ (не самого компилятора
— `flang/self/cli.flang` — это разбор ключей самого `flang`, другая
вещь) в списке не найден.

## Порядок работы

1. Прочитать `docs/stdlib.md`/`docs/site/stdlib.md` (если описывают то
   же дерево) и каждый файл `flang/stdlib/*.flang` — хотя бы список
   объявленных функций (`grep -n "^функция\|^тотальная функция"
   flang/stdlib/*.flang`), чтобы не предлагать то, что уже есть под
   другим именем.
2. Свести список НАСТОЯЩИХ пробелов на три уровня, по образцу владельца:
   - **Простой** — парсер CLI-аргументов (флаги, позиционные, `--help`
     генерируется из объявления), обёртки над строками сверх того, что
     уже даёт `strings.flang`/`strlists.flang` (что именно отсутствует —
     назвать поимённо, не просто «строки»).
   - **Средний** — UUID (генерация v4 минимум, разбор, сравнение), то,
     чего не хватает в `datetime.flang` (часовые пояса? интервалы?
     разбор произвольных форматов?), то, чего не хватает в
     `math-classics*.flang` (статистика? комплексные числа? матрицы?).
   - **Сложный** — протоколы и парсеры специфичных форматов ВНЕ уже
     закрытого (TLS/X.509/DER/CRL, HTTP, Postgres, Redis, JSON, base64
     уже есть — не предлагать их снова): кандидаты вроде YAML, TOML,
     Protobuf/gRPC-провода, WebSocket-рукопожатие, DNS-пакет, SMTP,
     что-то из уже названных в дереве нерешённых пунктов (проверить
     `docs/open-work.md`).
3. Каждый пункт списка — не одно слово, а: имя библиотеки, что она
   даёт (2-3 предложения), почему этого уровня сложности (что делает
   её простой/средней/сложной именно в flang — тотальность, доказанное
   завершение, отсутствие эффектов), и на что она уже может опереться в
   `flang/stdlib/` (не начинать с нуля, если есть на что встать).
4. Оформить как отдельные задачи `tasks/NNNN-*.md` по одной на пункт
   (или на подмножество тесно связанных пунктов) — по тому же шаблону,
   что эта, — чтобы внешний автор мог взять ОДНУ задачу, а не весь
   список целиком. Сколько именно задач заводить — решить по месту;
   плохой исход — десяток однострочных, хороший — по одной вдумчивой на
   уровень сложности минимум, крупные уровни дробить на несколько.

## Порог

- Список опирается на прочитанный код `flang/stdlib/`, а не на
  предположения по именам файлов — при разборе честно писать, что
  прочитано целиком, а что по одним объявлениям функций.
- Ни один пункт списка не дублирует то, что уже есть (проверено
  чтением, не грепом по одному слову).
- Итог — не только этот файл с пересказом задания, а РЕАЛЬНЫЕ новые
  файлы `tasks/*.md`, каждый пригодный к тому, чтобы кто-то посторонний
  взял и начал работать без дополнительных вопросов.
