# 9968 — язык должен позволять создавать, ставить и делиться пакетами

Владелец: «Язык должен позволять создавать пакеты (`flang package new`),
чтобы разработчики по всему миру могли начать создавать пакеты для
языка, ставить их и делиться ими.»

Это шире задачи 9961 (`flang new` — старт ОДНОГО пакета с нуля,
структура папок и файлов) и прямо названо в ней как отдельная,
более крупная задача — вот она.

## Что уже есть — не начинать с нуля, проверено координатором

- CLI-подкоманды **уже объявлены**: `flang lock <файл>` («замок: сами
  зависимости, а не ссылки на них») и `flang package <файл>` («пакет:
  замок с именем, версией и ведомостью») — реализация в
  `flang/self/cli.flang` (ветки разбора команды на строках ~420-422,
  номера могли сдвинуться). Прочитать, что они РЕАЛЬНО делают сегодня
  — по коду, не по одной строке из `--help`.
- **`scripts/registry-example/` — уже не пустое место, а рабочий
  черновик протокола реестра**: настоящие версии пакетов
  (`lists-1.4.2.flang-package`, `logic-1.0.0/1.2.0/2.0.0.flang-package`,
  `optional-0.9.0.flang-package`, `sets-1.0.0/1.1.0.flang-package`),
  плюс `package-list`, `registry.list`, `request.needs`,
  `request.search` — похоже на прототип запроса/поиска по реестру.
  Прочитать формат каждого файла целиком прежде, чем проектировать
  свой — весь замысел может уже быть здесь, недоделан только конец.
- `docs/road-to-1-0.md`, пункт 6 «Полноценная история пакетов и
  модулей» — официальная точка отсчёта: «Чего нет: почти всего —
  установки, разрешения версий, замыкания зависимостей. Как узнаем,
  что взято: чужой человек ставит пакет одной командой, и его сборка
  воспроизводима.» Это и есть мерка успеха всей задачи.

## Три части, владелец назвал их явно

1. **Создать** — `flang package new` (или как ляжет на уже существующие
   `flang package`/`flang lock`, не обязательно новое имя подкоманды:
   решить, прочитав код, а не гадая заранее) — обёртка над задачей 9961
   (`flang new`) плюс то, чего пакету не хватает для публикации: имя,
   версия, ведомость зависимостей в формате, который уже читает
   `flang package`/`flang lock`.
2. **Поставить** — по имени и версии (или диапазону версий) скачать/
   найти пакет (реестр — `registry-example/` как прототип формата,
   решить, где реальный реестр живёт: файл, HTTP, git — что дешевле
   для первой версии) и разрешить его зависимости — та часть, которой
   «почти нет» по road-to-1-0.md.
3. **Поделиться** — опубликовать свой пакет так, чтобы его смог
   поставить кто-то другой той же командой. Не обязательно настоящий
   публичный реестр в этом заходе — рабочий локальный/файловый
   прототип, который доказывает, что путь целиком проходим, весомее,
   чем недоделанный настоящий сервис.

## Порог

- Прочитан код `flang lock`/`flang package` в `flang/self/cli.flang` и
  весь `scripts/registry-example/` — что уже есть, названо конкретно,
  не переоткрыто заново.
- Сквозной прогон, доказывающий путь целиком, а не по частям на словах:
  пакет A создан → зависит от пакета B → B «опубликован» (хотя бы в
  локальный прототип реестра) → A ставится одной командой → сборка A
  воспроизводима (тот же результат при повторной установке).
- Если весь путь не укладывается в объём одной ячейки — честно взять
  ОДНУ часть целиком (создать/поставить/поделиться) и назвать
  остальные как следующий шаг, не размазывать по всем трём понемногу.
- Ничего из road-to-1-0.md пункта 6 не обещать взятым без прогона —
  сам пункт уже один раз предупреждает не путать «сделано» с «похоже
  на сделанное».

## Не входит

Полноценный публичный сервис реестра (аутентификация издателей,
приватные пакеты, зеркалирование) — задача про то, что путь ОТ
СОЗДАНИЯ ДО УСТАНОВКИ технически проходим и воспроизводим, не про
production-инфраструктуру.
