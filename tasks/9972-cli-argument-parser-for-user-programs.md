# 9972 — CLI-парсер доводов командной строки для программ пользователя

Вытекает из 9962 (простой уровень, названо владельцем прямо: «парсеры
CLI-аргументов»). Проверено, что это НЕ дубль: `flang/self/cli.flang`
разбирает ключи самого компилятора (`check`, `run`, `--target`,
`--max-steps`…) и в `flang/stdlib/` не ввозится — это закрытая система про
одну конкретную программу. Библиотеки, которая разбирала бы доводы ЛЮБОЙ
программы пользователя по объявленному списку флагов, в `flang/stdlib/`
нет: ни файла, ни функции с таким смыслом не нашлось (поиск «флаг»/
«командной строки» по всем 42 файлам даёт два случайных совпадения не по
теме — слово «флаг» как значение примера в `http.flang` и regex-флаг `i`
в `образцы.flang` — и ни одного про разбор доводов вызова).

## Что она даёт

- Объявление ожидаемых флагов: имя, берёт ли значение, обязателен ли,
  значение по умолчанию — и отдельно список позиционных доводов.
- Разбор `список строки` (уже разбитых по пробелу доводов — так же, как
  доводы приезжают в `flang/self/cli.flang`, а не строкой целиком) против
  этого объявления: сумма типов «Доводы разобраны» (признанные флаги +
  позиционные) / «Доводы не разобраны» (причина — неизвестный флаг,
  пропущено обязательное значение, флаг задан дважды — каждая со своим
  именем, не одной общей «ошибка»).
- Печать `--help` ИЗ ТОГО ЖЕ объявления, а не отдельным текстом. Это не
  украшение, а прямое требование владельца («--help генерируется из
  объявления»), и цена его отсутствия уже измерена в этом же дереве —
  ниже.

## Почему этот уровень сложности

Тотальность здесь дешёвая: разбор — это свёртка объявленного списка флагов
по разбираемому списку доводов, оба конечны и известны на входе, ровно тот
случай, который свёрткой берётся даром (см. навык по языку: свёртка —
тотальна по построению, вторая по частоте форма тела в библиотеке). Ни
меры, ни особого шага не нужно. Настоящая работа — не в завершаемости, а в
том, чтобы КАЖДЫЙ вид отказа был назван отдельно и проверен примером
(неизвестный флаг ≠ пропущенное значение ≠ повтор), и чтобы `--help` было
доказанно тем же объявлением, а не отдельно живущей строкой.

Последнее — не абстрактный риск. `docs/zettel/cli-help-diverges-between-
the-two-implementations.md` меряет ровно эту болезнь на СУЩЕСТВУЮЩЕЙ
командной строке flang: два независимых текста `--help` (свидетель на
JavaScript и эталон на flang) расходились четыре раза за одни сутки, и
каждый раз — молча, потому что справочный текст правили в одном месте и
забывали во втором. Библиотека, где `--help` не хранится отдельной
строкой, а вычисляется из объявления флагов, эту болезнь предотвращает по
устройству, а не бдительностью.

## На что опереться

- `flang/self/cli.flang` — НЕ ввозить, а прочитать как образец устройства:
  чистая половина решает, мир исполняет хозяин («Прочитать доводы» —
  инструкция из словаря эффектов, см. `flang/self/parser.flang`); функция
  здесь принимает уже готовый `список строки`, а не лезет за `process.argv`
  сама. Держаться того же разделения: библиотека — чистая функция от
  списка строк к разобранному результату, чтение настоящего argv — дело
  вызывающей программы.
- `flang/stdlib/result.flang` / `flang/stdlib/optional.flang` — образец
  суммы типов для «получилось / не получилось с причиной»; не изобретать
  третий похожий тип.
- `flang/stdlib/strlists.flang`, функция «Слова» — если библиотека также
  даст удобство «разобрать одну строку целиком», токенизация по пробелу с
  выбрасыванием пустых кусков уже написана и доказана, повторять незачем.
- Стиль справочных функций `flang/self/cli.flang` («Краткая справка»,
  «Подробная справка», «Справка по теме») — как ПРИМЕР организации текста
  помощи по темам, не как код для ввоза.

## Что не входит

- Чтение настоящего `process.argv` / «Прочитать доводы» — эффект, дело
  хозяина, не библиотеки (та же граница, что у `datetime.flang` с «сейчас»
  и у `http.flang` с сокетом).
- Подкоманды в духе `git commit -m` (глагол, потом свои флаги у глагола) —
  честно назвать как возможное продолжение, не обещать в этой задаче.
- Слияние с переменными окружения (флаг как запасной путь к `ENV_VAR`) —
  отдельная, более поздняя надстройка.

## Порог

- Не меньше одного примера на каждый именованный вид отказа (неизвестный
  флаг, пропущенное значение обязательного флага, флаг задан дважды),
  каждый — с ОТДЕЛЬНЫМ вариантом суммы, не общей строкой.
- Текст `--help` для двух РАЗНЫХ объявлений флагов проверен примером —
  показано, что при изменении объявления (добавлен флаг) текст меняется
  сам, без отдельной правки строки помощи.
- Целая программа (по образцу таблиц `docs/site/stdlib.md`: «целая
  программа, проверенная flang check»), разбирающая 3-4 реалистичных
  флага (например, `--выход <файл>`, `--подробно`, один обязательный
  позиционный довод) — от объявления до разобранного значения.
- `использует «CLI»` не тянет `flang/self/cli.flang` и ничего из
  компилятора — библиотека самостоятельна.
