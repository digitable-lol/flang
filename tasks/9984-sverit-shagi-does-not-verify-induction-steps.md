`sverit_shagi` — не та функция. Она разбирает только АВТОРСКИЕ блоки
`теорема ... шаг N ... по предположению`; проверено на самом же примере
этой задачи (`corpus-lists.flang::«Длина»`) — там блока `теорема` нет

**Настоящий пробел — `sverit_polya_posylok`** (сверщик.c, ~2887): для
посылки вида «вид step / закрыта reduction» (ровно эта безтеоремная
форма) чекер проверяет только `шагов == 0` — учёт, не довод.

**Поправка Ч414: «сходятся в одной функции» — неточно.** Маршруты 9616
(«по объявлению», функция «Вердикт по объявлению») и 9984 («по
предположению», функция «Случай сведённый ядром») делят только ТИП

той же идее (прокинуть поля «Сведения» вместо того, чтобы их ронять).
9616 уже сдвинута в этом направлении Ч414 (см. её отчёт) — начинать
9984 стоит с чтения ЕЁ работы как образца приёма, не как готового кода.
Также:
`zapis.flang`, «Ходы сведённой посылки записи» печатает ходы только для
`kind=="base"` — случай шага сегодня безусловно даёт пустой список.

Design остаётся в силе (путь б ниже), но метить его — не под
«sverit_shagi:1829», а под связку `proofterm.flang`:«Случай сведённый
ядром» + `sverit_polya_posylok`. Полный отчёт: Ч412,

# 9984 — «по предположению» проверяется текстом, не смыслом

Найдено расследованием Ч409 (4 сентября, продолжение цепочки Ч405→Ч406→Ч408
по задаче 9616), не реализовано — намеренно, см. «Порог».

## Находка

`sverit_shagi` (`flang/proof/чекер/сверщик.c:1829`) для шагов «по
предположению» (обращение к индукционной гипотезе внутри разбора по
случаям) проверяет ТОЛЬКО, что текст шага в записи совпадает с текстом
шага в исходнике (`strcmp`/`soderzhit`). Он НИКОГДА не проверяет, что сам
шаг математически состоятелен — запись может звать «по предположению» для
любого утверждения, на любом подтерме, и пройдёт, пока слова совпадают.

Это ТОТ ЖЕ КЛАСС уязвимости, что снял Г2 31 августа и что чинила Ч392
вечером 3 сентября — только в другом маршруте чекера.

**Масштаб:** 29 вхождений `по предположению` в 15+ файлах корпуса
(списки, деревья, стеки, факториал, доказательства предусловий) — это
ОСНОВНОЙ механизм закрытия структурной индукции в корпусе, не редкий
случай. Задача 9616 сама называла этот маршрут только мимоходом (33 «шага
допущением» одной ячейкой) — реальный охват органа шире, чем виделось.

## Как ядро на самом деле это доказывает

`flang/self/proofterm.flang:2899` («Индукция по разбору») и сосед
«Сведение посылки допущением» (~2960): ядро строит РОВНО ОДНУ гипотезу на
рекурсивно убывающее поле совпавшего конструктора (например, `хвост` в
`случай голова и хвост`), подставляет её в цель. Шаг, зовущий не тот
подтерм, «не совпадёт с гипотезой — сравнение синтаксическое, и вердикта
не будет» (комментарий самого ядра). Реальные шаги (`corpus-lists.flang`
«длина неотрицательна») пишут голое `то по предположению` БЕЗ видимой
формулы — ядро само выводит связь гипотезы с целью перезаписью выражений
(теми же правилами, что «неотрицательность по построению» в
`proof-kernel.flang`), а НЕ из того, что говорит запись.

## Почему не реализовано этим же вечером

Честный, независимый чекер шага потребовал бы РЕАЛЬНОГО повтора вывода на
уровне выражений (подставить механически построенную гипотезу в тело
случая, подтвердить, что она влечёт цель) — не простого повтора терма, как
у `proigrat_uzel` для других видов шагов. Два честных пути:

(а) переписать значимый срез собственных правил перезаписи ядра в чекере
на C — дорого и само по себе рискованно (чекер снова растёт, снова может
ошибиться в том же классе);

(б) вероятно более дешёвый путь — тот же архитектурный пробел, что уже
назван задачей 9616 для маршрута «по объявлению»: ядро вычисляет
подстановку/влечение по-настоящему и ВЫБРАСЫВАЕТ результат при печати
записи. Прокинуть эту же цепочку (proofterm.flang → zapis.flang →
сверщик.c) для маршрута «по предположению» позволила бы чекеру сверять
НАПЕЧАТАННУЮ цепочку синтаксически, не выводя её заново, — вероятно,
намного меньше строк C, чем (а).

## Порог

## ⚑ ПРИМЕР НАЙДЕН 4 сентября: 7 настоящих `kind:"step"`+`by:"reduction"` в flang/stdlib/tree.flang

Полный обход, не догадка. `check --proof --json` прогнан на всех 16
файлах `flang/proof/examples/*.flang`, чей исходник содержит «по
предположению» (список см. `grep -l 'по предположению'
flang/proof/examples/`, ровно те 15+, что называет находка задачи), плюс
два файла, которые Ч415 не досчитала за 200 млн шагов —
`flang/stdlib/tree.flang` (657 строк) и `flang/stdlib/hashmap.flang`
(1016 строк). Для последних двух хватило бюджета `--предел-шагов
3000000000` (3 млрд) — оба досчитались за секунды, 200 млн оказалось
малым бюджетом, не признаком дороговизны файла.

**Свод `(kind, by)` по всем 18 файлам:**

| kind | by | штук |
|---|---|---:|
| step | term | 19 |
| постусловие | declaration | 71 |
| base | term | 16 |
| base | reduction | 15 |
| **step** | **reduction** | **7** |

Все 7 — в `flang/stdlib/tree.flang`, ноль в `hashmap.flang` и ноль в
остальных 16 файлах `flang/proof/examples`. Ч415 не нашла ни одного,
потому что искала среди `flang/proof/examples` (где их и правда нет) и
не досчитала единственные два файла, где они есть.

**Семь настоящих мест**, все `variant:"Узел"` (структурный случай-шаг
дерева), все `"verdict":"доказано"`, все `"steps":0` — то есть именно
та форма, которую, по находке Ч412, `sverit_polya_posylok` сегодня
принимает по одному учёту «шагов == 0», а не доводом:

| obligations[N] | теорема/обязательство |
|---:|---|
| 21 | узел без левого ребёнка не меняет приоритета корня |
| 28 | узел без правого ребёнка не меняет приоритета корня |
| 43 | размер неотрицателен |

| 48 | есть ключи — глубина не меньше одного |
| 49 | глубина неотрицательна |
| 52 | у узла глубина — глубже обоих поддеревьев |

**Как повторить, дёшево (секунды, не часы):**

```
make -C bootstrap
./bootstrap/flang check flang/stdlib/tree.flang --proof --json \

python3 -c '
import json
d = json.load(open("tree.json", encoding="utf-8"))
for i, ob in enumerate(d["obligations"]):
    s = json.dumps(ob)
    if "\"kind\": \"step\"" in s and "\"by\": \"reduction\"" in s:

```

**Чего это НЕ делает.** Не проба порчи (её всё ещё нет — «Порог» задачи

## ⚑ ПРОБА ПОРЧИ 4 сентября: дыра подтверждена, и найдена её граница

Дисциплина «проба порчи ДО того, как считать дырой» (та же, что применена
дважды на Г2 сегодня). Метод дешевле, чем прогонять `flang/stdlib/tree.flang`
через ядро заново: `sverit_polya_posylok` (`сверщик.c:2889-2909`) для
`закрыта reduction` смотрит РОВНО ОДНО поле — `шагов == 0` — и делает это
одинаково для ЛЮБОЙ посылки с этой формой, независимо от файла. Взят уже
существующий в дереве честный образец с той же формой
(`flang/proof/чекер/пробы/записи/корпус/substantive.запись`, утверждение
«С5», посылка «голова и хвост» `закрыта reduction шагов 0`) — не сам
`tree.flang`, но тот же код чекера, та же проверка, тот же класс.

### Проба 1 — принята: реальное имя, ложный вердикт, поддельная посылка

Утверждение «С1» честно стоит в записи как `вердикт нет вердикта`
(ядро НЕ доказало квантор «все элементы результата неотрицательны» —
у ядра просто нет вида цели для кванторов, см. комментарий в исходнике
`flang/proof/map/substantive.flang:9`). Подделка меняет ТОЛЬКО блок
верdikта на честную копию структуры С5 (вердикт `доказано` + `принцип`/
`сведение` + посылка `закрыта reduction шагов 0`), имя и строку не трогает:

```
$ ./сверщик flang/proof/map/substantive.flang проба-порчи/1-c1-lozhnyy-reduction.запись
НЕ ПРОВЕРЕНО ...: Числятся доказанными 4    (было 3 на честной записи)
код=3
```

**Ни слова жалобы про С1.** Подделка молча зачлась в «доказанными 4» —
чекер принял «доказано» утверждение, которое САМО ЯДРО пометило «нет
вердикта», без единого несовпадения. Целый прогон кода не меняется (3,
как на честной записи) ТОЛЬКО потому, что в записи и без того остаются
другие непроверенные утверждения — сам факт принятия С1 ничем не
подсвечен.

**Честная оговорка о степени лжи.** «Все элементы результата
неотрицательны» для «Единицы» (отображает список в список единиц) —
утверждение, скорее всего, ИСТИННОЕ по факту, просто вне вида целей,
которые умеет ядро. Проба доказывает МЕХАНИЗМ (чекер не отличает
«ядро доказало» от «ядро не бралось, а кто-то сказал, что доказало»),
а не подсовывает содержательно ложный факт — таких же честных
постусловий, ложных по факту, в открытом корпусе взять неоткуда (ядро
никогда не печатает заведомо ложное как «доказано»).

### Проба 2 — отклонена: граница дыры

Та же подделка, но с переименованием утверждения в заведомо ложное
(«длина результата равна минус единице»):

```
$ ./сверщик flang/proof/map/substantive.flang проба-порчи/2-imya-ne-sovpadaet.запись
НЕ СОШЛОСЬ: строка 41 исходника не несёт «обеспечивает «С2-ЛОЖЬ: ...»» —
записанное утверждение в исходнике не стоит
код=1
```

Имя утверждения СВЕРЯЕТСЯ с текстом `обеспечивает «...»` по указанной
строке источника — придумать целиком новую ложь нельзя, чекер это ловит.

### Вывод — дыра есть, и она именно там, где предсказывала находка Ч412

**Граница дыры именно такая:** подделыватель не может изобрести
утверждение из ничего (проба 2 это ловит), но МОЖЕТ взять любое честное,
реально написанное в исходнике постусловие, которое ядро НЕ доказало
(«нет вердикта» — таких 119 из 359 по замеру Ч318), и объявить его
доказанным через сфабрикованную посылку `закрыта reduction шагов 0`.
Чекер это примет молча, потому что для этой формы посылки у него ВООБЩЕ
НЕТ проверки, кроме счёта шагов, — не потому что проверка слабая, а
потому что для `reduction` авторских «шаг N» строк не бывает по
конструкции (`шагов 0` и означает «ходов не записано»), и `sverit_shagi`
здесь нечего разбирать.

**Не сделано.** Починка (пути (а)/(б) выше в этой же задаче) — не
начата, по прежнему решению координатора. Проба НЕ пыталась найти
честное постусловие, ложное по факту (см. оговорку выше) — если такое
найдётся в корпусе, проба на нём была бы строго убедительнее.

**Файлы пробы** (не в git, клон `/srv/tmp/dokazuemyy/Ч9984b-proba-porchi/
проба-порчи/`): `1-c1-lozhnyy-reduction.запись` (принята), `2-imya-ne-
sovpadaet.запись` (отклонена) — оба воспроизводятся секундами, чекер
собирается отдельно (`make -C flang/proof/чекер`, не требует
`bootstrap/flang`).
