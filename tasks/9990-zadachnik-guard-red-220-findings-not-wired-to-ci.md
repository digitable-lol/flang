# 9990 — сторож задачника молчал, потому что его никто не звал

## Как найдено

Тихий цикл обхода (гейты Г1-Г7 без движения несколько часов подряд):
вместо простого ожидания решила прогнать существующие быстрые сторожи
по накопленным за вечер правкам. `./ярлык задачник:проверка`
(`flang/scripts/tasks.flang --plan 'Задачник цел'`) дал:

```
задачник разъехался, замечаний 220
```

**Этого ярлыка нет НИ В ОДНОМ workflow** (`grep -rn 'задачник:проверка'
.github/workflows/*.yml` — пусто). Только ручной прогон. Отсюда и накопление —
не потому что кто-то сломал, а потому что смотреть было некому.

## Разбор 220 замечаний — две РАЗНЫЕ беды, не одна

```
163  ссылка в никуда           — задача ссылается на номер, которого нет в tasks/
 31  статус «открыта» не из четырёх
  5  команда «—» не из трёх
  3  статус «заведена» не из четырёх
 15  статус <развёрнутая строка> не из четырёх (разные, поимённо ниже)
  3  другое (поле не названо и т.п., по одному)
```

### Беда 1 (163 из 220) — вероятно, эхо архивации `tasks/completed/`

Задачи вроде `0003-seed-reprint-finishes.md` ссылаются полем «рядом» на
`0001`/`0002` — тех нет в `tasks/`, потому что 79 задач были перенесены в
`tasks/completed/` (задача 9960, ячейка Ч419, слито координатором как
`84e97cbf`, было раньше этого вечера). Сторож `tasks.flang`, похоже, ищет
номер только в `tasks/`, не в `tasks/completed/`. **Не проверено окончательно
чтением кода сторожа** — гипотеза, не установленный факт.

### Беда 2 — статус НЕ ОДНОГО СЛОВА ИЗ ЧЕТЫРЁХ, и это касается СЕГОДНЯШНИХ задач тоже

Канон сторожа (`flang/scripts/tasks.flang:463`): статус обязан быть РОВНО
одним из четырёх слов — **`свободна`, `в работе`, `сделана`, `отменена`**.
Ни «не начата», ни «открыта», ни «заведена» сюда не входят.

**Это не только старые задачи.** Пять статусов из сегодняшних, написанных
этим же вечером мной и ячейками, тоже красные, ПОТОМУ ЧТО несут честную
пояснительную приписку в скобках, а не голое слово:

- 9983: `сделана — путь 2 (сторож), путь 1 отклонён обоснованно`
- 9984: `не начата (реализации нет; пример найден И проба порчи ПОДТВЕРДИЛА дыру...)`
- 9985: `сделана (частично) — span-утечка починена (d621bda9)...`
- 9986: `сделана (частично) — полный обход и корень обоих регрессов найдены...`
- 9987: `сделана (полный передний край измерен честно...)`

## Почему это НЕ починено прямо сейчас координатором

Две причины, обе весомые:

1. **Масштаб.** 220 замечаний, разброс от задачи `0003` до `9989` — это не
   точечная правка, а вопрос конвенции для ВСЕГО каталога `tasks/`. Решение
   такого масштаба ночью, в тихом цикле, без владельца — не по чину.
2. **Направление решения не очевидно и не мне выбирать.** Два честных пути,
   и они противоречат друг другу:
   - **(а) Ужесточить практику** — статус всегда одно из четырёх слов,
     пояснение уезжает в тело задачи (например, отдельный раздел «Чем
     закрыта», как уже делают многие задачи). Сторож остаётся как есть.
   - **(б) Ослабить сторожа** — разрешить статусу нести короткую пометку
     через тире/скобки ПОСЛЕ одного из четырёх канонических слов, проверяя
     только префикс. Практика вечера (богатые, честные статусы) остаётся.

   Путь (б) ближе к духу этого же вечера — КРИТЕРИЙ.md весь построен на
   «названо число с происхождением, а не голое слово». Но это ЧЕЙ-ТО выбор
   конвенции для всего дерева, не разовая правка кода.

## Как понять, что сделано

1. Подтвердить или опровергнуть гипотезу беды 1 (чтение `tasks.flang`:
   ищет ли он `tasks/completed/`, и должен ли).
2. Владелец выбирает путь (а) или (б) для беды 2.
3. По выбранному пути — либо переписать статусы задач на голое слово +
   раздел в теле, либо расширить сторож на «слово + необязательный
   постфикс», с пробой порчи (статус вообще не по протоколу — обязан
   остаться красным).
4. `./ярлык задачник:проверка` — код 0 или явно названный, кому доверенный,
   остаток.
