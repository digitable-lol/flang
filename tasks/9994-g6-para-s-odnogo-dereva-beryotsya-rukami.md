# 9994 — «одно дерево» это не то, что кажется, и оно достижимо руками

## Что спрашивалось

Г6 стоит с формулировкой «ждёт самостоятельного раннера — решение
владельца». Но раннер закрывает только ОДНО из двух оставшихся условий
(«прибор зовётся сам, а не руками»). Второе — «пара должна быть с ОДНОГО
дерева, а не из двух клонов» — раннера не требует вовсе. Разбор: что
именно значит «одно дерево», сколько стоит, и берётся ли руками.

## Находка 1: прибор «одно дерево» от «двух клонов НЕ ОТЛИЧАЕТ»

`scripts/two-prints-identical.sh` (226 строк) прочитан целиком. Он берёт
**два каталога** и сверяет их `bootstrap/**` побайтово. Проверок родства
деревьев в нём НЕТ НИ ОДНОЙ: ни сверки коммитов, ни inode, ни origin.
Требование «одного дерева» живёт только в его последней строке —

```
Г6 на ЭТОЙ паре взят. На гейт целиком этого мало: нужна пара из ОДНОГО
дерева и прибор, зовущийся сам, а не руками.
```

— то есть это **условие методики, а не проверка прибора**. Соблюсти его
обязан тот, кто ставит пару; прибор соврать не помешает.

## Находка 2: «одно дерево» у CI — это одна выкладка, СКОПИРОВАННАЯ дважды

Работа `dve-pechati` (`.github/workflows/reprint.yml`, строки ~350-500)
названа «одно дерево печатает себя дважды». По коду это НЕ последовательная
двойная печать в одном каталоге, а:

1. одна `actions/checkout`;
2. **одна** сборка двоичного: `make -C bootstrap -j"$(nproc)"`;
3. `cp -a "$GITHUB_WORKSPACE/." "$BAZA/pervaya/derevo/"` и то же во
   `vtoraya` — две копии ОДНОЙ выкладки, **вместе с `.git` и уже собранным
   `bootstrap/flang`** (комментарий там же: печать спрашивает git, из какого
   коммита печатает, и отказывается печатать из правленого дерева);
4. тождество копий ПРОВЕРЯЕТСЯ, а не берётся на веру: `git rev-parse HEAD`
   у обеих, при расхождении — выход 2;
5. две печати `timeout 39600 sh scripts/raskrutka.sh` (11 ч на каждую);
6. сверка с ЯВНО названными журналами `ZHURNAL_1=`/`ZHURNAL_2=`.

**Отсюда содержательная разница с парой, уже снятой 4 сентября.** Та пара
(`pechat-dev-2`/`pechat-dev-3`, коммит `22d54485`, сошлась побайтово:
файлов 4, байт 1 216 932) — это **два независимых клона, каждый со своей
сборкой компилятора**. У CI печатающий двоичный один и тот же побайтово,
у нас их было два. То есть 4 сентября доказано более сильное в одном
измерении (два независимо собранных двоичных печатают одинаково) и НЕ
доказано то, что просит гейт (одна выкладка, один двоичный, две печати).

## Цена — числами с этой машины, а не из комментариев CI

|---|---|---:|---:|---|

| `pechat-dev-2` | `22d54485` | 15 752 | **4 ч 23 мин** | 03.09 23:44 → 04.09 04:06 |
| `pechat-dev-3` | `22d54485` | 15 698 | **4 ч 22 мин** | 04.09 01:01 → 05:22 |

**Разброс 2,8× не объяснён, и выдавать за цену одно число нельзя.**
Оболочки запуска у всех трёх идентичны (сверено построчно: тот же
`raskrutka.sh`, тот же `FLANG_TMP`, различаются только путь и метка) —
значит дело в дереве/коммите, не в запуске. `raskrutka.sh` кеша приговоров
не зовёт (`grep` по нему: ноль упоминаний), так что кешем разрыв тоже не

Комментарий CI называет свой замер: 8 ч 34 мин – 9 ч 56 мин (31 августа
2026, `tasks/1310`), и закладывает 11 ч на печать, 22 ч на пару.

**Честная оценка пары на сегодняшнем dev: от 8 ч 45 мин (две по 4 ч 22)
до 24 ч 42 мин (две по 12 ч 21) последовательно.** Параллельно —
наблюдённые 5 ч 39 мин на пару (dev-2 и dev-3 перекрывались: 23:44 → 05:22),
но это на коммите с быстрой печатью.

**Место и память — не препятствие.** Дерево 106 МБ без `.git`, 408 МБ с
`.git`; две копии ≈ 816 МБ. Свободно на разделе 171 ГБ. Память: всего
499 ГБ, доступно 440 ГБ; печати нужно 64 ГБ (замер в КРИТЕРИЙ.md), двум
параллельным — 128 ГБ. Запас многократный.

## Ответ прямо: ДА, условие (а) берётся руками

Раннер для него не нужен, CI не нужен. Всё, что делает работа
`dve-pechati`, воспроизводится семью командами. Оболочка запуска, пишущая
дословный контракт `ПЕЧАТЬ КОД=`, уже заведена этой ночью —
`scripts/print-launch.sh` (задача 9988); раскладка под неё («рабочий
каталог» с подкаталогом `клон` внутри) как раз даёт каждой печати
собственного родителя с единственным журналом, чего прибор и требует.

```sh
# 0. Выбрать коммит пары и завести чистое дерево ОДИН раз.
БАЗА=/srv/tmp/dokazuemyy/g6-para
rm -rf "$БАЗА" && mkdir -p "$БАЗА"
git clone /srv/tmp/dokazuemyy/peredacha "$БАЗА/исходное"
cd "$БАЗА/исходное" && git fetch gh dev && git checkout -q FETCH_HEAD

# 1. Собрать двоичный ОДИН раз — обе печати обязаны печатать одним и тем же.
make -C bootstrap -j"$(nproc)"

# 2. Развести две копии ВМЕСТЕ с .git и собранным bootstrap/flang.
mkdir -p "$БАЗА/первая" "$БАЗА/вторая"
cp -a "$БАЗА/исходное" "$БАЗА/первая/клон"
cp -a "$БАЗА/исходное" "$БАЗА/вторая/клон"

# 3. Проверить тождество копий, а не поверить в него.
k1=$(git -C "$БАЗА/первая/клон" rev-parse HEAD)
k2=$(git -C "$БАЗА/вторая/клон" rev-parse HEAD)
[ "$k1" = "$k2" ] || { echo "копии с разных коммитов: $k1 и $k2" >&2; exit 2; }
echo "коммит пары: $k1"

# 4. Две печати. Последовательно — надёжнее; параллельно (обе строки в фоне)
#    вдвое быстрее по стенным часам, памяти хватает с запасом.
sh "$БАЗА/исходное/scripts/print-launch.sh" "$БАЗА/первая"  первая
sh "$БАЗА/исходное/scripts/print-launch.sh" "$БАЗА/вторая"  вторая

# 5. Сверить, назвав журналы прямо (прибор просит именно этого).
ZHURNAL_1="$БАЗА/первая/печать.log" ZHURNAL_2="$БАЗА/вторая/печать.log" \
  sh "$БАЗА/исходное/scripts/two-prints-identical.sh" \
     "$БАЗА/первая/клон" "$БАЗА/вторая/клон"
```

Исходы прибора: `0` — пара сошлась, условие (а) взято; `1` — печать
невоспроизводима (это находка, а не поломка); `3` — не проверено.

## Чего это НЕ даёт

Взятие условия (а) **гейт Г6 не закрывает**: остаётся условие (б) — прибор
обязан зваться сам, а не руками, и оно упирается в самостоятельный раннер,
которого владелец заводить не разрешил. Эта задача его не трогает.

Печать намеренно НЕ ЗАПУСКАЛАСЬ: это решение на 9–25 часов машины, его
принимает координатор, а не работник замера.
