# 9998 — правило под ключ, и цена его названа честно: ноль процентов Г4

Задача 9991 разложила 43 непокрытых места Г4 по ФОРМЕ постусловия и
предложила начать с формы «результат начинается с <строка>» — 5+ мест,
все в одном файле, «наименьшая неоднородность». Здесь эта форма
доведена до готового правила и **измерена**. Правило работает; порядок
работ, который она открывала, — нет.

## Пять мест названы поимённо

Прибор: копия `сверщик.c` с диагностическим `fprintf` в `razborom_celi`
(своя, в `/srv/tmp/dokazuemyy/F2-forma-nachinaetsya/диагноз/`; общий файл
не тронут). Дерево `gh/dev` `488d44e1`, чекер собран из него же.

Файл один — `flang/test/fixtures/nachalo-po-postroeniyu-chestnaya.flang`,
7 функций. Цель после подстановки тела вместо «результат»:

| функция | цель после подстановки | сегодня |
|---|---|---|
| Склейка начинается левым | `( соединить начало с конец ) начинается с начало` | не закрылось |
| Всякая строка начинается пустым | `текст начинается с ""` | не закрылось |

| Приставка приставки взята | `( «Обещает длинную приставку» от хвост ) начинается с "аб"` | не закрылось |

Счётчик записи сходится: «разбор цели по условию» проиграно заново 1,
вне приёма 1, **разобрано, но не закрылось 5**.

**Шестая строка объясняет, каким должно быть правило.** Литерал уже
закрывается — `znach_moya` считает ЗАМКНУТЫЙ терм по закрытому списку
десяти отношений, и `начинается с` среди них есть (`сверщик.c:1459`).
Значит новое правило обязано закрывать ровно то, чего вычислитель не
может: где стороны несут ПЕРЕМЕННЫЕ.

## Правило: две двери, и обе структурные

Место — седьмой способ в `polovina_zakryta`, рядом с
`mera_neotricatelna` (та же форма: найти отношение `nayti_sverhu`,
разрезать, решить). Устроено роднёй существующего, а не изобретением:
разрез склейки `razrez_slovom(t, " с ", &l, &p)` + `nachinaetsya(l,
"соединить ")` — тот же приём, каким `svesti_term` разбирает «Меру
склейки» (сверщик.c:2192); сличение сторон — тот же `tozhdestvenny`,
каким закрывается `равен`.

```c
/* «Т начинается с П» ПО ПОСТРОЕНИЮ. Дверей ДВЕ, список закрыт:
     1. П пусто — сравнивается ноль знаков, и это истина при любом Т,
        включая пустое;
     2. Т есть склейка `соединить L с R`, и L тождественно П — знаки
        итога суть знаки L, за ними знаки R, значит итог начинается с L
        при любом R.
   Ни одна дверь не смотрит на R и ни одна не считает знаки: считать
   умеет `znach_moya` на ЗАМКНУТОМ терме, и «"привет" начинается с
   "при"» закрывает уже она. Здесь закрывается ровно то, чего она не
   может, — где стороны несут переменные. Третьей двери («П — приставка
   L, обе литералы») тут нет нарочно: на честном корпусе она не нужна
   ни разу, а всякая новая дверь в этот список есть шаг ко второму
   вычислителю языка внутри сверщика. */
static int nachalo_po_postroeniyu(const char *t, Sp stroki) {
  static const char *NS[1] = { " начинается с " };
  char *l, *p, *sl, *levyy, *pravyy; long gde; int kakoe;
  if (!nayti_sverhu(t, NS, 1, &gde, &kakoe)) return 0;
  l = bez_vneshnih(kopiya(t, (size_t)gde));
  p = bez_vneshnih(t + gde + strlen(" начинается с "));
  if (strcmp(p, "\"\"") == 0) return 1;
  sl = bez_vneshnih(l);
  if (!razrez_slovom(sl, " с ", &levyy, &pravyy)) return 0;
  if (!nachinaetsya(levyy, "соединить ")) return 0;
  return tozhdestvenny(slova_posle(levyy, 1), p, stroki, 6);
}
```

Объявление ставится перед `static int polovina_zakryta(...);`, вызов —
строкой ниже `if (mera_neotricatelna(t, stroki)) return 1;`. Рост: **19
строк кода плюс 13 строк примечания**. Собрано строгими флагами
проекта (`-std=c99 -Wall -Wextra -Werror -pedantic`) — чисто, без
единого предупреждения.

Закрылись три: «Склейка начинается левым» и «Обещает длинную приставку»
(дверь 2), «Всякая строка начинается пустым» (дверь 1). Не закрылись
два, и оба честно вне этой формы: «Точный текст» требует ВЫЧИСЛИТЬ
правую часть склейки (`к строке (длина [первый, второй])`), «Приставка
приставки» — цепочку через обещание вызванной функции плюс
транзитивность приставок.

**Три из пяти, а не пять. Оценка 9991 «5+ мест» была верхней границей
формы, не числом закрываемого.**

## Главное: доля Г4 не двигается ВОВСЕ

Прогон `flang/proof/доля-корпуса.sh --набор корпус` обоими двоичными,
всё дерево, 86 записей:

| | старый | с правилом |
|---|---:|---:|
| **по УТВЕРЖДЕНИЯМ (это и есть Г4)** | **18 из 240 = 7,50 %** | **18 из 240 = 7,50 %** |
| на слово ядра — посылок и утверждений | 144 | **141** |

Ни одной десятой процента. Причина видна в записи: Г4 считает
утверждения из записей, дошедших до кода 0, а запись остаётся кодом 3,
пока на слове ядра остаётся хоть одно место. Здесь их было 6, стало 3 —
меньше, но не ноль.

**Отсюда настоящий порядок работ, обратный предложенному в 9991.**
Этот файл — не «5 мест по 0,4 % каждое», а **всё или ничего: 7
утверждений одним броском**. Закрыть надо ВСЕ семь; тогда запись
переходит 3 → 0 и Г4 растёт сразу на 7 из 240, то есть **7,50 % →
10,42 %, плюс 2,92 пункта**. Осталось после этого правила три места:
две формы выше плюс «Выбор начинается общим», которое даже не доходит
до приёма (тело в три строки, `telo_bez_pust` такое не берёт —
`сверщик.c:2680`, «строка не-`пусть` до последней делает тело
многострочным»).

Тот же счёт, надо полагать, верен и для прочих форм из 9991: правило,
закрывающее часть мест записи, доли не даёт совсем. Проверять это на
каждой форме отдельно не нужно — достаточно смотреть, обнуляет ли
работа «на слово ядра» ЦЕЛОЙ записи.

## Пробы: они сторожат не то, что заказывали, и вот почему

Заказ просил пробу, которая «обязана краснеть после внесения правила».
**Такой пробы тут быть не может по устройству приёма.** `polovina_zakryta`
объявлена так: «Ни один способ не объявляет половину ЛОЖНОЙ: незакрытая
половина значит „не берусь"» (`сверщик.c:2637`). Правило умеет только
закрывать больше — покраснеть от него не может ничто.

Поэтому проба сторожит противоположное и не менее нужное: **что правило
не закрывает ЛОЖНОЕ**. Положены две, обе в
`flang/proof/чекер/пробы/записи/9991-nachinaetsya-s/`:

| подлог | почему ложно | старый | с правилом |
|---|---|---|---|
| `соединить начало с конец` объявлено начинающимся с `конец` | склейка начинается ЛЕВЫМ куском; при «аб»+«в» итог «абв» с «в» не начинается | не закрылось | **не закрылось** |
| произвольный `текст` объявлен начинающимся с `"х"` | про переменную строку не известно ничего | не закрылось | **не закрылось** |

Числа старого и нового совпадают знак в знак: «разобрано, но не
закрылось 2», на слово ядра 2, код 3. Дверь 2 не путает левый кусок с
правым, дверь 1 не распространяется с пустой приставки на непустую.

**Ложность подлогов подтверждена ядром, а не только рассуждением:**
`flang check` на этом файле даёт `FLANG_PROPERTY: нарушено свойство` на
обоих утверждениях, код 1. То есть запись объявляет «вердикт доказано»
там, где ядро предъявляет контрпример.

Оговорка к находке 9992 (набор проб слеп к «тихому зачёту», сверяет
только код возврата): здесь она не мешает — обе пробы и до, и после
дают код 3, и сторожат они именно ЧИСЛО («не закрылось 2»), которое у
обоих двоичных одинаково. Если правило когда-нибудь станет
закрывать лишнее, число упадёт, а код останется 3 — то есть проба
должна попасть в ведомость `dolg`, сверяющую числа, а не в обычный
набор. Это делает вносящий.
