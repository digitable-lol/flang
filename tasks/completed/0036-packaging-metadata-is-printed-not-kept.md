# 0036. package.json печатается пакетировщиком на flang, а не лежит написанным руками

Замер 24 августа 2026, всё прогоном:

```
package-lock.json           20 строк, зависимостей "resolved" — НОЛЬ
пакет @digitable-lol/flang  https://registry.npmjs.org → {"error":"Not found"}
релизов на GitHub           5, последний v0.6.2 от 22 августа
тегов в дереве              21
работа publish-npm.yml      есть, гоняется на тегах
```

**Пять тегов, пять релизов на GitHub, ноль пакетов в npm.** Половина выпускного
пути не сработала ни разу, а оснастку под неё дерево носит: `package.json`,
пустой `package-lock.json`, `packaging/postinstall.mjs`,
`packaging/flang-launch.mjs`, `flang/bin/flang-lsp.mjs`, `engines: node >= 20`.

Отдельно: **зависимостей у проекта нет вовсе**. `package-lock.json` — двадцать
строк церемонии вокруг пустоты.

## Чего делать НЕЛЬЗЯ сходу

`package.json` сегодня **несущий**, и это записано в коде:

```
docs/site/site-numbers.mjs:180
/** Версия выпуска — из `package.json`, а не из памяти. */
```

Подстановка `{{выпуск.версия}}` на всех 587 страницах сайта читает версию
оттуда. Убрать файл, не перенеся источник версии, значит сломать сборку сайта.

Версия сейчас записана ещё в четырнадцати местах (`changelog.json`,
`CHANGELOG.md`, `docs/site/numbers.json`, `flang/scripts/npm-install.flang`,
три файла библиотеки, шесть в документации). Проверено — **все сходятся на
0.6.2**, расхождения нет. Но сходятся они трудом, а не устройством.

## Что делать

Пакетировщик на самом flang, как всё остальное в этом дереве:

1. **Один источник** — объявление пакета на flang: имя, версия, описание,
   список путей, точки входа. Оттуда же берёт версию сборка сайта.
2. **Цель ярлыка**, печатающая `package.json` из этого объявления. Печать в JSON
   у языка есть (`«Печать JSON»` в словаре поручений), запись файла есть
   (`«Записать файл»`, проверено прогоном).
3. **`package-lock.json` убрать.** Зависимостей ноль; `npm install` напишет его
   заново за секунду, если понадобится.
4. Список `files` (22 пути) **считать из дерева**, а не держать написанным. Он
   сейчас точен — все 22 существуют, — но он ручной, и первая же перестановка
   каталогов его разойдёт молча.

## Решение, которое надо принять до работы

**Нужен ли нам npm вообще.** Каналов доставки уже два — GitHub-релиз с архивом C
и формула Homebrew (`packaging/homebrew/flang.rb`), плюс asdf. Третий канал не
работал ни разу.

Если ответ «не нужен» — задача становится вдвое проще и заодно уносит из дерева
три `.mjs`. Если «нужен» — сперва починить публикацию, потом печатать метаданные.

Отрицательный ответ («npm выкидываем») тоже закрывает задачу.

## Как понять, что сделано

```sh
./ярлык пакет
```

печатает `package.json`, и он совпадает с прежним по смыслу (имя, версия, bin,
files), а версия в нём и версия на собранном сайте берутся из ОДНОГО места.
Проверяется тем, что правка версии в одном файле меняет оба.

## Чем закрыта — 26 августа 2026, ветка `u/printed-not-kept`

**Решение, которого задача требовала до работы: npm остаётся, а метаданные под
него печатаются, и порядок именно такой, а не обратный.** Убрать npm — решение
владельца с разлётом по `publish-npm.yml`, по сторожу формулы Homebrew (он берёт
версию из `package.json`), по сборке сайта и по README. Печать же нужна при
ЛЮБОМ ответе: если npm остаётся — она снимает ручной список; если однажды
уходит — удалять придётся один напечатанный файл, а не искать, откуда сайт берёт
версию.

**Пакетировщик — `scripts/emit-package.flang`**, на самом flang, два плана:
`./ярлык пакет` печатает, `./ярлык пакет:проверка` сверяет знак в знак. Оба
вписаны в `ярлыки.flang`, ярлыков 90 → 92 (эта же ветка подняла 89 → 90 задачей
0062). `check --proof`: функций 39, тотальных 39, **утверждений 10: доказано 10,
объявлено, не доказано 0**.

### Напечатанное совпало с прежним ЗНАК В ЗНАК — и это показано до всякого сноса

Первым делом прогнана СВЕРКА, не печать: она читает лежащий файл и сравнивает с
напечатанным, не записывая ничего. Ответ:

```
код 1  FLANG_ZAMOK_USTAREL: package-lock.json разошёлся с объявлением пакета
```

До замка сверка доходит только тогда, когда `package.json` совпал, — то есть
**`package.json` напечатался знак в знак, ни одного знака разницы**. И тем же
ответом названа единственная настоящая беда: врал `package-lock.json`.

Первая печать это подтвердила `git diff`-ом:

```
package.json       без изменений вовсе
package-lock.json  1 insertion, 1 deletion
-        "flang": "flang/bin/flang.mjs",
+        "flang": "packaging/flang-launch.mjs",
```

### Почему `package-lock.json` не снят, а тоже печатается

Задача велела его убрать. Замер сказал иначе. **`npm ci` стоит в четырёх работах
CI** (`ci.yml`, `install-path.yml` дважды, `publish-npm.yml`), а `npm ci` без
замка не работает вовсе — прогон в пустом каталоге:

```
с замком      npm ci → код 0, «up to date in 278ms»
без замка     npm ci → код 1, «can only install with an existing package-lock.json»
```

Снять его — сломать четыре работы CI ради двадцати строк. Печатать же его надо
было в любом случае: он **врал**. Точкой входа `flang` он называл
`flang/bin/flang.mjs` — путь, которого в дереве нет вовсе (снят коммитом
`fe8e8a37`), тогда как в `package.json` стоит `packaging/flang-launch.mjs`. Врал
молча: `npm ci` со старым замком отвечает кодом 0. С напечатанным — тоже код 0,
проверено.

### Список `files` больше не расходится молча

Он не «считается из дерева» списком имён — так в пакет уехали бы `flang/self`,
`flang/test` и `flang/проверки`, — а **сверяется с деревом при каждой печати**, и
сверяются обе стороны:

* каждый из 24 путей обязан в дереве быть;
* каждое имя в `flang/` обязано стоять либо в «Внутри flang» (едет), либо в «Не
  едет из flang» — с названной причиной. Имя, стоящее ни там, ни там, роняет
  печать.

Обе порчи прогнаны, обе краснеют именно там, где их внесли:

```
mkdir flang/probe-new-directory   → код 1: «flang/probe-new-directory появился в
                                    дереве и не назван ни в files, ни в отказах»
files: packaging/net-takogo.flang → код 1: «объявлен в files, а в дереве его нет:
                                    npm положил бы в пакет не то»
```

### Версия — из одного места, и это показано прогоном

Правка `«Версия»` в `scripts/emit-package.flang` и одна печать:

```
package.json:          "version": "0.6.3"
package-lock.json:     "version": "0.6.3"
версияВыпуска() сайта:  0.6.3
```

Возврат правки и печать назад — `0.6.2` во всех трёх. Сайт берёт версию из
`package.json` (`docs/site/site-numbers.mjs`, «Версия выпуска — из
`package.json`, а не из памяти»), а `package.json` печатается из объявления;
забыть напечатать нельзя молча — `./ярлык пакет:проверка` краснеет.

### Чего эта работа не сделала

**Полнокорпусные сторожа не прогнаны** — `подсчёты:проверка`, `имена:проверка`,
`числа:проверка` и `утверждения:проверка` требуют собранного двоичного В СВОЁМ
дереве и греют весь корпус (тысяча программ, часы). Смене велено держать не
больше одного прогона разом. Их предмет закрыт сличением: `package.json`
не изменился ни на знак, а в `package-lock.json` изменилась одна строка.

**Три `.mjs` доставки (`packaging/postinstall.mjs`,
`packaging/flang-launch.mjs`, `flang/bin/flang-lsp.mjs`) остались.** Они не
метаданные, а сам путь установки; выносить их — отдельная работа и отдельное
решение владельца о том, нужен ли npm.
