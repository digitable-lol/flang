# Почему двойник ел три миллиарда шагов там, где node тратит четыре секунды

Задача 6858 установила, что flang-двойники node-сторожей не доходят до конца:
`link-collision-guard` при пределе в два миллиарда шагов на вызов съел
**3 211 671 257** шагов, дорос до 4,4 ГиБ, полоса всё время «0 %», и его снял
срок в десять минут. Node на том же дереве укладывается в **4,3 секунды**.
Причина не была найдена ни у одного двойника. Здесь она найдена, доказана
замером и починена.

## Причина: каждый поиск — полный проход по списку

Node держит словари и спрашивает их за постоянное время
(`link-collision-guard.mjs`): `загружены = new Set()`, `просьбы = new Map()`,
`прочитано = new Map()`, `именаМодулей = new Map()`, и главное — `где = new
Map()` с `где.has(файл.имя)` в ядре поиска столкновений.

Двойник на всех тех же местах делает `отфильтровать`, то есть проходит список
целиком:

| место в двойнике | что делает | у node |
|---|---|---|
| `отфильтровать виденные где вид → (вид.«имя») равен (декл.«имя»)` | ядро поиска столкновений | `где.has(имя)` |
| `(длина (отфильтровать просьбы где п → (п.«путь») равен путь)) больше 0` | «есть ли ключ» — через длину отфильтрованного | `просьбы.has(путь)` |
| `отфильтровать индекс где з → (з.«модуль») равен название` | поиск модуля по имени | `Map.get` |
| `(обход.«загружены») содержит цель` | «посещали ли» | `загружены.has(цель)` |

Гнездование в ядре: свёртка по файлам → свёртка по декларациям файла →
**полный проход по всем ранее виденным**. Список виденных растёт с каждой
декларацией, поэтому при N декларациях работа равна N(N+1)/2 сравнений.

## Доказано замером, а не рассуждением

В дереве **21 603** декларации (`тип`/`объект`/`функция` с первой колонки, 1249
файлов `.flang`). Тогда у node 21 603 обращения к словарю, у двойника —
233 344 804 сравнения. Наблюдённые 3 211 671 257 шагов дают **13,8 шага на
сравнение** — правдоподобная постоянная для сличения двух полей записи.

Согласованность — ещё не доказательство, поэтому поставлен решающий опыт:
отдельная программа строит N файлов по одной декларации с РАЗНЫМИ именами
(столкновений нет — меряется чистая стоимость поиска) и зовёт
`«Столкновения из порядка»`. Двоичный `bootstrap/flang`; постоянная плата за
разбор самого сторожа вычтена.

| N | работа ДО | рост | работа ПОСЛЕ | рост |
|---:|---:|---:|---:|---:|
| 200 | 0,40 с | — | 1,10 с | — |
| 400 | 1,50 с | **3,75×** | 2,30 с | 2,09× |
| 800 | 5,00 с | **3,33×** | 3,90 с | 1,70× |
| 1600 | 24,62 с | **4,92×** | 10,50 с | 2,69× |

Линейный рост дал бы 2×, квадратичный 4×. **До починки наблюдается ~4×, после
— ~2,1×.** Это и есть доказательство: квадрат был, и его больше нет.

Перенос замера на настоящее дерево: до починки ~**75 минут**, что сходится с
наблюдавшимся («снят сроком в десять минут при полосе 0 %»); после починки
~**142 секунды**.

## Починка: словарь уже лежал в библиотеке

Это не ограничение языка. `flang/stdlib/hashmap.flang` (1016 строк) даёт ровно
три действия, которыми пользуется node:

    «Положить в словарь» от словарь и ключ:строка и значение
    «Найти в словаре»    от словарь и искомый:строка и запасное
    «Есть ключ в словаре» от словарь и искомый:строка

Ключи — строки, а имена деклараций и есть строки. Порт просто им не
воспользовался.

Внесено три правки в `flang/scripts/link-collision-guard.flang`:

1. импорт `«Hash map»`;
2. в `объект «СборСтолкновений»` поля `виденныеТипы`/`виденныеФункции` из
   `список «Виденное»` стали `«Узел хеша» от «Виденное»`, а `«Пустой сбор»` —
   `вариант «Пустое место»`;
3. в `«Записать первым»` `добавить … к списку` стало `«Положить в словарь»`, а
   в `«Учесть в разряде»` `отфильтровать` + `разбор совпадения` стало
   `«Есть ключ в словаре»` + `«Найти в словаре»`.

**Правильность держат собственные примеры сторожа**, а не слово: у него три
примера ровно на это поведение («Два файла, одна функция дважды —
столкновение», «Разные роды одноимённых деклараций не сталкиваются»,
«Сужение видимости прячет имя от столкновения»). После правки
`flang check flang/scripts/link-collision-guard.flang` даёт «проверено —
разбор, типы, завершаемость, ядро и примеры; замечаний нет», функций 90, из
них с доказанным завершением 90.

Оговорка по устройству `«Найти в словаре»`: ей нужно запасное значение, потому
что у произвольного типа нет заведомо невозможного. Оно недостижимо — ветвь
«ключа нет» отводится раньше, `«Есть ключ в словаре»`. Связывание поднято до
`если`, потому что `пусть` внутри ветви `иначе` не разбирается.

## Настоящий прогон: двойник ДОШЁЛ ДО КОНЦА и ответил то же, что node

Опыт выше меряет функцию в отрыве; последнее слово — за самим сторожем на
настоящем дереве.

    flang io flang/scripts/link-collision-guard.flang

| | до починки | после |
|---|---|---|
| исход | снят сроком в 10 минут | **код 0** |
| шагов | 3 211 671 257 | **пик 777 114 713** |
| время | не дошёл | **137 с** |
| ответ | нет | **«файлов 45, столкновений 0»** |

Ответ совпадает с node знак в знак: шапка этого же файла записывает прогон
`.mjs` как «замыкание: 45 файлов, столкновений: 0».

Предсказание по замеру было ~142 с, наблюдалось 137 с — ошибка 4 %. То есть
перенос квадратичного замера на настоящее дерево оказался верным, и это
подтверждает разбор причины, а не только починку.

## Что это значит шире одного сторожа

Двойников четырнадцать из двадцати, и ни один ярлык на них не переключён
(задача 6858). Здесь показано, что причина по крайней мере у одного —
**не язык и не бюджет шагов, а замена словаря списком при переносе**. Node-код,
переписываемый на flang дословно, теряет `Map`/`Set` и получает квадрат там,
где его не было. Стоит проверить тем же приёмом остальные тринадцать: искать в
них `отфильтровать`/`содержит` на месте, где у `.mjs` стоит `Map`/`Set`.

## Не сделано

* Остальные тринадцать двойников не смотрены — вывод на них не переносится
  без замера, у каждого может быть своя причина.
* Прочие места этого же файла, где поиск остался списковым
  (`просьбы`, `индекс`, `загружены`, `Пути стека`), не переписаны: ядро
  столкновений было горячим, эти — нет, но при росте дерева станут.
* Двойник и после починки медленнее node (~142 с против 4,3 с) — это
  постоянная стоимость толкования, отдельный вопрос, здесь не трогался.
* Ярлык `столкновения:проверка` по-прежнему зовёт `.mjs`; переключать не мой
  файл (`ярлыки.flang` занят другим работником) и не мой порог — сперва
  прогон на настоящем дереве до конца.
