# Заметки о выпусках были написаны. Просто не в той ветке

## Что просили и что оказалось

Поручение: «заметок о выпусках серии 0.7 не было НИКОГДА, напиши
одиннадцать». Основание — задача 5209: `git log -S` пуст.

**Основание неверно, и неверно оно по способу замера.** `git log -S` был
прогнан по dev. На main заметки лежат все одиннадцать, написанные, с
датами и содержанием.

```
git log --all -S'0.7.10' -- docs/release-notes.json
  → 35f4c9d8 release(0.7.10): реальный sha256 (сухой прогон),
              release-notes, честная история формулы

git log dev  -S'0.7.10' -- docs/release-notes.json
  → (пусто)
```

Это ровно то, что задача **4970** установила про версии: **выпуск
делается на main и в dev не возвращается**. 5209 увидела следствие
(в dev заметок нет) и назвала его причиной («не писались»).

## Почему писать заново было бы вредно, а не просто лишним

Заметки на main честные — именно такие, каких требовало поручение.
Дословно, `0.7.4`:

> **Метка есть, публикация остановлена конвейером.** Тот же материал,
> что вышел как 0.7.5: sha256 в Homebrew-формуле стоял от 0.7.3,
> конвейер выпуска сверил его с архивом, который сам собрал на теге, и
> остановился ДО публикации — прибор сработал как задуман, ничего
> битого не вышло. Тег не удалялся (запись запрещена), просто пропущен.

Написать одиннадцать новых значило бы **завести вторую версию истории**
рядом с уже опубликованной — и разойтись с ней в мелочах, которые никто
потом не свёл бы. Дисциплина суток (задачи 10004, 3397, 4471) требует
обратного: датированную запись не переписывать.

## Что сделано вместо

Файл `docs/release-notes.json` взят с main **целиком**. Так можно,
и это проверено, а не предположено:

| сверка | итог |
|---|---|
| общих версий | 14 |
| из них расходятся | **0** |
| есть только на main | 11 (вся серия 0.7) |
| есть только на dev | **нет** |

main — строгое надмножество. Перенос есть **добавление**, а не правка
прошлого. Тот же приём, каким 4970 брала формулу Homebrew с main
целиком, и по той же причине.

Страницы перепечатаны названной самим сторожем командой —
`flang io scripts/releases-page.flang`, «Напечатано: выпусков 25».
Правились не они, а источник: `releases.md` и `releases.ru.md`
печатаются из `release-notes.json`.

## Числа

```
до:    сторож выпусков — 13 замечаний
       (11 тегов без заметок + releases.md + releases.ru.md)
после: «Сверка прошла: выпусков 25, расхождений 0», код 0
```

Прогон обоих концов — `bootstrap/flang io scripts/releases-page-verify.flang
--max-steps 40000000`, двоичный положен в клон из `peredacha` перед
работой (задача 3740: без этого прогон даёт код 127, замаскированный
под настоящую беду).

## Оговорка про предел шагов

`releases-page.flang` не проходит при умолчании 10 млн — «функция «Шаг
разметки json» исчерпала лимит шагов». Ярлык `выпуски:страница` предела
не задаёт, и на 25 выпусках его не хватает; прошло при 400 млн. Это тот
же род, что задача **3397** нашла у `времянки`: сторож сломан не сам, а
**вызовом**. Ярлык не правился — `ярлыки.flang` занят другим работником.

## Не сделано

* **Остальное расхождение main и dev не тронуто.** Заметки — один файл
  из тридцати двух коммитов, которые 4970 назвала неслитыми. Слияние
  main в dev остаётся решением координатора, и эта задача его не
  заменяет и не приближает: она закрывает ровно сторож выпусков.
* Ярлык `выпуски:страница` без предела шагов — назван, не починен.
* Заметки 0.4.x–0.6.2 не читались: они и на main, и на dev одни и те же
  побайтово, трогать их незачем.
