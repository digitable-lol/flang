# 5144. ADR-0026 §5 шаг 2, §11 п.3: свободное утверждение доказывается правилами ведомости и переигрывается

## Что известно из замера (11 сентября 2026, семя из `r/partiya-2` 6b7c43f86)

Форма `утверждение «И»` / `для всех х: Т` / `утверждаем Ц` в стволе есть (К3a–К3c, партия №1),
но сверщик переигрывает её доказательство ТОЛЬКО сведением к постусловию функции, которую цель
зовёт на связанном имени (К3b). Цель без функции — чистая арифметика — на трёх приёмочных
утверждениях владельца даёт (`bootstrap/flang check --proof --записать`):

| утверждение | ядро | запись | сверщик |
|---|---|---|---|
| `для всех н: неотрицательное — (н плюс 0) равен н` | «нет вердикта» | без правила | — |
| `для всех а: число и б: число — (а плюс б) равен (б плюс а)` | доказано, «тождество после переписки допущением» | ходов нет | код 3: «несколько связываний в одной строке «для всех»: форма записи для них контрактом не названа» |
| `утверждаем (длина пустой список) равен 0` (без «для всех») | `FLANG_PARSE` «ничего не связывает» | — | — |
| то же с пустым связыванием `для всех л: список числа` | доказано, тождество | ходов нет | код 3: «значение «по объявлению нет» — сверщик не повторяет изъятие объявленного типа» |

Ведомость словами (`--proof` без `--записать`) печатает «утверждений 0» — свободные утверждения в
её счёт не входят вовсе (`proof.flang` «Все утверждения» отбирает только `postcondition`), хотя в
записи стоят все три.

**Первое утверждение владельца ложно в этом языке.** `неотрицательное` при работе принимает минус
ноль (`flang run … --args '{"н": -0}'` проходит проверку типа), `−0 плюс 0` есть `+0`, а `равен`
языка — `Object.is`: `«Нейтрален» от −0` печатает `false`. Ядро отвечает «нет вердикта» честно.
Модель Lean (`Модель.lean`: `«неотр» «минусНоль» = true`, `«равен» «минусНоль» («кон» 0) = false`)
говорит то же. Поэтому тождество нуля доказывается только при посылке, исключающей минус ноль:
`для всех н: неотрицательное таких что н больше 0`.

Опыт с рукотворной записью показал: ходы под утверждением без функции сверщик УЖЕ переигрывает
(`без_теоремы` → `проиграть_блок`, функция пустая) — `соседи ⟨а плюс 1⟩` и
`вычислить ⟨(длина пустой список)⟩ = ⟨0⟩` дают код 0 при одном связывании. Не хватает печати
ходов ядром, чтения нескольких связываний и правила о нуле.

## Что сделать

- **Ш1 разбор.** Утверждение без единой строки «для всех» — замкнутая цель — разбирается (отказ
  «ничего не связывает» снят; свободное имя по-прежнему `FLANG_PROOF_UNKNOWN_VAR`). Русская и
  английская запись (`statement` / `for all … and …` / `claim`).
- **Ш2 ядро.** В «Свести равенство» — правило нейтрального нуля: `Т плюс 0` (или `0 плюс Т`) есть `Т`,
  если `Т` строго положительно по факту (`таких что Т больше К`, К ≥ 0). Имя правила в поле `rule`
  остаётся «тождество после переписки допущением» (закрытый список сверщика не растёт); строка
  ведомости и лемма Lean — свои.
- **Ш3 печать.** Под блоком `вид statement` ядро печатает ходы: `соседи ⟨…⟩`, `нейтральный ноль ⟨…⟩`,
  `вычислить ⟨…⟩ = ⟨…⟩` и `закрыть тождеством` — без `развернуть` (функции нет). Тип связанной
  в английской записи (`and`) печатается, а не пустеет.
- **Ш4 ведомость словами** считает свободные утверждения рядом с постусловиями.
- **Ш5 сверщик.** Несколько связываний в одной строке «для всех» читаются по строке записи на каждое;
  новый ход «нейтральный ноль» проверяет форму терма и посылку о положительности из «таких что»
  исходника; закрытый список ходов — тринадцать.
- **Ш6 ведомость правил.** Семейство «Тожд» (тождества одного узла): Тожд1 — перестановка соседей,
  Тожд2 — нейтральный ноль при положительном; леммы Lean, искажение в «Ловушка.lean».
- **Ш7 пробы.** Семья `утверждение/`: три честные записи (печать ядра толкованием), подделки: ложное
  `(н плюс 1) равен н`, подмена типа связывания, пропущенная посылка «таких что», запись без ходов
  («не бери»). Ловушка проверки 1: три новых вида «снята», цель «на слове» заменена (храповик
  «на слове» не опущен, «видов» 34 → 37).
- **Ш8 прибор.** `sh scripts/доказуемость.sh` ДОКАЗУЕМ, доля не ниже 625/651, «сошлось всё»;
  Lean «сошлось всё»; сторожа ведомости С-1…С-6.

## Чего эта задача НЕ делает

Не заводит индукцию по связанному имени для цели без функции (К3b как было). Не трогает квантор в
`требует` (ADR-0026 §11 п.5). Не добавляет запятую как разделитель связываний — только `и` / `and`.
Не учит сверщик читать английский исходник (он читает русские слова языка — как и до задачи).
Не перепечатывает семя: правки `flang/self/**` проверены толкованием (зонд К7), до двоичного
доедут перепечаткой у ведущего. Не меняет модель Lean: расхождение `«равен» «неЧисло» «неЧисло»`
(модель — ложь, язык — `Object.is`, истина) названо в леммах посылкой, а не спрятано.

**Первое утверждение владельца ложно в этом языке, и это замер, а не осторожность.**
`неотрицательное` при работе принимает минус ноль, `−0 плюс 0` есть `+0`, а `равен` —
`Object.is` — их различает. Поэтому «для всех н: неотрицательное — (н плюс 0) равен н»
ядро не доказывает вовсе; доказывается оно только с посылкой `таких что н больше 0`, и
порча `ноль-без-посылки` стережёт ровно это.

Что пришлось поправить против ожиданий предыдущего исполнителя (все три — замером):

1. Опора Тожд2 в ведомости звала `proof-kernel.flang:9004`, а функция стоит на 9001 —
   сторож С-1 был красен.
2. Проба `несколько-связываний` ждала кода 0; на деле код 3, и причина другая: её
   рукотворный узел закрыт правилом без единого хода. Ожидание исправлено, а рядом
   поставлена проверка, что ПРЕЖНЕГО отказа «формы записи нет» больше нет.
3. Цель ловушки «не бери» не срабатывала: сверщик уходил в ветку «по объявлению нет».
   Запись порчи приведена к виду, где блок сведения вынут целиком (ядро печатает
   «правило» и «по объявлению» вместе) — тогда звучит нужное «за узел не взялся».
