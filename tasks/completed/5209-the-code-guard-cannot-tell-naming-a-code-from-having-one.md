# Сторож кодов краснел на прозе, которая его же и объясняет

## Откуда взялось

Задача 9028 сосчитала сторожей: их 56, CI зовёт 29, двадцать семь не зовёт
никто. Среди незваных нашлось десять красных с настоящим долгом. Этот разбор —
про одного из них, `коды:проверка`, и он оказался самым дешёвым: **8 нарушений
→ 4**, две правки, обе с прогоном до и после.

## Устройство сторожа — хорошее, и это надо сказать сразу

`flang/scripts/code-guard.flang` требует: код отказа, названный прозой, обязан
существовать в исходниках. Код, которого нет, обязан стоять в закрытом списке
«Объявлено, не сделано» — поимённо, с местом и с доводом. Родов ровно три:

* **долг** — код обещан прозой и ещё не написан;
* **отвергнут** — код назван затем, чтобы объяснить, почему его НЕ будет;
* **снят** — код существовал и убран вместе с тем, что его читало.

Список проверяется **в обе стороны**: код из списка, который ПОЯВИЛСЯ в
исходниках, — тоже отказ, потому что долг закрыт и запись стала неправдой. Без
второй половины список стал бы свалкой, куда сваливают всё покрасневшее, то есть
выключателем проверки.

## Беда: он не отличает употребление имени от существования кода

Четыре из восьми нарушений оказались не бедой дерева, а слепотой сторожа.

### 1. `FLANG_CACHE` — «долг закрыт», хотя ничего не вернулось

Сторож сказал: код числится «снят», а в исходниках УЖЕ ЕСТЬ — убирайте запись.
Прогон показал, где именно: `scripts/link-guard.flang`, **пример** функции
«Известные расширения улик»:

```
пример «Код отказа без точки — не путь»
  дано кусок равно "FLANG_CACHE"
  ожидается ""
```

Имя взято **как образец** строки, которая не является путём. Кеш не возвращался;
вернулось только имя, и то в тестовых данных чужого сторожа.

**Починено:** образцом взят `FLANG_RECURSION_LIMIT` — код, который в дереве
действительно есть (49 файлов). Пример стал вернее по смыслу (образец —
настоящий код отказа) и перестал врать сторожу кодов.

**Попутно наступил на ту же грабку сам.** Первая редакция примечания к правке
объясняла, почему нельзя брать это имя, — и называла его буквально. Сторож
покраснел снова: 8 → 8. Объяснение беды воспроизвело беду. Примечание
переписано так, чтобы прежнее имя не называлось.

### 2. Три кода подлога — имена, которых не должно быть никогда

`FLANG_PODLOG_VYDUMANNYY_KOD`, `FLANG_PODLOG_KODA_VZYAT` (задача 6805) и
`FLANG_VYDUMKA_SPRAVKI` (задача 1389) — это **инструменты проб**. Первый
подкладывается в страницу дерева, чтобы проверить, покраснеет ли сторож
кодов; второй — код, которым проба отвечает, поймав беду; третий — из показа
красноты сторожей на подлоге.

Сама проба (`flang/scripts/code-forgery.flang:83`) склеивает имя из кусков:

```
соединить ["FLANG", "_", "PODLOG_VYDUMANNYY_KOD"] по ""
```

— то есть приём обхода собственного сторожа там уже придуман. А задача, которая
беду **описывает**, назвать имя обязана: иначе описания не выйдет.

**Починено:** три записи родом «отвергнут» в закрытый список, каждая с местом и
доводом. Это законный механизм сторожа, а не глушение: появление любого из них
в исходниках по-прежнему отказ.

## Проба порчи — в обе стороны, своим прогоном

Без неё правка не принимается: список «Объявлено, не сделано» тем и опасен, что
им легко заткнуть проверку.

```
подложено в docs/ci-inventory.md: «FLANG_L7_PODLOG_PROVERKA — кода нет нигде»
  → сторож кодов: 5 нарушени(й), подлог НАЗВАН, код 1
возврат страницы (git checkout)
  → сторож кодов: 4 нарушени(й), подлог ЗАБЫТ, код 1
```

Сторож ловит новый выдуманный код и забывает его после уборки. Не заглушён.

Сам сторож проверен целиком: `flang check flang/scripts/code-guard.flang` —
функций 32, все с доказанным завершением, замечаний нет, код 0. То же для
`scripts/link-guard.flang` — функций 54, все с доказанным завершением, код 0.

## Что осталось — четыре, названы числом

Не чинились: каждое требует решения о прозе, которого у меня нет.

| код | мест | что установлено |
|---|---:|---|
| `FLANG_ZAMER` | 8 | в дереве есть `FLANG_ZAMER_ПУСТО` и `FLANG_ZAMER_ДЕРЕВО` (`benchmarks/proof-cost/count-20.flang`). Проза называет **семейство** по префиксу, сторож требует точного имени |
| `FLANG_PROBE_MAX_DEPTH` | 7 | нет нигде. Опись (`docs/ci-inventory.md:74`) сама говорит: это **переменная среды**, принятая за код отказа |
| `FLANG_CHARGE_OUT` | 1 | нет нигде; одно место, заметка базы знаний |
| `FLANG_ZAMOK_USTAREL` | 2 | нет нигде; оба места в закрытой задаче `tasks/completed/0036` |

Развилка у всех четырёх одна и решать её не мне: **переписать прозу** (но
часть мест — записи о том, как было, и переписывать историю нельзя) **или
завести записи в закрытый список** (но род «долг/отвергнут/снят» надо выбрать
по факту, а факта я не знаю: обещаны они или отвергнуты).

Отдельно про `FLANG_ZAMER`: половина его мест — задачи, описывающие СТОРОЖЕЙ
(`tasks/9028` — вчерашняя, `tasks/9350`, `tasks/1389`). Это та же порода, что
вылечена выше: проза о сторожах вынуждена называть коды. Возможно, правильный
ответ — не список, а умение сторожа не считать прозой цитату внутри огороженного
блока; но это правка его устройства, а не запись, и она дороже.

## Чем это НЕ является

Не является общим решением беды 6805 («сторож помнит подлог после уборки»). Тот
сценарий идёт через `code-forgery.flang` и здесь не воспроизводился: моя проба
порчи забыла подлог сразу. Возможно, беда 6805 уже снята, возможно — живёт в
другом сценарии; я её не проверял и не закрываю.
