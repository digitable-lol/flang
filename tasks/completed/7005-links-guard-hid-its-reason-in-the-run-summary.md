# 7005 — единственная красная работа CI, причину которой нельзя было узнать

## Как найдено

Задача 9420 разбирала шесть красных работ на `main`. Пять названы поимённо,
про `links` записано: **«сторож красен — НЕ УСТАНОВЛЕНО»**, и названа
причина невозможности: работа печатает ответ сторожа в
`$GITHUB_STEP_SUMMARY`, а в лог кладёт одну строку
предупреждение со словами «подробности в сводке прогона». Через
`gh run view --log-failed` ответа не достать, а сводка стареет вместе с
прогоном.

## Причина красноты установлена — прогоном из дерева

Прогон `scripts/link-guard.flang` двоичным, собран из дерева,
прогон около семи минут под чужой нагрузкой (записанный замер — 4 мин
39 с), память 395–572 МиБ (записано было 1,23 ГиБ):

```
сторож ссылок ОТКАЗЫВАЕТ, битых 2507 из 14638, устаревших исключений 43
```

Роды, посчитаны разбором ответа:

```
2498  путь в кавычках ведёт в никуда
   9  ссылка в никуда (настоящая ссылка Markdown)
  43  исключение больше не срабатывает
```

По расширению цели у битых:

```
~2254  .mjs      упоминания снятых файлов эпохи JavaScript
  ~80  .flang
  ~56  .md
```

**Девять десятых красноты — проза, называющая файлы, снятые при уходе с
JavaScript**: flang/src/proofterm.mjs, flang/bin/flang.mjs, flang/src/compat.mjs и им
подобные (нарочно без кавычек: цели нет, и в кавычках сторож счёл бы их
ещё одной битой ссылкой — этой самой задачей) в `CHANGELOG.md`, `README.md`,
`AGENTS.md`, `CONTRIBUTING.md`. Это известный долг: `.github/workflows/ci.yml` держит работу
с `continue-on-error: true` именно поэтому и объясняет это в шапке.

**Расхождение с шапкой названо, а не замолчано.** Шапка `.github/workflows/ci.yml` говорит о
«порядка 470–500 подтверждённых историей мёртвых ссылок». Сторож сегодня
называет 2507 битых. Числа разные, потому что 470–500 — это подтверждённые
историей ветки, а 2507 — все, у кого цели нет в дереве. Свести их эта
работа не бралась.

## 43 устаревших исключения — следствие сегодняшнего переноса архива

`scripts/link-guard-known-not-a-path.tsv` закрыт по правилу задачи 1389:
запись, которая на прогоне ни разу не понадобилась, — **тоже отказ**, иначе
список гниёт молча. Правило не только в шапке, оно в коде
(`«Про устаревшее исключение»`, беда «исключение больше не срабатывает»).

Сегодня задача 5379 перенесла 48 закрытых задач в `tasks/completed/`.
**Восемнадцать из них названы в этом списке — 41 запись**, и все 41 стали
указывать в пустоту. Проверено поимённо: ни один файл не пропал, все 18
лежат в `tasks/completed/`, и упоминания в них на месте.

Починка — переписать путь записи на архивный. Ничего не удаляется и не
гасится по маске: файл переехал, запись едет за ним.

## Слепота починена — это важнее конкретных ссылок

Работа `links` в `.github/workflows/ci.yml` теперь печатает ответ сторожа **и в лог, и в
сводку**. Сводка остаётся ради разметки; лог получает то же дословно, между
строками «── СТОРОЖ ССЫЛОК КРАСЕН, вот его ответ целиком ──» и «── конец
ответа сторожа ──».

Пока причина видна только в стареющей сводке, всякий следующий разбор
упрётся в то же самое — что и случилось с задачей 9420.

## Побочная находка: сторож не пишет в stdout ВООБЩЕ

Проверено прогоном: при коде 1 сохранённый стандартный вывод остаётся **пустым (0 байт)**, весь ответ идёт в stderr — и там же вперемешку лежат отметки
хода («шагов N …, идёт „Шаг плана", 414 МиБ»).

Значит на дороге отказа вывод сохранённого ответа в старой редакции работы
выводил пустоту, а полезное приезжало только из потока ошибок вместе с шумом
отметок. Правка это не меняет (оба файла печатаются), но знать надо:
**разделение stdout/stderr у этого сторожа не несёт смысла «ответ/шум»**.

## Чего эта работа НЕ делает

* **2507 битых ссылок не чинились.** Это отдельный объём: ~2254 из них —
  проза о снятых файлах JavaScript, и чинить её значит править историю в
  `CHANGELOG.md` либо заводить второй закрытый список (путь «б» из шапки
  `.github/workflows/ci.yml`). Решение владельца, и оно там уже описано.
* **Два устаревших исключения из 43 не разобраны** — 41 объяснено переносом
  архива, остальные два не искались поимённо.
* `continue-on-error: true` не снимался.

## Замер после починки списка — A/B на ОДНОМ дереве

Первое A/B вышло не однопеременным: клоны различались ещё и правкой
`.github/workflows/ci.yml`, и знаменатель разошёлся (14638 против 14648). Переснято на одном
клоне, разница ровно в списке:

```
до     битых 2508 из 14648, устаревших исключений 43
после  битых 2457 из 14648, устаревших исключений  2
```

Устаревших стало 2 из 43 — переписан 41 путь. Битых убыло 51: записи,
которые указывали в пустоту, снова начали исключать свои (файл, цель), а
до починки те считались битыми.

Два оставшихся устаревших исключения поимённо не разбирались.

## Проба порчи — сторож называет выдуманную ссылку поимённо

В `docs/zettel/` заведён файл с ссылкой на заведомо несуществующий файл:

```
· docs/zettel/проба-порчи-ссылок.md: ссылка в никуда → flang/этого-файла-нет-и-не-будет.flang
```

Названы и файл, и цель. Проба снята, в дереве её нет.

## Эта задача чуть не выросла в тот самый долг, который описывает

Первая редакция цитировала мёртвые пути в кавычках как примеры — и сторож
законно счёл их новыми битыми ссылками: девять путей в кавычках без цели.
Проверено разбором собственного текста, кавычки сняты там, где цели нет, а
короткое `ci.yml` выправлено на полный путь.

Итоговый прогон всей ветки:

```
база (то же дерево, до правок)   битых 2508 из 14648, устаревших 43
ветка целиком                    битых 2456 из 14650, устаревших  2
```

Ссылок стало на две больше — обе из этой задачи и обе целы. Битых **не
прибавилось ни одной**.
