# stdlib — стандартная библиотека ftsc

Четыре пакета словарей, которые в каждом сервисе пишут заново: HTTP, хранилище,
репозиторий и типовые политики (повтор, идемпотентность, ограничение частоты).
Всё написано на самом FTS: объекты, именованные состояния, морфизмы допуска и
чистые утилиты с примерами-тестами.

Граница честности библиотеки та же, что у языка и у `ftsc` (см. `../SPEC.md`):

> **Библиотека не выполняет ни одного эффекта.** Она не открывает сокет, не
> печатает SQL, не читает часы, не спит и не повторяет. Она считает **число** и
> выдаёт **допуск**. Ждать, звать, писать и повторять — работа приложения.

Из этого следуют три ограничения, которые видны в каждом модуле:

1. **Нет строковых операций.** Ни разбора URL, ни склейки, ни сравнения по
   префиксу. Строка — только идентификатор в данных.
2. **Нет времени.** Возраст, TTL, задержка, окно — обычные числа, которые
   измеряет приложение своими часами.
3. **Нет коллекций и умножения.** Утилита принимает один объект и складывает
   числа; умножение выражается процентом от поля (`200 процентов от поля X`),
   вычитание — отрицательным процентом (`-100 процентов от поля X`).

Это ограничения дизайна, а не пробелы: там, где вычисление невыразимо честно,
библиотека возвращает явный признак невычислимости, а не правдоподобное число.

## Как подключить

Заголовок модуля разбирает `ftsc`, тело — компилятор ядра:

```fts
модуль «Каталог товаров»
  использует «HTTP» из «../http/request.fts»
  использует «Хранилище» из «../sql/storage.fts»
  экспортирует «Запрос каталога», «Определить размер выдачи»

категория «Каталог товаров»
  ...
```

Путь указывается относительно текущего файла; можно указать файл или каталог с
одним `.fts`. Импорт имени, которого нет в строке `экспортирует` модуля-донора,
даёт ошибку `FTSC_NOT_EXPORTED`.

Подключение даёт **три** способа переиспользования, и их полезно различать:

- **объекты и утилиты** — по имени из `экспортирует`;
- **состояния** — имя состояния (`«Обработка запроса разрешена»`) свободно
  используется в морфизме своего модуля; так соединяются два пакета без
  копирования их объектов;
- **объекты целиком** — через функтор (см. ниже), когда данные надо перенести
  из одной категории в другую.

Живой пример всех трёх — в `example/`.

## Пакеты

### `http/` — категории «HTTP» и «Запрос списка»

| Файл | Категория | Объекты | Утилиты |
|---|---|---|---|
| `http/request.fts` | «HTTP» | «Запрос», «Ответ» | «Определить код ответа», «Определить класс ответа» |
| `http/query.fts` | «Запрос списка» | «Запрос страницы» | «Нормализовать размер страницы», «Нормализовать номер страницы» |

Состояния: «Авторизован», «Обработка запроса разрешена», «Ответ может быть
отправлен», «Запрос страницы проверен». Морфизмы допуска: «Авторизованный
запрос можно обработать», «Обработанный запрос порождает ответ», «Проверенный
запрос страницы допускает выборку».

«Определить код ответа» считает код по уже установленным признакам: правила
выполняются по порядку, и последнее сработавшее задаёт код, поэтому
аутентификация (401/403) перекрывает метод (405) и тело (400). «Определить
класс ответа» сводит код к 2/4/5; для кодов ниже 200 класс остаётся 0.

**Чего пакет не делает:** не открывает соединение, не разбирает URL, заголовки
и cookie, не проверяет подпись токена, не сериализует тело. Признаки «токен
действителен», «метод разрешён», «тело валидно» устанавливает приложение — FTS
принимает их как факты и решает по ним.

### `sql/` — категория «Хранилище»

Объекты: «Условие выборки», «Страница», «Единица работы».
Утилиты: «Рассчитать смещение», «Рассчитать предел выборки», «Рассчитать
остаток записей», «Страница в границах данных».
Состояния: «Условие проверено», «Транзакция открыта». Морфизмы: «Проверенное
условие допускает выборку», «Открытая транзакция допускает запись»,
«Разрешённая запись допускает фиксацию».

**Ни одной строки SQL здесь нет и не будет.** Генерация SQL не входит в язык:
в ядре нет строк как данных, нет конкатенации и нет коллекций, поэтому любой
«генератор запросов» был бы подделкой — шаблоном на JavaScript, притворяющимся
моделью. Пакет даёт форму условия, арифметику страницы и допуск записи; текст
запроса, соединение, курсор, `COMMIT` и `ROLLBACK` остаются за приложением.

Отдельно про смещение: `(номер − 1) × размер` для произвольного номера
страницы **невыразимо** — умножения на переменную в ядре нет. «Рассчитать
смещение» честно покрывает окно первых пяти страниц таблицей правил, а для
номера за окном возвращает `-1` — явный признак «считай сам». Молча вернуть
неверное смещение было бы хуже, чем отказаться.

### `repository/` — категория «Репозиторий»

Объекты: «Ключ», «Кэш-запись». Состояния: «Найдено», «Не найдено».
Морфизмы: «Найденную запись можно прочитать», «Найденную запись можно
обновить», «Отсутствующую запись можно создать», «Разрешённое обновление
допускает запись».
Утилиты политики кэша: «Кэш пригоден» (допуск), «Рассчитать остаток времени
жизни» (число).

**Чего пакет не делает:** не читает и не пишет данные, не знает про драйверы и
транзакции, не измеряет время. TTL и возраст — числа, которые приложение
получило от своих часов; факты «Найдено»/«Не найдено» приложение установило
запросом. Репозиторий здесь — это контракт допуска, а не реализация.

### `patterns/` — категории «Повтор», «Идемпотентность», «Ограничение частоты»

| Файл | Категория | Объекты | Утилиты |
|---|---|---|---|
| `patterns/retry.fts` | «Повтор» | «Попытка» | «Рассчитать задержку», «Повтор разрешён» |
| `patterns/idempotency.fts` | «Идемпотентность» | «Команда» | «Определить решение по команде», «Повтор безопасен» |
| `patterns/rate-limit.fts` | «Ограничение частоты» | «Бюджет», «Заявка на запрос» | «Рассчитать остаток бюджета», «Запрос допущен к обработке» |

«Рассчитать задержку» — экспоненциальная стратегия с потолком: 1×, 2×, 4×, 8×
базовой задержки, дальше 16× для всех попыток (кратность выражена процентом от
поля). «Определить решение по команде» возвращает число: `0` — выполнить, `1` —
вернуть сохранённый результат, `2` — отклонить как конфликт. «Рассчитать
остаток бюджета» и «Запрос допущен к обработке» разделены, потому что утилита
принимает ровно один объект: сначала считается остаток по счётчику, затем по
остатку решается допуск.

**Чего пакет не делает:** не спит, не повторяет вызов, не хранит счётчики и
ключи, не сдвигает окно, не знает, сколько прошло времени. Он считает число
задержки и выдаёт допуск; цикл повтора, таймер, хранилище ключей идемпотентности
и счётчик частоты — в приложении.

## Функтор между пакетами

`mapping/query-to-storage.fts` — функтор «Запрос страницы в условие выборки» из
«Запрос списка» в «Хранилище»:

```fts
объект «Запрос страницы» отображается в «Условие выборки»
  поле «номер страницы» отображается в поле «номер страницы»
  поле «размер страницы» отображается в поле «размер страницы»
  поле «только активные» отображается в поле «только активные»
  поле проверен отображается в поле проверено

морфизм «Проверенный запрос страницы допускает выборку» отображается в морфизм «Проверенное условие допускает выборку»
```

Ради этого функторы и нужны. Без них параметры листинга пришлось бы либо
описать дважды и переносить руками, либо смешать границу HTTP и хранилище в
одну категорию. Функтор проверяет форму переноса машиной: каждый объект домена
имеет образ, каждое поле отображено, типы совместимы, морфизм переходит в
морфизм согласованной формы (`F(f): F(a) → F(b)`). Отображение состояний здесь
согласовано: `F(«Запрос страницы проверен») = «Условие проверено»` задано
отображением полей, `F(«Выборка разрешена») = «Выборка разрешена»`.

Чего функтор не доказывает — что перенос верен по смыслу. Он проверяет форму,
ровно как теорема в ядре.

## Демонстрационный проект `example/`

Три файла: `catalog.fts` (модуль), `catalog-to-storage.fts` (функтор),
`ftsc.json` (манифест). Модуль подключает четыре модуля библиотеки, не
переописывая ни кодов ответа, ни арифметики страницы, и добавляет только своё:
потолок выдачи каталога и морфизм-мост «Обработка запроса открывает проверку
условия», который связывает состояние из «HTTP» с состоянием из «Хранилища».
Теорема модуля показывает, как факт из данных проходит через этот мост.

Порядок вызовов в приложении, который проект иллюстрирует:

1. «Определить код ответа» («HTTP») — пускать ли запрос дальше;
2. «Нормализовать размер страницы» («Запрос списка») и «Определить размер
   выдачи» («Каталог товаров») — какой объём отдавать;
3. функтор «Запрос каталога в условие выборки» — перенос в словарь хранилища;
4. «Рассчитать смещение» и «Рассчитать предел выборки» («Хранилище») — границы;
5. «Кэш пригоден» («Репозиторий») — брать ли данные из кэша.

Сами вызовы, кэш, соединение и сериализацию делает приложение.

## Проверка модулей

Заголовок (`модуль`/`использует`/`экспортирует`) и строки функтора разбирает
`ftsc`; тело модуля — обычный документ ядра. Пока `ftsc` собирается, каждый
модуль проверяется ядром напрямую: заголовочные строки отбрасываются, тело
компилируется, валидируется и прогоняется примерами.

Из корня репозитория:

```bash
npm run build
node --no-warnings -e '
import("./dist/src/index.js").then(async (fts) => {
  const fs = await import("node:fs");
  const HEAD = /^\s*(модуль|использует|экспортирует|функтор|объект .* отображается|поле .* отображается|морфизм .* отображается)(?![\p{L}])/u;
  const raw = fs.readFileSync("tools/ftsc/stdlib/http/request.fts","utf8");
  const body = raw.split("\n").filter((l) => !HEAD.test(l)).join("\n").trim();
  const doc = fts.compile(body);
  console.log(doc.category, JSON.stringify(fts.validate(doc).valid), JSON.stringify(fts.testUtilities(doc)));
});'
```

Текущее состояние: восемь модулей с категориями, 60 примеров, все проходят;
у каждой утилиты не меньше двух примеров. Файлы функторов тела не имеют и ядром
не компилируются — их проверяет `ftsc`.

## Правила пополнения библиотеки

1. У каждой утилиты минимум два примера, и они обязаны сходиться. Утилита без
   примеров в библиотеку не принимается.
2. Никаких конструкций вне `docs/rukovodstvo/language.ru.md`. Если вычисление невыразимо —
   вернуть явный признак невычислимости и написать об этом в README, а не
   изобретать синтаксис.
3. Раздел «чего пакет не делает» обязателен и важнее раздела «что даёт».
4. Одна категория — один файл; имя модуля по умолчанию равно имени категории.
5. Имена — по-русски, в стиле моделей из `examples/`.
