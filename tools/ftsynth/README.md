# ftsynth — синтез моделей FTS из исторических решений

Обычное генетическое программирование выдаёт дерево выражений, которое никто не
может прочитать: доверять ему приходится на слово. Здесь популяция состоит из
**правил FTS**, поэтому результат поиска — не чёрный ящик, а читаемая
исполняемая спецификация. Её можно показать аналитику, проверить примерами,
положить в CI, скомпилировать в TypeScript и напечатать на восьми языках — всё
это уже умеет ядро FTS, потому что на выходе получается обычная `.fts`-модель.

Практическая постановка: есть журнал решений (входы и то, что фактически решили —
скидка, тариф, допуск). Нужно найти набор правил, который эти решения объясняет
и при этом достаточно прост, чтобы человек согласился с ним как с политикой.

Зависимостей ноль. Node ≥ 20, ES-модули. Ядро FTS берётся из вендоренной сборки
`static/js/vendor/fts/browser.js` — тем же способом, что и `ftsc`, `ftsvm`,
`ftspec`.

```
tools/ftsynth/
  bin/ftsynth.mjs       CLI: fit, gen-data, sets
  src/prng.mjs          воспроизводимый поток случайных чисел
  src/schema.mjs        схема задачи и кандидаты пространства поиска
  src/individual.mjs    особь: генотип, сборка модели, печать в текст
  src/operators.mjs     мутации и кроссоверы
  src/fitness.mjs       три критерия, свёртка, недоминируемая сортировка
  src/refine.mjs        локальная доводка (меметическая часть)
  src/evolve.mjs        эволюционный цикл, разбиение выборки
  src/generate.mjs      детерминированный генератор наборов данных
  src/behaviour.mjs     сравнение моделей по поведению
  src/report.mjs        текст модели и отчёт
  data/                 два набора + истинные политики рядом
  test/                 node:test
```

## Особь — это модель, а не строка

Генотип — начальное значение утилиты плюс упорядоченный список правил в точности
той форме, что описана в `src/model.ts` ядра:

```js
{
  initial: 0,
  rules: [
    { when: [{ field: "сумма", operator: "gte", value: { kind: "value", value: 10000 } }],
      action: { kind: "add", value: { kind: "percent", percent: 10, field: "сумма" } } },
  ],
}
```

Мутируется **структура**; текст печатается только на выходе. Обратный порядок —
мутировать текст — неизбежно порождает то, что не разбирается, и главный
инвариант рассыпается.

Инвариант звучит так: **любая особь любого поколения печатается в текст,
разбирается естественной поверхностью и проходит `validate` ядра.** Не «на
выходе получается валидная модель», а именно любая особь: если инвариант держит
только победитель, значит поиск шёл по пространству, часть которого не является
программами. Он проверяется в `test/invariants.test.mjs` на каждом уникальном
генотипе каждого поколения обоих наборов.

Держится инвариант не проверками после мутации, а конструкцией: все значения
берутся из кандидатов пространства поиска, типы условий и действий соблюдают те
же правила, что проверяет `src/validate.ts` ядра (порядковые сравнения только
для чисел, `добавить` только для числового результата, тип операнда действия
совпадает с типом результата), а число правил и условий держится в границах.
Имена правил в генотипе не хранятся — они выводятся из условий при печати, иначе
кроссовер таскал бы за правилами устаревшие имена и читаемость терялась бы к
десятому поколению.

Пороги берутся не из воздуха, а из наблюдённых значений поля: порог между двумя
наблюдениями неразличим на данных, поэтому любое промежуточное значение — произвол,
который нечем обосновать. Константы действия берутся с «человеческой лестницы»
1-2-5 × 10^k: политика, написанная человеком, почти никогда не содержит числа
4837.

## Операторы

Все операторы — чистые функции `(особь, пространство, поток) → особь`: вход не
мутируется, результат всегда новый объект. Это не эстетика: элита переносится в
следующее поколение по ссылке, и оператор, меняющий аргумент на месте, тихо
испортил бы уже оценённую особь. Такой баг невоспроизводим и не виден по фитнесу.
Чистота проверяется тестом отдельно для каждого оператора.

Мутации (`src/operators.mjs`): сдвинуть порог условия на шаг по лестнице
кандидатов, сменить сравнение, изменить действие (процент, константа, вид
операнда, `добавить` ↔ `результат равен`), добавить условие, убрать условие,
добавить правило, убрать правило, переставить правила, изменить начальное
значение. Веса смещены к тонкой настройке; за один ход иногда делается 2–3
мутации, потому что одиночная мутация не может одновременно добавить правило и
настроить его действие, а по отдельности каждый из этих ходов ухудшает фитнес.

Кроссоверы: одноточечный по списку правил (голова одной политики, хвост другой —
режем список, а не перемешиваем, потому что порядок правил несёт смысл) и обмен
условиями внутри соответствующих правил (кроссовер по правилам переносит блоки
целиком и не умеет комбинировать посылки).

Случайность — из своего PRNG (mulberry32 + FNV-1a для семени, `src/prng.mjs`) с
расщеплением потоков: разбиение выборки берёт свой поток и не зависит от того,
сколько чисел израсходовала эволюция.

## Фитнес

Три критерия:

| критерий | что меряет | почему |
|---|---|---|
| точность | насколько модель воспроизводит исторические решения | ради этого всё |
| простота | штраф за число правил и условий | политика из двадцати правил бесполезна, её никто не примет |
| допустимость | доля наблюдений, на которых модель нарушает свои свойства | модель, ломающая объявленные инварианты, недопустима независимо от точности |

**Мера точности выбрана разной для разных типов ответа, и это осознанно.** Для
числового ответа берётся средняя абсолютная ошибка, а не доля точных попаданий:
скидка непрерывна, попадание «в копейку» — во многом случайность, а MAE даёт
поиску градиент — модель, промахнувшаяся на 50 рублей, лучше промахнувшейся на
5000, и отбор это видит. Для категориального ответа (допустить / отказать)
метрики расстояния между метками не существует, поэтому точность — доля точных
совпадений. Обе величины отчёт печатает всегда, так что подмены не происходит.

MAE нормируется на среднее абсолютное отклонение цели от её среднего по обучающей
выборке. Тогда `1.0` — качество тривиальной модели «всегда среднее», `0.0` —
идеальное совпадение, и веса критериев означают одно и то же независимо от того,
в рублях цель или в штуках. Сложность тоже приведена к `[0, 1]` по потолку
пространства поиска; условие стоит вдвое дешевле правила (лишнее правило — это
отдельный абзац политики, лишнее условие — уточнение существующего).

### Взвешенная свёртка или Парето

Реализованы оба режима.

**Взвешенный** (по умолчанию): `фитнес = w_точность·ошибка + w_простота·сложность
+ w_допустимость·нарушения`, минимизируется. Веса задаются флагами
`--w-accuracy`, `--w-simplicity`, `--w-admissibility` и печатаются в отчёте.
Быстро, даёт ровно один ответ.

**Парето** (`--pareto`): недоминируемая сортировка со скученностью по Дебу
(NSGA-II). Отбор ничего не взвешивает; на выходе — фронт компромиссов, живущий
в архиве и переживающий перезапуски популяции.

Когда какой уместен:

- **взвешенный** — когда обмен уже согласован. «Одно лишнее правило стоит не
  больше полупроцента точности» — это решение аналитика, а не поиска; если оно
  принято, свёртка честно его исполняет и экономит время.
- **Парето** — когда обмен ещё не согласован, а именно это обычно и есть предмет
  разговора. Веса — скрытая форма уже принятого за аналитика решения; фронт
  показывает, что реально можно купить простотой, и оставляет выбор человеку. В
  SBSE это стандарт, и он честнее.

Чтобы вернуть из фронта одну модель для stdout, правило выбора объявлено явно:
сначала отбрасываются модели, нарушающие свойства, затем берётся точнейшая, при
равной точности — простейшая. Весь фронт остаётся в `--json` и в отчёте stderr.

### Локальная доводка

Эволюция хорошо находит структуру (сколько правил, по каким полям, в каком
порядке) и плохо — числа. К лидеру каждого поколения применяется покоординатный
спуск по числовым параметрам, попытка выбросить каждое правило (прямая
реализация бритвы) и полная замена действия правила на «круглом» множестве
операндов. Последнее лечит самый упрямый промах синтеза: эволюция находит
правильные условия, но прикрепляет к ним `то результат равен 12 процентов от
поля сумма` вместо `то добавить 500`, а перейти от одного к другому нужно за
один ход — оба промежуточных варианта хуже обоих концов.

Доводка сравнивает кандидатов **тем же критерием, что и отбор**: свёрткой во
взвешенном режиме, доминированием в Парето. Скрытых весов внутри неё нет.

## Защита от переобучения — не опция

Данные детерминированно по семени делятся на обучающую и контрольную выборки
(`--holdout`, по умолчанию 0.3). Поиск видит только обучающую. Отчёт печатает
ошибку на обеих. **Без контрольной выборки синтез бессмыслен**: подогнать правила
под конкретный журнал решений тривиально, и «относительная ошибка 0.02» без
второго числа рядом не значит ничего.

Второй рубеж — штраф за сложность. Вот тот же прогон с выключенной бритвой
(`--w-simplicity 0 --max-rules 12`):

```
поколений: 600 (лучшая найдена на 262, перезапусков при застое 16)
размер модели: правил 7, условий 13
обучение: наблюдений 224, относительная ошибка 0.0379, MAE 43.9732, точных попаданий 0.8214
контроль: наблюдений 96, относительная ошибка 0.0117, MAE 13.5417, точных попаданий 0.9167
```

Ошибка **та же самая**, размер — вдвое больше, и в модели появляется мусор,
подогнанный под шум:

```fts
правило «Правило 1 — объём больше поле сумма и сумма больше 10000»
  если «объём» больше поле «сумма»
  и «сумма» больше 10000
  то добавить 10

правило «Правило 6 — объём не меньше 5 и сумма не больше 13000»
  если «объём» не меньше 5
  и «сумма» не больше 13000
  то добавить 0
```

Условие «объём больше суммы» не выполняется никогда, `добавить 0` не делает
ничего. Такую политику невозможно вынести на согласование. Бритва — не украшение
фитнеса, а то, что делает результат пригодным.

## Данные

`data/` содержит два набора, каждый — в двух вариантах (чистый и зашумлённый), и
рядом с каждым лежит **истинная политика**, из которой он порождён:

| файл | что это |
|---|---|
| `discounts.truth.fts` | истинная политика скидок: три правила, четыре условия |
| `discounts.clean.json` | 320 наблюдений без шума |
| `discounts.json` | те же входы, 15 % решений искажены |
| `admission.truth.fts` | истинная политика допуска заявки: три правила, порядок значим |
| `admission.clean.json` | 300 наблюдений без шума |
| `admission.json` | те же входы, 10 % решений искажены |

Метки не выдуманы: они вычислены ядром FTS по настоящей модели из `*.truth.fts`.
Поэтому у синтеза есть проверяемая цель — на данных без шума найденная модель
обязана вести себя как истинная **на всей сетке входов**, а не только на выборке.
Синтез, который нельзя проверить на задаче с известным ответом, невозможно
отличить от подгонки.

Генератор детерминирован по семени и воспроизводит поставленные файлы:

```
node bin/ftsynth.mjs gen-data --set discounts --seed 7 --noise 0.15 --out data/discounts.json
node bin/ftsynth.mjs gen-data --set admission --seed 7 --noise 0.1  --out data/admission.json
```

В набор данных из истинной модели попадают только объект, тип ответа и
свойства-инварианты — то, что аналитик готов подписать заранее. Правила и
начальное значение — то, что ищет поиск.

Шум применяется к части наблюдений целиком, а не размазан по всем: так ближе к
«менеджер отклонился от политики», чем к «датчик врёт».

## CLI

```
ftsynth fit --data data/discounts.json --object «Покупка» --utility «Рассчитать скидку» --seed 42 --generations 600
ftsynth fit ... --pareto      недоминируемая сортировка вместо взвешенной суммы
ftsynth fit ... --json        отчёт машинно-читаемо в stdout вместо текста модели
ftsynth fit ... --out политика.fts
ftsynth gen-data --set discounts --seed 7 --noise 0.15 --out data/discounts.json
ftsynth sets
```

Контракт вывода тот же, что у ядра FTS и у соседних инструментов: полезный
результат — готовый текст `.fts` — в stdout, отчёт и диагностика — в stderr,
ненулевой код возврата при ошибке. Поэтому `ftsynth fit … > политика.fts` сразу
даёт пригодный файл, а отчёт остаётся видимым в терминале и в логе CI.

Прочие флаги: `--population`, `--holdout`, `--max-rules`, `--max-conditions`,
`--w-accuracy`, `--w-simplicity`, `--w-admissibility`, `--examples`.

Про `--generations`. Поиск устроен как multi-start: при застое популяция
заменяется целиком, а лучшая модель живёт вне популяции. Подмешивать свежих
особей в сошедшуюся популяцию бесполезно — отбор выбивает их за два поколения.
Бюджет поколений расходуется поэтому на несколько независимых попыток, и от него
прямо зависит, будет ли найдена истинная политика. Замеры на наборе скидок без
шума, восемь семян (1, 2, 3, 7, 42, 99, 123, 2024), сверка с истиной по
поведению на всех 540 точках сетки:

| поколений | восстановлено | время прогона |
|---|---|---|
| 200 | 2 из 8 | ≈ 2.5 с |
| 600 | 7 из 8 | ≈ 8 с |
| 1500 | 8 из 8 | ≈ 20 с |

Прогоны, где истина не найдена, останавливаются на относительной ошибке
0.03–0.05 и, как правило, отличаются от истины одним правилом. Метод стохастичен,
и делать вид, что он всегда попадает, было бы неправдой: на семени 2024
шестисот поколений не хватает. Значение по умолчанию — 600, как компромисс между
надёжностью и десятком секунд ожидания.

```
размер модели: правил 3, условий 4
```

Сравнение с `data/discounts.truth.fts` на всей сетке входов (30 сумм × 3 статуса

поэтому восстановление проверяется по поведению, а не по буквам.

### Скидки, 15 % решений искажены — истинная политика всё равно восстановлена

```fts

      если «сумма» больше 9000
      то результат равен 10 процентов от поля «сумма»
```

## Про `пример` в выданной модели

Примеры в результате фиксируют **поведение найденной модели** на выбранных
входах: ожидание в примере — это то, что предсказывает модель, а не то, что решил
человек. Это регрессионный тест артефакта: `fts test` на нём зелёный и обязан
таким оставаться при любой правке политики. Правильность примеры не
подтверждают — правильность измеряется ошибкой на контрольной выборке, и она в
отчёте. Смешивать эти две вещи нельзя, поэтому названы они «Снимок поведения», а
не «Проверка».

## Честная граница метода

Синтез ищет в пространстве, ограниченном выразительностью правил FTS: **конъюнкция
сравнений поля с константой (или с другим полем) и действие из операндов —
константа, поле, процент от поля**. Всё, что не выражается правилом такого вида,
найдено не будет — и это не недостаток метода, а его область определения:

- **дизъюнкции** внутри одного правила: «если А или Б» приходится записывать
  двумя правилами, и если истинная политика дизъюнктивна, найденная запись будет
  длиннее и читаться хуже;
- **арифметические зависимости между полями**: `сумма / объём`, `цена × количество`,
  любая производная величина. Сравнить два поля правило умеет, вычислить из них
  третье — нет;
- **нелинейности**: прогрессивная шкала, кусочно-заданная функция сверх десятка
  порогов, любое сглаживание. Ступеньки набираются правилами, но ценой их числа,
  а бритва их же и срежет;
- **зависимость от истории и от других объектов**: утилита FTS — чистая функция
  одного плоского объекта. Ни предыдущих решений, ни агрегатов по клиенту, ни
  вложенных структур в правиле выразить нечем;
- **операнд `результат` в действии** исключён из поиска сознательно: `то результат
  равен результат` — тождество, `то добавить результат` — удвоение. Печатать и
  разбирать их инструмент умеет, но искать в них нечего.

Отдельно: пороги ищутся только среди наблюдённых значений. Если истинная граница
лежит между двумя соседними значениями в данных, синтез не может её угадать и не
должен делать вид, что может — это видно на примере `стаж больше 3` в прогоне с
шумом.

## И главное

Соответствие данным не делает правило справедливым.

Найденная политика — это гипотеза о том, как решения принимались, а не суждение о
том, как их следует принимать. Журнал решений содержит и ошибки, и предвзятость,
и обстоятельства, которых в полях нет; синтез воспроизведёт их вместе со всем
остальным, потому что именно этого от него и требуют. Если в данных постоянным
клиентам систематически давали больше, синтез напишет это правилом — и правило
будет точным, читаемым, проходящим свойства и при этом, возможно, неприемлемым.

Поэтому результат `ftsynth` — вход в согласование, а не его итог. Модель на то и
выдаётся текстом на языке, который читается вслух: чтобы человек мог посмотреть
на каждое правило и сказать, согласен ли он подписать его как политику. Это
решение остаётся за ним, и никакая метрика его не заменяет.
