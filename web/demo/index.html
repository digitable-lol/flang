The FTS compiler is 88 KB of ES modules with no dependencies, so the whole thing runs in this tab: parsing, domain examples, executing a utility, generating TypeScript, and proving a theorem against data. Nothing on this page talks to a server.

1. A model written inside the tag

Exactly like a mermaid block: the model is the text content of the element. Edit it and every panel recomputes. view="check" picks the tab that opens first.

2. Events reach the host page

The component lives behind a shadow root, but fts:compiled, fts:error and fts:result are composed events: the page sees them on document. Type in the editor above or run the utility to fill this log.

3. Read-only, for prose

    

      readonly drops the editor and keeps the results. This is what documentation usually wants: the
      reader cannot break the sample, but can still run it.
    

    
      category "Sales"

        object Purchase
          amount is money
          "loyal customer" is boolean

        utility "Calculate discount"
          accepts Purchase
          returns money
          starts with 0

          rule "Large purchase"
            if amount is at least 10000
            then add 10 percent of field amount

          rule "Loyal customer"
            if "loyal customer" equals true
            then add 5 percent of field amount

          property "Discount is capped"
            result is at most 20 percent of field amount

          example "Regular purchase"
            given amount equals 5000
            given "loyal customer" equals false
            expected result equals 0

          example "Large loyal purchase"
            given amount equals 20000
            given "loyal customer" equals true
            expected result equals 3000
    

    
4. Loaded from a file, opened on the proof

    

      src fetches the model, context-src fetches the JSON the theorem is checked against, and
      view="proof" opens the tab that matters. Change true to false in the data
      and the permission disappears.

категория «Кредитная политика»

  объект «Заявка на лимит»
    сумма является деньгами
    «скоринг пройден» является признаком

  утилита «Одобренная сумма»
    принимает «Заявка на лимит»
    возвращает деньги
    начинает с 0

    правило «Скоринг пройден»
      если «скоринг пройден» равен да
      то добавить 50 процентов от поля сумма

    пример «Заявка без скоринга»
      дано сумма равна 100000
      дано «скоринг пройден» равен нет
      ожидается результат равен 0

    пример «Заявка со скорингом»
      дано сумма равна 100000
      дано «скоринг пройден» равен да
      ожидается результат равен 50000
